# 排障清单

按下面顺序检查，可以避免把协议、权限、媒体格式和异步状态混在一起。

## Base URL

- OpenAI 兼容 SDK 使用 `{{OPENAI_BASE_URL}}`。
- Anthropic SDK 使用 `{{ANTHROPIC_BASE_URL}}`。
- ModelArk、Kling 和即梦示例使用 `{{SITE_BASE_URL}}` 下的原生路径。
- 检查反向代理是否保留请求方法、认证头、SSE 和较大的请求体。

## 鉴权与模型

- 确认请求头中只有占位位置被替换为你的 Key。
- 调用 `GET /v1/models` 确认模型对当前 Key 可见。
- 不要把展示名称或内部标识当作公开模型 ID。
- `401` 先查 Key，`403` 先查权限，`429` 再区分限流与额度。

## Content-Type

- JSON 请求使用 `application/json`。
- 图片编辑使用 `multipart/form-data`，让客户端自动生成 boundary。
- 视频内容下载前验证状态和媒体类型。
- 错误响应通常是 JSON，不要按图片或视频解码。

## 图片与视频

- 检查远程媒体 URL 是否可公开访问、有效期是否覆盖处理时间。
- Base64 不要包含不受支持的数据 URL 前缀。
- `n`、时长、分辨率、宽高比和文件大小必须在模型范围内。
- 不同视频协议的字段不能互换。
- 图片请求在本次 HTTP 请求内返回结果；超时后不要把它当成可轮询任务，也不要盲目重复创建。

## 素材

- 调用前检查模型目录中的 `api.assets`，确认当前模型支持所需操作。
- 调用方需要同时保存客户模型、不透明 ID 和返回的 `asset://` 引用。
- 平台不在视频生成前验证素材所有权、状态或兼容性；单项查询成功也不保证生成成功。
- `404 model_not_found` 表示客户模型不可用；`422 unsupported_asset_operation` 表示该模型或操作明确未发布。

## 异步任务

- 仅对明确返回任务 ID 的视频接口执行以下步骤。
- 保存创建响应里的任务 ID 和请求 ID。
- 使用退避轮询，不要每几十毫秒查询一次。
- 客户端超时后先查询原任务，不要立即重复创建。
- 终态失败后记录公开错误码，并停止轮询。

## 提交支持信息

提供时间、公开请求 ID、接口路径、HTTP 状态、公开错误码和已脱敏的最小请求。不要提供 API Key、Cookie、完整媒体、个人材料或内部管理页面导出。
