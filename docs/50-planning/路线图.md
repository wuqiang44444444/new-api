## Seedance 生产验收

当前架构以[Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)为准。
应用代码已经完成专用 ChannelType、ModelArk V3 四组接口、代码化视频/素材协议、确定性路由、单次
Provider POST、冻结 Task、一对一素材代理和旧 Link 合同删除。本阶段不再开发 publication、SKU、
implementation、execution binding、候选分发或自动换渠道。

### 数据与环境

- [ ] 使用生产同版本 SQLite、MySQL、PostgreSQL 验证迁移、旧结构物理清理以及保留的 Task、资金和审计事实；
  无状态素材代理不建立本地 Asset/AssetGroup 映射，不恢复旧字段 decoder 或应用层兼容读取。
- [ ] 对已有 `DoubaoVideo` Seedance 配置采用“新建独立 Seedance Channel 与客户模型—隔离分组验证—
  禁用旧配置”的方式迁移，不原地改型，也不把多个 Provider 映射为同一客户模型。
- [ ] 验证服务重启、缓存重建、渠道停用和凭据轮换不会改变在途 Task 的冻结查询、删除和结算事实。

### 官方线路

- [ ] 国内火山和海外 BytePlus 分别完成 ModelArk V3 create/get/list/delete、明确失败、发送结果不明、
  内容代理、真实账单与限流验证；一个地区的成功不能替代另一个地区。
- [ ] 两个官方素材协议分别完成 Provider 素材/素材组创建、单项查询、删除、真人认证链接、审核、URL TTL、
  权限拒绝和视频引用验证；网关不发布素材列表，国内、海外账号与 opaque ID 不能互换。

### 第三方线路

- [ ] FunCloud Standard/Fast/Mini/2.5 分别完成真实创建/查询、图片/音频/视频输入、实际输出、
  结果 URL 生命周期和失败/超时验证；Standard/Fast/Mini 额外完成虚拟素材组、上传/刷新、
  `asset://` 生成和严格列表信封验证，2.5 保持无素材。
- [ ] 逐个 FunCloud 模型和档位对齐查询响应 `completionTokens`、Provider 后台 Token、`pointConsume`
  和美元账单，覆盖跨模型、输入类型、分辨率和账号的样本；字段缺失或计量漂移时停流并进入对账，
  不回退到金额反推；真人能力保持不发布。
- [ ] TokenSave 2.0 对单首帧、首尾帧、参考图、`duration=-1`、失败/unknown 和 480p/720p/1080p 完成
  本站 E2E 与 Provider 对账，不把未接入的音视频参考算作验收能力。
- [ ] 墨行国内 2.0 对 JoyCreator 图片/视频/音频素材与 facade 转换完成真实闭环；Fast、Mini、2.5 分别
  验证 ModelArk 输入、火山素材、默认音频、智能时长和各自边界，不能用一个模型的结果替代其它模型。
- [ ] 飞彩按每个独立客户模型验证声明支持的分辨率、画幅、媒体输入、实际输出、音频语义和逐任务成本；
  Fast、value、Standard 4K、SD2、Pro PI 等不能复用其它模型的证据。当前两个五模型 Channel 保持停用；
  `/v1/tasks` 不作为任务级对账源，Provider 单任务成本在取得可靠账单前保持未知。
- [ ] 每条第三方线路验证创建失败、查询失败、任务失败、超时、重复轮询、普通响应脱敏和内容代理，
  证明只发生一次结算或退款，失败时不重发、不换渠道。

### 灰度完成条件

- [ ] 技术人员按精确客户模型给出协议、映射、价格、分组和已验证字段结论，管理员只配置这些普通字段。
- [ ] 每个准备开放的客户模型完成[全渠道上线验收手册](../40-operations/05-全渠道上线验收手册.md)要求的
  真实黑盒、账单、脱敏和回滚验收。
- [ ] 一般线路只启用客户模型对应的唯一 Channel；飞彩按 VIP/性价比两个五模型 Channel 管理，一次性开放
  十模型前两组都必须完成验收。若需要逐模型灰度，先收窄 Channel 模型清单；异常时不切到另一 Provider。

当前事实见[计费表达式与协议探针架构](../20-architecture/计费表达式与协议探针架构.md)及各 Provider 接入设计。

  `<nil> * float64` 或模型表达式串值。
- [ ] 用 4/5/15 秒受控任务核对预扣、终态结算和冻结 Task 事实；墨行 Fast/Mini/2.5 分别核对实际 completion tokens、
  Provider 账单和客户差额结算，不能以同协议其它模型替代。

- [ ] 对墨行 Standard、TokenSave 和其它 Provider 的 502 增加脱敏错误分类与请求关联日志；只有代码协议和真实文档共同
