   无中间态残留。
2. error_events 请求体保留决策：《系统4xx日志缺失问题分析与修复方案》§4 承诺不保存用户提示词与
   原始请求体，`http_exchange` 快照实际把请求体持久化进 `error_events.detail`；叠加无 TTL 与约
   14 个索引构成隐私驻留与容量风险。需显式决策保留/截断/按模块关闭，并建立保留清理排期。完成
   信号：决策落地为契约修订或代码变更，清理计划进入运维事实。
3. 邮件报告"无调用"状态：需求要求零流量小时显示"无调用，无法据此判断稳定性"；复核确认无可靠
   活动证据时不能声称零调用，当前未实现。需补实现（基于可信活动信号）或经用户确认降级并记录。
4. 生产级验收门槛（多方案共同声明，均不得以本地/SQLite 结果替代）：MySQL 5.7.8 与
   PostgreSQL 9.6 最低版本实测、真实三库并发、OSS 备份恢复演练、ClickHouse 实库、真实 SMTP 收件、
   多实例灰度、来源修订钩子生产延迟基线、`repair-task-billing-logs` 生产一致性副本复演。
   其中 PostgreSQL 9.6.24、ClickHouse 指定用例及真实 SMTP 收件已完成本轮本地验收；精确
   MySQL 5.7.8 和其余生产门槛继续保留。
5. 来源修订钩子热路径成本：logs/tasks 写事务内保存点+多次 UPDATE，开关关闭仍有成本；启用账单
   确认能力前必须完成目标库延迟实测。
6. 低优先跟进（择要，细节见对应归档件）：partial 围栏区分瞬时与确认性失败；error_events 启动
   回填改版本标记跳过；`CancelCustomerExportJob` 递归改循环；确认幂等键参与重复判定；
   `failSystemTask` 错误统一脱敏；`deliverClaims` 冗余全表 UPDATE 消除；流式协议失败
   `strings.Contains` 匹配精确化；`http_exchange` 类型断言补 ok 检查；66 笔补正等核验入口固化为
   受控只读命令使核验数字可重放；`customer_export_i18n` 超 en/zh 的额外语言标签维护面。
