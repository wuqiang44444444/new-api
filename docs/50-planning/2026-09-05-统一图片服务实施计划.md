# 统一图片服务实施计划

本计划把[统一图片生成、编辑与异步查询方案](../80-dev/2026-09-05-Gemini与Vertex标准图片接口适配方案.md)
（已接受的目标合同）拆为可执行的工程阶段。方案的 §4.2 硬约束修订草案与 §4.3 接线面在本计划中落定为
G0 结论；G1 合同冻结表随本计划一并给出。方案中的 G2—G5、G11、G12 属于真实 Provider、容量与灰度取证，
不在代码阶段内完成，保留在[路线图](路线图.md)。

## 0. 范围与既定事实

- 同步合同：既有 `POST /v1/images/generations`、`POST /v1/images/edits` 增加 Gemini(24)/Vertex(41)
  履约，南向走 `generateContent`（image 模型），不改动聊天与 imagen `:predict` 路径。
- 异步合同：同一对入口以 `Prefer: respond-async` 显式选择 202 受理；任务查询复用
  `GET /v1/tasks/{task_id}`，仅图片任务返回图片投影。
- 图片中转（`ChannelTypeAsyncImage=63`）纳入同一北向合同与异步执行底座；各协议 profile 当前发布的
  参数面维持管理员与证据门控（参考图、编辑操作在 Provider 计费证据完成前保持未发布并显式 400）。
- 对象存储使用部署方提供的 S3 兼容端点（当前为 Azure Blob S3 兼容网关），网关侧用代码内 SigV4 签名
  （path-style），不引入新的 Go 依赖。
- 本计划实施后，`docs/00-context/硬约束.md` §4 按方案 §4.2 草案修订（已由用户授权全量实施）。

`RECONCILIATION_REQUIRED`，禁止自动重发、换渠道或退款。

## 2. G1 合同冻结表（v1）

标准字段语义以 OpenAI Images 为基准；逐模型族生效矩阵如下。未列字段=该族不支持，显式非空提交返回
`400 invalid_request_error`，不静默删除或改义。

### 2.1 gemini_image 族（Gemini 24 / Vertex 41，`generateContent` image 模型）

| 字段 | generations | edits | 取值/默认 | 说明 |
| --- | --- | --- | --- | --- |
| model | ✔ | ✔ | 客户模型 | 管理员 mapping 到上游 image 模型 |
| prompt | ✔ | ✔ | 1—20000 字符 | 原样传递，不改写 |
| n | ✔ | ✔ | 仅 `1`；未传默认 1；其它值 400 | Google 每响应一图（P3 例外） |
| size | ✔ | ✔ | `auto` 或精确支持宽高比的 `WxH`，每边 ≤ 4096 | 按长边映射 1K/2K/4K，返回图等比例缩放到请求像素；不支持的比例事前 400，上游比例不符报交付错误；不接受 `a:b` |
| quality/style/moderation/background/output_format/output_compression/watermark/input_fidelity/partial_images | ✘ | ✘ | 显式非空 400 | 缺 Provider 证据，按 C3/P7/P9/P10/P11 阻断 |
| response_format | ✔ | ✔ | 默认 `b64_json`；显式 `b64_json` ✔；显式 `url` 在对象存储启用时返回 300 秒签名 URL，否则 400 | P13 |
| stream | ✔ | ✔ | 显式 `false` 合法；`true` 400（未发布 SSE） | P14 |
| images（JSON edits） | — | ✔ | 数组，每项 Data URL 或 HTTPS URL | E1；上传字节上限见 2.3 |
| image/image[]（multipart edits） | — | ✔ | 文件字段，PNG/JPEG/WebP | E1 |
| mask | — | ✘ | 400 | E2：无法真实履约遮罩语义，不降级为提示词 |
| user | ✔ | ✔ | 字符串 | 仅日志辅助标识 |

### 2.2 图片中转族（`ChannelTypeAsyncImage=63`）

维持各协议已发布 profile（FunCloud 4 模型、Moxing 2 模型）：generations-only、`n=1`、`response_format`
默认 `url`（Provider URL）；`edits`、`mask`、参考图与 `stream=true` 在 Provider 计费证据完成前显式
400。异步模式下结果转入平台 OSS 并按 300 秒签名交付（见 2.4）。

### 2.3 输入图片预算（E5，跨族共享）

- 最多 14 张输入图（URL 与二进制合计，不含 mask——mask 在 v1 全族未发布）。
- 二进制单张解码后 ≤ 20 MB（20×1024×1024 字节），合计 ≤ 50 MB；按解码字节数计，不按 Base64 长度。
- URL 仅计数，不下载探测（U1/U2）。

### 2.4 异步合同（Prefer: respond-async）

- 受理成功：`202`，Body `{"created","id","object":"image_task","status":"queued","query_url"}`，
  `Location` 头指向查询地址。
- `Idempotency-Key`：仅异步模式支持（同步请求携带该头返回 400）；键域 = user + app(token) + 操作 +
  客户键，重放返回原任务 ID；不同请求体 409。绑定任务未终态（含待核实）期间 claim 到期不重置；
  multipart 摘要忽略 boundary（排序字段 + 文件内容 hash）；受理未完成窗口内重放返回
  `idempotency_in_progress`，不签发第二个 202。
- 查询 `GET /v1/tasks/{task_id}`（图片任务投影）：`status` ∈ `queued|in_progress|succeeded|failed|expired|unknown`；
  已登记结果（含待核实的部分结果）通过 `data[]` 逐张 `{"status":"available|deleted|unavailable","url","url_expires_at"}`（300 秒
  签名，过期重查续签）或创建时显式 `b64_json` 的原文；HEAD 404 → `deleted`（保留历史状态、不抹除其它
  图片），其它探测错误 → `unavailable`（不判删除）；失败给 `error{message,code}`；`unknown` 表示结果
  待核实，不自动退款。
- 背压：应用未完成任务超限 `429`，全局等待超限 `503`，均不受理、不预扣、不发送；`Retry-After` 尽力给出。

### 2.4.1 资金与容量补充（修复轮冻结）

- 资金单一所有者：容量、钱包/令牌预扣、Task 与幂等绑定同一事务；失败全部回滚，不依赖事后退款。
- 成功结算按冻结规则分流：tiered 表达式用冻结快照、加密请求探针及实际 p/c 重算；token 倍率使用冻结价格与可信 usage；
  固定价保持预扣（不按张数折价）。异步 v1 资金来源为钱包（订阅接入留 G11）。
- 目标计算无资金副作用；仅由共享原子入口提交资金差额、计费状态、最终统计与受理槽释放。
- 容量变更/重建先锁同一全局计数行，Task 状态和槽位增减同事务；终态待结算继续占用受理容量。

### 2.5 状态枚举与部分成功（§3.9）

`queued → in_progress → succeeded | failed | expired | unknown(RECONCILIATION_REQUIRED)`；一次任务
一次生成/编辑，不拆调用凑 n；部分成功按已验证图片交付，不自动补生成；生成成功而 OSS 保存失败是交付
异常（`unknown`/重试保存），不冒充生成失败。

## 4. 依赖与顺序

A → B → C → D → E → F → G；B 不依赖 C（同步默认 b64），D 依赖 C（异步输入/结果必须落 OSS）。
数据库仅新增 `image_task_slots` 容量计数表（可由 Task 重建，每轮对账），SQLite/MySQL/PostgreSQL 同构迁移。
