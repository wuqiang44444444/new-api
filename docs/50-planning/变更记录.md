> 只记录已落地的对外合同、架构边界、运维入口和文档治理变化；未完成事项进入[路线图](路线图.md)。

## 2026-08-21

- 图片中转管理身份已统一为 `ChannelTypeAsyncImage=62` / `APITypeAsyncImage`：管理员通过必填的
	  `image_upstream_protocol` 显式选择 `funcloud_aigc_v2` 或 `moxing_images_v1`，每条渠道只承载一个协议。
	  FunCloud/Moxing adaptor 继续独立履约；协议不从模型、mapping、价格或 Base URL 推断，协议选择也不创建
	  或改写管理员 `model_mapping`。旧类型 63 由幂等、无损 settings 的数据库迁移改为类型 62；所有节点启动
	  都验证迁移 marker 和旧类型清零，运行时和前端不保留旧类型分支。strict image 热路径同时拒绝 Param
	  Override，不能在 adaptor profile 校验后改写 Provider 请求。
- Moxing 渠道保存合同由“单渠道单模型”收敛为“单渠道可承载多个精确模型”：Models 与 `model_mapping`
  完全由管理员维护，保存和请求链路复用 NEWAPI 原生映射语义，代码只校验每个渠道模型最终解析到唯一
  Provider profile 注册表；Lite/Pro 可共用同一 Key，北向入口、普通 Ability/分发和按客户模型计费语义不变。
- 本地两个空 KEY、手工禁用且无 Ability 的 Moxing 渠道已安全合并为一个 Lite/Pro 渠道；删除的 ID 79
  可由合并前 SQLite 备份恢复。显式 `stream=false` 现与 `stream=true` 一样按未发布字段在发送前拒绝，
  Moxing 前端登记回归测试已纳入标准 Vitest。

## 2026-08-20

- 新增普通图片渠道 `ChannelTypeMoxingImage=63`：北向继续使用原生 `/v1/images/generations`，登记
  Moxing Seedream 5 Lite/Pro 同步单图、固定 `2K` 和 URL 响应；客户模型通过一条精确 `model_mapping`
  转换，不使用 Link、图片 Task、body pass-through、Param Override、自动重试或模型抓取。
- 管理端已登记 Moxing 渠道类型、展示顺序、渠道测试 endpoint 和七种 locale；本地数据库分别预建空 KEY、
  手工禁用的 Lite/Pro 渠道，真实 Provider、供应商账单、超时 exposure 和灰度仍由路线图跟踪。
- 中转异步图片生成已收敛为普通 `ChannelTypeAsyncImage=62`：客户继续调用
  `/v1/images/generations`，FunCloud task 只在 adaptor 内轮询，成功返回单 URL 的 HTTP `200`；
  不创建图片 Task、create attempt、图片幂等状态或 `/v1/images/tasks/:task_id`。
- 旧 `mediaimage` / `media_task_image_blocking` 图片任务桥已退出生产路径；当前架构事实统一进入
  [图片服务与异步 Provider 适配架构](../20-architecture/图片服务与异步Provider适配架构.md)，真实价格、
  失败退款、超时 exposure、残留数据和生产灰度继续由路线图跟踪。

## 2026-08-12

- FunCloud Seedance 收敛为 `seedance-2-funcloud`、`seedance-2-fast-funcloud`、
  `seedance-2-mini-funcloud`、`seedance-2-5-funcloud` 四个独立客户模型和 Channel；
  `funcloud_seedance` 通过 Provider 模型精确注册创建路径，未知模型失败关闭，不再通过
  模型名包含关系猜测。
- Standard/Fast/Mini 已接入 `funcloud_material` 虚拟素材库，共享平台 `ast_*` /
  `astgrp_*` 身份和 Resolver；上传使用 HTTPS/443 安全回源和流式 multipart，删除组前必须取得
  Provider `materialCount=0` 的唯一证据。2.5、真人素材和单素材重命名/删除保持明确不支持。
- FunCloud 四模型计费改为冻结美元 Token `tiered_expr`；成功终态只在可信
  `pointConsume` 存在时按版本化公式反推 completion tokens。原始计量、算法/价格版本和推导结果
  持久化为 Task 私有计费证据，只向管理员日志投影；不可信计量进入
  `RECONCILIATION_REQUIRED` 并保留预扣。
- FunCloud 管理协议统一为无版本名 `funcloud_seedance` / `funcloud_material`，运行时不保留
  v2 decoder、alias 或 fallback。一次性旧名称迁移在发现活动 Task、create attempt 或 idempotency 时整体中止。
- FunCloud 两份实施增量已收敛到
  [FunCloud 模型与素材库对接设计](../20-architecture/Seedance模型接入设计/FunCloud/FunCloud模型与素材库对接设计.md)；
  未完成的真实 Provider、账单和灰度继续由[路线图](路线图.md#seedance-生产验收)承载。
- 素材组更新不属于统一 `/v1/asset-groups` 北向合同；已删除共享 `GroupAdapter.UpdateGroup`、各
  Provider 不可达实现和对应测试，不为 FunCloud 新增品牌化北向。

## 2026-08-05

  `models` / `model_mapping`，系统通过 implementation execution binding 推导 Link SKU；普通保存
  只能创建或核对，改绑必须携带 expected version、真实操作人和原因。

  回滚整批状态，缓存只在提交后刷新，人工新增、编辑、克隆和标签操作不再写匿名审计。
- 管理端以“Link 接入方案”投影精确 implementation，方案字段随模型和模型映射响应式重算；切换时
  清理旧路径和 Advanced Custom routes，route family 直接取 execution binding，并提供受权限控制的
  显式 rebind 对话框。
- Link publication 列表改为批量计算 Channel/Ability 可用性；`end_user_subject` 能力只在冻结
  publication 后由 SKU capability 校验。补齐链式模型映射、循环保护、事务回滚、显式改绑、真实
  implementation 投影和三数据库回归。
- 当前代码完成不代表生产发布：真实 Provider、生产价格与账单、存量冲突审计和灰度回滚仍按
  [路线图](路线图.md)与运维手册执行。
- 文档归档规则由“99 完全不可写”收窄为“只增不改”：只允许将通过收敛和校验闸门、目标路径不存在
  的新历史文件移入；既有归档仍永久禁止修改、覆盖、删除、重命名或格式化。本次三份 Link 实施与
  复评文档已移动到 `docs/99-archive/2026/08/`。
