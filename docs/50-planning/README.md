# 50-planning — 计划与变更

## 目标

让维护者快速看清仍未完成的工作、优先级、依赖和完成信号，同时保留正式变更记录。

## 放什么

- 当前未完成事项、阶段优先级、依赖、验收和发布门槛；
- 尚在执行且需要跨批次推进的实施计划；
- 已落地的对外合同、架构边界和运维入口的正式变更记录。

## 不放什么

- 已实现的系统边界和状态机，放入 `20-architecture/`；
- 产品行为和验收口径，放入 `10-product/`；
- 一次性分析、排障和实施流水，放入 `80-dev/`；
- 已完成计划的全文不得继续充当当前事实；事实收敛后应列为归档候选，获得用户明确授权后才能进入
  `99-archive/`。

## 命名格式

- `路线图.md` 和 `变更记录.md` 是固定事实文件，不加日期前缀；
- 临时实施或阶段计划使用 `YYYY-MM-DD-中文主题.md`；
- 文件名不使用含糊的“最终版”“新版”或只写供应商英文缩写。

## 内容格式

- 路线图只写未完成事项，按优先级、当前边界和完成信号组织，不堆叠大量 `[x]` 历史；
- 实施计划写目标与范围、批次与依赖、状态与验收；完成后不再继续追加过程；
- 变更记录按日期记录正式变化，旧条目只用于追溯，不覆盖当前架构事实。

## 编写要求

- 只保留未来动作，完成项及时移入变更记录或事实文档；
- 每个事项必须能回答“为什么还没完成、完成后如何判断”；
- 不把单元测试通过写成真实 Provider、生产账单或灰度发布完成；
- 每周复核路线图与代码、Provider 证据和当前事实文档，删除失效链接与被取代术语。
