# 邮件与运维通知产品设计

本文记录已确认的产品行为。当前实现的技术说明见[用户通知架构](../20-architecture/运维-用户生命周期邮件通知架构.md)和
[系统错误报告架构](../20-architecture/运维-系统错误报告架构.md)。本地实测与 Microsoft 365 租户验收分别记录。

## 1. 角色与目标

| 角色 | 目标 |
| --- | --- |
| 有系统设置权限的管理员 | 选择发信通道、配置运维收件人和阈值，并手动测试投递。 |
| 管理员 | 创建用户时录入有效邮箱，供用户接收账户通知和自行找回密码。 |
| 用户 | 用账户邮箱获取一次性链接，自行设置并确认新密码。 |
| 运维收件人 | 在网关资源达到阈值时收到对应告警，并在每天汇总完成后收到一封运维日报。 |

## 2. 发信配置与模板

- 每个站点只启用一套发信配置。管理员选择 SMTP 或 Microsoft Graph。该站点所有邮件均使用所选通道和
  同一个配置发件邮箱。Graph 使用专用发件邮箱，应用权限限定在该邮箱。
- 保存后，各节点的新提交使用当前配置。切换前已经开始的提交按当次配置结束。
- 收件规则按事件区分。自助找回发到用户的账户邮箱。采用个人通知设置的邮件仍按该设置选择渠道及地址。
  资源告警、运维日报和上游低余额提醒共用现有「报告收件人」名单。
- 每类邮件随版本提供简体中文和英文模板，主题应能识别事件，正文说明发生了什么和收件人可采取的行动。
  模板由版本维护。安全邮件中的验证信息仅用于当次操作，API Key 通知只说明创建事件。
- 管理员可以用已保存的配置向指定地址发送测试邮件。后台应区分提交成功与提交失败。实际收件以目标邮箱
  为准。

## 3. 用户创建与自助找回密码

| 触发 | 行为与结果 |
| --- | --- |
| 管理员建号 | 管理页和保存接口都要求填写格式有效的邮箱。欢迎信依照事件通知设置发送，发信故障与账户保存结果分别呈现。 |
| 用户请求找回 | 启用账户使用自己的账户邮箱接收一次性重置链接。界面统一提示用户检查邮箱，避免透露某地址是否属于账户。 |
| 用户打开链接 | 页面要求两次输入新密码。两次一致并符合密码规则后才可提交。过期、已使用或与当前账户状态不匹配的链接提示重新申请。 |
| 重置成功 | 用户用自己设置的新密码登录。重置链接失效，原有登录会话按账户安全规则失效。 |

本期账户创建场景只有管理员建号。密码流程的变更范围是用户自助找回。

## 4. 网关资源告警

- CPU 和内存按网关实际可用资源衡量。容器有资源限额时使用该限额。硬盘监控网关实际使用的数据卷和日志卷。
- CPU、内存和硬盘的默认阈值各为 **85%**，管理员可独立调整。某项首次采样达到或超过阈值即触发对应
  邮件。持续超限属于同一次异常，只发一次。确认恢复后再次达到阈值，触发下一次告警。
- 每位收件人单独记录投递。明确失败可延后重试。提交结果不明时保留待核对记录，避免重复发信。
- 邮件说明节点、资源项、采样使用率和阈值。这类告警依赖网关能够采样和发信，进程卡死或不可运行的
  探活告警在本期邮件能力范围之外。

## 5. 运维日报

- 配置运维收件人后自动发送日报。按北京时间前一自然日统计，即昨日 00:00（含）至今日 00:00（不含）。
  北京时间 **06:00** 为最早发送时间。汇总未完成时延后，完成后发送。
- 首次配置收件人时从前一自然日开始。收件人清空时暂停生成和发送，重新配置后从已保存的进度继续。
- 一封日报展示已记录错误总数、主要错误类型、受影响渠道、异常运维任务和资源告警次数。逐条详情在
  后台查看。统计允许少量迟到数据遗漏和排行误差，邮件说明覆盖范围及口径。
- 有效数据源中零错误也有日报。数据源读取失败属于汇总未完成，不能显示成零错误。
- 汇总可以提前分批处理。批量邮件和统计工作应受资源限制，模型调用与计费优先。发送失败可在运维侧
  查明，已完成的业务结果仍有效。

## 6. 验收口径

- **投递**。在本地运行目标版本，逐类触发本部署实际启用的邮件并核对收件箱、发件人、主题、正文及
  链接。手动测试邮件另行验收。SMTP 或 Graph 接受提交只是投递的中间结果。
- **账户**。管理员创建用户时拒绝空白或非法邮箱。一次性链接有效时可设置密码，两次输入不一致时无法
  提交，过期或重复使用失败。
- **告警与日报**。CPU、内存、硬盘分别覆盖达到阈值、持续超限、恢复后再次超限。日报覆盖自然日边界、
  06:00 前后和晚于 06:00 才完成的情况。
- **性能**。同等流量下，模型请求 P95 延迟增幅 **不超过 5%**，超时率**不升高**。对照覆盖错误量突增、
  日报汇总和邮件服务响应缓慢。

本地收件与三库迁移已验收；Microsoft 365 Graph 真实邮箱收件验收待用户配置专用发件邮箱后执行，
见[路线图](../50-planning/路线图.md)第 39 项。技术边界见
[邮件投递与用户生命周期通知架构](../20-architecture/运维-用户生命周期邮件通知架构.md)。
