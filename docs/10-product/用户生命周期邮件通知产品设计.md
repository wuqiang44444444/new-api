# 用户生命周期邮件通知产品设计

## 1. 文档定位

本文定义账户创建、密码修改、API Key 创建三类用户生命周期事件邮件的目标产品行为与验收口径。

代码与管理开关已经完成，但**真实 SMTP 投递与灰度验收尚未完成，能力未生产发布**。下文按“目标行为
— 代码现状 — 真实验证 — 生产发布”分别表述：目标行为是产品要求，代码现状说明已实现的可观察事实，
未标“已完成”的均为待验证或待发布。实现细节与控制流见
[用户生命周期邮件通知架构](../20-architecture/运维-用户生命周期邮件通知架构.md)，未完成事项见
[路线图](../50-planning/路线图.md#用户生命周期邮件生产验收)。

本产品复用平台既有的 SMTP 收发与多通道通知底座，只新增“按事件开关投递事务性邮件”这一能力，不新建
邮件通道、事件总线，也不改动既有的余额低提醒等 always-on 通知。

## 2. 产品目标

1. 管理员可以为账户创建、密码修改、API Key 创建三类事件**逐个**开启或关闭通知邮件，默认全部关闭。
2. 事件发生后，平台在主请求成功之后**异步**投递一封事务性邮件；邮件发送不阻断、不重试、不影响业务结果。
3. 邮件内容按用户语言设置提供中英文（简体、繁体、英文）版本，安全类邮件（密码修改、密钥创建）
   明确提示“非本人操作应立即处理”。
4. 注册与管理员建号要求填写邮箱；OAuth/微信等不返回邮箱的注册渠道不强制邮箱，此时欢迎信静默跳过。
5. 平台不修改既有 always-on 通知，不引入退订、邮箱验证或营销分类。

## 3. 角色与权限

| 角色 | 与本能力的关系 | 可观察结果 |
| --- | --- | --- |
| 用户 | 邮件收件人；在密码修改、密钥创建等安全事件后收到提醒 | 在自己邮箱收到按语言渲染的事务性邮件 |
| 平台管理员 | 开关配置者；可代用户建号、改密 | 在 Operations → Monitoring & Alerts 切换三个事件开关；代用户改密同样触发密码通知 |
| 系统 | 事件发生后异步投递 | 开关关闭则不发；SMTP 未配置或发送失败只记日志 |

管理员代用户改密、代用户建号触发的事件，与用户自助操作触发的事件走同一通知口径，不区分来源。

## 4. 触发场景与业务流程

每个事件遵循统一流程：事件在主操作事务提交成功后触发 → 平台读取对应开关 → 关闭则不投递 → 开启
则按用户语言渲染邮件并异步投递。

| 事件 | 触发操作 | 不触发的相邻操作 |
| --- | --- | --- |
| 账户创建 | 用户自助注册成功；管理员新建用户成功 | OAuth/微信注册但 Provider 未返回邮箱（欢迎信静默跳过） |
| 密码修改 | 用户自助修改密码成功；管理员修改用户密码成功 | 非密码字段的资料更新；忘记密码重置（重置链接本身已发邮箱） |
| API Key 创建 | 用户显式创建 API Key 成功 | 注册时系统自动生成的默认 Token（避免注册即发两封） |

设计取舍：

- 注册自动生成的默认 Token **不**触发密钥创建邮件，因此一次成功注册最多收到一封账户创建邮件。
- 密码通知只在真正进入改密分支时触发，普通资料更新不触发。
- 忘记密码重置不重复接线，因为重置流程已经向邮箱发送了重置链接。

## 5. 管理开关

- 三个独立开关，分别控制三类事件，默认全部关闭；开关关闭时对应事件一律不投递，无论邮箱是否存在。
- 开关位于现有 **Operations → Monitoring & Alerts**，不新建独立设置页或 Tab。
- 开关变更经平台统一配置接口持久化，刷新或重载后保留；投递口径只读当前开关值。
- 开关是 per-event 的事务性邮件开关，与既有余额低提醒（阈值触发、always-on）相互独立，互不影响。

## 6. 邮件内容与语言

- 邮件标题与正文按用户语言设置（简体中文、繁体中文、英文）渲染，模板包含站点名称与用户显示名。
- 账户创建邮件为欢迎信，提示“如非本人操作请联系管理员”。
- 密码修改、API Key 创建邮件为安全提醒，提示“如非本人操作请立即重置密码 / 检查密钥列表”。
- 本期不引入退订入口、法律分类或营销内容；既有其它邮件模板保持不变。

## 7. 邮箱边界

- **必填**：用户自助注册、管理员新建用户时邮箱为必填，为空时被拒绝。
- **不强制**：OAuth、微信等注册渠道不强制邮箱；Provider 未返回邮箱时注册仍可成功，但账户创建邮件
  静默跳过。
- **不验证**：本期不校验邮箱可达性，不增加邮箱已验证标记或验证流程。
- **存量用户**：历史已存在但无邮箱的用户，目前在个人设置页**没有**前端提示；该提示为待补齐项，见
  [路线图](../50-planning/路线图.md#用户生命周期邮件生产验收)。

## 8. 失败与限频语义

- **不阻断**：邮件发送在主请求事务提交之后异步进行；无论发送成功、失败或未配置，主业务请求的结果
  不受影响。
- **不重试**：单次投递失败只记日志，不自动重发，不换通道，不因发送失败退款或回滚业务。
- **SMTP 未配置**：开关开启但平台未配置 SMTP 时不投递，只记日志。
- **无邮箱**：开关开启但目标用户无邮箱时静默跳过，只记日志。
- **限频**：复用平台既有的每用户每小时通知限频；极端情况下连续的密码修改可能被限频压掉，本期接受
  该行为。

## 9. 明确不做

- 不修改既有 always-on 通知（渠道禁用、额度耗尽、余额低提醒）。
- 不做账户余额提醒（已由既有 `checkAndSendQuotaNotify` 提供，不在本能力范围）。
- 不做退订、同意、营销或法律分类。
- 不做邮箱验证，不增加邮箱已验证标记。
- 不新建邮件通道、事件总线或观察者机制。
- 不为发送失败提供自动重发、换通道或人工补偿流程。

## 10. 交付约束

- 复用平台既有鉴权、用户、API Key、通知底座与配置管理，不建立第二套通知体系。
- 新增能力优先放入独立的服务、配置与前端模块；既有入口只保留必要的单行触发与极窄校验。
- 每处既有入口改动都必须说明必要性、最小接线点和未来接取上游时的冲突影响；无法说明时不得修改。
- 详细实现事实见[用户生命周期邮件通知架构](../20-architecture/运维-用户生命周期邮件通知架构.md)。

## 11. 产品验收标准

### 11.1 代码已完成（可观察）

- Operations → Monitoring & Alerts 出现三个事件开关，默认全部关闭。
- 切换开关后配置持久化，刷新或重载后值保留。
- 注册、管理员建号不填邮箱时被拒绝；填邮箱后进入正常流程。
- 事件触发点与第 4 节一致：注册自动 Token 不发密钥信，非密码资料更新不发密码信，忘记密码重置不重复发信。
- 邮件模板按用户语言存在简体、繁体、英文版本。

### 11.2 真实 SMTP 验证（待完成）

- 配置真实 SMTP 并开启某事件开关后，对应事件投递一封正确语言的事务性邮件。
- 开关关闭时对应事件不投递；SMTP 未配置或用户无邮箱时不投递且只记日志。
- 发送失败只记日志，不重发，且对应主业务请求结果不受影响。
- 一次成功注册只收到账户创建邮件，不收到密钥创建邮件。

### 11.3 生产发布（待完成）

- 在灰度环境验证注册与管理员建号的邮箱必填行为，以及 OAuth/微信和存量无邮箱用户的既定边界。
- 未完成真实 SMTP 投递与灰度验收前，该能力不得标记为生产可用。

## 12. 产品成功指标

- 管理员未开启开关前，因本能力意外发出的邮件数为 `0`。
- 开关关闭时对应事件投递率为 `0`；开关开启且用户有邮箱时投递成功。
- 因邮件发送失败导致主业务请求被阻断或回滚的次数为 `0`。
- 一次成功注册触发的邮件数为 `1`（仅账户创建），不出现注册即两封。
- 普通资料更新触发密码修改邮件的次数为 `0`。
