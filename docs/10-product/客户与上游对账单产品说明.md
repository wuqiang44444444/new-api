# 客户与上游对账单产品说明

## 1. 文档定位

本文定义客户账单和上游对账的产品行为。两个管理 Tab、自助月账单、明细下钻、渠道月度折扣与审计、
请求级计费快照已实现；期初/期末余额勾稽、不可变余额流水与统一 PriceBook 版本快照是未实现的目标
能力（见第 7 节与[客户与上游对账架构](../20-architecture/账单计费-客户与上游对账架构.md) §2）。
真实 MySQL/PostgreSQL/ClickHouse 用量与月末边界验证未完成前，不宣称生产验收通过。

当前平台已经具有 Request ID、用量日志、结算日志和账单明细入口。本产品不建立第二套 Request ID
或在账单主页复制请求明细，而是在现有事实之上提供月度汇总、模型聚合和带筛选条件的明细链接。

普通用户从“我的账单”入口查看自己的账单；平台管理员从独立的“账单对账”入口进入，并通过
“客户账单”和“上游对账”两个一级 Tab 切换。管理员也可以从“我的账单”查看自己的用户账单。
两个管理 Tab 使用独立口径：客户账单回答“客户用了多少、应付多少”；上游对账在一个入口完成
“选择月份 → 找到上游 URL → 检查渠道折扣 → 查看汇总 → 查找或导出调用明细”，按渠道当前基础
URL 把渠道用量合并为管理统计视角，并提供渠道月度折扣维护与双方请求 ID 证据，不构成结算凭据。
平台没有供应商账单接口时，不录入、模拟或比较供应商侧 Token、次数和金额。

## 2. 产品目标

1. 用户打开账单后先看到金额汇总，不需要先浏览请求明细。平台管理员进入“客户账单”时，先看到整个账期的全客户汇总和客户账单列表，再选择客户下钻。
2. 平台管理员从客户账单列表下钻某个用户后，可以在“渠道”和“API Key”两个维度间切换；每个维度下展示模型
   汇总，不能展示一条条请求记录。
3. 模型汇总支持按 Token、按次和按时长收费，并明确展示计费方式、用量、结算原价、优惠和净结算金额。
4. 上游对账只展示平台数据库已有用量：按 Token 收费的模型展示各类 Token，按次收费的模型展示
   平台记录的计费次数；不创建未知的供应商侧数值。
5. 每个渠道可以按月设置一个综合上游折扣系数；新月份复制上一个自然月的渠道配置，上月没有值时
   使用默认系数 `1`。
6. 历史账单使用请求发生时的价格和折扣快照，不因当前价格、用户折扣或上游折扣变化而改变。
7. 页面上的汇总、筛选、折扣、平台侧上游用量、余额和审计结果全部以数据库持久化事实为准。

## 3. 角色与权限

系统只有两个账单角色：

| 角色 | 可见范围 | 允许操作 |
| --- | --- | --- |
| 用户 | 自己的金额汇总、API Key → 客户模型汇总、余额流水和明细链接 | 查询、筛选、下钻和导出自己的账单 |
| 平台管理员 | “客户账单”Tab 中全客户账期列表及任一用户的两种客户汇总；“上游对账”Tab 中按渠道当前基础 URL 归组的全部渠道用量、渠道月度折扣和逐笔证据 | 查询、录入和初始化渠道月度折扣、导出上游汇总和发起余额调整 |

“我的账单”和“账单对账”必须使用独立路由和独立侧栏入口。`/billing` 对所有已登录用户开放，且始终
只查询当前登录用户；`/admin/billing` 仅平台管理员可进入，非管理员必须被前端路由和后端接口同时
拒绝。普通用户页面不得渲染客户数量、客户搜索、客户列表或上游对账控件。

渠道维度和上游对账只对平台管理员开放。用户不看到 Provider 账号、真实 Provider 模型、Provider
成本、内部实现或其他管理员审计字段。API Key 只显示名称和稳定 ID，不显示密钥值。

## 4. 数据权威与展示边界

- 主数据库保存用户、API Key、渠道、余额流水、上游折扣和人工审计事实。
- 日志数据库保存现有 Request ID、请求用量、计费结果、渠道和模型等请求级事实。
- 客户汇总和平台侧上游用量只能由后端查询数据库产生；前端不得把已加载的部分明细自行汇总为
  正式账单，也不得用浏览器状态补齐缺失数据。
- 平台侧上游 Token 和计费次数只从日志数据库读取；上游折扣必须先成功保存到主数据库。不得增加
  供应商账单录入表单、供应商用量字段、双方差异字段或对账处理状态来补充平台并不知道的事实。
- Redis、进程缓存、React Query 缓存和页面状态只用于性能或交互，均可重建，不能成为账单权威。
- 缓存与数据库不一致时，以数据库为准；账单接口必须返回数据生成时间和数据库事实版本或账期版本。
- 数据库缺少某项历史用量、价格或折扣时必须显示“未知”或“不可用”，不得从当前配置、页面合计、
  Provider 金额或缓存值反向推断。
- 页面导出必须由后端按相同数据库查询口径生成，或使用后端返回的完整汇总结果；不能导出仅存在于
  前端的未持久化数据。

## 5. 统一计费口径

### 5.1 计费方式

每个模型汇总必须明确标记一种计费方式，不能只展示金额而隐藏计费单位。

| 计费方式 | 主要用量 | 金额计算 |
| --- | --- | --- |
| 按 Token 收费 | 输入 Token、缓存读取 Token、缓存写入 Token、输出 Token | 各类 Token × 各自成交单价后求和 |
| 按次收费 | 总请求次数、计费次数、免费或退款次数 | 计费次数 × 单次成交价 |
| 按时长收费 | 请求数；未保存完整计量时不显示累计秒数 | 按历史时长表达式结算的消费减退款 |

同一模型在同一账期存在多种计费方式时，必须拆成独立汇总行，不得把 Token 和次数相加成一个“总量”。
不同模型的 Token 单价、按次价格或计费语义不同，父级渠道和 API Key 只汇总金额与请求数；具体用量
在展开后的模型行查看。

### 5.2 金额精度

- Token、请求次数和计费次数保存原始整数。
- 金额以实际结算的整数 quota 为事实源，账单不重新计价或把逐笔金额舍入到分后相加。
- 客户账单页面和 CSV 按当前展示币种使用同一格式，最多保留 8 位小数，超出显示精度时按普通
  舍入显示；不能把微小非零金额抬高到某个最小收费值。客户账单 CSV 突出币种金额，管理员使用记录 CSV 另保留原始 `net_quota` 精度核验信息。
- 页面格式化不改变账务事实；原价和优惠的估算边界见“自助账单下载与金额解释”。

### 5.3 价格与折扣快照

- 请求结算时在日志 `other.admin_info.statement_snapshot` 冻结当时的计费方式、Provider 模型、单价、
  倍率、冻结表达式与计量单位（`usage_units`）；快照位于 `admin_info` 下，普通用户不可见。
- 按 Token 收费时，输入、缓存读取、缓存写入和输出分别保存单价快照；按次收费时保存单次价格快照。
- 月度账单直接汇总已经结算的历史金额，不使用当前价格或当前用户折扣重新计算。
- 统一的“人民币/百万 Token” PriceBook 版本快照与不可变余额流水尚未实现；当前按逐行冻结快照
  解释历史。没有合同记录时仅用当时分组倍率估算；有合同优惠则叠乘合同倍率。缺少分组倍率、
  合同信息残缺或冲突时才保留未知，不从当前配置回算。

用户折扣统一使用系数表达：`1` 表示无折扣，`0.8` 表示按原价的 80% 成交。
使用日志中，普通记录没有合同字段或明确未适用合同时显示“无合同”，合同因子按 `1` 展示最终折扣。
最终折扣为当次有效分组倍率（用户专属优先）乘以合同因子；例如分组倍率 `1` 且无合同时显示 `×1`，
分组倍率 `0.8` 且无合同时显示 `×0.8`。桌面、移动端与日志详情共用该判定；该显示规则不改写历史金额。
客户账单中，没有合同记录的合同列显示“未记录”，按合同因子 `1` 计算最终折扣、估算原价和优惠；
含不完整、冲突合同事实的记录仍保留未知。既有固化版本不重写，不能从历史版本缺少原因推断无合同。

## 6. 客户账单 Tab

### 6.1 页面结构

平台管理员在独立“账单对账”页的“客户账单”Tab 按管理员的实际核对顺序分为三层：

1. 当月全客户账单总览和客户账单列表；
2. 点击客户后的单客户账期金额总览，以及按渠道或 API Key 分组的汇总；
3. 展开渠道或 API Key 后的模型用量和金额汇总。

普通用户不经过全客户列表，直接进入自己的账期金额总览与 API Key 汇总。

请求明细不出现在该 Tab。页面只提供“查看明细”链接，跳转到平台现有用量日志或独立明细页，并
自动携带当前用户、账期、渠道、API Key、模型和计费方式等筛选条件。

该 Tab 不提供 Request ID 列表，也不重新设计请求详情。用户发生争议时，通过现有 Request ID 在明细
入口定位原始请求和结算记录。

### 6.2 全客户账单列表

平台管理员进入“客户账单”Tab 时，默认展示当前自然月全部已有账务事实的客户，不要求先选择一个客户。首屏总览至少包含客户数、请求数、结算原价、优惠和净结算金额。

每个客户行至少展示：

- 客户名称、用户名和稳定用户 ID；
- 请求数、结算原价、优惠、净结算金额、累计扣减和累计退回；
- 数据质量与最近账务活动时间；
- “查看账单”下钻入口。

用户记录被物理删除但仍存在客户结算日志时，列表与详情仍可按稳定用户 ID 查看：身份显示删除标记，
当前余额显示不可用（`null`），不显示为零；没有用户记录且没有客户结算历史时仍返回未找到，
渠道测试日志不构成客户结算历史。

列表支持按客户名称、用户名或 ID 搜索，按数据质量过滤，按金额、请求数或客户排序，并做服务端分页。总览始终是当前全部筛选结果的数据库汇总，不得由当前页行相加。

### 6.3 单客户账期金额总览

单客户详情当前展示：

- 结算原价（扣除退回对应原价后的折前净金额）、优惠、净结算金额相邻排列；
- 累计扣减（包含任务预扣与后续补扣的期间流水）与累计退回（包含结算退差额与其他退款）；
- 两条对照等式说明：`结算原价 − 优惠 = 净结算金额`、`累计扣减 − 累计退回 = 净结算金额`；
- 账期、币种、结算时区和数据更新时间。

期初余额、本期充值、人工调整与期末余额勾稽属于未实现的余额流水目标（见第 7 节）；
未落地前页面不展示虚构勾稽，也不得用估算值填平。

部分数据行在数据质量徽标下显示计费方式未识别等具体原因的记录数量；该标记不表示金额缺失，
未知价格仍显示未知。客户账单排除渠道测试写入的记录（见 6.6），真实游乐场调用保留。

### 6.4 平台管理员的两种汇总维度

平台管理员从账单列表点击某个客户下钻后，可以切换：

```text
渠道 → 客户模型汇总
API Key → 客户模型汇总
```

渠道或 API Key 父级行只展示：请求数、结算原价、优惠、净结算金额、累计扣减和累计退回。展开父级后，
每一行代表一个模型在该账期内的聚合结果，不代表单个请求。

用户自己的账单只提供：

```text
API Key → 客户模型汇总
```

用户不能通过账单推断内部渠道或 Provider 信息。

### 6.5 模型汇总字段

所有模型行共同展示：

- 客户模型；
- 计费方式（按 Token / 按次 / 按时长 / 暂未识别）；
- 请求数；
- 结算原价；
- 用户折扣；
- 优惠；
- 净结算金额、累计扣减和累计退回；
- “查看明细”链接。

计费方式暂未识别的历史记录按后端质量计数如实展示，不伪造按次用量，原始扣减与退回继续计入金额；
历史退款仅在能唯一确认原任务及其冻结计费方式时归入对应行，不能用模型当前价格猜测。
同一模型存在多种真实计费方式时仍分行展示，不在前端强行合并。折前金额与优惠按每笔各自冻结的
分组与合同倍率还原，使用定点十进制汇总；净额与折前净额保留符号，退款不隐藏为负。

按 Token 收费的模型额外展示：

- 输入 Token 总量；
- 缓存读取 Token 总量；
- 缓存写入 Token 总量；
- 输出 Token 总量；
- 对应的单位价格或“账期内多价格版本”标记。

按次收费的模型额外展示：

- 总请求次数；
- 计费次数；
- 未计费或已退款次数；
- 单次价格或“账期内多价格版本”标记。

同一账期只有一个折扣版本时展示该折扣系数；存在多个价格或折扣版本时显示“多版本”，并展示：

```text
账期有效折扣 = 净结算金额 / 结算原价
优惠 = 结算原价 - 净结算金额
```

结算原价为零时不计算有效折扣，显示“不适用”。

### 6.6 查询与筛选

客户账单统一排除原生渠道测试写入的记录（消费类型、`token_id=0`、`token_name=模型测试`、
`content=模型测试`）：这些请求只有计算费用，没有客户资金扣款；不能仅按 `token_id=0` 排除，
真实游乐场、免费调用、退款与已删除 API Key 的历史记录全部保留。上游对账继续保留实际发生的
测试调用；原始日志与余额不因此回写。

- 用户账单：账期、API Key、客户模型、计费方式；
- 管理员客户账单列表：账期、客户搜索、数据质量、排序和分页；
- 管理员单客户下钻：账期、渠道/API Key 汇总维度、客户模型和计费方式；
- 默认进入当前自然月，并支持选择历史自然月；
- 切换渠道/API Key 维度或筛选条件时，顶部金额必须与当前可见汇总一致。

### 自助账单下载与金额解释

“我的账单”与管理员客户账单在“导出记录”旁提供一个“导出并下载”入口，点击后须二次确认，可选择
账单汇总或账单明细，选择器直接解释两种用途。

- 汇总（`statement-summary.csv`）：每个 API Key × 客户模型 × 计费方式一行，前置请求数、币种、
  净额、估算原价、估算优惠、扣款和退款金额，随后为用量、质量提示及账期。折叠模型全部导出；
  不混入总计、API Key 小计或优惠组合，避免金额重复累计。未知估算为空并附原因，不能把已知部分当完整估算。
- 调用明细（`statement-details.csv`，大文件按事件边界分片）：逐笔列出入账时间、请求 ID、
  API Key、模型、扣款/退款、金额和优惠，其后为用量、分组倍率、合同状态/倍率、最终倍率和单价说明。
  同一调用可能有多笔入账事件；退款保留负净额和零新增请求数，按记录中的请求 ID 核对，不伪造历史关联。
  多个计费分项合并在单个单元格，保留数量、单位、USD 单价基数及小计，不重复入账金额。

文件使用 UTF-8 BOM 和中英文表头，可供表格软件打开。数据加载、刷新或请求失败时禁用导出；
空月份返回无记录提示，文件不包含渠道、Provider、凭据或调用正文。新生成的固化账单共用上述格式，
已有固化文件不重写。管理员使用记录导出保留技术字段格式。
相同申请仍在排队或生成时返回原任务；已完成文件在来源修订可验证、数据及导出条件未变化且文件未过期时
直接复用，不新增导出记录。单文件直接下载，多分片从导出记录选择；文件过期后可重新生成。当前自动复用
适用于主库与日志库同库且正常维护来源修订的部署，分库部署不自动复用已完成文件。已固化账单始终下载当前
查看版本的文件，不创建实时导出任务。

原价和优惠按已舍入扣款与历史倍率反推，只能作为估算值，页面与下载统一标为“估算原价”“估算优惠”。
API Key 汇总和展开后的模型行在同一“估算优惠”列均显示金额，不混用折扣倍率；已知优惠为零时
显示零，历史信息不足时说明原因。倍率等于 1 时不重复显示两个 ×1。
净额包括期间任务预扣及结算调整，不能理解成所有在途任务都已最终结清。输入 Token 为总输入，缓存
是其中子项；历史记录可由当时保存的完整计费与转换证据恢复总输入，缓存不重复相加；确实无法
确认输入语义时显示未知，金额继续保留。人工退款可以从明确且唯一的原预扣引用恢复分类、分组和
合同优惠事实，不因该 API Key 历史退款数量多而放弃核验。恢复覆盖账单、明细和新导出，已确认
版本与已有固化文件不改写。日志完整性与保留由管理员负责。

## 7. 余额流水（未实现目标）

本节是未实现的阶段目标；当前余额直读主数据库，不提供流水勾稽。落地前不得宣称账单支持期初/期末
余额复算。目标合同：

余额只能由流水累计得到，禁止后台直接覆盖余额。流水至少包含：

| 类型 | 方向 | 关联事实 |
| --- | --- | --- |
| 充值 | 增加余额 | 充值单号 |
| 消费 | 减少余额 | 现有 Request ID 或结算记录 |
| 退款 | 增加余额 | 原 Request ID 和退款原因 |
| 人工调整 | 增加或减少余额 | 唯一调整单号、原因、平台管理员和操作时间 |

已入账流水不可编辑或删除。纠错必须追加冲正或调整流水，并关联原流水。用户可以查看自己的流水；
只有平台管理员可以发起人工调整，且缺少调整单号或原因时不能提交。

## 8. 上游对账 Tab

### 8.1 页面结构

平台管理员账单管理页的“上游对账”Tab 是统一入口，主结构固定为：

```text
账期月份 → 上游 URL → 上游模型 × 计费方式 → 渠道贡献；渠道折扣编辑区与该层级并列
```

页面按“选择月份 → 查看或搜索上游 URL → 集中查看和编辑渠道当月折扣（优先展示待填写项）→
查看模型汇总并展开渠道贡献 → 进入调用明细 → 导出”的顺序组织。该 Tab 的汇总不展示逐请求记录；
每个模型行和渠道贡献行提供“查看明细”入口，进入跨客户逐笔证据视图，可按我们的请求 ID 和上游
请求 ID 搜索。旧“按上游 URL 汇总”独立 Tab 已并入本视图。

### 8.2 平台用量口径

按 Token 收费的 Provider 模型展示平台日志已保存的输入、缓存读取、缓存写入和输出 Token；按次收费
的模型展示平台记录的请求数和计费次数。缺失字段显示未知，Token 与次数不能互相换算，也不能跨
计费方式相加。

客户退款日志表示平台对客户的资金调整，不表示供应商已经退款，因此不得从普通客户退款日志生成
上游退款次数或冲减平台记录的 Provider 用量。能确认属于 Task 结算调整的退款行（Task ID 与明确
adjustment 事件，或旧日志同时具备实扣与预扣字段）可能承载完成用量：其用量按实测正计、不增加
请求次数；明确 refund/create 事件不作为退款行上的完成用量。
原生渠道测试历史记录缺少缓存写入总量及 TTL 字段时，缓存写入栏显示“未记录”并计入质量计数；
显式记录为 0 不属于缺失。用量覆盖全部已记录上游调用（含渠道测试）；原价金额只覆盖有客户结算的
记录，测试行保留用量、单独计数且不进入金额，两个覆盖范围有意不同，不能从测试用量缺少对应金额
推断上游免费。

### 8.3 金额展示边界

上游对账允许在“本地与上游采用相同官方原价”的业务前提下，依据已记录的本地计费金额及冻结
或有历史证据的计价、折扣事实，沿用本地账单原价投影，结合渠道当月综合折扣计算折后参考金额。
原价由历史金额还原时继续标为估算；缺少依据时保留未知。参考金额不代表独立采集的 Provider
成本、供应商账单金额或最终应付金额，不证明覆盖所有上游扣费。不通过当前价格回算、手填供应商
金额或无依据反推补造历史成本，不生成双方金额差异或自动调整客户资金。

### 8.4 渠道月度折扣

上游折扣的业务键为：

```text
账期 + 上游渠道
```

一个渠道当月所有 Provider 模型和计费方式共用一个综合系数，不按模型维护不同折扣。规则：

- 折扣由平台管理员以百分比形式输入（如输入 80 表示系数 0.8）；未配置时默认系数为 `1`（无折扣）；
  只有历史冲突或来源无法确认时保持待确认。合法范围为 `0 < 系数 <= 1`。
- 月度初始化是显式、幂等的写入操作：当月无记录的渠道复制上一个自然月同渠道的有效配置，并标明
  来源月份；上月没有有效值时使用默认系数 1，不向更早月份静默追溯。初始化不覆盖人工值、迁移值或已
  更正的继承值。
- 复制后形成当前月份自己的版本，修改当前月不会影响上月或已生成的其他月份。
- 每次修改必须填写原因并校验记录版本；并发修改冲突提示重新读取，不静默覆盖。修改前后值、
  平台管理员、原因和时间写入追加式审计。
- 编辑入口位于上游对账页的渠道折扣编辑区，不改变渠道调用行为。

该折扣是平台内部月度配置，不修改客户成交价，也不得据此生成供应商账单金额。旧模型级月度折扣在
系统升级时按历史审计证据一次性收敛为渠道记录；无法证明统一口径、存在冲突或来源不明的
渠道月份保持待填写，由管理员人工补填。

### 8.5 明确不做的能力

- 不提供供应商账单录入、导入或编辑接口；
- 不保存供应商 Token、次数、退款或实际金额；
- 不计算平台与供应商的差异和差异率；
- 不提供基于未知供应商事实的处理状态或关闭流程。

### 8.6 URL 归组与导出

上游对账按渠道当前配置的基础 URL 归组聚合平台用量：

- 页面和 CSV 明确标注“按渠道当前基础 URL 归组”及上海时区账期起止时刻，表示当前渠道归组下的
  历史用量，不表示请求发生时已确认的供应商归属。渠道 URL 修改后，历史账期的归组可能随之变化，
  日志中的历史用量和金额不因此改变；已导出文件保留当次内容。
- 域名大小写、默认端口和末尾斜线视为等价；协议、非默认端口和基础路径不同则分别归组。基础
  地址缺失、不可解析或含敏感内容的渠道单独保留，不合并为统一“未知供应商”。
- 该视图是管理统计视角，不是供应商结算凭据：相同 URL 不证明账号、合同、价格或折扣相同。
  供应商应付金额所需的独立成本事实仍属未实现目标。
- 同一上游模型按计费方式分行，模型数按模型身份去重；数据质量标记逐层保留，未知不显示为零。
- 汇总导出为完整筛选结果的 CSV，逐行记录当次使用的渠道折扣值和版本；后续修改折扣不改写已
  生成文件。逐笔证据支持按双方请求 ID 查询；缺失 ID 显示“未记录”，不按时间或金额推断匹配，
  且资金持款、结算调整与普通调用以行类型区分，不把每条资金日志显示为新的上游调用。
- 完整明细支持后台异步导出，包含当前筛选下全部客户的匹配记录，不限当前页；可在“导出记录”
  查看进度、取消和下载。文件固定当次渠道范围、折扣版本与金额单位；重新生成保留这些条件。
  下载时再次检查当前管理员权限，含上游任务 ID 的文件仅 Root 可取得。
- 普通“我的账单”不提供本 Tab；供应商基础地址与归组信息仅平台管理员可见。

## 9. 客户收费规则

| 场景 | 按 Token 收费 | 按次收费 |
| --- | --- | --- |
| 成功交付 | 按实际可计费 Token 结算 | 计一次 |
| 平台或上游异常且未交付 | 不收费或全额退款 | 不计次或全额退款 |
| 流式输出被用户中断 | 仅按可信且可计量的已交付 Token 结算；无法确认时不收费 | 按产品合同明确是否已形成一次有效交付 |
| 系统自动重试 | 一个逻辑 Request ID 只结算一次客户 Token | 一个逻辑 Request ID 最多计一次 |
| 余额不足 | 发送 Provider 前拒绝，不允许透支 | 发送 Provider 前拒绝，不允许透支 |

系统重试产生的多次 Provider 用量或计费次数必须分别进入上游对账，但不能导致客户重复收费。
本期能力边界：上游对账展示已持久化的 Provider 用量证据（消费行与可确认的 Task 结算调整行）；
未交付不收费、流中断计量差异与未持久化的尝试级用量属于可能的双边口径差异，由运维线下核实，
不把“一次客户结算”宣称为“上游只调用一次”。

## 10. 账期、数据质量与审计

- 默认结算时区为北京时间 `Asia/Shanghai`（UTC+8），页面、导出和明细链接使用同一账期边界。
- 月账期按该时区自然月计算；跨期退款进入实际退款发生的账期并关联原请求。
- 价格、用户折扣和上游折扣均按生效时间版本化。
- 用户只能读取自己的账单；平台管理员的用户选择、折扣修改和余额调整必须经过权限校验。
- 平台或上游用量缺失时显示“未知”或“上游未提供”，不按当前配置补算，不用金额反推用量。
- 页面查询、筛选或明细链接失败不能修改消费、余额、折扣或对账状态。
- 所有人工调整和上游折扣修改均记录平台管理员、时间、原因和业务单号。

## 11. 交付约束

- 复用 NEWAPI 现有鉴权、用户、API Key、渠道、Request ID、消费日志、退款日志和计费结果，不建立
  平行请求体系或重写原生计费语义。
- 新增账单能力优先放入独立的后端查询、对账服务、数据模型和前端功能模块。
- 原生 Router 和数据库迁移入口只保留必要的注册调用；原生请求、Relay、Provider adapter 和计费
  热路径只允许必要的单行快照调用或极窄分支。
- 不为消除新增模块内的少量局部重复而重构、移动或格式化 NEWAPI 原生文件。
- 每个原生文件修改都必须说明必要性、最小接线点和未来接取上游时的冲突影响；无法说明时不得修改。

## 12. 产品验收标准

### 12.1 客户账单 Tab

- 首屏先展示金额总览，页面上没有逐请求记录表。
- 管理员可以在“渠道 → 模型”和“API Key → 模型”之间切换；两种维度的账期总金额一致。
- 父级展开后每行都是模型聚合结果，模型金额之和等于父级金额。
- 按 Token 模型展示输入、缓存读取/写入和输出 Token 总量；按次模型展示计费次数。
- 每个模型行只有明细链接，链接能正确带入当前筛选条件并使用平台现有 Request ID 定位请求。
- 修改当前价格或用户折扣后，历史账期的原价、折扣和实付金额不变化。
- 刷新页面、切换设备或清空缓存后，账单结果不变化；数据库缺失的数据不会由前端补算。

### 12.2 上游对账 Tab

- 页面按「上游 URL → 上游模型 × 计费方式 → 渠道贡献」展开，不显示逐请求列表；渠道折扣编辑区
  与汇总并列，优先展示待填写渠道。
- 按 Token 模型展示平台记录的各类 Token；按次模型展示平台记录的计费次数。
- 页面不出现供应商侧 Token、次数、退款、差异或录入操作；原价与折后参考金额明确标注为本地口径
  参考值，折扣待填写或原价未知的父级金额显示不完整，不把部分已知金额冒充完整总额。
- 新月份折扣经显式初始化只复制上一个自然月的有效渠道配置；上月没有值时使用默认系数 1，修改后不
  影响上月；重复初始化不覆盖人工值；默认 1 与历史待确认状态在界面明确区分。
- 旧模型级折扣迁移后，冲突与证据不足的渠道月份保持待填写，不静默选值或平均。
- 系统重试只有在平台留下独立 Provider 用量事实时才进入汇总；客户仍只发生一次有效结算。
- 上游折扣保存成功后重新加载结果一致，且不会生成供应商账单事实。
- 同一筛选下 URL 组的用量合计等于所属渠道贡献合计，模型汇总等于对应渠道模型行之和；页面与
  CSV 均标注“按渠道当前基础 URL 归组”、上海时区账期起止，CSV 逐行记录当次折扣值和版本，且
  不出现供应商金额或应付金额。
- 逐笔证据展示双方请求 ID 与平台/上游任务 ID（上游任务 ID 仅根管理员可见），缺失显示“未记录”；
  渠道测试行保留并标记，不进入原价金额。

### 12.3 余额、权限和一致性

- 余额可以由充值、消费、退款和调整流水逐笔复算，平台管理员不能直接覆盖余额。
- 用户只能访问自己的账单和明细链接；渠道、Provider 模型和平台记录的上游用量只对平台管理员开放。
- 按次、按 Token 两种模型不会被合并为同一用量总数。
- 月初边界请求按 `Asia/Shanghai` 唯一归属一个账期。
- 未完成真实数据库用量、权限、金额精度和账期边界验证前，该能力不得标记为生产可用。
- 平台管理员页面固定提供“客户账单”和“上游对账”两个一级 Tab，两个 Tab 的金额和用量口径互不
  覆盖；旧 `upstream_url` 地址进入统一上游视图。

## 13. 产品成功指标

- 客户账单主页逐请求记录数为 `0`，所有明细访问均通过带筛选条件的链接完成；
- 两种管理员汇总维度的客户账期金额一致率为 `100%`；
- 数据库已记录上游用量的模型中，Token 或计费次数可完整汇总的比例达到 `100%`；
- 历史账单因当前价格或折扣变化而改变的次数为 `0`；
- 因重试、回调或退款导致的重复客户收费次数为 `0`。

## 14. 客户月账单确认与更正（默认关闭）

经核验来源完整的已结束自然月，可由管理员生成待确认草稿。页面在排队、生成期间每 5 秒刷新，
终态停止刷新；管理员查看冻结预览、质量提示与基础文件后确认，客户才看到正式版本。
来源已清理、证据变化、完整性不足或维护中不能继续确认；质量提示的知悉不能绕过来源完整性检查。

已确认金额、用量、折扣与换算参数从该版本读取，当前价格或合同变化不改写历史。更正生成新草稿，
同时展示金额、用量、数据质量与折扣组合的前后依据；净额相同也展示非金额变化，未知保持未知。
确认时保留更正原因和被更正版本，历史版继续可查。当前余额独立展示，不纳入历史快照。

当前版和历史版提供确认说明下载。说明文件暂时不可用时可重试，系统从冻结确认事实恢复，不撤销账单。
失效、失败或取消草稿可清理；存储故障时保留“清理中”状态并允许重试。关闭生成开关仍可清理历史草稿，
执行记录过期不等于正式版本或待清理对象丢失。

本能力已具备本地实现与回归验证，开关默认关闭；真实数据库、对象存储、多实例和备份恢复未完成验收。
[实施方案](../99-archive/2026/09/2026-09-17-客户月账单确认与版本固化方案.md)记录具体支持范围，不作为生产已启用声明。


### 来源核验与待确认版本生成

管理员在账单版本区打开“核验与差异”，查看本客户、本自然月的完整检查范围、时间、待处理数及阻断数。
普通管理员可读，超级管理员可逐项登记结论；关闭正式生成开关不隐藏管理员核验入口。清单分页展示模型、时间、消费/退款金额和缺证原因，内部编号与精确额度放入折叠详情；
任务比较项可展开关联日志的时间、类型、金额及身份匹配结果。比较只纳入显式关联，不代表应收费用。

管理员选择“保留现有记录，不新增退款”时备注选填，原始未知状态仍保留。
“金额有疑问，待复核”“申请减免费用”“申请排除重复记录”“申请更正账期”均登记为待处理，
保存前显示本次账单调整与余额变化为零，不代表退款、减免或排除已执行。任务金额差异不能点击通过。
金额差异需经既有受控补正或证据修复后重新检查，本页面不扣费、退款或直接修改历史金额。
