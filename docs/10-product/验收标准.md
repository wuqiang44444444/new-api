# 验收标准

目标产品只有同时满足客户行为、资金安全、素材隔离、敏感信息和真实 Provider 验证，才能视为可发布。
“代码存在”或单一成功样本不等于生产验收通过。

## 1. 模型、渠道和管理员体验

- 所有 Seedance 线路使用管理端可识别的“Seedance 专用渠道”，不隐藏在 `DoubaoVideo` 或 Link 方案中。
- 不同 Seedance 渠道使用不同客户模型名；一个已启用客户模型只对应一个 Seedance 渠道。
- 新建启用、编辑已启用渠道模型和重新启用时发现重名，系统使用普通人能理解的提示拒绝操作。
- 停用渠道可保留重名；请求时不重复运行重名检查，也不建立启动扫描、数据库唯一约束或自动修复。
- Seedance 的 Priority/Weight 显示为无效，并明确提示请求不会自动切换渠道。
- 管理员只选择代码中已有的上游协议，不需要填写请求/响应 JSON 映射或状态脚本。
- 新模型完全兼容已有协议时，技术人员确认后可由管理员配置上线；不兼容时先开发 adapter。

## 2. 原生与 Seedance 客户入口

- NEWAPI 原生 Chat、Responses、Images、`/v1/video/generations` 等入口保持上游原生行为。
- `ChannelTypeSeedanceLink` 只通过 ModelArk V3 create/get/list/delete 四组接口服务客户。
- `/api/v3` 不选择普通 `DoubaoVideo`；`/v1/video/generations` 不选择 Seedance 专用渠道。
- 北向校验标准 ModelArk V3 结构、必填字段、媒体类型和计费安全上界。
- adapter 不支持的字段返回明确错误，不静默删除、钳制、降级或改义。
- Provider 模型、渠道 ID、上游协议、Key 和私有响应不进入普通客户响应。

## 3. Seedance 确定性执行

- 客户模型直接确定唯一 Channel，不使用 Priority、Weight、Affinity、随机分发或候选交集。
- 每个视频创建只发送一次 Provider POST；失败或结果不明时不换渠道、不 fallback、不自动重发。
- Provider POST 前已有 durable create attempt 和资金 hold；没有可信 task ID 时不创建正式 Task。
- 创建结果 unknown 时不自动退款，并保留客户资金和 Provider exposure 的可审计事实。
- 单次无效轮询响应不直接产生业务失败或退款；可信终态只结算一次。
- Task 查询和删除使用创建时冻结 Channel、adapter、连接、素材和计费事实。
- 数量、时长、分辨率和其它计费乘数有明确上界，异常输入不会产生负费用或重复退款。

## 4. Asset 与 AssetGroup

- `/v1/assets` 返回 `ast_*`，`/v1/asset-groups` 返回 `astgrp_*`；普通客户不能提交或看到裸 Provider ID。
- 每个 Asset/AssetGroup 一对一固定到 `user_id + app_id`、Channel、Provider 账号及协议需要的
  Region/Project。
- 平台不保存媒体二进制；source URL 在取得可信 Provider ID 或创建失败后立即删除。
- 同账号正常轮换 Key/AK/SK 不使既有素材失效；改变账号、Region、Project 或素材协议必须新建渠道。
- 国内与海外资源互不复用、自动迁移或自动同步。
- 控制台既有 Provider 素材只有经管理员显式导入并分配租户后才能产生平台资源。
- `asset://ast_*` 可与 HTTP/Data URL 混用，但所有平台素材必须匹配请求模型的固定渠道和相同账号作用域。
- 渠道不一致返回 `asset_channel_mismatch`；账号/Region/Project 不一致返回 `asset_scope_conflict`。
- moderation 保持 Provider 语义；不支持时明确失败，active 不被宣传为平台已完成全面法律审核。

## 5. 真人认证代理

- 客户通过 `POST /v1/asset-groups` 创建真人素材组，并直接获得官方或第三方认证链接/二维码。
- 平台不提供 `/v1/real-person-authorizations`，不建设人脸、活体、证件或授权表单。
- 平台不保存人脸媒体、身份证件、活体数据、人脸特征或授权正文。
- Provider callback 只能触发状态刷新；没有可信查询结果时不能直接把 Group 标为 active。
- Provider 支持删除/撤回时调用真实能力；不支持或结果不明确时明确告知，不能宣称已完全删除。
- 平台不承诺收回平台外副本，也不代替客户保存自然人的法律同意证明。

## 6. 素材操作的简化失败语义

- 每个素材/素材组 POST 都表示创建新资源，不提供平台幂等键或自动重复检测。
- 创建未取得可信 Provider ID 时返回失败并记录脱敏技术日志，不建立 `create_unknown`。
- 删除未取得明确成功时返回失败并保留原状态，不建立 `delete_unknown`。
- 后续 GET 明确确认 Provider 不存在后才更新为 deleted。
- 不建设管理员孤儿核查页、自动孤儿扫描、持续后台轮询或自动迁移。

## 7. 图片

- Link 图片使用客户模型、Ability、Channel、`model_mapping` 和代码 converter/protocol。
- 异步图片使用共享 `media-image-task/v1` 生命周期，不为 Provider 建第二套 Task 或计费状态机。
- 无可信 task ID 时不创建异步 Task；不支持字段明确失败。
- Seedance 的单渠道、不切换和 Priority/Weight 规则不会未经图片产品评审自动扩张到图片。

## 8. 账单与数据质量

- `/billing` 和 `GET /api/billing/self` 只返回当前用户，账期边界符合产品约束。
- 账单按 API Key 与客户模型聚合已结算日志，历史账单不按当前价格重算。
- 净费用不会低于零；异步调整不会重复计算请求、退款或额度。
- Provider 实际金额未知时显示未知，不使用客户 quota、当前报价或相近时间任务推断。
- CSV 和页面不包含 Key、prompt、Provider 私有数据或 Task 私有快照。

## 9. 公开文档与生产发布

- 公开 ModelArk V3 operation 与实际方法、路径、鉴权、Content-Type 和 schema 一致。
- OpenAPI 只描述统一请求合同，不发布已删除的 SKU/publication/implementation 机器投影。
- 未验证模型不出现在正式示例中，也不能仅因 Channel 配置存在而标为生产可用。
- SQLite、MySQL 和 PostgreSQL 上的迁移、attempt、Task、计费和素材行为一致。
- 每个准备开放的客户模型完成真实 Provider 成功/失败、unknown、内容、账单、脱敏和回滚验证。
- 回滚只停止新请求；在途 Task 继续使用冻结事实，客户资金与 Provider exposure 继续补偿。

生产验收执行以[全渠道上线验收手册](../40-operations/05-全渠道上线验收手册.md)为准。
