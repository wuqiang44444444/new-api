# 验收标准

## 1. 通用通过条件

- 请求只能访问当前用户、API Key 应用和分组允许的模型/资源；越权与不存在不泄露资源差异。
- 同一公开 SKU 命中不同渠道时，客户路由、DTO、字段值域、状态、错误与计费语义一致。
- 普通响应、日志、指标、trace、CSV 和可分享验收证据不包含密钥、凭据指纹、上游资源/任务 ID、签名/源 URL、Cookie 或完整 Provider 错误。
- 确定性测试通过，且拟发布的每个真实 Provider 实现都完成黑盒证据、账单核对和回滚演练。

## 2. 合同与路由

- 统一图片在 `/v1/images/generations` 保留显式 `0`/`false`，只接受已发布能力和值域；异步成功的结果数与请求 `n` 一致。
- rc23 原生 OpenAI Videos 的创建、Remix、查询、内容下载和旧版平台入口按上游合同可用，且本地
  Link 代码未包装、复制或收紧其 Router、DTO、Relay、Adapter、模型发现与计费；Link SKU 只在
  自身类型化路由和候选实现中验收。
- Seedance、Kling 和即梦分别使用自己的类型化公开合同，不可通过原生视频入口、`metadata` 或 `extra` 绕过白名单。
- Ability 发布、选渠道和发送前均校验公开能力、代码注册的实现 ID/version 与 adapter 版本；未知实现 fail closed。

## 3. 异步任务与资金安全

- 每个可能创建上游任务的 POST 在发送前都有唯一 `TaskCreateAttempt`；即使客户未提供幂等 Key 也不得跳过。
- 预扣、`held + sending`、Task 创建、hold 转移、终态 CAS、结算和退款都可重放且不重复扣费/退款。
- 发送后结果不可确定时返回/记录 `create_outcome_unknown`，不自动换渠道、重发或退款；对账耗尽后的客户资金释放与 Provider 成本风险通过唯一 exposure 审计。
- 所有数量、时长和 Token 上限在校验层受限；额度转换使用统一 checked 饱和函数，异常夹断进入管理员日志。任何路径不产生负额度或负费用。

## 4. 素材与真人授权

- `/v1/assets` 返回稳定 `ast_*`；平台不下载媒体字节，源 URL 只在 `asset-source:<public_id>` 作用域加密的 `AssetSource` 中保存，明文不进入 Task/attempt/日志/响应。
- 一个 Asset 可在当前 Link 实现版本下使用 active binding，或在 TTL 满足时使用 source URL；旧实现版本、凭据指纹不匹配、过期 source 和无多素材渠道交集均 fail closed。
- 未授权或已撤回真人素材不得发送给 Provider；撤回与 reservation 的并发结果线性可解释，内容代理不回源。
- FunCloud v2 只使用 JSON `content` 和 Link `source_url`/请求级媒体；旧 H5、raw upload、multipart、素材列表与专用 attempt 链不存在。`realPersonMode` 未有书面合同前不发布真人能力。

## 5. 账单与数据质量

- `/billing`、`GET /api/billing/self` 和 `/breakdown` 只返回当前登录用户，周期大于 0 且不超过 31 天。
- 账单按 API Key ID 与模型聚合已结算日志；异步调整影响 Token/费用但不重复计请求数，净费用为 `max(消费-退款, 0)`。
- 基础账单与 breakdown 按相同 `token_id + model_name` 合并；breakdown 缺失或 `unavailable_requests > 0` 时明示数据不可用，不把缺失显示为零。
- CSV 继承当前筛选和视图，包含可核对的原始 quota/比例字段，但不含凭据、prompt、Provider 私有字段。
- 账单不声称任意历史余额、`as_of` 快照、会计关账或税务发票能力。

## 6. 兼容、发布与回滚

- 新持久化状态在 SQLite、MySQL >= 5.7.8 和 PostgreSQL >= 9.6 上迁移与回归通过；`relaykit/` 受影响时另外在 `GOWORK=off` 下独立构建。
- 对每个拟发布的合同、SKU、渠道实现和分组执行[05 全渠道上线验收手册](../40-operations/05-全渠道上线验收手册.md)。
- 回滚只停止新流量，保留 Task、attempt、exposure、幂等记录、计费日志和后台轮询，直到在途任务完成对账。
