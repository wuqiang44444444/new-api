# 验收标准

产品只有同时满足客户合同、资金安全、资源授权、敏感信息和真实 Provider 验证，才能视为可发布。
“代码存在”或单一渠道成功不等于生产验收通过。

## 1. 身份、模型与隔离

- API Key 只能访问当前用户、应用和分组允许的模型、Task、资源和账单；越权与不存在不泄露差异。
- 客户模型名在请求、响应、价格、日志和账单中保持一致，不暴露内部 Link SKU 或 Provider 模型。
- 同一 Link 客户模型在渠道禁用、删除、重启和缓存重建后仍代表原产品；没有候选时返回暂不可用。
- 普通渠道保存不能把既有客户模型改绑到另一 Link SKU；显式改绑产生新版本和可查询审计。
- 同一客户模型命中不同候选时，字段、值域、默认值、响应、错误、生命周期和计费语义一致。

## 2. 原生与 Link 合同

- NEWAPI 原生 Chat、Responses、Images、OpenAI Videos 等入口继续符合上游合同，本地 Link 代码未包装、复制或收紧其行为。
- Link 模型只在对应类型化客户合同中出现；不能通过原生入口、metadata、extra 或 Provider 私有参数绕过能力白名单。
- 未登记、实现版本不匹配、能力不完整或无法证明等价的渠道不会接收 Link 请求。
- 没有合格候选时 fail closed，不降级为普通模型、另一 SKU 或未验证 Provider。
- 请求中显式 `0`、`false` 等合法值在转换后仍被保留；不支持字段返回明确 4xx 或能力错误。

## 3. 异步任务与资金安全

- 每个适用的 Provider POST 在发送前都有唯一创建事实和资金 hold；未提供幂等 Key 也不能跳过。
- 没有可信 Provider task ID 时不创建正式 Task；Task 创建与 hold 转移不会出现重复或部分成功。
- 同一幂等 Key、同一请求不会重复调用 Provider；同键不同请求返回冲突。
- 创建结果 unknown 时不自动换渠道、重发或退款，并提供稳定、可对账的客户语义。
- 在途 Task 不因客户模型改绑、渠道编辑、Key 轮换或价格变化而改变 Provider、合同和结算目标。
- 单次无效轮询响应不会直接产生业务失败或退款；可信终态只提交和结算一次。
- 数量、时长、Token 和计费乘数均有上界；饱和或异常输入不会产生负额度、负费用或重复退款。
- 客户资金释放与 Provider 潜在成本分别审计；同一 exposure 不重复记录。

## 4. Link 资源

- `/v1/assets` 返回稳定 `ast_*`，查询和列表不暴露完整 source URL、Provider ID、账号或凭据指纹。
- 平台不下载或保存媒体二进制；source URL 只存在于 Asset 作用域密文。
- `asset://ast_*` 只能由资源所有者和同一应用使用，并且必须与本次客户模型 publication 一致。
- active binding 只有在 implementation、channel、profile 和凭据作用域一致时可用；source 只有在可解密且 TTL 满足时可用。
- 多素材请求只有在存在共同可执行候选时才能发送；无交集、source 过期或 binding 失效时 fail closed。
- 每次 Provider 尝试前都会重新检查状态、授权、实现、凭据和 TTL；Converter 不接受未解析的裸平台引用。
- 换源或迁移生成新 `ast_*`；删除后新引用立即失败，晚到 Provider 结果不能复活资源。
- 请求级 URL/Data URL 不被记录成平台 Asset，也不获得 binding、迁移、授权或撤回承诺。

## 5. 真人授权与撤回

- 未接受当前 API 服务规则、认证未可信成功、作用域不匹配或已撤回的 authorization 不能创建真人 Asset。
- authorization 固定到应用、匿名最终用户、客户模型 publication 和 Provider 账号，不能跨作用域复用。
- Provider callback 不能单独把 authorization 置为成功；平台必须主动查询可信最终结果。
- 撤回先提交时没有新的 Provider POST；任务使用先被接受时，撤回能够索引到对应 attempt 和 Task。
- 撤回后新资源解析和视频/last-frame 内容回源不访问 Provider，并返回稳定撤回错误。
- 取消失败、Provider 继续执行、清理失败和真实任务计费分别可见，不能被表述为“已经完全删除”。
- 普通响应、日志和证据不包含原始最终用户标识、Provider H5 handle、认证长链接或真人素材 source。

## 6. 账单与数据质量

- `/billing`、`GET /api/billing/self` 和 breakdown 只返回当前用户，周期大于 0 且不超过 31 天。
- 账单按 API Key ID 与客户模型聚合已结算日志；异步调整影响 Token/费用但不重复计算请求次数。
- 净费用不会低于零，历史账单不按当前价格重算。
- 基础账单是金额和 Token 权威；breakdown 使用相同维度合并，缺失或不可用时明确提示。
- CSV 继承当前筛选与视图，只包含可核对的脱敏字段，不包含 Key、prompt、Provider 私有数据或内部快照。
- 页面和导出不声称税务发票、会计关账、任意历史余额或 Provider 实际成本能力。

## 7. 公开文档与敏感信息

- 公开 API Reference 中的每个 operation 都在白名单中，并与实际方法、路径、鉴权、Content-Type 和 OpenAPI schema 一致。
- Manifest、Markdown、搜索索引和最终静态文件属于同一内容版本；未登记文件不会进入发布产物。
- 内部 `docs/`、后台 API、渠道配置、Provider 私有字段、Task 私有数据和真实凭据不会进入公开文档。
- 文档页面不执行作者 HTML、脚本或危险链接；示例只使用动态 Base URL 与固定占位 Key。
- 未验证、未发布或已退休能力不出现在新用户导航和正式示例中。

## 8. 兼容与生产发布

- 新持久化与补偿路径在 SQLite、MySQL >= 5.7.8 和 PostgreSQL >= 9.6 上通过迁移和行为回归。
- `relaykit/` 受影响时在 `GOWORK=off` 下独立构建通过。
- 每个拟发布合同、客户模型、渠道实现和分组都完成真实 Provider 成功/失败、幂等、账单、脱敏和回滚验证。
- 回滚只停止新流量，不删除 publication，也不中断在途 Task、attempt、exposure、授权清理和计费补偿。
- 外部验证未完成的能力保持隔离或未发布；验收执行以
  [全渠道上线验收手册](../40-operations/05-全渠道上线验收手册.md)为准。
