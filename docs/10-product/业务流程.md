# 业务流程

## 1. 角色

| 角色 | 核心责任 |
| --- | --- |
| API 用户 | 管理 API Key，调用已授权模型，使用平台任务/素材 ID，查看用量与账单 |
| 应用管理者 | 接受生效的 API 服务规则，维护稳定匿名最终用户标识和真人授权生命周期 |
| 平台管理员 | 配置渠道、实现身份、Ability、分组、价格、凭据、灰度与回滚 |
| 运维/审计人员 | 验收 Provider、核对账单与 exposure，处理不可确定结果、合同违例和敏感信息事件 |

## 2. 普通模型调用

1. 客户使用 API Key 和公开模型发送请求。
2. 网关校验用户、应用、分组、限流、模型能力和可用额度。
3. 分发器从与该公开合同等价的 Ability 中选择渠道，再执行模型映射。
4. Provider adapter 只负责南向请求/响应转换，不改变客户字段、状态或错误语义。
5. 网关记录请求、usage、分组和计费快照，执行结算并返回统一响应。

## 3. 图片与视频异步调用

1. 客户为一次业务操作生成 `Idempotency-Key`，并调用统一图片、原生 OpenAI Videos 或目标 Link 合同。
2. 平台在发送任何上游字节前预生成任务 ID，写入 `TaskCreateAttempt`，完成保守预扣，并在一个事务中进入 `sending + held`。
3. 上游明确成功时，平台创建 Task，冻结合同、渠道、实现、素材与计费快照，并把 hold 转入异步 pending。
4. 上游明确拒绝且能证明未创建任务时，释放预扣；发送后结果不可确定时进入 `unknown`，由补偿器对账，客户不得换 Key 重建。
5. 客户用平台任务 ID 轮询。后台按冻结连接查询，用 CAS 提交终态和一次性结算/退款。
6. 成功后客户通过平台内容端点下载；平台不暴露上游任务 ID 和结果源地址。

## 4. Link 虚拟素材

1. 客户向 `/v1/assets` 提交 Provider 可访问的 HTTPS 源。平台完成用户/App、URL 形状、TTL、类型与幂等校验，保存逻辑 `ast_*` 和作用域加密 `AssetSource`。
2. 如果目标实现需要上游托管素材，平台可异步物化 binding；只支持 URL 的实现直接使用 source。
3. 客户在图片或视频官方媒体字段中使用 `asset://ast_*`。
4. 选渠道前，Resolver 核对所有权、授权、实现版本、凭据作用域、binding 状态、source TTL 和多素材候选交集。
5. 每次 Provider 尝试前再次校验，然后将平台引用改写为该实现可消费的上游引用或源 URL。
6. 删除时先禁止新引用，再异步清理各 binding；更换源创建新 `ast_*`，不原地改变媒体身份。

## 5. 真人素材与撤回

1. 应用先接受当前生效的 API 服务规则，然后为 `app_id + end_user_subject` 创建 `rpa_*` 授权。
2. 平台冻结 Provider 账号、实现和最终用户摘要，通过平台短时跳转链接编排 Provider H5 技术验证，只有主动查询到可信成功才进入 `authorized`。
3. 真人素材创建继承该授权作用域。任务发送前锁定授权并写入 `TaskAssetAuthorization` reservation。
4. 撤回与任务 reservation 锁定同一授权行：撤回先提交则请求不发送；reservation 先提交则撤回可索引到在途 attempt/Task。
5. 撤回后新引用立即失败，内容代理在回源前返回 `real_person_authorization_revoked`，并在实现声明支持时安排取消/清理。

## 6. 账单查看与对账

1. 用户在 `/billing` 选择最长 31 天的周期，查看 API Key × 模型明细及两类汇总。
2. 页面以 `/api/billing/self` 的已结算消费/退款日志为金额和基础 Token 权威来源，再合并 `/api/billing/self/breakdown` 的可选解释。
3. 用户可下钻到单次用量日志，或导出脱敏 CSV；导出不包含 Key 密钥、prompt、Provider 凭据或渠道私有信息。

## 7. 渠道上线

1. 管理员审批公开 SKU、能力、价格、实现身份和回滚值，新渠道只加入隔离测试分组。
2. 验收人从当前 Ability 生成“合同 × SKU × 渠道实现 × 分组”矩阵，串行执行成功、失败、幂等、结算、脱敏和回滚用例。
3. 只有全部拟发布实现通过真实 Provider 与账单核对才扩大分组；部分 SKU 成功只表示链路接通。
