# 业务流程

本文描述当前已实现的产品行为；真实 Provider、实际账单和生产灰度仍需单独验收。

## 1. 角色

| 角色 | 核心任务 |
| --- | --- |
| API 用户 | 创建 API Key、选择客户模型、发起请求、查询 Task、使用 Provider opaque 素材 ID、查看账单 |
| 应用管理者 | 管理应用作用域、Task，以及本应用自行保存的素材 ID |
| 平台管理员 | 配置客户模型、Seedance 专用渠道、价格、分组和启停状态 |
| 技术人员 | 线下判断 Provider 协议兼容性，开发新 adapter，完成真实验证并给管理员配置指引 |
| 运维与审计人员 | 核对任务、账单和 Provider 风险，通知技术人员处理异常 |

客户只需理解 API Key、客户模型、ModelArk V3、Task、素材 opaque ID 和账单。Channel、Provider 模型、
上游协议、账号和凭据属于平台内部信息。

## 2. Seedance 模型配置与发现

1. 技术人员确认一条官方或第三方线路是否兼容已有代码协议；不兼容时先开发新的 adapter。
2. 技术人员给管理员明确的客户模型名、Provider 模型、视频协议、素材协议和必要配置。
3. 管理员创建 `Seedance 专用渠道`，配置模型映射、价格、分组和凭据。
4. 不同 Seedance 渠道必须使用不同客户模型名；系统在保存或启用时发现重名就拒绝操作。
5. Seedance 的 Priority 和 Weight 对管理员显示为无效，客户模型不会在多个渠道之间分配或切换。
6. 客户通过 `/v1/models` 或 `/api/v3/contents/generations/models` 获得全部已配置的 Seedance
   客户模型；停用或当前分组不可用的模型仍保留在目录中，由 `available` / `availability` 单独表达
   调用资格。
7. 每个目录项同时返回 ModelArk 视频调用路径，以及该模型实际发布的素材、素材组、真人认证和公共
   素材引用操作矩阵；未发布的操作明确标记为不支持。

停用渠道可以保留重复模型名，但重新启用前必须解决冲突。目录中的“有这个模型”和“当前能否调用”
是两件事；系统不在每次请求时重复验证配置唯一性，也不建立自动兼容性认证或历史数据修复流程。
目录只公开稳定的客户合同，不返回 Provider 模型、渠道 ID、凭据、南向协议名或私有路径。

NEWAPI 原生模型继续使用原生发现、路由和计费行为，不进入 Seedance 专用渠道流程。

站点管理员可在「顶部导航 → 模型广场」设置是否开放模型广场、是否要求登录。默认对访客开放。
启用登录要求后，访客访问受限的模型列表或详情直达链接时进入登录流程。内置入口的显示规则见
[页面清单](../90-ui-ux/页面清单.md#模型广场)。

## 3. 标准视频任务

### 3.1 渠道配置与上线

Seedance 与 MiniMax 标准视频共享 ModelArk V3 入口。同一客户模型只能在一个已启用的标准视频渠道履约。
管理员为每条线路配置客户模型、映射、分组和价格。MiniMax 的原生接口继续使用自己的入口。

#### MiniMax 管理入口

管理员新建渠道时选择 MiniMax 分类，再选择“原生接口”“京东云 · 标准视频”“官方直连 · 标准视频”或
“Nexhina · 标准视频”。原生接口沿用已配置模型与插件的能力。官方直连当前支持基础 H3 的生成、单查、列表和结果交付，取消和删除按
不支持返回。选择接入方式不会自动发起测试请求。官方标准链路的本地回归已完成，真实 Provider、账单、
外部数据库和生产灰度仍需验收。
Nexhina Hailuo V2 支持 16:9 文生视频及最多一张参考图，实际开放范围以模型目录和验收为准。

使用支持可配置模型的 MiniMax 标准视频插件时，管理员分别维护渠道模型列表和模型映射。网关按客户
模型名查一次 `model_mapping`，原样发送配置的上游 ID，找不到该条目时发送客户模型名。已选协议决定请求
参数范围，客户模型使用其独立价格。新增客户模型名后，首次调用前须为该模型配置 `tiered_expr` 价格。
上游按其账号和模型可用性受理请求。

切换未保存的接入方式保留名称、备注、分组、标签与状态，清除连接凭据、模型和专用配置，需重新填写。
已保存的 MiniMax Link 渠道可从下拉框切换标准视频协议。切换保留模型、映射、分组和连接字段，
管理员可按需更新 API 地址和密钥。计费与新协议不兼容时可选择停用保存，配置兼容价格后再启用。
已有任务继续使用创建时冻结的协议、连接和价格。MiniMax 原生接口独立配置，复制渠道保留原接入方式。
列表统一显示 MiniMax 并标注接入方式，管理员可筛选全部 MiniMax 或单独一种方式；独立渠道的状态、
用量和账单分别保留。标准视频能力说明读取对应协议的插件声明，声明不可用时无法保存。插件停用时可
查看声明并保存停用渠道，启用渠道和接受新请求前须启用插件。普通连接探针和远端模型获取操作不适用于
标准视频方式。

### 3.2 创建

1. 客户调用 `POST /api/v3/contents/generations/tasks`，提交客户模型和标准 ModelArk V3 请求。
2. 平台校验 API Key、应用、分组、标准请求结构和计费边界。素材引用按第 5 节的两种模式处理。
3. 客户模型直接确定唯一标准视频渠道；平台应用模型映射和代码 adapter。
4. 平台在发送 Provider 请求前建立创建事实、冻结执行与计费信息并完成资金预扣。
5. 平台只向该 Provider 发送一次创建请求，不自动重发、换渠道或降级。
6. 取得可信 Provider task ID 后返回平台 Task ID；结果不明时返回稳定 unknown 语义并保持对账事实。

unknown 不表示 Provider 一定失败。客户不得依赖平台自动切换到任何其它线路再创建一次；平台也不会
因为结果不明立即退款。预扣成功 24 小时后仍未转移到 Task 且符合资金保障条件的占款
自动退还。客户退款与 Provider 是否生成成功分别记录。

### 3.3 查询、列表和删除

- `GET /api/v3/contents/generations/tasks/{task_id}` 返回本地已保存的任务状态和交付结果，由后台按冻结渠道和 adapter 更新；
- `GET /api/v3/contents/generations/tasks` 返回当前 `user_id + app_id` 的本地任务列表；
- `DELETE /api/v3/contents/generations/tasks/{task_id}` 调用创建时 Provider；Provider 不支持时明确告知；
- 单次查询异常不直接把任务判为失败；
- 渠道停用、模型映射变化或凭据轮换不改变在途任务的 Provider 和计费目标。

单查和列表始终返回固定的 `usage` 结构，字段口径见[视频任务用量设计](ModelArk视频任务用量设计.md)。

`/v1/video/generations` 继续属于 NEWAPI 原生视频渠道，不是 Seedance 专用渠道的客户入口。

## 4. 图片调用

图片继续使用自己的客户入口和 Channel 分发行为。客户模型、Ability、Channel、模型映射和代码
converter 决定 Provider。客户始终调用 `POST /v1/images/generations`（编辑调用
`POST /v1/images/edits`），默认在本次请求内等待图片响应；南向任务式 Provider 由渠道 adaptor
内联轮询，不向客户返回 task ID，也不创建平台图片 Task。

OpenAI、Azure、Gemini、Vertex 和统一图片中转的已接入路径可显式选择异步模式：请求头携带 `Prefer: respond-async` 时，平台受理
（容量、资金与幂等一次提交）后返回 `202` 和平台任务 ID，后台执行，客户用同一 API Key 经
`GET /v1/tasks/{task_id}` 查询状态与结果；客户端断开不取消任务，结果 URL 到期后重新查询即续签。
原生 OpenAI／Azure 可同时发送 `Prefer: respond-async` 和 `stream=true`，由后台接收上游流并交付任务结果。
Gemini、Vertex 和统一图片中转的异步请求携带 `stream=true` 返回 `400`。其他渠道沿用原生响应。
同步请求携带 `Idempotency-Key` 返回 `400`。

Seedance 的“一个模型一个渠道”“Priority/Weight 无效”和“一次创建不切换”不会自动扩张到图片；
图片产品按各自正式合同处理。

## 5. 素材管理

### 5.1 创建素材组和真人认证

管理员准备 Channel 默认普通 AIGC 素材组（管理控制面与运行时回退代码已实现）：

> 真实 Provider 与生产灰度验收完成前，不得把默认素材组能力写成全部线路已生产可用；
> 验收口径见[路线图](../50-planning/路线图.md)。

1. 管理员在已保存 Channel 的编辑页面点击创建或复用默认素材组；
2. 支持查询的 adapter 遍历完整匹配结果集，再对名称做完全相等过滤；找到完全同名
   `aigctokenaigeneral` 时保存第一个结果，没有时创建；查询失败、名称缺失或不能证明分页已经耗尽时
   停止；没有查询能力但能创建时直接创建；
3. 平台为该 Channel 保存一个当前默认 Provider group ID；业务素材请求不自动创建组；
4. 停用保留默认 ID，复制不继承，删除 Channel 不删除 Provider 组。

客户仍可按业务需要创建自己的普通或真人素材组：

1. 客户使用客户模型调用 `POST /v1/asset-groups`。
2. 平台通过该模型确定唯一 Seedance 渠道，并调用该渠道的素材 adapter。
3. 普通素材组返回 Provider opaque 组 ID；真人素材组返回 opaque 会话/组 ID 和认证链接或二维码。
4. 客户直接在 Provider 页面完成认证，不在平台提交人脸、活体、证件或授权表单。
5. 客户通过带同一 `model` 的 `GET /v1/asset-groups/{id}` 刷新单项 Provider 状态。

平台不提供独立真人授权 API，不承诺代替 Provider 完成法律授权或撤回平台外副本；也不提供素材组更新
或删除接口，不主动删除 Provider 已经建立的素材组。

### 5.2 创建和使用无状态素材

1. 客户始终使用同一北向请求形状，以客户模型、可访问 HTTPS URL 和可选 `asset_group_id` 创建
   `/v1/assets`，不判断当前 Provider 是否使用素材组。
2. 客户模型确定唯一渠道；不支持素材操作的模型直接返回明确错误，不扫描其他渠道。
3. 策略为 `default_fallback` 时，裁剪后非空的客户 ID 保持原值并优先；未传、空或空白时使用 Channel
   默认组。北向结构错误返回 `invalid_request`，不得改用默认组；默认组未配置则返回
   `default_asset_group_not_configured`；Provider 拒绝显式 ID 后不回退。
4. 策略为 `none` 时，adapter 不发送组字段并继续履约，不能因北向携带 `asset_group_id` 报错。
5. 平台返回 Provider opaque Asset ID；可用时同时返回 `asset://<opaque-id>`，调用方和模型一起保存。
6. 无状态代理在当次创建中使用源 URL。平台不为这些素材和素材组建立本地资源记录。
7. 客户通过带同一 `model` 的 `GET /v1/assets/{id}` 按需查询单项状态；平台不提供素材列表。
8. ready Asset 在视频请求中以 `asset://<opaque-id>` 使用。

同一视频可以混用 `asset://<opaque-id>`、HTTP/HTTPS URL 和 Data URL。平台不验证 opaque ID 是否属于
当前模型、账号、Region 或 Project，不探测其它 Provider；所选 Provider 最终判断兼容性并返回错误。

每次素材 POST 都是一次新建，不提供平台幂等、自动重试或 orphan 管理。素材创建、查询或单素材删除失败只返回
脱敏错误，不建立本地 unknown 状态，也不切换渠道。

素材操作严格以客户模型的 `api.assets` 元数据为准；不支持的真人素材、单素材重命名和删除明确返回
不支持。素材组删除不进入公开元数据，也不存在对应北向 adapter 操作。

### 5.3 本站托管素材

平台在创建时将模型支持的托管素材复制到私有存储，并返回 `asset://fhas_*`。同账号的 API Key 共享素材。
跨模型引用要求复用域相同且目标模型发布相应媒体类型。平台在视频预扣前校验引用，
删除后拒绝新引用，已经受理的任务继续使用其冻结素材。具体支持范围见
[素材库支持矩阵](../20-architecture/Seedance模型素材库支持矩阵.md)。

## 6. Azure Batch 作业

1. 试点客户通过 `POST /v1/files` 上传同一客户模型的 Chat Completions JSONL，取得本站文件 ID。
2. 客户用该文件 ID 和 `completion_window: 24h` 创建作业，并通过 `/v1/batches/{id}` 查询进度；需要时调用取消操作。
3. 终态结果通过授权的本站文件接口获取。即使作业取消、过期或部分失败，已有可信用量的行仍可能计费。
4. 调用方从创建时使用的应用作用域读取作业和文件。部署验收检查成功行、错误行、结果交付和资金差额。当前接口尚未进入公开 API 白名单。

支持的端点、文件与状态边界见 [Azure Batch 渠道与批处理作业架构](../20-architecture/AzureBatch渠道与批处理作业架构.md)。

## 7. 账单查看与对账

1. 用户在 `/billing` 选择北京时间自然月，按 API Key 与客户模型核对已入账的扣款、退款及净额。
2. 月账单已确认时读取正式版本，其余账期读取已发布日报。同一版本下钻可展开逐笔资金记录或导出 CSV。
3. 用户在「我的用量」按日、周或月查看自己的调用、计量和净费用。管理员从独立入口查看客户账单、
   客户用量及按 URL、渠道划分的上游报表。
4. 费用按账单入账日与用量任务完成日分别核对。缺证据的上游参考金额或实际成本保持未知。

页面范围、数据状态与版本绑定见[使用日志与报表产品设计](使用日志与报表产品设计.md)。

视频 unknown、客户退款和 Provider 潜在成本分别记录。账单不代表税务发票、会计关账或供应商正式
账单。

使用上游 Token 结算的线路直接读取 Provider 返回的可信用量，再使用创建时冻结的价格表达式结算。
Provider 成本字段只作为可选成本证据，不参与 Token 反推。缺少结算所需可信用量时，成功任务保留预扣并进入后台补查或运营核实；非法、冲突及超界用量按协议异常处理。创建时的预扣只是资金暂挂：真实费用高于预扣时平台
自动补扣差额；客户余额确实不足时任务记为欠费并保持成功结果，充值后自动结清，不把已生成的内容
改判为失败。

## 8. 邮件与运维通知

管理员建号、自助找回密码、用户事件邮件、资源阈值告警和日报的目标流程由
[邮件与运维通知产品设计](用户生命周期邮件通知产品设计.md)统一描述。该专题区分现有实现、已确认的目标和发布验收。

## 9. 公开与上线

1. 技术人员完成代码协议、真实 Provider、失败、内容、账单和三数据库验证。
2. 产品确认公开路径、请求结构、错误和模型说明。
3. 管理员按技术指引配置独立客户模型和渠道，在保存/启用时通过重名检查。
4. OpenAPI、公开页面和实际行为共同通过校验后，才向目标分组开放。

代码存在、渠道可保存或单个样本成功都不等于生产发布。
