# 业务流程

## 1. 角色

| 角色 | 核心任务 |
| --- | --- |
| API 用户 | 创建 API Key、发现模型、发起调用、查询 Task、使用 Link 资源、查看账单 |
| 应用管理者 | 维护应用作用域、接受 API 服务规则、管理匿名最终用户与真人授权 |
| 平台管理员 | 发布客户模型、配置渠道和价格、控制分组、灰度与回滚 |
| 运维与审计人员 | 验证 Provider、核对账单、处理未知结果、风险暴露和敏感信息事件 |

客户只需要理解 API Key、调用协议、客户模型、Task、`ast_*` 和账单。Link SKU、implementation、
Provider 模型、渠道账号和 execution binding 属于平台内部履约信息。

## 2. 客户模型发布与发现

1. 平台管理员选择已注册的 Link 接入方案，配置客户模型、Provider 模型、渠道、分组和价格。
2. 系统在启用时发布或核对客户模型所代表的 Link 产品；已存在冲突时拒绝启用，不静默改绑。
3. 客户从模型发现或管理员提供的清单获得其 API Key、应用和分组可用的客户模型名。
4. 后续渠道禁用、删除或缓存重建只影响当前可用性，不改变客户模型已经代表的产品。
5. 确需把客户模型改绑到另一产品时，管理员使用显式敏感操作并留下版本化审计。

NEWAPI 原生模型继续沿用原生模型发现和渠道逻辑，不进入上述 Link publication 流程。

## 3. 同步模型调用

1. 客户使用 API Key、已授权客户模型和对应公开协议发起请求。
2. 平台校验用户、应用、分组、限流、字段能力和可用额度。
3. 平台从能够完整履约该客户合同的候选中选择渠道，并转换为 Provider 所需模型和请求。
4. Provider 同步返回后，平台归一化结果、完成结算并写入消费日志。
5. 客户看到的模型名、响应、错误和价格不随命中的 Provider 改变。

没有合格候选时返回稳定的暂不可用错误，不切换到另一份客户合同，也不透传 Provider 私有参数。

## 4. 异步图片与视频

1. 客户使用目标图片或视频合同提交请求；需要安全重放时提供 `Idempotency-Key`。
2. 平台在调用 Provider 前建立本次业务尝试、冻结客户合同与执行事实，并完成资金预扣。
3. Provider 明确创建成功后，平台返回稳定 Task ID；图片同步成功时直接返回结果，不创建伪 Task。
4. Provider 明确未创建时释放预扣；发送后结果不可确定时返回稳定 unknown 语义并进入后台对账。
5. 客户用平台 Task ID 查询进度。平台始终使用创建时渠道、连接和合同，不因后续配置改变而换 Provider。
6. 可信终态只结算一次；失败、取消、退款、补偿和平台成本风险分别记录。
7. 成功结果通过客户合同规定的响应或平台内容端点交付，不暴露上游 task ID、凭据和签名地址。

unknown 状态下客户不得换 Key 自动重建；单次轮询响应异常也不等于业务任务已经失败。

## 5. Link 资源

1. 客户向 `/v1/assets` 提交 Provider 可访问的 HTTPS source，可选指定客户模型。
2. 平台校验所有权、应用、类型、URL、TTL、幂等和可选授权，返回稳定 `ast_*`。
3. 平台可以为需要托管素材的 Provider 异步创建 binding；只支持 URL 的实现继续使用受保护 source。
4. 客户在已声明支持 Link 资源的媒体字段中使用 `asset://ast_*`。
5. 平台从全部资源共同可用的渠道中选路，并在每次 Provider 尝试前转换为精确上游引用。
6. 查询只返回平台资源及脱敏状态；更换 source 或迁移账号会创建新 `ast_*` 并保留关联。
7. 删除先阻止新引用，再异步清理 Provider binding；客户自己的 OSS/CDN 对象不由平台删除。

请求级 URL/Data URL 仅属于当前调用，不会自动成为 `ast_*`，也不获得资源迁移、授权和撤回能力。

## 6. 真人素材授权与撤回

1. 应用接受当前生效的 API 服务规则，并为稳定匿名最终用户创建真人授权。
2. 平台冻结客户模型和 Provider 账号，通过短时平台链接发起 Provider H5 技术认证。
3. 只有平台主动查询到可信成功后，authorization 才可用于创建 `real_person` Asset。
4. 每次任务发送前，平台记录该 Task 对真人素材的已接受使用关系。
5. 撤回先发生时，新任务不会发送；任务使用已被接受时，撤回能够找到在途 Task 并安排取消或清理。
6. 撤回后新的资源解析和平台内容回源立即失败；任务元数据和真实计费终态仍按合同处理。

平台不承诺撤回 Provider 已处理数据、删除平台外副本或替应用保存自然人的法律同意证明。

## 7. 账单查看与对账

1. 用户在 `/billing` 选择不超过 31 天的周期和需要的视图。
2. 平台按 API Key 与客户模型聚合已结算消费和退款日志，并提供总览。
3. 可选 breakdown 解释缓存、长短 Context 或其它计费维度，但不改变基础金额和 Token 事实。
4. 用户可以下钻到用量记录或导出当前筛选的脱敏 CSV。
5. 数据缺失或质量不足时明确显示不可用，不把未知值显示为零。

账单用于用量核对，不代表税务发票、会计关账、Provider 成本账单或任意历史余额快照。

## 8. 公开文档与能力发布

1. 产品团队确认准备公开的客户合同和 operation。
2. OpenAPI、公开 operation 白名单、Manifest 和人类可读页面在同一变更中更新。
3. Web 构建校验公开范围、内容、安全、搜索索引和最终静态文件。
4. 未验证能力不进入公开导航；构建失败时不发布半成品文档。
5. 渠道真实调用、账单、外部数据库和回滚验证全部通过后，管理员才扩大目标分组流量。

部分渠道链路接通不等于整个客户模型已经完成生产发布。
