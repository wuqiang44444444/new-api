# 业务流程

本文描述当前已实现的产品行为；真实 Provider、实际账单和生产灰度仍需单独验收。

## 1. 角色

| 角色 | 核心任务 |
| --- | --- |
| API 用户 | 创建 API Key、选择客户模型、发起请求、查询 Task、使用 `ast_*`、查看账单 |
| 应用管理者 | 管理应用作用域和本应用的 Task、Asset、AssetGroup |
| 平台管理员 | 配置客户模型、Seedance 专用渠道、价格、分组和启停状态 |
| 技术人员 | 线下判断 Provider 协议兼容性，开发新 adapter，完成真实验证并给管理员配置指引 |
| 运维与审计人员 | 核对任务、账单和 Provider 风险，通知技术人员处理异常 |

客户只需理解 API Key、客户模型、ModelArk V3、Task、`ast_*` / `astgrp_*` 和账单。Channel、Provider
模型、上游协议、账号和凭据属于平台内部信息。

## 2. Seedance 模型配置与发现

1. 技术人员确认一条官方或第三方线路是否兼容已有代码协议；不兼容时先开发新的 adapter。
2. 技术人员给管理员明确的客户模型名、Provider 模型、视频协议、素材协议和必要配置。
3. 管理员创建 `Seedance 专用渠道`，配置模型映射、价格、分组和凭据。
4. 不同 Seedance 渠道必须使用不同客户模型名；系统在保存或启用时发现重名就拒绝操作。
5. Seedance 的 Priority 和 Weight 对管理员显示为无效，客户模型不会在多个渠道之间分配或切换。
6. 客户从模型页面或清单获得 API Key 当前可用的客户模型，并由模型名称识别国内、海外或第三方产品。

停用渠道可以保留重复模型名，但重新启用前必须解决冲突。系统不在每次请求时重复验证配置唯一性，
也不建立自动兼容性认证或历史数据修复流程。

NEWAPI 原生模型继续使用原生发现、路由和计费行为，不进入 Seedance 专用渠道流程。

## 3. Seedance 视频任务

### 3.1 创建

1. 客户调用 `POST /api/v3/contents/generations/tasks`，提交客户模型和标准 ModelArk V3 请求。
2. 平台校验 API Key、应用、分组、标准请求结构、素材作用域和计费安全上界。
3. 客户模型直接确定唯一 Seedance 渠道；平台应用模型映射和代码 adapter。
4. 平台在发送 Provider 请求前建立创建事实、冻结执行与计费信息并完成资金预扣。
5. 平台只向该 Provider 发送一次创建请求，不自动重发、换渠道或降级。
6. 取得可信 Provider task ID 后返回平台 Task ID；结果不明时返回稳定 unknown 语义并保持对账事实。

unknown 不表示 Provider 一定失败。客户不得依赖平台自动切换火山、BytePlus、飞彩、FunCloud 或
TokenSave 再创建一次；平台也不会因为结果不明立即退款。

### 3.2 查询、列表和删除

- `GET /api/v3/contents/generations/tasks/{task_id}` 使用创建时冻结的渠道和 adapter 查询；
- `GET /api/v3/contents/generations/tasks` 返回当前 `user_id + app_id` 的本地任务列表；
- `DELETE /api/v3/contents/generations/tasks/{task_id}` 调用创建时 Provider；Provider 不支持时明确告知；
- 单次查询异常不直接把任务判为失败；
- 渠道停用、模型映射变化或凭据轮换不改变在途任务的 Provider 和计费目标。

`/v1/video/generations` 继续属于 NEWAPI 原生视频渠道，不是 Seedance 专用渠道的客户入口。

## 4. 图片调用

图片继续使用自己的客户入口和 Channel 分发行为。客户模型、Ability、Channel、模型映射和代码
converter 决定 Provider。图片可能同步返回，也可能进入共享图片 Task。

Seedance 的“一个模型一个渠道”“Priority/Weight 无效”和“一次创建不切换”不会自动扩张到图片；
图片产品按各自正式合同处理。

## 5. 素材库

### 5.1 创建素材组和真人认证

1. 客户使用客户模型调用 `POST /v1/asset-groups`。
2. 平台通过该模型确定唯一 Seedance 渠道，并调用该渠道的素材 adapter。
3. 普通素材组返回平台 `astgrp_*`；真人素材组同时直接返回官方或第三方认证链接/二维码。
4. 客户直接在 Provider 页面完成认证，不在平台提交人脸、活体、证件或授权表单。
5. 客户通过 `GET /v1/asset-groups/{id}` 刷新 Provider 状态。

平台不提供独立真人授权 API，不承诺代替 Provider 完成法律授权、撤回平台外副本或删除 Provider
已经处理的数据。

### 5.2 创建和使用 Asset

1. 客户使用客户模型、可访问 URL、可选 `astgrp_*` 和 moderation 创建 `/v1/assets`。
2. 客户模型确定唯一渠道；不支持素材库的模型直接返回明确错误，不扫描其他渠道。
3. 平台创建一个 `ast_*`，它只对应一个固定渠道、Provider 账号和 Provider Asset。
4. Provider 返回可信 Asset ID 或创建失败后，平台立即删除临时保存的 source URL。
5. 客户通过 `GET /v1/assets/{id}` 按需刷新状态；列表主要读取平台本地记录。
6. active Asset 在视频请求中以 `asset://ast_*` 使用。

同一视频可以混用 `asset://ast_*`、HTTP/HTTPS URL 和 Data URL，但所有平台素材必须属于客户模型确定
的同一渠道、账号、Region 和 Project。国内与海外素材互不迁移；同一媒体需要分别创建和审核。

每次素材 POST 都是一次新建，不提供素材幂等或自动重试。创建未取得可信 Provider ID 就返回失败；
删除结果不明确也返回失败并保留原状态，由后续 GET 在确认 Provider 不存在后更新。管理员通知技术
人员处理少见孤儿资源，不建设专门核查系统。

## 6. 账单查看与对账

1. 用户在 `/billing` 选择账期和视图。
2. 平台按 API Key 与客户模型聚合已结算消费和退款日志。
3. 用户可以下钻到用量记录或导出脱敏 CSV。
4. 管理员从独立入口查看客户账单和平台记录的渠道/Provider 用量。
5. 缺失的 Provider 金额保持未知，不使用客户 quota 或当前报价伪装实际成本。

视频 unknown、客户退款和 Provider 潜在成本分别记录。账单不代表税务发票、会计关账或供应商正式
账单。

## 7. 用户生命周期邮件

平台管理员可以分别开启账户创建、密码修改和 API Key 创建邮件，三个开关默认关闭。事件发生且开关
开启时，平台按用户语言异步发送通知；发送失败只写系统日志，不回滚账户、密码或 API Key 操作。

- 普通注册和管理员创建本地账户要求填写邮箱；OAuth/微信登录不因 Provider 缺少邮箱而被阻断；
- 用户显式创建 API Key 时发送通知，注册流程自动创建的默认 Token 不重复发送 API Key 邮件；
- 只有实际密码修改发送安全通知，普通资料更新不发送；
- 本期不验证邮箱归属，不建立退订、营销同意或重试队列。

## 8. 公开与上线

1. 技术人员完成代码协议、真实 Provider、失败、内容、账单和三数据库验证。
2. 产品确认公开路径、请求结构、错误和模型说明。
3. 管理员按技术指引配置独立客户模型和渠道，在保存/启用时通过重名检查。
4. OpenAPI、公开页面和实际行为共同通过校验后，才向目标分组开放。

代码存在、渠道可保存或单个样本成功都不等于生产发布。
