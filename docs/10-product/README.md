# 10-product — 产品行为

## 目标

从客户和运营视角说明平台为谁服务、用户如何完成核心任务，以及哪些可观察结果才算产品通过。

## 放什么

- 用户、应用管理者、平台管理员和审计人员的角色；
- 模型调用、异步任务、无状态素材代理、真人认证代理、账单和发布流程；
- 客户可观察的成功、失败、安全与一致性验收标准。

## 阅读顺序

1. [业务流程](业务流程.md)介绍角色、模型接入、视频与图片任务、素材、Batch 和账单。
2. 按下表选择产品专题。
3. [验收标准](验收标准.md)定义客户可观察的结果与发布条件。

| 场景 | 专题 |
| --- | --- |
| 视频、素材和真人认证 | [Seedance 视频与素材产品设计](Seedance视频与素材产品设计.md)、[ModelArk 视频任务用量设计](ModelArk视频任务用量设计.md) |
| 合同模型权限与折扣 | [用户模型合同定价](用户模型合同定价.md) |
| 日志、用量和账单 | [使用日志与报表产品设计](使用日志与报表产品设计.md)、[客户与上游对账单产品说明](客户与上游对账单产品说明.md) |
| 渠道诊断 | [渠道自动检查与配置诊断](渠道自动检查与配置诊断.md) |
| 账户、邮件与告警 | [邮件与运维通知产品设计](用户生命周期邮件通知产品设计.md) |

## 不放什么

- 系统组件、数据库字段、锁、状态机实现和架构取舍，放入 `20-architecture/`；
- 开发命令和接入步骤，放入 `30-engineering/`；
- 部署、监控、灰度、回滚操作，放入 `40-operations/`；
- 市场文案和页面交互，分别放入 `60-marketing/`、`90-ui-ux/`。

## 命名格式

- 使用稳定的中文业务名称，不加日期前缀，例如 `业务流程.md`、`验收标准.md`；
- 文件名应直接说明用户流程、验收范围或产品能力，避免“新版”“最终版”等阶段性措辞；
- 同一产品主题只保留一份当前事实文档，细分主题通过清晰的业务名称区分。

## 内容格式

- 业务流程按角色、前置条件、触发、步骤、结果和失败语义组织；
- 验收标准按适用范围、前置条件、操作和客户可观察结果组织；
- 产品说明优先解释用户看到的模型、任务、素材和账单，不展开内部 Channel、数据库或事务实现；
- 涉及未完成能力时，明确区分目标行为、代码现状、真实 Provider 验证和生产发布状态。

## 编写要求

- 使用角色、触发、产品行为、结果和失败语义描述流程；
- 验收必须可观察、可复现，并区分代码完成、真实 Provider 验证和生产发布；
- 客户术语使用客户模型、API Key、Task、素材 opaque ID 和账单，不要求客户理解 Channel、协议或 Provider 模型；
- 不写代码文件清单、事务细节、实施顺序或排障过程。
