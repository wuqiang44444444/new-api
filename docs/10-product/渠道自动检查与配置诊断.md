# 渠道自动检查与配置诊断

## 产品目标

定时渠道自动检查以零生成费用监控渠道可用性：文本模型执行有输出上限的真实探测，图片、视频
渠道只做本地配置检查和已登记的只读探针，不发送生成请求、不创建收费资源。配置失败必须以可
操作的诊断展示给管理员，减少重复通知不等于隐藏失败。

## 自动检查与手工测试边界

- 定时任务进入自动检查策略；手工单项测试与手工批量测试保持原有请求、参数、收费、结果展示、
  日志和通知行为，不新增确认步骤或按钮。任务来源由入口决定，不根据执行结果推断。
- 文本模型的自动探测保留既有真实请求路径与输出上限。部分协议（如 Responses/Codex）的
  adapter 可能移除不支持的输出上限参数，这类路径的严格成本封顶尚未验收。
- 图片、视频渠道的定时检查禁止调用生成 POST、创建素材或其他可能收费的资源；不使用"创建后
  立即取消"、故意非法请求等方式假设不收费。

## 检查表达的三项事实

自动检查把三个不同证明范围的事实分开表达，不用单个"健康"结论覆盖：

| 维度 | 结果 | 证明范围 |
| --- | --- | --- |
| 本地配置 | 通过／失败／依赖前置项未检查 | 当前检查项及样例成立，不证明所有业务输入或上游可用 |
| 上游只读检查 | 通过／失败／不支持／本次未执行 | 仅证明对应接口、凭据和操作的结果 |
| 最近业务生成 | 本次未验证（历史结果展示待实施） | 不以下一次生成成功为承诺 |

配置失败是明确失败，不合并为笼统"跳过"；没有只读能力是"不支持检查"，不伪装成 Provider 故障。

图片目标的定时检查复用现有端点解析：AsyncImage、Gemini/Vertex 图片分支、AdvancedCustom 唯一
图片端点只执行本地前置校验；AdvancedCustom 多端点含图片且目标不唯一，或命中 VolcEngine
seedream 既有名称信号时显示"检查目标需确认"，不回退文本探测、不发送请求。名称信号只阻止
自动调用，不赋予渠道身份或生成资格；手工测试的目标解析与调用行为不变。

## 配置失败诊断

- 配置检查复用正式路径的渠道上下文、协议注册、模型映射、测试样例与价格校验，不预扣、不创建
  任务、不调用生成接口，也不新设第二套定价规则或能力表。
- 失败原因取自计费校验的类型化错误：区分价格未配置、表达式缺失、表达式求值失败、图片价格或
  用量支持缺失等；无法可靠细分时显示"计费校验失败"，不靠匹配错误文案猜测具体字段。未知计费
  错误显示通用失败。
- 摘要是固定的中英文安全文案，不嵌入原始表达式、凭据或 Provider 内容；客户模型与实际定价模型
  分列展示；管理入口链接由前端按受控目的地固定生成，不接受日志中的任意 URL。
- 依赖无效协议、映射等前置项的检查标为"前置项失败，未检查"，不伪造下游错误。

## 网络执行事实与启停隔离

- 自动检查用 HTTP transport trace 区分"未调用上游""已尝试连接但未取得响应""已取得响应字节"。
  调用尝试不证明请求字节已发送；未取得响应不证明 Provider 未受理。仅对发送前明确终止的路径
  显示"未发送上游请求：本地计费校验失败"。
- 本地配置失败不进入上游故障自动禁用/恢复判断，不覆盖上次有效上游延迟；连接失败同样不覆盖
  延迟。只读调用无论成败都不用于生成渠道恢复，也不作为履约延迟。手工批量测试保留原有的启停
  和延迟处理。

## 只读能力边界

- Seedance 渠道继续复用已登记的素材只读探针；协议未登记只读能力时自动结果显示"不支持只读
  检查"，计入独立的"不支持"数量，不计为 Provider 失败，也不声称已调用。协议未配置仍是配置失败。
- 只读接口成功只证明对应能力，不证明视频生成、指定模型或生成凭据可用；不因只读成功恢复被禁
  渠道。

## 结果查看

- 每轮定时检查的每渠道分项结果（配置结论、只读结论、网络事实、客户模型与时间）保存在系统任务
  历史的结果 JSON 中，管理员在系统任务面板"检查结果"查看；修复配置后的通过结果与"本次未验证
  生成"同时可见。"配置通过"与"探测失败"可以并存展示（如配置正确但上游 401/500、连接失败或
  超过响应阈值）。
- 自动检查失败仍写入错误事件，携带受控分项字段；错误日志详情与任务结果复用同一分项展示组件，
  提供中英文摘要与固定管理链接。仅自动检查事件（`channel_test + test_mode=auto`）在详情中排除
  分项同名附加键，手工测试事件的日志展示保持原行为。
- 渠道列表的 `test_time/response_time` 继续保留上次生成探测事实；定时检查时间在任务历史查看。
  历史任务按既有保留/清理策略处理，历史通过不作为当前配置有效的证明。

## 验收口径与边界

- 验收标准：定时自动检查对图片/视频渠道不产生任何生成或资源创建请求；文本探测有输出上限；
  配置失败诊断可见且能区分上述类型；本地失败不触发自动禁用、不覆盖延迟；手工测试全行为不变。
- 当前边界：取消收费探针后，无合适只读接口的图片、视频渠道失去周期性生成验证手段，上游故障
  可能到首个真实客户请求失败才暴露；该被动发现代价由运维说明显式承载。"最近业务生成结果展示、
  配置变化关联、长期未验证提醒、重复告警聚合"尚未实施（见
  [路线图](../50-planning/路线图.md)），当前统一显示
  "本次未验证生成"。
- 本地模拟 Provider 与回归测试不构成真实 Provider 只读能力、生产配置或账单验收；个别 Provider
  只读接口的操作范围、凭据与费用须核实后才能接入自动探针。
