# 用户模型合同定价

## 1. 产品目标

管理员为客户建立合同，选择精确模型、组、渠道与折扣。一个用户可持有多份合同，API Key 逐个绑定，
每个 Key 至多绑定一份。同一模型可以选择多个渠道，所有组合使用同一个折扣。

启用合同限定绑定 Key 的模型与渠道范围。合同是调用范围与折扣的授权来源，替代用户可用组及 Key 的选路组范围；
Default 用户无需额外开放内部组即可使用合同组合。Key 模型限制、额度和安全校验继续生效。渠道优先级、权重和组倍率仍按现有配置生效。

## 2. 价格与分发

```text
客户模型费用 = 原生模型费用小计 × 实际执行组倍率（含特殊倍率）× 合同模型折扣
```

组倍率决定价格，不决定选路顺序。同模型跨组可以有不同成交价；合同承诺折扣，不承诺最低候选价成交。
工具费、违规费、充值折扣和 Provider 成本不乘合同模型折扣。

首次请求在有效合同组合中按渠道机制竞争，范围内的 pin/亲和按原有顺序生效；合同不新增优先级或权重。
跨组重试关闭时，重试只能使用首次选中组中的合同渠道；开启时可在合同内跨组。非 auto Key 已保存的
关闭状态不会被自动打开。未列模型、所有组合不可用或被 Key 模型限制排除时明确拒绝，不回退到默认组。

Seedance、素材代理和 Batch 按各自入口规则处理。合同不会让普通渠道取得类型化资格，也不会因为
原生另有可用渠道就绕过合同。素材操作仅受范围约束，不因此新增模型费用。

## 3. 展示与管理

管理员从客户合同总览或用户管理进入同一编辑器。新增/变更来源必须有效；已保存但失效的来源允许
保留和编辑，运行时不会使用。修改需要完整规则集、版本与变更原因，同模型各条折扣必须一致。
合同与模板编辑器保留失效规则的模型、分组和渠道标识，并显示渠道停用、渠道不存在、模型在该组
不可用或分组已移除等具体原因。选择当前有效候选后清除旧原因，保存时仍由服务端校验；原因只在
管理员视图显示，不进入客户合同或 Key 明细。

客户明细显示完整的模型与折扣，并标注渠道不可用或合同停用；不公开渠道名称、渠道 ID、
Provider 或上游模型。Key 编辑界面同时提示自身模型限制。Key 模型发现/详情和报价只显示有效调用范围，
价格按普通/Batch 的对应基础价格和适用组倍率展示。全站目录与未选择合同的会话保持原生范围。

新建 Key 时，用户恰有一份启用合同会作为初始选择，用户可以更改；编辑已有 Key 保留原绑定。
未绑定、停用与加载失败必须分开表达。合同读取失败阻止请求，不伪装为原价或无合同。

管理员可把常用合同配置保存为全站共享的合同模板，也可将已有合同另存为模板；新建用户合同时套用
模板带入全部规则，并可针对当前用户调整，保存产物是归属于该用户的独立合同。模板只用于创建：
后续修改或停用模板不影响已生成的合同与 Key 绑定；模板支持停用与恢复，不提供删除。含失效来源的
模板完整保留规则并标出原因，管理员修正或删除后才能保存新合同，不静默跳过。

## 4. 生命周期

- 停用或解绑后，Key 恢复自身分组的路由与计价，可能使用合同范围外渠道；停用界面明确提示。
- 修改、换绑或停用只影响新请求。已受理请求重试保留本次合同快照；已有任务按冻结事实完成。
- 新 remix 属于新请求，须在当前合同中使用原生锁定的原渠道；不满足则拒绝，不影响旧任务自身。
- 跨组换到更贵组前补充预扣，换到便宜组后在最终结算时退差额；已受理异步任务遵守原资金事务。
