# 用户模型合同定价

## 1. 产品目标

用户模型合同用于按 `User ID` 管理 B 端客户的模型权限和成交折扣。一个合同只属于一个用户；同一用户的
全部现有和未来 API Key 立即共享合同状态。管理员维护的最小事实是：

```text
精确公开模型 + 唯一渠道组 + 合同折扣
```

未建立或已明确停用合同的用户继续使用 NEWAPI 原生权限、分发和计费。启用合同后，未配置的模型不可见、
不可调用；启用但零规则表示零模型权限，不会自动退回原生模式。

## 2. 价格语义

合同承诺的是折扣，不是固定价格：

```text
客户模型费用 = 原生模型费用小计 × 当前完整原生有效组倍率 × 合同模型折扣
```

例如 `100 × 0.87 × 0.8 = 69.6`。合同折扣只作用于模型费用，不作用于独立工具费、违规费、充值折扣或
Provider 成本。管理员修改原生组倍率后，合同客户的新请求价格会同步变化；保存组倍率前界面必须显示
受影响的生效合同数、规则数和渠道组。

## 3. 权限和路由

- 模型名按大小写精确匹配；为保证 SQLite、MySQL、PostgreSQL 一致，同一合同禁止保存仅大小写不同的
  两个模型名。
- 每个合同模型只绑定一个具体渠道组，组内可以有任意多条普通渠道，并继续使用原生组内选渠。
- Token 模型限制与合同白名单取交集；指定 Channel、AutoGroups、Playground 和重试不能扩大合同权限。
- Seedance 继续使用其专用唯一 Channel 路由，不写入原生 Ability。
- 素材与素材组不属于模型真实调用和合同计费范围。

## 4. 用户和管理员体验

管理员从用户列表的“管理模型合同”进入独立侧边栏，批量选择渠道组内可履约模型、填写折扣、预览当前
价格并提交必填变更原因。用户列表区分原生、生效、停用和“生效但零模型权限”四种状态。

普通用户只在 API Key 页面看到自己的合同模型、折扣、当前折后价格和可用状态；不展示渠道组、Channel、
Provider 或上游模型。`/v1/models`、模型详情、控制台模型选择器和价格接口使用同一合同投影，读取失败时
失败关闭。

## 5. 生命周期

- 建立第一批规则即标记并启用合同；所有存量 Key 立即进入合同约束。
- 删除最后一条规则仍保持合同模式并拒绝全部模型。
- 停用需要二次确认，停用后恢复原生权限但保留规则和审计。
- 重新启用会重新校验规则可履约性。
- 每次替换使用 `expected_version`；冲突时编辑器加载最新已提交版本，禁止覆盖他人修改。

本能力的真实 Provider、真实账单和生产灰度仍按实施计划单独验收，不能仅凭自动化测试宣称已生产发布。
