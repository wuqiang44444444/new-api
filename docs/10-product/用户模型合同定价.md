# 用户模型合同定价

## 1. 产品目标

用户模型合同用于按 `User ID` 管理 B 端客户的模型成交折扣。合同只是折扣层：它不授予、不收窄模型
权限，也不改变分组、渠道选择或重试。一个合同只属于一个用户；API Key 逐个绑定合同，绑定后该 Key
对合同内模型按折扣结算。管理员维护的最小事实是：

```text
精确公开模型（可对应多个渠道来源）+ 唯一合同折扣
```

未绑定或绑定已停用合同的用户继续使用 NEWAPI 原生权限、分发和计费。同一公开模型可以在同一合同中
配置多个渠道来源，但整个合同内该模型只允许一个折扣；不同合同可以为同一模型独立约定折扣，以 Key
当前绑定的合同为准。

## 2. 价格语义

合同承诺的是折扣，不是固定价格：

```text
客户模型费用 = 原生模型费用小计 × 实际有效原生组倍率 × 合同模型折扣
```

实际有效组倍率来自请求真实使用的分组（含适用的特殊组倍率），与合同明细中的渠道配置无关；因此同一
模型在不同分组上下文中的最终成交价可以不同。合同折扣只作用于模型费用，不作用于独立工具费、违规费、
充值折扣或 Provider 成本。管理员修改原生组倍率后，合同客户的新请求价格同步变化；保存组倍率前界面
显示受影响的生效合同数、规则数和渠道组。

## 3. 权限和路由

- 模型名按大小写精确匹配；为保证 SQLite、MySQL、PostgreSQL 一致，同一合同禁止保存仅大小写不同的
  两个模型名。
- 合同模型清单不参与权限判定：绑定合同的 Key 未调用合同内模型时按原生价格计费，调用合同内模型时
  应用折扣；权限、Token 模型限制、指定 Channel、AutoGroups、Playground 与重试全部按原有机制执行。
- 实际选中的渠道不需要出现在合同明细中；来源渠道失效不取消折扣，也不导致渠道被拒绝。
- Seedance、Azure Batch 等类型化入口的资格、选渠与计价方式由各自入口决定；同一模型的普通与类型化
  渠道规则在折扣相同时可以在合同中共存。Seedance 保留一个已启用客户模型只对应一个 Seedance
  Channel 的约束。
- 素材与素材组不属于模型真实调用和合同计费范围。

## 4. 用户和管理员体验

管理员可从“客户合同”查看全部已建立合同的状态摘要和分页列表（状态为生效 / 已停用），并按客户、
公开模型或状态检索；也可从用户列表的“管理模型合同”进入目标用户的独立侧边栏。两个入口复用同一个
编辑器和写接口：选择模型与渠道来源、填写折扣、预览当前价格并提交必填变更原因。已添加的模型可以
继续添加其他渠道来源；相同模型与渠道的重复、同模型折扣冲突和仅大小写不同的模型名会被明确拒绝；
同模型折扣调整必须在一次完整替换中覆盖该模型的所有渠道规则。

普通用户在 API Key 处看到所绑定合同的折扣明细：按公开模型去重后的“模型 + 合同折扣”两列，不展示
渠道名称、渠道 ID、路由组、Provider 或上游模型；模型当前不可用不抹去其已约定折扣。未绑定、已停用
与加载失败三种状态明确区分。新建 API Key 时，若用户全部合同中恰有一份且已启用，表单自动选中该
合同作为初始值；用户可手动改为不绑定或其他合同，主动选择不会被数据刷新覆盖；编辑已有 Key 保留原
绑定。价格页按普通/Batch 执行模式取得各自基础价格再叠加合同折扣，读取失败时明确失败。
管理员价格预览按所选来源及其组倍率计算；实际成交价使用真实请求的执行模式与组倍率。

## 5. 生命周期

- 合同建立规则并启用后，绑定该合同的 Key 立即对合同内模型按折扣结算。
- 停用需要二次确认；停用后绑定 Key 只是失去折扣（权限与路由本就由原生机制决定），规则和审计保留。
- 已有来源渠道失效或原组删除不会阻止修改折扣、停用或重新启用合同；只有新增或变更的来源才重新校验渠道引用。
- 每次替换使用 `expected_version`；冲突时编辑器加载最新已提交版本，禁止覆盖他人修改。
- 合同修改与 Key 换绑不重解释在途或历史任务；异步任务按创建时冻结的折扣与执行事实结算。

本能力的真实 Provider、真实账单和生产灰度仍按实施计划单独验收，不能仅凭自动化测试宣称已生产发布。
