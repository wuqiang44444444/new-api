# 素材代理与真人授权配置手册

## 1. 上线前提

素材能力只适用于客户能够长期保留私有源对象，并在创建素材时签发 Provider 可访问 HTTPS URL 的场景。new-api 不接收文件、不托管对象、不把 base64 转成 URL，也不删除客户自己的源对象。

启用任一 Provider 前必须取得并验证：

- 最晚首次抓取时间、Processing 阶段是否重复抓取以及建议的签名 URL 有效期；
- Provider 对重定向、DNS rebinding、私网地址和云元数据地址的 SSRF 防护；
- 素材创建、查询、改名、删除和 404 幂等语义；
- 素材实际归属 Key、账号、Project 还是 group，换 Key 后能否继续管理；
- 真人能力所需的白名单/权益、处理地区、接收方、H5 回调、撤回和删除 SLA。

任一合同没有确认时，不要在对应渠道启用素材 profile。网关的 URL 预校验不是 Provider 抓取安全的替代品。

## 2. 全局配置

动态配置注册在 `asset_setting`：

| 字段 | 默认值 | 作用 |
| --- | ---: | --- |
| `enabled` | `true` | 允许创建和引用普通素材；需要紧急停止新建时可动态关闭 |
| `real_person_enabled` | `false` | 允许真人授权与真人素材 |
| `job_max_attempts` | `12` | 素材后台操作最大尝试次数 |
| `verification_poll_max_attempts` | `360` | 真人认证最大轮询次数 |
| `job_lease_seconds` | `60` | 多实例 Job 租约时间 |
| `poll_interval_seconds` | `5` | 素材系统任务调度间隔 |
| `max_assets_per_user` | `1000` | 每用户未删除素材数量上限 |
| `remote_url_max_length` | `8192` | URL 最大长度 |
| `create_unknown_ttl_seconds` | `300` | 不确定创建结果的有界等待时间 |

普通素材只使用动态配置 `asset_setting.enabled`，不需要额外的环境变量才能启用。环境变量 `REAL_PERSON_ASSET_ENABLED` 存在时仍会覆盖真人素材动态开关。关闭创建开关不会停止已开始的轮询、删除、撤回和 watchdog。

真人能力还需要：

| 环境变量 | 要求 |
| --- | --- |
| `ASSET_PUBLIC_BASE_URL` | 公网可访问的 HTTPS 根地址，用于同意页、回执页和 Provider 返回地址 |
| `ASSET_CONSENT_EVIDENCE_HMAC_KEY` | 至少 32 字符，仅用于同意证据 HMAC，不得复用公开值 |
| `ASSET_H5_ALLOWED_HOSTS` | 可选；逗号分隔的额外 Provider H5 host 白名单。渠道 Base URL 的 host 默认允许 |

只有普通和真人开关均开启、HMAC 密钥合格且公网基址是有效 HTTPS URL 时，真人同意链路才进入 ready 状态。Provider 返回的 H5 URL 还必须使用 HTTPS，并命中渠道 Base URL host 或额外白名单。

## 3. 渠道配置

素材 profile 只允许配置在 DoubaoVideo 渠道，并要求单 Key。后台渠道表单中的关键字段为：

| 素材 profile | 必须搭配的视频 profile | 是否可用于视频 | 说明 |
| --- | --- | --- | --- |
| `ark_assets` | `third_party_reverse_proxy` | 是 | Ark 兼容普通素材与当前真人 H5 链路；精确的素材组删除合同未确认 |
| `relay_assets` | `third_party_relay` | 是 | 中转素材协议 |
| `joycreator_assets` | 按管理渠道配置 | 否 | 南向管理适配器；北向统一使用 `target=management_library` |
| `official_action_assets` | `official` | 是 | BytePlus 官方 Action；视频使用模型 API Key，素材使用独立 AK/SK |
| `none` | 任意 | 否 | 关闭该渠道素材能力 |

本地 TokenSave 渠道的已验证映射为：

| 渠道记录 | 视频配置 | 素材配置 | 只读素材测试 |
| --- | --- | --- | --- |
| `#27 Seedance 2.0 海外版(MOXING)` | `third_party_relay`，创建 `/v1/media/generations`，查询 `/v1/media/tasks/{task_id}` | `relay_assets` | `POST /assets/list`，每页 1 条 |
| `#28 Seedance 2.0 海外官 Key` | `third_party_reverse_proxy`，创建 `/v1/ark/media/generations`，查询 `/v1/ark/media/tasks/{task_id}` | `ark_assets` | `POST /v1/ark/assets/list`，每页 1 条 |

`#28` 还必须把公开模型 `doubao-seedance-2-0-260128` 映射为上游 `dreamina-seedance-2-0-260128`。两条渠道均只保存 TokenSave 平台 Key，不填写 BytePlus AK/SK。TokenSave `/v1/asset/*` 是 JoyCreator management-only facade 合同，不属于 `#27/#28`；当前 `joycreator_assets` 使用的是 `/joycreator/openApi/v1/asset/*` 直连合同，二者不能混配。若后续需要该 facade，必须建立独立 profile 和管理渠道，不得覆盖 `#27` 的 `relay_assets`。

每个启用的 profile 必须配置正数 `asset_min_url_ttl_seconds`。该值只能来自 Provider 已验证的抓取窗口，建议至少覆盖：

```text
最晚首次抓取 + 可能的重复抓取窗口 + 网络、队列和时钟偏差裕量
```

不要为了降低创建失败率随意填一个很小的值。TTL 只用于提前拒绝明显会过期的 URL，不证明 Provider 一定能够访问该 URL。

配置 `official_action_assets` 时必须额外填写 Provider Project、Provider Region、素材 Access Key ID 和素材 Secret Access Key。渠道主 Key 只填写视频模型 API Key，不能再填写 `AK|SK`。编辑已配置渠道时 AK/SK 留空表示保留；同时填写两项表示轮换。保存后在渠道编辑页分别执行“测试视频 API”和“测试素材 Action”：前者只读列出最多一个已有视频任务，后者只读调用 `ListAssets`，都不会创建或删除上游资源。界面持久显示两条链路各自的未测试、测试中、可用或失败状态。

`ark_assets` 与 `relay_assets` 保存后也会显示“测试素材库”：前者只读调用 `/v1/ark/assets/list`，后者只读调用 `/assets/list`。第三方视频协议没有已确认的免费列表接口，因此素材测试通过只证明素材 Base URL、平台 Key 和素材路由可用，视频模型与额度仍需单独验收。

TokenSave 文档把 `#28` 的素材组能力概括为查询、更新和删除，但没有公开可据此安全实现的精确删除方法与路径。当前 `ark_assets` 对未确认的素材组删除继续 fail closed；这不影响本阶段普通素材的创建、查询、改名、视频引用和素材删除，但在真人素材或要求自动清理素材组的生产场景中，必须先取得并验证精确合同。需要完整素材组生命周期时使用已验证的 `official_action_assets`。

第三方 profile 的 Base URL/Key，以及官方 profile 的 Action host/AK/SK/Project/Region都会进入相应凭据指纹。存在未删除的素材、素材组或真人授权时，系统会拒绝直接改变这些账号身份字段、清除素材凭据或删除渠道。正确流程是先停止新建、撤回授权并完成上游清理，再调整渠道。

清除独立 AK/SK 必须先把官方素材 profile 改为 `none` 并保存，再使用明确的“清除素材凭据”动作；留空保存只表示保留，系统不会隐式删除凭据。

历史渠道若曾把 `AK|SK` 写入主 Key 且已经产生存量官方素材记录，必须在停服和备份后使用 `cmd/migrate-official-asset-credential` 逐渠道迁移。命令默认只输出计划，`--apply` 会先执行只读 Action 校验，再以单事务同步更新独立凭据、模型 API Key、绑定、素材组、真人授权、所有权声明、对账指纹与对账 scope hash。密钥只能通过权限受控的标准输入文件提供；任何未知指纹或唯一索引冲突都必须回滚并停止上线。

## 4. 推荐上线顺序

1. 保持所有渠道的素材 profile 关闭，完成数据库迁移和相关服务测试。
2. 为单个测试渠道配置正确的视频 profile、素材 profile、单 Key 和最小 URL TTL；普通素材全局能力默认开启，但只有配置了兼容素材 profile 的渠道会参与注册。
3. 使用非敏感、私有且版本化的测试对象签发单对象 HTTPS GET URL。
4. 分别验证普通素材创建、轮询至 ready、改名、视频引用和删除。
5. 验证签名 URL、上游 ID、Key 和凭据指纹没有进入数据库可见业务字段、普通日志或错误响应。
6. 验证非公网目标、TTL 不足、model 不匹配、Key 改变和多素材无共同渠道均 fail closed。
7. 再扩大普通素材渠道范围。
8. 真人能力独立灰度；只有同意政策、H5 host、权威结果查询、撤回和删除全部通过后才开启 `real_person_enabled`。

官方 AK/SK 真人接口、缺少抓取合同的 Provider 或 management-only profile 不得因普通素材测试通过而自动进入视频路由集。

## 5. 最小验收请求

创建普通素材：

```http
POST /v1/assets
Authorization: Bearer <token>
Idempotency-Key: <unique-key>
Content-Type: application/json

{
  "name": "reference-image",
  "asset_kind": "general",
  "media_type": "image",
  "model": "<public-video-model>",
  "source": {
    "type": "url",
    "url": "https://customer-storage.example/object?signature=...",
    "expires_at": 1784700000
  }
}
```

成功接受后返回 HTTP 202、`ast_xxx` 和 `creating`、`create_unknown`、`processing` 或 `ready`。保存平台 ID；后续相同 model 的视频请求使用 `asset://ast_xxx`，不再提交源 URL。

创建真人授权：

```http
POST /v1/real-person-authorizations
Authorization: Bearer <token>
Content-Type: application/json

{
  "model": "<public-video-model>",
  "locale": "zh-CN"
}
```

调用方把返回的 `consent_url` 交给素材中的真人本人。只有授权状态成为 `authorized` 后，才可在创建 `real_person` 图片素材时提交该 `authorization_id`。浏览器返回或 callback 到达不等于授权成功，必须以平台主动查询 Provider 的最终结果为准。

## 6. 状态与处置

| 状态/错误 | 运维含义 | 处置 |
| --- | --- | --- |
| `processing` | 上游仍在处理 | 检查 `poll_binding` 是否持续运行，避免手工重复创建 |
| `create_unknown` | Create 结果不确定 | 使用同一幂等键只会返回原资源；等待 watchdog，不要换键盲重试 |
| `asset_creation_outcome_unknown` | 等待到期仍无法确认 | 记录潜在上游孤儿；客户需换幂等键重新创建 |
| `asset_url_ttl_insufficient` | URL 剩余有效期不足 | 重新签发更长 TTL 的单对象 URL |
| `asset_binding_required` | 没有匹配 model/账号的 active binding | 核对素材 model、渠道状态、profile 和共同渠道交集 |
| `asset_credential_changed` | 创建后的渠道账号身份发生变化 | 恢复原账号完成清理，或从客户源对象创建新素材 |
| `deletion_failed` | 上游删除重试耗尽 | 保持本地不可引用，排查 Provider 删除合同后显式重试 |
| `real_person_consent_required` | 真人授权未完成或已撤回 | 不得绕过；让真人完成同意/认证或重新创建授权 |
| `real_person_verification_rejected` | Provider 权威结果为拒绝 | 不允许创建真人素材；按业务流程重新发起独立授权 |

查询和错误输出会隐藏上游 ID 与原始 Provider 错误。排障应使用平台 asset/authorization ID、Job kind、状态和内部请求关联信息，不要临时增加完整 URL 或响应体日志。

## 7. 监控与告警

至少监控：

- 各 profile 的创建成功率、processing 时长和 `create_unknown` 比例；
- `AssetOperationJob` 的 pending/running/failed/dead 数量、租约过期和重试耗尽；
- `deletion_failed`、`orphan_suspected`、凭据指纹失效和渠道生命周期栅栏拒绝；
- 真人授权从 consent 到 authorized 的转化、过期/拒绝、轮询耗尽和撤回清理时长；
- `asset_url_ttl_insufficient`、非公网 URL 拒绝和 model/channel 不匹配；
- 日志、trace 和审计字段中是否出现 URL query、上游 ID 或凭据。

功能回滚优先关闭新建开关，并保留后台清理能力。不要通过停掉素材系统任务来回滚，否则 processing、删除和撤回记录会永久滞留。
