# BytePlus 官方视频与素材渠道配置操作指南

## 1. 适用范围

本文用于在管理后台配置一个同时支持以下能力的 BytePlus 官方渠道：

- 使用 ModelArk API Key 调用官方视频 Endpoint；
- 使用独立 Access Key ID / Secret Access Key 调用官方素材 Action；
- 通过统一的 `/v1/assets` 接口注册普通素材；
- 在后续视频请求中通过平台素材编号引用已注册素材。

一个渠道中包含两套南向凭据，两者不能混填：

| 用途 | 管理后台字段 | 凭据形式 |
| --- | --- | --- |
| 视频模型调用 | `Model API Key` | `ark-...` |
| 素材 Action 签名 | `Asset Access Key ID` + `Asset Secret Access Key` | AK 与 SK 两个独立字段 |

普通素材能力默认开启，不需要配置 `ASSET_LIBRARY_ENABLED`。本地 `ServerAddress=http://localhost:8100` 是平台 API 地址，也不是 BytePlus 上游地址。

### 1.1 与本地渠道 27/28 的关系

本地数据库中的 `27`、`28` 是渠道记录 ID；两条记录的渠道类型都是 `DoubaoVideo`（类型值 `54`），不能与渠道类型编号混淆。它们使用 TokenSave 的平台 Key，不使用本指南后续章节所述的 BytePlus 独立 AK/SK：

| 渠道记录 | TokenSave 南向视频合同 | TokenSave 南向素材合同 | 渠道配置 |
| --- | --- | --- | --- |
| `#27 Seedance 2.0 海外版(MOXING)` | `POST /v1/media/generations`、`GET /v1/media/tasks/{task_id}` | `POST /assets`、`GET /assets/{uuid}` 等 | `third_party_relay` + `relay_assets` |
| `#28 Seedance 2.0 海外官 Key` | `POST /v1/ark/media/generations`、`GET /v1/ark/media/tasks/{task_id}` | `/v1/ark/assets/*` | `third_party_reverse_proxy` + `ark_assets` |

渠道 `#28` 对外模型 `doubao-seedance-2-0-260128` 还需映射为 TokenSave 文档规定的上游模型 `dreamina-seedance-2-0-260128`。两条渠道的 `Base URL` 都是 `https://tokensave.pro`，`Channel.Key` 都是对应的 TokenSave 平台 Key，不能在这两条渠道填写 BytePlus AK/SK。

截至 2026-07-27，本地配置已校正为：

```text
#27
video_upstream_profile = third_party_relay
video_upstream_create_path = /v1/media/generations
video_upstream_query_path_template = /v1/media/tasks/{task_id}
asset_upstream_profile = relay_assets

#28
video_upstream_profile = third_party_reverse_proxy
video_upstream_create_path = /v1/ark/media/generations
video_upstream_query_path_template = /v1/ark/media/tasks/{task_id}
asset_upstream_profile = ark_assets
model mapping = doubao-seedance-2-0-260128 → dreamina-seedance-2-0-260128
```

TokenSave 的 `/v1/asset/*` 文档描述的是 JoyCreator 管理素材库，不参与视频素材路由，也不能代替渠道 `#27` 的 `/assets` 海外素材协议。当前 `joycreator_assets` 适配器实现的是已有的 JoyCreator 直连路径 `/joycreator/openApi/v1/asset/*`，不能把 TokenSave facade 当成同一路径直接配置。需要接入 TokenSave `/v1/asset/*` 时应新增独立的 management-only facade profile 和渠道；本次不得把 `#27` 从 `relay_assets` 改掉。

## 2. 当前测试资源与字段对应关系

当前测试资源应按下表映射到渠道表单。凭据值不得写入本文、代码、提交记录或截图。

| 已有资源 | 当前测试值或格式 | 填入位置 |
| --- | --- | --- |
| 对用户公开的模型名 | 例如 `seedance-byteplus` | `Models` |
| BytePlus Endpoint ID | `ep-20260623151323-jjcxw` | `Model Mapping` 的上游模型 |
| ModelArk API Key | `ark-...` | `Model API Key` |
| Provider Project | `huashu_4` | `Provider Project` |
| Access Key ID | 以 BytePlus 控制台实际值为准 | `Asset Access Key ID` |
| Secret Access Key | 以 BytePlus 控制台实际值为准 | `Asset Secret Access Key` |
| Provider Region | 必须从当前 Project/Endpoint 所在区域确认 | `Provider Region` |

Region 不应根据 Endpoint 名称或 Access Key 猜测。若 BytePlus 控制台确认当前资源位于 `ap-southeast-1`，则填写：

```text
ap-southeast-1
```

表单与后端只接受 BytePlus 当前使用的 Provider Region ID 结构（例如 `ap-southeast-1`、`eu-west-1`）；`a`、`123` 或 URL 都会被拒绝。

系统会根据 Region 自动生成素材 Action 地址：

```text
https://ark.<region>.byteplusapi.com
```

该 Action 地址不需要在表单中手工填写。

## 3. 配置前检查

开始前确认：

1. API 服务和 Web 管理端已经部署本次双凭据改造并重启；
2. 数据库迁移已创建 `channel_asset_credentials` 表；
3. BytePlus 账号已开通对应视频 Endpoint 和素材库权益；
4. Endpoint、Project、AK/SK 属于同一个 BytePlus 账号和 Project；
5. 当前使用单 Key 渠道，不使用批量新增或多 Key；
6. 已准备一个对用户公开的模型名，例如 `seedance-byteplus`；
7. 已确认 Provider Region；
8. 已确认素材源 URL 所需的最小有效时间。

## 4. 在管理后台新建渠道

进入“渠道管理”，点击“添加渠道”。

### 4.1 基本信息

| 表单字段 | 填写方式 |
| --- | --- |
| `Name` | 自定义容易识别的名称，例如 `seedance-byteplus-official` |
| `Type` | 选择 `DoubaoVideo` |
| `Group` | 选择允许使用该渠道的用户组，例如 `default` |
| `Add Mode` | 必须选择单 Key 模式 |
| `Status` | 选择启用 |

不要使用批量新增、多 Key 或轮询 Key 模式。官方素材账号绑定要求一个渠道只有一套确定的视频 Key 和一套确定的素材 AK/SK。

### 4.2 配置官方视频协议

| 表单字段 | 当前渠道填写方式 |
| --- | --- |
| `Video Upstream Profile` | 选择 `Official Protocol` |
| `API Address` / `Base URL` | BytePlus 官方视频 API 根地址 |
| `Model API Key` | 填写 `ark-...` 模型调用 Key |

BytePlus 国际站常用的视频 API 根地址示例：

```text
https://ark.ap-southeast.bytepluses.com
```

应以当前 BytePlus 控制台或官方文档显示的地址为准。不要填写：

- `http://localhost:8100`：这是平台 API；
- `http://localhost:3100`：这是 Web 管理端；
- `ACCESS_KEY|SECRET_KEY`：这是旧的错误混填方式；
- 素材 Action 地址：该地址由 Region 自动生成。

官方视频协议已经内置创建与查询路径，无需填写第三方 Create Path 或 Query Path。

### 4.3 配置模型与 Endpoint 映射

在 `Models` 中加入用户调用时使用的公开模型名，例如：

```text
seedance-byteplus
```

在 `Model Mapping` 中建立“公开模型名 → BytePlus Endpoint ID”的映射：

```json
{
  "seedance-byteplus": "ep-20260623151323-jjcxw"
}
```

方向不能写反：

```text
用户请求 model=seedance-byteplus
        ↓
上游请求 model=ep-20260623151323-jjcxw
```

如果填写 `Test Model`，也应选择左侧的公开模型名 `seedance-byteplus`，不能填写 Endpoint ID。

### 4.4 配置官方素材 Action

| 表单字段 | 填写方式 |
| --- | --- |
| `Asset Upstream Profile` | 选择 `Official Action Assets` |
| `Minimum Asset URL TTL (seconds)` | 填写经过验证的正整数 |
| `Asset Access Key ID` | 填写 BytePlus 素材 AK |
| `Asset Secret Access Key` | 填写 BytePlus 素材 SK |
| `Provider Project` | 当前测试渠道填写 `huashu_4` |
| `Provider Region` | 填写控制台确认的 Region，例如 `ap-southeast-1` |

AK 和 SK 必须同时填写，不能：

- 只填其中一项；
- 使用 `AK|SK` 拼接格式；
- 把 AK/SK 填入 `Model API Key`；
- 把 ModelArk API Key 填入素材 AK/SK。

`Minimum Asset URL TTL` 是平台接收素材时要求源 HTTPS URL 至少还可访问多少秒。生产值必须覆盖 Provider 最晚首次抓取、可能的重复抓取以及网络和时钟偏差。

如果目前只在测试环境验证链路，可以暂时填写：

```text
3600
```

这只表示测试素材 URL 在提交时至少还应有效 1 小时，不代表已确认生产抓取合同。上线前必须根据 BytePlus 实际要求复核。

### 4.5 保存

确认以下组合同时成立后保存：

```text
Type = DoubaoVideo
Video Upstream Profile = official
Asset Upstream Profile = official_action_assets
Add Mode = single
Model API Key = ark-...
Asset AK/SK = 两个独立字段
Provider Project = huashu_4
Provider Region = 控制台确认值
```

保存是原子操作。渠道或素材凭据任一部分校验失败时，两者都不会只保存一半。

## 5. 保存后分别测试两条链路

视频和素材使用不同凭据，必须分别测试。视频测试成功不能证明素材 AK/SK 可用，素材测试成功也不能证明视频 API Key 或 Endpoint 映射正确。

### 5.1 测试视频

保存渠道后重新打开编辑页面，在“连通性测试”区域点击“测试视频 API”。页面会独立显示“未测试 / 测试中 / 可用 / 失败”状态。

该操作使用模型 API Key 调用官方只读任务列表接口，最多读取一条已有任务，不会创建、取消或删除视频任务，也不会产生视频生成费用。

成功表示以下内容基本正确：

- 视频 API Base URL；
- ModelArk API Key；
- 官方视频任务接口可访问。

该只读测试不提交模型 Endpoint，因此不验证公开模型到 Endpoint ID 的映射。映射仍需通过一次受控的视频生成验收单独确认。如果失败，优先检查 `Model API Key` 和视频 API Base URL，不要修改素材 AK/SK。

### 5.2 测试素材 Action

在同一个“连通性测试”区域点击：

```text
Test Asset Action / 测试素材 Action
```

该操作只读调用 `ListAssets`，不会创建或删除上游素材。

成功表示以下内容基本正确：

- 素材 Access Key ID；
- 素材 Secret Access Key；
- Provider Project；
- Provider Region；
- BytePlus 素材库权限。

如果按钮不可点击，先检查：

1. 渠道是否已经成功保存；
2. `Asset Upstream Profile` 是否为 `Official Action Assets`；
3. 页面是否显示素材凭据“已配置”；
4. 当前是否正在输入一套尚未保存的新 AK/SK；
5. 是否存在尚未保存的 profile 变更。

输入新的模型 API Key 或素材 AK/SK 后，两个测试按钮不会消失，但对应按钮会暂时禁用并提示先保存。测试只使用已保存凭据，避免界面显示的草稿和服务端实际测试对象不一致。

### 5.3 测试渠道 27/28 的素材链路

编辑已保存的渠道 `#27` 或 `#28` 时，“连通性测试”区域会显示“素材库”卡片：

- `#27` 使用当前 TokenSave Key 对 `/assets/list` 发起 `page_size=1` 的只读请求；
- `#28` 使用当前 TokenSave Key 对 `/v1/ark/assets/list` 发起 `PageSize=1` 的只读请求。

测试不会创建、修改或删除素材。成功可以证明当前 Base URL、TokenSave Key 和对应素材路由可访问；不会证明指定模型一定有视频生成额度。第三方视频协议没有已确认的无费用列表接口，因此这里不伪造视频连通性探测，视频链路仍通过受控模型测试验收。

## 6. 注册普通素材

两项测试都通过后，在素材库中选择：

- 模型：`seedance-byteplus`；
- 类型：普通素材；
- 一个公网可访问的 HTTPS 素材 URL；
- URL 到期时间晚于当前时间，并满足渠道的 Minimum Asset URL TTL。

然后执行注册。成功后状态可能依次变化：

```text
creating → processing → ready
```

只有 `ready` 素材才能稳定用于视频生成。

如果之前失败的卡片一直显示“创建中”，先删除旧的本地占位，再用新的幂等键重新注册。不要反复复用一次失败请求的不同参数。

## 7. 编辑已有渠道

重新打开已配置渠道时：

- 素材 AK/SK 不会回显；
- 页面只显示“已配置”和脱敏后的 Access Key ID；
- 两个素材凭据字段都留空，表示保留现有 AK/SK；
- 同时填写新的 AK 和 SK，表示轮换整套素材凭据；
- 只填写其中一个字段会被拒绝。

需要彻底删除已保存的素材 AK/SK 时，必须执行显式清除：

1. 把 `Asset Upstream Profile` 改为 `No Asset Protocol`；
2. 保存渠道；
3. 重新打开编辑页，在“已存储的素材凭据”区域点击“清除素材凭据”并确认。

只把两个输入框留空不会删除凭据。系统也不会允许在 `Official Action Assets` 仍处于已保存启用状态时清除凭据，避免留下“profile 已启用但凭据不存在”的无效配置。

如果渠道存在未删除的素材、素材组、真人授权或相关所有权记录，系统会拒绝：

- 轮换 AK/SK；
- 修改 Project 或 Region；
- 改变素材账号身份相关配置；
- 清除素材凭据；
- 删除渠道。

正确操作顺序是停止新建、完成素材及授权清理，再修改凭据。

## 8. 存量旧渠道迁移

仅当旧版本曾把素材 `AK|SK` 写入 `Channel.Key`，并且该渠道已经存在官方素材绑定、素材组、真人授权、所有权声明或对账记录时，使用受控迁移命令。无存量资源的新渠道直接按本文第 4 节重新配置，不需要执行此命令。

迁移前必须：

1. 停止应用服务和新的素材创建；
2. 完成主数据库备份并验证可恢复；
3. 确认历史 `Channel.Key` 确实是本次提供的素材 AK/SK；
4. 确认 Project、Region 与旧资源属于同一 BytePlus 账号；
5. 准备新的模型 API Key。

把迁移输入保存在权限为 `0600` 的临时 JSON 文件中，禁止把密钥放到命令行参数、提交记录或普通日志：

```json
{
  "channel_id": 123,
  "model_api_key": "<new-model-api-key>",
  "asset_access_key_id": "<existing-asset-access-key-id>",
  "asset_secret_access_key": "<existing-asset-secret-access-key>",
  "expected_provider_project": "<saved-project>",
  "expected_region": "<saved-region>",
  "acknowledge_same_provider_account": true
}
```

先执行只读计划：

```bash
go run ./cmd/migrate-official-asset-credential < /secure/path/channel-123.json
```

确认输出的渠道 ID 和各类记录数量后再执行：

```bash
go run ./cmd/migrate-official-asset-credential --apply < /secure/path/channel-123.json
```

应用模式会先用所提供的 AK/SK 执行只读素材 `ListAssets` 校验，再在一个事务中写入独立凭据、替换视频模型 API Key，并同步迁移绑定、素材组、真人授权、所有权声明和对账指纹。任何未知指纹、唯一索引冲突或写入错误都会整体回滚。每条旧渠道分别执行；全部完成后删除临时凭据文件，正常启动服务，并重新执行视频 API 与素材 Action 双测试。

## 9. 地址不要混淆

| 地址 | 示例 | 用途 |
| --- | --- | --- |
| Web 管理端 | `http://localhost:3100` | 浏览器打开后台 |
| 平台 API / ServerAddress | `http://localhost:8100` | Web 调用 new-api |
| BytePlus 视频 Base URL | `https://ark.ap-southeast.bytepluses.com` | 视频创建与查询 |
| BytePlus 素材 Action host | `https://ark.<region>.byteplusapi.com` | 系统根据 Region 自动生成 |

因此，本地 Web 为 3100、API 为 8100 时，把平台服务器地址设置成 `http://localhost:8100` 是正确的；但渠道的 BytePlus `Base URL` 不能设置成 localhost。

## 10. 常见错误

| 现象或错误 | 主要原因 | 处理 |
| --- | --- | --- |
| HTTP 409 `asset_binding_required` | 没有与请求模型兼容的单 Key 素材渠道 | 检查渠道启用状态、用户组、Models、模型映射和两个 profile |
| `no compatible single-key asset channel` | 渠道是多 Key，或没有配置完整素材 profile | 改为单 Key，并补齐官方素材字段 |
| HTTP 503 `asset_upstream_unavailable` | 无可用素材渠道、动态开关关闭或上游不可用 | 检查 `asset_setting.enabled`、渠道状态和素材 Action 测试 |
| `video_api_upstream_rejected` | ModelArk API Key 或视频 Base URL 被上游拒绝 | 只检查视频凭据和地址；Endpoint 映射需通过生成验收确认 |
| `asset_action_upstream_rejected` | AK/SK、Project、Region 或素材权限被上游拒绝 | 只检查素材凭据，不要替换视频 API Key |
| `asset_upstream_rejected` | TokenSave Key 无效、无素材权限或素材 profile/路径不匹配 | 检查渠道 27/28 的 TokenSave Key、Base URL 和 profile 组合 |
| `asset_credential_profile_active` | 在官方素材 profile 仍启用时请求清除 AK/SK | 先把素材 profile 改为 `none` 并保存，再执行显式清除 |
| `asset_url_ttl_insufficient` | 源 URL 剩余时间小于渠道要求 | 重新签发有效时间更长的 URL |
| `asset_credential_changed` | 活动素材绑定的账号身份与当前配置不同 | 恢复原配置完成清理，或重新创建素材 |
| 日志出现 `record not found` | 后台暂时没有待执行 Job，或幂等记录首次查询为空 | 结合最终 HTTP 状态判断；该日志本身通常不是失败根因 |
| 页面一直显示“注册中” | 客户端没有清除失败请求的本地占位 | 查看 POST `/v1/assets` 最终状态，删除占位并修正配置后重试 |

## 11. 安全要求

- 不在文档、代码、Issue、聊天记录或截图中保存完整 API Key、AK、SK；
- 不通过渠道详情接口读取素材 Secret Access Key；
- 不把 AK/SK 放进 `Other Settings` JSON；
- 不在日志中临时打印渠道对象、签名请求头或完整上游响应；
- 轮换凭据前必须确认没有活动素材资源；
- 复制渠道后必须重新配置素材 AK/SK，系统不会复制敏感凭据。

- [ ] 普通素材可以从 `creating/processing` 进入 `ready`。
- [ ] `ready` 素材能够用于同一公开模型的视频生成。
- [ ] 素材删除后不能再被新视频引用。
