# 价格设置与倍率说明

## 1. 文档目标

本文统一说明平台的价格设计、全部计费倍率之间的关系，以及管理端、模型广场、充值页和用量日志应如何展示价格。

适用对象：

- 产品与商务：确定售卖价格、分组折扣和充值策略。
- 运营与管理员：配置模型价格、动态表达式、分组倍率和工具价格。
- 研发与测试：核对预扣、结算、日志及前端展示是否使用同一计费口径。

本文只说明平台价格体系。特定模型或渠道的独立价格表，继续以对应的渠道配置文档为准。

## 2. 核心结论

1. 平台有三种互斥的模型计费模式：**按 Token 倍率计费、按次固定价格、动态表达式计费**。
2. 模型价格决定“基础价”，有效分组倍率决定“当前用户实际支付基础价的多少倍”。
3. 用户专属分组倍率会**覆盖**普通分组倍率，不会与普通分组倍率再次相乘。
4. 缓存、图片、音频等倍率都以模型输入价格为基准；音频输出是“输入基价 × 音频输入倍率 × 音频输出倍率”。
5. `OtherRatios` 是请求级附加倍率，主要表示图片数量、视频时长、分辨率、质量等，多个附加倍率相乘。
6. `TopupGroupRatio`、充值档位折扣和支付渠道单价只影响充值付款，不参与模型调用扣费。
7. `QuotaPerUnit` 是“1 美元对应多少内部额度”的换算系数，不是模型售价；用户看到的货币价格必须由同一换算口径生成。
8. 预扣只是冻结额度，最终应按上游实际用量和请求开始时冻结的计费快照结算。
9. 面向用户的主展示应是**实际价格**，倍率只作为解释信息；不能要求普通用户自行连乘倍率。

## 3. 三层价格模型

平台价格应分成三层理解。

| 层级 | 解决的问题 | 主要配置 |
| --- | --- | --- |
| 模型基础价格 | 这个模型本身多少钱 | `ModelRatio`、`ModelPrice`、`BillingExpr` |
| 消费调整 | 当前用户、分组、请求规格实际付多少 | `GroupRatio`、`GroupGroupRatio`、`OtherRatios`、工具附加费 |
| 充值与展示 | 用户花多少钱获得额度、页面用什么币种展示 | `Price`、`TopupGroupRatio`、充值档位折扣、`QuotaPerUnit`、展示汇率 |

这三层不能混用：

- 模型降价应改模型基础价格或消费分组倍率。
- VIP 充值优惠应改充值倍率或充值档位折扣。
- 币种切换只改变展示，不应改变内部扣费结果。

## 4. 基础概念

### 4.1 内部额度与美元

内部额度通过 `QuotaPerUnit` 与美元费用换算：

```text
内部额度 = 美元费用 × QuotaPerUnit
美元费用 = 内部额度 ÷ QuotaPerUnit
```

系统默认：

```text
QuotaPerUnit = 500000
```

即：

```text
$1 = 500000 内部额度
```

`QuotaPerUnit` 同时参与余额展示、预扣和结算。修改它会影响所有“额度 ↔ 美元”的换算，必须作为全局迁移处理，不能只当作普通前端显示项修改。

### 4.2 公开模型名

所有价格应配置在客户端请求使用的**公开模型名**上，而不是渠道映射后的上游模型名上。计费入口使用请求的原始公开模型名查找模型价格。

### 4.3 实际计费分组

一次请求使用的计费分组可能来自：

1. API Key 选择的普通分组；
2. 用户分组回退；
3. `auto` 按可用渠道最终选中的分组。

`auto` 只是选择分组的机制，本身没有额外倍率。真正参与计费的是最终选中的实际分组。

## 5. 三种模型计费模式

### 5.1 模式选择优先级

对同一个模型，系统按以下优先级选择计费模式：

```text
BillingMode[模型] == "tiered_expr" 且存在有效 BillingExpr
  → 动态表达式计费

否则，ModelPrice[模型] 存在
  → 按次固定价格

否则，ModelRatio[模型] 存在
  → 按 Token 倍率计费

以上都不存在
  → 价格未配置；除自用模式或显式允许外，请求被拒绝
```

动态表达式启用后，`ModelPrice` 和 `ModelRatio` 即使仍有历史值也不参与该模型计费。

### 5.2 按 Token 倍率计费

该模式使用 `ModelRatio` 作为输入 Token 的基础倍率，再叠加输出、缓存、图片、音频及分组倍率。

在默认 `QuotaPerUnit = 500000` 下：

```text
输入价格（$/1M Token） = ModelRatio × 2
```

例如：

```text
ModelRatio = 1.5
输入价格 = $3 / 1M Token
```

更一般的内部换算公式为：

```text
输入价格（$/1M Token） = 1,000,000 × ModelRatio ÷ QuotaPerUnit
```

因此，现有前端使用的 `ModelRatio × 2` 展示公式依赖 `QuotaPerUnit = 500000`。只要继续使用传统倍率计费，就应保持这个基准不变；如确需修改 `QuotaPerUnit`，必须同步改造所有价格展示公式并完成余额迁移验证。

普通文本请求的核心计算可以概括为：

```text
基础输入 Token =
  输入 Token
  - 单独计价的缓存读取 Token
  - 单独计价的缓存写入 Token
  - 单独计价的图片 Token
  - 使用独立美元价计费的音频 Token

加权 Token =
  基础输入 Token
  + 缓存读取 Token × CacheRatio
  + 缓存写入 Token × CreateCacheRatio
  + 图片输入 Token × ImageRatio
  + 输出 Token × CompletionRatio

基础额度 =
  加权 Token × ModelRatio × 有效分组倍率

最终额度 =
  （基础额度 + 工具附加费额度 + 独立音频费用额度）
  × 所有请求级 OtherRatios
```

系统会避免同一类 Token 同时计入基础输入和单独计价项。

### 5.3 按次固定价格

`ModelPrice` 表示一次请求的基础美元价：

```text
基础美元费用 = ModelPrice
最终美元费用 = ModelPrice × 有效分组倍率 × ∏OtherRatios
最终额度 = 最终美元费用 × QuotaPerUnit
```

适合：

- 图片生成；
- 视频或异步任务；
- 每次调用成本基本固定的接口；
- 上游按张、按段、按任务收费的模型。

图片请求可能先通过 `ImagePriceRatio` 按尺寸和质量调整 `ModelPrice`，再通过 `OtherRatios["n"]` 乘以生成数量。

如果异步任务没有明确配置 `ModelPrice`，系统部分兼容路径会用 `ModelRatio / 2` 估算按次预扣。该路径只用于兼容，不应作为正式商业定价方案；生产模型应明确配置固定价或动态表达式。

### 5.4 动态表达式计费

动态表达式中的价格系数直接填写供应商公布的真实美元价，单位为 `$/1M Token`，不使用传统的 `/2` 倍率换算。

示例：

```text
tier("base", p * 3 + c * 15 + cr * 0.3)
```

含义：

- 输入：`$3 / 1M Token`
- 输出：`$15 / 1M Token`
- 缓存读取：`$0.3 / 1M Token`

计算公式：

```text
表达式原始结果 =
  各 Token 数 × 各自的 $/1M 系数之和

表达式美元费用 =
  表达式原始结果 ÷ 1,000,000

最终额度 =
  表达式美元费用 × QuotaPerUnit × 有效分组倍率
```

表达式变量：

| 变量 | 含义 |
| --- | --- |
| `p` | 未被其他变量单独计价的输入 Token |
| `c` | 未被其他变量单独计价的输出 Token |
| `len` | 完整输入上下文长度，只用于条件判断，不因子类别拆分而减少 |
| `cr` | 缓存读取 Token |
| `cc` | 通用或 5 分钟缓存创建 Token |
| `cc1h` | 1 小时缓存创建 Token |
| `img` | 图片输入 Token |
| `img_o` | 图片输出 Token |
| `ai` | 音频输入 Token |
| `ao` | 音频输出 Token |

分档条件必须使用 `len` 判断上下文长度：

```text
len <= 200000
  ? tier("standard", p * 3 + c * 15 + cr * 0.3)
  : tier("long_context", p * 6 + c * 22.5 + cr * 0.6)
```

不能用扣除了缓存后的 `p` 判断长上下文档位。

请求条件可读取请求体、请求头和时间，并对表达式结果应用请求级规则。完整语法见[表达式计费系统设计](../../pkg/billingexpr/expr.md)。

异步任务使用表达式计费时还必须配置该模型的“异步任务预扣 Token 上界”。异步任务预扣与终态会分别执行表达式，因此禁止使用未冻结的请求头和时间函数，以保证两次计算确定一致。

## 6. 全部倍率及关系

### 6.1 倍率总表

| 配置或运行时字段 | 作用范围 | 基准 | 默认/缺省 | 与其他倍率的关系 |
| --- | --- | --- | --- | --- |
| `ModelRatio` | 按 Token 模型 | 输入 Token | 未配置时模型不可用；自用模式有兼容回退 | 传统计费的总基础倍率 |
| `CompletionRatio` | 输出文本 Token | 输入 Token 价格 | 通常为 `1`，部分模型由代码规则锁定 | 与 `ModelRatio`、有效分组倍率相乘 |
| `CacheRatio` | 缓存读取 Token | 输入 Token 价格 | 未配置时计算回退为 `1` | 与 `ModelRatio`、有效分组倍率相乘 |
| `CreateCacheRatio` | 缓存创建 Token | 输入 Token 价格 | 未配置时计算回退为 `1.25` | 5 分钟写入使用该值；1 小时写入为该值 × `1.6` |
| `ImageRatio` | 图片输入 Token | 输入 Token 价格 | 未配置时计算回退为 `1` | 与 `ModelRatio`、有效分组倍率相乘 |
| `AudioRatio` | 音频输入 Token | 输入 Token 价格 | 未配置时为 `1` | 音频输入价的基础倍率 |
| `AudioCompletionRatio` | 音频输出 Token | 音频输入价格 | 未配置时为 `1` | 音频输出需同时乘 `AudioRatio` |
| `GroupRatio` | 某个实际计费分组 | 模型基础费用 | 分组不存在时回退为 `1` | 与模型基础费用相乘 |
| `GroupGroupRatio` | 用户分组 × 实际计费分组 | 模型基础费用 | 未配置时不生效 | **覆盖** `GroupRatio`，不是再乘一次 |
| `OtherRatios` | 单次请求 | 当前请求基础费用 | 没有时为 `1` | 多个值连乘，常见为数量、时长、分辨率、质量 |
| `ImagePriceRatio` | 固定价图片请求 | `ModelPrice` | 没有时不调整 | 先调整单张基础价，再乘图片数量 |
| `TopupGroupRatio` | 充值付款 | 充值金额 | 未配置时为 `1` | 只影响充值，不影响调用扣费 |
| 充值档位折扣 | 指定充值档位 | 应付金额 | 未配置时为 `1` | 与支付单价、充值倍率相乘 |
| `Price` / 支付渠道单价 | 充值付款 | 购买的额度或美元信用 | 按支付渠道配置 | 不是消费倍率 |
| `QuotaPerUnit` | 全局额度换算 | 美元费用 | 默认 `500000` | 把美元费用转换为内部额度 |

### 6.2 各类 Token 的实际价格

以下公式适用于传统按 Token 倍率计费，且默认 `QuotaPerUnit = 500000`。

设：

```text
P_in = ModelRatio × 2
G = 有效分组倍率
```

则用户实际单价为：

| 项目 | 用户实际价格 |
| --- | --- |
| 文本输入 | `P_in × G` |
| 文本输出 | `P_in × CompletionRatio × G` |
| 缓存读取 | `P_in × CacheRatio × G` |
| 缓存创建（通用/5 分钟） | `P_in × CreateCacheRatio × G` |
| 缓存创建（1 小时） | `P_in × CreateCacheRatio × 1.6 × G` |
| 图片输入 | `P_in × ImageRatio × G` |
| 音频输入 | `P_in × AudioRatio × G` |
| 音频输出 | `P_in × AudioRatio × AudioCompletionRatio × G` |

单位均为 `$/1M Token`。

### 6.3 有效分组倍率优先级

```text
如果 GroupGroupRatio[用户分组][实际计费分组] 存在：
  有效分组倍率 = GroupGroupRatio[用户分组][实际计费分组]
否则：
  有效分组倍率 = GroupRatio[实际计费分组]
```

示例：

```json
{
  "GroupRatio": {
    "default": 1,
    "economy": 0.8
  },
  "GroupGroupRatio": {
    "vip": {
      "economy": 0.6
    }
  }
}
```

结果：

- 普通用户使用 `economy`：倍率为 `0.8`。
- `vip` 用户使用 `economy`：倍率为 `0.6`。
- `vip` 的最终倍率不是 `0.8 × 0.6 = 0.48`。

### 6.4 请求级附加倍率

`OtherRatios` 表示请求规格相对基础价的变化：

```text
附加倍率总乘数 = ratio1 × ratio2 × ... × ratioN
```

常见键：

| 键 | 典型含义 |
| --- | --- |
| `n` | 图片或结果数量 |
| `seconds` | 视频时长 |
| `size` | 分辨率或画幅 |
| `quality` | 质量档位 |
| `prompt_extend` | 特定上游的提示词扩展附加倍率 |

这些倍率由请求校验和 Provider 适配器生成，不应由前端自由提交任意值。系统只接受大于 `0` 且有限的倍率，避免负数、`NaN` 或无穷值污染计费。

### 6.5 工具与独立附加费

以下价格不是模型倍率，而是额外美元费用：

- Web Search：通常按 `$/1K 次调用` 配置；
- File Search：通常按 `$/1K 次调用` 配置；
- 图片生成工具调用：按质量和尺寸的单次美元价；
- 部分 Gemini 音频输入：按模型对应的独立 `$/1M Token` 价格。

计算后再乘有效分组倍率并转换为内部额度。工具价格应在“模型定价 → 工具价格”中单独维护，不要折算进 `ModelRatio`。

### 6.6 充值倍率

普通充值链路可概括为：

```text
应付金额 =
  购买数量
  × 支付渠道单价
  × TopupGroupRatio[用户分组]
  × 充值档位折扣
```

其中：

- `TopupGroupRatio < 1`：该用户分组充值更便宜；
- `TopupGroupRatio > 1`：该用户分组充值更贵；
- 充值档位折扣只匹配配置的购买数量；
- Stripe、Waffo 等支付渠道使用各自单价，不能假设都使用全局 `Price`。

充值倍率与消费分组倍率相互独立。例如 VIP 充值九折、调用八折，应分别配置：

```text
TopupGroupRatio[vip] = 0.9
有效消费分组倍率 = 0.8
```

## 7. 缓存与多模态 Token 的去重规则

不同上游的 usage 语义不同：

- OpenAI/GPT 语义的 `prompt_tokens` 通常包含文本、缓存、图片和音频子项；
- Claude 语义的 `input_tokens` 通常只表示文本，缓存另行返回。

传统计费与表达式计费都会按 usage 语义做归一化：

1. 子类别被单独计价时，从 OpenAI/GPT 的基础输入 Token 中扣除；
2. Claude 语义不重复扣除已经分离的缓存；
3. 表达式没有引用某个子类别变量时，该子类别继续留在 `p` 或 `c` 中按基础价格计费；
4. 缓存读取和缓存写入出现重叠、导致基础输入为负时，基础输入按 `0` 处理，不能产生负费用。

这保证同一个 Token 不会因“总量字段 + 明细字段”同时存在而重复收费。

## 8. 预扣、结算与计费快照

### 8.1 同步请求

```text
请求进入
  → 按估算输入和 max_tokens 预扣
  → 上游返回实际 usage
  → 按实际 usage 重新计算
  → 多退少补并写入用量日志
```

动态表达式请求会在预扣时冻结：

- 表达式正文与哈希；
- 表达式版本；
- `QuotaPerUnit`；
- 有效分组倍率；
- 估算 Token 与命中档位；
- 计费需要的请求体和请求头上下文。

因此，请求执行期间管理员修改价格，不应改变这次请求的最终结算规则。

### 8.2 异步任务

异步任务应冻结提交时的价格、分组倍率和请求规格，并在终态 usage 返回后结算。

动态表达式任务必须：

- 配置可信的预扣 Token 上界；
- 用实际 Token 做终态结算；
- 禁止使用未冻结的时间和 Header 条件；
- 实际用量缺失时保持预扣，不可猜测或反向生成费用；
- 预扣不足产生欠款状态时进入人工处理，而不是静默少扣。

### 8.3 免费模型

`ModelRatio = 0`、`ModelPrice = 0`、表达式结果为 `0` 或有效分组倍率为 `0` 都可能形成免费请求。

当“免费模型预扣”关闭时，系统对零价格或零分组倍率跳过预扣。管理端和模型广场应明确显示“免费”，不要显示空白或错误地回退成 `1x`。

## 9. 管理端如何配置与展示

入口：

```text
系统设置 → 计费
```

### 9.1 额度与展示

“币种与展示”页负责：

- `QuotaPerUnit`；
- 美元、人民币、自定义币种或仅额度展示；
- 美元到展示币种的汇率；
- 是否展示 Token 统计。

界面要求：

- 明确标注 `QuotaPerUnit` 为“1 美元对应的内部额度”；
- 展示修改风险提示；
- 同时显示示例：`$1 = N 额度`；
- 汇率只改变显示币种，不改变模型美元基础价；
- `TOKENS` 模式显示内部额度时，不再附加货币符号。

### 9.2 模型定价

“模型定价”页应以模型为行，展示：

| 列 | 展示内容 |
| --- | --- |
| 模型 | 公开模型名 |
| 计费模式 | 按 Token / 按次 / 动态表达式 |
| 输入 | 实际 `$/1M` 基础价 |
| 输出 | 实际 `$/1M` 基础价 |
| 缓存读取 | 有配置时显示 |
| 分档 | 动态表达式的档位数量或主要档位 |
| 状态 | 已配置、未配置、表达式无效 |

编辑器提供三种模式。

#### 按 Token

管理员输入实际价格，而不是手算倍率：

```text
输入价格 $/1M
输出价格 $/1M
缓存读取价格 $/1M
缓存写入价格 $/1M
图片输入价格 $/1M
音频输入价格 $/1M
音频输出价格 $/1M
```

界面内部换算：

```text
ModelRatio = 输入价格 ÷ 2
CompletionRatio = 输出价格 ÷ 输入价格
CacheRatio = 缓存读取价格 ÷ 输入价格
CreateCacheRatio = 缓存写入价格 ÷ 输入价格
ImageRatio = 图片输入价格 ÷ 输入价格
AudioRatio = 音频输入价格 ÷ 输入价格
AudioCompletionRatio = 音频输出价格 ÷ 音频输入价格
```

当输入价格为 `0` 时，依赖除法的倍率不能自动推导，界面应要求直接配置免费项目或切换到表达式计费，不能产生无穷值。

#### 按次

只要求：

```text
ModelPrice：$/次
```

如果请求还会按数量、时长、分辨率或质量变化，应在界面中提示这些规格由 Provider 适配器的请求级倍率处理。

#### 动态表达式

编辑器应提供：

- 可视化档位编辑；
- 原始表达式编辑；
- 输入、输出、缓存、图片、音频价格列；
- `len` 条件和请求条件；
- Token 与请求参数试算器；
- 命中档位、美元费用和内部额度预览；
- 异步任务预扣 Token 上界；
- 保存前编译和非负结果校验。

管理员看到的表达式价格单位始终是 `$/1M Token`。

### 9.3 分组定价

“分组定价”页应分成四块：

1. 分组基础倍率 `GroupRatio`；
2. 充值倍率 `TopupGroupRatio`；
3. 用户分组 × 计费分组专属覆盖 `GroupGroupRatio`；
4. 自动分组顺序、可选分组和特殊可用分组。

分组主表建议列：

| 分组 | 消费倍率 | 充值倍率 | 用户可选 | 说明 |
| --- | ---: | ---: | --- | --- |
| default | 1.00x | 1.00x | 是 | 标准 |
| economy | 0.80x | 1.00x | 是 | 低价线路 |
| premium | 1.20x | 0.95x | 是 | 高质量线路 |

专属覆盖规则必须使用“覆盖为”文案：

```text
VIP 用户使用 economy 时，消费倍率覆盖为 0.60x
```

不能写成容易误解的“额外 0.60x”。

### 9.4 原始 JSON 与倍率暴露

可视化编辑器是默认入口，同时保留 JSON 模式用于批量维护和迁移。

`ExposeRatioEnabled` 只控制倍率配置接口是否向外暴露，不应改变模型广场的正常价格接口，也不参与计费。开启前应提示可能泄露站点的完整定价结构。

## 10. 面向用户的价格展示

### 10.1 模型广场列表与卡片

模型广场应优先展示最终可理解价格：

- 按 Token：`输入 $X / 输出 $Y / 1M Token`；
- 按次：`$X / 次`；
- 动态表达式：主要档位的输入/输出价格，并显示“共 N 档”；
- 缓存价存在时单独显示“缓存读取”；
- 使用徽标区分“按 Token”“按次”“动态价格”。

当用户未选择分组时，当前实现会显示该用户可用分组中的最低价格。界面必须加“最低可用价”或“起”标识，避免用户误认为所有分组都是这个价格。

当用户选择分组筛选时，应展示该分组的准确价格，并显示分组倍率。

### 10.2 模型详情

模型详情应分三层：

1. **基础价格**：不乘分组倍率；
2. **分组价格**：按每个可用分组展开实际价格；
3. **计费说明**：单位、动态档位条件、请求规则和可能的附加费用。

传统按 Token 模型的分组价格表：

| 分组 | 倍率 | 输入 | 输出 | 缓存读取 | 缓存写入 | 图片 | 音频输入 | 音频输出 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

动态表达式模型按“分组 → 档位 → 各 Token 类型价格”展示。

分组倍率为 `0` 时必须显示 `0x` 和“免费”，不能使用 `ratio || 1` 一类回退逻辑将其错误显示为 `1x`。

### 10.3 标准价与充值价

模型广场可提供：

- **标准价**：模型美元费用按当前展示币种汇率换算；
- **充值价**：按充值购买成本折算的等效价格。

当前“充值价”计算主要使用全局充值单价与汇率。若用户分组还有 `TopupGroupRatio` 或命中充值档位折扣，最终收银台金额可能不同。因此：

- 列表中的充值价应标注“估算”；
- 最终价格以充值订单确认页为准；
- 若要展示精确充值价，必须同时纳入用户充值倍率、支付渠道单价和档位折扣。

### 10.4 币种与单位

界面允许：

- `/1M Token` 与 `/1K Token` 切换；
- USD、CNY、自定义货币和内部额度切换；
- 小价格保留足够精度，不能因四舍五入显示成 `0`；
- 所有价格同时显示单位，禁止只显示裸数字。

动态表达式里的系数仍以美元保存，币种转换只发生在展示层。

## 11. 用量日志如何展示

每条消费日志应使用请求结算时写入的计费快照，而不是读取当前最新配置。

基础字段：

- 计费模式；
- 公开模型名；
- 实际计费分组；
- 普通分组倍率或用户专属倍率；
- 输入、输出及各类 Token；
- 最终扣除额度和货币费用；
- 管理员可见的计费路径与额度饱和审计信息。

### 11.1 按 Token 日志

展示：

- 输入单价；
- 输出单价；
- 实际出现时才展示缓存读取、缓存写入、图片和音频价格；
- 请求级数量、时长、分辨率等附加倍率；
- 工具调用次数和单独附加费；
- 有效分组倍率；
- 最终费用。

音频输出的展示公式必须与后端一致：

```text
音频输出价格 =
  输入价格 × AudioRatio × AudioCompletionRatio
```

不能只乘 `AudioCompletionRatio`。

### 11.2 按次日志

展示：

- 单次模型基础价；
- 有效分组倍率；
- 数量、时长、分辨率、质量等请求级倍率；
- 调整前与调整后的实际单次费用；
- 最终费用。

### 11.3 动态表达式日志

日志保存：

- `billing_mode = tiered_expr`；
- Base64 编码的冻结表达式；
- 实际命中档位；
- 各 Token 类型价格；
- 是否跨越预估档位；
- 最终费用。

普通用户看到结构化价格表和命中档位；管理员可额外查看原始表达式、计费路径和异常审计信息。

## 12. 完整计算示例

### 12.1 传统按 Token 模型

配置：

```text
ModelRatio = 1.5
CompletionRatio = 5
CacheRatio = 0.1
CreateCacheRatio = 1.25
ImageRatio = 0.8
GroupRatio[economy] = 0.8
QuotaPerUnit = 500000
```

基础价格：

```text
输入 = 1.5 × 2 = $3/M
输出 = $3 × 5 = $15/M
缓存读取 = $3 × 0.1 = $0.3/M
缓存写入 = $3 × 1.25 = $3.75/M
图片输入 = $3 × 0.8 = $2.4/M
```

`economy` 分组实际价格：

```text
输入 = $2.4/M
输出 = $12/M
缓存读取 = $0.24/M
缓存写入 = $3/M
图片输入 = $1.92/M
```

一次请求使用：

```text
纯文本输入 800000 Token
缓存读取 200000 Token
输出 100000 Token
```

美元费用：

```text
800000/1M × $3 × 0.8
+ 200000/1M × $0.3 × 0.8
+ 100000/1M × $15 × 0.8
= $3.168
```

内部额度：

```text
$3.168 × 500000 = 1584000
```

### 12.2 用户专属覆盖

继续使用上例，增加：

```text
GroupGroupRatio[vip][economy] = 0.6
```

VIP 用户的同一请求：

```text
费用 = 未乘分组的模型费用 × 0.6
```

不会先乘 `0.8` 再乘 `0.6`。

### 12.3 按次图片模型

配置：

```text
ModelPrice = $0.04/张
ImagePriceRatio = 1.5
OtherRatios["n"] = 4
有效分组倍率 = 0.8
```

费用：

```text
$0.04 × 1.5 × 4 × 0.8 = $0.192
```

内部额度：

```text
$0.192 × 500000 = 96000
```

### 12.4 动态表达式模型

表达式：

```text
len <= 200000
  ? tier("standard", p * 3 + c * 15 + cr * 0.3)
  : tier("long", p * 6 + c * 22.5 + cr * 0.6)
```

请求：

```text
完整上下文 len = 300000
纯文本输入 p = 50000
缓存读取 cr = 250000
输出 c = 10000
有效分组倍率 = 0.8
```

命中 `long`：

```text
表达式原始结果 =
  50000 × 6
  + 10000 × 22.5
  + 250000 × 0.6
  = 675000

表达式美元费用 = 675000 / 1M = $0.675
最终美元费用 = $0.675 × 0.8 = $0.54
最终额度 = $0.54 × 500000 = 270000
```

## 13. 推荐配置流程

### 13.1 新增普通文本模型

1. 确认供应商输入、输出、缓存和多模态的真实美元价格。
2. 在“模型定价”新增公开模型名。
3. 选择“按 Token”。
4. 直接填写各类 `$/1M Token` 价格。
5. 检查界面换算出的倍率预览。
6. 配置模型可用渠道与分组。
7. 在模型广场核对基础价、最低价和指定分组价。
8. 发起包含输入和输出 Token 的最小请求，在用量日志核账。

### 13.2 新增按次图片或任务模型

1. 确认基础规格的单次美元价。
2. 配置 `ModelPrice`。
3. 确认适配器是否按数量、尺寸、质量、时长和分辨率生成 `OtherRatios`。
4. 对所有可选规格做价格矩阵测试。
5. 验证预扣、提交后规格修正、终态结算和退款。

### 13.3 新增动态或阶梯模型

1. 选择“动态表达式”。
2. 系数直接填写供应商的 `$/1M Token` 价格。
3. 每个价格分支用 `tier(name, value)` 包裹。
4. 长上下文条件使用 `len`。
5. 使用试算器覆盖每个档位和请求条件。
6. 异步任务配置最坏情况下的预扣 Token 上界。
7. 保存前通过编译和非负结果校验。
8. 小流量验证预估档位、实际档位和最终日志。

### 13.4 配置用户折扣

选择方式：

| 需求 | 推荐配置 |
| --- | --- |
| 所有用户的某个模型统一降价 | 修改模型基础价格 |
| 某条渠道分组统一打折 | 修改 `GroupRatio` |
| 只有 VIP 使用某个分组时打折 | 配置 `GroupGroupRatio` |
| VIP 充值更便宜 | 配置 `TopupGroupRatio` |
| 指定充值金额优惠 | 配置充值档位折扣 |

当前分组场景见 [01 计费与分组运维手册](../40-operations/01-计费与分组运维手册.md)。

## 14. 上线验收清单

### 14.1 配置正确性

- [ ] 价格配置在公开模型名上。
- [ ] 每个模型只启用一种主计费模式。
- [ ] 按 Token 模型的输入、输出、缓存和多模态实际价格正确。
- [ ] 动态表达式每个分支都有 `tier()`。
- [ ] 长上下文条件使用 `len`。
- [ ] 异步表达式已配置预扣 Token 上界。
- [ ] 工具价格与模型价格分开配置。

### 14.2 倍率正确性

- [ ] 普通分组使用 `GroupRatio`。
- [ ] 用户专属规则覆盖而不是叠乘 `GroupRatio`。
- [ ] 音频输出同时乘 `AudioRatio` 和 `AudioCompletionRatio`。
- [ ] 多个 `OtherRatios` 使用乘积。
- [ ] 充值倍率没有进入消费扣费公式。
- [ ] `0x` 分组和免费模型没有被前端回退成 `1x`。

### 14.3 展示正确性

- [ ] 所有价格带币种和 `/1M`、`/1K` 或 `/次` 单位。
- [ ] 未选择分组时的最低价有“起”或“最低可用价”标识。
- [ ] 指定分组后显示该分组的准确价格。
- [ ] 动态模型展示全部档位、条件和请求规则。
- [ ] 充值价标明是估算还是最终收银台价格。
- [ ] 小价格没有因精度不足显示成 `0`。

### 14.4 结算与日志

- [ ] 预扣后按实际 usage 结算。
- [ ] 价格变更不会影响已开始请求的冻结快照。
- [ ] 缓存和多模态 Token 没有重复计费。
- [ ] 用量日志显示有效分组倍率和最终费用。
- [ ] 动态日志显示实际命中档位。
- [ ] 管理员能查看计费路径和额度饱和异常。
- [ ] 异步任务覆盖成功、失败、取消、超时、退款和欠款状态。

## 15. 当前实现需要持续保持一致的展示口径

以下项目是价格页面、用量日志和后端公式之间的关键一致性边界：

1. 传统价格页的 `ModelRatio × 2` 依赖默认 `QuotaPerUnit = 500000`。
2. 任意分组倍率读取都必须保留合法的 `0`，不能用布尔回退将 `0` 当作未配置。
3. 音频输出展示必须使用 `AudioRatio × AudioCompletionRatio`。
4. “充值价”如未包含用户充值倍率和档位折扣，必须明确标注为估算。
5. 模型广场默认展示最低可用分组价格时，必须标明是最低价而不是统一价。
6. 用量日志必须读取请求结算时保存的价格快照，不能用当前最新设置回算历史账单。
