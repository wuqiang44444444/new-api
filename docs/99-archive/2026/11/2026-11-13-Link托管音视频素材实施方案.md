# Link 托管音视频素材实施方案

## 1. 问题与目标

Seedance Link 客户可以按每个参考音频或视频内容项选择传入已有 URL，或引用事先保存到本站托管素材库的文件。
两条路径使用同一个 ModelArk V3 生成入口和相同的媒体字段。托管是客户主动选择的复用能力，直接 URL 按现有合同透传。

| 客户选择 | 调用方式 | 网关行为 |
| --- | --- | --- |
| 直接使用 URL | 在生成请求的 `audio_url.url` 或 `video_url.url` 填写 URL。 | 按既有模型与协议校验，把原地址交给选定 Provider。无需创建素材或启用本站素材库，生成过程不为该 URL 下载、转存、签名或读取本站素材。 |
| 保存到托管素材库后复用 | 显式调用 `POST /v1/assets`，以 `media_type=audio` 或 `video` 和当次可读的公网 HTTPS 源地址创建素材。之后将返回的 `asset://fhas_*` 填入同一个媒体字段。 | 创建素材时复制到本站私有对象存储。生成时按账号和媒体槽位校验引用，只把对应托管引用替换为本站签名 URL。 |

例如，客户可以在一次生成请求里传直接视频 URL 和托管音频引用。能否混用这两个参考项由所选模型的既有媒体组合规则决定。
建议扩展现有 `funcloud_material_hosted`、素材组和 `fhas_*`，先验收 MP3，再开放实测通过的 MP4。素材列表、
素材库文件直传和生成结果入库另行定义。

代码已实现。Synlink Mini 的直传与签名 URL 对照、托管创建及混合生成已通过隔离环境验收。
真实供应商账单、跨数据库升级和生产灰度待验收。

## 2. 当前实际情况

| 路径 | 已核实的合同与实现 |
| --- | --- |
| 本站托管图片 | `funcloud_material_hosted` 可配对 FunCloud V3、Synlink Video V1、Vidu ModelArk V3。素材和组按 `user_id` 隔离，同账号 API Key 共享。创建时复制源文件并落库，生成前校验并冻结对象事实，出站签发临时 URL。删除停止新引用，已受理任务沿用冻结事实。当前 adapter、公开声明和出站替换均只支持图片。 |
| 参考音视频 URL | 在支持该媒体类型和组合的模型上，现有生成请求可直接传入音频或视频地址。目标 Provider 拉取该地址。素材库是否启用及其类型声明独立于模型的直接参考输入能力。 |

| Link 视频结果交付 | 成功任务的视频和尾帧可转存本站 OSS，按任务访问权限签名交付。现有 S3 分片和 Azure UploadStream 可作为有界上传实现的基础。 |

## 3. 优化方案

### 3.1 先验证签名 URL，再登记合同

1. 在隔离环境选择一条已登记托管图片的 Seedance 线路，优先验证 Synlink Mini。用同一份样本分别提交普通 HTTPS
   URL 和本站私有对象签名 URL。MP3 使用该模型已发布的参考组合，例如参考图加参考音频。MP4 单独覆盖合法的参考视频组合。
2. 两组均验证生成到终态、结果可交付、Provider 实际取件、MIME 和 Range/206（当 Provider 使用范围读取时）。
   验证现有 24 小时内部签名可覆盖排队到取件的窗口，同时记录客户用量、结算和可核对的 Provider 账单。
   验收材料记录环境、模型、媒体格式、组合、脱敏任务标识和结果摘要。签名查询串和真实凭据仅在当次调用中使用。
3. 实施前更新硬约束第 5 节和托管专题，明确直接 URL 是既有用法，`general` 托管音视频由客户显式创建和引用。
   首批保留现有三种协议的图片配对，新增类型仅登记到通过实测的协议与映射后的 Provider 模型。签名 URL 取件或
   托管链路验收失败时，该线路的对应托管类型继续待验收，直接 URL 按现行模型合同履约。

### 3.2 素材写入与存量兼容

- 复用 `/v1/assets` 的单资源创建、查询、删除，沿用 `source.type=url`、可选组和 `fhas_*`。继续按客户模型选
  Channel，组归属与素材归属按 `user_id` 校验。同账号可在支持对应类型的托管模型间复用素材。
- 在现有托管记录增加 `media_type`，新记录显式写入类型。迁移按旧合同把既有记录定为 `image`，覆盖 SQLite、
  MySQL、PostgreSQL 及升级中的旧图片写入。现有 ID、对象路径、组关系继续有效。Task/attempt 的托管对象快照新增类型，
  历史快照按原图片语义读取。
- 延续 HTTPS、SSRF、重定向和超时防护。音视频使用有界格式探测，校验 MIME 与实际媒体容器一致。分别检查
  `Content-Length` 和实际流量，覆盖未知长度、截断、空文件及超限。复用对象存储的有界分片上传，上传确认且数据库
  写入成功后才返回 `ready`。同源重复创建继续得到独立 ID；数据库落库失败按既有孤儿对象约定处理。
- 复用既有对象保留与逻辑删除语义。灰度前落实部署侧的容量预算、监控和告警阈值，确保对象保留策略覆盖已受理任务的
  取件窗口及素材对客户承诺的复用期。MP3/MP4 的大小、请求超时和并发预算根据实测确定，图片像素限制继续适用于图片。
  模型组合、实际时长及媒体适用性由已发布模型合同和 Provider 校验。

### 3.3 生成请求校验、冻结与发送

| 素材类型 | ModelArk 字段 | 角色 |
| --- | --- | --- |
| `image` | `image_url.url` | 既有图片角色 |
| `audio` | `audio_url.url` | `reference_audio` |
| `video` | `video_url.url` | `reference_video` |

1. 按内容项处理地址。直接 URL 按现有 adapter 合同透传，保留原地址及查询参数，绕过本站托管能力判断和对象存储访问。
   仅对 `asset://fhas_*` 执行托管校验。待映射后的目标模型确定，在计价和资金 hold 前校验目标模型的托管类型能力、
   当前账号归属、可引用状态、存储位置和对象存在性。相同 ID 可以共用一次读取和 HEAD，每个内容项仍独立校验槽位和
   类型，防止重复 ID 绕过错槽校验。越权、错槽、删除或不支持的引用走既有 4xx，已知存储不可用走既有 503。
   失败以本次请求为单位返回，客户可按需改用自己持有的有效 URL 重新提交。
2. 在既有 Task/attempt 快照中冻结素材 ID、类型、存储位置、对象 key、MIME 和字节数。延续存储会话固定与删除竞态的
   接受边界。请求级参考音频继续走原准备逻辑，本站音频引用走托管素材解析。调整 Synlink 的预扣前媒体校验，使它只对
   已验证的对应槽位放行本站引用，保持非本站 opaque 引用的既有协议判定。
3. 插件转换继续使用未签名的素材引用。建议在 Seedance 专用预扣前阶段，基于冻结事实预签名并校验替换覆盖，临时地址
   仅保存在当次请求内存中。宿主构建实际出站体时仅替换已校验的本站引用，保留直接 URL、类型、角色、顺序和其余字段。
   当前图片出站构建在 hold 之后，若仍有本地构建失败，应按确定未发送释放占款。预签名失败应在预扣前返回。
   签名 URL、源 URL 和媒体正文遵守既有快照、日志及受保护请求证据边界。
4. 沿用 durable attempt、资金事务与可信 Provider task ID 接受流程。创建结果为 `unknown` 时沿用冻结事实及既有资金
   保障期限。参考视频仍由 `video_url` 触发 `has_video_input`，报价和结算沿用既有表达式、冻结参数及可信用量。
   存储字节数与本地探测结果用于存储和准入，不作为客户生成费用或 Provider 成本。

### 3.4 能力发布与回退

从代码登记的目标视频协议及映射后 Provider 模型取得有效的托管媒体类型。素材创建、生成时的引用准入和
`api.assets.media` 共同使用这份能力声明，目录同时投影对应的格式和大小限制。保留 `platform_hosted` 和既有
托管复用域，客户创建或引用托管素材时需确认目标模型发布了该类型。直接 URL 继续以 ModelArk 的模型输入合同为准。
管理员按已有客户模型配置流程启用验证通过的线路。

灰度发现某类型无法履约时，从对应模型的发布与运行时准入同步撤下该类型，保留已写对象与历史快照。
受理中的任务按既有快照与协议执行。回退验证覆盖直接 URL、旧图片、已保存音视频、同账号跨 Key 与历史任务。
公开中英文文档与目录在该类型具备发布条件时同步更新。

## 4. 验收矩阵

| 边界 | 预期结果 |
| --- | --- |
| 创建与迁移 | 旧图片升级后能查、能引用。已开放类型上传后字节与 MIME 正确。源 URL 过期后仍可通过素材 ID 生成。超限、空体、错 MIME、拉取或上传失败无 `ready`。 |
| 直接 URL 独立可用 | 对支持参考音视频的模型，素材库关闭、对应类型未发布或本站对象存储不可用时，合法直接 URL 仍按原合同发送。带签名参数的客户 URL 保留原值，且该路径不产生素材记录或本站对象访问。 |
| 权限与类型 | 同账号不同 Key 可复用。跨账号、错槽、已删除及模型未开放类型的请求无资金 hold、无 Provider POST。一个 ID 同时出现在正确和错误槽位仍失败。 |
| 对象与删除 | 位置不匹配、对象缺失或不可访问时在预扣前失败。删除后新请求失败，已接受任务可按冻结对象取件。 |
| 出站与证据 | 直接视频 URL 与托管音频引用可以按模型合同混用。出站保留直接 URL、顺序和角色，仅替换托管引用。模拟签名、构建和未知创建故障，核对资金释放或保障期限及脱敏结果。 |
| 真实生成与对账 | 逐模型验证直接 URL 与托管引用均可生成。同一参考视频的两种输入方式命中相同计费档位，可信用量、结算和供应商账单可核对。 |
| 目录与发布 | 目录公开类型与运行时一致。未验收模型不显示新增类型，撤下单一媒体类型不影响图片及历史任务。 |

实现时按素材服务、模型目录、Seedance adapter、真实对象存储及任务计费边界执行定向验证，并在外部数据库和灰度环境
复验。文档运行 `task docs:check` 与 `task ai:check`。公开 API 文档更新时执行
`cd web && bun run docs:validate`。若修改 `relaykit/`，另执行 `cd relaykit && GOWORK=off go build ./...`。
真实渠道、对象存储和对账结果记录齐全后，才发布该模型的对应托管类型。

## 5. 实施与验证记录

### 真实 URL 对照

2026-11-13 使用本地独立 PostgreSQL、独立测试用户、Synlink Mini 及 Azure Blob 私有对象存储。先在原版网关验证
同一份 MP3 和 MP4 分别经公网 HTTPS 原址和本站 24 小时签名 URL 提交。签名样本的 Range 读取返回 206，
字节与原样本一致。

| 样本 | 直接 URL | 本站签名 URL | 客户结算 |
| --- | --- | --- | --- |
| MP3，搭配同一张 640 × 360 参考图 | 成功并可交付，40,594 completion tokens | 成功并可交付，40,594 completion tokens | 均为 68,624 quota |
| MP4，参考视频 | 成功并可交付，90,814 completion tokens | 成功并可交付，90,814 completion tokens | 均为 93,448 quota |

音频首轮参考图高度低于上游 300 像素下限，两种地址均在上游终态失败，结算为零。更换参考图后，两组均通过。
上述结果验证这条线路的输入传输及本站结算。供应商账单金额仍待核对。

### 代码范围

在现有托管记录增加带 `image` 默认值的 `media_type`，让存量记录与升级期间的旧写入保留图片语义。
本批仅为 Synlink Mini 登记 MP3 和 MP4。编码大小继续使用既有 100 MiB 上限，MP3 以有界帧探测校验，
MP4 以容器头探测校验，交给 S3/Azure 的现有有界上传实现。生成预扣前签名，出站保留客户直接 URL。

代码接线集中在 Link 素材服务、Seedance adapter 和模型目录。既有托管表 AutoMigrate、通用 Task 快照入口及
资金事务继续复用。定向测试覆盖托管音频与直接视频混用、同 ID 错槽拒绝、已有图片与 Synlink 生命周期。

### 真实托管与混合生成

在独立 PostgreSQL 和 Azure Blob 的新构建上，通过 `POST /v1/assets` 创建 MP3 和 MP4 均返回 201 与
`ready`。创建采用当次可读的 Azure Blob HTTPS 签名源地址。试用的公网样本域未通过本机既有源地址安全校验，
因此更换源地址；首次 MP4 写入返回 502，重试成功，首次失败原因未确认。

- 直接视频 URL 加托管音频、托管视频加直接音频均生成成功并达到交付 `ready`，各为 90,814 completion
  tokens 和 93,448 quota。两个创建 attempt 均完成并转移资金，错槽和跨账号引用两项未建立 attempt。
- 跨账号单项查询两种素材均返回 404。错槽引用和跨账号引用均返回 400。
- 定向 Go 测试、`GOWORK=off go build ./...`（relaykit）、`task docs:check`、`task ai:check` 和
  `bun run docs:validate` 通过。
