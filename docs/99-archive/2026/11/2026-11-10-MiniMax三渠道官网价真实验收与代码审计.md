# MiniMax H3 三渠道官网价真实验收与代码审计

## 1. 问题与目标

核对京东云和 Nexhina 标准视频在分辨率、时长、比例与素材变化下的真实履约；对照官网原价、本站
资金和供应商账单；查清 Token 字段的来源与准确性；创建原生 Hailuo 渠道，用 Nexhina V2 实测兼容性。
审计覆盖北向路由、南向适配、创建占款、后台查询、用量、日志、请求证据和交付。取消、删除、生产灰度
及 MiniMax 官方直连账户不在本轮测试范围。

## 2. 当前实际情况

### 2.1 实例、渠道和价格

- 2026-11-10（Asia/Shanghai），在现有 TokenAI 单实例执行。前端 3500、后端 3501，沿用现有
  PostgreSQL 与私有 Azure Blob。运行制品 `minimax-link@1.5.0`、`hailuo@1.2.1`。
- 测试资源仅使用 `minimax-price-test`。Nexhina 标准渠道 141 保留 `minimax-h3-nexhina-pilot`；
  新建原生 MiniMax 类型 35 渠道 142，模型 `minimax-h3-nexhina-native-qa`；从现有 JD 标准渠道
  138 创建停用副本，再配置并启用渠道 143，模型 `minimax-h3-jd-qa`。新别名均映射 `MiniMax-H3`。
  渠道 142 的管理表单同时保留了上游模型名，两个原生 Ability 均限该试点分组。渠道 144 使用独立模型
  `minimax-h3-nexhina-error-qa` 和无效凭据，专用于鉴权拒绝对照。该对照触发自动禁用，本轮九把临时 Key
  已全部停用。
- 官网基础版美元原价为 768p 每输出秒 $0.08、2K 每输出秒 $0.13。输入视频按输出分辨率的同一秒价；
  单任务前五张图片免费，超出部分每张 $0.04，输入音频免费。试点价格配置按该规则，分组倍率 1，
  无折扣。500,000 quota 对应 $1。已替换渠道 141 的旧 $0.50/秒试点价。 [MiniMax 官网定价](https://platform.minimax.io/docs/pricing/overview#h3-series-flagship-models)
- 京东 JoyMaaS 的人民币输出挂牌价为 768p ¥0.576/秒、2K ¥0.936/秒。按两张价表隐含的
  7.2 元兑 1 美元作算术比较，与所配置的美元原价相同。它是挂牌价比较，JD 账户账单仍单独核对。
  [京东云 JoyMaaS 模型价格](https://joymaas.jdcloud.com/models)

| 路线 | 本站表达式事实 | 实际可复算范围 |
| --- | --- | --- |
| Nexhina 标准视频 | `(output_seconds + input_video_seconds) × 秒价 + max(input_image_count − 5, 0) × 0.04`，分辨率从创建快照读取 | 本轮文生和单图；相同单价也用于拒绝对照。该协议公开仅支持 16:9、最多一张参考图。 |

Azure Blob GET/HEAD 200、Range 206。原生 Hailuo 使用凭据隔离的 CDN 代理交付，走已有原生分发

对应专用 Key 的用量、attempt 和 Task 均为零。只确认这两个当前公开范围，未把 480p、Nexhina
其它画幅、首尾帧或多图视为基础版当前可用范围。 [Nexhina 创建文档](https://doc.nexhina.cn/531513206e0)

### 2.5 证据、日志与错误

- 当前证据开关已启用。抽查两笔标准创建、两笔原生创建和鉴权拒绝，共 20 个四段事件；每条都有本地
  `NEVSIO3` 加密对象，保留期为 172,800 秒。新流式对象以索引 ID 推导路径，旧 `object_key` 为空、
  `stored_bytes=0` 不能据此判为未存。后台标准任务的 polling 事件可按 Task 关联。
- 管理后台可展开真实拒绝的北向请求、南向发送、上游 401 和客户端 503。Root 原文预览失败，显示
  “证据正文完整性校验失败”。PostgreSQL 返回空 `CHAR(64)` 为 64 个空格，和读取器把空串当无摘要
  的判断相冲突。普通 API Key 与匿名访问证据详情均为 401，普通控制台会话为 403。原始文件下载未完成，
  不能据此判定该入口。
- 采样普通消费、差额及错误事件未检出测试源域、完整签名参数、已知无效凭据标记或 Bearer Key。
  标准客户状态和已授权交付只暴露客户模型及本站 OSS；同一用户用另一应用的 Key 查询任务为 404。
- 独立渠道 144 真实上游 401，错误信封为 Nexhina 的 `error` 对象，无任务标识。本站返回 503
  `create_outcome_unknown`，无 Task，保留唯一 attempt 的 600,000 quota（$1.20）。证据与错误日志
  对上请求。重复 POST 未执行，创建占款按现有 24 小时保障进入到期释放路径。

## 3. 优化方案与代码质量审计

### 3.1 审计范围与验证

基线为当前工作区和 `HEAD`，当前差异包含此前的独立开发内容。审计追踪 Router → 权限与渠道 →
adapter → 创建 attempt / Task → 后台查询 → 计费、证据和交付。遵循 [仓库硬约束](../00-context/硬约束.md)、
[异步任务与计费事实架构](../20-architecture/账单计费-异步任务与计费事实架构.md)、
[全渠道验收手册](../40-operations/05-全渠道上线验收手册.md) 和表达式说明。

定向 Go 回归通过，覆盖 Hailuo、MiniMax 标准视频、费用恢复、轮询、公开路由、请求证据与账单投递。
管理后台用真实 PostgreSQL 验证证据预览，文件下载用实际 Azure Blob 或原生 CDN 代理。未验证 MySQL、
生产灰度或供应商的内部 Token 生成算法。

### 3.4 最小接线与健康度

- 继续以 [`router/video-router.go:35`](../../router/video-router.go#L35) 的标准入口和
  [`middleware/standard_video_channel.go:25`](../../middleware/standard_video_channel.go#L25) 的类型分发为权威。
  Nexhina、JD 与官方直连协议在类型 69 的制品和冻结快照内选择；原生 Hailuo 通过类型 35 和既有插件
