# 邮件与运维通知改造方案

## 1. 目标与状态

目标行为和验收门槛以[产品设计](../10-product/用户生命周期邮件通知产品设计.md)为准。代码已接入发信
底座、账户流程、告警与日报。Microsoft 365 真实邮箱的收件验收待用户配置后执行。本地证据见
[实施与验收文档](../80-dev/2026-11-10-邮件与运维通知实施与验收.md)。

## 2. 发信底座与模板

- 复用现有邮件发送入口和 SMTP 能力，在同一入口按已保存配置选择 SMTP 或 Graph。配置按站点保存，
  一次保存一个完整配置，所有发信调用取得一致的配置快照。升级时识别既有 SMTP 设置，切换时由管理员
  保存新的活动配置。切换后由活动配置独占发信。
- Graph 使用应用身份获取令牌，并以专用邮箱调用发信接口。应用授权用 Exchange Online 的邮箱范围控制，
  租户须核查是否同时存在扩大权限范围的其他授权。保存凭据的接口只返回非敏感配置与凭据是否已配置。
  [Microsoft Graph 发信](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0) ·
  [Exchange Online 应用授权范围](https://learn.microsoft.com/en-us/exchange/permissions-exo/application-rbac)
- 在统一入口限制并发和连接总时长。普通通知使用有容量上限的后台工作，明确记录跳过、限频、排队失败和
  提交失败。凭证邮件保留可重试入口。SMTP 的 DATA 接受和 Graph 的 HTTP 202 均记录为通道受理。
  结果不明时保持可核对状态，避免跨通道自动重发。日报沿用逐收件人投递记录与有界退避。
- 邮件盘点以可达触发入口为准，按事件确认开关、收件人来源、既有个人通知渠道和模板。移除无业务入口的
  密码修改邮件开关，保留实际安全事件发信语义。用户邮件使用已有语言解析，公共运维邮件采用同一封中英
  双语模板。转义模板中的用户输入和运维名称，过滤不适合出现在邮件里的原始错误及凭据。
- 手动测试入口复用已保存配置和同一发信函数，限制系统设置权限和请求频率。测试地址只用于本次请求。
  管理后台显示提交结果，审计记录使用脱敏状态。

## 3. 建号与自助找回

- 管理员建号在保存边界校验邮箱，沿用邮箱规范化和唯一性校验。存量无邮箱账户仍可按已有方式登录。
- 找回入口采用统一受理提示。后台只为能唯一匹配有效账户的地址创建短时凭证并发送。保护请求频率和任务
  容量，邮件及日志中避免出现账户密码。
- 复用持久化认证流程保存凭证摘要、账户身份、邮箱、版本和有效期。链接建议有效 15 分钟，凭证置于 URL
  片段，提交重置时随请求正文发送。多实例须使用一致的认证密钥配置。
- 前端和服务端都校验两次密码一致，使用现有密码规则。凭证消费与密码更新、账户认证版本变更同一事务
  提交。完成后用现有会话失效机制撤销旧会话。过期、并发重复、账户停用、邮箱更换和已有密码变化均需
  覆盖。

## 4. 资源告警与日报

### 4.1 资源采样与异常记录

- 每个网关部署单元低频采样本地资源。容器按有效 CPU 和内存限额计算，数据与日志路径解析到实际文件
  系统，同一卷去重。采样缺失保持未知，只有可信的低于阈值读数才结束异常。
- 每个节点和资源项持久化一次异常的开启和恢复。首次采样达到阈值即记录并触发，不加超限持续时长。
  恢复后可开启下一次异常。后台只在状态变化时写入，日报统计异常开启次数。
- 告警用共享的运维收件人名单。采样、投递或状态记录失败有可见的脱敏结果。持续超限去重按异常身份
  执行，重启和并发时保持一致。

### 4.2 日报汇总与切换

- 保留现有报告收件人、调度与逐地址投递能力。将小时邮件切换为日报。既有历史投递结果保留，尚未投递的
  旧小时邮件在切换时停止。切换前确认旧调度器退出，避免两个版本同时处理。
- 以北京时间自然日作为唯一窗口，前一自然日为发送对象。提前按短窗口分批扫描已记录错误，只读统计字段。
  每批持久化游标与有限候选聚合，重启后从已提交的进度续跑。
- 汇总完成且到达次日 06:00 后冻结一份邮件，生成逐收件人投递记录。失败窗口保持待处理，读取错误不产生
  零数据。对当日明细和迟到数据说明统计边界。限制单轮扫描、数据库超时、正文大小和投递并发。
- 首轮调优可使用 15 秒资源采样、5 分钟汇总切片与单次数据库读取 2 秒预算。它们是工程试值，实际采用值
  由验收数据决定。

## 5. 批次与发布门槛

| 批次 | 完成信号 |
| --- | --- |
| 1. 发信与模板 | SMTP 和 Graph 均经过协议测试，单选配置和权限正确。每个活跃邮件入口都有模板和收件规则，后台可用已保存配置发送测试信。 |
| 2. 账户 | 管理员建号校验通过，自助找回完成一次性、并发、过期、重复使用和会话失效回归。 |
| 3. 告警与日报 | 达阈值即告警并去重，日报按前一自然日与 06:00 门槛发布，验证异常与恢复，验证小时邮件切换。 |
| 4. 本地验收 | 逐类实际收件，提供相同模型流量下的基线与变更组结果。P95 增幅不超过 5%，超时率不升高。 |

实际收件在本地网关上执行。本地 SMTP 收件箱能证明本地 SMTP 链路实际到达。Graph 模拟服务仅验证协议，
Microsoft 365 实际到达需租户完成专用发件邮箱授权后核对测试收件箱。发布结论分别记录各通道证据和
性能证据。权限、跨数据库迁移和旧小时任务切换均完成验证后，再把实现事实更新至架构和运维文档。
