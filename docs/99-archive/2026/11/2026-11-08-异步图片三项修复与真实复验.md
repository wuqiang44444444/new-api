# 异步图片三项修复与真实复验

## 1. 结论与范围

[上一轮真实冒烟](2026-11-06-本地真实渠道端到端冒烟结果.md)暴露的三项问题已修复，并在本地真实渠道复验通过：
图片同键重放复用原任务、同键不同请求返回 409；旧 Token 定价正常异步受理和结算；原生异步图片
可通过任务制品接口交付，Chrome 实际显示图片。文本、同步图片与 Seedance Mini 4 秒视频回归通过。
本轮是指定渠道与配置的本地验证，未进行生产发布。

## 2. 最小接线与回归

| 问题 | 修复与上游同步影响 | 回归保护 |
| --- | --- | --- |
| 图片幂等没有进入运行时 | `router/task-plugin-protocol-router.go` 仅在标准图片入口分发后接入现有 `ImageCreateIdempotency`，在渠道已确定、受理与扣费之前使用原有键域和事务；不增加路由或幂等表 | 实际注册路由：同步带键拒绝、等价重放同任务、冲突 409、同用户不同 app 可独立使用相同键、重放不再次占款 |
| 旧 Token 定价初始计算与预扣不一致 | `relay/helper/price.go` 仅在既有旧图片 Token 预扣分支记录已计算额度的取整与完成值，两行必要接线；不改变额度计算、兼容语义或受理一致性校验 | 以明确正数预扣测试计算记录与实际 500 quota 一致；注册路由验证旧定价和按次定价均可受理 |
| 图片任务页制品为空 | `controller/task.go` 现有共享授权、投影和内容入口作窄接线，主体在独立的 `controller/task_image_artifacts.go`；复用持久化图片对象和现有签名服务，不改浏览器组件、插件或视频 adapter | 已成功的 b64 图片制品列表、跨用户/app 拒绝且无存储探测、已登记对象签名、HEAD、对象删除/不可用和未登记键失败关闭 |

三处共用代码的修改均为实际接线需要；同步上游时只需检查图片路由顺序、旧图片预扣记录位置与
共享制品入口的三个分派点，避免整段重排或第二套实现。无数据库迁移与新前端文案。

## 3. 真实本地 E2E

使用 HEAD `b6254ff26dbde9a7ad411b0ae0adb543dabe7f60` 加本轮工作区修复编译完整程序，
生产构建前端由 Go 服务直接提供。独立 SQLite 副本端口 3513，仅复用原有 121 文本、57 Azure 图片、
139 Seedance Mini 渠道及真实私有对象存储；原库只读，副本无历史任务，关闭自动渠道检查和重试。
测试客户钱包和有限额 Key 各 2,500,000 quota（$5），无并行业务流量或人工额度调整。

| 场景 | 真实结果 | 最终 quota |
| --- | --- | ---: |
| 文本非流式 | 200，3.069 秒，返回指定文本；18 输入/7 输出 Token | 265 |
| 文本 SSE | 200，1.782 秒，实际流式完成，usage 同上 | 265 |
| 同步文生图 | 200，15.196 秒，1024×1024 PNG | 2,998 |
| 同步参考图编辑 | 200，14.353 秒，1024×1024 PNG；25 文本、1,024 图片输入、196 输出 Token | 7,099 |
| 旧 Token 定价异步图 | 202，0.982 秒；预扣 32，后台完成，计费依据完整 | 2,988 |
| 表达式定价异步图 | 202，0.379 秒；预扣 35，后台完成，计费依据完整 | 2,990 |
| Seedance Mini 4 秒 | 创建 200，2.523 秒；succeeded 后托管 ready；MP4 794,663 字节、864×496、4.041667 秒、无音轨 | 69,058 |
| **净额** | **7 次实际执行，均完成** | **85,663** |

两种图片定价分别验证了受理后立即重放与终态后重放，均为 202 且返回原 ID；各自改变请求体仍用
同一键均得到 `409 idempotency_conflict`。最终仅 2 个图片任务、2 条幂等绑定、每个任务一笔净消费。
真实图片结果来自同一现有渠道。为第二个用例，仅在副本经现有转换/保存接口启用等价表达式；
原旧模式任务继续按创建时冻结事实结算，结束时经正式接口恢复副本价格。

两张异步图片查询均返回有效 1024×1024 PNG。相同任务的制品接口各返回一个 `image`；站内内容
GET 返回 302，私有存储下载 200，字节与查询返回的 Base64 解码结果完全一致；HEAD 为 200、
MIME 和长度正确。视频 GET/HEAD 均 302，存储 Range 206、HEAD 200；一次只读探测遇到 TLS 握手超时，
后续重新查询并读取通过，未重发任何业务生成请求。

缺失/无效 Key 均 401、越权模型 403、非法图片数量均 400，无新增扣款。跨用户和跨 app 查询
任务、图片制品列表/内容均 404；普通客户访问管理接口 403。业务错误事件无 5xx，两个冲突 409
均可在管理端错误日志筛出。重复任务查询和终态重放均未改变钱包、Key 或消费日志。

## 4. 资金、界面与收尾

- 钱包和 Key 从 2,500,000 降至 2,414,337，Key used 为 85,663；7 条消费毛额 948,854，
  1 条退款 863,191，净额 **85,663 quota（$0.171326）**。视频预扣 932,249，退差额 863,191，
  最终 69,058；attempt 为 `complete/transferred`。全部 3 个任务 SUCCESS/settled，无待处置占款。
- 客户账单权威接口 `/api/billing/statement/self` 和浏览器均显示 7 次请求、净额 $0.171326、
  钱包余额 $4.828674。图片编辑的原始分项 $0.014197，经 quota 取整实扣 $0.014198，中英文一致；
  旧定价异步任务详情实际显示 `32 + 2956 = 2988 quota` 的结算过程。
- Chrome 客户界面两张异步图的实际 `naturalWidth/naturalHeight` 均为 1024×1024，视频播放至
  4.041667 秒并 `ended=true`。另一个测试客户任务列表为空；管理员实际看到了两条冲突记录。
- 旧日志页顶部用量仍是消费毛额口径，旧 `/api/billing/self` 次数口径与新版账单不同；
  原生图片任务副标题仍可显示“未知”。这些已知显示差异未纳入本次三个修复，也不影响已验证的
  消费明细、账单净额、任务和制品。真实缓存正样本、供应商实付账单、素材扩展、外部数据库和生产灰度未验收。
- 副本价格已恢复，历史账单未变化；4 个测试 Key 停用，测试会话撤销，复制的渠道/存储配置凭据清除，
  实例已停止。原业务库、已有业务渠道和业务资金未改动。报告金额是本地客户账单。
