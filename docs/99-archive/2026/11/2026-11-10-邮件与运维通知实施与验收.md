# 邮件与运维通知实施与验收

## 1. 状态

产品口径见[产品设计](../10-product/用户生命周期邮件通知产品设计.md)，技术选择见
[改造方案](../50-planning/2026-11-10-邮件与运维通知改造方案.md)。已接入单一发信配置、邮件模板、建号
校验、自助找回、资源告警和运维日报。本地验收使用合成账户和本地 SMTP 收件箱。用户将使用真实
Microsoft 365 邮箱做 Graph 端到端验收。

## 2. 实现与复核点

| 模块 | 接线和验证 |
| --- | --- |
| 发信与设置 | 统一入口按活动配置选择 SMTP 或 Graph，Root 专用设置路由接入 `option:read` 和 `option:write`。切换配置只保留一套活动通道，凭据不回显。 [发信入口](../../common/mail_transport.go) · [设置路由](../../controller/mail_settings.go) |
| 建号与找回 | 管理员建号校验邮箱，重置令牌以摘要持久化，消费和密码修改原子提交。前后端校验双密码。 [重置模型](../../model/password_reset.go) · [找回入口](../../controller/password_reset.go) |
| 资源告警 | 读取网关可用资源，默认阈值 85%。每节点和资源项的开放异常去重，恢复后可再次触发。 [采样与投递](../../service/resource_alert.go) |
| 日报 | 按北京时间前一自然日，限量增量汇总，06:00 后完成才冻结发送。保留历史，切换时停止未发送的旧小时邮件。 [日报处理器](../../service/daily_error_report.go) · [持久化](../../model/daily_error_report.go) |

复审修复把邮件提交的活动配置读取接到启动入口。告警异常与逐收件人待投递状态同事务保存，明确失败退避
重试，结果不明保留待核对。日报暂停后续用原游标，退役小时生成和测试逻辑，保留旧记录及升级迁移。
额度邮件在独立有界队列内渲染、限频和提交，渠道通知对 HTML 邮件中的动态文本转义。

上游合并需复查三个最小接线面。原生账户控制器的邮箱校验用来封住后台建号入口，公开找回路由复用原路径
和限流。邮件设置注册及令牌策略使新入口在既有 Root 权限下可达。数据库迁移注册新增状态和兼容索引，
其余逻辑位于邮件、认证流程、资源监控与系统任务的专用文件。

## 3. 本地逐类实际收件

| 类型 | 本地证据 |
| --- | --- |
| 后台测试信 | 本地网关调用已保存的 SMTP 配置，收件箱收到测试信。 |
| 欢迎信、API Key 创建 | 管理员建号拒绝空邮箱。启用开关后，管理员建号和用户显式创建 Key 分别收到对应模板。 |
| 自助找回 | 从收到的邮件提取链接，验证两次密码不一致被拒绝。用同一数据库和认证密钥的另一节点消费链接，随后重新登录并验证链接复用失败。 |
| 账户安全、邮箱绑定 | 自助改密收到安全通知。邮箱换绑的旧、新邮箱收到各自验证码及确认邮件。 |
| 钱包、订阅额度 | 真实模型结算触发钱包提醒。订阅阈值通过受控结算数据驱动通知入口，两类均实际收到 SMTP 邮件。 |
| 渠道与运维事件 | 本地网关收到手动渠道批量测试和上游模型变更邮件。用合成渠道状态变化及资金告警事件驱动通知入口，收到了禁用、恢复和视频退款提醒。 |
| 上游低余额 | 模拟上游返回有效低余额，现有余额检查处理器向两位配置收件人逐封提交并实际收件。 |
| CPU、内存、硬盘 | 本地实例采样并收到三类资源告警。Linux 容器实测读取 0.5 核 CPU 与 256 MiB 内存限额。受控阈值样本进一步验证等于阈值触发、同次异常去重、恢复后再次发信。 |
| 运维日报 | 本地实例完成受控自然日汇总并实际收件。回归覆盖午夜边界、06:00 前、延迟完成、零错误和旧小时投递停止。 |

该部署关闭自助注册，第三方绑定未作为本次实际收件场景。Graph 本地模拟验证应用身份、邮箱对象 ID 和
配置发件邮箱、HTTP 202 与 403 行为。真实 Graph 送达需由用户按[邮件设置步骤](../40-operations/环境配置.md#5-邮件投递与运维通知)
配置专用邮箱后确认。

SQLite、MySQL 5.7.44、PostgreSQL 15 已验证单选配置保存、旧日报索引升级、小时投递停止、
统计读取及异常去重。验证使用本地测试数据。

复审修复后重复核对本地 SMTP 收件。两个共享主库的网关验证保存后另一节点立即使用新发件人，并立即读到
Graph 活动模式。模拟 SMTP 返回 421 后恢复，原内存异常在默认 60 秒退避后进入本地收件箱。SMTP
收件端读完日报后断开，投递保留为 `submission_unknown`。定向回归同时覆盖已受理收件人去重、未知记录
停止重试、日报恢复和邮件 HTML 转义。修复后的迁移和状态回归再次通过 SQLite、MySQL 5.7.44 与
PostgreSQL 15。ClickHouse 25.8 日报聚合保留同键独立错误事件计数。

## 4. 本地性能对照

每组使用相同网关、SQLite 设置、合成上游和负载。每轮 45 请求/秒、30 秒，共 1,350 次模型请求。前
3 秒为正常请求，此后 75% 请求返回可预期的上游 503。功能组在负载期间汇总 45,000 条历史错误样本，
同时 SMTP 接受回复延迟 5 秒。两轮交换基线与功能组的执行顺序。每组累计 2,700 次请求。

首轮实现的两次试验对照中，全段 P95 增幅为 6.81%，超过验收线。随后把通常的三次切片扫描合并为一次，
并将每轮统计进度合并成一次持久化写入。相同负载复测如下。

| 对照 | 基线 P95 | 功能组 P95 | 相对变化 | 基线 / 功能组超时 |
| --- | --- | --- | --- | --- |
| 第一次全段 | 16.483 ms | 16.638 ms | +0.94% | 0 / 0 |
| 第二次全段 | 17.440 ms | 16.897 ms | −3.11% | 0 / 0 |
| 两次全段 P95 中位数 | 16.962 ms | 16.768 ms | −1.14% | 0 / 0 |
| 两次错误突增阶段 P95 中位数 | 17.094 ms | 16.748 ms | −2.02% | 0 / 0 |

两次功能组均完成日报生成和延迟 SMTP 提交，基线未开启汇总。各次每组均产生相同的 911 次预期上游
错误，其他错误为零。该本地配置达到 P95 增幅不超过 5%、超时率不升高的标准。

复审修复后按相同请求速率和轮次再次对照，使用 24 个测试账户轮转发请求。功能组同时开启日报和钱包额度
提醒，SMTP 接受回复延迟 5 秒。每轮功能组实际收到一封日报和五封额度邮件。两组每轮均有 911 次预期
上游错误，其他错误为零。前一轮和后一轮全段 P95 增幅分别为 +0.65% 和 +0.01%。

| 修复后对照 | 基线 P95 | 功能组 P95 | 相对变化 | 基线 / 功能组超时 |
| --- | --- | --- | --- | --- |

## 5. Microsoft 365 待验收

用已授权的专用发件邮箱保存 Graph 配置，先从后台向指定邮箱发测试信，确认实际收件和发件地址，再按
第 3 节核对所启用的业务邮件。凭据通过设置页提供，验收记录保留脱敏结果。Graph 接受提交与最终送达
分别判断。
