# 本地真实渠道端到端冒烟重跑结果

## 1. 问题与目标

按[本地真实渠道端到端冒烟测试方案](../../../70-research/2026-11-06-本地真实渠道端到端冒烟测试方案.md)
重跑文本、同步和异步图片、Seedance Mini 4 秒视频及授权边界。目标渠道公开启用了本站托管素材，
因此将一张本轮异步图片登记为素材，并复用于唯一一次视频创建。

**整体未通过。** 七笔真实计费请求都成功且已结算。旧 Token 定价的异步图在客户账单中被标为
按次计费，Seedance 视频客户用量详情泄露实际南向模型，两项均在实际浏览器中复现。

## 2. 当前实际情况

- 2026-11-08 晚间（Asia/Shanghai），使用干净提交 `8bd9eb2c61411bfd54da96ab672a48cf93b42c6a`

  得到的 SQLite 副本，日志同库、Redis 关闭。启动前清空历史任务、队列和业务身份，关闭自动渠道检查
  和业务重试。主库只读，原本地实例继续运行。

### 本轮发现

1. **Seedance 南向模型泄露。** 普通客户的 `GET /api/log/self` 在本轮视频消费与退款记录的
   `other.upstream_model_name` 中返回真实南向模型。Chrome 消费详情在「实际模型」中显示同一值。
   公开 ModelArk 视频查询只返回客户模型及已发布字段。
   [任务消费与差额日志](../../../../service/task_billing.go#L69)把模型映射写入公开元数据，
   [前端详情](../../../../web/src/features/usage-logs/components/dialogs/details-dialog.tsx#L1351)渲染该值。
2. **旧定价异步图片的账单计费单位错误。** 该任务按真实 19 输入 / 196 输出 Token 结算，
   冻结价格及净扣 2,988 quota 正确。结算日志的账单快照却标为 `per_call`，同一笔 $0.005976
   在客户账单中英文页面分别归为「按次计费」和 “Per-call billing”。
   [异步任务账单快照](../../../../service/task_billing.go#L175)给无表达式路径传入按次分类，
   [异步图片完成分支](../../../../service/task_billing_delivery.go#L64)补了真实计量但沿用了该分类。

普通客户任务页的原生图片副标题仍显示「3 · 未知」。旧用量汇总仍显示消费毛额，
旧 `/api/billing/self` 仅计四次请求，当前客户账单聚合七次，两处口径延续上一轮观察。

## 3. 优化方案与收尾

- 南向身份的后续修复应同时覆盖新写入和既有 Link 日志的客户读取，保留管理员对账能力并验证原生
  日志合同。旧 Token 异步图的账单单位应取已冻结的计价分支，保留明确按次的图片合同。
  本轮只执行测试与记录。
- 隔离副本的价格已通过管理 API 恢复并复核资金未变。四个测试 Key 停用，浏览器会话登出，
  剩余副本会话撤销。3517 实例已停止，含连接凭据的临时数据库、运行日志及登录文件已移除。
  本轮测试对象保留在其独立前缀，未删除远端对象或素材组。
- 范围为三个指定渠道、SQLite、本次托管素材创建和引用。未执行其它渠道、其它托管素材生命周期
  场景、供应商账单对账、真实缓存命中、外部数据库、故障恢复和 24 小时资金保障演练、生产灰度。

私有证据在 `.local-tests/e2e-smoke-20261108-qkmIDm/`。其中 `case-recalculation.json`、
`checks.json`、`browser-checks.json`、`V1-complete.json` 和 `closeout.json` 分别记录逐笔复算、
资金与隔离、浏览器结果、媒体和收尾。截图见本次 Chrome 工具记录，证据文件保留脱敏数值、关联 ID
和合成媒体。
