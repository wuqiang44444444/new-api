# 使用日志查询减负设计与实施方案

## 1. 目标与范围

让用户打开「使用日志」即可查看最新记录，粘贴完整 Request ID 即可定位相关事件。精确总数、跳页、
末页和范围统计由用户需要时触发。现有筛选、每页条数选择、单笔详情、日志导出和访问权限继续可用。

本期只调整普通使用日志的读取和界面交互。日志写入、留存、错误日志、操作审计、请求证据、
用量与账单后台汇总沿用各自现有路径。范围统计、首页按需计数与 Request ID 查单已本地实施。
历史窗口执行计划、生产查询归因与灰度仍待验证。

## 3. 用户行为

| 操作 | 预期结果 |
| --- | --- |
| 打开首页或应用新的筛选 | 默认最近一小时、每页 20 条。服务端取 21 条，最多返回 20 条及是否有下一页。条数在一页以内时直接显示精确总数。 |
| 上一页、下一页或返回首页 | 沿用当前查询边界。有下一页以多取的一条为准。翻页无需提前知道总页数。刷新最新记录或提交新筛选时建立新边界并回到首页。 |
| 查看总数、指定页码或末页 | 用户发起操作后才执行精确计数。沿用当前搜索条件与分页边界，计数成功后复用结果。失败保留已显示记录，提供手动重试。 |
| 粘贴完整 Request ID 或打开某一行 | 以现有等值查找和索引定位。用户明确选择的时间范围继续生效。未选时间时按当前角色允许的日志查询范围搜索，并显示实际范围。同一 ID 的失败、重试成功等匹配事件按原权限显示，详情沿用单条引用读取。 |
| 查看范围统计 | 由点击触发。筛选变化后提示按新范围重新统计，旧结果不能标成新范围。请求未完成时同一筛选不能重复触发，失败或超时由用户主动重试。 |

「查看总数」只返回匹配行数。范围统计继续提供现有费用和速率口径。两类操作各自处理加载和错误，
首页数据在等待期间仍可使用。产品现状以[使用日志与报表产品设计](../../../10-product/使用日志与报表产品设计.md#2-使用日志)为准。

## 4. 读取合同与一致性

1. 在现有关系库 `page_snapshot` 路径上扩展按需计数。新控制台显式请求该行为，未选择该行为的请求
   沿用既有精确分页。响应能区分「总数未知」「精确 0 条」及 `has_more`，前端不能把未知总数当作
   空结果，也不能用估算值生成末页。ClickHouse 继续使用其现有路径，是否扩展另行验证。
2. 分页令牌继续绑定调用范围和过滤条件，保存起止时间、最大可见 ID、有效期及可选精确总数。
   列表、计数、跳页及末页使用同一过滤条件和固定边界。令牌过期后提供刷新操作，保留筛选和每页条数并返回第一页。
   边界限制后续读取范围。跨请求之间，迟提交的旧 ID 或留存清理仍可能改变实际可见行，故总数表示
   该范围在计数时的精确值。末页计算和读取需要对齐时，在同一个短只读事务内完成。
3. 管理端沿用 `created_at DESC, id DESC`，个人端沿用 `id DESC` 和服务端用户隔离。顺序翻页先复用
   现有编号路径，多取一条判断后续页。灰度前需核对生产带显式时间范围的实际排序，
   并用本地目标 SQL 验证历史窄窗能否从时间索引起读。
   已知上一页末行时，游标可用实际排序键继续读取。任意页码没有这个锚点，时间边界只能缩小搜索范围，
   精确计数也不能直接给出第 N 页的首行。任意跳页先保留按排序键取 ID 后再读摘要的精确路径。
   若深页超过查询预算，结合实测评估近端游标定位。末页单独验证反向取页，按同次精确总数确定末页条数，
   并恢复正常展示顺序。使用普通 `SELECT`，分页和统计无需 `FOR UPDATE` 或 `FOR SHARE`，也不跨用户操作持有数据库事务。
4. 普通范围统计沿用已显示列表解析出的起止时间，延迟点击时也不移动默认窗口。
   列表、计数和范围统计继续传递 HTTP 取消信号。普通页面按角色、身份和筛选隔离查询缓存，
   相同正在执行的请求合并，变更筛选时取消过时请求，超时后由用户触发重试。后端延续已有请求期限，
   灰度前核对实际取消能传播到数据库。
5. 保留服务端授权、现有过滤白名单和返回脱敏。按需计数令牌使用独立的签名作用域。
   新控制台的分页、查单详情和同窗统计使用独立的控制台路由。V50 和旧分页版在这些路径返回 404，
   因而不会把探测当成普通日志列表、执行精确计数。状态接口未报告新版能力，或分页路由收到 404 时，
   使用带明确起止时间的旧版普通列表。旧路径单次显式操作最多发出一次列表请求。若跳页或末页的计数请求
   需要回退，先显示已算出的总数，再请用户选择目标页。旧列表每次取页仍执行它自身的计数。
   详情收到 404 时，仅用同一引用及列表行的精确秒尝试一次旧入口，只接收授权的单条明细。统计路由不可用时
   提示重试，避免旧统计口径混入结果。灰度验证负载均衡保留新路由和 HTTP 404 语义。

## 5. 实施顺序

| 批次 | 工作及依赖 | 完成信号 |
| --- | --- | --- |
| 1. 范围统计与基线 | 先核对 V50 打开页面、应用筛选和切回窗口时的统计请求。验证当前代码已有的首次点击触发，再补齐筛选变化后显式重算、查询去重、取消和超时手动重试。登记生产镜像和候选提交。现有观测无法拆分时，在候选构建增加分段计时。 | 打开列表或更改筛选均不自动发起统计。点击仍能拿到相同口径的结果，常见交互不会重复触发全范围查询。可独立灰度。 |
| 2. 首页与查单 | 复用分页令牌、摘要投影和详情接口，实现按需计数、总数未知时的分页交互及 Request ID 精确搜索。补普通日志页中英文文案。 | 首页、顺序翻页和查单在不需要总数时均不触发计数。总数、跳页、末页仍可得到准确结果。 |
| 3. 历史窗口与深页 | 用接近生产规模的数据验证最近一小时、昨天一小时、跨日、稀疏类型及深页。分别核对计划、耗时和页结果。在下一次自然高峰继续查证 500 条扫描入口。 | 历史窗口与跳页、末页保留正确行为，实测结果可解释。500 条扫描已使用 ID 下界条件，具体调用方未确认。确认属于本期日志入口且确有首批读放大后，再比较从目标时间窗起读。 |
| 4. 灰度 | 先验证从 V50 升级时前后端协议、迁移和既有功能的兼容性。性能测试分别比较 V50 与当前代码，以及当前代码与候选改动。若制品还包含新版日报或历史回补，独立验收其上线负载，并记录候选镜像对应提交。 | 能区分已有升级收益和本期新增收益。灰度窗口内，列表、统计和核心写入指标可单独比较。功能与性能均通过后再扩大流量。 |

## 6. 验收、监控与回滚

- **功能**：覆盖 0、20、21 条及多页范围，同秒多条日志、翻页、每页条数切换、精确总数、跳页及末页。
  核对跨账号令牌不可复用、个人与管理范围隔离、显式时间筛选、历史 Request ID 和同 ID 多条事件。
  核对计数或统计超时后仍可查单、查看已显示记录和重试。新版查询行为验证 PostgreSQL、MySQL 和 SQLite，
  前端用 Bun 执行相关测试。旧客户端及现有导出入口做回归验证。
- **性能**：用相同查询窗口和相近并发，对比普通日志首屏 P95、每百次新搜索的精确计数次数、
  日志查询耗时、读块和取消率。分别看管理员和个人入口。验收硬条件是仅看首页或顺序翻页的用例
  产生零次精确计数。增加「未点击统计却发起的统计次数」和「同筛选并行统计次数」，验收目标均为零。
  无语句级读块数据时，实例或库级读取增量单独列示。具体延迟和读块改善幅度由基线确定，发布时附实际值。
- **生产归因**：按同一窗口观察 `temp_bytes` 增量、I/O 等待和核心 API 写入尾延迟。捕获慢查询时记录
  脱敏 SQL 形状及等待事件。若出现锁等待，核对阻塞 PID 与事务。统计窗口包含完成、失败和重试成功的任务，
  不用累计值推算某条 SQL 的临时写入。
- **回滚**：发现漏记录、越权、分页合同回归或核心 API 延迟恶化时，撤下新控制台行为或切回上一已验证制品。
  发布前核对回退制品与当时数据库模式兼容。本方案的日志优化不依赖数据迁移、额外索引或改变持久化参数。

上线验证后将已确认的分页和统计行为更新到产品事实文档，将已确认的读取合同和生产验证口径收敛到对应文档。
