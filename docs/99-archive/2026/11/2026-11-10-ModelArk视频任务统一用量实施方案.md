# ModelArk 视频任务统一用量实施方案

## 1. 目标与完成条件

单查和列表的每个 ModelArk V3 视频任务都返回完整、固定的 `usage`。H3、Seedance、JD 及同协议后续模型
使用相同字段与单位。未知值在输出时补 `0`，源数据仍区分未报告和已确认的零。字段清单以
[产品设计](../10-product/ModelArk视频任务用量设计.md)为准，事实边界以
[ModelArk V3 北向合同](../20-architecture/Seedance专用渠道与Link架构.md#6-modelark-v3-北向合同)为准。

本批只实现 ModelArk V3 单查和列表的用量展示，以及现有南向适配器为展示所需的计量提取。创建和删除
响应、原生 NEWAPI、OpenAI、Kling、即梦等接口沿用原协议。接口查询仍只读已保存的 Task。历史记录
读取已有可信值，缺项补零。实施无需历史迁移、批量回源、新轮询任务或供应商重提。

完成条件是北向结构、南向字段映射、部分用量补齐、账本不变和非 ModelArk 接口隔离均通过回归，
且 OpenAPI 与运行时同时更新。代码与 OpenAPI 已实现，真实供应商字段证据和发布验收见第 6 节。

## 2. 实施前基线与缺口

| 路径 | 实施前事实 | 原缺口 |
| --- | --- | --- |
| 单查与列表 | [查询控制器](../../controller/video_modelark.go)调用同一个 [ModelArk 投影](../../controller/modelark_video_projection.go)，由 [Task 转换](../../model/task_modelark.go)组装 `usage`。 | 当前对象及部分数字使用 `omitempty`，没有可展示 Token 时整个对象可能省略。 |
| H3 V2 与 Nexhina | [V2 观察解析](../../relay/channel/task/minimax/official_observation.go)按成功回包解析输出秒、输入视频秒和输入图数，Token 单独归一。[Task 计量接受规则](../../model/task_minimax_official_usage.go)验证预算和边界。 | 已接受的媒体事实未用于公开展示。总秒、音频秒和输入 Token 缺少明确的公开提取路径。 |
| JD | [计费探针](../../relay/channel/task/minimax/adaptor.go)冻结请求秒数，[JD 计量声明](../../pkg/minimaxlink/usage_fields.go)明确 credit 属于供应商证据。 | 当前验收样本只有请求时长和 credit，没有可信输出时长可展示。 |
| Seedance | [Token 归一器](../../relay/channel/task/seedance/thirdparty/usage.go)按现有规则产生完成量和总量。[已接受 Token 投影](../../model/task_seedance_billing_facts.go)保护完成量。 | 保留已发布 Token 语义，按协议确认新增展示字段的来源。 |
| 补报持久化 | [类型化观察保存](../../model/task_seedance_billing_facts.go)在 Task 行锁内更新状态、`data` 和私有计费事实。已有 Token 事实时，它保留整段旧 `data.usage`。 | 把新增字段放入原 `data.usage` 会被整段保护逻辑拦住。需要独立合并展示专用值。 |

现有样本包括 Nexhina #145 的 4 秒、无 Token，#141 的 2K 和单图任务同时报告秒数与 Token，JD
#143 的按请求秒数结算，以及 Seedance 本地历史中的有 Token 和无 Token 任务。参见
[真实验收记录](../99-archive/2026/11/2026-11-10-MiniMax三渠道官网价真实验收与代码审计.md#24-token-数与计费单位)。

## 3. 实施步骤

### 3.1 北向 DTO 与同源投影

1. 更新 [ModelArk DTO](../../dto/modelark_video.go)。`usage` 和 `tool_usage` 使用始终序列化的对象，
   固定数值字段移除 `omitempty`。秒数支持小数，图片、Token 和工具次数为非负整数。
2. 在 [Task 转换](../../model/task_modelark.go)中将用量组装集中到一个 ModelArk 专用投影。它读取已有
   Token 和工具计量、已接受的 V2 媒体计量，以及新增展示专用字段。两条查询路线继续调用同一个投影。
3. 只有已确认的值才进入投影，未知值留到构造公开 DTO 时由数字零值补齐。无用量任务也实例化完整对象。
   保持客户模型名、任务状态、交付地址和时间戳的现有含义。
4. [公开 OpenAPI](../openapi/relay.json)与代码同批发布。为 `ModelArkVideoTask` 加上必返的 `usage`，
   将其全部字段及 `tool_usage.web_search` 标为必返，写清数字类型、秒的单位、零值含义及示例。
   列表复用同一 schema。POST 继续返回既有任务 ID 结构。实施前保持当前公开文档与已运行代码一致。

### 3.2 南向映射与数值校验

| 协议或字段 | 具体接线 | 接受条件 |
| --- | --- | --- |
| H3 V2、Nexhina 的输出、输入视频和图片 | 复用已接受的 `OfficialUsage`。内部 `input_video_seconds` 映射为公开 `input_seconds`。 | 只用通过当前协议、冻结上界和首次接受规则的值。 |
| H3 V2、Nexhina 的音频和上游总秒 | 在 [V2 观察解析](../../relay/channel/task/minimax/official_observation.go)增加独立展示提取。 | 先核对任务身份、状态、已登记字段和单位。音频秒保留有效小数。上游总秒只在协议明确使用输入视频加输出视频的口径时接受。 |
| `total_seconds` 的可计算值 | 在统一投影用已确认的 `input_seconds` 和 `output_seconds` 计算。分项不齐时，使用通过一致性校验的同口径上游总数。 | 先保留字段是否存在，再求和。部分分项下校验已知分项下界和冻结请求上界。分项补齐后按两个已确认分项展示总数。音频秒单列。 |
| H3 与 Seedance 的 Token | 继续使用现有完成和总量归一结果。输入 Token 从已核实的协议路径提取，作为展示字段处理。 | 禁止用缺失值或不同来源的数反推 `prompt_tokens`。已有 Seedance 完成量和总量语义继续由原归一规则决定。 |
| JD 与其他 ModelArk 适配器 | JD 保持原请求秒数计价。其他适配器仅接入可明确映射的媒体或工具用量。 | 请求时长、预计量、计量凭证和私有供应商字段不转成实测。供应商差异由冻结协议解释，客户模型别名不作为判定条件。 |

新增展示字段接受有限、非负且符合协议边界的秒数，以及满足现有计数范围的整数。显式 `0` 是可接受值。
缺失、`null`、负数、非法类型、溢出和语义不明确均按未取得该字段处理。新增展示字段的缺项或无效值
不改变任务状态。现有身份、协议和计费字段校验继续走原入口。

### 3.3 持久化、补报与资金隔离

1. 通过现有观察结果向宿主传递经过验证的展示专用值。只为现有 Task 私有 JSON 增加可选的类型化展示对象，
   保存已有事实源无法承载的新值。字段使用可区分缺失与零的表示。已有的 Token、工具计量及
   `OfficialUsage` 继续从各自权威来源读取，避免为公开响应复制一份结算事实。
2. 在 [观察保存事务](../../model/task_seedance_billing_facts.go)的现有 Task 行锁内，对展示专用字段逐项合并。
   第一次有效值，包括明确的零，可成为已确认事实。后续可信观察补齐尚未接受的字段。重复相同值幂等，
   缺失、无效值、陈旧回包和冲突值均保留先前接受的有效值。既有 `data.usage` 的 Token 保护仍适用。
3. 同时核对 [轮询写入](../../service/task_polling.go)和 [用量补查](../../service/task_usage_recovery.go)
   的传递路径。仅使用已存在的可信观察和恢复入口。已终态任务若后续没有观察，展示缺项保持为零。
   只读查询和 OSS 转存不写用量，展示缺项不新增调度或资金事件。
4. 保持 [终态计费准备](../../service/task_billing_reconcile.go)与
   [结算求值](../../service/task_tiered_calculation.go)读取原事实源。新增展示值及北向默认零不得写入
   `UsageFacts`、计费快照、已接受计量、资金目标或账本。缺少计费必需用量的任务继续等待现有补查。
5. 历史 Task 无新增展示对象时只读原字段并补零。保持数据库列、索引、异步状态机和现有权限边界。
   诊断只记录必要的字段名与结果类别，公开响应只输出白名单字段和数值。

## 4. 验收矩阵

| 场景 | 预期结果 | 验证方法 |
| --- | --- | --- |
| 排队、运行、失败、取消、过期及历史任务无用量 | 单查与列表中的任务都包含完整 `usage` 和 `tool_usage`，所有数值为数字 `0`。 | 固定本地任务和 HTTP JSON 断言，同时覆盖同一任务版本的两条 GET。 |
| Nexhina #145 已有成功任务 | 已保存的 4 秒输出与 0 秒输入视频可投影出总秒 4。缺少 Token 时，三个字段都为 0。原预扣、结算、退款与尝试次数一致。 | 复用既有任务和本地账本，核对原 600,000 预扣、160,000 结算、440,000 单次退款。 |
| Nexhina #141 已有成功任务 | 秒数和 Token 可同时返回。原有完成、总 Token 值保持。 | 复用 2K 文生或单图样本的 Task 与计费快照。 |
| H3 V2 新字段 | 供应商回包有可信音频秒、输入 Token 或总秒时，数值经过保存后在两条 GET 可见。6 秒音频不计入视频总秒。 | 固定官方 V2 回包，例如输入视频 0、输出 5、音频 6、总秒 5。含音频组合使用允许该输入的协议测试。 |
| Seedance 有用量、部分用量、无用量 | 已发布 Token 归一结果一致。输入 Token 来源明确时显示，未确认的媒体和工具计量补零。 | 使用已有 Task 和协议回包，覆盖仅完成、总量减输入、显式零及仅输入 Token。 |
| JD 请求秒数与 credit | 请求 4 秒且仅有 credit 时，展示输出秒仍为 0，客户计费按冻结请求秒数计算。 | 复用 JD #143 或固定 JD 回包，检查账单和响应口径。 |
| 补齐、冲突与并发 | 首次缺项显示 0，可信补报后显示实测。明确接受的零、既有值及旧 Token 快照受保护，重复或陈旧回包不会增加资金事件。 | 复用观察与补查测试入口，核对响应、Task 快照及预扣、结算、退款的行数和金额。 |
| 协议与授权隔离 | ModelArk 的用户和应用隔离继续生效。创建、删除、错误响应与其他协议仍符合各自契约。 | 复用路由、错误和归属隔离回归，增加与本次响应结构直接相关的断言。 |

实施后运行定向 Go 测试，覆盖 ModelArk 投影与路由、H3 与 Seedance 观察解析、部分用量补查及异步结算。
文档验证运行 `task docs:check`、`task ai:check` 和 `cd web && bun run docs:validate`。
新增真实任务只有在既有任务和固定回包无法覆盖明确的供应商字段时才需要。届时选目标协议最短有效时长、
最低价可用模型和分辨率，限制请求次数，分别记录真实验证与自动化验证的结论。

## 5. 发布与风险控制

| 风险 | 处理与发布门槛 |
| --- | --- |
| 旧客户端把 `usage` 存在视为用量已齐 | 更新接口说明和示例，检查受控客户端对新增字段、全零对象和零值出现的处理。对拒绝额外字段的严格客户端，发布前确认升级安排。 |
| 新字段一直显示零，响应结构测试仍通过 | 每个新增字段至少有一个可信输入到客户 JSON 的非零断言。另验缺字段和显式零。 |
| 同名值含义或单位不同 | 每种协议只映射有依据的字段。秒数支持小数，计数保持整数。总秒和 Token 都不能由占位零推算。 |
| 并发轮询或补查让已接受值回退 | 现有行锁内逐项合并。发布前通过缺项补齐、冲突、并发和重复事件的验收。 |
| 混合版本的后台节点重写私有 JSON | 确认同一环境处理 Task 的轮询、恢复和查询节点均支持新字段后再宣布新合同可用。灰度核对重启后的用量持久性。 |
| 展示字段改变资金结果 | 对相同观察序列比较结算目标、账户变化和资金事件。任何变化都阻断发布，先定位是否把展示字段传入资金逻辑。 |

灰度前核对调用方解析和任务写入节点版本。回滚时应用和 OpenAPI 使用同一版本。旧节点重写整段私有 JSON
可能丢失新字段，灰度和回滚演练都要核对已保存的用量及账本。

## 6. 完成度复核与实施顺序

| 顺序 | 项目 | 当前状态与交付条件 |
| --- | --- | --- |
| 1 | 北向契约与隔离 | 已实现。单查和列表共用投影与 schema。已有真实记录和渠道回归覆盖基本结构、账本与归属。 |
| 2 | 展示值与协议边界 | 已修复并回归。MiniMax V2 丢弃小于已知分项或超过冻结上界的候选总秒。Seedance 从已确认的回包结构提取计数。共享轮询按北向协议清理展示字段。 |
| 3 | 展示字段的协议证据 | 部分验收。已保存任务证明秒数与 Token 可同时返回。H3 音频秒、Seedance 搜索次数等正值使用固定回包。对官方 V2 与 Nexhina V2 分别核对总秒和音频单位，对 Seedance 的正值来源按协议留证。 |
| 4 | 发布与运行验收 | 待验证。确认交付版本包含代码及 OpenAPI，受控客户端能处理固定字段和全零对象。核对同版本任务写入节点、滚动切换、重启与回滚后的用量、资金事件和单查列表一致性。 |

第 2 项沿用南向解析、Task 行锁合并与北向投影。行锁内以已接受的分项和冻结上界校验候选总秒，
查询使用同一规则。固定回包覆盖以下场景。

- 输出已知、输入待报、候选总秒低于输出或高于冻结上界。公开总秒为 `0`，后续有效候选可以补齐。
- 部分分项下的同口径候选合法。分项补齐后按已接受分项求和，重复观察保持资金事件的行数和金额。
- 冻结请求明确无输入视频。总秒等于已确认的输出秒数，音频秒单列。
- Seedance 的搜索次数仅接受登记结构中的数字计数。点号键和字符串计数不会进入展示字段。
- Seedance 观察清理内部展示字段的大小写变体。查询解析按精确键接收宿主生成的载体。
- Seedance 中转的展示值支持顶层和 `data` 内的 `usage`。同值保留，冲突只影响对应展示字段，完成 Token 仍按既有规则结算。

单查和列表回归覆盖排队、运行、失败、成功、取消和过期。真实既有任务只读复验覆盖 Nexhina 768p、Nexhina 2K、
JD 和 Seedance，单查与列表一致，既有预扣、结算和退差额与前述记录一致。

第 3 项优先读取已有任务和脱敏供应商观察。证据不足的字段按待验收登记。第 4 项记录实际版本、抽样结果和
回滚演练结论后，再关闭本方案。
