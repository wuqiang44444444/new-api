# Nexhina 视频履约边界实施方案

## 目标与范围

Nexhina Seedance Mini 已在同一客户模型和 ModelArk V3 入口验证 HTTPS 图片直传、普通图片 `asset://`、
结算和本站 OSS 交付。本次修正新协议继承官方传输 profile 后的取消、删除和轮询语义，并将 Mini 模型目录的
媒体能力对齐实测。MiniMax H3 沿用既有 Link 协议和能力范围。真实真人认证、音视频素材入库及其它模型的媒体
能力另行验收。

## 实施顺序

1. 在 Seedance 任务生命周期中以冻结的 Nexhina 视频协议为依据，禁止未验证的上游取消与删除。插件模型声明
   同时关闭视频删除，并按实测发布文本与普通图片。保留统一北向入口、URL 直传与显式素材入库的分工。
2. 在 Nexhina Seedance 查询层拦截未证实为永久缺失的 HTTP 404/410，交给现有观察对账路径。
   真实任务状态和用量继续由当前 ModelArk V3 解析与结算处理。
3. 验证公开能力与生命周期一致，验证一次查询异常后仍可读到成功并正常结算，补充当前架构事实。

## 完成条件

- Nexhina 排队任务的取消和终态删除都不向上游发出请求。火山官方的已支持操作不受影响。
- 任务收到 HTTP 404 或 410 后仍可完成，资金不因该次观察而失败或退款，后续成功仅结算一次。
- Mini 目录发布文本和图片，保持普通图片素材能力，完成插件、轮询、生命周期与文档检查。
- 现有真实 HTTPS、素材引用和 OSS 证据作为正向基线，异常响应使用可重复的本地回归验证。

## 状态

代码与本地回归已完成。回归覆盖排队取消和终态删除不出站、404/410 后保留预扣并按成功用量结算一次，
以及 Mini 的公开媒体类型、单图和删除能力。当前事实见 [Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)。
本轮验证未发布生产或灰度，也未改变真人认证与其它未验证能力的开放范围。
