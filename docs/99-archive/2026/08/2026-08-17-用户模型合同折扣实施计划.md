# 用户模型合同折扣实施计划

## 1. 目标与范围

本计划落实[用户模型合同折扣与渠道组约束设计](../80-dev/2026-08-17-用户模型合同折扣与渠道组约束设计.md)，
为按 `User ID` 管理的 B 端客户提供精确模型白名单、唯一渠道组和每模型合同折扣，同时证明未启用合同
模式的用户继续执行 NEWAPI 原生权限、分发和计费逻辑。

实施完成后，管理员只需维护：

```text
User ID + 精确公开模型 + 唯一渠道组 + 合同折扣
```

本计划不包括素材/素材组合同、多用户组织合同、定时生效、单 KEY 独立定价、Provider 成本折扣或历史
账单重算。代码、SQLite 与本地自动化测试阶段已完成；真实 MySQL/PostgreSQL 环境、真实 Provider/
真实账单核对、人工响应式验收和生产灰度仍未完成，因此本计划继续保持 `in-progress`，不得表述为生产已发布。

## 2. 实施原则

1. **原生分支零变化：** `contract_mode=false` 必须尽早返回原生路径，不能读取规则表或改变上下文。
2. **一份合同事实：** 授权、模型发现、价格展示、路由和计费读取同一版本化合同快照。
3. **失败关闭：** 合同状态无法确认时，不允许回退到原生权限、倍率 `1` 或旧缓存。
4. **最小入侵：** 业务主体放入新增文件；原生热路径只增加必要的单行调用或极窄分支。
5. **先修结算一致性：** 在开放合同用户前，关闭 Realtime 和异步非表达式重读当前倍率的风险。
6. **三库一致：** 所有模型、索引、事务、锁和迁移同时支持 SQLite、MySQL 与 PostgreSQL。
7. **先测试后灰度：** 单元测试或 SQLite 通过不等于真实账单、外部数据库或生产可用。

### 2.1 2026-08-17 实施状态

已完成：

- 按 User ID 的合同模式、八位定点折扣、完整替换事务、`expected_version`、只追加审计和鉴权缓存围栏；
- 精确模型白名单、Token 模型限制交集、唯一渠道组锁定、组内原生选渠、Seedance 确定性路由约束；
- 同一合同拒绝仅大小写不同的模型名；可履约查询统一要求启用 Ability 与启用 Channel；
- `/v1/models`、控制台 `/api/models`、Seedance 模型目录、模型详情和 `/api/pricing` 的合同投影与失败关闭；
- Token、固定价、tiered、图片/视频固有倍率、音频、Realtime 和异步任务合同计费快照；独立工具费不打折；
- 固定价音频/Realtime 的 `ModelPrice` 终态接线、异步规范化实际用量和原生特殊组倍率回归；
- 管理员四态用户摘要、宽合同侧边栏、批量选模型、未保存价格预览、版本冲突恢复和分页审计；
- 原生组倍率保存前展示受影响的生效合同数、规则数和渠道组；
- API Key 页面用户级只读合同价格，且不返回渠道组、Channel、Provider 或上游模型；
- 七种前端语言、合同 UI 组件测试、后端合同测试，以及可由独立 DSN 启用的 MySQL/PostgreSQL 关键事务测试。

仍需发布阶段完成：真实 Provider 请求和真实额度/账单对账、订阅与钱包生产样本、最低数据库版本环境、
375px—1440px 人工响应式/键盘验收、内部用户灰度和低流量 B 端客户灰度。

### 2.2 最小入侵复核

| 接线面 | 原生文件中的必要窄改动 | 合同主体所在新增文件 |
| --- | --- | --- |
| 用户与鉴权 | User 增加模式/版本，缓存 hash 增加同字段，鉴权写入上下文 | `model/customer_contract.go`、`service/customer_contract.go` |
| 分发 | 分发最前方调用精确合同守卫；合同分支锁组并禁止扩大权限 | `middleware/customer_contract.go` |
| 发现与价格 | 原生 Controller 顶部早返回 | `controller/customer_contract_models.go`、`controller/customer_contract_pricing.go` |
| 计费 | 各模型费用舍入前调用合同乘数；nil 事实原值返回 | `relay/helper/customer_contract_billing.go`、合同 service 测试 |
| 异步 | 既有 Task/attempt 快照增加合同事实 | `types/customer_contract.go` 与合同结算测试 |
| 前端 | 用户行和 KEY 页各插入一个入口/卡片 | `user-contract-drawer.tsx`、`customer-contract-pricing.tsx` |

没有为原生用户查询合同规则；没有改写原生分组、Token、Ability 或价格配置；没有给素材控制面增加合同
语义。原生异步任务仍保留当前倍率读取，只有带冻结合同事实的 Task 走合同快照。

## 5. P1：数据模型、迁移与合同聚合服务

### 5.1 目的

建立跨数据库、可审计、可版本化的合同持久化事实，并让其它层只依赖一个合同聚合服务。

### 5.2 数据模型

- [x] 在 `User` 增加 `contract_mode` 和 `contract_version`，业务默认值由代码与迁移初始化，不使用会导致
  三库重复 `ALTER` 的布尔 GORM 默认标签。
- [x] 同步扩展 `UserBase`、`ToBaseUser()`、Redis hash 编解码和 `userCacheSchemaVersion`。
- [x] 新增 `CustomerModelContract`，使用 `ratio_units` 八位定点整数及
  `UNIQUE(user_id, public_model)`。
- [x] 新增只追加 `CustomerContractAudit`，before/after 使用 `TEXT`，通过 `common.Marshal` 写入。
- [x] 在 `model/main.go` 的 AutoMigrate/初始化路径注册新结构，验证存量用户初始化为原生模式。
- [x] 明确软删除、硬删除和审计保留：软删除用户不删除合同；硬删除清理当前规则，但保留不含敏感信息的
  审计或按现有用户删除政策处理，实施前用测试固定唯一口径。

### 5.3 聚合服务

建议新增独立文件而不是扩写原生模型：

```text
model/customer_contract.go
model/customer_contract_audit.go
service/customer_contract.go
service/customer_contract_validation.go
service/customer_contract_cache.go
types/customer_contract.go
```

服务职责：

- [x] 解析并验证十进制折扣，转换为 `ratio_units`，拒绝 `<=0`、`>1`、超过八位小数和非有限值。
- [x] 精确保存公开模型名，不调用原生模型通配/别名格式化函数。
- [x] 读取用户合同聚合：模式、版本、按公开模型索引的不可变规则快照。
- [x] 校验具体组存在、不是 `auto`，且保存/启用时当前至少有一条可履约渠道。
- [x] 为 Seedance Link 模型复用现有唯一渠道查询，只校验唯一渠道属于指定组，不写 Ability、不建立候选路由。
- [x] 提供合同当前可用性的只读派生，不把渠道不可用状态写回规则。
- [x] 提供统一 `ContractBillingFact`，供请求、价格、日志和 Task 快照使用。

### 5.4 单元与数据库测试

- [x] 表驱动测试覆盖比例最小值、`1`、八位精度、零、负数、加价、九位小数和非法字符串。
- [x] 唯一约束在 SQLite、MySQL、PostgreSQL 行为一致。
- [x] 同一用户同一精确模型不能重复，不同用户可以使用不同折扣。
- [x] 请求按 `Model-A` 与 `model-a` 精确匹配；为消除 MySQL 默认 collation 差异，同一合同禁止同时保存

### 5.5 退出条件

- [x] 其它层不直接查询合同表，只通过合同聚合服务取得快照。
- [x] 未启用合同的用户能在鉴权缓存中明确识别为原生模式。

## 6. P2：事务、鉴权缓存围栏与管理 API

### 6.1 目的

保证合同启用、收窄、改组和改价提交后，存量 KEY 不能继续使用陈旧权限或旧价格；管理员并发修改不能
互相覆盖。

### 6.2 写事务

- [x] 写接口接受完整期望规则集、目标模式、`expected_version` 和必填原因。
- [x] 使用 `lockForUpdate(tx)` 锁定用户，比较 `contract_version`。
- [x] 在事务中完成规则 diff、校验、批量写入、模式切换、版本增加和审计写入。
- [x] 所有影响授权或计费的合同写操作调用 `IncrementUserAuthVersionWithTx`，复用现有 Redis pending
  fence；事务提交后刷新 `UserBase` 和 committed version。
- [x] 创建第一批规则与启用合同必须是同一事务；不能出现规则已保存但用户仍原生，或用户已合同化但
  规则尚未保存的窗口。
- [x] 删除最后规则不修改 `contract_mode`；显式停用只修改模式并保留规则。
- [x] 启用零规则合同允许成功，结果为零模型权限。
- [x] 重新启用时重新校验全部规则和当前渠道可用性。

### 6.3 版本缓存

- [x] 合同快照缓存键包含 `user_id + contract_version`，值写入后不可变。
- [x] 读取返回 `native / contract(snapshot) / error` 三态，错误不能转换为 native。
- [x] 合同用户缓存 miss 回源主数据库；主库失败或快照损坏时失败关闭。
- [x] 原生用户根据 `UserBase.contract_mode=false` 直接走旧路径，不访问规则缓存或数据库。
- [x] 事务提交后即使缓存刷新失败，pending fence 仍阻断陈旧请求；恢复后从主库读取新版本。
- [x] 禁止用过期合同缓存、默认倍率 `1` 或旧规则作为可用性降级。

### 6.4 管理 API

在现有管理员 Router 下新增用户合同聚合接口，最小支持：

- [x] GET：模式、版本、完整规则、派生可用性、当前原生倍率和最终价格预览；
- [x] PUT：使用 `expected_version` 原子替换完整规则集；
- [x] POST/PATCH：显式启用或停用，或统一并入 PUT 的目标状态；
- [x] GET audit：分页读取该用户合同审计。

具体 URL 遵循现有用户管理路由，不额外建设第二套管理员身份或权限系统。

### 6.5 风险提示

- [x] 存在 `GroupGroupRatio[userGroup][routeGroup] != 1` 时返回双重折扣提示，不删除或忽略该原生配置。
- [x] 停用合同前返回“所有 KEY 将恢复原生权限”的高风险确认信息。
- [x] 修改原生组倍率的现有管理界面能够预览受影响的生效合同数、规则数和渠道组，并在保存前提示；
  不自动冻结或改写合同。
- [x] 审计保存管理员实际看到的警告、原生倍率、合同折扣和最终倍率。

### 6.6 测试与退出条件

- [x] 两个管理员用同一 `expected_version` 更新时只有一个成功，另一个收到版本冲突。
- [x] 事务任一步失败均不产生部分规则、错误模式或缺失审计。
- [x] Redis 正常、不可用、写失败、陈旧 hash、陈旧合同快照均覆盖失败关闭测试。
- [x] 合同启用后所有已缓存 Token 的下一次请求取得新用户 auth version，不能继续原生授权。
- [x] 管理 API 只允许管理员访问，不在响应中泄露 Channel Key、Provider 模型或凭据。

## 7. P3：请求授权、模型发现与唯一组路由

### 7.1 目的

使合同规则真正成为服务端授权，而不是只过滤页面；任何直接请求、陈旧 KEY 或原生组选项都不能绕过。

### 7.2 请求上下文

新增合同上下文键或 `RelayInfo` 字段：

```text
contract mode
contract version
exact public model
route group
ratio units
```

- [x] Token 鉴权把 `UserBase` 中的合同模式和版本写入上下文。
- [x] 在能够取得公开模型的最早公共位置调用合同守卫。
- [x] 合同守卫先精确匹配合同，再执行 Token 模型限制交集。
- [x] 合同外模型使用统一普通用户错误；管理员日志包含脱敏拒绝原因。
- [x] 合同失败发生在 Affinity、分发、`model_mapping`、预扣、attempt 和 Provider POST 之前。

### 7.3 原生路由接线

- [x] 合同命中后将 `UsingGroup` 设置为规则 `route_group`。
- [x] 忽略 Token 固定组、AutoGroups、Playground Group 和跨组重试对候选组的扩大作用。
- [x] 允许原生 Affinity、Priority、Weight、随机选择和重试在合同组内部继续工作。
- [x] 每次重试校验最终组仍等于合同组；禁止因无渠道切到其它组。
- [x] 使用合同用户 Key 的指定渠道请求仍检查该 Channel 是否属于合同组并支持精确模型；管理员独立渠道
  测试入口保持排除。

原生热路径预计只在以下位置增加窄接线：

| 原生文件 | 必要性 | 最大允许改动 |
| --- | --- | --- |
| `middleware/auth.go` | 将已缓存合同模式/版本写入请求上下文 | 字段写入，不放业务校验 |
| `middleware/distributor.go` | 在分发前执行合同守卫并锁定组 | 单个早期调用与窄分支 |
| `controller/model.go` | 合同模式返回精确模型投影 | 早期分支调用新增服务 |
| `controller/pricing.go` | 合同用户返回合同价格投影 | 早期分支调用新增服务 |

若某个入口不经过 `Distribute()`，在该 Router 增加同一合同 middleware，不复制校验逻辑。

### 7.4 Link 视频边界

- [x] Seedance 视频创建检查精确合同模型并冻结合同计费事实。
- [x] 继续由现有 Seedance 专用模型登记选择唯一 Channel，不写原生 Ability，不使用合同组构造候选集。
- [x] 校验该唯一 Channel 属于合同 `route_group`；不匹配时失败关闭。
- [x] Task 查询、删除、结果和素材 API 不重新读取当前合同，也不因规则删除而隐藏历史 Task。

### 7.5 模型发现和价格投影

- [x] `/v1/models` 合同分支只读取精确规则与当前可用性，再与 Token 模型限制取交集。
- [x] 渠道组以后新增的模型不会自动出现在合同列表。
- [x] `/api/pricing` 合同分支只返回合同模型及当前折后价格，不返回其它可用组模型。
- [x] 普通用户响应不返回组名、特殊组倍率、Channel、Provider 或上游模型。
- [x] 合同读取失败时返回失败，不回退原生模型列表或价格列表。

### 7.6 测试与退出条件

- [x] 覆盖无档案、停用档案、启用零规则、命中规则、合同外模型、Token 进一步收窄。
- [x] 覆盖直接 API 请求、陈旧 Token Group、AutoGroups、Playground Group、Affinity 和跨组重试绕过尝试。
- [x] 覆盖组内多渠道正常选择、全组不可用、恢复同组和禁止跨组 fallback。

task docs:check

## 14. 完成定义

只有同时满足以下条件，计划才可标记完成：

1. 原生模式黄金测试证明模型发现、分发和计费无变化。
2. 合同模式严格执行精确模型白名单、唯一渠道组和每模型折扣。
3. 同步、Realtime 和异步客户费用全部使用同一合同快照语义。
4. 工具费、违规费、充值折扣和 Provider 成本不受合同折扣影响。
5. 合同启停、规则修改、缓存失败和并发更新全部满足失败关闭与审计要求。
6. SQLite、MySQL、PostgreSQL 迁移和关键事务通过验证。
7. 管理端配置流程和 API Key 只读价格展示通过前端测试与人工验收。
8. 至少一个真实 B 端灰度客户完成模型权限、同步账单和异步终态账单核对。
9. 稳定事实已经收敛到 10/20/30/40/90，未完成生产事项保留在路线图。

单元测试通过、SQLite 本地运行或页面能够保存，均不能单独视为本计划完成。
