# 飞彩十模型双渠道实施计划

## 目标与范围

按[飞彩十模型双渠道专用协议设计](2026-08-11-飞彩十模型双渠道专用协议设计.md)完成首版代码、管理界面、
当前事实文档和本地数据库配置。本计划只开放十模型的 16:9 请求，建立两个初始停用的飞彩
Seedance Link Channel，不包含真实 Provider 生产启用或真实账单确认；旧飞彩历史数据按明确授权直接清理。

## 批次与依赖

### P0：固定协议与模型事实

- [x] 新增 `feicai_videos_v1` 管理协议和 `third_party_feicai_videos` 内部 profile。
- [x] 新增飞彩专用 adapter package，精确登记 10 个 Provider 模型。
- [x] 在持有资金前校验分辨率、16:9 画幅、时长和媒体输入限制。
- [x] 计费探针区分九个按秒模型与 Pro PI 按次模型。

依赖：已确认模型表、`size=1280x720` 的 16:9 语义和首版不开放其它画幅。

### P1：接线与旧实现清理

- [x] 将创建、轮询、删除不支持声明、内容代理和 adapter version 精确接到新 profile。
- [x] 删除 `third_party_json_video_media_arrays` profile 及其轮询、响应归一和内容代理兼容分支。
- [x] 移除新 Channel 对 `url_media_arrays_v1` 的选择与自动迁移，不增加 alias 或 fallback。

依赖：P0 完成，现有 durable attempt/Task 合同不改。

### P2：管理界面与七语言

- [x] 更新 Channel 表单类型、协议选项与协议-素材配对。

- [x] 通过项目 i18n 脚本写入 en、zh、zh-TW、fr、ja、ru、vi 并运行同步校验。

依赖：P1 的最终协议枚举。

### P3：当前事实文档

- [x] 把飞彩当前协议、十模型表、16:9 限制、两渠道与旧数据清理事实收敛到允许的
  `10-product/`、`20-architecture/`、`30-engineering/` 和 `40-operations/` 当前事实文档。
- [x] 不修改 `70-research/` 原始调研和 `99-archive/` 历史文档。

依赖：P0—P2 代码合同稳定。

### P4：数据库配置

- [x] 备份本地 `one-api.db`。
- [x] 新建初始停用的飞彩 VIP 五模型 Channel。
- [x] 新建初始停用的飞彩性价比五模型 Channel。
- [x] 删除旧飞彩 `DoubaoVideo` Channel、Ability、历史 Task、attempt 和直接关联数据。
- [x] 以只读查询核对新 Channel 类型、状态、协议、模型清单和映射，不输出密钥。

依赖：P1 已实现；凭据从已有 VIP/性价比作用域安全复用，新 Channel 在真实验收前保持停用。

### P5：验证与交付

- [x] 运行受影响前端测试、typecheck、lint、i18n sync 和生产构建。
- [x] 运行 `task docs:check` 和 `task ai:check`。
- [x] 区分“本地实现完成”与“真实 Provider/账单/生产验收完成”，新 Channel 保持停用。

依赖：P0—P4 完成。

## 状态与验收

当前状态：本地实现已完成；真实 Provider、账单和生产灰度尚未验收，两个新 Channel 保持停用。

本地实现完成信号：

1. 新 Channel 只能选择 `feicai_videos_v1`，10 个精确 Provider 模型均可进入对应校验与计费分支；
2. 任意非 16:9、分辨率不匹配、时长/媒体越界都在 Provider POST 之前明确失败；
3. Pro PI 计费模式为按次，其余九个为按秒；
4. 代码和数据库均不再引用 `third_party_json_video_media_arrays`；
5. 本地数据库有且仅有本次新增的两个停用飞彩 Link Channel，模型清单与映射精确；
6. 相关代码、前端、i18n 和文档校验通过。

生产启用信号仍为：使用正式 HTTPS、目标凭据和 ModelArk V3 完成十模型真实视频、账单、
unknown/失败和灰度验收；不得用本地测试替代。
