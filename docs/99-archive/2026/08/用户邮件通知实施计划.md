# 用户邮件通知实施计划

> 本计划的代码、管理开关、前端表单和 i18n 已完成；真实 SMTP 与灰度验证转入
> [路线图](路线图.md#用户生命周期邮件生产验收)。本文等待用户明确授权后归档，不再作为当前执行入口。

## 1. 计划定位

本计划把《用户邮件通知改造方案》（`../80-dev/2026-08-10-用户邮件通知改造方案.md`）落地为代码。方案文档定义设计与决策，本计划定义**批次、文件、门禁和完成顺序**。本期只做账户创建 / 密码修改 / 密钥创建三类事件即时邮件；余额提醒、退订、邮箱验证不在本期。

## 2. 设计决策（摘要，详见方案文档）

- 事件即时，**controller 提交事务后内联**（不放 model 尾部，避免 `model → service` 循环依赖）。
- 异步 `gopool.Go`，失败不重试。
- 配置驱动：新建注册块 `notification_setting`（Pattern b），3 个 bool 开关，UI 塞进现有 **Operations → Monitoring & Alerts**。
- 统一走 `service.NotifyUser`（复用地址解析、`NotificationEmail` 覆盖、限频、未设 NotifyType 默认 email）。
- 中英双语 `i18n.Translate`。
- 邮箱强制：`Register` + `CreateUser` 两处；OAuth/微信不强制；存量用户前端提示；**不验证、不加 `email_verified` 列**。

## 3. 实施批次（最小优先，每批可独立合入与验证）

### 批次 0 — 配置底座 + 管理开关

后端新增文件（零上游冲突）：

- `setting/operation_setting/notification_setting.go`：照搬 `monitor_setting.go`（Pattern b）。结构体 `NotificationSetting{ SendEmailOnAccountCreated, SendEmailOnPasswordChanged, SendEmailOnTokenCreated bool }`，默认全 `false`，`init()` 里 `config.GlobalConfig.Register("notification_setting", &notificationSetting)`，导出 `GetNotificationSetting()`。
- `service/user_lifecycle_notify.go`：三个封装函数 `NotifyAccountCreated(userId)` / `NotifyPasswordChanged(userId)` / `NotifyTokenCreated(userId)`。每个统一做：读 `GetNotificationSetting()` 对应开关 → 关则 `return` → `gopool.Go` 异步 → `model.GetUserLanguage(userId)` 取语言 → `i18n.Translate` 构双语标题/正文 → `service.NotifyUser(userId, email, setting, dto.NewNotify(...))`。复用 `model.GetUserById` + `User.GetSetting()`。
- i18n：`i18n/locales/{en,zh-CN,zh-TW}.yaml` 追加 `notify.account_created.* / password_changed.* / token_created.*`（标题 + 正文）；`i18n/keys.go` 加常量。

前端：

- `web/src/features/system-settings/types.ts`：`OperationsSettings` 加 `SendEmailOnAccountCreated / SendEmailOnPasswordChanged / SendEmailOnTokenCreated: boolean`。
- `web/src/features/system-settings/integrations/monitoring-settings-section.tsx`：`QuotaRemindThreshold` 旁加 3 个 `SettingsSwitchItem` + zod 字段，**复用现有逐字段 diff + `updateOption.mutateAsync` 保存循环**。

门禁：`go build ./...`；`cd relaykit && GOWORK=off go build ./...`；`cd web && bun run build`；页面可见 3 开关、切换后 `PUT /api/option` 持久化、重载保留；默认全关。

### 批次 1 — 密钥创建通知（1 接线点）

- `controller/token.go` `AddToken`：`cleanToken.Insert()` 成功后、响应前（约 `token.go:336`）加 `service.NotifyTokenCreated(c.GetInt("id"))`。
- 注册时 `GenerateDefaultToken` 自动建 token 路径（`user.go:291-317`）**不接线**，避免注册即两封。

门禁：开关开 + 配 SMTP → 建 token 收到中英邮件；开关关 → 不发。

### 批次 2 — 密码修改通知（2 接线点，安全价值最高）

- `controller/user.go` `UpdateSelf`：密码分支 `AdvanceCurrentSessionToUserVersion` 后（约 `user.go:909`）加 `service.NotifyPasswordChanged(userId)`。
- `controller/user.go` `UpdateUser`：`updatePassword` 分支 `EditWithTx` 提交后（约 `user.go:713` / `:729`）加 `service.NotifyPasswordChanged(updatedUser.Id)`。
- 忘记密码重置路径不接线（重置链接已发邮箱）。

门禁：自改密码 / 管理员改密码 → 收到邮件；非密码字段更新 → 不发。

### 批次 3 — 账户创建通知 + 邮箱强制（前端改动最大）

后端：

- `controller/user.go` `Register`：username 校验后（约 `user.go:223`）加 `if user.Email == "" { 报错 }`；`insertedUser` 取出后（约 `user.go:289`）加 `service.NotifyAccountCreated(insertedUser.Id)`。
- `controller/user.go` `CreateUser`：初始必填判断（`user.go:1015`）把 `user.Email == ""` 加入；`cleanUser` 增加 `Email: user.Email`（`user.go:1032`，目前被丢弃）；`FinishInsert(0)` 后（`user.go:1056`）加 `service.NotifyAccountCreated(cleanUser.Id)`。

前端（两处真实表单改动，**非"+2 行"**）：

- 注册表单 `web/src/features/auth/sign-up/components/sign-up-form.tsx`（`:299`）：邮箱字段当前包在 `emailVerificationRequired && (...)` 内 → 拆出**始终渲染且必填**；验证码字段保留条件渲染；标签 "Email (required for verification)" → "Email"。
- 管理员建号抽屉 `web/src/features/users/components/users-mutate-drawer.tsx`：当前**无邮箱字段** → 新增 email 输入 + 必填校验。
- 个人设置页：当前登录用户 `Email == ""` 时显示一行提示（条件渲染 + i18n）。

门禁：注册不填邮箱 → 被拒；填邮箱 → 收欢迎信；管理员建号不填邮箱 → 被拒；OAuth/微信无邮箱 → 注册成功、不发信；存量无邮箱用户设置页见提示。

## 4. 最小入侵自检

- 新逻辑 100% 在新文件（2 个 Go 文件 + i18n key/常量）。
- 现有文件改动仅两类：(a) 单行 `service.NotifyXxx(...)` 接线（5 处 controller）；(b) 校验 / 类型字段 / 表单字段。无重命名、无重排、无抽象提取。
- model 层零改动（规避循环依赖）。
- 三数据库：`notification_setting` 走 `options` key-value 表，**无 schema 迁移**，天然兼容 SQLite/MySQL/PostgreSQL。

## 5. 端到端验证矩阵

| 场景 | 预期 |
|---|---|
| SMTP 未配 + 开关开 | 不发（`SendEmail` 返回未配置，日志记录） |
| 开关关 + 事件发生 | 不发 |
| 开关开 + 有邮箱 + 事件 | 发中英邮件 |
| 开关开 + 无邮箱 | 静默跳过（`NotifyUser` 日志） |
| 注册自动建 token | 只收欢迎信，不收密钥信 |
| 非密码字段更新 | 不发密码通知 |

## 6. 风险与回滚

- 每批独立，回滚 = revert 该批 commit。
- `NotifyUser` 限频可能压掉 password-changed：单人小时级改密不现实，可接受；后续若需绝对保证，password-changed 改走 `common.SendEmail` 直发（与现有重置密码邮件一致）。
- 邮箱不可信：本期不验证；未来需可信送达时再加 `email_verified`。
