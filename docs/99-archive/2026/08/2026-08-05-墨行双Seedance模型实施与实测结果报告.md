# 墨行双 Seedance 模型实施与实测结果报告

## 1. 结论

本次只实施和测试墨行当前两个模型，不把飞彩、FunCloud、BytePlus 或历史 Ark 当作墨行模型：

| 当前模型 | 当前 implementation | 计费候选 | 生产姿态 |
| --- | --- | --- | --- |
| `seedance-2-0-oversea` | `moxing.seedance-media-task@v2` | 480p/720p 按量 | Channel/Ability 禁用；无 publication；模型 Key 预检 401 |
| `doubao-seedance-2-0-260128` | `tokensave.seedance-media-task@v2` | 480p/720p/1080p 按秒 | Channel/Ability 禁用；保留 publication；4 秒 480p 文生及本站 8100 全链路实测成功 |

代码、合同、数据库候选配置和基础文生黑盒已经推进，但尚不能宣称生产发布。oversea 缺少有效凭据；
doubao 尚缺素材场景、其它分辨率、智能时长、音频开关、实际 Provider 账单及失败/exposure 链路证据。
因此两个渠道都保持失败关闭，本报告保持 `in-progress`。

## 2. 设计与代码实施

### 2.1 当前模型边界

- 两个模型分别使用 Moxing 与 TokenSave origin、独立 implementation、精确 execution binding、价格和素材 binding；不能互相降级。
- `seedance-2-0-oversea` 只发布 480p/720p；`doubao-seedance-2-0-260128` 才发布 1080p。
- 两者都要求非空文本、显式 `duration/resolution/ratio`，时长只允许 4～15 或 `-1`，提示词最多 2500 字符。
- 初版只发布文生、单首帧、首尾帧和参考图；视频/音频输入、watermark、真人素材和 last-frame 结果保持未发布。
- 单首帧固定转换为 `input_mode=single_image, control_mode=none`；首尾帧与参考图互斥。

### 2.2 履约和历史兼容

- 当前 relay adapter 提升到 `54:third_party_relay:v2`，轮询必须返回精确 task ID，未知状态和成功无可信 HTTPS 结果均按合同违例失败关闭。
- v2 结果只接受直接 HTTPS URL、JSON 字符串对象或对象中的 `primary_url/url/urls` 白名单。
- TokenSave v1 与 Moxing Ark v1 仅保留 deprecated 历史解析；不进入新任务候选，也不能保存到新渠道。
- 当前实现只登记 `general` 图片，最多 9 张；不再用旧实现的 real-person、视频或音频素材声明扩张当前合同。

### 2.3 计费

- oversea 使用候选表达式 `v1:tier("480p720p", c * 7.0)`；最长 15 秒、最高 720p 的预扣上界为 324000 token。
- doubao 使用冻结请求的分辨率、时长和场景按秒表达式；`preconsume_tokens=1` 只作为表达式载体。
- `duration=-1` 在预扣时统一按 15 秒最大档，不以 4 秒、5 秒或全局 3600 秒上限代替模型边界。
- 两个当前模型页的 `usage` 都不能作为已验 token 证据；v2 不投影未验 `usage`。TokenSave 成功样本实际未返回 usage。

## 3. 本地数据库状态

变更前创建一致性快照 `one-api-pre-moxing-dual-20260805.db`；变更后 `PRAGMA integrity_check` 为 `ok`。

| 渠道 | 模型 | implementation | Channel/Ability | publication | 历史执行事实 |
| ---: | --- | --- | --- | --- | --- |
| 49 | `seedance-2-0-oversea` | Moxing v2 | 禁用/禁用 | 无 | 升级前无相关 Task/attempt/exposure/binding |
| 50 | `doubao-seedance-2-0-260128` | TokenSave v2 | 禁用/禁用 | 保留 v1 publication | 升级前无相关 Task/attempt/exposure/binding |

publication 与当前候选是不同事实：渠道 50 保留 publication 但没有启用候选，因此运行时不可调用；
没有通过删除 publication 隐藏不一致，也没有在禁用状态下误称模型已发布。

## 5. 真实 Provider 验证

### 5.1 `seedance-2-0-oversea`

使用渠道 49 保存的模型 Key 分别对 `www.moxing.pro` 与裸域名的 `/v1/media/generations` 发起空请求
认证预检，均返回 HTTP 401，而不是有效 Key 下预期的字段校验 HTTP 400。校验器在付费创建前终止：

- 真实付费任务：0；
- 本轮墨行 oversea 费用：¥0；
- 未验证：创建、轮询、结果、内容、usage、素材和账单。

该阻断必须通过替换或修复 Moxing 模型 Key 解决；不能改为 TokenSave、Ark 或其它 Provider 凭据。

### 5.2 `doubao-seedance-2-0-260128`

使用渠道 50 保存的 TokenSave Key 完成 4 秒、480p、16:9、文生视频真实验证。脱敏结果：

| 检查项 | 结果 |
| --- | --- |
| 认证预检 | HTTP 400，证明 Key 已进入字段校验 |
| 创建 | HTTP 200；捕获到 Provider request ID，但不保存其值 |
| 轮询 | 52 次后 `succeeded` |
| result / usage | `result` 为对象；`usage` 缺失 |
| 内容 | HTTP 200，`video/mp4`，421555 bytes |
| Range | HTTP 206 |
| 视频流 | 864×496，可被 ffprobe 解析 |
| 校验器结论 | 通过 |

该样本闭合基础文生的创建、轮询、终态、结果解析、下载和 Range，不证明 `480p` 是固定像素，也不
证明 720p/1080p、其它画幅、图片素材、`duration=-1`、音频开关、失败扣费或 Provider 实际账单。

首次 TokenSave 调用已通过预检并进入付费任务后，终端输出管道未被保留；为取得可审计的脱敏报告，
在首个进程结束后执行了第二条同规格任务。第二次校验器将脱敏报告以 0600 权限写入临时文件，报告
不包含 Provider task ID、结果 URL、密钥或原始响应。

### 5.3 费用边界

- TokenSave 校验器对每条 4 秒 480p 任务的保守费用上界为 ¥2.38；三条任务合计上界 ¥7.14，其中
  第三条为本站 8100 端到端验收任务。
- 本轮 oversea 未创建任务，费用为 ¥0；因此本轮墨行费用保守上界为 ¥7.14。
- 此数值是基于已登记单价、汇率和 1.25 安全系数的上界，不冒充 Provider 实际账单。
- 先前误发的飞彩调用费用 ¥25.74 未被本轮继续扩大；连同本轮墨行保守上界，总费用不超过 ¥32.88，仍低于授权的 ¥100。

### 5.4 本站 8100 端到端验证

完成代码与配置校验后，先创建 SQLite 一致性备份，再临时启用渠道 50，通过本站
`POST /api/v3/contents/generations/tasks` 在 `127.0.0.1:8100` 发起 4 秒、480p、16:9、无音频文生任务。
任务完成后立即通过事务入口恢复 Channel/Ability 为禁用，并再次重启系统加载禁用状态。

| 检查项 | 结果 |
| --- | --- |
| 本站创建 | HTTP 200；公共 Task ID 已生成 |
| durable create attempt | `complete`；hold 状态 `transferred`；Provider task/request ID 均已捕获 |
| 冻结合同 | `tokensave.seedance-media-task@v2`、`tokensave-media-task-v2`、`54:third_party_relay:v2` |
| 轮询 | 66 次后 `succeeded` |
| 客户计费 | 480p 档，预扣与结算均为 135800 quota；Task billing 为 `settled` |
| 内容代理 | 本站内容 URL HTTP 200，484028 bytes |
| 视频流 | 864×496，时长约 4.04 秒，无音频流 |

实测同时发现异步 Task 消费日志虽然金额正确，但没有投影 `tiered_expr`、表达式和命中档位。代码已在
`LogTaskConsumption` 复用统一 `InjectTieredBillingInfo`，把创建时冻结的分档证据写入 Task 消费日志，
并新增回归测试，避免客户金额正确但管理员日志缺少计费证据。

## 6. 剩余门禁

1. 更换有效 Moxing oversea 模型 Key，重新完成最小付费任务和账单对账。
2. TokenSave 分别验证单首帧、首尾帧、参考图、720p、1080p、`duration=-1` 和音频开关。
3. 核对 TokenSave Provider 实际扣款、失败扣费、币种、精度和请求时长/实际时长口径。
4. 本站 ModelArk v3 的成功路径已闭合 durable attempt、客户 hold/结算、内容代理和日志脱敏；继续
   验证失败、create unknown、退款、exposure 与补偿幂等。
5. 分别验证素材创建/绑定、账号作用域、Key 轮换和 TTL；没有证据前不发布真人、视频或音频素材。
6. 所有证据闭合后才按“隔离分组 Ability → publication 候选 → 灰度”顺序开放，不批量启用两个模型。
