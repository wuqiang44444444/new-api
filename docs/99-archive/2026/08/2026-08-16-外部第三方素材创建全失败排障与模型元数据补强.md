# 外部第三方素材创建全失败排障与模型元数据补强

## 1. 问题与目标

2026-08-16，外部第三方素材平台注册页面对图片
`enterprise-virtual-person-20260816.png` 执行 15 个模型的批量注册，页面汇总为“成功 0、跳过 0、
失败 15”。本次工作有两个目标：

1. 用网关日志、第三方应用日志和双方数据库定位失败层级，区分确定的合同错误与仍需 Provider
   复测的上游拒绝；
2. 扩充模型元数据，使第三方在调用前即可判断模型是否支持素材、是否支持素材组，以及
   `POST /v1/assets` 的请求形状和已经由代码验证的限制，避免把所有视频模型当成同一种素材能力。

## 2. 当前实际情况

### 2.1 真实测试记录

- 时间：2026-08-16 09:49—09:50（Asia/Shanghai）。
- 调用方：本机外部第三方应用 `os-mtr-proxyverify` 的素材平台注册页面。
- 网关：本仓库本地运行实例；模型线路包括 Volcengine、墨行、FunCloud、TokenSave 和飞彩。
- 请求形状：先为每个目标模型创建/选择 `general` 素材组，再以 `asset_kind=general`、
  `media_type=image`、`source.type=url` 创建图片素材。
- 图片事实：PNG、256×256、15,402 bytes，第三方数据库状态为 ready；来源是具有到期时间的
  HTTPS OSS URL。文档只记录 OSS 主机名 `os-mtr-proxy.oss-cn-heyuan.aliyuncs.com`，不保存完整
  签名 URL。
- 可公开结果：15 个目标全部失败；网关数据库仅新增 1 个 ready 素材组，没有新增素材；第三方
  应用没有新增成功 binding。

该次真实运行证明 15 条批量路径失败，但没有证明 256×256 是所有 Provider 的共同非法尺寸，
也没有得到可公开的 Provider 原始错误。因此本次不把最小尺寸、分辨率、码率等猜测写入 API 元数据。

### 2.2 日志与数据库归因

第三方访问日志与网关响应长度、HTTP 状态逐条对齐后，可将 15 条失败分为三类：

| 类别 | 数量 | 已验证事实 | 结论 |
| --- | ---: | --- | --- |
| 调用前即可排除 | 8 | 5 个飞彩网关模型和 FunCloud 2.5 的 `asset_upstream_protocol=none`；TokenSave 支持素材但不支持素材组；另一个飞彩直连目标不属于网关统一素材 API | 第三方只按视频协议筛选并强制“先建组”，能力判断错误 |
| 已进入真实素材 adapter 后失败 | 7 | Volcengine 1 次素材创建失败；墨行 2 次素材创建失败、1 次素材组创建失败；FunCloud 3 次素材上传失败 | Provider 拒绝或线路配置问题仍需带脱敏错误码复测 |
| 本地持久化成功 | 1 个组、0 个素材 | Volcengine mini 的素材组创建成功；所有素材创建都未取得可信 `ast_*` | 数据库与“0 成功”页面汇总一致 |

第三方应用的模型筛选条件只检查目标启用且视频协议为 `newapi_modelark_video_v3`，没有读取网关模型
元数据中的素材能力；批量逻辑随后对 15 个目标一律创建素材组。这直接触发了
`asset Provider is unavailable`、`asset type is not supported` 等本可在调用前避免的错误。

其余 7 条已进入真实 adapter 的失败目前只能确认失败层级：`service/asset_service.go` 对 Provider
错误只记录通用的 `Seedance asset creation failed` / `Seedance asset group creation failed`，没有保存
脱敏错误分类；第三方前端 catch 分支也只累计失败数。原始 Provider 错误事后不可恢复，不能据此
发布图片尺寸限制。

### 2.3 改接口前先验证的限制

在增加模型元数据字段前，先运行了现有协议能力与服务约束测试，并为缺失的 URL/TTL、FunCloud
素材组要求补了直接回归测试。已确认的限制如下：

| 限制 | 证据边界 |
| --- | --- |
| 素材来源只接受绝对 HTTPS URL、公共网络地址、443 端口，禁止 userinfo 和 fragment | `validateRemoteAssetURL` 直接测试 |
| URL 长度受当前 `asset_setting.remote_url_max_length` 限制 | 配置边界和 URL 直接测试 |
| `source.expires_at` 可省略；提供时剩余有效期必须不小于渠道 `asset_min_url_ttl_seconds` | TTL 直接测试 |
| 素材名最多 64 个 Unicode 字符；每用户未删除素材数受当前配置限制 | `CreateRemoteAsset` 校验与配置测试 |
| `real_person` 只支持图片并且必须提供同作用域 ready 素材组 | 服务合同校验 |
| FunCloud general 素材必须先有素材组，网关抓取来源后上传 | adapter 直接测试 |
| FunCloud 最大 100 MiB、最多 5 次重定向，且响应 MIME 必须与 `media_type` 匹配 | 流式抓取和 adapter 测试 |
| TokenSave 没有素材组操作 | 协议操作表和 catalog 测试 |
| `asset_upstream_protocol=none` 不支持统一素材创建 | catalog 与渠道设置测试 |

上述限制是平台代码当前确实执行的合同。未经过直接测试或公开 Provider 证据确认的尺寸、宽高比、
时长、码率和 Provider 文件格式限制均不进入模型元数据。

### 2.4 使用当前测试 Key 的真实复测

2026-08-16 10:23—10:26（Asia/Shanghai），使用第三方应用当前加密保存的 tokenai local 测试 Key，
对新生成的 AIGC 虚拟人像执行真实素材创建。测试输入为 PNG、1254×1254、1,952,551 bytes，第三方
OSS 状态 ready、HTTPS 公网可读且剩余有效期约 7 天。测试没有输出 Key、完整签名 URL 或 Provider
原始响应。

测试复用了 6 个与当前 target revision 匹配的 ready general 素材组；墨行标准版先尝试新建素材组，
失败后按网关当前“组可选”合同再做无组素材创建；TokenSave 按“素材组不支持”合同直接创建素材。

| 客户模型 | 素材组路径 | 创建结果 | 最终状态 | 创建耗时 |
| --- | --- | --- | --- | ---: |
| `doubao-seedance-2-0-mini-260615-volcengine` | 复用 ready 组 | HTTP 201 | ready | 3.01s |
| `doubao-seedance-2-0-mini-260615-moxing` | 复用 ready 组 | HTTP 201 | ready | 6.34s |
| `doubao-seedance-2-0-fast-260128-moxing` | 复用 ready 组 | HTTP 201 | ready | 5.86s |
| `doubao-seedance-2-0-260128-moxing` | 新建组 HTTP 502；随后无组创建 | HTTP 502 | 未创建 | 5.49s（合计） |
| `seedance-2-funcloud` | 复用 ready 组 | HTTP 201 | ready | 25.79s |
| `seedance-2-fast-funcloud` | 复用 ready 组 | HTTP 201 | ready | 25.62s |
| `seedance-2-mini-funcloud` | 复用 ready 组 | HTTP 201 | ready | 23.94s |
| `doubao-seedance-2-0-260128-tokensave` | 不创建组 | HTTP 502 | 未创建 | 3.27s |

Volcengine 与墨行两条成功创建最初返回 processing，随后通过 `GET /v1/assets/{asset_id}` 查询均转为
ready；FunCloud 三条创建响应直接为 ready。网关数据库最终新增 6 个 ready 素材，和 Provider 查询
结果一致。

这次复测证明相同线路下 1254×1254 PNG 可被上述 6 个模型接受，而早先 256×256 PNG 在这些线路
失败；它显著支持“原测试图片不满足上游输入条件”的判断，但两个样本不足以确定精确最小边长、
最小字节数或是否还存在内容识别条件。因此 API 仍只发布平台确实强制的限制，不把 1254 当作
最小尺寸，也不把 512/1024 等未经本次真实调用确认的值写成合同。

墨行标准版和 TokenSave 的失败与素材组分支无关：墨行标准版新建组和无组创建都失败，TokenSave
已按无组合同调用仍失败。当前公开错误仍只有 `asset Provider operation failed`，需要增强脱敏错误
分类后才能确认是 Provider 接口合同、账号权限、模型映射还是其它上游限制。

### 2.5 官网文档复核与“不支持”判定边界

本次没有把 502、超时或单次 Provider 拒绝直接解释为模型不支持，而是重新核对了 Provider 当前
公开文档：

| Provider | 公开证据 | 判定 |
| --- | --- | --- |
| Volcengine | 火山方舟可信素材库说明和 CreateAsset API 均已公开；可信素材可通过 `asset://<asset_id>` 参与视频生成 | 明确支持素材库；原 256×256 失败属于输入/上游失败，不能返回“不支持” |
| 墨行 Standard | 模型页的“素材库”页签明确列出素材组、素材创建、状态查询及 `asset://` 调用示例 | 明确支持；本次 502 保持 `asset_upstream_error` |
| TokenSave | 官网“素材库”API 明确列出 `/v1/asset/*` 创建和查询合同 | 明确支持；本次 502 保持 `asset_upstream_error` |
| 飞彩 | 当前公开站点仅发布视频 URL 调用，没有可验证的素材资源 ID、素材组或素材生命周期 API；当前渠道合同也显式配置 `asset_upstream_protocol=none` | 当前平台模型明确不发布素材库；只有该显式合同可以返回“不支持” |
| FunCloud 2.5 | 当前已验收的 Provider 合同没有 2.5 素材引用入口，当前渠道显式配置 `asset_upstream_protocol=none`；Standard/Fast/Mini 则已真实创建成功 | 只对当前 2.5 平台模型返回“不支持”，不外推为 FunCloud 全部模型不支持 |

因此“不支持”是当前平台模型合同的确定事实，不是对 Provider 永久能力的猜测。若未来 Provider 发布
稳定素材资源身份和模型引用合同，应先新增/启用代码注册的素材协议并完成真实验收，再改变模型元数据
和错误分类；不得根据模型名、失败文本或 404 动态推断。

## 3. 优化方案

### 3.1 模型元数据合同

`GET /v1/models` 与 ModelArk V3 模型目录继续在每个 Seedance 模型的 `api.assets` 下返回完整操作表，
并新增：

- `media[].asset_group_requirement`：按 `asset_kind + media_type` 返回 `required`、`optional` 或
  `unsupported`；
- `creation`：仅当 `create_asset` 支持时返回，包含 `POST /v1/assets` 的方法、路径、内容类型、
  必填字段、当前素材名/用户数量上限、来源 URL 规则和与当前模型绑定的请求示例；
- FunCloud 的 `creation.source` 额外返回 `max_bytes=104857600`、`redirect_limit=5`、MIME 必须匹配
  以及已验证的 MIME 白名单；
- 没有素材协议的模型保持 `assets.supported=false`、`create_asset.supported=false` 且不返回
  `creation`；TokenSave 返回素材创建合同，但所有 general media 的素材组要求为 `unsupported`。

第三方批量注册应按以下顺序决策：

1. 目标模型本身必须 `available=true`；
2. `api.assets.supported=true` 且 `create_asset.supported=true`；
3. 按所选 kind/media 读取 `asset_group_requirement`，只有 `required` 才强制先创建/选择 ready 组，
   `unsupported` 时不得调用素材组接口；
4. 按 `creation.required_fields` 和 `creation.source` 构造请求；
5. 飞彩直连等非网关目标使用自己的能力合同，不得仅因视频协议同名就调用网关素材 API。

### 3.2 示例响应片段

以下仅展示结构；实际 `model`、TTL 和全局上限由当前模型/配置动态返回：

```json
{
  "api": {
    "assets": {
      "supported": true,
      "media": [
        {
          "kind": "general",
          "media_type": "image",
          "asset_group_requirement": "required"
        }
      ],
      "creation": {
        "method": "POST",
        "path": "/v1/assets",
        "content_type": "application/json",
        "required_fields": [
          "name",
          "asset_kind",
          "media_type",
          "model",
          "source.type",
          "source.url",
          "asset_group_id"
        ],
        "source": {
          "type": "url",
          "url_scheme": "https",
          "public_network_only": true,
          "port": 443,
          "max_url_length": 8192,
          "expires_at_min_remaining_seconds": 3600
        }
      }
    }
  }
}
```

### 3.3 验证与剩余事项

当前代码另以 8101 临时实例和同一测试 Key 实际请求 `/v1/models`，验证新增 `creation` 已按真实渠道
配置返回：FunCloud 要求素材组并返回 100 MiB、5 次重定向和 MIME 规则；TokenSave 明确素材组
`unsupported`；无素材协议模型不返回 `creation`。临时实例验证后已关闭，正在运行的 8100 旧进程
尚未重启，因此要让外部第三方实际读取新字段仍需部署/重启当前代码。

统一素材创建和素材组创建的错误也已拆分：当唯一 Seedance Channel 明确配置
`asset_upstream_protocol=none` 时返回 HTTP 422、错误码 `unsupported_asset_library`、消息
`asset library is not supported by this model`。未知/非法素材协议仍返回 503
`asset_upstream_unavailable`；Provider 已接收但拒绝或执行失败仍返回 502 `asset_upstream_error`。
该拆分保证外部调用方可以停止调用真正不支持的模型，同时不会把墨行 Standard、TokenSave 等已由官网
确认支持但当前运行失败的线路误标为“不支持”。

同一 8101 临时实例还使用当前 `tokenai local` 测试 Key 实际调用了飞彩
`seedance-2.0-mini-720p`：`POST /v1/assets` 和 `POST /v1/asset-groups` 均返回 422
`unsupported_asset_library`；请求在 Provider I/O 和本地资源创建前终止，数据库中没有产生测试素材或
素材组。同期模型目录仍返回墨行 Standard 与 TokenSave `api.assets.supported=true`。测试完成后 8101
已关闭，8100 未重启。

发布前仍需：

- 部署或重启网关后，让第三方应用消费上述模型元数据，再验证 8 条确定不适用路径被跳过或正确分流；
- 为 Provider 错误增加不含凭据、签名 URL 和原始响应的错误类别/请求关联日志；
- 定位墨行标准版和 TokenSave 的 Provider 失败；只有得到可重复边界证据后，才把新的尺寸/格式
  限制加入元数据和回归测试。
