# Link 视频结果自有 OSS 托管与 24 小时预签名交付方案

> 实施状态（2026-10-14）：本地代码已完成——对象登记表 `task_video_result_objects`、转存 worker
> （`service/video_result_transfer*.go`，system task `video_result_transfer`）、S3 分片/Azure
> UploadStream 有界上传、ModelArk 投影与内容入口的 86400 秒预签名交付、公共交付状态合同
> （`content.delivery_status`：`ready`/`preparing`/`unavailable`），并删除范围内线路的旧上游回源
> 代理路径（`video_feicai_content.go`、`video_synlink_content.go`、`video_synlink_expiry.go`）。
> 合同事实已收敛至 [Link视频结果OSS托管交付架构](../20-architecture/Link视频结果OSS托管交付架构.md)。
> [真实渠道验收](2026-10-15-Link视频结果OSS真实渠道验收.md)已验证 Vidu/FunCloud/Synlink
> 主视频与真实 Azure Blob 的 MIME/完整下载/Range/HEAD/CORS/即时续签，以及 Vidu/FunCloud
> 尾帧；Synlink 尾帧被 SSRF 策略拦截，墨行创建结果未知，整体验收未完成。
> 其他 Provider/存储、浏览器、签名凭据持续 24 小时支持、多数据库与生产灰度仍待验收；
> 对象保留期、存量任务一次性盘点范围与大小/并发上限
> 仍是部署方待确认项（代码默认：单文件 1 GiB、批次 4、租约 30 分钟、累计 8 次退避重试、
> 补扫窗口 24 小时）。

## 1. 问题与目标

当前 ModelArk 视频查询把上游结果 URL 替换为本站内容接口。客户下载时，网关再次请求上游，
把视频字节流传给客户；重复下载重复回源，增加网关带宽与连接负担，并要求下载方携带平台鉴权。
上游文件和签名链接的可用时间仍决定能否交付，本站代理地址不代表已经保存结果。

用户于 2026-10-14 确认：目标范围内的所有生成结果先转存本站私有 OSS，最终统一返回本站 OSS
预签名下载地址，每次签发有效 24 小时。用户同时确认客户模型后缀 `-f` 对应 FunCloud。

本文保留已确认方案与实施验收边界；当前本地实现已完成，并补齐上传完成证据、全部实际尾帧、
登记缺口恢复与 HEAD 签名的回归修复。真实 Provider 与 Azure Blob 已完成部分验收，详见上述
真实渠道记录；其余线路、浏览器、外部数据库与生产灰度仍待验收，不代表生产已发布。

### 1.1 已确认的交付规则

| 项目 | 规则 |
| --- | --- |
| 结果归属 | 生成结果转存本站自有私有 OSS，不把上游结果直链下发客户 |
| 交付方式 | 返回本站 OSS 预签名 GET URL，客户直接访问对象存储下载 |
| 链接有效期 | 从本次签发时刻起固定 24 小时，即 86400 秒；不是从任务创建或生成完成时开始计算 |
| 统一范围 | 同一交付规则覆盖本地 Link 视频请求的所有 Provider 线路，不按模型后缀选择方式 |
| FunCloud 身份 | `-f` 是部署方对 FunCloud 客户模型的命名约定；履约仍以渠道类型及登记协议为准 |
| 上游凭据 | 仅后台读取上游结果时使用，不进入客户 URL、响应或普通日志 |
| 转存次数 | 每个结果对象成功转存一次，后续查询与下载不重复搬运 |

“统一预签名地址”表示统一来源和访问合同：每个任务的每个结果文件各有自己的 URL，不是所有任务
共用一个地址，也不要求签名字符串在多次查询之间保持相同。

### 1.2 范围与边界

- 本次范围为本地 Link 视频结果交付，包括 Seedance 的 Synlink、FunCloud、墨行、Vidu、官方及
  其他已登记线路，以及 MiniMax 标准视频扩展；成功主视频与实际提供的尾帧采用相同托管规则。
- “所有请求”指上述范围内各 Provider、各客户模型的结果处理，不表示把所有请求正文、参考素材或
  文本响应上传 OSS。素材控制面、参考音频暂存、请求证据仍遵守各自合同。
- NEWAPI 原生 Router、DTO、Relay、Provider adapter 及其图片、视频、文本响应语义继续以上游
  代码为权威；不得借本方案统一改写原生接口。已有图片托管可复用基础能力，不能直接把其 300 秒
  URL 有效期改为 24 小时。
- 不建立第二套 Task、资金账本或模型路由。继续按创建时冻结的协议、连接与执行事实读取上游。

- 报告中的 Vidu 上游链接有效期不等于本站目标有效期，也不能推广为所有 Provider 的统一期限。
- 会话内既有回归验证了当前模型投影隐藏上游 URL、应用隔离、制品交付、Range/HEAD 与带凭据的
  回源，以及相关 Provider 结果解析。这些测试证明当前行为，不证明新托管方案已实现。
- OSS 预签名链接用于限时访问私有文件；上传、存储、请求与公网分发有各自成本，详见
  [OSS 预签名下载说明](https://www.alibabacloud.com/help/en/oss/user-guide/download-files/)与

## 3. 优化方案

### 3.1 目标数据与控制流

```text
上游返回可信生成成功事实
    ↓
持久登记待转存结果，后台及时领取
    ↓
按冻结协议与连接读取完整结果文件
    ↓
有界流式或分片上传本站私有 OSS
    ↓
确认完整上传并提交本站对象登记事实
    ↓
客户鉴权查询，签发有效 86400 秒的本站 GET URL
    ↓
客户直连 OSS 下载；网关不再传输结果字节
```

转存应在可信生成完成后及时执行，不等第一次客户端下载才读取上游。需要附加 Provider 凭据的
线路由代码 adapter 在后台履约；客户看到的来源与下载方式不受南向差异影响。

### 3.2 唯一持久事实与恢复

- 主数据库记录任务归属、结果部件、存储实例/桶、对象位置、MIME、大小以及必要的交付进度与
  重试事实。结果按 `user_id + app_id` 隔离；公开响应仅包含授权交付所需字段。
- 对象位置由平台生成，不从上游文件名或模型后缀推导。主视频与尾帧各有独立对象登记。
- 保存对象引用，不保存本站完整预签名 URL；每次授权查询按对象事实重新签发。
- 通过现有 Task 和后台执行底座持久领取与恢复转存。并发领取、多节点重启、上传成功但数据库
  提交失败等情况须能恢复，不反复生成新对象，不把进程内队列当成唯一事实源。
- 上游生成状态和资金事实保持原有语义；转存准备中或失败不能覆盖已确认生成成功。交付就绪前
  不发布不可下载的本站 URL。准备中与不可用的客户端表达须在实现前落实到唯一公共合同。
- 重试仅针对同一任务、同一结果的读取或上传，不重发生成 POST，不换 Provider、模型或渠道，
  不重复扣费或因转存失败自动退款。上游结果已失效时如实记录交付不可用。
- 本站存储不可用时不下发上游直链，不回退当前视频字节代理；通过持久恢复和明确交付错误处理。
- 转存完成后，后续查询、续签与下载不再依赖上游文件、当前渠道凭据或上游签名有效期。

### 3.3 固定 24 小时预签名合同

- 所有范围内的结果下载采用私有 OSS 的预签名 GET URL，签发时固定设置 86400 秒。
- `content.video_url` 返回本站主视频预签名 URL；实际存在尾帧时，`content.last_frame_url` 返回
  本站尾帧预签名 URL。每个文件独立签名，不把两个文件合并为一个链接。
- API 查询、列表及控制台制品使用同一对象登记与签名规则；具体已发布入口按自身鉴权边界处理。
  不新增平行的上游直链字段或临时代理交付开关。
- 客户访问已签发 URL 不附加平台 API Key 或 Provider Key。浏览器下载和播放器读取由 OSS
  履约；实际 MIME、Range/206、HEAD、CORS 与下载文件名需要真实对象存储验收。
- 链接到期后，在对象仍存在且调用方仍获授权时，重新查询签发新的 24 小时 URL；不重新生成视频
  或再次复制对象。已签发地址在有效期内的访问能力不等于每次都重新验证平台 API Key。
- 签名凭据有效期、对象保留期限和存储策略必须覆盖签发后的完整 24 小时。不能签发一个对象将于
  数小时后删除的 URL，再向客户承诺 24 小时可用。
- URL 有效期和文件保留期是不同概念：本次已确认的是签名有效期，不是对象仅保存 24 小时，
  也不是永久保存。对象保留期、删除与生命周期策略仍待明确。
- 此次确认允许目标合同向有权限的客户交付本站结果预签名 URL。实现时同步调整现有禁止完整
  签名 URL 进入公共响应的笼统表述，限定该结果交付例外；上游凭据、上游私有结果链接及完整
  签名 URL 的日志、证据展示与工单脱敏边界继续有效。

### 3.4 复用与最小侵入

- 复用既有存储配置、签名能力、Task、应用隔离与后台执行设施；视频结果对象登记放在本地扩展
  文件，不能冒用 `ImageTask` 登记或建立第二套 Provider 结果事实。
- 视频上传采用有大小和并发上限的流式或分片实现，不能沿用无界 `io.ReadAll`，不能把完整视频
  正文放入 Task、数据库、日志或缓存。
- 保留上游读取所需的 SSRF 防护、冻结凭据边界及带凭据时的重定向限制；不得把客户或 Provider
  返回的任意 URL 交给缺少保护的通用 HTTP 客户端。
- 修改 Link 专属任务投影与制品交付。既有 Link 内容入口如需保留，应在授权后重定向本站
  预签名 URL，不再逐次传输文件；直接返回的结果字段必须已经是本站 OSS URL。
- 原生共享入口仅保留必要的窄接线，不重构 NEWAPI 原生视频代理，不统一改写原生协议。
- 不新增历史 decoder、双读双写或缺失对象时的旧代理 fallback。存量任务处理通过上线前盘点
  确定明确范围，不在请求时临时探测或静默迁移。

### 3.5 实施顺序

1. 同步目标合同与当前事实文档：明确视频托管、本站结果签名 URL 交付例外、24 小时签名语义、
   交付准备中/失败表达及文件保留策略。按项目门禁判断是否需要 ADR，不自动新增决策。
2. 补齐视频对象登记、有界上传、持久转存领取及恢复，先验证同一结果只建立一个成功对象事实。
3. 将 Provider 结果读取接入转存流程，覆盖无额外凭据与需 Provider 凭据的主视频/尾帧。
4. 切换 ModelArk 与通用制品的结果交付、控制台播放和下载，使客户直接访问本站签名地址。
5. 替换锁定旧代理行为的测试，同步公开文档，完成真实 Provider、对象存储和多数据库验收。
6. 上线前盘点存量任务：区分可读取上游结果、已过期、缺少冻结连接等情况，制定一次性处理清单；
   不能把不可恢复的历史任务写成已托管，不自动修改其生成状态或计费结果。

## 4. 验收要求与剩余事项

### 4.1 可观察验收

- 范围内每条已启用协议的成功主视频，以及实际支持的尾帧，均在完整转存后返回本站 OSS URL，
  不含 Provider 下载地址或 Key；`-s/-f/-m` 不能因名字不同走不同交付策略。
- 对每次签发验证有效期为 86400 秒；客户无需平台鉴权下载，重查可以续签，续签不读取上游或
  重新上传；在签发的 24 小时内对象没有被生命周期清除。
- 关闭或使上游结果链接失效后，已经转存的对象仍可交付；客户重复下载不再触发网关视频传输。
- 外用户、外 app、已删除任务和错误部件不得获得签名；视频签名不授权尾帧或其他对象。
- 转存中断、存储故障、超大文件、并发领取及进程重启能得到明确结果并按持久事实恢复；部分
  上传不得成为可交付对象，失败不重生成、不改已确认资金事实、不回退上游直链或旧代理。
- 真实验证下载 MIME、文件完整性、Range/206、HEAD、浏览器播放与 CORS，并测量一次转存及
  多次下载的资源消耗。不得只以本地 mock 或签名参数存在判断生产可用。
- 主数据库迁移与恢复覆盖 SQLite、MySQL、PostgreSQL；涉及 `relaykit/` 时另跑独立构建。

### 4.2 尚未确认或完成

- 本站对象保留期限、到期删除策略及存量任务转存范围。
- 存储部署区域、签名凭据是否支持完整 24 小时、实际传输与存储成本，以及是否需要独立搬运 worker。
- 部署方确认转存并发、文件大小与超时上限，以及删除任务后的对象处理；公开表达已固定为
  `content.delivery_status`，生成成功与交付进度分别表达。
- 本地实现之外的真实验收与部署，包括所有目标 Provider 主视频/尾帧、真实 OSS、浏览器、
  外部数据库及生产灰度。

文档维护执行 `task docs:check`、`task ai:check`。实现阶段同步公开
API 文档后还须执行 `cd web && bun run docs:validate`，并按变更边界运行后端回归；不能将本次
文档校验通过记为新交付流程已验收。


## 5. 本地评审修复与验证边界

- 成功状态提交后按耐久 Task 登记结果，CAS 输家不建立交付行；全量部件使用一个事务幂等登记。
- 补扫按 `FinishTime` 的最近 24 小时窗口恢复任一缺失部件，无已登记工作也可触发调度；已存在的
  ready/unavailable 行保持原事实，不在客户查询时搬运历史任务。
- Synlink 尾帧继续使用冻结接口与凭据，其它线路读取可信任务响应中的尾帧地址，不向 CDN 附加凭据。
- S3 响应 context 在正文关闭后取消；multipart 初始化携带 MIME；只有完整成功 XML 与非空 ETag
  才视为上传完成，空正文、畸形 XML 和错误响应均不发布 ready。读取只接受完整 HTTP 200，文件
  大小上限包含边界值，不把部分文件或超限前缀发布为结果。
- ModelArk URL 固定签 GET；内容入口 HEAD 使用匹配的 HEAD 签名。签名只在授权响应中使用。
- 原生轮询文件的必要改动仅将既有登记调用移到成功 CAS 之后；主体实现位于 Link 新增文件。
  此接线保证登记来自已提交事实，未来上游合并只需保留这一窄调用。
- 本地回归覆盖零登记/部分登记恢复、事务失败回滚、CAS 输赢、长运行任务完成窗口、普通与
  Synlink 尾帧、分片完成证据、上传 MIME、大小上界、响应正文生命周期及 HEAD 签名验证。
  这些回归不替代真实 Provider、OSS 生命周期、浏览器或三数据库部署验收。
