# 任务失败 HTTP 与请求证据缺失分析及实施方案

## 1. 问题与目标

2026-10-09 16:01:09，用户提供上线服务的 Seedance 视频任务失败事件：客户模型为
`seedance-2-5-s`，渠道为 Synlink 海外 Seedance，事件类型为任务失败，原因 `task_failed`，
阶段 `task_lifecycle`。页面显示“无客户 HTTP 状态”，四处正文显示“此事件未记录正文”。
失败说明包含下游提交 HTTP 400 及“不支持 callback_url，请轮询任务”的诊断摘要。
本文不保存完整请求标识、Task 私有数据、原始 Provider 响应或敏感 URL。

用户明确目标：不论失败原因、HTTP 状态码或请求是否成功，都应如实记录与展示实际存在的请求数据，
便于事后排查；同时保存问题、分析和实施方案以供后续检索。

2026-10-09 用户再次明确：非音视频请求也必须遵循同一记录与展示要求。覆盖非音视频是本任务的
必做范围，不是可选优化，不能以媒体类型、Provider、HTTP 状态或错误原因作为跳过记录的条件。

完整目标包括客户原始业务请求、实际南向请求、上游响应、轮询交换及客户交付；必须区分各次交换的
状态、时间与来源。尚未发生的请求、没有收到的响应及无法取得的数据保持缺失，不猜测、不补造。
凭据在采集时脱敏，受保护证据中的签名 URL 在管理预览中遮盖，原文按既有 Root 权限与审计访问。

本次覆盖音视频与非音视频业务入口；最终验收同时核对正文、实际状态、安全边界和后台交换，
不能仅以音视频回归通过作为全站完成依据。

## 2. 当前实际情况

### 2.1 已验证的本地代码事实

| 位置 | 事实与影响 |
| --- | --- |
| `model/task_error_event.go` | 后台失败终态生成事件，`Status` 为 0，未附 `HTTPExchange`；该值表示此事件没有客户 HTTP 响应，不表示从未访问上游 |
| `clienterrlog/backend.go` | 后台错误事件与客户请求诊断采用受控快照；任务失败事件不自动复制创建请求的 HTTP 交换 |
| `plugins/seedance-link/plugin.js` 的 Synlink 转换 | 当前本地创建路径拒绝非空 `callback_url`；轮询解析读取 `task.status` 和 `task.error` |
| `relay/channel/task/seedance/adaptor.go` | 实际轮询 HTTP 边界已接入原始响应证据采集，位于 Provider 正文转换前 |
| `service/task_request_evidence_capture.go` | 修改前，创建响应的 Body 为 nil 时直接跳过，已收到的状态与响应元数据未记录 |
| `service/task_request_evidence_polling.go` | 修改前，空轮询响应跳过；响应与 transport error 同时存在时按无响应处理，丢失状态及已有正文 |
| `service/task_request_evidence_redaction.go` | 修改前通过 `any` 解码 JSON，大整数被 float64 改写，原始十进制数值表示也被改变 |
| `web/src/features/usage-logs/components/task-evidence.tsx` | 既有按需证据入口能查任务/请求关联记录；修改前未展示接口已返回的方法、目标、内容类型、采集时间与诊断详情 |

错误日志与请求证据是两个不同用途的记录：前者记录失败事件，后者存储 HTTP 交换证据。页面中
“此事件未记录正文”只能说明错误事件没有快照，不能证明独立证据不存在。当前本地代码已有错误
详情的任务证据入口及空快照隐藏行为；线上是否部署该版本未核实。

### 2.2 本次事件的原因推断

可能的链路是本站创建 → Synlink 返回可信任务 ID → Synlink 后台向其下游提交 → 下游拒绝回调
参数并返回 400 → 本站轮询取得失败终态。已有任务 ID 和 `task_lifecycle` 事件支持这一解释，
但仅凭用户提供的错误摘要不能确认 callback_url 由哪一层添加。

错误文字中的 400 属于 Provider 报告的更下游状态，不能填写为本站实际收到的创建或轮询状态。
本站轮询可能收到 HTTP 200 且正文表示任务 failed；实际值必须读取证据，不能由业务失败反推。

### 2.3 未确认事项

- 线上服务的代码版本、实际启用及任务冻结的 Seedance 插件版本。
- 本次创建最终南向正文是否含 callback_url，以及渠道参数覆盖是否注入该字段。
- Synlink 是否自动添加回调地址，其目标网关是否仅支持轮询。
- 线上证据采集开关、持久目录、密钥及索引关联是否正常；本次事件是否已有创建和轮询证据。
- 真实 Provider 终态、客户资金处置与生产页面表现。

本次未访问生产数据库、服务器或真实 Provider，未实施生产修复或重新发送任务。

## 3. 优化方案

### 3.1 统一记录原则

1. 采集不以 HTTP 成功或失败筛选；空正文仍保存实际状态、方法、目标和头摘要。
2. 响应与传输错误同时存在时，保留已经观察到的响应，另外标记错误及采集不完整。
3. 创建、轮询、客户交付分别保留，不把一次交换覆盖为另一次交换，不把 Provider 描述的状态
   冒充本站观测状态。
4. 凭据脱敏保持业务数值准确，包括大整数 ID、显式零值、false、null 和十进制数值表示。
5. 采集失败明确区分类别、阶段和正文来源；超限、读失败、过期或存储不可用不能解释为未发送。
6. 详情从既有受保护证据读取数据；原始业务正文不复制到普通错误日志、Task 或缓存。

### 3.2 全业务请求覆盖范围（用户已明确）

| 请求类别 | 必须采集与展示的实际数据 | 重点边界 |
| --- | --- | --- |
| Chat、Completions、Responses、Claude、Gemini 等文本生成 | 客户请求、最终南向请求、各次上游响应、客户响应 | 普通成功与失败同样可追溯；适配后请求与客户请求分开 |
| SSE、其他流式文本与实时连接 | 实际发送/接收的消息或事件、连接状态及结束原因 | 已提交 200 后发生业务错误仍记录原状态与已有数据，不等待失败才开始采集 |
| Embeddings、Rerank、Moderations 等非生成 API | 客户请求、南向请求、上游及客户响应 | 不因为没有 Task、没有媒体或没有消费日志而缺失 |
| 图片同步与异步入口 | 提交、各次上游 HTTP 交换、异步推进及客户交付 | 不用音视频入口作为统一采集资格；二进制与业务正文区分 |
| Files、Batch、资源和素材接口 | 创建、查询、更新、删除等实际交换及后台请求 | 使用真实请求/任务关联，不把后台业务失败冒充客户端 HTTP 失败 |
| 音视频及其他异步任务 | 创建、轮询、结果交付与传输异常 | 已完成修复作为全站统一要求的一部分 |
| 本地校验、鉴权、路由、限流或选渠拒绝 | 已接收的客户请求及已写出的客户响应 | 没有南向请求时明确未发生；不能因此丢弃北向数据 |

上表覆盖实际业务 API，不将静态资源、健康检查和证据查看接口本身当作客户履约请求，避免自递归
采集。请求正文、上传及响应中的现有数据按格式与权限展示；未收到、部分读取、超限和安全脱敏
失败必须显示具体状态，不统一归为“未记录”。

本地进一步核查确认：`clienterrlog/recorder.go` 的持久错误出口只处理已鉴权的 4xx/5xx 及显式流式
错误，普通成功请求不进入该出口；`clienterrlog/http_exchange.go` 的普通快照只保留有界 JSON，
并不等于所有业务请求的完整证据存储。`relay/channel/api_request.go` 已有共享南向观察接线，但
不能由此推定所有 adapter、特殊 transport 或后台调用都已覆盖。

全站实施必须将“请求证据采集”和“错误事件登记”分开：在请求开始及实际 I/O 边界持续观察，
无论最终是否产生错误事件都保留证据；发生错误时关联已存记录。不能仅取消 Recorder 的状态过滤，
把成功请求全写成错误事件来冒充完成。

#### 全站实施顺序

1. 建立各业务 Router、共享 transport、独立 adapter 与后台执行入口的覆盖清单，标出实际接线点。
2. 在独立文件实现通用证据观察与持久化，优先复用既有受保护存储、索引、脱敏和查询合同；
   原生热路径只保留必要窄接线，不对原生请求增加 Link 模型推断或业务拒绝。
3. 接入北向接收、最终南向发送、上游原始响应、客户端写出与后台交换，按次序保留重试交换，
   不用“最后一份正文”覆盖前一次失败。格式、安全和容量无法完成时保存明确元数据与缺失原因。
4. 管理端按请求 ID/Task ID 展示统一时间线及各次 HTTP 状态，成功请求也可查询；错误详情关联证据。
5. 按上表类别验证成功、4xx、5xx、超时、断流、空正文、本地拒绝和后台失败，记录已覆盖与未覆盖。
   全站代码、管理展示及生产验收分别确认，剩余非音视频路径不得留作未注明的例外。

### 3.3 本次已实施

- 创建及轮询空响应立即持久化事件，保留实际 HTTP 状态与元数据。
- 轮询响应与传输错误同时存在时使用同一响应捕获入口，保留已消费正文并标记 transport_failed。
- 南向创建保存脱敏查询参数；响应证据区分响应头、请求头和请求查询参数，签名/查询认证参数脱敏。
- 缺少响应 Request 描述符时不再猜测方法为 GET。
- 使用 `json.RawMessage` 递归凭据脱敏，实际编解码仍通过 `common.*`，避免 float64 改写数值。
- 正文脱敏或存储失败在事件 Detail 添加 `capture_failure` 的 category、stage、source，
  保留已观察的状态和字节数，不写原始错误或可能包含凭据的正文。
- 证据时间线展示已有方法、脱敏目标、内容类型、时间与诊断信息，继续保留预览、原文查看及下载权限。
- 运维查看流程补充至[音视频证据运维手册](../40-operations/11-音视频证据运维手册.md)。

全站观察逻辑放在新增 `service/api_request_evidence*.go`，复用既有证据表与加密对象存储。
全局中间件位于请求 ID 建立后、鉴权前，覆盖 `/v1`、`/v1beta`、`/api/v3`、`/pg`、`/mj`
及具名 Midjourney、Kling、Jimeng 业务入口；管理接口和证据读取不再次采集，避免递归留存。
共享 HTTP transport 在实际 I/O 边界逐次观察，保留每次重试/重定向的请求和响应；响应读取通过 tee，
不预读上游流。北向通过实际读取 tee 观察，不在鉴权前主动读取。业务已经拒绝时，先交付错误
响应，再在 100ms 读取期限和正文容量内补采未读输入；未到达的部分保持不完整，慢正文不阻断鉴权。

普通同步成功/失败、鉴权或校验拒绝、SSE、图片后台任务和 Batch 后台推进均独立留证，不依赖错误
日志筛选。OpenAI 实时连接及讯飞 JSON WebSocket 记录帧；WebSocket 握手保留实际状态，Gin
Hijack 后的客户握手从真实写入头读取。火山 TTS 保留握手及客户交付，二进制协议帧不冒充 JSON。
插件后台轮询在解析前挂接真实请求及响应，保留 batch 查询的真实方法与正文响应。

管理员在用量日志页面“请求证据”中浏览全部记录或按请求 ID 查询；错误详情、消费详情和任务详情
继续使用同一个证据组件。展示实际方法、目标、状态、时间、内容类型、字节数、采集状态及头/query
摘要，Root 可经既有审计接口查看和下载凭据脱敏正文。JSON 大整数及小数表示保留；非法或截断
JSON/SSE 的安全前缀通过独立字符串扫描脱敏后保留，并标记格式异常；不把非法 JSON 描述成存储
读取失败。签名 URL 被遮盖；素材 source URL 不留存。

#### 原生文件接线必要性与同步影响

| 接线 | 必要性与最小改动 | 上游同步影响 |
| --- | --- | --- |
| `main.go` | 请求 ID 后增加单行全局中间件，才能覆盖鉴权前拒绝 | 一行注册冲突 |
| `service/http_client.go`、受保护下载客户端 | transport 单行包装，覆盖共享网络出口与下载；保留原代理/TLS/超时策略 | 构造器局部冲突 |
| `relay/channel/api_request.go` | WebSocket 出口委托观察 helper；普通 HTTP 利用已有证据接线传播载体 | 单行调用冲突 |
| Coze、Dify、Replicate | GET/上传请求继承现有请求 context，进入同一观察链 | 各调用点一行冲突 |
| 阿里图片轮询 | 带入现有 Gin context 并包装原客户端，保留其配置 | 方法签名及调用点局部冲突 |
| 图片执行器、Batch 创建/推进/对象读取 | 进入后台时绑定冻结身份，包装独立客户端 | 每个入口少量接线 |
| OpenAI realtime、讯飞、火山 | 握手/帧边界增加观察调用，业务解析和发送逻辑保留 | 各 I/O 点局部冲突 |
| 本地图片证据中间件 | 全站观察存在时不再分配第二份图片错误缓冲 | 本地扩展，不增加原生冲突 |

未修改数据库 schema、任务状态、资金合同、选渠或重试策略；采集失败不改变普通原生 API 响应。

### 3.4 后续实施与验收

| 项目 | 动作 | 验收标准 |
| --- | --- | --- |
| 本次线上事件归因 | 按任务 ID/请求 ID 查既有创建和轮询证据，核对实际南向字段；向 Synlink 核查其下游提交 | 能确认 callback_url 的注入层；没有证据时明确记录无法确认 |
| 部署验收 | 部署本次代码后验证真实空响应、失败终态、正常创建与轮询的记录展示 | HTTP 状态及现有正文可查，失败不倒转业务状态和资金事实 |
| 全站 API 部署验收 | 本地实现已覆盖共享入口/出口，部署后核对各实际入口 | 成功、拒绝、上游异常及后台调用均可查询 |
| 特殊正文 | 评审超限、截断、非法 JSON、multipart、二进制及流式正文的安全保存和展示 | 保留可安全采集的数据与缺失原因，不伪称完整、不泄露凭据、不阻断既有原生能力 |
| 历史数据 | 区分已存证据、未采集、过期与历史覆盖 | 升级不补造过去没有保存的内容 |

全站业务请求观察已实现，范围包含非音视频。容量及故障边界仍如实标记：每份请求使用既有总缓冲
预算，每个交换正文受 `MAX_BODY_BYTES` 限制；通用请求不使用旧图片错误采集的 8 个缓冲槽位，
不会因为第 9 个并发请求而放弃正文。对象写入槽位使用已有写入期限内的等待，不再因瞬时繁忙立即
放弃对象。对象存储或脱敏失败保留 `capture_failure`。
无法安全处理的破损 multipart 只保留事件和明确故障原因；二进制正文不强制转 JSON，使用受保护
对象下载。以上配置与资源限制不能等同于无限正文永久完整保存，生产容量应由部署验收确认。
过去未采集的正文无法恢复，未访问生产核实原事件 callback_url 的来源。

### 评审问题修复记录

1. **持久化前脱敏**：头和 query 中嵌入的 URL 在写数据库前脱敏，包含制品 302 `Location`；
   普通 JSON 的数字不执行凭据子串替换，凭据键和实际字符串值按结构处理，短凭据不破坏数字。
2. **最终客户响应**：请求 ID、错误记录、证据观察位于 Recovery 外层，最终 500 正文及已提交 SSE
   后追加的错误均被观察；记录真实状态，不把已提交 200 改写为 500。

   删除已无用途的通用 `capture_capacity_unavailable`、`slotHeld` 和预读回放生产类型。
4. **鉴权与拒绝**：HTTP server 的单行 handler 包装只提供原生读期限控制。错误状态提交时启用
   HTTP/1 full duplex 防止 net/http 自动吞掉未读正文；先 flush 拒绝响应，再限时补采。正常请求不
   主动预读、不设置额外读期限。无法提供期限控制的测试/嵌入宿主不补读，保留 `body_not_read`。
5. **后台 POST**：插件轮询复用实际 transport 观察，每个 Task 关联保存一次请求/响应；在响应关闭
