目录回收失败；新版本数据库删除统计显示「无法展示」。用户明确要求定期回收磁盘，正文没有

本次目标是使用已启动的真实本地服务确认故障、修复容量回收行为，并通过真实 HTTP 验证媒体

## 优化方案与实施结果

- 已关闭、已到期或在手动截止范围内的证据目录，除按事件 ID 删除外，还枚举并删除剩余正文
  和暂存文件；缺失事件记录不构成保留理由。
- 完全无索引的数字证据目录及根目录孤立文件，以文件修改时间为锚：自动执行当前正文期限，
  手动执行 Root 明确截止。有效索引仍使用既有创建时间与关闭范围。严格「早于截止」删除。
- 枚举限制在证据专属目录，不跟随目录符号链接或进入正式资源目录。真实 IO 失败仍报失败并
  保留重试依据；没有将权限或磁盘故障伪装为成功。
- 插件内层 Router 仅增加一个证据中间件接线；完整收尾逻辑继续由同一证据服务持有。
  新增嵌套 Gin 回归，覆盖真实架构下的成功创建去重、鉴权事实和批量查询上下文。
- service、controller、model、router、middleware、system_setting 六包回归通过；新增容量与
  嵌套上下文回归通过 race 检查，六包 go vet 通过。文档执行 docs:check、ai:check。

剩余验收：部署实际生产版本后，核对真实磁盘/inode 回收、连续失败告警接收与媒体流量容量。
数据库行删除可回收内部空间供复用，不保证数据库文件或 PostgreSQL relation 立即等比例缩小；
本次不自动执行 VACUUM 或数据库文件重写。小时清理是容量保留策略，不是磁盘用量硬上限。

### 并发清理与业务隔离修复

用户补充业务目标为不影响当前业务后，发现手动清理可在北向证据已创建、南向尚未发送时关闭
索引；原代码把正常关闭包装为取证故障，导致业务 503。新增真实发送边界回归在修复前确定性
复现三种发送前拒绝，修复后五种并发场景通过：手动受理、手动清理完成、自动到期清理后发送，
以及手动/自动清理与上游响应等待交错。Provider 为本地 HTTP 模拟，每请求只发送一次，客户状态
和响应保持原值；没有使用 sleeps 或随机并发碰撞判断成功。

修复以正常关闭为取证无操作，覆盖事件预留、正文预检、对象发布和事件完成边界；关闭或索引已
删除时不快照南向正文，也不依赖证据存储。正常关闭不会产生传输/交付故障告警；真实数据库、
脱敏、存储故障继续保留原始错误，unknown/recovered attempt 仍不能因关闭而获得发送许可。
底层对象提交守卫不变，已关闭索引依然不能发布晚到对象或复活已删除事件。

每种并发场景还逐字段比对 users、tokens、channels、tasks、task_create_attempts、logs，确认余额、
累计消费、额度、使用记录、任务和资金占款快照未被清理修改。另有回归验证发布后事件被清理时
正常完成、不以清理掩盖真实采集故障，以及关闭后发送仍遵守资金许可。全部修改限于本地证据模块
与测试，未修改原生 Relay 发送、计费或退款实现。

修复后二进制重跑隔离真实 HTTP 验收，共 41 项通过。在新增的实际并发场景中，视频创建到达
本地模拟上游后先暂停响应；Root 经真实 API 完成该请求证据清理，再释放上游响应。创建仍返回
HTTP 200，上游 POST 恰好一次，原索引保持关闭，事件与证据目录均未重新生成。用户实际 3501
服务已更新并保持取证开启；3500/3501 健康检查成功。测试数据库和 3502 服务不保留。
