# 异步退款日志费用展示修改方案

## 目标与范围

使用日志的异步差额退款行直接展示预扣费用、本次退款和最终费用，避免用户跨行计算。
差额补扣使用同一展示规则。桌面费用列、移动卡片和日志详情保持一致，文案仅维护简体中文和英文。
普通消费、订阅标识、工具附加费及资金流水的统计、排序、导出语义保持原状。

## 数据与展示规则

- 差额结算读取日志已有的 `pre_consumed_quota`、`actual_quota`；本次退款或补扣仍读取该行 `quota`。
- 正常差额结算展示“预扣费用 / 本次退款或补扣 / 最终费用”，最终费用加粗。
- 失败退款及人工退款新增只读日志金额 `adjustment_before_quota`、`actual_quota`，从已提交的资金事件
  或原子退款返回值取得，不读取当前 Task 金额、不重新计价、不新增数据库列。
- 退款前金额不必然等于最初预扣；这两类事件使用“调整前费用”。失败退款展示“最终费用”，人工退款
  使用“调整后费用”，避免把历史事件投影成持续变化的全局最终状态。
- 历史退款缺少金额证据时显示“未记录”；不补写旧日志、不跨当前分页拼接，不按时间、模型名或渠道猜关联。
- 仅类型化任务计费元数据触发增强展示。金额须为非负安全整数，前后金额必须与本次资金差额一致；
  证据矛盾时隐藏无法确认的前后金额，本次流水金额仍保留。明确零金额必须正常展示。
- 钱包金额统一调用 `formatLogQuota`，先读取 quota 事实再格式化，不对已格式化的货币字符串做减法。
  订阅仍保留订阅身份，并说明这些金额是订阅额度折算，不表示钱包现金流。
  资金来源由 Task 创建时冻结的 `billing_source` 写入日志，不从当前用户套餐或余额推断。
- 退款说明区分结算退款、任务失败退款和人工退款；无法分类的历史记录保留现有泛称。

## 最小入侵实施

1. 新增日志专属的费用事实投影和展示组件，复用现有金额格式化、主题色和静态布局。
2. 现有费用组件只增加任务展示分支；表格仅传递日志类型，移动卡片继续复用同一费用单元格。
3. 详情仅接入同一展示组件；新增字段只补 TypeScript 类型，不扩展公共价格或 Task 合同。
4. 后端只在本地 Task 日志投影和既有退款日志写入点附加金额，资金事务、日志 quota、统计和
   NEWAPI 原生请求热路径均不变。独立回归测试放入新增文件。
5. 涉及既有前端文件的改动仅用于调用新组件和传递类型。这些入口接线是必要冲突点，未来上游同步
   只需核对相关 import、props 和窄分支；不顺带重排、格式化或抽象原生业务逻辑。

## 验收与状态

- 先补失败回归：差额退款能同时看到三个可信金额；当前只显示退款额的实现应使该测试失败。
- 覆盖补扣、全额退款、人工退款、金额零值、缺失/矛盾证据、订阅及普通消费保持原状。
- 覆盖同一费用摘要在列表、移动卡片与详情展示，以及中英文切换。
- 后端验证日志投影使用不可变事件金额、延迟交付不受当前 Task quota 干扰，以及重复交付不重放资金。
- 执行受影响 Vitest、后端窄边界测试、`bun run typecheck`、涉及文件 lint 与格式检查；
  文档执行 `task docs:check`、`task ai:check`。
- 方案与本地验证不代表真实 Provider、生产账单或灰度验收通过。实施完成后记录本地验证结果；
  当前方案不自动进入归档，也不主动更新受保护目录。

## 本地实施结果

代码及本地验证已完成，部署后界面和真实历史账单人工验收仍待执行。

- 费用投影与三行展示分别隔离到 `task-cost.ts`、`task-cost-display.tsx`；既有表格、费用组件和详情
  只做必要调用接线，移动卡片直接复用费用单元格，无需修改移动卡片文件。
- 后端两处本地文件合计新增七行：退款前后金额写入四行，冻结资金来源写入三行。
  新字段只放在日志 `other` 内；资金事务、日志主金额、统计与数据库结构均未改变。
- 前端六个相关测试文件共 63 个用例通过，包含新功能、已有工具附加费、移动卡片、详情和账单解释。
  新增前端测试先复现旧实现缺少费用明细，再验证修复。
- 后端新增金额投影与原子退款日志回归、既有 TaskBillingDelivery 交付恢复与 RefundTaskQuota
  钱包/订阅/幂等回归通过；验证延迟交付采用不可变事件金额，不读取当前 Task quota。
- `bun run typecheck`、涉及文件的 oxlint/oxfmt、`task docs:check`、`task ai:check` 与
  `git diff --check` 通过。
- 历史差额日志已有预扣/结算字段时可直接增强展示；字段缺失的旧退款只展示已知事实，缺项为“未记录”。
  未改写历史日志，未重算历史金额。
