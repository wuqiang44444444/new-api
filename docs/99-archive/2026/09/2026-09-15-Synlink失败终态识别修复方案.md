# Synlink 失败终态识别修复方案

## 问题与目标

Synlink 已返回任务失败，本站仍停留在 `RECONCILIATION_REQUIRED`，预扣资金未按失败终态释放。
目标是由 Synlink 专属 adapter 识别经取证的失败响应，复用现有任务终态与幂等退款链路，保留未知
观察、身份不匹配、非终态提前交付及冻结版本隔离的保护。

## 当前实际情况

### 已验证代码事实

- `seedance-link` 1.3.3 在读取状态前将 ID 不匹配、根级 `error`、`task.error` 合并为身份违例。
- 状态仅映射 `pending`、`processing`、`completed`，没有 `failed`。移除错误字段拦截仍会落入未知状态。
- 合同违例进入待核对并跳过普通轮询失败计数；整体超时清扫独立存在，默认 1440 分钟，不能笼统称为
  无限等待。线上是否启用、是否正常运行仍须核实。
- 任务按创建时冻结插件版本执行；发布新版不改变旧 Task 的执行快照。
- 失败退款已经有 CAS、数据库事务、资金来源与 Token 额度处理、幂等计费目标及日志交付，不应另写余额 SQL。

### 用户提供的线上证据

- HTTP 200；`task.id` 匹配冻结上游 ID；`task.status=failed`；`task.error` 为非空字符串；
  `task.outputs=[]`。`task.metadata` 中有内部任务 ID、失败状态与错误码。
- 根级 `error` 不存在；实际触发项只有 `task.error`。内部 metadata 不能成为第二状态或身份来源。
- 上游页面对应任务显示失败。同期另一条成功任务的时间与已提供账单一致；未取得任务与账单关联前，
  不能认定该失败任务被扣取供应商费用。
- 本地不保存生产 ID、凭据、请求正文、原始 Provider 响应或私有任务事实。回归使用虚构 ID 与脱敏样例。

### 补充证据与已接受决定

- 新增轻量失败样例：HTTP 200，`task.id` 匹配、`task.status=failed`、`outputs=[]`，
  `task.error` 为含字符串 `code/message` 的对象，无 metadata。原 1.3.4 的字符串限定会拒绝它。
- 完整失败样例仍是 `task.error` 字符串、`task.metadata.error` 对象；样例没有根级 `error`。
  不采用与样例冲突的表格描述，也不据此增加三处错误优先级或 metadata 状态回退。
- 用户确认保持 Synlink 专属解析。OpenAI Videos 的路径、根对象、`queued/in_progress`、下载入口和
  用量合同不能直接移植。当前缺口只在已取证的对象型错误，不扩大到自动协议识别。
- HTTP 404 的形状已获用户样例支持，但既有任务不存在时是否代表可退款的生成失败尚未证明；
  继续保持待核对。下载故障不转成生成失败；用户随后确认仅需临时下载，不建设长期托管或自动刷新，
  明确签名过期的处理见下方补充记录。

### 尚未确认

生产受影响任务范围、实际资金状态、供应商账单关联、多节点当前制品及真实 Provider 修复验收。
本地复现不等于生产部署；Provider 内部错误来源以其调查为准。

## 优化方案

1. 先补失败响应与边界回归，再修改 `parseSynlinkVideoTask`：身份、接口级错误、任务失败分别处理；
   仅 `task.status` 决定业务状态。经验证的失败形状归一为 `failed` 与脱敏错误；不采集失败中的输出或用量。
2. 非终态仍不交付输出、不结算；成功仍须 `completed` 与可信结果；未知状态、错误类型、矛盾结果、
   ID 不匹配及非 2xx 不转业务失败或退款。创建仍只接受可信 `pending`。
3. 发布新的内置插件版本，保留旧制品与冻结快照。不修改原生分发、轮询、资金算法或历史 Go adapter。
4. 通过实际插件到 HTTP 轮询和数据库资金的集成回归，验证待核对恢复为失败、预扣全额释放、重复处理
   不重复退款、钱包与 Token 额度一致、失败日志脱敏、终态不再调度。
5. 补充旧版本任务的人工核实处置与发布步骤：按任务精确关联证据，经既有状态和资金入口恢复；不直接
   改余额、不重发生成、不把当前插件静默替换进历史任务。生产操作需在实际运行环境另行执行和验收。
6. 补齐对象型 `task.error`：保留外层任务身份／状态及输出校验，明确校验可选 `code/message` 的类型，
   错误经宿主脱敏后落同一失败退款入口。升级至 1.3.5，不覆盖可能已冻结的 1.3.4 制品；
   用字符串和对象两种样例验证终态、公开错误码、无 usage 退款和重复处理幂等。
7. 同步架构事实与未完成验收项；执行相关 Go 测试、`task docs:check`、`task ai:check` 与差异检查。

## 实施与验证记录

### 本地实施结果

- 首轮内置插件升级至 1.3.4，补齐可信 `failed` 归一，并将身份不匹配、查询错误、非失败状态错误、
  畸形失败分开诊断。可选错误缺失／null／空白使用通用失败说明；只接收已验证的字符串错误类型。
- `task.status` 保持唯一状态来源，失败不传播 metadata、结果或用量；脱敏复用宿主既有入口。
- 首轮新增 13 组失败与异常边界用例，以及实际插件／HTTP／SQLite 的完整资金回归。后者从生成中经过
  三种不可信观察进入待核对，再接受可信失败，验证钱包、Token、退款日志与终态调度；重复查询不重复退款，
  创建调用保持一次，敏感错误内容不出现在任务失败原因及退款日志。
- 删除一个强制新版插件沿用历史 Go“不接受 failed”行为的对照样例，用直接失败合同回归替代。
  历史 Go 实现及旧插件源码不变。现有冻结版本缺失与旧制品保留测试继续通过。
- 同步[协议架构](../20-architecture/Seedance专用渠道与Link架构.md)、
  [处置手册](../40-operations/Synlink失败任务处置手册.md)与[路线图](../50-planning/路线图.md)。
- 补齐 Synlink 供应商名称脱敏；插件宿主使用 Task 冻结的客户／上游模型身份处理错误，保留客户模型别名。
- 新增单笔维护 CLI：默认只读、明确限定 SQLite 同库离线且未使用 Redis 的部署；验证 Root、客户／应用／渠道、
  旧插件身份、待核对状态和占用 quota。人工终态与审计同事务，资金仍调用既有幂等退款与日志交付入口。
  失败可续跑，拒绝重复备份覆盖，不增加通用管理接口、数据表或第二套资金算法。
- 本次没有修改 NEWAPI 原生实现、共享轮询／计费算法、数据库结构或 relaykit API；
  无新增原生接线点，未来上游同步的原生冲突面不扩大。

### 剩余生产事项

需部署并核对各节点实际加载 1.3.5；新任务真实成功／失败与资金验收仍待执行。旧任务继续冻结原版本，
需在生产环境逐笔核实后经单笔维护工具或该环境适用的受审查入口处置，本次未执行线上退款。
已交付工具仅支持 SQLite 主库／日志同库、全部节点停机且未使用 Redis 的部署；其它环境仍需适用工具。
当前没有已创建 Task 的通用人工失败管理接口，不以 attempt reject 替代，也不声称升级可自动修复历史任务。
供应商计费归属与更多受影响任务只接受精确关联证据；不能按时间、金额或同一错误串自动归因。

### 本轮补充实施记录

- 文档先记录用户接受的 Synlink 专属协议边界，再将插件升级为 1.3.5。新增对象型 `task.error` 的
  字段校验与提取；字符串、缺失／null／空白错误行为保持一致。只接受 `task` 包裹和已取证状态，
  不读取 metadata 作为备用状态或错误，不增加 OpenAI 协议猜测分支。
- 失败解析回归扩至 26 组，覆盖对象型完整／可选字段、额外字段丢弃、错误类型、矛盾输出及无 metadata
  回退；补充 OpenAI 根对象和未经取证状态别名的拒绝用例。对象型样例在修改前复现合同违例，修改后通过。
- 完整资金回归分别执行字符串型与对象型样例，验证无 usage 的失败退款、钱包／Token 额度、唯一退款日志、
  敏感内容脱敏、客户模型别名与公开错误码保留。定向回归及冻结版本缺失保护已通过。
- 本轮实现只改 Synlink 插件，Go 变动为回归测试；没有修改共享轮询、计费算法、历史 Go adapter 或原生入口。
- 本轮静态检查、`task docs:check`、`task ai:check` 与差异检查通过。
- 完整后端回归中，model、middleware、service 与 relay 全部通过，Synlink 解析和资金回归通过；
  controller 的 `TestSecurityAccountDeletionConcurrentRequestsHaveOneWinner` 出现 SQLite `SQLITE_BUSY`，
  是本轮未改动的账户注销并发路径。controller 整包独立重跑再次出现同一失败，
  其余用例通过。该账户注销用例单独执行通过，但整包锁竞争问题尚未解决；
  不能将本轮全量验证标为通过。本次不扩大到修改账户注销逻辑。

### 临时下载与查询诊断优化

- 用户确认旧任务不自动修复、视频不长期保存；本轮只完善查询 404 诊断、临时下载说明和明确过期提示。
- Synlink HTTP 404 仍返回不可采信观察，但原因明确为查询返回 404、结果未确认；JSON 错误和代理 HTML
  都不据此退款。其它非 2xx 保留 HTTP 诊断，不采集原始错误正文作公开说明。
- 独立内容辅助逻辑只识别 Synlink 选中 HTTPS 地址的 TOS4 签名日期与有效时长；缺失、重复或畸形参数
  不判过期。已明确到期返回既有 `410 video_content_expired`，GET 与 HEAD 共用同一行为。
  既有 `expires_at` 检查保留；裸 403/404 和连接故障继续按读取失败处理。
- 不新增数据库字段、不持久化到期推算、不改变冻结插件或 URL、不重新查询或重发视频、不修改成功状态
  和计费。代码只接入 Link 内容入口与 Seedance adapter，没有新增 NEWAPI 原生文件修改。
- 控制台 Seedance 成功结果区复用现有说明布局并补齐七种语言；公开接入文档说明及时下载与无长期存储，
  不显示缺乏依据的倒计时，不声称 24 小时内必然可用。i18n 工具仅增加一个键，其余差异为既有键排序。
- 新增 404 资金回归先复现旧笼统诊断；修复后包含两种失败形态的资金回归与 Synlink 定向回归通过。
  内容测试覆盖签名明确到期、缺失／重复／畸形参数、协议隔离、普通 403/404、连接失败、正常下载、
  GET/HEAD、跨应用拒绝，以及任务成功状态、费用与完成时间不变。
- 前端临时下载提示与待核对展示回归通过，类型检查与所改文件 lint 通过；`go vet ./controller
  ./relay/channel/task/seedance`、`task docs:check`、`task ai:check`、公开 API 文档校验与差异检查通过。
  本轮只运行上述相关回归，不将此前账户注销并发用例的 SQLite 锁竞争问题标记为已解决。
- 本轮未部署、未操作生产任务或资金，也未执行付费生成取证；真实交付验收仍列在路线图。

### 人工维护诊断补齐

- 修复审计发现的错误折叠：模型层用固定拒绝类别区分任务范围、Root 操作人、冻结合同／资金、额度、
  状态及既有证据冲突；仅记录不存在才归入操作人／任务条件错误，数据库查询失败保留为基础设施错误。
- CLI 按参数、数据库打开、预检、备份、终态事务、退款与日志交付标注阶段。只输出允许的固定错误说明，
  数据库异常、未知异常和被包装的错误均不透出原始正文；参数解析错误不再回显输入值，保留帮助入口。
- 没有改变恢复资格、冻结版本限制、事务边界或资金算法；没有修改 NEWAPI 原生文件、数据库结构、
  在线调度与共享计费入口。旧任务仍须人工核实授权，本轮没有部署或操作生产任务。
- 新诊断用例在修改前复现通用错误折叠与参数值回显；修改后维护工具和 model 整包测试通过：
  `go test ./cmd/recover-synlink-failure ./model -count=1`。覆盖范围拒绝、数据库与业务错误区分、
  审计回滚、退款续跑、日志交付续跑且不重复退款、错误包装脱敏和帮助输出。
- `go vet ./cmd/recover-synlink-failure ./model`、`task docs:check`、`task ai:check` 和差异检查通过；
  处置手册补齐阶段、类别与对应恢复步骤。
