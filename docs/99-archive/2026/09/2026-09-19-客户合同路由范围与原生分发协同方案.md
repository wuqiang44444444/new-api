# 客户合同路由范围与原生分发协同方案

> 状态：已获用户授权实施，合同范围、原生分发接线、计费刷新、投影及界面已落地本地工作区。
> 本文保留方案和实施前基线；当前代码边界以合同专题架构与 ADR-0020 为准。
> 本地验证及未完成的部署验收见文末，未进行生产配置变更或生产验收。

## 问题与目标

客户合同编辑器同时选择模型、路由组、渠道与折扣，但实施前运行时只消费模型折扣，不使用合同中的
组与渠道限定路由。绑定合同的 Key 如果仍使用 `default`，请求就可能进入合同未选择的渠道。

目标是让合同定义“允许使用哪些模型、组与渠道组合，以及模型折扣”，由既有原生分发机制在
允许范围内执行渠道选择。合同不维护另一套优先级、权重或随机算法，也不把多渠道规则退化为
旧版的单渠道固定执行。

### 用户已确认的决策

| 项目 | 已确认要求 |
| --- | --- |
| 合同范围 | 使用当前编辑器明确保存的“公开模型 + 路由组 + 渠道”组合，不授权整个组中的其他渠道 |
| Key 分组 | 合同启用且 Key 绑定时，合同范围决定该模型的候选组合；Key 留在 `default` 不阻止使用合同指定的其他组 |
| 渠道选择 | 合同不设置优先级和权重，候选渠道使用原有优先级、权重及适用的原生分发规则 |
| 同模型跨组 | 合同选择的多个渠道可以来自不同组，在允许范围内按原有渠道优先级、权重竞争；使用最终选中组合对应的组计费 |
| 分组设置 | 原有组倍率、适用的特殊组倍率等设置继续生效，合同不改写组配置、不把合同折扣冒充组倍率 |
| 未列模型 | 绑定启用合同的 Key 请求合同未列出的模型时拒绝，不按原生价格继续调用 |
| 停用合同 | 合同不再参与范围限制和折扣，请求按 Key 自身分组及原生规则执行；停用不等于停用 Key |
| 解除绑定 | 请求按 Key 自身分组及原生规则执行 |
| 合同读取失败 | 绑定合同的读取、归属或解析异常时拒绝本次请求，不回退到 Key 原生分组 |

“原有组逻辑不变”在本方案中的边界：保留组配置、组与模型及渠道关系、有效组倍率计算，以及未启用
合同请求的原生行为。启用合同的请求从合同组合取得候选范围，并按已确认规则跨组比较渠道；这不是
保留 Key 原生 `auto_groups` 的先组后渠道顺序，不能同时声称合同跨组竞争与该顺序完全不变。
不得把本次候选范围变化扩展到无合同请求，也不得根据组倍率排序或推断路由优先级。

### 评审后补充的设计选择

以下是依据已确认目标、现有原生边界及评审意见形成的方案选择，不冒充用户此前逐项确认过的内容，
用户随后授权按方案完整实施。后文执行流程与验收均按这些选择展开，不能在实现时另选相反行为而不修订方案。

| 编号 | 本次修订采用的设计 | 理由与适用边界 |
| --- | --- | --- |
| D1 | 用户可用组权限继续作为上限；启用合同时，合同替代 Key 的选路组，但不替代用户组访问权限 | 区分 Key 的路由偏好与用户访问权限；用户可访问合同组时，Key 为 default 仍可使用该组 |
| D2 | 首次在全部有效合同组合内选路；重试保留现有 `CrossGroupRetry` 开关，关闭时只在首次实际选中组内重试，开启时可在合同范围内跨组重试 | 不把首次跨组竞争与失败后的跨组重试混为一谈，也不因合同绑定自动打开重试权限 |
| D3 | 新 remix/continuation 校验当前合同与锁定渠道，范围不符即拒绝；旧任务自身继续按冻结事实执行 | 原渠道锁定是新调用的执行条件，不是当前合同的授权豁免 |
| D4 | 绑定启用合同的 Key 发现/价格投影使用有效合同范围；合同明细保留完整约定并区分不可用项 | 保证发现面与执行面一致，又不把临时不可用误写成合同条款消失 |
| D5 | 可重试的新请求逐次按实际组重估，复用同一资金会话补足更高预估，较低预估在最终结算时处理差额 | 复用原生资金与信任策略，不预扣全部候选上界、不为每次重试创建独立净消费 |

上述选择有明确业务后果：无用户组权限的合同组合不会因管理员保存而自动授予权限；非 auto Key
当前保存逻辑会将 `CrossGroupRetry` 置为 false，因此这类 Key 默认只允许首次跨组选择，后续重试不
跨出首次选中组。本方案不自动修改现有 Key 的开关或分组；需要跨组重试时使用原有可配置入口，
即使 Key 使用 auto，其生效合同范围仍不取自 auto 组列表。

### 成功标准

1. 合同为文本模型只选择渠道 56、为图片模型只选择渠道 57，且用户具有对应组权限时，Key 保持
   `default` 仍只使用对应合同组合，其他渠道的高优先级、权重或历史亲和记录不能使请求越界。
2. 同一模型选择多个有效渠道时，渠道原有优先级与权重生效；选择一个渠道时候选自然为单个，
   不通过额外合同 pin 强制改变原生重试语义。
3. 实际组、渠道与有效组倍率来自最终执行组合，合同折扣按精确公开模型解析，不随渠道变化。
4. 停用或解绑后恢复 Key 自身原生逻辑；合同仍绑定但读取失败时不外发请求、不产生消费。
5. 绑定 Key 的模型发现和价格反映同一有效范围；新派生请求不能利用原任务渠道绕过当前合同。

## 优化方案

以下实施措施是根据已确认需求推导的工程约束；具体类型和函数接线需结合实施时最新代码确定。

### 1. 合同生效状态与失败语义

| 请求状态 | 路由范围 | 合同折扣 | 结果 |
| --- | --- | --- | --- |
| Key 未绑定合同 | Key 原生分组与权限 | 不应用 | 原生执行 |
| 合同成功读取且明确停用 | Key 原生分组与权限 | 不应用 | 原生执行 |
| 绑定启用合同，精确模型存在且有有效组合 | 合同明确选定的有效组合 | 应用该模型唯一折扣 | 受范围约束地执行 |
| 绑定启用合同，模型未列出 | 不产生候选 | 不计费 | 拒绝请求 |
| 绑定启用合同，模型列出但 Key 模型限制排除，或合同组均无用户访问权限 | 不产生候选 | 不计费 | 拒绝请求，不转入 Key 原生模式 |
| 绑定启用合同，所有组合均不可用 | 不产生候选 | 不产生成功消费 | 返回不可用，不回退 |
| 绑定引用缺失、归属异常、数据库故障、版本或折扣一致性异常 | 不产生候选 | 不降级为原价 | 失败关闭 |

合同记录丢失不等同于正常解除绑定。不能将“模型未列出”“合同不可用”和“合同已停用”统一转成
nil 并继续原生请求。错误状态复用现有错误协议，具体错误码在实现时核对，不暴露内部渠道或组详情。
普通新请求在选路和首次计费前解析一次合同状态与版本；延迟解析模型的请求在模型明确后、首次计费
和外发前完成范围校验。同一已受理请求的重试不因中途停用或解绑改成原生模式；后续新请求才读取
新状态。历史任务的轮询、查询、交付、结算仍使用既有鉴权与冻结事实，不要求重新通过当前模型合同。

### 2. 唯一范围来源与候选构建

- 继续以 `tokens.contract_id`、合同实体和实体规则为权威，不读取旧用户级模型合同作为运行时 fallback，
  不新增用户级路由表、合同 Ability 表、影子组、虚拟渠道或第二套公共分发缓存。
- 一条规则代表一个允许的组合，不能只提取组后放开组内全部渠道，也不能只提取渠道后丢失组与计费归属。
- 复用当前保存规则：精确公开模型、具体组、具体渠道、同模型同折扣；同模型同渠道唯一性保留，
  使选中渠道对应的合同组无歧义。本方案不以数据库结构迁移为前提；如实施证明必须改结构，另列原因。
- 渠道启停、渠道对模型的支持、规则组中的有效关系及入口兼容性必须按当前原生事实判断。
  渠道被移出合同规则组后，该组合不可用；不得自动跟随渠道到其他组或改用组内未选渠道。
- 合同不绕过用户/Key 启停、额度、限流、Key 模型限制或类型化入口资格。按 D1 使用原生
  `GetUserUsableGroups` 解析用户可用组（包含原生特殊可用组规则），过滤无访问权限的合同组合。
  不拿 Key 的 `group` 或 `auto_groups` 与合同组求交集，也不把用户可用组误当成全部候选渠道。
  全部合同组均无权限时明确拒绝；部分组有权限时仅在剩余组合内选择。
- 鉴权顺序必须区分原生身份检查与 Key 选路组检查：先验证身份并读取合同状态；生效合同按 D1
  检查合同候选组，无合同/停用合同才沿用 Key 原生选路组检查。不得在判定合同状态之前因 Key 保存
  的旧路由组失效而提前拒绝有效合同请求；原生身份、安全和模型限制检查仍然执行。
- 复用现有合同版本与鉴权版本缓存失效机制；新请求观察合同修改、停用与 Key 解绑，不建立独立版本源。

有效候选集合统一定义为：当前请求模型的合同规则，经过用户组权限、Key 模型限制、入口资格及当前
渠道/组/模型有效性筛选后的组合。发现和价格投影消费同一规则源及等价筛选政策，不依赖前端自算，
不从原生 Key 候选列表出发过滤而漏掉合同指定的其他组。管理预览显示无权限或不可用原因，但不静默
删除持久规则；运行时不得自动修改权限或修复合同。投影不是履约承诺，真正调用仍须检查实时可用性。

### 3. 原生分发接线与跨组限制

合同入口只提供允许组合及折扣，不决定获胜渠道。优先复用既有候选约束和选择路径，将合同专属
解析与组合构建放在独立文件；现有入口只保留必要的窄接线。

适用的原生筛选及亲和规则通过后，对需要随机选择的候选使用渠道现有优先级及同优先级权重。
同模型跨组候选的优先级比较按本次确认执行，不新增合同优先级、跨组排序配置或倍率择优算法。
候选最终必须携带所对应的合同组，不能从渠道的多个分组字段中任取一个。

当前单组选择器不能仅靠传入 Key 的 `default` 完成该行为，也不能先在组内任取渠道再检查合同，
因为那会遗漏允许范围内的可用渠道。实施前应证明现有选择入口能够在优先级计算之前接收候选约束；
允许在合同专属 service 文件中增加薄的候选编排，输出完整有效组合与选中组事实；如原生抽样入口
必须扩展，保留单一权威实现并记录最小接线原因。禁止另写会与原生优先级、权重语义漂移的平行算法，
而不是禁止组合编排本身。

不得每组先抽一个渠道再对各组结果等概率选择，这不等价于全体候选按权重竞争。例如同优先级、
同权重的三个渠道分属“两个渠道的组”和“一个渠道的组”，在均匀抽样的数学示例中各为 1/3，先组内抽样再
等概率选组会成为 1/4、1/4、1/2。测试需证明完整候选集合的优先级与权重边界，不能以“调用了
原生函数”代替语义证明。合法且范围内的原生 pin、亲和按原有先后顺序处理；优先级胜出断言仅
适用于实际进入随机选择的场景，不能宣称有亲和时也必定选择最高优先级。数学示例用于说明分组
抽样造成的额外偏差；实际代码回归以对应缓存/数据库路径的既有原生抽样行为为基线，不能借此
顺手统一两条原生路径的既有权重细节或修复范围外的抽样问题。

必须覆盖以下入口，不能只约束第一次随机选路：

- 亲和缓存命中：只有仍属于当前合同有效组合的渠道才可使用；范围外缓存不得放行。
- 失败重试：按 D2 先确定本次允许重试的组范围，再使用原生优先级层级和权重；关闭跨组重试时
  固定的是首次实际选中组，不是固定渠道，同组其他允许渠道仍可按原生规则使用。开启时可在有效
  合同组合内跨组，不引入先组后渠道顺序；重试次数、错误可重试性、pin 和 unknown 禁止重试
  等原生或类型化约束继续有效。候选耗尽即失败，不回退到 Key 组、全局 auto 组或范围外渠道。
- 指定渠道及后解析模型入口：新模型调用不得借 pin、Playground 组覆盖或延迟解析绕过合同范围。
  已受理任务的持续执行与新请求须区分，不把当前合同重新套在历史任务上。
- 无合同和停用合同：原生优先级、权重、auto 分组顺序、亲和及重试语义保持原样。

#### 新派生请求与历史任务的明确分界

- 轮询、恢复执行、交付或结算同一个已受理任务：保持任务创建时冻结事实；停用合同不撤销原任务。
- 新 remix/continuation：先通过既有任务归属和操作资格校验，解析公开模型及原生锁定渠道，再按
  本次请求合同校验该渠道是否存在于有效组合中。模型无法可靠解析时失败关闭，不猜测合同模型。
- 锁定渠道在当前有效合同组合中：使用该组合的组、本次合同折扣与新请求的定价事实提交新任务。
  原生要求继承的时长等业务参数照常继承，不把历史组倍率或旧合同折扣冒充本次定价。
- 锁定渠道不在范围内或已不可用：在新请求计费与外发前拒绝，不换到其他合同渠道，不因历史任务
  曾被允许而豁免。旧任务自身不受该拒绝影响。
- 无合同或合同明确停用的新派生请求：不增加合同范围检查，保留原生任务亲和/锁定等操作约束，
  “恢复 Key 原生逻辑”不意味着强制把原生锁定渠道重新随机选择。

实施时替换 `ApplyCustomerContractResolvedModel` 中“锁定渠道无需出现在合同明细”的旧语义及测试，
不能同时保留旧注释、旧豁免与新范围检查。

组倍率影响价格，不决定分发顺序。候选范围变化可能改变成交组，不能把“沿用组倍率规则”写成
“升级前后成交金额保证相同”。内存缓存与数据库选择路径均须验证范围约束；已存在的原生权重细节
差异须如实记录，不借本方案无关重写原生算法。

### 4. 计费与在途请求

模型费用按以下顺序处理，独立工具费等继续遵循原有合同计费边界：

```text
客户模型费用 = 原生模型费用小计 × 实际执行组合的有效组倍率 × 合同模型折扣
```

- 管理明细中的组成为本次候选组合的组依据；实际选择完成后写入真实执行上下文，再使用现有
  原生组倍率及特殊组倍率解析。不能仅在日志里改组名而预扣、结算仍使用 `default`。
- 合同折扣按受理时合同版本及精确公开模型冻结，同模型切换渠道不重新选择折扣、不重复叠乘。
- 每次允许外发的新尝试须先确定实际组合并刷新组相关价格状态，不能机械沿用首个候选组的价格。
  合同折扣与已冻结的模型/表达式事实保持稳定；不按重试时钟重新求值已冻结请求规则。
- 已受理的 Task/attempt 按其冻结事实执行；合同改价、停用或 Key 解绑只影响后续新受理请求，
  不重解释历史任务、不自动重算账单、不自动处理 unknown 请求。
- 合同内无可用渠道属于请求履约失败，不能把它当成合同停用以恢复原生执行。

#### 跨组重试的资金规则（实施前必须证明）

采用 D5 的“逐次重估、同会话补充预扣、最终结算差额”，不把三种备选机制留给实现者自由选择。
参考原生 `PrepareTieredBillingForSelectedGroup` 和 `BillingSession.Reserve`，但不能据此假定
固定价、token、图片、音频和各异步入口全部已覆盖。接线前必须逐个证明对应生命周期，不得在
部分计费分支使用旧组价格时上线跨组重试。

| 下一次允许的尝试 | 发送前要求 | 终态要求 |
| --- | --- | --- |
| 需要实际预扣且预估高于当前会话预扣 | 更新实际组及价格，使用同一会话补充预扣到本次目标；不得把目标再次作为全额独立扣款 | 按实际可计费结果一次结算差额 |
| 需要实际预扣且预估低于或等于当前会话预扣 | 更新实际组及价格，不因重试立即释放原预扣 | 以最终实际费用统一计算应退/应补差额 |
| 初始免费、未创建资金会话，后续付费 | 在付费尝试外发前经现有统一入口创建会话并执行相应预扣策略 | 正常结算，不能因旧 FreeModel 标记漏收费 |
| 付费转免费 | 更新实际价格，不把已有预扣伪装为未发生；组倍率为零不代表独立工具费等必定为零 | 按真实计费边界结算和释放多余预扣 |
| 估价、额度或资金动作按原生政策返回错误 | 停止本次外发，不通过再次换渠道绕过错误 | 确知请求失败时沿原生幂等退款路径处理，不重复退款 |
| 已出现 durable attempt、发送结果 unknown 或已受理异步任务 | 遵循原生命周期禁止重发、换渠道与自动退款的约束，不进入本表的普通跨组重试 | 保持冻结事实和必要持款，交由原生命周期处理 |

资金“检查成功”指满足现有对应资金策略，不承诺钱包永不欠费。已有信任旁路、钱包补充预扣允许
欠费、订阅额度校验和 Key 额度校验均保持原生边界；不得为合同默认添加强制全额 hold，也不得将
其他资金类型改成钱包语义。可信会话可能不实际补扣，预扣日志必须写真实资金动作，不能写估算目标。
对需要实际预扣的会话，在连续涨价重试时保留的是已成功覆盖的最高目标，不是所有目标之和。

免费转付费、信任额度、钱包、订阅、Key 配额及失败回滚分别验收。所有用户量、倍率与 quota 转换
继续遵守已有边界和饱和/拒绝策略；本方案不改变计费表达式语言、不另建账本，不以重试为由改变
独立工具费、违规费和 Provider 成本的现有归属。

### 5. 类型化入口与最小侵入

Seedance、异步图片、Azure Batch 等入口必须分别检查现有类型化选渠与合同接线。合同范围不能
为渠道创造入口资格，也不能把类型化渠道送入 NEWAPI 通用 Ability 分发池。
Seedance 的“一客户模型一启用渠道”、不亲和、不跨渠道重试等硬约束继续有效；合同多渠道规则
不构成放宽这些约束的授权。

类型化组合必须用入口自身的渠道类型、组归属、精确模型与启用状态判断，不要求存在通用 Ability。
现有 `validateCustomerContractEntityChannel` 的分支可作为事实来源参照，但管理保存校验不能替代
请求执行时的有效性判断。合同过滤不授予入口资格，也不把来自其他执行模式的同名规则混入候选。

例如 Seedance 在合同有效组范围内，按自身模型登记与启用渠道事实确定唯一可履约渠道，只有它同时
出现在该请求的有效合同组合中才可提交；不能仍用 Key 的 default/auto 组选渠后才过滤，否则会漏掉
合同其他组中的有效组合。无合同或停用合同才保持原有组选取入口。
合同只列旧渠道而该模型已转到另一个渠道时，新请求失败关闭；不得沿原生唯一渠道直接放行，也不得
尝试合同中的其他协议。异步图片与 Azure Batch 同样分别核对自身事实；故障和空候选不等于合同
停用。各入口不支持的优先级、亲和或重试机制不因合同有多条规则而新增。

| 接线面 | 拟修改必要性 | 最小范围与上游同步影响 |
| --- | --- | --- |
| 合同专属 model/service/middleware 文件 | 解析范围、区分状态并提供折扣事实 | 主体逻辑放本地新增或已有合同专属文件，避免扩大原生文件 |
| 原生鉴权和分发入口 | 生效合同的范围解析须早于依赖 Key 分组的选路；错误不得外发 | 只保留必要调用或窄分支；原生鉴权语义须逐项核对，是上游合并复核点 |
| 原生候选选择与重试入口 | 接收合同约束并返回对应实际组，保证重试不越界 | 优先复用现有入口及约束；跨组接线确有需要时记录不能零修改的原因，不重写随机算法 |
| 计费及任务接线 | 保证真实组与冻结折扣、预扣和终态一致 | 复用现有价格及资金逻辑；只有证明确有缺口才增加窄接线 |
| 合同管理界面 | 说明选中的组和渠道会限制执行，停用恢复 Key 原生模式 | 复用现有四项字段与规则编辑，不新增优先级、权重配置；文案仅要求简中和英文 |
| 模型发现与价格投影 | 绑定 Key 的公开能力及价格须与执行范围一致 | 合同专属只读投影复用范围规则；原生接口必要早返回/窄接线，保留全站目录与未绑定路径 |

### 6. 模型发现、价格与合同明细

| 查询身份/用途 | 模型与价格口径 | 停用或异常处理 |
| --- | --- | --- |
| 绑定启用合同的 Key 查询 `/v1/models` 及同类发现接口 | 使用该 Key 的有效合同范围及现有公开资格、价格配置要求；去重公开模型，不通告合同未列模型；不能漏掉 Key 默认组之外的有效合同模型 | 合同停用则原生投影；读取异常失败，不返回原生全量或伪装为空列表 |
| 绑定启用合同的 Key 查询 `/api/pricing` | 仅投影有效合同组合支持的模型/执行模式和适用价格，按真实有效组倍率叠加一次合同折扣 | 同上；无可用组合可以正确返回空的有效报价，不将读取故障解释为空 |
| 会话显式选择合同 | 校验合同归属；按所选合同、用户组权限及执行模式展示预览，注明不代表任意 Key 的完整权限 | 停用合同不能冒充生效报价；沿用明确不可用响应 |
| 全站目录或未选择合同的会话 | 保留原生目录/价格，不擅自挑选用户的一份合同、不把公开目录描述成某 Key 的权限清单 | 保留原生语义 |
| Key 合同明细与管理预览 | 保留合同完整模型约定；分别标注合同停用、组合无权限/不可用及 Key 自身限制，不静默删掉合同条款 | 解除绑定显示未绑定；读取失败显示加载失败 |

同模型多个有效组倍率不同时，预览展示合法公开维度的价格差异或有效候选组合的报价范围，不任取
第一条规则生成单一固定价承诺。价格范围不包含范围外分组，也不承诺本次请求一定会遍历全部组合；
实际执行还受优先级、亲和和跨组重试开关约束，最低候选报价不是必然成交价。
普通与 Batch 等执行模式使用各自基础价格，再叠加对应组倍率与合同折扣。
沿用现有公开字段边界，不新增内部渠道 ID、Provider 身份或合同内部路由字段的泄露。

发现、价格和运行时必须共享合同状态、模型匹配、范围与权限政策；不要求发现时保证资源永久可用。
组权限和渠道状态变化后，展示与新请求都应重新反映变化；各查询不创建合同或资源，也不成为第二
份授权事实。接口形状保持既有兼容要求，具体投影文案与中文/英文错误文案随实施一并验证。

### 7. 文档、ADR 与关联方案

正式实施时同步 [合同产品说明](../10-product/用户模型合同定价.md)、
[合同定价架构](../20-architecture/账单计费-用户模型合同定价架构.md)、
[开发与验证指南](../30-engineering/用户模型合同开发与验证.md)和适用 UI 说明。
同步范围明确包含模型发现、价格投影、Key 合同明细、新 remix、类型化入口和逐次预扣规则，不能只
改路由说明而保留“合同不影响可用模型清单”等旧断言。

本次是对 ADR-0019“合同只提供折扣、不控制范围”的核心决策反转，不是对同一决策补充实现细节。
正式实施时按现有 ADR 门禁记录取代决策：新编号取当时最大值加一，旧 ADR-0019 保留原文决定与
否决理由，更新为 `status: superseded` 并填写 `superseded-by`，索引记录替代关系。当前事实由
同一合同专题架构维护，不保留两套同时生效的规范。实施已建立 ADR-0020 → ADR-0019 的取代关系。

取代理由须正面回答旧 ADR 的取舍：

1. 现在明确需要合同控制履约范围，单纯折扣层不能满足；保留纯折扣层已不符合本次确认的业务目标。
2. 跨组比较是显式接受的选路语义变化，不宣称完全保留 auto 组顺序；统一比较现有渠道优先级与
   权重，不通过价格推断优先级，也不新增合同排序配置。
3. 组倍率及特殊倍率仍各自生效，客户接受按实际组合计价；不以“同模型同折扣”承诺跨组同价。
4. 候选编排复用单一选择实现，范围约束覆盖所有入口，避免旧 ADR 担忧的两套分发器和资格事实漂移。
5. 用户组权限、类型化入口与资金生命周期继续独立约束；接受由合同范围新增的拒绝情形及升级核对成本。

仓库并非规定每次修改 accepted ADR 都必须新建；这里选择取代，是因为直接改写核心决定会抹去
曾经导致本次行为变化的历史取舍。新 ADR 记录本地客户合同边界，不重定义 NEWAPI 上游协议事实。

[客户合同模板方案](2026-09-18-客户合同模板功能分析与实施方案.md)的合同作用说明已同步到新范围政策；
模板只复制规则、不持续同步合同、不自动绑定 Key 的独立边界不受影响。
模板方案的作用边界须引用新的合同专题架构；本次不实施模板功能、不归档其他增量文件。

## 验证与验收

### 行为矩阵

| 场景 | 必须证明的结果 |
| --- | --- |
| Key 为 default，合同指定用户有权限的其他组单个渠道 | 使用合同组合及该组倍率，不受 default 候选池替代 |
| 用户无全部合同组权限或 Key 模型限制排除请求模型 | 发现不通告有效调用资格；执行拒绝，不回到 default |
| 用户只拥有部分合同组权限 | 只在有权限的有效组合内发现、报价、选路；管理明细保留完整约定 |
| Key 保存的原选路组已失效，但生效合同组合有效 | 合同模式使用有效组合；合同停用后恢复原生校验，不能保证旧 Key 组可用 |
| 同组存在未选高优先级渠道，或新增渠道 | 未选渠道不参与，无权限自动扩张 |
| 同模型允许多个不同优先级渠道 | 无亲和/pin 的选择场景中，原生有效优先级胜出 |
| 同优先级多个允许渠道 | 使用原生权重规则；通过可控随机输入或既有可验证边界证明，不用大循环概率测试 |
| 同模型首次跨组、渠道优先级和组倍率不同 | 按渠道竞争规则选择，预估使用实际组合，实际预扣遵循资金策略，结算和日志归属一致 |
| 同优先级等权渠道按 2+1 分属两个组 | 与对应原生路径对完整三候选的抽样行为一致，不能增加按组等概率抽样；均匀抽样示例为各 1/3 |
| 特殊组倍率生效 | 使用原生有效倍率一次，再乘合同折扣一次 |
| 范围外历史亲和、指定渠道或 Playground 组覆盖 | 不越过合同范围；范围内亲和保持适用的原生行为 |
| 首次渠道失败后重试 | 只使用允许候选，最终渠道、组与计费证据一致 |
| 跨组重试关闭 | 首次仍可跨组竞争；后续仅在首次选中组的合同渠道内重试，该组耗尽即失败 |
| 跨组重试开启 | 可使用其他有效合同组，仍受重试次数、错误类型、原生 pin 与异步发送闸门限制 |
| 非 auto Key 保存后绑定多组合同 | 保持原有 CrossGroupRetry=false，不自动改成 auto 或开启开关 |
| 多次涨价、随后降价重试 | 非信任会话按更高目标补差，不累加每次全额预估；低目标不提前释放，最终按实际金额结算 |
| 免费转付费、付费转免费 | 正确建立或保留会话；不得因旧免费标记漏扣或因倍率为零误免独立费用 |
| 信任会话、钱包允许欠费、订阅/Key 额度不足 | 分别遵循既有资金政策；真实预扣与估算目标分开记录，资金错误阻止下次外发 |
| 所有候选停用、移出组或不再支持模型 | 明确失败，不进入 default 或其他未选渠道 |
| 启用合同未列出请求模型 | 无 Provider 调用，无消费，明确拒绝 |
| 合同停用、Key 解绑 | 恢复 Key 原生分组、模型限制、auto 顺序和价格，无合同折扣 |
| 合同恢复或 Key 换绑 | 后续请求读取新的有效范围，不复用过期亲和资格或合同缓存 |
| 合同记录丢失、归属/版本/折扣异常、读取错误 | 失败关闭，不当作停用或未绑定 |
| 内存缓存开启与关闭 | 上述范围与优先级约束均成立，测试显式初始化数据库列名和全部依赖状态 |
| 在途 Task 与新请求并存时修改/停用合同 | 旧任务保持冻结事实，新请求按新合同状态执行 |
| 同步请求重试期间合同被停用或解绑 | 保持该请求已解析的合同范围和折扣，不中途切换原生；下一新请求恢复原生 |
| 新 remix 锁定渠道不在有效合同组合内 | 计费和外发前拒绝；不换渠道，不影响原任务查询、轮询、交付或结算 |
| 新 remix 锁定渠道在有效合同组合内 | 使用当前请求合同组合的组与折扣建立新事实；不搬用旧任务的组倍率或合同折扣 |
| 无合同或停用合同的新 remix | 无合同范围限制，但保留原生归属校验、模型解析与原渠道锁定 |
| 类型化渠道不存在通用 Ability，但自身入口资格及合同组合有效 | 正常执行；不能因为通用 Ability 查不到而误拒绝 |
| 类型化入口有原生可履约渠道，但合同只列过期/其他执行模式渠道 | 失败关闭；不因原生能服务而豁免合同，也不跨入口尝试 |
| Key 发现/价格包含 default 之外的有效合同模型 | 正确返回；不从原生 Key 候选出发而漏项 |
| Key 发现/价格遇到未列模型、全候选不可用或读取故障 | 未列及不可用不作为有效报价；读取故障明确失败，不能伪装为空或全量原生 |
| 同模型有效合同组合存在多个成交倍率 | 展示适用价格差异/范围，不把最低价或第一条报价当作固定成交价 |
| 全站目录、会话未选合同、会话显式选合同、Key 合同明细 | 各自符合第 6 节身份口径，完整合同约定与实际可用性不混淆 |

后端用确定性测试覆盖真实请求、路由与资金不变量，使用 `require`/`assert`。先跑受影响的最小
测试集合，再按触及范围扩展到 middleware、service、model、controller 和计费边界；不把历史测试
名称或原“忽略合同渠道”断言直接当成新行为正确。需要替换旧断言，并保留无合同原生行为回归。
数据库新增查询/迁移同时验证 SQLite、MySQL、PostgreSQL；无环境时明确记为未验证。
涉及 `relaykit/` 时另跑 `GOWORK=off go build ./...`，根模块通过不能替代独立模块验证。

文档修改执行 `task docs:check` 与 `task ai:check`；如实施涉及公开 API 文档，另执行
`cd web && bun run docs:validate`。前端变更按实际范围运行 Bun 检查，并先加载适用前端与 i18n 规范。

## 实施顺序、风险与剩余事项

1. 复核最新代码及未提交改动，列出单组选择器、亲和、pin、后解析模型、类型化入口、公开投影与资金
   接线。先证明 D1—D5 的最小接法：完整候选的权重分布、用户权限筛选、重试开关、各计费形式
   的发送前价格刷新及资金动作。未能证明时不能将“代码已有类似函数”当作该行为已具备。
2. 按第 7 节建立 ADR 取代关系并更新唯一合同专题规范，明确这是本地合同的范围政策改变；
   在实现和验收完成前保留清晰的待实施状态。
3. 实现合同状态与范围解析，接入首选、亲和、重试、新派生请求和类型化约束；使用同一范围政策
   驱动模型/价格投影，并校正实际组进入预扣与结算的路径。
4. 更新管理提示、Key 明细与旧行为测试，执行上述行为矩阵，分别记录本地、数据库及真实环境结果。
5. 升级前只读盘点所有启用合同的模型、组合、折扣与绑定 Key，列出已失效组合、未列模型流量、
   用户组权限冲突、跨组重试开关、停用后 Key 原生范围及跨组价格差异；不得静默修正合同、修改
   开关或自动放宽权限。私有合同组不在用户可用组中的存量记录须先按 D1 完成配置治理。
6. 发布时避免新旧路由语义实例混用。上线验收核对实际渠道、组、折扣、预扣和结算；旧版本回滚会
   恢复纯折扣语义，可能再次越出业务约定范围，不能将代码回滚默认描述成安全止血。

主要风险：存量 Key 可能依赖合同未列模型，实施后这类请求会被拒绝；跨组选择可能改变成交组倍率；
合同停用或解绑按用户明确选择会恢复更宽的原生范围，管理界面应清楚表达该后果；亲和、重试及延迟
模型解析路径若遗漏约束，会重新出现渠道越界。D1 会使无用户组权限的已保存规则不可执行，D2 会使
现有非 auto Key 无法在失败后跨组尝试；这些是本方案明确采用的限制，不得到部署时才解释。
原生文件接线是未来上游合并的重点复核面。

历史图片折扣为 1 的核查独立进行：对照日志真实字段、精确合同版本、审计前后折扣和实际组倍率，
先确认事实与差额，再处理补偿决策。本方案不授权自动退款、改写历史账单或重算在途任务。

## 逻辑自洽复核

按“状态与权限 → 有效候选 → 首选/重试 → 资金 → 展示 → 生命周期”复核。本节是对方案文字的
推演，不替代运行时代码测试；实现与验证证据另列于文末。

| 边界/反例 | 决策依据 | 流程与验收结论 |
| --- | --- | --- |
| default Key 能否使用合同其他组 | 已确认 Key 范围规则 + D1 | Key 选路组被合同替代，用户组权限仍保留；有权限可用，无权限明确拒绝，无相互冲突 |
| 首次跨组是否必然允许重试跨组 | 已确认首次竞争 + D2 | 首次候选为全体有效组合；重试关闭时限定首次组，开启时可跨合同组；两个阶段明确区分 |
| 全候选失效是否等于合同停用 | 失败语义表 | 不等于；前者失败关闭，只有明确停用或解绑才进入原生路径 |
| 已有历史任务是否豁免新的派生请求 | D3 | 同一任务延续保留冻结事实；新提交重新授权，渠道锁定冲突即拒绝；没有同时适用两种相反规则 |
| 模型被执行面拒绝却仍被 Key 通告 | D4 | Key 发现/报价使用有效范围；全站目录及完整合同明细有明确不同用途，不作为 Key 调用资格承诺 |
| 类型化渠道无 Ability 是否失效 | 类型化入口规则 | 使用自身事实验证，合同只是进一步限制；自身可用也不能绕过合同 |
| 先按组抽样是否等价于扁平权重 | 候选编排规则 | 不等价；禁止以组为抽样单位改变概率，完整候选语义必须有确定性验证 |
| 换到贵组是否沿用旧预扣/产生两笔消费 | D5 | 发送前刷新价格并在同一会话补差，低估转高估和免费转付费有明确路径；信任和各资金策略不混淆 |
| 方案与 ADR-0019 是否同时生效 | 文档状态 + 第 7 节 | 已建立 ADR-0020 取代关系，不将旧禁止条款与新范围政策同时作为有效规范 |

复核结论：上述设计选择下，未发现决策表、失败语义、执行步骤、计费规则与验收矩阵之间的未解释
矛盾。D1—D5 是本次实施采用的明确选择。候选、计价、生命周期与投影的本地证据见下节；
外部数据库、真实 Provider 与账单及灰度仍须单独验证，不能将文档自洽等同于上线验收通过。
