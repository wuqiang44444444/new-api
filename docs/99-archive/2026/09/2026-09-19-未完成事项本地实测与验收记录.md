# 未完成事项本地实测与验收记录

## 问题与目标

逐项核对 [80 目录未完成事项汇总](../50-planning/2026-09-19-80目录未完成事项汇总.md)，实际执行本地
可完成的数据库、导出、存储、邮件、账单页面和回归测试。用户授权本地测试，并单独明确授权发送一封

### 本地历史审计与真实 4xx

- 对本地 SQLite 使用一致性备份生成临时副本，在副本上执行 `repair-task-billing-logs` 的
  `-hold-plan` 只读模式。得到 66 个候选、0 个已应用、548 个未解决：其中 27 个缺少唯一已转移钱包
  hold，521 个初始记录数量不为一。未使用 `-apply`，未改本地或生产资金。
- 该结果仅重放本地候选，不构成生产 66 笔执行依据，不能解释全部历史残差。
- Gemini Lite 实际向本地网关提交两次合成请求：模型 `gemini-3.1-flash-lite-image`、`n=1`、
  `response_format=b64_json`，尺寸分别为 `2048x2048` 与 `auto`。两次均在合同/模型访问检查处返回
  `403 model_not_found`，没有到达 Google，不能由此判断尺寸校验或上游账号状态。
- 两次请求分别只产生一条 `error_events`，模块 relay、类型 api_error、状态 403。实际持久化通过，
  原因仍是 unclassified；不据此宣称所有 dashboard/插件错误原因分类已经完成。
- 换用其他测试 Key 继续 Lite 请求的动作最初被自动审批拒绝，理由是合同拒绝后更换凭据可能绕过
  访问限制。用户随后明确授权使用正常允许模型的现有测试 Key，最多生成一张合成图片。
- 按该授权，使用未绑定合同且允许该模型的 Key 发送一次 `auto` 请求，Vertex 41 渠道返回 HTTP 200、
  一项图片结果，耗时约 5.86 秒。本地消费记录为 16,802 quota，输入 13 token、输出 1,120 token，
  计费模式 `tiered_expr`。没有修改合同/权限，也未额外重发。这一请求未复现 Google 403，不代表
  所有账号或渠道的风控状态已经解除。
- 采集脚本只解析 PNG 尺寸，此次未取得尺寸值，也未保留原始响应图片，所以实际像素仍未验收。
  不追加生成请求来突破一次授权数量；本地消费记录也不等同于 Google 正式账单核对。

## 优化方案

1. 保留静默窗口合并检查：已有冻结副本全量通过，但其他会话的后续 22 个文件改动尚未被本轮覆盖。
   前端 lint 失败另行处理，不写成“所有检查全绿”。
2. 将本轮已验证的 PostgreSQL 9.6、MySQL 5.7.44、ClickHouse、导出容量、对象存储往返、SMTP 收件
   和桌面账单实页结果回写汇总；精确 MySQL 5.7.8、生产三库并发/延迟、多实例灰度、OSS 恢复、
   存量证据密钥恢复、生产一致性副本审计保持未完成。
3. Vertex 41 的 Gemini Lite `auto` 单图请求已成功；实际像素、非正方形 auto、Gemini 24 生成/编辑、
   供应商账单仍未验收；
   `pkg/geminiimage/size.go` 唯一规则与架构逐模型档位表述已核对，不能替代真实 Provider 结果。
4. 合同模板、error_events 请求体保留/TTL、“无调用”状态、财务人工执行流程与历史金额裁决属于待
   实现或待决策事项，不能通过测试消除；保持原汇总跟进。
5. 已清理本轮创建的三个隔离数据库容器及其卷、含本地数据的临时 SQLite 审计副本和逐笔计划；保留
   脱敏测试日志。本轮未操作生产数据、未执行财务补正、未修改既有归档。
