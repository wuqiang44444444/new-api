# 图片视频连接探测运维口径与优化

> 代码与本次运行跟踪已完成；真实失败分支和页面验收仍待完成。后续验收统一见
> [80目录方案验收清单](../50-planning/2026-09-23-80目录方案验收清单.md)，本次跟踪结束不等于生产验收完成。

## 1. 问题与目标

本轮仅优化图片、视频及有媒体信号但目标不明确的自动检查。文本模型自动测试的请求、计费前置校验、
超时阈值、渠道启停、响应时间及日志展示均保持原状；手工单项与批量测试保持原状。

管理员需要判断连接是否有响应，不应把探测请求不适用误读为客户的图片或视频生成失败。媒体自动检查
禁止调用生成接口，也不能退回 Chat；使用已确认的只读操作，没有适用探针时明确显示未验证。
不实施重复告警聚合、次数累计或新状态机，不修改真实渠道配置。

原优化方案在本轮开发过程中已被工作区的文档整理移动归档。本文件记录随后确认的范围与实施，
不修改既有归档。早期记录中将本轮范围扩大为所有自动任务的表述无效，以本节为准。

## 3. 优化方案

### 3.1 执行边界

- 复用原生图片模型识别和模型映射，补齐普通 OpenAI/Azure 的 GPT Image 目标。Seedance 名称信号
  只用于保守阻止自动生成，不赋予 Link 身份、路由或履约资格。
- 普通 OpenAI 媒体目标使用已有模型发现操作的 `GET /v1/models`，复用密钥、Header override、代理
  与连接设置；新探针有 10 秒总时限，不跟随重定向，不解析或持久化模型列表内容（最多丢弃 1 KB 响应体），不依赖客户余额或价格。
- Seedance 专用渠道保持已有素材只读探针，不能以素材端点结果证明视频生成；Azure Batch 不属于本次
  改造范围，维持原有检查。其余媒体协议没有适用只读接口时，连接记为不支持/未验证；
  已有适用图片配置校验的渠道继续做本地诊断，原生视频任务适配器不使用 Chat 样例伪造配置校验。
  Kling/Vidu/Sora/Doubao/Jimeng/Midjourney 等没有适用探针的分支显示连接未验证、配置未检查，
  不将其归为配置通过，也不为补齐展示而新增配置检查流程。
- 无适用探针但配置通过不计作连接成功；价格、协议等配置失败继续显示。已有媒体端点但目标存在歧义时
  明确提示目标待确认，不能发送 Chat。没有媒体信号的文本渠道维持既有行为。
- 媒体连接结果不自动启用/禁用生成渠道，不覆盖生成响应时间；不得修改密钥轮询位置、预扣资金或创建任务。

### 3.2 运维展示

- 列表与详情直接标出自动连接探测/自动配置检查及“非客户业务请求”，有明确依据时显示图片/视频类别。
  旧媒体事件有 `generation_probe` 时标为“自动生成探测（历史记录）”；缺少检查范围时标为
  “历史自动探测”，不推断曾发送生成请求。不改写数据库，也不把旧事件伪装成新只读检查；
  文本与手工日志展示不变。
- 收到 HTTP 响应说明响应节点可达，不等于生成可用：401/403 为认证或权限异常，429 为限流，5xx 为
  服务或网关异常。404/405 为当前探针路径或方法不适用，保留任务结果，不作为业务失败刷入错误日志。
- 新只读探针不解析 Provider 正文，400 统一显示“已收到响应，探测请求被拒绝”。历史媒体事件
  （无检查范围或 `generation_probe`）保留已记录的上游 `model_not_supported` 错误码解释，显示
  “探测请求不适用”；该错误码经原生错误转换透传，确有真实历史记录，不能视为不可达分支。
  已有失败响应可作连通证据，不能故意发可能触发生成的请求来获取这种证据。
- 本地错误显示请求未发送；有网络失败证据才显示连接异常；没有证据时显示连接未验证。原始 HTTP 状态保留。

### 3.3 实施约束与验证

核心逻辑放在自动检查扩展文件中。原生测试入口只保留既有窄接线，不改正式 Relay、Provider 生成实现、
渠道保存或数据库结构；日志列表/详情仅增加媒体自动事件组件接线。此举限制未来上游合并的冲突范围。

验证覆盖媒体无生成 POST、别名映射、歧义目标、404/405/401/403/429/5xx、网络失败、禁止重定向、
渠道及密钥状态不变、结果持久化、中英文列表与详情，以及文本自动测试和手工测试不变。
仅使用本地模拟服务和临时数据库；真实 Provider、只读接口可用性和账单不得据此宣称已验收。
