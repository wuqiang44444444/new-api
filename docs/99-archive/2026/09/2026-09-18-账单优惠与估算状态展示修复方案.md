# 账单优惠与估算状态展示修复方案

## 问题与目标

“我的账单”的最终折扣使用破折号，估算原价和估算优惠使用“无法展示”，没有说明是无优惠、
历史事实缺失还是估算失败。修复客户及管理员单客户账单、优惠组合与下载文件的解释一致性，
保留已入账消费、退款与净额，不重新计价。

## 当前实际情况

- 首轮分析时的旧实现：没有合同因子且没有明确未适用标记时，合同状态为 unknown；组合内任一
  非零金额行缺少可解释的折扣事实，该组合原价和优惠均为空，前端统一显示“无法展示”。
- 原版本在未命中合同时没有记录状态；当前工作区已有明确写入未适用的修复。本次复用该入口，
  不补写旧日志、不使用当前合同或倍率猜测历史。
- “历史价格不可用”计数还包含附加费、不可读/冲突事实及估算金额越界，名称过于狭窄。
- 截图提示 12 条不能替代数据库核验；本次未确认这些记录的实际来源或目标服务运行版本。
- 工作区已有其他任务修改；本次仅修改账单解释相关文件，不覆盖既有实现与归档文件。

## 优化方案

### 状态与文案

| 条件 | 展示 |
| --- | --- |
| 已确认无合同优惠 | 合同列显示“无合同优惠”；最终倍率仍包含已知分组倍率 |
| 最终倍率为 1 | “无折扣（×1）”；可估算且优惠为零时金额显示 0 |
| 历史没有合同记录 | 合同列“未记录”；只按分组倍率计算最终折扣、原价和优惠 |
| 合同有记录但信息残缺，或缺少分组倍率 | “无法估算”并直接说明缺失字段；最终折扣显示“未知”及原因 |
| 含不可拆分附加费 | “无法估算：附加费明细不足” |
| 历史计费记录不可读/冲突 | “估算失败：计费记录异常” |
| 估算结果超出可表示范围 | “估算失败：金额超出范围” |
| 超过组合明细上限的汇总行 | 明确说明“合并明细不足”，不冒充历史数据缺失 |

### 实现边界

1. 在现有只读账单解析边界统一生成安全原因码，去重稳定排序；模型、API Key、账单与折扣组合
   汇总保留原因。读取逻辑共用此判定，不建立第二套计价算法。
2. 复用账单现有表格与金额组件，空金额展示明确状态及原因；净额继续显示事实金额。顶部提示
   改为“无法完成原价与优惠估算”，不把所有原因称为缺价格。中英文使用 i18n 技能脚本维护。
3. 汇总和明细 CSV 增加估算原因字段，数值列未知保持空白，已知零保留零；升级字段版本防止
   自动复用旧格式。既有固化文件不改写；缺少新原因的历史版本显示“历史账单未记录估算原因”。
4. 不修改原生计费执行、资金、数据库结构、当前折扣配置或真实历史记录。本次涉及的后端文件
   均为本地账单/导出扩展，前端复用已存在的账单入口，无新增原生热路径接线。

### 验证与风险

- 先增加页面回归复现空金额原因不明，再实现并验证中英文、无折扣、缺失合同、缺失分组、异常
  记录、附加费、越界、组合汇总与零金额；已知/未知混合时不能用部分总额冒充完整估算。
- 后端确定性测试覆盖同一记录在组合、模型、API Key、账单和导出中的一致原因及净额不变。
- 执行相关 Go/Bun 测试、前端类型检查与改动文件 lint、i18n 同步、文档和 AI 规范检查。
- 不新增数据库查询或迁移；真实账单、生产运行版本与外部数据库验收保持未完成，不声称线上
  提示已经消失或所有历史记录能够恢复估算。

## 实施与验证记录

### 已完成的本地修复

- 新增 `model/billing_statement_estimate.go` 作为只读原因判定入口：缺少历史合同状态、缺少分组倍率、
  计费记录异常、附加费明细不足分别返回安全原因码；估算转换越界与组合明细上限分别记录独立原因。
  原因在模型、API Key、账单及组合中去重、稳定排序，不使用已知部分金额代替完整金额。
- 账单金额卡、优惠组合、API Key 汇总及模型原价改为显式解释；最终倍率为 1 显示“无折扣（×1）”，
  不能确定的最终倍率显示“未知”及原因。原价/优惠已知为零时保留零；零扣款模型和明细导出与已有
  组合的零金额口径一致。所有消费、退款、净额与资金写入入口不变。
- 顶部质量提示改为“无法完成原价与优惠估算”，保留既有 API 计数字段，避免破坏调用方。
  页面没有新增通用 UI 或交互封装，继续使用现有 Table/Card，原因文字就近展示并允许换行。
- 汇总与明细 CSV 字段版本升级到 5，新增估算未完成原因列，按导出时冻结语言输出中英文解释。
  固化版本制品同样使用其冻结语言；已有制品不重写。API 投影保存原因码，CSV 输出客户可读文字。
- 版本投影保存并恢复原因；按模型筛选后重新汇总原因，不残留被过滤模型的异常。
  旧固化版本没有原因字段时，页面明确提示“历史账单未记录原因”，不从现价或配置推断原因。
- 已沿用现有无合同优惠写入修复，不另建合同状态来源，不补写截图涉及的历史日志。

## 用户口径修正：历史无合同记录按分组倍率估算

本节取代上文“缺少历史合同状态就阻止估算”的方案。用户明确要求：合同列“合同优惠：未记录”
简化为“未记录”；历史没有合同优惠时，仅按分组倍率计算最终折扣、原价与优惠，有合同再叠乘。

实施时将“没有合同记录”和“存在不完整/冲突合同信息”分开：前者在只读投影中使用
`contract_applicable=unrecorded`，合同列保持未记录，计算合同因子为 1；后者继续 unknown，
不把已记录但损坏的合同当作没有合同。显式无合同仍为 no，已知合同倍率仍为 yes。
汇总、组合、明细、导出共享同一解析；退款可继承已验证原预扣合同事实，缺失记录本身不构成
与原预扣的冲突。原始日志和实际净额不变，不读取当前配置，不改写已有固化账单。

本轮验证覆盖：无合同字段且分组倍率为 1/0.5、有合同叠乘、退款负号、残缺合同及矛盾记录、
中英文简短文案及明细/导出一致性。当前事实文档同步修正该口径；导出字段版本递增以避免复用旧估算。


### 口径修正实施与验证结果

- 已完成只读合同状态区分及所有账单聚合、折扣组合、明细与 CSV 的统一计算。历史无合同记录
  不再产生 missing_contract 原因，不再阻止完整汇总；组倍率 1 时原价等于净额、优惠为 0。
- 合同列复用现有中英文“Not recorded / 未记录”翻译。版本差异及账单专属日志明细同步识别
  unrecorded；有明确合同信息但缺少倍率、无效合同倍率与相互矛盾的证据仍保留异常状态。
- 导出字段版本升为 6，避免自动复用按旧口径估算的文件；已确认版本及历史文件不改写。
- model 全量测试通过；service/controller 账单、导出、费用解释相关回归通过；前端账单与使用
  日志 48 个文件、330 个用例通过；类型检查、改动文件 lint、docs:check、ai:check、差异检查通过。
- 原有“缺失合同字段必须阻止估算”的测试改为验证分组估算；保留并新增残缺/矛盾合同的回归。
  表达式费用解释额外验证：无合同记录时使用组倍率核对已入账金额，金额不吻合时不伪造分项等式，
  表达式执行器与资金路径未修改。
- 未部署或改写生产数据；上述是代码与本地回归结果。

## 同页其它同类展示修复

用户进一步要求检查同页其它位置。本轮检查确认：金额卡、优惠组合总计、API Key 汇总已共用后端
上一轮修正后的估算；不能在前端用当前配置补算旧响应。另有模型行“优惠”列显示倍率而父行显示
金额、模型汇总 CSV 优惠为空、倍率为 1 重复显示的问题，需要继续修复。

实施范围：模型行与 CSV 的优惠统一为估算金额，列名统一“估算优惠”；后台从已知估算原价与净额
相减得到模型优惠，保持未知为空并检查范围。旧固化版本可从已冻结原价与净额作同一算术投影，不
重新定价、不改写制品。分组及合同倍率等于 1 时只显示一次。增加整页无合同数据和模型优惠测试，
检查汇总卡、总计、分组、模型与 CSV 的一致性。版本差异页没有合同倍率时使用明确无合同/未记录
标签，避免把没有合同优惠误称为无法展示。实际扣款不变。


### 同页修复完成与验证

- 模型行的“估算优惠”改为金额，后端增加模型级 discount_quota；按已知原价减净额计算，
  未知保持空、已知零显示零、退款保留负号。减法使用十进制并检查 int64 表示范围，不发生整数回绕。
- 金额卡、组合总计、API Key、模型五处通过同页回归验证：无合同且组倍率 1 时均显示正常原价与
  零优惠，不再因未记录合同产生未知。分组和合同倍率 1 及加价倍率只显示一次。
- 模型 CSV 优惠列同步补齐；字段版本升至 7，避免复用之前缺少模型优惠的文件。旧固化投影仅用
  已冻结金额派生模型优惠，不读取当前价格、不修改已有固化记录或制品。
- 版本比较的无合同倍率使用“未记录/不适用”标签；当前余额读不到时说明“客户记录不存在，
  无法读取当前余额”，不以零或笼统的“无法展示”代替。
- 修复前两项页面回归失败，修复后通过。model 全量测试、service 账单/导出相关回归通过；
  前端账单 16 个文件、90 个用例通过，类型检查、改动文件 lint、i18n 同步、差异检查通过。
  docs:check 与 ai:check 通过。现有 Table/Card 等组件继续复用，没有新增通用交互实现。
- 未部署或读取生产数据。截图中仍为旧文案的原因不能仅靠图片确定；本次不声称目标运行服务已更新。
