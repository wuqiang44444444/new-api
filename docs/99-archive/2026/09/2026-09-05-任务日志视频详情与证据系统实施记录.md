# 任务日志视频详情与证据系统实施记录

对应方案：[任务日志视频详情分析与修复方案](2026-09-05-任务日志视频详情分析与修复方案.md)。
本文记录已实施内容、覆盖矩阵与原生文件接线清单；二期路径未实施，不宣称全量覆盖。

## 1. 已实施内容

### 详情独立交付（方案 §3）

- `TaskClientRequestSnapshot` 新增 `resolution`/`ratio`/`generate_audio`（指针布尔区分显式
  false 与缺失），由 `attachTaskProtocolSnapshot` 在创建时从统一北向合同冻结。
- 新增 `dto/task_video_details.go` 与 `controller/task_video_details.go`：从客户请求快照
  （request）、计费探针（billing）、结算事实（settlement）三来源投影 `video_details`，
  缺失即"未记录"，不从当前配置推断历史。
- `TaskRootInfo` 新增 `upstream_request_id`/`video_upstream_protocol`/
  `southbound_adapter_version`，仍仅 Root 投影；`channel_id`/`quota` 既有口径不变。
- 前端详情弹窗新增"视频结果"（复用产物查询/播放器/重试，含打开、复制链接、下载）与
  "视频参数"区域；成功无结果显示明确文案而非 `-`；i18n 七语言补齐。

### 证据一期（方案 §6.8 闸门 1-2）

- 新增模型 `TaskRequestEvidence` / `TaskRequestEvidenceEvent` / `TaskRequestEvidenceAccessLog`
  （三库兼容，均已注册 AutoMigrate）。
- 新增加密对象存储（AES-256-GCM，本地独立命名空间，接口化预留 S3）；启动期由
  `TASK_REQUEST_EVIDENCE_*` 环境变量装配，默认开启（`TASK_REQUEST_EVIDENCE_ENABLED=false`
  显式关闭），加密密钥未配置时从 CRYPTO_SECRET/SESSION_SECRET 派生并输出告警。
- 采集核心：北向会话建立（同步持久化，失败在 hold 前拒绝）、南向发送前持久化
  （位于 `MarkTaskCreateAttemptUpstreamStarted` 之前）、响应体有界边转发捕获（发送后故障
  只告警标记）、轮询追加、结果交付字节统计。脱敏在采集时单向执行（凭据占位、
  `max_tokens` 保留）。
- 查询：管理员列表/详情（脱敏预览、签名 URL 遮盖），Root 原始对象下载；逐次访问审计。
- 保留期清理系统任务（`RetentionDays>0` 时启用）。
- 测试：脱敏规则（含 `max_tokens` 保留）、存储加密回读、南向快照重放契约、超限拒绝、
  响应捕获转发、签名遮盖；§3 投影与角色分级测试。
- 端到端契约测试（`service/task_request_evidence_integration_test.go`）：真实 sqlite +
  真实加密存储 + 假 Provider HTTP 回环，覆盖北向脱敏采集 → 南向最终正文 → 响应有界捕获 →
  任务关联 → 权限视图，以及存储不可用/正文超限的发送前拒绝。
- 进程级实测：真实启动服务（sqlite + CRYPTO_SECRET），完成初始化、渠道/令牌配置、
  真实 `/v1/audio/speech` 中继（假 Provider），验证三阶段事件落库、磁盘密文、
  `Authorization` 头 `[REDACTED]`、Root 原始对象下载与访问审计（view/download）。

## 2. 原生/既有文件接线清单

| 文件 | 接线 | 必要性与替代方案 | 合并冲突面 |
| --- | --- | --- | --- |
| `relay/channel/api_request.go` | `doRequest` 内 2 处窄调用（南向采集、响应包装） | 共享发送点是唯一能按"每次出站尝试"采集的位置；无不改原生的替代点（既有 `MarkTaskCreateAttemptUpstreamStarted` 同址） | 2 行级调用，冲突面极小 |
| `relay/relay_task.go` | DoRequest 错误分支增加证据哨兵判断（3 行） | 区分"未发送的本地拒绝"与"发送后未知"，复用既有释放路径；替代方案需改 attempt 状态机，侵入更大 | 1 个 if 分支 |
| `controller/relay.go` | 入口建立证据（约 6 行）+ 落库后关联（2 行） | 覆盖全部任务类入口（含 Responses 桥）的最小公共点 | 与本仓库既有 Link 接线同区 |
| `relay/audio_handler.go` | 入口建立证据（1 个 if） | TTS/转写/翻译唯一入口 | 1 处窄调用 |
| `service/task_polling.go` | 批量/单任务两个正文读取点 + 错误路径（约 8 行） | 轮询正文在 task_polling 读取，此处是 adapter 解析前的公共点；替代方案需侵入各 adaptor，点多面大 | 行级调用 |
| `controller/video_proxy.go` / `video_proxy_link.go` | 交付统计（各约 4 行） | io.Copy 是唯一实际写出点 | 行级调用 |
| `model/main.go` / `model/system_task.go` | 注册 3 张表 + 1 个系统任务类型常量 | 惯例注册点 | 常量追加 1 行 |
| `router/api-router.go` | 3 条查询路由 | 惯例注册点 | 独立分组块 |

## 4. 待验证与未完成

- 未连接真实 Provider、未做生产灰度与真实页面验收；attempt 注入失败用例
  （方案 §6.7 末项）与崩溃窗口时序测试待下一轮实施。
- 实测中发现并修复：音频等无任务路径 `RelayInfo.TaskRelayInfo` 为 nil 时，
  南向采集访问经嵌入指针提升的 `info.ClientProtocol` 会空指针崩溃。
  已在最窄边界补回归测试
  `TestEvidenceCaptureSouthboundNilTaskRelayInfo`，并经变异验证
  （移除守卫 → 测试复现同一 panic；恢复 → 通过）。全量扫尾确认这是唯一
  无调用方保证的提升字段访问：`ChannelType`/`ChannelId`/`ChannelOtherSettings`
  经 `*ChannelMeta` 提升，由 doRequest 调用点的 `InitChannelMeta` 合同保证非空。
- 保留周期、存储容量数字是显式部署决策，当前默认值不构成合同。
- 崩溃窗口语义保持原状（unknown），不凭证据缺失自动处置。
