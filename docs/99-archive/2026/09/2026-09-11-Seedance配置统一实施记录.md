# Seedance 配置统一实施记录

## 1. 问题与目标

按[独立插件迁移方案](2026-09-09-Seedance独立插件迁移方案.md)实施 U0—U5。Provider 配置定义与
南向转换进入同一个 `seedance-link`；Channel 继续拥有配置实例、模型映射与凭据，Task 和资金继续
使用宿主已有事实与事务。本文记录代码交付及剩余工作，不代替架构合同或生产验收。

对象存储和临时 URL 签发不进入 JS。表格以代码支持为准，不表示每条线路已完成真实验收。

### 2.3 配置唯一来源与实例值

- `channelConfiguration` 声明视频模型、公开模型参数、素材配对、Project/Region 规则、凭据槽位、
  素材操作/媒体、组策略及管理默认 TTL。编译拒绝未知字段、非法类型、重复模型、缺少 hook 和无效配对。
- 前端读取 `/api/channel/seedance/configuration` 的不可变版本快照；声明失败时阻止保存，不退回旧
  Provider 表。管理请求只提交现有实例值及非持久化 `seedance_plugin_version`。
- Channel 模型、映射、地址、代理、`other` 中素材配置、额外 AK/SK 与默认素材组继续由原有存储拥有。
  插件不保存渠道实例，不接触凭据，不写原生 Ability；公开元数据不暴露 Provider 身份。
- Channel 最终保存/启用事务与插件激活、重新启用、自动晋升共同校验版本和全部现有渠道兼容性。
  PostgreSQL 首次发布使用事务 advisory lock；MySQL 使用索引 UPDATE 锁；SQLite 使用写事务。
- TTL 管理默认值为默认建议，不成为业务最小值；合法正数按原值保存。发布和请求不自动补写配置。
- [共享版本存储](../../pkg/seedanceplugin/store.go)供视频与素材使用。请求首次读取声明/hook 时固定同一
  编译制品，转换结果在 hold 前缓存；后续不因 active 变化混用版本。

### 2.4 行为与历史履约

新视频创建只通过插件，未登记或退役协议拒绝新请求。宿主保持统一北向验证、计费输入校验、
`TaskCreateAttempt`、资金 hold、可信任务 ID 和 Task 原子落地。unknown 不自动重发或退款；
托管图片在既有冻结/归属校验后由宿主签发 URL，临时签名与密钥不进入 JS。

公开参数投影消费插件声明，已删除生产 Go 公开参数表的回退。多数旧视频创建与远端素材转换已移到
`*_legacy_test.go`，仅用于等价回归。仍有执行依赖的旧 Go 轮询、响应和内容处理保留给精确冻结历史
Task；原始 API v1 测试制品保留原源码，不用修改新制品版本号伪造历史。

## 3. 优化方案、原生接线与同步影响

| 文件/边界 | 必要性与最小接线 | 上游同步影响 |
| --- | --- | --- |
| `model/channel.go` | 一个 `gorm:"-"` 输入版本字段，传到原管理事务 | 不新增数据库列；仅结构体一行 |
| `controller/channel_authz.go` | 将版本字段纳入普通渠道管理权限分类 | 一项分类，不授予敏感字段权限 |
| `controller/channel.go` | Seedance 输入版本预校验 | 窄调用，最终校验仍在写事务 |
| `model/task_plugin.go` | 发布/启用/删除晋升真实事务入口加锁和兼容校验 | 多个必要窄接线；不是仅 Controller 预检 |
| `constant/channel.go` | 专用类型常量移至新增 `constant/seedance_channel.go` | 移除本地常量插入，降低原生枚举修改面 |
| `router/channel-router.go` | ChannelRead 管理投影入口 | 已有本地渠道 Router 增加一条路由 |
| `pkg/jsplugin/seedance_*`、`pkg/seedanceplugin/` | 有限本地合同、编译和版本解析 | 新文件隔离，不扩展原生候选资格 |
| Channel/素材专属文件与前端 | 消费声明替代各 Provider 配置表 | 保持原生 Channel、字段、权限及提交方式 |

`model/channel_asset_credential_storage.go`、`model/channel_model_mapping.go` 单独放置既有存储与精确
映射逻辑，使配置合同重放无需拉入无关图像或素材服务。未重构原生 Provider adapter、分发或计费公式。

### 4.2 上游补丁重放

1. [配置合同重放脚本](../../scripts/seedance-replay-configuration.py)从固定上游提交导出，加入实际新增
   配置文件和必要依赖，仅在上游 Channel/TaskPlugin 的对应事务位置接入生产同款窄调用。
   上游完整 `model` 与 `pkg/jsplugin` 测试通过；无需覆盖本地业务目录。
2. [运行时重放脚本](../../scripts/seedance-replay-runtime.py)将既有 Link 宿主基线与本次迁移补丁分开：
   上游至本地 HEAD 的既有后端底座为 1110 个路径，本次选定迁移变化为 140 个路径。
   两份补丁均通过 `git apply --check`，记录逐文件 hash 与依赖清单后独立应用。
   本次补丁 SHA256 为 `c18cc15b6f0f439d84a717de396580db83537bf99cab5cf401194e9c18f50d37`。
   隔离环境中的 model、controller、service、middleware、jsplugin、publicmodel、plugins 与全部
   Seedance 子包的 12 个相关包回归全部通过。

第一项证明配置扩展可在固定上游独立接线；第二项验证在明确既有 Link 底座之上重放当前迁移。
第二项是"重建当前实现"验收，不是合并兼容性验收：它先用 upstream→本地 HEAD 的全量差异恢复本地树，
不能证明保留上游独立新增后的合并结果。真正的三方合并演练按
[评审问题修复方案](2026-09-11-Seedance插件迁移评审问题修复方案.md) R7 在隔离环境执行后再计入 U4。
两项均未覆盖未来尚未获取的上游提交，前端由本工作区构建验证。
