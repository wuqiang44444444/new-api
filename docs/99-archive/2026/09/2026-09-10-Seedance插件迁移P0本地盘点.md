# Seedance 插件迁移 P0 本地盘点

本文是[插件迁移 P1P2 实施记录](2026-09-09-Seedance插件迁移P1P2实施记录.md)对应方案 §8.1 的
P0 本地部分：对本地快照库重新生成脱敏渠道/模型/价格矩阵，并给出数据迁移判定。
**这是本地快照结论，不等于生产矩阵导出**；生产导出须在生产库上用同一工具重新执行。

## 1. 工具与脱敏边界

盘点工具为 `cmd/seedance-p0-inventory`（本批新增）：以只读方式打开 SQLite 快照，
不查询密钥列，不输出 Base URL、代理、Provider Project/Region、素材 ID 或 Task 私有数据。
模型名、渠道 ID、分组名按方案 §8.1 属于受保护内部清单允许记录的字段。

```bash
go run ./cmd/seedance-p0-inventory -dsn <sqlite 快照文件>
```

本轮数据源：本地快照 `one-api.db.bak0909`（2026-09-09 14:58，integrity_check 通过）。

## 3. 特殊记录（有待处理项的线路不进入切换批次）

- **渠道 92（启用）`seedance-2.0-cmcc` 无任何定价条目**：mode/expr/ModelPrice/ModelRatio 均无，
  请求会以 `model_price_error` 失败关闭（不会错计费，但线路不可服务）。切换前必须补价格。
- `happyhorse-1.1-i2v` 配置了 tiered 模式但无表达式（原生侧模型，非 Link 线路，独立待办）。
- 无渠道引用的 Seedance 命名价格条目：`seedance-2-0-oversea`、`seedance-2-0-oversea-key`、
  `seedance-byteplus`、`dreamina-seedance-2-0-260128`、`live-hosted-mini-20260908`
  （模型倍率/预扣残留，未自动清理，仅记录）。
- 客户合同覆盖 5 个 Link 模型（渠道 81 线路的 4 个模型 + `seedance-2.0-cmcc`）；
  渠道 81 线路切换时按合同折扣路径单独核对（结算链已有回归覆盖）。
- 跨原生/Link 价格键冲突：**无**（36 个 Link 模型与全部原生渠道模型零交集）。

## 4. 存量事实与数据迁移判定

- tasks(62)：SUCCESS+settled 27 条、FAILURE+settled 4 条，**无任何未决任务**——
  满足方案 §7.3"迁移前优先排空本批活动任务"，无需单列 unknown/awaiting_usage/debt。
- task_create_attempts：complete 453 / rejected 19 / released_with_exposure 3 / unknown 164；
  其中 feicai 19 条（complete 4、unknown 15）全部产生于插件迁移之前，冻结快照不含插件身份，
  不构成 seedance-link 版本删除保护引用，也不需要回填。
- task_plugins：**空表**。seedance-link 1.0.1 由运行时 sync 循环在首次启动自动 seed，
  无需任何手工 SQL 或数据搬迁。
- channel_default_asset_groups 6 行（含停用渠道 97 的保留行），停用保留语义按既有设计，零改动。

**数据迁移判定：本批不需要数据迁移。** 依据：零 schema 变更（插件身份复用既有 JSON 列）、
插件行自动 seed、存量任务全 settled 无回填对象、渠道/租户/价格零改义（方案 §5.3/§7.3）。
平台既有的 `migration.*_v1` 一次性迁移标记模式本批不新增条目。

## 5. 本轮已完成并记录的非实机验证

- **三库实机**：新增 env 门控测试
  `model/task_plugin_seedance_lock_cross_database_test.go`
  （`TEST_SEEDANCE_PLUGIN_MYSQL_DSN` / `TEST_SEEDANCE_PLUGIN_POSTGRES_DSN`，
  拒绝非空库，用后删表），在真实 PostgreSQL 16 与 MySQL 8.0 上验证版本锁并发互斥
  （受理先提交→删除被拒；删除先提交→受理失败关闭）、依赖查询在服务器 SQL 上的
  终态/未决/冻结身份语义——两库全部通过。SQLite 路径由既有套件覆盖。
- **容量基线（本机）**：新增 `plugin_extension_bench_test.go`（手工运行，非 CI 断言），
  本机（10 核）实测：冷编译 ≈1.03ms/571KB/8317 allocs（每进程每版本一次）；热 buildCreate
  ≈77µs/85KB/941 allocs；热观察解析 ≈13µs/16KB/226 allocs；并发 8 信号量 10 调用方超订
  ≈17 万次观察/秒聚合吞吐，无准入超时，槽位全部释放。默认 2s 准入与 8 并发相对现有
  创建/轮询速率有几个数量级余量；§8.3 的多节点与素材叠加压测仍待真实环境。
