# 图片中转编辑南向适配实施方案

## 1. 问题与目标

为图片中转的 `funcloud_aigc_v2`、`moxing_images_v1` 补齐标准图片编辑南向履约，复用已有
Gemini/Vertex 图片服务的公共输入合同、同步/异步入口、对象存储和资金底座。

本方案只覆盖 Gemini、Vertex、FunCloud、Moxing 四类。前两类作为已实现链路的回归基线，
后两类为新增编辑适配目标；不扩展其它原生 Provider，不修改 Seedance 视频或素材代理合同。

**目标同时支持两种调用形式：**

| 客户形式 | 请求入口 | 成功语义 | FunCloud 南向执行 | Moxing 南向执行 |
| --- | --- | --- | --- | --- |
| 同步 | `POST /v1/images/edits`，不带 Prefer | 等待完成后返回 200 和图片结果 | 本次请求内创建并轮询 | 单次调用 `/v1/images/generations`，携带 image |
| 异步 | 同一入口，`Prefer: respond-async` | 202 和平台任务 ID；再查询 `GET /v1/tasks/{id}` | worker 创建并轮询，冻结 Provider task ID | worker 单次请求，结果进入 OSS |

这是一项目标方案，不是当前生产支持声明。只有逐模型完成接口、图片效果、存储和计费验收，
才能发布该模型的对应操作；同步还须具备适用的失败/超时计费证据。Moxing 的南向即使为同步接口，
也不妨碍平台用现有 worker 提供北向异步形式。

### 2.2 已验证的代码事实

- 图片中转的协议选择唯一入口为 `relay/channel/imagerelay/adaptor.go`，登记的南向协议只有
  `funcloud_aigc_v2`、`moxing_images_v1`；不新增渠道类型、客户模型别名或第二套分发逻辑。
- FunCloud `ConvertImageRequest` 限定 ImagesGenerations，拒绝 `image/images`，并明确以输入图
  计费未验证为由拒绝 `extra_fields.reference_images`；其当前 payload 没有参考图字段。
- Moxing 同样限定 ImagesGenerations，拒绝参考图字段，payload 固定 `capability=image_generation`。
- `service.ParseImageContract` 已有 Edit 操作、JSON `image/images`、multipart、输入数量与字节预算。
- Gemini/Vertex 已将标准输入转换为 `generateContent` 的 `inlineData/fileData`；Imagen 不在
  该编辑支持范围内。
- `relay/image_async.go` 在受理前调用同一 Provider 转换校验；worker 再调用同一适配器。
  只删除同步入口的拒绝条件，不能完成异步编辑。
- 异步输入暂存已支持：字节写 `images/tasks/{id}/input-N`，HTTPS URL 保存在受保护执行快照；
  worker 当前将存储字节重建为 Data URL。仅接受 URL 的 Provider 需要专门的南向输入准备步骤，
  不能把当前重建出的 Data URL 不经确认直接发送。

## 3. 优化方案

### 3.1 P0：逐模型合同与剩余证据

必须为以下六个 Provider 模型分别填完证据表，不因同属一个协议就推定能力一致：

| 协议 | Provider 模型 | 保持的输出规格 | 文档确认的参考图限制与转换 |
| --- | --- | --- | --- |
| FunCloud | nano-banana-2-lite | 单一分辨率，不传 resolution/outputFormat | 1–10 张；imageUrls；JPEG/PNG/WebP，Provider 30 MB/张 |
| FunCloud | nano-banana-2 | 1K | 1–14 张；imageUrls；JPEG/PNG/WebP，Provider 30 MB/张 |
| FunCloud | seedream-5.0-lite | 2K/basic | 1–14 张；imageUrls + genType=i2i；JPEG/PNG/WebP，Provider 10 MB/张 |
| FunCloud | seedream-5.0-pro | 1K/basic | 1–10 张；imageUrls + genType=i2i；JPEG/PNG/WebP，Provider 10 MB/张 |
| Moxing | doubao-seedream-5-0-260128 | 2K 单图 | 1–14 张；单图 image 字符串，多图 image 数组；URL/Data URL |
| Moxing | doubao-seedream-5-0-pro-260628 | 2K 单图 | 1–10 张；单图 image 字符串，多图 image 数组；URL/Data URL |

Moxing 文档列单图 ≤30 MB、像素数 ≤6000×6000、宽高均 >14px、宽高比 [1/16,16]。
本地字节仍受公共 20 MiB/张和 50 MiB/请求预算约束，FunCloud Seedream 另外采用不超过文档
10 MB 的保守字节上限。URL 输入不新增回源探测，无法本地验证的尺寸/格式由 Provider 校验；
公开元数据必须区分本地已验证限制与来源 URL 的调用方责任。首批测试使用 JPEG/PNG/WebP；
Moxing 其它文档格式不扩大公共解析器已有支持范围。

每行须确认：编辑是否存在；创建路径、方法、鉴权；参考图准确字段及顺序；URL/Data URL/文件接受方式；
数量、字节、像素、格式和 URL 有效期要求；尺寸与编辑类型；任务查询和结果形状；明确失败、超时与
审核拒绝是否收费；输入图如何计价，终态提供哪些用量字段。

FunCloud 编辑继续调用 `/api/v2/open/aigc/{provider_model}`，Nano Banana 两模型通过 imageUrls
进入编辑，Seedream 两模型设置 genType=i2i；文生图保持现有 t2i 行为。
Moxing 编辑继续调用 `/v1/images/generations`，capability **保持 image_generation**，增加 image。
客户 images 数组只转换为这一个南向字段，不同时发送 image/reference_images，也不透传任意 extra。

Moxing 文档另有 `/v1/media/generations` + `/v1/media/tasks/{id}` 的南向异步接口。
本期不切换到该接口：既有 `moxing_images_v1` 保持同步南向，由平台 worker 提供北向异步，避免为 Edit
引入新 Provider 任务解析/恢复合同。未来若需要增强 Moxing 可重查恢复，另立明确范围，不在运行时 fallback。

对于供应商确实不支持 Edit 的模型，保持代码登记为不支持，返回明确错误；不降级成文生图、
不换模型、不过滤参考图后继续生成。平台结构可支持两种执行形式，不意味着六个模型必然都具备编辑能力。

### 3.2 P1：统一北向输入，保持 Provider 差异在南向

1. 同步/异步共用 `/v1/images/edits`，模型通过既有 `model_mapping` 解析，不新增客户协议。
2. 统一接受 JSON `images: [Data URL 或 HTTPS URL]`、单图 `image`，以及 multipart `image/image[]`；
   复用解析器的互斥、格式、20 MiB/张、50 MiB/请求和 14 张总体预算。
3. Provider 更小的数量/规格限制必须经 P0 确认，由当前代码模型登记表达，运行时与公开投影共同读取；
   不从模型名称临时猜测，不新增管理员编写的字段映射或 capability JSON。
4. 输入顺序不可改变。`n=1` 继续作为图片中转当前边界；图数为零、超限、无效图片、未发布字段在
   南向业务请求前拒绝。mask、透明背景、流式等不因本次 Edit 自动开放。
5. `reference_images` 等 Provider 私有参数不成为新的北向透传入口；客户始终使用标准 `image/images`。
6. 编辑校验分为无副作用的合同/计费校验与必要的输入准备。异步受理前的合同校验不能上传到 Provider、
   生成短期 Provider 输入 URL 或创建任务；同步解析不得遗漏 multipart 文件。

### 3.3 P2：FunCloud 编辑适配

- 在 `relay/channel/asyncimage/` 新增局部图片编辑实现与测试，标准参考图统一转换为 imageUrls；
  Nano Banana 由有图进入编辑，Seedream 明确设置 genType=i2i。
- `ConvertImageRequest` 按操作接受已发布 Edit，复用现有 generations 的模型与规格校验；仅移除被
  本次已验证输入替代的拒绝逻辑，保留其它未发布字段的明确错误。
- 文生图与图生图使用明确的协议转换；若上游要求操作标志，由 adapter 设置，客户不提供私有标志。
- 同步仍复用本次请求内轮询，后台模式仍复用现有 headless 创建/轮询和任务 ID 冻结；不得各写一套
  编辑字段转换。恢复只能查已取得的 Provider task ID，不能因输入 URL 过期而重新创建。
- 转换输出、Provider 接受参考图和返回结果三段均须验收；只得到 HTTP 200 或 task ID 不算完成。

### 3.4 P3：Moxing 编辑适配

- 在 `relay/channel/moxingimage/` 新增局部编辑实现与测试，路径仍为 images/generations，
  capability 仍为 image_generation，单图 image 为字符串，多图为数组；请求类型需保持标量/数组语义。
- 不复用墨行视频、TokenSave 海外视频或 Seedance 素材 API 来托管图片输入。
- Lite/Pro 分别登记编辑支持与限制；当前固定 2K、单图输出作为回归基线，不擅自扩大模型规格。
- 同步调用和 worker 调用共用转换及结果归一，保留“零有效结果即失败”的边界。
- 若上游只提供单次同步返回，平台异步 worker 只发送一次；无可查 Provider ID 的不明结果保持待核实，
  不生成伪 ID，不宣称支持重查恢复，不自动重发。

### 3.5 参考图与 OSS

采用现有 `imageObjectStore`，不建立客户素材表、素材组、公共文件 ID 或第二套上传服务。

| 输入形态 | 同步 | 异步 |
| --- | --- | --- |
| 客户 HTTPS URL | 按已验证 Provider 合同传递，不主动下载探测；需明确在处理期间保持可读 | 使用既有受保护快照保存来源，发送时检查可确认的失效条件；URL 过期不得重生成 |
| Data URL / multipart 字节，Provider 接受 inline | 从统一解析结果直接转换，不强制上传 OSS | 先按现有流程存私有输入对象，worker 读出并按 Provider inline 格式转换 |
| Data URL / multipart 字节，Provider 只接受 URL | 经存储健康检查后写临时私有输入对象，为南向签发可用时限的 URL | 重用 `input-N` 对象，发送前签发 URL，不保存签名串为事实 |

FunCloud 文档只有 URL 输入，没有 inline 证据，因此字节参考图必须走 URL-only 分支；
Moxing 文档明确接受 Data URL，同步字节直接内联，异步读取既有输入对象后内联，不新增第二次输入上传。
输入签名有效期按 Provider 最晚取图时间、排队/执行预算和容错余量制定并验证；**不能复用结果链接
固定 300 秒的 TTL**。输入签名不返回客户、不进入普通日志；过期续签只发生在尚未发送业务请求时，
不得由此重新发送已受理生成。对象位置与存储配置绑定使用现有会话机制。

同步结果维持当前两类中转的 URL 输出基线；Provider URL 不自动视为已上传平台 OSS。
异步结果下载并保存平台 OSS，经授权查询签发 300 秒 URL；既有支持的 `b64_json` 按现有查询合同读取。
本次不把同步 b64 转换、同步强制结果托管和永久结果链接作为 Edit 上线前置需求。
存储失败不伪报图片可交付；异步只恢复存储/查询，不补生成。临时输入与结果由存储生命周期清理。

### 3.6 计费、安全与恢复

Pro 本地客户价按用户授权采用火山官网标准；其它文档报价仅作为核实与测试向量。客户价与供应商采购折扣独立：

| 编辑模型与本期规格 | 文档计价依据 | 实施结论 |
| --- | --- | --- |
| FunCloud Nano Banana 2 / 1K | t2i/i2i 均为 0.0672 USD/输出张；折扣另列 | 先核实是否无输入图附加费，再复用正确的按张价格 |
| FunCloud Nano Banana 2 Lite | t2i/i2i 均为 0.0336 USD/输出张 | 同上 |
| FunCloud Seedream Lite / 2K | t2i/i2i 0.0324 USD/输出张 | 本期只保留 2K；4K/3K 资料差异不带入本期扩规格 |
| FunCloud Seedream Pro / 1K | i2i 输出 0.045 USD/张，另列输入 0.003 USD/张 | 本地客户价采用官网普通单图公式；1K 输出为 0.30 CNY/张，输入首张免费；采购价歧义另行核对 |
| Moxing Lite / 2K | t2i/i2i 均为 0.22 CNY/输出张 | 核实无输入图附加费；按部署已有币种转换约定配置客户价，不硬编码新汇率 |
| Moxing Pro / 2K | 文档大图输出 0.60 CNY/张，输入 0.02 CNY/张 | 官网已确认 261 万像素分界；本期 2K 输出客户价为 0.60 CNY/张，输入附加费为 0.02×max(输入张数−1, 0) CNY |

Pro 的输入张数是计费事实，不能通过 `images` 的 JSON 文本长度估算。应在统一解析后产生已验证张数，
映射到现有请求探针并冻结；定义具体探针前先核对 `billingexpr` 支持，不臆造表达式函数。
Moxing 的 `usage.output_tokens` 与 `usage.input_images` 应按可信含义保留，不能因为存在 Token 字段
就把按张价格套入 Token 公式。Pro 客户价按官网普通单图公式计算：输出张价之和 + 0.02×max(输入张数−1, 0) CNY；预扣与结算都冻结有效汇率和输入张数。增加 0/1/2 张输入及 261 万像素分界测试。供应商采购价仍单独核对，不以官网客户价冒充实际成本。

- 执行前读取并遵循 `pkg/billingexpr/expr.md`；价格仍由现有模型价格/表达式作为唯一事实源。
- 逐模型确认输入图是免费、按张还是按 Token 收费，不沿用文生图固定价作为未验证的编辑价格。
  不把图片数量当成图片 Token，也不从视频报价反推图片费率。
- 若需新请求计费探针，仅在现有计费入口增加必要事实，并冻结操作、输入数/规格及价格；不得在 adapter
  硬编码第二套扣费规则。按 Token 计费捕获可信输入/输出分项，避免 `p/c` 与 `img/img_o` 重复计费。
- 同步预扣/结算与异步预扣/结算分别追踪，不能以一方通过替代另一方。当前路线图中的 FunCloud
  图片用量和结算缺口，若影响本次编辑收费，必须一并解决后验收。
- 所有乘数有界，使用 checked quota 转换及既有饱和审计。模型无价格时执行前失败，不自动开启自用模式。
- 异步保持现有 Task 接受、容量槽、资金 hold、幂等键绑定的原子事务；SENDING 持久提交后才发送。
  查询、结果与恢复按 user+app 隔离，按冻结 Channel/协议/连接/价格履约。
- 异步已发送结果未知不重发、不换渠道、不自动退款；明确失败走幂等结算/退款。平台客户费用与
  Provider exposure 分账，未知 Provider 金额保持未知。
- 同步沿用当前已发布协议的生命周期，不暗改为 202 或持久 Task；若新编辑操作缺少能够支持同步
  失败/超时语义的 Provider 账单证据，该模型同步 Edit 暂不发布。不得仅为满足“双模式”而自动重试。
