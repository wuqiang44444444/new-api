# 图片交付预检与大图完整性修复记录

## 目标与范围

修复复审中的三个根因：实际渠道初始化前的错误预检、同步格式交付对已生成大图的固定阈值丢弃、
账单事实投影对原生前端通用解析文件的入侵。保持 Provider 调用、计费与现有平台 Task 的唯一职责。

## 实施

- 预扣前用原生渠道上下文初始化预检副本；图片每次执行前复检，覆盖渠道切换与映射变化。
- 显式同步 JSON 响应用私有临时文件承载，字段按文件区间索引；Base64 解码与编码、URL 下载、
  S3/Azure 上传均通过文件或流，原始响应直到交付完成才释放。取消 50 MiB/512 MiB 的同步交付拒绝。
- 只对结果下载、同对象键上传和签名重试，最多三次且共用原有总预算。仍失败时返回明确 502，
  `data` 保留原结果，`requested_response_format` 说明目标格式；客户可从失败正文救回图片。
  不静默返回与请求格式不同的成功响应，不自动重发生成或再次结算，不新增 Task/账本/后台恢复。
- 文件上传复用现有对象存储实例，将导出已有 S3/Azure 文件上传实现在本地新增文件中共用；导出的
  公开内部接口保持原样，图片与导出的诊断阶段分别保留。
- 前端账单投影移至 `statement-log-facts.ts`，`format.ts` 只保留 import 与一次调用。

## 原生接线必要性与同步影响

- `relay/image_handler.go`：每次选渠后预检、建立/关闭交付载体和错误返回是必须保留的接线；
  生成后转换及结算顺序沿用已审核入口。业务实现放在 `relay/image_delivery*.go`，不改 Provider adapter。
- `web/src/features/usage-logs/lib/format.ts`：通用解析只调用独立账单投影。没有增加消费方分叉。
- Controller 原有首次预检接线继续保留。未来上游合并只需复核这些窄接线与 ResponseWriter 契约。

## 验证

- `relay/...`、Controller、Service、Model 全量相关回归通过；初次新增下载用例缺少 HTTP 客户端
  初始化，修正夹具后 relay 全包及最终图片契约回归通过。
- 新增行为测试覆盖无映射 GPT Image、Azure、Gemini/Vertex 存储不可用时零上游调用且资金不变；
  实际 ImageHelper 入口在选渠变化后复检；超过原 50 MiB 的双向格式转换；超过原 512 MiB 的完整结果；
  图片 SHA-256 与长度完全一致；交付失败原图保留；同结果重试成功；JSON 转义与未知元数据保持；
  null、空字符串及非字符串不能伪装为成功图片。
- 账单解释与下载测试 2 个文件、15 项通过；测试夹具补齐工作区月账单版本新增的空版本缓存键。
  前端类型检查、变更文件 lint、前端生产构建通过。
- 后端 `go build ./...` 在前端构建完成后通过；文档结构、AI 规范、公开文档与目标差异检查通过。
- 上述网络测试使用本机模拟 Provider 和对象存储，不发送真实生成或付费请求。

## 验证边界

本轮为本地实现与自动回归，不宣称真实 Provider、外部数据库、生产存储或灰度验收完成。
文件处理只约束新增同步交付层内存；原生 adapter 的协议处理仍由原生实现负责。临时文件不是持久恢复
事实，断连未收到正文或 Provider URL 过期时不能保证救回；需要断连后可查询的调用使用既有显式 Task。

## 评审修复与验收跟踪（本轮）

状态：预检、文件中转与交付失败不重生成已有本地回归，评审未要求新增交付框架。

Provider、对象存储和最大图片容量仍需目标环境验证。本轮未重新执行收费调用，不把本地测试表述为
全渠道生产验收；已有失败记录继续保留。

后续本地基础设施验收已验证配置的 Azure Blob 小对象及 1,440,000 字节合成导出文件的完整往返与清理，
同时记录 30/90 秒下载超时；这不替代最大图片容量、Provider 图像或生产网络验收。
参见[剩余项与本地基础设施验收](2026-09-17-评审剩余项修复与本地基础设施验收.md)。
