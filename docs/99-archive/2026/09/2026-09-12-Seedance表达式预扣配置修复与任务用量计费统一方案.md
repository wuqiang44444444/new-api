# Seedance 表达式预扣配置修复与任务用量计费统一方案

## 1. 问题与目标

用户反馈管理端模型表达式定价无法再配置预扣上限，并询问是否应向 NEWAPI 新增的任务用量表达式
`u()` 靠拢。本文按用户要求写入 `80-dev`，作为本次问题的完整分析与待实施方案。

本方案有两个独立交付目标：

1. 修复 Seedance 定价编辑器选择错误，恢复异步 Token 预扣上限的读取、编辑、保存和缺失提示。
2. 在保留 Seedance 北向、资金及历史事实的前提下，统一使用 NEWAPI 已有任务用量表达式引擎、用量
   类型和价格编辑能力，减少本地重复计价逻辑。迁移必须覆盖完整生命周期，不以替换变量名作为完成。

两项按依赖独立开发与验证；按用户随后明确的直接上线诉求，本次默认合成一个完整发布包，不要求
运营先使用旧规则再进行第二轮配置。开发分步不等于线上双轨。第二项必须先完成等价性验证和资金路径适配。本文不是已批准的架构事实，
不授权生产变更，不表示已完成迁移、Provider 验收或账单验证。

### 1.1 范围

- 包含：Seedance Link 客户模型定价元数据、表达式编辑、预扣估计、快照、终态用量、补查、结算、
  退款、合同折扣、价格展示、配置迁移和上游同步成本验证。
- 覆盖现有全部允许新受理的 Seedance 视频协议；具体清单在实施盘点时从类型化协议登记导出，
  不在本文另造固定模型白名单。已退休协议不重新开放。
- 普通文本模型继续使用 `p`、`c` 等既有 Token 表达式；原生任务插件继续使用上游自己的用量合同。
- 不修改客户 ModelArk V3 请求形状、ChannelType、模型映射、素材租户或路由资格；不迁移原生
  Doubao 渠道，不改变 Azure Batch、异步图片或原生视频合同。
- 不把 Provider 成本、用户合同折扣、工具费、违规费写进模型价格表达式；不建设第二个账本、
  表达式引擎、资源表或插件平台。

### 1.2 权威资料与关系

- [硬约束](../00-context/硬约束.md)：原生最小入侵、Link 身份、资金与历史冻结事实的约束。
- [表达式引擎设计](../../pkg/billingexpr/expr.md)：语言、变量、任务美元换算和版本的权威。
- [计费表达式与协议探针架构](../20-architecture/账单计费-计费表达式与协议探针架构.md)：当前 Seedance 合同。
- [异步任务与计费事实架构](../20-architecture/账单计费-异步任务与计费事实架构.md)：当前资金生命周期。
- [用户模型合同定价架构](../20-architecture/账单计费-用户模型合同定价架构.md)：客户合同折扣的权威。
- [Seedance 独立插件迁移方案](2026-09-09-Seedance独立插件迁移方案.md)：插件配置与南向履约迁移；

## 2. 当前实际情况

请求日志或真实 Provider 账单，也未重新拉取远端，不能把本地历史说成上游最新状态。

不是上游废弃 `c`，也不是所有模型都需要迁移。

### 2.2 根因链

```text
Seedance 客户模型或其映射命中原生插件模型索引
  → 管理价格接口返回原生 usage_schema
  → 面板优先使用该 schema，覆盖公开价格接口已做的 Seedance 隔离
  → 打开 TaskUsagePricingEditor
  → c / param("_task.*") 表达式显示在 u() 编辑器里
  → 预扣上限输入和缺失警告都不挂载
  → 后端继续要求原有预扣配置，新模型无法通过界面补齐
```

截图中的 `u("resolution")`、`u("tokens")`、`u("video_input")` 提示与现有 `c`、`_task` 表达式并存，
与该代码分支吻合。这里的“混用”指 UI 合同选择错误，不代表保存的表达式文本必然已经混写两套变量。

影响范围是返回任务 schema 的模型，不能据截图断言所有表达式模型都受影响。既有预扣值仍有
初始化、草稿提交和保存路径，字段消失不等于数据库已删除该值；线上是否发生配置丢失需另行核对。

### 2.3 两种表达式的差别

| 维度 | 当前 Seedance | 原生任务用量 |
| --- | --- | --- |
| 用量 | `c` 表示可计费 Token | `u("tokens")` 等声明过的字段 |
| 条件 | `param("_task.resolution")` 等受控探针 | `u("resolution")` 等声明字段 |
| 表达式结果 | 经宿主 `/ 1000000` 后得到美元 | 表达式直接得到美元 |
| 预扣 | 模型配置的 Token 预算及冻结请求条件 | 提交阶段提取的用量 facts |
| 成功缺用量 | 按现有 Seedance 合同等待、补查、转运营 | 通用合并可保留提交估计；不能直接当作 Seedance 的真实用量 |

两种方式都复用 `pkg/billingexpr`。`tiered_expr` 仍是定价模式；`u()` 不是一个替代所有 Token 表达式的
新语言版本。不得把语法 `v1:`、价格模式、金额单位和任务生命周期合并成一个开关。

## 3. 优化方案与关键决策

### 3.1 推荐方案

采用“先修复入口，再统一表达式求值与用量合同，保持宿主资金职责”的路线：

1. 当前阶段使管理、公开展示、保存校验与运行时对同一客户模型的计费归属一致。
2. 目标阶段 Seedance 也使用上游 `u()`、类型化 usage schema 与美元求值；通用引擎不增加
   Seedance 语法，不在运行时把旧表达式即时翻译成新表达式。
3. Provider 插件负责南向数据提取；Go 宿主校验可信度，持有 Token 预算、attempt hold、任务资金
   状态、合同折扣、补查和结算幂等。插件无权定义余额、冻结金额或直接退款。
4. 新受理只有一种 Seedance 计费合同。全量切换前停止 Seedance 新受理，并完成旧任务资金处理，
   避免长期双读双写和按表达式文本选择两套后端。

### 3.2 不采用的方式

| 方式 | 不采用原因 |
| --- | --- |
| 只在错误编辑器里补输入框 | 根因仍在；变量、预览、默认表达式和保存校验继续不一致 |
| 只把 `c` 改为 `u("tokens")` | 金额单位、预扣来源、缺失用量和资金生命周期没有迁移 |
| 直接替换成通用 JS TaskAdaptor | 会连带影响北向协议、执行版本、attempt 和资金归属 |
| 两种新受理长期并行，失败后回退 | 引入第二套计费合同，无法证明单一费用权威 |
| 根据模型名或表达式包含 `_task` 推断身份 | 身份必须来自 Seedance 类型和已选协议；文本只用于表达式合法性检查 |
| 缺预算时填零或默认大值 | 掩盖配置问题，改变实际预扣；预算应明确且有界 |

### 3.3 切换前的否决条件

任何一项不满足时，只交付入口修复，停止计费切换：

- 无法在最小修改面内分离任务金额求值方式与资金生命周期归属。
- 有模型表达式无法完成语义、单位和最终整数 quota 等价验证。
- 有 `unknown` attempt、未完成任务、待用量补查、欠费或未完成退款/补偿，无法完成存量资金处理。
- 当前协议的可信用量、默认条件或价格档缺少证据。
- 新实现仅增加翻译层和并行判断，没有明确删除的本地重复计价代码。
- 三数据库、原生合同回归、多节点切换或真实 Provider/账单验收不完整。

## 4. 第一阶段：恢复管理端预扣配置

### 4.1 后端元数据归属修复

管理价格快照必须复用现有按 ChannelType 与精确客户模型判断的 Seedance 归属事实，不能仅凭
`generation.GetByModel` 或模型映射赋予原生用量合同。

- Seedance Link：当前返回其既有表达式配置，不返回会使 UI 进入原生任务编辑器的 schema。
- 原生任务模型及其有效原生 alias：继续返回原生 schema。
- 普通模型：继续原生 Token 定价语义。
- 原生和 Seedance 配置存在同名合同冲突：管理端与公开端一致报告冲突并阻止编辑/保存，
  不以其中一类覆盖另一类。
- 禁用 Seedance、尚未定价模型、客户别名与 Provider 模型重名均纳入验证；不通过价格是否存在推断身份。

若现有归属查询需要抽取，只隔离复用稳定的类型化归属事实，不为 UI 新增独立判断表、模型缓存或配置源。
本次管理快照请求一次加载全部 Seedance Link 渠道，按精确客户模型构建请求内归属集合，覆盖启用与
禁用配置；循环生成模型条目时复用该集合，不退化为每模型查询。请求内临时集合是数据库事实的投影，
不属于禁止新增的持久判断表或跨请求模型缓存。
修复模型价格接口、模型详情内嵌编辑器及窄屏抽屉，避免只修截图中的桌面入口。

### 4.2 编辑与保存行为

- 恢复旧 Seedance 编辑器中预扣输入；清楚标注“预扣 Token 预算”，不称为 Provider 接受上限、
  实际扣费封顶或余额授信上限。
- 读取并保留已配置值；表达式编辑、模型切换、价格同步预览不应清空预算。
- 正整数范围复用后端 `MaxTaskPreConsumeTokens`；空值表示管理员主动清空，不能把非法输入转换为空。
- 补充脏状态跟踪，验证仅改预扣时保存按钮、离开提示和提交路径正常；当前 `onDirtyChange` 对预算
  的覆盖不足应一并在真实入口验证，不能只断言内部 state。
- 当前表达式保存校验与预算要求遵循现有协议规则，包括已登记的纯参数表达式例外。
- 保存失败保留草稿；并发价格变更沿用 `expected_version` 冲突机制，不能覆盖另一管理员的修改。
- 不自动将普通倍率模式改为表达式；`requires tiered_expr billing` 应作为单独配置项检查。

### 4.3 第一阶段退出标准

真实管理接口数据经过页面父组件传入面板后，Seedance 仍能修改预算并保存、重新打开取得同值；原生
任务编辑器行为不变。完成第 11 节 A 组测试即可进入后续集成；本次上线默认交付最终统一版本。

## 5. 第二阶段：目标用量合同与单一权威

### 5.1 数据流

```text
管理员价格配置
  → 类型化 Seedance 归属 + 当前已选协议的计费字段定义
  → 表达式编译、用量字段及预算校验
  → 唯一模型价格存储

客户请求
  → 类型化入口、唯一 Channel、固定协议/插件版本
  → 受控请求事实 + 明确 Token 预算
  → u() 表达式求值为美元 + 原有组倍率/合同折扣 + quota 转换
  → 冻结快照、durable attempt 与资金 hold
  → Provider POST
  → 可信 Provider task ID 后原子创建 Task 并转移 hold
  → 可信终态用量覆盖获准的用量字段
  → 同一表达式重新求值 → 幂等应用资金目标/补查/退款
```

### 5.2 计费元数据

目标 schema 仅描述当前代码/插件协议已承诺的计费字段。它不描述逐模型路由资格，不复活 capability、
SKU、publication 或 implementation 合同。

- 先使用现有 `UsageFieldSchema`、类型、单位和枚举定义，不另建平行 schema。
- Seedance schema 从已经选定且冻结的协议取得；不得把 Provider 模型登记注入通用全局模型索引。
- 编辑、公开价格、表达式保存验证、预扣提取和终态验证消费同一字段定义。
- 现有 Seedance 扩展编译器拒绝原生顶层 `usageSchema`，因此不能直接往插件顶层添加该字段。
  本次不新增插件 ABI 或发布格式：由已有 Go 宿主计费探针字段定义形成唯一计费字段描述，复用
  `UsageFieldSchema` 类型，并使用已固定的协议配置约束有效字段/可选枚举。管理端、保存与执行
  读取该描述；现有探针负责取值，不能为 schema 再实现一套 Provider 解析或模型支持表。
  合并当前散落的字段类型/验证描述时，替换原调用方并删除重复定义，不增加第二份 Go/JS 字段合同。
- 宿主的数值上界、可信用量校验和资金策略不可由插件版本任意放宽。
- 前端通过明确的计费编辑上下文区分“字段定义”与“预算是否必需”；不能继续把有 schema 等同于
  “无需预算”。优先扩展现有管理价格响应，不新建价格接口或单独预算服务。

### 5.3 字段映射建议

以下是迁移目标字段的建议命名。实施时在协议层一次固定；不是允许客户端新增这些请求字段。

| 旧表达式来源 | 目标表达式字段 | 类型/单位 | 提交与完成策略 |
| --- | --- | --- | --- |
| `c` | `u("tokens")` | number/token | 提交为管理员预算；完成仅以可信实际 Token 替换 |
| `_task.resolution` | `u("resolution")` | string/协议枚举 | 冻结规范化请求条件，不被任意上游值覆盖 |
| `_task.has_video_input` | `u("has_video_input")` | boolean | 由结构化视频输入产生；图片和音频不算视频输入 |
| `_task.duration_seconds` | `u("duration_seconds")` | number/second | 首次迁移保持既有冻结语义，不能顺便改为上游实际时长 |
| `_task.generate_audio` | `u("generate_audio")` | boolean | 保留显式 false、协议默认值及条件生效语义 |
| `_task.input_mode`、`_task.control_mode` | 同名 `u()` 字段 | string/协议枚举 | 冻结，不允许客户通过私有价格参数覆盖 |
| 协议专属 ratio/billing_mode 等 | 同名且仅该协议声明 | 明确类型/单位 | 先盘点实际依赖，不升级为全局必填字段 |

若未来需要按“实际生成秒数”结算，应使用含义明确的实测字段，并另行评审客户价格合同；不能在
本次迁移中改变 `duration_seconds` 的既有含义。仍被使用的历史专属字段先做等价转换；无依赖后才删除。

### 5.4 估计事实、冻结条件与真实用量

三类事实必须分开处理，即使它们最终都通过 `u()` 读取：

1. 估计事实：创建前的 Token 预算，只为预扣提供数量。
2. 冻结条件：分辨率、输入类型、请求时长、声音等客户价格条件。
3. 真实用量：完成时已通过协议校验、可用于结算的 Token。

复用现有完成用量“是否报告”及可信来源标记，不能根据合并后的 `UsageFacts` 中有 `tokens` 就断定
已有实际用量。缺少最终 `tokens` 时，提交预算仍存在也必须进入等待用量流程。

完成 facts 只能覆盖 schema 中明确允许的实测字段；不能沿通用 map 合并覆盖冻结价格条件。
本次实测客户计量限定为已有的 `tokens`；其他字段保持冻结请求条件。该固定来源规则放入 Seedance
唯一字段描述，复用 `ActualUsageReported`、`ActualTokens` 和既有用量来源字段，不扩展为通用多计量
来源框架，不再建立一份公共业务状态。

### 5.5 表达式依赖与等待条件

2026-09-12 补充代码核对：[RequiresUsage](../../pkg/billingexpr/usage_dependencies.go) 当前将任何
`u()` 调用都视为依赖用量。这是通用表达式依赖判断，不能直接承担迁移后 Seedance 的“是否必须
等待 Provider 实际 Token”判断，否则只读取分辨率或冻结时长的表达式也会错误进入补查。

目标是在 Seedance 已冻结字段合同上区分以下含义，不全局改写原生 `RequiresUsage` 的行为：

| 表达式依赖 | 数据来源 | 是否要求完成时报告实际用量 |
| --- | --- | --- |
| `u("tokens")` | 创建时为预算，完成时为可信实测 Token | 是；预算不能满足该要求 |
| `u("resolution")` | 创建时冻结的请求事实 | 否 |
| `u("duration_seconds")` | 当前合同中冻结的请求计费时长 | 否；不顺便改为实测时长 |
| `u("has_video_input")`、`u("generate_audio")` | 受控请求及协议默认值 | 否 |
| 将来明确发布的实测字段 | 对应协议的可信完成事实 | 另行定义；不在本次凭字段名称推断 |

实现时复用引擎 AST 字段依赖提取，在 Seedance 专属边界将依赖集合与冻结字段来源相交，形成所需
实测字段集合。来源和覆盖规则来自 §5.2 的唯一合同，不能在保存、轮询和退款处各维护一份字段表。
该集合即使被缓存或写入快照，也只是冻结表达式与字段合同的确定性派生值，不是管理员可配置的第二合同。

首次迁移对表达式中的静态字段依赖作保守分析，包括各条件分支；不根据一次求值未执行某分支就
临时免除预算或等待要求。未知字段、未定义来源或无法证明的动态 `u()` 键在保存/受理前拒绝。
预算是否必须配置仍受 §6.1 的既有协议规则约束，不把“无需等待实测”自动等同于“无需预算”。

等待判定必须贯穿成功终态、后台补查和最终资金写入校验。特别是
[资金目标保护](../../model/task_seedance_billing_facts.go) 的 `enforceSeedanceBillingTarget`，必须与
[结算入口](../../service/task_tiered_settle.go)、[用量等待入口](../../service/task_seedance_usage.go)
使用同一依赖规则。仅在 UI 或轮询层放宽判断会留下数据库入口不一致。

同批切换检查按消费者列明，不以固定的“五处”代替影响范围：

| 消费者 | 本次责任 |
| --- | --- |
| `relay/helper/task_tiered_price.go:36` | Seedance 预扣依赖读取本节规则，同时保留既有协议预算要求；合法非 Seedance 调用保持原行为 |
| `service/task_tiered_settle.go:44` | 成功结算只等待表达式真正需要的可信实测 |
| `service/task_seedance_usage.go:19` | 补查与结算使用相同等待条件 |
| `model/task_seedance_billing_facts.go:180` | 资金目标写入在事务内执行同一规则，不能绕过实测要求 |
| `cmd/seedance-p0-inventory/main.go:197、204` | 盘点复用同一依赖含义，并先纠正 §7.1 的价格键回退问题 |
| Seedance 表达式保存校验及其管理调用入口 | 字段、静态依赖与预算校验同批生效，不能出现可保存但不可受理的配置 |

以上行号为审查时定位；实现时重新搜索消费者。四个 Seedance 运行时位置、盘点工具和保存校验
必须在同一候选版本通过联合验收。`relay/helper/image_relay_billing.go:36` 保持原生语义，
`pkg/billingexpr/usage_dependencies.go` 不作全局改写。

## 6. 第三阶段：预扣、资金与历史快照

### 6.1 预扣策略

- 继续使用 `task_billing_setting.preconsume_tokens[customer_model]`，不新增并行配置键。
- 依赖 `u("tokens")` 的新 Seedance 表达式要求有效预算。动态字段名若不能静态证明依赖和字段集合，
  保存时拒绝，不根据运行一次碰巧未读到 Token 就免除预算。
- 纯冻结参数表达式按现有协议已发布的例外处理；其他协议取消预算要求属于额外行为变更，不能
  随迁移自动放宽。各协议矩阵必须记录“当前要求”和“目标要求”，首次迁移原则上等价。
- 先完成请求数量/时长上界校验，再构造受控 facts；预算不替代北向数量、时长或用量可信度校验。
- 无有效预算时在资金 hold 和视频 POST 前拒绝；素材调用独立，不自动撤销已经创建的素材。
- 不在迁移中增加音视频探测、访问客户源 URL、自动时长测量或根据模型名推导估算器。

### 6.2 金额与折扣

目标路径计算：

```text
模型费用 USD = u() 表达式结果
客户费用 = 按现有顺序应用组倍率与冻结客户合同规则
quota = 按现有规则转换为整数内部额度
```

复用上游表达式引擎与项目既有安全 quota 转换，不直接复制通用插件示例中的 `cost * groupRatio`
代码：还须证明客户合同折扣、零费模型、资金来源、审计字段与原路径完全一致。

预扣和结算都使用相同冻结表达式、单位、组倍率和客户合同事实。Provider 金额未知仍为未知，
Provider exposure 与客户退款分账，不以 quota 反推供应商成本。

### 6.3 生命周期归属与 `TaskUsageBilling`

当前 `TaskUsageBilling` 不仅影响金额换算，还被用于判断原生任务与本地 AsyncBilling 的边界。
直接把它置为 true 会触发拒绝或跳过补偿。因此实施必须先完成以下拆分：

- 金额求值方式：复用现有任务用量快照标记及美元换算，不能另造求值引擎。
- 资金生命周期归属：依据既有冻结 Seedance 类型、平台和协议事实判断，不能仅凭该标记推断为
  原生任务，也不能根据当前 Channel 配置重新判断。
- 原生任务继续执行上游既有生命周期；其错误附加本地 AsyncBilling 的保护继续有效。
- Seedance 的资金写入仍只经现有 attempt/Task 原子资金目标入口，不能同时走通用增减 quota 分支。

优先在 Link 专属新增文件实现 Seedance 用量金额适配与生命周期接线。只有确需经过共享入口时保留
窄调用；不为统一而重写原生 `service/task_polling.go` 或全局改变原生任务缺用量行为。

必须审查所有 `TaskUsageBilling`、`HasTaskUsageBilling` 与 `rejectTaskUsageAsyncBilling` 的消费者，
包括数据库筛选、退款、账单分类和后台扫描。只改提交入口不算完成。B1 若证明需要扩大修改面，
必须在具体文件清单中说明原因、必要接线点和上游冲突成本，再进入实现。

#### 6.3.1 推荐解法：共用求值，保留资金状态机

“原生 u() 路径与 Seedance 不兼容”的准确含义是当前接线把金额单位与生命周期归属绑定在一起；
`u()` 引擎本身没有禁止补查或退款。推荐结构为：

```text
固定表达式 + 经过校验的 facts
  → NEWAPI 原生 u() 引擎：计算费用
  → 既有组倍率、客户合同与 quota 规则：计算资金目标
  → Seedance 现有 AsyncBilling：决定等待、结算、退款或补偿
  → 现有原子资金目标入口：唯一账本写入
```

这不是再造一套 Seedance u() 结算流程。复用现有状态、重试调度、可信用量合并、目标冻结和
`ApplyTaskBillingTarget` / `ApplyTaskBillingTargetWithExposure` 入口，只替换金额输入的构造与求值方式。
两个资金函数是同一既有事务边界下的不同业务操作，不得再调用通用直接增减额度路径。

`TaskUsageBilling` 保持其冻结金额单位语义，不改名、不增加同义标记，也不通过修改其值欺骗换算。
生命周期从既有冻结类型化身份推导；不新增管理员可编辑的生命周期选择、不从表达式语法推断归属。
原生任务仍走原生生命周期，原生任务误带 AsyncBilling 时的保护必须继续生效。

#### 6.3.2 接线顺序与必须覆盖的位置

本次接线决策已固定：Seedance 不实现通用 `TaskUsageFactsProvider`，也不为这次迁移新增替代接口；
沿既有 `ModelPriceHelperTaskTiered` 接线构造受控 Usage 输入，保留合同折扣、零费处理和资金来源。
完成求值继续落在 `settleTaskTieredSnapshot` 的同一次 `ComputeTieredQuotaWithRequest` 调用：
调整输入构造，金额单位由现有引擎按冻结 `TaskUsageBilling` 分派，不新增平行结算函数或宿主换算器。
`relay/relay_task.go` 与 `service/task_polling.go` 目标零新增修改；B1 核验这些决定的可实施性及
例外证据，不重新开放已排除的通用分支捷径。实际用量、预算与冻结条件继续使用 §15.4 的既有承载位置。

以下是本次已定位的修改责任清单；实现时仍须全仓搜索补齐消费者，不以表内文件穷尽影响范围。

| 位置 | 当前行为/缺口 | 目标责任 |
| --- | --- | --- |

| `cmd/seedance-p0-inventory` | 存在价格键回退与通用 RequiresUsage 调用 | B0 复用并修正现有工具；精确客户价格键、依赖规则及未完成资金盘点符合运行时 |

顺序为先明确冻结身份判定，再接入快照/扫描/保护，随后替换求值输入，最后验证唯一资金写入。
不能只将各处排除条件删除后依赖测试碰巧通过。

特别注意：[HasSeedanceBillingFacts](../../model/task_seedance_billing_facts.go) 当前要求 AsyncBilling
已经存在，不能直接用于“是否首次创建 AsyncBilling”的判断，否则形成循环条件。首次附加时使用
已有 RelayInfo 与即将冻结的类型化身份；任务恢复时读取持久快照。两处遵循同一归属规则，不查当前
Channel；尚未建立的新受理上下文缺必要事实时应在 hold 前拒绝。

预算误结算是错误接线风险，不是本次已证明的线上错账：当前结算函数对具有冻结 Seedance 身份的任务
先重读已接受事实，再令 `actualTokens = async.ActualTokens`，随后才执行正数推导报告标记。
仅在提交 UsageFacts 中存在预算不会自动越过这道事实重读。迁移必须防止预算被写入 ActualTokens、
绕过重读或落入通用 facts 合并路径；Seedance 是否报告仍以可信接受事实为准，明确零与未报告分别验收。

#### 6.3.3 从预扣到补查退款的确定性样例

以下采用合成单价 5 美元/百万 Token、组倍率与合同折扣均为 1，仅说明处理流程：

| 阶段 | 数据与应有动作 |
| --- | --- |
| 创建 | 预算 300000 Token，表达式 `tier("base", u("tokens") * 5 / 1000000)` 得到 1.50 美元预扣估计；按既有规则转换 quota 并原子 hold |
| Provider 视频成功但未报 Token | 视频保持成功，ActualUsageReported 为 false，进入 awaiting_usage；不得因提交 facts 中有 300000 而写 settled 或冻结最终 TargetQuota |
| 补查取得可信 120000 Token | 以已接受实测值构造最终 facts，求得 0.60 美元模型费用；按最终整数 quota 应用差额，不在表达式引擎内直接退款 |
| 补查/结算再次执行 | 已冻结目标与事务幂等保证不重复退款；后续矛盾用量记录差异，不覆盖已接受事实 |
| 独立失败场景：Provider 明确失败 | 直接沿原客户合同退款，不等待成功计价需要的 Token；Provider 成本未知继续保持未知 |

1.50 和 0.60 美元是表达式结果示意，实际账本差额以各阶段按冻结合同换算的整数 quota 为准。
提交预算、冻结条件和可信实测不做无约束 map 覆盖；终态实际 Token 明确为零时也必须有报告与校验证据。

### 6.4 冻结快照

复用现有 Task/attempt 快照，至少覆盖：

- 客户模型、客户身份、资金来源、组倍率、客户合同事实。
- Channel、Provider 模型、协议、固定插件版本、连接和已受理素材事实。
- 表达式原文、表达式语言版本、任务美元求值方式、用量 schema/单位或其固定版本引用。
- 提交 facts、Token 预算、冻结价格条件、可信实测用量与来源。

缺少必要冻结事实必须阻止新受理，不能在恢复时读取当前配置补齐。尽量复用现有 JSON 私有快照；
是否需要新增字段由实现评审确认，不预先承诺数据库无需迁移。任何结构变化均需三数据库验证。

账单单位使用既有 `BillingSnapshot.UsageUnits`，由同一宿主字段描述在创建时冻结，正常与恢复快照同源。
例如 tokens 为 `token`、分辨率为 `enum`、布尔条件为 `boolean`；秒数按真实单位声明，不能为获得
Token 分类而改标为枚举。当前分类器对缺少单位的 u() 表达式返回 `unknown`，不会自动归入原生任务单位；
Token 加枚举/布尔条件可识别，秒数或混合计量即使单位齐全仍可能为 `unknown`。
验收须逐类检查账单与修复命令的真实行为，不假设冻结单位后所有表达式都会变成 Token 分类；
历史未知单位保持未知，不通过当前配置推断补齐。

### 6.5 终态处理

| 观测 | 客户业务状态与资金处理 |
| --- | --- |
| 创建结果 unknown | 保留 attempt hold；不自动重发、重选或退款 |
| 成功且依赖的实际用量可信 | 按冻结表达式求最终 quota，并幂等应用差额 |
| 成功、Token 表达式缺实际用量 | 保持视频成功与预算 hold，沿用 awaiting_usage、有限补查和运营队列 |
| 成功、纯冻结参数表达式 | 依冻结事实求值；不要求无关 Token，不能把预扣结果直接当作结算完成证据 |
| 合法明确零 Token | 按冻结表达式计算；固定费用仍可能非零，不与“未报告”混同 |
| 非法/矛盾/溢出用量 | 按既有协议证据策略处理，不覆盖可信事实，不补零、不触发默认收费 |
| 失败/取消/过期 | 按现有 Seedance 客户合同退款；Provider exposure 独立记账 |
| 结算余额不足 | 保留真实资金目标及 debt，沿现有补偿处理，不降低实际费用或改写视频状态 |
| 重复轮询/并发补偿/重启 | 同一资金目标幂等，日志与账本不重复计费 |

## 7. 第四阶段：表达式与配置迁移

### 7.1 只读盘点产物

实施前输出受保护的迁移清单：客户模型、类型化归属、协议、原模式、表达式、预算、价格配置版本、
字段依赖、未完成任务/attempt/资金数量和转换结论。不得导出凭据、完整签名 URL、Task 私有正文。

盘点覆盖全部 Seedance 价格配置及有效/禁用渠道，区分无渠道价格残留、同名原生冲突、未定价模型。
不使用扫描结果自动修复渠道唯一性，不在请求路径新增唯一性检查。

B0 优先扩展已有 `cmd/seedance-p0-inventory`，不另建平行盘点工具。但当前命令不能直接作为放行依据：
`main.go:181—205` 在客户模型未配置模式时回退到映射后的 Provider 模型价格；当前 Seedance adaptor
按 `OriginModelName` 校验模式，本地 helper 也按精确客户模型读取表达式。该回退会把客户价格缺失
误报为已配置，真实请求仍可能返回 `requires tiered_expr billing`。

盘点接入本次迁移前必须删除不符合运行时的映射价格回退，模式、表达式、预算均遵循当前客户价格键
语义；Provider 映射只作独立履约事实，不充当价格来源。增加“客户键缺失但 Provider 键已配置”及
“两者都配置但价格不同”的确定性回归，验证报告不会把上游价格冒充客户价格。§5.5 的依赖判断同步替换。
现有命令仅打开只读 SQLite 快照；B0 须明确盘点数据来源与时点，不能宣称已经覆盖 MySQL/PostgreSQL
生产库，也不能用不完整快照证明存量资金为空。价格键或数据覆盖未核实，阻止使用该报告放行。

### 7.2 转换方法

迁移工具是显式离线/管理维护工具，不是运行时 decoder。默认仅生成候选和差异，不写线上配置。

推荐以 AST 校验和转换已有合法表达式：

1. 确认字段都能映射到该协议已声明事实；使用未支持变量、动态路径或非确定性函数的表达式转人工。
2. `c` 转为 `u("tokens")`，已登记的 `_task` 路径转为对应字段；保留比较、布尔与短路语义。
3. 将旧表达式的金额结果恰好缩小一百万倍；可以对 `tier` 的金额体转换，以保留档位追踪。
   不机械修改每个数字，条件阈值、折扣、时长和倍率均不属于价格系数。
4. 保留 `|||` 请求规则、匹配档位和已冻结条件的含义；异步现有禁用的 header/时间函数不得被迁移放行。
5. 重新编译、字段校验并执行等价验证；不支持的表达式不得猜测或静默归一。

示例仅说明数学转换，不代表任何 Provider 的当前售价：

```text
旧 Token 价格：tier("base", c * 5)
新 Token 价格：tier("base", u("tokens") * 5 / 1000000)

旧按秒价格：tier("base", param("_task.duration_seconds") * 400000)
新按秒价格：tier("base", u("duration_seconds") * 0.4)
```

### 7.3 等价证明

§7.2 示例只证明数学缩放关系，不证明计算机求值与最终扣费已经等价。浮点运算顺序、Usage 数值类型、
组倍率、合同折扣和整数取整都属于验证范围；优先保留原金额运算结构，再执行一次美元缩放。

- 自动转换仅支持可证明金额缩放和字段替换合法的 AST 子集；测试向量不能代替任意自定义表达式的证明。
- 对每个模型枚举所有实际支持的离散价格条件组合、分支阈值两侧、显式零值、最大合法数量和真实脱敏样本。
- 计算旧/新模型美元费用、组倍率后费用、合同折扣后费用、最终整数 quota、匹配档位及规则追踪。
- 最终 quota 必须相同；不能以浮点差异小于某容差代替资金等价。转换引起边界取整差异时调整候选
  求值结构并复验，无法等价则阻止该批切换，不能全局改变上游 rounding 规则。
- 固定费用加用量、嵌套条件、零价、预算上界和真实 Token 超过预算的场景都必须覆盖。
- 合同折扣不被迁移工具重复写入表达式；Provider 成本事实不参加客户价格转换。

### 7.4 配置写入

沿用 `ModelPricingChange` 的每模型 `expected_version` 及现有事务存储，一次提交本批模式、表达式和
原预算；不直接覆盖整个 options JSON，不丢失其他管理员或非 Seedance 模型的配置。

最终切换批次涵盖此次迁移范围内全部 Seedance 新受理模型；未完成转换的模型不得悄悄继续旧受理。
需要保留未迁移模型时，应先明确缩小发布范围并保持其停用，不新增按语法自动选择旧路径的逻辑。

准备阶段生成精确恢复清单和配置版本；应用前再次检查并发改动。发生版本冲突停止整批，由管理员
重新生成清单，不能强制覆盖。迁移中的首次应用、重复执行和失败重试均须可检查，禁止重复缩放价格。

## 8. 发布、存量处理与回退

### 8.1 首选切换方式

采用一次 Seedance 受理维护窗口，避免在同一模型上随机灰度不同计费合同：

1. 在候选版本中完成入口修复与计费统一，盘点模式、价格和预算；输出一次最终配置清单，运营无需
   先手工配置旧表达式再重新配置新表达式。
2. 完成测试环境全链路与真实受控 Provider/账单验收，候选版本及恢复版本都准备好。若经只读检查
   证明确实没有旧任务、attempt 和资金依赖，则存量处理为空操作；不能仅因尚未正式上线就假定测试调用没有资金事实。
   切换前置检查必须确认：§5.5 的四个 Seedance 运行时消费位置、盘点和保存校验已同批生效，
   图片/原生依赖语义不变；§7.1 盘点价格键已纠正；§6.4 单位快照及账单分类验收完成。
3. 在正式请求入口停止 Seedance 新视频受理；使用现有运维入口隔离能力，不增加业务随机路由。
   已受理查询、轮询、退款和补偿继续工作。价格、Channel 配置及插件激活写入同时冻结。
4. 等待所有已进入入口的请求结束，检查 prepared/sending/unknown attempts、任务、资金 hold、
   awaiting_usage、debt 和退款补偿数量。业务终态不等于资金终态。
5. 未完成项全部结清后才能切换；unknown 不因维护窗口超时自动退款。无法处理则延期，继续旧版本。
6. 在暂停新受理期间停止可能执行旧计费代码的 worker，部署所有处理节点；使用新版本验证器原子
   写入已经验证的价格批次，再启动处理器、刷新配置缓存并确认各节点版本。不得先向旧在线保存器写入 u()。
7. 原生入口回归和 Seedance 管理读取校验完成后，先开放受控测试账号验证，再开放正式客户。
8. 解除管理写入冻结，观察费用、错误、待用量和补偿结果；形成脱敏验收记录。

如无可验证的入口隔离与请求排空能力，先在运维层补齐该能力再发布，不能假设重启单个节点能停止全站受理。
不以全站数据库恢复方式回退这次价格迁移。

### 8.2 历史数据

- 历史 Task/attempt 的表达式、价格单位、账单、Provider 证据及冻结版本永久保持原事实。
- 只转换当前价格配置；不批量改写旧快照为 `u()`，不重新结算历史费用。
- 未完成旧任务在切换前由原有实现完成；不新增旧合同 decoder、兼容 alias 或双结算路径。
- 只读历史展示继续使用已存在的表达式/账单展示能力。通用引擎保留 `c` 本来就是原生文本模型的需要，
  不把通用 Token 语言当作应删除的“旧代码”。
- 删除本地旧运行时前证明所有可恢复旧任务已完成资金处理，包括后台扫描、管理员恢复和待补查记录；
  无证据不能删除，也不能宣布统一完成。

### 8.3 回退矩阵

| 时点 | 允许的动作 | 禁止的动作 |
| --- | --- | --- |
| 仅第一阶段 UI 修复 | 回退该独立补丁；预算/表达式仍按原合同存储 | 为回退界面清空价格或预算 |
| 新配置未应用、无新任务 | 撤销候选部署，保持旧配置，重新开放旧受理 | 部分节点以新语义接收旧价格 |
| 新配置已应用、尚无新受理 | 暂停下用版本校验恢复精确旧配置，再恢复旧版本 | 恢复整个数据库覆盖其他业务交易 |
| 已有新任务/hold | 先停止新受理，保持可解释新快照的版本完成结算，或发布前向修复 | 降级到无法履约新快照的旧版本；把新任务改成旧快照 |
| 新任务资金均完成 | 经验证恢复价格配置/旧版本，仅作用于后续新请求 | 修改已完成新任务的费用和日志 |

旧表达式备份只用于显式维护恢复，不能成为在线失败后的自动回退价格。

## 9. 管理界面、价格展示与用户体验

目标界面复用 `TaskUsagePricingEditor` 的字段/价格能力，并独立组合现有预算组件：

- 当前计费合同需要 Token 预算时显示预算，明确单位、已有值和缺失错误；不与本地试算输入共用 state。
- 表达式依赖实际 Token 时，预览要求用户提供“试算 Token”，不能默认将预扣预算展示为真实费用。
- 切换可视化/原始模式不修改收费语义；不能无损转换的自定义表达式保持原始模式，不生成默认价格覆盖。
- 公开价格、模型详情、用户合同价格、消费日志和历史账单都核对美元/百万 Token、美元/秒、美元/次
  的单位展示，禁止再次除以一百万或把预算当用量。
- 不暴露 Provider 模型、Channel、凭据或协议内部信息；对管理员展示的计费配置错误使用既有权限边界。
- 前端只提示、编辑与试算；后端保存校验与真实预扣仍为权威。
- 所有新增或修改 UI 文案先加载 i18n 技能并覆盖七种语言；UI 实现复用现有组件，按项目要求补交互测试。

| D | 客户价格键缺失但 Provider 键已配置；两者价格不同 | 盘点与运行时按精确客户键一致判断；不通过映射价格掩盖配置错误 |
| D | 正常创建与 unknown 恢复后序列化重读单位快照 | UsageUnits 同源冻结，创建/结算/退款日志一致；当前 schema 修改不改历史 |
| D | Token 加枚举/布尔、缺失单位、秒数及混合计量 | 分类符合真实单位；不支持的组合保留 unknown，日志修复命令继续拒绝非 Token 分类 |
| D | 旧/新历史账单、成本单位、公共信息脱敏 | 不改历史金额，不误显示百万比例或内部身份 |
| D | 发布时排空、缓存、旧节点、维护回退 | 新请求只落同一合同；有未完资金禁止破坏性降级 |

后端新增/重写测试使用 testify require/assert；测试固定输入与精确输出，不依赖随机循环、sleep、
日志打印或大范围 mock。协议/资金副作用断言必须覆盖数据库事实与真实调用次数，不能只测返回值。

- 类型：语义混同；置信度：高。
- 位置：`service/task_polling.go:789`、`pkg/billingexpr/usage_dependencies.go:5`、

### 15.3 建议问题：删减没有本次收益的设计

#### A1：为这次迁移扩展插件 ABI 与多用量来源框架没有必要

- 类型：过度抽象风险；置信度：高（针对方案拟新增范围，不是现存死代码判断）。

  负责实测事实；当前业务没有要求新增任意实测字段或客户可编辑计费来源。
- 最小修改：采用 §5.2 的宿主单一字段描述；协议合法范围读取现有固定配置，不另维护 Provider 模型表。
  不修改插件装载/发布 ABI，不新增 source/owner 配置表或生命周期枚举。
- 验证：新增一个普通价格档只需修改表达式，不需要 Go/JS/前端各改一份字段表；原插件制品可继续履约。

- 类型：编辑器表达能力边界；置信度：高。

  不把 bool 改成字符串枚举，也不为全量模型统一外观扩大矩阵编辑器重构。
- 验证：含视频/无视频价档的原始模式保存不变、错误提示准确、预算可编辑；不生成零价默认值覆盖。

### 15.5 一次上线的实际执行顺序

1. **候选版本完整交付。** A1—B5 在隔离环境完成；原规则不作为一个中间运营版本发布。
2. **只读生产预检。** 输出需要转换的模型数量、价格/预算缺口、协议和未完成资金数量；配置内容与
   私有数据受保护。没有生产数据时不预设为零。若只有初始化/测试样本，也必须处理其实际资金事实。
   使用 §7.1 已纠正客户价格键且明确数据来源的盘点工具；不得把原命令的映射价格回退结果作为放行证据。
3. **生成一次最终配置。** 已配置旧价格等价转换；未定价模型按明确售价人工定价。界面“8折”或
   Channel 名称不是价格事实，不能自动生成 0.8 乘数。预算空缺直接列为待补配置，不猜默认值。
4. **固定切换上下文。** 在入口暂停新视频受理及价格、Channel、插件激活写操作；现有已受理任务继续
   查询和资金处理。只锁价格不锁协议变更，不能保证迁移候选仍适用。复用运维访问限制，不新增业务开关。
5. **完成存量依赖。** 检查所有请求入口和 worker。只有旧业务及资金依赖全部完成才能移除旧新受理路径；
   无存量则直接通过。有 unknown/欠费不能靠改状态或退款“清空”，不能为了上线抹掉资金事实。
6. **统一版本与价格。** 停止可能执行旧计费代码的后台 worker，部署候选所有节点；此时仍不对外受理。
   用新版本 Seedance 验证器在事务中应用一次转换批次、校验原价格版本，再启动处理器并重载配置。
   旧版本保存器本来拒绝 u()，所以不得先在旧在线进程中写入新表达式。
7. **恢复受理前检查。** 全节点验证客户模型模式、表达式、预算、协议配置一致；跑一笔受控实际任务
   验证预扣、结果、用量和最终账单后开放。无多节点确认能力则采用可验证的全进程重启和入口隔离，
   不为本次临时建设配置一致性平台。
   §8.1 的依赖规则同批生效、原生边界与冻结单位验收必须已经通过；单笔任务不能替代这些组合回归。
8. **资金出现异常先停新请求。** 新版本已创建的任务继续由能识别其快照的版本处理；不能直接降级，
   也不从旧配置反推新任务的价格。按第 8 节既有恢复边界执行。

`expected_version` 只证明价格配置未变化，不能证明 Channel/插件配置未变化；维护窗口必须同时
控制这些管理写入。迁移工具再次读取上下文与版本，不把一次预览永久当作执行许可。

### 15.6 健康度与优先修复根因

本节评分仅针对“当前 Seedance 定价接线直接复用 u() 的准备度”，不是全仓质量或上线可靠性概率。

| 维度 | 得分 | 依据 |
| --- | --- | --- |
| 需求符合性 | 1/2 | 管理入口与实际计费合同不一致，S5 |
| 单一路径与单一事实来源 | 1/2 | S1—S3 的接口、归属和快照语义需要明确 |
| 冗余与死代码控制 | 2/2 | 本次未证明需要全局清理；历史探针有真实消费者，不误判死代码 |
| 抽象与类型设计 | 1/2 | TaskUsageBilling 同时被用于金额与归属判断，S1 |
| 规范与验证能力 | 1/2 | 现有基础测试通过，但没有迁移组合与管理真实数据入口覆盖，S2/S5 |
| 合计 | 6/10 | 待实施准备度，不构成发布批准 |

优先处理三个根因：

1. **计费归属与元数据不一致：** 修管理/保存唯一入口，避免 UI 与后端仍各用一套合同。
2. **求值与资金职责耦合：** 仅替换本地求值输入，正常创建和恢复同源冻结，保留唯一资金写入。
3. **冻结条件、预算、实测未精确区分：** 依赖规则统一到保存、补查和数据库保护，堵住提前结清与无谓等待。

完成本节收敛后，方案可实施为一个上线版本；是否可以放行仍取决于实际产物和验证。最小入侵的
判断依据是原生文件新增差异与真实语义变化，不是要求少测资金链，也不是省略已知恢复入口。
