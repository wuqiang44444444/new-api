# 全量复审问题修复与合同查询优化

## 问题与目标

承接 80-dev 全量复审，修复账单版本读取失败被显示为空状态、WARN panic 跳过错误事件持久化、
合同停用测试仍断言旧文案三个问题，并消除合同运行时资格校验及管理投影的逐规则来源查询。
合同模板开发、生产历史金额补正和真实外部系统验收不属于本轮修复交付。

## 当前实际情况

- 修复前回归已复现：月份查询故障返回成功空历史；正式版本或草稿读取失败、引用记录缺失时返回
  成功的未确认状态。客户与管理员接口均受影响。
- WARN 普通返回错误仍可持久化，但 panic 被整个投递函数恢复，跳过后续数据库出口；新增回归已复现。
- 合同停用组件已采用现行 Key 自身路由与价格语义，测试保留旧提示，前次单 worker 复查稳定失败。
- 13 条混合合同规则产生 22 次来源查询；管理可用性投影还将渠道或 Ability 读取失败当作不可用。
  查询计数及故障注入回归在原实现上均失败。

## 优化方案与实现

1. 月份不存在与查询错误分别处理；正式版本、活动草稿引用读取失败时立即返回既有错误响应，
   不返回部分月份状态。正常空月份、正式版本和客户不可见草稿的状态语义保留。
2. WARN 与数据库出口各自恢复 panic、维护计数；WARN 失败后继续现有持久化路径。
   不新增队列、重试或投递框架，不改变请求响应。
3. 仅更新合同停用测试为现行提示，继续断言绑定可见且有效折扣隐藏；不修改组件或翻译文件。
4. 来源读取与资格判定在本地合同模型中共享：每批最多 200 条规则，最多一次渠道读取和一次
   Ability 读取。普通渠道依赖启用 Ability，类型化渠道依赖自身精确组及模型成员；保留规则顺序。
   任一批失败不发布部分结果、不修改已有快照。用户组权限仍在 service 校验，原生优先级、权重、
   pin、重试、折扣和资金流程不变；不增加跨请求缓存或第二套渠道资格。
   类型化组资格不再复用管理列表的筛选函数；`all` / `null` 只有在渠道确实包含该组时才可用，
   不将列表“取消筛选”语义用于合同授权。普通特殊字符组按实际名称判断，管理保存与运行时一致。

### 变更边界

主体及接线均位于本地账单、合同、错误日志扩展及其测试；未修改 NEWAPI 原生 Router、分发、
Provider、资金或数据库 schema。删除被批量入口替代的单规则运行时包装和吞错投影辅助函数。
上游同步无需新增原生接线；既有工作区改动保持原样。本轮不提交、不部署、不写入客户数据库。

### 验证与剩余事项

验证使用本地隔离 SQLite、模拟请求和已有前端测试环境：

- 账单及 WARN 回归先在旧实现上失败，修复后通过；覆盖空月份、引用缺失、客户/管理员状态、
  WARN error/panic 与实际请求状态、持久化及各出口计数。
- 合同 13 条混合规则查询由 22 次降为 2 次，普通和类型化资格结果一致；201 条规则跨批读取
  完整保序，第二批失败不发布第一批结果。渠道/Ability 故障、组权限、输入快照不变及
  `all` / `null` / 特殊字符组的精确资格回归通过。
- 后端 `model/service/controller/middleware/router/relay/clienterrlog/logger` 八包全量通过；
  覆盖原生合同选渠、优先级、重试、价格投影和资金关联测试。最终补充的特殊组用例另行通过。
- 前端单 worker 关联测试全量通过：63 个文件、469 项用例；包含上轮失败的合同停用提示与日志页面。
- 根项目 `go build ./...`、相关五包 `go vet`、前端类型检查及修改测试文件 lint 通过。
- `task docs:check`、`task ai:check` 与修改范围的差异空白检查通过。
- 本轮未修改 relaykit 或公开 API 文档，不涉及数据库迁移与客户资金写入。

未运行真实 Provider、SMTP、对象存储或生产数据库验收；MySQL/PostgreSQL 实机及最低版本
不能由 SQLite 回归代替。合同模板和生产财务核准等原有剩余事项继续独立跟踪。
