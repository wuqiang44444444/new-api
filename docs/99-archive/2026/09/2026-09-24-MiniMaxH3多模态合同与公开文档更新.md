# MiniMax H3 多模态合同与公开文档更新

## 问题与目标

[真实调用验证](2026-09-24-MiniMaxH3多模态真实调用验证.md)证明 JD 能处理九图三音频、10 秒、2K，
但 1.0.0 插件只开放文生 6 秒/768p。用户明确要求同步扩展 adapter、元数据及 API 文档，不能仅扩大
目录后让实际请求失败。本文记录本轮代码与本地验证，不把既有直连结果追认为新网关实测。

## 当前实际情况

- 新制品 `minimax-link@1.1.0`：单文本（最多 7000 Unicode 码点）、九参考图、三参考音频；整数
  4–15 秒，768p/2k，官方画幅枚举。缺省仍为 6 秒、768p、16:9；纯文本 adaptive 在占款前拒绝。
- 图片 Data URL/HTTP(S) 与音频标准 URL/Base64/multipart 沿用 ModelArk 字段；参考视频、首尾帧、
  asset/mm_file 引用和素材库未开放。固定提示词优化、水印 false，未发布 generate_audio。
- 官方范围与 JD 实测组合的证据来源见前述验证记录及公开 H3 页面。15 秒、其它比例与新标准多模态
  链路尚待真实 Provider 验收，不以本地成功扩大生产状态。

## 优化方案与实施结果

### 唯一合同与最小改动

- 插件拥有 JD 转换和范围校验，原生入口、分发与 Seedance adapter 未修改。宿主将完整准备后的
  content 与转换结果比较，禁止删项、重排、改角色或换 URL。
- 元数据按激活制品的声明生成，旧 1.0.0 声明仍返回文本/6 秒/768p，不因部署新代码自动扩大。
  duration、媒体数量、枚举和提示词长度来自插件；默认枚举首项同时驱动宿主计费与保真检查。
- 共享插件声明仅增加可选 `maxPromptLength` 字段、白名单与范围验证。这是发布实际长度限制所需的
  最小共享接线，不另建 H3 配置表；其它制品未声明时无行为变化。
- MiniMax 的计费选择器集合覆盖各冻结版本可产生的 resolution/ratio，不授予模型履约资格；客户
  允许参数仍由精确插件声明决定。未增加 credit/Token 计价，也未改用户价格。
- MiniMax 复用既有音频准备服务与对象事实冻结，未复制 OSS 实现。公共任务错误投影增加一个精确的
  本地 503/reference_audio_unavailable 分支，仅返回固定安全文案；这是保持公开错误合同所需接线。
  该文件属于本地协议层；没有新增原生热路径改动或扩大上游合并面。
- 公共 H3 页面、ModelArk 入口说明、OpenAPI 描述、导航与搜索索引同步更新。20 架构与硬约束补明
  MiniMax 复用现有音频例外；不调整现有素材所有权、计费状态机或原生 API。

### 发布与剩余验证

部署只入库 1.1.0，按既有机制由管理员显式激活，不覆盖存储中的 1.0.0，不自动启用渠道；旧 Task
继续使用冻结版本。本轮未修改本地业务数据库、价格、渠道或运行实例，未发起新付费生成请求。

必须继续完成：新标准多模态与内联音频真实验收、正常公网 DNS 下受保护下载、JD 账单、冷缓存跨节点、
90 分钟过期与真实 MySQL/PostgreSQL 矩阵。现有测试视频与本次桩测试不能代替这些验收。

## 验证结果

本地验证覆盖：标准鉴权入口九图三音频到一次 JD POST 的完整字段、10 秒预扣与 2k/9:16 冻结探针；
缺省 768p/16:9；超数量、超时长、长提示词、错误 role/素材引用、私有字段及音频存储缺失均无 attempt、
无占款、无 Provider POST；宿主内容保真、4/15 秒与画幅边界；旧声明投影不被扩大。

11 个相关 Go 包回归、元数据专项测试、`task docs:check`、`task ai:check`、
`cd web && bun run docs:validate` 与 Web 完整构建（含 docs/branding 产物检查）通过。
未运行外部数据库和真实 Provider 的新增链路。
