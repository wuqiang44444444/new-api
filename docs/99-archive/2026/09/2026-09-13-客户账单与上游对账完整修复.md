# 客户账单与上游对账完整修复

## 问题与目标

对客户账单和上游对账执行代码修复及本地历史日志补录：修复上游筛选后父级总计与子行范围不一致、
物理删除客户详情不可查、合同启停期间误显示单一折扣，以及冻结任务金额与日志净额不一致的问题。

当前事实分别见 [客户与上游对账架构](../20-architecture/账单计费-客户与上游对账架构.md) 和
[历史任务日志补修命令](../30-engineering/命令清单.md#历史任务日志补修)。

## 当前实际情况

### 代码修复

- 上游渠道、模型筛选进入后端聚合条件。页面总计、模型行、质量说明和 CSV 使用同一筛选响应；
  筛选选项保留全量集合，查询加载或失败时可继续切换条件且禁用导出。
- 物理删除客户仍有结算日志时，列表、详情及明细统计均可查看；余额返回 `null` 并显示不可用。
  没有用户或客户结算历史时仍返回未找到，渠道测试记录不构成客户结算历史。
- 无合同记录按有效倍率 1 参与合同折扣变化判断。合同开始或结束造成混用时显示多折扣，
  全部无合同事实时不新增合同折扣展示。金额沿用逐行冻结倍率计算。
- 补录工具新增精确冻结 Provider 请求 ID 关联，并复核唯一已转移预扣。允许重算冻结参数表达式，
  缺少 Token 计量依据时保留未知分类。拒绝重复身份、预扣不符、未闭合结算和在线交付记录。
- 扩大历史检查时发现零金额计费异常诊断可能被补录工具改成完成调整，造成重复 Token 投影。
  完整性检查在写入前阻止该范围提交；现已保留明确失败/欠费诊断原样，并拒绝无法确认的计费事件。

全部代码修改位于既有本地对账模块或独立补录命令；未扩大 NEWAPI 原生热路径接线。

### 本地数据修复结果

环境：本地 `one-api.db`，SQLite 主库与日志同库。没有调用真实 Provider、扣款、退款或结算 API。
先在一致性副本执行，再应用本地目标库；目标库首次备份为
`one-api.backup-20260913-before-billing-full-fix.db`，文件权限为仅当前用户可读写。

| 核验项 | 结果 |
| --- | --- |
| 完整通过的历史范围 | 35 个客户 / Key / 模型 / 完整生命周期范围 |
| 逐项闭合的任务 | 646 个 |
| 补齐初始日志任务归属 | 190 条 |
| 更新冻结展示元数据 | 941 条既有日志，包含上述归属补齐 |
| 新增缺失初始日志 | 1 条，117,871 quota |
| 原缺失范围净额 | 40,957,475 → 41,075,346 quota |
| 该范围冻结任务结算合计 | 41,075,346 quota，102 个任务 |
| 修复后差额 | 0；初始、完成、归属、净额及最终用量检查均通过 |
| 幂等复核 | 全部范围再次预览均无待修改、关联或补录项 |

新增日志属于已发生的预扣事实恢复，不是新增扣费。没有证据的历史 Token 保持原值与未知分类。

一致性副本前后比较：76 张非日志表全部不变；所有既有日志除元数据外的字段，包括 quota 和 Token，
全部不变。目标库与首次备份比较：所有既有日志金额和 Token 不变，资金、用户、Key、Task、attempt
及其余业务表不变；仅 `system_instances` 与 `system_tasks` 出现运行中心后台活动变化，这两表没有
被补录命令写入。

### 尚不能确认的历史事实

剩余 457 条初始日志未建立可验证的完整任务归属：

- 441 条缺少可唯一匹配的冻结请求身份；
- 16 条虽可匹配请求，但缺少匹配的唯一已转移预扣证明；

另有 37 条最初因账期范围交叉而未通过；按相交任务的完整生命周期收敛查询边界后，全部通过原有
校验并完成归属补齐，没有放宽预扣或结算验证。

这些记录保留原金额，没有按时间、相同金额或当前价格推测补写。完成剩余逐任务确认，需要补充历史
请求、预扣转移和结算事实；不能把“汇总金额相等”写成所有历史任务都已核实，也不能把未知 Provider
成本替换为客户 quota。本次没有取得供应商原始账单，不构成供应商成本逐笔验收。

## 优化方案

### 已完成验证

- Go：补录命令全部测试；model、controller、service 的账单、对账、客户结算范围及 Task 日志交付
  相关测试通过。覆盖折扣双向切换、无合同、物理删除身份、拒绝无历史身份、预扣冲突、重复请求身份、
  诊断日志保留、幂等及不改变资金。
- 前端：账单模块 6 个测试文件、23 个测试通过；TypeScript 检查与模块 lint 通过。
  覆盖筛选后总计/CSV 同范围、保留筛选选项、加载/失败禁用导出、恢复全量和未知余额展示。
- 数据：2026 年 4—9 月全客户列表与两种详情维度一致；最终按模型下钻的 890 项净额比较无差异。
  同期上游渠道/模型筛选的 214 项用量与质量比较无差异。上游查询的折扣写入隔离到内存库，
  数据核查不修改目标库的折扣与审计。
- 一次较宽的 Go 测试名称匹配额外选中了无关 Redis 缓存测试，受本地监听权限限制未能运行；
  已按本次实际修改边界重新执行并通过。不将此记录写成全仓库测试通过。

### 剩余验收边界

历史证据缺口维持可见，不自动退款、不重发任务、不重新解释当前配置。未执行生产部署、真实 Provider
账单验收或真实 MySQL/PostgreSQL 验收；这次查询修改沿用跨数据库 GORM 方法，无迁移或方言专属 SQL。
