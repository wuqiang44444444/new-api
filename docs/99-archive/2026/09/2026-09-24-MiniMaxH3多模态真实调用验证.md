# MiniMax H3 多模态真实调用验证

## 问题与目标

验证现有京东云连接对 H3 多参考图、参考音频及更多输出参数的实际支持，并区分 Provider 能力与
当前标准渠道已开放的合同。遵守 [Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)
和 [MiniMax 适配方案](2026-09-23-MiniMax标准北向与京东云南向适配方案.md)：不以直连成功代替网关验收，
不为测试绕过现有 adapter 校验，不将未验证能力写成生产发布。

## 当前实际情况

### 环境与证据边界

- 原本地服务端口为 3501，数据库仅有停用的 MiniMax 原生类型 35 渠道 137；没有类型 64 标准渠道，
  也没有入库的 `minimax-link` 制品。该环境不能直接代表本轮已实施代码。
- 使用当前代码编译独立本地实例（3502），在独立 SQLite 数据库配置类型 64、`minimax-link@1.0.0`，
  复用渠道 137 的 JD Base URL 和凭据。没有修改原渠道、原业务数据库或原服务。
- 独立测试用户使用专用 Token 与测试客户模型。测试计费为 `u("duration_seconds") * 0.01` 美元，
  只是本地客户计费校验值，不代表 JD 成本；JD 实际金额须以账单为准。
- 初次隔离环境请求暴露证据对象存储缺失（503）与必须配置 `tiered_expr` 两个环境前置条件。
  修正测试价格并显式关闭独立实例的可选请求证据采集后重测；原服务证据设置未改变。
- 原连接上的多模态探测直接使用 JD `/v1/task/submit`，仅用于验证南向。每组只提交一次，
  没有创建结果 unknown 后重发或切换渠道；这类探测不经过网关 Task、客户账单与退款链路。
- 标准链路使用 `/api/v3/contents/generations/tasks` 和受保护的 `/v1/videos/{id}/content`。
  保留 15 分钟任务查询调度，没有通过修改 Task 的调度时间缩短验收等待。
- 本文不保存凭据、任务私有字段、签名下载地址和原始 Provider 响应。媒体是公开样例输入与测试生成物。

### 官方参数与 JD 证据不是同一层

2026-09-24 读取 [MiniMax 官方 H3 创建接口](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create)
的官方 Markdown 版本（同路径加 `.md`）：H3 支持文生、首尾帧和参考多模态输入，参数如下。

| 参数 | MiniMax 官方 H3 范围 | 当前网关 MiniMax 首期合同 |
| --- | --- | --- |
| 参考图 | 最多 9 张，`reference_image` | 未开放 |
| 参考视频 | 最多 3 段，单段 2–15 秒、合计不超过 15 秒 | 未开放 |
| 参考音频 | 最多 3 段，单段 2–15 秒、合计不超过 15 秒 | 未开放 |
| 时长 | 整数 4–15 秒 | 6 秒 |
| 分辨率 | `768P`、`2K` | 北向 `768p`，南向 `768P` |
| 宽高比 | adaptive、21:9、16:9、4:3、1:1、3:4、9:16；文生不能 adaptive | 16:9 |
| 水印 | 官方直连使用 `aigc_watermark`；JD 文档使用 `parameters.watermark` | false |
| 音频开关 | H3 官方创建参数未声明 `generate_audio` | 拒绝显式传入 |

图生首尾帧与参考模式互斥。这里的模型能力不能自动授权 JD 协议；[京东云图生文档](https://docs.jdcloud.com/cn/jdaip/hailuo-image-to-video)
仍以 Hailuo 2.3 为例，没有完整 H3 多模态参数合同。JD 包裹、role 和多音频组合需要本次真实探测。

28 个 `video_output` credit，不据此计算 Provider 金额。

四个实际 MP4 和脱敏检查摘要保存在仓库本地 `.local-tests/minimax-h3-live-20260924/`，未提交媒体、
凭据或原始响应。测试结束后已停用独立测试 Token、独立类型 64 渠道，并停止 3502 测试实例。

### 标准任务结算与下载环境问题

标准任务创建的 attempt 为 complete、hold 为 transferred；终态计费为 settled、operation=settle、
target_quota=30,000。用户与 Token 从各 10,000,000 减至 9,970,000；两条消费事件 quota 合计 30,000，
没有终态重复扣款。持久用量来源是 `credit:video_output`，证据为 `video_output=6`，未转换成 Token。

受保护内容下载实际返回 HTTP 403 `content_url_not_allowed`。日志与 DNS 对照定位到本机 Fake-IP：
`maas-task.s3.cn-north-1.jdcloud-oss.com` 被系统解析为保留地址 `198.18.1.4`，SSRF 防护因此拒绝。
同一时刻通过阿里 DNS-over-HTTPS 查询得到公网地址 `116.196.126.148` / `116.196.126.180`。
用同一任务从 JD 直连下载得到 HTTP 200、1,472,476 字节，H.264 1344×768、AAC 双声道、约 6.583 秒。
这证明文件存在且可下载，但**不能记为网关受保护下载通过**。本次没有关闭 SSRF、放行私网 IP、
修改系统 DNS 或更改 frozen Task；停止了对该确定性失败的重复下载检查。

## 优化方案

当前多模态限制来自已实现的首期合同，不应描述成京东云或 H3 本身不支持。
如扩展标准渠道，应基于 JD 终态与下载证据，在 MiniMax 专属插件发布新版本，同时更新宿主内容保真
校验与公开参数投影；不得仅删除 `content.length` 校验、透传私有参数或修改 Seedance/native 路由。

后续动作：恢复正常公网 DNS 后复验标准受保护下载；如需通过统一北向使用本次已验证组合，另行完成
MiniMax 多模态插件、宿主保真校验与公开声明的同步扩展。本次只做真实调用验证，没有修改业务代码。
不在本次结果中推定完成：JD 实际账单、跨数据库、多节点冷缓存、90 分钟过期、参考素材逐项遵循率、
参考视频输入以及多模态标准渠道实现。
