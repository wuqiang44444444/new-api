# Vidu 协议适配与合同覆盖修复

## 问题与目标

国内、海外 Drama 实测均成功生成视频，但数值与用量返回字符串，旧官方协议无法解析。
本次根据[国内原始资料](../../../70-research/Vidu国内站视频接口原始信息.md)、
[海外原始资料](../../../70-research/Vidu国外站视频接口原始信息.md)和
[上次实测](2026-09-28-Vidu双站渠道接入与实测.md)修复新任务的创建、轮询、结算及管理员合同选择。
用户明确要求本轮不再执行真实生成测试；仅执行本地夹具、构建与管理接口核对。

原始地址：

- 国内：https://shengshu.feishu.cn/wiki/PkFHwrme8ihMA8kshbgc5QwPnxe
- 海外：https://shengshu.feishu.cn/wiki/UdZNw56HxiLfEykYOjmcsaYQn08

## 当前实现

使用 `seedance-link` 1.4.2 的独立 `vidu_modelark_v3` 协议；两站 wire 合同一致，连接、密钥和模型映射
分别保存在两个 Channel。没有修改原生 NEWAPI Provider、通用路由或 Ability；注册、转换及校验均在
Link 扩展文件，未来上游合并的接线面仅涉及本地协议别名与注册表。

共享 `service/task_polling.go` 另保留四个窄接线点：识别 Vidu 的可信 expired、补齐终态和退款、
退款兜底及旧计费上下文保护。原因是原共享状态集合不接受 expired，只有 adapter 转换不足以释放
到期任务预扣。Vidu 判断与终态处理集中在新增 `service/vidu_task_polling.go`，不扩大原生状态集合，
不修改 MiniMax 原有分支；后续上游同步只需保留这四处接线，不复制另一套资金实现。

| 项目 | 国内 | 海外 |
| --- | --- | --- |
| 本地 Channel ID | 139 | 140 |
| Base URL | `https://api.vidu.cn/ent` | `https://api.vidu.com/ent` |
| 创建 | `POST /api/v3/contents/generations/tasks` | 同左 |
| 查询 | `GET /api/v3/contents/generations/tasks/{id}` | 同左 |
| 鉴权 | Bearer | Bearer |
| 视频协议 / 素材协议 | `vidu_modelark_v3` / `none` | 同左 |
| 客户模型后缀 | `-vidu-cn` | `-vidu-global` |

每站四个客户模型前缀为 `seedance-2-0`、`seedance-2-0-fast`、`seedance-2-0-mini`、`seedance-2-5`。
国内映射 `viduq3-drama-std/fast/mini`、`viduq3.1-drama-std`；海外映射对应 `-drama-ab-` 名称。
Vidu 协议只登记这八个精确上游模型，不借火山或 BytePlus 协议兼容，也不跨站回退。

### 创建字段逐项对应

| 北向字段 | 南向处理与校验 |
| --- | --- |
| `model` | 客户别名按 Channel 精确映射为上游模型 |
| `content` | text、image_url、video_url、audio_url 结构与角色保留；已有音频上传转换继续履约 |
| `duration` | 不传为 5；Q3 为 4–15，Q3.1 为 4–30，支持 -1；预扣探针使用对应最大时长 |
| `resolution` | 不传 720p；4K 转小写 4k；std 支持 480p/720p/1080p/4k，fast/mini 仅 480p/720p，2.5 不支持 4k |
| `ratio` | 不传 adaptive；校验文档七种比例 |
| `generate_audio` | 不传显式 false，消除文档默认值冲突；显式 true/false 保留 |
| `watermark` | 原值保留，包括 false；Provider 默认 false |
| `callback_url` | 原值透传；不以未验签回调作为网关资金结算证据 |
| `return_last_frame` | 原值保留，包括 false；尾帧结果交由既有内容代理 |
| `execution_expires_after` | 原值保留，范围 3600–259200；未传由上游使用 172800 默认 |
| `tools` | 仅允许 `web_search`，原结构保留；未另外推定搜索计费规则 |
| `safety_identifier` | 原值保留，最多 64 个字符 |

首尾帧模式与多模态参考互斥；首帧和尾帧各至多一张，尾帧须有首帧。
Q3 参考图片/视频/音频上限 9/3/3，Q3.1 为 30/10/10。参考音频不能单独作为唯一媒体。
模型限制和未发布参数校验发生在资金 hold 和 Provider POST 前。
`seed`、`camera_fixed`、`frames`、`draft`、`output_format`、`priority`、`service_tier` 没有本次
Vidu 文档依据，保持未发布且明确拒绝，不静默丢弃；公网媒体规格仍由 Provider 检查，不额外下载探测。
素材控制面未声明支持，不能将 `none` 理解为支持素材库；opaque 引用遵循既有统一合同交由上游判断。

### 响应与用量

| 字段 | 归一行为 |
| --- | --- |
| `id` | 必须为字符串且与创建 ID 一致，不经 JavaScript 数值转换 |
| `status` | queued/running/succeeded/failed/expired；未知值不形成终态 |
| `seed`、`duration`、`created_at`、`updated_at`、`execution_expires_after` | 文档整数和实测十进制整数字符串均接受；负值、溢出及非法格式按字段边界拒绝 |
| `frames_per_second` | 整数或整数字符串转为统一 `framespersecond` |
| `model`、`resolution`、`ratio`、`generate_audio`、`draft` | 已知字段按类型保留；公开客户模型仍由冻结客户身份投影 |
| `content.video_url` / `content.last_frame_url` | 成功必须有视频结果；保留尾帧，继续通过既有客户资源代理提供 |
| `error.code` / `error.message` | 只接受既有结构；失败同时返回有效视频属于冲突观察，不据此退款 |
| `usage.completion_tokens` | 有界非负整数或规范十进制字符串；明确的零合法，最大 int32 |
| `usage.total_tokens` / `prompt_tokens` | 保留可信证据；不能替代缺失的 completion；非法或 total 小于 completion 阻止结算 |

指数、浮点、布尔、空白字符串、负值及溢出不能变为可信扣费量。只有 total 或缺失/非法 completion
时，成功视频可交付但保持 `awaiting_usage`；后续同一冻结任务补齐用量后结算。上游 HTTP 404/410
等错误不直接证明业务失败，资金保持原状态。Vidu 的数字字符串兼容没有放宽火山/BytePlus 解析。
可信 `expired` 保留北向到期状态，通过既有退款事务释放客户预扣；其失败原因区别于平台观察超时，
不会冒充“上游结果未知”。明确零用量、可信 failed 和 expired 均验证重复轮询不重复退款。

## 账单与合同

八个客户模型的表达式、计价模式和预扣 Token 配置，经只读逐项校验与现有官方 Seedance 对应型号
完全相等。海外客户报价也统一使用该官方价；供应商海外美元价格和供应商实际成本不混入客户账单。
结算继续冻结表达式、汇率、组倍率、合同折扣及输入视频档位；既有资金入口负责差额退款与幂等。

本地完整链路夹具使用两站 std 的实测响应形状、108900 输出 Token、928000 预扣 Token、
CNY/USD 6.76、500000 quota/USD 和 80% 合同折扣：

| 请求媒体档位 | 官方价 CNY/百万 Token | 预扣 quota | 最终 quota |
| --- | --- | --- | --- |
| 图片＋参考音频 | 46 | 2525917 | 296414 |
| 图片＋视频＋参考音频 | 28 | 1537515 | 180426 |

钱包、Key 已用/剩余额度、Task 最终 quota 和消费减退款的日志净额一致；中途修改价格/汇率不重算
旧任务，重复轮询不重复结算。供应商真实账单仍待用户验收，不能把本地夹具当作供应商实扣证明。

用户已明确：仅要求管理员选择模型时出现，不追加到具体合同。现有合同及模板选择 API 均沿用
Seedance Channel 的只读投影；八个模型无需新建 Ability 或新增合同供应商名单。已核对管理员
模型选项、渠道选项和模板选项均显示八个客户模型，现有合同版本没有改变。

本地渠道 139/140 已通过管理入口切换为专用协议并恢复启用，组为 `default,randy,seedance`；
本地服务已加载 1.4.2 制品，存储源码摘要与工作区一致。旧测试 Token 184 继续停用，用户自行选择
现有 Key 或配置合同后验收。本次任务数量仍为原来的两条，没有新增真实视频任务。

## 验证与剩余验收

- 新增字段、数字字符串、非法用量、素材模式及数量、模型限制、4K 转换与默认值回归。
- Controller 真实中间件、SQLite 资金事务及本地 HTTP Provider 夹具覆盖创建→轮询→待用量→结算。
- Seedance、插件、公开元数据、Controller、Model、Middleware、Service 和适配器版本相关测试。
- 根模块构建，`relaykit` 的 `GOWORK=off go build ./...`，以及文档和 AI 指引检查。
- 本轮没有调用真实 Provider 生成接口；本地管理接口读取不构成真实 Provider 验收。

上次 Task 3851/3852 的冻结官方协议及预扣保持不变，新协议不会自动迁移或结算这两条旧任务。
历史占款仍需既有受审计资金流程处理。本次修复的用户验收对象是新提交任务：两站成功生成、查询、
尾帧、真实用量、差额结算以及供应商账单。删除操作的在途与终态含义仍无足够证据，暂不发布；
北向任务列表读取本地数据库。
