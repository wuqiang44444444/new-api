# 客户合同模板功能分析与实施方案

> 状态：业务需求已通过逐项讨论确认，本文记录拟实施方案。尚未开发合同模板功能，未执行功能测试、
> 数据库升级或生产验收。本文中的接口、字段、页面组织和并发处置是实现建议，不冒充已有系统事实。

## 问题与目标

管理员目前为不同客户创建类似折扣合同时，需要重复添加模型、来源渠道、分组和折扣。
本次增加全站共享的合同模板，将常用配置保存并复用于新建客户合同，减少重复操作与漏配。

这里的合同是系统现有的客户模型折扣合同。保存模板生成的是归属于目标用户的一份独立合同，
不是文书、签署文件或用户专属模板；一个用户可同时持有多份启用合同。

### 用户已确认的业务决策

| 项目 | 已确认要求 |
| --- | --- |
| 模板内容 | 保存完整的模型、来源渠道、分组和折扣规则 |
| 模板来源 | 支持直接新建；支持将已有用户合同另存为模板 |
| 模板共享 | 全站管理员共享使用和维护，记录操作人 |
| 用户权限 | 为用户创建合同仍遵循现有用户管理权限，不因共享模板扩大权限 |
| 套用范围 | 用于创建新的用户合同；带入规则后可增删规则、修改折扣和来源 |
| 保存产物 | 保存到现有客户合同体系，归属于所选用户 |
| 独立维护 | 模板只在创建时提供配置，生成后独立维护；修改模板不回写已有合同 |
| 失效来源 | 渠道停用、模型移除或分组删除时，保留全部规则并标出失效项；修正或删除后才可保存用户合同，不自动跳过 |
| 模板生命周期 | 只支持停用和恢复，不提供删除；停用后不能再套用，保留模板及修改记录 |
| 新合同状态 | 通过模板创建的新合同默认启用，可与已有合同同时启用 |
| Key 绑定 | 保存不自动绑定或替换任何现有 API Key 的合同，仍沿用现有 Key 绑定流程 |

### 成功标准

管理员可维护一个通用模板，分别给甲、乙创建独立合同，并在创建时调整甲的折扣。
模板后续修改或停用，甲、乙的合同、已有合同及 Key 绑定均不变化。
套用时所有配置可见，失效来源有明确提示，不能静默遗漏模型折扣。

### 范围边界

- 首期只在新建用户合同时套用单个模板，不向已有合同重新套用，也不合并多个模板。
- 不增加模板到用户合同的同步、批量改价、继承覆盖或自动更新机制。
- 模板只复制既有合同规则；合同按 ADR-0020 限定范围并提供折扣。模板不另增权限、选渠、重试、固定价或计费分支。
- 不增加自动 Key 绑定、已有合同停用、文书生成、在线签署或用户自助模板管理。

前两项是依据“模板只用于创建”收敛的首期实现范围，不扩大已确认业务目标。

## 优化方案

以下为基于已确认需求制定的实现建议。名称、接口和布局在实现时可按现有工程约定细化，业务边界不变。

### 1. 页面与操作流程

#### 1.1 模板管理

在现有“客户合同”页面增加“合同模板”入口，打开独立的模板管理视图，避免新增无关一级菜单。
列表支持名称检索、启用/停用筛选、分页；展示名称、状态、模型数、规则数、失效规则数、更新时间与操作人。
模型数按公开模型去重，规则数按渠道规则计数，两者分别展示。

支持查看、新建、编辑、停用、恢复和查看修改记录。模板使用稳定 ID 标识；不以名称推断身份或合并模板。
模板名称必填；模板新建默认启用，管理员可改为停用保存，这是本方案采用的初始默认值。
修改、停用和恢复使用版本检查并记录变更原因。停用、恢复不修改任何用户合同。

模板规则编辑尽量复用现有添加规则、规则列表及折扣解析组件。模板没有目标用户，价格提示使用当前
来源分组的一般价格语义，不借用某客户的特殊组倍率，不把预览金额保存为模板承诺价格。

#### 1.2 已有合同另存为模板

在已保存合同的管理员视图提供“另存为模板”：

1. 先校验管理员对源合同所属用户的管理权限。
2. 基于服务端读取的已保存合同版本载入模板草稿；如当前合同有未保存编辑，明确提示另存采用已保存版本。
3. 复制规则，名称可预填并修改；不复制用户身份、Key 绑定、合同启停状态或历史审计。
4. 管理员可调整草稿；填写模板名称及创建原因，校验通过后保存新模板。
5. 源合同完全不变。若复制来的来源已失效，保留并提示，修正或删除后再保存新模板。

另存为模板本质上仍提交普通模板创建，不建立持续的源合同关联，不增加合同与模板间的双向更新。

#### 1.3 使用模板创建用户合同

1. 管理员进入目标用户的新建合同流程，可选择空白创建或一个启用模板。
2. 选择模板后带入全部规则，合同名称可预填模板名称并允许修改；新合同初始设为启用。
3. 按目标用户当前上下文重新计算价格预览，不复制模板或源客户的历史预览金额。
4. 管理员可调整名称、规则与启停状态，填写本次创建原因；模板内容不被反向修改。
5. 失效规则保留原模型及来源标识并标注原因；不能因当前选项已不存在而从草稿中消失。
6. 保存通过现有用户合同创建入口执行，新合同拥有独立 ID、规则和版本。
7. 保存成功后展示新合同，提示可通过现有 API Key 管理功能绑定，不自动写入 Key。

只将“模板创建”的初始状态设为启用；不借本次功能改变既有空白创建和历史客户端省略字段时的行为。
新草稿已经修改时，再选模板属于替换整份草稿规则，必须确认后执行；取消保留原草稿，不做隐式合并。

### 2. 数据与权威边界

建议新增以下持久化结构，具体命名可按模型约定调整：

| 结构 | 主要字段与约束 |
| --- | --- |
| `customer_contract_templates` | ID、名称、启用状态、单调版本、创建/更新时间、创建/修改管理员；全站共享，无客户归属字段 |
| `customer_contract_template_rules` | 模板 ID、公开模型、渠道 ID、分组、`ratio_units`；唯一键为模板 ID + 模型 + 渠道 |
| `customer_contract_template_audits` | 模板 ID、版本、操作人、create/update/enable/disable、原因、变更前后快照和时间；只追加 |

用户合同建议增加可选的 `source_template_id`、`source_template_version` 与创建时模板名称快照。
普通创建合同保持无来源，已有合同无需回填。来源字段只解释“创建时从哪里开始配置”，不表示生成后的
规则仍与模板完全相等；不得作为运行时计费、授权、价格或合同更新的读取依赖。

模板规则复用现有八位定点折扣语义与规则规范化：非空规则集、精确模型名、同模型同折扣、
模型与渠道组合不重复、拒绝仅大小写不同的模型名。不得另写一套浮点折扣解析或校验。

模板保存采用新增/变更来源校验；已接受的来源后续失效可保留并展示，不能阻止停用模板。
模板恢复仅恢复选择资格，不承诺所有来源可用；套用时继续展示失效项，创建用户合同时校验全部最终规则。
因此模板的启用状态与来源可用性是两个独立概念，可用性由当前渠道事实推导，不持久化为另一套状态。

### 3. 管理接口与唯一写入入口

建议模板管理使用独立管理员路由：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/customer-contract-templates` | 分页查询、名称与状态筛选 |
| `GET /api/customer-contract-templates/:id` | 获取完整规则、版本和当前来源可用性 |
| `POST /api/customer-contract-templates` | 创建模板 |
| `PUT /api/customer-contract-templates/:id` | 带 `expected_version` 完整更新名称、启停和规则 |
| `GET /api/customer-contract-templates/:id/audits` | 分页查询修改记录 |

不提供删除接口；停用和恢复走同一个版本化更新入口。
所有接口服务端校验管理员身份；隐藏界面不能代替权限检查。模板列表不开放给普通用户。

为现有 `POST /api/user/:id/contract` 增加可选的模板 ID 与所选模板版本：

- 两项必须同时提供；服务端检查模板存在、启用且版本匹配。
- 最终规则由管理员编辑后的完整草稿提供，继续执行现有客户合同规则校验。
- 模板名称等追溯事实由服务端读取，不能采信客户端伪造的名称或操作人。
- 目标用户权限继续通过现有授权函数判定；另存模板读取源合同也必须通过相同权限边界。
- 现有合同更新接口不接受修改来源字段，不为模板建立另一套用户合同创建或更新接口。
- API Key 绑定和请求计费不新增任何模板查询。

### 4. 事务、并发与异常处理

#### 4.1 模板写入

在同一事务中完成模板版本比较、规则替换、版本递增和审计。
版本不符返回冲突；界面保留未提交草稿并提示重新查看当前版本，不自动覆盖或后台重试。
停用/恢复也递增版本并审计，保证创建合同能够识别套用期间的状态变化。

#### 4.2 用户合同创建

带模板来源的创建需要将模板状态/版本检查、用户合同实体、最终规则、来源快照及创建审计纳入同一事务。
与模板更新统一通过 `lockForUpdate` 协调；SQLite 使用项目支持的事务和条件写入保证，不能假定该库支持行锁。
用并发回归证明失效版本不会提交，而不是仅检查是否调用锁函数。

现有创建函数应保持唯一权威实现。仅在本地合同模型中做满足事务接入所必需的小范围调整：
模板事务逻辑放入新增文件；现有创建事务增加可选来源校验及保存接线，必要的最终来源校验放在写入事务内。
普通创建保留既有语义，不复制整套创建、审计与规则保存逻辑。

| 保存时情况 | 拟采用的处理 |
| --- | --- |
| 模板已经修改 | 返回版本冲突；保留草稿，重新选择并确认模板后再提交，不自动使用新内容 |
| 模板已经停用或不存在 | 拒绝本次模板创建并保留草稿；不能静默取消模板来源或绕过为普通创建 |
| 规则来源在编辑期间失效 | 明确返回失效规则，修正或删除后重新保存 |
| 最后一条规则被删除 | 按现有非空规则约束拒绝保存，不能生成空合同 |
| 保存失败 | 不留下部分合同、规则或审计；前端保留可修正内容 |
| 管理员无权管理目标用户 | 保存前拒绝，不因模板共享而放行 |

上述保存时冲突处置是实现建议。模板并发变更不等于用户同意更新草稿，系统不得静默替换。
来源校验以保存时可读事实为准；提交后渠道仍可能变化，按既有合同语义保留约定折扣，不新增渠道锁定机制。

### 5. 最小改动面与数据库兼容

| 位置 | 拟改动 | 必要性与上游同步影响 |
| --- | --- | --- |
| 新增 `model/customer_contract_template*.go` | 模板实体、规则、审计、版本事务与迁移入口 | 本地主体隔离，避免扩写原生模型 |
| 新增 `controller/customer_contract_template*.go`、`router/customer_contract_template_router.go` | 管理接口及鉴权 | 复用既有管理员合同路由注册点，仅增加注册调用 |
| 本地 `model/customer_contract_entity.go`、`controller/customer_contract.go` | 来源字段及唯一创建事务的窄接线 | 必须保障来源和合同原子写入，不引入平行创建器 |
| 原生 `model/main.go` | 一行独立模板迁移调用 | 新表必须注册到主库迁移；新增逻辑留在独立文件，上游同步仅需保留此调用 |
| `web/src/features/customer-contracts/` | 模板列表、编辑、API 与类型 | 本地功能目录承载，不改无关管理页 |
| `web/src/features/users/components/user-contract-drawer.tsx` | 新建时选模板、另存模板、来源与冲突提示 | 复用现有用户合同入口，编辑既有合同时不提供套用 |
| `web/src/i18n/locales/en.json`、`zh.json` | 必要中英文文案 | 只补齐项目要求的中英文，不扩展其他语言 |

实施时如发现可通过独立注册表完成迁移，优先减少原生文件修改。不得为本功能重排或重构原生鉴权、
分发、计费、Task 或 Token 代码。模板权限和来源校验留在管理员写入边界。

数据库兼容 SQLite、MySQL 5.7.8+、PostgreSQL 9.6+：GORM 建表与查询、事务使用统一锁封装；
默认启用由创建逻辑设置，不添加 `default:true` 布尔标签；规则和审计 JSON 编解码使用 `common.*`，
不引入特定数据库 JSON 类型、大小写排序规则依赖或手写自增主键。
迁移应支持已有数据及重复执行；不回填模板、不改写历史合同规则和绑定。

### 6. 验收与验证计划

| 验收场景 | 必须验证的结果 |
| --- | --- |
| 新建模板与共享 | 管理员甲创建，管理员乙可读取、编辑，审计准确记录各操作人；普通用户被拒绝 |
| 从已有合同另存 | 仅复制规则和可编辑名称；源合同、所属用户和绑定不变；越权读取失败 |
| 套用后定制 | 两个客户从同一模板创建，修改甲的折扣或规则不影响乙与模板 |
| 默认启用与多合同 | 模板创建初始启用；既有启用合同不被停用；所有既有 Key 绑定保持不变 |
| 空白创建回归 | 不使用模板时沿用现有行为，无强制模板来源或启用默认值变化 |
| 修改、停用、恢复模板 | 已生成合同内容、版本和绑定不变；停用后不能用于新的模板创建 |
| 来源失效 | 渠道停用/删除、模型移除、分组删除均保留规则并提示；不能静默跳过；修正后可创建 |
| 规则合同 | 同模型多渠道同折扣通过；同模型不同折扣、重复来源、大小写冲突、空规则与非法折扣拒绝 |
| 多人编辑 | 旧版本更新拒绝且不覆盖他人修改；修改、停用与创建竞争时不能提交已失效模板版本 |
| 原子提交 | 模板或合同写入中途失败，实体、规则、来源和审计不部分提交 |
| 来源追溯 | 用户合同记录所选模板的服务端身份与版本；用户定制规则仍可保存；后续不依赖模板计费 |
