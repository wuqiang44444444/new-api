# 上游同步后视频图片扩展配对修复记录

## 问题与目标

项目同步 NEWAPI `v1.0.0-rc.31` 后，需要同时核对已提交和工作树中的本地视频、图片、素材扩展，确认
ChannelType、北向入口、南向协议、异步任务、计费和管理端展示没有因上游核心逻辑变化而错配。本次修复
聚焦审计发现的确定问题：Seedance 被错当作 Chat 渠道测试、素材探针误修改视频 Channel 状态和
响应时间、不可用探针被误记成功、FunCloud 素材上传可能等待阻塞源、失败异步任务误保留预扣，
以及 SQLite 恢复后的跨表坏行。

目标是在不改写 NEWAPI 原生视频/图片合同的前提下，把代码修复限制在 Link 专属健康检查、素材 adapter
和异步计费副作边界，并为每个失败形状补充可观察行为测试；SQLite 仅做有备份的定向数据清理。

## 当前实际情况

### 已验证的配对事实

- `ChannelTypeTaskPlugin=61`、`ChannelTypeSeedanceLink=62`、`ChannelTypeAsyncImage=63`；CMCC 只读验证器和
  前端图标映射均引用类型常量，不再复制旧编号。
- Seedance 继续只由 ModelArk V3 北向入口和类型 62 的代码协议 adapter 履约；创建前 durable attempt、
  冻结连接、轮询 adapter 版本、终态结算和失败退款路径保持原边界。
- 普通图片继续使用 NEWAPI 原生 `POST /v1/images/generations`；类型 63 只负责严格图片中转协议，未建立
  第二套客户图片 API。
- 素材继续是按客户模型选择唯一 Seedance Channel 的无状态代理；本次健康检查只调用代码登记的素材
  只读列表探针，不创建收费视频或素材。

### 修复前问题

1. 通用渠道测试会把 Seedance 客户模型当作 Chat 模型请求；改用素材列表探针后，早期实现又把
   素材鉴权拒绝投影成视频 Channel 自动禁用，并把素材列表耗时写入通用视频响应时间。CMCC 等
   协议的素材与视频凭据可以不同，这两种状态变更都没有证明力。
2. 未配置素材协议、配置无效或上游不可达只写入 `localErr`，通用汇总却只检查 `newAPIError`，导致失败
   被计入 `Succeeded`。
3. FunCloud multipart 上传的 Provider `Do` 若在消费请求体前失败，生产协程可能仍阻塞在调用方
   `Source.Read`；同步等待生产协程结果会把一次明确的出站失败放大为长期挂起。
4. 异步 Task 进入 `FAILURE` / 取消 / 过期等应退款终态后，`AsyncBilling` 路径仍会执行 tiered/token 结算。
   当 Provider 没有上报用量时，任务会被错误标为 `settled` 并永久保留预扣；轮询连续失败达限分支还绕过了
   可重试的原子退款入口。
5. 2026-09-04 的 SQLite 结构损坏已经过恢复，但 `.recover` 产物中仍有 25 条其它表记录误落入 `logs`、
   1 条无效记录误落入 `customer_contract_audits`；它们虽不再破坏 B-tree，但会污染日志查询与审计统计。

这些问题位于当前工作树新增的健康检查和诊断增强路径，不是 rc31 对原生视频或图片 Router、DTO、Relay
合同的破坏。真实 Provider 创建、真实账单和生产灰度未在本次代码修复中执行，不能据单元测试写成生产已验收。

## 优化方案

### 已实施修复

1. **隔离 Link 健康语义**：Seedance 手动/自动测试不再退回 Chat 探针。素材只读探针无论成功还是 HTTP/业务码/
   transport 失败，都不自动禁用或启用承载视频履约的 Channel，也不改写通用 `response_time/test_time`。
   被自动禁用的 Seedance 不进入无法完成恢复证明的 passive-recovery 任务。
2. **修正健康汇总**：汇总同时检查 `newAPIError` 和 `localErr`；未配置素材协议、上游不可达或 Provider 拒绝都计为
   探针失败，但不由素材结果改变视频 Channel 状态。因禁用分支已被消除，同时删除了 Provider 业务码到 401 的
   启发式投影和人工 Gin Context，避免将素材凭据错误放大为视频停服。
3. **消除上传等待竞态**：素材生产协程先发布 source 结果，再关闭 pipe。Provider 已消费完请求体时可稳定
   区分 `wait_response`；Provider 在消费前失败时使用非阻塞分支立即返回 `upload_body`，上层随后关闭 source
   body，使生产协程退出。
4. **修正失败任务退款**：`settleTaskBillingWithState` 在所有 `ShouldRefundOnTerminal` 状态下直接交还统一退款入口；
   轮询连续失败达限和失败任务补偿扫描也改用 `refundTaskWithReconcile`。原子事务同时回退钱包/订阅、Token 和
   Task 计费状态，
   失败则保留冻结目标供 reconciliation 重试，不会重发 Provider 请求。
5. **清理 SQLite 恢复污染**：先通过 SQLite online backup 生成
   `one-api.backup-2026-09-05-post-recovery-cleanup.db`，再事务删除 25 条类型/时间列形状不可能的 `logs` 行与
   1 条空合同审计行。清理后 `quick_check` / `integrity_check` 均为 `ok`，坏行计数为 0。修复前的
   `one-api.backup-2026-09-04-1936-pre-recover.db` 保留不动。
6. **保持脱敏诊断**：日志只记录 operation、客户模型、Channel ID、协议、耗时、阶段、类别、HTTP 状态和
   经过字符集限制的 Provider code，不记录凭据、source URL、签名 URL 或原始响应。

### 回归验证

- 根模块 `go test ./...`、`go build ./...`、`go vet ./...`：通过。
- `relaykit` 独立模块 `GOWORK=off go build ./...` 与 `GOWORK=off go test ./...`：通过。
- 前端 `bun run typecheck`、`bun run test`（93 文件 / 557 用例）、`bun run build`（含 API docs 与 TokenAI 品牌产物校验）：通过。
- FunCloud 上传的“目标立即失败、源持续阻塞”“请求体完成后等待响应失败”“上传大小超限”三组测试重复
  运行 50 次：通过，无偶发挂起或阶段误分类。
- 新增测试覆盖：不可用 Link 探针计失败、素材探针不得自动启用/禁用视频渠道、不改写视频响应时间、
  passive-recovery 跳过 Seedance、Provider 业务码仅记失败、包装后 transport 诊断稳定，以及 FunCloud `30003`
  连续失败达限后 `FAILURE + 原子退款 + settled`，以及历史失败任务补偿扫描不绕过异步计费状态。
- SQLite 在包含当前 WAL 的在线视图上执行 `quick_check` 与 `integrity_check`：均为 `ok`；坏行清理后复核计数为 0。

### 剩余验收边界

- 当前本地库有 65 个 `SUCCESS + debt` 任务仍保留旧的“actual quota exceeds pre-consumed upper bound”错误。
  它们的冻结 `TargetQuota` 已存在，但 `attempts` 均已达到 10；旧扫描条件把所有达到 10 次的状态都永久排除，
  所以即使轮询继续运行也不会再选中这些 debt。现已只对可等待充值恢复的 `debt` 取消普通故障重试上限：
  到达 `next_retry_at` 后，`HasTaskPollingWork` 会继续触发系统任务，并通过原子入口按冻结目标尝试补扣；普通
  `failed` 状态仍保留原有 10 次上限。本次没有在代码验证阶段手工执行这笔真实计费副作用。部署并重启修复版本后，
  应核对 65 条记录是否转为 `settled`，以及差额日志是否一次且仅一次。
- 代码测试只证明本地合同和失败关闭行为；仍需在渠道手动停用和无业务流量窗口内执行只读 Provider 探针。
- 真实视频创建、图片生成、素材上传、Provider 账单和生产灰度会产生外部副作用或费用，不属于本次自动
  验证范围，必须按对应运维手册另行执行和记录。
