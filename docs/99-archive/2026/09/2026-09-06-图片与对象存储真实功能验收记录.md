# 图片与对象存储真实功能验收记录

## 问题与目标

使用本地数据库已有渠道及用户提供的 Azure 凭据，直接调用文档中的图片、视频、对象存储和
证据接口。区分真实 Provider 成功、网关客户账单、配置阻塞与尚未验证的能力，不以 mock
或编译成功替代生产验收。

## 当前实际情况

### 环境与边界

- 使用当前工作区构建的独立网关（端口 3507）、独立 SQLite、测试用户与独立证据目录。
  原网关（3501）、原客户余额和原数据库配置未修改。
- 只读复制所需渠道凭据及价格配置；测试渠道组在独立库归一为 default，禁止失败重选。
- 原数据库未配置对象存储，项目及运行环境未发现可用存储环境变量。使用用户提供的 Azure
  Shared Key 在隔离实例保存加密配置；容器为 `task-artifacts`，测试对象前缀为
  `acceptance-20260906`。连通性探针只删除自身随机对象，验收图片保留在此前缀。
- 报告不保存密钥、签名 URL、Task 私有字段、Provider 原始响应或客户数据。初始测试用户
  字段和不合该模型规范的 size 曾导致夹具失败，修正后才计入下表。

### 真实测试发现并修复的问题

1. **Azure 非 UTC 主机签名失效。** 当前 azblob SDK 将签名时间按字面 UTC 格式写出；
   直接传入本地 UTC+8 时间会使 SAS 生效时间落在未来。最初探针的鉴权读取成功而签名读取
   403，正确阻止配置保存。修复为使用同一 UTC 当前时刻计算开始与结束时间；补充 UTC+8
   回归测试，真实探针、生图交付和自然到期续签均通过。
2. **Gemini/Vertex multipart 编辑的南向 Content-Type 错误。** 图片正文已转换成 JSON，
   共享头部逻辑仍复制北向 multipart 类型，上游返回 multipart 解析错误。转换成功标记驱动
   图片专属头部设置；两个原生 adaptor 的 SetupRequestHeader 各增加一行接线，主体位于
   本地图片扩展文件，不改变北向请求或共享原生头部实现。新增两种适配器的实际 multipart
   转换回归测试；Gemini 中转真实复测成功。未来上游同步只涉及这两个头部接线点。

当前合同事实见[图片服务架构](../../../20-architecture/图片服务与异步Provider适配架构.md)。

### 尚未通过或未验证

- 官方 Google 图片调用返回 429，账户月度支出上限不足，客户扣款为 0；没有反复重试。
- FunCloud Lite 原配置缺少按次价格，按 Token 计算本次成功生成的客户 quota 为 0。
  这是明确的运营定价缺口；未擅自修改原库价格，不能将该场景记作计费验收通过。
- 视频请求与实际发送的证据都保留 `generate_audio=false`，但成品仍有非静音音轨。
  只能确认网关传递和展示正确，不能确认 Provider 已按参数关闭音频；应携带内部证据向
  对应 Provider 核查支持语义与实现，不自动转码去音频或改变统一协议。
- 已配置 Vertex 渠道没有发布图片模型，未修改其在线模型清单来冒充现有能力验收。
- 未找到 S3 配置或启用的音频模型；S3 真云调用、音频生成/转写真实证据仍未验证。
- Provider 财务账单、MySQL/PostgreSQL 实库、生产灰度、浏览器管理 UI 和异常网络下的
  恢复/退款没有本轮真实外部证据；对应代码回归测试不能替代这些验收。

## 优化方案

- 本轮修复回归：`go test ./service ./controller -count=1`、Gemini/Vertex 两个适配器测试
  及 `go test ./relay/... -count=1`；构建隔离网关并完成上述真实复测。
- 文档检查执行 `task docs:check`、`task ai:check`；公开文档验证沿用项目入口。
- 上述回归测试、相关包 `go vet` 和构建均通过；文档与 AI 检查通过，公开文档验证通过
  （20 个页面、30 个操作）。
- 部署方补齐官方账户额度、FunCloud Lite 定价、Vertex 图片模型和 S3/音频配置后，按同样
  最小请求补验；之后完成 Provider 对账和灰度，才可更新为完整生产验收通过。
- 测试结束已停止隔离网关并清除含凭据的临时验收数据库、配置和日志；原服务保持运行。
  Azure 验收图片按既定生命周期管理，不扩展为平台自动删除生产对象。
