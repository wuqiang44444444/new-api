# 账单计费架构复核与自定义表达式预览修复

## 1. 审计范围与验证

基线为 `3ed0f5c57`，开始审查时工作树干净。本次范围包括同步/任务计费、Seedance、异步图片、Batch、
钱包/订阅/合同折扣、消费及退款日志、看板、客户月账单、上游对账、明细与导出，以及管理价格和试算。
依据硬约束、计费表达式说明、异步计费与客户/上游对账架构；用户明确要求兼容路径无需修改。

结论：**在用 Seedance 当前价格已经完成新合同迁移；所有业务没有、也不应一律改成任务美元表达式。**
原生 Token、原生 TaskUsage、Batch 和历史冻结快照的金额单位有明确边界，继续保留兼容语义。
本次没有修改资金计算、结算状态机或真实数据库价格与余额。

| 链路 | 当前权威入口/事实 | 复核结论 |
| --- | --- | --- |
| 同步文本、多模态与同步图片 | `relay/helper/price.go`、`service/tiered_settle.go`、共享表达式引擎 | 保留原生 Token 归一与百万单位换算；不迁成任务 USD |

| 钱包、Token、订阅、合同 | 已有 funding 事务、冻结合同事实、checked quota 换算 | 未引入新的收费入口；相应本地资金回归覆盖 |

## 2. 已验证问题与修复

### P2：有效自定义任务表达式没有真实试算入口（已修复）

- 位置：`web/src/features/system-settings/models/task-usage-pricing-editor.tsx:118`；
  `service/billing_expr_preview.go:100`；新隔离实现 `service/billing_expr_task_preview.go:13`。
- 类型：需求缺口；置信度：高。
- 证据：旧预览依赖 `tryParseTaskVisualConfig` 的规范线性形状；解析失败直接返回“无法预览”。
  已迁移表达式的整体除法、嵌套分支、布尔条件和字典取价都可能是合法引擎表达式，但超出前端解析范围。
  原有后端管理员试算又明确拒绝 `u()`，因此不能仅放开前端提示。
- 最小修复：保留规范可视化编辑器；自定义部分调用同一个管理员只读 preview 接口，显式传入
  `task_usage=true` 与合成 `sample.usage`。新 service 文件复用 `ComputeTieredQuotaWithRequest`，
  `TaskUsageBilling=true`、`GroupRatio=1`，不创建 Task、资金会话或日志。
- 试算支持数字、枚举、布尔、嵌套分支、查表与固定 USD 价格；所有引用字段须提供样本，拒绝负值、
  非有限值、过大数量与嵌套用量对象。返回实际 USD、命中 tier 与额度饱和提示。
  可提供合成请求上下文及模拟时刻；计算使用完整表达式，不含分组及合同折扣。
- 界面不会因“解析失败”改写表达式，也不会把预算当实测。输入或表达式改变后旧结果隐藏，异步旧响应
  不覆盖新的计算结果。试算样本与真实预扣预算保持独立。
- 验证：整体除法、字典索引、布尔及常量价格与真实结算换算一致；缺用量、负值、非有限值和旧 Token
  变量错误单位试算均拒绝；界面覆盖 API 参数、布尔值、样本校验、结果失效和原表达式保留。

### P3：截图是未绑定渠道的旧价格，不是已迁移在用模型（已定位，保留配置）

- 位置：当前数据库配置的 `doubao-seedance-2-0-260128`；模型编辑器选择见
  `model/model_pricing_config.go` 的 `GetModelPricingSnapshot`。
- 类型：配置归属与展示误解；置信度：高。
- 证据：精确客户模型名没有任何 Channel 引用，但 options 中仍保留旧 `c/param` 表达式。
  通用插件模型目录仍提供其 usage schema，所以编辑器能显示 `u()` 字段提示；这不构成 Link 路由资格。
- 当前无渠道引用的表达式配置共 14 项，不等同于 14 个在用模型定价错误。不能按模型名将它们擅自归入
  Seedance，也不能因为看到旧语法而重写历史单价。
- 处置：保留配置供核对。任务 USD 试算识别到 Token 变量时明确报单位错误；用户可显式选择“按旧 Token
  规则试算”，复用原有 Token preview，并提供合成 body/headers 与 `tokens` 输出用量样本。
  页面明确该结果是旧规则试算，不会修改价格配置。没有自动单位 fallback，也不意味着该表达式可直接
  用于新的原生任务或 Link 渠道；实际启用必须按目标合同独立校验。
- 验证：默认不会把旧 `c*5` 当作任务 USD；显式旧试算的 100 万输出 Token 为 5 USD，配置不变。

## 3. 本地数据复核与未完成边界

本节为 2026-09-13 复核时点，实际库只读：

- 28 个 Link 客户模型全部为新美元表达式合同，旧 `c/param` 残留为 0。
- 26 个表达式价格仍有原生渠道引用；继续走相应原生计费合同，不因名称中包含 Seedance 就迁移。
- 14 个表达式价格无渠道引用，包含截图模型；本次不删除、不改价。
- 1397 个历史 Task 的计费状态均为 settled；1341 份带表达式快照仍是旧单位，56 份没有 tiered 快照。
  所有表达式快照均有 `expr_hash`，不为追求格式统一而重新写账。
- `task_billing_deliveries` 表已存在，待投递记录为 0；它不是余额账本，也不证明历史日志全部齐全。
- 173 条 unknown/held 仍未处置；缺 Provider 证明或明确损失承担决定，不能假定失败退款。
- 历史日志关联不明、外部数据库、真实 Provider 与真实支付验收继续保持未完成；不能仅凭本地回归
  宣称所有历史账单已完全勾稽。此前方案中的外部验收事项没有被本次预览修复自动关闭。

## 4. 单一逻辑与最小入侵

本次没有修改 `pkg/billingexpr`、原生 Relay、原生轮询、资金事务或账单聚合。后端试算入口仅增加显式单位
字段与小分支，任务试算集中在新文件；前端只在原本无预览的分支接入新组件，并复用已有上下文输入和 API。
后端依旧由同一引擎和统一 quota 换算负责金额。两个试算单位对应真实存在的两种冻结合同，不是两套收费实现。
原生及历史路径按用户要求兼容保留；本次不增加新计价配置、迁移开关、后台兼容层或数据库表。
