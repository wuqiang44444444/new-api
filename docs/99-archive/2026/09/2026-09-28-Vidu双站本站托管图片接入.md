# Vidu 双站本站托管图片接入

## 目标与结果

Vidu 国内、海外八个已登记型号使用统一 `image_url.url`，同时支持直接图片 URL 与本站托管图片
`asset://fhas_*`。复用既有图片素材库，不新增资源表、不复制上传实现，也不改客户计费表达式。
代码与本地回归已完成。本地渠道已启用托管协议，国内、海外 mini 各一条真实付费生成成功，
两站取图、成片获取及成功任务结算已通过；本次没有部署或修改 tokenai.page 线上渠道。
首次国内禁用 Key 请求的占款仍待正式退款验证，不能把本轮全部资金写成已闭环。

## 实现边界

- `seedance-link` 制品升为 `1.5.0`，Vidu 素材协议允许本站托管与 `none`，新建渠道默认本站托管。
  存量渠道不自动改写，历史任务继续使用冻结版本。
- 素材创建、查询、删除，以及组创建与查询复用宿主托管 adapter；仅普通图片，不开放音频/视频素材库。
- 首帧、尾帧、参考图保留角色、内容顺序和既有组合限制；允许托管引用与直接图片 URL 混用。
- 预扣前按用户、素材状态、对象位置与 HEAD 可用性接受引用，冻结对象事实；发送时替换为临时 URL。
  签名 URL 不进入 Task/attempt 长期快照。非本站 opaque 引用无法履约，在预扣前拒绝。
- 直接 URL 不访问本站存储、不自动导入素材库；`none` 渠道继续支持直接 URL。
- 国内与海外按同一用户共享既有托管复用域，不绑定 Provider 凭据；删除只阻止新的引用。
- 管理表单与公开 `api.assets` 由同一插件声明驱动，无需新增前端协议分支。

生产改动均在 Link 专属协议声明、托管校验和出站转换文件内；没有增加 NEWAPI 原生文件接线。
继续使用已有 Task/attempt 快照，不引入迁移或新的资金入口。

## 验证

- 国内、海外八型号的真实 HTTP 创建入口对接本地 Provider/对象存储夹具：映射正确、直接 URL 保真、
  托管引用转换、首尾帧角色、发送前 durable hold、成功 Task 素材快照。
- 两站分别验证跨用户、已删除、不存在、错误媒体槽位、未启用托管、对象缺失/不可用、存储位置变化与
  非本站 opaque 引用：无 Provider POST、无 attempt、钱包与 Token 余额不变。
- 创建响应不明只形成一次 unknown attempt，保留资金及无签名素材快照；删除不影响已接受事实。
- 宿主素材 adapter 验证国内创建、海外读取与删除，同用户共享、存储对象保留。
- 八型号渠道配置与公开托管元数据验证，保留 `none`，拒绝不匹配的 Provider 素材协议。
- 既有 Vidu 计费、字段校验及 FunCloud/Synlink 托管回归通过；制品编译检查补齐已有 Vidu 协议登记。
- 渠道表单 21 项测试、`relaykit` 独立构建、`task docs:check`、`task ai:check`、公开文档校验通过。

## 部署与验收

部署新代码及内置制品后，在国内、海外已有渠道中将素材协议由 `none` 改为“本站托管图片库”，通过
现有渠道保存流程启用。确认私有对象存储可用，并且签发 URL 可以被对应站点拉取。
先查询客户模型元数据，确认 `api.assets.supported=true`、`management_mode=platform_hosted`，再通过
`POST /v1/assets` 创建图片并把响应 `reference` 放入视频请求的 `image_url.url`。

最终生产验收需分别覆盖两站的图片创建、混合图片生成、成片取得与原有计费结算；本地夹具不替代这一验收。
调用合同见[Seedance V 视频](../../../../web/public/docs-content/zh/api-reference/videos/seedance-v.md)，
架构见[本站托管图片](../../../20-architecture/Seedance无状态素材代理架构.md#7-本站托管图片例外)。
