# Vidu 评审问题修复与交付验证

## 范围与结果

本轮按评审结论修复结果地址校验、历史对账恢复、当前启用模型的漏配定价和本机海外内容下载。
未提交新的 Provider 视频生成请求，未再次执行真实历史资金对账；本地开发服务已重启载入修复。
生产部署、供应商账单金额及用户最终验收不在本轮已验证范围内。

相关记录：[协议适配与合同覆盖](2026-09-28-Vidu协议适配与合同覆盖修复.md)、
[八型号实测与历史对账](2026-09-28-Vidu八型号实测与历史预扣对账.md)。

## 代码修复

### 结果地址校验

`relay/channel/task/seedance/vidu.go` 在宿主归一化阶段调用已有的
`relay/common.ValidateHTTPSVideoResultURL`，验证成功响应的 video_url 和可选 last_frame_url。
冻结插件仍不能替换宿主核实的任务身份和用量事实。不合法地址产生合同违例，进入待核查，
不接受这次用量、不设置结算目标，也不提前扣除最终费用。后续合法观察仍可正常结算。

新增真实控制器、SQLite 资金事务回归覆盖：非 URL、HTTP 地址、含 userinfo 的地址以及坏的末帧地址；
同时断言余额保持预扣、没有调整账单，恢复合法响应后只结算一次、没有第二次 Provider POST。
该校验检查结果合同；实际下载继续使用原有 DNS/IP、端口、重定向与 TLS 安全检查。

### 历史对账恢复

`cmd/reconcile-vidu-history` 先读取并核对持久化审计和 Task，只有首次接受观察时查询 Provider。
已审计任务重跑核对 reference、任务 ID、用量、原占款、目标金额和终态；一致后按既有目标继续资金
或日志交付，不再依赖 Provider 的任务保留期。冲突记录拒绝执行。

资金仍只经过 ApplyTaskBillingTarget / DeliverTaskBillingLog；备份、离线守卫、Root 校验和旧版本
白名单保持有效。恢复不重新解释冻结协议、模型、插件、价格与汇率。
工具入口参数解析局部化并注入输出 writer，使数据库恢复路径可直接验证。
新增数据库故障注入覆盖资金事务失败、日志投递失败和审计目标冲突；重试及再次重复均不查询 Provider，
退款恰好一次、钱包/Token/渠道统计与任务目标一致、账单恰好一条，备份权限为 0600。

### execution_expires_after 评审勘误

此字段已由 `middleware/modelark_video.go` 在资金 hold 与 Provider POST 之前校验
3600—259200，因此没有重复增加 adapter 校验。补充 Vidu 完整请求链回归：3600/259200 可接受，
3599/259201 拒绝且余额不变、无 create attempt、无 Provider POST。

本轮新增代码局限于已有 Vidu 专属文件、专属回归和离线工具；没有增加 NEWAPI 原生热路径接线，
没有修改 MiniMax 分支。合同全量目录及前端改动属于同工作树另一项任务，本轮保留。

## 本地定价修复

核对当前启用渠道上的 25 个 Seedance 客户模型，24 个专用渠道模型已使用对应官方人民币单价及
系统汇率表达式；原生渠道 39 的 `Seedance2.0` 仍为旧固定美元费率。
通过管理员 `PATCH /api/option/model_pricing`，携带 expected_version，只更新该模型表达式为系统
既有 `doubao-seedance-2-0-260128` 官方表达式。保留原生 c / _task 语义，不换成专用渠道 u() 表达式。
管理 API 回读一致，并产生既有定价变更审计。旧配置备份在本机
`/tmp/vidu-review-pricing-before.json`（0600）；没有全量覆盖其他模型选项或修改现有合同折扣。

本轮核对范围是当前启用的 25 个模型，不把未启用历史别名配置宣称为已验收。
本次价格修改仅作用于后续请求，历史任务继续使用原冻结价格；两条旧任务仍各 370518 quota，
八条矩阵仍合计 1038620 quota，均为 SUCCESS / settled。

## 海外网关交付

本机实际运行 Shadowrocket，其 TUN DNS 对结果域名及 CNAME 返回 198.18.0.0/15 的假 IP，
网关按既有 SSRF 规则正确拒绝。通过应用配置的真实 IP 域名列表新增两个精确域名并保存：

- `video.cf.vidu.com`
- `d3cs8aate1iukp.cloudfront.net`（当次 DNS 返回的 CNAME）

系统与 Go 默认解析均恢复为公网地址；未放行私网、未关闭 SSRF、未修改 TLS、未固定 CDN IP。
没有修改渠道或 Task 的冻结连接。若 Provider 以后更换 CNAME，部署环境须按实际 DNS 重新检查；
使用正常公网 DNS 的部署不需要本机 Shadowrocket 例外。

## 渠道编辑保存补充修复

用户随后在管理页面编辑 Vidu 渠道时遇到视频协议字段 `Invalid input`，保存被前端阻止。
下拉选项使用插件公布的协议，表单 Zod 枚举和 ChannelOtherSettings 类型却漏了
`vidu_modelark_v3`，导致已配置的协议可以显示但不能通过保存校验。
此前后端 API 配置、生成验收和合同选择器测试没有覆盖渠道编辑表单，这属于前端覆盖遗漏。

补齐 `web/src/features/channels/lib/channel-form.ts` 的协议枚举和
`web/src/features/channels/types.ts` 的协议类型，各增加一项，不放宽为任意字符串。
素材配对及声明版本校验仍使用原有插件配置，未引入新的协议推断或兼容回退。
这两处是渠道表单已有的协议接入点，仅增加一行枚举；不重构原生表单，后续同步冲突限定在该列表。

新增真实 React Hook Form / Zod resolver / 协议选择控件回归，读取仓库插件声明作为夹具，覆盖：

- 国内和海外各四模型渠道从读取、展示到表单提交，保持模型映射及连接地址，编辑时不发送空 Key 覆盖凭据。
- 创建/编辑载荷保留 Vidu 协议和插件声明版本；无需独立素材凭据。
- 从官方素材协议切换至 Vidu 时，默认素材协议为 none，清除不适用的素材 Region、Project 和 URL TTL。
- 对当前插件公布的所有视频协议执行完整表单校验，避免未来再次出现选项与校验枚举不同步。
- Vidu 不接受其他素材库；缺少声明、声明中未登记的协议、未知协议仍拒绝。

验证：渠道模块 26 个测试文件、114 项测试全部通过；`bun run typecheck`、改动文件 oxlint、
`bun run build`（包括 API 文档与构建产物检查）通过。表单回归使用本地模拟配置查询及提交回调，
未对真实渠道进行新增/改配，未产生 Provider 视频请求或费用。浏览器刷新后重新打开渠道编辑框即可使用。
