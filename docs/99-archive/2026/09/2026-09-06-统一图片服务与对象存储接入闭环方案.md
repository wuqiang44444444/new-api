# 统一图片服务与对象存储接入闭环方案

## 问题与目标

在既有 Gemini/Vertex 标准图片接口与类型 63 图片中转改造基础上，接入已实现的数据库对象存储配置、
S3 与 Azure Blob。用户授权本次编写方案后实施；不修改线上配置、价格、模型映射或调用真实 Provider。
目标是上传、后台执行、崩溃恢复、查询和五分钟签名交付形成闭环，不新增存储平台或第二套任务事实。

## 当前实际情况

- 图片已通过 `service/task_artifact_store_image.go` 统一能力接口调用 S3/Azure；输入暂存、结果逐图登记、
  授权查询和重新签名已有接线，不需要给 Gemini/Vertex 分别接 OSS。
- 开始实施时工作区已有新增修正：配置保存事务禁止在线更换已建立的存储位置，S3/Azure 使用逻辑对象键，
  物理前缀由适配器处理。保留这些用户改动并增加行为验证，不将其归为本轮新实现。
- 图片上传、HEAD、签名分别读取全局实例，可能跨配置 revision；回读尚未贯穿调用方上下文，超限读取
  可能静默截断；异步受理仅检查 Enabled，无法识别运行中存储不可写。
- 本地测试与代码事实不等同于真实 Azure/S3、HK/US 节点、Provider、账单或生产灰度验收。

## 优化方案

### 1. 保持业务边界

| 场景 | 合同 |
| --- | --- |
| HTTPS 参考图 | 仅校验请求结构与数量，原样透传，不下载或检查远程大小 |
| 异步文件/Data URL | 受理前落私有存储；引用进入 Task，执行时回读 |
| 同步 Google 图片 | 默认 b64_json；显式 url 保存后签名，不创建 Task |
| 异步结果 | 逐图落存储，默认 url，显式 b64_json 回读；不循环生成凑 n |
| 异步查询 | user_id + app_id 授权，逐图 HEAD，签发 300 秒链接；重查续签 |
| 存储故障 | 未发送任务暂停发送；已发送结果不明保持待核实，不重发、不换渠道、不自动退款 |

同步 URL 无任务查询凭据，不承诺续签；需要续签选择显式异步。OSS 不改变参数发布范围或管理员计费。
清理归部署方生命周期策略，不新增图片清理任务；五分钟是授权期限，不是对象保留期。

### 2. 单次操作与读取

在图片专属 service 接口中提供绑定当前不可变存储实例的操作上下文。输入暂存、后台执行/恢复、同步
结果投递和一次查询各使用同一实例；已有底层存储接口与凭据实现继续唯一，不增加配置历史或备用存储。
读取传递调用方 context，保留单次读取超时并遵守总预算；读取上限用 limit+1 检查，超限明确失败。
URL 输入不经过该读取边界。签名错误与下载错误不得泄漏完整签名地址。

### 3. 异步可用性

在新异步受理预扣前、后台任务 SENDING 提交前，检查绑定实例的轻量读写能力。使用独立健康检查命名空间
中的非客户小对象验证写入和读取；按存储实例短期缓存并串行合并探测，避免每次请求运行完整管理员探针。
探测有短超时，不覆盖客户对象、不删除图片；配置实例变化自然失效。该检查是运行保护，不是未来写入保证。
不可用时新请求 503、不预扣、不调用 Provider；排队任务仍由既有队列期限处理，恢复后继续原任务。
已经 SENDING 的任务不因探测失败回队，也不重新生成。

### 4. 位置与前缀

复用工作区已建立的在线位置冻结：初次启用后 backend、账号、端点、容器、前缀、region 固定，普通保存和
环境导入统一经过持久化入口；只允许同位置轮换凭据。在线关闭同样不绕过保护。首版不试图通过任务计数
证明历史/同步对象已无人依赖；迁移或停用在暂停业务、验证数据后离线维护。不添加自动迁移或双路径读取。
逻辑对象键贯穿上传/登记/Resolve/读取/签名；只有适配器构造请求时加一次 prefix。升级前须盘点旧 S3
未应用前缀的对象，必要时由部署方显式迁移；本次不操作已有对象。

### 5. 最小入侵与验证

主体仅修改图片专属 service、relay、查询与存储适配器、新增独立测试；不修改原生认证、公共路由、
DTO、资金算法、relaykit 或前端。任何必要的原生接线单独记录；不顺手清理其它工作区变更。

验证覆盖：S3/Azure 非空前缀与旧产物访问一致；配置位置变更拒绝/同位置轮换；跨实例更新不拆分一次操作；
读取取消与超限；存储故障不受理或发送、恢复后仅发送一次；逐图查询可用/删除/暂不可用与到期续签。
运行相关 Go 测试、必要竞态检查与构建，以及 `task docs:check`、`task ai:check`。真实存储与 Provider
验收另行授权执行，不以模拟测试代替。

## 实施与验证记录

### 本轮实现

- 新增 `service/image_object_session.go`，绑定不可变存储实例，增加按实例合并/缓存的读写探测；
  结果写入失败立即失效此前的可用性缓存。探测成功缓存 10 秒、失败 2 秒，总时限 5 秒。
- 图片读取/签名 API 显式传递 context；S3/Azure 回读使用同一 limit+1 字节边界。
  图片任务查询总预算 60 秒、单次 HEAD 最长 5 秒；不对客户参考图 URL 执行下载检查。
- 受理预扣前和后台领取前接入探测；异步 Google 参数校验不再混入同步 URL 托管可用性校验，
  北向 response_format 仍独立验证与冻结，禁用存储时显式 url 同样返回异步 503。
- 同步 URL 图片批次、输入暂存、后台执行/恢复和查询共用各自绑定实例。未新增 NEWAPI 原生热路径
  接线，未改认证、公共路由、DTO、资金算法、relaykit 或前端。原生同步默认行为保持不变。
- 保留并验证工作区并行形成的配置位置冻结、前缀与错误脱敏修正；相关已有测试不重复建立第二套。
  更新当前图片架构及运维说明，不归档本文件，不修改受保护目录。

新增行为测试位于 `service/image_object_session_test.go`、`relay/image_storage_admission_test.go` 与

多图可用/删除/暂不可用、跨 user/app 404、旧任务按查询时刻签发 300 秒链接和显式 Base64。

### 发布前剩余验证

真实 Azure/S3 应用内上传与客户下载、HK/US 节点网络和凭据轮换、外部 MySQL/PostgreSQL、Provider
生成/编辑与账单、真实链接自然到期续签、故障注入和灰度仍需单独验收。部署方须对旧对象位置与生命周期
完成盘点，不能用本地模拟测试推断现有对象已迁移。本轮未修改生产配置、数据库、对象或模型映射。
