# Seedance 渠道素材库边界设计

## 问题与目标

当前 Seedance 模型目录通过匿名 `api.assets.reuse_scope` 告知调用方哪些客户模型可以尝试复用同一份
Provider opaque 素材。现有 scope 主要由素材协议、服务地址、Project 和 Region 等配置生成，不能可靠
区分真实上游素材租户：两个不同租户可能使用相同协议、公共 endpoint、相同 Project 名和 Region，从而
得到相同 scope；凭据不同也不能证明租户一定不同，因为同一租户可以拥有多组 Key 或发生正常轮换。

本次目标是实现以下设计：

> 一个支持素材的 Seedance Channel 代表一个由管理员明确声明、并由后端冻结租户定义字段的
> 上游素材租户边界。只有同一 Channel 内的客户模型才发布相同的非空 `reuse_scope`；
> 不同 Channel 永远不发布相同 scope。

该设计优先消除跨租户误判，同时保持调用方自管的无状态素材代理，不新增 Asset/AssetGroup 持久化、
素材 binding、跨 Provider 探测或请求时 resolver。代码、管理端和当前事实文档已按本设计实现；真实
Provider 素材控制面已完成一轮全渠道验收；移动云 AICC 的素材组 404 已定位为固定路径尾斜杠错误并完成
真实渠道复测。真实视频引用、生产数据库迁移和客户通知仍必须在发布流程中单独完成，不能由本地测试替代。

## 当前实际情况

### 1. 已验证代码事实

Seedance 路由当前已经支持一个 Channel 配置多个客户模型：请求按客户模型找到唯一已启用 Channel，再由
`model_mapping` 解析精确 Provider 模型。公共目录也会遍历 Channel 的全部 Models，为每个客户模型生成
一份 `api.video` 和 `api.assets` 投影。

当前普通素材协议的公开 scope 由以下配置组成：

```text
asset_upstream_protocol
+ asset endpoint/base_url
+ asset_provider_project
+ asset_region
```

`AssetCredentialFingerprint` 的凭据参数当前未参与指纹；公共目录调用该函数时也没有传入凭据。结果是：
不同 Channel 只要上述公开连接配置相同，就可能发布相同 scope，即使平台没有证据证明它们属于同一素材
租户。CMCC 是当前例外：其 Channel 已有单独生成并持久化的随机 `asset_scope_identity`。

素材代理不持久化 `asset ID -> model/channel/scope` 映射。视频请求中的 `asset://<opaque-id>` 只做结构和
非空校验，随后原样发送给当前客户模型选定的 Provider。因此平台不能在请求时判断某个 ID 最初来自哪个
scope，也不能在不改变无状态合同的前提下返回本地 `asset_scope_mismatch`。

当前 Channel 更新事务会锁定旧记录后直接保存新字段，没有比较 Base URL、素材协议、Project
或 Region 是否改变。CMCC identity 通过 `OnConflict DoNothing` 保持不变，所以管理员可以在原
Channel 更换租户定义字段而不改变 identity。如果将该机制直接推广到所有素材协议，同一 scope
就可能在不同时间点代表不同租户；因此只有管理端提示而没有后端保存拦截不足以成立新设计。

公共目录当前无缓存，并在每个 Channel 的每个客户模型投影中计算 scope；CMCC 因此会逐模型读取
identity。目录被模型列表、模型详情、定价、客户合同和素材服务调用；其中普通 Seedance 模型列表的同一
请求还会加载两次目录。`ResolveAssetChannelCredential` 生成的 fingerprint 被素材 adapter 继续返回，
但两个上层调用点都丢弃它；公共 scope 切换到 Channel identity 后，这条第二返回值链不再有用。

#### 移动云 AICC 404 根因、优化与系统渠道复测

移动云素材协议使用固定 AICC V2 endpoint，不跟随视频 Channel 的 `base_url`。供应商创建素材组合同为：

```text
POST https://ecloud.10086.cn/api/openapi-maas/exp/aicc/v2/asset-group
```

旧 adapter 实际请求 `/asset-group/`。使用同一素材凭据、请求体和签名逻辑做最小 A/B 验证时，带尾斜杠
路径稳定返回 HTTP 404 和 `C404001`，无尾斜杠路径返回 HTTP 200 并生成非空素材组 ID。因此本次 404
不是服务未开通、租户权限不足或客户模型选路错误，而是 Provider 对固定资源路径进行精确匹配，尾斜杠
改变了请求资源。修复只把 `CMCCAICCV2Adapter.CreateGroup` 的固定路径从 `/asset-group/` 改为
`/asset-group`，没有增加双路径 fallback、404 重试、动态 endpoint、权限错误吞噬或其它 Provider 探测。
固定签名向量和 adapter 合同测试同步改为无尾斜杠路径。

修复后分两层执行真实复测，所有输出均省略凭据、opaque ID、签名参数和上游原始响应：

1. 直接运行修复后的 Go adapter，AIGC 素材组创建与单项查询均成功，测试组保留在 Provider 侧；
2. 使用当前代码构建本地测试实例，以工作区数据库受保护副本加载现有移动云渠道和测试 Token，通过
   `seedance-2.0-cmcc` 调用平台北向 `POST /v1/asset-groups`，返回 HTTP 201、`status=ready`；随后调用
   `GET /v1/asset-groups/{id}?model=seedance-2.0-cmcc`，返回 HTTP 200、`status=ready`，查询 ID 与创建
   结果一致；
3. 数据库中只有一个启用且匹配该客户模型与 `cmcc_aicc_assets_v2` 的 Seedance Channel，证明系统按
   客户模型走现有移动云渠道，而不是直连脚本或其它 Provider；
4. 北向响应字段严格为 `id`、`model`、`object`、`status`，没有返回 Provider、Channel ID、账号、
   Region/Project、协议、凭据或上游原始模型；
5. 测试实例的本地 `asset_groups` 行数前后均为 6，证明创建和查询没有重新建立平台 AssetGroup 事实；
6. 全程只执行素材组创建与单项查询，没有发送删除请求。新建素材组保留在 Provider 侧，opaque ID 仅保存
   于 Git 忽略且权限为 `0600` 的本地验收记录；测试完成后本地实例、数据库副本和响应文件均已清理。

相关代码与文档验证结果：素材 adapter、Router、Controller、Service、Model 定向 Go 测试全部通过；
移动云签名和路径合同、全部 8 种素材协议不发布组删除操作、北向路由不注册组删除入口的回归测试通过；
`bun run docs:validate`、`task docs:check`、`task ai:check` 与 `git diff --check` 均通过。

该复测证明当前移动云素材组控制面可通过平台完整北向链路履约，但不证明视频素材引用、真人认证或未来
租户权限永久有效；这些能力仍须按各自合同单独验收。

#### 2026-08-26 编辑渠道“测试素材库”出现 EOF

管理员在编辑移动云渠道时点击“测试素材库”，界面显示 `POST ...: EOF`。该操作实际调用移动云 AICC
`POST /asset/query`，请求体固定为第一页、每页最多一条、AIGC 素材组类型；它只验证现有素材库的只读
查询能力，不创建、更新或删除任何上游素材或素材组。

对实际服务链路进行无签名、无资源写入的对照探测后，结论如下：

1. 公网入口先到香港代理节点，实际 API 进程运行在美国节点；
2. 美国节点分别使用 HTTP/2 和 HTTP/1.1 请求移动云固定查询 endpoint，TLS 建连后均收到空响应；
3. 香港节点对相同 endpoint 和请求体可收到正常 HTTP 拒绝响应，证明路径、方法和请求体可以到达移动云
   网关；
4. 因此本次 EOF 发生在美国节点到移动云的出站网络链路或来源地址策略上，Provider 尚未返回可用于判断
   签名、服务开通或租户权限的 HTTP/业务响应。它不是此前 `/asset-group/` 尾斜杠 404 的复发。

管理端错误链路同时暴露出一个独立安全问题：Go HTTP 客户端的原始传输错误会携带完整签名 URL，旧
Controller 直接把 `err.Error()` 返回给界面。本次优化将素材连通性错误统一映射为稳定错误码和脱敏消息；
上游明确拒绝与网络不可用分别返回 `asset_action_upstream_rejected` 和
`asset_action_upstream_unavailable`。Controller 还增加失败关闭边界：任何未分类错误只返回通用连通性
失败消息，不再回显 URL、AccessKey、Signature 或 Nonce。原始错误只保留在内存错误链中供受控诊断，
不会进入管理端响应。

新增回归测试使用包含模拟 AccessKey 和 Signature 的原始 EOF 错误，验证响应只显示
`asset upstream is unavailable`、错误码正确且不包含主机、URL 或签名字段；配置未开通和配置无效也分别
映射为稳定错误码。Service、Controller 和移动云 adapter 定向测试以及 `git diff --check` 均通过。

当前代码修复解决错误信息泄露和错误分类，但不改变服务器出站路径。要让美国节点上的真实查询成功，
仍需选择一项运维措施：为该渠道配置受限且认证的香港/中国大陆出站代理、把实际 API 出站迁移到可用
地域，或由移动云确认并放行美国节点来源地址。代理配置属于 Channel 级连接设置，会同时影响该渠道的
视频与素材请求，上线前必须同时复测两条链路。由于本次错误页面已经出现过完整签名 URL，对应素材凭据
应轮换后再继续生产验证。

#### 素材组删除能力统一收敛

排障期间再次确认，素材组属于可能承载多人素材并可能发生级联影响的 Provider 资源。平台将素材组合同
统一收敛为创建与单项查询：

- 北向不注册 `DELETE /v1/asset-groups/{group_id}`，Controller 和 Service 不保留对应入口；
- 全部素材协议 adapter 不再暴露 `DeleteGroup`，不允许内部调用绕过北向边界；
- 公开模型元数据不登记 `delete_asset_group`，OpenAPI 的素材组单项路径只发布 `GET`；
- 单素材 `DELETE /v1/assets/{asset_id}` 仍按已验证合同保留，不能与素材组删除混淆；
- 平台不主动清理本轮创建的素材组，确需清理由 Provider 管理员确认归属和级联影响后执行。

回归测试遍历当前 8 种素材协议，验证任何协议都不会发布素材组删除操作；路由合同测试同时验证素材组
删除路由不存在。该边界没有增加 deprecated alias、空壳接口、兼容 decoder 或双路由。

#### 墨行与 TokenSave 数据库 Key 直测

在用户明确授权后，直接读取 Channel `#65`、`#66`、`#73` 的数据库 Key 发起真实请求。诊断输出只保留
HTTP 状态、脱敏错误和字段存在性，不输出 Key、Provider 资源 ID、原始响应或签名 URL。

- JoyCreator 创建素材组返回 HTTP 200 且 `error=null`，真实创建字段直接位于 `result.id/groupId`；旧
  adapter 只读取 `result.group`，因此把成功响应归一为空 ID，并由服务层误报为上游失败。修复后又使用
  500 像素以上的公开 JPEG 创建图片素材成功，素材删除成功。首次使用的小图片被 Provider 以“宽度需在
  300 至 6000 像素”明确拒绝，证明该失败属于输入约束而非鉴权。JoyCreator 没有已验证的素材组删除合同，
  本轮创建的诊断素材组保留在 Provider 侧。
- Moxing Volc 的素材与素材组列表均返回 HTTP 200。首次创建素材组时显式传入
  `ProjectName=default`，请求返回 HTTP 502，错误指向无权访问 `project/default`。上游确认创建素材组
  不应传该字段后，使用同一数据库 Key、同一业务参数，仅省略 `ProjectName` 复测即返回 HTTP 200 和非空
  素材组 ID。根因是 adapter 的错误硬编码，不是 Key 缺少通用素材组创建权限；创建组请求现已删除该字段，
  未增加 fallback 或权限错误吞噬。新建诊断素材组保留在 Provider 侧供核验。
- TokenSave 使用同一 Key 调用 `/assets/list` 返回 HTTP 200，但 `/assets` 创建稳定返回 HTTP 401 和
  `Missing Authorization header`。继续核对供应商资料后确认，该 Seedance 2.0 线路应使用独立的
  `/v1/asset` 组/素材接口，而不是 `/assets` 默认组代理。同一数据库 Key 调用
  `/v1/asset/group/create` 和 `/v1/asset/create` 均返回 HTTP 200，测试素材删除成功。代码将
  `tokensave_assets_v1` 唯一实现切换到 `/v1/asset`，删除旧 `/assets` adapter，并把素材组公开合同由
  `unsupported` 改为 `required`；没有保留双路径 fallback。最后直接运行修复后的 Go adapter，并从数据库
  读取 Channel `#66` 与 `#73` 的 Base URL 和 Key：两个渠道均完成素材组创建、图片素材创建和素材删除，
  四个创建步骤与两个素材清理步骤全部成功。素材组按平台保守合同不主动删除，诊断素材组保留在 Provider 侧。

#### FunCloud Provider 直测与系统渠道复测

在用户明确授权后，使用与系统验收相同的公开 JPEG，先按 Provider 文档直接调用 FunCloud，再通过
系统 Channel `#61` 的公共北向接口复测。脚本仅从本地受保护配置读取凭据，输出只包含状态、字段名和计数，
不输出 Key、opaque ID、文件 URL 或 Provider 原始响应。

Provider 直测结果：

1. 创建虚拟素材组成功；
2. `/material/virtual/upload` 返回 `assetStatus=Active`，同时返回非空 `assetUrl`；
3. 随后的 `/material/list` 返回同一素材及非空 `assetUrl`、`isAsset`，但实际响应完全省略
   `assetStatus` 字段；
4. `/material/group/delete` 能直接删除非空素材组并级联清理组内素材；前一轮残留测试组和本轮直测组
   均已通过该接口清理。

系统渠道复测结果：

1. 素材组和素材创建成功，创建响应为 `ready` 且包含匿名素材引用；
2. 后续 `GET /v1/assets/{id}` 返回 `processing`，但仍包含同一匿名素材引用；
3. Channel 内 Standard/Fast/Mini 三个客户模型均能查询同一素材，跨模型结果为 3/3；
4. 系统删除非空组返回 `409 asset_group_not_empty`，随后使用 Provider 已验证的组级联删除完成测试资源清理。

根因不是素材仍在 Provider 处理，而是两处合同不匹配：

- `funCloudMaterial.AssetStatus` 使用普通 string；Provider 列表省略该字段后，
  `normalizeFunCloudMaterialStatus("")` 固定返回 `processing`，没有结合非空 `assetUrl` 和 `isAsset=true`
  恢复 `active`。因此同一素材在创建响应是 `ready`，查询响应却回退为 `processing`；
- Provider 文档和真实直测都证明删除素材组会级联删除组内素材，但 `DeleteGroup` 先读取
  `materialCount` 并主动拒绝非空组，额外收紧了 Provider 合同，导致系统无法清理自己创建的 FunCloud
  素材。

另有一项模型兼容性证据缺口：当前 FunCloud 素材文档和视频文档只明确声明 Seedance 2.0 Standard 与
Fast 可以使用 `assetUrl`，没有 Mini 的素材引用说明。本轮 3/3 跨模型查询只证明 Standard/Fast/Mini
共用素材控制面连接，不能替代 Mini 使用同一 `asset://` 完成真实视频生成的证据。Mini 在完成一次受控的
付费视频引用验收前，不能仅凭同 scope 和查询成功对外承诺素材生成兼容性。

最终按多人共享下游的保守决策收敛：列表状态缺失时只在 `isAsset=true` 且存在合法 `assetUrl` 的情况下
归一为 `active`，其它缺失状态继续保持 `processing`。随后将素材组删除边界统一到全部 Provider：北向不
注册删除路由，公开元数据不登记删除操作，adapter 也不保留 `DeleteGroup`；平台不主动删除素材组，确需
清理由 Provider 管理员执行。上文真实直测中的级联删除只作为 Provider 风险证据，不再作为平台验收步骤。
没有新增级联确认参数、素材表、状态缓存、单素材删除伪实现或 fallback。Mini 的视频素材引用验收单独
执行，不把状态解析修复扩大成视频兼容性推断。

### 4. 修改前的多模型保存限制与本次确认

运行时路由和目录能够处理多模型 Channel，但本次修改前部分协议的管理保存校验仍要求一个 Channel 只能
包含一个客户模型：

- FunCloud Seedance 要求一个客户模型和一条精确 `model_mapping`；
- TokenSave、Moxing Media Task、Moxing ModelArk 统一要求一个客户模型；
- CMCC 要求一个客户模型并映射到唯一已登记 Provider 模型；
- 火山/BytePlus 官方协议目前可以使用多模型 Channel。

该限制来自早期“一客户模型一独立 Channel”的上线策略，不是运行时技术要求。本次确认后，保存合同改为：
Models、客户模型名称和 `model_mapping` 由管理员维护；代码逐项解析每个 Channel Model 的最终 Provider
模型，并只校验它是否属于所选协议的代码登记表以及是否兼容所选素材协议。单模型数量限制本身删除。

## 优化方案

### 1. 将 Channel 定义为素材租户的唯一配置边界

建立以下管理不变量：

```text
一个支持素材的 Seedance Channel
  = 一个上游素材租户/素材库
  = 一套素材协议、endpoint、账号、Project、Region 和凭据上下文
  = 一个匿名且稳定的 reuse_scope
```

具体规则：

1. 需要共享素材的所有客户模型必须配置在同一个 Channel；
2. 不同素材租户必须创建不同 Channel；
3. 不同 Channel 即使 URL、协议、Project、Region 或凭据看起来相同，也不得发布相同 scope；
4. 同一素材库如果被拆成多个 Channel，平台保守地视为不能跨模型复用；管理员需要先合并 Channel；
5. 平台不根据模型名、价格、Provider 名称、域名或 Key 推断两个 Channel 是否属于同一租户；
6. 素材协议为 `none` 时不发布 `reuse_scope`。

该规则选择“安全假阴性”而不是“危险假阳性”：同一租户被拆到不同 Channel 时只是暂时不能跨模型复用，
不同租户则不会再因为配置碰撞而被误报为同一素材库。

`reuse_scope` 表示“同一个由管理员声明且由平台保持稳定的 Channel 边界”，不是平台对 Provider
内部真实租户的独立证明。如果管理员将不同账号误配在同一 Channel，Provider 仍是存在性、权限与兼容性的
最终裁决者。

### 2. 使用每 Channel 随机稳定身份生成 scope

将现有 `ChannelAssetScopeIdentity` 机制推广到所有启用素材协议的 Seedance Channel：

```text
channel_asset_scope_identity = 密码学安全随机值，仅内部持久化
scope_format_version = "seedance_channel_asset_scope:v1"
reuse_scope = "asset_scope_" + hex(SHA-256(scope_format_version + "\n" + identity))
```

要求：

- identity 在 Channel 首次保存为支持素材时生成，存量素材 Channel 在切换公式前回填；
- identity 不能使用可枚举 Channel ID，持久化层保证不同 Channel 不会共享 identity；
- 同一 Channel 的所有客户模型读取同一个 identity；
- 不同 Channel 的 identity 必须不同；
- scope 不包含或泄露 Provider、账号、Project、Region、协议、凭据和 Channel ID；
- 正常凭据轮换不改变 identity，管理员通过在原 Channel 轮换凭据声明素材租户未变化；
- 更换账号、Base URL、Region、Project、国内/海外类型、素材协议或真实素材租户时，必须由管理员在原
  Channel 编辑界面确认替换素材租户，并原子生成新的 identity；
- identity 缺失时 fail closed：不发布 scope，并记录不含敏感信息的系统错误，不能退回旧配置指纹算法。

`scope_format_version` 是代码中的固定格式与域分隔常量，不是 API 字段，也不根据 Provider 或协议动态改变。
任何字节级变更都是新的 scope 格式版本，必须按显式迁移处理，不得双读或 fallback。CMCC 现有公式还包含
协议和固定素材 Base URL，切换到 v1 后其已发布 scope 也会全部变化。

不建议直接把 Key/AK/SK 加入 scope。原始凭据不能公开，凭据哈希仍会在正常轮换时改变，而且不同 Key
既不能证明租户不同，也不能证明租户相同。

#### 2.1 租户定义字段的后端替换约束

管理页文案只负责解释，权威约束必须在 Channel 更新事务内执行。后端在锁定已持久化 Channel 后，对新旧
配置做规范化比较：

- 当已持久化 Channel 的当前素材协议非 `none`，或者已有 `channel_asset_scope_identity` 时，Channel
  Type 继续拒绝修改；Base URL、视频/素材协议、`asset_provider_project` 或 `asset_region` 的变化必须
  携带显式替换确认，否则返回稳定冲突错误码和精确变化字段；
- “国内/海外类型”不新增独立字段，由 Volcengine/BytePlus 视频和素材协议组合表达；
- 从未配置素材、且没有 identity 的已持久化 Channel，可以首次从 `none` 配置为非 `none`，并在同一
  事务中创建 identity；已有 identity 的 Channel 经替换确认后可切换为 `none`、换协议或重定义租户
  边界，后端在同一事务中删除或重建 identity；
- 校验必须放在 Link 专属 model 逻辑并由所有管理保存入口共用，不能只放在 controller 或前端；
- 仅修改通用 Channel Key 或独立素材 AK/SK 时，必须在管理请求中显式声明“仅轮换凭据，素材租户未
  变化”；后端缺少该声明时拒绝保存。替换边界时使用单独的替换确认；后端将确认结果和具体边界字段而
  非凭据内容写入管理审计。

平台无法仅根据新 Key/AK/SK 判断它是同租户轮换还是换账号；显式声明是管理员责任边界，不是技术等价
证明。需要换账号或无法确认时，应使用同一编辑界面的素材租户替换流程，使新请求切到新的 identity 和
`reuse_scope`；旧素材不迁移，既有 Task 仍按快照执行。

### 3. 多模型 Channel 的协议校验

只对已经具备多 Provider 模型代码合同的协议放开多模型：

| 协议 | 候选处理 |
| --- | --- |
| FunCloud Seedance | 允许 Standard/Fast/Mini 等多个客户模型；逐项校验最终 mapping 目标；选择 `funcloud_material` 时任何最终映射到不支持素材模型（当前包括 2.5）的 Channel 保存失败 |
| Moxing ModelArk | 允许 Fast/Mini/2.5 多模型；逐项校验最终 mapping 目标和已登记 Provider 模型能力 |
| 火山/BytePlus 官方 | 保持已有多模型能力；同一 Channel 的所有模型共享素材连接 |
| CMCC、TokenSave、Moxing Media Task | 即使当前只登记一个 Provider 模型，也允许多个管理员客户模型；每个客户模型最终都必须解析到该协议已登记模型 |

多模型保存必须校验：

- Models、客户名称和 mapping 由管理员维护，代码不生成、改写或限制客户别名；
- 每个 Channel Model 按 NEWAPI 原生 mapping 语义解析，映射链有环时保存失败；未配置 mapping 时客户模型
  本身必须是已登记 Provider 模型；
- mapping 可以包含其它管理员条目，但只有 Channel Models 的最终解析结果参与协议资格判断；
- 所有 Provider 模型都由所选视频协议登记；
- 所有 Provider 模型都与所选素材协议兼容；
- 同一个已启用客户模型仍只能属于一个 Seedance Channel；
- 任一模型不满足条件时整个保存失败，不自动拆 Channel、不删除模型、不切换素材协议。

### 4. Channel 级配置一致性的代价

同一 Channel 内的模型会共同使用以下事实：

- 视频和素材凭据；
- Base URL、视频协议和素材协议；
- Group、代理、Header Override 和 Param Override；
- Project、Region、URL TTL 等素材配置。

如果两个模型虽然位于同一真实素材租户，但必须使用不同视频凭据、协议、Group 或覆盖配置，则不能安全
合并为一个 Channel。此时继续使用不同 Channel，并且不向用户声明跨模型共享。当前设计不为这种例外新增
跨 Channel `asset_library_id`、binding 或管理员自填 scope，以免重新引入平台无法验证的第二套事实。

### 5. 用户和管理员如何获知素材共享关系

#### 5.1 管理端

Seedance Channel 选择非 `none` 素材协议后，必须显示以下说明：

> 一个 Seedance 渠道代表一个上游素材租户。需要共享素材的所有模型必须配置在同一渠道；不同素材租户
> 必须创建不同渠道。系统不会判断两个不同渠道是否属于同一素材库，也不会跨渠道发布素材复用关系。

保存前展示确认摘要：

```text
素材库边界：当前渠道
共享模型：model-a、model-b、model-c

本渠道全部模型将发布相同的匿名素材共享组。
```

修改账号、Base URL、Region、Project、素材协议等租户定义字段时，管理端在当前 Channel 编辑界面显示
精确新旧差异；点击原保存按钮后复用现有确认弹窗，要求管理员确认旧素材可能不可用，再将显式替换确认
传给后端。凭据轮换弹窗仍要求管理员确认“仅轮换凭据，素材租户未变化”。两类确认均进入现有渠道审计。

#### 5.2 API 调用方

继续使用现有 `api.assets` 字段，不暴露 Channel ID，也不新增调用方可填写的 scope：

- `supported` 表示该模型是否支持素材操作；
- `operations`、`media` 和 `creation` 表示具体素材操作合同；
- 非空 `reuse_scope` 表示匿名素材共享组；
- 两个模型只有非空 scope 完全相同时，才属于同一个由管理员声明、并由平台强制稳定的 Channel
  素材边界；它不是 Provider 真实租户的独立证明；
- scope 不同或缺失时，调用方不得跨模型发送素材 ID；
- scope 相同解决的是租户选路边界，不保证每种素材类型、审核状态或引用都被每个视频模型接受，最终仍由
  Provider 裁决。

模型列表页面可以按 scope 聚合当前 Token 可见且 `available=true` 的模型，并把长 scope 显示为匿名短标签，
例如“素材共享组 A7F3”。短标签必须直接从 scope 哈希稳定派生：默认取前 4–6 位，当本次可见集合
内发生碰撞时逐步增加长度，最终可回退到完整匿名 scope。不得使用列表序号，否则 Token 白名单、Group 和
可用性过滤会使同一组的标签漂移。模型详情页显示同组模型，但不得显示 Provider、Channel、账号或上游模型。
`shared_models` 不建议写入模型 DTO：该列表受 Token 白名单、Group、可用性和目录过滤影响，可以由客户端
对本次返回的模型按 scope 分组，避免建立冗余且可能不一致的公共事实。

#### 5.3 请求时错误语义

平台仍不保存 opaque 素材 ID 的来源 scope，因此不能在视频请求时本地证明该 ID 属于当前共享组。错误 ID
只发送到当前模型选定的 Provider，Provider 的不存在、权限、审核或模型不兼容结果继续按现有脱敏错误合同
返回，不换 Channel、不探测来源、不 fallback。若要本地强制 scope 校验，就必须建立素材映射或要求可信
来源证明，这超出本设计并违反当前无状态素材代理边界。

### 6. 迁移路径

建议分阶段实施，优先避免跨租户假阳性：

1. 在 Channel 更新事务内实现租户定义字段不可变校验，并为凭据轮换增加后端强制的“租户未变化”
   显式声明与审计；
2. 扩展 `ChannelAssetScopeIdentity`，为所有已配置素材协议的 Seedance Channel 回填随机稳定 identity，
   包括当前停用但仍会进入公共目录的 Channel；
3. 公共目录统一使用 `seedance_channel_asset_scope:v1` 和 Channel identity 生成 scope，删除普通协议配置
   指纹、CMCC 专属公式与 fallback；
4. 保持已确认的多模型保存合同：FunCloud、Moxing、TokenSave 和 CMCC 都逐 Channel Model 解析并验证
   最终 Provider 模型，不恢复单模型数量限制；
5. 为已确认同一素材库且全部 Channel 级配置一致的模型创建合并后的多模型 Channel；
6. 先停用承载相同客户模型的旧 Channel，确认停用成功后再启用新 Channel。按当前两个独立管理操作执行
   会有短暂不可用窗口；直接先启用新 Channel 会被已启用客户模型唯一性校验拒绝。本设计不新增原子替换入口；
7. 火山官方第二套连接保持独立 Channel，不因 endpoint、Project 和 Region 相同而与第一套合并；
8. 通知 API 调用方刷新模型元数据缓存；包括 CMCC 在内的所有旧 scope 都不能继续作为判断依据；
9. 真实 Provider 分别验证同 Channel 跨模型查询和视频引用，不把代码完成写成生产验收完成。

迁移期间允许短暂出现安全假阴性：尚未合并的同租户 Channel 会得到不同 scope。不得为了保持旧 scope
而继续使用配置指纹或增加双读、alias、兼容 resolver。

历史 Task 已冻结创建时的 Channel、连接、协议和凭据事实，不能因新 Channel 合并而改写。Provider opaque
素材 ID 不迁移、不物化；只要合并后的 Channel 仍指向同一真实素材租户，既有 ID 是否可见由 Provider
判断。

### 7. 最小入侵实施边界

改动限制在 Link 专属新增文件和窄接线：

- 扩展 `model/channel_asset_scope_identity.go` 的适用协议，或新增通用 Seedance Channel scope 文件；
- 新增 Link 专属租户边界校验文件，在现有 Channel 更新事务中只保留一个窄调用点；
- `model/channel_seedance_public_catalog.go` 在进入模型循环前一次批量读取所有 Channel identity，构建
  `channel_id -> reuse_scope` 映射并传入模型投影；不按模型或按 Channel 发生 N+1 查询；
- 普通 Seedance 模型列表在同一请求中复用已加载目录，不再为过滤和投影分别查询；
- 目录切换后将 credential resolver 收敛为 `(key, error)`、素材 adapter 收敛为 `(adapter, error)`，删除
  最终无消费者的 fingerprint 返回链；`AssetCredentialFingerprint` 只能在公共目录已不再使用后删除；
- 在协议专属校验文件中逐项验证多模型 mapping；
- 管理端 Seedance Channel 表单增加边界说明、凭据轮换显式确认、后端拒绝错误展示和相关 i18n；
- 模型列表/详情按现有 scope 做只读展示，短标签使用 scope 哈希的可变长度前缀处理当前可见集合内碰撞；
- 更新当前架构、素材支持矩阵、公开 API 文档和运维验收手册。

不得修改 NEWAPI 原生模型分发和视频入口来识别素材 scope，不新增素材表、binding、列表、resolver、运行时
跨 Channel 校验或 fallback。

### 8. 验证方式

实现后至少验证：

1. 同一 Channel 的全部素材模型返回相同且非空的 scope；
2. 不同 Channel 即使协议、URL、Project、Region 和测试凭据配置相同，也返回不同 scope；
3. 已有 identity 的 Channel 修改 Type、Base URL、视频/素材协议、Project 或 Region 时后端拒绝保存，
   identity 和 scope 不变；
4. 没有 identity 且素材协议从未非 `none` 的 Channel，首次启用素材时在同一事务创建 identity；
5. 凭据轮换缺少“租户未变化”显式声明时拒绝；声明完整时轮换成功、scope 保持稳定且审计不含凭据；
6. 新建素材协议为 `none` 的 Channel 不生成 scope；已有 identity 的 Channel 不能切回 `none`；
7. identity 缺失时不回退配置指纹；
8. CMCC 和普通素材协议都使用同一 v1 公式；迁移通知明确旧 CMCC scope 同样失效；
9. FunCloud Standard/Fast/Mini、Moxing Fast/Mini/2.5，以及当前单 Provider 模型协议的多客户模型
   mapping 均按各自协议逐项校验；映射链和无关管理员条目不改变最终协议资格；
10. 不支持素材的 Provider 模型不能混入启用素材协议的 Channel；
11. 先启用包含重叠客户模型的新 Channel 会被唯一性校验拒绝；先停用旧 Channel 后可启用新 Channel；
12. 不同 Channel 的模型在 UI 中不显示为同一素材共享组；同一 scope 的短标签不因可见模型过滤而变化，
    短前缀碰撞时能稳定延长区分；
13. 当前 Token 不可见或 `available=false` 的模型不进入普通用户的同组模型展示；
14. 使用同 Channel 模型 A 创建的素材，能由模型 B 查询并参与一次真实视频创建；该结果只记录为当前
    Provider 验收事实，不扩大为永久兼容承诺；
15. 错误 opaque ID 仍只发送给当前 Provider，不查询本地素材映射、不换 Channel；
16. SQLite、MySQL 和 PostgreSQL 的 identity 创建、批量读取、唯一性和删除路径均通过验证；
17. 通过 SQL 日志或定向性能检查确认目录构建不再按模型读取 identity，模型列表的单次请求不重复加载目录；
18. 移动云 AICC 素材组创建固定使用无尾斜杠的 `/asset-group`，签名路径与实际 HTTP 资源完全一致；
19. 任一素材协议均不发布素材组删除操作，北向不存在素材组列表、更新或删除路由，adapter 不保留
    `DeleteGroup` 绕行入口。
