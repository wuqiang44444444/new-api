# FunCloud 新版视频协议与统一素材库实施方案

## 1. 问题与目标

将 FunCloud Seedance 2.0、Fast、Mini、2.5 接入新版统一视频 API 和统一素材库，支持同一渠道配置四个
客户模型，以同一素材引用完成跨模型生成，并将参考图片上限由旧 2.0 的 3 张扩展为 9 张。

本方案已进入实施，代码与自动测试已完成首轮验证，真实渠道验收进行中，详见第 8 节。
用户已明确确认：素材接口与当前版本保持一致，仅统一四模型的素材使用范围。因此只升级视频协议，
素材继续使用 `funcloud_material` 与现有 adapter，不新增素材版本、接口或迁移流程。

实施遵守最小入侵原则：继续使用 Seedance Link、现有 ModelArk V3 北向、无状态素材代理、Task、资金和
日志底座；不修改 NEWAPI 原生视频入口，不新建任务系统、客户素材库或通用协议映射框架。

## 2. 当前实际情况与证据

### 2.1 已读取的外部资料

- [全系视频 V3](https://docs.leonecloud.com/docs/seedance-2-5-v3-protocol)：四模型统一端点，snake_case；
  通用输入表为 9 图、3 视频、3 音频；页面标注更新于 2026-09-06。
- [Mini 文档](https://docs.leonecloud.com/docs/seedance-2-0-mini/)：页面本身介绍 V2，明确 Mini 可以使用
  `assetUrl`，不能把该页面的 V2 创建路径当作统一 V3。
- 用户进一步确认素材协议与当前版本一致，四模型可以统一素材库。以此作为实施范围依据，复用现有
  素材路径、鉴权、字段、状态、上传方式、数量/字节约束和组策略，不再等待新版素材文档。

共享素材能力属于用户确认的设计前提，四模型实际引用效果仍纳入验收；视频 V3 的九图声明也不能作为
旧视频 V2 接口九图已验收的证据。本次不扩展素材控制面的格式、上传大小或操作范围。

### 2.2 本地代码事实

| 位置 | 当前行为 | 需要改变的边界 |
| --- | --- | --- |
| `relaykit/dto/upstream_protocol.go` | `funcloud_seedance` 按模型选择 V2 路径 | 注册明确的 V3 视频协议与对应传输路径 |
| `relay/channel/task/seedance/funcloud_models.go` | 旧模型名；2.0 为 3/1/1 | 新协议模型登记、9/3/3 及分辨率差异 |
| `relay/channel/task/seedance/thirdparty/funcloud/` | camelCase 请求、V2 包装响应 | V3 请求、创建结果、查询状态和用量解析 |
| `pkg/publicmodel/video.go` | 另有一份 FunCloud 视频限制 | 新协议运行时与公开投影共读单一登记 |
| `model/channel_seedance_funcloud.go` | 禁止 2.5 配对 `funcloud_material` | V3 视频与既有素材协议配对，允许四模型共用 |
| `relay/channel/task/seedance/assets/funcloud.go` | V2 素材组、上传、列表中匹配单项；更新/删除不支持 | 直接复用现有 adapter 和素材合同 |
| `model/channel_seedance_public_catalog.go` | 公开素材操作和复用域投影 | 同步新协议的实际操作、组策略和复用范围 |
| `web/src/features/channels/lib/seedance-protocol-pairing.ts` | 前端也阻止 2.5 素材配对 | 新组合与服务端校验保持一致 |

已有 Channel 可以配置多个客户模型，并不需要新建“统一渠道”类型。现有异步任务冻结连接、协议和计费
事实；素材是调用方自管的 Provider opaque ID，不需要创建跨模型素材映射表。

### 2.3 实施前核对项

| 项目 | 已确定的处理 | 验收要求 |
| --- | --- | --- |
| 素材 API 版本与接口 | 保持 `funcloud_material`、现有路径/鉴权/字段/状态 | 现有素材合同测试回归 |
| 四模型共用范围 | 同一素材连接与组配置供四模型使用 | 同一个 asset 分别完成四模型视频生成 |
| 既有组和素材引用 | 原组 ID、asset ID 与 `asset://` 引用保持原值 | 既有素材在视频 V3 中继续使用，无重传或转换 |
| 上传方式与大小限制 | 复用当前实现 | 原有安全回源和边界用例通过 |
| 视频 V3 的计费与用量 | 独立核对账号报价及按秒/Token 结算依据 | 不将缺失 Token 当作零或推算 Token |

素材版本和路径不再是待确认项；账号计费证据与真实跨模型生成属于实施验收内容。

## 3. 优化方案

### 3.1 唯一协议与模型登记

视频协议拟登记为 `funcloud_modelark_v3`，这是本地代码协议标识，不是供应商字段。
内部 transport profile 明确登记为 FunCloud V3 专属 profile，仅服务 adapter 复用与任务冻结，
不新增第二套管理员配置；不得映射为 official profile，也不得复用旧 V2 profile 触发旧请求转换。
素材协议继续为 `funcloud_material`，直接复用 `FunCloudMaterialAdapter`。新增视频 V3 与该素材协议的
合法配对，四模型共享现有素材能力；不增加素材协议枚举、新 adapter 或版本兼容分支。

| Provider V3 模型 | 建议隔离测试客户模型 | 分辨率 | duration | 图/视频/音频数量 |
| --- | --- | --- | --- | --- |
| `seedance-2-0` | `test-fc-v3-standard` | 480p / 720p | 4–15 | 9/3/3 |
| `seedance-2-0-fast` | `test-fc-v3-fast` | 480p / 720p | 4–15 | 9/3/3 |
| `seedance-2-0-mini` | `test-fc-v3-mini` | 480p / 720p | 4–15 | 9/3/3 |
| `seedance-2-5` | `test-fc-v3-25` | 480p / 720p / 1080p | 4–30 或 -1 | 9/3/3 |

这些测试名是拟定值，配置前核对没有重名。正式客户模型名可以保持不变，由 `model_mapping` 精确映射到
上表的 V3 Provider 模型。禁止通过模型后缀猜测协议，禁止将旧 `seedance-2` 自动作为 V3 别名。

在独立的共享登记文件中表达新协议的模型范围、数量、时长、分辨率和稳定的计量类别，供运行时校验与
公开元数据共同读取；优先放在独立可构建的 `relaykit` 或现有无反向依赖的登记层。只归一新增 V3 的事实，
不借机重构其他 Provider。价格仍由现有价格设置表达，不能硬编码进模型能力表。

### 3.2 视频请求和响应

统一南向创建为 `POST /api/v3/contents/generations/tasks`，查询为同路径追加 `/{id}`。
沿用北向的类型化请求与模型映射结果，必要转换隔离在 FunCloud 专属新文件中。

1. 新请求显式发送 V3 Provider `model`，不再按模型拼接不同创建路径。
2. 保持图片顺序、role、URL 与 `asset://` 原值，不截断第 4–9 张，不自动拼图，不将素材转为 OSS URL。
3. 普通图片参考允许至 9 张；第 10 张在预扣和 Provider I/O 前返回 400。首尾帧数量及组合仍按既有北向合同
   验证，不能把“参考图最多 9 张”误用为“允许 9 张首帧”。URL 图片和 asset 图片合计计数。
4. 已发布字段按北向含义转换，显式 `false/0` 通过指针保留。缺省值以北向合同为准并在需要时明确发送，
   不因 V3 默认音频 true、比例 adaptive、2.5 时长 -1 而静默改变现有客户请求语义。
5. 不把 Provider 的 `real_person_mode`、`task_nickname` 等私有字段开放为客户端透传口。已发布但 Provider
   不生效的字段按既有合同处理，不反向要求客户改变请求形状。
6. 参考视频需单独审查：V3 的自动模式可能强制编辑、adaptive 与智能时长。adapter 必须保持北向已发布
   “参考视频”的语义；只有文档与实测证明等价的转换才使用对应任务类型。不能以静默改变时长解决差异，
   也不能将某个组合不支持扩大为整个模型不支持。
7. 新 V3 创建返回顶层 `id`；查询解析 `submitted/running/succeeded/failed`、`content.video_url` 和可选
   `usage`。复用现有正常化结果类型，不建立第二套任务状态。用 HTTP 与错误对象判断确定性失败；没有可信
   ID 的不确定请求进入 unknown，不自动重发。

视频仍是异步接口：创建返回任务 ID，随后查询结果。本次不新增“同步生成视频”入口或长连接等待模式。
素材接口沿用现有单资源调用方式；素材处理未完成时返回对应处理状态，由调用方查询。

**任务生命周期与复用范围：**只复用已确认等价的 ModelArk DTO、结果类型和解析逻辑，不继承官方渠道资格。
新 FunCloud V3 profile 明确声明支持内容读取；取消排队任务、删除终态任务在本次已确认文档未提供对应
操作的情况下保持不支持，北向按既有明确错误返回，不发起供应商 DELETE。公开模型操作与运行时读取相同
生命周期能力。北向任务列表始终读取主数据库的 `user_id + app_id` Task，不代理供应商列表。
单项查询和内容读取使用冻结的 V3 协议与连接，并沿用平台任务 ID 和脱敏投影。

### 3.3 复用现有素材协议，统一四模型

一个视频 V3 Channel 配置四模型，配对既有 `funcloud_material`，共用同一素材连接与组策略。解除新协议组合下对 2.5 的人为排除，
不再按模型名字分成 2.0 素材渠道和 2.5 无素材渠道。旧协议配置保持原有已验证范围，直到明确迁移。

| 北向操作 | 实施要求 |
| --- | --- |
| `POST /v1/asset-groups` | 复用现有普通组创建；真人流程保持当前发布范围，不新增能力 |
| `GET /v1/asset-groups/{id}` | 复用现有 adapter 的列表内精确单项匹配，不公开列表 |
| `POST /v1/assets` | 复用现有安全回源与上传，返回 opaque ID 和引用，不持久化 source URL 或二进制 |
| `GET /v1/assets/{id}` | 复用现有状态、身份和脱敏错误映射，不另建状态规则 |
| `PATCH /v1/assets/{id}` | 保持当前不支持，本次统一不新增更新操作 |
| `DELETE /v1/assets/{id}` | 保持当前不支持，不将单素材删除扩展混入本方案 |

不新增素材列表、客户 Asset 表、binding、resolver、自动复制/迁移或跨账号探测。
`DELETE /v1/asset-groups` 仍不发布；不调用供应商级联删除组来模拟删除单个素材。

普通素材组策略继续以 `GeneralAssetGroupPolicy` 为唯一事实源，沿用现有 `default_fallback`：
显式非空组 ID 优先，未传/空白才用 Channel 默认组，错误显式 ID 不回退。视频协议升级触发的本地默认组
配置清理由下述租户替换流程处理；管理员确认同域后重新关联原 Provider 组，无需在供应商处重建组。
没有默认组时仍只能由管理员手工创建或复用，业务请求不自动建组。

同一 Channel 下四模型投影相同匿名 `reuse_scope`，前提是确为同一素材连接和相同引用格式。
`reuse_scope` 只是可尝试复用提示，不能变成请求时的所有权/兼容性验证。不得通过手工复制 identity
伪造两个账号或不同素材库可互用；更换素材租户时按现有机制更新作用域和默认组配置。

素材没有版本迁移：供应商的既有组 ID、asset ID 与 `asset://` 引用保持原值，不要求重建组、重新上传或
转换引用。但这些 Provider 资源与平台 `reuse_scope` 是不同概念，不能承诺视频协议升级后复用域不变。

按现有架构，修改 `video_upstream_protocol` 会触发素材租户替换确认。未确认时保存失败且无配置变化；
确认后在同一事务更新配置、生成新 identity，并清除本地默认组关联。因此迁移后四模型共享新的匿名
`reuse_scope`，管理员确认同一供应商素材域后重新关联原组 ID。该流程不删除 Provider 组或素材。
本方案不豁免视频协议变更的租户边界，不复制旧 identity，也不新增“同域升级”特殊迁移分支。
如采用新 Channel 承载 V3，同样使用该 Channel 自己的 identity，并手工关联确认可用的 Provider 组。

同一素材“查询成功”不足以证明视频可用，必须用既有 asset 引用完成四模型视频 V3 生成验收；
失败应诊断具体接线或配置原因，不自动重传素材。

### 3.4 计费、资金与用量

供应商 V3 文档描述 2.0 系列按秒计费、2.5 智能时长按 Token 计费。供应商收费口径与平台客户价格分别
记录，不能把供应商变化直接当成修改客户价格的授权，也不能继续假设所有成功响应都有 Token。

- 优先复用现有按秒/固定参数计费路径；确认需要扩展时，只在 Seedance 专属计量接线处新增窄分支。
  固定秒数按创建时冻结的有效时长、分辨率、输入视频档及客户单价预扣和结算，不将秒数写成 `c`。
- 用量采集与客户计价单位分离：所有合法终态用量均进入耐久证据，即使任务按秒或按次收费也不跳过采集。
  复用 `relay/channel/task/seedance/thirdparty/usage.go` 的现有归一入口，不另写 V3 字段白名单或推导器。
  优先 completion/output，缺失时使用合法的 total−prompt，只有 total 且无 prompt 时使用 total；
  prompt-only、total 小于 prompt 等情形不伪装为输出量，多个字段不相加。原字段与来源按现有机制保留。
- 归一后按创建时冻结的计价方式结算：按秒/次仍按冻结数量收费，Token 用量只作为证据；按 Token 才使用
  归一出的合法实际用量。确实无合法用量时保留预扣事实并沿用既有待核实处理，不能把 completion 字段
  单独缺失直接判成无用量，也不能零扣费、伪造用量或退款。缺用量不改写已确认的视频成功状态。
  首次成功结算的终态用量不被后续查询覆盖；重复结果幂等处理，差异按现有合同异常审计。
- 2.5 固定秒数与智能时长、输入视频场景分别确认单价和计量依据；未完成确认的组合不开放付费流量。
- `frames` 只有在北向已发布且与现有合同一致时才适配其计费秒数；不能因为上游支持就新开放该字段。
- 全部可控数量先校验范围，quota 经过现有 checked 转换与饱和审计；预扣和结算同时验证，禁止负数费用。
- Provider POST 发出前建立 durable attempt，hold 与 sending 原子提交；可信 ID、Task 创建和 hold 转移
  原子完成。明确鉴权/参数拒绝与 unknown 分开处理，未知结果不自动退款、重发或换渠。

本次不修改表达式引擎，不新增平行账本，不以客户 quota 伪造供应商成本。

### 3.5 最小实现落点

| 模块 | 计划改动 | 最小侵入方式 |
| --- | --- | --- |
| `relaykit/dto/` | 新视频协议及专属 transport profile、固定路径、必要模型登记；复用素材协议枚举 | 新文件为主，既有 switch 仅登记分支 |
| `relay/channel/task/seedance/` | V3 验证、转换、结果解析及用量归一；生命周期沿用通用规则、冻结版本登记与公开投影 | 专属新文件，复用现有 TaskAdaptor/ModelArk 结构 |
| `relay/channel/task/seedance/assets/` | 复用现有 FunCloudMaterialAdapter；V3 配对回归位于 model 层 | 原则上不修改素材传输实现，不新增 adapter 或中间层 |
| `model/channel_seedance_funcloud.go` | 新模型枚举、协议配对、四模型统一素材校验 | 只改变新协议范围，不放宽其他 Provider |
| `model/channel_seedance_public_catalog.go`、`pkg/publicmodel/` | 统一公开数量、操作和组策略 | 只读同一登记，不复制第二份 V3 限制 |
| `web/src/features/channels/` | 新协议选择、配对、移除新组合下 2.5 禁用条件 | 延续现有表单，新增文案遵循 i18n 技能 |
| Seedance 专属 service/计费入口 | 必要的按秒/Token 结算接线 | 复用已有机制；原生热路径原则上零改动 |

每个必须修改的原生文件在实施记录说明必要性、最小接线和上游合并影响。不得为统一 FunCloud 重构
所有 Provider、原生视频或图片模块。

## 4. 实施顺序与迁移

1. **P0：锁定配置和计费。**记录当前素材连接、默认组和可复用的既有引用，确认账号的 V3 计费依据。
   素材继续使用当前合同，无需新增素材版本或字段映射表。
2. **P1：视频 V3。**实现新协议与单一模型登记，覆盖四模型请求/响应和 9 图校验；通过本地 API 的模拟
   Provider 合同测试，断言真正发出的南向 payload，而非只测 DTO。
3. **P2：统一素材。**复用现有 adapter，完成视频 V3 与 `funcloud_material` 的四模型配对，
   更新服务端校验、公开元数据与管理表单，沿用现有租户替换确认和默认组重新关联流程，保留 Provider 引用。
4. **P3：计费与历史任务。**验证按秒/Token 两种证据链、完整用量归一、unknown、退款幂等和创建结果分类；
   同时验证新 profile 不继承官方取消/删除行为，列表仍按本地用户与应用隔离。
5. **P4：真实验收。**使用不重名测试模型和一个统一 Channel，从本地入口完成下节矩阵。保留旧配置，
   不自动转发测试到上游直连，不向已有业务模型注入测试价格。
6. **P5：切换。**四模型、统一素材引用、账单验收通过后，明确选择保留的 Channel，按配置保存路径更新
   模型归属与映射，避免同一客户模型同时启用两条渠道。既有 Channel 的视频协议变更按正式租户替换流程
   确认，生成新 `reuse_scope` 并清除本地默认组关联；管理员确认同域后重新关联原 Provider 组，再放行
   依赖默认组的素材请求。迁移通知分别说明复用域变化与既有 Provider 引用继续使用。

旧协议只在仍有按旧协议冻结的活动任务/待核实 attempt 时承担原查询和结算职责，不对新请求做 fallback。
停止旧协议新建后，待活动任务与资金事项全部收敛，再删除无用旧创建入口/登记；历史记录不重写、不迁移
成 V3。回滚仅影响之后的新请求，已创建 V3 任务继续按其冻结协议完成，不重发到 V2。

  和冻结连接，不生成最终目标费用。该状态由后台有界低频补查，不依赖调用方；取得可信用量后进入资金补偿并按冻结表达式结算。明确报告的零用量按零结算，固定秒数/次数不等待 Token。
- 用量和目标以数据库行锁内的首次接受结果为准；旧轮询和旧计费快照不能恢复预扣、重开 settled，
  或清除 debt/failed 的既定目标。取得迟到用量时立即进入 pending，计算目标前进程中断也可由资金
  补偿继续。负表达式结果在保存 TargetQuota 前拒绝，保留资金并记录计费失败。
- 公开用量与已接受的计费事实一致，包括明确零用量；首次后续用量差异记录在私有 usage_discrepancy
  中，保留数值证据而不改账。其它结果字段仍可刷新。观察事务失败时停止结算；北向 GET 重读失败时返回刷新前不可变的耐久投影。
- V3 响应归一保留已发布结果字段 seed、generate_audio、frames、framespersecond；不透传供应商私有字段。
- 共享结算文件的改动用于资金状态和负费用边界；后续用户已确认将缺用量政策推广到全部登记 Seedance 协议，按冻结表达式判断，原生入口不变。上游同步须保留该专属调用、已结算门闩和负目标保护。
- 持久化合并隔离在 model/task_seedance_billing_facts.go。Task.UpdateBilling 和 UpdateWithStatus
  各增加专属分支，原子资金入口增加冻结目标校验，公开投影增加接受用量接线；这些共享入口是所有
  轮询和补偿都必须经过的边界，单靠服务层内存门闩不能防止并发覆盖。上游合并冲突集中于这些窄接线。

  查询异常不触发重复退款。后续跨协议修复已将该保护用于全部登记 Seedance 协议。
