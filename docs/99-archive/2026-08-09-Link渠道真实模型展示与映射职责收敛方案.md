# Link 渠道真实模型展示与映射职责收敛方案

## 背景与问题

渠道表单的 Link 访问方案区域当前根据客户模型和 `model_mapping` 生成发布预览，并展示
`客户模型 → Provider 模型 · 发布状态 · 可用状态`。这会产生两类问题：

- 未配置别名时出现 `A → A`，向管理员表达了不存在的映射关系。
- 已配置映射时，Link 区域重复展示 NEWAPI 原生“模型映射”区域已经负责的信息，使“方案支持的真实模型”与“请求模型转换规则”混在一起。

## 已确认的产品边界

1. Link 访问方案区域只展示该实现 `create` 执行绑定中注册的真实 Provider 模型。
2. Link 访问方案区域不展示任何 `A → A` 或 `A → B`，也不展示“已发布”“可用”“保存后发布”等逐模型状态。
3. NEWAPI 原生“模型”字段仍是客户可见渠道模型列表的编辑入口；新建空白渠道选择 Link 方案时，不自动填充该字段，也不自动创建 `model_mapping`。
4. NEWAPI 原生“模型映射”区域是管理员配置和查看客户模型到 Provider 模型转换的唯一界面。
5. Link 内部仍需根据模型与映射推导 publication、execution binding、Link SKU 和协议字段；本次只收敛展示职责，不移除保存校验或运行时 fail-closed 约束。
6. 已发布客户模型需要显式改绑时，冲突与“重新绑定”入口保留在“模型映射”区域，不放回 Link 方案区域。

## 实现范围

### Link 方案字段

- 使用 `linkAccessPlanProviderModelDefaults` 读取选中实现中符合渠道类型、route family、profile 和 `create` action 的 Provider 模型。
- 以纯模型名列表展示，隐藏客户别名、映射箭头、Link SKU 和 publication 状态。
- 同一列表作为模型映射右侧候选；选中 Link 方案时不混入普通渠道模型候选。
- 保留 `deriveLinkPublicationPreviews` 与 `linkAccessPlanAutofill`，继续驱动协议字段投影和提交前校验。

### 模型映射字段

- 将 Link publication 的 SKU 不一致提示及显式改绑入口放在通用 `ModelMappingEditor` 之后。
- 非 Link 渠道或不存在冲突时不渲染额外内容。
- 保持敏感渠道写权限和 expected version、改绑原因审计要求不变。

### 回归测试

- 显式配置 `customer-model → provider-model` 后，Link 方案区域只能看到 `provider-model`。
- Link 方案区域不得出现客户模型、箭头或发布状态。
- 新建空白渠道选择方案时客户模型和模型映射都保持不变。
- 选中 Link 方案后，模型映射右侧候选只来自当前 implementation 的精确 create bindings。
- publication 的 SKU 冲突只在模型映射区域提供改绑入口。

## 约束与风险

- 不改变后端 DTO、数据库和 Link publication 权威模型。
- 不把 Provider 模型反向推断为客户合同，也不从渠道模型或映射扩张 Link 合同。
- 对 NEWAPI 原生渠道表单只增加必要的窄接线点，Link 查询与冲突逻辑放在独立组件中，降低后续上游合并冲突。
