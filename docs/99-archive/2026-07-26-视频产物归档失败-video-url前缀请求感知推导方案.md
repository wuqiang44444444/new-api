# 视频产物归档失败：video_url 前缀改为请求感知推导方案

> 适用范围：ModelArk v3 协议（`/api/v3/contents/generations/tasks`，含 seedance-byteplus 等豆包视频渠道）返回给调用方的视频内容 URL。
> 部署目标：同一份代码同时兼容「线上公网域名」与「本地 localhost」两种访问入口，无需切换配置。

---

## 0. TL;DR（给赶时间的人）

- 现象：外部调用方生成视频成功（`provider_succeeded`），但产物归档失败（`archived 0 of 1 final artifacts`）。
- 根因：本服务返回给调用方的 `video_url` 形如 `https://tokenai.page/v1/videos/{id}/content`，其主机部分取自全局静态配置 `ServerAddress`；而本地测试时调用方走 `127.0.0.1:8100`，`tokenai.page` 在本机解析到代理 fake-ip、回环不到本服务 → 归档器拿不到视频字节。
- 解决：把 `video_url` 的主机前缀从「全局 `ServerAddress`」改为「跟随本次入站请求实际访问本服务的主机名」(`scheme://host`)。线上自动是公网域名，本地自动是 `127.0.0.1:8100`，零配置切换。`ServerAddress` 仅在拿不到请求上下文时兜底。
- 改动面：仅 1 处投影逻辑（ModelArk）+ 1 个新 helper；OpenAI 协议经核实不受影响。

---

## 1. 现象与背景

外部调用方系统的执行时间线（摘录）：

```
... processing → provider_succeeded            （上游火山引擎返回成功）
provider_succeeded → archiving_outputs         （开始归档产物）
archiving_outputs → archive_failed             （归档失败）
terminal · archived 0 of 1 final artifacts     （1 个产物中归档了 0 个）
```

调用入口：`POST http://127.0.0.1:8100/api/v3/contents/generations/tasks`，模型 `seedance-byteplus`，协议 `newapi_modelark_video_v3`。上游任务 id（即本服务对外 task_id）：`task_DZEBCmVMozw70H5z7LSn2fDIlSBcvXJK`。

外部系统的「产物归档」不在本服务内实现，是其侧把视频内容下载转存到自己存储的过程。归档失败 = 归档器下载本服务返回的 `video_url` 失败。

---

## 2. 根因分析（证据链，均已实测）

### 2.1 本服务侧任务完全成功、上游 URL 有效

DB（`one-api.db`，tasks 表 id=8）：

| 字段 | 值 |
|---|---|
| `status` | `SUCCESS` |
| `client_protocol` | `modelark_v3` |
| `channel_id` | 26 |
| `task_id` | `task_DZEBCmVMozw70H5z7LSn2fDIlSBcvXJK` |
| `data.content.video_url` | 火山引擎 TOS 签名直链，`X-Tos-Expires=86400`（24h） |
| `private_data.result_url` | 同一直链 |

结论：上游、本服务侧均成功，视频直链在归档时刻远未过期。问题不在生成链路。

### 2.2 但返回给调用方的不是直链，而是本服务代理路径

- [model/task_modelark.go](../../model/task_modelark.go) `ToModelArkVideoTask`：成功时硬编码 `VideoURL = "/v1/videos/" + taskID + "/content"`（相对路径）。
- [controller/modelark_video_projection.go](../../controller/modelark_video_projection.go) `projectModelArkVideoTask`：以 `/` 开头时拼上 `system_setting.ServerAddress`。

DB `options.ServerAddress = https://tokenai.page`。

→ 调用方最终拿到：`https://tokenai.page/v1/videos/task_DZEBCmVMozw70H5z7LSn2fDIlSBcvXJK/content`

### 2.3 该主机名在本地环境回环不到本服务（主因）

- 本服务实际监听 `127.0.0.1:8100`；调用方也走 `http://127.0.0.1:8100`（同机）。
- `nslookup tokenai.page` → `198.18.1.16`（Clash/Surge fake-ip 段，被本机代理接管）。
- 实测 `curl https://tokenai.page/v1/videos/.../content` → 401，但**本服务日志无任何该请求记录** → 请求未回到 8100，该 401 非本服务发出。
- 任务时段（21:44–21:46）日志里**零条** `/v1/videos/.../content` 请求 → 归档器根本没把下载请求送达本服务。

### 2.4 即便主机名可达，VideoProxy 仍要求鉴权（次因）

[router/video-router.go](../../router/video-router.go) 中 `/v1/videos/:task_id/content` 挂在 `middleware.TokenOrUserAuth()` 下。实测本机直连不带 token → 401 `Invalid token`，本服务日志即时记录。归档器下载时必须带 `Authorization`。

### 2.5 三段对比实测（定锤）

| 目标 URL | 结果 | remote | 本服务日志 |
|---|---|---|---|
| `http://127.0.0.1:8100/v1/videos/.../content`（无 token） | 401 | `127.0.0.1` | ✅ 有 |
| `https://tokenai.page/v1/videos/.../content`（`ServerAddress`） | 401 | `198.18.1.16`（fake-ip） | ❌ 无 |

证明：路径在本服务是活的；`tokenai.page` 没有回环到本机 8100。

## 3. 为什么不选「给 ServerAddress 加 env 覆盖」

`ServerAddress` 当前只从 DB options 加载（[model/option.go](../../model/option.go) `case "ServerAddress"`），无 env 优先级。一种快速修法是给它加 env 覆盖，本地 `set SERVER_ADDRESS=http://127.0.0.1:8100`。

否决理由：

- 治标不治本：每次切环境要改 env；同一进程无法同时服务「公网调用方」和「本地调用方」。
- 违背「兼顾线上部署与本地测试」的目标——它只是把切换从 DB 挪到 env。

请求感知推导才是真正与环境解耦：主机名来自调用方本次请求，天然匹配其网络可达性。

## 4. 解决方案：请求感知推导 video_url 前缀

### 4.1 设计

`video_url` 的主机前缀 = 本次入站请求实际访问本服务所用的 `scheme://host[:port]`，推导顺序：

1. `scheme`：`X-Forwarded-Proto`（反代）→ `r.TLS`（直连 TLS）→ `http`。
2. `host`：`X-Forwarded-Host`（反代）→ `c.Request.Host`。
3. 任一拿不到 → 回退 `strings.TrimRight(system_setting.ServerAddress, "/")`。

依据：调用方能访问到 `GET /api/v3/.../tasks/:id`（拿 task 详情），就必然能访问同主机下的 `/v1/videos/:id/content`。让前缀跟随入站请求，两种环境自动正确。

### 4.2 改动清单（最小入侵）

| 文件 | 改动 |
|---|---|
| [controller/video_baseurl.go](../../controller/video_baseurl.go)（新增） | `incomingVideoBaseURL(c *gin.Context) string` + `requestScheme(r *http.Request) string` |
| [controller/modelark_video_projection.go](../../controller/modelark_video_projection.go) | 函数签名加 `c *gin.Context`；前缀由 `ServerAddress` 改为 `incomingVideoBaseURL(c)` |
| [controller/video_modelark.go](../../controller/video_modelark.go) | `ModelArkVideoGet` / `ModelArkVideoList` 两个调用点传入 `c` |
| [controller/modelark_video_projection_test.go](../../controller/modelark_video_projection_test.go) | 双路径测试：① 请求推导 ② `nil` 兜底 `ServerAddress` |

`ServerAddress` 全局语义不变（仍被 midjourney、passkey、reset 链接、return_path 等依赖），只改 video 客户端 URL 这一处拼接。

### 4.3 核心代码

```go
// controller/video_baseurl.go
func incomingVideoBaseURL(c *gin.Context) string {
    if c != nil && c.Request != nil {
        host := strings.TrimSpace(c.GetHeader("X-Forwarded-Host"))
        if host == "" {
            host = strings.TrimSpace(c.Request.Host)
        }
        if host != "" {
            return requestScheme(c.Request) + "://" + host
        }
    }
    return strings.TrimRight(system_setting.ServerAddress, "/")
}
```

```go
// controller/modelark_video_projection.go
func projectModelArkVideoTask(c *gin.Context, task *model.Task) *dto.ModelArkVideoTask {
    projected := task.ToModelArkVideoTask()
    if projected.Content == nil {
        return projected
    }
    baseURL := incomingVideoBaseURL(c)   // 原为 system_setting.ServerAddress
    if baseURL == "" {
        return projected
    }
    // 拼接相对路径 /v1/videos/<id>/content[?part=last_frame]
    ...
}
```

## 5. 解决后 URL 的访问流程

> 关键不变量：**`video_url` 的主机部分 ≡ 调用方本次请求访问本服务所用的主机** → 调用方必然能回访。

### 5.1 本地测试流程（调用方 = 同机归档器，走 127.0.0.1:8100）

```
归档器(同机)              new-api (127.0.0.1:8100)              火山引擎 TOS
   │
   │ ① POST /api/v3/contents/generations/tasks   (Authorization: Bearer sk-xxx)
   │──────────────────────────►│
   │                           │  创建 task，转发上游
   │   ◄─── 200 { task_id } ───│
   │
   │ ② GET /api/v3/.../tasks/{id}   (轮询，带 token)
   │──────────────────────────►│
   │   ◄── status: queued/running ─│       后台 worker 轮询上游
   │          ……轮询中……            │──────────────────────►│
   │                                │ ◄── succeeded + TOS 直链 ──│
   │                                │ task → SUCCESS
   │ ③ GET /api/v3/.../tasks/{id}   (带 token，本机直连)
   │──────────────────────────►│
   │   projectModelArkVideoTask(c, task):
   │     incomingVideoBaseURL(c):
   │       scheme = http        (无 X-Forwarded-Proto、无 TLS)
   │       host   = c.Request.Host = "127.0.0.1:8100"
   │       → "http://127.0.0.1:8100"
   │     video_url = "http://127.0.0.1:8100/v1/videos/{id}/content"
   │   ◄── 200 { content.video_url: http://127.0.0.1:8100/.../content } ──│
   │
   │ ④ GET http://127.0.0.1:8100/v1/videos/{id}/content   (带 token)
   │──────────────────────────►│  VideoProxy
   │                           │   TokenOrUserAuth ✓
   │                           │   回源 task.PrivateData.ResultURL (TOS 直链)
   │                           │────────────────────────────────►│
   │                           │ ◄──────── 视频字节流 ────────────│
   │   ◄──── 200 video/mp4 ────│   流式透传
   │
   归档器收到字节 → 转存 → archived 1/1 ✅
```

### 5.2 线上部署流程（调用方经反向代理访问公网域名）

与 5.1 的唯一差别在第 ③ 步推导出的前缀：

- 反代（nginx/CDN）将公网请求转发到本服务，并设置 `X-Forwarded-Proto: https` 与 `Host: tokenai.page`（或 `X-Forwarded-Host: tokenai.page`）。
- `incomingVideoBaseURL(c)`：`scheme=https`、`host=tokenai.page` → `https://tokenai.page`。
- `video_url = https://tokenai.page/v1/videos/{id}/content`。
- 归档器下载该 URL（带 token），经反代回到本服务 → VideoProxy 回源 → 成功。

### 5.3 兜底路径

当 `projectModelArkVideoTask` 拿不到请求上下文（`c == nil`，如未来出现非 HTTP 触发的投影场景）时，`incomingVideoBaseURL` 回退 `ServerAddress`，保持与历史行为一致。

## 7. 注意事项与边界

### 7.1 反向代理必须正确转发协议头

线上 nginx/CDN 需设置：

- `X-Forwarded-Proto: https`（或标准 `Forwarded` 头）；
- 保留 `Host` 为公网域名，或显式设置 `X-Forwarded-Host`。

否则反代后推导出的 host 会落到内网/上游地址，公网调用方仍不可达。这是反代标准配置。

### 7.2 鉴权是第二道关卡

`/v1/videos/:id/content` 走 `TokenOrUserAuth`，归档器下载时必须带 `Authorization`。本案例调用 task 接口时已带 token；若归档器复用同一 token 下载即可通过。若归档器**裸下载不带 token**，仍会 401 —— 该场景需单独评估（例如为 content 端点引入短期签名凭证），有安全权衡，不在本次范围。

### 7.3 Host 头注入的安全结论

`incomingVideoBaseURL` 返回值仅用于客户端回访本服务自身端点，**不会被本服务用作回源地址**（VideoProxy 回源用的是 `task.PrivateData.ResultURL` / 上游直链）。因此即便请求 `Host` 头被伪造，也不会引入 SSRF；最坏情况是客户端拿到一个不可达的视频 URL 导致下载失败。

### 7.4 OpenAI 协议为何无需改动

- `ProjectOpenAIVideo`（[model/task_video_lifecycle.go](../../model/task_video_lifecycle.go)）不输出视频 url 字段；OpenAI 提交响应里的 url 由各 adaptor 的 `ConvertToOpenAIVideo` 用**上游直链**设置（如 doubao [relay/channel/task/doubao/adaptor.go](../../relay/channel/task/doubao/adaptor.go)），不经 `ServerAddress`。
- `BuildProxyURL`（[relay/channel/task/taskcommon/helpers.go](../../relay/channel/task/taskcommon/helpers.go)）的结果只写入 `PrivateData.ResultURL`，供 `VideoProxy` 回源兜底，不返回给客户端。
- 故全代码库中「返回给客户端的视频 URL 用 `ServerAddress` 拼前缀」的唯一一处即 ModelArk 投影，本次已修复。
