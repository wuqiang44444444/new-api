# 任务公开响应与存储凭据泄漏修复

## 问题与目标

修复评审确认的四项问题：仪表盘 Task DTO 原样输出 Properties/Data、带引号凭据穿透错误净化、
创建与查询的上游模型名净化分叉，以及 DEBUG 模式下对象存储凭据进入 SQL 日志。

原始 Data 的公开旁路位于仪表盘 DTO；ModelArk 错误对象已有失败消息一致性校验，不能混为同一出口。
DEBUG 风险不限于慢查询和驱动错误：InitDB 调用 GORM Debug()，使日志级别由 Warn 变为 Info，
同时 SQL 参数隐藏关闭，因此正常成功写入也需要保护。

## 当前实际情况

- Link 视频任务按已有 ClientProtocol 判断公开边界，仪表盘/通用 DTO 的 properties 只包含客户模型名，
  data 返回 null，不输出上游结果直链或客户输入。媒体继续通过既有附件接口交付，管理员渠道信息和
  既有分级诊断保留；原生任务的 Data/Properties 行为保持不变。
- 创建和查询共用 common.PublicTaskErrorMessageForModel。创建错误使用本次 RelayInfo 已解析的模型身份，
  不重新查渠道映射；查询使用 Task 冻结身份。凭据清除先于模型名保护，完整身份替换先于长度截断。
- 共享规则支持双引号、单引号、转义引号、含空格/分隔符及未闭合的凭据值，保留正常版权、内容审核和
  参数错误说明。新旧记录读取都经过公开规则，不通过修改历史 Task 来修复展示。
- 对象存储保存事务使用独立 Silent 会话，覆盖成功、慢查询和失败 SQL；全局 DEBUG 诊断行为不变。
  不恢复凭据加密、不新增配置项、不改变凭据轮换与原子保存语义。
- 本地回归覆盖完整 HTTP 响应、真实路由连接本地模拟 Provider、客户别名含 Provider 单词、模型名互为
  前缀、凭据字段与客户模型重名、截断边界、原生音频数据保留，以及 DEBUG 成功轮换和数据库拒绝。
  模拟 Provider 测试同时核对原有 hold、拒绝退款、unknown 保留资金与单次发送行为。

## 优化方案与验证

主体实现位于本地错误处理、公开投影和对象存储扩展文件。原生文件接线及合并影响如下：

| 文件 | 必要改动 | 上游同步影响 |
| --- | --- | --- |
| relay/relay_task.go | 登记 Link 请求上下文；把 HTTP 错误交给扩展处理；DTO 返回前调用 Link 字段投影 | 仅提交错误与 DTO 返回接线附近可能冲突，不重排原生流程 |
| service/error.go | 原生调用向共享错误分类显式传入空模型上下文 | 单行参数调整，原生分类与响应保持原语义 |
| controller/task.go | 管理员投影保留渠道字段 | 单行接线，不扩大普通用户公开字段 |

本次只调整公开输出与日志边界，不改变路由、资金、Task 状态或 Provider 协议语义。
本地验证通过：

- `go test ./common ./model ./service ./relay/... ./controller`
- `go vet ./common ./model ./service ./relay/... ./controller`
- `go build ./...`
- `task docs:check`、`task ai:check`
- 本次改动的 `git diff --check`

测试使用本地 SQLite 和模拟 Provider；真实 Provider、生产对象存储、外部 MySQL/PostgreSQL 与账单验收
不属于这些回归的证明范围，仍需按照对应验收记录执行。
