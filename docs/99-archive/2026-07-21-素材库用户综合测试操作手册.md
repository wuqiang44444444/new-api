# 素材库运维验收操作手册

> 适用人员：测试环境或预发布环境的运维、值班和验收人员。
> 本手册只要求会打开终端、复制命令和查看返回结果，不要求理解程序代码或数据库。

## 1. 这次要确认什么

素材库的工作方式可以简单理解为：

1. 客户把图片、视频或音频放在一个临时公网 HTTPS 地址上；
2. 平台把这个地址交给视频服务商处理；
3. 平台返回一个 `ast_...` 素材编号；
4. 后续生成视频时使用这个素材编号。

平台不会上传、下载或保存素材文件本身，也不会删除客户原来的文件。

本次验收只需确认以下结果：

- 素材能创建，并最终变成 `ready`；
- `ready` 素材可以生成视频；
- 不安全或即将过期的链接会被拒绝；
- A 用户看不到 B 用户的素材；
- 删除素材后不能继续生成新视频；
- 如果测试真人素材，必须先完成本人同意和服务商认证。

## 2. 开始前请管理员准备

请部署或研发同事填写下面的“测试参数卡”，运维人员不要自行猜测。

| 参数 | 示例 | 由谁提供 |
| --- | --- | --- |
| 测试环境地址 | `https://api-test.example.com` | 部署人员 |
| 用户 A Token | `sk-...` | 管理员 |
| 用户 A 的另一个 Token | `sk-...` | 管理员 |
| 用户 B Token | `sk-...` | 管理员 |
| 测试模型 | `seedance-...` | 渠道管理员 |
| 素材临时 HTTPS 地址 | `https://...` | 测试负责人 |
| 地址到期时间 | 10 位 Unix 时间戳 | 测试负责人 |
| 本次测试编号 | `ops-20260723-01` | 测试负责人 |

管理员还需要提前确认：

- 已开启素材库；
- 测试模型已有可用的单密钥视频渠道；
- 视频渠道和素材渠道属于同一个服务商账号；
- 素材地址的剩余有效时间满足渠道要求；
- 真人素材测试已单独开启真人能力，并配置好同意页面和有效政策。

如果使用 BytePlus 官方视频和官方素材 Action，渠道管理员必须先按
[BytePlus 官方视频与素材渠道配置操作指南](./2026-07-26-BytePlus官方视频与素材渠道配置操作指南.md)
完成双凭据配置，并确认“视频测试”和“素材 Action 测试”分别通过。视频 `Model API Key` 与素材 AK/SK 是两套不同凭据，不能混填。

### 2.1 安全要求

- 只能使用测试素材，不要使用生产素材。
- 真人图片必须得到本人明确授权。
- Token、素材完整地址、地址中的签名参数不得粘贴到群聊、工单标题或截图中。
- 缺陷记录中的素材地址只保留域名，删除 `?` 后面的全部内容。

## 3. 第一次操作：填写测试变量

打开终端，将下面内容中的尖括号替换为测试参数卡里的实际值，然后整体复制执行：

```bash
export API_BASE="https://<测试环境域名>"
export TOKEN_A1="sk-<用户A Token 1>"
export TOKEN_A2="sk-<用户A Token 2>"
export TOKEN_B="sk-<用户B Token>"
export TEST_MODEL="<测试模型>"
export SOURCE_URL="https://<测试素材临时地址>"
export SOURCE_EXPIRES_AT="<10位到期时间戳>"
export RUN_ID="<本次测试编号>"
```

看到终端没有报错即可继续。关闭终端后再次测试，需要重新执行这一步。

## 4. 主流程验收

主流程共 6 步。每一步成功后再执行下一步。

### 第 1 步：创建素材

复制执行：

```bash
curl -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-asset" \
  -d "{
    \"name\": \"ops-reference-image\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"$SOURCE_URL\",
      \"expires_at\": $SOURCE_EXPIRES_AT
    }
  }"
```

通过标准：

- 返回内容中能看到 `"id":"ast_..."`；
- 状态是 `processing`、`ready` 或 `create_unknown`；
- 返回内容中看不到完整素材地址、渠道编号、服务商素材编号或密钥。

请复制并保存返回的 `ast_...`，后文称为 `ASSET_ID`：

```bash
export ASSET_ID="<刚才返回的 ast_...>"
```

以下情况判定失败：

- 没有返回 `ast_...`；
- 返回了完整素材 URL 或任何密钥；
- 返回 `failed`，或出现本文第 9 节没有说明的错误。

### 第 2 步：等待素材就绪

复制执行：

```bash
curl -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

根据 `status` 判断：

| 状态 | 怎么做 |
| --- | --- |
| `ready` | 通过，进入第 3 步 |
| `creating` / `processing` | 等 10 秒后再查 |
| `create_unknown` | 暂时不要重新创建，记录时间并联系研发观察 |
| `failed` | 失败，记录 `error_code` |
| `deleting` / `deleted` | 素材已进入删除流程，本次用例需重新开始 |

### 第 3 步：使用素材创建视频

复制执行：

```bash
curl -sS -X POST "$API_BASE/v1/videos" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-video" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"prompt\": \"让参考画面产生轻微、自然的镜头运动\",
    \"seconds\": \"4\",
    \"size\": \"720x1280\",
    \"input_reference\": {
      \"image_url\": \"asset://$ASSET_ID\"
    }
  }"
```

通过标准：

- 返回内容中能看到 `"id":"task_..."`；
- 状态是 `queued`、`in_progress` 或 `completed`；
- 没有返回上游渠道编号、服务商任务编号或密钥。

保存返回的 `task_...`：

```bash
export VIDEO_ID="<刚才返回的 task_...>"
```

### 第 4 步：等待视频完成

复制执行：

```bash
curl -sS "$API_BASE/v1/videos/$VIDEO_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

根据 `status` 判断：

| 状态 | 怎么做 |
| --- | --- |
| `queued` / `in_progress` | 等 10 秒后再查 |
| `completed` | 通过，进入第 5 步 |
| `failed` | 失败，记录 `error.code`、请求时间和任务编号 |

不要每秒连续查询。正常情况下每 10 秒查询一次即可。

### 第 5 步：下载结果

复制执行：

```bash
curl -fL "$API_BASE/v1/videos/$VIDEO_ID/content" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -o "video-result.mp4"
```

通过标准：

- 当前目录出现 `video-result.mp4`；
- 文件可以正常播放；
- 文件不是 HTML 错误页面，也不是空文件。

### 第 6 步：修改素材名称

先改名：

```bash
curl -sS -X PATCH "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d '{"name":"ops-reference-image-renamed"}'
```

通过标准：返回的 `name` 是 `ops-reference-image-renamed`。

先不要删除素材。完成第 5～7 节后，再按第 7.1 节清理。

## 5. 同一用户与不同用户隔离

此处需要管理员提供的 Token A2 和 Token B。

### 5.1 同一用户的另一个 Token

```bash
curl -i "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A2"
```

如果素材尚未删除，应能正常查询。同一账号下的 Token 可以共享该账号的素材。

### 5.2 不同用户

```bash
curl -i "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_B"
```

通过标准：返回 `404`，并且不能从返回内容判断这个素材是否属于其他人。

## 6. 幂等检查

“幂等”表示同一次操作因为网络问题重复提交时，不会重复创建或重复收费。

重新执行第 1 步完全相同的命令：

- 应返回同一个 `ast_...`；
- 不应产生第二个素材。

保持 `Idempotency-Key: ${RUN_ID}-asset` 不变，但修改创建请求中的 `name` 后重新提交：

- 应返回 HTTP `409`；
- 错误码应为 `idempotency_conflict`。

需要查看 HTTP 状态时，把命令开头的 `curl -sS` 改为 `curl -i -sS`。

视频创建的 `Idempotency-Key` 也遵循同样规则。一次业务操作使用一个随机且唯一的 Key；重试原操作时复用原 Key。

## 7. 链接安全检查

下面用例只需任选 2～3 个执行。预期都应在联系服务商之前直接失败。

每个安全用例必须使用一个从未用过的 `Idempotency-Key`，例如 `${RUN_ID}-unsafe-01`、`${RUN_ID}-unsafe-02`。如果继续使用第 1 步的 Key，平台会先返回 `idempotency_conflict`，无法验证链接安全。

下面是“拒绝 HTTP 地址”的完整示例，可直接复制：

```bash
curl -i -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-unsafe-01" \
  -d "{
    \"name\": \"unsafe-http-url\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"http://example.com/unsafe.png\",
      \"expires_at\": $SOURCE_EXPIRES_AT
    }
  }"
```

预期看到 HTTP `400` 和 `unsafe_asset_url`。

| 输入 | 预期结果 |
| --- | --- |
| `http://example.com/a.jpg` | `400 unsafe_asset_url` |
| `https://127.0.0.1/a.jpg` | `400 unsafe_asset_url` |
| `https://user:pass@example.com/a.jpg` | `400 unsafe_asset_url` |
| 带 `#fragment` 的地址 | `400 unsafe_asset_url` |
| 到期时间太近 | `400 asset_url_ttl_insufficient` |
| `source.type` 改成 `base64` 或 `direct_upload` | `400 asset_url_required` |

如果返回 `asset_url_ttl_insufficient`，查看：

```json
"required_min_ttl_seconds": 3600
```

这个数字表示素材地址至少还要有效多少秒。请重新生成有效期更长的地址，不要反复提交原地址。

### 7.1 完成普通素材测试并清理

确认第 5～7 节都已经执行后，再删除素材：

```bash
curl -i -X DELETE "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

通过标准：

- HTTP 状态为 `204`；
- 删除后不能再用该素材创建新视频；
- 客户提供的原始 HTTPS 文件仍然存在，平台不会删除它。

## 8. 真人素材验收

真人素材只在业务明确要求时测试。普通素材验收不需要执行本节。

### 8.1 创建授权

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"locale\": \"zh-CN\"
  }"
```

保存返回的：

- `id`：授权编号；
- `consent_url`：本人操作链接。

### 8.2 由本人完成授权

必须由照片本人打开 `consent_url`：

1. 阅读同意内容；
2. 勾选单独同意和已满 18 周岁；
3. 进入服务商认证页面并完成认证；
4. 返回授权回执页面。

运维人员不得代替本人勾选同意。

### 8.3 查询授权状态

```bash
export AUTH_ID="<授权编号>"

curl -sS "$API_BASE/v1/real-person-authorizations/$AUTH_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

只有状态为 `authorized` 才能继续创建真人素材。其他状态按第 9 节处理。

### 8.4 创建真人素材

使用第 1 步的命令，并做三处修改：

```json
{
  "asset_kind": "real_person",
  "media_type": "image",
  "authorization_id": "<授权编号>"
}
```

真人素材必须和授权使用同一个模型、同一个用户和同一个服务商账号。

### 8.5 撤回授权

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations/$AUTH_ID/revoke" \
  -H "Authorization: Bearer $TOKEN_A1"
```

通过标准：

- 授权状态变为 `revoked`；
- 相关真人素材立即不能再用于创建新视频；
- 上游删除可在后台继续执行。

## 9. 常见结果速查

| 状态或错误码 | 含义 | 运维处理 |
| --- | --- | --- |
| `ready` | 素材可用 | 继续生成视频 |
| `processing` | 服务商处理中 | 10 秒后再查 |
| `create_unknown` | 创建结果暂时不确定 | 不要换 Key 重建，记录时间并联系研发 |
| `asset_url_ttl_insufficient` | 临时地址有效期不足 | 申请更长有效期的新地址 |
| `unsafe_asset_url` | 地址不符合安全规则 | 检查是否为公网 HTTPS 地址 |
| `asset_not_ready` | 素材尚未准备好 | 等待素材变为 `ready` |
| `asset_binding_required` | 素材和视频渠道不匹配 | 联系渠道管理员，不要反复提交 |
| `asset_credential_changed` | 渠道密钥已变化 | 联系渠道管理员迁移或重建素材 |
| `idempotency_conflict` | 同一个 Key 被用于不同请求 | 核对是否误改请求；新业务使用新 Key |
| `insufficient_quota` | 账户额度不足 | 联系管理员充值或调整额度 |
| `rate_limit_exceeded` | 请求过快 | 稍后重试 |
| `upstream_unavailable` | 服务商暂时不可用 | 保留原 Key，稍后重试或联系值班人员 |
| `real_person_consent_required` | 真人授权未完成 | 让本人完成授权 |
| `real_person_verification_rejected` | 服务商认证拒绝 | 核对认证结果，不要绕过授权 |

## 10. 最终验收清单

- [ ] 普通图片素材可以创建并变为 `ready`。
- [ ] 同一素材可以成功生成视频并下载。
- [ ] 返回内容不包含完整素材 URL、渠道信息、上游编号或密钥。
- [ ] 重复相同请求不会产生第二个素材或视频任务。
- [ ] 即将过期和不安全的 URL 会被拒绝。
- [ ] 同一账号可以共享素材，不同账号无法查询或引用。
- [ ] 删除后不能新建引用，且客户原始文件不受影响。
- [ ] 如测试真人素材：本人同意、认证、创建、使用和撤回全部完成。
- [ ] SQLite、MySQL、PostgreSQL 的兼容验证已由研发或发布流水线确认。

以下内容不要求运维人员自行检查，但发布负责人必须给出验证结果：

- 数据库不保存完整源 URL；
- 日志和链路追踪不记录 URL 签名或密钥；
- 素材和视频始终使用创建时绑定的服务商账号；
- 服务商侧重定向、DNS 变化和最终连接地址具备 SSRF 防护。
