# BytePlus 官方视频与素材双凭据渠道接入完整方案

## 1. 文档目的

本文记录普通素材库注册失败问题的完整排查过程，并给出 BytePlus ModelArk 官方视频与官方素材 Action 共用一个渠道时的双凭据接入方案。

本文覆盖：

- 原始现象、日志和排查结论；
- BytePlus 官方视频与素材的鉴权差异；
- 当前实现为什么无法仅靠渠道配置完成接入；
- 目标渠道配置、数据模型、后端和前端改造；
- 北向统一、南向适配边界；
- 数据迁移、安全、兼容、测试、上线和回滚要求；
- 改造完成后新增同类渠道的标准配置流程。

本文同时保留实施方案和 2026-07-26 的实现验证记录。稳定结论已同步到 `docs/20-architecture/`、`docs/40-operations/` 和 ADR-0005。

## 2. 范围与非目标

### 2.1 本期范围

- 优先打通普通素材库；
- 支持 DoubaoVideo 官方视频协议与 `official_action_assets` 素材协议共存；
- 同一渠道分别保存和使用：
  - 视频模型 API Key；
  - 素材 Access Key ID；
  - 素材 Secret Access Key；
- 保持现有平台 `/v1/assets` 和 `asset://ast_xxx` 北向合同不变；
- 保持模型公开名称到 BytePlus Endpoint ID 的内部映射；
- 保证新增同类渠道只需要填写配置，不需要再次修改代码。

### 2.2 本期非目标

- 不把普通客户北向接口改造成 BytePlus Action API；
- 不向普通客户暴露 AK/SK、ProjectName、Endpoint ID、GroupId 或上游 Asset ID；
- 不为每个 BytePlus 账号写专用代码；
- 不把测试账号、ProjectName、Endpoint ID 或任何密钥写死在代码中；
- 不新增普通素材库环境变量开关；
- 不在本期默认开启真人素材能力；
- 不改变第三方 `ark_assets`、`relay_assets` 和 `joycreator_assets` 的既有凭据合同；
- 不把渠道 `ServerAddress`、前端开发端口或平台 API 地址当作素材源 URL。

## 3. 执行摘要

问题已经分成两个阶段：

1. 首次注册返回 HTTP 503：普通素材库被当时的本地环境开关关闭。普通素材库作为本项目核心业务，现已明确应默认启用，不依赖 `ASSET_LIBRARY_ENABLED`；该历史变量已在本次排障中移除，当前代码库不存在该变量。
2. 再次注册返回 HTTP 409：全局开关已经通过，但系统没有找到兼容的素材渠道。

第二阶段的根因不是缺少普通渠道配置项本身，而是当前代码把 `Channel.Key` 同时当作：

- 视频模型调用的 Bearer API Key；
- 官方素材 Action 的 `ACCESS_KEY|SECRET_KEY`。

BytePlus 官方合同要求这两条链路使用不同凭据，因此当前单凭据模型存在不可同时满足的冲突：

- `Channel.Key` 保存模型 API Key 时，视频正常，但官方素材校验失败；
- `Channel.Key` 保存 `AK|SK` 时，素材 Action 可以签名，但视频会把 `AK|SK` 错误地作为 Bearer Token。

正确方案是在一个官方渠道内维护两套南向凭据，视频和素材适配器按协议分别读取。改造完成后，管理员新增同类渠道只需填写配置，不需要修改代码。

## 4. 原始问题与时间线

### 4.1 首次现象：界面一直显示“注册中”

用户在素材卡片选择 `seedance-byteplus` 和普通素材后点击注册，界面持续显示创建中。后台日志包含：

```text
record not found
SELECT * FROM asset_operation_jobs ...

record not found
SELECT * FROM asset_create_idempotencies ...

503 POST /v1/assets
```

### 4.2 首次根因：普通素材库曾被历史本地环境开关关闭

排查确认故障发生时的本地实现和运行环境曾包含：

```text
ASSET_LIBRARY_ENABLED=false
```

这使 `/v1/assets` 在进入渠道选择前返回 503。该变量已在本次排障中从本地实现和运行配置移除，因此当前代码全库搜索不到它是预期结果，不表示原始排障记录有误。

普通素材库已确定为默认业务能力，因此当前目标行为是：

- `asset_setting.enabled` 默认 `true`；
- 普通素材库不依赖 `ASSET_LIBRARY_ENABLED`；
- 如需紧急停用，通过数据库动态配置执行；
- 真人素材仍保留独立、默认关闭的安全边界。

当前 `/v1/assets` 控制器把素材库不可用和素材上游不可用统一映射为：

```text
HTTP 503
code=asset_upstream_unavailable
```

`asset_library_disabled` 仍是视频请求引用平台素材、但素材库已关闭时由 `AssetRouteConstraint` 返回的独立错误码。两个错误码属于不同入口，不能全局互换。

### 4.3 第二次现象：重启后返回 HTTP 409

普通素材能力生效后，再次请求出现：

```text
record not found
SELECT * FROM asset_operation_jobs ...

record not found
SELECT * FROM asset_create_idempotencies ...

409 POST /v1/assets
```

请求在约 1 毫秒内结束，素材、绑定、幂等和任务表均无新增记录，证明请求没有到达上游。

### 4.4 `record not found` 不是根因

两条 GORM 日志都是预期的空查询：

- `asset_create_idempotencies` 无记录：新幂等键首次请求时正常；
- `asset_operation_jobs` 无记录：后台队列暂时没有可执行任务时正常。

真正错误是渠道选择阶段返回：

```text
asset_binding_required
no compatible single-key asset channel is available
```

HTTP 409 映射位于 `controller/asset.go`，渠道过滤逻辑位于 `service/asset_binding_service.go`。

### 4.5 当时的渠道状态

相关官方渠道当时具备：

- 渠道类型：DoubaoVideo；
- 视频协议：`official`；
- 公开模型：`seedance-byteplus`；
- 模型映射：已映射到正确的 BytePlus Endpoint ID；
- 渠道 Key：模型调用 API Key；
- 素材协议：空；
- Provider Project：空；
- Provider Region：空；
- Minimum Asset URL TTL：`0`。

因此该渠道不会进入普通素材路由候选集，HTTP 409 符合当前代码行为。

## 5. ServerAddress 与素材源地址结论

本地开发环境：

```text
Web: http://localhost:3100
API: http://localhost:8100
ServerAddress: http://localhost:8100
```

该配置对本地开发是正确的，并且和 HTTP 409 无关。

需要区分：

- `ServerAddress`：平台后端对外地址，用于 OAuth 回调、Webhook 等平台能力；
- 渠道 Base URL：南向 Provider 视频接口地址；
- Provider Action URL：由素材 Region 推导的 BytePlus Action 地址；
- `source.url`：客户提供、供 BytePlus 拉取的公网 HTTPS 素材地址。

生产环境中的 `ServerAddress` 应使用外部可访问的 HTTPS 地址。普通素材请求的 `source.url` 不能是 `localhost`、私网地址或只对平台本机可见的地址。

## 6. BytePlus 官方合同基线

### 6.1 视频模型调用

BytePlus ModelArk 视频推理使用：

- 模型 API Key；
- `Authorization: Bearer <API_KEY>`；
- 视频 API Base URL；
- 请求中的 `model` 为模型 ID 或推理 Endpoint ID。

平台继续使用公开模型名，例如：

```text
seedance-byteplus
```

通过渠道模型映射转换为实际 Endpoint ID。Endpoint ID 不作为平台北向模型名称暴露。

### 6.2 素材库 Action

BytePlus 素材和素材组使用：

- Access Key ID；
- Secret Access Key；
- HMAC-SHA256 Action 签名；
- `ServiceName=ark`；
- `Version=2024-01-01`；
- 明确的 Region；
- 明确的 `ProjectName`。

素材 Action 地址按 Region 生成，例如：

```text
https://ark.<region>.byteplusapi.com/?Action=<action>&Version=2024-01-01
```

当前 `OfficialActionAdapter` 已实现素材、素材组和真人认证 Action，本方案不重新实现 Action 协议，只修正它的凭据来源。

### 6.3 Project 隔离

以下资源必须位于同一个 BytePlus Project：

- 模型 Endpoint；
- 模型 API Key 的授权范围；
- 素材和素材组；
- AK/SK 对应身份的 Ark 项目权限。

`ProjectName` 区分大小写，不能把平台渠道分组 `group` 当作 Provider Project。

### 6.4 权益要求

即使配置和签名均正确，上游账号仍需满足：

- 已开通对应素材库或高级创作权益；
- AK/SK 身份拥有目标 Project 的 Ark 权限；
- 目标 Endpoint 支持对应素材引用；
- 源素材 URL 能被 BytePlus 安全访问。

## 7. 根因分析

### 7.1 当前单凭据冲突

当前官方视频适配器读取 `Channel.Key` 并设置：

```http
Authorization: Bearer <Channel.Key>
```

当前官方素材适配器也读取 `Channel.Key`，但要求格式：

```text
ACCESS_KEY|SECRET_KEY
```

这两个合同不能由同一个字符串同时满足。

### 7.2 为什么不能通过新增“素材专用渠道”绕过

平台素材绑定保存 `ChannelID`、素材 profile、Provider Project、Region 和凭据指纹。视频引用素材时会限制到拥有该 active binding 的同一渠道，并在提交前把：

```text
asset://ast_xxx
```

转换为：

```text
asset://asset-xxx
```

如果建立一个只保存 AK/SK 的“素材渠道”，后续视频仍会被路由到该渠道，而视频适配器会把 AK/SK 当成 Bearer Token。因此单独增加素材渠道不能完整解决问题。

### 7.3 为什么不能把 AK/SK 放进 `ChannelOtherSettings`

`ChannelOtherSettings` 会作为渠道 settings JSON 参与管理接口和表单读写。把 Secret Access Key 放入该 JSON 会增加以下风险：

- 管理列表或详情误返回；
- 浏览器表单状态和调试工具长期保留；
- 更新普通 settings 时意外覆盖；
- 日志或错误信息输出完整 JSON；
- 未来上游合并时难以识别其敏感边界。

因此素材 AK/SK 必须使用独立的敏感数据模型，不能放入普通 settings JSON。

## 8. 设计原则与硬约束

1. **北向统一**：普通客户只使用平台 API Key、平台模型名和平台素材 ID。
2. **南向适配**：视频 Bearer 与素材 AK/SK 由不同适配器消费。
3. **配置驱动**：账号、Project、Region、Endpoint 全部来自渠道配置，不写死。
4. **凭据隔离**：模型 API Key 与素材 AK/SK 分开存储、读取、轮换和审计。
5. **默认可用**：普通素材能力默认开启，不新增业务 ENV 开关。
6. **失败关闭**：缺少任一官方素材必填项时，渠道不得参与素材路由。
7. **生命周期保护**：存在未删除素材、素材组或真人授权时，禁止直接改变素材账号身份。
8. **不泄密**：AK/SK 不进入普通管理响应、客户响应、日志、审计详情或前端持久状态。
9. **跨数据库兼容**：SQLite、MySQL 5.7.8+、PostgreSQL 9.6+ 行为一致。
10. **最小入侵**：新增逻辑优先进入独立文件，现有上游文件只保留必要接线。

## 9. 目标架构

```text
普通客户
  |
  | 平台 API Key
  | POST /v1/assets
  | model=seedance-byteplus
  v
平台统一素材服务
  |
  | 选择渠道、绑定用户、校验 URL/TTL
  | 保存 ast_xxx、ab_xxx、状态和幂等记录
  v
渠道 26（示意）
  |\
  | \__ 视频凭据：模型 API Key
  |       |
  |       v
  |     BytePlus Video API（Bearer）
  |
  \____ 素材凭据：Access Key ID + Secret Access Key
          |
          v
        BytePlus ModelArk Action（HMAC）
          ServiceName=ark
          Version=2024-01-01
          Region + ProjectName
```

视频和素材仍属于同一个渠道和同一个 Provider Project，因此素材绑定后的渠道约束保持有效。

## 10. 渠道配置模型

### 10.1 管理员可见字段

当且仅当满足以下条件时显示官方素材凭据区域：

```text
channel.type == DoubaoVideo
video_upstream_profile == official
asset_upstream_profile == official_action_assets
```

字段定义：

| 字段 | 是否必填 | 是否敏感 | 用途 |
| --- | --- | --- | --- |
| 模型 API Key | 是 | 是 | 视频 Bearer 调用，继续使用 `Channel.Key` |
| 素材 Access Key ID | 是 | 是 | 素材 Action 签名 |
| 素材 Secret Access Key | 是 | 是 | 素材 Action 签名 |
| Provider Project | 是 | 否 | 对应官方 `ProjectName` |
| Provider Region | 是 | 否 | 签名 Region 与 Action host |
| Minimum Asset URL TTL | 是 | 否 | 平台对源 URL 剩余 TTL 的预检查阈值 |
| 公开模型 | 是 | 否 | 平台北向模型名 |
| 模型映射 | 是 | 否 | 公开模型名到 Endpoint ID |

### 10.2 不属于该区域的字段

- `ServerAddress` 不属于渠道素材配置；
- Web 端口和 API 端口不属于 Provider 配置；
- 平台渠道 `group` 不是 Provider Project；
- Endpoint ID 不是 Base URL；
- 素材 AK/SK 不能覆盖模型 API Key。

### 10.3 最小 URL TTL

当前代码要求启用素材 profile 时配置正数 TTL。该值表达：

```text
最晚首次抓取时间
+ Processing 阶段可能的重复抓取窗口
+ 网络、队列与时钟偏差裕量
```

官方文档中“查询结果返回的 URL 有效 12 小时”描述的是 Provider 返回 URL，不等价于客户源 URL 的抓取 SLA，不能直接据此把阈值设置为 43200。

生产值必须通过 BytePlus 明确说明或真实合同测试确认。没有证据时不得把任意较小值当作已验证生产配置。

## 11. 敏感凭据数据模型

### 11.1 推荐采用独立一对一表

新增独立模型文件，例如：

```text
model/channel_asset_credential.go
```

建议表：

```text
channel_asset_credentials
```

建议字段：

| 字段 | 类型/约束 | 说明 |
| --- | --- | --- |
| `channel_id` | 主键或唯一索引 | 一条渠道最多一组素材凭据 |
| `access_key_id` | TEXT，非空 | Access Key ID，`json:"-"` |
| `secret_access_key` | TEXT，非空 | Secret Access Key，`json:"-"` |
| `created_time` | BIGINT | 创建时间 |
| `updated_time` | BIGINT | 最近轮换时间 |

第一阶段的数据库保护等级与现有 `Channel.Key` 保持一致，但必须做到：

- Model 字段使用 `json:"-"`；
- 普通渠道查询不联表读取凭据；
- 管理 API 不返回完整凭据；
- 不写入 `settings`、`other`、任务快照或审计详情；
- 不把凭据传给前端编辑默认值；
- 不把请求体或签名 Authorization 写入日志。

如果未来统一实现渠道密钥静态加密，应同时迁移 `Channel.Key` 和素材凭据，不能只为新字段增加一套依赖不稳定运行密钥的局部加密方案。

### 11.2 为什么使用独立表

- 避免扩写核心 `Channel` 表的供应商专用列；
- 减少上游代码同步冲突；
- 明确敏感信息和普通 settings 的边界；
- 便于独立轮换、审计和清理；
- 未来可以支持其他“控制面凭据不同于数据面凭据”的 Provider。

### 11.3 删除与复制规则

- 删除渠道时，在同一事务中显式删除对应素材凭据；
- 不依赖仅某一数据库支持的级联行为；
- 复制渠道时默认不复制素材 AK/SK；
- 批量新增和多 Key 模式下不得启用 `official_action_assets`；
- 新复制渠道如保留官方素材 profile，必须处于不可启用状态，直到管理员补齐独立素材凭据；
- 更推荐复制时把素材 profile 重置为 `none` 并显示提示。

## 12. 管理 API 合同

### 12.1 写入结构

渠道新增和更新请求增加仅写字段：

```json
{
  "asset_credential": {
    "access_key_id": "<write-only>",
    "secret_access_key": "<write-only>"
  }
}
```

要求：

- 新增官方 Action 渠道时两个字段必须同时存在；
- 更新时完全省略 `asset_credential` 表示保留原值；
- 更新时只提交其中一个字段必须拒绝；
- 两个空字符串不能被解释成“清空”；
- 清除凭据使用明确的管理动作，不使用空字符串隐式删除；
- 所有写入要求 `ChannelSensitiveWrite`；
- 审计仅记录 `asset_credential=created|rotated|removed`，不记录内容。

### 12.2 读取结构

普通渠道详情不返回凭据。管理表单只需要状态：

```json
{
  "asset_credential_status": {
    "configured": true,
    "access_key_id_hint": "AK******YAA"
  }
}
```

要求：

- 永不返回 Secret Access Key；
- Access Key ID 只返回不可用于认证的脱敏提示；
- Access Key ID 脱敏采用确定性规则：
  - 先去除首尾空白；
  - 长度大于 5 个 ASCII 字符时，仅保留前 2 位和后 3 位，中间固定显示 6 个 `*`，不通过星号数量暴露原始长度；
  - 长度不超过 5 时全部显示为 `*`；
  - 脱敏值只在响应时计算，不单独持久化；
- Secret Access Key 不返回任何前缀、后缀、长度或摘要提示；
- 未通过敏感权限验证的管理员只能看到 `configured`；
- 是否提供“查看完整 Access Key ID”应复用现有安全验证和审计机制，首期可以不提供。

### 12.3 原子性

渠道、新增 Ability 和素材凭据必须在同一数据库事务中保存。任一环节失败时全部回滚，不能出现：

- 渠道创建成功但素材凭据缺失；
- 凭据创建成功但渠道或 Ability 缺失；
- settings 已切换为官方素材 profile，但凭据轮换失败。

## 13. 后端改造方案

### 13.1 Model 层

新增独立文件承担：

- `ChannelAssetCredential` 模型；
- 按 ChannelID 查询凭据；
- 在事务中创建、替换和删除凭据；
- 返回是否已配置及脱敏提示；
- 计算官方素材账号身份所需的规范化 credential；
- 素材凭据变更时复用渠道素材生命周期栅栏。

在 `model/main.go` 的 AutoMigrate 列表中新增模型。迁移只能使用 GORM 和三数据库兼容字段。

### 13.2 渠道校验

现有 `validateChannelAssetSettings` 继续校验非敏感 settings：

- 渠道类型；
- 视频 profile 和素材 profile 的兼容性；
- Provider Project；
- Provider Region；
- Region 格式；
- Minimum Asset URL TTL；
- 单 Key 渠道约束。

以下校验从 `Channel.Key` 解析逻辑中移出：

```text
official_action_assets credential must use ACCESS_KEY|SECRET_KEY
```

替换为跨记录校验：

- `Channel.Key` 必须是非空模型 API Key；
- 独立素材凭据必须同时包含 AK 和 SK；
- 素材 profile 为 `official_action_assets` 时凭据必须存在；
- 非官方素材 profile 不得误用官方素材凭据；
- batch 和 multi-key 创建模式拒绝官方素材 profile。

### 13.3 凭据选择

新增统一的素材凭据解析入口，按 profile 选择：

| 素材 profile | 素材适配器使用的凭据 |
| --- | --- |
| `official_action_assets` | 独立素材 AK/SK |
| `ark_assets` | 现有 `Channel.Key` |
| `relay_assets` | 现有 `Channel.Key` |
| `joycreator_assets` | 现有 `Channel.Key` |

视频适配器不改语义，始终继续使用 `Channel.Key`。

TokenSave 渠道记录 `#27/#28` 不使用独立 AK/SK：`#27` 对应 `third_party_relay + relay_assets`（`/v1/media/* + /assets`），`#28` 对应 `third_party_reverse_proxy + ark_assets`（`/v1/ark/media/* + /v1/ark/assets/*`）。两者的 `Channel.Key` 都是 TokenSave 平台 Key。TokenSave `/v1/asset/*` 是独立的 JoyCreator management-only facade，不参与视频路由，也不等同于现有 `joycreator_assets` 直连路径。

`OfficialActionAdapter` 可以继续接收内部组合后的：

```text
ACCESS_KEY|SECRET_KEY
```

但该组合只允许在服务端内存中短暂生成，不保存到 `Channel.Key`，不返回给前端。

### 13.4 必须替换的素材凭据读取点

所有计算素材账号身份或建立适配器的路径必须统一读取素材凭据，包括：

- 普通素材渠道选择；
- 素材创建；
- 素材状态轮询；
- 素材改名和删除；
- 素材组创建、查询和删除；
- 对账任务；
- 真人授权渠道选择；
- 视频素材路由约束；
- `asset://ast_xxx` 南向引用解析；
- 生命周期栅栏与凭据变更检测。

不能只修改 `CreateAsset`，否则创建成功后轮询、视频引用或删除仍会因指纹不一致失败。

### 13.5 凭据指纹

当前实现把 `channel.GetBaseURL()` 和 `Channel.Key` 放入所有素材 profile 的指纹。对 `official_action_assets` 而言，这两个值分别是视频 Base URL 和视频/素材复用 Key，并不能准确表达官方素材账号身份。官方素材的真实 Action host 由 Region 推导，与视频 Base URL 无关。

本次改造必须显式修正该历史语义：官方素材指纹使用 Action host 和独立素材 AK/SK，不能沿用旧的 `channel.GetBaseURL()` 入参。

官方素材 binding 的凭据指纹应包含：

```text
版本域分隔符 official_action_assets/v2
+ official Action host（由 Region 规范化推导）
+ Access Key ID
+ Secret Access Key
+ asset_upstream_profile
+ Provider Project
+ Provider Region
```

视频 API Key 不再进入 `official_action_assets` 的素材指纹。

第三方素材 profile 的指纹行为保持不变。

凭据原文不得写入 binding；binding 只保存不可逆指纹。轮换 AK/SK、Project 或 Region 都必须导致新指纹。

该变化属于内部 Provider 账号身份算法升级。即使 AK/SK、Project 和 Region 实际没有变化，新算法生成的指纹也会与历史算法不同，因此不能在存在存量 `official_action_assets` 记录时直接切换。迁移必须按第 16.2 节执行；不得把指纹不一致的存量记录静默视为凭据已轮换。

### 13.6 生命周期栅栏

存在以下任一未删除资源时，禁止直接修改或清除素材账号身份：

- `AssetBinding`；
- `AssetGroupBinding`；
- 未终结的 `RealPersonAuthorization`。

受保护字段包括：

- 素材 Access Key ID；
- 素材 Secret Access Key；
- Provider Project；
- Provider Region；
- 素材 profile；
- 会改变 Action host 的配置。

模型 API Key 的变更是否应阻止，取决于绑定是否仍要求同渠道完成视频调用。当前资产绑定和视频路由共享 ChannelID，因此在本期仍按敏感渠道身份变更处理，避免创建后立即失去视频消费能力。

### 13.7 渠道删除

渠道删除流程：

1. 锁定渠道；
2. 检查活动素材生命周期记录；
3. 有活动资源时拒绝删除；
4. 删除渠道；
5. 删除 Ability；
6. 删除 `channel_asset_credentials`；
7. 提交事务。

### 13.8 渠道连通性测试

配置测试必须分成两个互不混淆的结果：

1. **视频凭据测试**
   - 使用模型 API Key；
   - 调用官方 `GET /api/v3/contents/generations/tasks?page_size=1` 任务列表接口；
   - 只读取最多一条已有任务，不创建、取消或删除视频任务；
   - 不发送 AK/SK。
2. **素材凭据测试**
   - 使用 AK/SK；
   - 优先调用只读 `ListAssets`；
   - 携带 Region 和 Provider Project；
   - 不创建或删除上游资源。

界面应分别显示：

```text
视频 API：可用 / 失败 / 未测试
素材 Action：可用 / 失败 / 未测试
```

不能只显示一个“渠道测试成功”，否则可能掩盖另一套凭据不可用。

管理表单持久显示两张测试卡片和各自状态。输入尚未保存的新模型 API Key 或素材 AK/SK 时，测试按钮保留但禁用，并提示先保存；测试始终使用数据库中已保存的凭据。两条测试接口只返回稳定错误码和不含 Provider 响应体的安全消息，禁止把上游错误正文或签名信息直接透传到浏览器。

## 14. 前端改造方案

### 14.1 条件显示

在 DoubaoVideo 渠道表单中：

- 选择官方视频协议后，现有 Key 标签显示为“模型 API Key”；
- 选择 `Official Action Assets` 后显示独立素材凭据区；
- 其他素材 profile 不显示 AK/SK；
- 切换 profile 不得把 AK/SK写入 settings JSON；
- 编辑已有渠道时素材凭据输入框保持空白，并提示“留空表示保留现有凭据”。

### 14.2 表单字段

新增：

```text
asset_access_key_id
asset_secret_access_key
```

它们只存在于表单值和写请求的 `asset_credential` 中，不序列化到：

```text
channel.settings
channel.other
channel.setting
```

### 14.3 交互与校验

- 新增官方素材渠道：AK、SK、Project、Region、TTL 全部必填；
- 编辑已配置渠道：AK/SK 留空表示不变；
- 只填写 AK 或只填写 SK：阻止提交；
- profile 与视频协议不兼容：阻止提交；
- multi-key、batch 模式：阻止启用官方素材；
- 显示已配置状态和脱敏 Access Key ID；
- Secret 输入使用密码控件，不提供自动回填；
- 错误信息指出具体字段，不使用笼统“渠道配置失败”；
- 所有用户可见文本通过 i18n；
- 不把密钥放入 URL、localStorage、错误 Toast 或调试日志。

### 14.4 防止重复“注册中”

素材注册界面必须处理后端终态错误：

- HTTP 409 `asset_binding_required`：停止 loading，提示“没有兼容的素材渠道”；
- `POST /v1/assets` 返回 HTTP 503 `asset_upstream_unavailable`：停止 loading，提示素材能力或素材上游暂不可用；
- 视频请求引用平台素材时返回 HTTP 503 `asset_library_disabled`：停止提交状态，提示素材库已关闭；
- HTTP 400 `asset_url_ttl_insufficient`：提示重新生成更长有效期 URL；
- HTTP 502/上游失败：显示平台稳定错误，不显示 Provider 原始敏感信息。

不能因为请求失败而保留本地“创建中”占位记录。

## 16. 数据迁移与兼容策略

### 16.1 新表迁移

通过 GORM AutoMigrate 新建 `channel_asset_credentials`，不得使用单数据库专有类型或 SQL。

必须验证：

- SQLite；
- MySQL 5.7.8+；
- PostgreSQL 9.6+。

### 16.2 旧配置识别

历史版本可能存在：

```text
Channel.Key = ACCESS_KEY|SECRET_KEY
asset_upstream_profile = official_action_assets
```

迁移不得自动假设该字符串一定是素材凭据并覆盖视频 Key，因为无法恢复原模型 API Key。指纹算法还会从“视频 Base URL + `Channel.Key`”升级为“Action host + 独立 AK/SK”，所以必须在部署前检查存量 `official_action_assets` 资源。

#### 16.2.1 上线前置检查

按渠道统计以下所有未终结记录：

- `AssetBinding`；
- `AssetGroupBinding`；
- `RealPersonAuthorization`；
- `AssetOwnershipClaim`；
- `AssetGroupOwnershipClaim`；
- `AssetReconciliationFinding`。

本次排障时当前本地数据库中素材、绑定、幂等和任务表均为空，因此当前测试实例不存在存量指纹迁移负担。但迁移程序和上线手册不能据此假设其他环境同样为空。

#### 16.2.2 无存量资源

如果所有官方素材渠道均无存量资源：

- 启动迁移只创建新表；
- 不自动拆解或搬运 `Channel.Key`；
- 管理界面标记“官方素材凭据未配置”；
- 渠道保持 fail closed，不参与素材路由；
- 管理员填写模型 API Key 和独立素材 AK/SK；
- 完成视频和素材双测试后再启用素材 profile。

#### 16.2.3 存在存量资源

如果存在存量资源，不得直接部署新指纹算法，也不得为了绕过生命周期栅栏把本地记录直接标记为 `deleted`。后者会掩盖仍存在的上游素材和素材组，并可能永久失去轮询、删除和所有权审计能力。

安全迁移流程：

1. 通过动态配置暂停新的普通素材创建，但保留轮询和删除任务；
2. 备份主数据库，并锁定待迁移渠道；
3. 确认旧 `Channel.Key` 能按历史官方素材合同解析为 AK/SK；
4. 使用只读 Action 验证旧 AK/SK、Provider Project 和 Region 仍指向同一 Provider 账号；
5. 由管理员显式提供新的模型 API Key，不能从旧记录推断；
6. 在同一数据库事务中：
   - 写入独立素材 AK/SK；
   - 把 `Channel.Key` 更新为模型 API Key；
   - 计算 `official_action_assets/v2` 新指纹；
   - 更新 `AssetBinding`、`AssetGroupBinding`、`RealPersonAuthorization`；
   - 同步更新 `AssetOwnershipClaim`、`AssetGroupOwnershipClaim` 和 `AssetReconciliationFinding` 中对应的 Provider 账号指纹；
   - 检查所有唯一索引冲突，任一冲突时整体回滚；
7. 提交后重新执行只读素材测试，并逐项验证轮询、引用和删除能力；
8. 验证通过后恢复普通素材创建。

该事务是受控的“同一 Provider 账号身份算法升级”，不是普通渠道编辑。只有在旧、新凭据被验证为同一账号边界时才能绕过普通生命周期变更拒绝；否则应保留旧兼容读取路径完成上游清理，或由管理员在旧版本下先删除上游资源。

如果无法确认旧凭据身份、无法提供模型 API Key，或出现所有权唯一索引冲突，迁移必须失败关闭，不得重算指纹、伪造终态或丢弃所有权记录。

实现提供受控命令 `cmd/migrate-official-asset-credential`。命令默认只检查并输出迁移计划；只有增加 `--apply`、在标准输入 JSON 中显式确认同一 Provider 账号，并通过只读 `ListAssets` 校验后才执行事务。输入中的旧 AK/SK 必须与历史 `Channel.Key=AK|SK` 完全一致，Project 与 Region 也必须与渠道已保存值一致。命令不接受命令行密钥参数，输出不包含任何凭据。

该命令会同步重算 `AssetReconciliationFinding.scope_hash`，并让绑定、素材组、真人授权、两类所有权声明与对账记录在同一事务内切换到 v2 指纹。任一未知指纹、所有权唯一索引冲突或写入失败都会整体回滚。多条历史渠道必须逐条迁移；全部完成后再正常启动服务，由启动迁移栅栏做全库复核。

- 输出只包含成功/失败和稳定错误类型，不打印请求签名、Authorization 或响应敏感字段。

### 18.6 端到端验收

1. 新建或更新官方渠道；
2. 视频凭据测试通过；
3. 素材凭据测试通过；
4. `POST /v1/assets` 返回 HTTP 202，而不是 409；
5. 自动创建或复用普通 `AIGC` 素材组；
6. 素材进入 `processing` 后轮询到 `ready`；
7. 平台素材详情不暴露上游 ID；
8. 视频使用 `asset://ast_xxx` 成功；
9. 南向请求使用上游 `asset://asset-xxx`；
10. 删除素材后完成上游删除和本地终态；
11. 数据库、后端日志、前端网络响应中无 AK/SK。

## 19. 验收标准

### 19.1 功能

- 普通素材全局能力默认开启；
- 官方渠道可以同时保存两套凭据；
- 新增同类渠道只需要管理员填写配置；
- 视频和素材分别使用正确鉴权；
- 素材创建、轮询、引用和删除闭环成功；
- 相同 Project 内素材可以被对应 Endpoint 消费。

### 19.2 北向合同

- `/v1/assets` 请求和响应字段不增加 Provider 凭据；
- 平台素材 ID 保持 `ast_xxx`；
- 普通客户不感知 Project、Region、AK/SK；
- Provider 错误被映射为平台稳定错误码。

### 19.3 安全

- Secret Access Key 不出现在任何读取 API；
- AK/SK 不出现在日志、审计详情和错误响应；
- 凭据修改需要敏感权限；
- 活动素材存在时不能直接轮换或删除凭据；
- 测试工具不执行有副作用的上游创建或删除操作。

### 19.4 兼容

- 第三方 DoubaoVideo 渠道不受影响；
- 非素材渠道不需要新增字段；
- SQLite、MySQL、PostgreSQL 均通过迁移和测试；
- 现有视频 API Key、模型映射和计费行为不变。

1. 合并并验证新表迁移；
2. 先部署兼容新旧渠道的后端；
3. 部署带双凭据表单的前端；
4. 对当前测试渠道补充素材配置；
5. 执行只读素材 Action 测试；
6. 使用公开 HTTPS 测试对象创建普通素材；

8. 检查日志与数据库敏感字段边界；
9. 再允许新增更多同类渠道。

上线期间不得把真实 AK/SK放进：

- `.env.example`；
- 文档；
- 单元测试；
- 前端默认值；
- Git 提交信息；
- 日志排障命令输出。

## 21. 回滚方案

### 21.1 功能回滚

如上线后素材创建异常：

- 通过数据库动态配置关闭新的普通素材创建；
- 保留后台轮询、删除和清理任务；
- 不删除已有素材表或凭据表；
- 不停止已进入 processing、deleting 的任务；
- 视频不引用素材时继续按原路径工作。

### 21.2 渠道回滚

- 没有活动素材资源时，可以把渠道素材 profile 改回 `none`；
- 有活动资源时不得绕过生命周期栅栏；
- 应先停止新建，完成素材删除和上游清理，再移除凭据；
- 回滚前端时后端仍需兼容已保存的双凭据，避免凭据和素材成为孤儿。

### 21.3 数据库回滚

不建议回滚时删除 `channel_asset_credentials` 表。表是附加结构，保留不会影响旧版非素材渠道；直接删除可能导致已有素材无法轮询或删除。

## 22. 风险与待确认项

| 风险/待确认项 | 影响 | 处理 |
| --- | --- | --- |
| BytePlus 未明确源 URL 最小抓取窗口 | TTL 可能不足或过度限制 | 通过官方说明或真实合同测试确认 |
| Endpoint 不属于配置的 Project | 素材创建成功但视频不能引用 | 上线前核对 Endpoint Project |
| AK/SK 权限不足 | Action 返回鉴权或权限错误 | 使用只读 `ListAssets` 验证 |
| 账号未开通素材权益 | 配置正确仍无法创建 | 控制台确认权益 |
| 凭据轮换破坏历史素材管理 | 无法轮询、删除或引用 | 生命周期栅栏禁止直接轮换 |
| 官方素材指纹算法升级 | 存量绑定、素材组、授权和所有权记录失效 | 上线前统计；零存量直接切换，非零按 §16.2 受控迁移 |
| 批量渠道共享同一素材账号 | 重复创建与绑定不确定 | 首期禁止 batch/multi-key |
| 管理接口误返回 Secret | 凭据泄露 | 独立表、`json:"-"`、合同测试 |
| 前端失败后仍显示“创建中” | 用户误判状态 | 对所有终态 HTTP 错误清理 loading |

## 23. 改造完成后的标准新增流程

后台逐字段配置、连通性测试和常见错误处理见
[BytePlus 官方视频与素材渠道配置操作指南](./2026-07-26-BytePlus官方视频与素材渠道配置操作指南.md)。

以后新增同类 BytePlus 官方渠道，管理员只需：

1. 选择 DoubaoVideo；
2. 选择官方视频协议；
3. 填写官方视频 Base URL；
4. 填写模型 API Key；
5. 填写平台公开模型名；
6. 配置公开模型到 Endpoint ID 的映射；
7. 选择 `Official Action Assets`；
8. 填写素材 Access Key ID；
9. 填写素材 Secret Access Key；
10. 填写 Provider Project；
11. 填写 Provider Region；
12. 填写经验证的 Minimum Asset URL TTL；
13. 分别执行视频和素材只读测试；
14. 保存并启用渠道。

只要新渠道继续遵循相同的 BytePlus 官方视频和素材 Action 合同，就不需要修改代码。只有 Provider 更改鉴权、Action、Version、域名规则或新增不同协议时，才需要扩展适配器。

## 26. 实施结果（2026-07-26，2026-07-27 补充）

已完成：

- 新增一对一表 `channel_asset_credentials`，并接入普通与 fast GORM 迁移；
- 渠道新增、更新、轮换和显式清除素材凭据均使用数据库事务；
- 渠道详情只返回 `configured` 与按固定规则生成的 Access Key ID 脱敏提示；
- `Channel.Key` 保持为视频 Bearer API Key，官方素材适配器改从独立表读取 AK/SK；
- 官方素材指纹升级为 `official_action_assets/v2 + Action host + AK + SK + profile + Project + Region`；
- 渠道选择、创建、轮询、删除、对账、真人授权、路由约束、引用解析和生命周期栅栏统一使用新的素材凭据解析入口；
- 删除渠道时同步删除独立素材凭据，复制官方素材渠道时把素材 profile 重置为 `none`；
- 新增只读视频任务列表测试和只读 `ListAssets` 素材 Action 测试，管理表单并列持久显示“未测试/测试中/可用/失败”状态；
- `ark_assets` 与 `relay_assets` 新增各自只读列表连通性测试，分别覆盖 TokenSave `/v1/ark/assets/list` 与 `/assets/list`，不创建、修改或删除素材；
- 本地渠道 `#27` 已配置为 `third_party_relay + relay_assets`；渠道 `#28` 已配置为 `third_party_reverse_proxy + ark_assets`，并补齐 `doubao-seedance-2-0-260128 → dreamina-seedance-2-0-260128` 模型映射；
- TokenSave `/v1/asset/*` 被确认是 JoyCreator management-only facade，不并入 `#27/#28` 的视频素材 profile，也不误用现有 JoyCreator 直连适配器；`ark_assets` 的精确素材组删除合同仍未公开，继续 fail closed，不以路径猜测换取表面能力完整；
- 连通性接口返回稳定错误码和安全消息，不再透传底层错误详情；
- 渠道表单新增独立 AK/SK 密码字段、已配置状态、脱敏提示、留空保留、双字段校验和显式清除入口；

- 新增受控存量迁移命令，支持计划检查、只读账号校验、v2 指纹全记录事务迁移和唯一索引冲突回滚；
