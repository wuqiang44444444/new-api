# 本地真实渠道端到端冒烟测试方案

## 1. 目标与交付口径

使用本地网关已经配置的真实渠道，在发布前完成一次低调用量、可复核的业务闭环：

```text
本站客户 API Key → 本地公开 API → 真实鉴权/授权/选渠/计费 → 真实 Provider
    → 同步结果或持久任务 → 真实媒体交付 → 主库资金事实与日志核验
    → Browser Use 登录客户/管理界面 → 定位同一请求/任务 → 核对展示
```

接口成功、数据正确、界面正确三项均有证据，单个用例才算通过。管理端渠道测试按钮只用于连通性预检；
直连 Provider、模拟 Provider、前端组件测试均不能代替本方案的真实客户链路。

本文件是待执行方案，不表示已发生真实调用、扣费、界面验收或生产发布。首版建议先做
“代表性链路冒烟”，再对本次拟发布渠道做定向覆盖，不把所有模型与所有参数的笛卡尔积放入日常冒烟。

## 3. 测试规模与执行前提

### 3.1 两种规模

| 规模 | 覆盖 | 频率与完成口径 |
| --- | --- | --- |
| 快速冒烟 | 发现/报价、文本非流式与流式、图片生成/编辑、已启用的异步图片、一个标准视频、授权失败、同笔界面核验 | 每次发布；人工操作目标约 20–40 分钟，Provider 排队与生成可能延长；只证明已测组合 |
| 发布覆盖 | 对每个拟发布渠道/协议至少补一个成功用例、一个可确定的失败用例，并执行本次变更关联项 | 渠道、adapter、计费或存储变更时；不能用另一个渠道成功代替 |

按“客户模型 + 实际渠道 + 代码协议/插件版本 + 入口 + 分组/合同 + 执行方式”生成本次清单。
同一协议多个渠道若都拟发布，则逐渠道覆盖；若只是日常快速抽样，报告明确列出未测组合。
模型名相似、同一个 Provider、同一渠道类型都不是等价通过证明。

### 3.2 前置检查

1. 确认前端和后端来自本次待发代码，记录 Git HEAD、dirty 状态与受测改动摘要、构建时间。
   浏览器禁用旧页面复用造成的版本误判，完成页面重载；生产构建发布前再用实际构建做一轮界面复核。
2. 确认实际主库、日志库及 Redis 命名空间，不打印 DSN；核实数据库方言、日志是否分库、后台 worker 是否工作。
   不直接把仓库根目录 SQLite 文件当作运行实例主库。只读 SQL 必须连接已确认的实际数据源。
3. 优先复用已存在的本地测试用户和渠道。测试用户 A 使用钱包资金来源、有限额 Key、独立测试分组，
   测试时不运行其它负载、不充值、不进行人工额度调整；用户 B 用于越权验证。
   若实现支持明确 app 隔离，再准备 A 的同 app Key 与不同 app Key；不能把换 Key 自动视为换 app。
4. 原生模型在隔离测试分组/合同内限定到本次目标渠道，随后从执行证据核实实际命中。
   不用管理员专属 pin 代替客户公开调用；不改全站分发策略。Seedance/MiniMax 遵守各自确定性模型路由，
   不为复制测试渠道新增同名已启用模型，不向 Ability 或通用分发池写入类型化渠道。
5. 记录每个用例的公开客户模型、入口、请求模板、协议、预计最多创建次数、单例与全轮费用上限、
   可接受等待时间和资金预扣上界。费用未知或余额不足的组合先阻塞，不能无限试探。
   预算计入预扣、在途及未知创建的可能成本，不只统计已完成日志；每次新 POST 前检查剩余预算。
6. 使用已批准的无敏感内容提示词与自有测试媒体。参考图必须能被真实 Provider 拉取；
   `localhost`、本机文件路径不等于可用的公开参考 URL。托管素材按现有私有存储配置执行。
7. 对象存储必须通过现有配置的实际读写与授权交付检查；不能只测 TCP 连通。
   不设置公开桶、不关闭鉴权/SSRF、不新增生产测试接口。
8. 管理员只读核验权限、客户登录会话和业务 API Key 分开使用。Key/密码由已有安全渠道读取到内存，
   不放进清单、命令行参数、终端输出、截图或仓库。缺少必要权限/配置记阻塞，不把未执行记通过。

首次执行推荐在独立本地数据库与独立缓存中使用现有渠道的受控配置副本，保留真实 Provider 连接。
SQLite 使用一致性备份机制，不能对在线 WAL 库只复制单个主文件；外部数据库使用原生一致性导出。
副本不得自动启动历史在途任务的 worker：只迁移本轮需要的配置及隔离测试身份，先检查旧任务，
避免同一个 Provider 任务被两个实例结算/转存。不要复制整库后立即启动后台扫描。

| N1 | 缺失/无效 Key；合同未列模型或 Key 明确排除模型 | 使用合法业务请求体隔离验证鉴权/授权错误；保存对应入口的预期 HTTP/错误类别；受拒绝请求无新增消费、hold 或 Provider 创建 | 客户错误提示可理解，客户无权打开管理页面或管理员证据 |
| N2 | 图片 `n > dto.MaxImageN`、负数；视频超已登记时长上限等确定性非法输入 | 入口明确 400；无外发、无预扣、无负费用；不把现有 `n=0` 归一行为误判成必须拒绝；不从猜测的数值上限写用例 | 如有该输入界面，验证提示；否则通过日志/错误页验证可观测性，不伪造不存在的表单 |
| N3 | 用户 B、以及明确不同 app 的 Key 查询本轮 Task/下载制品 | 按各合同的无权/不可见语义拒绝；没有响应正文或下载链接泄漏；同用户同 app 替换 Key 按实际合同校验，不能一概断言拒绝 | B 的列表/搜索/详情无法看到 A 的私有任务与账单 |

建议基础真实创建量：T1/T2 两次文本，I1/I2 两次图片，I3 一次异步图片，V1 一次视频；
A1 启用时额外一次素材创建。I3 幂等重放不是新的付费创建意图，须核实确实没有第二次执行。
API 与 UI 共用这些结果，减少重复付费。预计次数是预算输入，不保证实际价格或 Provider SLA。

对每个拟发布协议增加一个已验证、可重复的失败请求。优先选择入口校验失败；它只能证明本地拒绝。
若变更涉及上游错误转换或失败退款，还必须取得真实 Provider 明确拒绝或失败证据，核对该次资金释放。
不得用随机坏参数或审核违规内容赌博式触发失败；无法确定或未出现时标未验证。

### 4.2 本轮明确覆盖：文本、图片、Seedance Mini 4 秒

本轮三类必测范围固定如下，不以未选中的其他能力扩大基础冒烟：

| 类别 | 必测用例 | API、数据、界面三层证据 |
| --- | --- | --- |
| 文本 | T1 非流式 + T2 流式 | 真实文本结果/SSE 完成 → 实际渠道、usage、净扣费 → 同笔消费日志与费用详情 |
| 图片 | I1 文生图 + I2 参考图编辑；已发布异步图片另加 I3 | 真实图片可解码 → 输入/输出计量及冻结费用 → 价格页、同笔账单分项和实际结果检查 |
| 视频 | V1 Seedance Mini，显式 4 秒 | 真实创建、轮询、OSS 就绪 → Mini 映射、4 秒冻结事实、预扣/结算 → 同笔任务、可播放结果与媒体时长 |

V1 的 `model` 必须是本地已配置并批准的公开客户模型，不能把 Provider 模型名直接填进客户请求，
也不能仅因客户名称包含 `mini` 就认定命中正确实现。执行前在内部核实专用 ChannelType、
代码协议与精确 `model_mapping`；公开报告只保留匹配结论。现有飞彩代码登记的 Mini 为 720p、
4–15 秒（`plugins/seedance-link/plugin.js` 的 `MODEL_SPECS`；另见
[飞彩验收手册](../40-operations/06-飞彩Seedance全模型上线验收手册.md)），
该事实不能推广为其它 Provider Mini 的相同参数合同。若本地目标 Mini 不支持 4 秒，应标阻塞，
不能静默改为 5 秒、换成标准版或用 MiniMax 结果代替。

4 秒请求必须显式填写北向 `duration: 4`，不能省略后依赖默认时长。下载后用媒体探测读取实际时长，
与 Provider/容器合同及浏览器显示对照；容器时间基误差按已验证合同记录，不能自行放宽为其它时长。
按秒模型核对冻结的秒数、单价及倍率/折扣；按 Token 模型按真实用量结算，不能直接以“4 × 秒价”
替代。素材引用 A1 若纳入本轮，可以并入这一次 Mini 4 秒创建，前提是所选协议明确支持该引用。

三类均必须完成各自真实 API、数据与 Browser Use 验证，才可以报告“三类覆盖通过”。
只有方案条目而没有运行证据时，只能报告“三类已纳入方案”。Responses、其它视频型号、
MiniMax 与 Batch 仍按 4.1 的发布/变更条件执行，不计入这三类最小覆盖的替代证据。

## 5. 数据如何核验

### 5.1 先建立唯一关联

每个用例生成 `run_id + case_id`，只放进无敏感内容的提示词标记或执行器元数据，不向 API 塞未发布字段。
记录响应头 **`X-Oneapi-Request-Id`**、公开任务 ID、测试用户/Key 的内部别名、请求开始/结束时间。
不要假设服务接受客户端指定的请求 ID。请求重放的 HTTP 请求 ID 与原业务任务 ID 分开保存。

同步请求用 request ID 关联日志；异步用公开 task ID 关联 Task、attempt、资金和后续日志。
`tasks.task_id` 与 `task_create_attempts.public_task_id` 的关联按对应实现读取，不能拿上游 task ID
冒充公开 ID。日志没有外键时，使用既有资金/任务引用解析关系，不只靠“时间相近、金额相等”。
若关联无法唯一证明，标 `BLOCKED`，不能猜选一条记录。主库与日志库分开读取，不要求跨库 SQL JOIN。

### 5.2 三个观察时点

| 时点 | 要读取的事实 | 断言 |
| --- | --- | --- |
| before | 用户钱包 quota、有限额 Key remaining/used、本轮任务/attempt/日志基线、实际价格/合同版本 | 明确没有并行流量和未纳入统计的资金变动；不能拿历史总额代替基线 |
| accepted | 适用路径的 Task 或 attempt、资金来源、hold/转移状态、冻结渠道/协议/价格摘要 | 同步/异步图片、视频、Batch 分别遵守自己的受理语义；短暂态没观察到不能断言原子性已证明 |
| settled | Task 业务与资金状态、消费/差额/退款日志、余额、用量、交付对象状态 | 资金已最终提交且日志交付完成；重复 GET 后业务终态、净额和计费次数不变 |

管理员优先通过既有 API 只读核对；API 不提供的必要内部事实使用受控只读 DB 查询。
查询显式列举白名单字段，不 `SELECT *`，不输出 Channel key、Task private_data、冻结连接或原始响应。
私有计费快照只在内存中取必要字段，输出“协议匹配/冻结事实匹配/数量/金额”等脱敏结果。
需要证明无外发时，结合既有发送证据/管理员错误分类；仅“没有日志”不是完整证明。

### 5.3 金额不变量

首轮固定钱包来源、有限额 Key、无充值/赠送/人工调整/并发负载。令 `Q` 为本轮已终结请求的
最终净扣费（消费 + 计费差额 − 已实际退款，按既有日志类型及资金引用分类，排除重复投影与诊断记录）：

```text
用户 quota_before − quota_after = Q
有限额 Key remaining_before − remaining_after = 该 Key 本轮实际受跟踪的净扣费
```

先确认 Key 是否参与 quota 跟踪；无限额 Key、订阅和信任旁路不能套用上述 Key 余额断言。
有在途 hold 时单独列出，不能用最终费用等式直接判断已结算。`used_quota` 按该路径实际累计/退款
语义校验；用户累计列是 64 位统计，不能套单笔 int32 截断。日志存在负的退款/冲正金额可能是正确会计
语义，要拒绝的是溢出形成的负收费、重复结算和无依据信用，不是拒绝一切负数。

复算仅读取本笔冻结价格、分支、真实计价用量、有效组倍率、合同折扣、附加费与当时 quota 单位；
使用现有换算和舍入规则。原始 quota 必须精确一致；UI 金额以其显示精度核对，不用一个宽泛百分比
容差掩盖误差。当前 `/api/pricing` 是下一笔报价，不能用于重新解释历史请求。

视频成功时 attempt 完成与 hold 转 Task 必须对应同一个业务创建，不能把 hold 与终态消费各算一笔
总消费。多条预扣/差额/退款日志可能合法，不能断言“只允许一行日志”。Provider 成本没有证据就保持
未知，不把客户费用当供应商账单。真实供应商账单有延迟时单独标“待对账”，不影响已证明部分的描述。

### 5.4 当前图片计费展示的专项断言

1. I1 提供无参考图正样本；I2 尽量取得真实 `img > 0` 正样本。Provider 未报告该分类时明确记录缺口，
   不能靠本地合成字段补成真实用量。
2. 只展开冻结表达式实际引用的变量。`c` 与 `img_o` 数量相同不表示两项都收费；
   `p/c` 保持未单独计价输入/输出的兜底语义，不根据模型名强行命名为某个模态。
3. 比较客户响应里的 `billing_explanation.lines`、页面分项、模型费与最终账本金额。
   缺失、显式 0、正值分别验证，缺少历史证据不得用当前价格回填分项。
4. 缓存价格已配置与本次缓存命中分开验收。重复两次真实请求不保证缓存命中；
   没有缓存正样本就标“真实缓存分项未验证”，不能声称缓存费用正确或供应商无优惠。
5. 历史无完整计费证据的记录只读验证“不可展开/未记录”等提示，不改库伪造历史。

## 6. Browser Use 界面验证流程

使用当前可用的 Computer Use/browser automation 工具实际操作浏览器；本方案不依赖安装名为
`browser-use` 的额外 Python 服务。每步基于当前 DOM/可访问树定位控件，并结合截图看布局。
工具初次发现返回清单不等于浏览器导航或登录已可用，正式执行须先打开受测本地页面完成预检。

1. **客户上下文 A**：打开本次前端 Origin，用现有账号登录。确认版本、身份、中文，进入 `/pricing`，
   搜索本轮模型并打开详情；核对价格单位、图片/缓存说明及实际选择的组/合同上下文。
2. **API 写入后 UI 读取**：打开 `/usage-logs/common`，用请求 ID 等现有筛选能力定位 T1/T2/I1/I2。
   以真实页面支持的搜索项操作；不假设一定存在 request ID 输入框。若页面不支持精准筛选，
   先由 API 得到唯一记录，再结合用户/Key/模型/时间定位并展开确认请求 ID。
3. **账单详情**：展开 I1/I2；比对真实 API/只读数据结果中的计价用量、冻结单价、组倍率/折扣、
   逐项金额与总费用。截图保留对应记录标识与摘要；不把价格表当成这笔实际用量。
4. **任务与交付**：打开 `/usage-logs/task`，定位 I3/V1，刷新确认后台终态可恢复；
   实际打开制品预览，验证图片尺寸/内容、视频可播放并拖动。主视频 ready 不代表末帧也 ready，分开检查。
   预签名链接仅留在受控运行内存中；下载重定向到 OSS 时不转发平台 Authorization。
5. **账单聚合**：在 `/billing` 查看本轮所属时间范围/Key 的变动。聚合存在延迟时按实际刷新周期有界等待，
   不把页面刚打开的一次旧缓存判成资金错误；最终与已结算明细对齐。
6. **管理员上下文**：单独登录管理员，在 `/channels` 只读核对本轮渠道状态和已登记协议；
   在对应日志/任务详情核对实际命中与客户不可见诊断。不要点击批量测试按钮或触发另一轮真实创建。
7. **越权上下文 B**：切换为 B 后访问本轮私有详情与受限下载入口，确认无记录、无链接泄漏。
   A/B 使用独立浏览器会话；工具不支持隔离会话时显式登出/登录并重新确认身份，不能只切标签页。
8. **英文复核**：同一 I1/I2 详情与价格页切换英文，验证标签、币种/百万 Token 等单位、数值和缺计量提示，
   再重载确认内容仍正确。仅要求 `zh/en`。

若本次发布包含 Playground，再增加一个通过 `/playground` 点击发送的真实短文本请求：确认逐步输出、
成功完成并关联新增消费日志。它单独纳入调用量/预算，因为 Playground 使用 `/pg/chat/completions`，
不能替代 T1/T2 的客户 Key 授权测试。图片/视频若没有已发布创建界面，不编造“在 UI 点击生成”的用例。

每个界面检查保存操作摘要、受测路由、对应 case/request/task 别名、可见关键值和脱敏截图。
截图须避开凭据显示、浏览器签名 URL 地址栏和私有证据原文；不要默认导出完整 HAR、Cookie、
localStorage 或原始网络正文。浏览器操作失败单列 `UI_BLOCKED`，接口通过不能覆盖界面缺口。

## 7. 执行器的最小实现建议

本批交付方案，以下为待实现入口，不是当前已有命令。首版建议独立放在 `scripts/e2e/`，
复用已有公开 API 与管理员只读接口，不修改生产 Router、计费热路径或原生 DTO：

| 拟新增文件 | 职责 |
| --- | --- |
| `scripts/e2e/local-real-smoke.mjs` | 使用 Bun 执行 preflight、公开请求、轮询、预算检查与断言；业务创建串行 |
| `scripts/e2e/local-real-smoke.example.json` | 只有非敏感模型别名/入口、用例选择、预算、截止时间与环境变量名称；不存凭据/私有配置 |
| `scripts/e2e/README.md` | 执行说明、Browser Use 操作清单、凭据注入方式、真实调用与费用边界 |
| 受控运行目录下的 `run.json`、`cases.json`、`checks.json`、截图与 `report.md` | 本轮脱敏证据；目录位置在运行前选择并排除版本控制；不保存完整原始请求/响应 |

执行阶段分为 `preflight → API → data → browser → report`，支持从已保存的公开 task ID 恢复查询。
恢复模式只读查询与核验，不能重新执行不明结果的 POST。首次发送前持久化本地用例发送意图，
崩溃恢复时把“可能已发”列为待核实；本地执行记录只是防误操作，不替代服务端 durable attempt 或幂等合同。
同一轮禁止并发创建，查询可有界轮询；错误退出必须输出仍在途/held 的用例摘要。

轮询间隔、最大等待时间按实际 Provider 与现有 Retry-After/公开合同配置，使用单调时间截止；
普通查询暂时失败可继续有界查询，但不得新建任务。仅状态查询达到 succeeded 还要等待适用的资金与交付。
输出结构至少包含：`run_id`、代码/工作区版本摘要、环境摘要、case ID、覆盖组合、HTTP 状态、
平台 request/task 别名、实际选渠匹配布尔值、业务/资金/交付状态、quota 差额、UI 结论、证据索引。
受控索引可保存后续查询必需的公开 task ID，不记录上游 task ID、Provider 连接信息或 Task 私有内容。

提供 `PASS / FAIL / BLOCKED / NOT_APPLICABLE` 四种单例结果，界面、账单、Provider 对账另列维度。
进程只在所有必测项 PASS、无 BLOCKED 且证据完整时成功退出；未勾选必测项视为清单错误，
不能让一个空用例集返回“全部通过”。所有失败退出都保留资金处置清单。

## 8. 异步异常、费用与清理

- POST 超时、连接断开或创建结果未知：记录平台请求 ID，停止该用例的创建动作，核查 attempt/hold。
  Seedance ModelArk V3 不提供客户 `Idempotency-Key` 合同，绝不因客户端超时再发一次。
- 不能在日常真实冒烟里主动断网/杀服务制造 unknown，这可能留下真实供应商成本。发送许可原子性、
  崩溃窗口、24 小时保障退款、并发结算与故障恢复由确定性回归/隔离演练保护；真实烟测只能证明本轮观测。
  若自然出现 unknown，按 [ADR-0021](../20-architecture/decisions/0021-视频创建占款24小时资金保障退款.md)
  保留未知业务结论和到期资金释放责任，不能因为测试窗口结束就提前退款或伪造失败。
- 明确失败的媒体请求按对应合同检查实际释放；Batch 按已执行行实际收费，不套用媒体全退规则。
  视频生成成功但 OSS 转存失败时，保留生成与资金事实，报告交付失败，不重新生成或自动退款。
- 超出费用预算、实际路由不符、重复上游创建、重复结算/退款或私有信息泄漏：停止发起后续新请求，
  保留后台查询/结算所需运行条件，产出失败及在途清单。不要为恢复余额而直接 UPDATE 数据库。
- 默认不删除 Provider 素材组、不删媒体对象、不改历史日志、不回滚已经发生的真实费用。
  临时测试 Key/分组在任务全部完成并对账后按既有管理流程停用；保留必要审计，不复用过期签名链接。
  素材组留存清单交运维，平台不提供素材组删除；托管素材删除只停止新引用，不承诺清理 OSS。

## 9. 发布判定与实施批次

### 9.1 本轮判定

只有同时满足以下条件，报告才写“本地真实冒烟通过”：

1. 本轮所有必测公开入口均有真实成功或明确合同失败证据；实际渠道/协议符合清单。
2. 结果可解码/播放，适用任务达到真实终态、资金终态与可交付状态；重复读取不产生重复费用。
3. 钱包/Key、冻结计费与分类后的日志净额对齐；无无法解释的差额、负收费或泄漏。
4. Browser Use 已实际完成同一笔数据的客户/管理界面核对和必要隔离检查。
5. 费用未超预算，未验证能力、在途资金与供应商对账缺口单独列出，不用“接口 200”覆盖。

报告还必须分别写清：本次未测渠道/协议、真实缓存正样本是否取得、真实 Provider 账单是否核对、
三数据库验证范围、恢复/24 小时保障是否仅有回归证据，以及生产灰度是否执行。
“快速冒烟通过”不自动升级为“全部渠道可上线”；本次拟发布组合有 FAIL/BLOCKED 时不得发布该组合。
