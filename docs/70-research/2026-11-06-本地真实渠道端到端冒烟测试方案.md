# 本地真实渠道端到端冒烟测试方案

## 1. 目标与交付口径

使用本地网关已经配置的真实渠道，在发布前完成一次低调用量、可复核的业务闭环：

```text
本站客户 API Key → 本地公开 API → 真实鉴权/授权/选渠/计费 → 真实 Provider
    → 同步结果或持久任务 → 真实媒体交付 → 主库资金事实与日志核验
    → Browser Use 登录客户/管理界面 → 定位同一请求/任务 → 核对展示
```

接口成功、数据正确、界面正确三项均有证据，单个用例才算通过。管理端渠道测试按钮只用于连通性预检；
直连 Provider、模拟 Provider、前端组件测试均不能代替本方案的真实客户链路。

本文件定义后续执行口径。历史执行与复验见第 9.3 节。建议先做
“代表性链路冒烟”，再对本次拟发布渠道做定向覆盖，不把所有模型与所有参数的笛卡尔积放入日常冒烟。

## 3. 测试规模与执行前提

### 3.1 两种规模

| 规模 | 覆盖 | 频率与完成口径 |
| --- | --- | --- |
| 快速冒烟 | 发现/报价、文本非流式与流式、图片生成/编辑、已启用的异步图片、一个标准视频、授权失败、已鉴权校验失败、本地浏览器验收 | 每次发布；人工操作目标约 20–40 分钟，Provider 排队、生成及报表发布可能延长；只证明已测组合 |
| 发布覆盖 | 对每个拟发布渠道/协议至少补一个成功用例、一个可确定的失败用例，并执行本次变更关联项 | 渠道、adapter、计费或存储变更时；不能用另一个渠道成功代替 |

按“客户模型 + 实际渠道 + 代码协议/插件版本 + 入口 + 分组/合同 + 执行方式”生成本次清单。
同一协议多个渠道若都拟发布，则逐渠道覆盖；若只是日常快速抽样，报告明确列出未测组合。
模型名相似、同一个 Provider、同一渠道类型都不是等价通过证明。

### 3.2 用 `./start.sh` 启动本地真实环境

每轮本地真实冒烟（含定向复验）必须从受测工作区的仓库根目录执行 `./start.sh`，由该脚本启动前后端。
先按[本地搭建](../30-engineering/本地搭建.md)
准备开发 PostgreSQL，确认脚本为本次后端生成的连接指向预期开发库，并核实实际日志库、缓存、对象存储、
真实渠道和测试身份。
启动脚本会停止所选端口的监听进程，运行前确认端口归本轮使用；遇到无关进程可显式指定空闲的
`FRONTEND_PORT` 和 `BACKEND_PORT`。

```bash
./start.sh
```

保持脚本会话运行。后端 `/api/status` 明确返回成功且前端首页就绪后，用客户 API 请求指向
`http://localhost:3501`，用本地 Browser Use 打开 `http://localhost:3500`；覆盖端口时使用实际地址。
通过浏览器登录和页面实际 API 请求确认前端连接本轮后端，记录实际启动命令、启动时间、两端地址、
本轮日志目录及脱敏数据源摘要。后续 API、界面及数据核对使用本轮实例产生的同一批数据。
启动、健康检查或前后端指向无法确认时，标 `BLOCKED`，暂停付费创建。启动诊断分别查
本次启动打印的 `logs/start-<后端端口>.<随机后缀>/` 下的 `backend.log` 和 `frontend.log`。
证据只保存脱敏摘要。需要续查在途任务、资金或报表时保留脚本会话。

### 3.3 前置检查

1. 确认前端和后端来自本次待发代码，记录 Git HEAD、dirty 状态与受测改动摘要、启动时间。
   浏览器禁用旧页面复用造成的版本误判，完成页面重载；生产构建发布前再用实际构建做一轮界面复核。
2. 确认实际主库、日志库及 Redis 命名空间，不打印 DSN；核实数据库方言、日志是否分库、后台 worker 是否工作。
   不直接把仓库根目录 SQLite 文件当作运行实例主库。只读 SQL 必须连接已确认的实际数据源。
3. 优先复用已存在的本地测试用户和渠道。测试用户 A 使用钱包资金来源、有限额 Key、独立测试分组，
   测试时不运行其它负载、不充值、不进行人工额度调整；用户 B 用于越权验证。
   若实现支持明确 app 隔离，再准备 A 的同 app Key 与不同 app Key；不能把换 Key 自动视为换 app。
4. 原生模型在隔离测试分组/合同内限定到本次目标渠道，随后从执行证据核实实际命中。
   不用管理员专属 pin 代替客户公开调用；不改全站分发策略。Seedance/MiniMax 遵守各自确定性模型路由，
   不为复制测试渠道新增同名已启用模型，不向 Ability 或通用分发池写入类型化渠道。
5. 记录每个用例的公开客户模型、入口、请求模板、协议、预计最多创建次数和可接受等待时间。
   分别记录单例与全轮的客户占款上限（quota）和 Provider 成本上限（注明币种及估算依据）。
   客户预算计入已扣与在途占款，Provider 预算计入已知成本和在途/未知创建的估算上界。
   每次新 POST 前分别核对剩余预算，无法估计上界或余额不足的组合记 `BLOCKED`。
6. 使用已批准的无敏感内容提示词与自有测试媒体。参考图必须能被真实 Provider 拉取；
   `localhost`、本机文件路径不等于可用的公开参考 URL。托管素材按现有私有存储配置执行。
7. 对象存储必须通过现有配置的实际读写与授权交付检查；不能只测 TCP 连通。
   不设置公开桶、不关闭鉴权/SSRF、不新增生产测试接口。
8. 管理员只读核验权限、客户登录会话和业务 API Key 分开使用。Key/密码由已有安全渠道读取到内存，
   不放进清单、命令行参数、终端输出、截图或仓库。缺少必要权限/配置记阻塞，不把未执行记通过。

首次执行推荐在独立开发 PostgreSQL 与独立缓存中使用现有渠道的受控配置副本，保留真实 Provider 连接。
配置副本使用数据库原生的一致性导出。来源若为在线 SQLite WAL 库，先做一致性备份再迁移配置。
副本不得自动启动历史在途任务的 worker：只迁移本轮需要的配置及隔离测试身份，先检查旧任务，
避免同一个 Provider 任务被两个实例结算/转存。不要复制整库后立即启动后台扫描。

## 4. 最小用例矩阵

“已启用”指明确列入本次发布范围且运行时有可用配置。某项不发布可标 `NOT_APPLICABLE`；
计划发布但缺凭据、模型、价格、存储或测试账号时标 `BLOCKED`，不能静默跳过。

| ID | 用例与真实调用入口 | 通过条件与数据检查 | 浏览器闭环 |
| --- | --- | --- | --- |
| P0 | 本地健康、客户 `GET /v1/models`、会话 `GET /api/pricing` | 响应来自同一受测实例；批准模型可见；合同报价须显式使用对应上下文；公开投影无上游身份；不产生业务扣费 | 客户 `/pricing` 与模型详情展示相同模型、币种、单位和适用组/合同 |
| T1 | `POST /v1/chat/completions`，非流式，短提示、较小合法输出上限 | 非空回复、模型/usage 符合合同；核实实际渠道与映射、单笔账单和余额差额 | `/usage-logs/common` 定位同一请求，核对用量、费用和详情 |
| T2 | 同入口 `stream=true`，使用确认支持流式用量的模型 | SSE 逐步到达且正常结束；usage 按协议解析；连接结束后只完成一次结算；无 usage 时按现有合同核验而非补造零用量 | 同一流式日志可见、无重复消费；可追加 Playground 真发送验证见第 6 节 |
| I1 | `POST /v1/images/generations`，`n=1`、最小批准规格，不带异步头 | 实际拿到一张可解码图片；按配置返回 URL/Base64；同步路径不因 Provider 内部异步就被误判必须有平台 Task；核对价格模式与扣费 | 图片价格卡/详情、消费日志详情中该笔分项与总额一致 |
| I2 | `POST /v1/images/edits`，按该公开入口使用 multipart 或已发布 JSON 参考图格式 | 真实参考图成功产生非空可解码结果；输入/输出计量只依据真实已报告字段；图片输入单独计价时不得重复计入输入兜底 | 参考图费用与文本/图片输出含义可理解；缺计量不显示为“已报告 0” |
| I3 | 已发布异步图片：同一图片入口加 `Prefer: respond-async`，仅在合同支持时携带 `Idempotency-Key` | 验证 202 受理、幂等、冻结定价分类、净扣和制品，见第 4.3 节 | 同一 Task 的用量详情、账单分类及制品预览/下载均须核对 |
| V1 | Seedance Mini：`POST /api/v3/contents/generations/tasks`，明确 `duration=4`，使用确认支持 4 秒的 Mini 客户模型及批准规格 | 验证一次创建、冻结事实、结算、交付和客户 API 脱敏，见第 4.3 节 | 同一 Task 的客户用量详情、脱敏、播放和实际时长均须核对 |
| A1 | 启用素材能力时：`POST /v1/assets`、带 `model` 的单项 GET，再把该 `reference` 用于一次 V1 | 按 `api.assets` 选择可执行操作；普通代理无客户 Asset/Group 落表；`default_fallback` 走已配置默认组或显式组；`none` 不发送组字段；无需另加视频 POST，可替换 V1 的输入 | 若无客户素材页，不发明列表验收；管理页只核对默认组已配置状态，不展示 opaque 默认组 ID |
| N1 | 缺失/无效 Key；合同未列模型或 Key 明确排除模型 | 使用合法业务请求体隔离验证鉴权/授权错误；保存对应入口的预期 HTTP/错误类别；受拒绝请求无新增消费、hold 或 Provider 创建 | 客户错误提示可理解，客户无权打开管理页面或管理员证据 |
| N2 | 用获准的客户 Key 提交确定性非法输入，快速冒烟必测图片 `n > dto.MaxImageN` | 客户收到合同约定的 400 错误及平台请求 ID；无外发、无预扣、无消费 | 管理员用本轮请求 ID 在 `/usage-logs/error` 定位错误并打开详情。已发布输入界面如有对应入口，再验证客户提示 |
| N3 | 用户 B、以及明确不同 app 的 Key 查询本轮 Task/下载制品 | 按各合同的无权/不可见语义拒绝；没有响应正文或下载链接泄漏；同用户同 app 替换 Key 按实际合同校验，不能一概断言拒绝 | B 的列表/搜索/详情无法看到 A 的私有任务与账单 |

建议基础真实创建量：T1/T2 两次文本，I1/I2 两次图片，I3 一次异步图片，V1 一次视频；
A1 启用时额外一次素材创建。I3 幂等重放不是新的付费创建意图，须核实确实没有第二次执行。
API 与 UI 共用这些结果，减少重复付费。预计次数是预算输入，不保证实际价格或 Provider SLA。

对每个拟发布协议增加一个已验证、可重复的失败请求。优先选择入口校验失败；它只能证明本地拒绝。
若变更涉及上游错误转换或失败退款，还必须取得真实 Provider 明确拒绝或失败证据，核对该次资金释放。
不得用随机坏参数或审核违规内容赌博式触发失败；无法确定或未出现时标未验证。

### 4.2 本轮明确覆盖：文本、图片、Seedance Mini 4 秒

本轮三类必测范围固定如下，不以未选中的其他能力扩大基础冒烟：

| 类别 | 必测用例 | API、数据、界面三层证据 |
| --- | --- | --- |
| 文本 | T1 非流式 + T2 流式 | 真实文本结果/SSE 完成 → 实际渠道、usage、净扣费 → 同笔消费日志与费用详情 |
| 图片 | I1 文生图 + I2 参考图编辑；已发布异步图片另加 I3 | 真实图片可解码 → 输入/输出计量及冻结费用 → 价格页、同笔账单分项和实际结果检查 |
| 视频 | V1 Seedance Mini，显式 4 秒 | 真实创建、轮询、OSS 就绪 → Mini 映射、4 秒冻结事实、预扣/结算 → 同笔任务、可播放结果与媒体时长 |

V1 的 `model` 必须是本地已配置并批准的公开客户模型，不能把 Provider 模型名直接填进客户请求，
也不能仅因客户名称包含 `mini` 就认定命中正确实现。执行前在内部核实专用 ChannelType、
代码协议与精确 `model_mapping`；公开报告只保留匹配结论。现有飞彩代码登记的 Mini 为 720p、
4–15 秒（`plugins/seedance-link/plugin.js` 的 `MODEL_SPECS`；另见
[飞彩验收手册](../40-operations/06-飞彩Seedance全模型上线验收手册.md)），
该事实不能推广为其它 Provider Mini 的相同参数合同。若本地目标 Mini 不支持 4 秒，应标阻塞，
不能静默改为 5 秒、换成标准版或用 MiniMax 结果代替。

4 秒请求必须显式填写北向 `duration: 4`，不能省略后依赖默认时长。下载后用媒体探测读取实际时长，
与 Provider/容器合同及浏览器显示对照；容器时间基误差按已验证合同记录，不能自行放宽为其它时长。
素材引用 A1 若纳入本轮，可以并入这一次 Mini 4 秒创建，前提是所选协议明确支持该引用。

三类均必须完成各自真实 API、数据与 Browser Use 验证，才可以报告“三类覆盖通过”。
只有方案条目而没有运行证据时，只能报告“三类已纳入方案”。Responses、其它视频型号、
MiniMax 与 Batch 仍按 4.1 的发布/变更条件执行，不计入这三类最小覆盖的替代证据。

### 4.3 I3 与 V1 必过断言

**I3 异步图片**

1. 首次提交返回 `202`，响应体的公开任务 ID、`query_url` 和 `Location` 指向同一
   `/v1/tasks/{id}`。用原客户 Key 查询到该任务，并核对受理时冻结的初始计费事实与实际预扣。
2. 仅在已确认首次受理且合同支持幂等时执行重放。同 key 等价请求返回原任务 ID，同 key 不同请求
   返回 `409`。结合任务、发送证据和资金事件核对只有一次受理、一次上游执行和一组资金事件。
   首次受理未知时按第 8.1 节恢复。
3. 用最终计价用量和冻结计价分支核对预扣、差额及净扣，再单独检查客户账单明细的分类与单位。
   旧 Token 定价且有已记录 Token 用量的样本必须归为 `token`，不能因异步受理或旧固定价标记归为
   按次。拟发布旧 Token 分支时，缺少该分支的真实样本或必要用量证据记 `BLOCKED`。按次和表达式
   样本按各自冻结分支验收，分类错误即使金额正确也记 `FAIL`。分类规则见[账单架构](../20-architecture/账单计费-APIKEY用量账单架构.md#54-计费方式分类与单位)。
4. 查询任务达到成功终态，按本例请求的结果格式验证图片可解码。使用同一任务在
   `/usage-logs/task` 打开制品，实际预览及下载已发布的可用制品，并与账单明细核对归属。

**V1 Seedance Mini**

1. 只发一次创建 POST。授权核验侧用同一公开任务 ID 关联 attempt 与 Task，核对冻结的客户模型、
   实际 Mini 映射、协议/adapter 版本、`duration=4` 和 hold 转移。核对适用的预扣、差额和最终净扣。
2. 新受理按[当前 Seedance 计费合同](../20-architecture/Seedance专用渠道与Link架构.md#110-新受理计费接线与历史边界)
   检查冻结的 `u()` 美元表达式、计量单位与价格事实，历史任务按原快照解释。纯冻结条件按对应事实复算。
   若使用 `u("tokens")`，预扣预算和终态可信实测分别核对。已生成但缺必要用量时记录
   `awaiting_usage` 及实际 hold，资金验收继续等待，禁止用预算、请求时长或展示用量结清。
3. 生成 `succeeded` 后等主视频 `delivery_status=ready`。验证授权内容入口返回 302、
   HEAD 使用独立签名，及对象存储下载的 MIME、Range 和解码结果。按已确认的媒体容器精度核对
   实测时长与浏览器播放，末帧仅在本例纳入且有对应事实时独立验收。
4. 以普通客户身份同时检查 ModelArk 查询投影、对应的客户任务/用量接口与浏览器详情。
   模型字段和界面展示应使用客户模型名，公开响应及页面不得暴露南向模型、真实渠道 ID、Provider 身份、
   上游任务/请求 ID 或内部协议。按授权合同签发的本站制品链接用于交付，证据只保留脱敏结果。
   发现泄漏即记 `FAIL`，按第 8.2 节停发新请求。

### 4.4 推理摘要真实渠道上线冒烟

用本轮启动的候选实例、受限客户 Key 和真实 Provider。发送前将拟发布的客户模型、实际渠道、北向入口、

确认实际选渠和模型映射。HTTP 200 只完成连通性检查，需继续核对下表断言、同笔费用和客户用量日志。

| ID | 真实调用 | 通过条件 |

`extra_body.google.thinking_config`，将 `include_thoughts` 设为 `true`。对 2026-11-16 验证过的特定映射，

`FAIL`。当次上游无摘要或缺少证据时，摘要正样本保持 `BLOCKED`，按预算做有界复测。按请求 ID 核对请求开关、

**稀有流式场景。** 若真实 Provider 返回同帧摘要和正文、多候选交错或关闭后再返回摘要，按 `index` 分别

## 5. 数据如何核验

### 5.1 先建立唯一关联

每个用例生成 `run_id + case_id`，只放进无敏感内容的提示词标记或执行器元数据，不向 API 塞未发布字段。
记录响应头 **`X-Oneapi-Request-Id`**、公开任务 ID、测试用户/Key 的内部别名、请求开始/结束时间。
不要假设服务接受客户端指定的请求 ID。请求重放的 HTTP 请求 ID 与原业务任务 ID 分开保存。

同步请求用 request ID 关联日志；异步用公开 task ID 关联 Task、attempt、资金和后续日志。
`tasks.task_id` 与 `task_create_attempts.public_task_id` 的关联按对应实现读取，不能拿上游 task ID
冒充公开 ID。日志没有外键时，使用既有资金/任务引用解析关系，不只靠“时间相近、金额相等”。
若关联无法唯一证明，标 `BLOCKED`，不能猜选一条记录。主库与日志库分开读取，不要求跨库 SQL JOIN。

### 5.2 三个观察时点

| 时点 | 要读取的事实 | 断言 |
| --- | --- | --- |
| before | 用户钱包 quota、有限额 Key remaining/used、本轮任务/attempt/日志基线、实际价格/合同版本 | 明确没有并行流量和未纳入统计的资金变动；不能拿历史总额代替基线 |
| accepted | 适用路径的 Task 或 attempt、资金来源、hold/转移状态、冻结渠道/协议/价格摘要 | 同步/异步图片、视频、Batch 分别遵守自己的受理语义；短暂态没观察到不能断言原子性已证明 |
| settled | Task 业务与资金状态、消费/差额/退款日志、余额、用量、交付对象状态 | 资金已最终提交且日志交付完成；重复 GET 后业务终态、净额和计费次数不变 |

管理员优先通过既有 API 只读核对；API 不提供的必要内部事实使用受控只读 DB 查询。
查询显式列举白名单字段，不 `SELECT *`，不输出 Channel key、Task private_data、冻结连接或原始响应。
私有计费快照只在内存中取必要字段，输出“协议匹配/冻结事实匹配/数量/金额”等脱敏结果。
需要证明无外发时，结合既有发送证据/管理员错误分类；仅“没有日志”不是完整证明。

### 5.3 单笔净扣与周期账单

首轮固定钱包来源、有限额 Key、无充值/赠送/人工调整/并发负载。令 `Q` 为本轮已终结请求的
最终净扣费（消费 + 计费差额 − 已实际退款，按既有日志类型及资金引用分类，排除重复投影与诊断记录）：

```text
用户 quota_before − quota_after = Q
有限额 Key remaining_before − remaining_after = 该 Key 本轮实际受跟踪的净扣费
```

先确认 Key 是否参与 quota 跟踪；无限额 Key、订阅和信任旁路不能套用上述 Key 余额断言。
有在途 hold 时单独列出，不能用最终费用等式直接判断已结算。`used_quota` 按该路径实际累计/退款
语义校验；用户累计列是 64 位统计，不能套单笔 int32 截断。日志存在负的退款/冲正金额可能是正确会计
语义，要拒绝的是溢出形成的负收费、重复结算和无依据信用，不是拒绝一切负数。

复算仅读取本笔冻结价格、分支、真实计价用量、有效组倍率、合同折扣、附加费、当时 quota 单位及适用的冻结汇率；
使用现有换算和舍入规则。原始 quota 必须精确一致；UI 金额以其显示精度核对，不用一个宽泛百分比
容差掩盖误差。当前 `/api/pricing` 是下一笔报价，不能用于重新解释历史请求。

视频成功时 attempt 完成与 hold 转 Task 必须对应同一个业务创建，不能把 hold 与终态消费各算一笔
总消费。多条预扣/差额/退款日志可能合法，按资金引用确认只结算一个业务意图。Provider 费用按其独立
账单核对，未取得账单证据时记“待对账”，实际金额保持未知。

周期账单以[账单架构](../20-architecture/账单计费-APIKEY用量账单架构.md#7-前端职责)为准。
在 `/billing` 选择北京时间自然月，用本轮 API Key、客户模型和同一报表版本下钻至逐笔入账事件。
未确认账期使用所选已发布日报版本集合，已确认账期使用所选正式月版本。记录版本和覆盖截止日，
再按本轮资金引用核对纳入范围。消费和退款分别按各自入账时间归属月份，跨月退款在退款月核对。
账单净额按已入账消费减退款，日志页顶部若展示消费毛额，则按对应消费流水核对毛额。
两个页面的比较须使用相同统计口径，日志和账单各自检查逻辑请求数，异步差额或退款不新增调用。
有界等待后，报表仍未覆盖本轮入账日或相应版本时，账单维度记 `BLOCKED`。确认同一版本已覆盖本轮
事件后，漏记、重复、错误分类或净额不符记 `FAIL`。

### 5.4 当前图片计费展示的专项断言

1. I1 提供无参考图正样本；I2 尽量取得真实 `img > 0` 正样本。Provider 未报告该分类时明确记录缺口，
   不能靠本地合成字段补成真实用量。
2. 只展开冻结表达式实际引用的变量。`c` 与 `img_o` 数量相同不表示两项都收费；
   `p/c` 保持未单独计价输入/输出的兜底语义，不根据模型名强行命名为某个模态。
3. 比较客户响应里的 `billing_explanation.lines`、页面分项、模型费与最终账本金额。
   缺失、显式 0、正值分别验证，缺少历史证据不得用当前价格回填分项。
4. 缓存价格已配置与本次缓存命中分开验收。重复两次真实请求不保证缓存命中；
   没有缓存正样本就标“真实缓存分项未验证”，不能声称缓存费用正确或供应商无优惠。
5. 历史无完整计费证据的记录只读验证“不可展开/未记录”等提示，不改库伪造历史。

## 6. 本地 Browser Use 页面验收

使用当前可用的 Browser Use 或 Computer Use 工具，在第 3.2 节启动的本地前端上实际登录、导航、筛选和
打开详情。预检确认客户 A、管理员以及越权测试用户 B 的会话可用。页面验收复用本轮成功请求、任务和
N2 错误样本。请求日志、错误信息、账单和用量四项均为快速冒烟必测。

1. **客户上下文 A**：打开本次前端 Origin，用现有账号登录。确认版本、身份、中文，进入 `/pricing`，
   搜索本轮模型并打开详情；核对价格单位、图片/缓存说明及实际选择的组/合同上下文。
2. **请求日志**：在 `/usage-logs/common` 用 Request ID 定位 T1/T2/I1/I2，打开同一笔请求详情，
   核对客户模型、时间、可见的计费用量和费用。必要时按 Key、模型、时间缩小范围，再在详情确认 ID。
   I1/I2 另核对冻结单价、组倍率/折扣、逐项金额与总费用。
3. **任务日志与交付**：在 `/usage-logs/task` 按公开任务 ID 定位 I3/V1，刷新确认终态与用量一致，
   实际打开制品预览，验证图片尺寸/内容、视频可播放并拖动。主视频 ready 不代表末帧也 ready，分开检查。
   预签名链接仅留在受控运行内存中；下载重定向到 OSS 时不转发平台 Authorization。
4. **错误信息**：用管理员会话打开 `/usage-logs/error`，按 N2 的平台 Request ID 筛选并展开详情。
   核对错误类型、HTTP 400、请求路径、客户模型及实际可见的脱敏错误摘要，与客户 API 响应对应。
   允许有界等待错误事件入库。缺失或无效 Key 的 N1 样本用于鉴权验收，错误页正样本使用已鉴权的 N2。
   用普通客户会话访问同一管理页面，确认无权查看错误记录或诊断详情。采集范围见[API 错误日志架构](../20-architecture/运维-API错误日志架构.md)。
5. **我的账单**：按第 5.3 节在 `/billing` 选择账期和版本，按 Key、客户模型下钻并打开本轮
   逐笔费用明细，核对入账分类、扣款、适用的退款和净额。
6. **我的用量**：在 `/usage` 显式选择覆盖本轮的北京时间日期或周期及测试 Key。核对汇总与本轮
   客户模型的调用数、已记录的 Token 或适用的非 Token 计量及客户净费用，确认缺失与明确零的显示。
   账单按入账日核对，用量按所选报表和实际归属日核对。记录报表版本、覆盖范围和发布状态；尚未覆盖
   本轮时按刷新周期有界等待，仍未覆盖记 `UI_BLOCKED`，已覆盖且有数据差异记 `FAIL`。
   口径见[使用日志与报表产品设计](../10-product/使用日志与报表产品设计.md)。
7. **管理员诊断**：在 `/channels` 只读核对本轮渠道状态和已登记协议，在对应日志/任务详情核对实际
   命中与授权诊断字段。通过浏览器读取已有结果，沿用本轮创建预算。
8. **越权上下文 B**：切换为 B 后访问本轮私有详情与受限下载入口，确认无记录、无链接泄漏。
   核对 B 的账单与用量均无 A 的数据。
   A/B 使用独立浏览器会话；工具不支持隔离会话时显式登出/登录并重新确认身份，不能只切标签页。
9. **英文复核**：同一 I1/I2 详情与价格页切换英文，验证标签、币种/百万 Token 等单位、数值和缺计量提示，
   再重载确认内容仍正确。仅要求 `zh/en`。

若本次发布包含 Playground，再增加一个通过 `/playground` 点击发送的真实短文本请求：确认逐步输出、
成功完成并关联新增消费日志。它单独纳入调用量/预算，因为 Playground 使用 `/pg/chat/completions`，
不能替代 T1/T2 的客户 Key 授权测试。图片/视频若没有已发布创建界面，不编造“在 UI 点击生成”的用例。

每个界面检查保存操作摘要、角色、受测路由、对应 case/request/task 别名、可见关键值和脱敏截图。
截图须避开凭据显示、浏览器签名 URL 地址栏和私有证据原文；不要默认导出完整 HAR、Cookie、
localStorage 或原始网络正文。浏览器或会话不可用、所需数据仍未就绪时记 `UI_BLOCKED`，
已确认页面显示、权限或脱敏错误时记 `FAIL`。

同一条 API 和账本证据，记录页面显示值、预期值和结果。对只提供 API 的操作，在对应日志、用量或账单页面
核对可见业务结果，专属字段使用授权 API 核验。

| 用例 | 页面与数据对照 |
| --- | --- |
| C1 合同准入 | 在「系统配置 → 请求策略」核对默认状态、保存反馈、重启后回显。在客户「API 密钥」和管理员「客户合同」对照同一把测试 Key 的绑定状态、模型和折扣。用成功请求对应的用量详情核对客户模型、用量和实扣。会话目录与 API Key 模型列表按各自权限核对 |

## 7. 执行器的最小实现建议

本批交付方案，以下为待实现入口，不是当前已有命令。首版建议独立放在 `scripts/e2e/`，
复用已有公开 API 与管理员只读接口，不修改生产 Router、计费热路径或原生 DTO：

| 拟新增文件 | 职责 |
| --- | --- |
| `scripts/e2e/local-real-smoke.mjs` | 使用 Bun 执行 preflight、公开请求、轮询、预算检查与断言；业务创建串行 |
| `scripts/e2e/local-real-smoke.example.json` | 只有非敏感模型别名/入口、用例选择、预算、截止时间与环境变量名称；不存凭据/私有配置 |
| `scripts/e2e/README.md` | 执行说明、Browser Use 操作清单、凭据注入方式、真实调用与费用边界 |
| 受控运行目录下的 `run.json`、`cases.json`、`checks.json`、截图与 `report.md` | 本轮脱敏证据；目录位置在运行前选择并排除版本控制；不保存完整原始请求/响应 |

执行阶段分为 `preflight → API → data → browser → report`。发送前保存用例意图，恢复模式按
第 8.1 节只读核验。本地记录用于防误操作，服务端 Task、attempt 与资金记录仍是业务事实源。
同一轮禁止并发创建，查询可有界轮询；错误退出必须输出仍在途/held 的用例摘要。

轮询间隔、最大等待时间按实际 Provider 与现有 Retry-After/公开合同配置，使用单调时间截止；
普通查询暂时失败可继续有界查询，但不得新建任务。仅状态查询达到 succeeded 还要等待适用的资金与交付。
输出结构至少包含：`run_id`、代码/工作区版本摘要、环境摘要、case ID、覆盖组合、HTTP 状态、
平台 request/task 别名、实际选渠匹配布尔值、业务/资金/交付状态、quota 差额、UI 结论、证据索引。
受控索引可保存后续查询必需的公开 task ID，不记录上游 task ID、Provider 连接信息或 Task 私有内容。

提供 `PASS / FAIL / BLOCKED / NOT_APPLICABLE` 四种单例结果，界面、账单、Provider 对账另列维度。
进程只在所有必测项 PASS、无 BLOCKED 且证据完整时成功退出；未勾选必测项视为清单错误，
不能让一个空用例集返回“全部通过”。所有失败退出都保留资金处置清单。

## 8. 异步异常、费用与清理

### 8.1 未知创建的只读恢复

1. **发送前**。在受控记录中持久化 `run_id + case_id`、目标实例、入口、客户模型、测试用户/Key/app
   别名、发送意图时间和第 5.2 节基线。业务创建串行。POST 超时、断连或进程退出时，把未确认的意图
   标为“可能已发送”，保留预算占用和已收到的标识。同一意图不补发、不换渠，I3 的验收重放只在
   首次受理已确认后进行。
2. **取得公开 Task ID**。按原入口与原授权继续 GET，结合既有只读证据核对归属、资金和交付。
   只有平台请求 ID 时，先按该 ID 查现有日志或管理证据，再通过已有业务引用关联 Task 或 attempt。
3. **两个 ID 都未收到，或请求 ID 无法继续关联**。按隔离测试身份、入口、客户模型、发送时间窗口，
   对照发送前基线读取该路径实际产生的新增日志、Task、attempt 和资金事件。结合身份、既有引用
   和单一在途意图核实唯一匹配。空结果、多个候选或仅时间/金额相近均记 `BLOCKED`，列入待核实清单。
   仅找到 attempt、尚未取得正式 Task 时，通过管理侧继续跟踪 attempt/hold。
4. **到达本轮等待上限**。尚待确认的业务、资金或交付维度记 `BLOCKED`，记录最近状态、客户占款、
   Provider 可能成本、续查标识及跟进人。保留必要 worker，后续只读续查。异步图片待核实按图片合同
   保留资金状态。适用的未转移视频创建占款按 [ADR-0021](../20-architecture/decisions/0021-视频创建占款24小时资金保障退款.md)
   跟踪独立的 `funds_deadline_at` 和到期释放结果。资金释放后，未获可信证据的 Provider 业务状态
   和实际成本仍保持未知。

发送许可原子性、崩溃窗口、24 小时保障退款、并发结算与故障恢复使用确定性回归或隔离演练验证。
日常冒烟仅记录自然发生的异常与实际观测。

### 8.2 确认失败、停发与清理

- 明确失败的媒体请求按对应合同检查实际释放；Batch 按已执行行实际收费，不套用媒体全退规则。
  视频生成成功但 OSS 交付已确认不可用时，保留生成与资金事实，交付维度记 `FAIL`，
  不重新生成或自动退款。
- 超出费用预算、实际路由不符、重复上游创建、重复结算/退款或私有信息泄漏：停止发起后续新请求，
  保留后台查询/结算所需运行条件，产出失败及在途清单。不要为恢复余额而直接 UPDATE 数据库。
- 默认不删除 Provider 素材组、不删媒体对象、不改历史日志、不回滚已经发生的真实费用。
  临时测试 Key/分组在任务全部完成并对账后按既有管理流程停用；保留必要审计，不复用过期签名链接。
  素材组留存清单交运维，平台不提供素材组删除；托管素材删除只停止新引用，不承诺清理 OSS。

## 9. 发布判定与实施批次

### 9.1 本轮判定

只有同时满足以下条件，报告才写“本地真实冒烟通过”：

1. 受测前后端由本轮 `./start.sh` 启动。所有必测公开入口均有真实成功或明确合同失败证据，
   实际渠道/协议符合清单。
2. 结果可解码/播放，适用任务达到真实终态、资金终态与可交付状态；重复读取不产生重复费用。
3. 按第 5.3 节核对钱包/Key、冻结计费、账单分类与周期净额；无无法解释的差额或负收费。
4. 第 6 节的请求日志、错误信息、账单、用量及适用的任务和制品检查均通过，所选扩展项通过第 6.1 节的
   浏览器数据对照。客户响应与界面通过脱敏及权限隔离检查。任一必测页面为 `UI_BLOCKED` 时，本轮不可判通过。
5. 两项预算均满足。所有适用的 I3/V1 及第 4.4、4.5 节必测组合通过。未验证能力、在途资金与供应商对账缺口按实际状态记录。

报告还必须分别写清：本次未测渠道/协议、真实缓存正样本是否取得、真实 Provider 账单是否核对、
三数据库验证范围、恢复/24 小时保障是否仅有回归证据，以及生产灰度是否执行。
“快速冒烟通过”不自动升级为“全部渠道可上线”；本次拟发布组合有 FAIL/BLOCKED 时不得发布该组合。
