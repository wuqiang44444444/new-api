# API Key 仅按合同调用模型实施方案

## 问题与目标

当前 API Key 未绑定合同或所绑合同已停用时，可以按原生分组发现和调用模型。用户已明确要求新增系统配置「API Key 仅允许按合同调用模型」，并确认**默认开启，覆盖所有用户分组的 API Key**。用户所属组、Key 指定组以及 `auto` 都不影响开关的适用范围。管理员可显式关闭开关，以便仍需使用原生分组选路的部署维持现有行为。 [新增配置项约束](../00-context/硬约束.md#1-项目与技术)

开启后，每把 Key 必须绑定一份启用的客户合同，才能发现和调用合同授权的模型。拥有合同但未给当前 Key 绑定，仍按未绑定处理。关闭后，启用合同优先，未绑定或明确停用时恢复现有分组逻辑。模型发现与新调用共用同一授权规则，每次请求只解析一次策略和合同快照。

### 目标行为

| 当前 Key 状态 | 开启（默认） | 关闭 |
| --- | --- | --- |
| 已绑定启用合同，目标模型和渠道组合有效 | 按合同范围发现、调用和计价 | 同开启 |
| 未绑定合同，或绑定的合同明确停用 | 列表返回 `200` 和空数组，模型详情返回 `404`，HTTP 新调用及新 WebSocket 握手返回 `403`，已建立的 Responses WebSocket 在新事件上返回协议错误 | 使用现有用户组、Key 指定组和 `auto` 规则，按原生价格计费 |
| 已绑定启用合同，但模型未授权、被 Key 模型限制排除或无有效组合 | 沿用现有合同过滤与拒绝逻辑 | 同开启 |
| 绑定记录缺失、归属或版本异常、合同读取失败 | 沿用现有错误响应，阻止请求 | 同开启 |

上述响应以 API Key 已通过身份校验为前提。启用合同继续决定精确模型、组、渠道和折扣，已有 Key 模型限制、有效期、IP、额度和限流规则继续生效。缺启用合同的受限请求跳过原生组检查，Key 保存的路由组已失效时也按本表处理。新调用使用对应协议的错误结构。支持字符串错误码的协议采用 `contract_required`，Kling 和即梦沿用其 `403` 对应的数字码。

## 优化方案

### 系统配置

- 在「系统配置 → 请求策略」增加布尔开关，配置键为 `customer_contract.require_for_api_keys`。纳入现有请求策略 API 的默认值、允许的配置键、布尔校验和运行时快照，通过 `GET` / `PATCH /api/option/request_policy` 读取和事务保存。数据库提交成功后发布新快照并通知实例同步。数据库写入失败时返回失败，管理页面和运行值保留上一次成功保存的值。新安装及未保存该项的旧部署读到 `true`，显式保存 `false` 后经重启和同步仍为关闭。 [请求策略读写](../../model/request_policy.go#L61) · [事务保存](../../model/request_policy.go#L212) · [前端请求策略 API](../../web/src/features/system-settings/request-policies/api.ts#L21)
- 页面说明采用「开启后，所有 API Key 必须绑定启用的合同才能查看和调用模型。关闭后，未绑定启用合同的 API Key 沿用现有分组规则。」以服务端返回值初始化并复用系统配置权限和保存反馈。设置及错误提示提供简体中文与英文。 [请求策略页面](../../web/src/features/system-settings/request-policies/section-registry.tsx)

### 请求授权与模型发现

1. 在已有 API Key 合同授权入口解析合同状态和本次请求的开关值。身份校验后再读取合同。合同启用时走现有快照与授权逻辑，读取或完整性异常按原错误处理。仅当没有启用合同、开关开启且入口受模型策略约束时标记请求受限，受限请求跳过原生分组选路检查。复用请求上下文传递该结论，分发、控制器和适配器无需再次读取配置。 [合同鉴权](../../middleware/customer_contract.go#L43)
2. 按已注册的路由及实际操作声明准入边界。普通调用、插件、类型化视频、Midjourney 提交、模型相关素材操作、Batch 创建和新 remix 均属于新调用。即梦按 `Action` 区分 `CVSync2AsyncSubmitTask` 与 `CVSync2AsyncGetResult`。历史任务或文件的查询、下载和取消按已登记资源入口及现有归属规则处理。Batch `POST /v1/files` 保留输入文件上传权限，`POST /v1/batches` 执行合同准入。Key 用量和账单查询继续使用现有权限。 [即梦路由](../../router/video-router.go#L79) · [Midjourney 路由](../../router/relay-router.go#L226) · [Batch 路由](../../router/batch_relay_router.go)
3. 收窄 Responses 的历史豁免。`GET /v1/responses` 是新 WebSocket 握手，`GET /v1/responses/:id` 是历史读取，`GET /v1/realtime` 是新模型操作。握手受限时在升级前返回 `403`。对已经建立的 Responses 连接，每个新 `response.create` 使用既有内部 POST 重新鉴权，并在首次选渠与复用已锁定渠道的两条路径之前检查准入。启用合同下应解析模型和折扣，复用渠道时重新确认当前合同允许该渠道及实际履约组，再准备计费或发送事件。合同变更影响后续事件，已受理事件继续使用各自冻结的事实。 [事件鉴权](../../controller/responses_websocket.go#L30) · [事件选渠与复用](../../relay/responses_websocket.go#L300) · [既有合同范围与计费解析](../../service/customer_contract_routes.go#L97)
4. 鉴权阶段产出受限状态，由各协议在上下文建立后、幂等占位、选渠、创建占款、写入任务和上游外发前输出拒绝。复用既有错误响应机制，在适用协议的公开错误码定义和投影中加入 `contract_required`。保留 OpenAI、Claude、Gemini、ModelArk、Kling、即梦及其他已发布入口的响应约定，文档同步写明各协议的错误形状和错误码。 [视频协议接线](../../router/video-router.go#L33) · [协议错误投影](../../controller/task_protocol_error.go#L17)
5. 模型发现使用同一准入结果，在查询组、读取模型元数据或追加视频目录前返回空列表。覆盖 `/v1/models` 的 OpenAI、Claude 和 Gemini 形状、`/v1beta/models`、`/v1beta/openai/models` 及 ModelArk 的 `/api/v3/contents/generations/models`。模型详情 `/v1/models/:model` 在查找任何模型元数据前返回 `404`，已知和未知的名称使用同一响应。会话、公开和管理目录继续使用各自的现有规则。 [通用模型路由](../../router/relay-router.go#L21) · [ModelArk 模型路由](../../router/video-router.go#L46)
6. 若方舟前缀缓存试点同批发布，按现有试点合同条件，在开关开启时停止试点的新创建和继续生成。准入检查须早于试点处理器和通用分发，覆盖自定义额度校验和幂等重放入口，已有缓存删除和后台结算沿用现有规则。若同批发布要求试点继续提供新调用，则先按客户合同完成试点的模型、渠道和计费授权设计及验收。 [试点接线](../../router/task-plugin-protocol-router.go#L30) · [试点删除路由](../../router/ark-prefix-cache-router.go)

### 接线与文档

策略主体放在本地合同扩展代码中，原生文件只保留必要接线，复用现有 Key 绑定、合同范围和选渠逻辑。开关通过 Option 保存，无需新增数据表或迁移存量 Key。实施时更新客户合同停用与 Key 解绑的影响说明，以及产品、架构和公开 API 文档。

实施批次新增 ADR，记录全站策略、默认开启的理由和关闭后的回退条件，明确替换 ADR-0020 中「停用或解绑后恢复原生组」的无条件语义。ADR-0020 关于合同范围、选渠和计费的决定继续适用，决策索引标明受新 ADR 修订的条款。 [ADR-0020](../20-architecture/decisions/0020-客户合同范围约束与原生分发协同.md) · [ADR 维护规则](../20-architecture/decisions/README.md#维护规则)

### 验收与部署

| 验收面 | 通过条件 |
| --- | --- |
| 开关与持久化 | 缺省值为开启。显式关闭经重启与多实例配置同步后仍为关闭，再次开启影响新请求。数据库写入失败时，保存返回失败，数据库和运行快照保留原值。 |
| 跨分组与合同状态 | 覆盖 `default` 和非默认用户组，以及 Key 继承组、指定组和 `auto`。开关两态均回归已绑定启用合同 Key 的模型限制、选渠和折扣。覆盖未绑定、停用、模型越界、无有效渠道和合同读取失败。验证关闭时恢复原生组，开启时即使保存组已失效也按合同准入响应。 |
| 模型发现 | 逐一核对 `/v1/models` 的 OpenAI、Claude、Gemini 形状及 `/v1beta/models`、`/v1beta/openai/models`、ModelArk 独立目录的原有包装和空数组。存在已配置的 Seedance 或 MiniMax 模型时仍保持空，且提前返回，无组或目录查询。详情对已知和未知模型返回同形的 `404`。 |
| 新请求拒绝 | 覆盖普通调用、Midjourney、类型化视频、插件、素材和 Batch 新建。校验各协议状态与错误结构，确认拒绝前无幂等占位、选渠、上游外发、预扣或任务创建。 |
| WebSocket | 覆盖 Responses 和 Realtime 的握手拒绝、已绑定 Key 的合同外模型拒绝，以及已建立的 Responses 连接在开关开启、合同停用、解绑或移除已锁定渠道后拒绝新事件。仍在合同范围内的复用事件按实际组和合同折扣结算。 |
| 历史资源与会话 | 验证即梦新提交受限时仍可查询已有任务。开启、停用或解绑后，已受理任务仍可在原有权限下查询、下载和取消，跨用户和应用访问仍拒绝。会话目录、Playground、Batch 文件上传和 Key 用量查询按现有规则工作。 |
| 方舟试点同批发布 | 校验开关开启时试点新创建、继续生成及相关重放入口的准入结果。验证开关关闭时试点仍按现有资格工作，已登记的删除与后台结算按现有规则履约。 |

上线前盘点仍依赖原生分组的活跃 Key，确定需要先完成合同绑定的客户和确需显式关闭的部署。Batch 输入上传继续开放，评估未绑定 Key 仍可占用的文件存储及现有容量限制。需要保留原生分组行为的旧部署，在首台新版实例接流量前确认 `false` 已持久化。如果旧版管理入口无法安全保存该键，可先启动隔离的新版实例完成保存并核对实际值。需要启用策略的部署，在旧节点退出接流量范围、所有服务实例均支持并读到 `true` 后确认全站生效。滚动升级期间按节点核对未绑定 Key 的发现和调用结果。需要恢复原生分组调用时，由管理员显式关闭，确认所有实例生效后复核模型列表、调用及价格。

### 实施与本地验证

- 开关已接入请求策略页面和 API。模型调用、发现、Responses 事件和原生插件入口已接入合同准入。产品、架构、公开 API 和运维说明已同步更新。 [ADR-0023](../20-architecture/decisions/0023-全站API密钥合同准入.md)
- SQLite、MySQL 5.7 和 PostgreSQL 本地验证了默认值、显式关闭持久化、配置重新加载、同步通知及失败回滚。路由回归覆盖协议响应、无幂等占位、受限模型发现、原生回退、启用合同及历史入口。Responses 使用本地模拟上游验证了长连接内拒绝和按折扣结算。
- 本地真实渠道验收已覆盖豆包文本与 Seedance ModelArk V3 视频。目标环境的活跃 Key 盘点、多实例传播耗时、供应商账单及生产灰度仍待完成。方舟前缀缓存与此功能同批发布时，按第 6 步的限制和验收执行。

### 评审问题修复

- 原生插件动态入口根据实际解码操作做准入。历史查询只使用已鉴权的用户和应用归属，新提交在选渠前检查合同。即梦官方任务查询使用同一归属边界。没有 `app_id` 且未纳入既有迁移的原生任务，通过创建时已冻结的应用或令牌记录校验归属。
- DashScope 和豆包原生响应保留各自信封，并返回 `contract_required`。配置回归从全新进程快照的默认开启状态模拟重载，验证显式关闭值、数据库记录和保存失败后的状态。
- 方舟增加配置态鉴权回归，覆盖创建、继续生成和已耗尽额度的幂等重放。开启时三者均被拦截，关闭时均可进入既有处理链。该测试在鉴权后结束，目标环境试点调用和结算仍需验收。
- Kling 原生端到端测试在提交与查询阶段使用同一应用身份，覆盖任务使用创建时冻结的 Key 归属完成查询。
- Kling、即梦、Responses、通用任务与产物读取按应用归属查询。历史行缺少主表应用 ID 时，通过创建时冻结的应用或 Key 验证所有权。视频幂等重放和恢复也校验同一归属。
- 无效持久化请求策略阻止新节点接流量，并在运行中上报同步失败。运行中继续使用最后一份有效快照及其路由选项。合同加载在判断启停前验证版本。
- 原生代理和视频父组恢复统一 Key 鉴权。新增路由默认执行模型准入，已登记的历史与资源操作保持原鉴权。普通 Responses 创建可独立使用合同鉴权，配置方舟试点时接入其独立处理链。
- Kling、即梦和 ModelArk 复用同一请求体替换逻辑，使选渠与重试读取已完成协议转换的内容。新增的正向路由回归验证绑定合同选渠与动态插件的原生分组回退。

### 真实渠道本地验收（2026-11-25）

使用独立 PostgreSQL 数据库、回环地址网关、两个不同分组的测试用户和四把测试 Key。复用开发环境的实际渠道连接与定价表达式，测试组倍率和合同折扣由隔离环境设置。

| 场景 | 实测结果 |
| --- | --- |
| 默认开启、显式关闭与重启 | 未绑定或绑定停用合同的 Key 在四个模型发现入口均返回空列表，已知和未知模型详情同为 `404`，新调用返回 `403`。真实 Responses WebSocket 升级请求同样被拒。关闭值跨重启保留，默认组和非默认组恢复原生发现与调用。启用合同的 Key 仍拒绝合同外模型。 |
| 豆包文本（渠道 265） | 四次请求各返回 54 个输入 Token、1 个输出 Token。启用的合同使用 `seed` 组倍率 1.5 和合同折扣 0.5，结算 3 quota。非默认组倍率 2 的未绑定 Key 和停用合同 Key 各结算 7 quota。默认组倍率 1 的未绑定 Key 结算 3 quota。消费日志中的模型、实际组、渠道、用量和合同快照均与请求及价格复算一致。 |
| Seedance 视频（渠道 245） | 真实提交一次，创建记录完成并把 84,897 quota 占款转入任务。停用合同后，原 Key 继续读取任务，同一用户的另一把 Key 和另一用户均返回 `404`。视频成功后，上游报告 40,594 个输出 Token，按创建时的合同折扣和分组倍率结算 68,624 quota，退回 16,273 quota。重复读取没有重复扣费，当前合同已停用且版本为 2，结算仍使用版本 1。 |
| 钱包、账单和用量 | 非默认组用户共 4 次调用，40,759 Token，净消费 68,641 quota。钱包、Key 用量接口、消费与退款日志、客户账单、渠道累计用量和用量看板一致。 |
| 拒绝日志 | 实测发现新准入拒绝曾落为未分类事件。补充诊断后，用六条实际 HTTP 请求验证错误事件按请求关联为 `contract_scope` 和 `contract_required`。实测的 OpenAI 和 ModelArk 路由同步记录公开码。拒绝前没有选渠、扣费或创建任务。 |
