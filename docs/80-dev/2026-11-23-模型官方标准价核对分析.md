# 模型官方标准价核对分析

## 问题与目标

以厂商公开的实时按量标准价核对本机已保存的模型定价。采用对应模型和地区的公开刊例，保留厂商定义的缓存、上下文、时段、输入和输出规格档位。促销、批量优惠和本站折扣单独核对。人民币刊例允许用本站 `usd_exchange_rate()` 折算。

核对对象是本机运行网关所用 PostgreSQL 在 2026-11-23 01:52（北京时间）的只读快照。按客户模型名区分大小写并去重。启用范围包括启用渠道的原生 Ability 以及启用的 Seedance Link 和 MiniMax Link 客户模型。先查出有效计费方式和渠道映射，再对照公开价或使用现有表达式引擎试算。配置和试算结论适用于本机快照，生产配置、供应商账单和真实调用仍待单独验证。

### Seedance、汇率和折扣

- 24 个启用的 Seedance Link 模型都匹配对应的火山方舟人民币刊例，也都有正数预扣 Token 上限。20 个沿用运维约定 `0.147 USD/CNY`，4 个使用 `usd_exchange_rate()`。本站当前 `USDExchangeRate` 为 `6.7 CNY/USD`，固定系数折算结果较本地函数低 `1.51%`。`seedance-2-0-fast-b` 配置的无视频／含视频 `$5.439/$3.234` 对应官方 `¥37/¥22`。较早的独立模型名 `Seedance2.0` 使用 BytePlus 美元刊例，单独核对。[火山方舟定价][ark] · [BytePlus 定价][byteplus] · [计费运维手册](../40-operations/01-计费与分组运维手册.md#23-seedance-当前统一标价) · [本地汇率函数](../../pkg/billingexpr/expr.md#frozen-exchange-rate-request-context)
- 启用模型的表达式中，有 13 个直接调用本地汇率函数，另有 14 个硬编码除以 `6.7`。改用函数时继续以官方人民币金额作为系数。美元刊例以美元计价。Seedance 固定系数组需在统一销售换算口径获确认后再调整。
- 已核实的非促销配置包括 `gpt-5.6-sol` 的促销前费率、Gemini 4 Argon/Carbon 与 Gemini 3.6/3.8 Flash 的完整标准价，以及 MiniMax-M3 的未打折人民币刊例。[OpenAI GPT-5.6 Sol][openai-sol] · [Google 定价][google] · [MiniMax 中国站][minimax-cn]
- 分组倍率中存在 `0.87`、`0.50`、`0.35`，另有一条用户分组到路由分组的 `0.35` 倍率。启用合同里有 494 条低于原价的规则，其中 486 条对应的渠道仍启用。该快照中启用合同没有绑定启用状态的 API Key。插件定价表达式覆盖为 0。[用户模型合同定价架构](../20-architecture/账单计费-用户模型合同定价架构.md)

### 需要复核计量或渠道的条目

- 小写 `minimax-h3` 的输出时长费率与 MiniMax 中国站一致，当前公式只读输出时长。渠道可接受参考视频和最多 9 张图。官方还按输入视频时长计费，第 6 张图起 `¥0.20`／张。需确认这条渠道的计量和销售口径。`MiniMax-H3` 和 `MiniMax-H3-idc` 的表达式与国际站输入、输出及超额图片费率一致。[MiniMax 中国站][minimax-cn] · [MiniMax 国际站][minimax-intl] · [渠道协议声明](../../plugins/minimax-link/plugin.js)
- `qwen3.8-max` 配置了中国内地的显式命中价 `¥1`，隐式命中官方为 `¥1.50`。当前只有一个 `cr` 单价，需要按实际用量字段确认能否区分。[百炼 Qwen3.8 Max 定价][qwen-max]
- `deepseek-v4-flash-0731` 同时配置了多条线路，当前统一用 Flash 的分时价。应查清独立 0731 快照与直连别名各自的销售基准。`gemini-3-flash-preview` 的当前官方主价页缺少同名条目。`gemini-3.1-flash-image-preview` 与 `gemini-3-pro-image-preview` 的 Google 官方 ID 已退役，启用渠道的映射仍需确认。[DeepSeek 定价][deepseek] · [Google 端点迁移][google-deprecations]
- GPT Image 的 15 个按张别名应核对是否保留独立的销售口径。采用官方按量口径时，输出尺寸、质量、输入图和文本的实际 Token 用量决定整次价格。[OpenAI 图像生成计费][openai-image]

## 优化方案

1. 优先复核并修正会导致多收的缓存价和分档规则。单独覆盖 `gpt-5.5` 总输入量 `272000` 的边界、Google 文本与图片输出的拆分、Seedream 单图像素档及首张参考图免费。
2. 用相同请求场景试算旧价与目标价。覆盖纯输入、纯输出、缓存命中和写入、上下文临界点、法定节假日、视频输入以及图片尺寸。人民币费率优先保留官方原始金额，在请求创建时用本地汇率换算并冻结。
3. 对照每条启用渠道的实际上游模型、地区和用量字段，再处理仍有多种口径的名称。厂商公开规则和渠道实测结果分别记录。配置替换后用管理接口读回并在目标环境核对真实结算。
4. 如果销售口径要求最终实收也按官方原价，复核分组及专属倍率和已有客户合同，再走对应管理修改流程。已发生的任务继续按创建时冻结的计费事实结算。[异步任务与计费事实架构](../20-architecture/账单计费-异步任务与计费事实架构.md)
