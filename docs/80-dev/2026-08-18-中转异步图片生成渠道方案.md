# 中转异步图片生成渠道方案（含 mediaimage 任务桥移除）

## 1. 渠道名与设计目标

### 1.1 渠道名

- **渠道类型名：中转异步图片生成**（常量建议 `ChannelTypeAsyncImage`，实现时定稿）。
- 定位：服务「任务式异步图片上游」——创建任务返回 task ID、轮询取图的第三方中转站。
  首个上游为 FunCloud；API 形状相同（camelCase 信封、`result` URL 数组、`GET …/{taskId}`
  轮询）的后续上游可直接配置复用，形状不同的上游按标准模式另行新增渠道类型（一事一议）。
- 这是**普通 new-api 渠道类型**（与 volcengine/ali 同权），不是 Link 类型化入口：参与原生
  Ability 与图片分发，无专用路由、无任务合同。

### 1.2 设计目标

1. 北向 `/v1/images/generations` 统一接口：该渠道模型对客户复用现有 OpenAI 图片同步
   生命周期，OpenAI SDK 零改造；等待上限沿用部署已有的 `RELAY_TIMEOUT`。`RELAY_TIMEOUT=0`
   表示当前系统没有整体应用层上限，因此上线该渠道前必须由运维配置有限的全局值。
2. 南向适配：异步只发生在网关与上游之间，由 adaptor 内联轮询消化，客户不可见 task ID。
3. 最小入侵：只在必要的类型/API/endpoint 注册点追加接线和新增
   `relay/channel/` 下的 adaptor 文件；不修改任何原生热路径或建立第二套图片生命周期。
4. 同时移除实现错误的 mediaimage 通用任务桥（AdvancedCustom JSON 协议耦合、信封不兼容
   FunCloud、违背「管理员不写协议 JSON」规则），消除约 2000 行无用途代码。

### 1.3 设计原因（决策链）

- **动机**：官方图片渠道存在付款/开户门槛，且 FunCloud 折扣价格有优势（Nano Banana 2 打
  55 折）。seedream 5 官方 volcengine 渠道并行保留；nano banana 2（及 Lite）借此渠道上线，
  取代此前「暂不上」决定；官方障碍消失后该渠道是否退役留待当时决策。
- **原则**（本会话确认）：图片北向统一 `/v1/images/generations`；new-api 官方已支持的不动
  （gpt-image-2 / seedream 5 / qwen image3 均纯配置上线，零代码）；第三方一事一议、优先零代码。
- **异步形态裁决**：曾评估「全套 Seedance 式任务合同 + 专用任务入口 / 202 双模式」，因客户
  重申北向统一要求而放弃。最终选**内联等待、北向纯同步**，直接借鉴当前 `gpt-image-2`
  的普通图片渠道实现：不新增 Task、create attempt、客户幂等或第二套超时/退款状态机；
  由现有 `RELAY_TIMEOUT` 控制等待边界，超时沿用同步图片请求的失败与退款语义。该决定只适用于
  客户合同仍是同步、Provider 结果直接由本次请求取得的线路；不把它扩展为通用异步任务规则。
- **旧桥处置**：现存 mediaimage 桥无法服务 FunCloud（已验证：信封只认 `task_id`/`id` 与
  `result.primary_url`/`result.urls`，FunCloud 是 camelCase `taskId` + `result` 字符串数组；
  查询路径硬编码 `/v1/media/tasks/{task_id}`），且实现形态违背自身规则，按第 4 节整体移除。

## 2. 当前实际情况

### 2.1 FunCloud API 事实（来源：`docs/70-research/图片/` 两份文档，未经独立核实）

- Base URL `https://mm-internal-cn.leonecloud.com`，`Authorization: Bearer` 认证。
- 任务式协议：`POST /api/v2/open/aigc/{model}` 返回 `data.taskId`（camelCase）+ `status:
"processing"`；`GET /api/v2/open/aigc/{taskId}` 轮询，终态 `status: "success"` 且 `result`
  为纯 URL 字符串数组；另有批量查询（≤100）、余额端点、`callbackUrl` 回调。
- 四个模型与参数差异：

| 模型               | 参考图                   | 分辨率/质量                                    | 宽高比       | 其它                              |
| ------------------ | ------------------------ | ---------------------------------------------- | ------------ | --------------------------------- |
| nano-banana-2-lite | ≤10 张 ×30MB             | 单一分辨率                                     | 15 档 + auto | prompt ≤20000 字符                |
| nano-banana-2      | ≤14 张 ×30MB             | `resolution` 1K/2K/4K + `outputFormat` jpg/png | 15 档 + auto | 同上                              |
| seedream-5.0-lite  | ≤14 张 ×10MB（i2i 必填） | `quality` basic=2K / high=3K                   | 8 档         | prompt 3–3000 字符；`nsfwChecker` |
| seedream-5.0-pro   | ≤10 张 ×10MB（i2i 必填） | `quality` basic=1K / high=2K                   | 7 档         | 同上                              |

- 典型完成 5–30 秒；官方建议轮询 3s（前 30 秒）→5s；FunCloud 侧创建时预扣、失败退冻结。
- 错误码：0 成功 / 10002 参数 / 10005 鉴权 / 30003 任务不存在 / 40001 余额不足 / 90003 内部错误。
- 价格：每图计价；Nano Banana 2 打 55 折（1K $0.037 / 2K $0.0554 / 4K $0.0832 实付）；
  Lite $0.0336；Seedream Lite $0.0324；**Seedream Pro 价目存在疑点**（t2i 1k $0.09 >
  t2i 2k $0.045，疑似错位）且有 **input image $0.003/张**独立计费维度。

## 3. 实施方案与细节

### 3.1 渠道架构

- 新增 `ChannelTypeAsyncImage`（显示名「中转异步图片生成」）与 `relay/channel/asyncimage/`
  adaptor：
  - `ConvertImageRequest`：OpenAI 图片请求 → FunCloud 各模型形状（逐模型参数校验以代码表达）；
  - `DoRequest`：`POST {base_url}/api/v2/open/aigc/{model}`，Bearer 鉴权；
  - `DoResponse`：解析 `data.taskId` → 内联轮询 → 终态转换为 OpenAI 图片响应 + 计费乘数。
- 参与原生 Ability 与图片分发；模型清单、`model_mapping`、价格由管理员配置；不新增客户路由，
  复用现有同步图片生命周期。实现范围分成“必要注册接线”和“旧桥清理”两部分；必要注册接线
  不是只有两个文件：还包括 APIType、endpoint、前端类型/i18n 和通道测试画像等明确入口。
  原生文件改动全部压缩为**注册表追加或单行分支**（各 1–3 行，上游标准扩展点）：
  `constant/channel.go`（常量，插在 `ChannelTypeDummy` 前 + 名称映射 + `ChannelBaseURLs` 位切片
  各 1 行）、APIType 常量与 `common/api_type.go` case、`common/endpoint_type.go` 的
  `EndpointTypeImageGeneration` case、`relay/relay_adaptor.go` 的 adaptor case、前端
  `channels/constants.ts` / `channel-utils.ts` / i18n 条目；`controller/channel-test.go` 目标
  零改动（通用测试路径按模型名判 mode），最多单行 case，实现时核实。
- **编号风险记录**：上游渠道类型已顺序用到 60，本地 `ChannelTypeSeedanceLink = 61`，本渠道
  取 62；上游将来发布自己的 62 号渠道时撞号需改号 + DB 数字字段迁移，属本地扩展固有风险
  （SeedanceLink 已接受同款），此处记录在案。
- 创建请求失败**不自动重试**（`ErrOptionWithSkipRetry`）：避免客户端/网关重发造成重复扣费；
  渠道内不做 fallback。该语义沿用当前同步图片渠道，不把 Provider task ID 暴露为客户合同。

### 3.2 北向合同（OpenAI images 语义 + 显式收缩）

- 这是 OpenAI 图片入口的**渠道专用兼容子集**，不是完整 OpenAI images 语义；以下收缩必须写入
  公开文档并由请求校验明确拒绝不支持字段：
  - `n` 固定为 1，`n>1` 明确拒绝（不拆单）；
  - `size` 承载固定分辨率档：`nano-banana-2` 为 1K、`seedream-5.0-lite` 为 2K、
    `seedream-5.0-pro` 为 1K；宽高比用显式字段承载，不接受 `WxH` 字符串伪装；
  - 参考图字段暂不发布。客户端传入 `extra_fields.reference_images` 明确返回 400，直到
    FunCloud input-image 计费规则被核实并纳入预扣；不静默剥离或改义；
  - `response_format` 仅 `url`；不支持 `b64_json`；
  - `callbackUrl` 不属于公开合同；客户端传入时明确返回 400，不静默剥离或改义。
- 公开文档声明：该渠道模型为长阻塞端点，等待边界由部署的 `RELAY_TIMEOUT` 决定；**超时后
  不得重试**，重试产生的重复计费由调用方承担。`RELAY_TIMEOUT=0` 的环境不得上线该渠道。
- input-image 计费维度：在 FunCloud 价目核实前不发布需要该维度的客户模型；已发布模型的客户价
  必须在预扣前已经覆盖其固定参考图成本，不在 `DoResponse` 阶段临时追加倍率。

### 3.3 adaptor 职责

- 请求转换：当前固定规格发布只产生 `t2i`；`extra_fields.aspect_ratio`/`resolution`/`quality`/`outputFormat`
  按 §2.1 表逐模型映射。请求字段和所有额外字段必须通过代码白名单校验，JSON 编解码使用
  `common.Marshal`/`common.Unmarshal`。
- 内联轮询：官方建议节奏（前 30s 每 3s，之后每 5s），但整体等待受现有 `RELAY_TIMEOUT`
  限制；轮询请求使用本次请求的 context 和现有 Provider HTTP client，不新增任务状态机。
  超时按同步图片链路失败路径处理（预扣退还）；若 Provider 合同不能保证该语义，则不能使用本方案。
- 状态与错误归一：`processing` → 继续等待；`success` 必须返回恰好一个合法 URL，否则按
  上游响应错误处理；空 task ID、未知状态、非法 JSON、非 2xx、空结果和未知错误码均不得伪装成
  成功。明确错误码按：
  10002 → 参数错误（400）；10005/40001 → 上游凭据/余额问题（502 + 管理员告警日志）；
  30003/90003 → 上游失败（502）。均不换渠道、不自动重试。
- 计费：终态成功按创建前已冻结的客户模型价格 ×1 结算；结果张数固定为 1，不在终态临时写入
  未预扣的 `n` 倍率。失败全额退预扣；客户退款与 FunCloud 冻结/实扣按同步图片现有语义处理，
  但上线前必须完成 FunCloud 失败扣费保证核实。

### 3.4 实施顺序

1. 先盘点并验证现存 `platform='media_image'` 任务，完成 drain/终态化和回滚方案；不得在验证
   前删除旧桥；
2. 新增渠道常量、adaptor 与逐模型转换测试；
3. 管理端配置（模型清单、价格、渠道）与公开文档更新；
4. §2.3 闸门全部通过后上线灰度。

### 3.5 验证

- `go build ./...` 与 `cd relaykit && GOWORK=off go build ./...`；
- 确定性测试：请求转换逐模型表测、轮询终态/失败/超时/取消、`callbackUrl` 和不支持字段 400、
  `n>1` 与越界参数 400、空 task ID/空结果/多结果拒绝、失败不重试、同步预扣与失败退款；
- FunCloud 真实环境验收：创建、文生图/图生图、参考图上界、余额不足、错误码、部署配置的
  `RELAY_TIMEOUT` 等待上限；
- `task docs:check`、`task ai:check`、`cd web && bun run docs:validate`。

### 3.6 明确不做

- 不做任务合同：无 202、无任务查询端点、无 durable Task、无 create-attempt/幂等接线、无
  `Prefer: respond-async` 双模式；等待和退款沿用当前普通同步图片生命周期，不新增专用状态机；
- 不做协议 JSON、注册表骨架或通用桥；不同形状的任务式上游各自新增渠道（一事一议）；
- 不拆单 `n>1`、不支持 `b64_json`、不做跨渠道 fallback 或已接受任务的换渠道重试。
