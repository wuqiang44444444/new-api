# 文本与图片渠道最小请求抽样验证

## 范围与方法

按用户授权，在当前工作区已运行的本机网关上，对 4 个文本渠道、4 个图片渠道各提交一次真实请求。
使用现有测试账号和 API Key，通过管理员渠道 pin 固定目标渠道，单次发送，不重选、不重发。
不记录凭据、签名 URL、图片正文或原始 Provider 响应；本记录仅保留公开模型、结果和资金事实。

文本提示要求只回复 OK，输出上限分别为 GPT 16、Claude 16、Gemini 32、GLM 64 Token。
图片提示为白底单个红色圆，每次一张；GPT Image 低质量 1024×1024，Moxing 固定 2K，
Google Lite 1024×1024；FunCloud Lite 采用模型默认规格并显式选择异步。

核对请求 ID 或 Task ID 对应的主库日志、客户日志接口、实际渠道、Token 数量及钱包差额。
图片响应验证单图数量、Base64 解码或 URL 可读取性、PNG/JPEG 文件标识；未执行浏览器视觉验收。

## 异步图片日志语义

FunCloud 的公开 Task ID 为 `task_l89chHfiLF1UdhExSEOZwSMaP7w1KX8H`。约 51 秒后成功并结清，
仅在完成时记录最终消费，没有视频那种预扣消费与差额退款两行。
完成日志使用独立交付请求编号 `task-billing:3871:complete`；客户日志查询应按同一 Task ID 关联，

该渠道按次计费，上游未提供 Token，日志为 0 / 0，但记录 `image_count=1`；不能把这个零值解释为

## 发现的问题

### 墨行 Seedream 被本地身份筛选拒绝

单次标准 2K、n=1 请求在约 32 毫秒内返回 `task_plugin_identity`。
渠道选择阶段的插件身份筛选拒绝目标渠道，未进入图片履约与资金预扣；钱包无变化，无消费日志。
相关代码为 `middleware/distributor.go` 的选择错误出口与 `model/channel_constraint.go` 的
`FilterTaskPluginIdentity`。渠道 34 是本地图片类型 68，使用 `moxing_images_v1`，模型精确映射到
已登记的 Doubao Seedream 模型；需要进一步修复原生插件模型匹配与本地图片入口的边界，
不能通过误挂原生插件或放宽所有渠道的身份校验掩盖问题。
错误事件 1961 已持久化，但其 channel_id 为 0、stage/reason 为 unclassified、public_code 为空，
错误归属信息不完整；响应错误码不能据此视为没有错误事件。

### GPT Image 返回尺寸与请求不同

请求明确为 1024×1024、low、n=1，图片实际 PNG 尺寸为 1254×1254。
渠道无 gpt-image-2 模型映射及 size/quality/n 参数覆盖，单图、响应用量与扣费日志都正常，
但本样本的尺寸语义不一致，不能列为完整请求合同验收通过。未缩放输出或重发请求。

## 边界与后续

本次完成真实抽样和只读定位，未修改业务代码、渠道配置、资金事实或受保护目录。
结论仅覆盖上述 8 个请求。墨行路由边界与 GPT Image 尺寸差异需要单独处理；
其它模型、流式文本、图片编辑与其它部署未在本次样本内验收。
