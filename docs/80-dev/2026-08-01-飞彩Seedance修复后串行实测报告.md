# 飞彩 Seedance 修复后串行实测报告

## 1. 结论

2026-08-01 01:01—01:20，在本地网关 `http://127.0.0.1:8100` 上按既定顺序严格串行复测了
5 个飞彩 Seedance 公开 SKU。代码修复已经在真实 Provider 链路生效：

- 5/5 创建请求均返回 HTTP 200 并取得平台任务 ID，未重现此前 4/5 的
  `create_outcome_unknown`；
- 3/5 任务生成成功，均经历 `queued/running/succeeded`，飞彩的 `processing` 没有再触发
  `upstream_contract_violation`；
- 3 个成功任务均冻结 `54:third_party_json_video_omni_reference:v2`，公开查询只返回平台
  content URL，数据库普通响应快照中的上游 URL 为 `[redacted]`；
- 修复本机 Shadowrocket Fake-IP 后，3 个成功视频均可通过平台
  `/v1/videos/{public_task_id}/content` 下载，HTTP 200，且下载内容与上游签名 URL 的文件
  SHA-256 完全一致；Range `bytes=0-1023` 返回 HTTP 206 和 1024 字节；
- 2/5 任务由上游明确返回生成失败，网关投影为 `failed`，完成退款结算，最终 `quota=0`；
  它们不是创建结果未知，也没有残留 hold；
- 5 个公开 SKU 的单次价格均为 3。成功任务各结算 `1,500,000` quota（本地
  `quota_per_unit=500,000`），失败任务最终为 0；
- `generate_audio:false` 下，3 个成功文件仍都包含 AAC 音轨。该项仍需 Provider 确认，不能
  仅凭本轮实测改写产品合同。

因此，本轮验证证明 v2 状态、结果 URL、内容代理、SSRF、日志脱敏、计费和幂等主链路已经闭环。
两个 value 高规格 SKU 的明确生成失败属于当前 Provider 可用性问题，渠道仍应保留在 `randy`
灰度分组，不宜立即扩大正式流量。

范围边界：本轮五个请求全部是纯文本、4 秒、`16:9`、`generate_audio=false`。
没有证明单首帧、首尾帧、多参考图或“参考图 + 参考音频”已在真实飞彩链路可用。
自动化机器合同可证明文档与运行时值域一致，不能代替这些 Provider 产品验收。

## 5. 原问题闭环情况

| 原问题 | 本轮结论 |
| --- | --- |
| `processing` 被拒绝 | 已修复；真实任务持续投影为 `running`，无错误对账 |
| 顶层 `video_url` 无法使用 | 已修复；v2 校验同源 HTTPS URL，私有保存并由平台代理 |
| 动态 URL 错误携带 Bearer 风险 | 已修复；v2 内容请求不附加上游 Authorization，单元测试锁定 |
| Fake-IP 被 SSRF 拒绝 | 已修复本地环境；保留 SSRF，Shadowrocket 对 `feicai123.top` 使用 `always-real-ip` |
| 成功后残留失败原因 | 已修复；本轮 3 个成功 Task 的 `fail_reason` 均为空，恢复迁移另有回归测试 |
| unknown 缺少 request ID | 已修复代码与测试；本轮没有产生 unknown，未做真实 502 样本复验 |
| unknown 无人工拒绝入口 | 已实现 Root + security proof + Provider 确认 + 审计备注的 reject 入口，并有服务测试 |

本机 Fake-IP 的实际来源是 Shadowrocket 网络扩展，不是 Clash Verge。已在 Shadowrocket 当前
配置中加入 `always-real-ip=feicai123.top`，重启网络扩展后解析从 `198.18.1.1` 变为公网地址
`43.161.227.198`。修改前数据库备份位于
`/tmp/shadowrocket-default-before-feicai-20260801.db`。

## 8. 仍需跟进

1. 请飞彩确认 `generate_audio:false` 仍返回 AAC 是否为稳定预期；确认前不能向用户承诺无音轨。
2. 对 `value-1080p` 和 `value-4k` 在不同时间窗口继续灰度观察。只有上游可用性达到预定标准，
   才扩大 Ability 分组。
3. 若再次出现创建 502/超时，验证新的 unknown 记录是否原子保存上游 request ID，并通过人工
   reject 或到期 exposure 路径处置；不得自动重发 POST。
4. 在 MySQL 与 PostgreSQL 集成环境补跑根模块测试和人工 reject 的事务用例。
5. 补齐单首帧、首尾帧、参考图以及“参考图 + 参考音频”的真实创建、轮询、
   内容下载和计费验收；完成前不对外宣布这些组合已通过飞彩实测。
