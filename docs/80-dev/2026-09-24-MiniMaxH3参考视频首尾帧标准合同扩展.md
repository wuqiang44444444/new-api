# MiniMax H3 参考视频首尾帧标准合同扩展

## 问题与目标

[京东南向实测](2026-09-24-MiniMaxH3参考视频首尾帧与文件素材实测.md)确认三参考视频、独立首帧、
独立尾帧及首尾帧组合可以生成和下载。用户要求完整接入，并明确拒绝不能履约的文件素材能力。
本轮在 [1.1.0 多模态扩展](2026-09-24-MiniMaxH3多模态合同与公开文档更新.md)基础上扩展标准合同，
遵守 [标准视频架构](../20-architecture/Seedance专用渠道与Link架构.md)及
[公开元数据架构](../20-architecture/公开模型元数据投影架构.md)，不新建 Provider 私有北向入口。

## 当前实际情况

- 新制品 `minimax-link@1.2.0` 使用同一 ModelArk V3 content：参考模式最多九图、三视频、三音频，
  加一文本共十六项；图生模式接受独立 first_frame、独立 last_frame 或二者各一张。
- 两种模式互斥；重复首帧/尾帧、超量、错误媒体类型和不支持的文件引用明确拒绝，资金 hold 和
  Provider POST 不发生。纯文本 adaptive 仍拒绝，未开放的参数与取消/删除不新增 fallback。
- 图片/视频接受 HTTP(S) 与对应 MIME 的 Data URL，字段、role 与顺序完整保留。音频仍复用标准
  请求级传输；不增加视频托管、媒体下载检查、转码、素材资源表或文件接口探测。
- 参考视频官方单段 2–15 秒、总计不超过 15 秒的限制写入 API 文档，由 Provider 验证媒体事实；
  网关检查内容数量与结构，不下载视频获取时长，不把未验证时长作为计费乘数。
- 帧模式的合法 ratio 保持出站，上游按条件生效语义忽略并取输入图比例；计费 ratio 仍是冻结请求
  选择值，不从图片探测输出画幅。has_video_input 由标准 content 派生，写入冻结探针参与预扣和结算。
- 文件素材/素材组继续不发布 api.assets；有权访问的合法操作返回 422 unsupported_asset_operation，
  不调用上游；无分组权限返回 model_not_found，避免泄露。asset/mm_file 视频引用返回 400；
  mm_file 属于统一入口不支持的 URL 格式，不新增识别或透传通道。

## 优化方案与实施结果

所有业务变更位于 MiniMax 专属制品、宿主 adapter 与元数据投影。共享插件声明仅增加可选
allowFrameImages 字段和解析白名单，用于显式声明帧角色；未声明的制品不扩大公开角色。
没有修改 NEWAPI 原生路由、DTO、数据库 schema、Seedance 转换器、计费状态机或业务数据库。
content 保真校验继续使用既有唯一实现；默认值、时长和资金安全上限不变，credit 不用于客户计价。

新版本按既有 MiniMax 发布机制入库，须显式激活；不覆盖旧源码，不自动启用渠道。历史 Task 和
attempt 使用精确冻结版本；1.0.0、1.1.0 的目录范围保持原声明，部署不自动宣称新能力已启用。
公开 H3 页面同步参数、互斥规则、媒体限制、不支持语义和首尾帧/三视频 JSON 示例。

### 验证与剩余事项

自动化验证覆盖标准鉴权入口到模拟 JD POST、首尾帧角色和视频 URL 保真、最大参考组合、
视频输入不同单价的预扣与终态结算、冻结版本和无原始素材持久化；非法组合/超量/文件引用无
attempt、无占款、无上游调用。素材六项操作覆盖可访问与不可访问分组，元数据覆盖旧版本范围。

相关 Go 回归通过：MiniMax adapter、plugins、jsplugin、minimaxplugin、publicmodel、model、
controller、middleware、service、relay；minimaxlink 包编译通过（无独立测试）。
`task docs:check`、`task ai:check`、`bun run docs:validate` 和 Web 完整构建通过。

此前真实南向生成与下载的结果仍有效，但本轮没有再提交付费生成，也没有把桩测试记为真实网关
验收。新标准链路真实 Provider、内联音频 OSS、正常公网 DNS 下受保护下载、供应商账单和生产
灰度仍须单独验收。本轮不涉及数据库变更，不由本地 SQLite 回归推定外部数据库验收完成。
