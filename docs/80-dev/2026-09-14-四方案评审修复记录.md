# 四方案评审修复记录

## 问题与目标

修复本次联合评审发现的合同异常回退原价、价格展示漏项和缺价失真、URL 汇总返回未加载折扣，
并落实 Synlink 已验证的生成中映射及待核对呈现。遵循最小入侵，不调整实际费率或重写历史任务。

## 当前实际情况

- 合同请求解析、客户折扣明细和价格覆盖统一使用已有 `ContractDiscountsFromSnapshot`。
  负数、零、超过上限和同模型冲突折扣统一返回合同不可用；未约定模型保留原生价格。
- URL 专属响应使用仅含用量事实的渠道投影，去掉未加载的 `discount`；普通渠道账单接口不变。
- 价格接口明确序列化 `basis_price_configured: false`，普通模型详情及分组详情显示未配置。
  Token 动态价格同时展示用量费和每次附加费，固定费范围不随 1K/1M Token 单位换算。
- Synlink 插件本地版本升为 `1.3.3`，仅新增 `processing → running`；创建仍只接受 `pending`。
  执行中载荷的内部成功、结果和用量不会提前交付或结算。旧制品及历史 Go adapter 保持原合同。
- 日志列表和详情按持久状态显示待核对标签、提醒色及说明；恢复后删除活动诊断呈现。
  文案已补齐七语言，未增加任何字段访问权限。

本地测试使用 SQLite、合成任务和本机模拟 Provider；没有发起真实收费请求或读写生产配置。

## 再评审补充修复：合同详情与跨档收费项

本轮补齐两类组合场景：合同卡片已经应用有效倍率，但分组详情仍读取全局倍率；动态摘要只从
代表档位提取收费项，导致仅在其他档位出现的图像输出费、任务用量费和固定附加费遗漏。
同时发现价格列表单元格截断主项，会再次隐藏摘要已包含的收费项，已移除该截断。

- 分组详情优先使用模型响应的 `group_ratio`，仅未提供时使用全局倍率；不重复计算合同折扣，
  保留显式零倍率。Token、按次、动态 Token、任务用量和条件多档路径均有渲染回归。
- 动态摘要从后端投影的全部实际档位汇总收费项。有完整倍率场景时以场景替代未乘倍率的底价，
  避免底价污染范围；多个场景同价时也显示实际金额。仅在部分档位出现的项目，其不收费档位
  以零参与范围；所有档位都不存在的项目不凭空展示。每次固定费不参与 1K/1M Token 换算。
- 新增独立 `pricing-contract-display.test.tsx`，共 25 项回归；五条条件公式的样例由后端投影生成，
  并由已有 Go 前后端合同测试重新计算比对。测试覆盖卡片、列表、分组详情与投影不被修改。
- 初始 16 项回归中 12 项失败、4 项通过，确认复现问题后实施修复；随后新增的三项倍率场景
  回归也先复现失败。最终价格模块、模型列表和合同价格调用方共 16 文件、208 项测试通过；
  `go test ./pkg/billingexpr`、Bun 类型检查、改动文件 lint、生产构建及文档/品牌产物校验通过。
  `task docs:check`、`task ai:check` 和改动差异空白检查通过。

本轮生产代码只涉及已有展示入口的三个文件：`model-details.tsx` 调整一个倍率接线点，
`dynamic-price.ts` 局部替换摘要汇总逻辑并删除失去调用方的范围辅助函数，`model-price-cell.tsx`
移除主项截断。原生文件修改的必要性是修复现有页面消费合同的入口，未来上游同步冲突仅限这三处
展示分支；没有修改计费求值、实际费率、渠道选择或任务履约。外部验证事项继续保持待验收状态。
