# 内置 API 文档中心实施方案

## 1. 方案定位

本方案负责把 [内置 API 文档中心架构](../20-architecture/内置API文档中心架构.md) 落地到当前 React Web，并保持现有单次 Web 构建和单个 Go 二进制部署方式。

本方案交付的是当前 Web 内的 Mintlify 风格文档体验，不引入 Mintlify 运行时、独立文档站或第二套构建产物。

目标发布链路：

```text
Markdown + React Docs 模块
  -> cd web && bun run build
  -> web/dist
  -> Go embed
  -> /docs
```

## 2. 当前基线

### 2.1 已具备能力

| 能力 | 当前状态 | 复用方式 |
| --- | --- | --- |
| TanStack Router | 已有 | 新增公开 `/docs` 路由 |
| Marked | 已有 | 新建 Docs 专用解析器 |
| DOMPurify | 已有 | 对渲染结果执行净化 |
| Shiki | 已有 | 文档路由内按需用于代码高亮 |
| Tailwind CSS | 已有 | 构建三栏与响应式布局 |
| `/api/status` | 已有 | 获取站点名、服务地址等公开信息 |
| `docs_link` | 已有 | 运行时配置为 `/docs` |
| Go 静态资源嵌入 | 已有 | 自动包含 `web/dist/docs-content` |
| 前端 i18n | 已有 | 文档框架 UI 文案 |

### 2.2 当前缺口

- 没有 `/docs` 公开路由和专用页面布局。
- 没有外部文档内容目录、导航 manifest 和内容加载器。
- 现有 Markdown 组件会统一给链接增加新窗口属性，不适合作为文档内部路由。
- 没有稳定 heading ID、本页目录、上一页/下一页和文档搜索。
- `docs_link` 只要非空就可能在顶部导航中被标记为外部链接，不能正确区分 `/docs`。
- 当前 `docs/openapi/relay.json` 存在公开图片合同偏差，不能未经修正直接生成 API Reference。
- 没有阻止内部 `docs/`、后台 OpenAPI 或私有字段进入公开产物的校验。

## 3. 交付范围

### 3.1 首期必须交付

- `/docs` 和 `/docs/*` 公开路由。
- 顶部文档栏、左侧导航、正文、右侧本页目录。
- 移动端目录抽屉。
- Markdown 按页加载和错误状态。
- 受控 manifest 导航。
- heading 锚点和内部链接。
- 代码高亮、语言标签和复制按钮。
- 页面标题、描述和基础客户端 meta 更新。
- Base URL 等公开变量动态替换。
- 标题、摘要、关键词和 heading 搜索。
- 上一页/下一页导航。
- 首批中文文档。
- 构建、类型、lint、i18n、链接和内容安全检查。

### 3.2 首期不交付

- 在线 Try it。
- API Key 自动读取或填充。
- 服务端全文搜索。
- SSR/SSG 和每页独立 HTML。
- 管理员在线文档编辑。
- SDK 自动生成。
- 自动公开全部 OpenAPI operation。
- 多语言正文。
- 将当前内部 `docs/` 直接展示给用户。

## 5. 分阶段实施

## 5.1 阶段 A：合同与内容清单冻结

### 工作项

1. 枚举首期公开接口：

   ```text
   GET  /v1/models
   POST /v1/chat/completions
   POST /v1/responses
   POST /v1/images/generations
   POST /v1/images/edits
   GET  /v1/images/tasks/:task_id
   ```

2. 对每个接口确认：

   - 鉴权方式；
   - Content-Type；
   - 必填字段；
   - 可选字段和显式零值；
   - 枚举和上限；
   - 同步、流式或异步响应；
   - 错误信封；
   - 幂等、限流和计费说明；
   - 支持的公开模型/SKU；
   - 合同来源和最后验证日期。

3. 修订文档写作模板，禁止以下内容：

   - 真实 API Key；
   - 生产私有域名；
   - 渠道 ID 和上游凭据；
   - 供应商真实模型 ID；
   - `private_data`；
   - 未发布路由；
   - 未验证字段；
   - 后台 `/api` 接口。

4. 记录现有 OpenAPI 偏差，OpenAPI 未修正前不启用自动页面生成。

### 退出标准

- 首期页面清单和接口清单一一对应。
- 每个公开页面都有明确合同依据。
- 图片接口不再沿用 `relay.json` 中的 Qwen 私有北向结构。

## 5.2 阶段 B：文档基础路由与加载器

### 工作项

1. 新增 `/docs` 公共布局路由。
2. 新增文档首页和 splat 内容路由。
3. 定义 TypeScript manifest 类型。
4. 加载 `/docs-content/manifest.json` 并执行运行时校验。
5. 建立 `slug -> page`、`page -> previous/next` 映射。
6. 只允许从 manifest 登记的 `file` 获取 Markdown。
7. 实现 loading、404、内容缺失和 manifest 错误状态。
8. 修正文档顶部导航的内部/外部链接判断。

### 设计细节

加载器不得执行：

```ts
fetch(`/docs-content/${userSlug}.md`)
```

必须执行：

```text
用户 slug
  -> 查 manifest
  -> 得到受控 file
  -> 校验 file
  -> fetch 受控路径
```

### 退出标准

- `/docs` 刷新后可正常恢复。
- 已登记页面可访问。
- 未登记 slug 显示文档 404。
- `../`、编码后的路径穿越和任意 URL 不能触发文件请求。
- `/docs` 不要求登录。

## 5.3 阶段 C：独立 Markdown 渲染器

### 工作项

1. 新建 Docs 专用 Marked 实例。
2. 解析受控 frontmatter：

   ```yaml
   ---
   title: 图片编辑
   description: 使用原图和提示词编辑图片
   last-verified: 2026-07-28
   ---
   ```

3. 在 Markdown 解析前替换公开占位符。
4. 为标题生成稳定且去重的 ID。
5. 收集 `h2/h3` 生成本页目录。
6. 实现内部链接、锚点和外部链接分类。
7. 渲染代码语言标签和复制按钮。
8. 使用 Shiki 高亮；失败时降级为转义纯文本。
9. 最终 HTML 经过 DOMPurify。

### 安全允许列表

允许：

- 标题、段落、列表；
- 表格；
- 引用；
- 链接；
- 图片；
- 行内代码和代码块；
- 水平线；
- 受控提示块。

禁止：

- `script`；
- `iframe`；
- 表单；
- 事件处理属性；
- `javascript:` URL；
- 任意远程组件；
- Markdown 内 React/MDX 执行。

### 退出标准

- 文档内部链接不打开新窗口。
- 外部链接带 `noopener noreferrer`。
- 恶意 HTML fixture 被净化。
- heading ID 稳定且不会重复。
- 代码复制只复制代码文本。

## 5.4 阶段 D：文档布局与响应式交互

### 工作项

1. 实现桌面三栏布局。
2. 实现顶部文档导航和返回控制台入口。
3. 实现左侧分组目录和当前项高亮。
4. 实现右侧本页目录和滚动章节高亮。
5. 实现移动端文档目录、页面目录抽屉。
6. 实现上一页/下一页。
7. 为主内容增加跳过导航入口。
8. 控制正文最大宽度、表格和代码块横向滚动。
9. 使用现有主题变量支持浅色和深色模式。

### 可访问性要求

- 导航使用 `nav` 和明确 `aria-label`；
- 当前页面使用 `aria-current="page"`；
- 抽屉按钮使用 `aria-expanded`；
- 搜索、复制和目录按钮具备可访问名称；
- 键盘可完成打开、关闭、搜索、选择和跳转；
- 焦点不会在路由切换或抽屉关闭后丢失；
- 移动端代码块不遮挡复制按钮。

### 退出标准

- 320px 宽度下无页面级横向溢出。
- 桌面端正文、目录和本页导航互不覆盖。
- 键盘可以访问全部文档导航。
- 主题切换后文字和代码对比度可读。

## 5.5 阶段 E：动态站点变量

### 工作项

1. 从现有状态 Hook 获取：

   - `system_name`；
   - `server_address`；
   - 当前浏览器 origin。

2. 统一推导：

   - OpenAI Base URL；
   - Anthropic Base URL；
   - API Key 占位符；
   - 模型 ID 占位符。

3. 替换 Markdown 中的受控占位符。
4. `/api/status` 失败时使用安全回退，不阻塞静态正文。

### 约束

- 不从用户令牌列表读取真实 Token。
- 不从 localStorage 或 Cookie 注入密钥。
- 不在文档源文件写死站点域名。
- Base URL 是否包含 `/v1` 必须按协议说明，不做无条件拼接。

### 退出标准

- 不同部署域名显示对应 Base URL。
- 页面源码和构建产物中不存在真实 API Key。
- 状态接口失败时仍能查看文档。

## 5.6 阶段 F：导航搜索

### 首期索引字段

```text
title
description
keywords
headings
slug
group
```

### 工作项

1. 从 manifest 建立基础搜索索引。
2. 首次打开搜索时按需加载索引。
3. 搜索结果展示标题、分组和摘要。
4. 支持键盘上下选择、Enter 跳转、Escape 关闭。
5. 搜索索引失败时隐藏搜索，不影响目录导航。

### 后续增强

全文搜索需要新增同构建脚本，读取 Markdown 并生成：

```text

```

脚本接入现有 `bun run build`，不形成第二个部署产物。

### 退出标准

- 标题、关键词和 heading 可搜索。
- 未登记页面不会出现在结果中。
- 搜索不会抓取内部 `docs/`。

## 5.7 阶段 G：首批文档内容

### 开始使用

- 文档概述；
- 快速开始；
- Base URL；
- Bearer 鉴权；
- 获取 API Key；
- 获取模型 ID；
- 最小请求；
- 在用量日志中验证调用。

### 通用概念

- 模型发现；
- 错误格式；
- 限流；
- 计费；
- 幂等；
- 重试；
- 流式响应；
- 同步与异步任务。

### API Reference

首期每个接口页面必须包含：

1. 功能说明；
2. HTTP 方法和路径；
3. 鉴权；
4. Content-Type；
5. 请求参数表；
6. 支持的公开模型/SKU；
7. cURL、Python、JavaScript 示例；
8. 成功响应；
9. 异步或流式响应；
10. 错误示例；
11. 限流、幂等和计费提示；
12. 最后验证日期。

图片编辑页必须明确区分 multipart 文件上传和已经发布的 URL 输入形式，不能用南向 Qwen `input.messages` 结构替代统一北向合同。

### 排障

至少覆盖：

- Base URL 路径错误；
- API Key 无效；
- 模型不存在或无权限；
- 额度不足；
- 限流；
- Content-Type 错误；
- multipart 文件字段错误；
- 异步任务长期未完成；
- 客户端仍使用旧环境变量。

### 退出标准

- 每个示例只使用占位符。
- 页面参数和响应与真实北向合同一致。
- 不出现渠道、Provider 私有配置和后台接口。

## 6. Manifest 设计

建议首期 schema：

```ts
export type DocsManifest = {
  version: string
  defaultLocale: string
  groups: DocsGroup[]
}

export type DocsGroup = {
  id: string
  title: string
  pages: DocsPage[]
}

export type DocsPage = {
  title: string
  slug: string
  file: string
  description: string
  keywords?: string[]
  badge?: string
}
```

运行时校验要求：

- 根对象和数组类型正确；
- 必填字符串 trim 后非空；
- group id 唯一；
- slug 唯一；
- file 唯一；
- file 以允许的 locale 目录开头；
- file 以 `.md` 结尾；
- slug 和 file 不包含 `..`；
- keywords 数量和单项长度有上限；
- 页面总数有合理上限，避免异常 manifest 造成浏览器资源消耗。

## 7. 页面加载状态机

```text
idle
  -> loading_manifest
  -> manifest_error
  -> resolving_page
  -> not_found
  -> loading_content
  -> content_error
  -> rendering
  -> ready
```

规则：

- manifest 请求可在多个页面间复用；
- 页面切换取消已过期的内容请求；
- 旧页面内容不能在新 slug 加载失败时继续伪装成新页面；
- 搜索和相邻页预取不能覆盖当前页面状态；
- 解析异常必须进入显式错误状态。

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| OpenAPI 与真实合同漂移 | 用户按错误参数接入 | 首期人工审计，中期增加三方一致性检查 |
| Markdown 被用作脚本载体 | XSS 或恶意跳转 | 受控语法、DOMPurify、危险协议过滤 |
| slug 路径穿越 | 读取非公开静态资源 | manifest 白名单，不按 slug 拼文件路径 |
| 文档扩大首页包 | 首屏变慢 | Docs 路由代码分割、Markdown按页请求 |
| 更新后缓存旧文档 | 页面与 API 版本不一致 | manifest 版本、请求版本参数和发布验证 |
| 当前 SPA SEO 较弱 | 搜索引擎发现能力有限 | 首期接受；未来按业务需求评估 SSG |
| UI 与内容耦合 | 内容更新需要应用发布 | 接受单构建决策，以审查和合同一致性换取独立发布能力 |
| 全部内容手写重复 | 参数表维护成本增加 | OpenAPI 修正后生成/校验结构化部分 |
| 文档误泄露内部实现 | 安全与合同风险 | 公开目录隔离、白名单、构建产物扫描 |

## 12. 回滚方案

文档中心不涉及数据库和后端 API 迁移，回滚边界清晰：

1. 将运行时 `docs_link` 恢复为原配置；
2. 回滚包含 `/docs` 路由和静态 Markdown 的 Web/Go 应用版本；
3. 不需要数据回填、数据库降级或任务迁移；
4. 如果只有某篇文档错误，可以先从 manifest 移除该页面并重新发布；
5. 受保护的项目归属和现有默认信息始终保留，不作为回滚对象。

## 13. 建议实施批次

| 批次 | 范围 | 预计结果 |
| --- | --- | --- |
| P0 | 合同清单、manifest、路由、加载器 | `/docs` 可以安全打开静态页面 |
| P1 | Markdown、代码块、目录、响应式 | 获得完整文档阅读体验 |
| P2 | 动态 Base URL、搜索、首批文档 | 可以供第三方完成接入 |
| P3 | OpenAPI 修正、校验、生成 | 降低合同漂移 |
| P4 | 英文、全文搜索、增强组件 | 按真实需求扩展 |

每个批次独立完成测试和生产构建后再进入下一批，避免同时搭 UI、重写 OpenAPI 和大规模撰写内容造成验收边界不清。

## 14. 完成定义

本方案完成必须同时满足：

```text
单次 Web 构建
+ 单个 Go 部署
+ /docs 公开路由
+ Markdown 按页加载
+ 受控导航与安全渲染
+ 首期 API 文档
+ 动态部署信息
+ 搜索与响应式
+ 合同和安全校验
```

仅出现一个漂亮的文档页面、仅能渲染 Markdown、或仅把 OpenAPI 文件暴露出去，都不能视为完成。
