# 墨行 Seedance 统一协议整合方案

## 1. 问题与目标

用户要求只维护一套最新墨行 Seedance 接入，完整承接文生、图生、参考视频和参考音频输入。
文档未明确禁止的媒体组合，本地不增加限制；Fast/Mini 的纯音频参考不应被本地拒绝。
本方案取代[跨渠道分析](2026-09-10-Seedance参考音视频支持问题分析与解决方案.md)中墨行的旧实施建议，
原文保留跨渠道问题与真实调用证据。本次重新核对用户提供的四份原文和当前代码，只更新分析文档。

目标模型必须保持以下精确 ID，不以 `-0818` 替换 2.0：

| 模型 | Provider 模型 ID |
| --- | --- |
| 2.0 | `doubao-seedance-2-0-260128` |
| Fast | `doubao-seedance-2-0-fast-260128` |
| Mini | `doubao-seedance-2-0-mini-260615` |
| 2.5 | `doubao-seedance-2-5-260628` |

唯一视频南向入口为 `POST /v1/media/generations`，查询为 `GET /v1/media/tasks/{task_id}`。
最终只提供一个墨行视频协议选项，并以统一国内素材库为素材整合目标；不新增 Ark 路径、自动探测或 fallback。
范围是上述 Seedance 视频与相关素材协议，不包含独立的墨行图片生成协议。

实施以完成四模型统一接入为目标：已明确的本地修复直接推进，准确 2.0 的外部验证同步开展。
外部证据缺口只约束依赖它的归并与发布，不阻塞其它模型的独立修复，也不以长期保留两套协议代替整合。

北向仍以[硬约束](../00-context/硬约束.md)、[Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)
和[素材代理架构](../20-architecture/Seedance无状态素材代理架构.md)为准。“不多拦截”指不添加无依据的
Provider 能力限制，不改变结构校验、资金安全、身份隔离或合同外私有字段的既有边界。

## 2. 当前实际情况

### 2.1 四份文档确认的能力

| 模型 | 文本 | 图片 | 参考视频 | 参考音频 | 纯音频参考的本地处理 |
| --- | --- | --- | --- | --- | --- |
| 2.0 | 支持 | 支持 | `reference_videos` | `reference_audios` | 原文明确写“不能只传音频”，至少有参考图片或视频；该条不能推广给其它模型 |
| Fast | 支持 | 支持 | `content[].video_url` | `content[].audio_url` | 按用户明确要求不拦截，交给上游判断 |
| Mini | 支持 | 支持 | `content[].video_url` | `content[].audio_url` | 按用户明确要求不拦截，交给上游判断 |
| 2.5 | 支持 | 支持 | `content[].video_url` | `content[].audio_url` | 文档明确支持，无需搭配图片或视频 |

“纯音频参考”指没有图片或视频的音频参考，可包含文本提示词；是否可以连文本也不传应单独验证。
`generate_audio` 是输出声音开关，与是否输入参考音频无关；不能因为有音频输入而强制打开它。
支持参考视频也不代表平台需要新增一套视频编辑 API；延长、运镜等意图由提示词及上游处理，
不在本地按关键词猜测场景或重写参数。

证据位置：

- [2.0 原文](<../70-research/墨行/国内/seedance 2.0.md>)：第 428–440 行列出参考生视频字段；
  第 435 行明确音频搭配条件，第 437 行明确参考视频。
- [Fast 原文](<../70-research/墨行/国内/seedance 2.0 fast.md>)与
  [Mini 原文](<../70-research/墨行/国内/seedance 2.0 mini.md>)：参数表列出四类 `content`；
  第 131 行混用“需配合”与“不建议仅传音频”，第 132 行明确官方字段原样透传。
  用户已明确这一表述不作为本站阻断纯音频的依据，不能继续把它解释成本地硬限制。
- [2.5 原文](<../70-research/墨行/国内/seedance 2.5.md>)：第 39 行列出四类输入及数量，
  第 141 行明确官方字段与唯一 Media 路径，第 144 行明确独立音频参考。

Fast/Mini 文档中的“常用”“建议”“不建议”不应转换为本地枚举、数量上限或必填条件。
当前代码的 9 图／3 视频／3 音频不能仅凭这两份页面得到确认，应追溯直接依据；没有依据的
模型限制应移除，不把其它 Provider 或其它模型规格移植过来。2.5 的 30 图／10 视频／10 音频、
总计 50、音视频各自总时长 30 秒是该模型的明确文档描述，不能倒推 Fast/Mini 的规格。
数量规则按准确模型的直接证据取舍：2.5 保留有依据的数量上限，Fast/Mini 移除无依据的数量上限；
统一北向的请求体大小、结构、类型、角色和字段校验继续生效，不表示接受任意 `content`。
不为验证远程媒体时长新增下载、媒体探测或素材物化链路，供应商可校验其实际媒体约束。

### 2.2 “官方字段原样透传”对方案的影响

Fast/Mini 明确声明 `content`、`duration`、`resolution`、`ratio`、`generate_audio`、`watermark`
直接透传，不做字段名映射；2.5 同样声明，并增加 `output_format`、`seed`。
因此这些模型应继续发送官方多模态形状，不再转换为 `prompt`、`reference_*`、`duration_seconds`、
`aspect_ratio` 或 `with_audio`，也不需要拼装 `input_mode/control_mode`。

这是墨行对自身入口的说明，不意味着本站应把整个未知 JSON 或供应商 `extra` 开放给客户。
本站从统一北向类型化请求构造南向报文；已发布字段保持其值和语义，合同外参数仍按北向规则处理。
文档表格把开关标成 string，但官方语义是布尔；不能据此把本站的 `false` 自动改成字符串。
现有 Fast/Mini/2.5 真实文本测试使用布尔 false 已成功；可选开关继续区分未传与显式 false。

指定 2.0 的原文仍展示 `duration_seconds/aspect_ratio/with_audio/reference_*` 和 JoyCreator 素材库，
并未出现 Fast/Mini 第 132 行的同一段官方字段声明。这是文档不一致，不能据此替换模型，
也不能假定 2.0 已验证可以全字段原样发送。整合优先验证精确 2.0 的官方 `content` 形状；
若供应商确认此形状适用于它，则直接删除旧转换。只有实测或供应商明确证明仍需差异转换时，
才在唯一 adapter 内保留必要序列化，不保留第二套可选协议，不自动尝试两种请求。

### 2.3 当前代码为何尚未达到目标

| 缺口 | 代码证据 | 影响与处理方向 |
| --- | --- | --- |
| 视频协议重复登记 | [upstream_protocol.go](../../relaykit/dto/upstream_protocol.go) 的两条 Moxing 视频协议 | 路径已经相同，仍是两个配置选项；最终收敛到一条 |
| 精确模型清单分裂 | [channel_seedance_settings.go](../../model/channel_seedance_settings.go) 的 `validateMoxingTokenSaveModelMapping` | 新协议只接受 Fast/Mini/2.5，指定 2.0 被留在旧协议；需将四个 ID 纳入唯一墨行登记 |
| 旧版重写请求 | [adaptor.go](../../relay/channel/task/seedance/adaptor.go) 与 [thirdparty/relay.go](../../relay/channel/task/seedance/thirdparty/relay.go) | 旧 2.0 调用转换，新协议直接发送类型化正文；不能只合并名称而不处理实际分支 |
| Fast/Mini 纯音频被拒绝 | [provider_model_specs.go](../../relay/channel/task/seedance/provider_model_specs.go) | `allowAudioOnly` 缺省 false，通用校验拒绝有音频而无图片、视频的请求；必须按用户要求解除 |
| 参数限制缺少逐项依据 | 同上 | `camera_fixed`、部分 `seed` 以及一组标准可选字段直接报错；应按北向合同和准确 Provider 文档逐项处理，不能整段复制为新协议规则 |
| 输入事实和展示不准确 | [relay_billing_mode.go](../../relay/channel/task/seedance/relay_billing_mode.go) | `relayBillingModes` 只看图片，视频／音频参考可能被记为 text；`modelArkTaskAction` 又将它们显示为图生视频 |
| 缺省时长的合同与预扣不一致 | [billing_probe.go](../../relay/channel/task/seedance/billing_probe.go)、[adaptor.go](../../relay/channel/task/seedance/adaptor.go) 与 [publicmodel/video.go](../../pkg/publicmodel/video.go) | 公开缺省与预扣均为 5 秒，新墨行协议南向却省略缺失的 `duration`；2.5 文档声明上游缺省为 `-1`，必须同时修正实际履约与预算，不能只提高预扣 |
| 运行时与公开规格重复 | [publicmodel/video.go](../../pkg/publicmodel/video.go) 与 `provider_model_specs.go` | 模型分组和媒体数量分别维护，容易继续出现“服务接受、页面不显示”或两处限制不一致 |
| 素材仍为两套 | [asset_service.go](../../service/asset_service.go)、[JoyCreator adapter](../../relay/channel/task/seedance/assets/moxing_joycreator.go)、[国内素材 adapter](../../relay/channel/task/seedance/assets/moxing_volc.go) | 两个协议对应不同 API 和资源表达，改一个显示名称并不能统一素材库 |

旧 converter 对音视频写入 `input_mode=multi_modal`，指定 2.0 原文的参考场景却写 `multi_image`。
该差异应随精确 2.0 请求形状验证解决，不能把当前 converter 视为正确标准后原样搬进新 adapter。
优先采用官方 `content` 后，这些场景字段只可能作为既有计费维度存在，不应重新加到官方南向正文。

### 2.4 watermark 的证据边界

此前直连墨行的 Fast/Mini/2.5 文本测试，官方字段形状和布尔 `watermark=false` 均取得成功终态。
指定 2.0 则在受理后异步拒绝 watermark；改用其页面的旧字段形状、把 false 改成字符串也未解决。
省略 watermark 的对照在观察期限结束时仍运行中；放入 extra 的对照返回 502 且未取得可信任务 ID，
创建结果未知。完整脱敏证据见[原分析 §6.7–6.8](2026-09-10-Seedance参考音视频支持问题分析与解决方案.md#67-真实路径测试结果)。

因此不能说是本站丢失 false，也不能断言模型底层不支持水印；已定位的是墨行当前异步调用链与
文档声明不一致。整合必须保留客户显式 watermark，不静默删除、不擅自改位置、不失败重发。
后续单独核验正确 2.0 的实际字段合同及 watermark 生效结果，不能以更换为 0818 代替修复。

## 3. 优化方案

### 3.1 一个视频 adapter，以官方多模态报文为目标

复用现有 `moxing_modelark_media_v1`，把四个精确模型登记到该协议。最新实现不要求协议标识
随供应商页面日期增加版本号；不要再创建一个并列的 `moxing_v2`。adapter 版本是否升级由冻结任务
语义决定，不能以“最新”名义修改已有任务含义。

| 北向输入 | 唯一墨行 adapter 的目标南向行为 |
| --- | --- |
| 客户 `model` | 只按显式 `model_mapping` 得到四个精确 Provider ID 之一 |
| `content[].text` | 保持文本内容，不按关键词推断编辑、延长或额外模式 |
| `image_url`、`video_url`、`audio_url` | 保持嵌套 URL、原有 role、顺序和引用；不丢弃混合媒体 |
| `duration`、`resolution`、`ratio` | 按官方字段发送，保留已发布北向默认语义，不为“常用值”收紧枚举 |
| `generate_audio`、`watermark` | 保留显式 false；不因为音频输入改开关，不把缺省与 false 合并 |
| 北向已发布的条件生效字段 | 按北向条件转换或忽略；不得把 Provider 不生效反向变为客户错误 |
| 合同外字段 | 继续由统一北向边界处理，不建立无约束 Provider extra 透传入口 |
| 创建与查询响应 | 复用 Media task 归一化，校验可信任务 ID，处理 `result`、`usage` 与真实状态 |

上述官方形状已用于 Fast/Mini/2.5；精确 2.0 的全字段可用性仍是完成四模型收敛的验收项。
其余三模型不需要等待该项才能移除无依据的纯音频限制、补充多模态测试或修正目录。
协议归并只作用于墨行专属入口，不改 NEWAPI 原生路由，不改 TokenSave 的业务限制。

### 3.2 校验遵循“没有明确禁止，就不额外阻断”

1. Fast/Mini 的 audio-only 请求通过本站模型校验，最终由墨行决定能否生成；拒绝断言改为
   校验通过且南向完整携带 `audio_url` 的回归测试。2.5 同样覆盖独立音频。
2. 2.0 原文明确的音频搭配规则单列，不能用它给 Fast/Mini 追加同样限制；参考场景中
   `reference_images` 标必填、音频又可搭配视频的矛盾也不能扩展为所有视频参考必须加图。
3. Fast/Mini “常用 5 秒”“建议 720p”不等于只支持这些值；未证实的模型数量、分辨率、
   可选字段限制逐项去除或留给上游。合法北向输入不因本地猜测供应商规格而提前失败。
4. 影响费用的数量和时长仍必须在既有安全边界内，不能为放开 Provider 能力绕过预扣保护。
   `duration=-1` 的预算上限只是资金估算，不应覆盖实际发出的 -1；北向缺省时长也不能被
   2.5 文档的上游缺省 -1 静默替换。具体处理与验收按下表执行。

缺省时长按已发布北向默认 5 秒履约。唯一墨行 adapter 在构造南向正文时显式落实该默认值，
客户请求 DTO 仍用指针保留“未传”事实；不把所有可选字段统一补零或覆盖客户显式值。
若精确 2.0 经验证仍需差异序列化，同一 5 秒语义也必须落到其实际时长字段。

| 客户时长输入 | 南向履约 | 预扣与结算要求 |
| --- | --- | --- |
| 未传 `duration` 和 `frames` | 发送北向默认 5 秒，不交给上游选择自动时长 | 按 5 秒构造预扣探针，公开默认值保持 5；真实验收确认 Provider 按该值履约 |
| 显式合法 `frames` | 原样发送；未传 `duration` 时不额外补 5 秒，显式时长也不覆盖 | 沿用统一北向探针的帧数优先语义，以 `ceil(frames/24)` 估算；仍须验证供应商实际履约 |
| 显式合法正整数 | 保持客户值 | 按该值估算，继续执行既有时长上界校验 |
| 显式 `-1` | 原样发送 `-1` | 复用代码登记的智能时长预算上限：当前 2.0/Fast/Mini 为 15 秒，2.5 为 30 秒；上限只用于估算 |

上述路径均按创建时冻结的计价方式和可信终态事实结算；预算上限不是实际用量，不因本次修复切换
计费模式，也不把缺失用量伪装成已知值。不能用“缺省仍省略、预扣改成 30 秒”代替默认 5 秒的履约。
当前 5 秒与 30 秒之比只是最大时长暴露差异；只有同单价、按秒线性计费时才对应最多六倍费用，
不代表实际任务必然生成 30 秒或实际账单必然低估六倍。

不为这个局部修复改造所有 Provider 的 `allowAudioOnly` 默认值。墨行精确模型规则应显式表达，
避免其它 Provider 被连带放开；也不新增管理员编辑能力 JSON、逐模型动态 capability 或 fallback。

### 3.3 统一目录、任务展示与计费输入事实

四个模型的公开目录都应展示文本、图片、视频和音频输入；目录应区分可接受类型与已实测成功组合，
不能把 Fast/Mini “本地不拦截”宣称为供应商纯音频已验收。
将墨行模型登记和有依据的规则作为有限、明确的代码定义供运行时与只读公开投影使用，避免继续
维护两套不同允许列表；不借此重构整个 Provider 能力系统。

从同一类型化 `content` 提取实际媒体事实：包含视频或音频参考的请求不能只因无图片就记为 text，
修正对象是 `input_mode/control_mode` 与任务动作，任务展示复用既有“参考生视频”动作。
`billing_probe.go` 已正确从非空 `video_url` 提取 `has_video_input`，保留该实现并回归验证；
音频输出开关继续按客户显式值或已定义默认值计算，不因参考音频输入而改变。
计费维度不等于上游必填字段，不为修正内部分类向官方南向正文添加场景字段。
实施前核对现有表达式如何使用这些维度，给出明确新请求语义并测试价格，不重解释历史探针。
按[计费表达式说明](../../pkg/billingexpr/expr.md)和已冻结价格履约，不因合并协议把秒价自动改成 Token 价。

### 3.4 素材目标是一套国内库，缺口针对准确 2.0 验证

目标复用 `moxing_volc_assets_v1` 与 `/v1/volc/assets`；素材南向不传 model，接受 Image/Video/Audio。
目前 Fast/Mini/2.5 国内素材页的复用列表写的是带 `-0818` 的 2.0，指定 2.0 原文仍是 JoyCreator。
这只构成指定模型的证据缺口，不能证明它一定不支持统一库，也不能因此替换它。

用同一真实素材租户，分别验证国内库创建的图片、视频、音频引用能够被四个准确模型消费。
官方 ID 若可直接复用，删除旧 JoyCreator 新建入口与无用途实现，所有目标模型配同一素材协议。
若准确 2.0 确实无法消费该库，应由墨行补齐或确认可行接入；在此之前不能宣布全部素材已统一，
更不能做两套库自动识别、素材复制或请求失败后切换来掩盖缺口。

同一本站 Channel 内共享账号／素材租户时发布相同匿名 `reuse_scope`。不同 Channel、不同墨行
内部 channel key 或上游账号不自动互通；墨行返回作用域错误后不跨账号重试。
复查国内素材 adapter 当前附加的 `ProjectName=default` 与文档“服务端配置项目”是否一致，
只发送履约所需字段，不引入新的客户项目选择参数。普通 AIGC 与真人素材流程分别按文档验证，
不能因为普通音视频素材可用就宣称全部真人音视频流程已验收。

渠道默认素材组继续由管理员手工创建或复用；显式组 ID 优先，不自动建组，不改变 opaque 引用。
旧素材 ID 不因迁移就被认定可在新库使用，平台不建立 ID 映射、resolver 或客户素材数据库。

### 3.5 修改范围与迁移顺序

| 阶段 | 具体工作 | 完成依据 |
| --- | --- | --- |
| 1. 确认准确 2.0 | 官方 `content` 形状、watermark、国内素材引用逐项验证，区分文档矛盾与真实失败 | 精确模型、可信任务 ID、成功终态及素材作用域证据；0818 不计入 |
| 2. 统一视频实现 | 单协议登记四模型，清理旧创建转换或吸收已证实必要差异，移除 Fast/Mini audio-only 阻断 | 管理保存、运行时、南向请求和公开投影一致 |
| 3. 校准事实 | 修正媒体模式和任务展示，保留并验证已有视频探针；落实缺省 5 秒、显式正整数、显式 -1 的南向与预算语义 | 全链测试证明未丢媒体、未改显式参数，公开默认、实际请求、预扣和结算一致 |
| 4. 收敛素材 | 单一国内素材 adapter；按租户迁移渠道配置，核对旧组与旧 ID | 四模型可消费同库资源，错误 scope 不 fallback |
| 5. 删除旧配置与无用途实现 | 移除旧墨行视频／JoyCreator 注册、管理选项和失去调用者的转换；保留 TokenSave 所需代码 | 新配置只有一个墨行视频选项和一个目标素材选项，没有自动兼容入口 |

阶段 1 的剩余外部证据不阻止独立的 Fast/Mini 校验和三模型官方字段回归工作。
阶段 2、3 的独立改动可以同步实现和本地验证；受影响配置切换前必须完成默认时长与资金链的一致性验证。
统一的是代码协议，不要求把不同账号或素材租户合并到一个 Channel。按实际迁移方式执行：

1. 迁移前盘点目标客户模型、渠道与素材租户，以及未终态 Task、unknown attempt、待补用量、
   待结算、交付依赖和默认素材组配置；先准备通过本地验证的新实现，确认新请求与旧任务均可履约。
2. 同一 Channel 原地改协议时，模型唯一性校验排除当前 Channel ID，无需仅为唯一性而先停用。
   视频与素材协议按合法配对一起保存；已有素材边界时，管理员明确确认替换素材租户，按既有事务
   重建 `reuse_scope` 并清除旧默认组配置，再手工创建或复用新租户默认组。默认组准备期间，依赖
   默认组的素材创建仍按既有缺失错误返回；不得沿用旧组或自动建组。
3. 只有客户模型迁往另一个 Channel 时，才需要解除旧渠道的启用占用。先以停用状态保存并准备
   目标渠道及默认组；切换时从旧渠道移除目标模型或停用旧渠道，再启用目标渠道。两次管理保存之间
   存在新建请求不可用窗口，应提前安排；不通过双启用、运行时 fallback 或绕过校验消除该窗口。
4. 切换后核对模型可用性、唯一渠道归属、协议配对、素材 scope 和默认组；完成目标租户的代表性
   创建与查询验收。旧 opaque ID 的兼容性按 §3.4 处理，不能因渠道迁移成功就认定旧素材可复用。
5. 停止旧配置承接新请求后，已有任务继续按冻结的模型、协议、连接和价格履约；不得改写快照。
   删除旧注册与实现前，确认上述存量任务、attempt、结算和交付依赖均不再需要旧路径。
   过渡期只保留仍有实际消费者的既有履约代码，不新增公开旧版入口、兼容 alias 或双写合同；
   无引用后完成阶段 5 的删除，不把阶段性修复作为整合完成。

本方案的本地实现及评审修复已完成对应回归验证，见 §3.7；尚未执行上述生产配置迁移或补充真实生成，
不将既往只读本地渠道快照当作生产盘点。

### 3.6 验证与完成标准

本地测试覆盖四个准确模型的文生、单图、多参考图、视频参考、图视频混合、图音频混合、
视频音频混合；另覆盖 Fast/Mini/2.5 的独立音频通过本地校验和原样出站。
准确 2.0 的音频搭配规则单独测试，不把该断言复制给其它模型。
测试捕获实际 HTTP 请求，确认 Media 路径、model、嵌套 URL、role、字段名称、false/0 和缺省语义，
而不是只测试规格对象里某个布尔值。按真实输入验证任务动作、预扣探针及 Provider 用量的结算路径。

以下回归与真实验收分别证明对应合同：

- 时长：分别覆盖缺省、显式 `5`、显式 `-1` 的实际出站正文与预扣值；缺省和显式 `5` 均按 5 秒
  履约，`-1` 出站不变且使用对应模型预算上限。覆盖余额不足时不发送 Provider POST，以及可信
  实际用量参与冻结规则结算和差额处理、重复结算不重复扣退、用量缺失不虚构数值。
  显式 `frames` 的请求另行覆盖，避免将“未传 duration”误判为“未指定时长”。
- 输入事实：无图的视频参考、独立音频、混合媒体均验证媒体模式和任务动作；视频存在与否仍由
  既有 `has_video_input` 正确表达，纯音频不会变成视频输入或强制打开 `generate_audio`。
- 数量：Fast/Mini 超过旧 9/3/3 上限的合法请求通过本地并完整出站；2.5 的 30/10/10 边界接受、
  超界拒绝，素材总数按 50 的文档约束表达。数量放开不跳过北向结构、角色和字段校验。
- 迁移：同渠道更新不与自身冲突，跨渠道同名双启用被拒；素材租户替换后的 scope 与默认组行为
  符合既有合同。配置变更后旧任务仍按冻结事实查询、结算，不能重新读取新协议解释历史任务。

真实验收需补充不传时长、显式固定时长与智能时长的代表性调用，核对实际时长及账单证据；
本地捕获到正确正文只能证明本站发送正确，不能代替 Provider 实际履约验证。

真实验收逐模型、逐场景记录成功或供应商明确拒绝；HTTP 200 创建成功不足以代表生成成功。
先用小规模代表性场景确认，再补必要边界，不机械执行大量重复付费调用。水印单独验证字段受理和
最终画面，媒体参考单独验证参考效果；不要用省略 watermark 的成功冒充 false 生效。
超时、502 或缺少可信任务 ID 时按 unknown 处理，不自动重发创建。早先未终态及 unknown 对照
应单独收尾，不先假定失败。真实账单、素材复用和本站完整资金链分别验收，不能互相替代。
