# Link 服务合同概念与协作关系

## 1. 目的与文档地位

本文在 [Link 服务合同注册与履约架构](../20-architecture/Link服务合同注册与履约架构.md) 与
[Link 资源合同与解析架构](../20-architecture/Link资源合同与解析架构.md) 的现有事实基础上，提出一套
面向产品、运维和开发人员都能稳定理解的 Link 术语。它解决以下问题：

- 什么是客户承诺，什么是 Provider 实现；
- 什么属于合同，什么属于实现、方案或渠道配置；
- 视频调用、素材调用、模型 SKU 与自定义客户模型如何协作；
- 管理端选择一个对象时，系统究竟自动确定了什么；
- 哪些概念可以向客户公开，哪些只能出现在内部执行和管理员审计中。

本文同时采纳 [Link 自定义客户模型反向解析复评结论](2026-08-04-Link自定义客户模型反向解析复评结论.md)
已经确认的设计边界：管理员可以继续使用任意客户模型名；Link SKU 仍是稳定能力合同；客户模型发布到
SKU 的事实不能只由当前在线渠道临时决定；Provider 反向解析只用于发布推导和执行复检。

本文是 `80-dev` 中的待实施术语方案。实施完成并通过验收后，应将已确认定义收敛到
`docs/20-architecture/`，再归档本文。

## 2. 统一概念树

```text
Link 服务合同
├── 客户接入合同（北向合同）
│   └── 客户模型发布事实（客户模型别名 -> Link SKU）
├── Link SKU 能力合同
├── Link 资源合同
├── 任务与计费合同
└── 上游调用合同（南向合同）
    ├── 视频上游合同
    └── 素材上游合同
```

这棵树描述一个 Link 扩展产品从客户调用到 Provider 执行的完整合同边界。其中：

- 客户接入、SKU 能力、Link 资源、任务与计费共同定义客户得到什么；
- 客户模型发布事实把管理员定义的客户模型名稳定关联到某个 Link SKU；
- 上游调用合同定义系统如何借助 Provider 履行这些承诺；
- 南向实现只能完整实现已经发布的客户承诺，不能反向扩张、缩减或改变客户合同；
- 同一个公开 SKU 可以由多个等价的南向实现履行。

## 3. 核心名词与定义

### 3.1 Link 服务合同

**定义：** Link 对一个扩展产品从客户调用、能力校验、资源解析、任务生命周期、计费，到 Provider
执行与结果归一化的端到端合同总称。

**范围内：**

- 客户调用方式和稳定响应；
- 公开 SKU 能力；
- `asset://` 资源语义；
- 同步或异步任务生命周期；
- 计费、结算、退费与对账；
- Provider 上游调用与归一化要求。

**范围外：**

- 普通 NEWAPI 原生渠道和模型的全局合同；
- 某个渠道的 API Key、价格、权重和启停状态；
- 运行时自动寻找 Provider 或自动选择价值档位；
- 仅靠数据库配置、模型名称或 Base URL 推断出来的能力。

“Link 服务合同”替代讨论中的“Link 总合同”，强调它是一份完整服务承诺，而不是一个需要管理员
直接选择的配置对象。

### 3.2 客户接入合同（北向合同）

**定义：** 客户调用 Link 网关时必须遵守、并由 Link 对客户稳定承诺的 API 入口合同。

**主要内容：**

- 路径和鉴权；
- 请求、响应和错误外壳；
- 幂等与可观测行为；
- 客户可见的任务创建、查询和取消入口；
- 客户使用自定义模型名的方式。

客户模型名继续遵守 NEWAPI 既有模型发现、Token 权限、价格、Ability、日志和响应语义。它可以与
Link SKU 完全不同，但一旦作为 Link 产品发布，就必须通过客户模型发布事实稳定指向一个 Link SKU，
不能随当前启用渠道或 `model_mapping` 的临时结果静默改变产品含义。

客户接入合同不包含 Provider 路径、Provider 模型 ID、上游素材 ID、上游鉴权或 Adapter。当前代码中
的 `contract_id` 仍是这类协议族和响应投影的内部身份。

“北向”只说明调用方向为“客户到网关”。在不需要强调方向时，统一使用更直观的“客户接入合同”。

### 3.3 客户模型发布事实

**定义：** 系统发布一个 Link 客户模型时形成的、稳定且可审计的客户模型别名到 Link SKU 的关系。

默认逻辑键为：

```text
(contract_namespace, route_family, customer_model)
  -> link_contract_sku + publication_version
```

其中：

- `contract_namespace` 表示可由请求稳定确定的客户合同命名空间，不得用运行时最终落到的动态 group
  隐式代替；
- `route_family` 表示图片生成、图片编辑、OpenAI Video、通用视频等代码注册的稳定入口族，不直接使用
  任意原始 URL；
- `customer_model` 是管理员在 NEWAPI `models` 中配置、客户实际调用的模型名；
- `link_contract_sku` 是代码注册的稳定能力身份；
- `publication_version` 用于区分显式改绑，不随渠道启停自动变化。

客户模型发布事实具有以下语义：

- 由同一次渠道配置自动推导、创建或校验，不要求管理员维护第二张手工映射表；
- 独立于当前在线渠道集合存在，禁用、熔断、删除最后一条渠道或重建缓存都不能让已发布产品失去身份；
- 新渠道只能加入同一 SKU 的履约集合；改绑到另一 SKU 必须显式确认、版本化并审计；
- “已经发布”和“当前可履约”是两个事实；零候选表示暂不可履约，不等于合同不存在；
- 同一命名空间、路由族和客户模型下，不允许 Link 与普通 NEWAPI 候选混用；若发生冲突，应拒绝 Link
  发布，不能收紧或改变普通渠道自身的原生语义；
- 不以自动分组、Affinity、优先级、权重、重试结果或渠道健康状态决定产品身份。

本文只确定这一逻辑事实及其不变量，不预先决定必须新建同名数据库表。物理载体可以是 Link 自有对象、
受约束的既有持久元数据或经证明能跨 Ability 生命周期存在的扩展；仅缓存或当前候选派生索引不能成为
权威来源。

### 3.4 Link SKU 能力合同

**定义：** 一个公开 Link SKU 向客户承诺的、版本化且可校验的模型能力。

**主要内容：**

- 字段、类型、值域、默认值和枚举；
- 分辨率、时长、质量、媒体组合等模型能力；
- 是否支持 Link 资源；
- 素材类型、数量、角色、组合和授权限制；
- 与任务、计费相关的能力维度。

例如：

```text
seedance-2.0-standard-720p
seedance-2.0-value-720p
```

Link SKU 是平台内部的标准能力身份，不等于客户自定义模型名，也不等于 Provider 实际模型名。这里的
“公开”表示它是已注册、可向客户承诺的公共能力，而不要求客户调用时使用 SKU 字符串。一个 SKU 只能
有一份客户可见能力合同；多个客户模型可以发布到同一 SKU，多个 Provider 实现只有在完整履行同一
能力时，才可以成为该 SKU 的等价渠道。

### 3.5 Link 资源合同

**定义：** 平台对虚拟素材身份、所有权、授权、绑定、解析和生命周期的稳定合同。

客户通过 `/v1/assets` 获得 `ast_*`，随后使用 `asset://ast_*`；客户不需要知道最终 Provider 使用
上游素材 ID 还是受保护 HTTPS URL。

**范围内：**

- `Asset`、`AssetSource`、`AssetBinding` 的平台语义；
- 所有权、App 隔离、真人授权和状态；
- `upstream_binding` 与 `source_url` 两种内部解析路径；
- 候选渠道的素材可解析资格。

**范围外：**

- 平台永久存储媒体二进制；
- 把 Provider 素材 API 原样暴露给客户；
- 承诺每个资源在所有 Provider 和所有时间点都可用；
- 根据 `asset_upstream_profile=none` 直接推断不支持 `asset://`。

Link 资源合同是 Link 服务合同的客户可见子合同；Provider 如何消费素材属于素材上游合同。

### 3.6 任务与计费合同

**定义：** 同步或异步任务从创建到终态，以及预扣、结算、退费和对账所遵守的客户与资金语义。

**主要内容：**

- 创建、查询、取消和终态；
- 幂等、未知创建结果和重复任务边界；
- 预扣、结算、差额、退费和异常审计；
- Task 与 create attempt 必须冻结的合同和执行事实。

客户价格继续依据客户模型名和现有价格体系配置。Provider 成本、渠道权重和价格差异不能在运行时
改变同一个客户模型已经发布的客户计费语义。

### 3.7 上游调用合同（南向合同）

**定义：** Link 网关为履行客户承诺，调用 Provider、反代或中转时遵守的内部执行合同。

**主要内容：**

- Provider 和渠道类型；
- 上游鉴权、路径与请求转换；
- Provider 模型映射；
- Provider 响应、错误和任务状态归一化；
- 视频和素材的具体调用协议；
- converter、profile、adapter 及其版本要求。

“南向”表示“网关到 Provider”的调用方向。上游调用合同对应现有架构中的“渠道适配协议”；新名称
强调它是一组必须整体一致、能够被验证的执行约束，而不是让管理员自由拼装的零散字段。

#### 3.7.1 视频上游合同

定义视频任务如何在一个 Provider 上创建、查询、取消和取得结果，包括：

- 创建、查询和取消路径；
- 请求字段和媒体数组转换；
- Provider 模型字段；
- 上游任务 ID、状态与错误映射；
- converter、video profile 和 adapter 版本。

视频上游合同不定义客户公开 SKU 的能力；它只能证明某个实现如何完整履行该能力。

#### 3.7.2 素材上游合同

定义 `asset://` 如何在一个 Provider 实现上被解析和发送，包括：

- 是否有 Provider 托管素材生命周期；
- 创建、查询、删除上游素材的协议；
- `upstream_binding`、`source_url` 或两者并存；
- 凭据作用域、最小 URL TTL 和支持的媒体类型；
- Resolver 与 converter 的职责边界。

素材上游合同为 `none` 只表示没有独立的 Provider 素材 API；若实现允许 `source_url`，仍可完整履行
支持 `asset://` 的 Link SKU。

## 4. 合同之外的实现与配置概念

### 4.1 Link 实现

**定义：** 由代码显式注册、以 `link_implementation_id + version` 标识的某个 Provider 对一组 Link
SKU 的具体实现声明。

Link 实现绑定：

- 一个明确的 Provider 与渠道类型；
- 视频上游合同；
- 素材上游合同和解析模式；
- profile、converter、adapter、路径和任务接线；
- 实现支持的 Link SKU；
- implementation execution binding（实现执行绑定）。

Link 实现是技术和审计身份，不是客户模型，也不是管理员临时组合出来的合同。改变实现执行绑定、素材
机制、路径或其它执行语义时，必须遵守实现版本和内容哈希约束。

### 4.2 Link 接入方案

**定义：** 管理端对一个精确 Link 实现的可选择、可理解投影。

例如：

```text
飞彩 · Seedance Videos v1
feicai.seedance-videos/v1
```

管理员选择一次 Link 接入方案，系统即可确定 Provider、视频上游合同、素材上游合同、解析模式、
路径、Adapter 和实现执行绑定。

Link 接入方案不是新的合同身份，也不建立与 `LinkImplementation` 平行的持久化事实。它解决的是
管理端“如何一次选定一套完整实现”的问题。

### 4.3 渠道实例

**定义：** 运维人员实际创建和管理的一条可执行上游连接。

渠道实例负责：

- 选择一个精确 Link 接入方案；
- Base URL、API Key、AK/SK、Region、Project 等账号和连接信息；
- 客户模型列表及 `model_mapping`；
- 客户价格、分组、优先级、权重、状态和并发等运营属性。

渠道实例不负责重新定义 Link SKU、视频上游合同或素材上游合同。选择接入方案以后，这些结构字段
只能由方案派生并只读展示。

### 4.4 实现执行绑定

**定义：** Link 实现内部登记的、用于证明某套 Provider 执行配置完整履行哪个 Link SKU 的版本化规则。

最简单的实现可以是：

```text
(implementation ID/version, route_family, Provider 模型)
  -> Link SKU
```

但 Provider 模型不是普适的唯一判别维度。对视频、图片编辑或多动作 Provider，执行绑定还可以显式包含：

- endpoint / route family；
- action 或 task kind；
- Provider profile、converter 或协议形状；
- 固定的素材角色和请求形态；
- 由接入方案锁定的分辨率、质量或其它产品维度。

例如：

```text
(feicai.seedance-videos/v1, openai_video, create,
 seedance-2.0-vip-720p-azhw)
  -> seedance-2.0-standard-720p
```

所有决定 SKU 的维度必须在发布时已经固定并能唯一解析。不得让一次请求中的可变字段临时选择另一个
SKU；如果同一个 Provider 模型在同一固定执行形状下仍可对应多个 SKU，就必须补充显式实现维度、拆分
接入方案/Provider 模型别名，或拒绝发布，不能任取一个结果。

实现执行绑定由代码注册和版本化，不由管理员维护第二张合同映射表，也不能按字符串相似度、Base URL
或 Provider 名称推断。原“Provider 模型目录”只是实现执行绑定在简单场景下的一种投影，不再作为普适
合同概念。

### 4.5 三种模型身份

| 身份 | 示例 | 权威用途 | 客户是否可见 |
| --- | --- | --- | --- |
| 客户模型名 | `sd-standard` | 模型发现、Token 权限、客户价格、Ability、日志和响应 | 可见且可自定义 |
| Link SKU | `seedance-2.0-standard-720p` | 能力、素材、合同等价、计费维度和审计 | 通常内部使用 |
| Provider 模型 | `seedance-2.0-vip-720p-azhw` | 发送 Provider、参与实现执行绑定复检 | 不向普通客户公开 |

三者通过以下链路协作：

```text
发布时：
  客户模型名
    -> 渠道 model_mapping
    -> Provider 模型
    -> 所选 Link 实现的 execution binding
    -> 唯一 Link SKU
    -> 创建或校验客户模型发布事实

请求时：
  contract_namespace + route_family + 客户模型名
    -> 客户模型发布事实
    -> 冻结 Link SKU
    -> NEWAPI 正常选渠
    -> 渠道 model_mapping 得到 Provider 模型
    -> 所选实现 execution binding 复检仍为同一 SKU
```

## 5. 概念范围矩阵

| 概念 | 客户承诺 | Provider 细节 | 管理员选择 | 管理员编辑 | 代码注册 | 运行时冻结 |
| --- | --- | --- | --- | --- | --- | --- |
| Link 服务合同 | 是 | 含内部履行边界 | 否 | 否 | 是 | 通过子合同冻结 |
| 客户接入合同 | 是 | 否 | 否 | 否 | 是 | 是 |
| 客户模型发布事实 | 是，表达客户模型对应的产品 | 否 | 由渠道配置自动形成 | 否 | SKU 与路由族由代码注册 | 是 |
| Link SKU 能力合同 | 是 | 否 | 否 | 否 | 是 | 是 |
| Link 资源合同 | 是 | 隐藏实现差异 | 否 | 否 | 是 | Asset/Binding 冻结 |
| 任务与计费合同 | 是 | 隐藏实现差异 | 否 | 价格另行配置 | 是 | 是 |
| 上游调用合同 | 否 | 是 | 通过接入方案间接选择 | 否 | 是 | 是 |
| Link 实现 | 否 | 是 | 通过接入方案选择 | 否 | 是 | 是 |
| Link 接入方案 | 否 | 展示摘要 | 是 | 否 | 由实现投影 | 冻结对应实现 |
| 渠道实例 | 否 | 是 | 不适用 | 是 | 否 | 冻结渠道事实 |
| 实现执行绑定 | 否 | 是 | 否 | 否 | 是 | 是 |

## 6. 协作关系

### 6.1 配置阶段

```text
管理员选择 Link 接入方案
  -> 系统锁定 Link 实现
  -> 自动带出 Provider、视频上游合同、素材上游合同和实现执行绑定摘要

管理员填写客户模型与 model_mapping
  -> 客户模型解析为 Provider 模型
  -> 固定执行维度在 implementation execution binding 中唯一解析 Link SKU
  -> 系统校验该实现完整履行 SKU 能力和 Link 资源要求
  -> 原子创建或校验客户模型发布事实
```

管理员不重复配置“客户模型到 Link SKU”，也不自由拼装视频与素材合同。若执行绑定不能从接入方案、
路由族和 Provider 模型等固定维度唯一得到 SKU，系统必须拒绝发布；不得在请求时动态猜测产品档位。

### 6.2 Ability 发布阶段

Ability 仍以客户模型名参与 NEWAPI 分发，但发布前必须先创建或读取权威客户模型发布事实，再校验本
渠道的派生执行事实：

```text
客户模型发布事实：
  contract namespace / route family / 客户模型名 / Link SKU / publication version

渠道派生执行事实：
  Provider 模型 / implementation ID/version/content hash / execution binding
```

同一合同命名空间和路由族内，同一个客户模型的所有 Link 候选渠道必须解析到发布事实中的同一个 Link
SKU。普通 NEWAPI 候选若会与其进入同一次选渠，也视为冲突并拒绝 Link 发布。当前候选只能证明渠道
是否有资格履约，不能创建或改变客户模型的合同身份。

### 6.3 请求执行阶段

```text
客户按客户接入合同发起请求
  -> 按命名空间、路由族和客户模型读取发布事实并冻结 Link SKU
  -> 按 Link SKU 校验公开字段、值域、素材和计费维度
  -> Link 资源约束排除无法解析本次 Asset 的既有渠道
  -> NEWAPI 在剩余已配置渠道中按现有规则选渠
  -> 应用选中渠道 model_mapping 得到 Provider 模型
  -> 使用实现 execution binding 复检实际执行仍履行冻结 SKU
  -> 按客户接入、任务与计费合同归一结果
```

这里不存在 Link 自动寻找 Provider：Provider 已由各渠道的 Link 接入方案固定；运行时只是 NEWAPI
在管理员已经配置的等价渠道中选择一个。无合格候选时，系统依据仍然存在的发布事实返回稳定的“SKU
暂不可履约”，而不是把模型解释为从未发布，也不降级到普通 NEWAPI 候选。

### 6.4 素材协作

Link SKU 能力合同先决定客户能否提交 `asset://` 以及数量、类型和组合限制；素材上游合同再决定
选中实现如何解析这些资源。

实现能力必须完整覆盖 SKU 公开素材合同：

```text
implementation_asset_capability ⊇ sku_asset_capability
```

不得在运行时对两者取交集后静默缩小客户能力。如果无法完整覆盖，应排除该实现或拆分 SKU。

### 6.5 Task、计费与审计协作

Task 与 create attempt 至少冻结：

- 客户接入合同版本；
- 客户合同命名空间、路由族、客户模型名、发布版本与 Link SKU；
- Provider 模型；
- 渠道 ID；
- implementation ID/version/content hash；
- 视频与素材上游执行快照；
- 计费快照。

普通客户只看到客户模型名和客户合同结果；管理员审计可以看到 Link SKU、实现、Provider 模型、
渠道以及视频和素材执行方式。

## 7. 名词替换与使用规则

| 原讨论名称 | 统一名称 | 原因 |
| --- | --- | --- |
| Link 总合同 | Link 服务合同 | 强调完整服务承诺，避免把它理解为配置对象 |
| 客户 API 合同 | 客户接入合同（北向合同） | 更直接描述客户如何接入；`contract_id` 等代码名暂不强制改名 |
| Link 模型合同 SKU | Link SKU 能力合同 / Link SKU | 避免把模型名、SKU 和合同重复叠加 |
| 客户模型到 SKU 的派生关系 | 客户模型发布事实 | 强调它是系统发布结果，不是管理员第二张映射表 |
| 渠道适配协议 | 上游调用合同（南向合同） | 面向跨角色沟通；代码层仍可使用 profile/adapter 等既有术语 |
| 视频上游协议 | 视频上游合同 | 表达路径、转换、任务和错误的完整约束，不只是报文协议 |
| 素材上游协议 | 素材上游合同 | 同时覆盖 binding、source URL、凭据作用域和生命周期 |
| Link 渠道合同 | Link 接入方案 | 它是 Link 实现的管理端投影，不是新的公开合同 |
| Provider 模型目录 | 实现执行绑定 | Provider 模型只是判别维度之一，不能概括路径、action 和 profile 等执行事实 |

使用规则：

1. “合同”描述稳定语义和必须满足的约束；
2. “实现”描述代码注册的 Provider 实现身份；
3. “方案”描述管理端一次选择的一整套实现；
4. “渠道”描述带凭据、价格和运营属性的实例；
5. “映射”只描述客户模型到 Provider 模型；实现执行配置到 Link SKU 属于代码注册的 execution binding；
6. “北向/南向”只作为方向别名，不单独建立另一套合同层级。

## 8. 不变量

1. 客户模型名可以自定义，不能依赖名称识别 Link 身份；
2. 客户模型一旦发布为 Link 产品，必须在命名空间和路由族内稳定指向一个 Link SKU；
3. 发布事实独立于当前候选存在，禁用或删除最后一条渠道不能让客户模型静默改义；
4. 改绑 SKU 必须显式确认、提升发布版本并审计；
5. 一个 Link SKU 只有一份客户可见能力合同；
6. 一个 Link SKU 可以有多个完整等价的 Link 实现；
7. execution binding 只在精确 implementation ID/version 和已声明执行维度内解析；
8. 选择 Link 接入方案后，不再独立配置 Provider、视频或素材上游合同；
9. 素材实现能力必须完整覆盖 SKU 能力，不能静默取交集；
10. NEWAPI 负责既有渠道分发，Link 不增加 Provider 自动选择；
11. 同一命名空间、路由族和客户模型下禁止 Link 与普通候选混用；冲突时拒绝 Link 发布，不改变普通
    NEWAPI 渠道的原生语义；
12. 客户价格、渠道成本、凭据和权重属于渠道运营配置，不属于 Link SKU；
13. 任务必须冻结客户、发布版本、SKU、实现、渠道、Provider 模型、素材和计费事实；
14. 普通客户不需要知道 Provider、Provider 模型、实现 ID、路径或上游素材 ID；
15. 客户模型发布事实的物理载体必须按最小入侵原则比较，不能以仅缓存的派生结果冒充合同权威。

## 9. 本次实施收敛

本次实现采用独立 `LinkModelPublication` 与不可变 audit 表作为客户模型发布事实载体，并将决定并入
[ADR-0015](../20-architecture/decisions/0015-Link服务合同发布与实现身份绑定.md)，不新增重复 ADR。
选择独立小表的原因是：它能在零候选、删除最后一条 Ability、服务重启和缓存重建后继续表达合同，
同时避免把多渠道权威、版本竞争和审计字段扩散进上游高冲突面的 Channel 或 Ability。

管理端概念已收敛为“Link 接入方案”：方案精确选择一个 implementation；客户模型和 Provider 模型
仍由既有 `models`、`model_mapping` 表达；Link SKU 由代码注册的多维 execution binding 推导。客户
模型发布、显式改绑、运行时冻结、发送前复检以及 Task/attempt/Asset/AssetBinding/ProviderCostExposure
快照均使用同一组 namespace、route family、customer model、Link SKU 和 publication version 身份。

SQLite、MySQL 8 与 PostgreSQL 17 的 disposable 实例已完成 publication、显式重绑、audit 以及
Task/attempt/Asset/AssetBinding/ProviderCostExposure 快照往返验证。当前文档继续保留在 `80-dev`，
因为真实 Provider、生产价格与账单和灰度黑盒验收不是本地代码实现可以替代的事实；完成这些外部门禁
后再按维护规范归档。
