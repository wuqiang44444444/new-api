# 客户账单结算金额与流水展示修复方案

## 问题与目标

客户列表把 gross_quota 标为“实付消费”，将累计预扣/扣减流水与扣除退回后的结算原价并列，
用户无法理解“原价低于退款、实付高于原价”。目标是让最终费用和资金流水各自可对照，保持所有
后端金额、余额与历史记录不变。

## 当前实际情况

本地 SQLite 只读查询复现 randy（用户 91）2026-09-01 至 09-10 北京时间的截图；列表和单客户
详情查询完全相同，共 12,313 次请求：

| 字段 | quota | 美元 | 含义 |
| --- | ---: | ---: | --- |
| original_quota | 956,064,294 | 1,912.128588 | 扣除退回对应原价后的折前净金额 |
| discount_quota | 124,288,358 | 248.576716 | 折前净金额与结算净额之差 |
| net_quota | 831,775,936 | 1,663.551872 | 本账期消费减退款的结算净额 |
| gross_quota | 1,827,905,721 | 3,655.811442 | 累计扣减，包含任务预扣和后续补扣 |
| refund_quota | 996,129,785 | 1,992.259570 | 累计退回，包含结算退差额与其他退款 |

两条等式同时成立：结算原价减优惠等于净结算金额；累计扣减减累计退回也等于净结算金额。
累计退回中 626 条带实际费用/预扣或 adjustment 事件的结算调整合计 1,807.680030 美元，
其余 81 条退回合计 184.579540 美元。不能把全部退回解读成失败请求退款或现金退款。

数据质量 partial 来自 370 条 unknown_billing_mode 记录；UnavailableRequests、
MissingHistoricalPriceRows 与 ProviderModelFallbackRows 均为 0。因此这个标记不表示本行金额
缺失，也不证明全部历史日志已经逐任务校验完整。未调用真实 Provider，未做外部账单验收。

## 优化方案

- 列表与详情将 original_quota 命名为“结算原价”；列表首先排列结算原价、优惠、净结算金额。
- gross_quota 改名“累计扣减”，refund_quota 改名“累计退回”，放在最终费用之后，增加可见说明
  与两条对照等式。前端仅格式化后端字段，不计算新的费用或替换金额。
- 部分数据行在已有质量徽标下显示缺少计费方式的记录数量，保留其他质量状态与未知金额展示。
- 复用已有 Card、Table、Badge 与排序/分页/下钻入口，不新增状态、组件框架或金额接口；调整可见
  文案时补齐七种语言。专项 UX 检索未取得直接匹配规则，此处按通用的信息分组原则调整现有界面。
- 使用截图对应的真实汇总数据建立前端回归，先确认旧字段命名与排列失败，再验证修复后的金额对应、
  中文文案、未知价格、排序与下钻。执行账单模块测试、typecheck、涉及文件 lint 和文档校验。
