# Seedance 账单分类、计数与金额修复方案

## 问题与目标

客户账单把按输出 Token 计费的异步视频显示为按次计费；创建日志携带 task_id 后请求数被漏计，
累计预扣反推的折前金额又与结算净额并列，导致用户误认为少量请求产生巨额费用。
本次修复账单投影、日志分类及历史日志缺口，不改变价格、Provider 用量、Task 结算目标或客户资金。

## 当前实际情况

本地 SQLite 只读核查精确复现截图：相关模型有 293 个任务，287 个成功、6 个失败且最终零费用。
292 条创建日志中只有 40 条没有 task_id；聚合错误排除另 252 条。每笔预估 920,000 Token，
冻结单价每百万输出 Token 7 美元、分组倍率 0.87，每笔预扣 5.6028 美元。
累计预扣反推折前金额为 1,880.48 美元，日志净额为 291.290246 美元。

成功任务合计 48,750,864 输出 Token，逐笔复算与 Task quota 一致，最终合计 296.893046 美元。
一笔已完成且 hold 已转移的任务缺少初始消费日志，造成账单少计 5.6028 美元。
缺口事实已确认；当时日志写失败、进程中断或事后数据操作的具体原因未确认。
这些结论不是供应商账单验收或生产发布结论；不保存私有任务正文、凭据或上游原始响应。

## 优化方案

### 评审后补充修复范围

- 补日志取消基于前后 5 秒的归属判断；存在无法排除的无关联创建日志时拒绝新增。预览增加全范围
  Task 结算与日志金额、创建计数的完整性核对，无需预先指定缺失任务即可报告差额。
- 管理员跨客户汇总保留有符号十进制原价，到最终汇总才舍入和处理非负展示；汇总溢出返回未知。
- 原生用量表达式按创建时选定 adapter 的已声明计量单位冻结展示证据，Token 与秒/credit 不混用；
  历史缺少单位的 u() 表达式不读取当前插件配置来补猜。
- 增加延迟旧日志、范围不完整、资金事实不符、跨客户退款、舍入、溢出和冻结单位的回归测试，
  并重新对照当前数据库及修复前备份。此次不修改 Provider 计费公式或资金动作。

### 1. 分类与日志事件

- 从冻结表达式的实际 Token 依赖判定按 Token 计费，不能用异步任务身份推断按次。
- 新日志在表达式和合同折扣字段齐全后生成账单快照；创建、差额结算、失败退款有明确事件语义。
- 历史日志只利用已有表达式、用量、创建标记与结算字段，不读取当前模型价格或按模型名猜测。
- 请求数只计算创建事件；task_id 是关联标识，不是排除请求的依据。差额退回不算失败退款次数。

### 2. 金额口径

- gross_quota / refund_quota 保留消费与退款的期间流水口径，net_quota 保留两者差额。
- original_quota 改为期间净费用按各笔冻结折扣还原的折前金额，消费正计、退款负计；
  discount_quota 同步为 original_quota 减 net_quota。使用定点十进制汇总，避免逐笔取整累积误差。
- 管理员列表、单客户、API Key/渠道分组共用规则；缺少退款历史价格或存在不可还原附加费时返回未知。
- 跨期退款按日志发生账期入账，不追溯改写其他账期；退款超过消费的账期不展示虚构负优惠。
- 前端只格式化后端事实，更新“优惠”解释并补齐七种语言。

### 3. 历史修复与完整性

- 提供默认只读预览、显式应用的离线修复入口，限定用户、模型、API Key 和任务范围。
- 利用创建 attempt 的已转移 hold、Task 冻结表达式与结算日志核对缺口；证据冲突或不完整必须拒绝。
- 只修正账单日志元数据并补写确定缺失的消费日志，保留原始业务时间和审计说明；重复执行不重复写入。
- 不调用预扣、结算、退款或用户统计变更函数，不用日志缺口驱动资金动作。
- 修复前备份，先在副本验证，应用后再对照 Task 最终金额、日志净额和 API 汇总。
- 日志数据库与资金事务独立的事实不被掩盖；补充完整性校验与可重跑修复，而不是把日志查询变成资金入口。

### 4. 最小入侵与验证

- 主要修改本地账单聚合与快照文件；独立新增事件判定、历史修复和回归测试文件。
- service/task_billing.go 属于与原生任务共享的接线点，只调整快照生成位置及事件字段；不重构资金热路径。
- 不新增 Provider、渠道、计费账本或表达式执行器，不修改 relaykit 公共 API。
- 回归覆盖：带任务 ID 的创建、Token 表达式误分类、多退少补、失败退款、不同折扣、跨期退款、
  缺失价格、重复修复、资金不变、管理员列表与详情一致。
- 执行相关 Go 测试与 vet、前端相关测试/typecheck/lint，以及 task docs:check、task ai:check。
- 外部 MySQL/PostgreSQL、真实供应商账单及生产灰度若未执行，必须列为未验证，不能写成通过。

## 实施与验证记录

### 已完成代码

- `model/billing_statement_task_facts.go`：复用表达式编译器识别 Token 依赖；非 Token 单位的表达式保持
  unknown，不把秒、credit 或未知表达式冒充按次/Token。u() 使用创建时冻结的 UsageUnits；仅计量
  Token 并使用已声明 enum/boolean 条件时显示 token，动态字段或缺失单位保持 unknown。解析创建、
  差额与失败退款事实。
- `model/billing_reconciliation.go`、`model/billing_customer_statement_list.go`：修复请求计数与折前净额；
  消费和退款先按各自冻结折扣进行定点累计，跨模型/分组保留有符号中间值，最后舍入展示，防止先把
  单模型退款截为零而夸大父级优惠。非有限倍率和超出 int64 的展示合计返回未知。
- `service/billing_statement_snapshot.go`、`service/task_billing.go`、`service/task_billing_state.go`：
  新日志冻结实际表达式分类及合同折扣；创建与退款事件明确标识。原生共享任务文件仅增加必要接线，
  未来同步冲突面限定在日志构造，不改变资金、任务状态机或上游协议。
- `cmd/repair-task-billing-logs/`：默认只读预览；必须显式指定用户、API Key、模型、最长 31 天范围及
  在申请补入初始日志时指定内部任务行号。完整性预览不要求预先知道缺失任务。应用前创建权限 0600
  的新备份，持有 SQLite immediate 事务再读取并
  验证事实；元数据使用旧值条件更新。无法确认唯一已转移 hold、冻结用量不符、合同需要专项处理、
  存在可能匹配的无关联创建日志、跨期证据或并发冲突时拒绝并回滚。仅支持 SQLite 主库与日志同库。
- 前端保留现有组件、数据查询及渲染机制；只把优惠说明改成“原价金额减去结算净额”，通过规定的
  脚本添加七种语言并运行 i18n:sync。

### 评审后修复与实际复核

- 删除 5 秒时间窗口及重复的跨期查询；工具读取同用户、Key、模型的完整消费/退款历史，写入仍严格
  限定所选账期。存在同渠道、无法排除归属的无关联创建日志时拒绝新增，不扩大时间阈值或猜关联。
- `integrity.go` 比较 Task 冻结结算、日志净额、创建计数和已关联任务各自的净额。`matched` 表示逐任务
  核对相符；旧日志无法关联但总量一致时仅报 `aggregate_matched` 并列出无关联数量；差额/计数异常报
  `mismatch`，未结算、跨期或范围事实不完整报 `incomplete`。后两种状态使只读 CLI 非零退出，应用时
  拒绝并回滚全部改动。不指定缺失任务也能发现差额，不自动猜测或补写候选任务。
- 跨客户汇总与详情共用有符号十进制折前事实，分页与筛选保持原合同；总计舍入和 int64 溢出处理
  与详情一致。不存在先对子客户退款截零而虚增父级优惠的路径。
- 在原生 `relay/relay_task.go` 的任务用量快照创建之后保留一行单位冻结接线；具体 adapter 只读单位
  投影与捕获逻辑分别隔离在新增文件。`pkg/billingexpr/types.go` 仅增加可序列化的可选单位字段，
  `service/task_billing.go` 仅增加创建/调整日志的单位复制。上述原生改动必要性是单位必须在选定 adapter
  尚在请求上下文时冻结，未来上游同步的冲突点限于该快照构造和日志构造；不改变计价或资金流程。
