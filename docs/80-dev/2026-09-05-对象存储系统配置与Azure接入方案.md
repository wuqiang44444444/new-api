# 对象存储系统配置与 Azure 接入方案

## 问题与目标

生产环境在 Azure HK、US，本地开发也需要直接访问对象存储。用户要求按 S3 类似的
Endpoint、容器与静态凭据方式接入，不安装 Azure CLI，不依赖托管身份或云端登录。
新增系统设置用于维护存储连接，业务通过统一存储接口调用，Azure 的协议差异由 adapter 吸收。

本文件是待实施方案及本次外部验证记录，不代表系统配置页面或 Azure adapter 已实现。
本次不修改应用代码、不写入环境文件、不持久化用户提供的密钥或完整连接字符串。

## 当前实际情况

### 已检查的本地代码

- `setting/system_setting/task_artifact_store.go` 目前只接受 `upstream`、`s3`，读取启动环境变量。
- `service/task_artifact_store.go` 在包初始化期间构造全局存储实例，不具备数据库设置动态装载能力。
- `service/task_artifact_store_s3.go` 实现 S3 path-style 与 SigV4；图片上传、HEAD 和签名操作直接
  断言具体 S3 类型，新增 Azure 实现仅实现旧 TaskArtifactStore 接口还不够。
- `controller/option.go` 的普通设置读取依赖名称后缀过滤敏感字段，不能把含凭据的连接字符串或
  JSON 直接当作普通可返回设置。
- `model/option.go` 有批量事务保存入口，但数据库事务不等于多进程缓存同步，也不能直接保证
  内存中多个字段更新时读者始终看到完整配置。
- 当前架构将 Azure Blob 的 S3 网关作为部署目标描述，原生 Azure Blob 支持仍需单独实现。

相关当前事实：[图片服务与异步 Provider 适配架构](../20-architecture/图片服务与异步Provider适配架构.md)、
[硬约束](../00-context/硬约束.md)。当前工作区存在其他任务的未提交修改，本次只新增本文件。

  两者是同一凭据的不同表达，不需要同时配置。

## 优化方案

### 1. 系统配置界面

在既有系统设置中增加「对象存储」区块，复用现有布局、表单、国际化和错误提示。
不新增独立存储管理平台，不建立多存储池、自动选路或故障切换。

| 字段 | 行为 |
| --- | --- |
| 存储类型 | 不启用对象存储 / S3 兼容 / Azure Blob |
| Bucket / Container | 对应存储类型的必填容器名；配置页不自动创建业务容器 |
| Azure 连接信息 | 默认粘贴连接字符串；可切换手动填写 Account Name、Account Key、Endpoint |
| S3 连接信息 | Endpoint、Region、Access Key、Secret Key，保留既有 path-style 语义 |
| 对象前缀 | 高级配置，统一应用于上传及对象引用；空值合法，不重复拼接 |
| 验证状态 | 未验证 / 最近测试通过 / 最近测试失败，显示时间，不承诺持续可用 |

Azure 连接字符串仅作为输入格式，解析为唯一标准化配置，展示脱敏账号与端点，不重复保存
原始连接字符串。按首个等号拆分属性，保留 Base64 Key 尾部等号；拒绝冲突重复属性及当前不支持
的鉴权方式，不能静默解释为另一个账号。第一版仅支持 Shared Key，不引入 CLI、SAS 凭据输入或
托管身份选择。含自定义 BlobEndpoint 时显式解析，不能忽略后改用默认端点。

图片结果签名有效期继续固定为现有 300 秒；不增加改变公开合同的可调 TTL。
旧 TaskArtifactStore 其他消费者已有 TTL 语义分别保留，不强制改为图片值。

### 2. 测试与保存

- 「测试连接」测试当前表单值，不替换在线配置；密钥未修改时可由后端使用已有密钥。
- 在指定容器下创建随机测试对象，验证 PUT、HEAD、GET 内容一致、短期签名 GET 和删除。
  PUT 使用仅在对象不存在时创建的条件，避免覆盖；只清理本次创建的对象，不操作客户文件。
- 临时对象清理失败单独提示，不能伪装测试全部成功；不回显签名 URL、Authorization 或上游正文。
- 测试请求限定最高管理员、限定目标与请求大小、设置超时，不向重定向地址转发凭据。
- 「保存并启用」对同一完整配置做校验与验证，通过后原子保存；表单变化后不能复用旧测试结论。
  测试失败保留既有有效配置。保存与实际网络可用性没有永久保证，运行期仍须明确处理失败。
- 显式关闭对象存储需检查待执行任务依赖；不把关闭动作默认为删除远端文件。

### 3. 数据与凭据

通过专用最高管理员接口读写本地扩展设置，普通选项接口不能读取或绕过校验写入该命名空间。
可沿用既有 Option 持久化底座，但不将明文凭据放入通用可读 OptionMap。

| 标准化数据 | 说明 |
| --- | --- |
| backend | upstream / s3 / azure_blob；upstream 表示沿用现有未启用存储行为 |
| endpoint、bucket、prefix | 存储位置；Azure bucket 对应 Container |
| region | 仅 S3 使用 |
| account_name / access_key | 由明确 backend 决定含义，不推断协议 |
| credential_ciphertext | 加密的 Azure Account Key 或 S3 Secret Key |
| revision | 用于完整配置更新和多节点缓存刷新，不建立多套运行合同 |

密钥字段只接受更新，读取返回 credential_configured 状态；空白表示保持原值，显式操作才允许
清除。客户端显示「已配置」，掩码不是密钥值。审计只记操作者、时间和变更字段，不记秘密值。
加密使用部署侧稳定主密钥，主密钥不与数据库密文存于同一事实表，HK、US 节点需要一致的解密
能力。实现前审查现有 secret envelope 的密钥来源与轮换语义，不直接复用短期凭据方案冒充
长期密钥管理。该基础配置与云厂商无关。

### 4. 配置来源和生效

系统配置数据库作为唯一持久事实。既有 S3 环境变量提供一次性、显式导入流程：导入预览不显示
密钥，验证后写入数据库；导入完成后旧变量不能继续覆盖数据库或作为失败 fallback。
没有数据库配置时保持现有未启用状态，并向旧部署明确提示导入步骤，避免无提示切换配置源。

在数据库就绪后初始化存储，替代依赖包 init 的装载方式。以完整不可变配置快照构造客户端，
一次操作期间持有同一个实例，上传位置和后续签名不能在半更新状态混用。
HK、US 通过持久 revision 检查刷新客户端，缓存可重建；不能只更新提交配置的那个进程。
涉及存储位置的切换需在维护窗口完成，暂停新受理并确认各节点就绪，不能把进程内原子替换
误写成跨区域瞬时同步。

### 5. 统一存储接口与任务边界

保留现有 TaskArtifactStore 消费者，在本地扩展文件建立图片所需的最小读写、HEAD 与签名能力接口，
去除图片业务对具体 s3ArtifactStore 的断言。Azure adapter 使用官方 Go SDK azblob 的 Shared Key
及 service SAS；业务不关心 SDK 和签名差异，不手写第二套业务流程。

保持 HEAD 404 为 deleted，权限或网络等失败为 unavailable。签名链接仅在授权后当次返回，
不持久化。私有输入和任务仍遵循 user_id + app_id 隔离，不能直接根据调用方传入任意 object key
签名。存储不可用时拒绝依赖持久化的新异步请求，不自动换存储、换渠道或退款。

本地专属实现与路由、设置、测试优先新增文件；现有文件仅做必要接线，记录原生文件改动必要性
和上游同步冲突面。relaykit 不引入主模块依赖。

### 6. 更换配置与历史文件

同一账号和容器下轮换密钥，经测试后更新；不保存第二份备用 Key，不自动尝试旧凭据。
旧 Key 已签发的 SAS 可能在 Azure 撤销该 Key 后失效，不能承诺自动续用。

账号、端点、容器、对象前缀及 backend 都属于存储位置边界。第一版有未完成任务或仍须交付的
历史对象依赖时禁止直接更换；需完成显式迁移并验证对象可达后，在维护窗口切换。
实现时必须核对哪些对象引用已保存完整 key、哪些仍依赖当前 prefix，不能用更新设置重新解释
历史引用。不建立后台自动迁移、多配置路由或跨存储探测。

### 7. 实施与验收

1. 标准化配置、专用管理员接口、秘密存储、原子保存与多节点生效。
2. 存储能力接口与 Azure Shared Key adapter，保留既有 S3 行为。
3. 系统设置区块、字段级校验、测试反馈、七种语言翻译。
4. 覆盖连接字符串解析、密钥不回显、不完整配置不生效、授权边界、清理失败和存储错误语义。
5. 用真实私有容器验证上传、内容读取、签名读取、无签名拒绝和测试对象清理。
6. 验证配置持久化的 SQLite/MySQL/PostgreSQL 兼容性，HK、US 和本地分别验证；真实账单、
   跨区域延迟、生命周期策略及生产灰度单独记录，不能用此次小文件测试替代。
7. 文档变更运行 task docs:check、task ai:check；后续涉及公开 API 文档再运行 docs:validate。

### 实测结果

| 操作 | 请求形状 | 结果 |
| --- | --- | --- |
| 容器存在性 | HEAD /task-artifacts?restype=container | HTTP 200 |
| 上传 | PUT /task-artifacts/codex-connectivity-check/<随机值>.txt，BlockBlob，If-None-Match: * | HTTP 201 |
| 对象属性 | HEAD 同一测试对象 | HTTP 200，Content-Length 与测试内容一致 |
| 鉴权读取 | GET 同一测试对象，Shared Key | HTTP 200，返回字节与上传内容完全一致 |
| 签名下载 | GET 同一测试对象，短期只读 service SAS，无 Authorization header | HTTP 200，返回字节一致 |
| 匿名读取 | GET 同一测试对象，无签名、无 Authorization | HTTP 409，PublicAccessNotPermitted，拒绝匿名访问 |
| 清理 | DELETE 同一测试对象 | HTTP 202 |
| 清理后确认 | HEAD 已删除测试对象 | HTTP 404，BlobNotFound |

首次受限执行环境在 HTTP 请求前遇到本地网络错误，不作为 Azure 鉴权失败。允许网络后第一次
完整运行的读写及 SAS 已通过，匿名请求 409 未在测试程序初始预期状态集合内，导致当轮总体
标记失败；该轮测试对象仍已删除并经 HEAD 404 确认。随后仅补充解析脱敏 Azure 错误码，并重新
验证完整流程，确认 409 是 PublicAccessNotPermitted，全部检查通过。两轮均只使用各自的新对象，
没有覆盖或删除已有文件。

结论：用户提供的账号连接信息和 Account Key 在本地真实环境中可用于该容器读写及签名下载；
当前账号禁止匿名读取。对象已逻辑删除且不能经 HEAD 访问；未检查账号软删除保留策略，不能
把 HEAD 404 解释为底层数据立即物理清除。

尚未验证：HK、US 节点网络、应用内 Azure adapter、系统设置保存与多节点刷新、大文件、性能、
外部客户下载路径、密钥轮换、生命周期、生产灰度及真实账单。验证脚本只用于此次外部连接验证，
不是新增的生产实现或仓库回归测试。

### 预签名专项补充验证（2026-09-05）

用户追加要求验证预签名能力。本地对同一容器中新建的独立随机测试对象完成以下真实请求；
除初始建文件与清理使用 Shared Key 外，SAS 操作均无 Authorization header，仅携带签名查询参数。
所有签名只保存在测试进程内存。正常 SAS 限定单个 Blob、HTTPS、约 300 秒有效期。

| 场景 | 结果 |
| --- | --- |
| 只读 SAS GET 下载 | HTTP 200，内容逐字节一致 |
| 只读 SAS HEAD | HTTP 200 |
| 篡改 SAS 签名 | HTTP 403，AuthenticationFailed |
| 正确签名但有效期已结束的 SAS | HTTP 403，AuthenticationFailed |
| 用只读 SAS PUT 覆盖本次测试对象 | HTTP 403，AuthorizationPermissionMismatch；再次 GET 确认原文未变 |
| 另签只写 SAS，PUT 本次测试对象 | HTTP 201；使用只读 SAS 读回后内容一致 |
| 用只写 SAS GET | HTTP 403，AuthorizationPermissionMismatch |
| 无签名 GET | HTTP 409，PublicAccessNotPermitted |
| 删除本次测试对象并 HEAD 确认 | HTTP 202；随后 HTTP 404，BlobNotFound |

过期测试采用开始时间为签发时刻前 15 分钟、结束时间为前 10 分钟的有效签名，验证过期授权
被拒绝；没有等待一个 300 秒链接自然过期，不能将其写成已验证精确到期时刻行为。
上传测试是覆盖本次新建的测试对象，没有读取或修改既有客户文件。

结论：Azure service SAS 可以履行预签名下载和带写权限的预签名上传，单对象与读写权限限制
在此次实测中有效。当前产品方案仍是后端上传、客户获取只读短期链接；此次验证上传能力不等于
发布客户直传接口，也不修改现有 API 合同。HK、US 和浏览器 CORS 仍未验证。
