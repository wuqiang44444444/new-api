# Synlink 海外火山中转协议与托管素材接入分析

## 1. 问题与目标

分析[海外火同中转调用指南](../70-research/synlinkai/海外火同中转.md)，确定视频协议选择、
本站托管素材与直接 URL 的处理方式，以及现有渠道可以复用到哪一层。

用户明确提出的目标行为：素材创建发生在本站；视频请求引用本站 asset 时，由本站签发临时 URL；
直接提供媒体 URL 时保留 URL 交给供应商拉取。用户进一步要求分析能否复用当前渠道。

本文保留实施前的接入分析与建议；后续代码实施与验证见
[分阶段实施计划](../50-planning/2026-09-08-Synlink海外火山中转分阶段实施计划.md)。
本文及本地测试均不代表真实 Provider 验收或生产发布。

## 2. 当前实际情况

### 2.1 外部文档证据

供应商文档声明以下接口与行为，尚未由本次任务实测：

| 项目 | 文档内容 |
| --- | --- |
| 创建 | `POST /v1/video/generate` |
| 查询 | `GET /v1/video/tasks/{taskId}` |
| 尾帧 | `GET /v1/video/files/{taskId}/last-frame`，需要 Bearer 鉴权 |
| 请求 | ModelArk 风格的 `model`、`content`、`duration`、`resolution`、`ratio` 等字段 |
| 创建响应 | ID 位于 `task.id`，示例状态为 `pending` |
| 成功查询 | 示例状态为 `task.status=completed`，结果位于 `task.outputs[]` |
| 用量 | 成功示例提供 `task.usage.completion_tokens` 与 `total_tokens` |
| 输入素材 | 支持图片、视频、音频 URL；明确不能使用素材 ID；创建时自动拉取并预处理 |

文档列出四个模型：`doubao-seedance-2-0-260128`、`doubao-seedance-2-0-fast-260128`、
`doubao-seedance-2-0-mini-260615`、`doubao-seedance-2-5-260628`。
这只能证明文档声明的模型范围，不能据此推导各模型的时长、分辨率或媒体数量限制。

文档没有提供独立素材库 API。“与 FunCloud V3 一致”在本次需求中指本站托管产品行为一致，
不能解释为两个供应商的素材接口或视频协议相同。

### 2.2 已核对的项目代码与合同

- Seedance 使用 `ChannelTypeSeedanceLink`，客户北向固定为 ModelArk V3；创建入口为
  `POST /api/v3/contents/generations/tasks`。
- 视频南向由代码登记的 `video_upstream_protocol` 决定；当前没有 Synlink 协议。
- 北向任务列表读取本站 Task，不依赖供应商列表接口；DELETE 根据任务状态和冻结生命周期能力，
  分别处理取消排队任务与删除终态任务，不等同于直接隐藏本站记录。
- `funcloud_modelark_v3` 南向使用 `/api/v3/contents/generations/tasks`，创建只接受顶层 `id`，
  查询读取顶层状态与 `content.video_url`，不能直接解读 Synlink 的 `task` 包裹和 `outputs`。
- `funcloud_material_hosted` 已有本站素材记录、私有对象存储、归属校验和内部 URL 签发实现；
  当前仅允许配对 `funcloud_modelark_v3`，预扣前的托管引用校验也限定了该视频协议。
- 托管素材按 `user_id` 隔离，同账号所有 API Key 共享，不绑定创建时的 Channel 或上游账号。
  当前范围为普通图片，视频和音频仍通过直接 URL 引用。
- FunCloud V3 请求构建会添加 `real_person_mode=true`，参考视频还会添加
  `omni_reference_task_type=reference`；Synlink 文档没有声明这些私有字段。

## 3. 优化方案

### 3.1 视频协议选择

保留 ModelArk V3 北向与现有 Seedance 渠道类型，新增独立的 Synlink 南向 adapter。
协议名可暂定为 `synlink_video_v1`，最终命名在实施时确定；它目前不是可选的已登记协议。

adapter 负责固定创建与查询路径，读取 `task.id`，把已确认的状态转换为平台状态，
校验任务 ID 与结果，并归一 `task.usage`。`pending` 与 `completed` 可分别映射到排队与成功，
其它状态必须取得证据后登记，不能从相似供应商推断。

尾帧南向路径已有文档依据，可由 adapter 登记；北向是否发布该能力，取决于鉴权回源与客户可访问
交付链路的适配结论。路径登记不代表尾帧交付已经完成。若适用的已发布北向合同承诺
`return_last_frame`，必须完成该语义的履约，不能静默忽略或仅转发开关却不交付尾帧。

请求继续保留统一北向内容顺序、媒体 role 和显式 false/0。南向路径包含 `/v1/video/` 不构成
选择 NEWAPI 原生 `/v1/videos` 或 `/v1/video/generations` 的理由。
不能只修改 Base URL，也不能给 FunCloud adapter 添加域名判断或通用响应猜测分支。
Synlink 不发送未经文档或实测确认的 FunCloud 私有字段。

### 3.2 素材双路径

| 客户行为 | 本站处理 | Synlink 实际接收 |
| --- | --- | --- |
| 创建素材 | 下载并校验源图片，复制进本站私有存储，写入素材事实，返回本站 asset 引用 | 不调用 Synlink 素材接口 |
| 视频传本站 asset | 预扣前校验归属、状态和对象可用性，冻结事实；发送时签发临时 URL 并替换引用 | 本站签发的可访问 URL |
| 视频直接传 URL | 通过请求校验后保留 URL，不自动保存为本站素材 | 调用方 URL |
| 同一视频混合两种输入 | 仅替换本站 asset，保持内容顺序、role 和直接 URL | 对应媒体 URL |

托管素材复用现有记录、存储和生命周期实现，不为 Synlink 复制第二套素材表、索引或状态机。
应把托管能力明确扩展为 FunCloud V3 与 Synlink 两条已登记视频协议共用，并同步配对校验、
运行时引用解析与公开元数据。素材协议最终名称及既有配置处理需在实施方案中明确，
不能仅通过增加一个管理端选项绕过当前限定，也不应借此进行无关表名或对象路径迁移。

扩展后的建议边界：

1. 保留按 `user_id` 的隔离与同账号共享；Task 继续按现有用户与应用边界隔离。
2. 素材对象事实在资金 hold 前冻结；发送时签发，不把完整签名 URL 写入普通日志、
   数据库字段或客户响应。既有受保护证据通道遵循其专属规则。
3. 删除只停止新引用，已受理任务按冻结事实继续，不删除对象或增加自动清理。
4. 本站托管 asset 必须解析为临时 URL；不存在、跨用户、已删除或对象不可用时，按托管校验失败
   在预扣前拒绝。非本站 opaque asset 没有已定义的 URL 转换方式，Synlink 又明确不支持素材 ID，
   建议在新协议中登记为不支持的输入并在预扣前拒绝。两类失败不回退源 URL、不跨 Provider 探测。
5. 首期复用普通图片托管范围，不由“支持视频/音频 URL”推导视频/音频托管能力。
6. 内部 URL 有效期应覆盖 Synlink 实际拉取窗口；直接 URL 由调用方保证窗口内可访问。
   既有 FunCloud 签发期限不能替代该线路的真实可达性与拉取时序验证。

上述第 4 项属于拟扩展的 Synlink 托管合同，不是当前所有 ModelArk V3 入口的通用规则。
其设计依据是[硬约束第 2 节](../00-context/硬约束.md)中“只有整个业务操作无法履约时才返回不支持”：
在没有合法转换方式时，Synlink 无法履约使用该 opaque 引用的生成操作。
但第 5 节同时明确规定现有 opaque 引用原样透传，且托管例外只登记 FunCloud V3，
因此不能仅引用通用条款就视为已覆盖该例外扩展。实施时必须同步更新权威合同、协议登记、
预扣前校验与公开能力描述；拒绝规则只作用于明确登记的 Synlink 协议，
不得修改其它现有协议的 opaque 引用语义，也不得因域名、模型名或价格推断适用范围。

### 3.3 是否可以复用当前渠道

可以复用现有渠道类型和基础设施；是否复用同一条 Channel 记录，需要区分同时运营与替换用途。

| 复用对象 | 结论 | 条件与影响 |
| --- | --- | --- |
| Seedance 渠道类型 | 可以，且建议复用 | 继续使用 `ChannelTypeSeedanceLink`，无需新增 ChannelType |
| 管理表单、鉴权、Task、预扣、结算、日志 | 可以 | 新增协议选项和必要接线，保持现有事实源与冻结语义 |
| 现有 FunCloud 视频协议 | 不可直接复用 | 路径、响应、状态与私有字段不同，需独立 adapter |
| 本站托管素材实现 | 可以复用 | 明确扩展当前仅限 FunCloud V3 的合同与代码配对 |
| 同一条 Channel 同时跑 FunCloud 与 Synlink | 不支持 | 每条 Channel 只有一套视频协议、Base URL 和视频凭据，不能按模型暗中切换供应商 |
| 将现有 Seedance Channel 改为 Synlink | 协议实现后可以考虑 | 是替换该渠道的新请求履约配置，不是同时承载两条线路 |
| 一条 Synlink Channel 放四个模型 | 可以按现有多模型设计接入 | 代码登记四个 Provider 模型的允许集合，保存／启用时校验最终映射结果与素材配对 |

模型校验沿用[渠道配置校验](../../model/channel_seedance_settings.go)中 TokenSave／Moxing 的机制：
先解析 `model_mapping`，再核对最终 Provider 模型是否属于该代码协议的允许集合。
四个文档模型名称可作为登记依据，但名称允许不等于参数能力已验证；时长、分辨率和媒体数量
仍须独立补齐证据，不能照搬 FunCloud，也不能将查询示例中的未登记后缀自动作为别名放行。

**推荐部署方式：保留当前 FunCloud Channel，另建一条相同类型的 Synlink Channel。**
两条渠道配置不同客户模型名，分别精确映射对应 Provider 模型。一个已启用客户模型仍只能对应
一个 Seedance Channel，不引入权重、失败重选或自动跨渠道回退。新增 Channel 记录不等于新增渠道类型。

如果目标是停用旧线路并原位改用 Synlink，则可以在新协议实现后，通过管理入口修改现有
Seedance Channel 的协议、Base URL、凭据和模型映射。已建立素材边界时需遵循当前
“替换素材租户”确认与审计流程，并核对客户价格；历史 Task 继续使用冻结的旧连接、协议和计费事实。
不能改写历史 Task，也不能把非 Seedance 渠道强行当作本协议渠道使用。

现有托管素材不绑定 Channel；明确扩展共享合同后，同一用户在两条已启用托管能力的线路上
复用同一图片，在设计上无需重传或重建素材。该共享是本站存储域共享，不是供应商素材 ID 互通。
实施必须同步公开 `platform_hosted`、素材能力与 `reuse_scope`，并验证跨线路引用；
现有 FunCloud 不透明 Provider 素材 ID 不属于可共享的本站素材。

### 3.4 北向列表、取消与删除

Synlink 未提供南向列表接口不影响本站列表能力；取消与删除则必须有相应履约证据。
接入时沿用[现有北向处理](../../controller/video_modelark.go)，明确以下行为：

| 北向操作／任务状态 | Synlink 接入后的目标行为 |
| --- | --- |
| `GET /api/v3/contents/generations/tasks` | 继续支持，从本站 Task 读取，保留用户与应用隔离、分页和筛选，不请求供应商列表 |
| DELETE 排队等可尝试取消的状态 | 未获得支持证据前不登记取消能力，返回 HTTP 409 `cancellation_unsupported` |
| DELETE 成功、失败等终态 | 未获得支持证据前不登记终态删除能力，返回 HTTP 409 `delete_unsupported` |
| DELETE 运行中或待核实状态 | 沿用 HTTP 409 `task_running` |

其它任务状态、不可见或不存在任务继续沿用现有处理，不新增统一错误去覆盖原有状态语义。
生命周期能力取自任务冻结协议；不能因为当前渠道配置改变而重新解释历史任务。
不通过隐藏本地记录、自动退款、停止轮询或清理对象来模拟取消／删除成功。
上述限制针对客户操作，不改变现有独立的任务保留与运维策略。

## 4. 未确认项与验收要求

- 获取处理中、明确失败、任务不存在、鉴权失败和限流响应；明确哪些创建错误表示结果未知。
- 按第 3.4 节验证本站列表包含 Synlink Task，且分页、筛选和用户／应用隔离不依赖南向列表。
  核对取消与删除支持证据；证据未补齐前，验证各状态沿用既有错误且不产生取消、删除或退款副作用。
- 核对四模型的时长、分辨率、比例、内容数量、默认值和媒体角色，不能复用 FunCloud 数值作为事实。
- 核对 `task.outputs[]` 的数量和元素含义，确认成功视频结果的有效性与访问方式。
- 创建与查询示例的模型名不一致，且查询出现未列出的模型后缀；时间字段也混有字符串与整数。
  需确认示例是否拼接，并按确认后的格式转换。公开客户模型始终取本站冻结事实。
- `return_last_frame` 需要完成独立鉴权下载到本站内容交付的适配；不能直接返回需要供应商 Key 的 URL，
  也不能仅传入开关却宣称已完整提供尾帧能力。核对适用的已发布北向承诺、能力元数据与实际交付一致，
  不以南向路径已登记替代交付验收，也不静默忽略已承诺的字段语义。
- `callback_url` 的正文、Task ID 和公开字段转换未说明；先核对本站已发布回调合同，
  不能把未经转换的供应商回调直接当成本站回调。其它北向字段同样遵循统一合同优先规则。
- 用量采集读取可信 `task.usage`，不得把 completion 与 total 相加；客户结算遵循创建时冻结价格。
  价格与供应商账单未确认；依赖实际用量时缺失不能按零或预扣估算直接结清。
- 真实验证本站 asset、直接 URL、两者混合、跨用户拒绝、已删除素材拒绝、对象不可用及未知创建结果。
  托管引用失败必须在预扣前关闭，已发送但创建结果未知时禁止自动重发、换渠道或退款。
- 验证同用户跨已登记线路的本站素材共享、非本站 asset 拒绝，以及切换配置后历史 Task 仍按快照执行。
- 确认 Synlink 托管合同扩展已同步权威文档、协议配对、运行时与公开元数据；
  回归其它现有协议，证明其 opaque 引用仍遵循各自合同，未被新拒绝规则收紧。
- 验证尾帧交付、音频开关、真实用量与账单后，才能评估生产灰度；本次分析不构成生产验收。
