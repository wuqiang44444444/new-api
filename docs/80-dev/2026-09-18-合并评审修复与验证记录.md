# 合并评审修复与验证记录

## 范围与判定

本轮修复两份专家报告及代码复核确认的缺陷，保留原有未签入业务实现。以中英文、原生文件最小接线、
资金事实不变为约束；没有调用真实 Provider、生产数据库或真实 SMTP，没有提交或部署。

以下候选不作为缺陷修改：图片 Provider 格式改写作用于 DeepCopy 后的请求；Gin 空 Content-Length 会删除头；
列表各行先按自己的冻结换算率换成 USD 后相加具有正确单位；ClickHouse 已被版本的同库拓扑门槛阻止。
协议取消不能一概认定是客户主动取消，保留事件并单独归类为 cancelled，不将其标记为 fatal。

## 最小入侵与上游同步

- `main.go` 只增加两库初始化后的来源跟踪注册与错误检查。这是从节点也生效所必需的接线；未来合并只需复核初始化顺序。
- `relay/image_handler.go` 只增加格式化请求资源的关闭接线；格式重写与磁盘保护位于本地独立文件。
- `model/batch_result.go` 只携带已提交失败原因到现有观察出口，不重排资金事务。
- 其它主体位于本地账单、导出、图片和邮件扩展文件；不重构 Router、Provider 协议、资金算法或通用状态机。
- 保留正常结算日志的必要修订写入，不为降低 SQL 数量跳过计费证据；热路径吞吐仍需目标部署验证。
