# 全客户账单按日导出实施方案

## 问题与目标

财务需要在「账单对账 → 客户账单 → 导出与下载」选定一个北京时间自然日，导出全客户汇总 CSV，每位客户一行。
抽屉提供「按月 / 按日」，按日默认选中最近可下载的完整自然日。客户列表仍用于按月查看，既有搜索、质量筛选和分页不影响全客户导出范围。
本方案覆盖管理员全客户汇总。单客户按日下载按后续明确需求单独实施，见[客户账单明细导出字段收敛分析](2026-11-23-客户账单明细导出字段收敛分析.md)。

## 当前实际情况

- 全客户导出复用客户导出任务与下载抽屉，现只接受自然月，生成时读取已确认月账单并与日报汇总合并。
- 日报已发布按天的客户汇总和明细，保留发布版本和覆盖证据；月账单列表接口只提供聚合后的账期状态。
- 既有异步队列、私有对象存储、下载鉴权和任务历史可复用。真实环境对象存储和历史日报可用性待验收。

## 优化方案

1. 管理员抽屉打开后按需读取当前页面月份的逐日状态。正常按日期倒序展示，默认选择最新的已发布、覆盖完整且有账单记录的自然日。
   当前月尚无可作为默认值的日期时，同时提供上一个自然月供选择；历史月份按照页面所选账期查询。
   当天进行中、未发布、重建中、来源不可用、已发布无记录各有可见状态，均禁用选择和提交。可用的覆盖不完整日报可显式选择，
   页面和文件都提示覆盖不完整。未来日期不展示，今天的阶段性数据不可导出。
2. 全客户导出继续使用既有管理接口和任务类型，按日请求使用明确日期和该日发布版本，服务端按上海时区确定
   左闭右开边界并重新校验发布、可读性、记录存在性和所见覆盖状态；入队冻结日期、报表版本和覆盖信息。
   同范围的活动任务返回原记录。日任务使用独立字段版本 29。月导出沿用正式月账单读取条件，随字段收敛升为版本 28。
   已冻结来源且尚未登记产物的版本 26 月任务在执行前升级制表版本。
3. 按日执行器只读选定日报客户汇总，复用客户金额投影、CSV、队列、对象存储与下载鉴权。文件名、首列、
   新任务反馈和导出历史用完整日期；覆盖信息随任务冻结。历史任务重新生成从原任务读取日期、报表版本及覆盖，
   使用当前简体中文格式。报表版本不可用时提示失败。
4. 使用本地测试验证默认日期、日期不可用与无记录的区别、覆盖不完整可见、日请求参数与导出历史展示；
   后端验证北京时间边界、管理员权限、冻结版本、同月相邻数据及正式月账单隔离、CSV 日期和覆盖字段。
   执行文档结构与 AI 约束检查，并记录目标部署验收条件。

## 实施与验证

- 管理员全客户抽屉已支持按月和按日导出。日任务沿用现有导出队列和权限，CSV 包含完整日期、日报版本与覆盖信息。
- 本地 Go 定向测试覆盖当前月缺少完整日报时的上月日期、日期状态、自然日边界、版本不匹配拒绝、正式月账单隔离，
  以及异步任务生成正确日期的 CSV。对象上传使用测试替身。
- 评审回归覆盖管理员令牌范围、按日字段版本隔离、覆盖变化冲突、活动任务去重，以及读取原任务的冻结条件重新生成。
- 前端账单对账模块 169 项测试通过，覆盖选择日期、覆盖变化后的确认、切换账期保留导出模式、历史日期显示和重新生成。
  TypeScript 检查、受影响模块 lint 及中文和英文翻译同步通过。
- 相关后端五包全量测试通过，包括全路由访问令牌声明检查。文档结构、AI 约束与 API 文档校验通过。
- 目标部署的实际日报覆盖情况、对象存储下载与生产数据对账待验收。
