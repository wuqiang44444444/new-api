# 客户与上游日周用量统计实施方案

> 根据本次用户访谈形成的新方案。需求确认不等于代码完成；本文中的页面、接口、数据组织和实施步骤
> 均为拟实施设计。当前仅完成需求澄清及代码入口核查，未实施日／周用量功能，未完成真实数据验收。

## 问题与目标

客户和管理员需要查看某天或某周已经结束的调用：谁使用了哪些模型、消耗了多少资源、产生了多少金额。
管理员还需要单独查看我们对各上游的使用情况。现有月度账单以入账记录为主，不能只扩大日期筛选，
就把它当作按完成时间统计的用量报表。

本次增加日／周用量查看与导出，保留客户、上游两个独立视角。查询不执行对账、关账、账单确认、
差异处理或资金调整，也不建立第二套 Task 状态和计费事实。

### 用户已确认的需求

| 项目 | 确认结论 |
| --- | --- |
| 查看对象 | 客户用量、平台对上游的用量都需要，可分 Tab 或分页面 |
| 时间范围 | 单日或自然周，不支持自定义起止日期 |
| 周展示 | 每天分别展示，并附整周合计 |
| 时间归属 | 只统计所选日期内已经完成／结束的调用，按结束时间归属 |
| 结果范围 | 成功、失败、取消均计入，不能只保留成功或收费调用 |
| 指标 | Token 明细、图片 Token／张数、视频秒数等实际用量，以及金额、上游折扣、净额 |
| 客户权限 | 管理员查看客户用量，普通客户查看自己的用量 |
| 客户分组 | 按 API Key 区分，并查看各模型 |
| 上游分组 | 上游 URL → 模型 → 渠道；相同 URL 下的渠道合并且可展开 |
| 上游折扣 | 沿用上游账单的渠道月度折扣；未配置按 1，现有上游账单也按同一规则调整 |
| 缺失用量 | 历史失败记录缺乏实际用量证据时，计入失败次数、用量标为“未记录”，只累计已知部分 |
| 导出 | 可以导出所选日／周的数据 |

### 本方案采用的实施默认值

以下为工程与产品默认方案，不冒充用户逐项确认：

- 时区沿用 `Asia/Shanghai`，自然周为周一至周日；默认查看今天。
- 使用独立“用量统计”页面，管理员包含“客户用量”“上游用量”两个 Tab；普通客户只显示自己的用量。
- 导出采用 CSV，导出当前筛选范围内的完整汇总，不受当前页码和展开状态限制。
- 首期以表格和汇总为主，不追加同比、环比、预测、利润分析或新的图表看板。
- 当日和本周显示“截至查询时间”；已经结束但数据晚到的调用在刷新后更新原结束日，无关账流程。

### 成功标准

用户选择一天或一周，即可按已确认的分组查看用量与金额；一周有七个日期位置和同口径合计。
跨日任务只归属结束日，预扣、结算调整、轮询和退款不重复增加调用数。失败和取消不被隐式过滤。
缺失与零值可区分，页面和导出使用同一统计逻辑；客户不能访问其他客户或上游内部信息。

### 尚未核实的数据条件

1. 原生同步、流式、同步图片、原生媒体任务、本地视频／异步图片、Batch 的终态时间和数量字段覆盖。
2. Task、attempt、消费日志、退款日志、错误日志之间可用的稳定关联；同请求多次上游尝试的记录覆盖。

不从模型名称、当前价格、相邻记录或金额反推用量。

## 优化方案

### 1. 统计口径与日期边界

查询参数只接受 `period=day|week` 和一个上海时区日历日期 `date=YYYY-MM-DD`。
周模式以该日期所在自然周计算范围；服务端统一返回起始日和排他的结束时刻，禁止任意起止时间绕过限制。

- 单日：当地当天 00:00 至次日 00:00，不含次日边界。
- 自然周：当地周一 00:00 至下周一 00:00，不含下周边界；允许自然周跨月、跨年。
- 自然周跨月仍是合法周查询，不属于自定义日期范围；折扣按每条记录的结束日所属月份分别读取。
- 今天只含已经结束的调用。本周尚未到来的日期显示“未到日期”，不能作为真实零用量；历史空白日
  在来源完整时显示 0，来源不完整时保留提示。
- `UNKNOWN`、待核实、排队和运行中不属于结束；过期或其他已确认失败终态按现有生命周期分类纳入，
  不新增结束判定或超时规则。

结束时刻优先使用对应执行路径已持久化的可信结束事实。同步日志写入时刻只在确认该路径为最终请求
结束记录时使用；异步任务用明确完成时刻，不能通用回退到 `updated_at`、提交时刻或退款入账时刻。
终态明确但历史完成时刻缺失的记录，不伪造日期；以来源覆盖提示说明无法纳入，必要的新记录补采集
必须另列最小接线点。

### 2. 计数、关联与去重

使用已有业务标识组织只读“已结束调用”投影，投影不是新资源表或新生命周期。

| 来源 | 计数单位与处理 |
| --- | --- |
| 同步最终消费／错误 | 客户最终请求；明确关联的重试错误不能再算为一个客户失败 |
| 已结束 Task | 一条逻辑任务计一次；关联创建、预扣、调整、退款日志只补充事实 |
| 无 Task 的明确创建拒绝 | 有可靠结束时间与身份时计一次失败；与同次请求错误日志去重 |
| attempt 已转入 Task | 由 Task 代表，不额外计数 |
| Batch | 请求次数使用可信行级计数，用量使用行级事实；作业数与行请求数分开，不能一笔作业加一笔行数 |
| 后续退款／补偿 | 不增加调用次数，不新增完成事件；有唯一关联时更新原结束日金额 |

拟采用的稳定标识顺序为：已有内部 Task／attempt 关联、同用户与应用内的可靠请求 ID、最后才是
无法关联的独立日志记录。具体标识必须通过现有路径的回归样本证明，不能仅凭字符串相同跨租户合并，
不能凭时间接近或金额相同猜测关联。缺少关联证据的历史范围须提示覆盖不足，不能宣称精确去重。

客户侧按最终逻辑调用计数；上游侧只纳入有渠道及实际上游调用证据的记录，鉴权失败、请求校验失败等
未触达上游的调用不虚构渠道。上游重试记录如能明确区分尝试，按实际已记录尝试分别归渠道；历史缺失
的尝试不补造。两侧次数不要求相等，不用此差异做对账或推算成本。

原生渠道测试沿用现有范围：客户侧排除，管理员上游侧保留并单独标注；测试用量没有金额证据时保持
“未记录”，不认定免费。无 API Key 的真实记录单列“无 API Key”，不能归到其他 Key。

### 3. 用量指标

| 指标组 | 展示与求和规则 |
| --- | --- |
| 调用情况 | 总次数、成功、失败、取消；可信其他终态按稳定分类展示，不从错误文案推断 |
| Token | 总输入、输出、缓存读取／写入；已记录的文本、图片、音频等分项按来源展开 |
| 图片 | 实际图片 Token、实际张数；二者可并存，不能由一次请求推断为一张图 |
| 视频 | 实际秒数；已有实际 Token 时另列，不能用 Token 反推时长或用预算时长冒充实际时长 |
| 其他单位 | 已有明确计量单位的数量分项展示；计费次数与业务产出数量分开 |

输入总量与缓存、图片等子项的包含关系沿用既有解析语义；父子分项不能重复相加。
不同单位不合并成一个“总用量”。模型映射使用请求时冻结身份，客户模型与上游模型分别展示；
历史身份未知时沿用已有明确的缺失标记，不读取当前映射猜测历史身份。

每个指标至少包含已知合计、缺失记录数和是否适用。明确的 0 显示 0；无证据显示“未记录”；
不适用显示“—”。部分已知显示“已知用量合计”及缺失条数，日期、模型、Key、渠道和总计一致传递。
成功记录同样遵守此规则，不能只对失败行标缺失。

### 4. 金额、折扣与净额

金额沿用既有冻结计费事实及十进制换算，不重新执行收费，不按当前价格重算历史。

- 客户侧展示原价金额、优惠金额、净额。原价由历史扣款及折扣还原时保留“估算原价”标签；净额来自
  该已结束调用的已记录扣款减可唯一关联退款，异步预扣与差额只能组成一次最终金额。
- Task 已结束但结算或日志交付尚未完成时，仍纳入次数与已知实际用量，金额显示“待更新”或已知部分；
  不能以预扣直接充当最终净额。后续完成后更新原结束日，不把它当成新一天的调用。
- 后来发生的人工退款只有明确关联时才影响原调用金额；无法关联的资金流水不凭入账日期塞入某日用量。
  因此本功能不保证与月度入账账单逐日相等。
- 上游侧复用既有本地原价投影：`折后参考净额 = 可确认的原价基数 × 渠道当月综合系数`。
  保留“参考／估算”含义，不命名为已核实供应商成本或最终应付款。
- 没有渠道月度配置时使用 1 并标明默认来源；已有配置直接读取。用量查询不自动创建配置、不复制
  上月折扣，不另建默认或继承规则，配置维护仍在原上游账单入口。
- 历史折扣冲突沿用共享折扣服务的异常状态；它不等于“没有配置”。该处理为当前实现依赖，若业务希望
  冲突也按 1 展示，应独立明确覆盖策略，不能在本查询中静默改变。
- 原价未知、未记录上游消耗等情况仍保持未知，默认系数 1 不能补齐缺失的金额基数。客户退款不证明
  Provider 已退款；沿用原价参考投影不改变这个边界。
- 周跨月或 URL 下存在不同渠道折扣时，逐日、逐渠道计算后求和，不平均折扣后乘总额；汇总折扣列
  显示“多种折扣”，下钻查看月份、渠道、系数与来源。

上述退款回归原结束日、晚到数据更新等属于本方案的只读展示规则，不改变资金事实或旧账单文件。

### 5. 页面组织与权限

建议新增普通客户 `/usage` 与管理员 `/admin/usage` 页面，路径在实施时检查路由冲突后登记。
这些是拟新增入口，不是当前已发布地址。

客户侧：管理员先选客户或查看客户列表，再进入“API Key → 客户模型”；普通客户直接进入自身视角。
同名或改名的 Key 使用稳定 `token_id` 区分，已删除 Key 保留历史身份和用量，不读取或展示密钥。

上游侧：管理员按“URL → 上游模型与计费方式 → 渠道”查看，复用现有安全 URL 归组和删除渠道展示。
上游地址、上游模型、渠道折扣和参考金额不出现在普通客户接口响应及导出中。

两侧先呈现所选范围的每日汇总和范围合计，再在业务分组中查看对应每日数据。周模式必须保留七日
分布；翻页、折叠不能影响范围总计。按单位分栏／分项，不生成 Token、张数、秒数混合总数。
首期不增加逐请求原始响应查看；需要排查时复用已有受权限保护的记录入口。

复用现有 [页面布局](../../web/src/components/layout/components/section-page-layout.tsx)、
[日期选择器](../../web/src/components/date-picker.tsx) 和 [表格组件](../../web/src/components/data-table/README.md)。
实施 UI 前依项目要求读取 shadcn-ui、React、UI/UX 与 i18n 技能；只维护中英文。

### 6. 查询实现与复用边界

采用新增用量查询模块，处理“来源选择 → 结束时间 → 关联去重 → 指标提取 → 分组聚合”，页面与导出
共用它。复用旧账单中可独立调用的身份、用量解析、金额换算、URL 归组及折扣查询，不复用其月度
入账扫描范围，不复制一套计费公式，也不把新增用量响应塞进旧账单响应。

建议新增文件集中在 `model/usage_analytics*.go`、`service/usage_analytics*.go`、
`controller/usage_analytics*.go`、`router/usage-analytics.go` 和 `web/src/features/usage-analytics/`。
文件名与下列接口为实施草案，实际接线前与仓库现有命名核对。

| 拟新增接口 | 权限 | 职责 |
| --- | --- | --- |
| `GET /api/usage/self/summary` | UserAuth | 本人 API Key、模型、日汇总及范围合计 |
| `GET /api/usage/admin/customers` | AdminAuth | 客户列表及所选范围总览 |
| `GET /api/usage/admin/customer-summary` | AdminAuth | 显式客户的 API Key 与模型汇总 |
| `GET /api/usage/admin/upstream-summary` | AdminAuth | URL、模型、渠道的日汇总 |
| `POST /api/usage/self/exports` | UserAuth | 本人用量汇总导出 |
| `POST /api/usage/admin/exports` | AdminAuth | 管理员客户／上游用量汇总导出，显式授权目标范围 |

服务端推导日期边界；Key 过滤必须验证属于目标客户。读取 Task 等客户资源时同时遵守既有用户与应用
隔离，不能仅靠前端隐藏实现权限。响应只包含公开汇总字段，不序列化 Task 私有快照。

完成时间筛选应优先走 Task 时间／状态索引及日志时间索引；依稳定关联批量加载该批调用的历史扣款与
调整，不能只读取结束周内的资金日志，否则跨周预扣会丢失。无界扫描、每行回查和无限制全量拉取不可接受。
主库和日志库分离时分批读取、取消与超时必须传递，不依赖跨库 JOIN；SQL 保持 SQLite、MySQL、PostgreSQL
兼容。若目标部署使用 ClickHouse 日志库，须额外验证对应读取能力，不能宣称关系库通过就覆盖该部署。

首期不新增持久化日汇总表、独立用量账本或新的后台重算状态机。先以真实规模验证只读查询；必要的
可重建缓存不作为权威。若容量测试证明需要物化汇总，再单独提出增量维护、迟到事件和纠正策略。

原生代码优先零修改；只有确定现有记录不足以支撑新完成事实时，才列出必要的极窄采集接线。
不得为了统计改写 Provider adapter、Task 终态、计价引擎、收费和退款行为。通用约束以
[硬约束](../00-context/硬约束.md) 与 [异步事实架构](../20-architecture/账单计费-异步任务与计费事实架构.md) 为准。

### 7. 导出方案

复用已有导出任务、队列、权限复核和私有文件交付，新增用量汇总任务类型及独立日期校验，
不放宽原月账单导出的合同。管理员全客户与上游导出必须显式授权，不能借单客户导出接口越权。

导出冻结视角、目标客户、Key／模型／URL／渠道筛选、日期范围、时区、语言、显示币种与换算、
适用的各月折扣及其来源。页面与导出共用聚合函数；CSV 包含日期、业务分组、结果次数、分单位用量、
金额、质量提示、生成时间，以及 `daily`／`period_total` 行类型，避免把日行与合计重复相加。

导出全部筛选结果，不只导出可见页。缺失留空并附状态，已知零写 0；按既有规范处理 CSV 公式注入。
下载时再次校验当前权限。晚到数据或折扣修改可能使新查询发生变化，已生成文件保持原样；相同数据
截止条件下页面与导出必须一致，不承诺运行中的页面和稍后生成的文件永远逐值相等。

### 8. 实施顺序与交付物

| 步骤 | 工作与交付物 | 完成条件 |
| --- | --- | --- |
| 1. 来源核查 | 按同步、流式、图片、视频、Batch、创建拒绝列出终态时间、关联标识、实际单位、金额来源矩阵；用最小脱敏 fixture 证明 | 各路径可直接读取或明确标出缺口；不以一套日志时间覆盖所有路径 |
| 2. 只读聚合 | 实现日期规范化、来源组合、终态过滤、去重、单位与金额质量、分组和合计 | 单日与跨月自然周、成功／失败／取消及跨期预扣测试通过 |
| 3. 权限接口 | 添加本人、管理员客户、上游查询及导出授权边界 | 目标客户、Key、应用边界和上游字段隔离测试通过 |
| 4. 页面与导出 | 完成两个视角、逐日与周合计、缺失提示、中英文及 CSV | 页面不因分页丢总计，导出完整且与同范围查询一致 |
| 5. 集成验收 | 真实部署数据抽样、查询规模、分库与数据库兼容检查；记录支持范围 | 无重复计量、无伪造零、无资金副作用；未验证项明确列出 |

上述为同一功能的实施顺序，不把“只上线成功 Token 统计”当作全部需求完成。某路径无法满足实际
用量完整性时，应展示缺失；某路径连结束归属都无法确定时，先记录覆盖限制与补采集动作。

### 9. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 周日提交、周一结束 | 只进入周一及其自然周；周日的预扣不新增该日完成用量 |
| 成功、失败、取消各一条 | 总次数 3，各结果次数正确；失败和取消不因金额为 0 被过滤 |
| 创建、预扣、终态、差额、重试交付属于同一 Task | 只计一次，实际用量不重复累加 |
| unknown 或轮询暂时失败 | 不当作完成或失败，不改变 Task／资金 |
| 同步请求重试后成功 | 客户只计一次成功；上游仅统计有证据的尝试，不虚构失败消耗 |
| 实际输入 100，其中缓存 30 | 输入仍为 100，不合计为 130 |
| 一次请求实际生成 4 张图 | 请求数 1、图片张数 4；图片 Token 独立展示 |
| 失败日志基础字段为 0 且无用量证据 | 失败次数加 1，用量显示未记录，不当作实际零 |
| 明确零用量与缺失用量混合 | 零与未知区分，已知合计及缺失条数正确 |
| 金额相同但不同单位／计费方式 | 各单位分别汇总，不按金额倒推用量 |
| 周跨月，渠道两月折扣不同 | 分月应用系数后汇总；缺配置的月份用 1，不平均系数 |
| Task 已结束但结算／日志晚到 | 次数与已知用量先出现，金额待更新；恢复后留在原结束日 |
| API Key 同名、改名、删除 | 按稳定 ID 分组，无串 Key 或历史遗漏 |
| 客户伪造其他用户、Key、导出任务标识 | 服务端拒绝，响应及文件不泄露上游字段 |
| 空日、本周未来日、已知数据缺失 | 分别展示真实零、未到日期、未记录／部分覆盖 |
| 当前表格分页或折叠后导出 | 导出仍覆盖全部筛选结果；合计不受分页影响 |
| 自定义起止时间、非法 period、非法日期 | 校验拒绝；合法跨月自然周可查询 |

后端测试使用项目现有断言库和确定性 fixture，优先验证聚合与权限边界；前端验证日期切换、逐日与
合计、缺失展示、Key 分组及导出行为，并运行类型检查和涉及文件 lint。表达式只读解析复用现有实现，
不在本任务增加一套公式测试或计算器。数据库与 Provider 验证未完成不得写成生产已可用。

### 10. 风险、依赖与剩余事项

- **日志覆盖**：错误基础字段的零、消费日志关闭、清理及晚到事件均可能造成缺口；必须报告已知覆盖，
  不能用页面的 0 制造完整性。
- **多源关联**：同一调用多条资金记录、跨日提交与异步完成是主要重复／漏计风险；应先建立回归样本，
  再接 UI，不能靠前端合计修正。
- **并行账单修复**：当前渠道折扣、上游导出及日志交付正在变化；实施时复核最终接口，复用共享规则，
  不覆盖其他任务改动，不把临时工作区代码当作已发布合同。
- **时间覆盖**：`finish_time` 字段存在不等于所有路径可靠填充；无法证明时不得以最后更新时间替代。
- **业务量与查询成本**：真实数据规模尚未测量；实现前记录日／周记录量和查询基线，容量不满足时给出
  实测结果及针对性方案，不先引入新账本或复杂汇总基础设施。
- **历史冲突与未知金额**：默认折扣 1 仅解决无配置情形，不能修复未知用量、历史价格缺失或冲突事实。
