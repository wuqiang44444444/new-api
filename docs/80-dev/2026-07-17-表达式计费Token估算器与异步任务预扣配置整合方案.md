# 表达式计费 Token 估算器与异步任务预扣配置整合方案

> 本文记录「模型价格 → 表达式计费」中浏览器本地试算、异步任务真实预扣配置和终态 Token 回算的实现与验收结果。代码已经完成；本文保留改造前根因，并以当前实现和验证记录为准。

## 1. 修复的业务目标

本次修复需要同时实现以下业务结果：

1. 管理员在同一模型上编辑并保存价格时，Token 试算现场不能被意外清空。
2. 页面必须明确区分：
   - **试算数据**：只用于预览表达式结果，不参与真实计费；
   - **计费配置**：会持久化，并参与请求预扣、终态结算、退款或计费债务判定。
3. 异步视频任务使用表达式计费时，管理员能够在单模型可视化编辑器中配置真正生效的「预扣输出 Token 上界」，不再必须切换到 JSON 模式手工维护整张映射。
4. 依赖 `param("_task.*")` 的视频计费表达式能够按分辨率、是否有输入视频正确试算，不再永远落入兜底档。
5. 前端显示的 USD 费用和内部配额必须与后端公式一致，不能把表达式原始结果误标为「配额费用」。
6. 保持现有表达式、数据库结构和异步任务计费状态机兼容，不改变已经创建任务的冻结快照与结算语义。

## 2. 改造前问题与根因

### 2.1 Token 估算器不是保存字段

改造前 [`CostEstimator`](../../web/default/src/features/system-settings/models/tiered-pricing-editor.tsx) 只接收 `effectiveExpr`。`promptTokens`、`completionTokens` 和缓存/图片/音频 Token 都是组件内部 `useState`，初始值为 `0`。

这些值没有进入：

- [`ModelRatioData`](../../web/default/src/features/system-settings/models/model-pricing-core.ts)；
- [`buildSubmitData`](../../web/default/src/features/system-settings/models/model-pricing-sheet.tsx)；
- [`persistPricingData`](../../web/default/src/features/system-settings/models/model-ratio-visual-editor.tsx)；
- `billing_setting.billing_mode`；
- `billing_setting.billing_expr`；
- 任何后端 Option 或数据库列。

所以原问题不是「后端保存后改成 0」，而是浏览器从未提交过这些值，重新加载只能再次执行 `useState(0)`。

### 2.2 同一模型保存也会强制重建编辑器

保存当前模型时：

1. `commitOpenEditor()` 生成 `ModelRatioData`；
2. `persistPricingData(data)` 更新表单中的 JSON 映射；
3. `setEditData(data)` 写入一个新的对象；
4. `ModelPricingEditorPanel` 监听到 `editData` 变化，递增 `editorReloadToken`；
5. `TieredPricingEditor` 的 React `key` 改变，整个编辑器被卸载并重新创建；
6. Token 试算状态重新变为 `0`。

`editorReloadToken` 原本用于修复「切换模型后仍显示上一个模型表达式」，但改造前的触发条件是整个 `editData` 对象变化，没有限制为模型身份变化，因此同一模型保存也被误判为需要重载。

### 2.3 试算器与真实异步预扣配置脱节

异步任务表达式计费不读取页面中的 `promptTokens` / `completionTokens`。真实预扣由后端读取：

```text
task_billing_setting.preconsume_tokens
```

对应代码：

- 配置和校验：[`setting/billing_setting/task_billing.go`](../../setting/billing_setting/task_billing.go)
- 异步任务预扣：[`relay/helper/task_tiered_price.go`](../../relay/helper/task_tiered_price.go)

异步任务预扣时只把该上界代入表达式变量 `c`：

```go
billingexpr.TokenParams{
    C: float64(estimatedTokens),
}
```

因此对 Seedance 等视频任务：

- `p` 不是输入视频时长，也不是视频计费 Token；
- 真实预扣配置只有一个「输出/可计费 Token 上界」；
- 终态结算使用上游返回的 `completion_tokens`，仍代入 `c`。

改造前 Default 前端只在 JSON 编辑模式暴露 `TaskPreConsumeTokens`，单模型可视化编辑器没有入口，导致管理员容易把下面的试算输入误认为真实预扣配置。

### 2.4 请求条件表达式无法准确试算

视频表达式可能依赖：

```text
param("_task.has_video_input")
param("_task.resolution")
```

改造前本地求值器没有真实请求 Body/Headers。`param()` 安全降级为空值，使所有 `_task` 条件均为假，所以页面只能命中兜底档，不能验证 4K、1080P、480P/720P 与有无输入视频的组合。

### 2.5 Default 前端配额展示公式不完整

表达式返回的是：

```text
Token 数 × USD/百万 Token 单价
```

后端真实换算是：

```text
USD 费用 = 表达式结果 / 1,000,000
配额 = USD 费用 × QuotaPerUnit
最终预扣配额 = 配额 × 用户组倍率
```

试算器文案声明「不含用户组倍率」，因此应显示倍率应用前的 USD 费用和配额。改造前 Default 前端直接显示表达式结果，和后端口径不一致；Classic 前端已有 `/ 1,000,000 × quota_per_unit` 的换算逻辑，可作为行为参考，但不应直接复制其组件实现。

## 3. 方案原则

### 3.1 一个字段只承担一种业务语义

- Token 估算器继续作为**试算工具**，不能暗中改变真实计费。
- `task_billing_setting.preconsume_tokens` 是异步任务预扣上界的唯一配置事实。
- `billing_setting.billing_expr` 继续作为表达式价格的唯一事实。
- 不把试算草稿写入计费表达式，也不为试算偏好新增数据库列。

### 3.2 最小入侵

- 后端已有预扣配置与校验，优先复用，不新增数据库迁移。
- 前端主要在现有模型价格编辑链路增加一个字段和一张映射。
- 新增的试算状态、请求探针和换算逻辑优先放入独立文件，避免继续扩大已经较大的 `tiered-pricing-editor.tsx`。
- 不借本次修复重构整个模型价格表单或表达式引擎。

### 3.3 保存行为必须符合用户认知

- 点击「保存模型价格」只保存明确标注为计费配置的字段。
- 试算器增加「仅用于预览，不影响实际计费」提示。
- 试算草稿可在当前浏览器恢复，但必须明确这是本地草稿，不是服务器计费配置。

## 4. 目标交互

### 4.1 表达式计费配置区

在表达式编辑器上方或表达式配置卡内增加：

```text
异步任务预扣 Token 上界（c）
[ 250000 ]

用于异步任务创建时预扣。仅异步任务表达式计费使用；
终态先按上游 completion_tokens、再按 total_tokens 回算。
```

交互规则：

- 可为空：同步文本模型不需要该配置。
- 非空时必须是 `1` 到 `1,073,741,823` 的整数；前后端使用同一上界合同。
- 保存到当前模型对应的 `task_billing_setting.preconsume_tokens[modelName]`。
- 编辑已有模型时从映射回填。
- 清空后保存时，从映射中删除当前模型。
- 若当前模型走异步任务表达式计费但未配置，运行时仍保持后端 fail-closed；前端在能够确认模型为异步任务时给出阻断提示，否则给出明显警告。
- 异步表达式禁止 `header()` 和 `hour/minute/weekday/month/day()`；这些值不会冻结到任务快照，预扣与终态复算可能不一致。

终态差额规则：

- `completion_tokens > 0`：使用 `completion_tokens`；
- 否则 `total_tokens > 0`：回退使用 `total_tokens`；
- 两者都不可用：保留原预扣额度；
- 实际费用低于预扣：退还差额；
- 实际费用高于预扣上界：进入 `debt`，不自动突破预扣上界补扣。

### 4.2 Token 试算器

试算器标题调整为：

```text
费用试算（浏览器本地草稿）
仅用于预览表达式结果，不会作为模型价格或预扣配置保存。
```

保留以下输入：

- `p`：输入 Token；
- `c`：输出 Token；
- 表达式实际引用到的缓存、图片、音频 Token。

增加：

- 「恢复默认值」按钮；
- 当前模型维度的本地草稿恢复；
- 请求探针区域；
- USD 费用与内部配额的双重展示。

建议展示：

```text
命中档位：1080p_video
预计费用：$0.7623
预计配额：381,150（不含用户组倍率）
```

### 4.3 视频任务请求探针

当表达式引用 `_task` 参数时显示：

```text
任务试算条件
是否包含输入视频：[否/是]
分辨率：[480p] [720p] [1080p] [4K]
```

构造本地请求 Body：

```json
{
  "_task": {
    "has_video_input": true,
    "resolution": "1080p"
  }
}
```

本地 `param(path)` 从该对象读取值，使截图中的六档视频表达式能够准确命中对应分支。

本阶段不实现任意业务表单生成器。其他 `param()` 路径仍可后续通过高级 JSON 请求上下文扩展；本次只完成已有异步视频计费合同需要的 `_task` 探针。

### 5.1 服务器持久化数据

扩展前端模型价格表单数据，但复用现有后端 Option：

```ts
type ModelRatioData = {
  // existing fields...
  taskPreConsumeTokens?: number
}
```

`ModelRatioVisualEditor` 增加：

```ts
savedTaskPreConsumeTokens: string

```

在 `persistPricingData()` 中解析并更新：

```ts
Record<string, number>
```

可视化编辑器内部先更新表单字段：

```ts
onChange(
  'TaskPreConsumeTokens',
  JSON.stringify(taskPreConsumeTokensMap, null, 2)

```

`saveModelRatios()` 再将 `TaskPreConsumeTokens` 映射为后端 Option `task_billing_setting.preconsume_tokens`，通过 `updateOption` 保存。后端使用 `ValidateTaskPreConsumeTokensJSON()` 校验整数范围，并在读取时再次拒绝越界的存量值。

### 5.2 浏览器本地试算草稿

新增独立类型：

```ts
type TieredEstimatorDraftV1 = {
  promptTokens: number
  completionTokens: number
  extras: ExtraTokenValues
  taskProbe: {
    hasVideoInput: boolean
    resolution: '480p' | '720p' | '1080p' | '4k'
  }
}
```

本地存储键按模型隔离：

```text
model-pricing-estimator:v1:<model-name>
```

约束：

- 只保存非敏感数字和枚举，不保存表达式、请求 Header、Key、Cookie 或真实请求 Body。
- JSON 解析失败、版本不兼容或数值非法时回退默认值。
- 历史草稿值 `480p720p` 在读取时迁移为后端真实合同值 `720p`。
- 新建模型在模型名为空时只保留组件内状态；名称确定后再写入对应键。
- 本地草稿不进入 `buildSubmitData()`，也不调用后端 API。

### 5.3 编辑器重载边界

删除「任意 `editData` 变化都递增」的重载方式，改为只按模型身份重建：

```tsx
<TieredPricingEditor
  key={editData?.name || '__new_model__'}
  ...
/>
```

或者使用 `previousModelNameRef`，只在模型名真正变化时递增 reload token。

必须满足：

- 同一模型保存：不重建试算器；
- 同一模型表达式变化：更新 `effectiveExpr`，保留试算输入；
- 切换到另一模型：加载另一模型的表达式与本地试算草稿；
- 新建模型与编辑已有模型之间切换：正确重建；
- 不能重新引入「切换模型显示旧表达式」问题。

## 6. 本地求值与费用换算

### 6.1 请求探针

扩展本地求值器参数：

```ts
type EstimatorRequestInput = {
  body?: Record<string, unknown>
  headers?: Record<string, string>
}
```

本次至少实现：

- `param(path)`：按点路径读取 `body`；
- `header(name)`：大小写不敏感读取 `headers`；
- `has(source, text)`：与后端子串判断语义一致。

没有提供探针值时返回安全空值，但页面同时提示「当前条件没有试算上下文，结果可能落入兜底档」，不能静默制造准确预览的假象。

安全与确定性边界：

- 浏览器本地求值前先做严格 Token 白名单校验，只允许计费变量、常量、算术/比较/逻辑/三元运算符和已声明函数；访问 `globalThis`、成员属性、箭头函数、注释等通用 JavaScript 语法会直接报错；
- 本地求值只是预览，服务端 `expr-lang` 编译与执行始终是计费权威；
- `header()` 只适用于同步表达式预览；异步表达式若同时引用 `_task` 与 Header/时间函数，页面提示错误，后端任务创建继续 fail-closed。

### 6.2 费用和配额

本地表达式结果记为 `rawCost`：

```ts
const usdCost = rawCost / 1_000_000
const quotaBeforeGroup = usdCost * quotaPerUnit
```

页面不应用用户组倍率，符合现有说明。`quotaPerUnit` 使用当前系统配置，不写死 `500000`；配置暂不可用时显示 USD 费用，并把配额标记为不可计算。

建议把本地结果类型改为：

```ts
type EstimatorResult = {
  rawCost: number
  usdCost: number
  quotaBeforeGroup: number | null
  matchedTier: string
  error: string | null
}
```

## 9. 测试方案

### 9.1 前端单元测试

1. `promptTokens`、`completionTokens`、extras 和 `_task` 探针可按模型写入并恢复。
2. 非法本地 JSON、负数、`NaN`、`Infinity` 回退安全默认值。
3. 同一模型保存后试算值保持不变。
4. 切换模型时加载目标模型草稿，不能串值。
5. 以下八种真实探针组合命中正确档位：
   - 无输入视频：480P、720P、1080P、4K；
   - 有输入视频：480P、720P、1080P、4K。
6. `rawCost → USD → quotaBeforeGroup` 与后端公式一致。
7. 表达式缺少请求探针时显示明确提示。
8. 版本前缀表达式可试算，浏览器全局、成员访问和通用 JavaScript 语法被白名单拒绝。

### 9.2 表单集成测试

1. 新增模型并填写预扣上界后，生成：

   ```json
   {
     "model-name": 250000
   }
   ```

2. 修改已有模型时只更新当前模型，不覆盖其他模型。
3. 清空字段时只删除当前模型键。
4. 批量复制表达式价格时，必须显式决定是否复制预扣上界；推荐默认一并复制，并在成功提示中说明。
5. 保存并重新获取系统设置后，字段正确回填。
6. `0`、负数、小数、非数字和大于 `1,073,741,823` 的值不能提交。

## 11. 风险与回滚

| 风险 | 控制方式 |
| --- | --- |
| 修复重载后重新出现模型间状态串用 | 用模型名作为明确身份边界，并补切换模型回归测试 |
| 管理员仍把试算值误认为计费值 | 分区、改标题、增加醒目说明，真实预扣字段使用不同名称 |
| 本地草稿损坏或旧版本不兼容 | 版本化 key、合法化读取、提供恢复默认值 |
| 可视化模式覆盖 JSON 模式中的其他模型配置 | 读整张映射，只修改当前模型键 |
| 请求探针与后端 `param()` 语义漂移 | 使用后端真实 `480p/720p/1080p/4k` 值，并用相同输入建立前后端对照用例 |
| 配额展示使用过期 `QuotaPerUnit` | 使用当前系统配置；不可用时不猜测配额 |
| 超大预扣 Token 形成长期不可用配置 | 前后端统一最大值，保存校验与运行时读取双重拒绝 |
| 本地表达式执行浏览器通用 JavaScript | 求值前执行严格 Token 白名单；服务端求值始终是计费权威 |
| 实际费用超过预扣上界 | 不自动突破上界补扣，任务计费进入 `debt` 并保留可审计错误 |
| 异步表达式使用 Header/时间函数导致两次求值不一致 | 页面提示，后端任务创建 fail-closed |

回滚时可按阶段独立处理：

1. 试算器本地草稿与探针均为前端能力，可单独回滚；
2. 可视化预扣字段只是现有 Option 的新入口，回滚前端不会破坏已保存配置；
3. 后端计费热路径和数据库未改变，无需数据回滚。

## 12. 最终建议

本问题不应通过「把输入/输出 Token 一起塞进 `billing_expr`」或「新增两个数据库列」修复。正确做法是拆开两个业务概念：

- **费用试算器**负责方便管理员验证表达式，允许保存浏览器本地草稿，但不参与真实计费；
- **异步任务预扣 Token 上界**通过现有服务器配置持久化，是视频任务预扣阶段代入 `c` 的唯一事实。

三个阶段均已完成。当前实现将试算草稿、服务器预扣配置和任务冻结快照保持为三个独立事实，并通过前端单元测试、后端计费回归和三个视频渠道的 mock E2E 验证 Token 回算与退款链路。
