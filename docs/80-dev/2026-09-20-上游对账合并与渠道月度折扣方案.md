# 上游对账合并与渠道月度折扣方案

> 本文记录已实施的业务范围、迁移规则与验收边界。上游折扣默认 1 以用户最新确认为准。
> 代码已在本地实现；真实账单、外部数据库升级和生产交付仍未完成验收，不代表生产已发布。

> 后续调整见[上游名称与渠道展开方案](2026-09-20-上游对账名称与渠道展开调整方案.md)：
> 增加上游显示名称、合并为渠道行展开模型、移除折扣编辑的人工原因输入。该方案已实施；
> 下文的旧层级与原因必填描述保留为本轮实现基线的历史记录，不再描述当前页面现状。

> 金额范围调整见[渠道测试费用纳入上游汇总分析与方案](2026-09-21-渠道测试费用纳入上游汇总分析与方案.md)：
> 有可靠计价依据的测试费用已计入上游原价和折后参考金额（2026-09-21 实施，历史恢复率待数据复核）；
> 下文“测试不进入金额”仅为该轮实施前的基线记录。客户账单与钱包继续排除测试。

## 问题与目标

现有“上游对账”和“按上游 URL 汇总”围绕同一份平台用量提供两个入口，运维需要切换视角，
且无法在页面内集中维护渠道折扣。本次合并为独立的“上游对账”功能，使运维能够按账期和
上游 URL 查看汇总、维护渠道月度折扣、查找调用证据并导出数据，在线下完成与上游的核对。

### 用户已确认的业务范围

| 项目 | 确认结论 |
| --- | --- |
| 功能定位 | 辅助人工核对，系统提供证据与数据，实际对账在线下完成 |
| 上游资料 | 上游提供汇总账单、调用明细与折扣 |
| 账单归组 | 一个上游 URL 对应一份账单，涵盖该 URL 下全部渠道 |
| 原价基数 | 使用本地账单的原价汇总；用户确认本地和上游都按模型官方原价计费 |
| 折扣口径 | 统一为原价乘一个综合系数，例如原价 1,000、系数 0.8，对应 800；折扣来源由运维自行折算 |
| 配置粒度 | 每个渠道每个月可人工填写和修改，不按模型维护不同折扣 |
| 月份继承 | 新月份自动沿用上个月的渠道折扣，标明来源月份；未配置时默认系数为 1 |
| 逐笔证据 | 同时展示我们的请求 ID 和上游请求 ID |
| 退款等差异 | 本期不增加专项处理，保留本地数据口径，由运维线下判断 |

“双方官方原价一致”是用户提供的业务前提，不是本次通过真实账单独立验证的结论。
系统计算结果称为“折后参考金额”，不称为已核实上游成本或最终应付金额。

### 成功标准与非目标

运维在同一个入口完成“选择月份 → 找到上游 URL → 检查渠道折扣 → 查看汇总 → 查找或导出
调用明细”，无需在两个上游页面之间切换。相同筛选、相同数据版本下，模型、渠道与 URL
金额能够解释并勾稽；双方请求 ID 可作为人工查找证据。

本期不做上游账单导入、供应商金额录入、自动逐笔匹配、差异计算、争议处理、对账确认、
关账或付款流程；不建立官方价格维护系统；不拆分协议折扣和充值折扣；不修改客户收费、
余额、退款、Task 结算或 Provider 调用行为。

### 尚需在实施中核实的数据条件

- 现有本地原价投影能否按渠道和模型复用，哪些记录是历史依据完整的金额，哪些仍是估算或未知。
- 不同调用类型实际保存的本地请求 ID、上游请求 ID、平台任务 ID 和上游任务 ID 的位置及覆盖率。
  筛选字段存在不代表历史记录完整。
- 旧月度模型折扣是否存在人工维护值、继承自人工值的历史链、同渠道同月不同值，以及系统自动
  生成的缺省值；审计能否证明复制当时的来源，不以来源月份当前值代替历史值。
- 上游账单的时区、切账时点及记账事件依据是否与本地一致；退款、不收费、流中断及重试等路径
  实际保留哪些调用与用量证据。未核实前仅列为可能差异，不宣称所有路径必然少计。
- 跨客户上游明细查询及导出可复用的查询、任务和文件交付基础设施；不能绕过单客户权限限制。

上述事项通过代码和脱敏样本核实，不重新扩大业务访谈范围，也不因此引入另一套计价体系。

## 优化方案

### 1. 入口与运维操作顺序

拟提供管理员专用“上游对账”独立导航和页面，移除两个上游 Tab 的重复入口；客户账单保留
独立入口，普通用户“我的账单”不受影响。具体路由名称随现有前端路由约定确定。

页面顺序：

1. 选择账单月份；沿用现有上海时区自然月，区间为月初包含、下月月初不包含。
2. 查看或搜索上游 URL 汇总，定位本月要核对的上游。
3. 在该上游内集中查看和编辑渠道当月折扣，优先展示待填写项。
4. 查看模型汇总，展开渠道贡献；同一模型不同计费方式分行。
5. 从 URL、模型或渠道进入带完整筛选的调用明细，可按双方请求 ID 搜索。
6. 导出当前筛选的完整汇总或明细，供运维线下比对与留存。

建议的信息层级为“上游 URL → 上游模型 × 计费方式 → 渠道贡献”；渠道折扣集中编辑区与该层级
并列，避免为了修改一次渠道折扣逐个展开模型。

### 2. 汇总字段与金额口径

| 层级 | 核心展示 |
| --- | --- |
| URL | 原价金额、折后参考金额、渠道数、折扣待填写数、数据完整性提示 |
| 模型 × 计费方式 | 上游模型、计费方式、对应单位用量、原价金额、折后参考金额 |
| 渠道贡献 | 渠道 ID 与名称、用量、原价金额、当月折扣、折后参考金额 |
| 渠道折扣编辑区 | 渠道、当月系数、继承来源月份、修改人和时间、修改入口 |

计算规则：

```text
逐笔折后参考金额 = round(逐笔本地原价金额 × 渠道当月折扣，1 quota)
渠道模型折后参考金额 = 该渠道模型下逐笔折后参考金额之和
渠道折后参考金额 = 该渠道各模型折后参考金额之和
URL 折后参考金额 = 该 URL 下各渠道折后参考金额之和
```

- 原价使用同一筛选范围内的现有本地账单原价口径；不使用客户净扣费代替原价，不另行查当前
  官网价格重算。历史估算、未知等质量标记继续保留。
- 按渠道应用折扣后再聚合，不使用简单平均折扣计算总额；不设置另一套 URL 级或模型级折扣。
- 本期不改变现有退款、免费记录、结算调整与用量识别规则；金额和用量沿用各自已定义的本地
  事实口径，不宣称它们覆盖上游全部扣费。差异由运维在线下核实。
- 复用客户账单原价算法，不等于套用客户账单全部记录过滤条件。上游已有的渠道测试用量与明细
  必须保留；金额仍遵循本地账单口径，只有测试费用记录而无客户结算的调用不能冒充客户原价
  纳入金额。页面和导出注明用量与金额覆盖范围不同，不能从测试用量缺少对应金额推断上游免费。
- 未配置折扣默认系数为 1；历史迁移冲突仍待确认，原价未知不当作零。受影响行的折后参考金额显示未完整，父级不得把
  部分已知金额冒充完整总额；可另列“已配置部分参考金额”，并显示未覆盖渠道数。
- Token、次数和秒数分别汇总，不混合相加；缺失用量保留“未记录”。
- 沿用本地账单的币种、quota 换算和精度规则，页面与导出显式标注单位；如数据存在不同币种，
  分币种展示，不新增隐式汇率转换。
- 使用服务端精确数值计算，统一最小计价粒度和舍入规则；各层从同一明细金额聚合，避免浏览器
  二次运算造成差额。已实现口径为逐笔原价还原后按 1 quota 四舍五入（半值远离零），逐笔乘
  渠道月度系数后按相同规则取整，各层仅求和；这只规定上游报表精度，不修改客户资金或账单口径。

#### 现行产品与架构条款的替换边界

以下为实施时同步到当前事实文档的目标表述。本方案阶段不把它们提前写成现行能力；实现交付时
必须同时调整对应条款，不保留“一律禁止参考金额”和“允许参考金额”两套相反的当前规则。

[产品说明](../10-product/客户与上游对账单产品说明.md)第 8.3 节拟替换为：

> 上游对账允许在“本地与上游采用相同官方原价”的业务前提下，依据已记录的本地计费金额及冻结
> 或有历史证据的计价、折扣事实，沿用本地账单原价投影，结合渠道当月综合折扣计算折后参考金额。
> 原价由历史金额还原时继续标为估算；缺少依据时保留未知。参考金额不代表独立采集的 Provider
> 成本、供应商账单金额或最终应付金额，不证明覆盖所有上游扣费。不通过当前价格回算、手填供应商
> 金额或无依据反推补造历史成本，不生成双方金额差异或自动调整客户资金。

第 8.4 节同步为渠道月度折扣、上月复制、默认 1 及历史冲突规则；第 8.6 节同步为单入口 URL 汇总与渠道折扣
管理，不再描述独立的第三 Tab。第 8.5 节关于不导入供应商账单、不计算双方差异的边界继续保留。
第 9 节关于多次上游重试用量的要求补充实际采集边界：本期展示已持久化的 Provider 用量证据，
尚未覆盖的尝试级事实列为缺口，不把“一次客户结算”宣称为“上游只调用一次”。

[对账架构](../20-architecture/账单计费-客户与上游对账架构.md)接口表及第 7.3 节拟统一为：

> URL 汇总读取已持久化的平台用量、本地账单原价投影和渠道月度折扣，返回原价及折后参考金额
> 与完整性标记。汇总查询保持只读，不物化折扣、不写审计、不回写日志；月度初始化和人工保存
> 分别通过明确的写入操作完成，并按其动作记录审计。页面提供编辑入口不改变查询的只读职责。
> Provider 实际成本与参考金额保持语义区分；参考金额不得进入客户结算或付款依据。

架构中的前端边界和不变量同步说明：客户账单与上游用量各自保留记录范围，参考金额只读复用
本地原价投影，不将二者混成供应商成本事实；修改渠道当月折扣只改变参考展示，不重算正式客户
账单或改写历史导出。实施者按上述替换范围更新权威事实文档，不另建平行合同。

### 3. 渠道月度折扣

新业务键为“账期开始时间＋渠道 ID”。模型和计费方式不再参与折扣唯一性。

- 一个渠道当月所有模型使用同一个综合系数；界面以 `0.8（八折）` 等形式避免把 8 输入为系数。
- 沿用现有合法范围 `0 < 系数 <= 1`；1 表示无折扣（未配置时也是默认值），空值仅表示历史冲突或来源无法确认。本期不支持
  大于 1 的加价系数；当前没有加价渠道的业务证据，不将此假设写成已验证“所有渠道均无加价”。
- 当月尚无配置时，只复制上一个自然月的有效渠道配置，形成当月独立记录并保存来源月份。
  上月无有效值时使用默认系数 1，不向更早月份静默追溯。
- 月度初始化为独立、幂等的写入操作，可在进入月份时由页面自动触发；汇总查询和导出读取不
  隐式生成折扣。初始化只处理未初始化项，不覆盖人工值或迁移冲突待填写项；并发初始化不会
  重复生成，失败时明确提示，不能把未完成初始化误报为已确认折扣。
- 复制完成后，更改上月不级联覆盖本月；更改本月不影响上月或已生成的其他月份。
- 修改包含原因并校验记录版本，保留旧值、新值、操作人和时间。并发修改冲突应提示重新读取，
  不静默覆盖他人的值；审计随配置变更在同一事务提交。
- 编辑入口直接位于对账页的渠道折扣区，不要求运维进入渠道连接配置，也不改变渠道调用行为。
- 月度配置与审计以主数据库为事实源，缓存仅可重建；支持 SQLite、MySQL 和 PostgreSQL。

### 4. 逐笔证据与导出

明细建议包含：调用时间、渠道 ID 和名称、客户模型与已记录的上游模型、计费方式、对应单位
用量、本地账单原价金额及其质量标记、我们的请求 ID、上游请求 ID。

有独立任务 ID 时另列平台任务 ID 和上游任务 ID，不用任务 ID 冒充请求 ID；缺失 ID 显示
“未记录”，不按时间接近或金额一致推断匹配。保留必要的日志行标识与事件类型，以区分同一请求
的持款、完成或调整证据，不能把每条资金日志都显示为一次新的上游调用。

汇总与明细共享账期、URL 对应渠道集合、模型、计费方式和 ID 等适用筛选。金额字段需与原价
投影保持一致；若一笔金额只能在已有生命周期投影中形成，不新增重复计费行凑齐合计。

导出要求：

- 导出完整筛选结果，不仅是当前页；数据量较大时复用已有异步导出与受保护文件交付设施，
  保留任务预算、权限检查和到期策略，不另建无界同步下载。
- 导出时记录生成时间、账期的时区及实际起止时刻、筛选、URL 归组说明及本次使用的渠道折扣值和版本；后续修改折扣
  不改写已经生成的文件。这只是导出数据的一致性，不引入对账确认或关账版本流程。
- 页面汇总与导出共用查询口径；跨客户上游导出提供明确管理员边界，不放宽现有单客户导出接口。
- URL 与 Provider 标识仅管理员可见；不输出密钥、完整签名 URL、原始 Provider 响应或 Task 私有
  正文。CSV 处理不可信文本时沿用现有转义及表格公式注入防护。

### 5. URL 归组与历史范围

拟沿用现有规范化规则：域名大小写、默认端口和末尾斜线可等价；协议、非默认端口和基础路径
不同仍分组。地址缺失、无效或不能安全展示的渠道分别保留，不合成一个“未知上游”。

本期沿用“按渠道当前基础 URL 归组”，页面和导出明确标注。修改渠道地址可能改变旧月份在新查询
中的分组，不能把它包装成请求发生时的供应商归属；已导出文件保留当次内容。暂不增加历史供应商
身份、账号台账或归属冻结系统。渠道删除等情况下保留可查历史与缺失提示，不静默丢掉账单数据。

### 6. 现有折扣数据迁移

从模型级月度折扣改为渠道级，不能直接取第一条或平均旧折扣。拟采用一次性迁移：

1. 只读盘点同渠道同月份的旧记录及审计，区分人工配置、继承自人工配置、系统自动缺省和来源
   不明记录，输出脱敏迁移与冲突清单。不得仅凭 `reason` 文本、操作人 ID 或系数是否等于 1
   判断来源；现有自动初始化也会填写操作人，人工无折扣也可能为 1。
2. 有效迁移候选包括人工确认值、系统默认系数 1，以及有审计证明的继承值。
   连续多月复制不使配置失效；系统默认 1 与人工配置 1 均可迁移，但不把系统默认标为人工确认。
3. 以各月份当时保存的值及其来源证据判断，不用来源月份后来更正的值覆盖后代月份。例如七月
   人工设为 0.85、八月复制 0.85 后，七月更正为 0.7，迁移应保留七月 0.7、八月 0.85；不能
   因二者当前值不同就认定八月继承无效。复制时来源版本需由历史审计等证据核实，不能凭当前
   `CopiedFromPeriod` 和祖先当前值猜测；证据不足的对应渠道月份进入待填写清单。
4. 同渠道同月有效候选系数全部一致，且证据足以支持统一渠道口径时，收敛为一条月度记录，保留
   来源及审计引用。混有其他模型的来源不明记录、无法证明渠道统一口径时仍待填写，
   不把局部模型折扣自动推广为渠道事实。不同有效系数冲突时也待填写，不取第一条、不平均。
   实现以当月留存日志核对模型 × 计费方式范围：候选必须覆盖全部已记录组合，且至少有一条用量证据；
   无日志、身份或计费方式未知、组合缺少候选时待确认。读取失败返回错误，不为该渠道月份落配置。
   不用当前渠道模型清单推断历史范围；已有渠道月度记录保持不变，先前迁移结果另行人工核对。
5. 已迁移的有效继承值可以作为下月初始化来源；冲突及来源不明的待确认项不能被
   自动继承绕过。迁移追溯是在核实已经发生的复制事实，不是在运行时跨过缺失月份寻找旧折扣；
   日常初始化仍只使用上一个自然月有效渠道配置，不从更早月份静默回填空月。
6. 验证迁移幂等和三数据库兼容性，切换运行时唯一读取来源；不长期保留两套折扣优先级或双读双写。

旧审计事实保留，不删除或伪造人工操作历史。具体表结构与旧记录保留方式由盘点结果决定，
实施前形成可审查迁移清单，不在未知存量数据上直接执行破坏性变更。
是否有有效继承链、冲突及需要人工补填的数量，以盘点结果为准，不预设迁移必然造成大范围断链。

## 验证方式与验收清单

### 核心算例

同一 URL 下，渠道甲原价 1,000、系数 0.8，渠道乙原价 2,000、系数 0.9：

- URL 原价合计 3,000，折后参考合计 2,600；模型拆分后的渠道贡献与上层金额一致。
- 甲次月自动得到 0.8 并标记来源月份；修改次月为 0.7，不改变上月。
- 首次配置的渠道丙原价 500、无上月折扣，使用默认系数 1；完整原价合计为 3,500，折后参考
  合计为 3,100。查询不写配置；首次人工保存使用版本 0。

折扣迁移补充算例：

- 七月人工 0.85，八月、九月依次复制且审计完整，同月各模型有效值一致且无未确认范围：三个
  月份均可迁移，不因八月、九月属于自动复制而断链，十月可从九月继承。
- 八月复制七月 0.85 后，七月更正为 0.7：迁移后八月仍为 0.85；依据当时审计验证来源，而非
  强制各月当前值相同。
- 七月系统默认 1、八月复制 1，审计证据一致时两月均可迁移；人工无折扣 1 同样可继承，
  不因系数为 1 而误判为缺失。
- 同渠道同月两个模型有效值分别为 0.8、0.9，或来源证据无法证明统一口径：只将受影响渠道月份
  列为待填写，不平均、不选取其一，也不由月份初始化覆盖该冲突。

### 必须验证的行为

- 同一个月同一个渠道只有一个折扣，所有模型及计费方式使用它；默认 1、人工值、继承值与历史待确认状态明确区分。
- 上月值复制后独立保存；同月重复访问、并发初始化、并发修改与修改审计正确；汇总查询与导出
  读取不写折扣或审计，月度初始化与人工保存通过各自写入操作完成。
- 旧模型折扣冲突、多月人工来源继承、来源月后续更正、系统缺省 1、人工无折扣 1、证据缺失及
  迁移重跑均按既定规则处理。
- 原价未知、用量未记录和上游 ID 缺失不变成零、假 ID 或完整金额；保留原价估算标记。
- 双方请求 ID 对应展示；异步任务标识独立，不把结算调整当作多次调用；不改变现有退款语义。
- 原有渠道测试用量和明细在合并后仍可见，不套用客户账单过滤条件误删；测试用量与客户金额
  覆盖不同得到明确说明，不能填零伪造测试成本。
- URL、模型与渠道下钻筛选一致；全量导出超过一页时无截断，生成文件使用确定的折扣版本。
- 页面与导出明确上海时区及账期实际起止时刻，月初、月末与跨月调整按既定本地边界归属；
  未核实上游切账规则时不宣称两边账期等价。
- URL 当前配置变化按说明影响归组；金额、原日志与已生成文件不被改写。
- 普通用户无法查询上游信息、修改折扣或下载管理员导出；中英文界面含义一致。
- 三数据库约束、迁移及并发行为经过对应验证，不能用 SQLite 通过替代另两种数据库结论。

后端测试按受影响合同选择最窄范围，使用确定性算例和项目要求的断言库；前端执行相关组件测试及
类型、构建等必要检查。本文及后续文档修改执行 `task docs:check`、`task ai:check`；若后续修改
公开 API 文档，再执行 `cd web && bun run docs:validate`。

## 风险、待证据项与后续动作

| 风险或待证据项 | 处理边界 |
| --- | --- |
| 本地原价存在还原误差或历史缺失 | 复用已有质量标记；不宣传为已核实上游金额，不用当前价格补造 |
| 请求 ID 覆盖不完整 | 核实真实脱敏样本，显示未记录；不承诺自动匹配 |
| 旧模型折扣不能统一或继承来源证据缺失 | 保留有历史证据的人工来源继承链；仅列出受影响渠道月份待填写，不用祖先当前值覆盖历史复制值 |
| 当前 URL 使历史归组变化 | 页面和导出注明归组依据，本期不新增历史归属体系 |
| 未交付后客户不收费或退款，但上游可能收费 | 本地金额变化不证明上游免费或退款；保留现有记录，由运维线下核实，不新增退款对账流程 |
| 流式中断后双方计量范围可能不同 | 客户交付计量不必然等于上游生成计量；实际行为按调用路径和证据核实，不一概断言只记录已交付 Token |
| 一次客户结算可能对应多次上游尝试 | 已持久化的上游用量证据继续保留；未采集尝试不得按零成本处理，本期不新增尝试级成本账本 |
| 渠道测试与客户金额覆盖范围不同 | 已有上游用量包含测试；合并时防止误用客户过滤条件丢失证据，不能宣称当前上游一概漏计测试 |
| 时区、切账时点或记账事件不同 | 本地按上海自然月及既定日志归属；上游可能按其他时区或受理、完成、扣费时点切账，需核实其规则，导出标明本地起止时刻 |
| 跨月退款或异步结算落入不同月份 | 保留本地既定记账口径及关联证据；月份差异由运维线下解释，不新增自动跨期平账 |
| 上游存在大于 1 的加价需求 | 尚无业务证据，本期系数仍限定为折扣；若后续证实该需求，再调整合同，不静默钳制为 1 |
| 导出横跨客户及数据量较大 | 管理员专属权限与现有受保护任务设施，验证预算和文件内容 |

表中的退款、流中断、重试和账期差异是可能的结构性来源，不等于本次已证明每个 Provider 或调用
路径都存在漏计；只有代码、日志与上游脱敏样本共同支持时，才记录为具体缺口。系统提供这些
范围说明和已知证据即可，不扩展为自动匹配、差异金额计算或处置状态机。
