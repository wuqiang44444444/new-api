# Seedance样片模式接入方案

## 1. 问题与目标

将 `draft` 作为统一 ModelArk V3 创建请求中的普通可选参数。客户只看到一个「样片模式」用法，兼容的协议
将参数按原语义发送，由上游决定是否受理。成功样片可用同一客户模型的本站 Task ID 生成成片；两次创建
各自经过已有的鉴权、占款、异步任务、查询、结算和视频交付流程。国内 Vidu 与 FunCloud 作为两步验收基线，
墨行作为上游拒绝的对照，海外 Vidu 暂不纳入本轮上线验收。

网关适配已实施，完成本地隔离 PostgreSQL 和真实渠道验收。供应商账单与目标环境灰度仍待验收。产品方向见
[产品设计](../10-product/Seedance视频与素材产品设计.md#96-样片模式)
和 [Link 架构](../20-architecture/Seedance专用渠道与Link架构.md#62-样片模式)。

## 2. 实施前现状

- `dto/video_contract.go` 的顶层 `Draft` 已是可选布尔指针，北向能解析。现有 Vidu 与 FunCloud adapter
  会拒绝该字段；墨行按完整 ModelArk 请求构造南向请求，已经原样发送该字段，但查询投影不保留样片标记。
  FunCloud 当前查询转换同样未保留 `draft`。有的普通生成 adapter 会缺省补 `720p`。
- 现有 Link `content` 结构和校验不支持 `draft_task`。`model/task_modelark.go` 已有返回字段，但未建立
  本站源 Task 的关系，不能依赖上游回填。

| --- | --- | --- |

| 海外 Vidu `viduq3.1-drama-ab-std` | 使用本地验收库的海外配置。创建返回 HTTP 200，查询回显 `draft: true`，但任务以 `InternalServiceFailure` 失败。仅省略 `draft` 的对照生成成功。 | 受理和回显不等于成功；本轮不启用海外渠道进行上线验收。 |

历史本站 Task；查询时长、MP4 时长和上游用量分别记录，不互相推算。

## 3. 优化方案

### 3.1 统一样片创建请求

- 北向复用可选布尔值 `draft`。共用 ModelArk V3 的 Link 入口都接受省略该字段或显式 `false`，
  两者表示普通生成。在不使用该字段的适配器前消除 `false` 的接入差异，覆盖飞彩、Synlink、CMCC、
  MiniMax 等已有校验，不改变 NEWAPI 原生入口。
- Vidu、FunCloud、墨行、Volcengine、BytePlus、Nexhina 和 ArkMedia 的同形协议原样发送 `draft: true`，
  由当前上游决定是否受理。其它协议按实际字段映射，无法表达这项操作时在预扣前返回不支持。
  上游拒绝时不删字段重发、不转普通生成、不换渠道。
- `true` 且未填分辨率时，同形协议在预扣前确定有效分辨率为 `480p`；显式分辨率沿用常规参数、
  模型约束和计费检查，不因 `draft` 被改写。计价与发送使用同一有效值。去掉针对 Vidu 和
  FunCloud 的 Draft 单独拒绝，保留其余参数校验。
- 在现有 attempt/Task 快照中冻结样片提交意图，查询转换保留可信的样片标记。只有匹配任务的可信
  终态为 `succeeded`、明确返回 `draft: true` 且结果有效，才交付样片并允许引用。HTTP 200、
  提交回显和 480p 结果不能单独证明样片成功。身份、状态、标记与结果地址来自同一条类型化观测。
  样片分辨率显式为空或只含空白时在预扣前拒绝。

### 3.2 复用源任务生成成片

1. 复用现有 Link ModelArk V3 入口。首发成片请求只接收 `model`、单个 `content` 项
   `{ "type": "draft_task", "draft_task": { "id": "<本站样片 Task ID>" } }` 和显式 `resolution`。
   国内 Vidu 与 FunCloud 使用已实测的 `1080p`。`draft: false` 等同省略，拒绝 `draft: true`、
   混用内容和其余字段。南向不补写普通生成默认值，也不重发源任务的提示词、素材、时长、画幅或音频。
2. Link 专用校验使用 `model.GetByTaskIDForApp(userID, appID, id)` 读取唯一源 Task，校验未删除、
   已可信成功、确认为样片且属于同一客户模型。在 `ResolveSeedanceChannel` 选渠前登记源任务 pin。
   `specificChannelID` 只约束当前已获授权的路由，仍检查合同授权、渠道启停和当前模型映射。模型已改绑
   或源渠道不可复用时，返回脱敏的样片引用错误，不切回旧渠道或误报普通 `503 model_not_found`；
   不存在与跨作用域引用使用同一公开错误。真实存储或依赖故障沿用服务不可用语义。
3. 复用 `ContextKeyOriginTasks`、`ApplyChannelPin` 和 `RelayInfo.OriginTasks` / `OriginTaskRef`，
   不复制原生 `applyOriginTaskIntent` 的查找流程，也不把仅按用户校验的原生入口当作 Link 授权。
   补 Link 插件桥接，将本站源任务 ID 和可信上游 ID 提供给创建 hook。适配器仅在南向替换
   `draft_task.id` 并发送同一上游模型；预扣依赖的私有事实由宿主读取。接线优先放到 Link 专用文件，
   复用 pin 不改变 Link 每次意图只发送一次的规则。
4. 首发将源任务冻结的渠道、上游模型、协议、连接根地址、创建路径、查询模板、代理和受保护凭据
   与当前连接逐项比较。不同或缺必要证据时在 hold 前拒绝。1.6.3 仅冻结查询模板的已有样片可在匹配
   已登记的端点对时复用。素材租户确认不能单独证明视频任务域连续，不使用旧 Key、跨渠道探测或 hash 等价
   证明。账号是否开放样片输入由上游决定。仅在有明确协议规则和可信上游 `created_at` 时本地检查期限：
   国内 Vidu 对 2026-10-28 10:00（UTC+8）及之后创建的源样片规定 14 天，此前为 7 天；缺少经核实的
   期限规则或可信创建时间时由上游判断。不用本站提交时间、文件交付或签名期限代替。
5. 将本站源 Task ID 冻结在现有 create attempt 快照，取得可信上游任务 ID 后，在创建成片 Task 和
   转移占款的同一事务写入 `Task.PrivateData`。恢复沿用同一事实。`ToModelArkVideoTask` 已从冻结的
   本站关系生成单查与列表的 `draft_task_id`，历史无关系时省略该字段。上游省略关联或返回同一任务的另一种 ID 均不改写本站关系；
   不重写旧 Task、不另建样片表。

### 3.3 非预期结果与退款

| 可信观测 | 客户任务与交付 | 资金与上游事实 |
| --- | --- | --- |
| 创建明确被拒，或取得可信的上游业务失败终态 | 沿用既有失败和脱敏错误，不降级交付 | 释放本次 attempt 占款，或对已建立的失败 Task 沿用幂等退款路径 |
| `draft: true` 请求取得同一任务的可信成功终态，但明确返回 `draft: false` | 本站样片履约失败，不交付普通视频，也不允许将它引用为样片 | 进入既有客户失败资金入口，幂等释放或退还本次费用。保留真实上游成功状态和成本证据；未知的上游金额保持未知 |
| 成片请求取得可信成功终态，但明确返回 `draft: true` | 成片履约失败，禁止交付该样片 | 退还成片费用，独立记录供应商成本证据；源样片状态与费用保持原值 |
| 样片成功响应缺少可信 `draft`，或任一步本次轮询不可采信 | 暂不确认样片、不交付、不开放引用。沿用有界补查，仍无法确认时进入现有对账 | 不以单次缺失或不可采信的响应触发收费、失败或退款。由后续可信证据或现有运营对账确定，禁止自动重发 |

现有 `UpstreamContractViolation` 只进入对账，不能代替明确的客户失败与退款接线。站内履约失败和上游
业务成功分开保存，不伪造上游失败。成片失败、未知或退款只影响成片本身，源样片的状态与账单不变。

### 3.4 首发计费边界

- 样片和成片只使用既有 Token 计价合同，要求可信的归一用量和安全预扣上界。宿主验证选中计价分支的金额
  为实测 Token 乘以由冻结条件决定的费率，预扣与结算使用同一费率。未满足条件的样片或成片
  请求在 hold 前明确拒绝，普通视频仍走原价格。首发不开放按秒或按次的样片操作，也不新增 `draft`
  表达式维度。生产发布前核对供应商真实账单和客户价格合同；实测 Token 数量不证明单价，也不据此报价。
- 两步独立建立 durable attempt，各自预扣并持久化 `sending` 后单次发送。成片预扣用本步目标分辨率、
  源任务可信的冻结输入及既有安全上界，缺估价必要事实时拒绝。成功后各按本任务的可信 Token 和冻结
  价格结算。补查可合并同一任务晚到的可信用量，并保留既有结果、样片标记和创建时间。不用样片用量、
  文件时长或成片查询时长折算成片费用。

### 3.5 元数据、文档与发布

- 客户侧只说明一个「样片模式」，`draft` 按普通参数记录类型和默认值，通过示例解释 `draft_task`。
  不新增两个公开开关，不展示上游开通或验收状态。协议透传不表示承诺创建成功。
- 实现后同步模型目录投影、Seedance V 专页、ModelArk V3 公共合同和 OpenAPI。按现有插件版本流程发布
  新制品。北向新增操作要求当前固定制品声明样片合同。回退到旧制品关闭相关新建入口，已冻结版本继续用于
  在途任务的查询、交付和结算。
- 国内 Vidu 与 FunCloud 纳入完整网关上线验收；墨行覆盖上游拒绝与占款释放，海外 Vidu 暂不纳入本轮。

## 4. 验证与发布条件

| 验证范围 | 通过条件 |
| --- | --- |
| 统一参数 | 全部 Link ModelArk V3 路径上，省略 `draft` 或显式 `false` 与普通生成一致；同形协议对 `true` 只发送一次；显式分辨率不被改写，省略时按有效 480p 估价与发送 |
| 源任务、选渠与关联脱敏 | 模型改绑、凭据变化、跨用户/应用/渠道、未成功、删除、普通视频或已知过期的样片均在 hold 前拒绝；越权与不存在不可区分；单查、列表、恢复只使用本站源关系 |
| 终态与资金 | 覆盖上游拒绝、可信失败、明确返回 `draft: false` 的成功响应、缺标记及其后恢复；不交付普通视频；退款幂等；不把无法确认的观测当作失败或已结算 |
| 计费 | 两个任务各自预扣、结算或退款；缺 Token 补查；按秒/按次配置拒绝样片操作且普通生成不受影响；按实测用量、价格合同与供应商账单分别核对 |
| 真实验收 | 国内 Vidu、FunCloud 在隔离网关生成 4 秒 480p 样片并引用本站 ID 得到 1080p 成片；验证实际交付与双账单。墨行真实拒绝不重试，目标环境灰度通过后再公开发布 |

## 5. 实施与验收

2026-11-18 使用隔离 PostgreSQL 网关、临时应用和本地已配渠道验证创建、单查、列表、视频下载和结算。
国内 Vidu 与 FunCloud 的两次创建均在发送前占款，独立转移并按各自确认的 Token 结算。两个模型的成片
在单查与列表中均回显第一步的本站 ID。两个模型的客户账本净额分别与各自两条 Task 的结算额相符。

| 本地渠道 | 样片交付 | 成片交付 | 完成 Token（样片 / 成片） |
| --- | --- | --- | --- |
| 国内 Vidu `seedance-2-5-v` | 854×480，约 4.04 秒 | 1920×1080，约 4.04 秒 | 38,830 / 196,425 |
| FunCloud `seedance-2-5-f` | 854×480，约 4.06 秒 | 1920×1080，约 4.06 秒 | 38,830 / 196,425 |
| 墨行 `seedance-2-5-m` | 独立复验只发送一次，返回 HTTP 400 `invalid_request_error` | 无任务 | 创建 attempt 确认为拒绝，客户预扣全额释放 |

墨行首轮的 HTTP 400 使用了中文参数校验消息，原分类保留为结果未知。已补充仅适用于该协议和样片操作的
拒绝识别，并用另一条独立请求核对释放；首轮意图没有重发。任一响应带有任务 ID 或非空数据载体时仍保留未知。
集成测试同时覆盖缺样片标记后补查、普通视频误交付退款、跨应用或凭据变更拒绝，以及非 Token 价格下预扣前拒绝。
同一组集成测试已在 SQLite、MySQL 5.7.44 和 PostgreSQL 上通过。

真实网关验收确认了输出、Token 用量和客户结算。供应商实际金额仍需凭账单逐项核对。目标环境灰度与生产
发布待验证；本轮价格和预算用于隔离验收，发布价格以账单核对后的合同为准。

文档阶段运行 `task docs:check` 和 `task ai:check`。实现阶段运行受影响的 ModelArk 校验、Vidu 插件、
控制器资金及模型元数据测试，公开文档同时运行 `cd web && bun run docs:validate`。涉及 `relaykit/` 的修改
另运行 `cd relaykit && GOWORK=off go build ./...`。在端到端验证和目标环境灰度前不声明已发布。


## 6. 评审修复与接线

1.6.4 源码修复已纳入本地回归。Volcengine、BytePlus、Nexhina 和 ArkMedia 分别用模拟上游验证请求、
查询、关联改写、结算及冲突回包保留占款。国内 Vidu、FunCloud 和墨行的真实证据仍以第 5 节为准。
样片集成回归通过 SQLite、PostgreSQL 15 和 MySQL 5.7。本地 Vidu 和 FunCloud 的现有计价配置
已使用 4 秒文生视频的冻结条件通过 480p 样片及 1080p 成片的价格校验。
本轮没有新增真实上游请求，生产未发布，供应商账单和目标环境灰度待验收。
