# 方舟显式缓存与小时结算实施方案

Seed 2.1 Lite 的 **Session 观察接入已实现**。渠道 267 已用现有方舟 Key 和 Model ID，通过非 CN 环境的真实三轮续接、重放和推理账本验收。Prefix 保留作对照。客户存储预留与扣费关闭，收费仍需真实小时账单和唯一计量合同。

## 1. 问题与目标

多轮对话需要保留上一轮输入和回复，下一轮只提交新增内容。方舟 Session 使用上一轮响应 ID 续接，首轮即生成回复。现有 Prefix 试点先写入固定前缀，之后的请求可以反复引用原始前缀。两种模式均受上游缓存作用域约束，存储费用可能出现在没有推理调用的小时。观察版支持非流式、纯文本、单条线性 Session。固定前缀继续用于判断存储计量。 [方舟缓存指南](https://console.volcengine.com/ark/region:cn-beijing/docs/context-cache)

| 问题 | 影响 | 拟解决方式 |
| --- | --- | --- |
| 当前试点只认原始前缀 ID | 客户引用上一轮生成结果会被拒绝 | 在限定应用、模型和渠道的专用分支承载 Session，按轮记录父响应和所有权 |
| 读取命中与存储量分别计费，账单聚合范围待确认 | 直接用命中量、请求输入量或会话数量扣费会产生偏差 | 依据生命周期回放候选用量，用独占账期的真实存储明细确认用量和归属 |
| 每轮可能新增缓存，回包可能丢失 | 重试可能重复生成和写入，按整个上下文逐轮预留会放大占款 | 每轮发送前持久化幂等和发送许可，按已验证的新增上界预留，已知结果可恢复 |
| 停新或回退期间仍存在存储义务 | 客户可能无法删除，未结算账期和待投递日志积压 | 新写入与存量处理独立，保留授权删除、上游核实、资金释放和日志投递 |

## 2. 当前实际情况

### 已核对的实现和实测

- 非 CN PostgreSQL 库 `yuan_gateway_dev` 的渠道 267 已用现有 Key 和 Model ID 验证 Prefix 与 Session。Prefix 的 6 次成功创建均无输出，3 次成功复用均引用根前缀。Session 已从直连和网关验证三轮逐轮续接，第三轮成功复述第二轮独有的信息。
- 宿主 `openai_responses.create` 沿用现有鉴权、限流和插件选渠前的接点。GET 保留插件 Task。Session、新写入开关、DELETE 与系统任务的改动集中在方舟专用文件。共享 DTO、通用选渠和普通推理定价沿用现有实现。共享余额和正式账单的接点见第 4 节。 [公共路由](../../router/task-plugin-protocol-router.go) · [Session 处理](../../controller/ark_session_cache.go)
- `ArkPrefixCache` 同时承载发送尝试、幂等回执、逐轮链、资源状态、推理预留和日志投递标记。`ArkPrefixCacheHour` 承载逐资源存储证据和结算事实。当前新增的候选回放可比较同时存活峰值和逐资源累计，输出供对账使用。共享范围收费和自动取证仍取决于真实账单。 [资源表](../../model/ark_prefix_cache.go) · [推理结算](../../model/ark_session_billing.go) · [候选回放](../../model/ark_cache_shadow.go)
- Root 入口 `POST /api/billing/admin/ark-prefix-cache-hours` 接受已冻结计量口径的人工逐资源小时证据。Session 还须先完成推理结算。缺少较早小时证据时，后续小时等待，保障期满释放未结预留。观察写入保持零存储预留，生产收费闸门仍关闭。 [证据入口](../../controller/ark_prefix_cache.go) · [存储结算](../../model/ark_prefix_cache_billing.go)
- 隔离库已支持 Session 自动结算试验。启用 `local_session_storage` 的本地开发构建仅能在回环地址的非 CN `yuan_gateway_dev` 专用 schema 中使用，并固定连接本地模拟上游。每轮以输入减读取命中再加输出作为试验新增量，按实际生命周期触及的闭合小时结算。该计量版本只由后台从持久事实生成小时记录，拒绝人工录入。普通构建不可开启此配置，生产仍待真实计量合同。 [本地计量](../../model/ark_session_storage.go) · [本地构建限制](../../setting/ark_cache_local_dev.go)
- 停新后的隔离库继续恢复本地试验存量。已落库的可信回执可以在资金期限后完成推理结算和小时补结，缺少可信回执仍按原资金期限释放。存储按生命周期与账期的正长度交集计量。试验记录误恢复到普通环境时，不参与结算、补投、候选回放或删除出站。 [小时结算](../../model/ark_prefix_cache_billing.go) · [试验存量过滤](../../model/ark_session_storage.go)
- Session 钱包预留随每轮发送许可提交。可信上游 ID、推理计价和用量先落库，随后原子确认扣费、返还余额并生成待投递日志。无需保存原始 Provider 响应。同键重放可向原作用域回读已知结果。到期或已删除的成功响应无法回读时返回 `410`。结果未知且保留可信上游 ID 的孤立资源由后台核实和清理，未取得 ID 的记录保留未知。 [Session 结算恢复](../../model/ark_session_billing.go) · [后台核实](../../service/ark_cache_deletion.go)

## 3. 优化方案

### 阶段一 · Session 实测与计量证据

非流式三轮功能验证使用现有 Key 和固定 Model ID，网关联调使用 `./start.sh` 的非 CN 库。第一轮保存响应 A。第二轮引用 A，新增独有的合成信息，并保存响应 B。第三轮只引用 B，要求复述该信息，验证续接内容、响应链、读取命中及推理用量。三轮使用相同的短绝对到期时间并逐个确认删除。用独立合成文本、短 TTL、小输出、串行三轮作为首轮探针范围。渠道负责人在运行前登记窗口与供应商预算。

| 实验 | 操作 | 所需证据 |
| --- | --- | --- |
| Session 逐轮写入 | 分别在独占窗口运行一轮和三轮，控制输入输出大小。对比相邻轮的响应、到期时间和账单 | 确认每轮实际新增量、共享内容、是否继承到期和逐轮存储的上界 |
| 新写入及读取对照 | 单独验证 `store:false` 或 `caching.type=disabled` 的行为，记录是否报错、命中、续链和出现存储费 | 两项仅作行为对照。正式 Session 逐轮使用已发布的字段组合 |
| 单资源跨整点 | 将缓存跨整点保留，采集到期、提前删除和无访问的自然小时。用独占样本覆盖整点恰好创建或结束 | 核对计费时区、每小时覆盖、写入起点和末小时截止 |
| 固定前缀峰值 | 同小时分别让 10k 和 20k 两前缀错开、重叠。独占账期比较只创建和固定前缀多次复用 | 同时存活峰值候选分别为 20k 和 30k，逐前缀累计候选均为 30k。验证复用产物是否另计及其有效期 |
| 相同内容双创建 | 重复创建字节相同、同 TTL 的前缀，使用两个独立幂等键使其重叠，再与单份样本比较 | 独立 ID 与删除行为证明资源可分别操作。账单用于判定存储是否合并 |
| 删除与重算 | 让同配置的多轮 Session 分别自然到期、删除末轮、删除中间轮后续接 | 区分删除确认、404 和结果未知，验证重算造成的写入和受影响账期 |
| 归属与接入范围 | 两个测试应用分别执行、错开与重叠。若拟生产使用 `ep-…`，在该接入范围重做关键实验 | 识别账单实际使用的账号、项目、接入点、模型或其他聚合键，证明能唯一映射到收费承担方 |

取证优先从方舟费用中心的「账单详情 → 计费项 → 明细」导出缓存存储项，同时验证 `ListBillDetail` 能否返回同等字段。记录账期、实例或计费范围标识、明细 ID、用量、单位、原价、优惠及应付金额。保留脱敏逐轮数据和逐小时复算表。使用足以跨过展示精度的合成样本，注意明细出账延迟，并在独立样本复验。缺少明细保持待核实，零用量须有完整覆盖或其他明确证据。 [费用中心明细接口](https://docs.volcengine.com/docs/billing-center/list-bill-detail-page-query-bill-details?lang=zh)

现有 `cmd/verify-ark-prefix-cache` 仅作 Prefix 对照。默认校验计划，显式执行才从环境读取 `ARK_API_KEY` 并发往方舟，计划要求 `ep-…`。Session 三轮使用独立的非流式探针，输出脱敏的响应 ID 关联、时间和用量。上游结果未知时停止该组，沿原作用域核实。 [Prefix 对照命令](../../cmd/verify-ark-prefix-cache/main.go)

渠道、财务和计费负责人共同签认**唯一计量合同**，冻结适用模式、模型、接入方式、聚合键、归属、账期时区、计量和证据来源、币种及换算、零量判定、延迟及更正规则。接口验证可以先完成。收费试点须能独立复算真实小时用量，且证明生产试点所用范围与实验一致。专用接入点只在其实际提供可验证隔离时解决归属问题。

### 阶段二 · 隔离接入、逐轮状态和存量恢复

观察版复用 `ARK_PREFIX_CACHE_PILOT` 的绑定和限额。Session 按应用及客户模型启用，使用有界 Token 比例定价和钱包结算，最多 8 轮、30 分钟，输出最多 1,024 tokens，默认 512。发送前用父轮已报告的输入加输出、新输入序列化字节数和 256 的包装余量做保守预检，合计超过 8,192 返回 `400 cache_session_context_limit`。因此首轮归一化输入的最大值为 7,936 字节。结算另用方舟回包的实际输入上限 8,192 tokens，返回缺少用量或超出预留时保持未知并走清理。强制合同使用既有 API Key 绑定、逐轮授权、组倍率和折扣，缺少有效合同或精确渠道规则时拒绝新写入。 [用户模型合同定价架构](../20-architecture/账单计费-用户模型合同定价架构.md)

| 操作 | 首版观察合同 |
| --- | --- |
| 创建 / 续接 Session | `POST /v1/responses`，使用已开通的客户模型、纯文本、`caching.type=enabled`、`store:true`，每轮要求 `Idempotency-Key`。首轮传有界 `expire_at`，后续只接当前有效的末轮响应 ID。以试点验证的会话截止时间构造上游到期参数，具体 TTL 语义按实际回包确认。首轮和后续轮均可在试点输出上界内生成回复。 |
| Prefix 对照 | 保持观察试点的创建、固定根复用和删除合同。创建显式传 `prefix:true`，输出为零且不接收 `max_output_tokens`。复用继续引用根 ID。现有试点复用接收 `max_output_tokens` 16–4096，客户端传 `expire_at` 返回 `400`。 |
| 删除 | `DELETE /v1/responses/{response_id}` 按托管 ID、应用和所有者校验，沿冻结的上游作用域执行。额度耗尽的有效应用仍可删除。可信删除幂等回放，未知结果进入核实，历史结算独立推进。平台清理按资源发起、有权限校验和审计。 |

保留现有宿主 POST 的单一注册，试点分支放在鉴权、限流之后和插件选渠之前。只对显式启用的 `user_id + app_id + 客户模型 + 渠道` 受理 Session 首轮。托管 ID 的续接先校验归属、模式、访问和到期，再固定到创建时的连接作用域。试点仍使用隔离的火山渠道，原生模型列表为空，拒绝代理、参数覆盖、头覆盖及多 Key。GET 保留插件 Task 语义。原生 adapter、通用分发及共享 DTO 沿用原实现。若启用状态下无法保持其他模型的原生行为一致，再评审专用入口。 [路由接点](../../router/task-plugin-protocol-router.go) · [硬约束](../00-context/硬约束.md#7-newapi-原生代码最小入侵)

- **幂等与权限。** 同应用、同操作、同键摘要唯一，幂等键上限 191 字节。缺失或非法幂等键返回 `400 invalid_idempotency_key`，同键异参返回 `409 idempotency_conflict`。同键进行中或结果未知返回 `409`，已成功返回同一响应及合同约定的结果。不存在、非本应用或不可引用的 ID 返回统一 `404`。写入限额用 `429`，余额不足沿用现有合同。每个父响应仅允许一轮未决或成功续接。方舟明确拒绝且返回可确认的错误码时，同一事务记录拒绝并释放父轮续接名额。原键重放拒绝，客户可用新键续接。网络断连、未知 4xx 或 5xx 保持未知并保留原名额。渠道写入速率限制按已发生的出站尝试统计，明确拒绝仍计入；当前一渠道一次绑定一个应用。逐轮冻结通道、身份、用量和价格。 [现有图片幂等](../../middleware/image_create_idempotency.go) · [方舟错误说明](https://console.volcengine.com/ark/region:cn-beijing/docs/error-codes)
- **发送、结算与回执。** Session 在发送前原子提交发送许可、钱包及 API Key 推理预留。观察模式的存储预留和扣费均为零。可信回复在进程可用时优先耐久落库，单次短暂失败只重试本地写入。推理结算随后扣费、退差额并安排消费日志投递，成功前确认资金事实。消费日志按同一事件补投，已排队日志不受后来关闭消费日志开关影响。正式账单确认检查该客户和账期是否还有未投递的已结算事件。固定 Prefix 对照沿用原生同步推理计费，回执与原生推理扣费依然是独立操作，收费前须单独验收该接口的崩溃窗口。 [推理结算](../../model/ark_session_billing.go) · [正式账单检查](../../model/ark_cache_statement.go)
- **未知结果与资金保障。** HTTP 等待上限 60 秒。Session 自发送许可提交计 180 秒后，后台可释放未获可信计价证据的推理预留，平台承担潜在成本，供应商结果仍为未知。已持久化的可信计价事实继续按原金额结算。该规则只覆盖同步 Session 推理；视频创建的 24 小时保障继续按 ADR-0021。进程在可信回包落库前退出时，未持久化的回包无法恢复。已知上游 ID 的孤立响应继续核实和清理。无 ID 时不自动重发，试点使用的关联标记仅用于对账。固定 Prefix 的过期发送许可也转入未知，已存在的存储预留沿原资金期限处理。结算或投递失败后单独写入重试时间，计量金额超预留时暂停对应计量版本的新占款，到原资金期限释放未结预留。 [后台任务](../../service/ark_prefix_cache.go) · [推理恢复](../../model/ark_session_billing.go) · [异步任务计费架构](../20-architecture/账单计费-异步任务与计费事实架构.md)
- **停新与凭据轮换。** 缺少有效配置时，现有 POST 拦截保留托管 ID 命名空间，普通 Responses 继续路由。存量 DELETE、Root 清理和已到期的后台任务独立于新写入开关。用户或 Key 禁用后由运维在原作用域清理已知资源。轮换上游凭据前停新，清理剩余响应或等待其到期，核对资金和日志后再轮换。原凭据不可用且已过期时停止后台探测，保留未知删除证据。 [DELETE 注册](../../router/ark-prefix-cache-router.go) · [删除核实](../../service/ark_cache_deletion.go)
- **持久化与敏感数据。** `ArkPrefixCache` 保存发送尝试、幂等、逐轮链、资源、推理资金及投递状态，`ArkPrefixCacheHour` 保存逐资源小时证据和存储结算。Session 使用钱包和现有 Token 比例价格，真实供应商存储范围冻结前保留这两个模型。Prompt、响应原文和密钥不进入业务表或普通日志；受控请求证据沿用已有权限。 [资源模型](../../model/ark_prefix_cache.go) · [请求证据硬约束](../00-context/硬约束.md#6-安全与数据)

### 阶段三 · 自动取证、预留与小时结算

1. **选定一个权威来源。** 若主库可观测的量和生命周期可稳定复算方舟账单，使用本地回放结算，方舟明细持续复核。若可信用量仅由账单提供，按小时自动拉取或从授权渠道批量导入，保存来源明细、覆盖范围和更正证据。人工逐资源小时入口只用于联调及异常复核。证据缺失、导入滞后和关账积压须可监测。无法拆分的共享费用留在供应商对账侧。
2. **按冻结范围结算。** 用主库影子回放并列核对逐资源累计和按范围同时存活峰值。候选区间左闭右开，整点继承存活量，同一时刻合并处理；影响结果的未知创建、删除或写入只阻塞相应范围和小时。确认共享峰值时以计费范围、账期和费用类型唯一结算，分开保存参与资源及证据。逐资源方案以单资源作计费对象。会话可用于本地归集，客户结算范围须有可验证归属。Redis 如用于展示，只保存可重建结果。
3. **控制每轮预留。** 出站前校验轮数、输入输出、TTL、应用活跃量、总占款及渠道敞口。以已验证的本轮新增用量上界、可能触及的小时和冻结单价计算预留。实际写入量与结束时间可信后，在资金事务中收缩剩余预留。推理输入和缓存命中只作为实验代理字段。7 天有效期在非整点起始时可能涉及 169 个自然小时，首个收费试点按最多 30 分钟设计，最多涉及两个自然小时。对未知量保留有界预留，缺乏可信上界时收费保持关闭。
4. **维持账本一致。** 冻结客户计费用量、单位、价格或档位、币种和 quota 换算，分别记录方舟原价、应付金额与客户扣款。存储费进入独立 `token·小时` 事件，正常推理沿用现有表达式和输入、命中、输出口径。价格运算使用定点数和现有 checked quota 转换。按闭合小时以同一主库事务写入资金变更、用量快照、预留消耗与待投递标记。MySQL 和 PostgreSQL 用 `lockForUpdate(tx)`，SQLite 用条件写、唯一约束和整事务重试。三库验证小时扫描索引、并发与迁移。 [现有小时结算](../../model/ark_prefix_cache_billing.go) · [计费表达式](../../pkg/billingexpr/expr.md)
5. **可恢复关账。** 用稳定事件 ID 补投日志及报表，重跑不再扣款。额度保障期限和账单延迟窗口以实际连续出账和迟到样本决定，由财务与计费负责人在收费前签认。到保障期仍缺证只释放未结部分，已确认结算保留，迟到差异进入供应商对账及客户账单更正审核。观察或免收记录不自动追扣。若上游实账突破已验证边界，停止受影响范围的新收费写入。

### 阶段四 · 账单与灰度

- 使用日志、API Key 账单、客户账单、日报及导出共同展示存储费、账期、用量和金额。存储事件对推理请求数、输入输出和缓存读取统计贡献为零。价格表中 Seed 2.1 Lite 文本命中输入 ¥0.16／百万 tokens，普通文本输入 ¥0.80／百万 tokens，官方存储 ¥0.017／百万 tokens／小时。渠道 267 的 Session 验收使用 `cache_ratio=0.2`；财务与计费负责人在收费前单独签认目标客户价、币种和毛利假设。现有存储参数 `usd_per_million_token_hour` 使用 USD，需要显式换算。 [方舟模型价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh&redirect=1) [共享消费解析](../../model/billing_reconciliation.go)
- 每条资源冻结计费模式。收费切换使用已证实隔离的范围，或先清理所有会影响新账期的旧模式及旧价格存量，再从下一个完整自然小时开始。运行时拒绝跨计量模式产生新的收费写入。
- 先做追加迁移，确认接入节点和后台版本能识别存量，再开写入。回退时旧版本可接管普通流量，保留支持缓存资源的版本处理删除、核实、预留释放和日志补投。记录切流方式、可接管版本及恢复命令。完成活动资源、未决证据、资金和投递清点后停用相应处理器。

### 观察成本与退出

下一次客户观察试点建议最多 7 天，每应用最多 8 次出站尝试／自然小时，Session TTL 最多 30 分钟，限定一个隔离渠道。若按 9,216 作为单次存储用量的估算代理、每次最多占用两个小时，8 次尝试对应的存储估算约 ¥0.00251，连续七天满负荷约 ¥0.42。实际方舟存储上界仍需独占账期确认，该估算用于审批试验预算。渠道负责人开跑前确认限制，财务每天核对费用中心。建议累计存储预算 ¥1，出现超预算、用量无法归属或到 7 天仍无法确认计量时停新并清理，后续窗口重新审批。Prefix 对照单独登记预算，避免和 Session 混用账期。 [方舟模型价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh&redirect=1)
