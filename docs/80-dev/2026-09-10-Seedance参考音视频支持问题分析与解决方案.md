# Seedance 参考音视频支持问题分析与解决方案

## 1. 问题与目标

**当前执行范围以 §8 为准：FunCloud V2 移除、仅维护 V3；墨行全部暂时排除，由正在进行的
独立整合处理。前文墨行分析保留为证据，不属于本轮待执行清单。**

用户反馈 Seedance 中转渠道的 2.5 模型不支持视频、音频参数。后续明确要求：上游支持的参考音频、
参考视频及统一协议内参数，本地不应额外限制；分析覆盖除 FunCloud V2 外的其它 Seedance 渠道。
用户进一步明确，本原则适用于本文全部渠道：上游没有明确禁止的输入、组合和参数交给上游判断，
本地不先要求“确认支持”或“实测成功”才放行，不把缺少说明解释为不支持。

本文记录代码核查、本地复现、证据边界及实施方案，不是生产发布声明。
本轮非墨行代码实施与最新 V3/TokenSave 在线证据见
[非墨行参考音视频限制清理实施记录](2026-09-10-非墨行参考音视频限制清理实施记录.md)。
以下各阶段“尚未实施”描述对应当时状态；最新实施状态以上述记录为准。
初轮只新增本文。后续墨行专项读取了用户指定原始文档并执行授权的真实 Provider 测试，见 §6；
没有修改业务代码、渠道配置、价格或历史任务。
墨行最新实施建议已重新整理到[墨行 Seedance 统一协议整合方案](2026-09-10-墨行Seedance统一协议整合方案.md)，
按用户补充要求，Fast/Mini 不在本地阻断纯音频参考；本文的跨渠道事实与真实测试记录继续保留。
后续按用户要求直接核对 70 原文与当前代码，逐项删除／保留结论见 §7；该节修正此前对飞彩
HTTPS 限制的错误判断，并区分 FunCloud V2 原文与 V3 实现，不能用不同接口文档互相背书。

### 1.1 范围与术语

- 初轮能力核查范围：除 `funcloud_seedance`（FunCloud V2）外全部 10 个已注册视频协议；当前范围按 §8 收窄，排除墨行。
- 最新退出范围：用户明确 FunCloud 以后只保留 V3；V2 加入移除清单，见 §7.6，不再安排 V2 能力补强。
- 参考视频：`content[].type=video_url`，对应 `video_url.url` 与 `role=reference_video`。
- 参考音频：`content[].type=audio_url`，对应 `audio_url.url` 与 `role=reference_audio`。
- “文本＋音频”：包含文本与参考音频，没有图片或视频；不能与“完全没有文本”混为一谈。
- `generate_audio`：生成结果是否带声音，独立于参考音频输入。支持音频参考不能证明支持这个开关。
- 素材创建与生成时引用是两种能力；本站托管图片的范围不能用于推断直接 URL 音视频输入不支持。
- 本文的“本地通过”仅表示结构校验、模型校验及请求转换通过，不表示 Provider 实际受理或生成成功。

### 1.2 用户目标与既有边界

以[硬约束](../00-context/硬约束.md)、[Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)
及[素材代理架构](../20-architecture/Seedance无状态素材代理架构.md)为权威，本文不建立第二套合同。

本次修复目标是消除缺少依据的限制，并完成上游已支持能力所需的适配。结构合法性、资金安全、
任务事实冻结和本站托管资源校验继续遵循既有约束。供应商私有字段差异由 adapter 吸收，
不要求客户按渠道更换请求形状，也不以静默删除、改义或跨渠道 fallback 代替履约。

本文统一采用以下实施原则，而非逐渠道建立一套“获准后才放行”的能力白名单：

- 对统一北向协议内的输入，上游没有明确禁止就完整发送，由上游判断；该原则同时覆盖媒体类型、
  纯音频、混合组合、数量、URL 表示和标准可选参数。
- “推荐”“常用”“不建议”、示例未出现、缺少成功样本、代码默认 false、本站旧目录未发布某类
  输入，都不能成为 Provider 能力拦截的依据；其它模型或其它供应商的限制也不能移植过来。
- 清理已有无依据的限制，不只是停止新增限制。证据不足时应撤销能力拒绝，不能以“待核实”为由
  无限期保留。需要南向转换的字段应完成适配，不要求客户自行更换请求形状。
- 仅对准确 Provider、接口和模型的明确禁止条款保留相应规则，不扩大范围。单次上游错误按该次
  调用处理，不能自动生成新的本地禁用规则。
- JSON、字段类型等北向结构校验及已有资金、身份、资源边界继续适用；这些边界不能被借用来
  包装未经证实的 Provider 能力限制。已发布条件生效字段按北向合同转换或忽略。

## 2. 当前实际情况

### 2.1 结论与证据等级

| 事项 | 结论 | 证据等级 |

### 2.3 F1：移动云公开目录漏报参考音视频

证据：

- [publicmodel/video.go](../../pkg/publicmodel/video.go) 的 `publicVideoSpec` 移动云分支
  （分析时第 145–152 行）未设置 `allowVideos`、`allowAudios`。
- [移动云请求校验](../../relay/channel/task/seedance/provider_mapped_validation_cmcc.go) 没有拒绝这两种内容。
- [移动云请求头适配](../../relay/channel/task/seedance/request_headers_cmcc.go) 识别视频输入并发送标记。
- [移动云供应商资料](../20-architecture/Seedance模型接入设计/移动云/移动云供应商原始技术文档整理.md)
  记录非加密 REST 的参考音视频示例，以及既往参考视频成功事实；该历史记录不等于本轮重测。

本地复现：文本＋视频、文本＋音频、图片＋音频都能构造南向请求，公开目录却只返回
`text`、`image_url`。按目录生成表单或校验请求的客户端可能隐藏或拒绝本来可以发送的输入。

判断：确定的公开能力投影缺陷，应优先修复，不需要新增视频履约入口。

### 2.4 F2：墨行 2.0 南向输入模式与冻结探针不一致

[请求转换](../../relay/channel/task/seedance/thirdparty/relay.go) 识别参考音视频并生成
`input_mode=multi_modal`、`control_mode=reference`；
[relayBillingModes](../../relay/channel/task/seedance/relay_billing_mode.go) 只遍历图片。

| 本地请求 | 南向模式 | 计费探针模式 |
| --- | --- | --- |
| 文本＋视频 | `multi_modal/reference` | `text/none` |
| 文本＋参考图片＋音频 | `multi_modal/reference` | `multi_image/reference` |

因此请求内容没有丢失，但计费描述与实际发送的输入模式不一致。若部署表达式使用
`_task.input_mode` 或 `_task.control_mode`，可能选择错误档位；本轮未读取生产表达式或真实账单，
不能声称已经多扣、少扣或影响全部客户。

`has_video_input` 在本轮探测中保持正确：真实视频输入为 true，图片或音频不冒充视频。
其它协议也调用这个探针帮助逻辑，但没有相同南向字段的协议应先明确探针语义，不能全局盲改。

### 2.5 F3：FunCloud V3 音频组合限制来自默认拒绝

[providerModelSpec](../../relay/channel/task/seedance/provider_model_specs.go) 包含默认 false 的
`allowAudioOnly`。[FunCloud V3 规格构造](../../relay/channel/task/seedance/funcloud_modelark.go)
设置了允许音频、视频，却未设置该字段；通用校验据此拒绝有音频但没有图片、视频的请求。

代码历史中，通用拒绝条件来自 `b6ec19f3fe`，V3 接入 `478b9ce4fd` 继承了默认值。
该历史只能证明实现来源，不能单独证明开发者意图或上游能力。

供应商 V3 页面列出音频输入并要求文本提示词，本次取得的正文未找到“音频必须搭配图片或视频”的
直接规定。没有找到禁止条款不等于已验证所有组合成功，但也不能把默认 false 当成供应商证据。
按用户要求应解除该组合拦截，让合法音频参考到达上游，无需先取得纯音频成功样本。

[现有音视频数量测试](../../relay/channel/task/seedance/funcloud_modelark_test.go) 在音频前固定添加图片，
没有覆盖文本＋音频，因而不能为该限制提供回归依据。

### 2.6 F4：墨行音频组合限制的补充核对

当前 2.0、Fast、Mini 不允许文本＋音频，2.5 显式允许。该代际区别有外部核对线索：BytePlus LAS
文档明确区分 2.0 与 2.5 的独立音频输入能力。但 LAS 不是墨行接口，也不是本站 BytePlus ModelArk
接入点，不能把其参数或价格当作墨行合同。

[墨行供应商摘要](../20-architecture/Seedance模型接入设计/墨行/墨行供应商原始技术文档整理.md)
和[能力元数据说明](../20-architecture/Seedance模型接入设计/墨行/墨行模型与素材能力元数据.md)
记录了多模态输入与数量，初轮未充分证明音频组合限制。

2026-09-10 补充核对原文：Fast/Mini 写有“audio_url 需配合图片或视频使用，不建议仅传音频”，
其参数表同时允许 audio_url。用户进一步明确：这不作为本地阻断纯音频的依据，文档没有明确禁止就
不额外拦截。因此撤回此前“保留 Fast/Mini 组合拦截”的建议；应解除该拦截并原样发送音频参考，
供应商是否成功留给真实响应判断，不能把本地放行写成上游全部组合已验收。

用户扩充的[准确 2.0 原文](<../70-research/墨行/国内/seedance 2.0.md>)第 435 行明确写有
“不能只传音频，至少同时提供参考图片或参考视频”，补齐此前缺失的证据；这条只适用于该准确模型。
2.5 明确支持纯音频参考。Fast/Mini 本轮原文没有完整列出代码中的 9/3/3 上限，不能用这次阅读
为全部数量限制背书。最新实施建议统一见[墨行专项方案](2026-09-10-墨行Seedance统一协议整合方案.md)。

### 2.7 F5：TokenSave 存在两层阻断，供应商完整能力待核

第一层是 `providerSpec` 未启用视频、音频；第二层是 `RelayCreateRequest` 以 false 调用共用转换，
再次拒绝 `video_url`、`audio_url`。只修改其中一层不能真正开放能力。

[计费与分组运维手册](../40-operations/01-计费与分组运维手册.md) 第 2.4 节明确说明当前仅开放文字、
图片，且完整报价中存在视频输入档位。报价不是 API 证据；本地未开放也不是上游不支持的证据。

没有明确上游禁止依据的两层媒体拦截应移除，不能以本地运维文档“仅开放文字、图片”维持拒绝。
同时核实并完成 TokenSave 自身的媒体字段、输入模式和计费适配，完整发送客户输入；该核对用于
保证履约正确，不是重新建立“上游明确宣布支持才准用”的门槛，也不能直接套用墨行字段。

### 2.8 F6：飞彩模型数量限制有依据，URL 限制需纠正

[飞彩供应商矩阵](../20-architecture/Seedance模型接入设计/飞彩/飞彩供应商原始技术文档整理.md)
明确记录普通模型音频≤3、视频为 0；SD2 两者均为 0；Pro PI 两者均≤3。

当前工作区的飞彩新请求由 [seedance-link 插件](../../plugins/seedance-link/plugin.js) 执行转换，
旧 Go converter 用于对照验证；实施时必须定位实际执行入口，不能只改旧 Go 文件。插件分别检查
音视频 role、URL 表示和数量，并生成 `audios[]`、`videos[]`。

当前显式 `generate_audio`（包括 false）会被拒绝，这是输出声音开关的发布缺口或协议限制，
不等于参考音频不能用。没有明确禁止该标准开关时，不应等待供应商额外确认才解除能力拒绝；
应按统一北向语义完成转换与相关计费，或按合同规定的条件生效规则处理，不能静默丢弃 false。

### 2.9 F7：媒体表示、输入规格与目录表达不能混为一谈

- 官方、Ark 反代、移动云、墨行相关路径接受统一入口允许的 HTTP(S)、Data URL、opaque asset 表示，
  本地通过不证明每种表示均被所选上游接受。
- Synlink 只接受 HTTP(S) 媒体 URL，另有本站托管图片例外；普通 opaque ID 无转换路径，拒绝有
  既有合同依据。这里描述当前实现；Data URL 未取得上游明确禁止依据时，不保留能力拦截，
  按相同媒体字段发送，由上游判断，不能从现有拒绝代码反推不支持。
- 飞彩当前代码对音视频要求 HTTPS、拒绝音视频 Data URL。直接核对 70 原文后确认：音频明确允许
  HTTP/HTTPS，视频参照音频类型；HTTPS 强制限制应删除。Data URL 未明确禁止，按用户原则交给
  上游判断。此前笼统写“与供应商摘要一致”不成立，详见 §7。
- `asset://fhas_*` 只表示本站托管图片。拒绝将其放入音视频槽位是资源类型边界，不是视频生成能力开关。
- 公开 `content_types` 当前描述类型、role、数量，但没有表达音频跨类型依赖或完整 URL 表示限制。
  合理的限制也需要客户可理解的说明；无需把所有 Provider 私有细节公开。

### 2.10 相关标准参数问题：单独列项，不混入参考媒体开关

FunCloud V3 的通用校验还会拒绝 `priority=0`、`return_last_frame=false`、`draft=false`、
`safety_identifier`、`frames=49`，本地已复现；供应商 V3 页面列出了这些标准字段。
含参考音视频的请求也可能因为附带这些字段失败，不能只看媒体节点就排除本地原因。

开放前须补齐对应语义：`frames` 的供应商秒数换算与现有探针取整方式不同；尾帧目前未被 V3 响应
转换完整保留；callback、service tier 等涉及任务身份或价格。不能把“本地尚未实现”描述为
“上游不支持”，也不能只删判断而遗漏结果交付和计费。该项作为后续专项，不扩大本文媒体修复批次。

## 3. 优化方案

以下保留初轮建议及修正过程；当前实施选择以 §8 为准，墨行项暂不执行。具体文件位置和插件迁移状态须在编码时重新核对。

### 3.1 优先修复确定缺陷

| 顺序 | 动作 | 最小修改方向 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 修复移动云目录 | 在既有公开投影启用音视频类型；不新增未经证实的数量限制 | 目录出现两类输入，与请求转换一致 |
| 2 | 修复墨行 2.0 探针 | 让该协议的输入模式与同一类型化请求的南向转换一致 | 文本＋视频、图片＋音频的模式与最终请求匹配 |
| 3 | 消除 FunCloud V3 无依据的音频组合拦截 | 不让未设置布尔值形成业务限制；数量规则只保留准确上游明确上限，结构校验遵循北向合同 | 文本＋音频到达既有 adapter；音频 URL、role、顺序不变 |
| 4 | 清理全部范围内渠道的无依据限制 | 检查校验、转换、插件及公开目录中的重复阻断；没有明确禁止即移除 | 未被上游明确禁止的合法请求完整出站，不以待核实或未实测为由拒绝 |

第 2 项不能简单全局改写所有 `_task.input_mode`：先检查调用者、冻结表达式及不同协议字段含义，
只调整本次确认不一致的边界。历史 Task/attempt 的探针、价格和执行快照保持冻结，不重算历史账单；
确有错账时另按现有审计和资金流程处理。

第 3 项本地放行不等于宣称真实 Provider 成功。供应商若返回明确不支持，按既有错误和资金语义处理，
不增设跨渠道重试；不以要求客户添加无业务意义图片作为解决方案。

### 3.2 清理剩余限制，未明确禁止的交给上游

| 对象 | 需核对的事项 | 实施动作，不以取得支持证明为前提 |
| --- | --- | --- |
| 墨行 2.0 与 Fast/Mini | 2.0 原文已明确音频搭配规则；Fast/Mini 数量上限是否有直接禁止依据 | 解除 Fast/Mini 纯音频阻断；未证实的数量限制不保留，2.0 规则不向其它模型扩散 |
| TokenSave | 准确媒体字段、`input_mode`、含视频计价，以及是否有明确禁止条款 | 移除没有明确禁止依据的两层媒体拦截，同时完成转换、目录与计费，不只改一个开关 |
| Synlink | 音视频 Data URL、数量与组合是否有明确禁止条款 | 没有明确禁止则按协议发送；保留已登记 opaque 资源边界，不增加素材物化或 fallback |

“没有真实验收”与“明确不支持”必须分开记录。对不影响既有资金安全、结构合法的已发布媒体字段，
不能因缺少支持声明或本地成功样本而默认拒绝；需要转换、计费或结果交付的能力应在同一修复中
完成必要实现，不把适配缺口伪装成上游不支持。真实验收仍用于确认效果和结算，不作为本地能力白名单。

## 6. 墨行协议与统一素材库整合评估

### 6.1 问题与核对方式

用户已明确业务目标：只保留一套最新墨行协议。路径最初提出 `/v1/ark/media/generations`，
随后明确修正为所有模型统一 `POST /v1/media/generations`；后者是本次方案的最终目标。
本节于 2026-09-10 通过浏览器读取四份动态页面的模型 API 和素材库页，并沿页面侧栏核对新增的
`doubao-seedance-2-0-260128-0818`。搜索抓取仅返回 JavaScript 页面框架，本文以下证据来自
浏览器实际渲染正文、用户指定的四份原始文档，以及后续授权的真实 Provider 调用。
测试使用本地已配置墨行凭据，仅在内存中读取使用，不输出或写入脚本；未修改渠道或执行素材创建。

目标是墨行一套视频协议与统一素材接入，2.0 精确 ID 保持用户指定的
`doubao-seedance-2-0-260128`。此前把素材库复用列表中的 `-0818` 当成目标 2.0，并建议替换模型，
属于分析错误，现撤回。用户补充截图也明确显示不带后缀的 ID、POST `/v1/media/generations` 与
GET `/v1/media/tasks/:task_id`。最新协议目标不授权替换业务模型。
Fast/Mini/2.5 已共用现有 adapter；指定 2.0 的完整字段适配及统一素材库兼容性仍需补证据。

### 6.2 页面呈现的三组合同

| 精确 Provider 模型 | 视频创建／查询 | 请求形状 | 素材库 |
| --- | --- | --- | --- |
| `doubao-seedance-2-0-260128` | `/v1/media/generations`、`/v1/media/tasks/:id` | `prompt`、`input_mode`、`control_mode`、`duration_seconds`、`aspect_ratio`、`with_audio`、`reference_*` | `/joycreator/openApi/v1/asset` |
| `doubao-seedance-2-0-fast-260128`、`doubao-seedance-2-0-mini-260615`、`doubao-seedance-2-5-260628` | 同上 | `content[]`、`duration`、`ratio`、`generate_audio` 等 | `/v1/volc/assets` |
| `doubao-seedance-2-0-260128-0818` | 专属正文写 `/v1/ark/media/generations`、`/v1/ark/media/tasks/:id`；通用区和生成示例却写 `/v1/media/...` | `content[]` 等官方形状 | `/v1/volc/assets` |

0818 页的标题显示不带后缀的 2.0，但模型 ID 和示例 `model` 都带 `-0818`，正文还明确区分旧 ID
继续走原合同。因此它不是可以从旧 ID 自动推导的别名。需要以完整 Provider ID 做显式代码登记和
`model_mapping`，不能静默重写已有映射。

上表保留文档当时的表述，实际方案采用用户最终确认的 `/v1/media/generations` 与
`/v1/media/tasks/{task_id}`。真实测试已发现两条路径对现代模型都能返回任务 ID，但响应形状不同：
`/v1/ark/media` 创建返回 `id`，查询采用 `content.video_url`；`/v1/media` 创建返回 `task_id`，
查询采用 media task 包装。另一条路径可受理不代表需要发布第二套协议或设置 fallback。
本站现有 `ark_media_v1` 与 media task 解析不同，不能只改 URL 而不核对响应；正式方案继续复用
墨行 ModelArk media task adapter，不切换到通用 Ark 反代协议。

### 6.3 素材统一的准确边界

国内素材库页面明确列出可复用的四个模型：0818、Fast、Mini、2.5。创建素材不向墨行发送 `model`，
使用 `GroupId`、`URL`、`AssetType`，支持 Image/Video/Audio；视频中使用平台素材 ID 的
`asset://` 引用。它与旧 2.0 的 JoyCreator 路径、字段大小写、状态及 ID 表达不同。

复用仍有供应商边界：素材固定到创建时的上游 channel key；混用不同火山账号、绑定 key 未挂载目标
模型等情况可返回 409。不能把“统一素材库”写成所有账号、全部墨行模型的任意互通。
这里的墨行内部 channel key 不等于本站 Channel ID，本站不复制其素材路由或所有权实现。

在本站，同一素材租户下的现代模型配置在一个 Seedance Channel 时，可发布同一匿名 `reuse_scope`。
不同本站 Channel 即使使用相同墨行地址，也不会自动合并 scope。普通 opaque 引用仍由供应商最终判断，
本站不新增跨渠道探测、素材映射、自动复制或失败切换。北向素材操作仍携带客户模型以选择 Channel；
墨行南向不需要 `model` 的差异由已有 adapter 吸收。

### 6.8 指定 2.0 的 watermark 专项对照

用户指出 [2.0 原文](<../70-research/墨行/国内/seedance 2.0.md>) 第 43–45 行声明支持 watermark，
类型标为 string，并说明可放入 extra 或平台兼容字段。第 133 行又描述原样透传。
因此之前单次失败不能直接推导“模型本身不支持水印”，需要区分参数位置、类型和供应商执行链。

本轮继续使用 `doubao-seedance-2-0-260128` 与 POST `/v1/media/generations`，改为文档的原生
请求形状：`capability=video_generation`、`input_mode=text`、`control_mode=none`、相同 prompt、
`duration_seconds=4`、`resolution=480p`、`aspect_ratio=16:9`、`with_audio=false`。
使用的凭据与本地该 2.0 Channel 配置的凭据一致；绕过本站入口直接请求墨行，结果不是本站校验错误。

| 对照 | 创建结果 | 查询结果／证据 |
| --- | --- | --- |
| 不传 watermark | HTTP 200，取得可信 task_id | 约 240 秒观察期限结束时仍为 running；生成终态未确认 |
| 顶层 `watermark: false`（布尔） | HTTP 200，取得可信 task_id | failed：参数 watermark 当前接口不支持 |
| 顶层 `watermark: "false"`（字符串） | HTTP 200，取得可信 task_id | failed：同一不支持参数错误 |
| `extra: {"watermark": false}` | HTTP 502，响应不是可解析 JSON，未取得可信 task_id | 创建结果未知；未重发，不判定该位置支持或不支持 |

两种顶层值失败时，查询返回 ID 均匹配，错误码均为 `upstream_unknown_error`，脱敏错误为
“参数 watermark 当前接口不支持，请检查字段名后重试。”
失败发生在创建受理之后的异步执行链；改用原生请求形状或将 false 改为字符串没有消除拒绝。
这将问题定位到当前墨行供应商调用链，不能进一步无证据地判定是墨行参数转发、其下游接口白名单，
还是文档与部署版本不一致。错误码名称本身也不足以证明一定来自模型底层。

`false` 仍表示显式提供该参数，不等于省略：当前本站 DTO 与 converter 使用可选指针，保留并发送
显式 false，这符合北向合同。因此若下游拒绝参数本身，传 false 也会触发拒绝。
不能以绕开错误为由直接删除客户的 watermark，更不能把省略后默认行为当成 false 已生效。

后续应核实墨行对指定模型实际支持的字段位置与映射。如果 extra 是有效入口，应只在南向 adapter
转换，客户继续使用统一北向字段；本次 extra 的 502 不能作为实现该转换已被验证的依据。
若两者确实不一致，应由供应商明确修正文档或实现；本地不换模型、不增加无依据拦截或静默吞字段。
本专项共 4 次创建，未重发未知请求、未下载视频或核对水印画面，费用及未知创建结果未完成对账。
不传 watermark 的对照只是没有在观察期内出现同一拒绝，并未取得成功终态；不能据此声称省略字段
已经验证可用或无水印。两次明确失败、一次生成待终态、一次创建未知分别记录，不能合并成失败率结论。

结论应写“适配缺口”，不能写“模型不支持”。不得以任意透传一个猜测字段、上游忽略后生成成功作为验收。

移动云运行时未拦截参考音视频，但 [publicmodel/video.go](../../pkg/publicmodel/video.go) 未声明两种类型，
会让根据目录构建的客户端隐藏输入。这项属于目录漏报，应修正；70 未找到独立移动云原文，
不能声称本次从 70 重新证实全部移动云参数。应沿用已有准确接入证据并补相应目录测试。

### 7.4 原文确实明确的限制

- **飞彩模型支持范围和数量**：只有 Pro PI 支持参考视频，最多 3 个；SD2 不支持音频、视频；
  其它已列支持音频的模型最多 3 段。这些是明确条款，不能与 HTTPS 误限制一起删除。
- **墨行准确 2.0 的音频搭配**：不能只有音频，至少搭配参考图片或视频。图片必填与“或视频”的
  文档矛盾不应被扩大成“有视频也必须加图片”。该模型条件不能用于拒绝 Fast/Mini。
- **墨行 2.5**：视频≤10、音频≤10，明确支持独立音频；首尾帧与多模态参考互斥是准确模型规则。
- **火山官方 2.0 系列**：最多 3 视频、3 音频，音频需搭配图片或视频；2.5 最多 10/10 且支持独立音频。
  这里只确认原文事实，不要求给当前直通官方请求新增一整套校验；交上游处理也能满足目标。
- **Synlink 普通素材 ID**：原文明确无法使用素材 ID，已登记 opaque 引用无合法转换的边界继续适用。
  本站托管图片能转换为 URL 是单独资源能力，不能把图片托管 ID 当音视频使用。

不新增媒体下载、文件探测、人脸识别、所有权探测来预判上游是否接受。媒体真实时长、内容质量、
素材审核和上游作用域仍由上游校验；显式限制的存在不代表本站必须重新实现全部上游校验。
