# 任务详情媒体预览修复

## 问题与目标

成功视频任务的预览失败后，详情不再提供媒体地址或打开、复制操作。
控制台应使用当前部署访问媒体，失败也保留结果地址供用户操作。

## 当前实际情况

- 本地数据库存在截图中的成功任务，包含视频结果地址；对该地址执行只读 HEAD，
  返回 200、video/mp4、483323 字节。未记录完整地址或媒体正文。
- 本地 ServerAddress 指向 tokenai.page，而浏览器控制台运行在 localhost:3500。
  原控制台产物链接使用公共地址，会把本地任务的媒体请求发往公共部署。
- LegacyVideoMedia 的失败分支替换整个结果区，连同操作按钮一起隐藏。
- 详情页部分已有翻译误置于 locale 根层级，导致使用英文键回显。

## 优化方案

- 控制台产物接口返回当前站点的相对内容路径，继续使用既有任务与产物绑定签名鉴权；
  前端解析为当前站点绝对地址以支持播放、打开和复制。
- 公共 API 保持使用 TaskPublicAddress / ServerAddress，不改变公开媒体地址合同。
- 播放失败只替换播放器，始终显示地址与操作；重试重新挂载播放器。
- 将详情页已有七种语言翻译归位到 translation，不引入新的翻译内容。
- 原生 controller/task.go 只增加控制台 URL 构建器选择及两个调用接线；
  新 URL 构建逻辑独立放置，上游同步冲突限于现有产物投影接线。

## 验证

- 前端两个测试文件共 9 个用例通过，覆盖错误后地址/操作保留、重试与当前站点路径解析。
- 控制器、服务和鉴权中间件媒体相关回归通过，公共地址合同保持。
- 前端 typecheck、目标文件 lint、i18n 同步通过。
- 实际源视频 HEAD 可访问；尚未重启用户正在调试的后端，也未宣称浏览器播放已验证。
- 本地需要重启后端并重新打开详情，以获取新的控制台媒体链接。
