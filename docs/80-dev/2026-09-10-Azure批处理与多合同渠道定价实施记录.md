## 2. 关键实现边界

- 合同授权为 Key 作用域：`tokens.contract_id=0` 完整走原生路径；绑定合同停用恢复原生逻辑；
  合同读取失败或绑定异常失败关闭。合同写入只有实体替换一个权威接口，事务内含 auth version
  fence，缓存按 `contract_id` 组织并以 `auth_version` 作 fence。
- 运行时不读取旧用户级合同规则（无双读路径）；`users.contract_mode/version` 仅作迁移数据源。
  迁移每用户至多一次，多候选渠道必须显式决策，Key 原组不被改写。
- Batch 渠道不进入原生 Ability 分发池（`channelSkipsGenericAbilities`）；渠道测试仅做只读
  files 连接验证，不创建计费作业。
- Batch 创建同步走完「冻结价格与计价时刻 → durable attempt → 资金 hold → 上传文件 → 创建作业
  → Task+作业快照+hold 转移同一事务」；上游受理不可确认时保持 unknown 与 hold，不自动重发。
- Batch 结算不适用「终态即全额退款」：可信终态后按逐行费用形成目标并原子调整（多退少补），
  取消后仍按实际执行结算；用量缺失保持待核实。通用超时/失败退款扫描按
  `platform <> 'azure_batch'` 排除；生命周期仅由 `batch_progress` 处理器推进。
- 计价时间冻结：`billingexpr.RequestInput.PricingTime` 为可选显式时刻，Batch 创建时持久化同一
  UTC 时刻并在预扣/结算/恢复间复用；未传入的原生调用保持 `time.Now()` 语义；共享编译缓存不固化时间。

### 3.2 预算、存储与价格支持边界

- 售价配置为 `batch_billing_setting.batch_billing_expr`；管理页有专用配置卡，客户价格页明确选择 Azure Batch。
  每行先计算模型费用及组/合同倍率，再进行最终整数 quota 转换；计费仍以现有 Go 引擎为唯一权威。
- 预扣对支持的 token 算术和条件/tier 分支取保守区间上界，避免非单调阶梯在输出上限处反而低估。
  这是资金预算器，不是第二套结算引擎。无法安全求预算上界的运算在保存/创建前明确拒绝；不声称支持任意表达式。
- 条件可读取冻结时间及允许的标量请求参数（例如 service_tier、reasoning_effort、n、输出上限）；只持久化表达式
  引用的允许参数。header、原始正文路径、任意 usage 探针及无法安全冻结的动态路径不支持，不按默认值静默结算。
- 输入最多 20 MiB/10,000 行，单行受相同文件字节上界约束；创建重读也有内存上界，并检查 checksum。
  输入仍采用受限内存缓冲及多次解析；结果文件改为临时磁盘流式归集，失去租约的 worker 不能覆盖获胜版本对象。
  未引用的临时 OSS 对象由部署侧既定生命周期管理，本轮没有添加自动删除任务。

### 3.4 原生文件最小接线说明

共享 attempt 持久化文件只增加 Batch 事务钩子，保障首次成功与恢复没有两套状态；auth 只接入有效合同判定，
通用 Task 查询只追加平台排除；pricing/option/router/任务详情只接入新增投影、验证与组件。上述位置是请求进入、
原子事务和通用扫描的必经边界，无法完全零修改；未来上游同步需复核这些窄接线，禁止顺带重构原生实现。
新增业务逻辑集中于 batch_*、合同实体文件及独立组件。工作区此前已有的大量修改不属于本轮新增接线。
输出 token 上界提到新增 common 常量；原生 validator 只将原常量定义改为引用同一值（含移除闲置 import），
防止 Batch 重复定义后漂移；因为 relay/helper 已依赖 service，不能反向从 service 导入该包。
