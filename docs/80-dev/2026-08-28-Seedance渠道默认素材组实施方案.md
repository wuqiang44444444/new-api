# Seedance 渠道默认素材组实施方案

## 问题与目标

当前统一北向素材创建合同允许调用方传入 `asset_group_id`，但部分已接入素材协议要求普通 AIGC 素材必须
属于一个 Provider 素材组。现有实现会在缺少必需组 ID 时直接拒绝请求，因此调用方必须先理解各 Provider
素材组差异、创建素材组并保存 opaque ID，未达到中转站统一北向协议应提供的使用体验。

本次目标是：

> 对能够创建素材组的 Seedance Channel，由管理员预先建立并保存一个稳定的默认 AIGC 素材组；普通调用方
> 未提供 `asset_group_id` 时由网关自动使用该 Channel 的默认组，使调用方可以直接创建素材。

本方案的第一优先级是统一北向协议。北向协议定义调用方唯一需要理解的请求形状和行为；各 Provider 的
素材组必填、可选或不存在等差异必须由南向 adapter 消化。不得把某个 Provider 的字段要求直接抬升为
客户调用条件，也不得要求调用方根据 Provider 或客户模型切换请求结构。

默认素材组名称固定为：

```text
aigctokenaigeneral
```

成功标准如下：

1. 每个支持素材组的 Channel 最多保存一个当前生效的 Provider 默认组 ID；不同 Channel 不共享本地记录。
2. 默认组只允许管理员在已保存 Channel 的编辑页面手工创建或复用，业务素材请求不得自动创建。
3. 普通 AIGC 素材创建未传组 ID 或裁剪后为空时自动使用 Channel 默认组；默认组尚未配置时明确失败。
4. 调用方传入裁剪后非空的组 ID 时原值优先，Provider 最终判断存在性、权限和兼容性，失败后不回退默认组。
5. 不使用素材组的代码协议继续接受统一北向请求，即使请求带有 `asset_group_id` 也不因此报错，南向不传该字段。
6. 不新增 Asset、AssetGroup 客户资源表、列表、所有权映射、resolver、自动创建、自动删除、孤儿扫描或并发补偿。
7. 相同北向素材请求在所有已发布素材协议上保持相同字段合法性；南向 adapter 只能转换和履约，不能反向
   收紧北向合同。

## 实施状态

第一批管理能力已经落地：代码已新增 `channel_default_asset_groups` 一对一表、Channel 删除与素材租户替换
清理、管理端状态与创建/复用接口、按名称完整查询的可选 adapter 能力，以及渠道编辑页“连通性测试”下方
的创建或复用按钮。按钮只针对已保存且素材协议支持组创建的 Channel，执行中禁用，成功后刷新配置状态；
页面不展示 Provider opaque group ID。相关 model、service、adapter、路由和前端组件测试已覆盖。

第二批代码已经实施：唯一 `GeneralAssetGroupPolicy` 同时驱动 `CreateRemoteAsset` 和公开元数据；普通素材
未传、传空或空白组 ID 时读取 Channel 默认组，显式非空 ID 原值优先，`none` 策略忽略组字段；同时启用
保留名称校验、稳定 409 错误和普通素材 optional 元数据。统一北向合同是运行时与元数据的第一优先级。

## 当前实际情况

### 1. 已验证代码事实

- `service.CreateRemoteAsset` 只用裁剪结果判断 `asset_group_id` 是否为空；普通素材根据协议唯一策略使用
  显式原值、Channel 默认组或忽略字段，不再读取 adapter requirement 接口。
- 素材 adapter 以 `GroupAdapter` 表达创建和单项查询能力，并以可选 `GroupSearchAdapter` 表达管理端组名
  查询；`GroupResult` 保留 Provider 返回名称。当前官方 Action adapter 实现查询，其它 adapter 直接创建。
- `Channel` 不增加默认素材组字段；Link 专属 `channel_default_asset_groups` 一对一表保存当前 Provider
  group ID，主数据库是唯一事实源。
- 管理端在“连通性测试”下方显示默认素材组配置状态和创建/复用动作，并通过 Channel 操作权限调用
  `GET/POST /api/channel/:id/default_asset_group`。
- 当前公开模型元数据从同一策略生成：普通素材的 `asset_group_id` 为 optional，创建必填字段不包含它。
- 本方案形成时，当前架构文档把“不持久化 AssetGroup”和“不支持字段必须失败”写成了没有例外的规则；
  2026-08-28 已将确认后的边界收敛到硬约束及产品/架构事实文档：不恢复客户 AssetGroup 资源模型，
  但允许 Channel 默认组内部配置，并以统一北向合同优先约束南向 adapter。管理控制面、运行时回退和公开
  合同均已完成代码接线；真实 Provider 与部署灰度仍需单独验收。

### 2. 已确认的产品与业务事实

以下事项已经在本次讨论中确认：

- 默认组按 Channel 保存，不按用户、应用或客户模型保存。
- 默认组只能由管理员点击渠道编辑页按钮创建；首次素材业务请求不自动创建。
- 普通素材的组行为由代码注册的 `GeneralAssetGroupPolicy` 唯一决定，不增加管理员能力开关，也不根据
  模型名、价格、URL 或请求字段推断。策略只允许 `none` 与 `default_fallback` 两种值。
- 同一 Channel 内模型必须具有一致的素材组语义，但该一致性由管理员负责；系统不增加逐模型校验。
- 如果协议支持查询组，管理员每次执行创建/复用动作时先查询完全同名的
  `aigctokenaigeneral`；模糊命中的其它名称不可采用。
- 查询得到多个完全同名组时直接采用 Provider 返回顺序中的第一个，不建立歧义状态。
- 查询明确成功且没有完全同名组时才创建；查询超时、鉴权失败、响应不可解析等情况直接失败，不把
  “无法确认”当作“不存在”。
- 如果协议能创建组但没有查询能力，则允许直接创建并保存。
- Provider 已创建组但本地保存失败时明确报错，不自动重试、不回滚 Provider 资源、不建立孤儿核查流程；
  管理员以后可以再次点击。
- 当前部署不存在多个管理员并发点击该动作的业务场景，不增加分布式锁、创建中状态或并发修复逻辑。
- 调用方未传组 ID、传入空字符串或纯空白时按“未传”处理，改用默认组。
- 调用方传入裁剪后非空的组 ID 时不预查询、不验证所有权，保持原值交给 Provider；若违反已发布北向
  结构约束则返回 `invalid_request`。任何非空错误值都不得静默替换成默认组。
- 对不使用素材组的协议，素材创建应忽略北向 `asset_group_id` 并正常履约；直接调用素材组创建接口仍返回
  既有 `unsupported_asset_operation`。
- 统一北向协议是客户合同和用户体验的第一优先级；南向 Provider 差异必须在 adapter 内处理，不能要求
  调用方了解或判断当前 Provider 是否使用素材组。
- `aigctokenaigeneral` 是系统保留名称，普通北向 `POST /v1/asset-groups` 不允许创建该名称。
- Channel 停用时保留默认组 ID；删除 Channel 时只删除本地记录，不删除 Provider 组；复制 Channel 时不
  复制默认组记录。
- 存量 Channel 不自动回填或批量创建，管理员配置前，依赖默认组的素材创建请求允许明确失败。
- Provider 不接受固定名称时直接返回创建错误，不做 Provider 专属改名或兼容降级。

### 3. 本方案的边界与未确认项

- 本方案把默认组限定为普通 AIGC 素材组。`real_person` 仍使用 Provider 真人认证流程产生的专用组 ID，
  不进入普通默认组回退。
- 组 ID 没有跨 Provider 的统一格式规则。Service 只用裁剪结果判断是否为空；非空值保持原值并交给
  Provider 最终判断，不能根据长度、前缀、模型或 Provider 猜测来源。未来如增加北向结构校验，失败只能
  返回 `invalid_request`，不得改用默认组。
- 本次不处理共享 Channel 默认组带来的调用方间强隔离、默认组 ID 对普通响应的可见性或 Provider 侧容量
  管理。这些风险由现有“一个中转站用户是一个受信应用”边界承担。
- 不考虑“创建素材强制要求组 ID，但 Provider 完全没有组创建 API”的接入形态，不为其增加控制台手工
  录入、fallback 或兼容分支。

## 优化方案

### 1. 协议优先级与适配责任

协议优先级固定如下：

```text
统一北向素材协议
  -> 客户模型选择唯一 Channel
  -> Channel 选择一个代码注册的素材协议
  -> 南向 adapter 把统一请求转换为 Provider 请求
```

统一北向协议是唯一客户合同，不是多个 Provider 请求结构的并集或透传层。具体约束如下：

1. `asset_group_id` 是统一北向素材创建协议中的合法可选字段，调用方可以始终使用同一请求结构。
2. `GeneralAssetGroupPolicy=default_fallback` 时，adapter 接收 Service 解析后的调用方组 ID 或 Channel 默认组 ID，并映射到
   Provider 要求的字段。
3. `GeneralAssetGroupPolicy=none` 时，adapter 明确不发送组字段；北向请求即使携带该字段也仍然合法。
4. Provider 的素材组必填规则不得导致公开北向协议把 `asset_group_id` 变成必填，因为 Channel 默认组已
   负责满足南向要求。
5. 只有整个业务操作无法履约时才返回既有 `unsupported_asset_operation`；不得因为南向没有对应字段而
   拒绝一个符合统一北向素材创建协议的请求。
6. 这一优先级只适用于平台已经定义的北向字段，不允许 adapter 借此接受任意 Provider 私有参数或静默
   改变其它字段语义。

因此，代码注册能力只决定 adapter 如何履约，不决定调用方是否需要改变请求。公开模型元数据用于说明
业务能力和结果，不得把 Provider 字段差异重新暴露为客户侧条件分支。

### 2. 收敛后的北向行为

普通 AIGC 素材创建按以下顺序解析素材组：

```text
客户模型
  -> 唯一 Seedance Channel
  -> 代码注册的 asset_upstream_protocol
  -> GeneralAssetGroupPolicy
       none：忽略北向 asset_group_id，南向不传
       default_fallback：请求组 ID 裁剪后是否非空？
            是：原值使用请求组 ID
            否：读取 Channel 默认组 ID
                 有：使用默认组 ID
                 无：default_asset_group_not_configured
```

运行时不得执行以下动作：

- 不因默认组缺失而调用 Provider 创建组；
- 不按固定名称临时查询 Provider；
- 不在请求组 ID 被 Provider 拒绝后改用默认组；
- 不切换 Channel、协议或 Provider；
- 不把默认组 ID 写入 Asset/AssetGroup 客户资源记录。

建议的公开行为矩阵：

| Channel 协议能力 | 请求中的 `asset_group_id` | 结果 |
| --- | --- | --- |
| `default_fallback` | 裁剪后非空值 | 原值交给当前 adapter，Provider 最终裁决 |
| `default_fallback` | 未传、空或空白 | 使用 Channel 默认组 |
| `default_fallback` | 未传且默认组未配置 | `409 default_asset_group_not_configured` |
| `none` | 任意值或未传 | 正常创建素材，南向不传组参数 |
| 任意策略 | 非空值违反已发布北向结构约束 | `400 invalid_request`，不得改用默认组 |
| 不支持素材组创建 | 调用 `POST /v1/asset-groups` | `422 unsupported_asset_operation` |
| 任意协议 | 普通调用方创建保留名称 | `400 reserved_asset_group_name` |

`real_person` 不使用上表的普通默认组回退；缺少其 Provider 专用组或认证结果时保持现有明确失败语义。

### 3. 协议能力表达

能力必须来自代码注册，不增加 Channel 配置字段。这些能力只服务南向转换和管理端默认组准备，不改变
统一北向请求字段的合法性。唯一权威注册必须同时供运行时和公开元数据读取，不能分别从 `GroupAdapter`、
`AssetGroupRequirementAdapter` 或另一份 catalog switch 推断。代码已经收敛为：

1. `GeneralAssetGroupPolicy` 只允许 `none` 与 `default_fallback`。前者表示普通素材南向不使用组；后者表示
   调用方省略组 ID 时必须使用 Channel 默认组。
2. `GroupAdapter` 只代表协议能够创建普通素材组，并作为管理按钮的能力门槛；不得用于推断运行时策略。
3. 新增可选的内部 `GroupSearchAdapter`，只用于管理端按名称查询默认组，不发布北向 List API。

`GroupSearchAdapter` 的结果必须包含 Provider opaque ID、返回名称和完整分页所需信息，以便 Service 对
`aigctokenaigeneral` 做本地完全相等过滤。注册该能力前必须验证服务端过滤语义，并保证遍历全部匹配页；
分页超过已验证上限、无法判断结果集已经耗尽或返回名称缺失时必须失败，不能据此创建。没有已验证完整
查询能力的 adapter 不实现该接口，管理动作直接创建。

普通 AIGC 的目标策略表如下；`real_person` 不在此表内：

| `asset_upstream_protocol` | 当前普通组能力事实 | `GeneralAssetGroupPolicy` |
| --- | --- | --- |
| `volcengine_action` | 可创建组，公开合同原为 optional | `default_fallback` |
| `byteplus_action` | 可创建组，公开合同原为 optional | `default_fallback` |
| `ark_assets_v1` | 可创建组，公开合同原为 optional | `default_fallback` |
| `tokensave_assets_v1` | 创建素材要求组 | `default_fallback` |
| `moxing_joycreator_v1` | 创建素材要求组 | `default_fallback` |
| `moxing_volc_assets_v1` | 创建素材要求组 | `default_fallback` |
| `funcloud_material` | adapter 内部要求组 | `default_fallback` |
| `cmcc_aicc_v2` | 创建素材要求组 | `default_fallback` |
| `none` | 普通素材不使用组 | `none` |

不建立逐模型 capability。Channel 内模型是否适合所选素材协议继续由管理员配置责任和既有协议配对边界
保证，运行时只按 Channel 的一个素材协议处理。

### 4. 持久化模型

建议新增 Link 专属一对一表，而不是给 NEWAPI 原生 `channels` 表增加本地字段：

```text
channel_default_asset_groups
  channel_id          主键，逻辑关联 Channel
  provider_group_id   Provider opaque ID，非空 TEXT
```

只保存当前生效 ID，不保存默认名称、Provider 名、客户模型、账号、Region/Project、查询响应、原始响应或
素材列表。名称由代码常量 `aigctokenaigeneral` 唯一表达。

选择独立表的原因：

- 把新增状态限制在 Link 专属文件，降低未来合并 NEWAPI 上游 `Channel` 结构的冲突面；
- 新 Channel/复制 Channel 天然没有记录，不会把旧默认组 ID 复制过去；
- 删除 Channel 时可以在现有本地扩展清理链中只删除一行，不触发任何 Provider 删除；
- GORM `TEXT` 和单列主键可以同时适配 SQLite、MySQL 和 PostgreSQL，不依赖数据库 JSON 运算或方言 SQL。

建议提供直接的 model 操作：读取、事务内保存/覆盖、按 Channel ID 批量删除。Channel 删除与素材租户
替换两个事务共用该删除操作。不要增加历史版本、状态机、名称索引、Provider ID 唯一约束或自动修复。
主数据库是该默认 ID 的唯一权威；Redis 和前端状态只能缓存。

### 5. 管理端创建或复用流程

在现有“测试素材库”按钮旁增加“创建默认素材组”入口，只对已保存、选择了可创建组素材协议的
Seedance Channel 显示。已配置时显示“默认素材组已配置”，管理员可主动执行“重新创建或复用”。

建议增加 Link 专属管理接口：

```text
GET  /api/channel/:id/default_asset_group
POST /api/channel/:id/default_asset_group
```

GET 只向有 Channel 管理权限的管理员返回页面需要的 `supported`、`configured` 和固定名称；Provider
opaque ID 不进入管理页面、普通客户接口、日志或验收输出。POST 执行以下流程：

1. 按现有 Channel 管理权限读取已持久化 Channel 和受保护凭据；未保存的新建页面不能调用。
2. 验证 Channel 为 `ChannelTypeSeedanceLink`，素材协议有效且 adapter 实现 `GroupAdapter`。
3. adapter 实现 `GroupSearchAdapter` 时，按 AIGC 组类型和固定名称查询完整结果集：
   - 查询失败：停止并返回脱敏管理错误；
   - 按 Provider 的 TotalCount、游标或已验证结束条件遍历全部页；不能证明结果集已耗尽时停止；
   - 对结果在 Service 再做名称完全相等过滤；
   - 存在一个或多个完全同名结果：采用返回顺序中的第一个；
   - 没有完全同名结果：继续创建。
4. adapter 没有查询能力时直接创建名称为 `aigctokenaigeneral`、类型为 `AIGC` 的组。
5. Provider 必须返回非空可信组 ID；否则按上游响应异常处理，不保存空值。
6. 把最终 ID 保存或覆盖到当前 Channel 的一对一记录，并写管理审计。审计只记录 Channel ID、动作和
   “复用/创建”结果，不记录凭据、签名 URL 或原始 Provider 响应。
7. Provider 成功但数据库保存失败时返回失败；不自动删除、重试或对账 Provider 组。

升级前已经存在的完全同名组可能由历史普通调用方创建。按已确认业务边界，管理员执行该动作即接受复用
返回顺序中的第一个完全同名组；平台不判断创建来源，也不建立组所有权事实。

该流程不使用长事务包裹 Provider 网络请求，也不增加锁或 `creating` 状态。依据已确认的单管理员业务事实，
不处理同时点击导致的重复同名组；即使 Provider 已存在多个完全同名组，也只保存查询顺序中的第一个。

### 6. 素材创建 Service 调整

默认组解析放在 Link 专属素材 Service 内，不进入 NEWAPI 原生 relay 热路径：

1. 完成客户模型选路并取得 Channel、adapter 后，再解析组 ID。
2. `real_person` 先走现有专用组要求，不使用普通默认组。
3. 策略为 `none` 时，把南向 `GroupResourceID` 固定为空；北向携带组 ID 也不报错。
4. 策略为 `default_fallback` 时，只用裁剪结果判断是否为空；非空值保持原值，空值读取当前 Channel 默认组。
5. 默认记录缺失时返回稳定错误 `default_asset_group_not_configured`。
6. 选定一个 ID 后只发送一次 Provider 创建素材请求，不做失败回退。

普通北向 `CreateAssetGroup` 对 `group_kind=general` 拒绝完全等于保留名称的请求。`real_person` 名称不参与
Provider 普通组命名，不适用该保留规则。保留名称比较与管理端完全相等匹配使用同一个代码常量和同一
规范化方式，避免出现两套拼写。

### 7. 公开模型元数据与文档

实现后，公开合同必须与“无需调用方先建组”保持一致：

- 对能够使用默认组的普通 AIGC 素材，`asset_group_requirement` 改为 `optional`；
- `creation.required_fields` 不再包含 `asset_group_id`，示例默认省略该字段；
- 真人素材仍按 Provider 认证合同发布 `required`；
- 不使用素材组的协议可以继续用 `unsupported` 表达南向不使用素材组，但该值不得解释为北向字段非法；
  公开文档必须明确说明统一北向字段会被忽略，不导致创建失败；
- 文档说明裁剪后非空的显式 ID 原值优先、只有空值使用默认组、Provider 拒绝后不回退默认组；
- 新增 `default_asset_group_not_configured`、`reserved_asset_group_name` 的稳定错误说明；素材组操作不支持
  继续使用既有 `unsupported_asset_operation`。

当前事实文档至少需要同步修订：

- `docs/00-context/硬约束.md`；
- `docs/20-architecture/Seedance专用渠道与Link架构.md`；
- `docs/20-architecture/Seedance无状态素材代理架构.md`；
- `docs/20-architecture/Seedance模型素材库支持矩阵.md`；
- `docs/20-architecture/decisions/0018-Channel默认素材组基础设施配置.md`；
- 对外 OpenAPI 与素材 API 使用文档。

修订后的边界应表述为：平台仍不持久化客户 Asset/AssetGroup 资源、映射、所有权或列表，但允许每个
Seedance Channel 持久化一个内部默认 Provider group ID，作为普通 AIGC 素材创建的基础设施配置。

同时为 `asset_group_id` 写明统一北向例外：当唯一策略为 `none` 时允许忽略该字段。这是经过产品
确认的用户体验优先规则。硬约束应明确写成“统一北向合同优先，南向 adapter 履约”，不能继续笼统地把
所有南向不存在的字段判为客户请求错误；但该规则不应推广为其它 Provider 私有字段的通用静默删除机制。

### 8. 前端方案

渠道编辑页保持现有“测试素材库”按钮，新按钮放在同一素材配置区域：

- 未配置且协议支持：`创建默认素材组`；
- 已配置：显示 `默认素材组已配置`，并继续提供 `创建或复用默认素材组`；
- 协议不支持素材组：不显示按钮；
- Channel 尚未保存：不显示或禁用，并提示先保存 Channel；
- 素材租户替换确认对话框需说明：替换会清除本地默认组配置，替换后需重新创建或复用；
- 请求执行期间禁用按钮，成功后刷新状态；失败只显示后端脱敏错误和稳定错误码对应文案。

前端不得通过模型名推断按钮资格，也不得自行查询 Provider。所有用户可见文本使用现有 i18n 体系，并补齐
`en`、`zh`、`zh-TW`、`fr`、`ja`、`ru`、`vi`。

### 9. 生命周期与存量数据

- 停用/重新启用 Channel：保留默认组记录。
- 复制 Channel：不复制一对一记录；新 Channel 需管理员重新创建或复用。
- 删除 Channel：同一数据库事务删除本地默认组记录；不调用 Provider 删除 API。
- 素材租户原地替换（管理员确认后修改 Base URL、协议、Project 或 Region，重建匿名 `reuse_scope`）：
  同一数据库事务删除该 Channel 的本地默认组记录；旧默认组属于旧素材租户，不得在替换后的租户中继续
  发送，也不调用 Provider 删除 API。替换后依赖默认组的请求返回 `default_asset_group_not_configured`，
  管理员需重新执行创建或复用。
- 凭据轮换且管理员确认素材租户未变化：保留默认组 ID。
- 存量 Channel：不启动扫描、不回填、不自动创建。管理员完成配置前，依赖默认组的请求返回
  `default_asset_group_not_configured`。

为避免公开元数据先变为 optional、存量 Channel 却尚未配置的错位，必须分两次兼容发布：

1. 第一批只上线默认组表、管理接口和管理按钮，不改变素材创建解析与公开元数据；
2. 管理员为全部存量 `default_fallback` Channel 创建或复用默认组；
3. 第二批同时启用运行时默认回退和普通素材 optional 元数据；
4. 新 Channel 仍由管理员自行控制配置顺序，未配置时稳定返回 409，不增加技术性启用门槛，也不把
   `asset_group_id` 重新声明为北向必填。

### 10. 验证方案

#### 10.1 后端合同测试

1. 默认组持久化：同一 Channel 保存后可读取和覆盖；删除 Channel 只删除本地记录；复制 Channel 无记录；
   确认替换素材租户时本地记录与 `reuse_scope` 在同一事务删除。
2. 默认解析：调用方非空 ID 原值优先；未传/空白时使用默认；违反北向结构约束时返回 400 且不回退；默认缺失明确失败。
3. 无组协议：即使北向传 ID，南向 `GroupResourceID` 仍为空且创建继续执行。
4. Provider 拒绝：调用方显式 ID失败后不得再次使用默认组发送第二次请求。
5. 管理动作：精确同名复用、模糊命中忽略、多个同名取第一个、完整结果集明确不存在时创建。
6. 查询失败、分页无法耗尽或名称缺失：不得调用创建；无查询能力时直接创建。
7. Provider 返回空 ID 或本地保存失败：不得写入空默认记录，不自动重试或删除 Provider 组。
8. 保留名称：普通 general 创建被拒绝，其它名称和真人认证合同保持既有行为。
9. 公开元数据：从同一策略表推导；普通 AIGC 创建不再要求 `asset_group_id`，真人素材要求不被放宽。
10. 路由与权限：只有具备 Channel 操作权限的管理员可以读取状态和执行创建/复用。
11. 北向一致性：同一合法素材创建请求分别进入“使用组”和“不使用组”的 fake adapter 时均通过北向校验；
    差异只体现在南向 `GroupResourceID` 是否存在。
12. 协议策略：Volcengine、BytePlus、Ark 省略组时使用已配置默认组；FunCloud 也进入相同默认回退；`none`
    协议省略组仍成功且不发送组字段。
13. 错误映射：默认组缺失稳定返回 409；不支持素材组操作继续返回 `unsupported_asset_operation`。

新增或重写的 Go 测试使用 `testify/require` 和 `testify/assert`，断言可观察合同，不断言私有字段列表或文件
布局。数据库测试至少覆盖当前 SQLite 测试夹具；涉及迁移和 GORM 写法时继续保证 MySQL 5.7.8+ 与
PostgreSQL 9.6+ 兼容。

#### 10.2 前端验证

- 按协议能力显示/隐藏按钮；
- 未保存 Channel 不触发请求；
- configured 状态、重复执行、loading 和脱敏错误展示正确；
- Channel 克隆页面不显示为已配置；
- i18n 同步与生产构建通过。

#### 10.3 建议命令

按最窄边界开始，再按风险扩大：

```bash
go test ./service ./model ./controller ./router
go test ./relay/channel/task/seedance/assets
cd web && bun run i18n:sync
cd web && bun run build
task docs:check
task ai:check
cd web && bun run docs:validate
git diff --check
```

真实 Provider 验收只验证管理员按钮能够复用或创建固定名称组，以及普通素材省略组 ID 后确实落入默认组；
验收日志和报告不得输出凭据、签名 URL、Provider opaque ID 或原始响应。经过鉴权的管理 UI 也只显示
`supported` / `configured` 状态和固定组名，不返回或显示内部 opaque ID。代码和本地测试通过不能写成
真实 Provider 或生产灰度已经完成。

### 11. 实施顺序

1. 先更新硬约束、当前事实文档和公开合同，明确“统一北向协议第一优先，南向 adapter 负责履约”，以及
   默认组是 Channel 基础设施配置。
2. 新增 Link 专属默认组一对一 model、迁移和 Channel 删除清理。
3. 建立唯一协议策略表，并为 adapter 注册默认组创建与可选完整查询能力，补齐查询结果名称和分页语义。
4. 实现管理端状态/创建接口、审计和稳定错误映射。
5. 调整素材创建的组 ID 解析以及保留名称校验。
6. 增加管理按钮及状态交互，作为第一批兼容发布；管理员完成存量 Channel 默认组配置。
7. 第二批同时启用运行时默认回退，并更新公开模型元数据、OpenAPI、外部文档和全部前端翻译。
8. 完成定向测试、构建、文档校验和真实 Provider 脱敏验收。

### 12. 主要风险与控制

| 风险 | 控制 |
| --- | --- |
| Provider 查询是模糊搜索或分页结果不完整 | Service 对完整结果集做名称完全相等过滤；不能证明已耗尽时失败 |
| 查询失败被误判为不存在 | 查询错误直接停止，不创建 |
| Provider 创建成功但本地保存失败 | 明确报错；不自动重试、回滚或建立 orphan 状态 |
| 多个完全同名组 | 按已确认规则取 Provider 返回的第一个 |
| 历史调用方创建的同名组被复用 | 管理员执行动作即接受第一个同名组；平台不承诺创建来源或所有权 |
| 显式错误组 ID 被偷偷改用默认组 | 只在裁剪后为空时用默认；非空原值交 Provider，北向结构错误返回 400 |
| 无组 Provider 因统一字段报错 | 北向接受字段，adapter 南向明确置空 |
| Provider 差异重新泄漏到客户合同 | 北向校验与公开请求形状保持统一，adapter 合同测试分别证明各南向映射 |
| 真人素材误用普通 AIGC 默认组 | `real_person` 保持专用认证/组 ID 合同，不进入普通默认回退 |
| Channel 克隆或租户替换复用旧 ID | 默认组使用独立一对一记录；克隆不复制，租户替换在同一事务删除本地记录并需管理员重新配置 |
| 元数据 optional 早于存量配置完成 | 两批兼容发布；先上线管理能力并配置存量 Channel，再切运行时和元数据 |
| 扩大 NEWAPI 上游冲突面 | 类型、model、Service、Controller 和测试主体放入 Link 专属新增文件；原生文件只保留迁移、路由和删除清理的极窄接线 |

## 剩余事项

- 编码前核对每个已注册素材 adapter 的创建组能力、可选查询能力、完整分页、名称字段和返回 ID 语义；
  没有真实证据的查询能力不要登记。
- 在现有 Channel 删除统一链中接入默认组记录清理；未来上游合并新增删除路径时必须同步接线，避免孤儿记录。
- 在素材租户替换的 `reuse_scope` 重建事务中同步接入默认组记录删除；该触发点与 Channel 删除共用同一
  model 删除操作，未来上游合并新增更新/删除路径时必须同步接线。
- 真实 Provider 验收后再决定哪些 Channel 可以在生产管理页启用按钮；未验收能力不得写成生产已发布。
