# 飞彩 V3 逐模型真实验证记录

## 1. 范围与安全边界

本记录承载 `feicai.seedance-videos/v3` 无后缀 Provider 模型的真实黑盒验证过程。验证按模型串行执行；
每个模型分别记录脱敏请求参数、前置检查、创建、轮询、内容探测、Provider 用量与日志分析。某一模型
通过不授权其它模型或其它参数组合。

- 凭证从本地主数据库的隔离渠道读取，不写入本文、命令输出或普通日志；
- 不记录 Provider Task ID、完整内容 URL、原始 Provider 响应或完整签名 URL；
- Base URL 为渠道当前保存的 `http://43.161.200.208`；这是明文 HTTP。2026-08-10 01:13:27 +0800，
  操作人已在获知凭证会经未加密 HTTP 传输后，明确授权读取数据库 URL/Key 并执行真实验证；
- 付费请求采用单模型最小规格和显式预算上限，结果不满足完整门禁时不登记 production evidence。

## 2. 验证工具准备

复用 `cmd/verify-feicai-v2` 的脱敏黑盒验证器，增加了显式 `v3` 模型集合、共享渠道 Key、明文 HTTP
二次确认和轮询状态序列。验证器仍不序列化 Provider Task ID 与完整内容 URL。

准备验证：

```text
go test ./cmd/verify-feicai-v2 -count=1
结果：通过
```

## 3. Mini 720p / 16:9 最小验证

### 3.1 请求计划

| 字段 | 值 |
| --- | --- |
| implementation | `feicai.seedance-videos/v3` |
| 客户 SKU | `seedance-2.0-mini-720p` |
| Provider model | `seedance-2.0-vip-720p-mini-azhw` |
| endpoint | `POST /v1/videos` |
| prompt | `A calm landscape with a slow cinematic camera movement` |
| duration | `4` |
| size | `1280x720`（候选值，待真实内容确认） |
| images / audios / videos | 均省略 |
| 预计 Provider 支出上限 | CNY 2.20 |

脱敏请求体：

```json
{
  "model": "seedance-2.0-vip-720p-mini-azhw",
  "prompt": "A calm landscape with a slow cinematic camera movement",
  "duration": 4,
  "size": "1280x720"
}
```

计划过程：

1. `GET /v1/models`：确认精确无后缀模型对当前 Key 可见；
2. `GET /v1/dashboard/billing/usage`：读取创建前账户用量；
3. `POST /v1/videos`：只发送上述脱敏参数；
4. `GET /v1/videos/{provider_id}`：串行轮询，记录状态序列但不保存 Provider ID；
5. `GET /v1/tasks?...`：尝试核对任务 quota 与对账可用性；
6. 下载与冻结 Base URL 同 scheme/host/port 的 HTTP(S) `video_url`，使用 `ffprobe`
   核对宽、高和时长；
7. 再次读取 usage，分析增量与任务 quota 是否一致。

### 3.2 前置网络与应用日志

首次沙箱内只读模型发现未获得网络出口，连接在本地立即失败，没有请求到达 Provider。随后尝试在不发送
凭证的情况下连接 `https://43.161.200.208/v1/models`，TLS 握手返回 `SSL_ERROR_SYSCALL`，说明当前 IP
没有可用的直接 HTTPS 端点；该结果不能证明 Provider 业务不可用。

本地 `logs/backend.log` 只记录了管理端读取渠道、读取 Link implementation/publication 和两次渠道更新
HTTP 访问，未记录请求体、响应 envelope 或上述 ratio/size 门禁正文。两次 `PUT /api/channel/` 的 HTTP
访问状态均为 200，但数据库中的隔离渠道仍保持旧 mapping 且没有已保存的 v3 implementation ref；因此
HTTP access log 的 200 只能证明 Controller 返回了响应，不能证明业务保存成功。当前尚未产生 Provider
创建、轮询、内容或账单日志。

### 3.4 日志分析

首轮脱敏验证日志完整字段为：implementation v3、请求 model/prompt/duration/size、创建 HTTP 状态、

首轮最终 `passed=false` 来自验证工具错误，而不是 Provider 业务失败：验证器把内容 URL 限制为同源 HTTPS，

HTTP 或 HTTPS。当前 Base URL 是 HTTP，因此同源 HTTP 内容应允许进入受控下载检查。验证器已改为复用
生产 URL 校验器，并通过以下回归：
