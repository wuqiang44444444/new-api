# admin 账单测试费用与缓存用量修复方案

## 问题与目标

用户发现“我的账单”缓存写入全部为 0。本次核对本地 admin 的 2026 年 9 月账期，目标是让客户
账单只汇总真实结算记录，补全后续渠道测试的缓存用量日志，避免测试与游乐场混入同一客户分组。

## 当前实际情况

已验证本地数据库快照（核查截止日志 ID 135044，金额按 500000 quota/USD 换算）：

| 来源 | 请求数 | quota | 美元 |
| --- | ---: | ---: | ---: |
| 渠道模型测试 | 12434 | 8591424 | 17.182848 |
| 实际钱包调用 | 9 | 15510 | 0.031020 |
| 原客户账单合计 | 12443 | 8606934 | 17.213868 |

- 9 笔实际钱包调用按日志冻结价格逐笔复算，金额全部相符；这不是期初/期末余额完整勾稽。
- `controller/channel-test.go` 的测试路径计算 quota 后只写消费日志，不执行钱包扣款。
- 测试日志的确定性身份是 `token_id=0`、`token_name=模型测试`、`content=模型测试`；客户账单
  原本不排除这些记录。上游确实收到测试请求，因此客户账单排除测试不等于上游用量也应排除。
- `buildTestLogOther` 仅保存缓存读取，没有保存创建总量与 5 分钟/1 小时拆分；账单读取缺失字段后
  得到 0。历史写入量不能凭费用反推补齐，也不能改余额或重算历史扣费。
- 测试与真实游乐场请求都使用 `token_id=0`，原页面将两者合并并显示为“模型测试”。
- 当前工作区已有其他任务的账单和前端改动；本次保留它们，仅添加必要接线。

## 优化方案

1. 在独立模型文件提供客户结算日志查询范围，按原生测试日志的完整确定性身份排除测试。
   自助月账单、管理员客户汇总/列表、旧自助账单和使用构成接口统一应用；不按模型名、价格或
   `token_id=0` 单独推断，不排除真实游乐场、免费调用、退款和删除 API Key 后的历史记录。
2. 上游对账继续保留实际测试调用。原生消费日志、余额、渠道、Provider 行为不迁移、不回写。
3. 渠道测试在独立新增文件中保存已取得的缓存创建总量、TTL 拆分和统一展示总量；原生
   `controller/channel-test.go` 仅新增一行日志接线，不改变测试定价或扣款语义。
4. 客户账单排除测试后，`token_id=0` 分组只包含真实游乐场调用，避免测试名称覆盖。
5. 用确定性回归测试保护客户/上游不同范围、多个客户汇总、旧接口一致性、缓存创建与读取共存及
   TTL 总量不重复计算。使用本地数据库只读验证修复后的账单，不发送额外付费 Provider 请求。

### 原生文件改动必要性

`controller/channel-test.go` 是唯一持有测试响应 usage 并生成日志的原生入口。新增单行调用用于补全
已取得的事实；实现和回归测试置于新增文件，未来同步仅需核对该日志接线点。客户账单属于本地
新增模块，使用共同查询范围，避免扩写原生日志写入函数或修改原生日志类型。

## 深入评审发现与追加修复

### 发现

1. 客户模型行的详情链接未传递密钥 0，也没有固定计费方式；按可变用户名读取通用日志，不能与账单勾稽。
   评审快照中游乐场汇总为 2 笔、3237 quota，而旧下钻会混入测试及密钥 90，共 283 行、58395 quota。
2. 历史测试没有保存缓存创建字段，解析结果为 0 且质量可能显示完整。首轮快照全历史 47427 条 admin 测试记录
   均缺少写入字段；这不能证明真实上游写入量为 0。
3. 首轮代码未加载时，实际页面仍显示旧口径。代码测试通过不等于运行服务已达成目标。

### 最小修复路径与代码质量

- 独立 `model/billing_statement_logs.go` 复用客户结算范围和唯一账单解析器，流式读取匹配事实，只保留
  当前页；不复制计费分类和退款规则。专用控制器及本地路由承载认证与筛选校验。
- 原生 `model/log.go` 的 3 个角色展示入口各增加一行调用，原因是历史测试标记必须在所有日志可见性
  投影中一致；实现放在新文件，未来同步仅需核对这 3 个接线点，不改变原生日志写入与资金行为。
- 用量日志前端 API 只增加账单分支；一般日志仍使用原生接口。账单详情保留固定范围，统计同源。
- 上游汇总、导出与日志桌面/移动/详情展示历史缓存缺失状态；显式零与缺失分别测试。
- 代价：账单明细为获得动态分类及全范围净额，需要扫描当前用户自然月内匹配日志；内存只保留当前页，
  没有新增索引或数据库方言分支。未以本地小数据验证替代大客户性能验收。
