# Link 资源虚拟素材库实施方案

## 1. 目的与实施状态

本文只描述当前代码到正式 Link 资源架构的实施差异。产品合同与长期边界以：

- [Link 资源虚拟素材库架构](../20-architecture/Link资源虚拟素材库架构.md)；
- [ADR-0015：Link 公开 SKU 与实现身份版本绑定](../20-architecture/decisions/0015-Link公开SKU与实现身份版本绑定.md)

为权威。

截至 2026-08-03，本方案的代码实施已完成：最小 `AssetSource`、binding/source 双模式 Resolver、
查询时 Asset 聚合状态、当前 binding 的实现/策略/凭据围栏、公开/内部能力分层、FunCloud JSON/v2
与旧 multipart 链删除均已落地。source 过期只关闭 source 路径，仍有当前 binding 时 Asset 保持
`ready`；真人授权失效始终优先 fail-closed。数据库审计识别出的 BytePlus、
Moxing、TokenSave、飞彩、FunCloud、Moxing Images 和 Qihang Images 共 9 个现有渠道已显式写入实现
ID/version，并通过后端配置校验。真实 Provider 抓取、外部 MySQL/PostgreSQL disposable DSN 和生产
灰度仍是发布门禁，不因代码完成而视为已验收。

## 2. 代码所有权与修改边界

### 2.1 本地 Link 代码可以直接重构

当前素材库主链由本项目在 new-api 上游之外新增，包括：

- `dto/asset*.go`；
- `model/asset*.go`；
- `service/asset*.go`；
- `relay/asset_reference_*.go`；
- `relay/channel/task/doubao/assets/`；
- `router/asset-router.go`；
- 素材 profile、能力和管理端素材表单。

这些代码不是 new-api 上游原有结构。为形成唯一正确实现，可以直接删除错误分支、修改类型或重写
局部流程，不保留本项目内部的旧 alias、fallback、feature flag 或双轨兼容。

项目负责人已确认本地 Link 实现尚无需要保留的业务数据。本方案直接以最新模型和唯一执行链为
目标：本地 Asset、binding、attempt、exposure 等扩展表可以重建或清理，不做旧字段回填、双读、
shadow write、运行时推断或兼容迁移。该数据策略只适用于本地新增且未发布的 Link 扩展，不允许借此
扩大修改 new-api 上游模型、API 或通用 relay 行为；最新 schema 仍必须同时支持 SQLite、MySQL 和
PostgreSQL。

### 2.2 共享上游文件只允许极窄接线

下列文件来自 new-api 上游，不能因 Link 改造被整体删除、移动、重排或抽象重构：

| 上游文件 | 允许的 Link 改动 |
| --- | --- |
| `model/main.go` | 删除本地旧模型注册；新增必要模型时只保留单行 AutoMigrate 注册 |
| `relaykit/dto/channel_settings.go` | 只删除本地 FunCloud 字段，并为通用 `LinkImplementationRef` 保留一行嵌套字段接线；不得重排或重构 `ChannelOtherSettings` |
| `web/src/features/channels/lib/channel-form.ts` | 只删除本地 FunCloud 分支并保留现有通用素材接线 |
| `web/src/features/channels/types.ts` | 只删除本地 FunCloud 类型成员 |
| 其它 controller/middleware/model 热路径 | 最多保留单行调用或极窄分支，新增逻辑放本地独立文件 |

宁可在 Link 本地模块保留少量清晰重复，也不为抽象复用扩大上游文件改动。

## 4. 唯一目标链路

```text
POST /v1/assets(source.url)
  -> Asset + 最小 AssetSource
  -> 可选预创建 AssetBinding

视频请求 asset://ast_*
  -> 候选渠道校验
  -> active binding 优先
  -> 否则恢复 source URL
  -> Provider converter
```

`ast_*` 是唯一资源身份。source URL 只承担 binding 创建输入和 URL-only Provider 的短期执行引用，
不承担媒体同一性、全局去重或长期档案职责。

## 5. 实施包 A：直接删除 FunCloud 旧素材链

### 5.1 删除原则

旧 FunCloud raw-upload/multipart 链尚未形成已发布能力，也没有需要兼容的正式数据合同。项目负责人
已确认本方案范围内的本地数据可以丢弃，因此直接删除且不提供：

- API 废弃期或 `410 Gone`；
- profile alias 或旧配置归一化；
- 数据扫描、回填、转换和保留期；
- 旧 adapter revision；
- feature flag、fallback 或回滚到旧链的分支；
- `real_person_mode` 的替代迁移。

本地开发数据库直接清理旧 attempt、binding 和相关扩展数据，再由最新模型建表；产品代码不增加
drop-table migration、历史扫描器或兼容读取。若未来发现本方案范围外存在真实部署或业务数据，必须
把该环境从本次直接切换中排除并单独决策，不能把开发数据可丢弃外推为生产删除授权。

## 6. 实施包 B：最小 AssetSource

### 6.1 数据模型

新增本地文件 `model/asset_source.go`，只保存：

| 字段 | 约束 |
| --- | --- |
| `asset_id` | 主键或唯一索引；一条 Asset 最多一个 source |
| `encrypted_url` | `json:"-"`；认证密文 |
| `expires_at` | Unix 秒；0 表示有效期未知 |

不增加：

- source public ID；
- `source_type`；
- `url_hmac`；
- `key_version`；
- source status/error；
- created/updated lifecycle；
- source operation job 或过期清理器。

新创建的 Asset 必须有 source，不能创建 source 与 binding 都为空的对象。本地旧 binding-only Asset
不兼容读取、不回填 source；实施时随本地扩展数据一起清理后按最新合同重新创建。

### 6.2 加密

直接复用本地 [scoped secret envelope](../../common/secret_envelope.go)：

```text
scope = "asset-source:" + asset.PublicID
EncryptShortLivedSecretForScope(scope, normalizedURL)
```

不新增 `asset_source_crypto.go`、独立密钥配置、密钥注册表或密文迁移。AssetSource 读取必须先
要求当前 scoped envelope 格式，再调用 scoped decrypt；不得使用该通用函数对旧 unscoped 密文的
兼容读取能力，因为本领域不存在旧 AssetSource 数据。无法解密时关闭当前 `source_url` 路径并
记录脱敏告警；已有 active binding 不受影响。

完整 URL 不进入响应、日志、错误、Task/attempt、metadata、metrics 或普通审计。Asset 删除时同步
删除 source 行；已声明过期后不再解密，不增加后台清理状态机。

### 6.3 `expires_at`

- `expires_at > 0`：创建、选渠和发送前按渠道最小 TTL 校验；不足时拒绝该解析路径；
- `expires_at = 0`：有效期未知，不解释为永久 URL，不识别厂商签名参数，按 best-effort 提交；
- Provider 抓取失败：按普通上游失败处理；
- active binding 已建立：source 过期不影响该 binding。

## 7. 实施包 C：创建、幂等与迁移

### 7.1 创建事务

重写本地 `createRemoteAsset` 流程：

1. 规范化 name、kind、media type、授权和 HTTPS URL；
2. 规范化完成后再计算幂等请求 HMAC；
3. 在事务中创建 Asset，由 `BeforeCreate` 生成 `ast_*`；
4. 使用 `ast_*` 作为 encryption scope，写入最小 AssetSource；
5. 写入或关联创建幂等记录；
6. 有 `model`/`target` 时可预创建 managed binding；
7. 没有提示时返回 source-only Asset；
8. source 与任一 binding 均不可用时才失败。

删除当前 `model`/`target` 强制二选一，改为“不能同时出现、允许都为空”。真人资源仍必须先通过
授权合同；不得利用 source-only 绕过授权。

### 7.2 幂等

唯一权威继续是 `AssetCreateIdempotency`：

- 作用域为 user + app + endpoint + Idempotency-Key；
- 请求 HMAC 覆盖规范化后的完整创建请求；
- 同键同请求返回同一 `ast_*`；
- 同键不同请求返回 conflict；
- 不在 AssetSource 增加第二个 URL HMAC 或 URL 去重索引；
- URL 字符串相同不等于媒体相同，重新签名后的 URL 也不做同一媒体合并。

### 7.3 客户显式换源

这里的“换源”是新合同中的客户业务操作，不是旧数据库兼容迁移。换源继续创建新 `ast_*`：

- 新 URL 写入新 AssetSource；
- `supersedes_asset_id`、batch 和 reason 保持可审计；
- 不覆盖旧 source；
- 不自动复制或迁移旧 binding；
- 不尝试通过 URL 判断新旧媒体相同。

## 8. 实施包 D：公开能力与内部实现分层

### 8.1 公开能力

本地 `VideoSKUCapability` 直接使用 `SupportsLinkAssets` 作为客户合同权威。因为该能力结构本身是
本项目新增代码，不需要保留公开 `SupportsManagedAssets` 过渡字段。一次完成：

- 增加 `SupportsLinkAssets`；
- 更新公开内容 hash 与 capability version；
- 把请求校验改为只读 `SupportsLinkAssets`；
- 删除公开 `SupportsManagedAssets` 字段及全部成员访问；
- 更新模型发现、Ability gate 和 fixture。

### 8.2 内部实现能力

在 Link 本地实现注册表中定义按
`(link_implementation_id, link_implementation_version)` 查询的内部能力：

```text
SupportsManagedAssets
AssetResolutionModes = [upstream_binding | source_url]
AssetSourceMinTTLSeconds
支持的 asset_kind / media_type / 数量与组合
```

内部能力注册项同时限定允许的 `channel_type`、`video_upstream_profile`、converter 和 adapter
version；profile 只描述协议适配形状，不能单独产生 Provider 身份或 Link 资格。不把能力字段本身
加入 new-api 上游 `ChannelOtherSettings`，也不放入客户 metadata/extra；渠道设置只保存窄的实现
ID/version。内部能力不参与公开 capability hash；Ability 发布和运行时只验证渠道绑定的精确实现
版本是否覆盖公开 Link 能力。

渠道引用采用 relaykit 新增文件定义的嵌套 `LinkImplementationRef{ID, Version}`，在上游
`ChannelOtherSettings` 中只增加一个字段。binding 保存实现 ID/version/content hash 普通列；Task 的
上游 `TaskPrivateData` 只增加一个嵌套 Link 快照字段，具体类型、哈希和解析逻辑均放本地新增文件，
避免在上游结构中散落三个平铺字段。

## 9. 实施包 E：选渠与 Resolver

### 9.1 候选渠道

对一个请求中的全部 Link Asset 计算同一候选渠道交集：

- 所有权、App、最终用户 subject 和真人授权有效；
- asset kind、media type、数量和组合符合公开 SKU；
- 每个 Asset 都存在作用域匹配的 active binding，或渠道允许 `source_url`；
- `expires_at > 0` 时满足最小 TTL；值为 0 时仅表示 best-effort。

单个 Asset 为 `ready` 不保证任意 SKU 或任意多 Asset 组合可执行。没有共同渠道时返回稳定的资源
不可解析错误，不向客户暴露 Provider 名称或渠道 ID。

### 9.2 Resolver

在本地 `relay/asset_reference_resolver.go` 内形成唯一实现：

1. 批量加载 Asset、最小 AssetSource 和选中渠道 binding；
2. 先执行现有所有权、App、subject、状态和真人授权校验；
3. active binding 优先；
4. 没有 binding 且渠道支持 `source_url` 时，检查已声明 TTL并解密 URL；
5. 新任务只接受代码注册的唯一当前实现；binding 必须匹配精确实现 ID/version/content hash；
6. 发送前再次校验授权、binding 作用域、当前实现版本和 TTL；
7. Task 只记录 Asset ID、可选 binding ID、解析模式和嵌套实现快照，不记录 URL 或 URL 指纹；
8. 未经解析的裸 `asset://ast_*` 不得进入 Provider converter。

`ErrAssetBindingRequired` 只用于明确需要 binding 的路径；通用无可解析路径使用
`ErrAssetReferenceUnresolvable`。已声明过期可使用 `ErrAssetSourceExpired`。不为
`expires_at=0` 创建错误或额外状态。

## 10. 实施包 F：FunCloud 普通视频

详细协议以
[FunCloud Seedance 2.0 中转接入分析方案](./2026-08-02-FunCloud-Seedance-2.0中转接入分析方案.md)
为准。Link 交界固定为：

- Standard/Fast 公开能力设 `SupportsLinkAssets=true`；
- 新增不可变的 FunCloud Link 实现 ID/version 注册项，其内部能力为
  `SupportsManagedAssets=false`、`AssetResolutionModes=[source_url]`；
- 只接受 `general` Link，不接受 `real_person`；
- 当前 9 图/3 视频/3 音频收窄为已证明的 3 图/1 视频/1 音频组合；
- 普通请求不创建 FunCloud AssetBinding；
- converter 只接受 Resolver 产出的 HTTPS URL，拒绝裸 `asset://ast_*`；
- 不实现、注册或发送 `realPersonMode=true`。

FunCloud adapter revision 直接切到唯一 v2。`CurrentVideoSouthboundAdapterVersion` 与
`ResolveVideoSouthboundAdapterVersion` 继续按渠道适配条件解析 revision；FunCloud 实现注册项必须
同时约束该 revision。空 snapshot、v1、未知 revision 或实现版本不匹配都 fail-closed，不保留兼容
parser。

## 11. 实施顺序

1. 删除 FunCloud 旧 raw-upload/multipart 本地链及其测试、配置和 UI；
2. 新增最小 AssetSource 与三数据库 migration 测试；
3. 重写创建事务和规范化幂等摘要；
4. 直接完成公开 `SupportsLinkAssets` 与按实现 ID/version 注册的内部解析能力分层；
5. 实现候选渠道交集、双模式 Resolver 和 converter 拒绝；
6. 切换 FunCloud 最新 JSON 协议和唯一 v2 revision；
7. 完成自动化、真实 Provider 和日志脱敏验收；
8. 同步用户指南、OpenAPI、运维手册和当前事实文档；
9. 实施完成后把本文归档到 `docs/99-archive/`。

旧 FunCloud 素材链和本地 binding-only 历史数据不参与上线和回滚。实施前直接清理本地扩展数据，
上线代码只支持最新 AssetSource、精确实现版本，以及 `upstream_binding`/`source_url` 两类素材解析
模式，不保留数据形状兼容分支。这里的两类解析模式是当前资源能力，不是实现版本双轨。

## 12. 测试门禁

### 12.1 代码来源与删除完整性

- `rg` 不再发现 `funcloud_real_person_stream`、`AssetVerificationCompletion`、
  `UploadRealPersonAuthorizationAsset`、`RealPersonAssetUploadAttempt` 的生产引用；
- 本地旧入口、attempt、binding 和相关扩展数据已清理，代码中没有扫描、回填、双读或 fallback；
- 路由和 OpenAPI 不包含旧 raw-upload endpoint；
- AutoMigrate 不再注册旧 attempt model；
- 管理端不再显示旧 FunCloud asset profile；
- 对 `model/main.go`、`channel_settings.go`、`channel-form.ts` 和 `types.ts` 的改动只删除本地插入行，
  不重排上游代码。

### 12.2 Source 与幂等

- 三数据库均能保存和按 Asset 加载最小 AssetSource；
- 数据库只出现密文，响应和日志搜索不到完整 URL；
- scope 不匹配、密文篡改和无法解密均关闭 source 路径；
- legacy unscoped 密文不能作为 AssetSource 解密；
- `expires_at > 0` 的过期和 TTL 不足在发送前拒绝；
- `expires_at=0` 不被当作永久保证，允许 best-effort 提交；
- active binding 在 source 过期或无法解密后继续可用；
- 同键同规范化请求重放，同键不同请求 conflict；
- 不存在 URL HMAC、URL 唯一索引或 source 状态机。

### 12.3 路由与能力

- binding 与 source 同时存在时优先 binding；
- 多 Asset 请求只选择能解析全部资源的渠道；
- `ready` 不绕过 SKU、渠道和发送前校验；
- 公开视频校验只读取 `SupportsLinkAssets`；
- 内部解析能力不进入公开 capability hash；
- 同一公开 SKU 的多个实现只比较公开 capability，implementation ID 不进入公开 hash；
- 渠道绑定的实现 ID/version 与 profile、converter 或 adapter version 不匹配时失败关闭；
- 开发期确认实现从 v1 升级到 v2 时，注册表、专属 adapter/parser、fixture 和测试中不再存在 v1；
- v1 binding、Task、attempt 和 exposure 本地数据已清理，v2 不读取、不迁移也不回退到 v1；
- 版本切换只修改本地 Link 文件；new-api 上游文件继续保留极窄当前版本接线；
- 每个 Provider converter 都拒绝裸 `asset://ast_*`。

### 12.4 FunCloud

- Standard/Fast 都是 managed false、source URL only；
- 只支持已证明的 3 图/1 视频/1 音频组合；
- 普通请求不创建 AssetBinding；
- v1、空 snapshot 和未知 revision 均 fail-closed；
- 没有 `realPersonMode=true` 可达路径。
