# 对象存储凭据保存方式简化

## 问题与目标

管理页面保存 Azure 凭据因缺少固定 CRYPTO_SECRET / SESSION_SECRET 被阻止。
用户确认采用与 NEWAPI 渠道密钥一致的数据库保存方式，不增加部署环境配置。

## 当前实际情况

- 专用配置改为保存 credential，删除对象存储专用加密模块。
- 保存前仍验证读写、预签名访问和清理结果；失败保留既有配置。
- 最高管理员专用接口和通用 OptionMap 隔离继续保留，查询与审计不返回密钥。
- 数据库和备份包含可用凭据，接受与渠道密钥相同的访问保护边界。
- 旧 credential_ciphertext 不双读、不自动解密；管理员重新输入一次密钥更新。
- 本次未修改图片执行会话实现。原生 option/router 文件仅修正既有接线注释，
  无新增控制流，上游同步冲突面仅涉及原有两行注释。

## 优化方案

验证无环境密钥时管理接口完整保存、凭据不回显、进程密钥变化后配置可重新装载，
以及旧加密记录缺少新凭据时不激活、重新输入后恢复。保持 Azure 与 S3 共用同一配置合同。

本次验证使用本地测试数据库及 HTTP 模拟存储；不代表 Azure 生产验证或部署完成。
上线需更新应用，未保存成功的配置重新提交；已存在旧加密记录的部署重新录入凭据。

## 验证结果

- 配置、模型、服务与控制器的对象存储回归通过；图片查询与入口存储校验回归通过。
- 管理接口无环境密钥时保存成功，数据库包含凭据，响应及审计不包含测试密钥。
- 前端 typecheck、目标组件 lint、七种语言同步通过。
- docs:check、ai:check 和差异空白检查通过。
