# 媒体请求证据配置化与七天数据库保留方案

## 1. 背景与已确认目标

用户提供的线上统计：数据库约 1.1GB，证据事件表约 304MB；近期证据元数据每日新增约
45–74MB；证据正文约 33GB，轮询约占历史事件数 75%。本次未连接生产数据库或 Provider
核验，统计不是本地实测。原先全站采集、仅回收正文的合同不能控制数据库增长。

用户已确认改为：仅采集明确媒体操作；正文与数据库证据数据均有期限。本文替代此前全站
采集和长期保留事件元数据的目标，保留首次文件路径。代码验证与生产验收分开，实施不含
线上删除、部署或自动 VACUUM。

## 2. 采集边界

| 操作 | 范围 |
| --- | --- |
| 图片生成/编辑、MJ 图片操作、异步图片执行 | 纳入 |
| TTS、转写、翻译、音乐生成 | 纳入；纯歌词/文本任务排除 |
| 视频创建、查询、取消、后台执行与轮询 | 纳入 |
| 媒体素材/素材组操作 | 纳入；source URL 禁止留存不变 |
| 普通聊天、Responses、Gemini 通用多模态、Embedding、Rerank、Batch、通用文件和模型列表 | 排除 |
| 管理面、静态、健康检查、证据读取 | 排除 |

唯一媒体判定放在本地证据服务；依据已登记方法/业务路径和冻结 Task 协议/类型，不猜模型
名称、价格或空模型字段。不引入类型环境变量、全站别名或平行取证系统。前台观察器、专用
会话、后台图片、JS 插件、轮询与交付共享资格；不改原生路由、分发或计费资格。

MJ 按已登记操作匹配 `/mj` 与 `/:mode/mj`，不以路径包含 `/mj/` 取得资格；管理列表排除。
Suno 的 MUSIC/LYRICS 按业务大小写语义处理，纯歌词创建及查询排除。`POST /v1/tasks/:key`
只是候选入口，准备阶段固定的插件须声明图片/视频协议或明确 MUSIC 操作才建立媒体会话；
通用文本插件不落库。通用媒体创建的索引保存资格，后续不读取当前插件配置重新解释旧 Task。

## 3. 配置与期限

- `TASK_REQUEST_EVIDENCE_ENABLED` 默认 false，仅显式 true 开启；禁用仍清理存量。
- `TASK_REQUEST_EVIDENCE_RETENTION_DAYS` 默认 7，允许整数 1–7；正文和事件明细跟随
  此期限，不支持永久保留。非法值沿用响亮报错合同。
- 普通证据索引最多保留七天。缩短正文期限或手动提前清理后，仅保留关闭索引到七天上限，
  阻止较早关闭的任务续采；不建立永久墓碑。
- 访问审计按访问时间独立保留七天，不随父索引立即级联删除，不复制正文。
- 证据清理/监控两类 SystemTask 历史保留三十天，保留各类型最新调度记录；其他系统任务
  历史和金融审计不属于本轮自动删除范围。
- 正文上限、稳定密钥、存储目录、写入超时沿用；不移动对象，不更换密钥。

后台及任务相关操作以可信 Task 创建时间为固定时间锚点，已有更早索引期限继续有效。
`SubmitTime` 可能由轮询响应改写，不作为不可变锚点。过期 Task 不得因索引消失而重新按当前
时间建证据；历史无可靠时间仅跳过采集并给出净化诊断，不拦截已有履约。客户新创建媒体请求
独立计算期限。任务查询/交付不得给同一 Task 续期。所有实际轮询继续取证，不引入采样。

原生 MJ 使用独立任务表，其 SubmitTime 会被 Provider 通知改写。创建请求观察到可信已落库
任务 ID 后，把请求开始时间和鉴权用户/应用固定到证据索引；单项与批量查询只复用该索引。
历史无此锚点、索引已删除、已关闭或超期时跳过取证，不从当前请求或 SubmitTime 补建。
原生 MJ 的 TokenId 是计费退款标记，不能充当应用所有权；证据应用边界取自创建时鉴权事实。
未鉴权的原生公共 MJ 图片交付不补建证据，不改变其原生交付权限。

## 4. 清理顺序与恢复

1. 持久 `cleanup_requested_at` 关闭读取和新增事件；既有 Root POST 截止时间和操作者
   原子受理不变，409 跟随运行任务，不修改其范围。
2. 稳定索引游标、小批次事件分页，按事件 ID 命名规则删除对象，包括回写失败窗口。
3. 文件全删成功且目录安全回收后标记 `body_expired`；缺失文件幂等单独计数，未知文件保留
   并报告失败，不递归删除根目录。
4. 在短事务内分批删除事件；数据库删除失败保留索引，下轮继续处理 `body_expired=true`
   的行，不能沿用仅扫未过期正文的筛选漏掉它们。
5. 七天索引期限到达后，确认关闭且没有事件，再删除索引。手动提前清理的索引保留到上限。
6. 独立分批删除七天前访问审计、三十天前证据任务历史；清理历史不得删除活动任务及最新
   调度记录。失败明确进入任务结果及告警，不能伪装成功。

对象 IO 不占数据库事务。新增事件的事务必须锁定并检查索引存在、未关闭、未到期后再插入；
正文最终发布仍复核相同索引锁。late callback 不能在父索引删除后插入孤儿事件或文件。
事件完成回写是 UPDATE，不允许缺失事件重新 INSERT。所有无正文的传输/交付事件也走守卫。
旧索引不论 Kind、retain_until=0、body_expired=true 均纳入相应历史回收；孤儿事件应先按命名
规则回收对象再删行。失败项不在同轮无限重扫，取消可恢复。所有数据库操作兼容三种数据库。

## 5. 交互、监控与统计

Root 日志维护入口复用现有选择截止时间、确认、运行进度与历史详情。文案说明正文与明细
不可恢复，关闭索引可能短期保留，Task/账单独立。页面不把数据库删除行数换算成释放磁盘字节。

结果保留原文件计数，并增加删除事件/索引/审计/历史行数、数据库失败数。监控增加数据库待
回收索引数及最老时间；正文回收完成不等于数据库回收完成。统计仅计数及净化类别，中英文
同步。无记录时显示“未采集或已超过保留期”，不凭空断言曾经删除。

事件、孤儿事件、访问审计和证据任务历史每批删除后持久化实际累计进度，索引删除后再次更新。
进度写入失去任务租约时停止，不覆盖其他执行者的状态；最终结果仍记录实际完成计数。

## 6. 验收与上线

- [x] 已接入媒体前台成功/失败/拒绝及后台可取证；管理与纯文本无新增索引、事件、审计或正文；未接入交换仍以架构覆盖矩阵为准。
- [x] Task 轮询共用索引与固定期限；到期/删除后不重建；不影响业务轮询与结算。
- [x] 所有事件在关闭、到期、父行不存在时拒绝追加；超时 worker 不产生晚到对象。
- [x] 历史零期限和已 BodyExpired 行能回收；事件分页、部分删除/失败/重启可继续。
- [x] 手动提前清理后关闭索引保留到上限；忙碌范围不变；同阶段去重不回退。
- [x] 审计独立七天、证据任务历史三十天；活动/最新记录及其他类型不误删。
- [x] 文件失败保持定位依据；缺失幂等；未知文件不删；不回收正式产物/输入/Task/账单。
- [x] SQLite、MySQL >=5.7.8、PostgreSQL >=9.6 的迁移、并发与删除合同验证。
- [x] 前端状态/计数/中英文、类型与构建、docs:check 与 ai:check 通过。
- [ ] 生产副本验证历史回收；灰度观测新增/删除速率、最老积压、磁盘/inode/数据库页复用。

上线先恢复可用空间、备份并在副本验证，再发布显式媒体开关的镜像。历史七天内非媒体证据
不在升级时默认提前删；Root 可按明确截止主动回收。SQLite 删除后先复用空闲页，需要缩小
文件再安排维护窗口，不在请求或周期任务自动 VACUUM。容量取决于媒体流量和清理吞吐，
七天期限不承诺固定容量，失败积压可能延长物理删除时间。

## 7. 实施与验证记录

- 媒体资格集中在 `service/media_evidence_scope.go`；前台、后台与插件轮询共用，Batch 保留既有
  调用接线但不采集；通用任务查询仅在鉴权后按冻结 Task 类型取证。
- `model/task_request_evidence_lifecycle.go` 统一事件登记守卫、Task 固定窗口、分批事件/索引/
  审计/证据任务历史删除；既有对象发布复用同一索引锁，不新增 Task 清理状态机。
- 小时清理支持已 BodyExpired 行、历史零期限、分页及孤儿对象；对象失败保留事件定位，
  数据库失败下轮继续，存储不可用不阻塞独立审计/任务历史 TTL。二进制交付仅保存统计。
- 本地完整 Go 回归：service/controller/router/model/middleware/system_setting 六个包通过；
  并发 race 回归与 go vet 通过。真实隔离 MySQL 5.7、PostgreSQL 9.6 验证迁移、关闭守卫、
  固定任务窗口与分批删除；SQLite 验证失败恢复、501 事件跨页、手动关闭、孤儿对象。
- 前端八个测试文件共 87 项通过，类型检查、相关文件 lint、生产构建（含文档/品牌验证）通过。
  全站 lint 存在其它文件的既有错误，本轮未改动这些文件；不宣称全站 lint 通过。
- docs:check、ai:check 与 diff 空白检查通过。源码实现不等于生产发布；仍需执行第 6 节最后一项
  生产副本与灰度容量验收。本次未访问生产数据、部署、VACUUM、提交或推送代码。
