# Link 插件列表与模型定价告警修复实施方案

## 问题与目标

rc.51 合并后，已安装插件页面无法看到 Seedance Link 和 MiniMax Link，系统设置同时提示七个模型的价格需要处理。
本次修复应恢复两个 Link 扩展的管理可见性，并让原生插件价格告警以实际可履约的渠道为准。四个 `-b` 客户模型
的 Seedance Link 定价单独核对和处理。插件列表、告警和价格配置分别验收。

## 修复前的实际情况

以下结论来自本地 PostgreSQL 的只读查询、管理接口处理函数和运行时规则验证。线上当前插件响应、价格配置、
真实请求和部署结果待核对。

| 现象 | 本地证据 |
| --- | --- |
| 插件页缺少两个 Link 扩展 | 插件列表接口返回 19 条。两条 Link 记录均启用且状态为 `registered`。专用分支在填充分类字段之前结束，三个分类字段均为 `false`，页面计数因此为任务 11、渠道 0、请求处理 6，与截图一致。 |
| 七条原生插件价格告警 | `GetEnabledModels` 将 Seedance Link 和 MiniMax Link 客户模型追加到全站启用模型投影，原生别名视图也读取全部启用渠道的映射。告警按这些投影匹配原生插件。触发告警的实际渠道逐个检查均不具备对应插件的履约资格。 |
| 四个 `-b` 客户模型在补价前缺价 | 本地四个模型都配置在已启用的 Seedance 专用渠道，当前视频协议为 `modelark_v3_volcengine`，均能固定 `seedance-link` 版本。补价前四个完整客户模型名下均缺计费表达式和正数预扣 Token 上限。 |

七条误报的具体表现如下。

- `MiniMax-H3` 的现有表达式使用 `output_seconds`、`input_image_count` 和小写 `2k`，符合当前
  MiniMax Link V2 计费用量合同。将同一表达式用于 Hailuo 原生插件用量会因字段缺失报错。
  小写 `minimax-h3` 走京东云 MiniMax Link，按自己的表达式和用量字段校验。
  [Link V2 用量字段](../../pkg/minimaxlink/official_usage.go) · [Hailuo 用量字段](../../plugins/tasks/hailuo/plugin.js)
- `doubao-seedance-2-0-260128`、`doubao-seedance-2-0-fast-260128`、`doubao-seedance-2-0-mini-260615`、
  `doubao-seedance-2-5-260628` 来自 Seedance Link 的上游模型映射。告警读取到这四个上游名称下保存的旧
  `c` 表达式，判定无法用于 Doubao 插件任务计费，显示「还没设置价格」。
- `doubao-seedream-5-0-260128`、`doubao-seedream-5-0-pro-260628` 来自图片中转的上游模型映射。
  实际客户模型 `seedream-5`、`seedream-5-pro` 分别已有按张价格和计费表达式。
  [图片中转取价](../../relay/helper/image_relay_billing.go)

全站启用模型投影仍供模型发现等既有调用方读取。本次收窄的是原生插件价格告警的检查范围。

## 优化方案

### 1. 恢复已安装插件页面的 Link 扩展

1. 插件管理列表、详情及上传成功响应使用同一分类语义。两个保留 key 输出 `link: true`，原生
   `task`、`provider`、`transform` 均显式为 `false`，`skipped_routes` 为 `[]`。详情接线在
   按版本读取并编译制品后生效，覆盖当前版和历史版。Link 制品的严格清单拒绝 `fetchMode`，现有详情的原生
   parts 推导对合法 Link 制品已经会给出 `task: false`，本次明确的是管理分类与输出合同。
   详情和上传使用已保存的插件 key。启用状态、注册版本和同步诊断由专用存储与同步状态提供。
   编译失败的版本在列表可见并展示错误，列表中的版本与已注册版本一致时才标记为已注册。
   [插件列表和详情](../../controller/task_plugin.go) · [Link 清单校验](../../pkg/jsplugin/seedance_extension.go) · [专用运行状态投影](../../controller/seedance_plugin_extension.go)
2. 「已安装」页在本地模块定义 Link 扩展分类及计数和筛选。插件市场继续使用共享的原生三分类定义。
   管理路由接收 `kind=link`，切换到市场时按合法的原生分类展示，从市场返回后可进入 Link 分类。
   Link 的卡片、表格、搜索、详情分类和中英文文案使用同一管理标记。详情保留版本、源码和差异入口。
   [共享原生分类](../../web/src/features/task-plugins/lib/plugin-kinds.ts) · [当前页面入口](../../web/src/features/task-plugins/index.tsx)
3. Link 管理标记用于插件列表、详情和上传成功响应。通过回归验证两个 key 均未进入 `/api/task_plugin_options`、
   原生渠道绑定选项、请求处理插件选项和原生注册表。专用渠道继续读取现有配置接口。
   [绑定选项来源](../../controller/task_plugin.go) · [Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)

### 2. 按实际履约渠道判断原生插件价格告警

1. 从原生 `abilities` 表读取已启用的模型和渠道关系，批量关联现存且启用的渠道。按模型名与渠道去重，
   查询字段限于关系键、渠道 `id`、`type`、`status`、`setting`。对每对模型名 `n` 与渠道 `C`，
   依次查找插件声明名和原生全局别名；再用同一个 `C` 验证声明该模型的每个插件 `P` 的身份。两项成立
   才记录 `served[P][M]`。原生候选可以使用其他原生渠道登记的别名，沿用共享入口解析。
   专用渠道沿用已有的 Ability 类型门禁，从原生别名索引的输入排除。
   [当前告警入口](../../model/model_pricing_config.go) · [运行时渠道过滤](../../model/channel_constraint.go)
2. 构造 `FilterTaskPluginIdentity`，填写待检查插件的 `TaskPluginKey` 与 `TaskPluginChannelTypes`，
   直接复用 `channelMatchesFilter`。每次只检查一个插件，避免把同名候选的类型或绑定合并为他方资格。
   原生类型、Task Plugin 绑定和 New API 扩展绑定统一由现有过滤器判断。对于使用 `setting` 的绑定类型，
   先对读取投影做只读合法性检查，无法解析时该候选无法证明插件资格。`Channel.GetSetting()` 遇到非法 JSON 会尝试
   清空数据库字段，因此调用既有过滤器前应阻断这条写入路径。
   [渠道设置读取](../../model/channel.go)
3. 在独立文件收集范围，`GetModelPricingIssues` 的两处消费同时接入同一结果。只将有
   `served[plugin.Meta.Key][name]` 的已加载插件声明模型加入候选，并在变体循环按
   `served[variant.PluginKey][entry.ModelName]` 判断服务资格。已保存插件表达式始终进入失效检查，
   保持现有 `stale` 与暂时停用插件的分支顺序，随后才判断 live 插件的渠道资格和价格兼容性。
   失效检查与渠道无关，表达式优先级、按次价格和价格结算沿用现有实现。
4. 全局模型定价告警和插件操作返回的单插件告警共用上述入口。普通中转可以使用已有原生路由和计费，
   其上游模型映射只作中转配置。两类告警都按插件及渠道资格验收。
   [普通中转与插件任务分流](../../middleware/task_plugin.go)

### 3. 核对并补齐 Seedance Link 客户模型价格

1. 在线上通过渠道管理和模型定价页面，按完整名称逐项核对以下四个模型的启用状态、实际视频协议、价格模式、表达式和
   预扣 Token 上限。客户模型名、上游模型名和渠道协议分别记录。

   | 客户模型 | 补价前本地表达式 | 补价前本地预扣 Token 上限 |
   | --- | --- | --- |
   | `seedance-2-0-b` | 缺失 | 缺失 |
   | `seedance-2-0-fast-b` | 缺失 | 缺失 |
   | `seedance-2-0-mini-b` | 缺失 | 缺失 |
   | `seedance-2-5-b` | 缺失 | 缺失 |

2. 线上若确认缺价，按该渠道和模型已确认的客户单价，通过现有模型定价入口分别配置 `tiered_expr`，使用协议用量字段
   校验并试算。预算要求以 `RequiresTokenBudget` 为准。本地四项使用的 `modelark_v3_volcengine` 即使采用
   仅读取冻结参数的表达式，也需要正数预扣 Token 上限。售价采用对应 Seedance 模型的火山方舟在线推理刊例价，
   按现有固定系数 `0.147 USD/CNY` 换算，应用渠道实际允许的分辨率，并以可信完成 Token 按档结算。
   [保存校验](../../model/seedance_billing_expression_validation.go) · [预算策略](../../pkg/seedancebilling/contract.go) · [Link 预扣取价](../../relay/helper/task_tiered_price.go)
3. 保存前记录四个模型各自的原配置和试算结果，作为生产配置变更及回退依据。优先处置线上确认缺价且对客户开放的模型，
   分类与告警修复可独立验收。需要回退时通过管理入口恢复最近一份通过校验的价格。首次补价前的空配置无法通过
   Seedance 保存校验，此时按现有渠道管理流程处理受影响模型的可用性，并先核对同渠道其他模型的影响。
   既有任务继续使用创建时冻结的计费事实。
4. 本次保留 `MiniMax-H3` 的 Link V2 表达式和四个 `doubao-seedance-*` 上游名称下的旧 `c` 表达式。
   Link 读取完整客户模型名下的表达式。旧价格条目仍可能被原生模型读取，清理前需独立核对原生用途。
   将来若为这四个上游名称启用原生 Doubao 履约渠道，应按该插件用量合同独立核价。
5. Link 缺价诊断列为后续事项。本轮通过实际渠道和客户模型名手工核验四个 `-b`。
   后续检查应直接使用 Link 类型、渠道协议与现有定价校验，原生插件告警仍按原生插件合同处理。

### 插件列表

使用本地 PostgreSQL 的只读事务运行新代码的列表、版本详情和绑定选项处理函数。列表共 19 个不同 key，
原有任务、渠道和请求处理分别为 11、0、6，新增 Link 扩展分类为 2。逐项核对结果如下。

| 插件 | 本地验收 |

### 复审修复与验收

- 原生别名由原生渠道登记。符合插件身份且有启用 Ability 的原生渠道可以使用其他原生渠道登记的别名；

  共用存量版本投影。临时 MySQL 5.7 在大小写不敏感排序规则下用大写 key 读取两条详情，均正确归类。
