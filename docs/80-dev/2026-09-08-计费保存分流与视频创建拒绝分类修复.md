# 计费保存分流与视频创建拒绝分类修复

## 问题与目标

依据[图片视频与素材全渠道真实验收](2026-09-08-图片视频与素材全渠道真实验收.md)，本轮只处理已定位的两处代码问题：

1. Seedance 客户模型映射到原生 Doubao 插件模型后，管理保存先命中插件别名校验，Link 表达式没有得到 `_task.duration_seconds` 等探针，导致整批价格无法保存。
2. 已确认的 TokenSave 分组权限拒绝、火山鉴权拒绝、移动云无效 Key 返回仍归为创建结果未知，造成新请求预扣无法按明确拒绝释放。

遵循[硬约束](../00-context/硬约束.md)与[异步任务与计费事实架构](../20-architecture/账单计费-异步任务与计费事实架构.md)，不新增状态机、重试、跨渠道 fallback 或资金处置入口。

## 当前实际情况

### 代码修改

- `controller/billing_expression_validation.go` 根据已启用 Seedance Channel 的客户模型精确匹配，优先使用既有 Link 表达式校验及协议探针。其余模型保留原生插件、别名和普通表达式校验。查询失败直接返回错误，不按普通模型继续猜测校验。
- 删除仅被测试调用的旧批量 controller 校验函数；测试改为调用真实 `UpdateOption`，覆盖客户别名与插件模型重合、直接使用插件同名模型、协议专属字段和负价格拒绝。
- `relay/task_create_disposition.go` 在既有分类边界读取结构化响应：TokenSave 的 HTTP 403 + `group_model_permission_denied`、火山 ModelArk 的 HTTP 401 + `AuthenticationError`、移动云 ModelArk 的 HTTP 403 + 无错误码且消息精确为 `api key is invalid`，按明确拒绝处理。
- 已有特定协议余额不足分类和 FunCloud V3 拒绝分类保留。无法解析、错误信息缺失、根级任务 ID 或非空 data 信封均保留 unknown。未登记协议/状态/错误组合、飞彩 503 和网络未知结果没有新增释放规则。
- 分类使用当次响应，公开脱敏信息不参与资金决策。没有保存原始 Provider 响应。
- 资金释放继续调用既有幂等入口，不修改历史 attempt。火山上游 401 对外仍为既有 502 `upstream_auth_error`，不与客户 Key 的鉴权失败混淆。

### 原生文件最小接线说明

| 文件 | 必要性与接线 | 上游同步影响 |
| --- | --- | --- |
| `controller/option.go` | 保存入口必须在插件模型/别名查询前选中明确的 Seedance 校验；仅添加窄分支，校验主体在 Link 专属文件 | 仅表达式保存分派附近需要对照合并；不修改插件或通用别名实现 |
| `relay/relay_task.go` | 将当次响应正文交给既有分类函数，以排除任务 ID 与错误同时出现的矛盾响应 | 仅非成功创建响应的分类接线；FunCloud 分派移入既有分类函数，减少热路径分支 |

### 验证范围

- 真实管理入口回归：插件模型/别名碰撞时合法 Link 价格保存成功；跨协议字段及负价格失败且不写入配置；原生插件别名继续使用自己的 usage schema。
- 创建结果分类回归：精确协议/状态/错误码匹配、未知组合、无效 JSON、缺失错误信息、矛盾任务 ID、原生渠道边界。
- 本地 HTTP 集成回归：发送前已建立 durable hold；每次只发送一次；明确拒绝不创建 Task，用户与 Key 的预扣均释放；重复释放不增加余额；矛盾响应及未登记服务端错误保留 unknown 和预扣。
- 本地测试使用内存 SQLite 与模拟 Provider，不调用真实付费上游。未改运行中服务、账户配置、价格或历史冻结资金。
- 已通过 `go test ./controller ./relay ./setting/billing_setting -count=1`、`task docs:check`、`task ai:check` 与 `git diff --check`。两项已有管理测试补齐内存数据库准备，避免依赖其他测试遗留的已关闭连接。

## 优化方案

两处代码修改及包级回归已完成；真实服务需要重新构建、重启后才会使用新逻辑。
