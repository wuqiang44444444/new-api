# 客户合同模板功能分析与实施方案

> 本文首次形成于 2026-09-18，2026-09-20 因原文件在当前工作区缺失，根据会话确认记录重新生成，
> 保留原文件名。代码已实现并完成本地自动化验证；真实数据库升级与生产验收仍未完成。
> 以下需求与设计保留为本次实施依据，当前实现与验收边界见文末记录。
> 重新生成时核对了最新合同事实：合同已按 ADR-0020 承担调用范围与折扣配置，不能继续沿用
> 早期“合同只提供折扣、不影响调用范围”的描述。本次模板功能沿用当前合同行为。

## 问题与目标

管理员为多个客户创建相似合同时，需要重复配置模型、来源渠道、分组和折扣。本次增加全站共享的
合同模板，支持在创建用户合同时复用配置，减少重复操作与漏配。

这里的合同是系统现有的客户模型合同，不是需要下载、签署的文书。模板生成的是归属于目标用户的
一份独立合同，不是用户专属模板。一个用户可以同时拥有多份启用合同，每个 API Key 至多绑定一份。

### 用户已确认的需求

| 项目 | 确认结论 |
| --- | --- |
| 自定义模板 | 管理员可以创建、编辑合同模板 |
| 模板内容 | 保存完整的模型、来源渠道、分组和折扣规则 |
| 模板来源 | 支持直接新建，也支持将已有用户合同另存为模板 |
| 共享范围 | 全站管理员共享使用和维护，记录操作人 |
| 管理权限 | 为用户创建合同继续遵循现有用户管理权限 |
| 套用与调整 | 创建用户合同时选择模板，带入全部规则，可针对当前用户增删规则、调整来源和折扣 |
| 保存产物 | 保存到现有客户合同体系，归属于目标用户 |
| 独立维护 | 模板只用于创建；生成后独立维护，模板修改不影响已有合同 |
| 失效来源 | 渠道停用、模型移除或分组删除时保留全部规则并标出失效项，修正或删除后才允许保存新用户合同，不自动跳过 |
| 模板生命周期 | 支持停用和恢复，不提供删除；停用后不能再套用，保留模板和修改记录 |
| 新合同状态 | 通过模板创建的新合同默认启用，可以与已有合同同时启用 |
| Key 绑定 | 保存不会自动绑定或替换现有 API Key 的合同，继续使用现有 Key 绑定流程 |

### 成功标准

管理员创建一个标准模板，分别为甲、乙生成合同，并在创建时单独调整甲的折扣。
模板后续修改或停用，甲、乙的合同、原有合同及 Key 绑定均保持不变。
含失效来源的模板仍完整展示规则，管理员明确修正后才能保存，不能静默减少配置。

### 首期范围

- 在新建用户合同时套用一个模板；不对已有合同重新套用，不合并多个模板。
- 不提供模板到用户合同的同步、批量改价、继承覆盖或自动更新。
- 不重新设计现有合同授权、选渠、折扣和计费语义；模板本身不参与运行时。
- 不自动停用已有合同，不自动换绑 Key，不增加文书、在线签署或客户自助模板管理。

上述首期范围是围绕“模板只用于创建”制定的实现边界，不扩大已确认需求。

## 优化方案

以下为拟实施方案，区分于上文用户明确确认的业务决策。实施时可按当前代码约定细化名称与布局。

### 1. 管理界面与操作流程

#### 1.1 模板管理

在现有“客户合同”页面增加“合同模板”入口，进入独立管理视图。
列表支持名称搜索、启停筛选和分页，展示名称、状态、模型数、规则数、失效规则数、更新时间及操作人。
模型数按公开模型去重，规则数按渠道规则计，两者不混用。

支持新建、查看、编辑、停用、恢复及查看修改记录，不提供删除。
模板名称必填，身份使用稳定 ID；不以名称自动合并模板。
本方案建议新建模板默认启用，并允许管理员选择停用保存；模板启停和用户合同启停分别管理。
所有修改记录操作人、原因及版本；停用和恢复不会修改任何已生成合同。

规则编辑尽量复用现有规则列表、添加规则及折扣解析组件。模板没有客户归属，不能借用某个客户的
特殊组倍率；可提供来源的一般价格参考，不将预览金额保存为承诺价格。
模板编辑使用无客户上下文的管理员来源选项接口，返回当前可选模型、渠道与组；不传入虚构用户 ID，
不借用创建管理员所属组计算客户价格。新建用户合同时再读取目标用户上下文的现有预览接口。

#### 1.2 已有合同另存为模板

1. 在已保存合同视图提供“另存为模板”，先校验管理员对源合同所属用户的管理权限。
2. 从服务端读取已保存合同版本，复制完整规则；模板名称可预填并修改。
3. 不复制用户身份、Key 绑定、历史审计或源合同启停状态。
4. 管理员可调整模板草稿，填写名称和创建原因后保存。
5. 源合同保持不变，新模板后续不与源合同同步。

若源合同有未保存编辑，应明确提示另存采用已保存版本；不要把未提交草稿冒充已保存合同事实。
复制来的失效规则仍展示，修正或删除后再保存新模板。另存复用普通模板创建接口，不建立双向关联。

#### 1.3 从模板创建用户合同

1. 管理员进入目标用户的新建合同流程，可以选择空白创建或一个启用模板。
2. 模板带入全部规则，名称可预填模板名称并允许修改；模板创建草稿默认启用。
3. 按目标用户与当前有效来源重新计算价格预览，不复制源客户或模板历史预览金额。
4. 允许编辑名称、启停、模型、渠道、组和折扣；修改仅影响新合同草稿。
5. 失效规则保留原模型与来源标识，标明原因；不能因为下拉选项消失而把规则过滤掉。
6. 管理员修正失效项、填写创建原因后提交，经现有合同创建入口保存新合同。
7. 成功后展示新合同，可通过现有 Key 管理流程绑定；不自动写入 Key。

已有合同和绑定保持不变。模板创建初始启用，不改变空白创建、历史客户端省略启用字段时的默认行为。
草稿已有改动时切换模板，需要确认替换整份规则；取消时保留草稿，不隐式合并多个模板。
创建前清楚展示最终模型、组、渠道和折扣，避免只看到折扣而忽略当前合同的范围约束。

### 2. 数据结构与事实源

建议新增独立模板表：

| 表 | 字段与约束 |
| --- | --- |
| `customer_contract_templates` | ID、名称、启用状态、单调版本、创建/更新时间、创建及修改管理员；全站共享，无客户归属 |
| `customer_contract_template_rules` | 模板 ID、公开模型、渠道 ID、组、`ratio_units`；唯一键为模板 ID + 模型 + 渠道 |
| `customer_contract_template_audits` | 模板 ID、版本、操作人、create/update/enable/disable、原因、变更前后快照及时间；只追加 |

建议用户合同增加可选的 `source_template_id`、`source_template_version` 和创建时模板名称快照。
这些字段仅用于创建来源追溯，普通创建与历史合同保持无来源，不回填。
来源不保证最终规则与模板完全相同，不参与授权、选渠、计费或合同后续更新。
模板 ID、版本、内部模板名称快照与模板审计仅管理员可见，不加入 `ContractEntityUserView`、
用户自助合同接口、客户 Key 明细或公开价格响应。保持显式响应投影，不直接返回数据库实体。
用户合同的客户可读名称继续沿用现有展示规则；即使管理员将合同命名为模板名称，也不等于开放内部来源字段。

模板复用现有规则规范化：至少一条规则、精确模型名、同模型同折扣、同模型同渠道不重复、
拒绝仅大小写不同的模型名。折扣使用八位定点整数，不另写浮点解析或一套宽松校验。

模板保存按新增/变更来源校验。历史已接受来源后来失效时，可以保留并展示，不妨碍停用。
恢复模板只恢复选择资格，不承诺全部来源可用；新用户合同保存仍校验全部最终规则。
可用性从当前渠道与组事实推导，读取失败要明确失败，不持久化另一份可用状态或授权名单。

### 3. 接口与权限

拟增加管理员接口：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/customer-contract-templates` | 分页、名称及启停筛选 |
| `GET /api/customer-contract-templates/options` | 无客户上下文的管理员模型、渠道与组选项，可包含按普通组倍率计算的价格参考 |
| `GET /api/customer-contract-templates/:id` | 模板规则、版本及来源可用性 |
| `POST /api/customer-contract-templates` | 创建模板 |
| `PUT /api/customer-contract-templates/:id` | 携带 `expected_version`，完整更新名称、启停和规则 |
| `GET /api/customer-contract-templates/:id/audits` | 分页修改记录 |

停用/恢复复用版本化更新，不提供删除接口。所有操作在服务端校验管理员身份，不仅隐藏前端入口。
共享模板不绕过目标用户管理权限；另存时读取源合同同样遵循既有授权。

模板选项接口复用现有模型/渠道枚举及来源资格判定，不复制一套授权规则，不经目标用户入口绕行。
接口不要求 `user_id`，也不应用某个客户的特殊组倍率；若返回价格参考，须标明无客户上下文，不能作为
目标用户成交价。只返回编辑所需的公开模型与管理员可见来源，不返回渠道凭据或上游私有响应。
已有失效规则由模板详情保留，不能根据选项列表中是否仍存在来过滤；选项查询失败明确报错，不返回成功空列表。

现有 `POST /api/user/:id/contract` 增加可选模板 ID 与模板版本，两者成对提供。
服务端检查模板存在、启用、版本匹配，以管理员最终提交规则生成用户合同。
来源名称和审计身份由服务端生成，不采信客户端伪造字段。
用户合同继续使用现有唯一写入入口，不提供另一套模板专属合同创建器。
用户合同更新不修改来源字段，API Key 与运行时不增加模板查询。

### 4. 事务、并发与异常

#### 4.1 模板状态与合同写入的一致性

模板写入应在同一事务完成版本比较、规则替换、版本递增及审计；停用和恢复也递增版本。
带模板来源的用户合同创建，应将模板状态/版本检查、用户合同、最终规则、来源快照和创建审计原子提交。

在现有本地合同创建函数内增加必要的事务接线，模板主体逻辑放独立文件；复用现有规则和审计实现。
普通创建保留当前来源校验时序；仅带模板来源的分支在创建事务中检查模板，并调用同一个来源校验函数
校验最终规则。实体、规则与审计仍共用一条写入路径，不复制创建器，不为调整时序另写校验算法，
也不在事务前后无目的地重复整套来源校验。

模板更新与模板创建合同协调同一模板行，使用项目 `lockForUpdate`；SQLite 使用其支持的事务/
条件写入保证，不假定存在行锁。若模板更新或停用先完成，持旧版本的创建必须拒绝；若合同创建
先成功提交，之后的模板修改或停用合法且不回写该合同。并发冲突或数据库忙碌时不能留下部分数据，
不能自动采用新模板版本重试。验收须验证这两种合法顺序，不能要求后来停用撤销已提交合同。

#### 4.2 来源可用性的保证范围

把渠道/组来源校验放入事务，只表示使用该事务下可读的数据库事实；它不会自动对 Channel、Ability
加锁，也不能冻结进程内组倍率。不得据此承诺“从校验到提交期间渠道和组都不会变化”。
模板行的状态/版本协调与渠道来源变化是两个边界，锁定模板行不能代替渠道资格检查。

服务端校验时已可观察到的失效来源必须拒绝，不依赖前端先前加载结果。校验后来源仍可能变化，
由现有运行时有效范围校验排除失效组合；无有效组合时按当前合同语义拒绝，不去范围外选渠。
不为模板功能增加渠道锁定或组配置冻结，不改变普通合同创建的并发语义。

#### 4.3 版本确认与草稿保留

模板版本匹配和模板是否启用分别检查：前者要求管理员明确确认当前参考版本，后者决定此模板能否
用于创建。强版本匹配是本方案采用的流程取舍，不是最终规则合法性的必要条件，也不能证明管理员
实际阅读过模板；最终规则仍须独立全量校验，来源字段只记录已确认的参考版本。

版本冲突只拒绝本次提交，不清空或作废草稿。界面保留合同名称、启停、规则、折扣及创建原因，
允许查看最新模板。管理员明确确认最新参考版本后，可保留当前定制规则继续提交；若选择重新套用
全部规则，则先确认替换草稿。读取最新模板本身不能自动更新来源版本、覆盖规则或重新提交。
无论保留定制规则还是重新套用，最终保存仍检查所确认的模板版本、启用状态及全部规则。

| 异常 | 拟采用的处理 |
| --- | --- |
| 套用后模板被修改 | 返回版本冲突，保留完整草稿；查看并明确确认最新参考版本后可保留定制规则，重新套用则确认替换 |
| 套用后模板被停用或不存在 | 拒绝本次模板创建，保留草稿；不自动去掉来源变成空白创建 |
| 保存前来源失效 | 返回明确失效项，修正或删除后重新保存，不跳过 |
| 删除最后一条规则 | 按现有非空规则要求拒绝保存 |
| 同时编辑模板 | 后提交的旧版本收到冲突，不覆盖已提交内容，未提交编辑保留 |
| 无权管理源合同或目标用户 | 拒绝操作，不因共享模板放行 |
| 持久化或审计失败 | 全部回滚，不留下部分模板、合同、规则或来源记录 |
| 来源读取失败 | 明确显示加载失败，不伪装成无规则或部分来源可用 |

上述冲突处置为本次评审后明确的实现方案，未实现或验证。草稿不能在后台自动改变；
不新增跨 Provider 探测或模板自动修复。

### 6. 验收标准

| 场景 | 预期 |
| --- | --- |
| 模板新建与共享 | 管理员甲创建，乙可使用和编辑；记录操作人；普通用户拒绝访问 |
| 已有合同另存 | 复制完整规则，不复制用户身份和绑定，不修改源合同；越权读取拒绝 |
| 两客户套用 | 甲乙生成不同合同，单独修改甲不影响乙及模板 |
| 默认启用与多合同 | 模板创建草稿默认启用，原有合同仍启用，已有 Key 绑定保持原状 |
| 空白创建回归 | 原流程与启用默认值保持不变，不强制来源 |
| 模板修改/停用/恢复 | 已生成合同内容、版本和绑定不变；停用模板不能再用于创建 |
| 失效来源 | 渠道停用/删除、模型移除、组删除均完整保留并标出；未修正不能保存新合同 |
| 规则合法性 | 同模型多渠道同折扣通过；冲突折扣、重复来源、大小写冲突、非法折扣和空规则拒绝 |
| 并发版本 | 模板变更先完成则旧版本创建被拒绝；合同先提交则后续模板变更不回写；多人编辑不能相互覆盖 |
| 冲突草稿 | 冲突后完整保留草稿；仅查看新版本不改来源或规则，明确确认后可保留定制规则；重新套用须确认替换 |
| 原子提交 | 写入失败不留下部分实体、规则、来源或审计 |
| 来源追溯 | 来源 ID、版本和名称来自服务端；允许用户定制；运行时不依赖模板 |
| 来源字段可见性 | 管理员可以追溯；用户自助合同、Key 明细和公开价格响应不含模板来源字段及模板审计 |
| 模板编辑选项 | 不提供客户 ID 即可读取管理员来源选项，不借用管理员或某客户的特殊倍率；普通用户被拒绝，读取失败不伪装空列表 |
| 来源变化边界 | 校验已观察到的失效来源拒绝；保存后来源失效按现有运行时范围校验拒绝或排除，不声称数据库事务冻结组配置 |
| 当前合同语义 | 模板生成与等价手工合同有相同有效模型/组/渠道范围和折扣，不绕过范围约束或 Key 安全校验 |
| 价格预览 | 按目标用户当前来源及适用倍率预览，不继承源客户预览金额 |
| 三库迁移 | 新建与重复升级通过，原合同数据和绑定不变 |
| 页面与语言 | 切换模板确认、来源失效、版本冲突、另存已保存版本提示及中英文均正确 |

后端新增或重写测试用 `testify/require` 与 `testify/assert`，优先确定性测试和实际可观察行为。
在模板/合同模型、控制器和页面最窄边界执行，再按风险扩展；不为覆盖率或静态文件布局写测试。

并发验证分开覆盖两类证据：

- 顺序冲突：读取版本后提交一次变更，再用旧版本保存，精确验证拒绝结果与数据不变。
- 受控并发：使用独立数据库连接与显式同步信号协调事务，验证竞争更新不能都成功，以及合同创建与
  模板修改/停用的两种提交顺序。结果断言针对成功数、版本、最终数据和审计，不指定哪个线程必须获胜。

一次成功、一次版本冲突的先例，可复用其专用数据库与状态清理方式；它不是仅顺序模拟的锁语义证明。
