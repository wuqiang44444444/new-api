# NEWAPI 统一图片接口生产级多渠道兼容方案

## 1. 文档定位与决策摘要

本文件是渠道 25、34 及后续图片渠道统一接入 NEWAPI 的主方案。它负责：

- 记录当前仓库和工作区已经具备的能力。
- 明确哪些事项只需配置，哪些事项确实需要代码。
- 约束后续新增代码的触发条件和冲突面。
- 定义 `gpt-image-2` 等既有图片模型的兼容门禁。
- 保存完整生产目标，但不把尚未验证的增强项提前实现。

本方案不采用“第三方渠道参数的并集”或未经证明的“最小公共参数”作为产品合同。北向字段只能来自 NEWAPI 当前稳定图片合同或模型厂商官方 API；第三方聚合商的字段、路径和任务信封全部留在南向适配层。不同模型可以拥有官方定义的模型专有参数，但不能把渠道私有字段包装成公共标准。

图片产品业务边界冻结为：

> 图片产品默认且受保障的产品合同是统一 NEWAPI 图片接口。供应商原生协议是按渠道开放的可选附加能力：只有上游真实支持、NEWAPI 已有对应转发能力并完成验证时才开放；上游不支持或尚未适配时可以不开放，网关不模拟供应商原生协议。统一接口是产品承诺，原生接口是渠道附加能力。

这意味着普通客户端始终优先使用统一图片接口。模型切换不要求客户端改用 Moxing、Qihang、Gemini 或其他供应商私有字段和路径；不同模型允许拥有不同的尺寸枚举、参考图上限、输入载体及同步/异步能力，并通过公开 SKU 能力说明和稳定 400 错误显式表达。供应商原生入口只服务明确选择原生协议的高级客户端，不属于本轮三个公开图片 SKU 的跨渠道兼容保证。

实施顺序采用：

```text
冻结北向标准来源和版本
  → 为不等价的南向合同拆分公开模型 SKU
  → 优先用配置完成渠道、模型和路由绑定
  → Qihang 复用 converter=none
  → Moxing 在既有 converter 内完成标准字段映射
  → 只为已证实的协议差异增加轻量 converter
  → 只在合同等价渠道间使用普通选渠
```

北向长期接口：

```text
POST /v1/images/generations
POST /v1/images/edits
GET  /v1/images/tasks/:task_id
```

第一阶段生产范围：

```text
POST /v1/images/generations
GET  /v1/images/tasks/:task_id
```

产品接口与附加接口的责任边界：

| 接口层 | 用户调用 | 产品保证 | 本轮动作 |
|---|---|---|---|
| 统一 NEWAPI 图片接口 | NEWAPI 图片路径和统一语义字段 | 鉴权、错误信封、同步/异步结果、Task 查询、计费和南向适配 | 本轮唯一默认交付面 |
| 供应商原生协议 | 供应商官方路径、请求和响应 | 仅保证已显式配置并真实验证的单渠道转发；不保证换 `model` 跨供应商迁移 | 保留既有能力，不新增模拟协议 |

“保留原生协议”不表示为每个聚合渠道建设第二套图片适配器。Moxing 提供 Nano Banana 2 并不自动意味着其渠道支持 Gemini 原生 `generateContent`；若上游只提供 `/v1/media/generations`，该模型仍只通过统一 NEWAPI 图片接口发布。

目标公开模型 SKU：

```text
seedream-5-moxing
seedream-5-qihang
nano-banana-2
```

供应商模型 ID 仅存在于渠道配置和 `model_mapping`：

```text
seedream-5-moxing
  └─ Moxing: seedream-5-0-260128

seedream-5-qihang
  └─ Qihang: seedream-5

nano-banana-2
  └─ Moxing: gemini-3.1-flash-image-preview-usage
```

本轮产品范围明确：`nano-banana-2` 只由 Moxing 提供；Qihang 图片渠道只承载 `seedream-5`。不能因为 Qihang 的公开文档存在同名 Nano 模型，就把它加入当前渠道候选。

现有 `seedream-5` 是迁移前兼容名，不能继续同时指向渠道 34 和 35。迁移期必须先增加两个新 SKU、完成真实调用和账单验收，再关闭旧名的跨渠道 ability；不得通过一次破坏性配置切换让现有客户端失去服务。

`doubao-seedream-4-5-251128` 已进入 Moxing 执行策略的模型级校验和渠道模板能力，但不属于本轮公开产品 SKU：当前不为它增加公开别名、生产 ability 或价格配置。只有后续明确决定发布并完成真实任务与成本验收后，才能加入上述公开模型清单。

附件对应的是 **Seedream 5.0 图片模型**。`Seedance` 通常表示视频模型，不能把它作为新的图片模型正式名称。如果历史客户端已经使用 `seeddance5`，只能在模型映射层提供临时兼容别名，不进入新文档和管理端推荐列表。

## 3. 不可突破的约束

### 3.1 最小入侵

1. 能通过已有渠道配置、模型映射、参数覆盖完成的，不新增代码。
2. 新供应商协议差异优先隔离在 Advanced Custom converter 新文件中。
3. 现有热路径只允许窄接线，不重构通用图片中继。
4. 不修改 `dto.ImageRequest` 的全局序列化行为。
5. 不把 `Extra` 中的未知字段全局合并回请求。
6. 不为了图片接入修改普通 OpenAI、Azure 或 Gemini 渠道语义。
7. 条件性增强没有真实触发证据时不得提前实施。

### 3.2 北向合同来源

1. 默认产品路径、公共字段、错误信封和响应优先复用 NEWAPI 当前稳定图片合同。
2. NEWAPI 没有定义的模型能力只能引用模型厂商官方 API，并冻结文档链接、版本或真实验证日期。
3. 第三方渠道文档只决定南向 converter 和配置，不能新增北向字段。
4. 同一语义在官方合同和第三方字段中名称不同时，北向保留官方/NEWAPI 名称，南向负责改名。
5. 旧私有字段只允许在明确迁移期兼容；新文档、SDK 示例和能力表不得继续发布。
6. 同一基础模型因南向合同差异拆分 SKU 时，两个 SKU 仍使用同一 NEWAPI 图片接口族和相同语义字段；模型能力导致的字段支持、枚举、数量上限、输入载体及同步/异步差异按 SKU 公布和校验，不要求伪造完全相同的能力。
7. 供应商原生路径不进入统一图片合同。只有上游真实支持、NEWAPI 已有对应转发能力且该渠道完成验证时，才可作为独立附加能力开放；不得根据模型来源推断原生协议可用，也不得由网关模拟上游未提供的原生协议。

当前图片合同采用：

| 能力 | 北向标准来源 | 北向字段 |
|---|---|---|
| 图片生成公共入口 | NEWAPI / OpenAI 兼容图片合同 | `/v1/images/generations` |
| Seedream 文生图/编辑/多参考图 | Seedream 官方图片生成合同 | `prompt`、`image`、`size` 等 |
| Nano 文生图/参考图 | NEWAPI 图片公共入口；模型能力以 Google 官方能力为依据 | 参考图统一使用 `image`，南向映射为 Moxing `reference_images` |
| 同步图片响应 | NEWAPI / OpenAI 兼容响应 | HTTP 200 + `data[].url` |
| 异步恢复扩展 | NEWAPI 本地扩展 | HTTP 202 + `/v1/images/tasks/:task_id` |
| 供应商原生协议 | 对应厂商官方合同 | 独立路径和原生请求/响应；仅按渠道可选开放 |

### 3.3 完整能力

“最小入侵”不等于“最小公共参数”：

- 每个公开模型可以拥有由标准来源定义的完整模型专有字段。
- 不支持字段返回清晰的 HTTP 400，不能静默删除。
- 同一公开模型只有在全部已发布语义等价时才允许跨多个供应商。
- 南向合同不等价时必须拆分公开模型 SKU，不能通过能力交集、随机失败或重试维持同名。
- 拆分后的同基础模型 SKU 仍使用同一 NEWAPI 图片接口和语义字段。客户端通常只需改变 `model`，但必须遵守目标 SKU 已公布的模型能力和值域；不能把“通常只改模型名”误写成“所有模型能力完全相同”。

### 3.4 供应商中立

- 供应商真实模型 ID 不进入北向稳定合同；用于显式固定商业渠道的公开 SKU 后缀不是上游模型 ID。
- 供应商名不进入新的 ChannelType。
- Task、计费、幂等和查询协议保持供应商无关。
- 不能依据 Base URL、Key 或渠道名称推断执行策略。

## 4. 当前代码基线

### 4.1 已实现的 Moxing 主路径

当前工作区已经实现以下链路：

```text
POST /v1/images/generations
  → Advanced Custom 路由
  → media_task_image_blocking
  → 上游 HTTP 200 + OpenAI data[]：同步返回
  → 上游 HTTP 200/202 + media.task：持久化共享 Task
       ├─ 等待期内完成：返回 HTTP 200
       └─ 等待期结束：返回本地 HTTP 202
            → GET /v1/images/tasks/:task_id
            → 后台轮询
            → 终态 CAS
            → 结算或退款
```

已具备的核心机制包括：

- `seedream-5-0-260128`、`doubao-seedream-4-5-251128` 和 `gemini-3.1-flash-image-preview-usage` 的模型级校验；其中 Doubao Seedream 4.5 仅是未发布适配器能力。
- `n`、参考图数量、尺寸和连续出图数量边界。
- 上游同步图片响应与 HTTP 200/202 异步任务信封识别。
- Gemini camelCase 组件 usage 转换为统一文本输入、图片输入和图片输出 token。
- Task 私有执行快照。
- 请求内等待和后台恢复。
- 取得上游任务 ID 后禁止重新创建。
- 计费责任从请求链路转移到 Task。
- 本地图片任务查询和脱敏投影。

这些能力应被复用和验收，不能在统一方案中再次建设第二套图片任务系统。

### 4.2 尚未完成生产证明

工作区实现不代表已经完成：

- 尚未形成一个已提交、可回溯的实现基线。
- Moxing `seedream-5-moxing` 已完成 `2K` 生成、单 `image` URL 编辑和账单验证；`3K`、多参考图与连续出图仍需按公开能力表决定是否发布。
- Moxing `doubao-seedream-4-5-251128` 尚未形成公开 SKU、生产 ability 或真实调用验收，不计入本轮发布范围。
- Nano 已确认组件 usage 字段，但各尺寸的长期成本分布仍需持续观察。
- `gpt-image-2` 已有请求合同、选渠/affinity、并发幂等、零 Task/claim 和同步计费日志专项回归，但仍需随发布在生产镜像执行。
- 渠道 34 已完成公开别名、ability 和固定售价配置，旧模型名兼容期仍需运营确认。
- Qihang `seedream-5-qihang` 已完成 `2K` 生成、单 `image` URL 编辑和账单验收；其 ability 仍只在 `randy` 灰度组启用。

## 5. 北向生产合同

### 5.1 标准图片生成与 URL 图像输入

```text
POST /v1/images/generations
Content-Type: application/json
```

字段载体必须与当前 `dto.ImageRequest` 保持一致：

| 字段 | 当前载体 | 本方案处理 |
|---|---|---|
| `model` | 一等字段 | 公开模型名 |
| `prompt` | 一等字段 | 必填 |
| `n` | 一等字段 `*uint` | 既有解析后默认 1；模型和平台双重上限 |
| `size` | 一等字段 | 模型专有枚举 |
| `response_format` | 一等字段 | 按渠道真实能力 |
| `quality` | 一等字段 | 不改变 OpenAI 行为；目标模型按合同校验 |
| `image` | 一等字段 `RawMessage` | 统一 URL 参考图扩展；接受 HTTP(S) URL 或 URL 数组 |
| `images` | 一等字段 `RawMessage` | 既有兼容别名；不进入新客户端示例 |
| `watermark` | 一等字段 `*bool` | 已有字段；仅目标 converter 解释 Seedream 语义 |
| `extra_fields` | 一等字段 `RawMessage` | 既有兼容字段；目标 SKU 不把渠道私有扩展发布为标准 |
| `reference_images` | `Extra` | Moxing Nano 旧兼容字段；迁移后不再公开 |
| `aspect_ratio` | `Extra` | 目标 converter 显式读取和校验 |
| `temperature` | `Extra` | 目标 converter 显式读取和校验 |
| `extra` | `Extra` | Seedream 连续出图等模型专有结构 |

关键边界：

- `images` 和 `watermark` 已经存在于公共 DTO，本方案不改变它们对 OpenAI 模型的既有行为。
- `reference_images` 等第三方字段不应为了方便而加入全局 DTO或全局回灌。
- `Extra` 字段只由明确支持它的目标 converter 读取。
- 参数完整性通过有来源的“模型专有合同”实现，不要求所有图片模型拥有同一枚举和值域，但相同语义必须使用相同北向字段。
- `image` 是本项目在 NEWAPI 图片公共入口上的 URL-only 参考图扩展。它必须在产品文档中明确标注，不能宣称为 OpenAI `/v1/images/generations` 原生字段。

### 5.2 参考图字段策略

北向立即统一使用 `image`：

- Seedream 官方合同使用 `image`；单图和多图统一建议发送 URL 数组。
- Qihang Seedream 已真实验证 `image` 双 URL 可用，`converter=none` 原样发送。
- Moxing Seedream 已由现有 converter 接受 `image` / `images` 并转换。
- Moxing Nano 必须由 `media_task_image_blocking` 把北向 `image` URL 数组转换为南向 `reference_images`。
- 旧 `reference_images` 仅作有期限兼容，不再进入公开文档；与 `image` 同时出现时返回 400。

兼容别名不能产生歧义：

- 同一请求同时提供多个参考图字段时返回 400。
- 不允许静默合并不同字段中的图片。
- 参考图总数按归一化结果统一校验。

三个公开 SKU 使用下面的公共子集请求作为跨模型冒烟样本，唯一变量是 `model`；`2K` 是本轮三个模型均已声明支持的共同测试值。该样本只证明公共字段语义和南向适配一致，不构成所有字段、枚举和值域完全相同的产品承诺：

```json
{
  "model": "seedream-5-moxing | seedream-5-qihang | nano-banana-2",
  "prompt": "使用图一主体和图二背景生成一张图片",
  "image": [
    "https://example.com/image-1.png",
    "https://example.com/image-2.png"
  ],
  "size": "2K",
  "n": 1,
  "response_format": "url",
  "stream": false
}
```

若任一渠道的同语义字段名称或路径不同，必须在对应南向 converter 中适配；不能要求客户端为该 SKU 改用 `reference_images` 或 `/v1/media/generations` 等供应商字段和路径。若目标模型本身不支持某项能力，则按 SKU 能力表和统一错误信封返回 400，不能通过适配器伪造能力。Nano 的 `image` 在南向转换为 `reference_images`，客户端对此无感。

### 5.3 数量安全

请求画像或 converter 读取 `n` 时必须复用既有解析结果：

```text
N == nil  → 已由公共解析归一化为 1
N == 0    → 按现有合同归一化为 1
N > MaxImageN → 公共解析返回 400
```

目标模型随后应用更严格的模型上限。不能直接把未经公共验证的 JSON 数字转换为 `uint`，也不能绕开 `dto.MaxImageN`。

### 5.4 图片编辑合同

标准 multipart 路径继续保留给 NEWAPI/OpenAI 兼容模型：

```text
POST /v1/images/edits
Content-Type: multipart/form-data
```

Seedream 官方合同把文生图、图生图和多参考图统一在 JSON `/v1/images/generations` 的 `image` 字段，因此 `seedream-5-moxing` 和 `seedream-5-qihang` 的标准编辑方式是该路径，而不是把第三方 URL 输入伪装成 multipart edits。Nano 同样通过该 JSON 路径接受 URL 参考图。

现有 OpenAI 模型继续使用当前 OpenAI multipart `/v1/images/edits`，不得因 Seedream/Nano 方案改变。

只有产品未来明确要求这些 URL-only 模型兼容 multipart SDK 时，才允许实施额外 edits 桥接，并同时满足：

1. 北向合同来源明确允许 multipart。
2. 南向文件输入方式、文件上传接口或 URL 合同已确认。
3. `mask`、多图、MIME、大小和返回格式的支持矩阵已冻结。
4. 已决定是否需要网关暂存。
5. 已定义异步 edits 的幂等和计费责任。

### 5.5 供应商原生协议的可选边界

供应商原生图片协议不是统一图片产品的默认入口，也不是本轮交付的必要条件。开放某个原生入口必须同时满足：

1. 上游渠道真实接受该官方协议，而不只是提供了同名基础模型。
2. NEWAPI 已有对应路由、鉴权、请求/响应转发和计费能力。
3. 已以该渠道完成生成、错误、限流、计费和敏感信息验收。
4. 管理端和能力文档明确标记为“原生协议附加能力”。

原生协议入口遵循供应商官方路径、字段和响应，不承诺：

- 与 `/v1/images/generations` 的字段完全相同。
- 通过替换 `model` 切换到其他供应商。
- 统一 Task 查询或统一错误信封。
- 为不支持该原生协议的聚合渠道进行模拟。

当前三个目标 SKU 的发布不依赖任何原生协议：

| 公开 SKU | 默认统一接口 | 原生协议承诺 |
|---|---|---|
| `seedream-5-moxing` | 必须支持 | 无 |
| `seedream-5-qihang` | 必须支持 | 无 |
| `nano-banana-2` | 必须支持 | Moxing 未提供 Gemini 原生协议证据，因此不开放 |

已有 Gemini 等原生路由继续作为仓库既有能力保留，但本方案不扩大其渠道范围，也不因统一图片适配而改变其请求、响应或计费语义。

## 6. 异步图片合同：复用而非新建

### 6.1 同步和异步分支

| 上游结果 | NEWAPI 行为 |
|---|---|
| HTTP 200 + `data[]` | 继续返回 OpenAI 图片 HTTP 200 |
| HTTP 200/202 + `status=queued/running` + `task_id` | 统一识别为异步任务并持久化 |
| 异步任务等待期内成功 | 返回 OpenAI 图片 HTTP 200 |
| 异步任务等待期内失败 | 返回稳定错误，由 Task 独占退款 |
| 异步任务等待期结束仍运行 | 返回本地 HTTP 202 任务对象 |
| 客户端发送 `Prefer: respond-async` | 上游返回任务信封时，持久化后立即返回 |

两个 Seedream SKU 对客户端声明同一个 `200 成功 / 202 任务` 北向响应联合合同。Qihang 当前总是命中同步 200 分支，Moxing 可能命中 200 或 202 分支；这是同一合同的不同运行结果，不是两套北向接口。Qihang 等同步上游不需要被包装成伪异步任务。`Prefer: respond-async` 是偏好，不要求同步供应商创建本地后台任务。

### 6.2 任务查询

```text
GET /v1/images/tasks/:task_id
```

必须：

- 只暴露本地任务 ID。
- 校验用户所有权或管理员权限。
- 只读取 `client_protocol=openai_images`。
- 不返回上游任务 ID、Key、Base URL、原始响应和内部计费状态。

### 6.3 创建幂等和责任转移

取得上游任务 ID并可靠持久化后：

```text
请求链路不再退款
Task 独占终态结算或退款
```

创建结果不确定时禁止换渠道重建。客户端断开、请求超时和服务重启不能成为重复创建的理由。

`Idempotency-Key` 在统一图片产品中只保护“上游返回任务信封并持久化为本地 Task”这条异步窗口。此时同 Key 可以回放本地任务或已完成结果，不能重复创建上游任务或重复扣费。

如果上游在创建请求内同步返回 HTTP 200 图片结果，NEWAPI 会完成本次计费并释放临时 claim，不创建 Task，也不持久化响应供幂等回放。客户端在收到响应前断网或随后以同一 Key 重试，会被视为一次新图片创建，可能再次调用上游并再次计费。这与既有同步 OpenAI 图片行为一致；客户端不能把同步图片的 `Idempotency-Key` 理解为结果存储或 exactly-once 保证。

## 7. `gpt-image-2` 兼容性：当前事实与阻断项

### 7.1 目标状态

`gpt-image-2` 必须继续：

- 命中现有普通 OpenAI / Azure 图片渠道。
- 使用现有 OpenAI 图片请求转换。
- 保持生成、multipart edits、流式和错误响应行为。
- 不进入 Moxing / Qihang converter。
- 不创建图片 Task。
- 不读取目标模型尺寸价格和能力规则。

### 7.2 已修复的工作区风险

此前工作区把所有 `/v1/images/generations` 请求挂到了图片 `TaskCreateIdempotency` 中间件。

没有 `Idempotency-Key` 时，中间件立即放行；但携带该 Header 的普通 `gpt-image-2` 请求会：

- 创建临时幂等 claim。
- 在并发同 Key 时可能返回 `idempotency_in_progress`。
- 依赖幂等存储可用性。
- 请求结束后再释放 claim。

这与修改前“不解释图片 Idempotency-Key”的行为不同。

当前工作区已将图片任务幂等移动到 `Distribute` 之后，并增加目标图片任务专用门禁。普通 OpenAI 渠道和 Advanced Custom `converter=none` 路由都会在进入通用任务幂等逻辑前退出，不创建 claim。

### 7.3 P0 收敛结果

图片任务幂等必须只作用于：

```text
ChannelTypeAdvancedCustom
+ /v1/images/generations
+ media_task_image_blocking
```

普通 OpenAI 图片请求不能创建幂等 claim。

工作区已经新增单一稳定判定 `SupportsPersistentMediaImageTask`，由 Task 准备逻辑和幂等门禁共同复用；现有路由只调整中间件顺序和一次窄调用，没有建设通用图片能力画像。

### 7.4 发布阻断测试

| 测试 | 断言 |
|---|---|
| `gpt-image-2` 无 Idempotency-Key | 请求和响应与 HEAD 基线一致 |
| `gpt-image-2` 有 Idempotency-Key | 不访问图片 Task 幂等存储，或由产品明确接受新合同 |
| 并发相同 Idempotency-Key | 不因目标模型功能新增 409 |
| JSON 黄金请求 | 上游字段与基线一致 |
| multipart 黄金请求 | 文件、字段、文件名和 Content-Type 与基线一致 |
| 选渠测试 | 候选渠道集合、priority、weight 和 affinity 不变 |
| Task 测试 | 不设置持久化标记，不创建 Task |
| 计费快照 | 预扣、倍率、结算和日志不变 |

没有这些测试，不允许以“代码会早退”作为生产无影响证明。

当前工作区已经以独立回归覆盖上述合同：OpenAI 请求与 multipart 由 `relay/channel/openai/gpt_image_2_regression_test.go` 保护；选渠、priority/weight、affinity、并发同键以及零 Task/claim 由 `middleware/gpt_image_2_distribution_regression_test.go` 保护；真实同步中继响应后的零 Task/claim 由 `relay/gpt_image_2_task_isolation_integration_test.go` 保护；预扣、`n` 倍率、同步结算和消费日志由 `service/gpt_image_2_billing_regression_test.go` 保护。

- 一个新的 `qihang_image.go`。
- Advanced Custom converter 注册和路径校验。
- `ConvertImageRequest`、`DoRequest`、`DoResponse` 中必要的窄分发。
- 独立合同测试。

不能同时引入能力选渠或暂存服务。

## 10. 模型 SKU 与选渠边界

### 10.1 当前主路径

以下情况使用现有“路径 + 模型 + priority/weight”，不增加通用能力层：

- 一个公开模型只在一个渠道启用。
- 多个渠道对该公开模型的请求、响应、错误、生命周期和计费合同已经证明等价。
- 当前发布阶段主动限制某个不稳定渠道的候选范围。

可使用的零代码手段：

- 每条 Advanced Custom route 只列一个模型。
- 不同模型拆成不同 route。
- 模型映射隐藏供应商版本名。
- 参数覆盖删除或转换已知字段。
- priority/weight 在能力一致的渠道之间负载均衡。

### 10.2 南向不等价时必须拆 SKU

同一基础模型在两个南向渠道出现以下任一差异时，不得共享公开模型名：

- 接收路径、字段、类型或枚举不同。
- 一个同步返回，另一个返回需要持久化的任务信封。
- 错误、结果数量或计费语义不同。
- 尚未以同一北向合同完成真实证明。

必须拆成两个公开 SKU，并分别绑定：

```text
公开模型名
  → 唯一候选渠道集合
  → Advanced Custom route
  → model_mapping
  → 参数适配
  → 价格与 ability
```

拆分后两个 SKU 仍必须使用同一 NEWAPI 图片接口族、相同语义字段、统一错误信封和任务查询方式。例如 `seedream-5-moxing` 与 `seedream-5-qihang` 都使用北向 `image` URL 数组；不能让一个使用 `image`、另一个要求客户端发送 `reference_images`。若两个 SKU 的参考图上限、尺寸枚举或同步/异步能力不同，应在各自能力表中明确，不要求通过能力交集或虚假兼容将其抹平。

### 10.3 能力选渠的保留边界

能力选渠不能用来把不兼容南向合同重新包装成同一模型名。未来只有多个渠道已证明北向合同等价、但存在不影响客户端合同的内部容量或成本标签时，才能另立方案设计。

当前禁止实现：

- `ImageRequestProfile`。
- `image_capabilities`。
- `image_route_constraint.go`。
- 通用图片 `AllowedChannelIDs` 过滤。

普通 priority/weight 仍只允许用于合同等价渠道。

## 11. URL-only 模型的 multipart edits 与暂存服务

### 11.1 当前结论

本阶段推迟 Seedream/Nano URL-only 合同到 `/v1/images/edits` 的额外桥接，原因是前置合同尚未完成：

- Qihang 的 edits 示例不能证明所有目标模型均支持。
- 当前 Moxing 转换器只接受 HTTP(S) 图片 URL，不接受 multipart 文件。
- 当前 Moxing 校验器也不接受 data URI。
- `mask`、多文件和异步 edits 的合同未冻结。

因此不能以“两家都接受 data URI”为前提删除暂存设计，也不能在尚未确认 edits 产品需求时提前建设对象存储子系统。

### 11.2 暂存层的真实触发条件

仅当以下条件成立时实施：

- 产品确认必须提供标准 multipart edits。
- 目标 Moxing 上游仍只接受 HTTP(S) URL。
- 上游没有可复用的受控文件上传接口。
- 客户端直传任意远程 URL不满足安全要求。

此时暂存层是协议桥接的必要基础设施，而不是可用简单 data URI 替代的抽象。

### 11.3 触发后的安全边界

- 对象默认私有。
- 使用短期只读签名 URL。
- 限制文件数量、单文件大小、总大小、像素和 MIME。
- 内容嗅探，不只信任扩展名。
- 禁止 SVG、HTML 和可执行内容。
- 日志不记录签名 URL和文件内容。
- Task 终态后删除，生命周期规则兜底。
- 删除失败有指标和补偿。
- 请求哈希使用文件内容哈希，不使用短期签名 URL。

## 12. 计费方案

### 12.1 用户售价与上游成本分离

用户售价按：

```text
公开模型 SKU + 尺寸 + 数量
```

供应商实际成本单独记录为 COGS。拆分后的两个 Seedream SKU 可以拥有各自公开售价；单个 SKU 内不能因内部选渠改变已经向用户声明的价格。

### 12.2 第一阶段

- `seedream-5-moxing`、`seedream-5-qihang`：分别配置固定公开售价和灰度 ability，不再共用共享模型价格作为长期合同。
- `nano-banana-2`：代码当前可按固定公开售价和实际结果数结算，但生产默认组暂不开放。
- Nano 的真实组件 usage 已确认并持久化：文本输入、图片输入、图片输出分别归一化。
- 当前固定售价 `$0.077` 只覆盖已测 1K，不覆盖已测 2K/4K，因此只允许 `randy` 灰度。
- 若改为 Token 精确售价，表达式必须为 `tier("nano_image", p * 0.5 + img * 0.5 + img_o * 60)`，并先配置覆盖提示词、参考图、输出数量和所有尺寸的可信预扣 Token 上界；不得把三个尺寸样本直接当作合同上界。

真实文生图样本（均为 `n=1`）：

| 尺寸 | 文本输入 Token | 图片输出 Token | 按上游价计算的成本 | 当前固定售价 |
|---|---:|---:|---:|---:|
| 1K | 16 | 1120 | `$0.067208` | `$0.077` |
| 2K | 13 | 1680 | `$0.1008065` | `$0.077` |
| 4K | 13 | 2520 | `$0.1512065` | `$0.077` |

这些数据足以证明当前统一固定售价不能全尺寸上线，但不足以证明 `2520` 是合法最大 Token 上界；图生图、参考图和多结果仍可能增加用量。

### 12.3 安全不变量

- `n` 复用 `dto.MaxImageN`。
- `max_images` 使用相同或更严格上限。
- 计费乘数进入 quota 计算前必须完成边界验证。
- 使用 `PriceData.AddOtherRatio`。
- quota 转换使用 `common.QuotaFrom*Checked`。
- 饱和事件进入管理员审计。
- 上游超发图片不得导致未授权补扣。
- 请求链路和 Task 不能同时承担退款责任。

- 等待期内成功。
- 返回本地 202。
- 服务重启后后台恢复。
- 同一任务重复 GET但不重复 POST。

- 成功结算、失败退款、补偿。
- Gemini 组件 usage 解析。
- 超发图片失败关闭。

## 15. 分阶段交付

### 阶段 0：工作区收敛

- 把当前 Moxing 异步实现登记为工作区基线。
- 不再重复设计 converter、Task 和结算。
- 已补齐 `gpt-image-2` JSON、multipart、选渠优先级/权重/affinity、并发同幂等键、零 Task/零 claim 及预扣—结算—日志快照回归。
- 已收窄图片创建幂等范围。
- 确认 ADR、实现和测试属于同一提交边界。

### 阶段 1：Seedream 模型 SKU 迁移

- 已增加 `seedream-5-moxing`、`seedream-5-qihang` 的价格和测试组 ability。
- 已分别更新渠道 34、35 的 route 和 model_mapping，两个名字不能跨渠道候选。
- 已使用相同北向语义完成两个 SKU 的生成、单 URL 编辑和账单验收；多参考图与扩展能力仍按各 SKU 能力表独立发布。
- 迁移期旧 `seedream-5` 只固定到当前主渠道 34，不得继续同时候选 34/35；新客户端只发布两个新 SKU，观察期后移除旧名 ability。

### 阶段 2：Nano 标准字段映射

- 保留公开模型 `nano-banana-2`。
- 工作区已将北向参考图改用统一扩展 `image` URL 数组。
- 工作区已在既有 Moxing converter 内转换为南向 `reference_images`。
- 旧字段只作迁移兼容；冲突、数量、异步和计费测试已补齐。
- 已用北向 `image` 完成真实 URL 参考图、Task、幂等与账单验收。
- 当前 `1K/2K/4K` 异步、终态和 usage 已验收；价格倒挂门禁继续生效。

### 阶段 3：Qihang 零代码迁移

- 保留渠道 25 Gemini 聊天。
- 渠道 #35 只发布 `seedream-5-qihang`，使用 `converter=none`。
- 单 `image` 和双 `image` URL 已真实返回同步 200 + `data[].url`，当前不需要专用 converter。

### 阶段 3B：可选 Qihang converter

当前未触发该阶段。未来只有标准北向字段无法通过配置或 `converter=none` 表达时，才实施一个轻量 converter，并再次验证失败边界和 `gpt-image-2` 黄金基线。

只有产品明确要求 URL-only 模型兼容 multipart SDK 且第 11.2 节条件成立时启动。不能为了“方案看起来完整”提前实现。

## 16. 灰度和回滚

### 16.1 灰度

1. 代码部署但新 ability 关闭。
2. 内部 `randy` 组验证 `seedream-5-moxing` 和 Nano 统一扩展 `image`。
3. 独立测试组验证 `seedream-5-qihang`。
4. 执行 `gpt-image-2` 黄金回归。
5. Nano 先完成 Token 预扣上界或固定售价门禁，再开放文生图。
6. 再开放已验证参考图能力。
7. 观察完整结算周期。
8. 最后下线共享 `seedream-5` 和旧供应商字段别名。

### 16.2 回滚

回滚优先通过：

- 关闭新 Advanced Custom 图片渠道。
- 移除测试组的新 ability。
- 在迁移窗口内恢复只固定到渠道 34 的旧模型名 ability；窗口结束后按版本回滚配置。

不得为了回滚目标模型而修改普通 OpenAI 图片渠道。

### 16.3 自动阻断条件

- `gpt-image-2` 请求或计费黄金对比变化。
- 普通 OpenAI 图片请求创建了本地 Task 或幂等 claim。
- 出现重复上游创建。
- 请求链路和 Task 重复退款。
- 任务终态与账单无法对齐。
- 同一公开模型跨候选渠道产生不同语义。
- `seedream-5-moxing` 与 `seedream-5-qihang` 对同一北向字段产生不同语义，或能力差异未在 SKU 能力表中公布。
- 新客户端仍需发送 `reference_images` 等第三方私有字段。
- Nano 固定售价低于任一已验收尺寸的上游成本，或实际 Token 结算缺少可信预扣上界。
- 暂存尚未启用却发布了必须文件 URL 化的 edits。
- 未经真实上游和 NEWAPI 转发验证就发布供应商原生协议入口。
- 为上游未支持的原生协议新增模拟层，或让原生协议改变统一图片接口语义。

## 18. 最终生产验收标准

全部满足才能完成本轮上线：

- 当前 Moxing 工作区实现形成可回溯的提交和测试基线。
- `seedream-5-moxing`、`seedream-5-qihang` 和 `nano-banana-2` 分别通过独立 route、公开模型名和模型映射工作。
- 两个 Seedream SKU 使用同一 NEWAPI 图片接口和相同语义字段；公共子集请求一致，各自能力和值域已独立登记并验证。
- Seedream 和 Nano 的 URL 参考图北向均使用统一扩展 `image`，第三方字段只存在于 converter 南向。
- 异步任务在断线和重启后可恢复。
- 异步持久化图片链路的幂等不会重复创建或重复扣费；同步 HTTP 200 图片释放 claim、不可回放的语义已在北向合同中明确。
- Qihang 优先以配置接入；新增代码有明确协议差异证据。
- 能力选渠和暂存没有在触发条件缺失时提前实施。
- 渠道 25 的 Gemini 聊天行为不变。
- 目标模型专有参数不会被静默删除。
- `gpt-image-2` 不进入目标 converter、图片 Task 或目标价格规则。
- `gpt-image-2` 携带和不携带 `Idempotency-Key` 的兼容合同均已明确并通过测试。
- 用户售价、实际结果数、退款和上游成本能够对账。
- 统一 NEWAPI 图片接口已作为默认产品入口发布；任何供应商原生入口均按渠道单独标记、单独验证且不进入统一兼容承诺。
