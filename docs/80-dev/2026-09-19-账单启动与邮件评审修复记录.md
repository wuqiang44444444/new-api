# 账单启动与邮件评审修复记录

## 问题与目标

结合[全量评审](2026-09-19-80目录方案全量评审报告.md)与
[数据质量分析](2026-09-16-客户账单数据质量提示问题分析与解决方案.md)，按最小入侵原则修复已确证的问题。
用户明确要求启动时停止原进程后重启，该行为作为本轮验收条件。

## 客观复核结论

- Task 修订写入失败且客户尚无来源保留行时，先前未产生持久 partial 记录；回归已复现旧来源版本仍可用于复用。
- 核验虽按页读取，原实现仍保留全历史关联 Log、月内全部退款证据、全客户 Task 分组，且扫描末尾才校验依赖数量。
- 原启动脚本在循环校验端口的同时停止进程，后续端口非法或前后端端口相同时会提前停服；隔离子进程回归已复现。
- 邮件功能具备冻结与重试机制，但固定正文仅中文；无可靠活动证据时，不能为补齐状态而声称“零调用”。
- 历史退款完整取证、按实际写入语义恢复、合同四态和导出复用已有后续实现。本轮保留其合同，旧方案只增加当前生效说明。

## 实际修复

1. `model/billing_statement_source_tracking.go`：Task 和 Log 修订失败均复用既有来源保留表写入 partial；
   原 Task 事实可以提交，失败围栏不能落库则返回错误。跨月导出仍通过客户级 partial 检查停止复用，不增加新表或 Relay 接线。
2. `model/billing_statement_source_review.go` 及独立预算文件：日志仅选需要的字段，跨月只保留核对与指纹字段；
   月内退款按批补证，仍复用完整历史引用校验；Task 身份分组限制为当前批的精确客户/应用/任务身份。
   保留 30 秒期限，当前批次与持续保留的证据、结果结构开销预算 64 MiB；已处理批次释放预算，超过 20,000 个依赖在扫描中立即失败。
   超限不返回半份报告或指纹，不自动跳过记录、不修改金额。该预算是工程限制，不是进程内存或部署容量承诺。
3. `start.sh`：先校验全部端口和超时，再执行原有 TERM → 等待 → KILL → 重启。
   占用端口测试改用一次性子进程，防止脚本按预期终止测试运行器本身；错误配置验证原进程仍存活；超长超时参数在停止进程前拒绝，避免计时溢出。
4. `service/error_report*.go`：新生成邮件使用固定中英双语主题、摘要、口径、表头、续段和补发标识。
   双语文本在分卷前生成，详情拆段时计入真实双语表头与包装开销，保持原 48 KiB 正文预算和冻结存储；重试不重译、不重分页，旧冻结邮件不改写。
   不增加语言选项、收件人语言推断、数据库字段或第二套模板与投递系统。

本轮仅修改本地账单扩展、邮件扩展和开发脚本，没有改动 NEWAPI 原生 Router、Relay、计费算法和 Task 生命周期。
同工作区另一任务正在实现账单决策接口，本轮保留其改动；相关业务功能不计入本轮修复交付。

## 最终评审补修

最终评审另确认两项缺口，已按最小入侵原则修复：

1. 修订写入失败时，单独写 partial 不能阻止故障前完成的扫描重新登记 intact。现复用既有维护控制行，
   在修订保存点回滚后锁定并推进代际，与 partial 和来源 SQL 同事务提交；首次失败、已处于 partial
   时的重复失败均使旧扫描失效。失败保护不可写则整个来源事务回滚。普通日志写入失败后的独立标记事务
   也锁定并推进代际，保留原错误、不重放日志；完全数据库故障仍无法保证标记写入。只有异常路径推进全局代际，代价
   是其他客户的旧来源证明、未确认草稿及导出复用也需重新验证；已确认版本及资金不变，不新增表或迁移。
2. 决策历史原先无界读取和解码。现按 ID 每批 100 条读取所需字段，解码前计入扫描剩余预算，锁内重读
   复用同一额度并替换历史，且受 30 秒期限和调用方取消约束。超限整体失败；保留完整历史、最新决定、
   旧决定被替代标记和并行任务的决策合同，不采用截断、静默忽略或第二套审计。

故障注入在修复前复现了旧核验覆盖 partial 并写入成功审计；修复后拒绝旧指纹、保留已提交来源及
partial，新扫描可恢复核验。预算回归在修复前复现了历史超额仍返回报告；修复后返回明确错误且无部分报告。
新增回归还覆盖失败代际无法写入时来源回滚、日志写入失败后旧扫描不能登记成功、跨页 101 条历史保留最新决定，
以及锁内重读不重置或重复扣除预算。

## 验证与验收

- 修复前：Task 修订失败回归确实仍返回复用版本，且未产生来源保留行；错误端口配置回归确实停止旧监听进程。
- 修复后：定向 model/service 回归通过，覆盖 Task 失效保护、预算失败无部分结果、跨月重复 Task 身份仍阻断、原核验流程和双语邮件。
- 启动脚本 8 项隔离场景通过，包括停止占用者再启动及错误配置不停止原进程。
- Go 相关 8 包全量通过：`model`、`service`、`controller`、`router`、`middleware`、`clienterrlog`、`common`、`cmd/repair-task-billing-logs`。首次扩大测试发现列名依赖未初始化与补发英文遗漏，修正后重跑 model/service 全量通过；其余 6 包首次已通过。
- 最终补修后，重新运行 `model`、`service`、`controller`、`cmd/repair-task-billing-logs` 全量并通过。日志失败现在先使旧草稿版本失效，原回归同步改为断言版本冲突并另验 partial；调整后 model 全量重跑通过。文档及差异检查再次通过。
- 双语超长明细先复现分卷超预算，修复后验证 40,000 个多字节字符完整保留、每卷不超过 48 KiB；原有完整明细、转义、失败不发布与冻结补发回归继续通过。
- `bash -n start.sh`、`task docs:check`、`task ai:check`、`git diff --check` 通过。当前环境未安装 ShellCheck，本轮未声称运行它。
- 本轮未修改 frontend 或 relaykit；未用真实数据库、邮件、Provider 结果冒充自动化验收。

## 未完成事项与边界

本轮不执行生产部署、历史金额补正、真实 SMTP 投递或 Provider 调用，也不实现独立的客户合同模板方案。
SQLite 回归不能代替 MySQL 5.7.8 / PostgreSQL 9.6 最低版本实测；生产灰度、真实投递、存量证据密钥恢复和
账单人工财务确认仍需各自验收。并行任务完成后，合并前应在静默工作树上重新运行其新增接口相关检查。
