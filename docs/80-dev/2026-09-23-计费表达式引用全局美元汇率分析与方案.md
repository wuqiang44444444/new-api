# 计费表达式引用全局美元汇率分析与方案

> 状态：分析与拟实施方案。汇率表达式能力尚未实现；本文未修改模型价格、系统汇率或运行时代码。
> 本文中的新函数与快照字段均为设计建议，不能直接用于当前配置。当前可用表达式见第 2 节。

## 1. 问题与目标

用户要求模型基础价格采用官网未打折的标准价格，计费单位与官网一致，金额显示为 USD；
涉及人民币转美元时使用系统整体 `USDExchangeRate`，不在每个模型表达式中长期维护固定汇率。

本次以 Seedream 5.0 Pro 为具体案例，分析现有表达式引擎、设置、预扣、结算和展示链路的缺口，
提出复用全局设置且能够追溯历史费用的方案。用户合同折扣与上游采购折扣不进入模型基础表达式。
不创建第二套模型价格表、汇率配置、计费引擎或资金账本，不自动修改现有模型的计费单位和单价。

## 2. 当前实际情况

### 2.1 已核实的官方价格与当前可用表达式

2026-09-23 核对[火山引擎官方模型价格表](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)：
Seedream 5.0 Pro 普通生图按图片张数计费，不按 Token 计费。图层拆分是另一种官方计价场景，
不用于本次普通生图表达式。

| 计费项 | 官方人民币原价 |
| --- | --- |
| 输出图不超过 261 万像素 | 0.30 元/张 |
| 输出图超过 261 万像素 | 0.60 元/张 |
| 第一张输入参考图 | 免费 |
| 第二张及以后的输入参考图 | 0.02 元/张 |

首张参考图免费是价格表列出的标准规则，不是需要剔除的限时折扣。官方同时说明因审核等原因未成功
输出的图片不计费；本次公式不替代既有成功、失败和退款判定。

[`constant/image_relay.go`](../../constant/image_relay.go) 登记的 FunCloud `seedream-5.0-pro`
当前固定为 `1K`，最多 10 张参考图。它与固定 `2K` 的 Moxing Pro 不能共用输出基础单价。
本文可用公式按当前单张 1K 输出场景给出；未来支持多张输出或其他分辨率时须按可信张数、像素档位
重新设计，不把本公式当成完整官方能力的通用价格。

本地运行实例使用的数据库中，2026-09-23 只读核查得到 `USDExchangeRate = 6.76`，单位为
`CNY/USD`，即 1 USD = 6.76 CNY。该值是本地当前设置，不代表其他部署或实时市场汇率。

当前可在 `seedream-5.0-pro` 的 `tiered_expr` 模式填写：

```text
tier("1K", (0.30 + (param("input_image_count") == nil ? 0 : max(param("input_image_count") - 1, 0) * 0.02)) / 6.76 * 1000000)
```

`input_image_count` 由服务端图片合同解析后注入，不能信任客户自行提交的同名值。
缺失分支用于没有请求探针的配置校验；真实图片请求必须继续提供服务端校验后的数量。
该路径沿用原生表达式的百万缩放，末尾 `1000000` 会在 quota 换算时除回，不表示业务按 Token 收费。

| 输入参考图数量 | 单张输出费用（USD，未做 quota 整数舍入） |
| --- | --- |
| 0 或 1 | 0.0443786982 |
| 2 | 0.0473372781 |
| 10 | 0.0710059172 |

上述公式已在本次会话用项目 `billingexpr.RunExprWithRequest` 对空探针及 0、1、2、10 张输入执行验证。
这仅证明表达式求值，不代表真实 Provider 或完整资金链路验收。公式尚未保存到模型配置。

固定 `6.76`，即使全局汇率改变，也不会自动变更该表达式的美元价格。

## 3. 优化方案

### 3.1 推荐合同：显式引用，服务端注入，按请求冻结

建议增加零参数函数 `usd_exchange_rate()`，含义严格限定为本次计费上下文中的 `CNY/USD`。
该名称为拟议语法，当前不可用。避免开放任意 `setting("key")`、任意配置读取或客户请求覆盖。

新增能力后的拟议表达式：

```text
tier("1K", (0.30 + (param("input_image_count") == nil ? 0 : max(param("input_image_count") - 1, 0) * 0.02)) / usd_exchange_rate() * 1000000)
```

只使用该函数的模型采用动态换汇；以美元发布的官网价格以及现有固定美元表达式不自动换汇。
函数只提供汇率，不改变表达式结果单位：普通表达式继续百万缩放；任务美元表达式继续直接返回 USD。
业务计量单位由官方合同和已有类型化入口确定，不能因使用汇率函数变为 Token，也不能因函数名改变
`TaskUsageBilling`。

表达式引擎保持确定性：引擎接收调用方提供的不可变汇率上下文，不直接查询数据库、全局变量或外部汇率
接口。相同表达式、用量和冻结上下文必须产生相同费用。新函数是新增显式语法，不重解释旧表达式；
是否需要语言版本升级须在实现评审时依现有版本合同决定，不以升级名义改变 v1 金额换算。

### 3.2 唯一事实源与读写校验

1. `options.USDExchangeRate` 继续作为当前配置的持久权威；不增加独立汇率选项或同步维护第二份值。
2. 在最接近配置持久写入的公共边界统一校验有限且大于零，覆盖 API、导入和内部写入口；前端校验只
   提供即时反馈。历史持久值加载也必须校验，不能忽略解析错误后把零值带入计费。
3. 取值接口需要保证并发读写一致，复用现有配置同步机制。多实例必须验证设置传播及生效边界；若现有
   缓存刷新不能保证所宣称的生效语义，则在受理快照处从权威配置读取，并明确生效点，不自行新建汇率缓存。
4. 引用新函数但取不到合法汇率时，在资金预扣和上游发送前报配置错误。不能回退到 1、7.3、最后成功值
   或客户端提供值；不引用汇率的模型不增加此依赖。
5. 全局汇率变更会影响已选择动态换汇模型的新请求售价，管理设置页应显示这一影响和受影响模型范围。
   已有支付、余额展示等使用同一设置的行为需一并盘点，但不在本次方案中重新定义其含义。

### 3.3 预扣、持久化、结算与退款

- 通过 AST 识别表达式对汇率函数的依赖，保存校验与运行时共用依赖检测，不用字符串包含判断。
  识别整个表达式，包括未命中的分支；不支持函数别名或动态调用时应在保存时明确拒绝。
- 同步请求在首次计算预扣之前取得一次汇率；同请求的重新估价、补充预扣和最终结算沿用这个值。
  自动组调整只调整既有组事实，不刷新本请求汇率。
- 在现有计费快照增加可选汇率事实，建议包含来源键 `USDExchangeRate`、数值、计价方向及冻结时间。
  该快照是已经发生的计费事实，不是第二个可编辑系统设置。
- 请求求值上下文中的汇率只是快照/受理事实的临时投影，不在多个位置分别维护可独立更新的数值。
  结算入口必须以快照覆盖任何外部传入值；旧快照不引用新函数时保持原语义。
- 异步图片、视频 attempt/Task、Batch 等必须在既有受理或资金事务边界持久化汇率事实。预扣与持久化
  使用同一不可变对象，不能先按一个值求价，再读取另一个值保存。Batch 以作业受理时冻结的汇率贯穿各行。
- 进程重启、轮询、失败恢复、欠费补偿均从持久快照恢复；全局汇率变化不影响已受理业务。
- 引用新函数却缺少冻结汇率的历史/损坏快照必须停止费用重算并进入既有异常处置，不能用当前汇率补齐，
  也不能视为免费或绕过资金状态机。
- 退款按原已扣 quota 和原资金事实执行，不把退款金额按最新汇率重新换算；冻结上下文只用于必要的原价
  重算和解释，不改变幂等退款入口。
- 金额转换继续使用统一 checked/strict quota 工具和现有审计，不新增裸浮点转整数或第二套舍入规则。

### 3.4 保存、试算、展示和缓存一致性

| 场景 | 汇率来源 | 行为要求 |
| --- | --- | --- |
| 配置保存校验 | 当前合法系统设置的本次读取值 | 编译、执行同一上下文；不把校验汇率固化成模型单价 |
| 管理员试算 | 服务端读取的当前系统设置 | 返回实际采用的汇率和方向；不得默认由客户样本 `param` 覆盖 |
| 当前公开价目表 | 本次响应绑定的当前系统汇率 | 返回 USD 金额及适用说明；页面说明实际请求受理时锁定汇率 |
| 合同定价预览 | 同一响应绑定的当前汇率 | 基础价与合同折扣分开计算，不能把汇率混入折扣 |
| 在途任务/历史账单 | 原请求冻结汇率 | 展示原始人民币计价、冻结汇率及 USD 事实，禁止最新设置反算历史价格 |

表达式编译缓存仍可仅按源码 hash 缓存不含汇率值的程序；禁止编译时把全局汇率捕获到闭包。
金额展示投影应保留可缓存的静态结构，再以本次汇率上下文生成金额；若缓存已求值投影，缓存键必须包含
汇率上下文及展示版本，并处理设置变更失效。不能修改共享缓存对象导致不同请求互相污染。

历史日志需保存足以解释费用的最小汇率事实。对没有记录过汇率的旧日志，不根据表达式中看似汇率的数字
推断其来源，不追加虚构的冻结时间。无法证明的展示继续返回明确不可展开，不能猜价。
新增文案仅要求简体中文和英文。前端消费后端投影，不自行解析执行表达式或计算另一套模型费用。

### 3.5 实施范围与最小接线

优先新增专用文件实现汇率上下文、依赖检测、校验和测试，不因本次需求重构现有价格系统。

| 必要改动边界 | 最小接线及必要性 | 上游同步影响 |
| --- | --- | --- |
| 表达式编译/运行环境 | 注册一个新函数，主体置于新增文件 | 共用引擎无法零改动；后续合并须核对函数环境和新增名称冲突 |
| 设置保存/加载 | 调用统一汇率校验和受控读取接口 | 原生选项处理仅保留窄分支，不能重排其他设置 |
| 计费快照与预扣/结算 | 可选事实字段及上下文接线 | 必须核对每个构造/复制/持久化/恢复入口，避免上游新增路径漏传 |
| 异步图片、视频、Batch | 在各自已有快照边界传递同一事实 | 不新增任务合同和账本；未完成接线的入口必须拒绝保存依赖新函数的配置 |
| 展示、日志、试算 | 传入明确汇率上下文，扩展投影元数据 | 展示版本和缓存语义需同步验证；不新增前端求值器 |

实现前扫描所有 `RunExpr*`、`ComputeTieredQuota*` 及快照构造/复制入口，建立完整覆盖清单。
上表为已定位的主要边界，不宣称已穷尽全部调用点。`relaykit/` 保持独立，不引入根模块配置依赖。

### 3.6 迁移、发布与回滚

1. 先完成后端函数、上下文冻结、保存校验、试算、展示和目标执行路径测试，再允许配置使用新函数。
2. 所有会处理该配置和在途任务的节点升级完成后，按明确模型名单替换固定汇率；禁止用正则批量猜测
   现有表达式里的除数是否为汇率，禁止自动更换全部美元模型价格。
3. 历史表达式及已冻结任务不迁移，现有公式继续按原常数结算；新增函数不会追溯改变历史费用。
4. 如需回滚，先停止新增使用新函数的受理，并将后续模型配置改为经核验的固定 USD 公式。
   引用新函数的在途任务仍需由支持该函数的节点处理完成，不能直接回滚到无法解释其快照的旧二进制。
5. 这会扩展“表达式 + 冻结上下文”的合同；实施时更新权威语言说明与架构事实，评估是否需独立 ADR，
   不把本临时文档作为第二套长期规范。未经真实 Provider、三库与部署验证，不标记生产可用。

## 4. 验证计划与验收标准

采用确定性输入与精确预期，覆盖真实费用和生命周期，不添加仅提高覆盖率的重复测试。

| 验证边界 | 必须保护的行为 |
| --- | --- |
| 函数语义 | 引擎只使用受控上下文；缺失、零、负数、NaN、无穷大汇率报错；旧表达式无需汇率仍可执行 |
| 官方按张合同 | 0/1/2/10 张参考图得到正确 USD 费用；不依赖 p/c/img_o，不能显示为 Token 单价 |
| 汇率变更 | A 请求以 6.76 预扣后，将设置改为 7；A 仍按 6.76 结算，新请求 B 按 7 求价 |
| 计量缩放 | 普通百万缩放与任务直接 USD 两条路径均只换汇一次，不相差百万倍 |
| 资金生命周期 | 补充预扣、组更新、部分结算、失败退款、欠费补偿不重新读汇率；退款不重复或产生额外收益 |
| 异步恢复 | 图片、视频 attempt/Task、Batch 序列化后重启恢复仍使用冻结值；缺失必要快照拒绝重算 |
| 不可信输入 | 请求 body/header、同名 param 和管理试算样本不能注入系统汇率；参考图数量由服务端归一 |
| 多实例与并发 | 设置更新与请求快照没有数据竞争；明确定义并验证各节点配置生效边界 |
| 展示与缓存 | 相同表达式在两个汇率下展示不同金额；历史按冻结值；编译缓存不锁死旧汇率，投影不串值 |
| 配置与发布 | 全部写入口拒绝非法汇率；未支持的执行入口拒绝新函数；无新语法的历史配置正常运行 |
| 持久化兼容 | SQLite/MySQL/PostgreSQL 保存及恢复一致；优先沿用快照 TEXT/JSON 字段，不引入专用 JSON 列 |

新增或实质重写的 Go 测试使用 `require`/`assert`。仅在实际涉及 `relaykit/` 或其公共 API 时追加
`cd relaykit && GOWORK=off go build ./...`；前端实现阶段按 `web/AGENTS.md` 与相关技能验证。
文档变更运行 `task docs:check`、`task ai:check`；将来修改公开 API 文档时追加 `cd web && bun run docs:validate`。
