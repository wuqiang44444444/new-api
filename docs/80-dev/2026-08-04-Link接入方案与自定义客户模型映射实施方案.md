# Link 接入方案与自定义客户模型映射实施方案

## 1. 目标与结论

本方案依据 [Link 服务合同概念与协作关系](2026-08-04-Link服务合同概念与协作关系.md)，从管理员
配置体验出发收敛 Link 渠道设计：管理员在一个渠道上只选择一次“Link 接入方案”，系统随即确定
Provider、视频上游合同、素材上游合同、素材解析方式、路径、Adapter 和 implementation execution
binding；
管理员继续使用 NEWAPI 现有 `models` 和 `model_mapping` 配置客户模型名及其 Provider 模型映射，
不再重复配置“客户模型到 Link SKU”的第二张映射表。

本方案同时落实 [Link 自定义客户模型反向解析复评结论](2026-08-04-Link自定义客户模型反向解析复评结论.md)：

- 任意客户模型名是必须保留的 NEWAPI 管理能力；
- Link SKU 是稳定能力合同，不退化为选中渠道后的临时执行身份；
- 系统从同一次渠道配置自动生成或校验客户模型发布事实，管理员不重复填写；
- 当前候选、Provider 模型和 execution binding 只用于发布推导与选渠后复检，不作为长期合同唯一来源；
- 发布事实的物理载体必须先按最小入侵原则比较，本文不预断定必须新建同名数据库表。

最终关系为：

```text
Link 服务合同
  -> 客户接入合同、SKU 能力、Link 资源、任务与计费
  -> 上游调用合同

渠道
  -> Link 接入方案（管理员选择一次）
       -> 精确 Link implementation ID/version
       -> Provider
       -> 视频上游合同
       -> 素材上游合同与素材解析方式
       -> 路径、Adapter、Task 与计费接线要求
       -> implementation execution binding
            -> Link SKU（发布推导与执行复检）

发布：
  客户模型名
    -> 现有 model_mapping
    -> Provider 实际模型名
    -> 所选 Link 实现的 execution binding 唯一解析 Link SKU
    -> 创建或校验客户模型发布事实

请求：
  contract namespace + route family + 客户模型名
    -> 客户模型发布事实冻结 Link SKU
    -> NEWAPI 按客户模型正常选渠
    -> 选中渠道的 model_mapping 与 execution binding 复检 SKU
```

明确不建设下列能力：

- Link 不在运行时寻找 Provider；
- Link 不自动选择 Standard、Value、Fast 等价值档位；
- Link 不增加成本优化器、健康调度器或跨 Provider 自动降级；
- Link 不替代 NEWAPI 已有的渠道优先级、权重和分发逻辑；
- 不新增管理员必须维护的 `link_model_contracts` 或“Link SKU 绑定”配置区，但允许系统保存自动发布事实；
- 不建立与 `LinkImplementation` 平行的“Link 接入方案”持久化事实。

多个等价渠道仍然允许存在。每个渠道由运维人员预先选择自己的 Link 接入方案，并配置凭据、价格和
权重；运行时由 NEWAPI 在这些已配置渠道中选择一个。Link 只验证候选是否真正履行同一 Link SKU，
并冻结最终执行事实。禁用、熔断或删除最后一条渠道只改变履约可用性，不自动删除或改写客户模型发布
事实。

## 2. 术语和配置边界

### 2.1 本方案使用的概念

| 概念 | 示例 | 作用 | 管理员是否配置 |
| --- | --- | --- | --- |
| Link 服务合同 | Link 视频服务 | 端到端合同总称 | 否 |
| 客户接入合同 | Seedance 官方客户协议 | 客户路径、请求、响应、错误与任务入口 | 否 |
| 客户模型发布事实 | `(link, openai_video, sd-standard) -> SKU` | 稳定记录客户模型在路由族中代表的 Link SKU | 系统自动生成或校验 |
| Link SKU | `seedance-2.0-standard-720p` | 字段、值域、素材、任务与计费能力权威 | 否，系统解析 |
| Link 接入方案 | 飞彩 · Seedance Videos v1 | 精确 Link 实现的管理端投影 | 选择一次 |
| Link 实现 | `feicai.seedance-videos/v1` | Provider 侧版本化代码注册身份 | 否 |
| 实现执行绑定 | `implementation + route/action/profile/provider_model -> SKU` | 发布时推导、发送前复检实际执行是否履行 SKU | 否 |
| 客户模型名 | `sd-standard` | 模型发现、权限、客户价格、Ability、日志与响应 | 是 |
| Provider 模型 | `seedance-2.0-vip-720p-azhw` | `model_mapping` 目标并发送给 Provider | 是，沿用模型映射 |

### 2.2 管理员实际配置

```text
渠道 51

Link 接入方案：
  飞彩 · Seedance Videos v1

模型：
  sd-standard
  sd-value

模型映射：
  sd-standard -> seedance-2.0-vip-720p-azhw
  sd-value    -> seedance-2.0-933-720p-azhw
```

选择 Link 接入方案后，系统自动得到只读结构事实：

```text
Provider：飞彩
视频上游合同：third_party_json_video_media_arrays
素材上游合同：无独立 Provider 素材 API
Link 素材解析方式：source_url
创建路径：/v1/videos
查询路径：/v1/videos/{task_id}
Adapter：54:third_party_json_video_media_arrays:v1
```

系统再根据模型映射目标和已锁定的路由/action/profile，在该 Link 实现的 execution binding 中解析：

```text
seedance-2.0-vip-720p-azhw
  -> seedance-2.0-standard-720p

seedance-2.0-933-720p-azhw
  -> seedance-2.0-value-720p
```

并形成或校验稳定发布事实：

```text
(link, openai_video, sd-standard)
  -> seedance-2.0-standard-720p

(link, openai_video, sd-value)
  -> seedance-2.0-value-720p
```

管理员不需要再配置：

```text
sd-standard -> seedance-2.0-standard-720p
sd-value    -> seedance-2.0-value-720p
```

### 2.3 Link 接入方案不能代替的配置

选择接入方案只完成 Link 结构配置。以下渠道实例和运营信息仍由管理员配置：

- 客户自定义模型名及模型映射；
- Base URL、API Key、AK/SK 或其它实例凭据；
- Provider Project、Region 等账号作用域；
- 客户价格、分组、优先级、权重和渠道状态；
- 部署环境特有的代理、网络、并发和限流配置。

客户价格继续按客户模型名和现有价格体系管理，不由 Link 接入方案动态决定。Provider 成本可用于
运维核算，但不进入 Link SKU 能力合同。

## 3. Link 实现与 implementation execution binding

### 3.1 不新增平行管理员配置

现有 `LinkImplementation` 已登记 Provider、支持的公开 SKU、视频 profile、素材 profile、解析模式、
路径、Adapter、Task 和计费接线。本次在同一代码注册事实中补齐 implementation execution binding，
管理端将精确 implementation 投影为“Link 接入方案”。

execution binding 是代码注册的执行证明，不是管理员需要维护的“客户模型到 SKU”映射。它至少表达：

```text
implementation ID/version
+ route family
+ 固定 endpoint/action/profile/converter（按实现需要）
+ Provider 模型
+ 固定请求形状或素材角色（按实现需要）
-> 唯一 Link SKU
```

必须满足：

- 只在所属 implementation ID/version 和显式声明的执行维度内解析，不建立全局反向推断；
- Provider 模型只是判别维度之一，不把图片/视频、不同 action 或 profile 错误合并；
- 发布时所有判别维度必须已经固定，并且只能解析到一个 Link SKU；
- 若同一固定执行配置仍可对应多个 SKU，则拒绝发布，或拆分接入方案/Provider 模型别名，不能由请求
  字段临时选择合同 SKU；
- 每个 Link SKU 必须存在于 implementation 明确支持的 SKU 集合；
- binding 改变执行语义时，必须遵守 implementation version 与 content hash 约束；
- 公开能力继续由 `VideoSKUCapability` / `ImageSKUCapability` 负责，不在 binding 中复制；
- 现有 `RequiredModelMappings` 必须迁入或投影自同一权威 binding，不能保留两份执行事实。

### 3.2 解析键和路由族

相同 Provider 模型字符串可能出现在不同聚合商、路径或动作中，但鉴权、载荷、素材合同和任务生命周期
不同。因此普适解析键不能只写成 `(implementation, provider_model)`，而应由 implementation 注册项
声明完整维度。例如：

```text
(implementation ID/version, route_family, action, profile, Provider 模型)
```

不能只使用：

```text
Provider 模型字符串
Provider 名称 + 模型字符串
Base URL + 模型字符串
```

`route_family` 使用代码注册的稳定枚举，至少区分图片生成、图片编辑、OpenAI Video、通用视频及需要
独立任务协议的 Provider 入口；不直接把任意原始 URL 当作合同键。Provider 已由渠道选择的 Link 接入
方案确定，execution binding 只负责证明该固定执行配置履行哪个 Link SKU。

### 3.3 飞彩示例

当前飞彩 Link 实现的 execution binding 只包含已注册并通过当前门禁的两个 720p 产品：

| Provider 模型 | Link SKU | 当前状态 | 公开素材能力 |
| --- | --- | --- | --- |
| `seedance-2.0-vip-720p-azhw` | `seedance-2.0-standard-720p` | 已注册，待生产验收 | 图片 ≤9、音频 ≤3、参考视频 0，支持 `asset://` |
| `seedance-2.0-933-720p-azhw` | `seedance-2.0-value-720p` | 已注册，待生产验收 | 图片 ≤9、音频 ≤3、参考视频 0，支持 `asset://` |

其余 Provider 模型只有研究资料时，不能仅通过管理端手工输入模型映射获得 Link 身份。必须先完成
能力、HTTPS、素材、计费和真实黑盒验收，再按实现版本规则加入 execution binding 和对应 SKU。

## 4. 模型映射与合同解析

### 4.1 唯一用户配置链路

不增加：

```json
{
  "link_model_contracts": {
    "sd-standard": "seedance-2.0-standard-720p"
  }
}
```

管理员仍只维护 NEWAPI 原有模型关系。系统在发布事务中自动派生并校验 Link 关系：

```text
customer_model
  -> model_mapping[customer_model]
  -> provider_model
  -> selected implementation execution binding + route family/固定执行维度
  -> 唯一 link_sku
  -> create or validate customer model publication
```

未配置 `model_mapping` 时，沿用 NEWAPI 现有语义，把客户模型名作为 Provider 模型名进行精确解析；
无法唯一解析时拒绝保存或发布，不做名称相似度推断。

自动生成发布事实不等于增加第二个管理员配置入口。其逻辑键为：

```text
(contract_namespace, route_family, customer_model)
  -> link_sku + publication_version
```

`group` 继续负责访问、倍率和渠道路由，默认不进入产品身份键。若未来允许不同客户范围使用同名不同
产品，必须通过请求可稳定确定的显式 `contract_namespace` 隔离，不能依赖最终路由到哪个 group。

### 4.2 三种模型身份

```text
OriginModelName          = 客户模型名
PublishedLinkContractSKU = 客户模型发布事实冻结的 Link SKU
UpstreamModelName        = Provider 实际模型名
```

- Distributor、Token 权限、客户价格、消费日志和响应使用 `OriginModelName`；
- capability、素材、合同等价、exposure 和内部审计使用 `PublishedLinkContractSKU`；
- Provider 请求模型字段使用 `UpstreamModelName`。

不得用内部 SKU 覆盖客户模型名，也不得从 Provider 模型字符串全局反推 Provider。execution binding
在发布时用于生成/校验 `PublishedLinkContractSKU`，运行时只复检实际执行没有偏离，不能根据当前候选
重新定义客户模型是什么产品。

### 4.3 Link 渠道模型语义封闭

选择 Link 接入方案后，该渠道准备发布的每个模型都必须在模型映射后进入实现 execution binding 并
结合 route family 等固定维度唯一解析。
无法解析的普通模型应放入普通渠道，避免同一渠道同时存在受 Link 服务合同约束和无法识别合同的两套
执行语义。

该约束只作用于显式选择 Link 接入方案的渠道，不改变普通 NEWAPI 渠道的自定义模型和模型映射。
若同一 `contract_namespace + route_family + customer_model` 下存在会进入同一次选渠的普通 NEWAPI
候选，则拒绝 Link 发布；不能忽略普通候选后继续发布，也不能为了 Link 收紧普通渠道本身的原生语义。

### 4.4 多个等价渠道

| 客户模型 | 渠道 | Link 接入方案 | Provider 模型 | execution binding 解析的 Link SKU |
| --- | ---: | --- | --- | --- |
| `sd-standard` | 51 | 飞彩 Seedance v1 | `seedance-2.0-vip-720p-azhw` | `seedance-2.0-standard-720p` |
| `sd-standard` | 63 | Provider B Seedance v1 | `provider-b-standard-720` | `seedance-2.0-standard-720p` |

保存和 Ability 发布时必须证明，同一合同命名空间和路由族内的全部 Link 渠道都解析为客户模型发布
事实中的同一 Link SKU。Provider、实际模型、视频上游合同和素材解析方式可以不同，但客户接入、公开
能力、资源、任务和计费语义必须等价。

解析结果不同时配置发布必须 fail closed，不能留给运行时随机选渠。禁用或删除最后一条渠道不删除
发布事实；之后新增不同 SKU 的渠道必须进入显式改绑流程，不能因两个时点都“各自唯一”而静默通过。

### 4.5 发布事实与物理载体

本文确定发布事实必须满足：

- 服务重启、缓存重建、Ability 禁用或删除最后一条渠道后仍存在；
- 能以唯一键原子创建或校验，防止两个渠道并发把同名模型发布到不同 SKU；
- 改绑 SKU 必须显式确认、提升 `publication_version` 并记录操作者、前后值和原因；
- “已发布”与“当前可履约”分离，零候选返回稳定的暂不可用语义；
- Task、attempt 和 AssetBinding 能冻结发布版本，不重新解释历史任务。

物理载体在编码前通过 ADR 或实施设计选择，不在本方案中预定必须是独立表。候选方案至少比较：

| 载体 | 优点 | 必须证明的问题 |
| --- | --- | --- |
| Link 自有独立持久化对象 | 语义清晰，可隔离在新文件，零候选时仍存在 | 三库迁移、事务、审计和运维成本 |
| 既有模型元数据扩展 | 可能减少新对象 | 是否污染普通 NEWAPI 模型语义和扩大上游冲突 |
| Ability 扩展/保留 tombstone | 接近发布流程 | 删除与缓存清理后是否仍是唯一权威，是否扭曲 Ability 生命周期 |
| 仅缓存或候选派生索引 | 实现最轻 | 不满足持久性和跨时间防改义，不得作为最终权威 |

“最小入侵”按实际上游文件改动、热路径接线、三库迁移、缓存一致性和长期合并成本综合裁决，不能
简单等同于“不新增表”。在载体决定前，不进入具体编码。

## 5. 视频、素材、任务与计费协作

### 5.1 视频上游合同

选择 Link 接入方案后，视频上游合同随 implementation 固定，管理端只读展示其 profile、创建和查询
路径、Adapter 与任务状态方式。管理员不能再把某个实现与另一个视频合同自由组合。

同一 implementation 可以覆盖多个 Link SKU；如果模型间差异只体现在公开字段、值域或计费能力，
由 execution binding 指向不同 SKU。如果差异涉及不相容鉴权、Base URL、Adapter 或任务生命周期，
应拆分 Link 实现或渠道。

### 5.2 素材能力必须完整覆盖

Link SKU 能力合同声明客户能否使用 `asset://`，以及素材类型、数量、角色、组合和授权要求；素材
上游合同声明实现通过 `upstream_binding`、`source_url` 或两者来履行该能力。

保存、Ability 发布和发送前必须验证：

```text
implementation_asset_capability ⊇ sku_asset_capability
```

不能使用“SKU 能力与实现能力取交集”作为有效公开能力，因为这会让同一个 SKU 随渠道静默缩水。
无法完整覆盖时必须排除实现或拆分 SKU。

`asset_upstream_profile=none` 只表示没有独立 Provider 素材 API；当实现支持 `source_url` 时，仍然可以
完整支持 `asset://`。

### 5.3 Asset 创建提示

如果 `/v1/assets` 的 `model` 或 `target` 接受客户模型名，预创建 binding 时必须复用相同解析链：

```text
contract namespace + route family + 客户模型名
  -> 客户模型发布事实
  -> 稳定 Link SKU
  -> SKU 素材能力校验
  -> 当前可履约 implementation（仅在需要预建 Provider binding 时选择）
  -> 素材上游合同
```

客户模型名和 Link SKU 都只是 binding 选择提示，不改变 Asset 的平台身份；Asset 身份始终由
`ast_*` 表达。即使当前没有可用渠道，仍可以依据发布事实判断客户模型是否存在以及 SKU 是否允许该
素材；只有确实需要 Provider 预建 binding 的步骤返回“暂不可履约”。

### 5.4 Task、计费和审计

Task 与 create attempt 至少冻结：

- 客户接入合同版本；
- 客户合同命名空间、route family 和 publication version；
- 客户模型名；
- Link SKU；
- Provider 模型；
- 渠道 ID；
- implementation ID/version/content hash；
- 视频、素材和 Adapter 执行快照；
- 计费快照与必要路径。

客户价格、倍率、Token 权限和客户消费日志继续按客户模型名处理，不静默继承 Link SKU 价格，也不
根据最终选中的 Provider 动态改变客户价格。

管理员审计显示客户模型、Link SKU、Link 实现、Provider 模型、渠道、视频和素材执行方式；普通
客户响应只显示客户模型名。

## 6. 保存、发布与运行时规则

### 6.1 渠道保存

选择 Link 接入方案时至少校验：

1. implementation ID/version 存在且渠道类型匹配；
2. implementation 对应唯一 Provider，并满足单凭据等既有要求；
3. 视频、素材、解析模式、路径和 Adapter 与注册事实一致；
4. 每个客户模型应用 `model_mapping` 后，都能结合 route family 和实现声明的固定维度在 execution
   binding 中唯一解析；
5. 解析出的 Link SKU 已注册 capability，且 implementation 明确支持；
6. implementation 视频和素材能力完整覆盖该 SKU；
7. Provider 模型需要的 SKU 专属路径、converter 和模型要求完整；
8. exposure、凭据、价格和现有协议门禁继续有效；
9. 拟发布的客户模型与现有客户模型发布事实一致；不同 SKU 不能由普通渠道保存操作自动改绑；
10. 同一命名空间、route family 和客户模型下不存在会进入同一次选渠的普通 NEWAPI 候选；
11. 任何缺失、未知、重复或冲突均拒绝，不回退普通渠道语义。

保存禁用渠道时只形成“发布提案”并完成上述校验，不必把尚未启用的模型认定为已经对客户发布。启用
保存或 Ability 发布时，必须在一致的事务边界内创建/校验发布事实，再发布 Ability；若发布事实已经
指向不同 SKU，则要求管理员先执行独立的显式改绑动作，不能让渠道保存隐式完成合同变更。

### 6.2 Ability 发布

Ability 仍以客户模型名参与 NEWAPI 分发，但 Link Ability 发布的前置顺序改为：

```text
1. 根据接入方案、route family、model_mapping 和 execution binding 推导唯一 SKU
2. 原子创建或校验客户模型发布事实
3. 校验本渠道 execution binding 完整履行已发布 SKU
4. 校验同一选渠范围没有普通 NEWAPI 候选混入
5. 发布原有 NEWAPI Ability
6. 缓存渠道派生执行事实用于候选过滤和发送前复检
```

同一命名空间和 route family 中，同一客户模型的多个启用 Link 渠道必须解析为发布事实中的同一 Link
SKU；不一致时不得发布 Ability。渠道派生事实可以进入缓存或内部索引，但缓存不是合同权威。禁用、
熔断或删除最后一条 Ability 只改变“当前是否可履约”，不删除发布事实。

### 6.3 请求执行

```text
1. 从请求稳定确定 contract namespace、route family 和 customer_model；
2. 读取客户模型发布事实，冻结 Link SKU 与 publication version；
3. 按客户接入合同和冻结 SKU 校验字段、值域、素材与计费维度；
4. 通过 NEWAPI 权威候选源施加 Link 资格和 Asset 可解析约束，不复制优先级、权重或重试选渠；
5. NEWAPI 按现有分组、路径、优先级、权重、Affinity 和重试规则选择渠道；
6. 应用选中渠道的 model_mapping，取得 Provider 模型；
7. 使用选中 implementation 的完整 execution binding 重新解析并复检仍为冻结 SKU；
8. 复检 implementation、视频、素材、路径、exposure 和凭据未漂移；
9. 发送 Provider，并冻结客户模型、发布版本、SKU、实现、渠道、上游模型和计费快照。
```

Link 不重新选择档位，不改投未配置 Provider，也不在发送后发生未知结果时盲目换渠道创建第二个异步
任务。当前没有合格候选时，根据仍然存在的发布事实返回稳定的“Link SKU 暂不可履约”，不返回“模型
不存在”，也不降级到普通 NEWAPI 候选。

## 7. 渠道管理端调整

### 7.1 当前问题

当前渠道页把“Link 实现”“视频上游方案”“素材上游协议”“模型”“模型映射”表现为多组近似独立的
配置，并根据模型名称动态隐藏 Link implementation。这会导致：

- 自定义客户模型名无法可靠参与 implementation 过滤；
- 管理员需要理解 Provider、profile、路径和素材机制之间的技术关系；
- implementation、视频协议和素材协议可能形成不匹配组合；
- 如果增加可编辑 Link SKU 绑定，同一客户模型关系需要维护两次；
- “素材协议=none”容易被误解为不支持 `asset://`。

### 7.2 目标界面

```text
Link 接入方案
[飞彩 · Seedance Videos v1]

执行摘要（自动、只读）
Provider：飞彩
视频上游合同：JSON Media Arrays
素材上游合同：无独立 Provider 素材 API
Link 素材解析：Source URL
支持的 Link SKU：Standard 720p、Value 720p

模型
[sd-standard] [sd-value]

模型映射
sd-standard -> seedance-2.0-vip-720p-azhw
sd-value    -> seedance-2.0-933-720p-azhw

发布结果（自动、只读）
openai_video / sd-standard -> Standard 720p · v1 · 当前可履约
openai_video / sd-value    -> Value 720p · v1 · 当前可履约
```

不显示可编辑的 Link SKU 绑定区，也不在模型行增加 Provider 下拉框。管理端可以只读展示自动推导的
发布事实、版本和当前履约状态；若映射目标将导致改绑 SKU，必须阻止普通保存并引导管理员进入显式
合同变更流程。

### 7.3 与当前 UI 的差异

| 区域 | 当前行为 | 目标行为 |
| --- | --- | --- |
| Link 选择 | “Link 实现”，并受当前模型名过滤 | “Link 接入方案”，只按渠道类型展示，不依赖模型填写顺序 |
| Provider | 隐含在实现名称 | 作为选中方案的只读摘要，不按模型选择 |
| 模型 | 支持自定义 | 保持不变 |
| 模型映射 | 客户模型到 Provider 模型 | 保持原语义，成为唯一模型关系配置入口 |
| Link SKU 绑定 | 当前没有 | 不新增可编辑绑定；通过 execution binding 自动推导并只读展示发布事实 |
| 视频上游配置 | 独立可选 | 作为“视频上游合同”自动填入并锁定 |
| 素材上游配置 | 独立可选 | 作为“素材上游合同”自动填入并锁定 |
| 素材解析方式 | 不直观 | 只读显示 `source_url` / `upstream_binding` / 不支持 |
| 路径和 Adapter | 分散配置 | 由 Link 接入方案派生并由后端复检 |
| 错误提示 | 字段级或保存后错误 | 定位到映射目标、Link SKU 或接入方案不匹配 |

### 7.4 模型映射交互

选择 Link 接入方案后，模型映射目标可使用 execution binding 的 Provider 模型投影提供下拉或建议项：

```text
seedance-2.0-vip-720p-azhw
  Standard 720p · 图片≤9 · 音频≤3

seedance-2.0-933-720p-azhw
  Value 720p · 图片≤9 · 音频≤3
```

这不是根据客户模型名过滤方案。顺序始终是：先选择 Link 接入方案，再填写客户模型和模型映射。
未知 Provider 模型不能因名称相似自动获得 Link 资格；确有账号级 Provider 模型别名需求时，必须由
该 implementation 显式登记别名规则。

### 7.5 非 Link 渠道

未选择 Link 接入方案时：

- 现有模型与模型映射不变；
- 视频和素材配置继续按普通渠道既有规则处理；
- 不执行 Link execution binding 解析；
- 不生成 Link SKU、implementation 或素材执行快照。

普通渠道自身的保存、选渠和 `model_mapping` 语义不因 Link 改变。若普通渠道后来发布了与既有 Link
客户模型相同、且会进入同一 route family/选渠范围的 Ability，系统不得收紧普通渠道；应让对应 Link
发布进入冲突/暂不可履约状态并告警，直到管理员调整命名空间、客户模型或渠道范围，禁止继续把普通
候选当成 Link 等价实现。

## 8. 设计门禁与实施分解

### 0. 编码前架构门禁

- 通过 ADR 或实施设计确定客户模型发布事实的物理载体，不预设独立表或 Ability 扩展天然更优；
- 对每个候选载体列出需要修改的上游文件、热路径接线、三库迁移、事务、缓存和审计方案；
- 证明删除最后一条 Ability、服务重启和缓存重建后发布事实仍存在；
- 定义 `contract_namespace` 与 route family 注册表，以及同名 Link/普通候选冲突的检测边界；
- 定义显式改绑、版本和审计的最小流程；没有真实运营需求时不预建暂停、退役、释放名称等完整状态机；
- 更新或补充 ADR-0015：SKU 仍是稳定能力合同，新增的是任意客户模型别名发布到 SKU 的规则。

以上门禁未完成前，不进入具体编码。

### A. 注册元数据与解析

- 扩展 Link implementation 注册元数据，增加多维 execution binding；
- 在独立新文件实现 `(implementation, route/action/profile/provider_model/固定执行维度) -> link_sku` 的
  规范化和唯一解析；
- 将现有 `RequiredModelMappings` 迁入或投影为同一 execution binding 的固定要求；
- implementation content hash 纳入会改变执行语义的 binding 字段；
- 不在 `ChannelOtherSettings` 增加 `link_model_contracts`。

### B. 保存与 Ability 门禁

- 收窄修改渠道 Link 校验接线，对每个客户模型应用现有模型映射后再解析 execution binding；
- 为选择 Link 接入方案的渠道实施 Link-only 模型封闭校验；
- 按已选物理载体实现发布事实的原子创建/校验、显式改绑和审计；
- 更新 Ability 发布门禁，保证同一客户模型跨渠道解析到发布事实中的相同 Link SKU；
- 检测同一命名空间、route family 和选渠范围内的普通候选冲突，只让 Link 侧 fail closed；
- 继续验证 exposure、单凭据、视频、素材、路径、Adapter 和 Provider 模型要求；
- Advanced Custom route 继续按客户模型参与路由，但用已发布 SKU 校验公开能力和 converter 要求。

### C. 请求与执行快照

- 增加独立的客户模型发布事实读取边界和请求上下文字段；
- Distributor 继续使用客户模型名和现有分发逻辑；
- 候选资格过滤复用 NEWAPI 权威候选源，不复制优先级、权重、Affinity 或重试逻辑；
- 选中渠道后通过完整 execution binding 重新解析并复检 SKU、implementation 和 Provider 模型；
- `RelayInfo`、Task、attempt、AssetBinding 与 exposure 使用已发布并冻结的 Link SKU 和 publication version；
- Provider 请求继续使用 `UpstreamModelName`，客户响应继续使用 `OriginModelName`。

### D. Link 资源接线

- `/v1/assets` 的 `model` / `target` 若接受客户模型名，直接读取同一发布事实；
- Resolver 使用已发布 Link SKU 和选中 implementation，不从当前候选或客户模型名猜能力；
- 保存、Ability 和运行时统一验证实现素材能力完整覆盖 SKU；
- 保持 Resolver 为 `asset://` 转换 Provider 引用的唯一权威。

### E. 管理端与 i18n

- 将管理端“Link 实现”显示名改为“Link 接入方案”；
- 删除按 `models` 动态过滤 Link 项目的逻辑；
- 选择方案后展示 Provider、视频、素材、路径、execution binding 和支持模型摘要；
- Link 模式下自动填入并锁定视频/素材合同及必要路径；
- 保留现有模型和模型映射，不新增 Link SKU 绑定编辑区；
- 只读展示推导出的客户模型发布 SKU、publication version 和当前履约状态；
- 模型映射目标使用 execution binding 的 Provider 模型投影提供建议和能力摘要；
- 普通保存若会把既有客户模型改绑到不同 SKU，必须阻止并引导显式合同变更；
- 完成 en、zh、zh-TW、fr、ja、ru、vi 全语言同步。

### F. 文档与运维

- 实施完成后把本文确认的术语和边界收敛到 Link 合同、资源和视频当前架构文档；
- 补充客户模型发布事实 ADR，并保持 ADR-0015 的稳定 SKU 能力合同决定；
- 更新渠道运维手册，以“选择 Link 接入方案 + 配置模型映射”为唯一操作路径；
- 用户调用文档只展示客户模型名和公开能力，不展示 Provider 模型或内部 execution binding；
- 完成实施和真实验收后归档两份 `80-dev` 文档。

## 9. 测试与验收

### 9.1 后端

至少覆盖：

1. 自定义客户模型通过 `model_mapping` 和多维 execution binding 推导 Link SKU，并自动创建发布事实；
2. 未配置 mapping 时，客户模型名可以作为 Provider 模型精确解析；
3. Provider 模型只在选中的 implementation、route family、action/profile 等声明维度内解析；
4. 未登记、重复、歧义或缺少执行维度时 fail closed；
5. Link 渠道中的每个模型都必须解析，普通非 Link 渠道不受影响；
6. 同一客户模型跨等价渠道解析到发布事实中的同一 SKU 时可以发布；
7. 同一客户模型跨渠道解析到不同 SKU 时拒绝发布和运行；
8. `T0 SKU-A -> T1 删除/禁用最后渠道 -> T2 新增 SKU-B` 不会静默改绑，必须显式变更并提升版本；
9. 全部渠道禁用、熔断或删除后仍能读取已发布 SKU，并返回“暂不可履约”而非“模型不存在”；
10. 删除 Ability、服务重启和缓存重建后，发布 SKU、版本和审计不丢失；
11. Link 与普通候选同名且会进入同一 route family/选渠范围时，Link 发布 fail closed，普通渠道语义不变；
12. 同一客户模型在不同 route family 的隔离规则生效，图片和视频不会互相解析；
13. 不同 Provider、视频合同和素材解析方式可以完整履行同一公开 SKU；
14. implementation 的视频、素材、路径或 Adapter 不匹配时保存失败；
15. 实现素材能力不能完整覆盖公开 SKU 时拒绝渠道或 Ability；
16. Task、attempt、AssetBinding、exposure 和计费冻结正确的三模型身份与 publication version；
17. Asset 创建提示在零候选时仍从发布事实校验 SKU 素材能力；
18. 客户响应和普通日志只显示客户模型名；
19. 渠道编辑或显式改绑后，在途任务继续使用冻结执行事实；
20. 普通 NEWAPI 自定义模型、模型映射和分发行为无回归。

新增或重写 Go 测试使用 `testify/require` 和 `testify/assert`，只覆盖用户行为、跨模块合同和回归边界。

### 9.2 前端

- 未填写模型时可以先选择该渠道类型的全部 Link 接入方案；
- 修改客户模型不会让已选方案从下拉框消失；
- 选择方案后正确展示 Provider、视频、素材和 execution binding 摘要；
- 只读展示自动推导的 Link SKU、发布版本和当前履约状态；
- 普通保存不会静默改绑既有发布 SKU，冲突时引导显式合同变更；
- 视频与素材合同自动填入、锁定，并能在清除方案后恢复普通渠道行为；
- 模型与模型映射保持现有编辑体验；
- 不出现独立 Link SKU 绑定区域；
- Provider 不成为模型级选择项；
- 未登记映射目标显示明确错误；
- 编辑已有渠道能够无损回填；
- 所有文案通过 i18n、typecheck、lint、format check 和 build。

### 9.3 必跑命令

```bash
go test ./model ./middleware ./service ./relay/...
cd relaykit && GOWORK=off go build ./...
cd web && bun run i18n:sync
cd web && bun run typecheck
cd web && bun run lint
cd web && bun run format:check

```

涉及客户模型发布事实、Channel、Task 或 AssetBinding 持久化语义时，必须验证 SQLite、MySQL 和
PostgreSQL。是否复用既有元数据或新增 Link 自有对象由编码前架构门禁决定；不得为了避免数据库迁移
把仅缓存的派生结果当成合同权威，也不得在未比较冲突面的情况下扩写上游核心表。

## 10. 数据审计与上线顺序

实施前只读审计：

- 已选择 implementation 的渠道及其当前模型映射；
- 同一 implementation 执行形状是否仍会把一个 Provider 模型解析到多个 Link SKU；
- 同一客户模型在多个渠道解析到不同 Link SKU 的冲突；
- 同一客户模型在图片、视频等 route family 中的实际使用和命名冲突；
- 同一选渠范围内 Link 与普通 NEWAPI 候选同名的冲突；
- Link 渠道中无法进入实现 execution binding 的普通模型；
- 现有视频、素材、路径和 Adapter 是否符合准备投影的 Link 接入方案；
- Ability、价格、Token 权限、Task、attempt 和 AssetBinding 的存量身份。

审计结果应生成“拟发布事实”清单，但在管理员确认歧义和改义前不得直接写入。对于无法唯一推导的
客户模型，保持未发布并要求拆分 execution binding、接入方案或客户模型，不按任意候选猜测。

上线顺序：

1. 完成发布事实载体、命名空间、route family、改绑和最小侵入比较，并记录 ADR；
2. 增加 implementation execution binding 及纯解析、校验和回归测试；
3. 为现有 Link implementation 补齐 binding，并只读生成拟发布事实和冲突报告；
4. 管理员确认存量客户模型对应的 SKU，解决 Link/普通同名及跨 route family 歧义；
5. 按已选载体写入初始发布事实，再接入渠道保存和 Ability 发布门禁；
6. 接入 Asset 提示、请求上下文、权威候选资格过滤和发送前复检；
7. 发布管理端“Link 接入方案”单一选择、只读发布事实和执行摘要；
8. 复核现有渠道模型映射、价格、Token 权限和等价渠道 SKU 一致性；
9. 完成真实 Provider、素材、异步 Task 和账单黑盒验收；
10. 最后启用目标渠道和 Ability，并验证零候选、重启和改绑场景。

不得仅因 Provider 模型名称相似就登记 Link SKU，也不得为了兼容未知映射恢复管理员重复配置的第二
张绑定表。

## 11. 完成标准

- 管理员在一个渠道上只选择一次 Link 接入方案；
- 选择后自动确定 Provider、视频上游合同、素材上游合同、解析方式、路径、Adapter 和 execution binding；
- 客户模型名和 Provider 模型继续只通过现有模型与模型映射配置；
- 系统能从“所选 implementation + route family/固定执行维度 + Provider 模型”唯一解析 Link SKU；
- 系统自动创建或校验稳定客户模型发布事实，管理员不维护第二张映射；
- 发布事实独立于当前渠道和 Ability 存在，零候选、重启与缓存重建不会丢失合同身份；
- 客户模型改绑 SKU 必须显式确认、版本化和审计；
- 管理端没有第二张客户模型到 Link SKU 的重复映射；
- 同一个 Link SKU 的实现能力完整覆盖其视频、素材、任务和计费合同；
- 多个等价渠道可以使用不同 Provider 实现同一客户模型和 Link SKU；
- NEWAPI 继续负责既有渠道选择，Link 不新增 Provider 自动选择；
- 候选资格过滤复用 NEWAPI 权威候选源，不复制 Distributor 的优先级、权重、Affinity 或重试逻辑；
- 同一范围内 Link 与普通候选不会混用，冲突时 Link fail closed 且普通 NEWAPI 语义不变；
- 客户接入、SKU、资源、任务、计费和南向执行分别使用正确身份；
- 普通 NEWAPI 渠道、自定义模型和模型映射行为无回归；
- 后端、前端、relaykit、三数据库和文档检查全部通过。

## 12. 实施结果
