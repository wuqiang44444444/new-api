### 保存及按需读取

- 共核对 20 个请求样本的证据，28 项实际请求/响应正文 SHA-256 比较全部相同；同时检查对象在盘
  为 `NEVSIO3` 密文。比较含真实成功、上游失败、本地拒绝、流式和图片大正文，不把缺少已记录
  哈希的历史 GET 样本算作成功比较。
- Base64 图片上游正文 509,447 B、客户响应正文 509,393 B 均完整可下载；客户响应哈希与实际收到
  的字节一致。区别来自原生业务交付转换，取证层未改写两边各自的正文。
- 小 JSON 默认读取返回原始文本，只有 `format=json` 返回格式化文本；非法 JSON 保留原文并报告
  `invalid_json`。格式化前后密文文件哈希不变。
- 大图片 JSON 的查看上限为 65,536 B，显式格式化返回 `display_limited`，不将截断预览当成完整
  JSON。完整下载继续返回全部正文。
- 两条视频媒体下载的请求与交付事件均没有正文对象，授权读对象返回 410，符合媒体旁路规则。
  这是媒体正文未采集，不是视频下载失败。
- 合成测试用户本轮普通错误事件没有 `http_exchange` 正文快照；结构化错误事实保留。

### 长连接测试发现并修复的缺陷

初次运行 24 路长连接时，业务消息全部送达，但五秒切段累计丢弃 64 个证据片段。旧片段等待
后台发布时仍占预算，新片段再次申请同一全局对象预算，导致切段时短暂双占。连接结束立即
封存的旧微基准未覆盖该场景，不能据其通过认定长连接完整性。

修复保持现有结构：同一 WS 方向的相邻待发布片段共享预算，有序 worker 在打开后段前先完成
已处理完的前段；保留 64 MiB 块预算和物理流上限。无正文握手立即释放请求记录，上游握手前
补一次身份事实。修复仅涉及取证专属文件，没有增加新的原生 Relay、DTO 或计费接线。

新增确定性回归占住其余 127 个预算并阻塞前段发布，要求下一段仍保存完整；修复前失败、修复后
及 race 模式通过。另保留原有截断、二进制旁路、方向并发、清理围栏与篡改认证回归。

### WebSocket CPU 与内存对照

相同修复后二进制，仅切换证据开关。每轮重启网关、先预热一条连接，再运行 24 路连接、每条消息
1,024 B、总目标 1,000 条/秒、稳态 20 秒。每轮实际发送及回显 19,992 条，业务错误为零。CPU
稳态区间排除握手、两秒静置及排空；另有完整阶段指标，未混入下表。RSS 为网关该轮峰值，
并非仅证据缓冲占用。100% CPU 表示一个 CPU 核，不是整机全部核心。

| 稳态 CPU / 单核 % | 15.102 / 17.201 / 17.753 | 22.177 / 22.379 / 21.543 |
| CPU 中位数 | 17.201% | 22.177% |
| 峰值 RSS / MiB | 87.859 / 92.969 / 94.328 | 139.094 / 144.891 / 138.656 |
| 峰值 RSS 中位数 | 92.969 MiB | 139.094 MiB |

开启证据 CPU 中位数增加 **4.976 个百分点**，相对关闭增加 **28.93%**；峰值 RSS 中位数增加

**240,024 条方向记录**（含预热），无重复、遗漏或正文变化，落盘均加密，最终活动记录/对象/块

## 实验 B 正式实施复验

### 实施范围与验证方式

实验 B 已写回原始工作树：两处固定额度为 512、WS 十五秒封存、OpenAI Realtime 两处高频运行
诊断使用既有 Debug；64 MiB 正文块预算、四个 worker、消息边界、按需读取和清理守卫保持。
本次使用无 overlay 的正式构建，按 `build-manifest.json` 记录三个生产逻辑文件及二进制 SHA-256。
原生文件新增修改只有两个日志调用，必要性和上游同步影响见[方案第 9 节](2026-10-31-业务请求证据全覆盖与低开销存储实施方案.md#9-实验-b-正式实施)。

性能基线为可复现 Git `383b81636`，不是关闭证据或逐消息参照。旧版 WS 按整连接内存缓冲、结束后
保存；本次 24 路、每条 1024 B、目标每秒 1000 条、20 秒负载低于旧版单连接限额，双方均逐对象
授权解密并核对四方向全部序号、边界与实际字节。三轮交替执行，CPU 统计含握手及全部证据落盘
排空；初始化/预热排除，RSS 每 250 ms 采样。全部 Go 检查结束后才启动性能采样。

使用独立空业务数据的 SQLite 模板、合成账号与凭据、本地回显 Provider；SMTP/错误报告/自动渠道
测试关闭，不复制真实渠道或历史任务，不进行真实 Provider 生成。原始凭据与运行数据不写入本文。
新增图片/视频 URL 回归覆盖实际四方向保存与读取，媒体地址访问次数必须为零；既有媒体代理和
对象存储搬运旁路回归继续执行。既有真实 Provider 样本、物理分辨率差异和回源限制保留在前文，
本轮合成负载不能替代生产 Provider、资金账单、共享盘或灰度验收。

### 64 路正式完整性

64 路、目标每秒 2,000 条、每条 1024 B、持续 45 秒；实际发送并收到 **89,984 条**业务消息，
错误为零。授权读取并解密全部片段，核对四方向序号、消息边界及原文，共 **359,976 条**方向记录
（含预热），全部一致；WS 加密对象 1,028 个，正常 failed/dropped 为零，活动记录/对象/正文块
最终归零。峰值 RSS **252.422 MiB**，P95 **3.154 ms**。此轮跨越多次十五秒封存，未复用此前
overlay 的验收结果。

该实测覆盖本地消息率与负载，512 仍是有界资源额度，更高并发或慢盘仍可能退让；不可解释为
无限连接或整体进程内存仅 64 MiB。

### 64 路清理并发复验

独立新数据运行 64 路、目标每秒 2000 条、45 秒，在持续发送第八秒由 Root 申请固定 cutoff
清理。**89,984 条**业务消息全部送达，业务错误为零；清理任务 succeeded，65 个旧窗口全部回收，
删除 325 个已发布或暂存文件，释放 **67,216,679 B**，删除失败和数据库失败均为零。

结束后选中的旧索引、孤立最终文件、加密暂存均为零；活动记录/对象/块归零，65 条消费日志及
测试渠道仍在。关闭窗口后的在途发布按围栏拒绝，本轮 failed=576、dropped=320，属于主动清理
后的取证拒绝，不计入正常容量的零缺证据结论，也不代表丢失业务消息。这些计数可能重叠，不能
相加当作互斥完成数。初次脚本因此误报排空超时；已修正清理阶段按资源归零判定，并以新数据
重跑上述结果，未覆盖初次指标。普通无故障性能轮次仍核对全部落盘与完整原文。

该演练没有填满宿主磁盘，也没有修改两天保留或五秒磁盘采样；超过 90% 的暂停/一天 cutoff
继续由已有确定性回归保护。专用卷/配额耗尽、外部数据库负载及多实例共享盘仍待部署验收。
