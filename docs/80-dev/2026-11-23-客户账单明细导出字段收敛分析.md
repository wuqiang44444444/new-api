# 账单与用量导出字段收敛方案

## 问题与目标

管理对账以核对账期用量和实际入账为主。财务先用汇总核对总量和金额，发现差异时再定位请求和查阅计价依据。各报表按这一流程选择字段和导出范围，逐笔文件保留实际用量、入账金额及必要的定位信息。用量分析保留各档缓存写入量，供用户按日期、模型或渠道比较。

## 调整前的情况

- 每行是一笔入账事件。同一请求可能有预扣、补扣和退款等多笔记录。净额使用实际入账，退款为负，原价和优惠缺少可核验依据时留空。当前基础表头 38 列，日报明细追加 4 列覆盖信息。历史固化文件直接下载既有文件。[客户账单产品说明](../10-product/客户与上游对账单产品说明.md#客户账单下载与金额解释)、[当前表头](../../service/customer_statement_export.go)、[日报覆盖列](../../service/billing_report_export.go)
- 单客户账单明细按整个账期导出，页面的令牌筛选不限定下载范围。服务端按行数和字节数分片。分片可单独下载，也可打包为 ZIP。[客户账单下载说明](../10-product/客户与上游对账单产品说明.md#客户账单下载与金额解释)、[明细分片规则](../../service/customer_statement_export_execution.go)
- 客户 CSV 目前同时有令牌名称和内部 ID。名称来自入账记录，账单汇总可按稳定 ID 合并改名前后的记录。日报已保存日志中的流式标记，账单明细 CSV 尚无对应列。[API Key 用量账单架构](../20-architecture/账单计费-APIKEY用量账单架构.md#51-聚合键)、[日报投影](../../model/billing_report_build.go)
- 计费组关联有效组倍率，可能采用客户专属组倍率。渠道 ID 标识实际履约渠道。现有客户 CSV 的公开范围排除内部渠道，管理员的上游对账按渠道 ID 和双方请求 ID 核对。[客户与上游对账架构](../20-architecture/账单计费-客户与上游对账架构.md)、[合同定价架构](../20-architecture/账单计费-用户模型合同定价架构.md#4-计费与任务生命周期)
- 现有明细只导出缓存写入总量。实际计价路径可分别应用普通写入、5 分钟、1 小时和 12 小时的倍率。历史记录可能只有总量。[缓存计价实现](../../service/text_quota.go)、[现有写入汇总口径](../../model/billing_statement_breakdown.go)
- 管理员用量记录的当前 CSV 使用固定英文技术字段。用量分析通过独立入口生成，当前同一份文件可能包含日行、周期汇总和总计，缓存写入使用总量列。[用量记录表头](../../service/customer_export_csv.go)、[用量分析导出](../../service/usage_analytics_export.go)

## 优化方案

### 管理对账与下载范围

- 日常对账先打开按日或按月的汇总。发现用量或入账差异后，在单客户账单明细的「账单日期」选择需要核对的一天。只列当前账期和账单版本中该客户有明细的日期，默认最近一天。管理侧上游对账继续支持按渠道 ID 和上游请求 ID 定位。
- 明细下载应在申请时明确显示所选范围，结果应与同范围、同版本的明细查询一致。按请求 ID 下钻时，列出关联证据明确的入账事件，并为实际查询范围计算一次请求净额。账期汇总仍按事件的入账时间归属。
- 全量逐笔 CSV 用于归档和批量处理，继续支持后台分片及 ZIP。用于人工查差异的下载优先通过缩小范围控制行数，单个明细分片还需考虑行数和字节数。按实际账期样本和财务使用的表格软件评估分片大小。
- 日期按北京时间。单客户及全客户汇总利用现有「对账说明」标明部分覆盖，并写入已发布与应发布天数。部分覆盖的明细在文件名中标明，并随下载提供同范围、同版本的汇总或日期清单。汇总 CSV 单独转发后仍能识别部分覆盖。

### 单客户账单明细列序

| 对账步骤 | 建议列序 |
| --- | --- |
| 定位交易与核对金额 | 入账时间 → 请求 ID → 入账类型 → 令牌 → 模型 → 流 → 实际入账净额（退款为负）→ 原价 |
| 核对合同与倍率 | 合同 ID → 合同版本 → 有效组倍率 → 合同倍率 → 模型最终倍率 |
| 检查计费用量 | 计费方式 → 计入请求数 → 输入 Token → 输出 Token → 缓存读取 Token → 普通缓存写入 Token → 5 分钟缓存写入 Token → 1 小时缓存写入 Token → 12 小时缓存写入 Token → 计费张数 → 计费秒数 → 计费说明 |

### 取值与对账规则

- 逐笔表只展示一列「令牌」，使用入账时记录的名称。单客户对账用请求 ID 定位调用，同一请求可对应多笔入账。接受改名后出现不同名称及同名令牌难以仅按 CSV 名称区分的取舍。
- 「流」紧跟模型，按本站记录的流式标记输出「是」或「否」。能可靠关联原请求的退款及异步调整沿用原请求标记，缺少证据时留空。
- 金额单位写入表头，沿用导出或固化版本实际采用的单位，删除逐行重复的币种列。汇总中的累计退回以正数展示，实际入账净额等于累计扣减减累计退回。逐笔退款净额为负。汇总范围的原价证据齐全时，展示原价与优惠，优惠为原价减净额。存在缺证时，对应汇总金额留空并在说明中提示。
- 合同 ID、合同版本和倍率取入账时冻结事实。模型最终倍率为有效组倍率乘合同倍率。确认无合同优惠时合同因子为 `1`，历史合同状态不明时最终倍率留空。模型倍率用于核对模型应收，独立附加费用、正式取整及异步预扣和结算差额按各自账务事实解释。
- 计费组名称及倍率来源可放入计费说明。管理员上游对账继续使用渠道 ID 和上游请求 ID 定位供应商证据。客户文件继续使用客户请求和价格证据。
- 数值列中，确认是零时填 `0`，缺少可核验值或不适用时留空。用量或计价证据有缺项时，通过汇总的说明提示受影响的项目和笔数。计费张数和秒数使用可核验的计费计量，多种时长计量在说明中分别标明，HTTP 请求耗时用于用量日志。
- 逐笔「计费说明」仅在有必要解释时填写，例如历史计量缺失、推导用量、原价来源和已核实的任务扣款差额。任务差额说明包含合同应收、实际扣款和差额。核实单价时按请求查询入账时的价格信息。
- 缓存写入按实际使用的普通、5 分钟、1 小时和 12 小时档分别记录。仅有正向总量的历史记录保留各档空白，在说明中写入可确认的未分档总量。汇总分别累加各档已知值，分档齐全时四档合计等于实际写入总量。上游用量分析在说明列披露冻结表达式另有计价归档或倍率换算的情况。

### 其他导出报表

以下列头按从左到右排列。客户账单优先展示实际入账金额，上游账单优先展示渠道和供应商匹配字段，用量分析优先展示日期和统计维度。面向客户的「令牌」使用名称。金额单位写入金额表头，管理员用量记录另保留便于脚本换算的单位字段。生成时间、日界时区等文件级信息放入文件名或导出记录，覆盖提示按下载范围交付。

#### 1. 单客户账单汇总

用于核对单个客户在账期内按令牌、模型、计费方式汇总的金额和用量。每个组合一行，先核对净额、扣减、退回和优惠，再按需下钻。合同 ID、版本与倍率按逐笔明细核对，汇总行保留可加总的金额与用量。

| 顺序 | 列头 |
| --- | --- |
| 识别 | 令牌 → 模型 → 计费方式 |
| 金额 | 实际入账净额 → 累计扣减 → 累计退回 → 原价 → 优惠 |
| 用量 | 计入请求数 → 计费次数 → 退款次数 → 输入 Token → 输出 Token → 缓存读取 Token → 普通写入 Token → 5 分钟写入 Token → 1 小时写入 Token → 12 小时写入 Token → 计费张数 → 计费秒数 |
| 核对 | 对账说明 |

#### 2. 全客户账单汇总

用于财务按日或按月核对全量客户。每位客户一行，可按客户 ID 匹配客户档案，按金额与版本定位需要下钻的账单。「客户」优先显示客户名称，缺少时显示用户名。「账单版本」按月填确认月账单版本，按日填日报版本。

账期（上海时区）→ 客户 ID → 客户 → 净结算金额（USD）→ 总扣减（USD）→ 总退回（USD）→ 原价（USD）→ 优惠（USD）→ 请求数 → 账单版本 → 对账说明

#### 3. 上游账单汇总

用于按渠道、上游模型和计费方式核对供应商账单。优先比较本地官方原价与按渠道折扣计算的参考金额。证据不完整时，用已知折后小计和待核算记录数表达覆盖程度。

| 顺序 | 列头 |
| --- | --- |
| 识别 | 渠道 ID → 渠道 → 上游名称 → URL 归组 → 上游模型 → 计费方式 |
| 金额 | 折后参考金额 → 本地官方原价 → 渠道折扣 → 折扣版本 → 已知折后小计 → 待核算记录数 |
| 用量 | 请求数 → 计费调用数 → 输入 Token → 输出 Token → 缓存读取 Token → 普通写入 Token → 5 分钟写入 Token → 1 小时写入 Token → 12 小时写入 Token → 计费秒数 → 本站计费张数 → 实际出图张数 → 渠道测试计价张数 |
| 核对 | 对账说明 |

#### 4. 上游账单明细

用于把供应商账单逐笔匹配到本站调用，并定位用量、渠道折扣或金额差异。供应商侧优先用渠道 ID 和上游请求 ID 匹配，本站用我方请求 ID 追溯。折后参考金额采用本地核算口径，「流」有可信记录时填写，上游任务 ID 继续按现有授权边界显示。

| 顺序 | 列头 |
| --- | --- |
| 逐笔匹配 | 时间 → 渠道 ID → 上游请求 ID → 我方请求 ID → 记录类型 → 渠道 → 上游名称 → URL 归组 → 上游模型 → 客户模型 → 流 |
| 核对金额 | 折后参考金额 → 本地官方原价 → 渠道折扣 → 折扣版本 → 核算状态 |
| 复核用量 | 计费方式 → 输入 Token → 输出 Token → 缓存读取 Token → 普通写入 Token → 5 分钟写入 Token → 1 小时写入 Token → 12 小时写入 Token → 计费秒数 → 计费张数 → 实际出图张数 |
| 追溯 | 记录 ID → 平台任务 ID → 上游任务 ID → 对账说明 |

#### 5. 管理员用量记录

用于处理客户争议、排查异常和供内部脚本逐笔核查。CSV 使用中文表头，保留稳定 ID、原始额度、币种和换算字段。字段版本用于区分新版中文表头与既有导出格式。

| 顺序 | 列头 |
| --- | --- |
| 定位 | 入账时间 → 请求 ID → 入账类型 → 客户 ID → 用户名 → 令牌 → 令牌 ID → 客户模型 → 流 |
| 入账 | 净额 → 原价 → 入账额度 → 折前额度 → 是否计入客户账单 |
| 复核 | 合同 ID → 合同版本 → 有效组倍率 → 合同倍率 → 模型最终倍率 → 计费方式 → 计入请求数 → 输入 Token → 输出 Token → 缓存读取 Token → 普通写入 Token → 5 分钟写入 Token → 1 小时写入 Token → 12 小时写入 Token → 计费张数 → 计费秒数 |
| 证据 | 用量及单价明细（USD，折扣前）→ 金额无法计算原因 → 任务合同应收 → 任务实际扣款 → 任务扣款差额 |
| 导出信息 | 字段版本 → 导出任务 ID → 币种 → 单位金额对应额度 → 汇率 |

#### 6. 用量分析汇总

用于按日期和业务维度分析调用结果、用量和费用走势。默认导出按日用量，周期汇总可单独下载。每个 CSV 只采用一种统计粒度，上游同名模型的确认值与回退值通过「数据说明」区分。按日文件首列为「日期」，周期汇总文件首列为「账期」。两种文件均提供各档缓存写入量，便于筛选、求和及核对缓存使用结构。覆盖不完整的日期随任务冻结，在两种文件的「数据说明」中披露。

| 视图 | 列头 |
| --- | --- |
| 客户侧 | 日期（周期版为账期）→ 客户 → 令牌 → 模型 → 计费方式 → 调用次数 → 成功 → 失败 → 取消 → 其他终态 → 净额 → 扣减 → 退回 → 估算原价 → 输入 Token → 输出 Token → 缓存读取 Token → 普通写入 Token → 5 分钟写入 Token → 1 小时写入 Token → 12 小时写入 Token → 图片张数 → 秒数 → 数据说明 |
| 上游侧 | 日期（周期版为账期）→ 渠道 ID → 渠道 → URL 归组 → 上游模型 → 计费方式 → 调用次数 → 成功 → 失败 → 取消 → 其他终态 → 折后参考金额 → 已知折后小计 → 渠道折扣 → 计费输入 Token → 计费输出 Token → 缓存读取 Token → 普通写入 Token → 5 分钟写入 Token → 1 小时写入 Token → 12 小时写入 Token → 实际出图张数 → 本站计费张数 → 秒数 → 数据说明 |

### 次数口径

- 「计入请求数」是账单事件对请求数的贡献。「请求数」是该字段的汇总。普通请求通常计 1，批处理可按已记录的子请求数计入，退款与异步结算调整的新增请求数为 0。
- 「计费次数」与上游汇总的「计费调用数」用于按次计费模式的调用数量。「退款次数」沿用客户汇总中按次计费的退款记录口径。
- 「调用次数」是用量分析的调用统计，按成功、失败、取消及其他终态查看，按用量报表自身统计范围核对。

### 实施与验收要求

- 核对日报与固化月账单来源能否提供合同身份、流式标记、分档缓存量和计费秒数，明确未知值及不适用时的表现。旧固化文件使用原已生成文件。
- 使用实际账期样本验证从汇总发现差异到按条件导出、打开和筛选明细的流程。按下载范围核对行数、用量与金额，并验证全量分片合并后行数一致。覆盖不全时单独打开转发后的汇总 CSV，仍应能判断覆盖范围。
- 验证日用量与周期汇总的文件各自可直接聚合。在日期、业务维度、数据版本和计量口径一致时，核对两种文件的各档缓存写入量，并覆盖历史仅有总量和明确记录为零的情况。
- 验证退款符号、净额和请求数加总、合同版本切换、任务差额与请求下钻合计。用同一输入校验各报表的列序、适用语言和下载产物，管理员用量记录校验中文表头与技术字段值的对应关系及字段版本。

### 工作区实现

- 已接入单客户明细和汇总、全客户汇总、上游汇总和明细、管理员用量记录及用量分析的新表头。所有新导出与重新生成的 CSV 使用简体中文。用量分析可分别下载按日和周期文件，两种粒度均保留四档缓存写入。
- 单客户明细使用所查看的日报或固化月版本。控制台默认提供一个账单日期选择器，按北京时间逐日生成明细。后台保留现有筛选任务和历史文件的读取行为。覆盖不足的明细可通过 ZIP 取得日期清单。
- 新受理的单客户单日明细每片最多 100 万行或 500 MB，其他缩小范围的逐笔导出每片最多 10 万行或 32 MiB。实际打开、筛选和汇总体验仍需使用目标环境的账期样本与财务日常工具核对。
- 管理员用量记录的字段版本与内部脚本更新方式见[运维手册](../40-operations/01-计费与分组运维手册.md#管理员用量记录字段迁移)。
