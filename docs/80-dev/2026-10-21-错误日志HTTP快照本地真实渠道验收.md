# 错误日志 HTTP 快照本地真实渠道验收

## 问题与目标

使用本地已配置渠道实际调用文本、图片和视频，验证错误日志 HTTP 快照优化在开启请求证据时的
业务行为、过滤、脱敏与性能。范围是验证当前实现，不调整业务处理、原文证据或 Provider 协议。

## 当前实际情况

### 环境和隔离

- macOS / Apple M5、当前工作区代码、SQLite；由本地 `one-api.db` 生成私有测试副本，真实渠道连接
  和对象存储配置保持有效。原数据库的相关表最大 ID 与用户余额在测试后核对未变。
- 加载 `.env` 中的证据密钥配置，显式设置 `TASK_REQUEST_EVIDENCE_ENABLED=true`，证据对象目录
  指向测试专用私有目录。不复制密钥、Token、签名 URL、Task 私有字段或原始响应到本文。
- API 进程以 slave 模式运行，关闭后台任务轮询及自动渠道更新；视频通过正式 GET 接口推进观察。
  结果托管使用生产同一 `RunVideoResultTransferPass` 执行一次，运行前仅在测试副本排除历史
  Task 和结果对象，避免领取历史转存；未重发视频创建。
- 真实 Provider 验证不等于生产发布。本次没有验证 MySQL、PostgreSQL、ClickHouse、生产负载、
  外部 Provider 账单或所有 Provider 的失败场景。

### 错误日志、过滤和安全

- 6 条真实错误事件覆盖本地校验拒绝、文本/图片上游 400 及图片传输 500。数据库快照正文为紧凑
  JSON；管理员读取变为缩进 JSON，解析后的字段、值和观察状态一致，读取前后数据库原值不变。
- 对真实事件执行 73 次正向过滤断言：模块、事件类型、客户 HTTP 状态、用户 ID/用户名、Token
  名称、客户模型、渠道、请求 ID、上游请求 ID、原因和起止时间均通过。错误状态、错误模型、错误
  Task ID 与错误上游请求 ID 的反向过滤通过，合计数和两页顺序正确。
- 真实失败事件没有可用的非空 Task ID，故 Task ID 正向过滤使用 `TestGetErrorEventsTypeTaskAndStatusFilters`
  的确定性回归覆盖。渠道测试按上游状态过滤、无 HTTP 状态按 0 过滤仍由
  `TestErrorEventStatusFilterMatchesDisplayedStatus` 覆盖，未制造真实自动渠道检查失败。
- 错误请求加入合成 `api_key` 标记；扫描新错误事件及管理员响应，标记、已知实际渠道密钥和当前
  测试 Token 均未出现。请求头不进入 HTTP 诊断快照，格式化不改变已脱敏内容。
- 图片和视频证据索引、加密对象及授权逐条读取可用；北向 POST 请求正文与发送字节相等。图片
  成功/错误的交付证据与实际 HTTP 响应 SHA-256 一致。加密对象不含明文 Token 或合成标记，授权
  解密后仍保留原请求头和合成字段，证实原文证据未复用诊断脱敏结果。
- 普通文本聊天不在媒体证据登记范围；证据开关开启也不会为本次四个文本请求建立媒体证据索引。

### 性能对照

用真实文本上游 400 事件的四段已脱敏快照构成固定负载，标准 Go benchmark 各运行三次。
旧版本用 `git show HEAD:clienterrlog/http_exchange.go` 的实现及 overlay，当前版本使用工作区
实现；两者执行同一基准。临时 benchmark 接线完成后已移除，不修改业务代码。

| 边界（三次中位数） | 优化前 | 优化后 |
| --- | --- | --- |
| 请求结束 `SnapshotHTTPExchange` | 134135 ns/op | 239 ns/op |
| 同一边界分配 | 208518 B/op，828 allocs/op | 1088 B/op，6 allocs/op |
| 冻结并序列化持久化 | 130499 ns/op | 136745 ns/op |

此样本请求结束阶段耗时减少约 99.82%，分配字节减少约 99.48%；证明 JSON 解释和脱敏已移离该
边界。包括后台脱敏的总成本仍相近，本次不能声称总 CPU 或端到端 API 耗时下降 99%。两组总成本
采样范围重叠；格式化成本由读取承担，未测错误日志页面高并发读取或大队列积压。
真实图片/视频耗时含 Provider 排队、生成和网络，不能用作诊断代码的前后性能对照。

## 优化方案与剩余事项

HTTP 诊断快照在本次样本中达到“请求结束不解释 JSON、后台落库前脱敏、读取再格式化”的预期，
没有发现文本/图片/视频业务、已覆盖过滤或敏感信息保护的回归。上述诊断性能优化没有改动业务处理
或原文证据链路；下述后续修复单独调整视频交付采集位置。

首次验收有一项取证边界未通过逐字校验：视频创建成功时，客户端收到 46 字节的北向响应，而
`client_delivery` 对象保存 174 字节的内部响应。`ModelArkVideoCreateConvert` 先结束 Task
会话采集，`TaskCreateResponseContract` 随后重投影并输出最终响应；快照优化未修改这两个入口。
业务任务、资金和可下载视频正常，但不能声称所有视频响应证据等于客户端最终字节。该事实已补充
到[请求证据架构](../20-architecture/音视频请求证据架构.md)。修正采集位置属于原文证据链路，
后续已单独按最终写出边界修复，见下节；首次样本及历史加密对象保持原样，不能把复验结论回填为
当时样本已经逐字一致。

本地可复核汇总位于 `.local-tests/http-snapshot-live-20261021/`：`results.json`、
`verification.json`、两份 benchmark 输出及基准源文件。私有数据库和加密证据不提交仓库，原始
Provider 响应、密钥和签名 URL 不复制到可分享报告中。

### 视频创建交付证据修复复验

修复只在 `TaskCreateResponseContract` 增加一行外层交付观察接线；新增服务回调复用既有
`evidenceClientWriter`、`FinishTaskRequestEvidenceClientDelivery` 和加密保存入口，Task 会话在
外层拥有交付采集时不再包裹内部缓冲器或提前结束采集。未修改原生 `controller/relay.go`、公开
响应投影、Provider adapter、资金处理、HTTP 诊断脱敏或 JSON 延迟处理策略。

新增真实 Gin / SQLite / 加密对象集成回归，先在修复前复现正文与状态偏差，修复后覆盖 10 个场景：
成功投影、合同错误投影、未投影错误、非法 JSON、捕获上限、断连、部分写出错误、短写、关闭采集
和存储不可用。交付正文与下游 writer 实际接受字节逐字相等，重复的内层结束调用及通用观察器不
生成第二条 `client_delivery`；北向原文仍为转换前请求，业务状态、额度与写出失败观察保持正确。
未经投影的错误保留空白、大整数和重复 JSON 键，不因取证重新解析或编码正文。

另通过真实 TokenAuth、ModelArk 转换、选渠、RelayTask、冻结插件与本地 HTTP Provider 桩完成
资金链集成回归：Provider POST 一次，预扣及 attempt → Task 转移正确，公开响应与解密后的交付
正文完全相同，消费日志没有额外扣费或退款。此复验未再次发起收费的真实 Provider 视频生成。
评审另验证 defer 顺序：资金交付状态先于证据落库记录，避免可选证据 I/O 延迟交付状态观察；

### 修复后的真实视频再次验收

在用户明确授权后，使用修复后的当前代码重新编译服务，加载证据环境变量与密钥，使用新的 SQLite
隔离副本和私有证据目录，实际调用本地渠道 139 的 `seedance-2-0-mini-vidu-cn` 一次。北向请求为
纯文本生成、4 秒、`generate_audio=true`、720p、16:9；南向证据确认 4 秒和声音开启参数均已发送。
服务继续以 slave 模式运行，正式单项 GET 推进状态，托管结果 worker 单独执行一轮。北向创建 POST、
南向创建 POST、Task 和 create attempt 均只有一个，没有重发生成请求。

创建返回 HTTP 200，约 0.443 秒。客户端原始响应为 **46 字节**，创建的 `client_delivery` 原文也
为 **46 字节**；授权读取后直接比较两个字节数组，完全相等，没有先解析 JSON 再重编码比较。
两者 SHA-256 均为 `f6e8756f336716959d3701372c30e768142c837bd90158ada2b02b5cdcd1e6a1`。
创建时交付证据恰好一条，北向原请求也与发送字节相等；后续三次 GET 各自的交付证据摘要与实际
响应匹配，合计四条交付事件分别对应创建和查询，不是同一次创建的重复取证。

最终 Task 为 `SUCCESS / settled`，客户端交付观察为 `server_written`，attempt 为
`complete / transferred`。托管转存一轮完成一个结果，`ready=1`，失败和不可用均为零。实际下载
MP4 为 1541590 字节，`ffprobe` 检查：1280×720、H.264 视频轨 4.041667 秒、AAC 音轨 4.096 秒、
容器 4.096 秒。`volumedetect` 得到平均音量 -35.0 dB、峰值 -17.6 dB，确认音轨存在且不是静音。

计费只有一条 932249 quota 预扣消费和一条 783736 quota 差额退款，最终净扣 **148513 quota**。
用户余额、用户累计用量、Token 余额、Token 累计用量、Task 最终 quota 与消费减退款完全对应。
这是网关侧计费对账，未核对 Provider 外部账单。

共 19 条证据事件和 19 个加密对象，全部可授权读取，读取未改写对象。没有新增错误事件；诊断队列
为空，丢弃、写入失败、持久化失败和诊断失败计数均为零，证据失败／丢弃计数也为零。检查运行、
转存日志以及新计费日志，未发现已知实际密钥或完整签名 URL；未发现证据保存故障。

原数据库的相关表最大 ID、用户余额保持不变，测试服务已停止。可复核汇总、构建摘要和视频位于
`.local-tests/video-delivery-live-20261021/`，主要文件为 `results.json`、`verification.json`、
`build-manifest.json` 和 `video.mp4`；不将私有数据库、加密证据、凭据或原始 Provider 响应提交仓库。
