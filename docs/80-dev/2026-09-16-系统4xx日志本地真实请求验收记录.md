# 系统 4xx 日志本地真实请求验收记录

`model=seedance-2-f` 和 `source={type:url,url:<公共 HTTPS 地址>,expires_at:<当前时间+7200>}`。
类型场景改为 `media_type=video`；TTL 场景改为 `model=seedance-2-0-m`、剩余约 5 秒；
默认组场景改为 `model=seedance-2-0` 且不传 `asset_group_id`；该 DEV 渠道实际未配置默认组。

不存在素材使用专用测试 ID，路径为 `/v1/assets/<测试 ID>?model=<客户模型>`；插件请求为
`GET /kling/v1/videos/text2video/<不存在的测试任务 ID>`；OAuth 为
`GET /api/oauth/<不存在的 provider>`；HeaderNav 场景为 `GET /api/perf-metrics`（不传 model）；

不把它归为未发生的源站 HTTP 404。

### 关键诊断内容

- 422：保留 `capability_check/unsupported_asset_type`、模型 `seedance-2-f`、渠道 72、托管协议、
  `asset_kind=general` 与 `media_type=video`。
- TTL 400：保留 `source_validation/url_ttl_insufficient`、模型 `seedance-2-0-m`、渠道 76、协议，
  公开码仍为 `asset_url_ttl_insufficient`，要求的最小 TTL 为 3600 秒。
- 409：保留 `group_resolution/default_asset_group_not_configured`、模型 `seedance-2-0`、渠道 81 与协议。
- 下载内容 400：公开码仍为 `invalid_request`，日志为 `content_validation/content_type_mismatch`，
  含 `detail.source_content_type=text/plain`；更深失败阶段未被控制器通用映射覆盖。
- Provider 查询 404：公开码 `asset_not_found`，日志保留 `upstream_operation/resource_not_found`、
  模型 `seedance-2-0-m`、渠道 76 与协议。
- 插件 404：正确记录 `module=relay` 和 `/kling/v1/videos/text2video/:task_id`，不记录具体任务 ID；
  OAuth/HeaderNav 携带 PAT 的 400 记录 `identity=personal_access_token`，匿名同请求不记录。
- 统一事件不含测试 KEY/PAT、源 URL 或插件原始任务 ID。模型和渠道字段仅在已经确定时出现。

### 计数与过程中的实际发现

最终 20 场景的健康计数增量为 `accepted=15`、`written=15`；`dropped=0`、`failed=0`、
`diagnostic_failures=0`，队列排空。包括先前 12 次探索请求，进程累计为 `accepted=23`、`written=23`。
3 个测试 KEY 的 `used_quota` 均为 0。

探索阶段使用的域名被本机代理 DNS 解析到 `198.18.0.0/15` 保留网段，源地址前置校验返回
`unsafe_url`，因此没有进入原计划的 422/TTL 分支。保留既有安全检查，改用正常公共 IP 地址后，
成功覆盖这两个目标分支。这表明同为 400，实测日志已能区分 URL 安全检查、TTL、MIME 与重定向失败。

额度耗尽 KEY 的实际合同是 401，统一日志正确排除；删除不存在的托管素材实际返回 404，并非 204。
这两项按实际代码与 HTTP 结果记录，没有修改业务状态码来满足测试假设。

## 优化方案
