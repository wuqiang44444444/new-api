# 本地真实渠道端到端冒烟结果

2026-11-08 已修复本次发现的三个异步图片问题，后续结果见
[异步图片三项修复与真实复验](2026-11-08-异步图片三项修复与真实复验.md)。下文保留首轮观察。

## 1. 结论

本轮已实际启动完整本地应用，使用真实渠道完成文本、图片和 Seedance Mini 4 秒视频调用，
核验主库资金、消费/退款日志、任务状态、真实媒体与 Chrome 页面。**本轮整体不通过，不建议直接发布异步图片功能。**

确认两个异步图片阻断问题：旧定价模式受理返回 500；表达式定价模式下客户幂等键没有约束重复创建。
另有异步图片任务页制品为空的界面缺口。成功结果、失败结果及幂等测试产生的额外费用均纳入本报告。
本轮未修改生产业务代码，也未实施这些缺陷的修复。

执行依据为[本地真实渠道端到端冒烟测试方案](../50-planning/2026-11-06-本地真实渠道端到端冒烟测试方案.md)。
这些结果只证明本轮选中的配置与入口，不等同于全渠道、真实供应商账单、三数据库或生产灰度验收。

## 5. 缺陷与最小修复方向

### P1：异步图片客户幂等没有接线

同一客户、同一 app、同一入口、同一 `Idempotency-Key`，三次测试请求得到三个不同 Task，
其中两次请求体相同，第三次不同；都实际完成并计费。主库 `task_create_idempotencies` 为 0 行。
这不是测试客户端超时自动重试，三次分别是方案明确规定的首次、重放、冲突验证。

代码证据：`router/task-plugin-protocol-router.go:37–44` 的图片路径没有挂接
`middleware.ImageCreateIdempotency`；全仓生产代码搜索该符号只有定义，没有调用。
`relay/image_async.go` 继续读取缺失上下文的 idempotency ID，最终按 0 受理。

最小修复方向：在唯一权威图片入口、执行方式确定后的正确边界恢复现有幂等中间件接线，
不另建幂等状态机；补真实等价重放、冲突、不同 app 与恢复回归，再重新执行本轮用例。

### P1：旧图片定价无法显式异步受理

原本地图片旧定价配置下，同步生成与编辑成功，但同模型 `Prefer: respond-async` 返回 500，
错误为 `initial billing calculation missing or inconsistent`。没有图片 Task 被接受。
在副本经现有 convert/PATCH 保存等价表达式后，同模型、同渠道的异步受理与执行成功。

代码定位：`model/task_image_lifecycle.go:146–150` 的初始计算一致性校验拒绝受理。
现有证据支持初始计算记录与旧定价预估的接线不一致；未通过修改数据库补造计算记录来绕过校验。
最小修复方向：核对旧定价的冻结预扣目标和计算记录生成路径，使合法旧模式履行现有异步合同，
同时保留记录不一致时的失败关闭，不删除一致性校验，也不要求管理员强制迁移价格作为修复。

### P2：成功异步图片在任务页没有可用制品

`GET /v1/tasks/{id}` 返回 succeeded 和有效图片；同任务在页面显示“制品：无”，
`GET /api/task/{id}/artifacts` 返回成功但 `artifacts=[]`。
`controller/task.go:181` 的投影处理专用视频后要求 plugin execution；该原生 Azure 异步图片
没有对应的制品投影路径。最小修复方向是把现有图片结果事实接入统一授权制品投影，
复用既有所有权和签名机制，不保存第二套结果或回退上游直链；同时补齐任务类型标签。

日志顶部毛额/净额以及旧账单接口请求数的口径差异单列待处理，不混入“账本不平”的结论。

## 6. 停止条件、未验证范围与收尾

确认异步幂等重复执行后，停止新增生成请求，只查询、下载、检查界面与对账。
所以本轮没有继续创建素材/素材组，没有追加 Playground 发送或真实 Provider 拒绝/失败测试。
它们不能标为通过；本轮视频退款证明的是成功结算退差额，不是上游失败退款。
合同折扣、其它渠道/模型、Batch、三数据库、断网未知、崩溃恢复、24 小时资金保障与生产灰度未实测。

所有已接受业务任务已完成资金与交付收尾。通过现有价格 PATCH 接口恢复副本原始图片配置，
再读取确认配置完全一致，历史金额未变化。随后停止本轮拥有的实例，停用 4 个临时 Key，
撤销副本会话，移除 transient 登录凭据文件，并清除副本渠道/存储配置中的连接凭据。
审计与冻结任务事实保留在私有目录中；没有删除远端素材组、媒体对象或历史业务记录。
原业务库始终只读；没有改动用户的业务渠道、价格、余额或原有实例。
