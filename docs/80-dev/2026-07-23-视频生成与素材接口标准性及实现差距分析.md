# 视频生成与素材接口标准性及实现差距分析

## 1. 文档目的

本文从 AI API 中转站而非单一厂商代理的角度，确定视频生成、素材资产、素材组和真人认证接口的协议边界、产品合同与实现优先级。

本文分析的原始接口清单包含：

- 视频生成任务：创建、列表、详情、取消或删除；
- 素材：创建、列表、详情、更新、删除；
- 素材组：创建、列表、详情、更新、删除；
- 真人认证：创建 H5 会话、通过 `BytedToken` 查询认证结果。

原始文本中的 `POS1` 按 `POST`、`/api/vl` 按 `/api/v1` 归一化。原始 `/api/v1` 路径没有提供来源 OpenAPI，因此只能判定为第三方 REST 兼容协议候选，不能直接当作 ModelArk 官方协议。

注：`客户 ──北向调用──> 中转站 ──南向调用──> 上游 Provider`

## 2. 中转站定位与最终决策

### 2.1 客户端只使用平台 Key

客户端只持有平台签发的 Bearer API Key，不持有任何上游 Provider 凭据。

```text
客户端
  Authorization: Bearer <platform-api-key>
        |
        v
北向协议适配层
  OpenAI Videos / ModelArk Video / Platform Assets
        |
        v
统一 Task / Asset / Authorization 服务
        |
        v
南向 Provider adaptor
  Bearer / AK-SK / Action / Region / ProviderProject
```

所有 AK/SK、上游 API Key、`BytedToken`、GroupId、上游资源 ID 和签名 URL 均由平台托管，不进入普通客户合同。

当前资源所有权绑定稳定的用户，而不是绑定可轮换的平台 API Key 字符串：

- `UserID`：当前资源所有者；
- `TokenID`：创建来源、限额和审计维度；
- 平台 API Key：身份认证凭据。

Key 轮换不得导致客户失去既有任务和素材。

未来如引入平台 Tenant/Project，必须通过独立数据迁移和 ADR 把所有权从 `UserID` 演进为明确的 owner scope；本轮不预建 Tenant/Project 子系统。文中的南向 `Project` 均指 Provider 项目，后文统一称为 `ProviderProject`，不得与未来的平台 Project 混用；具体南向 DTO 仍使用官方字段名 `ProjectName`。

### 2.2 视频双协议均为 P0

视频北向协议采用：

1. **OpenAI Videos**：面向通用 SDK 和跨 Provider 调用的兼容入口；
2. **ModelArk `/api/v3`**：面向当前 Seedance 2 主业务的字节官方兼容入口；
3. **平台旧视频接口**：保留兼容，不作为新客户首选；
4. **第三方 `/api/v1`**：仅在取得真实 OpenAPI 和客户需求后增加薄兼容层。

OpenAI 和 ModelArk 只能共享内部业务能力，不能混用对外请求字段、状态、分页和错误响应。

当前视频生成绝大部分为字节 Seedance 2，ModelArk `/api/v3` 不是需求门控的边缘兼容项，而是核心业务协议。因此，OpenAI Videos Core 与 ModelArk `/api/v3` 均为 P0：前者保证中转站的通用接入价值，后者保证当前主力模型和字节生态客户的原生接入能力。

双协议 P0 不等于同时建设两套业务系统。两者只能增加薄北向 handler、协议 DTO 和合同测试，必须复用同一 Task、路由、轮询、计费和审计主链路。平台不再新增第三套视频主协议。

### 2.3 素材采用平台托管协议

素材北向只提供平台 API：

```text
/v1/assets
/v1/real-person-authorizations
```

平台不要求客户使用 AK/SK 签名，也不宣称北向兼容 ModelArk Asset Action 的线级协议。中转站内部新增官方 AK/SK Action profile，负责调用 ModelArk 官方素材、素材组和真人认证 Action。

因此，“素材遵守官方规范”的含义是：

- 南向鉴权、Action、Version、Region、ProviderProject、请求和响应遵守官方合同；
- 北向使用平台 API Key 和平台资源 ID；
- 平台负责用户隔离、资源绑定、授权、轮询、清理和审计；
- Provider 私有信息不透传给客户。

### 2.4 中转站边界与复杂度约束

本阶段明确不建设：

- 平台视频或素材对象存储、CDN 和长期二进制托管；
- 普通客户可见的独立素材组 CRUD；
- 通用工作流引擎、动态 Provider 能力注册中心或远程能力探测系统；
- 新的 Tenant/Project 子系统；
- 作为 P0 前提的任务完成 webhook。

视频内容继续采用受鉴权的平台流式代理；任务完成通知以客户端轮询为标准方式。Webhook 仅作为未来平台增强能力，不影响 OpenAI 或 ModelArk 兼容声明。

## 3. 官方协议基线

### 3.1 OpenAI Videos

OpenAI 当前官方 Videos 接口包含：

| 能力           | 方法与路径                                 |
| -------------- | ------------------------------------------ |
| 创建视频       | `POST /v1/videos`                          |
| 查询视频列表   | `GET /v1/videos`                           |
| 查询视频       | `GET /v1/videos/{video_id}`                |
| 删除视频       | `DELETE /v1/videos/{video_id}`             |
| 下载内容       | `GET /v1/videos/{video_id}/content`        |
| Remix          | `POST /v1/videos/{video_id}/remix`         |
| Edit           | `POST /v1/videos/edits`                    |
| Extend         | `POST /v1/videos/extensions`               |
| 创建 Character | `POST /v1/videos/characters`               |
| 查询 Character | `GET /v1/videos/characters/{character_id}` |

为避免把阶段实现误称为完整兼容，平台定义两个能力级别：

- **OpenAI Videos Core**：创建、列表、详情、删除、内容下载、Remix；
- **OpenAI Videos Extended**：Edit、Extend、Character 等新增能力。

只有 Core 合同测试全部通过后，才可声明支持 OpenAI Videos Core；Extended 未完成前不得笼统声明“完整 OpenAI Videos 兼容”。

OpenAI 列表使用 `after`、`limit`、`order`，单页最大 100，返回 `object=list`、`data`、`first_id`、`last_id` 和 `has_more`。视频状态为 `queued`、`in_progress`、`completed`、`failed`。这些是对外合同，不得直接返回本地 Task DTO。

OpenAI 当前创建合同使用 `prompt`、可选 `input_reference`、`model`、`seconds` 和 `size`。其中 `input_reference` 是 `{file_id, image_url}`，不是任意媒体的通用 `input`。官方 `image_url` 继续接受其规定的 URL 或 data URL；`asset://ast_xxx` 仅作为平台文档化扩展，在南向转换前解析到冻结的 AssetBinding。不得为此新增一套通用输入 AST。

OpenAI DELETE 只删除 `completed` 或 `failed` 视频及其存储内容，不承担取消语义。平台若因管理员操作或南向状态产生 `cancelled`，OpenAI 投影统一为 `failed`，并返回稳定的 `error.code=cancelled`；不得向 OpenAI 客户返回不存在的 `cancelled` 状态。

### 3.2 ModelArk 视频生成

ModelArk 官方视频任务接口为：

| 能力           | 方法与路径                                       |
| -------------- | ------------------------------------------------ |
| 创建任务       | `POST /api/v3/contents/generations/tasks`        |
| 查询任务列表   | `GET /api/v3/contents/generations/tasks`         |
| 查询任务       | `GET /api/v3/contents/generations/tasks/{id}`    |
| 取消或删除任务 | `DELETE /api/v3/contents/generations/tasks/{id}` |

官方列表合同必须完整模拟：

- `page_num`、`page_size`，取值上限 500；
- `filter.status`；
- 可重复的 `filter.task_ids`；
- `filter.model`；
- `filter.service_tier`；
- 只返回最近 7 天任务；
- 时间窗口按 UTC 计算；
- 返回官方 `total` 和 `items` 结构。

本地任务账本可以保存更长历史，但 `/api/v3` 只能返回官方允许的 7 天范围。更长历史应通过平台控制台或平台自有任务 API 查询。

平台控制台显示完整保留期内的内部任务，并标注创建协议；超过 7 天的 ModelArk 任务应标注“已超出 ModelArk API 查询窗口”。`/api/v3` 的职责是 SDK 和线级合同兼容，不通过扩大查询窗口提供平台增强能力。

ModelArk DELETE 按任务状态执行：

| 当前状态                         | 官方行为                   |
| -------------------------------- | -------------------------- |
| `queued`                         | 取消任务，进入 `cancelled` |
| `running`                        | 不允许删除                 |
| `succeeded`、`failed`、`expired` | 删除任务记录               |
| `cancelled`                      | 不允许再次删除             |

平台不能用本地隐藏记录代替上游取消成功，也不能因 DELETE 物理删除计费和审计数据。

### 3.3 ModelArk 素材与真人认证

ModelArk 官方真人素材使用 AK/SK 签名 Action API，核心能力包括：

| 领域     | 官方 Action                                                                                    |
| -------- | ---------------------------------------------------------------------------------------------- |
| 素材     | `CreateAsset`、`ListAssets`、`GetAsset`、`UpdateAsset`、`DeleteAsset`                          |
| 素材组   | `CreateAssetGroup`、`ListAssetGroups`、`GetAssetGroup`、`UpdateAssetGroup`、`DeleteAssetGroup` |
| 真人认证 | `CreateVisualValidateSession`、`GetVisualValidateResult`                                       |

官方接入还要求：

- `ServiceName=ark`；
- `Version=2024-01-01`；
- 明确 Region；
- ProviderProject 与视频推理接入点一致；
- 素材能力已为上游账号开通；
- 使用 AK/SK 签名，而不是把 AK/SK 当 Bearer Token。

真人认证流程为：

1. 中转站调用 `CreateVisualValidateSession`；
2. 真人本人通过平台一次性验证地址进入 Provider H5 页面并完成认证；
3. callback 的 `resultCode` 仅作为非可信的前端流程和 UX 信号，不能直接把平台 Authorization 置为 `authorized`；
4. 中转站使用短期 `BytedToken` 调用 `GetVisualValidateResult`；
5. 获取 GroupId 后建立平台 Authorization 和 GroupBinding；
6. `BytedToken` 明文在完成换取后立即清除。

`BytedToken` 是短期认证凭证，不是素材组查询参数。平台北向接口不得要求普通客户通过 GET query 提交该 Token。

平台不得把 Provider 原始 H5 地址作为普通 API 数据长期保存或记录。北向返回平台 opaque verification URL，由平台在真人本人打开后短暂跳转到 Provider H5；callback query、访问日志、trace 和错误日志必须清洗 `BytedToken`。平台内部 verification handle 只映射短期加密保存的 `BytedToken`，成功换取 GroupId、明确失败或过期后立即清除。

## 4. 原始 `/api/v1` 接口的标准性判定

### 4.1 视频接口

| 原始接口                                              | 判定                                                             | 平台处置                                                          |
| ----------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| `POST /api/v1/contents/generations/tasks`             | 若声称 ModelArk 官方兼容，则路径版本错误；否则为未验证第三方协议 | 官方兼容使用 `/api/v3`；取得第三方 OpenAPI 后再决定是否增加 alias |
| `GET /api/v1/contents/generations/tasks`              | 同上                                                             | 不直接映射本地 DTO，必须按目标协议转换                            |
| `GET /api/v1/contents/generations/tasks/{task_id}`    | 同上                                                             | 使用平台 ID 查找冻结任务绑定                                      |
| `DELETE /api/v1/contents/generations/tasks/{task_id}` | 同上                                                             | 必须取得该协议的状态和错误合同，不能猜测 DELETE 语义              |

不能仅凭资源名相似就把第三方 `/api/v1` “修正”为 ModelArk。只有在其请求字段、鉴权、分页、状态、响应和错误码均与官方一致时，才能作为无状态 alias 接入 ModelArk handler。

### 4.2 素材、素材组与 H5 接口

| 原始接口                                | 对应能力                      | 官方地址判定                          | 平台处置                                         |
| --------------------------------------- | ----------------------------- | ------------------------------------- | ------------------------------------------------ |
| `POST /api/v1/assets`                   | `CreateAsset`                 | 非 ModelArk 官方 Action 地址          | 平台已有 `/v1/assets`；第三方别名按需实现        |
| `POST /api/v1/assets/query`             | `ListAssets`                  | 第三方 RPC 风格                       | 平台继续使用 `GET /v1/assets`                    |
| `GET /api/v1/assets/{id}`               | `GetAsset`                    | 第三方 REST 风格                      | 使用平台 ID，不暴露上游 ID                       |
| `PUT /api/v1/assets/{id}`               | `UpdateAsset`                 | 第三方 REST 风格                      | 平台受控更新继续使用 PATCH                       |
| `DELETE /api/v1/assets/{id}`            | `DeleteAsset`                 | 第三方 REST 风格                      | 进入平台异步清理和幂等删除                       |
| 素材组 CRUD                             | 对应官方 Group Actions        | 非官方 Action 地址                    | 默认作为平台内部资源；仅为已确认合同公开兼容路由 |
| `POST /api/v1/assets/h5-auth`           | `CreateVisualValidateSession` | 第三方 REST 包装                      | 平台使用 Authorization 资源托管                  |
| `GET /api/v1/assets/groups/byted-token` | `GetVisualValidateResult`     | 第三方 REST 包装，且 query 泄漏风险高 | 不作为平台标准接口                               |

原始接口可作为能力检查表，但是否实现对应能力与是否原样公开路径是两个独立决策。

## 5. 当前实现评估

### 5.1 已注册的北向路由

当前已注册：

```text
POST   /v1/video/generations
GET    /v1/video/generations/:task_id

POST   /v1/videos
GET    /v1/videos
GET    /v1/videos/:task_id
DELETE /v1/videos/:task_id
GET    /v1/videos/:task_id/content
POST   /v1/videos/:video_id/remix

POST   /api/v3/contents/generations/tasks
GET    /api/v3/contents/generations/tasks
GET    /api/v3/contents/generations/tasks/:task_id
DELETE /api/v3/contents/generations/tasks/:task_id

POST   /v1/assets
GET    /v1/assets
GET    /v1/assets/:asset_id
PATCH  /v1/assets/:asset_id
DELETE /v1/assets/:asset_id
GET    /v1/assets/:asset_id/bindings
POST   /v1/assets/:asset_id/migrations

POST   /v1/real-person-authorizations
GET    /v1/real-person-authorizations/:authorization_id
POST   /v1/real-person-authorizations/:authorization_id/retry
POST   /v1/real-person-authorizations/:authorization_id/revoke
```

“路由存在”只证明入口已注册，不能证明请求、响应、状态、分页、错误和所有 Provider 转换均符合 OpenAI 合同。当前 OpenAI Videos 应标记为**部分实现**，直到 Core 合同测试全部通过。

新增 OpenAI Videos Core handler 的创建、详情和列表统一使用模型层 `Task.ToOpenAIVideo()` 投影；当前 `GET /v1/videos/:task_id` 由 `OpenAIVideoGet` 处理，不进入旧 `RelayTaskFetch`。为保持上游兼容和最小入侵，既有 `OpenAIVideoConverter` 接口、Ali、Doubao、Gemini、Hailuo、Jimeng、Kling、Sora、Vertex、Vidu 这 9 个 Provider 转换实现，以及 `RelayTaskFetch` 对 `/v1/videos` 的转换分支完整保留，作为上游兼容接缝。统一投影仅作为新增北向 handler 的主路径，不通过删除上游转换器来消除重复，也不把兼容接缝误写为当前 Core 详情路由的执行路径。内容端点使用受鉴权、带 SSRF 校验、Range 支持和响应头 allowlist 的流式代理。

截至本次复核，OpenAI Videos Core 的路由与主要合同已实现；仍保留“部分实现”标记，是因为真实 Provider 生命周期矩阵和全部可路由 Provider 的统一合同套件尚未在具备真实凭据的环境全部执行。OpenAI Extended 仍明确不在当前完成范围内。

### 5.2 视频任务缺口

已实现：

- OpenAI Core 的创建、列表、详情、DELETE、内容和 Remix 路由；
- ModelArk `/api/v3` 四接口、7 天 UTC 窗口、过滤、分页和 `total/items` DTO；
- `CANCELLED`、`EXPIRED`、独立 `CancellationState`、取消 CAS journal、客户删除墓碑和 `ClientProtocol`；
- `IsActive`、`IsTerminal`、`CanRequestCancellation`、`ShouldRefundOnTerminal` 等集中状态判断，Suno 终态写入也使用 CAS 后再触发退款；
- 静态 Provider lifecycle capabilities；不支持终态删除时返回显式错误，不再把本地隐藏伪装为上游删除成功；
- 所有北向视频任务使用 `AsyncBilling` 持久化门闩，取消、轮询和补偿通过 `ApplyTaskBillingTarget` 的行锁与 settled 状态实现最多一次结算；
- 内容代理和轮询使用冻结的 BaseURL、Key、代理配置和上游任务 ID；渠道被删除或配置发生变化后仍使用任务快照，新北向协议任务缺失快照时 fail closed，不回退渠道当前凭据；
- OpenAI 与 ModelArk 创建错误按各自 envelope 输出，并根据 `LocalError` 区分客户鉴权与 Provider 鉴权；原始上游 body 不再回显，Gemini Key 只走请求头，URL、凭据字段、HTML/JSON 原文和网络错误统一清洗；
- `Idempotency-Key` 支持同请求重放与不同请求 conflict；上游成功先写 recovery journal，再持久化 Task，Task 持久化成功后才执行结算和消费日志；本地失败后重放只完成本地恢复，不再次提交上游；
- JSON 请求摘要规范化，multipart 摘要不受随机 boundary 影响；OpenAI multipart `input_reference` 识别并限制为 20 MB；
- ModelArk `content[]` 按类型、URL、role、媒体数量、duration、resolution、ratio 和 service tier 校验，允许合法的 media-only 请求；
- ModelArk 成功 DTO 返回平台绝对内容代理 URL，并保留 `last_frame_url` 的受鉴权代理投影。

仍未完成或需要外部条件：

- OpenAI Extended 的 Edit、Extend 和 Character；
- 全部真实 Provider 的统一 Core/lifecycle 合同执行；无真实凭据时只能运行确定性的本地合同测试；
- 历史无 `ClientProtocol` 任务只在共享内容代理中保留兼容可见性，不混入 OpenAI 或 ModelArk 列表；
- 非北向旧异步任务仍保留原计费路径，但其终态调用方必须先赢得状态 CAS；本轮没有把视频计费状态机扩张为全站通用工作流。

### 5.3 素材绑定的现有基础

当前素材架构已经具备正确的中转站基础：

- `Asset` 保存平台公开 ID、`UserID` 和 `CreatedByTokenID`；
- `AssetBinding` 保存 `ChannelID`、凭据指纹、上游 profile 和上游资源 ID；
- 远程素材创建时，Asset、Binding、幂等记录和 watchdog 在同一事务建立；
- 视频引用素材时，按用户、渠道、凭据指纹和 active binding 精确解析；
- Task 冻结 `AssetPublicIDs` 和 `AssetBindingIDs`，在途任务不会因后续配置变化漂移；
- 删除通过 operation job 异步执行，保留失败和重试状态。

这套结构已经同时具备 `AssetOwnershipClaim` 和 `AssetGroupOwnershipClaim`。两者都以 Provider 账号指纹、profile、ProviderProject、Region 和上游资源 ID 建立复合唯一约束；相同 Provider 账号作用域内的素材或素材组不能被错误绑定给两个平台用户。

### 5.4 ModelArk 素材适配缺口

现有两个 profile 必须明确区分：

- `official_action_assets`：AK/SK Action 合同，要求 HTTPS BaseURL、Region 和 ProviderProject，固定 `ServiceName=ark`、`Version=2024-01-01`，已实现素材、素材组、列表、删除和真人认证 Actions；
- `ark_assets`：既有 Bearer REST 兼容线，不宣称官方 Action 兼容；未确认的列表和素材组删除端点继续 fail closed，不为能力对称而猜测。

`OfficialActionAdapter` 已使用 opaque verification handle 表达 `BytedToken`，平台仅保存短期密文和不可逆 token hash。短期密文使用独立派生密钥并绑定 Authorization/Session AAD；历史无 AAD 密文只保留兼容解密。换取成功、明确失败、Provider 过期、本地轮询过期、孤儿化或用户撤销时，handle、H5 URL 密文和 token hash 均在状态事务中清除。启用真人授权还要求显式配置稳定的 `CRYPTO_SECRET` 或 `SESSION_SECRET`，避免进程重启后失去解密能力。

本地已有签名向量和 Action 合同测试，并新增凭据门控、只读的真实 `ListAssets` 测试。由于当前评审环境未提供真实 AK/SK，仍不能把“测试入口存在”误写成“真实账号验证已通过”；生产启用必须满足 ADR-0005 的外部门槛。

## 6. 目标架构

### 6.1 北向协议与内部服务分离

```text
OpenAIVideoHandler ─┐
ArkVideoHandler ────┼─> VideoTaskService ─> Task Provider adaptor
LegacyVideoHandler ─┘

PlatformAssetHandler ───────> AssetService ───────> Asset Provider adaptor
PlatformAuthorizationHandler -> AuthorizationService -> Verification adaptor
```

北向 handler 只负责：

- 平台 Key 鉴权；
- 协议请求校验；
- 协议字段转换；
- 协议状态、分页和错误响应转换。

内部 service 负责：

- 所有权与项目范围；
- 渠道选择和资源亲和；
- 平台 ID 与上游 ID 映射；
- 状态转换和并发控制；
- 预扣、结算、退款和补偿；
- 删除、轮询、审计和幂等。

南向 adaptor 负责：

- 上游鉴权和签名；
- 上游请求、响应和错误解析；
- 能力声明；
- 上游取消、删除、轮询和素材 Action。

### 6.2 任务操作不能继续合并为无策略的 CancelOrDelete

内部稳定动作应为：

```text
CreateTask
ListTasks
GetTask
RequestCancellation
DeleteTaskResource
HideTaskRecord
```

协议层按自身合同组合动作：

- ModelArk queued DELETE：`RequestCancellation`；
- ModelArk 终态 DELETE：上游删除后 `HideTaskRecord`；
- OpenAI DELETE：`DeleteTaskResource`，返回 OpenAI 删除对象；
- 平台后台清理：不得伪装成客户协议操作。

如果所选 Provider 不支持取消，平台不得仅在本地标记成功。对于声明严格 ModelArk 兼容的模型，创建阶段就只能选择满足 queued 取消和终态删除合同的渠道；不能先创建到不支持完整生命周期的 Provider，再等客户 DELETE 时才暴露能力缺口。

### 6.3 Provider 能力声明保持静态和轻量

能力由南向 adaptor/profile 以代码级接口或 type assertion 静态声明，渠道配置只能关闭已支持能力，不能把 adaptor 不支持的能力强行打开。当前不建设动态能力注册中心或远程探测系统。

首批能力只覆盖北向合同实际需要：

```text
SupportsContent
SupportsRemix
SupportsCancelQueued
SupportsDeleteTerminal
SupportsAssetReferences
```

北向 handler 在创建或执行对应操作前检查能力；渠道 profile 和实际选中渠道继续冻结到 Task。新增渠道必须通过真实上游测试证明能力声明与行为一致。

### 6.4 状态、协议来源和可见性分离

Task 已具备：

```text
ClientProtocol
ClientDeletedAt
CancellationState
CancellationRequestedAt
CancellationCompletedAt
CancellationError
```

内部执行状态已经补充：

```text
CANCELLED
EXPIRED
```

`CANCEL_REQUESTED` 是平台操作状态，不是 Provider 任务执行状态。取消结果未知时，Task 保留最后确认的 queued/running 等执行状态，并通过 `CancellationState=requested|unknown|confirmed|rejected` 表达取消操作进度。不为此建设通用工作流引擎。

并已提供集中方法：

```text
IsActive
IsTerminal
CanRequestCancellation
```

退款资格不能简化为终态布尔值。计费层按冻结价格、可信 usage 和目标结算额度决定退款或差额，并通过持久化幂等门闩保证最多执行一次。

`ClientProtocol` 冻结任务由 OpenAI、ModelArk 或平台旧协议创建。兼容列表默认只返回由相同北向协议创建的任务：

- 避免把 ModelArk `cancelled/expired` 强行映射为不存在的 OpenAI 状态；
- 避免一个协议的分页和删除语义污染另一个协议；
- 平台控制台使用内部 Task DTO 跨协议显示所有任务，并单独标注 `ClientProtocol`。

OpenAI 来源任务若被平台管理员取消，对 OpenAI 详情和列表投影为 `failed`，并使用 `error.code=cancelled`；不得返回非 OpenAI 状态。

### 6.5 ModelArk 七天列表使用本地账本

`/api/v3` 列表以本地任务账本为查询源，但严格执行：

- 当前 `UserID` 范围；
- `ClientProtocol=modelark_v3`；
- UTC 最近 7 天；
- 官方过滤、分页上限和排序；
- 排除已按 ModelArk 合同删除的任务；
- 返回包含 `total` 和 `items` 的 ModelArk DTO。

上游不可用不应导致历史列表不可用；仍在运行的任务继续由既有轮询系统刷新。

平台控制台可显示更长历史，但必须标明已超出 ModelArk API 查询窗口。首版不增加上游列表全量对账；现有逐任务轮询、失败补偿和必要的人工对账足以作为状态收敛机制。

### 6.6 视频内容只做代理数据面

`GET /v1/videos/{video_id}/content` 继续使用受 Token 或用户鉴权的平台流式代理，不返回上游签名 URL，也不建设平台对象存储或 CDN。

内容代理必须：

- 使用任务冻结的上游账号、profile、查询地址和上游任务 ID，不因渠道后续修改而漂移；
- 对 Provider URL 保持 SSRF 防护；
- 按 allowlist 转发 `Content-Type`、`Content-Length`、`Content-Range`、`Accept-Ranges`、`ETag`、`Last-Modified` 和安全的下载文件名；
- 支持必要的 Range/断点续传，不复制 Cookie、鉴权、内部追踪和其他任意上游响应头；
- 对私有生成内容使用 `private` 或 `no-store` 缓存策略，不设置公共缓存；
- 在 Video DTO 中按已知上游有效期返回 `expires_at`；内容过期时返回目标协议的稳定错误。

平台不承诺超过上游有效期保存视频。需要长期保留的客户应在有效期内下载到自有 OSS/S3/Blob。

### 6.7 北向错误转换

南向错误必须先归一化为平台内部错误分类，再由北向 handler 转为目标协议格式：

| 内部分类               | OpenAI Videos              | ModelArk `/api/v3`           | Platform Assets |
| ---------------------- | -------------------------- | ---------------------------- | --------------- |
| `invalid_request`      | OpenAI error envelope      | ModelArk 参数错误            | 平台稳定错误码  |
| `authentication_error` | OpenAI 鉴权错误             | ModelArk 鉴权错误             | 平台鉴权错误    |
| `upstream_auth_error`  | OpenAI server/upstream 错误 | ModelArk 服务不可用           | 平台上游错误    |
| `permission_denied`    | OpenAI 权限错误             | ModelArk 权限错误             | 平台权限错误    |
| `not_found`            | OpenAI not found           | ModelArk not found           | 平台 not found  |
| `conflict`             | OpenAI invalid/conflict    | ModelArk 状态冲突             | 平台 conflict   |
| `rate_limit`           | OpenAI rate limit          | ModelArk 限流错误             | 平台限流错误    |
| `upstream_unavailable` | OpenAI server/upstream 错误 | ModelArk 服务不可用           | 平台上游错误    |
| `internal_error`       | OpenAI server error        | ModelArk 内部错误             | 平台内部错误    |

普通响应和错误不得包含 Provider Key、AK/SK、`BytedToken`、上游资源 ID、签名 URL、内部 IP、原始请求体或未经清洗的上游错误。平台生成 request ID 用于客户报障；真实上游 request ID 仅进入管理员审计。

`authentication_error` 只表示客户的平台 Key 无效或无权访问；南向 Provider 凭据失效属于平台配置故障，必须归类为 `upstream_auth_error`，不能误导客户更换平台 Key。

### 6.8 取消、删除和计费

上游 API 只定义任务生命周期，不定义中转站客户退款。平台计费规则为：

| 场景                      | 状态处理                             | 计费处理                                               |
| ------------------------- | ------------------------------------ | ------------------------------------------------------ |
| queued 取消且上游确认成功 | CAS 为 `CANCELLED`                   | 结算目标为 0，或按上游已报告的实际消费结算；只执行一次 |
| queued 取消结果未知       | 执行状态不变，取消状态为 `unknown`   | 不提前退款                                             |
| running DELETE 被官方拒绝 | 状态不变                             | 不退款                                                 |
| succeeded 后删除          | 只删除上游资源或客户可见记录         | 不退款                                                 |
| failed 后删除             | 保留失败和退款审计                   | 不得二次退款                                           |
| cancelled 再次 DELETE     | 返回官方错误                         | 不得二次退款                                           |
| expired 后删除            | 删除客户可见记录                     | DELETE 本身不触发退款                                  |

所有 OpenAI、ModelArk 和平台北向视频任务必须进入统一、持久化、原子且可补偿的 billing state。非视频或历史异步任务不因此被强制迁移到新状态机，但其退款调用方必须先赢得任务状态 CAS；旧任务的资金源退款、Token 额度退款和 Task quota 清零也必须在同一数据库事务完成，以 quota 作为幂等门闩。这样既消除补偿扫描重复退款窗口，也避免把局部需求扩张为全站工作流重构。

取消与轮询存在竞争，必须使用 CAS 或独立 operation journal：

1. 记录取消请求；
2. 调用上游；
3. 根据确认结果竞争写入终态；
4. 只有终态写入胜者可以触发计费目标调整；
5. 重试只能重复读取结果，不能重复退款。

任务、消费日志和退款日志不得物理删除。协议 DELETE 使用客户可见墓碑，并保留管理员审计和补偿入口。

视频具体定价维度、预扣上界、可信 usage、差额结算和债务状态继续复用现有异步计费设计及 ADR-0002，本文不建立第二套计价系统。

### 6.9 素材所有权和唯一认领

平台创建素材时继续先建立：

```text
User -> Asset -> AssetBinding -> Channel/Credential/Profile
```

上游返回 ResourceId 后，在事务中建立唯一认领：

```text
AssetOwnershipClaim:
  ProviderAccountFingerprint
  UpstreamProfile
  ProviderProject
  Region
  UpstreamResourceID
  AssetBindingID
  UserID
```

以下组合必须唯一：

```text
(ProviderAccountFingerprint, UpstreamProfile, ProviderProject, Region, UpstreamResourceID)
```

唯一约束以 Provider 账号为作用域：两个不同上游账号出现相同 ResourceID 时可以分别认领；同一账号、profile、ProviderProject 和 Region 内的同一 ResourceID 不能分配给两个平台用户。

自动素材组使用独立的 `AssetGroupOwnershipClaim` 执行同样的复合唯一约束。真人认证返回 GroupId 和自动建组结果都必须先完成认领，再把上游 ID 持久化到 GroupBinding；冲突时整个事务回滚。

认领规则同样适用于 `create_unknown` 后续对账。发生冲突时进入人工处理，不能覆盖原绑定。

上游列表只用于：

- 已绑定资源对账；
- 孤儿检测；
- 删除完成确认；
- ProviderProject、Region 和凭据错误排查。

禁止仅凭名称、GroupId、ProviderProject 或上游列表自动把资源分配给平台用户。数据库灾难恢复依赖备份；存量资源导入必须有原始绑定证明、不可伪造的外部引用或管理员审核。

当前 CredentialFingerprint 包含实际凭据，因而南向 Key 变化按账号身份变化处理；存在活动素材、素材组或真人授权时继续由生命周期栅栏禁止原地修改。本轮不新增 ProviderAccount/CredentialVersion 子系统。未来确需支持同一 Provider 账号内的 AK/SK 轮换时，再引入管理员显式配置的稳定 account scope。

### 6.10 Provider 迁移创建新资源

已创建资源的 Provider、账号、ProviderProject、Region 和 Binding 不可原地修改。迁移必须创建新的平台素材和新的上游资源：

```text
ast_old
  -> Provider A binding，保持不变

ast_new
  -> Provider B binding
  -> supersedes_asset_id = ast_old
```

当前已经具备：

```text
SupersedesAssetID
MigrationBatchID
MigrationReason
```

禁止把旧 `asset_id` 自动重定向到新 Provider。客户必须显式使用新 `asset_id`，旧任务继续使用冻结的旧 Binding。

真人素材迁移到新的 Provider、账号、ProviderProject 或 Region 时，必须重新判断是否需要认证、素材组和用户授权，不能直接复用旧 GroupId。

## 8. 验收标准

### 8.1 OpenAI Videos Core

- 创建请求和 Video 对象符合官方合同；
- 列表支持 `after`、`limit`、`order`，最大 100；
- 返回 `object=list`、`data`、`first_id`、`last_id`、`has_more`；
- 状态只返回 OpenAI 合法枚举；
- 平台取消投影为 `failed` 和 `error.code=cancelled`；
- DELETE 返回 OpenAI 删除响应；
- `prompt`、`input_reference`、multipart、文件或引用对象按当前官方合同验证；
- 内容下载和 Remix 不泄露上游 URL、ID 和错误结构；
- 内容代理使用冻结账号、支持必要 Range、只转发安全响应头且不设置公共缓存；
- 上游内容过期后返回稳定错误，不承诺平台长期保存；
- 未支持的 Extended 能力明确返回稳定错误，不伪装已支持。

### 8.2 ModelArk 视频

- `/api/v3` 四接口方法、路径、字段和错误符合官方文档；
- 列表严格最近 7 天 UTC；
- 分页、过滤以及 `total/items` 响应合同完整；
- queued、running、succeeded、failed、cancelled、expired 全部有合同测试；
- 取消结果未知时不退款、不伪报成功；
- 终态 DELETE 不删除计费和审计；
- 非 ModelArk 来源任务不进入 ModelArk 列表。

### 8.3 素材与真人认证

- 客户全程只使用平台 API Key；
- AK/SK、`BytedToken`、GroupId 和上游资源 ID 不进入普通响应和日志；
- 官方 Action 签名、Region、ProviderProject 和 Version 有真实上游测试；
- `BytedToken` 加密短期保存并在换取结果后清除；
- callback 只作为非可信 UX 信号，不能直接完成授权；
- 同一 Provider 账号作用域内的 ResourceId 只能被一个 OwnershipClaim 认领；
- 素材引用必须匹配用户、渠道、凭据指纹、profile、ProviderProject 和 Region；
- Provider 迁移产生新平台 ID，旧 Binding 不变。

### 8.4 计费、并发和数据库

- 取消、轮询、回调和补偿并发时最多退款一次；
- running 删除失败不退款；
- succeeded 删除不退款；
- failed 删除不重复退款；
- 所有操作幂等且可重试；
- 在途任务继续使用创建时冻结的上游账号；
- SQLite、MySQL 和 PostgreSQL 行为一致。

### 8.5 错误与信息隔离

- OpenAI、ModelArk 和平台素材接口分别返回各自合同规定的错误 envelope；
- 相同内部错误分类在同一北向协议下返回稳定 HTTP 状态和错误码；
- Provider 凭据、内部地址、上游资源 ID、签名 URL 和未经清洗的原始错误不进入普通响应；
- 平台 request ID 对客户可见，上游 request ID 仅进入管理员审计。

未完成对应合同测试前，不得在 API 文档、控制台或发布说明中宣称完整 OpenAI Videos、ModelArk Video 或 ModelArk Asset 兼容。

当前验收已经通过全量 `go test ./...`（默认 SQLite）、视频与素材相关包的定向 race 检查、前端类型检查、前端定向测试和生产构建；`start.sh` 已在非默认端口完成前后端联合启动，`GET /api/status` 和前端首页 smoke test 均通过。此前隔离容器执行的 MySQL 8.4、PostgreSQL 16 门控合同仍然有效，但本次收口未重新拉起数据库容器。这里的 race 结论不等同于全仓 `go test -race ./...`；前端全量 oxlint 仍受上游现存基线错误阻断。真实 BytePlus Action 测试仍由显式环境变量门控；只有以生产候选账号实际运行成功后，才可把该条目标记为已验证。

## 9. 最终实施清单

本轮已经完成：

1. 视频状态、取消、墓碑、协议快照、幂等计费和 lifecycle capability；
2. OpenAI Videos Core 的本地合同；
3. ModelArk `/api/v3` 四接口、列表和生命周期合同；
4. 官方 AK/SK `official_action_assets`、真人认证、素材组和对账；
5. 素材与素材组唯一认领、Provider 迁移；
6. 视频创建幂等、上游成功恢复日志和 multipart/多模态边界；
7. 协议错误隔离、冻结凭据 fail-closed、敏感 token 清理；
8. ADR-0005、MySQL/PostgreSQL/真实 Action gated test harness，并实际通过 MySQL 8.4 与 PostgreSQL 16 合同。

下一阶段包含本地集成收尾、外部门槛和明确延期项：

1. 增加上游 `OpenAIVideoConverter` 兼容链路的直接回归测试；
2. 把 MySQL、PostgreSQL 门控合同接入持续集成；
3. 以生产候选 BytePlus 账号运行只读 Action 合同；
4. 对实际启用 Provider 执行统一 lifecycle 矩阵；
5. 取得第三方 `/api/v1` OpenAPI 后再决定兼容别名；
6. 有明确客户需求后再评估 OpenAI Extended 和平台 webhook。

## 10. 与既有 ADR 的关系

- 北向 `OpenAI Videos` 和 `ModelArk /api/v3` 是客户兼容目标，可以使用官方协议名称；
- 南向通用 profile、运行时常量和业务组件继续遵守 ADR-0001 的供应商中立命名约束；
- `official_action_assets` 表达 Doubao asset adaptor 域内的官方 AK/SK Action 合同，不使用 `ark_action_assets` 作为通用 profile 名称；
- 本文不取代 ADR-0001 的视频上游 profile、任务快照和单主链路决策；
- [ADR-0005](../20-architecture/decisions/0005-官方-action-素材合同与-bearer-兼容边界.md) 已正式记录官方 AK/SK 素材合同、现有 Bearer profile 的兼容边界、真实测试门槛以及不新增公开素材组 API 的决定。
