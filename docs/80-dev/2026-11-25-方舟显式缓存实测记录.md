# 方舟显式缓存实测记录

本记录用于核对开发环境的历史试验。计量候选、约束和收费条件见 [实施方案](2026-11-24-方舟显式前缀缓存接入与小时结算实施方案.md)。

## 渠道 267 真实上游与价格界面验收

用 `./start.sh` 启动并重启非 CN `yuan_gateway_dev` 的隔离 schema。隔离实例的渠道 267 使用现有有效方舟凭据和 Seed 2.1 Lite Model ID，走真实方舟端点。全局强制合同开启，收费测试 Key 无客户合同。默认实例和生产配置均未调整。

- 在模型定价界面保存推理和小时存储表达式。按方舟文本刊例价配置每百万普通输入 ¥0.80、读取命中 ¥0.16、输出 ¥2.70，存储 ¥0.017／百万 token·小时。隔离库使用 6.7 CNY/USD。存储价在第二轮前改为 ¥0.034，随后恢复刊例价。三次保存均在重新打开页面后读回，重启后价格仍在。非线性存储表达式返回 400，已保存价格保留。 [方舟模型价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh&redirect=1)
- 三轮真实调用均返回 200。输入依次为 2,586、5,139、7,692，读取命中依次为 0、2,586、5,139，输出每轮为 1 token。独立复算的推理费用分别为 155、183、214 quota。跨 Key 续接返回 404，同键异参返回 409，重启后同键重放无重复扣费。三轮托管响应均经真实渠道确认删除。
- 保留真实用量和生命周期长度，在隔离库将生命周期平移到已闭账期。重启前保留占款，重启后运行系统结算。三笔存储费按写入时的单价分别结算 3、6、3 quota，推理与存储合计 564 quota。确认钱包、Key、消费日志、用量聚合、月账单总览及三条明细一致，并在浏览器查看钱包、用量和账单。重跑不改变余额或日志。本次计量使用平台保留量，未核对方舟费用中心。
- 原生渠道 265 和 228 的普通 Responses、同模型组外请求、原生续接、SSE 及 Chat Completions 均通过。缺失的插件 GET 资源返回 404。当前真实对照渠道上的 Compact 返回 502，WebSocket 可握手但调用返回 `model_not_found`。隔离实例切到观察模式复测时，这两项结果一致。渠道 267 的真实观察请求只扣 4 quota 推理费，存储预留、扣费和存储日志均为零。已记录 ID 的原生持久响应均已删除，另一个原生对照通过透传设置了到期时间，测试脚本未保存其 ID。

## 收费请求隔离与精度回归

- 用 `./start.sh` 启动非 CN PostgreSQL 的隔离 schema，以渠道 267 和回环模拟上游验收。在全局强制合同开启时，符合资格的无合同 Key 完成两轮 Session。原生请求继续按站点鉴权。同模型组外首轮与普通续接、同模型 SSE、另一模型和 Compact 全部经原生渠道返回成功。
- 余额已用尽的 Key 通过已保存的回执重放历史 Prefix，异参同键返回 `409`。原生流量、重放和拒绝请求均未新增方舟出站。两轮 Session 已删除。
- 两轮推理共扣 313 quota。同一闭合小时的两笔存储明细按各自写入时的单价扣 15、16 quota。钱包、Key、渠道累计、用量和账单合计 344 quota，重跑没有重复扣费。精度回归覆盖舍入前金额为 14.5 及略低于 14.5 quota 的情况。
- SQLite、MySQL 5.7 与 PostgreSQL 的双 Key 并发用例通过。跨整点用例验证发送许可按锁后的小时归属，失败申请回滚资金。

## 本地储存用量与定价回归

以 `./start.sh` 启动非 CN `yuan_gateway_dev` 的隔离 schema，使用渠道 267 的本地测试配置，保持强制 API Key 合同。测试进程通过临时 Go overlay 把方舟传输指向回环地址的模拟上游，使用专用测试凭据。正式代码、原渠道和默认开发实例保持原配置。

- 文本价为每百万 tokens 普通输入 ¥0.80、命中输入 ¥0.16、输出 ¥2.70。隔离库使用 7.3 CNY/USD 和 500,000 quota/USD，试点模型倍率约 0.05479452055，命中倍率 0.2，输出倍率 3.375。合同和执行组倍率均为 1，用于直接核对基准价。参考存储价为 ¥0.017／百万 tokens／小时，对应约 $0.002328767123／百万 tokens／小时，独立验证金额公式。 [方舟模型价格](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh&redirect=1)
- 一轮组和三轮组实际经过本地网关，共四次发送。同键重放走已存回执。四轮推理分别结算 45、45、17、18 quota，合计 125。输入 3,560、命中 1,720、输出 32 tokens，消费日志、钱包、API Key、用量看板与本地账单一致。无合同返回 `403`、跨应用续接返回 `404`、超上下文返回 `400`，均未新增出站或扣费。
- 将四个本地请求的用量及生命周期按两组复制到互不重叠的闭合测试小时，经 Root 回放接口验证。一轮组的同时存活峰值与累计候选均为 808，三轮组分别为 936 和 1,064。第二应用查询两个小时均为零。观察记录的存储预留、扣费和实际小时明细均为零。
- SQLite、MySQL 5.7 与 PostgreSQL 18 的耐久预留、恢复及账单确认回归通过。四个模拟响应均已删除，隔离 schema 和测试进程已经清理。本节结果用于本地验收。

## Session 存储费自动计量与小时结算本地验收

使用 `./start.sh` 启动非 CN `yuan_gateway_dev`，使用 `ark_session_local_<12 位十六进制>` 专用 PostgreSQL schema。渠道 267 保持强制 API Key 合同。仅隔离进程的试点配置启用 `local_session_storage: true`，固定连接回环地址的模拟上游。存储试验价为 $0.002328767123／百万 token·小时，应用存储预留上限为 100 quota。无需 Go overlay、方舟凭据或人工录入小时证据。

| 轮次 | 输入 tokens | 读取命中 | 输出 tokens | 小时用量（token·小时） | 存储 quota |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首轮 | 3,000 | 0 | 8 | 3,008 | 4 |
| 续接 | 4,600 | 3,000 | 8 | 1,608 | 2 |
| 合计 | | | | 4,616 | 6 |

- 模拟上游收到首轮请求时，主库已原子提交发送许可及推理、存储两项预留。首轮存储预留 20 quota。两轮的可信回执落库后，存储预留合计收缩为 6 quota，推理实扣 288 quota。未关账前没有存储消费记录。
- 通过接口确认删除两轮响应后，将隔离库的生命周期时间移到闭合测试小时。资金、原始用量和小时明细均由网关生成。后台任务自动写入两条小时记录并扣费，正式账单明细显示同一小时的单价、用量和金额。钱包、绑定 Key、渠道累计、消费日志和看板一致。存储费未产生额外请求或推理 tokens，两类合计 294 quota。另一把 Key 无法续接，其他 Key 和客户均无该笔账单。
- 同键重放不新增上游请求，异参同键返回 `409`。重跑小时结算及补投保留原有日志事件和金额，余额及看板不重复增加。模型回归另覆盖跨整点两次计量，以及删除状态不确定时只收已确认的小时、到期释放剩余预留。

使用 `./start.sh` 启动非 CN `yuan_gateway_dev` 的独立 PostgreSQL schema，在其中复制渠道 267 的测试配置并启用强制 API Key 合同。Session 连接本地模拟上游。首轮和续接均成功，推理合计 62 quota。对观察 Session 提交存储证据返回 `409`。另建一条归属同一客户和应用的合成历史 Session，冻结下表用量对应的测试价格及 12 quota 预留。价格按 ¥0.017／百万 tokens／小时、7.3 CNY/USD 和 500,000 quota/USD 换算。此次仅核对网关内部账本。

| 已闭合账期（北京时间） | 合成用量（token·小时） | 结算 quota |
| --- | ---: | ---: |
| 2026-11-22 08:00–09:00 | 2,500 | 3 |
| 2026-11-22 09:00–10:00 | 5,000 | 6 |

- Root 通过已有小时证据入口登记用量，后台结算任务按小时顺序处理。第二小时先登记时不会越过第一小时扣款。未闭小时、改写已登记用量和普通客户提交均被拒绝。

- 重提同一证据并重跑结算，通过模拟日志已落地、主库确认丢失再补投，仍只有两条原消费日志和两条对应的看板用量。资金和账单均维持 9 quota。测试后删除模拟响应及临时 schema，并停止隔离实例。
