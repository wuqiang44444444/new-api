# 模型价格展示与线上定价配置优化方案

## 问题与目标

用户发现模型卡片直接展示计费表达式，要求恢复具体价格展示，并进一步要求排查其他价格问题，
提供可用于线上调整的清单。本方案记录本次代码分析、线上只读核对结果和拟实施方案。

2026-09-14 已按本方案完成阶段 B/C 的代码实施与自动化测试（Seedance 公开字段同源装配、任务
USD 单位投影、卡片/单元格/详情的投影化消费、多档范围、图像输出主项、纯固定价主项、不可展开
提示与七语言文案）。同日第二轮评审修复：任务投影支持 tier() 内部条件单价与任意层级嵌套展开
（分辨率矩阵类公式不再不可展开）、详情档位条件按结构化树本地化渲染否定/或/数值比较、固定
附加费与可证明倍率场景纳入卡片范围且固定费在卡片主项可见、显式零价与零组倍率按存在性语义
展示、示例金额装配写时复制以隔离定价缓存、公开定价新增 `basis_price_configured` 缺价存在性
字段并在页面区分缺价与显式合法默认价、详情页不可展开收敛为单一状态提示。线上配置核对、等价
迁移、费率调整与受控发布仍未执行；本文中的相应步骤仍为计划，不表示真实 Provider、实际扣费、
数据库迁移或生产灰度已经通过。

目标：

1. 模型卡片显示可证明的价格、计量单位和必要条件；多档价格不能被无条件展示为第一档价格。
2. Seedance 管理定价与公开价格展示使用同一类型化字段合同，旧价格迁移与展示修复分别验收。
3. 图片模型显示图像输出价格，纯固定费用显示每次请求价格，不能只展示次要的输入价格。
4. 区分已确认的展示缺陷与待确认的线上费率，避免为修页面而改变实际收费。
5. 保持 NEWAPI 原生计费、渠道选择、异步任务冻结事实及资金语义不变。

## 当前实际情况

### 2. 已确认的展示缺陷

#### 2.1 21 个 Seedance 卡片直接显示原式

| 类型 | 模型清单 | 数量 |
| --- | --- | ---: |
| 嵌套条件 Token 定价 | `seedance-2-0`、`seedance-2-0-s`、`seedance-2-0-fast-s` | 3 |
| 嵌套条件 Token 定价 | `seedance-2-5`、`seedance-2-5-f`、`seedance-2-5-m`、`seedance-2-5-s`、`doubao-seedance-2-5-m` | 5 |
| 嵌套条件 Token 定价 | `seedance-2-f` | 1 |
| 条件按秒定价 | `seedance-2-0-m`、`seedance-2-0-t` | 2 |
| 含旧 `size_multiplier` | `seedance-2.0-720p`、`seedance-2.0-sd2-720p`、`seedance-2.0-value-720p` | 3 |
| 含旧 `size_multiplier` | `seedance-2.0-1080p`、`seedance-2.0-value-1080p` | 2 |
| 含旧 `size_multiplier` | `seedance-2.0-4k`、`seedance-2.0-value-4k` | 2 |
| 含旧 `size_multiplier` | `seedance-2.0-fast-720p`、`seedance-2.0-mini-720p`、`seedance-2.0-pro-pi-720p` | 3 |

同形公式的本地展示解析复现结果：

| 公式形态 | 返回结果 | 已确认原因 |
| --- | --- | --- |
| 是否带视频 → 分辨率 → `tier(..., c * 单价)` | `opaque / unsupported_shape` | 条件成立分支内再次出现条件树，现有档位遍历要求该分支直接为 `tier()` |
| 是否带视频 → 分辨率 → 时长乘单价 | `opaque / unsupported_shape` | 同样存在嵌套分支 |
| 单独的 `tier(..., param("_task.duration_seconds") * 单价)` | `opaque / nonlinear_pricing` | 通用 Token 展示解析器不把旧时长调用解释为按秒计量；该原因码不表示业务上一定是非线性价格 |
| 单层条件 → 两个 `tier(..., c * 单价)` | `exact`，两个档位 | 证明不是所有带 `param()` 的条件都会导致 Token 展示解析失败 |

卡片把“表达式非空且没有可展示档位”直接归为特殊表达式并输出原式；这不是价格为空时偶然出现的
浏览器问题，而是当前组件明确实现的降级行为。

#### 2.2 7 个 Seedance 显示了未标注条件的第一档价格

下表均为美元/百万 Token、`randy ×0.87` 分组，数字来自线上详情展示，存在显示精度舍入：

| 模型 | 卡片显示，也是带参考视频价 | 不带参考视频价 |
| --- | ---: | ---: |
| `seedance-2-0-fast`、`seedance-2-0-fast-m` | 2.8065 | 4.7199 |
| `seedance-2-0-mini`、`seedance-2-0-mini-m`、`seedance-2-0-mini-s` | 1.7859 | 2.934 |
| `seedance-2-fast-f` | 2.871 | 4.872 |
| `seedance-2-mini-f` | 1.827 | 3.045 |

这 7 个与前述 21 个不重叠。其详情已显示两档及 `param("_task.has_video_input")` 条件，但卡片只取
第一档，没有“起价”、范围或适用条件。当前非任务用量分支使用 `tiers[0]`，价格范围仅在任务用量
分支计算。不能把这些卡片看起来有数字解释为价格展示正确。

#### 2.3 两个 Nano Banana 卡片遗漏图像输出价格

下表同样为美元/百万 Token、`randy ×0.87` 分组：

| 模型 | 卡片现有输入价 | 详情已有、卡片遗漏的图像输出价 |
| --- | ---: | ---: |
| `nano-banana-2` | 0.435 | 52.2 |
| `nano-banana-2-lite` | 0.2175 | 26.1 |

后端已解析图像输出单价，详情能够展示。卡片仅消费 `primaryEntries`，而普通动态价格只把
`inputPrice`、`outputPrice` 归为主要项，`imageOutputPrice` 被归为次要项后未渲染。
应修正展示项选择，不应为修复卡片把图像输出改写成普通输出计费变量。

### 3. 需要管理员核对的线上配置

以下为疑点清单，不是已确认的费率错误，也不是建议售价。名称相似、公式相同或倍率反常均不能
替代渠道合同、实际模型及管理员定价意图的核验。

| 优先级 | 模型 | 当日观察 | 待核对事项 |
| --- | --- | --- | --- |
| 高 | `seedance-2.0-cmcc` | 视频入口模型展示普通 Token 模式；基础输入/输出均为 $75/1M，当前分组均为 $65.25/1M | 精确客户模型的模式、表达式、渠道类型/协议、预扣预算；当前 Seedance 保存合同要求表达式计费 |
| 高 | `seedream-5-pro` | 图片模型基础输入/输出均为 $75/1M，当前分组均为 $65.25/1M | 是否未配置有效价格、是否配置在其他名称下，以及实际计量应为按次还是按用量 |
| 高 | `deepseek-v4-flash-0731` | 当前分组输入 $0.00522/1M，缓存 $0.261/1M，缓存为输入的 50 倍 | 普通输入、缓存命中价格及缓存倍率是否填反，金额单位是否一致 |
| 高 | `deepseek-v4-pro-0813` | 当前分组输入 $0.03915/1M，缓存 $1.1658/1M，缓存约为输入的 29.78 倍 | 同上；不据此直接给出应调整后的费率 |
| 中 | `seedance-2-0-fast-s` | 公开公式与 `seedance-2-0-s`、`seedance-2-0` 完全一致 | 是否有意采用相同售价，是否发生配置复制遗漏；不由名称推断应使用哪个 Provider 模型 |
| 中 | `gemini-3-pro-image-preview` | 当前分组输出 $10.44/1M；`gemini-3-pro-image` 为 $104.4/1M | 10 倍差异是否是独立定价意图，不能按名称相似直接合并 |

`GetModelRatio()` 找不到配置时返回 `37.5`，现有展示乘以 `2` 后得到 `$75/1M`。因此两个 `$75`
模型符合缺价默认值的表现，但缺少管理配置证据时不能断言一定未配置。若后续证实缺价，应通过
明确的配置存在性向公开展示提供“未配置”状态，不能把所有价格恰好等于 75 的模型统一判为缺价。

### 4. Seedance 新旧合同与公开字段的断点

1. 管理价格快照通过类型化 Seedance 渠道归属加载 `pkg/seedancebilling` 的专属字段，支持 `u()`。
2. 公开价格装配排除了 Seedance 从通用插件模型索引继承用量字段，但未补上其自己的专属字段。
3. 前端仅在存在 `billing_usage_schema` 时进入任务用量展示；字段缺失时进入通用 Token 投影路径。
4. 通用 Token 投影不承担任务 USD 合同；因此直接把线上旧公式换成 `u()` 仍可能显示特殊表达式。

本地调用当前前端函数验证同一条 `tier("base", u("tokens") * 5 / 1000000)`：无字段信息时没有
价格且标记特殊表达式；提供 Token 字段及单位后，正常得到 $5/百万 Token。

线上 28 个表达式计费的 Seedance 均仍可见旧 `_task` 条件或计量；当前仓库的新受理/保存校验拒绝
`c`、`param()` 等旧输入合同。它们需要进行部署版本与配置迁移核对。尚未验证线上实际运行版本，
不能宣称这些模型线上调用已经失败，也不能把历史 Task 的旧冻结表达式当作需要重写的当前配置。

历史提交比较确认：`2023de5d1` 使用前端正则提取档位，`4d46ebb79` 已切换通用金额展示为后端严格
投影。旧方式能抽出部分数字，不代表完整保留所有条件和倍率；本方案不恢复正则猜价。

## 优化方案

### 1. 分离展示修复与费率调整

| 工作项 | 执行原则 | 不得混同的事项 |
| --- | --- | --- |
| 展示修复 | 使用现有价格事实生成完整、带单位的展示 | 不为页面适配修改实际表达式金额、模型映射或渠道资格 |
| 新旧合同迁移 | 按当前类型化合同转换输入和金额单位，证明费用等价 | 不等于修改销售价格，也不重算历史 Task |
| 销售费率调整 | 管理员根据有效业务依据修改精确客户模型价格 | 不把可疑数值当作自动修复依据 |
| 缺价处理 | 以真实配置存在性判定，展示明确未配置状态 | 不从默认金额、模型名称或端点名称猜测费率 |

### 2. 补齐 Seedance 公开用量字段

- 通过已有类型化渠道事实和 `SeedancePricingChannels` 选择当前合同，复用
  `UsageFieldsForProtocol` 与字段交集逻辑；不接回通用插件模型名推断。
- 为公开定价中已经通过可见性过滤的 Seedance 模型补齐自身用量字段和单位。字段名称与业务说明
  可公开，渠道 ID、协议标识、上游模型与连接信息不能随字段投影外泄。
- 管理端、公开价格、合同价格与详情读取同一字段权威源。合同仍只影响既有有效倍率，不建立另一份
  基础表达式或独立单价表。
- 沿用既有跨类型同名冲突处理，不为了显示价格绕过冲突，也不新增请求时选渠或启用模型唯一性校验。
- 不伪造用量示例；只有具备明确输入事实及可复算依据的示例才显示估算费用。

### 3. 在后端形成有明确单位的完整价格展示

拟在已有 `billing_display` 体系内补齐任务用量展示，不新建表达式执行引擎或管理员价格映射配置。
普通 Token 合同继续沿用原生语义；任务 USD 合同必须由调用方传入已经确认的类型化上下文，不能
只靠表达式中是否包含 `u()` 判断单位，尤其不能误判纯固定价。

应支持并验证：

1. 条件成立与条件不成立两侧都可继续嵌套，完整保留前序条件否定、布尔与/或及枚举分支。
2. 同一档位内的线性用量、常数运算、显式零价与已有固定乘除，不丢弃外层倍率或缩放。
3. Token、秒、credit、数量及固定每请求费用分别携带明确单位；不同单位不混合成一个价格区间。
4. 纯固定价作为主要价格展示；“用量费 + 固定费用”同时展示，不能只展示用量部分。
5. 条件倍率只有在完整可证明时纳入范围。不能通过当前时间、假定请求参数或局部抽取给出无条件价格。
6. 原式合法但展示语义无法证明时维持明确的不可展开状态；不能返回错误单价，也不能把局部价冒充
   完整报价。用户页说明价格暂无法展开，原式留在管理员定价/诊断上下文中。

展示只读且可重建，不参与预扣、结算或 Provider exposure。新增任务价格解析主体优先放独立文件，
在现有投影入口保留必要窄接线。改变投影合同语义时协调更新现有版本及消费者；缓存必须区分实际
参与解释的表达式、单位和字段上下文，不能让同一文本在不同单位下复用错误结果。

前端金额展示迁到该已验证投影后，移除当前展示路径中的任务表达式金额解析与本地示例求值。
管理编辑器为生成/编辑表达式所需的逻辑可继续保留，不因函数名相同而误删；明确审查真实调用方，
不新增“后端失败再用前端解析”的双轨逻辑。

本期不为旧 `_task` 当前配置增加运行时兼容。旧快照的履约与日志只读解释沿用已有历史合同；
当前配置按迁移步骤收敛，不能通过新展示解析器扩大新请求允许的旧字段集合。

### 4. 卡片、表格与详情一致展示

| 情况 | 卡片/列表目标 | 详情目标 |
| --- | --- | --- |
| 单档普通 Token | 输入、输出及关键计费项，清晰标注 `/1M tokens` 或用户选择的单位 | 完整单价与分组价格 |
| 多档同单位价格 | 显示范围，明确价格随条件变化；不能无标识使用首档 | 完整条件与每档单价，支持查看各分组有效价格 |
| Seedance 按秒/Token | 依据真实计量展示 `/秒` 或 `/1M tokens` | 分辨率、参考视频等完整条件及对应价格 |
| 图片生成 | 图像输出作为关键项，保留输入等其他收费项 | 图像输入/输出与其他分类不混用 |
| 纯固定费用 | `金额/请求`，包括明确配置的零价 | 对应固定费用及分组计算 |
| 用量加固定费用 | 用量单价与固定附加费同时可见 | 完整计算组成 |
| 缺少配置 | 明确未配置 | 不能用默认 75 冒充已配置售价 |
| 合法但无法证明展示 | 明确不可展开状态，不输出原始表达式 | 保留清楚的业务说明；不以部分金额误导客户 |

复用现有价格摘要、货币格式化、有效组倍率及合同折扣入口，避免各页面单独计算。一次价格展示只
应用一次组倍率/合同折扣，基础价格与当前分组价格分别标明；充值显示换算不改账务价格。
所有新增用户文案及条件说明遵循现有七语言 i18n，不向客户暴露代码字段或协议细节作为主要内容。

### 5. 线上配置核对与迁移顺序

#### 5.1 先建立可核验的配置基线

由有权限的管理员核对部署提交、当前前后端版本和精确客户模型配置；本次 52 个可见模型清单只是
起点，管理员还须覆盖停用模型及当前账号不可见模型。

对 Seedance 记录模式、协议字段合同、表达式类别、预扣预算是否存在及其有效性；对疑似缺价的模型
确认价格字段是否显式配置。使用受控副本与已有只读盘点工具核验，不在本方案或普通日志保存生产配置。

#### 5.2 把 28 个旧表达式模型分成两个迁移批次

- **18 个不含 `size_multiplier` 的模型**：前述 9 个嵌套 Token、2 个条件按秒和 7 个第一档展示模型。
  使用现有迁移工具逐模型预览，只有实际协议字段、输入与旧来源单位均可证明时才进入可应用批次。
  数量划分不代表工具已经对线上配置生成或验证了批次。
- **10 个含 `size_multiplier` 的模型**：转人工核验该字段在实际线上版本及相应请求中的含义。
  当前文档的历史恒为 1 描述不能代替线上版本证据；确认后以新合同支持的业务单位重建价格并做等价
  验证。尤其 `seedance-2.0-pro-pi-720p` 的可见旧式没有时长乘数，不得擅自改成按秒计费。

迁移保持整个费用表达式的金额语义，包括固定项、外层运算和条件阈值。以下仅是简单形式的单位说明：

| 旧合同简单形式 | 新合同等价形式 |
| --- | --- |
| `tier("base", c * 5)` | `tier("base", u("tokens") * 5 / 1000000)` |
| `tier("base", param("_task.duration_seconds") * 145747.800587)` | `tier("base", u("duration_seconds") * 0.145747800587)` |

不能仅替换变量名而保留旧金额尺度；不能对已为 USD 的表达式再次除以一百万；不能逐个修改条件中
的数值阈值来代替对完整金额输出的换算。实际转换优先使用现有工具及原生引擎的等价证明。

命令及适用范围参考[命令清单](../30-engineering/命令清单.md)。现有 `seedance-price-migrate`
仅支持从受控 SQLite 快照只读预览/输出变更批次，不直接写线上数据库；不得假定支持直接连接任意
生产数据库。实际保存通过既有模型价格事务与校验入口执行。

#### 5.3 再确认是否需要改变销售费率

管理员分别确认两个默认价疑点、DeepSeek 缓存倍率、Fast-S 复制疑点及 Gemini 10 倍差异。
给出各模型明确的目标业务计量和售价后再保存；不能把本次公开价格或不同渠道的近似名称当作定价依据。
费率调整批次与等价迁移批次分别记录，不能在一个“迁移成功”结论中掩盖主动调价。

#### 5.4 发布及回退

- 在生产写入前验证新版本实际支持的表达式合同和前后端投影版本；先在受控环境完成展示与金额等价验证。
- 使用维护窗口或已有流量控制避免新旧计价版本与配置错配，不增加长期双读双写或兼容开关。
- 按既有保存事务应用已核验批次，确认缓存失效后读取管理价格、原生公开价格和适用合同价格。
- 在途 Task/attempt 继续使用创建时冻结的表达式、单位和资金事实，不修改历史快照、日志金额或持款状态。
- 回退必须按匹配的应用版本与当前价格配置执行；禁止在新请求已按新合同受理后，仅回写旧式并假定
  历史任务仍可由不支持新冻结合同的旧版本处理。需保留能够履约现存在途任务的版本与冻结事实解释能力。

### 6. 最小改动边界

| 范围 | 拟改动 | 原生文件必要性与上游同步影响 |
| --- | --- | --- |
| Seedance 公开字段装配 | 在 Link 专属新增文件中复用类型化字段源 | `model/pricing.go` 如需修改，只增加补齐响应字段的窄接线；不重排原生价格计算 |
| 后端展示投影 | 在既有体系内新增任务单位与条件树支持 | 不修改原生表达式运行语义；入口变更限明确上下文传入及投影分派，减少上游合并冲突 |
| 响应装配 | 原生/合同价格均附加同源展示事实 | 复用现有附加函数，不重构正在变动的合同折扣实现；不接触路由与资金热路径 |
| 前端价格组件 | 完整消费价格项、范围和固定费用 | 修改当前本地增强的摘要与展示入口，不复制第二套卡片价格算法 |
| 配置核对与迁移 | 使用现有盘点、迁移及保存工具 | 本期不新增价格表、数据库自动迁移、启动扫描或业务请求自动修复 |

项目当前有并行的合同折扣改动，实施前重新确认工作区差异。合同仅折扣的独立方案不是本文的新决策；
本方案只验证与其实际完成状态相匹配的价格结果，不提前假定该改动已部署。

### 7. 验收矩阵

| 边界 | 必须验证的行为 |
| --- | --- |
| 字段归属 | 自定义客户模型按 Seedance 类型化渠道取得自身字段；同名插件、模型映射不得覆盖；公开端与管理端一致 |
| 单位 | 同一系数在 Token 与任务 USD 合同下按明确单位解释；纯常量不依赖 `u()` 字符串识别；不多乘/少除一百万 |
| 条件树 | 条件两侧嵌套、完整前序否定、枚举/布尔、外层倍率；所有相关分支对照原生引擎求值 |
| 边界数值 | 显式零价、固定费、数值阈值、无效/非有限结果、无法证明结构；不得返回局部猜价或静默补零 |
| 线上复现样本 | 覆盖本清单 21 个原式模型的结构类别、7 个首档模型、2 个图片输出模型；已确认配置的样本展示具体价格 |
| 缺价 | 配置缺失与显式合法 $75 区分；不存在价格不能伪装为免费或固定默认售价 |
| 页面 | 卡片、表格、详情、适用合同视图价格一致；显示范围或条件；固定每次费与图像输出可见 |
| 倍率与显示 | 原价、分组、特殊组倍率、合同折扣、零组倍率、充值换算、1K/1M 不重复换算、不改变实际账务 |
| 多语言与布局 | 七语言、长模型名、小屏和条件说明可读；不再用大段代码占据卡片价格区 |
| 迁移 | 对各协议实际声明的相关输入建立有界确定性矩阵；同一输入下旧金额/一百万与新 USD 金额及命中档位一致 |
| 历史任务 | 新配置不重解释已有 Task/attempt；新旧冻结快照各自按冻结单位结算，保持持款和幂等边界 |
| 真实验收 | 管理员核对线上版本与配置；受控请求的预扣、终态金额及账单一致，Provider 金额未知时保持未知 |

回归必须从真实响应装配走到摘要/页面，不能仅在前端测试手填字段或预制投影，从而绕过本次
“管理端有字段、公开端没字段”的缺口。保留有效的不可证明表达式测试，但取消把原式直接展示给客户
作为产品正确性的断言。
