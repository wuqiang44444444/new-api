## 冻结汇率日志修复（本地）

- `service/task_billing.go` 在原有两个表达式快照分支各增加一行 `usd_exchange_rate` 投影，创建、结算和退款日志共用该组装入口。异步快照与其表达式一起覆盖普通计费上下文；即使异步快照汇率缺失，也明确写为 null，避免误用其他快照汇率。
- 不读取当前系统汇率，不改变计费计算、资金状态或快照。没有冻结汇率的历史日志继续明确不可证明；未执行线上数据库补写、部署或新视频生成，限流配置不变。通用日志对 `u()` 表达式原有的展示能力边界不因补齐汇率而改变。
- 原有文件只增加两行必要字段接线，原因是日志投影必须与现有表达式快照选择保持一致；未重排或抽象原计费流程，后续上游合并冲突面限于这两个字段写入点。
- 新增 `service/task_billing_exchange_rate_test.go` 验证日志生成到展示的完整链路，覆盖普通快照、异步快照优先、缺失汇率不回退，以及创建、结算、退款三类事件。当前系统汇率改为 8.8 后，历史冻结值和时间仍保持原样；日志金额与 Task 资金事实不受投影影响。
- 验证通过：新增汇率日志回归、已有冻结汇率展示测试，以及 TaskBillingDelivery、TaskBillingOther、LogTaskConsumption、DelayedCreateLog、TieredSettlement、FrozenExpressionFailure、TerminalTaskBilling 相关服务回归。`task docs:check`、`task ai:check` 与 `git diff --check` 通过。
