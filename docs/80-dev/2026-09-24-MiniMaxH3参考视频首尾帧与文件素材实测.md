# MiniMax H3 参考视频首尾帧与文件素材实测

## 问题与目标

用户要求重新核对“参考视频、首尾帧和素材库暂不开放”的官方依据，并使用现有京东连接实测。
本轮是南向能力验证，不以创建 pending 作为生成成功，不将直连结果等同于标准网关完成验收。

## 当前实际情况

### 官方证据

2026-09-24 重新获取 MiniMax 官方 HTML 与 Markdown 原文：

- [H3 创建接口](https://platform.minimax.cn/docs/api-reference/video-generation-v2-create)：明确支持
  reference_video，最多三段、每段 2–15 秒且总计不超过 15 秒；首帧、尾帧、首尾帧组合属于图生模式，
  与 reference_image/video/audio 模式互斥。图生比例由图片决定，按 adaptive 处理。
- 同一文档的场景列表列出独立尾帧，但 role 子字段仍描述尾帧需与首帧配对，存在文字不一致；
  因此单首帧、单尾帧、首尾帧分别提交，按实际终态判断。
- [官方文件上传](https://platform.minimax.cn/docs/api-reference/file-management-upload)明确声明
  `POST /v1/files/upload`、multipart、`purpose=video_generation_input`：支持生成输入图片、视频、
  音频，得到 file_id 后可在 H3 URL 字段使用 mm_file 引用，有效期七天。
  [官方文件列表](https://platform.minimax.cn/docs/api-reference/file-management-list)同样包含此 purpose。
  此处应纠正之前“只确认已有文件引用、未确认 H3 专用上传用途”的不完整判断；不能由此推定京东已透传。
- 这是官方可复用的临时文件素材机制，未由上述文档证明具有 Seedance 素材组、真人认证或相同租户复用语义。
- [京东海螺文档](https://docs.jdcloud.com/cn/jdaip/hailuo-text-to-video)仍提供统一任务接口，不能将
  MiniMax 官方域名、文件接口或账号作用域直接视为京东合同。

### 测试环境与输入

只读使用原本地数据库渠道 137 的 JD Base URL 与凭据；没有启用或修改渠道、价格、标准插件及业务
数据库。凭据只发给已配置 JD 域名，不发送给 MiniMax 官网。生成请求使用 `/v1/task/submit`，每项
预先记录发送状态、只 POST 一次；结果不明确不重发。任务标识仅保存于本机受保护临时目录，不写入本文。

输入取自前轮已下载的公开样例生成物：两张 1344×768 JPEG（一张室内木桌、一张林岸水面）；
三个不同的连续 2 秒 MP4 片段（H.264/AAC、24 fps、1344×768，合计 6 秒）。参考视频以 Data URL
提交，三段不是三个独立来源。文件上传另使用一个 2.5 秒 MP3 样例；各文件大小远低于官方上限。

### 生成矩阵

四项输出均请求 6 秒、768P，固定 prompt_optimizer=true、watermark=false。

| 测试 | 输入 role / 参数 | 创建 | 终态与下载 |
| --- | --- | --- | --- |
| 单首帧 | first_frame，ratio=adaptive | HTTP 200 / pending | success；下载 HTTP 200，714,651 字节 |
| 单尾帧 | last_frame，ratio=adaptive | HTTP 200 / pending | success；下载 HTTP 200，1,286,109 字节 |
| 首尾帧 | first_frame + last_frame，ratio=adaptive | HTTP 200 / pending | success；下载 HTTP 200，1,213,707 字节 |
| 三参考视频 | 三项 reference_video，ratio=16:9 | HTTP 200 / pending | success；下载 HTTP 200，1,260,425 字节 |

按京东建议等待约十五分钟后，每个任务首次查询均为可信成功；这不是精确生成耗时。
四个下载文件经 ffprobe 检查均为 H.264/AAC、24 fps、1344×768，容器时长 6.583333 秒；
不能把请求的 6 秒、实际容器时长与 credit 混为一谈。每项返回的 video_output 均为 6，
只作为上游 credit 证据，不据此推断货币成本或账单金额。

逐张查看输入图与视频解码后的首帧/最后一帧：单首帧和组合模式的起始画面均对应室内木桌输入；
单尾帧和组合模式的最终画面均对应林岸水面输入。视觉检查确认构图与主体相符，未宣称像素完全相等。
独立尾帧本次实际可用，补足官方文字不一致处的单例证据。三参考视频任务返回 video_input=6，
确认三段共六秒输入被受理并完成生成，但不证明每段都产生可独立辨识的影响。

生成物和脱敏摘要保存在本机忽略目录 `.local-tests/minimax-h3-extended-20260924/`：
`first-frame.mp4`、`last-frame.mp4`、`first-last-frames.mp4`、`three-reference-videos.mp4`、
`summary.json`、`file-api-summary.json` 与 `evidence-manifest.json`。证据清单记录官方原文和输入的
SHA-256；临时签名地址、凭据和 Provider 任务 ID 不纳入该目录或本文。

### 文件素材探测

| 京东请求 | 结果 |
| --- | --- |
| POST /v1/files/upload，purpose=video_generation_input，JPEG | HTTP 400，参数解析失败，无 file_id |
| 同接口/同 purpose，MP4 | HTTP 400，参数解析失败，无 file_id |
| 同接口/同 purpose，MP3 | HTTP 400，参数解析失败，无 file_id |
| GET /v1/files/list?purpose=video_generation_input | HTTP 400，参数解析失败，无文件列表 |
| curl --form 独立客户端对照，JPEG + video_generation_input | HTTP 400，参数解析失败，无 file_id |

较早另按 video_understanding purpose 做过一次视频上传，亦为 HTTP 400，无 file_id；它不是本轮
H3 专用上传结论的依据。未获得合法 file_id，因此没有伪造 ID 触发生成，也没有调用删除或跨账号引用。
独立 curl --form 与手写 multipart 返回一致，不能把失败归咎于手写请求的边界封装。
上述结果只能证明“当前京东地址与凭据按官方文件接口格式调用未通过”；不能证明京东所有产品都没有
素材库，也不能把参数解析失败直接归因为模型不支持。仍需京东提供其文件接口映射与授权说明。

## 优化方案

本轮四项南向验证已完成，参考视频与首尾帧不应再标记为“未经京东验证”。公开 API 文档已补充
实测范围，但现有 minimax-link 1.1.0 标准合同仍未开放这些输入，元数据不提前发布。
后续标准渠道开放仍须同步扩展专属插件、宿主保真校验、媒体计费事实、元数据和公开文档，
并完成标准网关真实链路验收，不得只扩大允许枚举。三参考视频的十五秒总长上界、与其它参考媒体
混合、不同首尾图宽高比等组合未在本轮验证；本轮不改网关架构、插件版本或渠道配置。

文件素材暂不作为已验证能力开放，不创建虚构 AssetGroup 或文件 ID 兼容层。
