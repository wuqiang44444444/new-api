# 美元汇率试算实际验收记录

## 问题与目标

验证 `usd_exchange_rate()` 编辑器修复在真实服务和浏览器中的行为，覆盖客户提供的原式、缓存 Token、
汇率修改、请求模拟及保存后刷新。单元测试通过不替代本次实际验收。

## 当前实际情况

### 环境与范围

- 使用当前工作区编译的完整 Go 应用与前端生产构建，独立临时 SQLite、临时管理员和随机本地端口。
- 使用 Google Chrome headless，实际填写登录、搜索模型、编辑定价和保存；所有试算 HTTP 响应来自
  真实服务，没有模拟计费响应或使用浏览器解释器计算预期金额。
- Provider：本次为管理员只读试算，不调用任何 Provider。对比数据库确认预览没有修改账户额度、
  累计用量、请求计数、Task 或 create attempt 数量。
- 范围仅为本地验收，未部署生产，未修改现有服务或线上数据库；外部 MySQL/PostgreSQL、真实
  Provider 账单与生产灰度不在本次结论内。

### 原式与金额

```text
tier("standard", (p * 12 + c * 36 + cr * 1 + cc * 15) / usd_exchange_rate())
```

浏览器填写的是已归一化计费变量；原生 OpenAI/Anthropic 原始用量仍走原有服务端归一化。

| 场景 | 输入摘要 | 实际 USD | 结果 |
| --- | --- | --- | --- |
| 零用量 | 汇率 7，所有 Token 为 0 | 0 | 通过 |
| 输入 Token | `p=1000000`，汇率 7 | 1.7142857142857144 | 通过 |
| 缓存与输出 | `p=1000000,c=100000,cr=200000,cc=50000,len=1250000`，汇率 7 | 2.364285714285714 | 通过，缓存未重复扣除 |
| OpenAI 原始用量 | `prompt=1000000,completion=100000,cache_read=200000,cache_creation=50000` | 1.9357142857142857 | 通过，原始用量归一化一次 |
| 汇率热更新 | 同一表达式与缓存/输出样本，汇率改为 10 | 1.655 | 通过，编译缓存未固化旧汇率 |
| 浏览器请求规则 | 原式乘 `param("priority") == true ? 2 : 1`，模拟 priority=true | 4.728571428571428 | 通过 |
| HTTP 多个请求倍率 | 同一缓存样本，priority 倍率 2、header 倍率 3 | 14.185714285714283 | 通过 |
| 任务用量 | `tier("task", u("seconds") * 7 / usd_exchange_rate())`，seconds=2、汇率 7 | 2 | 通过，无 Token 百万除数 |
| 图片计费数量 | `tier("image", fixed(0.04)) * image_count`，计费数量 3，模拟 body.n=9 | 0.12 | 通过，数量与原请求字段分离 |

### 实际 HTTP：19 项检查通过

除上表场景外，逐项验证 `0`、`-1`、`NaN`、`+Inf`、非数字与空字符串汇率写入失败后，数据库与当前
有效汇率仍为 10，后续原式继续正常试算。负数、超过 int32 上限与 null Token 样本均失败且不返回
成功金额；匿名调用返回 401；试算前后账户与任务事实不变。

### 实际浏览器：12 项检查通过

覆盖密码登录、原式零费用、百万输入、缓存与长度输入、真实服务端汇率修改、非法汇率拒绝后的连续
试算、请求规则倍率、JSON 错误隐藏旧模拟金额、保存并重新加载后保留函数、简体中文页面、无浏览器
运行时异常，以及观察真实 HTTP 试算响应。

保存流程实际把输出系数 36 修改为 37 并保存，重新加载后核对表达式仍含 `usd_exchange_rate()`；
随后在同一测试模型中恢复原式并再次保存。中英文页面均捕获了真实截图。

脱敏验收产物位于本地忽略目录 `.local-tests/usd-exchange-rate-20261015/`：

- `http-results.json`、`browser-results.json`：检查结果与脱敏后的计费响应摘要；
- `token-estimator-en.png`、`pricing-page-zh.png`：真实页面截图；
- `http-acceptance.py`、`browser-acceptance.cjs`：本次实际操作脚本，运行时认证信息单独保存在临时
  受限目录，不进入验收产物或仓库。

验收结束后，临时实例已停止，临时数据库、账号认证文件与测试二进制已删除；上述脱敏产物保留供复核。

### 本次实际测试发现并修复的问题

首次实际保存 `USDExchangeRate=0` 返回失败，但旧实现已经先写数据库并更新 OptionMap，随后才由
`SetUSDExchangeRate` 将内存计费状态标为无效，导致后续试算失败。上游合并前的通用保存校验原本包含
汇率校验，当前工作区缺少这一接线。

修复在 `model/option.go:validateOptionValue` 恢复调用既有的 `ValidateUSDExchangeRate`，共三行，
同时覆盖单项和批量写入。必要性是阻止错误候选值污染持久化事实及有效运行时状态；业务逻辑继续位于
既有独立汇率文件，未来上游同步只需保留这一持久化前校验接线。非法持久值在启动/同步加载时依旧失败
关闭，没有引入运行时默认汇率或最后成功值回退。

新增 `controller/billing_exchange_rate_option_test.go`，先复现失败，再验证 HTTP 与批量两条写路径，
覆盖数据库、OptionMap、受控汇率读接口以及批量关联字段不应被部分提交的约束。
