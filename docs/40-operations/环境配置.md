# 环境配置

> 本页记录与「对外可达性」直接相关的部署配置：反向代理转发头、`ServerAddress` 的角色，以及本地测试与线上部署的差异。其他环境变量与依赖服务后续按需补充。

## 1. 反向代理必须转发的请求头

当 new-api 部署在反向代理（nginx / CDN / 负载均衡）之后时，以下请求头必须正确转发；否则服务推导出的「调用方回访地址」会落到内网或上游地址，导致客户端拿到不可达链接（典型表现：视频产物归档失败、Passkey Origin 异常、回调地址错误等）。

| 请求头 | 作用 | 示例 |
| --- | --- | --- |
| `X-Forwarded-Proto` | 推导协议（http/https），优先级最高 | `https` |
| `Host`（或 `X-Forwarded-Host`） | 推导调用方实际访问的主机名 | `your-domain.example` |

推导逻辑见 [controller/video_baseurl.go](../../controller/video_baseurl.go) 的 `incomingVideoBaseURL` / `requestScheme`：`scheme` 取 `X-Forwarded-Proto` → `TLS` → `http`；`host` 取 `X-Forwarded-Host` → `Request.Host`。

nginx 参考配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:8100;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host  $host;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
}
```

## 2. ServerAddress 的角色

`ServerAddress`（管理后台「系统设置」→ 服务器地址，存于 `options` 表）：

- **兜底**：当某次响应拿不到请求上下文时，作为对外 URL 前缀的回退值。
- **其他模块自用**：仍被密码重置链接、Midjourney 图片回链、Passkey Origin、支付回调等模块直接使用，需配置为「客户端可访问的对外地址」。

ModelArk V3 范围外原生线路返回的本站内容代理 URL 主机跟随入站请求主机，不取自 `ServerAddress`。
Seedance Link 与 MiniMax 标准视频返回的托管结果 URL 来自对象存储签名配置，不随入站主机或
`ServerAddress` 改写；必须保证对象存储签名地址对客户可达。
任务边界见 [Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)。
本地测试与线上部署无需为视频结果切换 `ServerAddress`，但内容入口的请求主机和对象存储地址
各自仍须满足对外可达要求。

## 3. 本地测试 vs 线上部署

下表只描述仍返回本站内容代理路径的范围外线路；托管线路直接返回对象存储预签名地址。

| 场景 | 调用方访问入口 | 本站内容代理 URL 主机推导结果 |
| --- | --- | --- |
| 本地测试 | 直连 `http://127.0.0.1:8100` | `http://127.0.0.1:8100` |
| 线上（反代正确转发头） | `https://your-domain.example` | `https://your-domain.example` |
| 线上（反代未转发头） | 经反代但无 `X-Forwarded-*` | 内网/上游地址（**不可达，须按 §1 修正反代**） |

## 4. 鉴权提示

视频内容入口 `/v1/videos/:task_id/content` 走 `TokenOrUserAuth`，访问该入口必须携带
`Authorization: Bearer <token>`，与调用任务接口所用 token 一致；不带 token 会得到 401。
Seedance Link 与 MiniMax 标准视频托管就绪后，该入口返回 302 跳转本站 OSS 预签名地址；
下载方应跟随跳转，但不得将平台鉴权转发给对象存储（curl 使用 `--location`，不用 `--location-trusted`）。
授权任务查询已返回 `content.video_url` 时，可直接按完整签名 URL 下载，无需附带平台或 Provider Key。
签名从每次签发起有效 24 小时；对象仍保留且授权有效时重新查询原任务可续签。
范围外原生视频保留原鉴权内容代理语义。交付状态、存储与保留策略见
[Link 视频结果 OSS 托管交付架构](../20-architecture/Link视频结果OSS托管交付架构.md)。

## 5. 用户生命周期邮件

账户创建、密码修改和 API Key 创建通知复用现有 SMTP 配置。管理员先在系统设置的 SMTP Email 区域
配置 Host、Port、Account、From、Token 和传输安全，再在 Operations → Monitoring & Alerts 的
Notification emails 区域分别启用三个事件开关。

三个开关默认关闭。邮件异步发送且失败不重试，也不改变账户、密码或 API Key 操作结果；排查时查看
脱敏系统日志，不记录 SMTP Token 或完整邮件正文。生产启用前至少验证：

1. 开关关闭时不发送；
2. 三个开关分别开启时只发送对应事件；
3. 注册自动创建默认 Token 不额外发送 API Key 邮件；
4. SMTP 不可用时主业务仍成功并产生技术日志。
