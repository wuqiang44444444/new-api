# 环境配置

本页用于配置反向代理、公开地址、邮件告警和错误事件保留期。本地启动流程见
[本地搭建](../30-engineering/本地搭建.md)，请求证据开关与磁盘策略见[业务请求证据运维](11-音视频证据运维手册.md)。

## 1. 反向代理必须转发的请求头

当 new-api 部署在反向代理（nginx / CDN / 负载均衡）之后时，以下请求头必须正确转发；否则服务推导出的「调用方回访地址」会落到内网或上游地址，导致客户端拿到不可达链接（例如原生视频内容入口返回内网地址）。

| 请求头 | 作用 | 示例 |
| --- | --- | --- |
| `X-Forwarded-Proto` | 推导协议（http/https），优先级最高 | `https` |
| `Host`（或 `X-Forwarded-Host`） | 推导调用方实际访问的主机名 | `your-domain.example` |

推导逻辑见 [controller/video_baseurl.go](../../controller/video_baseurl.go) 的 `incomingVideoBaseURL` / `requestScheme`：`scheme` 取 `X-Forwarded-Proto` → `TLS` → `http`；`host` 取 `X-Forwarded-Host` → `Request.Host`。

nginx 参考配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:8100;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host  $host;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
}
```

## 2. ServerAddress 的角色

`ServerAddress`（管理后台「系统设置」→ 服务器地址，存于 `options` 表）：

- **兜底**：当某次响应拿不到请求上下文时，作为对外 URL 前缀的回退值。
- **其他模块自用**：仍被密码重置链接、Midjourney 图片回链、Passkey Origin、支付回调等模块直接使用，需配置为「客户端可访问的对外地址」。

ModelArk V3 范围外原生线路返回的本站内容代理 URL 主机跟随入站请求主机，不取自 `ServerAddress`。
Seedance Link 与 MiniMax 标准视频返回的托管结果 URL 来自对象存储签名配置，不随入站主机或
`ServerAddress` 改写；必须保证对象存储签名地址对客户可达。
任务边界见 [Seedance 专用渠道与 Link 架构](../20-architecture/Seedance专用渠道与Link架构.md)。
本地测试与线上部署无需为视频结果切换 `ServerAddress`，但内容入口的请求主机和对象存储地址
各自仍须满足对外可达要求。

## 3. 本地测试 vs 线上部署

下表只描述仍返回本站内容代理路径的范围外线路；托管线路直接返回对象存储预签名地址。

| 场景 | 调用方访问入口 | 本站内容代理 URL 主机推导结果 |
| --- | --- | --- |
| 本地测试 | 直连 `http://127.0.0.1:8100` | `http://127.0.0.1:8100` |
| 线上（反代正确转发头） | `https://your-domain.example` | `https://your-domain.example` |
| 线上（反代未转发头） | 经反代但无 `X-Forwarded-*` | 内网/上游地址（**不可达，须按 §1 修正反代**） |

## 4. 鉴权提示

视频内容入口 `/v1/videos/:task_id/content` 走 `TokenOrUserAuth`，访问该入口必须携带
`Authorization: Bearer <token>`。API 调用方使用创建任务时所属应用的 API Key。后台可使用有效的
登录访问令牌，仍需满足对应任务权限。未提供有效认证时返回 401。
Seedance Link 与 MiniMax 标准视频托管就绪后，该入口返回 302 跳转本站 OSS 预签名地址；
下载方应跟随跳转，但不得将平台鉴权转发给对象存储（curl 使用 `--location`，不用 `--location-trusted`）。
授权任务查询已返回 `content.video_url` 时，可直接按完整签名 URL 下载，无需附带平台或 Provider Key。
签名从每次签发起有效 24 小时；对象仍保留且授权有效时重新查询原任务可续签。
范围外原生视频保留原鉴权内容代理语义。交付状态、存储与保留策略见
[Link 视频结果 OSS 托管交付架构](../20-architecture/Link视频结果OSS托管交付架构.md)。

## 5. 邮件投递与运维通知

在 **系统设置 → 运维 → 邮件投递** 选择活动通道并保存。每个站点选择一套配置，全部邮件使用同一发件邮箱。

- **SMTP**。填写服务器、端口、发件邮箱和服务端要求的加密方式。需要认证时填写账号和凭据。发件邮箱
  留空时使用 SMTP 账号。升级后可沿用原有 SMTP 配置。
- **Microsoft Graph**。填写租户 ID、应用客户端 ID、客户端密钥和专用发件邮箱。发件邮箱对应的用户
  主体名与 SMTP 地址不同时，补充邮箱的 Microsoft Entra 对象 ID。由租户管理员给应用授予仅限该邮箱的
  Exchange Online `Application Mail.Send` 权限，并检查其他授权是否扩大范围。
  [Exchange Online 应用权限](https://learn.microsoft.com/en-us/exchange/permissions-exo/application-rbac)
- 保存后在同页发送测试邮件，核对实际收件、发件人和主题。提交成功后仍需检查收件箱。Graph 认证或授权
  失败时按脱敏提交状态排查租户、应用身份和邮箱范围。
- 设置报告收件人及 CPU、内存、硬盘阈值。三项阈值默认 85%。运维日报、资源告警、上游低余额提醒和
  渠道不可用告警自动发给这份名单。前一自然日的日报在北京时间 06:00 后汇总完成时发送。
- 欢迎信和显式创建 API Key 通知在「监控与告警」分开启用。管理员建号时填写账户邮箱。用户在登录页
  请求找回，链接有效期 15 分钟，多实例部署使用一致的会话密钥。

检查日报时查看系统任务中的 `error_report` 及其待投递状态。已受理但收件箱未见的邮件，应继续核对
邮箱隔离、退信或邮件服务商投递记录。部署时区分本地实际收件、Microsoft 365 租户实测和性能证据；
未完成的 Graph 真实收件验收见[路线图](../50-planning/路线图.md)第 39 项。
日报与资源告警的 `submission_unknown` 表示收件端可能已受理，系统保留记录供核对。可按日报系统任务结果
或资源告警日志中的投递 ID 定位，投递状态保存在主库的 `error_report_deliveries` 与
`resource_alert_deliveries`，并可对照发信服务和收件箱记录。升级前应先退出旧版本小时邮件调度器。

### 渠道不可用邮件告警

- 渠道告警随网关启动。配置发信通道和报告收件人即可投递。共享 Redis 部署自动按系统实例心跳识别在线成员，
  跨节点窗口支持最多 32 个在线实例。未接入 Redis 时，各节点按自己的观测判定并在告警中标明节点。
- Root 可读 `GET /api/system-info/client-error-log` 的 `channel_alerts` 字段。出现 Redis 缺批或中断时，
  未确认的观测窗口从新批次重新计数。每个节点的 5 秒批次最多汇总 512 个范围，编码后大小上限为
  192 KiB。超限时丢弃整批并计数。邮件判定、首次提交及结果不明可按渠道或投递编号核对后台日志。
  收件验证以测试收件箱为准。

## 6. 错误事件保留期限

`ERROR_EVENTS_RETENTION_DAYS` 默认 30 天，设置 0 关闭自动清理，合法范围 0—3650；负数、超限
或无法解析时使用默认 30 天。部署新版本后会逐轮删除早于该期限的错误事件，请按诊断留存需要配置。

清理复用系统任务，每小时一次；任务列表名称为“错误日志清理”，保留成功/失败、删除数量和固定截止
时间。SQL 每轮最多 20000 行并限 30 秒，积压会留到后续轮次，不能承诺物理存储始终恰好保留 30 天。
只删诊断事件，不删资金日志、Task、审计和请求证据。ClickHouse 为同步 mutation，需先验证目标库负载
与完成状态；客户端超时仍须核查 mutation，不据此判断已取消。详见[API 错误日志架构](../20-architecture/运维-API错误日志架构.md)。
