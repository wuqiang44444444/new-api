# 音视频证据运维手册

## 启用与配置（启动期环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TASK_REQUEST_EVIDENCE_ENABLED` | `true` | 总开关；设为 `false` 显式关闭（关闭时零行为变化、零新增存储） |
| `TASK_REQUEST_EVIDENCE_STORAGE_DIR` | `data/task-request-evidence` | 加密对象目录（独立命名空间，权限 0700/0600） |
| `TASK_REQUEST_EVIDENCE_ENCRYPTION_KEY` | 无（派生） | 64 位 hex（32 字节 AES-256-GCM 密钥）。未配置时从 CRYPTO_SECRET/SESSION_SECRET 派生；两者均未配置时派生自临时密钥，重启后旧正文不可解密并输出告警。生产环境建议显式配置 |
| `TASK_REQUEST_EVIDENCE_MAX_BODY_BYTES` | 8388608 | 北向/南向正文上限；北向超限返回 413，南向处理后超限返回服务错误，不静默截断或归责客户 |
| `TASK_REQUEST_EVIDENCE_MAX_RESPONSE_BYTES` | 33554432 | 上游响应捕获上限；超出部分标记截断，转发不受影响 |
| `TASK_REQUEST_EVIDENCE_WRITE_TIMEOUT_SECONDS` | 5 | 文件写入的有界等待（最多 8 个在途写入）；超时拒绝发送，不强制取消底层文件系统操作 |
| `TASK_REQUEST_EVIDENCE_RETENTION_DAYS` | 0 | 0 = 不自动清理（显式决策）；>0 时每 6 小时清理过期正文，保留索引并标记"正文已过期" |

密钥轮换：更换密钥后旧对象无法解密，读取会返回明确失败；轮换前应先等待保留期清理完成或迁移对象。

## 权限与审计

- 管理员：`GET /api/task_request_evidence?request_id=|task_id=|upstream_request_id=`（索引列表，无正文）、
  `GET /api/task_request_evidence/{id}`（事件时间线 + 脱敏预览，签名 URL 参数已遮盖）。
- Root：`GET /api/task_request_evidence/{id}/events/{event_id}/object`（下载原始对象）。
- 每次查看/下载写入 `task_request_evidence_access_logs`（操作者、对象、动作、范围、时间）。
- 上游诊断列（上游请求 ID 等）仅 Root 视图返回。

任务日志及带平台请求 ID 的消费日志详情中的“请求证据”按需加载索引和时间线；Root 的正文下载继续通过受保护接口并记访问审计。

本地目录必须使用持久化挂载。多实例部署须共享目录及密钥；单机临时目录不能作为跨实例证据存储。

## 故障与处置

- 配置错误保持功能启用并拒绝新请求，不静默降级为无证据发送。
- EOF 未到、读写错误与超限分别记录；发送前正文无法安全记录时拒绝发送。发送后响应片段无法安全
  脱敏时标记正文 unavailable，不由记录故障倒转业务结果。
- 删除对象失败不标记正文过期，下次清理重试。
- 创建正文与轮询正文按唯一事件 ID 分别保存；历史已覆盖对象无法通过升级恢复。

- 证据写入不可用：有限正文的高成本请求在发送前被拒绝（本地不可重试）；
  attempt hold 经既有释放路径退回。查看后端日志 `task request evidence` 相关告警定位存储故障。
- 发送后证据故障：记录标记不完整并告警，业务结果与资金事实不受影响，不做补偿性重发。
- 崩溃窗口：hold/sending 后、发送前崩溃仍按既有 unknown 语义处理；证据缺失不能证明未发送。

### 按请求 ID 定位原因

公开错误码和客户处置口径见[错误与重试](../../web/public/docs-content/zh/concepts/errors.md#请求记录相关错误)。
管理员以平台请求 ID 关联证据时间线和后端净化诊断，读取 `category`、`stage`、`source`、`cause`；
存在 `secondary` 时保留它作为次因，按主因分类定位故障，不把完成更新失败误认为最初失败原因。
容量故障还可查看 `observed` / `limit`；不得为排障输出正文、凭据或完整签名 URL。

- `evidence_configuration_error`：检查启动配置、持久化目录及加密配置。
- `evidence_database_unavailable`：核对索引/事件预留/完成更新阶段及主数据库可用性。
- `evidence_storage_unavailable`、`evidence_store_busy`、`evidence_write_timeout`：核对存储权限、
  写入延迟与在途写入；不通过关闭记录或自动补发创建绕过故障。
- `evidence_processing_failed`：先分清 north/south/response 来源；南向或响应解析失败不能认定
  客户 JSON 错误。
- `evidence_unavailable` 且阶段为 `send_verify`：先核对 attempt/Task 的耐久状态；结果未核实前
  不自动补发、不按状态码退款。
