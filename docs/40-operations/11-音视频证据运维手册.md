# 业务请求证据运维手册

## 启用与配置

| 启动期环境变量 | 默认 | 规则 |
| --- | --- | --- |
| `TASK_REQUEST_EVIDENCE_ENABLED` | `false` | 仅显式 true 开启，独立于 ERROR_LOG_ENABLED |
| `TASK_REQUEST_EVIDENCE_STORAGE_DIR` | `data/task-request-evidence` | 私有持久化目录，目录/文件权限 0700/0600；装配不创建目录 |
| `TASK_REQUEST_EVIDENCE_ENCRYPTION_KEY` | 从宿主稳定密钥派生 | 64 位 hex（32 字节）；建议显式配置，不能输出密钥 |
| `TASK_REQUEST_EVIDENCE_RETENTION_DAYS` | `2` | 仅整数 1～7；作为数据库尚无有效设置时的部署兜底。非法值告警并使用两天 |

Root 在「系统管理 → 日志维护」设置请求证据保留天数。页面显示当前生效值及其来源。
保存成功后当前实例应用数据库值，其它实例在下一轮设置同步后应用，默认间隔 60 秒。
多实例升级时，先升级所有实例，再保存大于两天的保留期，避免旧实例按两天清理。
数据库尚未配置时，各实例应使用一致的环境兜底值。

旧 MAX_BODY_BYTES、MAX_RESPONSE_BYTES、WRITE_TIMEOUT_SECONDS 不再参与配置。普通正文不按大小
截断；只观察业务实际 I/O，不解析或补读正文。已知文件上传、multipart、媒体和文件内容传输不
保存正文；JSON 内嵌 Base64 不扫描。范围和实际接线以[架构文档](../20-architecture/音视频请求证据架构.md)为准。

关闭采集仅停止新增，历史读取、小时清理、磁盘采样和 Root 手动清理继续。稳定密钥与共享持久卷
是跨重启/多实例读取条件；不使用临时宿主密钥。轮换密钥会使原对象无法解密，先按保留期完成回收
或安排独立迁移，不能把解密失败当作对象未保存。

## 容量与高水位

每五秒检查证据目录所在文件系统（目录未建时检查最近存在的父目录）。使用率 **大于 90%** 时：

1. 暂停新证据记录和在途证据写入，业务继续。
2. 立即申请现有证据清理 SystemTask，trigger 为 `disk_pressure`，cutoff 固定为检测时刻前一天。
3. 只删除窗口开始时间早于 cutoff 的证据；等于 cutoff 和一天内数据保留。文件孤儿按修改时间判断。
4. 与手动/定时清理互斥，正在运行的任务不修改范围；持续高位时最多每分钟申请一次。
5. 使用率恢复至 90% 或以下时恢复未来采集；已中止的对象不接续，已关闭的窗口不重开。

“立即”指首次采样发现后提交申请与唤醒 runner，不代表同步删完；已有任务、主节点不可用、慢盘和
删除故障会延迟回收。不要承诺仅凭一天清理就能避免整机满盘：当天大流量和其它业务仍会占盘。

**生产启用条件：** 为证据目录配置有容量上限的专用卷或文件系统配额，与主库、日志库、业务输入/
结果及系统临时区隔离。只有不同目录名不算隔离。在隔离测试卷演练配额耗尽，证明证据停止且主库、
日志与业务对象仍可写；不得在共享生产磁盘直接填满演练。本次代码不自动修改宿主机挂载或配额。
专用卷也不隔离物理 I/O 吞吐，应测业务延迟、队列退让和实际写入量。

监控 active_records、活动对象、buffer_blocks、disk_pressure、written/failed/dropped、清理失败、
最旧积压、根目录磁盘及 inode，同时核对主库证据索引增长。
四个 worker、1024 个 64 KiB 块、512 个活动记录/对象是固定资源预算；不是所有证据内存仅 64 MiB。
持续退让意味着证据可能缺失，应降低负载或扩容，不凭缺证据自动补发、退款或改任务。

## 清理与数据库回收

正常默认滚动保留两天，每小时调度。缩短期限在实例应用后即关闭超期证据的读取，下一轮自动清理回收。
延长时，新窗口使用新期限，已有窗口的较早到期时间仍有效。每个请求/后台周期独立窗口，
长连接每小时滚动。Task 仍在运行不阻止旧窗口回收，其新轮询形成新窗口。

Root 在系统管理 → 日志维护 → 清理请求证据选择 cutoff（默认两天前，支持一天/两天快捷项）。
受理将固定范围申请与任务原子提交；申请立即关闭读取和追加。忙碌时返回当前任务信息；取消/重启
不撤销已提交的关闭范围，后续自动任务继续回收。

回收顺序为：申请关闭 → 分页删对象与加密暂存 → 标记正文回收完成 → 分批删事件 → 删空窗口索引
和关联。关闭且无事件的窗口不保留七天墓碑。访问审计七天，证据清理/监控系统任务历史三十天，
活动及最新调度行保留。其它类型 SystemTask、Task、attempt、资金、Batch 文件、恢复输入与正式
结果不在本次清理范围。

按系统任务结果核对 trigger、cutoff、扫描/成功/失败数、真实删除字节、事件/索引/访问审计删除行数
与数据库积压。释放字节是文件长度，不是即时文件系统空闲空间；打开文件、分配块及在途暂存影响
实际空间。SQLite DELETE 会留下可复用页，不在自动任务 VACUUM，需缩文件时另排维护窗口。

删除失败保留定位并重试；BodyExpired 行仍进入数据库恢复队列。孤儿文件只枚举私有根和数字命名
空间，不跟随符号链接；不会递归删除正式资源。十五分钟健康任务检查连续失败与积压，净化告警写
后端日志和任务结果；未配置邮件/Webhook 接收方时不能宣称通知渠道已接通。

## 授权排障

Admin/Root 先按平台 RequestID 或 TaskID 查询目录，再显式读取单条；普通用户无权访问。目录不读取
全部正文，目录、查看、下载分别发起审计。查询失败显示重试；无记录不能证明业务没有发送。

raw 查看最多前 64 KiB，提示显示受限；下载获取完整已存负载（封装元数据加原字节），服务端流式
解密。点击“格式化 JSON”才对当前完整预览进行只读格式化，保留大整数、重复键和数字写法；
预览截断、非 JSON 或格式化展开过大时显示原文，不改变保存内容。无媒体预览。WS 每方向按十五秒
片段展示多条消息的边界、类型、时间和原始大小，二进制消息仅元数据。片段封存前不可读取，
可见时间受一秒 tick、worker 和存储影响；正常停机、重启或崩溃都可能损失未封存片段及排队证据。
这是已接受的非核心数据边界，不为证据延迟进程退出，不补记或重放业务。
普通业务错误日志不再保存重复正文快照，按 RequestID/TaskID 进入受保护证据；证据未开启或到期
不会由错误日志补存原文。管理渠道测试的显式脱敏诊断与历史读取仍保留。
浏览器支持文件流 API 时直接保存，兼容 Blob 下载可能消耗与文件
大小相近的浏览器内存；大文件优先使用支持流式保存的浏览器或授权流式 HTTP 客户端。不要把凭据
或完整签名 URL 放进命令历史、普通日志或工单。关闭弹窗/切换身份会取消并清除原文缓存。

`missing` 表示对象缺失，`expired` 表示窗口关闭，`decrypt_failed` 表示解密/认证失败，
`storage_unavailable` 表示存储/读取预算不可用，`read_failed` 表示读取故障。明确排除文件的事件
没有正文对象。流式下载后段认证失败会中断传输，不应继续使用不完整下载。

## 一致升级与待验收项

全部实例应使用一致版本与同一命名空间/稳定密钥。新对象用 SIO DARE v2，标记 NEVSIO3；历史
AES-GCM 只读且不重写。旧密文读取上限为 32 MiB + 128 KiB，同时最多一条，且同样受八个总读取
槽位限制；超限/忙时返回 `storage_unavailable`，不影响新格式大正文流式读取或业务请求。旧版本不能读取新格式；回滚时关闭新增采集，并保留能读取和清理新格式的
版本，不双写或清空目录。启动环境从旧 retention=7 调整到 2，重建容器以使变量生效。

本地隔离 MySQL 5.7.44/PostgreSQL 9.6.24 合同已验证。上线前还需生产数据库、共享卷多节点、
连续清理周期、Provider 与业务资金回归、容量
隔离及固定工作量性能对照。本地测试和构建通过不能代替这些验收；未完成时不标为生产已发布。

## 性能验收的关注项

- WebSocket 每连接、方向、十五秒片段生成事件和对象；原消息只增加 32 字节边界头及错误元数据，
  不解析正文。accepted/written 统计片段或事件工作，failed/dropped 是可能重叠的诊断计数，
  不能当作消息数，也不能相加判断排空；排空核对 active_records、活动对象和 buffer_blocks 归零，
  正常保存验收还需逐消息核对原文。持续方向记录
  占用现有 512 活动记录预算，需验证长连接并发与 dropped/failed。
  双向代理通常有四个采集方向，512 不等于能完整采集 512 条连接；相邻片段交接共享同方向预算，
  worker 先封存前段再打开后段。
  事务和文件同步按片段发生，仍可能成为瓶颈；
  inode 也可能先于字节容量耗尽。当前高水位按文件系统字节使用率触发，inode 告警不能当作自动暂停。
- 保留期限制库存时长，每日写入量取决于流量。固定 worker 和缓冲保护采集内存，持续超出吞吐仍会丢证据；
  证据开关关闭时不会新增采集。不要通过扩大无界队列或放开句柄来掩盖退让。
- 业务自身的校验、JSON 转换和正文缓存仍存在；此改造只限制证据增加的开销，不能据此承诺整个网关
  对任意大请求内存恒定或总 CPU 必然下降。
- 本地合成微基准与 CPU 样本见[实施记录](../99-archive/2026/10/2026-10-31-业务请求证据全覆盖与低开销存储实施方案.md)。
  请求处理延迟、worker 排空耗时、CPU 与累计分配须分别报告；B/op 不是峰值 RSS。
- 完整程序、真实 Provider 与长连接采样见[验收记录](../99-archive/2026/10/2026-10-31-请求证据真实调用与WebSocket采样验收.md)。
  用数据库备份启动本地实例前，必须先在副本禁用 SMTP、错误报告及其它通知入口，清空历史待投递
  队列、移除历史用户通知配置并关闭自动渠道测试；同时排除历史待执行业务任务。只改端口与数据库
  路径不能隔离后台外发副作用。副本应轮换会话密钥、Root 访问凭据并停用历史用户及 Token，只保留
  测试身份；源库不执行这些操作。

OpenAI Realtime 两处逐消息运行诊断已使用现有 Debug 日志；默认关闭调试时不输出这两类行，
错误、最终用量与消费记录继续保留。十五秒片段延长可读等待和停机/故障未封存损失窗口；正文仍流式写入，
不在内存中积攒十五秒消息。URL JSON 不触发证据层媒体下载，业务托管和测试样片独立于证据。

清理目录及单窗口文件按 256 项迭代；存活目录按批量主库查询过滤。此举限制扫描内存并减少查库次数，
不限制总文件数或清理耗时；大量保留数据仍须评估主库与磁盘竞争。清理与在途写入并发时，已打开
暂存句柄可能延迟空间释放，但关闭窗口不能重新发布对象；不为立即回收空间增加逐块数据库检查。
