# 音视频证据运维手册

## 启用与配置（启动期环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TASK_REQUEST_EVIDENCE_ENABLED` | `false` | 唯一新增采集总开关；只有显式 `true` 开启。未配置或其它值都不采集，单独提供加密密钥不启用。显式开启后仅采集已登记媒体操作；早期方案的 `TASK_REQUEST_EVIDENCE_TYPES` 已移除，不提供 `all` 别名 |
| `TASK_REQUEST_EVIDENCE_STORAGE_DIR` | `data/task-request-evidence` | 加密对象目录（独立命名空间，权限 0700/0600）；装配不创建目录 |
| `TASK_REQUEST_EVIDENCE_ENCRYPTION_KEY` | 无（派生） | 64 位 hex（32 字节 AES-256-GCM 密钥）。未配置时从 CRYPTO_SECRET/SESSION_SECRET 派生；生产环境建议显式配置。密钥是加密参数，不产生采集资格 |
| `TASK_REQUEST_EVIDENCE_MAX_BODY_BYTES` | 8388608 | 北向/南向正文上限；北向超限返回 413，南向处理后超限返回服务错误，不静默截断或归责客户 |
| `TASK_REQUEST_EVIDENCE_MAX_RESPONSE_BYTES` | 33554432 | 上游响应捕获上限；超出部分标记截断，转发不受影响 |
| `TASK_REQUEST_EVIDENCE_WRITE_TIMEOUT_SECONDS` | 5 | 文件写入的有界等待（最多 8 个在途写入）；超时拒绝发送，不强制取消底层文件系统操作 |
| `TASK_REQUEST_EVIDENCE_RETENTION_DAYS` | `7` | 只允许整数 1～7；正文与事件明细滚动保留天数，正文回收后物理删除明细，索引七天到期后删除。不再支持 `0` 永久保留或超过七天 |

密钥轮换：更换密钥后旧对象无法解密，读取会返回明确失败；轮换前应先等待保留期清理完成或迁移对象。

## 部署示例与升级

启用请求证据时只新增/调整以下环境项（合并进原有 `environment`，保留现有稳定密钥与数据挂载）：

```yaml
services:
  newapi:
    environment:
      - TASK_REQUEST_EVIDENCE_ENABLED=true
      - TASK_REQUEST_EVIDENCE_RETENTION_DAYS=7
```

`ERROR_LOG_ENABLED` 继续独立控制错误日志，不控制正文采集。环境变量在启动期加载，仅执行
restart 不会更新容器环境；从默认开启的旧版本升级时，必须重建服务并让全部实例升级一致，避免旧
实例继续按旧行为全量落盘。暂不启用时不配置启用变量即可默认关闭；保留历史存储配置供读取与清理。

## 权限与审计

- 管理员：`GET /api/task_request_evidence?request_id=|task_id=|upstream_request_id=`（索引列表，无正文）、
  `GET /api/task_request_evidence/{id}`（事件时间线 + 脱敏预览，签名 URL 参数已遮盖）。
- Root：`GET /api/task_request_evidence/{id}/events/{event_id}/object`（下载原始对象）。
- 每次查看/下载写入 `task_request_evidence_access_logs`（操作者、对象、动作、范围、时间）。
- 上游诊断列（上游请求 ID 等）仅 Root 视图返回。

任务日志及带平台请求 ID 的消费日志详情中的“请求证据”按需加载索引和时间线；Root 的正文下载继续通过受保护接口并记访问审计。

### 排障时查看实际 HTTP 交换

错误日志详情中的“请求证据”按任务 ID 或请求 ID 关联既有证据，分别查看客户原始业务请求、最终南向
请求、上游创建响应、历次轮询响应与客户交付。时间线展示实际 HTTP 状态、方法、脱敏目标、内容类型、
采集时间和诊断信息；响应头与请求头分别标识，凭据以占位符表示。

采集不按 HTTP 成功或失败筛选。空响应也保存已收到的状态与元数据；响应与传输错误同时存在时保留
已观察到的状态和正文，同时标记采集不完整。JSON 凭据脱敏保留大整数 ID、显式零值和原始数值表示。
发送后正文不能安全脱敏或存储失败时，事件保留实际状态、字节数和 `capture_failure` 的类别、阶段与来源。
超限、读失败、存储不可用、正文过期不等于“请求没有发生”，不得据此重发任务。

后台任务失败事件本身没有客户 HTTP 响应；其“无客户 HTTP 状态”不能替代证据中的创建和轮询状态。
Provider 在错误文字中描述的更下游状态只是 Provider 报告，不能填为本站实际收到的 HTTP 状态。
未采集、已过期或历史被覆盖的正文不能通过升级补造；以上行为只覆盖已接入音视频证据的路径。

本地目录必须使用持久化挂载。多实例部署须共享目录及密钥；单机临时目录不能作为跨实例证据存储。

## 故障与处置

- 配置错误保持功能启用并拒绝新请求，不静默降级为无证据发送。
- EOF 未到、读写错误与超限分别记录；发送前正文无法安全记录时拒绝发送。发送后响应片段无法安全
  脱敏时标记正文 unavailable，不由记录故障倒转业务结果。
- 删除对象失败不标记正文过期，下次清理重试。
- 创建正文与轮询正文按唯一事件 ID 分别保存；历史已覆盖对象无法通过升级恢复。

- 证据写入不可用：有限正文的高成本请求在发送前被拒绝（本地不可重试）；
  attempt hold 经既有释放路径退回。查看后端日志 `task request evidence` 相关告警定位存储故障。
- 发送后证据故障：记录标记不完整并告警，业务结果与资金事实不受影响，不做补偿性重发。
- 崩溃窗口：hold/sending 后、发送前崩溃仍按既有 unknown 语义处理；证据缺失不能证明未发送。

### 按请求 ID 定位原因

公开错误码和客户处置口径见[错误与重试](../../web/public/docs-content/zh/concepts/errors.md#请求记录相关错误)。
管理员以平台请求 ID 关联证据时间线和后端净化诊断，读取 `category`、`stage`、`source`、`cause`；
存在 `secondary` 时保留它作为次因，按主因分类定位故障，不把完成更新失败误认为最初失败原因。
容量故障还可查看 `observed` / `limit`；不得为排障输出正文、凭据或完整签名 URL。

- `evidence_configuration_error`：检查启动配置、持久化目录及加密配置。
- `evidence_database_unavailable`：核对索引/事件预留/完成更新阶段及主数据库可用性。
- `evidence_storage_unavailable`、`evidence_store_busy`、`evidence_write_timeout`：核对存储权限、
  写入延迟与在途写入；不通过关闭记录或自动补发创建绕过故障。
- `evidence_processing_failed`：先分清 north/south/response 来源；南向或响应解析失败不能认定
  客户 JSON 错误。
- `evidence_unavailable` 且阶段为 `send_verify`：先核对 attempt/Task 的耐久状态；结果未核实前
  不自动补发、不按状态码退款。

## 验收边界

媒体开关覆盖已接入的实际媒体交换，不保证任意 WebSocket 帧或未绑定后台 context 的南向交换。
当前覆盖矩阵和明确缺口见[请求证据架构](../20-architecture/音视频请求证据架构.md#覆盖矩阵与验证边界)。


## 媒体请求证据与手动清理

显式开启后仅采集已登记图片、音频、视频和素材操作，覆盖已接入的后台媒体 Task 执行。
普通聊天、Responses、Gemini 通用多模态、Embedding/Rerank、Batch/通用文件排除；成功、失败
和本地拒绝均留证。管理面和自身查询维护不产生正文；Link 素材 source URL 不留存。
覆盖边界与缺口见架构文档。

任务受理路径上任务证据会话持有同一交换的证据时，通用观察器不重复落盘；每次实际 HTTP 交换只
保留一份阶段证据。关闭采集（`TASK_REQUEST_EVIDENCE_ENABLED=false`）只停止新增正文；期限内
历史证据继续可读，存量正文仍由每小时系统任务按七天政策自动回收。部署时核对按阶段新增字节、
磁盘/inode、最旧未清理到期时间与清理失败计数；连续失败或超过两个调度周期没有成功执行说明
清理停摆，需人工介入。

Root 手动清理：系统管理 → 日志维护 →「清理请求证据」。选择截止时间（默认七天前，提供
24 小时/7 天快捷项），确认后创建后台任务；截止时间与操作者持久化在任务上，执行与重试始终
使用原有边界。受理时把任务与当前截止范围的清理申请一并提交；候选严格为索引创建时间早于
截止点，等于截止点保留，不混入其它自然到期记录。申请立即关闭读取与追加；即使任务在扫描前
取消或重启，已接受的范围仍由后续自动任务重试。已有清理任务运行时提交返回忙碌及
当前任务信息；页面展示扫描/清理/删除/失败计数与真实释放字节，中英文均完整。

事件 `detail` 保留头/query 摘要、`eof`、`truncated`、`body_format_invalid`、`io_failed`、
`body_not_read` 和 `capture_failure`。对象写入在既有期限内等待槽位，真实故障明确标记。
对象存储不可用时不改变普通 API 结果。破损 JSON/SSE 可保留脱敏前缀，破损 multipart 无法安全
脱敏时正文不可用；二进制经受控对象接口读取。素材 source URL 不留存。

普通请求只观察实际读取。鉴权或校验拒绝先交付响应，再在 100ms 读期限内补采输入；超过期限的
正文保留已有前缀并标记 `io_failed`，尚未到达的数据不补造。HTTP server 必须使用已接入的
`APIRequestEvidenceHTTPHandler`，以提供 Gin 外层的标准读期限控制。证据观察必须在 Recovery
外层收尾；头/query 的签名 URL 在持久化前脱敏，不依赖页面预览隐藏。后台插件交换只留一份实际
请求/响应，保持真实内容类型。

清理运行结果查看系统任务历史（`task_request_evidence_retention`）：每轮含开始/结束时间、触发
方式与清理截止、扫描数、成功清理索引数、成功删除文件数、移除对象字节、对象已不存在数、失败数
与未归属文件数量，以及删除事件/索引/访问审计/证据任务历史行数和数据库失败数。字节按实际被移除对象的文件长度统计；缺失对象不计入字节。文件系统空闲空间
还受分配块、打开的文件和在途暂存影响，必须单独核对，不将此计数冒充即时磁盘可用空间。删除失败不标记正文过期，下一轮自动重试；目录不可用
或无存储句柄按失败报告，不伪装清理成功。

## 清理监控与异常残留

日志维护只向 Root 显示证据清理。确认窗口说明截止时间、浏览器时区、包含全部类型的历史证据及不可恢复性；
后台失败仍可查看本轮实际删除结果。刷新恢复最近任务；系统任务历史可按“请求证据清理”筛选并
展开详情，按“证据清理监控”查看独立健康检查。

独立监控每十五分钟运行，即使正文采集关闭仍继续。检查连续两次失败、超过两小时无成功及积压；
同时观察证据根目录所在文件系统的可用字节/inode。磁盘使用率使用既有磁盘告警阈值，inode 使用率
达到 95% 时告警；inode 不可用显示未知。告警写后端 warning 日志和系统任务结果，部署方可将这些
净化类别接入现有日志告警平台；这不代表已配置邮件、Webhook 或生产告警接收渠道。

`directory_cleanup_failed` 与非零未归属文件数说明目录还有未知文件或未完成的暂存。系统保留它们，
不猜测删除；先确认所有实例已停止相应写入，再按文件系统副本盘点。旧版升级后的 NULL 申请标记
按未申请处理，下一次申请会确认实际落库；不要自行将未成功删除的正文标记完成。

最终对象链接在实际 worker 中与主库清理申请互斥；调用方超时不能绕过这一步。没有共享持久卷的
多个实例不能据此获得跨节点物理存储一致性，部署仍须共享同一正文命名空间和稳定密钥。真实流量
容量、连续周期、文件消失、目录回收及磁盘/inode 余量仍需按生产副本和灰度验收。

## 数据库回收与媒体范围

采集仅纳入已登记图片生成/编辑、音频转写/翻译/TTS/音乐生成、视频及素材操作。普通聊天、
Responses/Gemini 通用多模态、Embedding/Rerank、Batch/通用文件和模型列表排除。历史非媒体
数据仍按到期策略回收，升级不默认提前删除七天内历史证据。

正文和事件明细默认七天（正文配置可缩至 1–7 天），索引七天，访问审计从访问起七天。
手动提前清理会删除正文和事件明细，最小关闭索引保留到七天，防止活动任务恢复取证。
后台复用同一 Task 证据与可信创建时间，不因轮询/查询或索引删除续期；无可靠时间跳过取证。

删除严格为申请关闭 → 分页删对象 → 标记正文完成 → 分批删事件 → 到期删索引。
数据库回收失败不会恢复读取，BodyExpired 行继续进入数据库回收队列。历史 BodyExpired 残留
文件和孤儿事件先删对象再删行；未知文件保留定位依据并告警。所有实例必须升级一致。

证据清理/监控 SystemTask 历史三十天回收，活动与最新调度行保留；报告中其它约七千条/天
系统任务历史需独立治理，不通过本次证据期限通删其它类型。Root 页面显示数据库待回收数量、
最老时间及删除行数；行数不等于物理空间。SQLite 删除后先复用 freelist，缩小数据库文件另行
安排维护窗口，不在小时任务内 VACUUM。生产验证要观察新增/删除速度、积压与数据库页复用，
不能只观察文件目录下降。
