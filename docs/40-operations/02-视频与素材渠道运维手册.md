# 02 视频与素材渠道运维手册

> 当前代码已实现发送前 durable attempt、`PROVIDER_CONTRACT_FAILURE`、authorization
> reservation、内容授权回查、exposure 指标/告警/公开 SKU 熔断、人工审计恢复和版本化
> `VideoSKUCapability`。生产启用仍必须完成本文的上游实测、价格审批、阈值审批与内部灰度；
> 代码能力不等于渠道已经上线。

## 1. 当前范围

当前 Seedance 公开模型：

```text
seedance-byteplus
doubao-seedance-2-0-260128
seedance-2-0-oversea
seedance-2.0-standard
seedance-2.0-fast
```

JSON Video omni-reference profile 另外登记以下固定分辨率公开 SKU；只有配置了能力等价渠道、
模型映射、价格和分组 Ability 后才可调用：

```text
seedance-2.0-standard-720p
seedance-2.0-standard-1080p
seedance-2.0-value-720p
seedance-2.0-value-1080p
seedance-2.0-value-4k
```

Seedance Link 客户端创建入口固定为：

```text
POST /api/v3/contents/generations/tasks
```

rc23 原生 OpenAI Videos 使用 `POST /v1/videos`，旧版兼容创建使用
`POST /v1/video/generations`。`sora-2`、`sora-2-pro` 等原生模型不得登记为 Link SKU；现有
Seedance、Kling、即梦 Link SKU 也不得配置到原生入口。

### 1.1 OpenAI/Sora 原生渠道上线门禁

恢复代码不会自动启用渠道或 Ability。上线前必须：

1. 新建或复核 Sora/OpenAI 视频渠道，模型只填写上游实际支持的原生模型；
2. 配置模型价格、分组和异步任务预扣 Token 上界；
3. 用测试分组分别验证 JSON、multipart、查询、内容下载和 Remix；
4. 验证 Provider 创建拒绝与超时语义。请求字节发送后的未确认结果必须进入
   `create_outcome_unknown`，不得自动退款、换渠道或重发；
5. 如开放 `asset://ast_*`，分别验证同应用所有权、撤权阻断、过期源、模型绑定和多素材渠道交集；
6. 确认任务与 create attempt 不含 Link implementation/capability 快照，且 Link SKU 经原生入口
   返回 `link_sku_contract_mismatch`。

## 2. 新建视频渠道

进入“渠道管理”，新建 `DoubaoVideo` 渠道。

| 线路 | 视频上游方案 | Base URL | 创建路径 | 查询路径 | 模型映射 |
| --- | --- | --- | --- | --- | --- |
| BytePlus 官方 | `official` | `https://ark.ap-southeast.bytepluses.com` | 系统内置 | 系统内置 | `seedance-byteplus -> Endpoint ID` |
| TokenSave doubao Seedance 2.0 | `third_party_relay` | `https://tokensave.pro` | `/v1/media/generations` | `/v1/media/tasks/{task_id}` | 无，公开模型与上游模型均为 `doubao-seedance-2-0-260128` |
| Moxing 海外版 | `third_party_relay` | `https://www.moxing.pro` | `/v1/media/generations` | `/v1/media/tasks/{task_id}` | `seedance-2-0-oversea -> seedance-2-0-oversea` |
| Moxing 海外官Key真人素材 | `third_party_reverse_proxy` | `https://tokensave.pro` | `/v1/ark/media/generations` | `/v1/ark/media/tasks/{task_id}` | `seedance-2-0-oversea -> dreamina-seedance-2-0-260128` |
| JSON Video omni-reference | `third_party_json_video_omni_reference` | 供应商 HTTPS 地址 | 供应商创建路径 | 含 `{task_id}` 的查询模板 | 固定分辨率公开 SKU -> 受控上游模型 |
| FunCloud Standard | `third_party_funcloud_seedance_v2` | `https://mm-internal-cn.leonecloud.com` | `/api/v2/open/aigc/seedance2-0` | `/api/v2/open/aigc/{task_id}` | 无；仅 `seedance-2.0-standard` |
| FunCloud Fast | `third_party_funcloud_seedance_v2` | `https://mm-internal-cn.leonecloud.com` | `/api/v2/open/aigc/seedance2-0-fast` | `/api/v2/open/aigc/{task_id}` | 无；仅 `seedance-2.0-fast` |

官方线路不要填写创建和查询路径。第三方路径必须以单个 `/` 开头，查询路径必须且只能包含一个 `{task_id}`。

`doubao-seedance-2-0-260128` 当前使用 TokenSave V2 relay 合同。不得把它配置为
`third_party_reverse_proxy`，不得使用 `/v1/ark/*`，也不得映射为 `dreamina-seedance-2-0-260128`；
这些配置属于 `seedance-2-0-oversea` 的 Ark 真人素材线路，会在 `doubao-seedance-2-0-260128` 发送前被能力门禁拒绝。`seedance-2-0-oversea` 同时登记 relay 与 reverse-proxy 实现能力；只有 reverse-proxy 渠道可以配对 `ark_assets` 并消费真人素材。

配置要求：

- `Models` 填客户端公开模型名；
- 模型映射方向为“公开模型名 → 上游模型名”；
- API Key 填上游 Key，不填本站用户令牌；
- Base URL 只填根地址，不追加任务路径；
- `service_tier=flex` 默认关闭；只有上游合同和价格已单独验收时才开启渠道允许开关；
- 先加入测试分组，验收后再加入生产分组。

TokenSave 当前模型页按秒列价。正式生产开放前必须用真实创建、轮询结果与账单核对各分辨率、
输入类型和是否包含视频输入的计价；仅链路测试通过不能视为价格验收完成。

FunCloud 必须使用两个独立供应商中立 SKU。不得把 FunCloud profile 加入
`doubao-seedance-2-0-260128` 或五个飞彩固定分辨率 SKU，也不得用 FunCloud 报价覆盖这些既有
模型。Standard 发布 480p/720p/1080p、4～15 秒显式时长；Fast 发布 480p/720p、4～15 秒显式
时长；二者都不接受智能时长 `-1`。基础价格按[01 计费与分组运维手册](01-计费与分组运维手册.md)
的 FunCloud 原价模板配置。

本地数据库中的 Standard/Fast 渠道和 Ability 当前保持禁用；配置存在只表示代码与运维事实已
落库。完成真实渠道创建、轮询、素材和账单验收前，不得把渠道或 Ability 改为启用。

发送前 durable attempt 是所有已发布客户端视频创建合同的安全不变量，不是可热变更的灰度开关。
OpenAI Videos、旧版平台视频、ModelArk、Kling 和即梦创建请求在任何上游 POST 前都会原子建立 `sending + held`；Ability、分组
和渠道权重只控制哪些流量可进入，不能让已发布视频合同回退到无 attempt 的旧路径。在途 attempt
始终由共享 scheduler 闭合。

请求字节已经发送后，只有已登记且经过 Provider 合同验证的 `HTTP status + error.code` 精确
组合才能作为确定拒绝释放 hold。当前飞彩没有登记此类组合，因此 400、401、403、429、其他
4xx/5xx、意外 2xx/3xx 和传输异常都按 `create_outcome_unknown` 处置，不自动重发或退款。

TokenSave doubao 线路已用真实响应验证 `HTTP 403 + user_quota_insufficient` 表示 Provider 账户
余额不足且任务未创建。该精确组合按终态拒绝处理：释放预扣、不换渠道、不重试，并向客户端保留
上游 403 语义；其他未登记组合仍然 fail closed 为 `create_outcome_unknown`。

保存或启用 Ability 时会使用 `VideoSKUCapability` 校验渠道类型与 profile。不等价绑定会直接
拒绝发布，不能通过先禁用、保存后再启用的方式绕过。

五个固定分辨率 Seedance 2.0 SKU 的可机器读公开约束位于 OpenAPI
`ModelArkVideoCreateRequest.x-fixed-seedance-2-capability`。上线审批时可用它核对模型、分辨率、
时长、画幅和媒体上限；代码一致性测试会将该投影与 `VideoSKUCapability` 逐值比较。
这只证明公开合同与代码一致，不能代替 Provider 真实创建、轮询、媒体组合、内容下载和账单验收。

纯视频渠道可使用多 Key；启用素材能力的渠道必须是单 Key。多上游账号优先拆成多个渠道。

## 3. 启用素材能力

### 3.1 Profile 配对

| 视频上游方案 | 素材上游方案 | 是否参与视频素材路由 |
| --- | --- | --- |
| `official` | `official_action_assets` | 是 |
| `third_party_reverse_proxy` | `ark_assets` | 是 |
| `third_party_relay` | `relay_assets` | 是 |
| `third_party_funcloud_seedance_v2` | `none` | 由显式登记的 `funcloud.seedance-json/v1` 实现以 `source_url` 解析 `general` Asset |
| 任意 | `joycreator_assets` | 否，仅管理用途 |
| 任意 | `none` | 否 |

启用素材时必须：

- 使用单 Key 渠道；
- 填写大于 0 的“最小素材 URL TTL”；
- 素材和视频属于同一上游账号；
- 渠道公开模型、模型映射和测试 Token 分组一致。

`asset_upstream_profile=none` 本身不授予 Link 素材能力。只有渠道显式选择 `funcloud.seedance-json/v1`、模型与 Standard/Fast 路径精确匹配且 exposure 策略有效时，运行时才允许以 `source_url` 消费普通 Link 资源；真人素材仍禁止。

### 3.2 BytePlus 官方双凭据

官方渠道中：

- 渠道主 Key：视频模型 API Key；
- 模型映射目标：Endpoint ID；
- 素材 Access Key ID / Secret Access Key：只用于素材 Action；
- Provider Project、Provider Region：从 BytePlus 控制台确认；
- 两套凭据不得混填。

保存规则：

| 操作 | 填写方式 |
| --- | --- |
| 新建 | AK、SK 同时填写 |
| 保留原凭据 | 编辑时 AK、SK 都留空 |
| 轮换 | AK、SK 同时填写 |
| 清除 | 先把素材方案改为 `none` 并保存，再执行清除动作 |

保存后分别执行“测试视频 API”和“测试素材 Action”。两项都通过后，再做真实生成和素材全链路验收。

### 3.3 全局素材配置

普通素材：

| 配置 | 默认值 |
| --- | ---: |
| `asset_setting.enabled` | `true` |
| `job_max_attempts` | `12` |
| `verification_poll_max_attempts` | `360` |
| `job_lease_seconds` | `60` |
| `poll_interval_seconds` | `5` |
| `max_assets_per_user` | `1000` |
| `remote_url_max_length` | `8192` |
| `create_unknown_ttl_seconds` | `300` |

真人素材除开启 `asset_setting.real_person_enabled` 外，还必须配置：

```text
ASSET_PUBLIC_BASE_URL=https://<公网域名>
ASSET_CONSENT_EVIDENCE_HMAC_KEY=<至少32字符>
CRYPTO_SECRET=<持久且非默认值>
```

也可使用持久的 `SESSION_SECRET` 代替 `CRYPTO_SECRET`。如 Provider H5 域名不等于渠道 Base URL 域名，再配置 `ASSET_H5_ALLOWED_HOSTS`。环境变量 `REAL_PERSON_ASSET_ENABLED` 存在时会覆盖后台真人开关。

## 4. 视频验收

```bash
export API_BASE="https://<本站域名>"
export API_KEY="sk-<测试令牌>"
export TEST_MODEL="seedance-byteplus"
export RUN_ID="video-<唯一编号>"
```

创建：

```bash
curl -sS -X POST "$API_BASE/api/v3/contents/generations/tasks" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $RUN_ID" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"content\": [{\"type\":\"text\",\"text\":\"清晨雪山，固定镜头，写实电影感\"}],
    \"duration\": 5,
    \"resolution\": \"720p\",
    \"ratio\": \"16:9\",
    \"generate_audio\": false
  }"
```

保存返回的 `task_...`，每 5 秒查询：

```bash
curl -sS "$API_BASE/api/v3/contents/generations/tasks/<task_id>" \
  -H "Authorization: Bearer $API_KEY"
```

成功后下载：

```bash
curl -fL "$API_BASE/v1/videos/<task_id>/content" \
  -H "Authorization: Bearer $API_KEY" \
  -o video-result.mp4
```

通过标准：

- 创建、查询、下载均使用平台任务 ID；
- 状态进入 `succeeded`；
- 文件非空且可播放；
- 响应不含上游 Key、渠道 ID 或上游任务 ID；
- 用量日志命中预期公开模型、渠道、分组和价格；
- 同一幂等 Key 重放不创建第二个任务。

单个任务通过以上标准只能证明协议链路接通。正式扩大分组还必须确认全部拟发布 SKU 的成功率、
失败类型、价格和账单、音频等产品字段语义，并在批准的观察窗口内没有超阈值 unknown、exposure
或合同违例。部分 SKU 成功、部分 SKU 由 Provider 明确失败时，应判定为“技术接入成功、生产
开放未通过”，继续受控灰度。

素材链路按[04 素材库验收操作手册](04-素材库验收操作手册.md)执行。

真人托管素材验收还必须覆盖：

- `sending` 事务锁定授权并写入可索引的 attempt—任务—素材—授权 reservation，Task 创建
  事务将其绑定；
- 并发“创建真人任务 / 撤回授权”测试证明：撤回先提交时没有上游 POST，reservation 先提交时
  撤回能索引到该 attempt/Task；
- 授权为 `authorized` 时视频和 `part=last_frame` 内容可以下载；
- 撤回后上述两个内容端点返回稳定的 `real_person_authorization_revoked`，且没有上游回源；
- 撤回能通过授权索引找到排队/运行任务；只在冻结生命周期能力支持时尝试取消；
- 已下载到平台外的副本不在撤回保证范围内。
- FunCloud v2 只消费 Link Resolver 输出的 `source_url` 或其公开 DTO 允许的请求级 URL/Data URL；
  旧 H5、raw upload、multipart 和 Provider 素材列表链路已删除，不得按历史文档恢复。
- `realPersonMode` 的 Provider 语义未获得书面确认前，FunCloud 不宣称支持真人素材公开能力。

## 5. 变更与轮换

在途视频任务会继续使用创建时选中的 Key 和查询配置。修改渠道只影响新任务。

存在未删除素材、素材组或真人授权时，不得直接：

- 轮换或清除素材凭据；
- 修改素材 profile、Project、Region 或上游账号；
- 删除渠道。

正确顺序：

1. 从生产分组移除渠道，停止新建。
2. 等待在途视频结束。
3. 撤回真人授权并清理活动素材。
4. 完成上游清理。
5. 修改凭据或渠道身份。
6. 重新执行两条链路测试、视频验收和素材验收。
7. 恢复生产分组。

## 6. 常见故障

| 现象 | 处理 |
| --- | --- |
| 无可用渠道 | 核对渠道启用状态、公开模型、分组、模型映射和素材共同渠道 |
| 飞彩创建返回任意异常 HTTP 状态 | 核对 Base URL、路径、鉴权和请求合同；按 unknown 处理，不要自动重发或手工退款 |
| `unsupported_parameter` | 删除当前渠道不支持的字段；中转线路不支持视频/音频输入及多项高级字段 |
| `asset_binding_required` | 核对单 Key、素材 profile、公开模型、账号和素材状态 |
| `asset_url_ttl_insufficient` | 重新签发更长有效期的 HTTPS URL |
| `asset_credential_changed` | 恢复原账号完成清理，或迁移为新素材 |
| `create_outcome_unknown` | 原请求有 Key 时只用同一 Key 重放；无 Key 时不要自动重试，保存 request ID 对账，事后新增 Key 不能恢复原 attempt |
| `debt` | 暂停该模型新增流量，按平台任务 ID 对账 |
| `released_with_exposure` | 立即 paging、暂停对应 SKU/渠道新流量，核对上游账单和潜在孤儿 |
| `upstream_outcome_unresolved` | 立即 paging，保留 Task/attempt/账单证据并按 SLA 复盘 |
| `real_person_authorization_revoked` | 确认授权状态、内容端点未回源以及取消/清理审计完整 |

排障记录只保留平台请求 ID、平台任务 ID、平台素材 ID、时间、状态和错误码。不要记录完整 Key、签名 URL、同意 URL或上游响应体。

飞彩任务完成响应中的 `metadata.url` 不属于 v2 合同，decoder 直接忽略；它不参与内容回源、
计费、健康审计或凭据转发。只检查顶层 `video_url`，且不得把完整 URL、userinfo 或 query 写入
普通日志。

## 7. Exposure 与对账告警

按公开 SKU、渠道和 profile 监控：

- `sending` 陈旧数、create unknown 数、hold 金额和年龄；
- `reconciliation_required` 数量、年龄和连续合同违例；
- `released_with_exposure`、`provider_contract_failure` 和
  `upstream_outcome_unresolved` 的金额、数量与单位时间速率；
- unknown 转 exposure 比例以及最老未处理记录。

对 `provider_contract_failure` 抽查资金状态：零目标应用成功后必须是 `settled`；若资金写入
失败则允许暂时为 `failed`，但共享补偿必须使用同一冻结目标恢复到 `settled`。不得因为业务
结果已经确定而跳过资金失败重试。

每个生产渠道上线审批必须填写单笔金额、单位时间金额/数量、转换率和年龄的 warning、paging
与自动停用阈值。新 profile 首期灰度时，任何 exposure 状态都立即 paging 并暂停对应公开 SKU
新流量；稳定后调整阈值仍需保留最大金额和最老年龄硬门禁。对账扫描由现有共享任务补偿调度器
承载，只新增扫描键与处理器，不启动供应商专用进程。

首期 JSON Video profile 的代码默认值就是“第一笔 exposure 立即 warning、paging 并停用该渠道
下受影响公开模型的 Ability”，不会停用同一渠道上的无关模型。配置前缀为
`provider_exposure_setting`，常用键如下：

| 配置键 | 默认值 | 说明 |
| --- | ---: | --- |
| `enabled` | `true` | 是否执行 exposure 策略；关闭后仍保留 exposure 指标 |
| `monitored_profiles` | `third_party_json_video_omni_reference` | 逗号分隔的受控 profile |
| `window_seconds` | `3600` | 数量、额度、速率和转换率统计窗口 |
| `warning_count` | `1` | warning 数量阈值 |
| `paging_count` | `1` | paging 数量阈值 |
| `auto_disable_count` | `1` | 公开模型 Ability 自动停用数量阈值 |
| `*_quota` | `0` | 客户已释放额度阈值；`0` 表示关闭该维度 |
| `*_rate_per_hour` | `0` | 每小时 exposure 速率阈值；`0` 表示关闭 |
| `*_conversion_ratio` | `0` | unknown 转 exposure 比例阈值，范围 `0`–`1` |
| `*_oldest_age_seconds` | `0` | 最老 exposure 年龄阈值；`0` 表示关闭 |
| `auto_disable_public_model_enabled` | `true` | 是否允许策略停用受影响公开模型 Ability |

其中 `*` 分别替换为 `warning`、`paging`、`auto_disable`。金额未知时不能把客户释放额度伪装成
供应商币种金额；接口分别保留 `customer_quota_released` 和可选的供应商金额字段。

自动停用前必须计算每个受影响 SKU 的剩余等价候选数，并把结果放入 paging 事件。若被停用的是
唯一等价渠道，该 SKU 没有可选 Ability 并按无可用等价渠道 fail closed，不得回退到能力不等价
的 profile。
恢复只能人工执行：完成 exposure/上游账单对账，确认根因修复和冻结合同回归通过，重置告警或
熔断状态，并先以内部灰度重新启用。不得因指标暂时恢复正常而自动重新开放唯一渠道。

Root 管理员可查看指标和 incident：

```bash
export ROOT_ACCESS_TOKEN="<Root 管理访问令牌>"

curl -sS "$API_BASE/api/task-contract/provider-exposures/metrics?window_seconds=3600" \
  -H "Authorization: Bearer $ROOT_ACCESS_TOKEN"

curl -sS "$API_BASE/api/task-contract/provider-exposures/incidents?status=open" \
  -H "Authorization: Bearer $ROOT_ACCESS_TOKEN"
```

对账完成后关闭 incident；只有确认可恢复流量时才把 `restore_public_model` 设为 `true`。若同一
渠道和公开模型仍有其他未关闭的熔断 incident，恢复请求会 fail closed：

```bash
curl -sS -X POST \
  "$API_BASE/api/task-contract/provider-exposures/incidents/<incident_id>/resolve" \
  -H "Authorization: Bearer <Root 会话访问令牌>" \
  -H "X-Security-Proof: <scope=task_contract.exposure.resolve 的二次验证证明>" \
  -H "Content-Type: application/json" \
  -d '{"note":"上游账单和任务已核对，修复已回归","restore_public_model":true}'
```

`sending`/`unknown` attempt 只有在管理员已从供应商侧独立确认“该请求已创建”并取得准确上游
任务 ID 后才可人工恢复。恢复不会再次 POST，也不能恢复已经释放 hold 的
`released_with_exposure`：

```bash
curl -sS "$API_BASE/api/task-contract/attempts?status=unknown" \
  -H "Authorization: Bearer $ROOT_ACCESS_TOKEN"

curl -sS -X POST \
  "$API_BASE/api/task-contract/attempts/<attempt_id>/recover" \
  -H "Authorization: Bearer <Root 会话访问令牌>" \
  -H "X-Security-Proof: <scope=task_contract.attempt.recover 的二次验证证明>" \
  -H "Content-Type: application/json" \
  -d '{
    "provider_verified": true,
    "upstream_task_id": "<已核验的上游任务ID>",
    "upstream_request_id": "<可选上游请求ID>",
    "note": "供应商控制台已确认创建时间、模型和请求归属"
  }'
```

上述两个写接口仅接受绑定当前 Root 登录会话的 2FA/passkey 安全证明，并进入管理审计；审计
证明分别使用示例中的 scope，可通过现有 `/api/verify` 或 Passkey verify 流程签发。审计备注
不得包含完整 Key、签名 URL、媒体内容或上游响应体。
