# 02 视频与素材渠道运维手册

## 1. 先区分两类渠道

- `DoubaoVideo` 是 NEWAPI 原生渠道，客户端使用 `/v1/video/generations`。
- `Seedance Link` 是 Seedance 专用渠道，客户端只使用 ModelArk V3 的 create/get/list/delete 四组
  `/api/v3/contents/generations/tasks` 接口。

不要为了复用已有配置把 Seedance 模型放进 `DoubaoVideo`。一个已启用 Seedance 客户模型只能出现在
一个 Seedance 渠道；不同 Provider 或不同账号必须使用不同客户模型名。

## 2. 新建 Seedance 渠道

1. 新建渠道并选择 `Seedance Link`。
2. `Models` 填客户看到的模型名；`Model Mapping` 明确映射到 Provider 模型或 Endpoint ID。
3. 选择代码内置的“Seedance 视频协议”。管理员不填写创建/查询路径或 JSON 转换规则。
4. 填 Base URL 与单个视频 API Key。Seedance 不支持多 Key。
5. 如需素材库，选择一个素材协议或 `none`，并填写该协议明确要求的普通字段。
6. 配置客户模型价格、Group 和 Seedance 模型目录投影；先保存为禁用状态。
7. 完成真实创建、查询、删除、下载与账单验收后再启用。

Priority 和 Weight 对 Seedance 无效。系统不会随机选渠，也不会在失败后换到另一个 Provider 重新创建。

## 3. 协议配对

| 视频协议 | 素材协议 | 说明 |
| --- | --- | --- |
| `modelark_v3_volcengine` | `volcengine_assets_action_v2024_01_01` 或 `none` | 国内火山官方；素材另用 AK/SK、Project，Region 固定为 `cn-beijing` |
| `modelark_v3_byteplus` | `byteplus_assets_action_v2024_01_01` 或 `none` | 海外官方；素材另用 AK/SK、Project、Region |
| `tokensave_media_task_v1` | `tokensave_assets_v1` 或 `none` | TokenSave 2.0 |
| `moxing_modelark_media_v1` | `moxing_volc_assets_v1` 或 `none` | 墨行 2.0、Fast、Mini、2.5 四个精确模型统一入口 |
| `ark_media_v1` | `ark_assets_v1` 或 `none` | Ark 反代协议 |
| `feicai_videos_v1` | `none` | 飞彩视频 V1（仅 URL，不支持素材库） |
| `funcloud_modelark_v3` | `funcloud_material` 或 `none` | 新 V3 四模型共用现有素材接口；真实素材复用待验收 |

保存或启用时会拒绝多 Key、未注册协议、错误协议配对、缺少素材 TTL，以及官方素材缺少
Project/Region/AK/SK。国内火山素材 Region 只接受 `cn-beijing`。请求时不会再重复扫描或修复管理员
绕过后台写入的非法配置。

## 4. 无状态素材代理配置

素材与视频固定使用同一 Seedance Channel、账号、Region/Project 和协议。一个模型只能发布官方素材能力、
第三方素材能力或无素材能力三种之一，不能同时配置多套素材线路。

BytePlus 官方素材使用两套凭据：渠道 Key 是视频 API Key；素材 AK/SK 只用于官方 Action。编辑时 AK/SK
同时留空表示保留，同时填写表示轮换。不要把素材 AK/SK 填入渠道视频 Key。

素材源 URL 只用于本次 Provider 创建，平台不保存二进制，也不在创建完成后保存源 URL。素材失败不会
自动迁移、重新物化或换渠道；记录 `request_id` 后交给技术人员分析。

旧 FunCloud V2 只允许 Standard/Fast/Mini 选择 `funcloud_material`；2.5 只能选择 `none`。
新 V3 四模型均可配对 `funcloud_material`，不升级素材接口版本。
FunCloud 素材上传源必须为 Provider 可访问的 HTTPS/443 URL，媒体上限 100MB。平台对所有 Provider
都不发布素材组删除，也不主动删除素材组。需要清理时只能由 Provider 管理员在确认整组归属、组内素材
和级联影响后执行，不得通过普通客户 Token 绕过。
统一北向不提供素材组更新；不要将 Provider `/material/group/update` 当作平台接口或配置能力。

## 5. 真人素材

真人能力通过 `POST /v1/asset-groups` 创建 `real_person` 组。响应返回 Provider 官网认证地址；平台不
采集人脸、不自建认证表单，也没有独立真人授权、撤回或重试后台。认证完成后查询组状态，达到
`ready` 才可向该组创建真人素材。

## 6. 上线与停流

上线至少验证：真实 Provider 凭据、客户模型到 Provider 模型映射、所有收费维度、一次创建、终态状态、
内容下载、素材引用、删除行为和账单。未完成验证的模型保持禁用。

发生模型误路由、重复 Provider POST、价格低于成本、素材账号/Region 不一致、凭据或签名 URL 泄露时，
立即禁用该客户模型所在的唯一渠道。停流不改变在途 Task 的冻结渠道和计费事实。

FunCloud 额外验证终态 `completionTokens`、可选 `pointConsume`、管理员计费证据和美元结算。出现
`RECONCILIATION_REQUIRED`、计量漂移或价格倒挂时立即停止新流量，保留 Task、hold 和私有证据供技术
对账。`RECONCILIATION_REQUIRED` 的 `FailReason` 携带脱敏违例原因，可直接据此定位，无需翻上游原文。
真实费用高于预扣时系统自动原子补扣；客户欠费（`debt`）任务保持 `SUCCESS`，补足额度后按冻结目标
自动补扣结清，不受普通结算故障的 10 次重试上限约束，无需人工逐单处理。

## 7. 健康检查与自动测试边界

- Seedance Link 渠道的手动与自动健康检查不再请求 `/v1/chat/completions`；视频协议没有无副作用的
  探针时显示“不支持视频自动测试”，不得为得到成功状态创建收费视频。
- 自动检查只执行代码登记的素材只读探针（如 FunCloud 分页大小为 1 的素材列表查询）。探针成功只
  证明素材控制面连通，HTTP/业务码/网络失败只记为探针失败；两者都不自动启用或禁用承载视频履约的
  Channel，也不写入通用 `response_time/test_time`。素材与视频凭据可分离的协议（如移动云）尤其不得
  用素材探针结果驱动视频渠道状态。
- 被禁用的 Seedance 渠道不进入无法完成视频恢复证明的 passive-recovery；不可用探针一律计为失败，
  不会误报成功。

## 7. FunCloud 协议名升级

从旧协议名 `funcloud_seedance_v2` / `funcloud_material_v2` 升级时，启动迁移会改写 Channel、Task、
create attempt、幂等和 Provider 成本中的冻结标识。它迁移的是持久化事实里的协议名，
不是创建新表，也不是把旧渠道继续当作兼容入口。

升级顺序：

1. 在旧版本禁用 FunCloud 渠道，停止新的 FunCloud 提交，但保持旧版本轮询和结算运行。
2. 等待使用旧协议名的测试 Task、create attempt 和幂等事实进入终态，并备份主数据库。
3. 使用备份副本和相同数据库引擎先运行一次新版本；确认启动成功、迁移 marker 为 `done`、旧协议名
   计数为零，且 Task、attempt 和账单记录数量未减少。平台不存在 Asset/AssetGroup 事实表，迁移不应创建或回填本地素材映射。
4. 停止旧实例后部署新版本；迁移完成并核对启动日志中的 `updated_values` 后，再按验收结果恢复流量。
5. 若启动报告仍有活动事实，回滚到旧版本继续排空后重试；不得手工删除 Task、attempt、hold 或账单事实。

迁移在单个数据库事务内执行：先核对真实表和列，再拒绝活动事实，逐值改写时要求每次恰好更新一行，
完成后复查旧协议名计数必须为零，最后才写入 marker。任一步失败都会回滚全部改写，不会留下半迁移状态。

只删除并重建 Channel 只能改变未来请求配置，不能修复历史 Task 的冻结查询路径、资金 hold 和审计证据，
因此不能代替迁移。仅当环境是可丢弃的本地开发库、从未承载需要保留的任务或计费事实时，
整体重建数据库才可以替代迁移；正常升级不需要额外手工清理。

## 8. FunCloud 视频 V3 配置与切换

新协议为 `funcloud_modelark_v3`，不是第 7 节的旧协议改名迁移。模型精确映射到 `seedance-2-0`、
`seedance-2-0-fast`、`seedance-2-0-mini`、`seedance-2-5`；可由一个 Channel 承载四个不重名客户模型。
素材选 `funcloud_material`，组策略及上传流程沿用现有版本。客户价格单独配置，不从协议名推导价格；
本地测试已按用户确认沿用现有 FunCloud 对应模型的价格与 Token 上限。

1. 先在隔离测试模型验收 4/9 图生成、10 图预先拒绝、素材引用、时长/音轨与计费。
2. V3 查询和内容读取可用，取消排队/删除终态不支持；不得将这些操作验收为供应商已提供。
3. 已有 Channel 改视频协议时，走现有素材租户替换确认；新 identity/reuse_scope 和默认组清理同事务完成。
4. 管理员确认仍为同一素材域后，手工重新关联原 Provider 默认组，不删除或重建 Provider 组/素材。
5. 旧 Task 与 attempt 使用冻结协议与资金事实，不自动重发或回退；完成验收后再决定业务模型切换。

本机代理若把 OSS 域名解析为 `198.18.0.0/15` 等 Fake-IP，素材安全回源会拒绝。应修正该域名的 DNS
或代理排除规则，不关闭 SSRF。当前实测视频在 `generate_audio=false` 时仍带音轨；该供应商行为需确认，
不能通过给视频消音来伪装接口已履约。详细结果与视频 URL 见
[归档实施记录](../99-archive/2026/09/2026-09-07-FunCloud新版视频协议与统一素材库实施方案.md)。

## Seedance 视频用量等待与运营处置

已登记 Seedance 视频协议中，仅冻结表达式依赖实际用量且缺少合法用量的成功任务进入 awaiting_usage；
固定秒价和合法明确零用量不等待。覆盖火山、BytePlus、移动云、墨行 Token 线路、FunCloud V2/V3 和
按 Token 定价的 Ark 反代；TokenSave、墨行 2.0、飞彩当前秒价直接按冻结参数结算。
FunCloud V2 缺失 completionTokens 可补查，但其已报 0、负值或超限值仍是合同异常；运营也不可补录 0。
确保异步任务后台调度已启用（UPDATE_TASK）且任务表升级完成。后台每轮最多串行补查 10 项，
每次 GET 最多 30 秒，首次立即执行，随后按 60 秒起指数退避、单次间隔最多 6 小时；
最多 12 次、最长 24 小时。该窗口是本地运营初值，不代表供应商承诺的返回时效。

超期或次数耗尽会写入运营待处理时间，日志出现 requires usage review，停止自动补查但保留预扣，
不逆转视频成功。运营应监控该队列，并在进入队列后一个工作日内建立供应商对账工单、记录负责人；
取得明确用量后完成核实处理。供应商尚不能提供用量时保持工单跟进，不通过数据库直接改账。

管理接口沿用 Root 登录鉴权，均位于 /api/task-contract：
- GET /usage-recovery?review_only=true&limit=50&offset=0：分页查询运营队列；省略 review_only
  可查询全部等待项。返回 task_id、user_id、app_id、model、held_quota、started_at、
  next_at、attempts、review_at、last_error。仅返回本地客户身份和错误分类，不含供应商凭据或原始响应。
- POST /usage-recovery/{task_id}/review：要求 X-Security-Proof，证明 scope 为
  task_contract.usage.review，支持 2fa/passkey，与当前登录会话绑定。
  仅提交 reference（事件编号）时，允许一次额外 GET，不重新开启整轮重试。
  提交 completion_tokens（整数；FunCloud V2 要求正数，其余允许已核实的 0）、provider_verified=true 和 reference（对账编号）时，
  按已核实账单建立首次用量事实，由既有后台资金补偿按冻结价格完成结算。
  reference 必填且最多 256 字节，只填写工单/账单编号，不填写密钥、签名 URL 或供应商原始响应。

重复提交相同已接受用量不会再次扣费；不同用量返回冲突，不能通过该入口覆盖已结算事实。
未知用量不得填 0，客户 quota 不得冒充供应商成本。补扣资金不足会进入既有 debt 流程；
队列移除只表示已获得用量，最终应在任务详情核对 billing_state=settled。

当前提供管理 API 与结构化日志入口，未新增专属管理页面或外部通知通道。运营可将队列查询接入现有
监控。后台 SQL/网络故障恢复依赖持久认领；不得为恢复而重新提交视频 POST。

部署验证应覆盖：添加 Task 补查列后旧数据可读、后台重启后不丢失认领、超期项可见、
安全证明越权拒绝、已核实用量只结算一次。SQLite 本机测试不能替代 MySQL/PostgreSQL 的实际升级和并发验收。


跨协议升级不自动重开已结算历史记录，也不把历史预扣金额伪装成真实用量。升级前后需分别核对：
已有 awaiting 项可继续补查；尚未结算的成功项按冻结合同处理；历史已结算但缺证据的账单只做人工对账。
运营窗口为共用初值；供应商无可用用量查询或查询持续无结果时，超限转运营，不要求客户重试。
