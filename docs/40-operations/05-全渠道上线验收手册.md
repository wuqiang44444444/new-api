# 05 全渠道上线验收手册

## 1. 目的与边界

本手册用于在测试分组或生产灰度分组中，以真实 API Key 对当前拟发布的公开合同和渠道实现执行黑盒验收。它回答“当前配置是否可以上线”，不以单元测试、渠道测试按钮或直连 Provider 的成功代替端到端验收。

验收范围从当前启用的客户模型、渠道协议和公开合同生成，不在文档中固定渠道 ID、凭据、实例名或生产域名。
代码存在、模型可见和某个相似渠道通过，都不能证明另一个实现已可发布。

## 2. 验收前准备

1. 创建隔离的测试分组、测试用户和专用 API Key；生产用户不参与首轮验收。
2. 导出待验收时点的渠道、原生 Ability（如适用）、Seedance 客户模型目录、模型映射、分组、价格和协议配置快照。
3. 只有客户入口明确声明支持时才生成和验证 `Idempotency-Key`；Seedance ModelArk V3 不支持该键。
4. 确保测试工具支持 HTTPS、JSON、multipart、持续轮询、二进制下载、Range 和结构化证据保存。
5. 预先记录每个渠道的停流方式、在途任务处理方式、回滚配置和账单核对人。

## 3. 生成验收矩阵

从当前启用的“客户模型 × 渠道协议 × 分组”生成用例，至少覆盖：

| 合同类型 | 必验内容 |
| --- | --- |
| 文本/多模态同步请求 | 模型发现、流式/非流式、usage、错误信封、账单 |
| 统一图片 | 文生图、已发布的参考图组合、`n` 边界、同步/HTTP 202、结果数、结算/退款 |
| rc23 原生 OpenAI Videos | JSON、multipart、Remix、查询、内容下载、发送后未知结果 |
| Seedance/Kling/即梦 Link | 各自类型化 DTO、已支持媒体组合、轮询、内容代理、合同错误 |
| 无状态素材代理 | 带客户模型的创建/查询/更新/删除、`asset://`、source 有效期、固定上游解析；不验证平台所有权或 App 归属 |
| 真人素材 | 上游认证链接、状态刷新、同模型素材使用和删除；仅对已批准协议执行 |

每个渠道协议至少有一个成功用例和一个可确定的失败用例。异步合同还要覆盖超时、重复轮询和发送后未知结果；未知结果不得自动换渠道、重发或退款。仅对明确支持幂等的入口验证幂等恢复。

## 4. 串行执行流程

1. 调用模型发现或查看控制台，确认当前 API Key 只能看到批准的模型。
2. 使用公开路由和 DTO 发送请求；不直接调 Provider，不用内部 `metadata`/`extra` 注入私有字段。
3. 记录平台请求 ID、平台任务 ID、HTTP 状态、响应摘要和开始时间。
4. 异步任务只轮询查询端点，不重新 POST。验证状态单调、终态稳定和平台 ID 不变。
5. 成功时通过平台内容端点下载，检查非空、MIME、可解码/可播放和 Range（如合同支持）。
6. 对声明支持幂等的入口复用原 `Idempotency-Key`，确认不产生第二个上游任务或重复扣费；Seedance 跳过此项。
7. 使用管理员只读证据核对实际渠道、上游模型、协议、attempt、exposure、价格快照、结算和退款。
8. 将用例标记为通过、失败或阻塞，并保存可复核的脱敏证据。

## 5. 通过标准

单个用例只有同时满足以下条件才通过：

- 客户模型、实际渠道、上游协议和上游模型与验收矩阵一致；
- 响应、状态、错误信封和媒体内容符合该公开合同；
- 预扣、结算、差额或退款只发生一次，且用户额度、Token 和日志不为负；
- 普通用户响应和日志不含 Provider Key、渠道 ID、上游任务 ID、签名 URL、源 URL 或管理员私有快照；
- 所有拟发布的渠道实现都通过自身用例，不用其他实现的结果代替。

某些客户模型成功而另一些受 Provider 拒绝时，只能记为“技术链路接通、发布未通过”。不得因为已有确定性测试就跳过真实 Provider、价格、账单和外部数据库验收。

## 6. 证据与脱敏

每次验收建立独立证据目录，至少保留：验收矩阵、配置快照摘要、脱敏请求/响应、轮询时序、媒体校验结果、用量日志摘要、Provider 账单核对和最终结论。

证据中不得保留完整 Bearer/API Key、Cookie、签名 URL、真实身份信息、未公开上游 ID 或完整 Provider 错误正文。对外共享前再执行一次脱敏检查。

## 7. 停流与回滚

出现路由错误、合同违例、负额度/负费用、重复上游创建、重复退款、未知结果被重发、素材引用被错误改写、
Provider 账号作用域错误或敏感信息泄露时，立即将对应渠道或客户模型移出生产分组。

回滚只阻止新流量；保留 Task、create attempt、exposure、幂等记录、计费日志和后台轮询，直到在途任务进入终态并完成对账。修复后从隔离分组重新执行全部受影响用例，不只复测最后一个失败点。
