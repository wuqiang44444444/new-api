# 40-operations — 运维与发布

## 目标

让管理员和运维人员能够安全地完成环境配置、渠道上线、观测、验收、故障处置和回滚。

## 放什么

- 环境配置、部署、监控和告警规则；
- 渠道配置、上线验收、灰度和回滚手册；
- 可长期复用的故障处置与技术升级路径；
- 生产状态、外部依赖和账单核对的操作边界。

## 不放什么

- 本地开发、构建和测试命令，放入 `30-engineering/`；
- 产品行为和客户验收口径，放入 `10-product/`；
- 架构状态机和数据模型，放入 `20-architecture/`；
- 未完成路线图和实施计划，放入 `50-planning/`；
- 一次性排障流水和临时验证记录，放入 `80-dev/`。

## 命名格式

- 通用手册使用稳定的中文名称，不加日期前缀；
- 专题运维手册可使用 `NN-中文主题.md`，编号创建后保持稳定，不因排序调整而重排或复用；
- 文件名应说明运维对象和操作范围，避免“最终版”“临时说明”等阶段性名称。

## 内容格式

- 手册按适用范围、前置条件、配置或操作步骤、成功信号、失败处置和升级路径组织；
- 上线验收明确区分代码验证、测试环境、真实 Provider、真实账单和生产灰度；
- 涉及异步任务时说明冻结配置、查询/删除边界、计费结果和不可自动重试或换渠道的条件；
- 命令、配置项和页面名称必须与当前实现一致，架构原理通过链接交给 `20-architecture/`。

## 编写要求

- 步骤必须能由普通管理员理解并执行，复杂协议判断由技术人员线下确认；
- 不记录或展示真实密钥、Token、Cookie、完整签名 URL、生产配置和 Task 私有数据；
- 未完成真实 Provider、真实账单、外部数据库和灰度验证时，不得写成生产可用；
- 不为极低概率异常新增不存在的管理员核查流程；操作失败进入日志，由技术人员分析处理。
