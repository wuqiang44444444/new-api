## 2. 标准上线顺序

1. 确定公开模型名和审批售价。
2. 配置模型价格、消费分组和测试用户。
3. 新建独立渠道，填写上游地址、凭据、路由和模型映射。
4. 检查异步任务、素材和真人能力所需配置。
5. 只加入测试分组，按[05 全渠道上线验收手册](05-全渠道上线验收手册.md)完成真实创建、查询、下载和计费核对。
6. 完成失败、超时、幂等和退款用例。
7. 加入生产分组，小流量观察一个完整结算周期。
8. 记录配置版本、变更人、时间、测试任务 ID和回滚值。

## 3. 通用操作规则

- 价格只配在客户端公开模型名上。
- 渠道 `Models`、路由 `models`、模型映射和价格使用同一公开模型名。
- 同一次业务重试复用原 `Idempotency-Key`；新业务操作使用新 Key。
- 在途异步任务使用创建时冻结的渠道、凭据和计费快照。
- 素材渠道必须单 Key；视频和素材必须属于同一上游账号。
- 不把上游 Key、签名 URL、同意 URL、上游资源 ID或完整响应写入文档、截图、群聊和普通工单。
- 回滚时保留轮询与清理任务，不删除 Task、幂等记录和计费日志。

## 4. 立即停流条件

出现以下任一情况，先从生产分组移除模型或渠道：

- 公开模型路由到错误上游模型；
- 动态表达式没有有效 usage；
- 售价低于已确认上游成本；
- 任务进入 `debt`；
- 同一幂等 Key创建多个上游任务；
- 失败或超时发生重复退款；
- 素材账号、Project、Region 或凭据指纹不一致；
- 日志或响应泄露 Key、签名 URL、同意 URL或上游 ID。

停流后继续处理在途任务、轮询、退款、撤回和删除，完成对账后再恢复。

## 5. 发布检查

- [ ] 公开模型名、模型映射和分组一致。
- [ ] 模型价格和分组倍率已由第二人复核。
- [ ] 真实成功请求和真实失败请求均已验收。
- [ ] 异步任务完成、退款和幂等已验收。
- [ ] 素材或真人能力已执行专项验收。
- [ ] 用量日志与上游账单一致。
- [ ] 监控、告警、变更记录和回滚值齐全。
