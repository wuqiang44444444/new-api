# 素材库验收操作手册

## 1. 目的与范围

本文供测试、预发布环境的运维、值班和验收人员验证素材库主链路，不要求理解代码或数据库。

验收目标：

- 普通素材能够创建并进入 `ready`；
- `ready` 素材能够生成和下载视频；
- 幂等、用户隔离和 URL 安全合同生效；
- 删除后不能建立新视频引用；
- 如测试真人素材，本人同意、Provider 认证和撤回链路完整。

平台不上传、下载或保存客户源素材，也不会删除客户自己的文件。

## 2. 测试前准备

由管理员填写测试参数：

| 参数 | 示例 |
| --- | --- |
| 测试 API 地址 | `https://api-test.example.com` |
| 用户 A Token 1 | `sk-...` |
| 用户 A Token 2 | `sk-...` |
| 用户 B Token | `sk-...` |
| 测试公开模型 | `seedance-...` |
| 素材公网 HTTPS URL | `https://...` |
| URL 到期时间 | 10 位 Unix 秒 |
| 本次测试编号 | `ops-20260727-01` |

开始前确认：

- `asset_setting.enabled` 已开启；
- 测试模型存在兼容、启用的单 Key 视频与素材渠道；
- 素材与视频链路属于同一个 Provider 账号；
- 源 URL 剩余 TTL 满足渠道要求；
- BytePlus 官方渠道已按 [配置指南](BytePlus官方视频与素材渠道配置指南.md) 完成视频和素材双凭据测试；
- 真人素材测试已单独启用真人能力，并配置同意页面、有效政策和 Provider 权益。

安全要求：

- 只使用测试素材，不使用生产素材；
- 真人图片必须得到本人明确授权；
- Token、签名 URL、同意 URL 和签名参数不进入群聊、工单标题或截图；
- 缺陷记录中的素材 URL 只保留域名，删除 `?` 之后的内容。

## 3. 设置测试变量

```bash
export API_BASE="https://<测试环境域名>"
export TOKEN_A1="sk-<用户A Token 1>"
export TOKEN_A2="sk-<用户A Token 2>"
export TOKEN_B="sk-<用户B Token>"
export TEST_MODEL="<测试公开模型>"
export SOURCE_URL="https://<测试素材临时地址>"
export SOURCE_EXPIRES_AT="<10位到期时间戳>"
export RUN_ID="<本次测试编号>"
```

每次新验收使用新的 `RUN_ID`。关闭终端后重新执行本节。

## 4. 主流程

### 4.1 创建素材

```bash
curl -i -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-asset" \
  -d "{
    \"name\": \"ops-reference-image\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"$SOURCE_URL\",
      \"expires_at\": $SOURCE_EXPIRES_AT
    }
  }"
```

通过标准：

- HTTP `202`；
- 返回 `ast_...`；
- 状态为 `creating`、`processing`、`ready` 或 `create_unknown`；
- 响应不包含完整源 URL、渠道 ID、上游素材 ID 或密钥。

保存素材 ID：

```bash
export ASSET_ID="<返回的 ast_...>"
```

### 4.2 等待素材就绪

```bash
curl -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

| 状态 | 操作 |
| --- | --- |
| `ready` | 继续创建视频 |
| `creating` / `processing` | 10 秒后再查 |
| `create_unknown` | 不换 Key 重建；记录时间并联系研发对账 |
| `failed` | 记录 `error_code`、请求 ID 和时间 |
| `deleting` / `deleted` | 本用例重新开始 |

不要每秒轮询。

### 4.3 使用素材创建视频

```bash
curl -i -sS -X POST "$API_BASE/v1/videos" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-video" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"prompt\": \"让参考画面产生轻微、自然的镜头运动\",
    \"seconds\": \"4\",
    \"size\": \"720x1280\",
    \"input_reference\": {
      \"image_url\": \"asset://$ASSET_ID\"
    }
  }"
```

通过标准：

- 返回 `task_...`；
- 状态为 `queued`、`in_progress` 或 `completed`；
- 响应不包含渠道 ID、上游任务 ID 或密钥。

```bash
export VIDEO_ID="<返回的 task_...>"
```

### 4.4 等待并下载视频

```bash
curl -sS "$API_BASE/v1/videos/$VIDEO_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

`queued` / `in_progress` 时每 10 秒查询一次；`failed` 时记录 `error.code`、请求时间和任务 ID；`completed` 后下载：

```bash
curl -fL "$API_BASE/v1/videos/$VIDEO_ID/content" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -o "video-result.mp4"
```

确认文件非空、不是 HTML 错误页并可正常播放。

### 4.5 修改素材名称

```bash
curl -sS -X PATCH "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d '{"name":"ops-reference-image-renamed"}'
```

响应中的 `name` 应为 `ops-reference-image-renamed`。

## 5. 用户隔离

同一用户的另一个 Token 应能查询素材：

```bash
curl -i -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A2"
```

不同用户查询应返回 `404`，且响应不能透露素材属于其他人：

```bash
curl -i -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_B"
```

## 6. 幂等

原样重放第 4.1 节请求：

- 返回同一个 `ast_...`；
- 不产生第二个素材；
- 不重复调用上游。

保持 `Idempotency-Key: ${RUN_ID}-asset` 不变，但修改 `name` 后重放：

- HTTP `409`；
- 错误码 `idempotency_conflict`。

视频创建遵循同一规则。新业务操作使用新 Key，原操作重试复用原 Key。

## 7. URL 安全

每个安全用例使用从未用过的 Idempotency-Key，例如 `${RUN_ID}-unsafe-01`。

拒绝 HTTP URL：

```bash
curl -i -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-unsafe-01" \
  -d "{
    \"name\": \"unsafe-http-url\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"http://example.com/unsafe.png\",
      \"expires_at\": $SOURCE_EXPIRES_AT
    }
  }"
```

预期 HTTP `400 unsafe_asset_url`。

至少再抽查两项：

| 输入 | 预期 |
| --- | --- |
| `https://127.0.0.1/a.jpg` | `400 unsafe_asset_url` |
| `https://user:pass@example.com/a.jpg` | `400 unsafe_asset_url` |
| 带 `#fragment` | `400 unsafe_asset_url` |
| 非 443 端口 | `400 unsafe_asset_url` |
| 到期时间太近 | `400 asset_url_ttl_insufficient` |
| `source.type=base64` 或 `direct_upload` | `400 asset_url_required` |

TTL 不足时确认响应的 `required_min_ttl_seconds`，重新签发更长有效期的 URL，不要重复提交原地址。

## 8. 删除与清理

完成隔离、幂等和安全用例后删除素材：

```bash
curl -i -sS -X DELETE "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

通过标准：

- HTTP `204`；
- 删除事务提交后不能再使用该素材创建新视频；
- 客户提供的原始 HTTPS 文件仍存在；
- 上游异步清理失败时有告警和重试记录。

## 9. 真人素材验收

只在业务明确要求、本人到场且环境配置完整时执行。

### 9.1 创建授权

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"locale\": \"zh-CN\"
  }"
```

保存 `id` 和 `consent_url`。必须由照片本人打开 `consent_url`，阅读政策、单独同意并完成 Provider 认证；运维人员不得代替本人操作。

### 9.2 查询授权

```bash
export AUTH_ID="<授权 ID>"

curl -sS "$API_BASE/v1/real-person-authorizations/$AUTH_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

只有 `authorized` 可以继续。创建真人素材时在第 4.1 节请求中改为：

```json
{
  "asset_kind": "real_person",
  "media_type": "image",
  "authorization_id": "<授权 ID>"
}
```

真人素材必须与授权使用同一用户、模型和 Provider 账号。

### 9.3 撤回

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations/$AUTH_ID/revoke" \
  -H "Authorization: Bearer $TOKEN_A1"
```

通过标准：

- 授权状态进入 `revoked`；
- 关联真人素材立即不能用于新视频；
- Provider 删除可在后台继续，但必须可追踪。

## 10. 常见状态与处置

| 状态或错误 | 处置 |
| --- | --- |
| `processing` | 10 秒后再查 |
| `create_unknown` | 不换 Key 重建，联系研发对账 |
| `unsafe_asset_url` | 检查公网 HTTPS、端口、地址和 fragment |
| `asset_url_ttl_insufficient` | 签发有效期更长的 URL |
| `asset_not_ready` | 等待 `ready` |
| `asset_binding_required` | 联系渠道管理员检查模型、profile 和账号绑定 |
| `asset_credential_changed` | 恢复原账号清理，或迁移为新素材 |
| `idempotency_conflict` | 核对是否复用了错误 Key |
| `insufficient_quota` | 联系管理员处理额度 |
| `rate_limit_exceeded` | 降低频率并退避 |
| `upstream_unavailable` | 保留原 Key，稍后重试 |
| `real_person_consent_required` | 由本人完成同意 |
| `real_person_verification_rejected` | 核对 Provider 认证，不得绕过 |

## 11. 最终验收清单

- [ ] 普通素材创建成功并进入 `ready`。
- [ ] 同一素材能够生成并下载视频。
- [ ] 响应无签名 URL、渠道 ID、上游 ID 或密钥。
- [ ] 同用户跨 Token 可见，不同用户返回 `404`。
- [ ] 同键同请求不重复创建，同键不同请求返回 `409`。
- [ ] URL 安全和 TTL 用例在调用上游前被拒绝。
- [ ] 删除后不能创建新引用，客户源对象未被删除。
- [ ] `create_unknown`、上游失败和清理失败均有可追踪记录。
- [ ] 如测试真人素材，已验证本人同意、认证、创建和撤回。
