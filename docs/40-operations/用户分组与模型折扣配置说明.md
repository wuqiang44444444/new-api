# 用户分组、计费分组与模型折扣配置说明

## 1. 目标

说明用户分组、令牌分组、计费分组及相关倍率的作用，并给出以下定价需求的配置方案：

- 调用 GLM 模型时按原价的 `0.6` 倍计费，即通常所说的六折。
- 调用 GPT 模型时按原价的 `0.7` 倍计费，即通常所说的七折。

> 注意：“0.6 折”按字面表示原价的 `0.06` 倍。本说明按实际常见意图，将其理解为“倍率 0.6 / 六折”；GPT 同理。

## 2. 分组与倍率的含义

### 2.1 用户分组

用户分组是账号的身份等级，例如：

- `default`
- `vip`
- `svip`

一个用户只有一个用户分组，由管理员分配。它主要决定：

- 用户的充值倍率。
- 用户创建令牌时可以选择哪些分组。
- 用户是否命中专属消费倍率。
- 与用户分组关联的限流、订阅等权益。

用户分组本身不直接决定每次请求走哪个模型渠道。

### 2.2 令牌分组

令牌分组是创建 API Key 时选择的分组。它决定该令牌默认使用哪组渠道，并作为请求的默认计费分组。

例如：

- 令牌选择 `glm-discount`，请求就从该分组下可用的渠道中进行路由，并按该分组计费。
- 令牌选择 `gpt-discount`，请求就使用 `gpt-discount` 分组的渠道和倍率。

### 2.3 计费分组

计费分组是一次请求最终实际使用的分组，其确定顺序为：

```text
令牌设置了普通分组
  → 使用令牌分组

令牌没有设置分组
  → 回退到用户分组

令牌使用 auto
  → 使用自动分组路由最终选中的实际分组
```

计费分组同时影响：

- 本次请求可以选择哪些渠道。
- 本次请求使用哪个基础分组倍率。

### 2.4 分组基础倍率

分组基础倍率是该计费分组的默认消费系数：

```text
最终费用 = 模型基础费用 × 分组倍率
```

例如：

```json
{
  "default": 1,
  "economy": 0.8,
  "premium": 1.2
}
```

表示：

- `default` 按模型基础费用计费。
- `economy` 按基础费用的 `0.8` 倍计费。
- `premium` 按基础费用的 `1.2` 倍计费。

### 2.5 用户专属倍率

用户专属倍率是“用户分组 × 计费分组”的二维覆盖规则。

例如：

```json
{
  "vip": {
    "economy": 0.6,
    "premium": 0.9
  }
}
```

表示：

- `vip` 用户按 `economy` 分组计费时使用倍率 `0.6`。
- `vip` 用户按 `premium` 分组计费时使用倍率 `0.9`。

最终倍率的确定规则为：

```text
专属倍率[用户分组][计费分组] 存在
  → 使用专属倍率

专属倍率不存在
  → 使用计费分组的基础倍率
```

专属倍率是覆盖关系，不会与基础倍率再次相乘。例如基础倍率为 `0.8`、专属倍率为 `0.6`，最终倍率是 `0.6`，不是 `0.48`。

### 2.6 可用分组与特殊可用分组

可用分组配置决定用户创建令牌时能看到和选择哪些分组。

特殊可用分组规则可以针对某个用户分组：

- 添加额外可选分组。
- 隐藏默认可选分组。
- 为分组提供展示说明。

该配置只决定“能不能选择”，不直接改变计费倍率。

### 2.7 充值倍率

充值倍率只影响充值金额或额度换算，不影响模型调用的消费价格。

不能通过修改充值倍率实现 GLM 六折、GPT 七折的调用定价。

## 3. 请求计费规则

一次普通请求可以概括为：

```text
计费分组 =
  令牌分组
  或用户分组
  或 auto 最终选择的分组

最终分组倍率 =
  专属倍率[用户分组][计费分组]
  若不存在，则为基础倍率[计费分组]

最终费用 =
  模型基础费用 × 最终分组倍率
```

需要特别注意：分组倍率只识别计费分组，不会根据模型名称自动判断 GLM 或 GPT。

## 4. GLM 六折、GPT 七折的推荐配置

### 4.1 所有用户都享受折扣

如果所有用户、所有渠道线路都执行相同折扣，推荐直接修改模型定价。

配置入口：

```text
系统设置 → 计费 → 模型定价
```

对每个实际开放的 GLM 模型：

```text
新输入价格 = 原输入价格 × 0.6
新输出价格 = 原输出价格 × 0.6
```

对每个实际开放的 GPT 模型：

```text
新输入价格 = 原输入价格 × 0.7
新输出价格 = 原输出价格 × 0.7
```

如果模型使用倍率计费：

```text
GLM 新 ModelRatio = 原 ModelRatio × 0.6
GPT 新 ModelRatio = 原 ModelRatio × 0.7
```

统一折扣输入和输出费用时，`CompletionRatio` 通常保持不变，因为 `ModelRatio` 已经作为输入、输出计算的共同基础被调整。

如果模型采用按次固定价格：

```text
GLM 新 ModelPrice = 原 ModelPrice × 0.6
GPT 新 ModelPrice = 原 ModelPrice × 0.7
```

模型定价必须配置在客户端请求中使用的公开模型名上，不要配置在渠道模型映射后的上游模型名上。

不要直接将模型倍率写成：

```json
{
  "glm-*": 0.6,
  "gpt-*": 0.7
}
```

原因如下：

1. `ModelRatio` 是模型自身的计费倍率，不是“在当前价格上继续打折”的折扣字段。
2. 普通模型定价通常按完整公开模型名匹配，不能依赖通用的 `glm-*` 或 `gpt-*` 家族通配符。
3. 不同 GLM、GPT 模型原价不同，直接全部设为 `0.6` 或 `0.7` 会破坏它们之间的价格差异。

### 4.2 通过计费分组实现全局折扣

如果需要同时用分组隔离 GLM 与 GPT 的渠道，可以创建两个计费分组：

```json
{
  "glm-discount": 0.6,
  "gpt-discount": 0.7
}
```

同时必须满足：

1. GLM 渠道只加入 `glm-discount` 分组。
2. GPT 渠道只加入 `gpt-discount` 分组。
3. 将这两个分组加入用户可选分组。
4. 用户分别创建对应分组的令牌，或者使用 `auto` 令牌自动选择实际分组。

这种方案的关键是模型能力必须按分组隔离。否则折扣会跟随令牌和计费分组，而不是跟随模型名称。

### 4.3 仅给特定用户分组折扣

如果只有 `vip` 用户享受 GLM 六折、GPT 七折，可保留两个计费分组的基础倍率为 `1`：

```json
{
  "glm-discount": 1,
  "gpt-discount": 1
}
```

然后配置用户专属倍率：

```json
{
  "vip": {
    "glm-discount": 0.6,
    "gpt-discount": 0.7
  }
}
```

还需要：

1. 将目标用户的用户分组设置为 `vip`。
2. 允许 `vip` 用户使用 `glm-discount` 和 `gpt-discount`。
3. GLM、GPT 渠道分别加入对应计费分组。
4. 用户创建对应分组的令牌，或者使用配置好的 `auto` 令牌。

其他用户没有命中专属倍率时，仍按两个计费分组的基础倍率 `1` 计费。

## 5. 单个 API Key 自动区分 GLM 与 GPT

如需使用同一个 API Key 调用两类模型，可配置自动分组：

```json
[
  "glm-discount",
  "gpt-discount"
]
```

然后让令牌使用 `auto` 分组。

自动路由的预期行为为：

```text
请求 GLM 模型
  → glm-discount 有对应模型渠道
  → 最终计费分组为 glm-discount
  → 使用 0.6 或对应专属倍率

请求 GPT 模型
  → glm-discount 没有对应模型渠道
  → 继续尝试 gpt-discount
  → 最终计费分组为 gpt-discount
  → 使用 0.7 或对应专属倍率
```

为避免错误计费，必须保证两个分组的模型能力严格隔离，并确认自动分组顺序和用户可用分组配置正确。

## 6. 方案选择

| 需求                                | 推荐方案                                            |
| ----------------------------------- | --------------------------------------------------- |
| 所有用户调用 GLM 都六折、GPT 都七折 | 修改每个公开模型的模型定价                          |
| 不同模型家族同时需要不同渠道池      | 创建`glm-discount`、`gpt-discount` 两个计费分组 |
| 只有 VIP 等特定用户享受折扣         | 两个计费分组加用户专属倍率                          |
| 一个 API Key 自动调用两类模型       | 两个模型隔离的计费分组加`auto`                    |

## 7. 验收检查

配置完成后至少执行以下检查：

1. 使用目标用户创建 GLM、GPT 请求各一次。
2. 在用量日志中确认客户端公开模型名正确。
3. 确认实际计费分组分别为预期的 GLM、GPT 分组。
4. 确认日志中的最终分组倍率分别为 `0.6`、`0.7`。
5. 分别核对输入、输出 token 的最终费用。
6. 使用非优惠用户验证其未错误命中专属倍率。
7. 如果使用 `auto`，验证分组切换由模型可用性驱动，而不是始终命中自动分组列表的第一个分组。
