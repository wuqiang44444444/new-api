# 10 用户模型合同运维手册

## 1. 配置入口

1. 进入“客户合同”查看全部已建立合同，按客户、公开模型或合同状态定位目标；首次建立合同则进入
   “用户”，找到目标 User ID。
2. 在合同总览或用户行操作选择“管理模型合同”。
3. 选择一个具体渠道组；模型选择器只显示该组当前可履约的精确模型。
4. 批量选择模型并输入 `0.8`、`80%` 或 `8折`，添加后可逐模型调整。
5. 核对原生组倍率、合同折扣、最终倍率和当前价格，填写必填变更原因后保存。

首次保存有效规则会立即启用合同，同一 User ID 的全部存量和新 Key 同时受限。合同模式下零规则代表零
权限。不要通过删除全部规则来恢复原生权限；必须使用“停用合同模式”并确认权限扩大风险。

## 2. 原生组倍率变更

合同是折扣承诺，原生 `GroupRatio` 或 `GroupGroupRatio` 的变化会实时改变新请求价格。系统设置保存分组
倍率前会计算并提示受影响的生效合同数、模型规则数和渠道组；确认后才继续保存。此提示不会冻结合同，
也不会自动修改合同折扣。组倍率设置审计会同时记录本次计算得到的影响摘要，便于关联后续客户价格变化。

变更后抽查：

- 目标合同的管理员价格预览；
- API Key 页面只读价格；
- 一条同步请求和一条异步任务的用量日志；
- 工具费和 Provider 成本未被客户折扣改变。

## 3. 并发与故障

- `409` 表示合同已被其他管理员修改；界面会加载最新版本，管理员必须重新确认后再保存。
- 合同提交瞬间少量已在途请求可能成功使用旧快照或因版本围栏返回 403；系统不会回退原生权限。
- 合同/价格接口读取失败、版本不一致或规则不可用均失败关闭。
- 保存 `GroupRatio` 或 `GroupGroupRatio` 前必须成功读取合同影响；合同表缺失、迁移不完整或查询失败时，
  系统会拒绝保存原生组倍率。先恢复合同表和数据库迁移后重试，不得绕过影响检查直接改写配置。
- 渠道组变为不可用后，合同请求不跨组重试。先恢复组内渠道，或停用合同并明确接受恢复原生权限。

## 4. 回滚

单客户异常时，使用合同抽屉“停用合同模式”。规则和审计保留，所有 Key 立即恢复原生权限。全局异常时
停止新增合同并逐用户受控停用；不要批量删除规则。正在运行的合同异步 Task 必须由能够读取其冻结计费
事实的版本完成终态结算。

## 5. 发布前核对

自动化测试不等于生产验收。至少核对一个 Token 计费、一个固定价音频或 Realtime、一个长运行异步任务、
钱包与订阅资金来源，并确认 `100 × 0.87 × 0.8 = 69.6` 在预扣、终态、日志和账单中语义一致。
