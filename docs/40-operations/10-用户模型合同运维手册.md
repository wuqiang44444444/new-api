# 10 用户模型合同运维手册

## 1. 配置入口

1. 进入“客户合同”查看全部已建立合同，按客户、公开模型或合同状态定位目标；首次建立合同则进入
   “用户”，找到目标 User ID。
2. 在合同总览或用户行操作选择“管理模型合同”。
3. 选择一个具体渠道组；模型选择器只显示该组当前可履约的精确模型。
4. 批量选择模型并输入 `0.8`、`80%` 或 `8折`，添加后可逐模型调整。
5. 核对原生组倍率、合同折扣、最终倍率和当前价格，填写必填变更原因后保存。

合同按 API Key 绑定。创建或启用客户合同后，为需要调用的 Key 逐一绑定并核对模型目录。
全站合同准入开关位于「系统配置 → 请求策略」，默认开启。开启时，停用或解绑使相关 Key 的模型列表为空，
并拒绝新调用。关闭时，停用或解绑后的 Key 按自身分组路由和计价。

## 2. 原生组倍率变更

合同是折扣承诺，原生 `GroupRatio` 或 `GroupGroupRatio` 的变化会实时改变新请求价格。系统设置保存分组
倍率前会计算并提示受影响的生效合同数、模型规则数和渠道组；确认后才继续保存。此提示不会冻结合同，
也不会自动修改合同折扣。组倍率设置审计会同时记录本次计算得到的影响摘要，便于关联后续客户价格变化。

变更后抽查：

- 目标合同的管理员价格预览；
- API Key 页面只读价格；
- 一条同步请求和一条异步任务的用量日志；
- 工具费和 Provider 成本未被客户折扣改变。

## 3. 并发与故障

- `409` 表示合同已被其他管理员修改；界面会加载最新版本，管理员必须重新确认后再保存。
- 合同提交瞬间少量已在途请求可能成功使用旧快照或因版本围栏返回 403；系统不会回退原生权限。
- 合同/价格接口读取失败、版本不一致或规则不可用均失败关闭。
- 保存 `GroupRatio` 或 `GroupGroupRatio` 前必须成功读取合同影响；合同表缺失、迁移不完整或查询失败时，
  系统会拒绝保存原生组倍率。先恢复合同表和数据库迁移后重试，不得绕过影响检查直接改写配置。
- 合同组合失效时拒绝该范围的调用。恢复合同内有效渠道，或按管理界面提示核对停用在当前系统策略下的影响。

## 4. 回滚

按客户恢复时，修复或换绑相关 Key 的合同。确需全站恢复未绑定 Key 的原生分组权限时，在请求策略显式关闭开关，
核对所有服务实例的生效值，再验证模型目录、调用和价格。启用合同仍按合同范围履约。正在运行的异步任务
由可读取其冻结计费事实的版本完成终态结算。

## 5. 发布前核对

1. 盘点仍依赖原生分组的活跃 Key。需要保留分组回退时，通过隔离的新版实例保存显式关闭值。
2. 先运行新版主节点的数据库迁移，确认存量任务已按冻结应用身份回填。选取存量即梦任务，用创建时的 Key 核对历史读取。
3. 逐节点检查请求策略的实际生效值和节点同步状态。需要保留分组回退时，确认每个节点都读到 `false`，再向新版节点导流。启用合同时，旧节点退出服务后，逐节点核对未绑定 Key 的空模型列表、新调用拒绝及历史查询权限。
4. 请求策略加载失败会阻止新进程接流量。运行中的节点保留最后一份校验通过的策略，并报告同步失败。发现节点值不一致或同步失败时，先修复持久化策略，再核对同步状态及该节点的实际行为。
5. 合同准入和方舟试点各自验收。启用合同准入的部署应确认方舟试点的新调用已停止；试点需继续服务时，单独核对其准入、实际调用和结算。

Batch 文件上传仍按原权限开放，应评估未绑定 Key 的存储使用。

至少核对一个 Token 计费、一个固定价音频或 Realtime、一个长运行异步任务、
钱包与订阅资金来源，并确认 `100 × 0.87 × 0.8 = 69.6` 在预扣、终态、日志和账单中语义一致。
