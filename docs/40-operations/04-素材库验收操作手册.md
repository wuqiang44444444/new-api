# 04 素材接口验收操作手册

## 1. 准备

准备测试 API Key、可访问的 Seedance 客户模型和 HTTPS 测试素材。默认素材合同在 `api.assets`，已配置上游
素材代理时，本站托管合同在 `api.hosted_assets`。普通代理执行第 2 至第 6 节，本站托管执行第 7 节。
真实 Key、完整签名 URL、认证 URL、Provider ID 和原始响应不得进入截图或工单。

## 2. 创建与单项查询

```bash
curl -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{
    \"name\": \"ops-reference-image\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {\"type\": \"url\", \"url\": \"$SOURCE_URL\"}
  }"
```

通过标准：HTTP 201；`id` 是 Provider opaque ID，`model` 是客户模型；可用时返回
`asset://<opaque-id>`。响应不得包含 source URL、Provider、Channel ID、账号、Region/Project、协议、
凭据或上游原始模型。

调用方保存 `model + id + reference`，并使用以下单项接口查询：

```text
GET /v1/assets/{id}?model={customer_model}
```

不得存在 `GET /v1/assets`、`GET /v1/asset-groups` 列表路由或
`DELETE /v1/asset-groups/{group_id}` 素材组删除路由。

## 3. 跨模型与视频直通

先查询两个客户模型的 `api.assets.reuse_scope`。只有两个非空值完全相同时，才分别使用每个客户模型查询
同一个 opaque 素材组 ID 和素材 ID；scope 不同或缺失时不得测试跨模型复用。结果只记录为 Provider
当次行为；scope 相同不构成所有权或永久兼容承诺。

在 ModelArk V3 媒体字段中传 `asset://<opaque-id>`。通过标准：请求到达当前客户模型选定的 Provider，
平台不查询素材、不验证所有权、应用、ready、模型、Channel、账号或地域，也不在失败时切换 Provider。

## 4. 错误与不支持

- 使用元数据中 `api.assets.supported=false` 的模型创建素材，应返回 HTTP 422
  `unsupported_asset_operation`，且不产生 Provider 请求。
- 将另一个 Provider 的已知素材 ID 交给当前模型，只允许请求当前模型选定的 Provider；返回脱敏错误，
  不得出现 Provider 名称、上游原始模型、Channel 或 fallback。
- 单项查询成功不是生成前置条件，也不保证稍后的生成一定成功。

## 5. 真人素材组

`POST /v1/asset-groups` 必须包含客户 `model`。普通组返回 Provider opaque 组 ID；真人流程返回 opaque
会话/组 ID 和 Provider 认证 URL。调用方在上游页面完成认证，并使用：

```text
GET /v1/asset-groups/{id}?model={customer_model}
GET /v1/asset-groups/{session_id}?model={customer_model}&verification_session=true
```

平台不得代理或收集人脸、活体、证件或授权表单。

## 6. 删除边界与验收清单

单素材删除必须携带创建时保存的客户模型和 opaque ID。失败按脱敏普通错误返回，不建立本地 unknown、
自动重试、孤儿扫描或人工修复状态。素材组不提供删除接口，平台也不主动删除；确需清理由 Provider
管理员在确认整组归属、组内素材和级联影响后执行。

- [ ] 单素材已发布的 CRUD 均按客户模型执行 Token 模型授权；素材组仅验收创建和单项查询。
- [ ] 不存在素材或素材组列表、平台 Asset/AssetGroup 映射、resolver 或所有权索引。
- [ ] 不存在素材组更新/删除路由，公开元数据不包含 `delete_asset_group`。
- [ ] source URL、媒体二进制、Provider 名称和上游原始模型不进入公开响应或普通日志。
- [ ] 视频 `asset://<opaque-id>` 不触发本地素材可用性和作用域校验。
- [ ] 错误 ID 只进入当前 Provider，失败不换渠道、不探测其它 Provider。
- [ ] 不支持的模型和操作明确返回 `unsupported_asset_operation`。
- [ ] `reuse_scope` 相同的模型按同一素材域验收；不同或缺失时不跨模型发送 ID。
- [ ] 真人认证只返回上游地址，不存在平台真人授权、撤回或自建 H5。

## 7. 本站托管素材

本站托管库按账号共享，统一接受图片、MP3 音频和 MP4 视频。素材 API 仍要求客户 `model` 以校验访问权限。
新 Seedance 模型接入 ModelArk V3 后自动使用同一套托管库，无需修改素材库代码或单独登记媒体类型。
生成时按目标模型的 `api.video.creation.content_types` 和视频合同校验媒体类型、角色、数量、组合及媒体规格。

准备同一账号的两个测试 API Key、另一账号的测试 Key，以及两个可用的客户模型。确认私有对象存储可写，
从模型目录选择最短输出时长和最低支持分辨率。按目标模型的输入合同选择测试素材。

1. 用 `management_mode=platform_hosted` 分别创建普通图片、MP3 和 MP4。确认 HTTP 201、`ready` 和
   `asset://fhas_…` 引用。核对素材记录及私有对象，
   响应不暴露源地址、内部签名或存储位置。
2. 用同一用户的另一个 Key 查询素材并在兼容模型中引用，确认可履约。用另一用户的 Key 查询或提交
   同一引用，确认失败，且视频请求没有预扣或上游生成。
3. 确认同一用户可查询自己的托管素材组，不能把另一用户的组 ID 用于创建素材。
4. 删除素材后，新的视频创建不能再引用它。已受理任务继续按冻结事实处理。对象及既有账单保持可核对。
5. 按[全渠道上线验收手册](05-全渠道上线验收手册.md)记录目标 Provider、用量、资金与结果交付证据。

按目标模型允许的组合验证三种托管引用，并用同一份媒体对照直接 URL 与托管引用。覆盖两种地址在同一请求中的
混用，以及错槽位、同一引用放入不同类型槽位和删除后再次引用。失败请求应在资金预扣及上游提交前拒绝。

对照测试使用相同的媒体字节、参数和参考素材。先确认临时 URL 支持 Provider 所需的 Range 读取，
再逐笔比较终态、交付状态、用量和本站结算。对有声成片用 FFprobe 检查容器时长、视频流和音轨，
再用 FFmpeg 检查音轨电平，以区分存在音轨和实际有声。

### 真实渠道回归

2026-11-13 使用 `./start.sh` 重启后的开发环境、PostgreSQL 和真实 Azure Blob 回归。模型目录中
23 个可用标准视频模型均发布相同的托管入库类型。真实生成覆盖以下两条 Mini 线路，均使用各模型公布的最短
4 秒和最低 480p。两个结果均达到 `delivery_status=ready`，已下载并用 FFprobe、FFmpeg 确认为有声成片，
容器时长均为 4.096 秒。

| 线路 | 参考输入 | 生成用量 | 本站结算 |
| --- | --- | --- | --- |
| Vidu Mini | 托管 PNG、MP3 和 MP4 | 70,726 completion tokens | 73,893 quota |
| Synlink Mini | 托管 PNG 和 MP3、直接 HTTPS MP4 | 70,726 completion tokens | 72,777 quota |

三种素材均通过入库、同账号跨模型及跨 Key 查询、跨账号隔离和删除验证。错槽位、跨账号引用及删除后新引用
均在预扣前拒绝。已受理的复测任务在素材删除后继续完成。另核对了首轮三个已删除素材的存储对象，
其 SHA-256 均与各自源文件一致。

首轮 Synlink 拒绝了像素数低于模型要求的参考视频，Vidu 返回上游内部错误。两笔失败任务均结算为 0。
换用 960 × 540 参考视频后，两条线路均通过。供应商账单与生产发布仍待验收，见
[路线图](../50-planning/路线图.md)第 40 项。

#### 2026-11-14 Seedance Mini 与 H3 端到端回归

在开发环境按公开 API 示例调用真实渠道。使用仅支持参考图的 `MiniMax-H3` 作为素材请求的 `model`，
通过 `POST /v1/assets` 和 `management_mode=platform_hosted` 分别提交 PNG、MP3、MP4，
三次均返回 HTTP `201`、`ready` 和托管引用。同账号切换到 `seedance-2-0-mini-v` 查询，
三种素材均返回 HTTP `200` 和原引用，随后直接将这些引用用于 Seedance 生成。

| 客户模型 | 托管参考输入 | 请求时长和分辨率 | 下载成片时长 | 本站结算 |
| --- | --- | --- | --- | --- |
| `seedance-2-0-mini-v` | PNG、MP3、MP4 同一请求 | 4 秒、480p | 4.096 秒，有声 | 73,893 quota |
| `MiniMax-H3` | PNG | 4 秒、768p | 4.458 秒 | 160,000 quota |

两条任务均使用模型目录公布的最短时长和最低分辨率，查询达到 `succeeded` 和
`content.delivery_status=ready`，下载后经 FFprobe 确认包含视频流。H3 首次创建因测试额度不足被拒绝，
补足测试额度后通过。

以相同的 H3 参考图请求为基线，分别加入已入库的 MP3 和 MP4，并放入对应的参考音频与参考视频字段。
两次都只在提交生成时返回 HTTP `400 invalid_request`。核对账户额度、创建尝试和任务记录均无变化，
确认未预扣、未提交上游、未创建任务。
