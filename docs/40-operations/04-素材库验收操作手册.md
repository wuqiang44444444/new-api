# 04 素材库验收操作手册

> authorization reservation、撤回并发线性化、既有任务内容逐次授权回查和关联
> attempt/Task 索引已实现。第 7.4 节仍是每个真实 Provider 生产分组的必须验收项，不能仅以单元测试代替。

## 1. 测试准备

准备：

- 用户 A 的两个测试 Token；
- 用户 B 的一个测试 Token；
- 已启用素材能力的公开 Seedance 模型；
- Provider 可访问的公网 HTTPS 测试素材；
- 满足渠道最小 TTL 的 10 位 Unix 到期时间；
- 本次测试唯一编号。

安全要求：

- 只用测试素材；
- 真人图片必须取得本人明确授权；
- Token、完整签名 URL、认证 URL 和签名参数不进入截图、群聊或工单；
- 缺陷记录中的源 URL 只保留域名。

```bash
export API_BASE="https://<测试环境域名>"
export TOKEN_A1="sk-<用户A Token 1>"
export TOKEN_A2="sk-<用户A Token 2>"
export TOKEN_B="sk-<用户B Token>"
export TEST_MODEL="seedance-byteplus"
export SOURCE_URL="https://<测试素材临时地址>"
export SOURCE_EXPIRES_AT="<10位到期时间戳>"
export RUN_ID="asset-<本次唯一编号>"
export END_USER_SUBJECT="qa-subject-<本次唯一编号>"
```

## 2. 主流程

### 2.1 创建素材

```bash
curl -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-create" \
  -d "{
    \"name\": \"ops-reference-image\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"$SOURCE_URL\",
      \"expires_at\": $SOURCE_EXPIRES_AT
    }
  }"
```

通过标准：

- HTTP `202`；
- 返回平台素材 ID `ast_...`；
- 状态为 `creating`、`processing`、`ready` 或 `create_unknown`；
- 响应不含完整源 URL、渠道 ID、上游素材 ID或密钥。

```bash
export ASSET_ID="ast_<创建响应中的ID>"
```

### 2.2 等待 `ready`

```bash
curl -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

| 状态 | 操作 |
| --- | --- |
| `ready` | 继续 |
| `creating` / `processing` | 5～10 秒后再查 |
| `create_unknown` | 保留原素材 ID和幂等 Key，等待对账 |
| `failed` | 记录错误码、request ID和时间 |
| `deleting` / `deleted` | 使用新幂等 Key重新开始 |

### 2.3 使用素材创建视频

```bash
curl -sS -X POST "$API_BASE/api/v3/contents/generations/tasks" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-video" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"content\": [
      {
        \"type\": \"text\",
        \"text\": \"让参考画面产生轻微、自然的镜头运动\"
      },
      {
        \"type\": \"image_url\",
        \"role\": \"reference_image\",
        \"image_url\": {\"url\": \"asset://$ASSET_ID\"}
      }
    ],
    \"duration\": 5,
    \"resolution\": \"720p\",
    \"ratio\": \"9:16\",
    \"generate_audio\": false
  }"
```

保存返回的 `task_...`：

```bash
export VIDEO_TASK_ID="task_<创建响应中的ID>"
```

### 2.4 查询和下载

```bash
curl -sS "$API_BASE/api/v3/contents/generations/tasks/$VIDEO_TASK_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

`queued` / `running` 时每 5～10 秒查询一次。进入 `succeeded` 后：

```bash
curl -fL "$API_BASE/v1/videos/$VIDEO_TASK_ID/content" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -o video-result.mp4
```

确认文件非空、不是 HTML 错误页且可正常播放。

### 2.5 修改名称

```bash
curl -sS -X PATCH "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d '{"name":"ops-reference-image-renamed"}'
```

响应名称应为 `ops-reference-image-renamed`。

## 3. 权限与幂等

### 3.1 应用与用户隔离

当前 Token ID 就是 `app_id`。同一用户的另一个 Token 也应返回 `404`，且不透露资源归属：

```bash
curl -i -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A2"
```

不同用户应返回 `404`，且不透露资源归属：

```bash
curl -i -sS "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_B"
```

### 3.2 幂等

原样重放第 2.1 节请求：

- 返回同一个 `ast_...`；
- 不创建第二个素材；
- 不重复调用上游。

保持 `Idempotency-Key` 不变但修改请求内容后重放：

- HTTP `409`；
- 错误码 `idempotency_conflict`。

视频创建和素材迁移使用相同规则。

## 4. URL 安全

每个用例使用新的幂等 Key。至少验证：

| 输入 | 预期 |
| --- | --- |
| `http://...` | `400 unsafe_asset_url` |
| `https://127.0.0.1/...` | `400 unsafe_asset_url` |
| URL 含 `user:pass@` | `400 unsafe_asset_url` |
| URL 含 `#fragment` | `400 unsafe_asset_url` |
| 非 443 端口 | `400 unsafe_asset_url` |
| 到期时间太近 | `400 asset_url_ttl_insufficient` |
| `source.type=base64` 或 `direct_upload` | `400 asset_url_required` |

TTL 不足时按响应中的 `required_min_ttl_seconds` 重新签发 URL，不要重复提交原地址。

## 5. 素材迁移

使用 `ready` 素材和新的源 URL：

```bash
export MIGRATION_SOURCE_URL="https://<新的测试素材临时地址>"
export MIGRATION_EXPIRES_AT="<10位到期时间戳>"

curl -sS -X POST "$API_BASE/v1/assets/$ASSET_ID/migrations" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-migration" \
  -d "{
    \"name\": \"ops-reference-image-migrated\",
    \"model\": \"$TEST_MODEL\",
    \"migration_reason\": \"operations acceptance\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"$MIGRATION_SOURCE_URL\",
      \"expires_at\": $MIGRATION_EXPIRES_AT
    }
  }"
```

通过标准：

- HTTP `202`；
- 返回新的 `ast_...`；
- `supersedes_asset_id` 指向原素材；
- 原素材未被原地改绑；
- 新素材进入 `ready` 后可独立用于视频。

## 6. 删除

```bash
curl -i -sS -X DELETE "$API_BASE/v1/assets/$ASSET_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

通过标准：

- HTTP `204`；
- 删除提交后不能再用该素材创建新视频；
- 客户源文件未被删除；
- 上游清理失败时有告警和重试记录。

如第 5 节创建了迁移素材，同样删除并记录其清理结果。

## 7. 真人素材

只在真人能力配置完整且本人到场时执行。

### 7.1 接受 API 服务规则并创建授权

先调用 `GET /v1/api-service-rules/current`，使用响应的 `version` 和 `content_sha256`
调用 `POST /v1/api-service-rules/acceptance`，并填写受控测试环境的
`compliance_owner` 与 `consent_record_system_ref`。再创建授权：

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"$TEST_MODEL\",
    \"end_user_subject\": \"$END_USER_SUBJECT\"
  }"
```

确认响应为 `verifying`，并将返回的 `verification_url` 交给需要认证的人。测试人员不得代替本人完成 H5 认证。

### 7.2 查询和重试

```bash
export AUTH_ID="rpa_<授权ID>"

curl -sS "$API_BASE/v1/real-person-authorizations/$AUTH_ID" \
  -H "Authorization: Bearer $TOKEN_A1"
```

只有 `authorized` 可以创建真人素材。允许重试时：

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations/$AUTH_ID/retry" \
  -H "Authorization: Bearer $TOKEN_A1"
```

新的认证 URL仍须由本人操作。

### 7.3 创建真人素材

复用第 2.1 节请求，改为：

```json
{
  "asset_kind": "real_person",
  "media_type": "image",
  "authorization_id": "rpa_xxx"
}
```

授权、素材和视频必须属于同一 `user_id + app_id + end_user_subject`、公开模型和 Provider 账号。创建视频时在 ModelArk 请求顶层传入同一 `end_user_subject`。

### 7.4 撤回

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations/$AUTH_ID/revoke" \
  -H "Authorization: Bearer $TOKEN_A1"
```

确认：

- 状态进入 `revoked`；
- 关联真人素材立即不能用于新视频；
- 撤回前已绑定该素材的任务，其 `/v1/videos/{task_id}/content` 和 `?part=last_frame` 派生读取返回
  `real_person_authorization_revoked`，且平台没有向上游发起内容请求；
- 可通过 authorization reservation 普通索引定位已接受 attempt 和仍活跃的关联 Task，并按
  公开 SKU 能力尝试取消；
- 已经下载或复制到平台之外的内容不在平台可撤回范围内；
- 上游删除继续后台执行且可追踪。

## 8. 最终检查

- [ ] 普通素材进入 `ready`。
- [ ] 素材可生成并下载视频。
- [ ] 响应和日志没有敏感信息。
- [ ] 同用户跨 Token（跨 `app_id`）与不同用户均返回 `404`。
- [ ] 并发创建真人任务与撤回覆盖两个提交顺序：撤回先提交时没有上游 POST，reservation
  先提交时撤回可索引到 attempt/Task。
- [ ] 真人授权撤回后，任务级内容和派生帧读取均 fail-closed，且没有上游回源。
- [ ] 同键同请求不重复创建，同键不同请求返回 `409`。
- [ ] URL 安全和 TTL 用例在上游调用前被拒绝。
- [ ] 迁移生成新素材且未原地改绑。
- [ ] 删除后不能建立新引用，客户源对象仍存在。
- [ ] `create_unknown`、上游失败和清理失败可追踪。
- [ ] 应用已接受当前 API 服务规则，真人能力已验证 H5 认证、创建、重试和撤回。
