# 04 素材库验收操作手册

## 1. 准备

准备两个不同 API Key、两个用户、一个已启用素材协议的 Seedance 客户模型、Provider 可访问的 HTTPS
测试素材和满足渠道最短 TTL 的到期时间。真实 Key、完整签名 URL、认证 URL 和 Provider ID 不进入
截图或工单。

## 2. 创建普通素材

```bash
curl -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d "{
    \"name\": \"ops-reference-image\",
    \"asset_kind\": \"general\",
    \"media_type\": \"image\",
    \"model\": \"$TEST_MODEL\",
    \"source\": {
      \"type\": \"url\",
      \"url\": \"$SOURCE_URL\",
      \"expires_at\": $SOURCE_EXPIRES_AT
    }
  }"
```

通过标准：HTTP `201`；ID 为 `ast_*`；响应不含源 URL、Channel ID、Provider ID 或凭据。查询
`GET /v1/assets/{asset_id}` 直到 `ready`。失败只记录失败与 `request_id`，不期待 unknown、自动重试、
迁移或核查后台。

## 3. 视频引用与隔离

在 ModelArk V3 媒体字段中传 `asset://ast_*`。确认同一 API Key、同一客户模型可用；同一用户的另一个
API Key、另一个用户、另一个客户模型或另一个 Seedance 渠道均不可解析。请求成功后确认只创建一个
Provider 视频任务，失败时不切换渠道。

## 4. 素材组与真人认证

```bash
curl -sS -X POST "$API_BASE/v1/asset-groups" \
  -H "Authorization: Bearer $TOKEN_A1" \
  -H "Content-Type: application/json" \
  -d "{
    \"name\": \"ops-real-person\",
    \"group_kind\": \"real_person\",
    \"model\": \"$TEST_MODEL\",
    \"redirect_url\": \"https://example.com/verified\"
  }"
```

确认响应 ID 为 `astgrp_*`，`verification_url` 指向已批准的 Provider 官方域名。由本人直接在上游页面
完成认证；平台页面不得代理、嵌入或收集人脸。通过 `GET /v1/asset-groups/{group_id}` 查询状态，达到
`ready` 后再以 `asset_group_id` 创建真人图片素材。

## 5. 删除

先删除组内素材，再删除素材组。Provider 删除失败应返回失败并保留本地资源；不得伪装成功、自动重试、
换渠道或建立人工核查状态。将 `request_id`、时间、公开素材 ID 和脱敏错误交给技术人员分析。

## 6. 验收清单

- [ ] 一个素材只冻结一个客户模型、Channel、账号、Region/Project 和素材协议。
- [ ] 源 URL 在 Provider 创建后不进入公开响应、普通日志或持久化素材事实。
- [ ] `asset://ast_*` 的 user + app + model + Channel 隔离生效。
- [ ] 不存在 binding、迁移、source fallback、自动物化或跨渠道复制接口。
- [ ] 真人认证只返回上游地址，不存在平台真人授权、撤回、reservation 或自建 H5。
- [ ] 创建/删除异常按普通失败处理，技术日志足够排查且不泄露敏感值。
