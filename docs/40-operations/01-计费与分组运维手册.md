# 01 计费与分组运维手册

## 1. 操作入口

| 操作 | 后台入口 |
| --- | --- |
| 模型价格 | 系统设置 → 计费与支付 → 模型定价 |
| 分组、折扣、自动分组 | 系统设置 → 计费与支付 → 分组定价 |
| 渠道所属分组与模型 | 渠道管理 |
| 用户身份分组 | 用户管理 |
| API Key 分组与模型限制 | 令牌管理 |
| 扣费核对 | 用量日志 |

所有价格都配置在客户端使用的公开模型名上，不配置在渠道映射后的上游模型名上。

## 2. 模型价格

### 2.1 选择计费方式

| 场景 | 计费方式 | 填写内容 |
| --- | --- | --- |
| 文本、按 Token 结算 | 按 Token | 输入、输出、缓存及多模态的 `$/1M Token` |
| 图片、按次任务 | 按次 | `$/次` |
| 按分辨率、输入类型或阶梯结算 | 动态表达式 | 已审核表达式；异步任务另填预扣 Token 上界 |

同一模型只保留一种生效方式。动态表达式启用后，不再使用该模型遗留的按次价或 Token 倍率。

最终消费价按以下口径核对：

```text
模型基础费用 × 有效消费分组倍率 × 请求规格倍率
```

充值倍率不参与调用扣费。

### 2.2 配置步骤

1. 新增或编辑公开模型名。
2. 选择计费方式。
3. 填入已审批价格。
4. 异步动态计费模型填入预扣 Token 上界。
5. 保存后在模型广场核对基础价和分组价。
6. 使用测试分组发起一次请求，在用量日志核对公开模型、计费方式、分组、倍率和最终费用。

### 2.3 Seedance 2.0 价格模板

以下价格于 2026-07-28 按 [BytePlus ModelArk 官方价格](https://docs.byteplus.com/docs/ModelArk/1099320)复核，单位为 `USD / 1M completion_tokens`。正式改价前再次核对官方页面。

| 输出分辨率 | 含视频输入 | 不含视频输入 |
| --- | ---: | ---: |
| 480p / 720p | 4.3 | 7.0 |
| 1080p | 4.7 | 7.7 |
| 4k | 2.4 | 4.0 |

适用于以下按 Token 返回可信用量的公开 SKU：

```text
seedance-byteplus
```

不要把本节 BytePlus Token 单价套用于 TokenSave 的 `doubao-seedance-2-0-260128`；该线路按秒列价，
使用下一节的独立表达式。

将计费方式设为“动态表达式”，复制以下表达式：

```text
param("_task.has_video_input") == true
  ? (param("_task.resolution") == "4k"     ? tier("4k_video",      c * 2.4)
    : param("_task.resolution") == "1080p" ? tier("1080p_video",   c * 4.7)
    :                                       tier("480p720p_video", c * 4.3))
  : (param("_task.resolution") == "4k"     ? tier("4k",            c * 4.0)
    : param("_task.resolution") == "1080p" ? tier("1080p",         c * 7.7)
    :                                       tier("480p720p",       c * 7.0))
```

预扣 Token 上界按渠道实际开放的最大规格填写：

| 渠道最大能力 | 建议下限 |
| --- | ---: |
| 中转，仅 720p、输出 5 秒 | 130,000 |
| 中转，仅 1080p、输出 5 秒 | 300,000 |
| 官方/反代，720p、输入 15 秒 + 输出 5 秒 | 520,000 |
| 官方/反代，1080p、输入 15 秒 + 输出 5 秒 | 1,200,000 |
| 官方/反代，4k、输入 15 秒 + 输出 15 秒 | 7,000,000 |

上界必须覆盖该 SKU 在该渠道真实开放的最长时长、最高分辨率和视频输入。取值范围为 `1` 至 `1,073,741,823`。

上线前完成一个 720p、5 秒任务，并确认：

- 终态 `usage.completion_tokens` 大于 0；
- 用量日志命中正确档位；
- 最终费用按真实 Token 结算；
- 没有进入 `debt`。

若终态没有有效 `completion_tokens` 或 `total_tokens`，立即改回审批后的按次固定价；不要继续使用动态表达式。

### 2.3.1 Moxing `seedance-2-0-oversea` 按量候选配置

Moxing 当前报价为 480p/720p、无视频输入 ¥49/百万 token；本地 `USDExchangeRate=7`，因此候选表达式为：

```text
v1:tier("480p720p", c * 7.0)
```

该 SKU 最长 15 秒、最高 720p，按 `seconds × width × height × 24 / 1024` 的已知上界配置
`preconsume_tokens=324000`；`duration=-1` 同样按 15 秒。Moxing 模型页把 `usage` 描述为字符串，v2
adapter 不将其投影成 token；成功任务在完成真实 usage/账单取证前保持冻结预扣费用。该配置只用于
禁用渠道的验证基线，不能因表达式存在而启用 Channel、Ability 或 publication。

### 2.4 TokenSave doubao Seedance 2.0 按秒模板

TokenSave 当前对 `doubao-seedance-2-0-260128` 按输出秒数和分辨率列价。平台当前只发布文字和
图片参考输入，因此只能使用模型页“视频输入：否”的价格；不要配置“视频输入：是”的档位。

将计费方式设为“动态表达式”，并使用以下表达式。表达式值的单位是“美元/百万计费单位”，
所以页面上的美元/秒价格必须乘以 `1,000,000`：

```text
param("_task.resolution") == "1080p"
  ? tier("1080p", param("_task.duration_seconds") * 364700)
  : param("_task.resolution") == "720p"
    ? (param("_task.input_mode") != "text" && param("_task.control_mode") != "reference"
      ? tier("720p_image", param("_task.duration_seconds") * 146100)
      : tier("720p_text_or_reference", param("_task.duration_seconds") * 146200))
    : tier("480p", param("_task.duration_seconds") * 67900)
```

该表达式对应 480p `$0.0679/秒`、720p 文生/参考生 `$0.1462/秒`、720p 图生
`$0.1461/秒`、1080p `$0.3647/秒`。预扣 Token 只承担表达式求值载体，不参与最终价格；建议填
`1`，因为表达式不读取 `c`。

当前 implementation 必须为 `tokensave.seedance-media-task@v2`。初版 Link 合同要求显式时长、
分辨率和比例，只开放文本、单图首帧、首尾帧与参考图；1080p 仅属于该 SKU，不能扩张到
`seedance-2-0-oversea`。TokenSave 模型页把 `usage` 描述为字符串，按秒结算只读取冻结请求探针，
不得回退到 BytePlus 六档 token 表达式。2026-08-05 的 4 秒 480p 成功样本未返回 `usage`，仍需用
Provider 实际账单核对请求时长、产出时长、币种和精度。

智能时长 `-1` 在预扣阶段按 15 秒上界处理。如果业务不能接受以上界计费，在 Provider 返回的
实际可计费时长尚未完成终态结算验证前，只开放显式 4～15 秒。生产启用前至少各跑一次文本、
首帧、参考图和拟开放分辨率，并将平台扣费与 Provider 账单逐项核对。

### 2.5 FunCloud Seedance 2.0 原价模板

FunCloud 使用独立公开 SKU，不覆盖官方、TokenSave 或飞彩模型的价格：

```text
seedance-2.0-standard
seedance-2.0-fast
```

当前按供应商原价（不采用括号内 85% 折扣价）配置。单位为美元/输出秒：

| 输入类型 | 480p | 720p | 1080p |
| --- | ---: | ---: | ---: |
| 文生、图生、参考生 | 0.0679 | 0.1465 | 0.3651 |
| 视频输入 | 0.1465 | 0.1600 | 0.3989 |

Fast 只发布 480p/720p。两个 SKU 均使用 `tiered_expr`，预扣 Token 设为 `1`；表达式不读取
`c`，直接按冻结的 `duration_seconds`、`resolution` 和 `has_video_input` 计算。

Standard：

```text
param("_task.has_video_input") == true
  ? (param("_task.resolution") == "1080p"
      ? tier("1080p_video", param("_task.duration_seconds") * 398900)
      : param("_task.resolution") == "720p"
        ? tier("720p_video", param("_task.duration_seconds") * 160000)
        : tier("480p_video", param("_task.duration_seconds") * 146500))
  : (param("_task.resolution") == "1080p"
      ? tier("1080p", param("_task.duration_seconds") * 365100)
      : param("_task.resolution") == "720p"
        ? tier("720p", param("_task.duration_seconds") * 146500)
        : tier("480p", param("_task.duration_seconds") * 67900))
```

Fast：

```text
param("_task.has_video_input") == true
  ? (param("_task.resolution") == "720p"
      ? tier("720p_video", param("_task.duration_seconds") * 160000)
      : tier("480p_video", param("_task.duration_seconds") * 146500))
  : (param("_task.resolution") == "720p"
      ? tier("720p", param("_task.duration_seconds") * 146500)
      : tier("480p", param("_task.duration_seconds") * 67900))
```

这只是客户端基础价配置，不等于供应商账单语义已经验收。生产启用前仍需按文本、图片、视频输入
和每个分辨率逐项核对实际扣费；若供应商按实际产出而非请求时长结算，必须先补齐可信终态用量，
不能在当前表达式下直接开放生产流量。

### 2.6 飞彩 Seedance 2.0 本地测试价格

2026-08-04 本地 `default` 分组按 Provider 2026-08-03 文档中的人民币每秒成本配置。
本地 `USDExchangeRate=7`，因此表达式系数为 `人民币/秒 ÷ 7 × 1,000,000`：

| 公开 SKU | Provider 成本（人民币/秒） | 表达式系数 |
| --- | ---: | ---: |
| `seedance-2.0-standard-720p` | 0.74 | 105714.285714 |
| `seedance-2.0-value-720p` | 0.62 | 88571.428571 |

两个 720p SKU 均使用 `tiered_expr`、预扣 Token `1`；每个 SKU 的表达式形式为：

```text
v1:tier("base", param("_task.duration_seconds") * <表达式系数> * param("_task.size_multiplier"))
```

`default` 分组消费倍率 `1` 作用于最终扣费。三条未发布 1080p/4K 价格键已删除。
该配置只是本地联调基线；生产开放前必须用真实
Provider 账单复核币种、精度、取整、失败扣费和画幅乘数，并独立批准客户售价。

## 3. 分组与折扣

### 3.1 字段口径

| 配置 | 用途 |
| --- | --- |
| 消费倍率 | 该计费分组的默认调用倍率 |
| 充值倍率 | 该用户分组的充值倍率，不参与调用扣费 |
| 用户专属倍率 | “用户身份分组 × 计费分组”的消费倍率覆盖 |
| 用户可选 | 是否允许用户创建该分组的 API Key |
| 自动分组 | `auto` Key 的选组顺序 |
| 特殊可用分组 | 给指定用户分组增加或移除可选分组 |

用户专属倍率是覆盖值，不与普通消费倍率再次相乘。

### 3.2 配置普通分组

1. 在“分组定价”新增分组。
2. 填写消费倍率。
3. 按需填写充值倍率。
4. 需要用户自行选择时开启“用户可选”并填写说明。
5. 在渠道管理中把目标渠道加入该分组。
6. 保存并使用固定到该分组的测试 Key 验证。

### 3.3 配置专属折扣

仅 VIP 使用某分组时打折：

```json
{
  "vip": {
    "economy": 0.6,
    "premium": 0.9
  }
}
```

`vip` 使用 `economy` 时最终消费倍率为 `0.6`，不是普通倍率再乘 `0.6`。

### 3.4 GLM 六折、GPT 七折

| 需求 | 操作 |
| --- | --- |
| 所有用户统一折扣 | 将每个 GLM 公开模型价格乘 `0.6`，每个 GPT 公开模型价格乘 `0.7` |
| 分渠道池折扣 | 建立 `glm-discount`、`gpt-discount`，消费倍率分别为 `0.6`、`0.7` |
| 仅 VIP 折扣 | 两个分组普通倍率设为 `1`，在用户专属倍率中分别覆盖为 `0.6`、`0.7` |
| 一个 Key 调两类模型 | 将 Key 设为 `auto`，并按顺序配置两个自动分组 |

使用自动分组时，GLM 渠道只能进入 GLM 分组，GPT 渠道只能进入 GPT 分组。模型能力未隔离时不要上线。

## 4. 上线验收

- [ ] 价格配置在公开模型名上。
- [ ] 每个模型只启用一种计费方式。
- [ ] 异步动态计费已配置足够的预扣 Token 上界。
- [ ] 普通倍率、专属倍率和充值倍率未混用。
- [ ] `auto` 分组顺序和模型隔离正确。
- [ ] 测试用户与普通用户均完成对照请求。
- [ ] 用量日志中的公开模型、计费分组、倍率、Token、档位和最终费用正确。
- [ ] 失败、取消和超时任务只退款一次。

## 5. 回滚

1. 先从生产分组移除目标模型或渠道。
2. 动态计费异常时改回最近一次已验收的固定价。
3. 恢复最近一次已验收的分组倍率。
4. 保留在途任务和计费日志，不删除任务记录。
5. 对 `debt`、重复退款或价格倒挂逐笔对账后再恢复流量。
