# 01 计费与分组运维手册

## 1. 操作入口

| 操作 | 后台入口 |
| --- | --- |
| 模型价格 | 系统设置 → 计费与支付 → 模型定价 |
| 分组、折扣、自动分组 | 系统设置 → 计费与支付 → 分组定价 |
| 渠道所属分组与模型 | 渠道管理 |
| 用户身份分组 | 用户管理 |
| API Key 分组与模型限制 | 令牌管理 |
| 扣费核对 | 用量日志 |

所有价格都配置在客户端使用的公开模型名上，不配置在渠道映射后的上游模型名上。

## 2. 模型价格

### 2.1 选择计费方式

| 场景 | 计费方式 | 填写内容 |
| --- | --- | --- |
| 文本、按 Token 结算 | 按 Token | 输入、输出、缓存及多模态的 `$/1M Token` |
| 图片、按次任务 | 按次 | `$/次` |
| 按分辨率、输入类型或阶梯结算 | 动态表达式 | 已审核表达式；异步任务另填预扣 Token 上界 |

同一模型只保留一种生效方式。动态表达式启用后，不再使用该模型遗留的按次价或 Token 倍率。

最终消费价按以下口径核对：

```text
模型基础费用 × 有效消费分组倍率 × 请求规格倍率
```

充值倍率不参与调用扣费。

### 2.2 配置步骤

1. 新增或编辑公开模型名。
2. 选择计费方式。
3. 填入已审批价格。
4. 异步动态计费模型填入预扣 Token 上界。
5. 保存后在模型广场核对基础价和分组价。
6. 使用测试分组发起一次请求，在用量日志核对公开模型、计费方式、分组、倍率和最终费用。

### 2.3 Seedance 2.0 价格模板

以下价格于 2026-07-28 按 [BytePlus ModelArk 官方价格](https://docs.byteplus.com/docs/ModelArk/1099320)复核，单位为 `USD / 1M completion_tokens`。正式改价前再次核对官方页面。

| 输出分辨率 | 含视频输入 | 不含视频输入 |
| --- | ---: | ---: |
| 480p / 720p | 4.3 | 7.0 |
| 1080p | 4.7 | 7.7 |
| 4k | 2.4 | 4.0 |

适用于以下按 Token 返回可信用量的公开 SKU：

```text
seedance-byteplus
```

不要把本节 BytePlus Token 单价套用于 TokenSave 的 `doubao-seedance-2-0-260128`；该线路按秒列价，
使用下一节的独立表达式。

将计费方式设为“动态表达式”，复制以下表达式：

```text
param("_task.has_video_input") == true
  ? (param("_task.resolution") == "4k"     ? tier("4k_video",      c * 2.4)
    : param("_task.resolution") == "1080p" ? tier("1080p_video",   c * 4.7)
    :                                       tier("480p720p_video", c * 4.3))
  : (param("_task.resolution") == "4k"     ? tier("4k",            c * 4.0)
    : param("_task.resolution") == "1080p" ? tier("1080p",         c * 7.7)
    :                                       tier("480p720p",       c * 7.0))
```

预扣 Token 上界按渠道实际开放的最大规格填写：

| 渠道最大能力 | 建议下限 |
| --- | ---: |
| 中转，仅 720p、输出 5 秒 | 130,000 |
| 中转，仅 1080p、输出 5 秒 | 300,000 |
| 官方/反代，720p、输入 15 秒 + 输出 5 秒 | 520,000 |
| 官方/反代，1080p、输入 15 秒 + 输出 5 秒 | 1,200,000 |
| 官方/反代，4k、输入 15 秒 + 输出 15 秒 | 7,000,000 |

上界必须覆盖该 SKU 在该渠道真实开放的最长时长、最高分辨率和视频输入。取值范围为 `1` 至 `1,073,741,823`。

上线前完成一个 720p、5 秒任务，并确认：

- 终态 `usage.completion_tokens` 大于 0；
- 用量日志命中正确档位；
- 最终费用按真实 Token 结算；
- 没有进入 `debt`。

若终态没有有效 `completion_tokens` 或 `total_tokens`，立即改回审批后的按次固定价；不要继续使用动态表达式。

### 2.3.1 墨行国内 Seedance 美元价格模板

墨行国内价格统一按 `1 USD = 6.82 CNY` 换算。以下配置全部写在客户模型名上，不写在映射后的
Provider 模型名上。

| 客户模型 | 计费方式 | 预扣 Token 上界 |
| --- | --- | ---: |
| `doubao-seedance-2-0-260128-moxing` | 请求时长与分辨率 | 1 |
| `doubao-seedance-2-0-fast-260128-moxing` | `USD / 1M completion tokens` | 324,000 |
| `doubao-seedance-2-0-mini-260615-moxing` | `USD / 1M completion tokens` | 324,000 |
| `doubao-seedance-2-5-260628-moxing` | `USD / 1M completion tokens` | 648,000 |

墨行 2.0 按输出秒数计费。表达式系数等于 `USD/秒 × 1,000,000`：

```text
param("_task.has_video_input") == true
  ? (param("_task.resolution") == "720p"
      ? tier("720p_video", param("_task.duration_seconds") * 354838.709677)
      : tier("480p_video", param("_task.duration_seconds") * 164809.384164))
  : (param("_task.resolution") == "720p"
      ? tier("720p", param("_task.duration_seconds") * 145747.800587)
      : tier("480p", param("_task.duration_seconds") * 67741.935484))
```

Fast、Mini 和 2.5 的报价单位为 `USD / 1M completion tokens`，表达式按是否含视频输入选择价格：

```text
# doubao-seedance-2-0-fast-260128-moxing
param("_task.has_video_input") == true
  ? tier("video_input", c * 3.225806451613)
  : tier("text_or_image", c * 5.425219941349)

# doubao-seedance-2-0-mini-260615-moxing
param("_task.has_video_input") == true
  ? tier("video_input", c * 2.052785923754)
  : tier("text_or_image", c * 3.372434017595)

# doubao-seedance-2-5-260628-moxing
param("_task.has_video_input") == true
  ? tier("video_input", c * 6.158357771261)
  : tier("without_video_input", c * 10.263929618768)
```

当前墨行轮询 adapter 会采集成功终态中格式有效的明确 `usage`/Token，并作为实际用量进入归一层；
创建时冻结的计费模式决定是否按该用量差额结算。生产启用前仍须逐模型核对 Provider 账单、字段单位和
终态稳定性，但采集行为本身不由运行时信任开关控制。

### 2.4 TokenSave doubao Seedance 2.0 按秒模板

TokenSave 客户模型为 `doubao-seedance-2-0-260128-tokensave`，按输出秒数、分辨率和图片控制类型
列价。当前协议只开放文字和图片参考；Provider 完整报价中的视频输入档位只保留在 research 文档，
不进入当前运行时表达式。

将计费方式设为“动态表达式”，并使用以下表达式。表达式值的单位是“美元/百万计费单位”，
所以页面上的美元/秒价格必须乘以 `1,000,000`：

```text
param("_task.resolution") == "1080p"
  ? tier("1080p", param("_task.duration_seconds") * 364700)
  : param("_task.resolution") == "720p"
    ? (param("_task.input_mode") != "text" && param("_task.control_mode") != "reference"
      ? tier("720p_image", param("_task.duration_seconds") * 146100)
      : tier("720p_text_or_reference", param("_task.duration_seconds") * 146200))
    : tier("480p", param("_task.duration_seconds") * 67900)
```

该表达式只覆盖当前已发布的文字和图片输入档位。预扣 Token 只承担表达式求值载体，不参与最终
价格，填写 `1`。按秒结算只读取冻结请求探针，不依赖 Provider `usage`。

智能时长 `-1` 在预扣阶段按 15 秒上界处理。生产启用前至少各跑一次文本、首帧、参考图和拟开放
分辨率，并将平台扣费与 Provider 账单逐项核对。

### 2.5 FunCloud Seedance 四模型 Token 价格

FunCloud 不再使用旧 Standard/Fast 按秒价或通用 SKU。四个独立客户模型都配置为
`tiered_expr`，单位为 USD/百万 completion tokens：

| 客户模型 | 无视频输入 480/720 | 无视频输入 1080 | 有视频输入 480/720 | 有视频输入 1080 | 预扣 Token 上界 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `seedance-2-funcloud` | 6.74 | 7.48 | 4.11 | 4.55 | 730000 |
| `seedance-2-fast-funcloud` | 5.43 | 不支持 | 3.23 | 不支持 | 324000 |
| `seedance-2-mini-funcloud` | 3.37 | 不支持 | 2.05 | 不支持 | 324000 |
| `seedance-2-5-funcloud` | 10.26 | 不支持 | 6.16 | 不支持 | 648000 |

表达式必须用 `param("_task.has_video_input")`、`param("_task.resolution")` 和
`tier(name, value)` 选择上表档位，并将冻结 completion tokens 作为 `c`。概念表达式为：

```text
seedance-2-funcloud      = has_video ? (1080p ? c*4.55 : c*4.11) : (1080p ? c*7.48 : c*6.74)
seedance-2-fast-funcloud = has_video ? c*3.23 : c*5.43
seedance-2-mini-funcloud = has_video ? c*2.05 : c*3.37
seedance-2-5-funcloud    = has_video ? c*6.16 : c*10.26
```

不得使用 `duration_seconds` 改回按秒计价，也不得使用当前价格重算历史 Task。可信成功终态直接使用
查询响应的 `completionTokens`；缺失、类型错误、非正数或超界时任务必须进入
`RECONCILIATION_REQUIRED` 并保留预扣，不估算、不退款。

运维人员只在管理员日志 `other.admin_info.provider_billing_evidence` 核对 Token 来源
`completionTokens`、Provider 报告 Token 和可选的原始 `pointConsume`。生产开放前必须逐模型、输入
类型、分辨率和账号与 FunCloud 后台 Token/美元账单核对。

## 3. 分组与折扣

### 3.1 字段口径

| 配置 | 用途 |
| --- | --- |
| 消费倍率 | 该计费分组的默认调用倍率 |
| 充值倍率 | 该用户分组的充值倍率，不参与调用扣费 |
| 用户专属倍率 | “用户身份分组 × 计费分组”的消费倍率覆盖 |
| 用户可选 | 是否允许用户创建该分组的 API Key |
| 自动分组 | `auto` Key 的选组顺序 |
| 特殊可用分组 | 给指定用户分组增加或移除可选分组 |

用户专属倍率是覆盖值，不与普通消费倍率再次相乘。

### 3.2 配置普通分组

1. 在“分组定价”新增分组。
2. 填写消费倍率。
3. 按需填写充值倍率。
4. 需要用户自行选择时开启“用户可选”并填写说明。
5. 在渠道管理中把目标渠道加入该分组。
6. 保存并使用固定到该分组的测试 Key 验证。

### 3.3 配置专属折扣

仅 VIP 使用某分组时打折：

```json
{
  "vip": {
    "economy": 0.6,
    "premium": 0.9
  }
}
```

`vip` 使用 `economy` 时最终消费倍率为 `0.6`，不是普通倍率再乘 `0.6`。

### 3.4 GLM 六折、GPT 七折

| 需求 | 操作 |
| --- | --- |
| 所有用户统一折扣 | 将每个 GLM 公开模型价格乘 `0.6`，每个 GPT 公开模型价格乘 `0.7` |
| 分渠道池折扣 | 建立 `glm-discount`、`gpt-discount`，消费倍率分别为 `0.6`、`0.7` |
| 仅 VIP 折扣 | 两个分组普通倍率设为 `1`，在用户专属倍率中分别覆盖为 `0.6`、`0.7` |
| 一个 Key 调两类模型 | 将 Key 设为 `auto`，并按顺序配置两个自动分组 |

使用自动分组时，GLM 渠道只能进入 GLM 分组，GPT 渠道只能进入 GPT 分组。模型能力未隔离时不要上线。

## 4. 上线验收

- [ ] 价格配置在公开模型名上。
- [ ] 每个模型只启用一种计费方式。
- [ ] 异步动态计费已配置足够的预扣 Token 上界。
- [ ] 普通倍率、专属倍率和充值倍率未混用。
- [ ] `auto` 分组顺序和模型隔离正确。
- [ ] 测试用户与普通用户均完成对照请求。
- [ ] 用量日志中的公开模型、计费分组、倍率、Token、档位和最终费用正确。
- [ ] 失败、取消和超时任务只退款一次。

## 5. 回滚

1. 先从生产分组移除目标模型或渠道。
2. 动态计费异常时改回最近一次已验收的固定价。
3. 恢复最近一次已验收的分组倍率。
4. 保留在途任务和计费日志，不删除任务记录。
5. 对 `debt`、重复退款或价格倒挂逐笔对账后再恢复流量。
