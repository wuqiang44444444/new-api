# 03 图片渠道与异步 Provider 运维手册

> 本手册描述当前普通图片渠道与显式图片异步执行。同步模式下 FunCloud 的 Provider 异步任务只在
> 一次请求内由 adaptor 轮询，Moxing 使用一次同步 POST；两者都继续返回原生图片响应。
> 显式异步模式（`Prefer: respond-async`）建立平台图片 Task 并由后台 worker 执行，查询复用
> `GET /v1/tasks/{task_id}`。代码已存在不等于生产已上线；上线前仍需完成真实 Provider、价格、
> 超时和退款灰度验收。

## 1. 创建统一图片中转渠道

管理端只选择「图片中转」（`ChannelType=63`），然后显式选择一个上游协议。每条渠道只能使用一个协议；
需要同时使用 FunCloud 和 Moxing 时创建两条渠道，不能在同一条渠道中混放 Provider 模型。

### 1.1 FunCloud

选择 `funcloud_aigc_v2`：

```text
Base URL: https://mm-internal-cn.leonecloud.com
API Key:  <FunCloud API key>
Models:   nano-banana-2-lite,nano-banana-2,seedream-5.0-lite,seedream-5.0-pro
```

### 1.2 Moxing

选择 `moxing_images_v1`：

```text
Base URL: https://www.moxing.pro
API Key:  <Moxing API key>
Models:   seedream-5-moxing,seedream-5-pro-moxing
ModelMapping:
  seedream-5-moxing     -> doubao-seedream-5-0-260128
  seedream-5-pro-moxing -> doubao-seedream-5-0-pro-260628
Test model: seedream-5-moxing
```

两种协议都允许管理员使用客户自定义模型名，并通过 `model_mapping` 精确映射到所选协议登记的 Provider
模型。协议选择、Models、ModelMapping 和价格是彼此独立的管理员配置；代码不生成、补齐或改写 mapping。
客户模型直接使用 Provider 模型名时可省略对应映射。body pass-through 必须关闭，Param Override、
Advanced Custom route 和模型抓取均不得配置。

Moxing Lite/Pro 代码合同都固定为 `2K`、`n=1`、URL 响应；客户固定价可分别配置为
`0.035 USD/次` 和 `0.09 USD/次`，但这些价格不代表供应商成本已经验真。渠道在真实 Provider 与账单验收
前保持手工禁用；参考图、组图、联网搜索、stream、任意尺寸以及 Pro `1K` 保持未发布。

## 2. 部署闸门

1. 图片中转代码固定 10 分钟总时限，无需配置 `RELAY_TIMEOUT`。若部署显式配置更短的正数，
   它作为所有 relay 共享的更早上限；`0` 或未配置不会禁用图片中转。
2. 分别完成 FunCloud/Moxing 价目、失败扣费/退款、余额不足和输入图收费规则的书面核实；一个 Provider
   的证据不能替代另一个。
3. 当前仅灰度固定规格文生图；Moxing Lite/Pro 都只有 `2K` 单图。参考图、高规格、高质量、Pro `1K`
   和组图在计费规则核实并实现预扣前不得开放。
4. 两种协议都关闭透传请求体且 Param Override 为空；Header Override 首次上线保持为空；Base URL 使用
   所选协议的站点根地址。
5. 观测请求耗时、固定 10 分钟或更短全局上限的命中率、HTTP 400/429/502/504、Provider code 及退款成功率。

### 2.1 从独立 Moxing 类型升级

该升级不能与仍会读写旧类型 63 的版本滚动混跑：

1. 备份主数据库，并在相同数据库引擎的生产等价副本上完成一次演练；
2. 摘除流量并停止全部旧版本实例，确认没有旧管理端或自动任务继续写 Channel；
3. 先启动一个新版本 master，由其完成 `migration.image_relay_protocol_v1`；迁移遇到非法 settings、
   Param Override 或冲突协议时会整体回滚，必须先修正对应渠道再重试；
4. 确认 marker 为 `done`、旧类型 63 计数为零，并抽查旧 62/63 渠道的协议、Base URL、Models、mapping、
   Key、分组、价格和 Ability；settings 中与协议无关的扩展字段必须仍然存在；
5. master 启动检查通过后再启动其它新版本节点。每个节点都会只读验证迁移结果，验证失败的节点不得接流量；
6. 全部新节点健康后恢复业务流量。不得通过恢复类型 63 alias、运行时 fallback 或手工跳过 marker 解除阻塞。

## 3. 北向请求合同

```http
POST /v1/images/generations
Authorization: Bearer <customer-key>
Content-Type: application/json
```

允许的通用字段为 `model`、`prompt`、`n=1`、`size`、`quality`、`response_format=url`、
`output_format` 和 `extra_fields`。当前 `nano-banana-2` 只允许 1K，`seedream-5.0-lite`
只允许 2K/basic，`seedream-5.0-pro` 只允许 1K/basic；`extra_fields.reference_images`
明确返回 `400`。`callbackUrl`、Base64、`stream` 和其它未知字段也必须返回 `400`。

渠道 adaptor 会校验模型专属 prompt 长度、固定规格和宽高比。参考图能力未发布，不进行远程探测或
额外下载；待 input-image 计费核实后再单独实现。

Moxing 只接受 `model`、`prompt`、省略或为 `1` 的 `n`、省略或为 `2K` 的 `size`，以及省略或为
`url` 的 `response_format`。其它图片字段、显式提交的 `stream`（包括 `false`）和未知字段均应在发送前
返回 `400`；管理端渠道测试必须使用图片生成 endpoint，并根据精确 Provider 映射生成 `2K` 请求。

## 4. 等待、超时与重试

- 创建成功后 adaptor 立即查询一次；Provider 仍为 `processing/queued` 时，前 30 秒每 3 秒、之后
  每 5 秒查询一次。
- 总等待固定不超过 10 分钟；显式配置的更短正数 `RELAY_TIMEOUT` 或本次请求 context 可提前终止，
  命中任一边界返回 HTTP `504`。
- 超时、取消、非法响应、空结果或多结果均沿用普通同步图片失败/退款语义。
- 不自动重发、跨渠道重试或把 Provider task ID 暴露给客户。调用方如需重试，应由业务自行决定，
  并承担可能的重复生成风险。
- Moxing 只发送一次同步 POST；网络错误、超时、Provider 4xx/5xx、非法响应和结果合同错误均不得自动
  重发或换到 FunCloud。`504` 不能证明 Provider 未受理或未计费。

## 5. 显式图片异步执行运维

### 5.1 对象存储（异步依赖）

配置事实在数据库：系统设置 → 运维 →「对象存储」。存储类型支持 `upstream`（不启用）、
`s3`（S3 兼容端点，path-style + 代码内 SigV4）与 `azure_blob`（原生 Azure Blob，官方
azblob SDK，Shared Key + service SAS）。容器/桶必须私有且已存在；配置页不自动创建。

标准启用流程（本地、HK、US 一致）：

1. 准备容器与 SharedKey 凭据（Azure 连接字符串或 Account Key 均可；仅支持 SharedKey，
   不支持 SAS/托管身份。连接字符串只作为输入格式，解析后不保存原文）。
2. 在「对象存储」填写存储类型、容器、前缀（可选）与凭据，点击「测试连接」——在容器内
   创建随机测试对象验证 PUT/HEAD/鉴权 GET/签名 GET/删除；测试不替换在线配置。
3. 「保存并启用」对同一完整配置重新校验并测试，通过后原子保存；失败保留既有配置。
   保存后按当前 revision 激活，其它节点经 `SyncOptions` 周期刷新（节点间主密钥
   `CRYPTO_SECRET`/`SESSION_SECRET` 必须一致，否则解密失败、存储失败关闭为禁用）。
4. 旧部署迁移：仍使用 `TASK_ARTIFACT_STORE_*` 环境变量的节点会在设置页看到导入提示；
   导入预览不含密钥，「验证并导入」通过连通性测试后写入数据库。导入完成后数据库是唯一
   配置源，旧环境变量不再生效、也不作失败 fallback，应尽快从启动配置中移除。

- 密钥状态只显示 `credential_configured` 与脱敏账号；密钥加密信封为 `objstore.v1.`
  （主密钥从部署侧稳定主密钥派生，不与数据库同表）。轮换密钥：同账号同容器内输入新
  Key 测试后保存即可；不保存第二把备用 Key，不自动尝试旧凭据，旧 Key 签发的 SAS 在
  撤销后失效。
- 初次启用后，存储类型/端点/容器/前缀/账号/region 在线固定，只允许同位置轮换凭据。
  更换位置或关闭须暂停业务，在维护窗口显式迁移并验证；任务计数为零不代表历史/同步对象已无人依赖。
  平台不自动迁移或删除远端对象。旧 S3 图片若曾绕过非空前缀保存，升级前须离线核实对象位置并迁移。
- 图片结果签名固定 300 秒；旧任务产物投递沿用 900 秒默认 TTL。
- 存储不可用时新异步受理返回 `503`，不预扣、不发送；已受理任务按事实恢复。
- 异步受理及后台发送前做最长 5 秒的小对象读写检查，同节点按存储实例缓存成功 10 秒、失败 2 秒。
  `object-storage-health/` 下每实例复用一个无客户内容的健康对象，由桶生命周期清理；并非每请求运行
  管理员完整探针。探测失败时后台不领取新任务，排队期限仍生效；实际写入失败会使此前成功缓存失效。
  这不是持续可用承诺，发送后的故障仍按交付恢复/待核实处理，不重新生成。
- 对象清理由部署方桶生命周期策略承担；平台不删除图片对象（仅清理自己的测试对象；
  测试对象清理失败会单独提示，需人工到容器内删除）。

### 5.2 容量与时间预算（默认值，G12 容量测试后冻结）

| 环境变量 | 默认 | 含义 |
| --- | --- | --- |
| `IMAGE_ASYNC_MAX_WAITING` | 1000 | 全局未完成图片任务上限（超限 `503`） |
| `IMAGE_ASYNC_MAX_PER_APP` | 20 | 每 user+app 未完成上限（超限 `429`） |
| `IMAGE_ASYNC_EXECUTE_CONCURRENCY` | 8 | 全局执行并发 |
| `IMAGE_ASYNC_CHANNEL_EXECUTE_CONCURRENCY` | 4 | 每渠道执行并发 |
| `IMAGE_ASYNC_QUEUE_SECONDS` | 1800 | 最大排队等待（仅证实未发送的过期任务安全失败退款） |
| `IMAGE_ASYNC_EXECUTE_SECONDS` | 600 | 单任务执行预算 |
| `IMAGE_ASYNC_STORE_SECONDS` | 300 | 结果保存预算 |
| `IMAGE_ASYNC_WORKER_BATCH` | 8 | worker 每轮领取数量 |

worker 以 `image_task_execute` system task 运行（默认 10 秒周期，`UPDATE_TASK` 总开关）。

### 5.3 受理与恢复事实

- 受理事务一次提交容量占用、Task（`QUEUED`）与幂等绑定；钱包与令牌额度预扣紧随其后，失败路径
  原子清零计费事实（补偿扫描不会退款一笔从未扣过的钱）。
- 发送许可（SENDING）持久提交后才写出 Provider 请求字节；发送后不可判定结果置
  `RECONCILIATION_REQUIRED`（查询投影 `unknown`），禁止自动重发/换渠道/退款。已持久化可信上游
  任务 ID 的待核实任务由 worker 每轮恢复查询（只查询不重建）；仍无法收敛的需技术人员核实。
- 结果对象键为确定性键（`images/tasks/{taskID}/result-N`）并逐图登记；崩溃后按键续传/补登记。
- 排队过期且证实从未发送的任务安全失败并退款；免费模型无预扣。
- `Idempotency-Key` 仅异步模式支持；同 key 重放返回原任务 ID，不同请求体 `409`；绑定任务未终态
  期间到期不重置；multipart 重传（boundary 变化）视为同一请求。
- 查询逐图区分 `available/deleted/unavailable`：对象被部署方删除保留历史状态，暂不可用稍后重查。

### 5.4 管理员操作

- Gemini/Vertex 渠道把客户模型映射到 imagine 登记模型（如 `gemini-3.1-flash-image`）后，
  该模型即发布生成 + 编辑图片合同；渠道测试默认走图片生成 endpoint。
- 图片中转渠道（63）异步模式无需额外配置；edits/参考图在 Provider 计费证据完成前显式 `400`。
- 异步任务在管理端任务列表按平台（渠道类型字符串）过滤；`RECONCILIATION_REQUIRED` 任务保留
  资金，人工核实后按现有任务人工恢复/拒绝流程处理。

## 6. 故障处置

| 现象 | 处置 |
| --- | --- |
| 大量 `504` | 核对 10 分钟固定边界、可选的更短 `RELAY_TIMEOUT`、Provider P99 和网络代理；必要时先停用渠道 |
| `10002` | 修正客户模型参数或请求字段，不能通过 Header/Param Override 绕过校验 |
| `10005/40001/90003` | 核对 API Key、FunCloud 余额和 Provider 状态；不切换其它渠道掩盖故障 |
| 成功响应零合法 URL | 立即停用受影响模型并保留脱敏错误日志，等待协议核实；多 URL 按 data[] 交付 |
| 退款失败 | 同步模式按现有同步计费补偿流程处理；异步任务由 `AsyncBilling` 补偿扫描自动重试 |
| 异步任务长时间 `unknown` | 发送结果待核实：核对 Provider 是否已受理并计费，走人工恢复/拒绝，不得自动重发 |
| 异步受理持续 `503` | 核对对象存储配置与可用性；存储恢复前保持新异步关闭（同步不受影响） |
| `429` 应用并发超限 | 核对该 user+app 未完成任务积压与容量配置；不是 Provider 限流 |
| Moxing 返回 `429` | 保持禁止重试，核对供应商限流与流量分组；不得临时打开 fallback |
| Moxing 鉴权/余额错误 | 核对 KEY 和供应商余额；客户只接收脱敏 `502`，日志不得记录原始响应或 KEY |

  src/features/channels/components/drawers/__tests__/image-relay-protocol-fields.test.tsx)

真实 Provider 验收至少分别覆盖：FunCloud 四模型和 Moxing Lite/Pro 固定规格文生图、错误码、超时/取消、
单 URL 响应、预扣/结算/失败退款、供应商账单以及固定 10 分钟边界。Moxing 还需确认同步超时或
客户端取消后是否已受理并计费；完成前保持禁用。
