# 03 图片渠道与异步任务运维手册

> 当前代码已实现发送前 durable attempt、同步结果
> `completed_no_replay/idempotency_result_unavailable`、`PROVIDER_CONTRACT_FAILURE` 和
> provider cost exposure。生产启用仍必须完成供应商实测、价格审批、paging/自动停用阈值配置
> 与内部灰度；代码能力不等于渠道已经上线。

## 1. 当前客户模型

| 公开模型 | 上游模型 | 上游路径 | Converter |
| --- | --- | --- | --- |
| `seedream-5-moxing` | `seedream-5-0-260128` | `/v1/images/generations` | `media_task_image_blocking` |
| `nano-banana-2` | `gemini-3.1-flash-image-preview-usage` | `/v1/media/generations` | `media_task_image_blocking` |
| `seedream-5-qihang` | `seedream-5` | `/v1/images/generations` | `none` |

客户端统一使用：

```text
POST /v1/images/generations
GET  /v1/images/tasks/:task_id
```

价格与 Token 权限使用客户模型名；渠道 `Models`、Advanced Custom 路由 `models` 也使用同一客户
模型名。`model_mapping` 的目标是 Provider 模型，不维护第二套 Link 模型身份或映射。

## 2. Moxing 图片渠道


按技术人员审核结果配置代码中已有的 `media_task_image_blocking` converter 和 Advanced Custom 路由。

## 4. 渠道开关

所有图片专用渠道确认：

- 请求体透传：关闭；
- 跳过异步轮询延迟：生产关闭；
- Header Override：不用于本路由鉴权；
- 参数覆盖：首次上线保持为空；
- Base URL：只填站点根地址，不以 `/` 结尾；
- 路由只加入上游已开通的模型。

后台任务：

```text
UPDATE_TASK=true
TASK_TIMEOUT_MINUTES=1440
```

`TASK_TIMEOUT_MINUTES` 至少大于上游任务 P99/SLA 加安全余量。

## 5. 计费门禁

1. 在“模型定价”按客户模型配置审批后的固定 `ModelPrice`。
2. 每个尺寸分别核对上游成本和本站售价。
3. `nano-banana-2` 的 1K、2K、4K 未全部完成价格覆盖前，只开放已验收尺寸和测试分组。
4. 只有真实 usage 与上游账单一致、且已配置可信预扣 Token 上界时，才允许改为动态表达式。
5. usage 异常时立即回退固定价。

## 6. 上线测试

```bash
export API_BASE="https://<本站域名>"
export API_KEY="sk-<测试令牌>"
export RUN_ID="image-<唯一编号>"
```

Moxing Seedream：

```bash
curl -i -sS -X POST "$API_BASE/v1/images/generations" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-seedream" \
  -d '{
    "model": "seedream-5-moxing",
    "prompt": "白色桌面上的蓝色陶瓷杯，产品摄影",
    "size": "2K",
    "n": 1,
    "response_format": "url"
  }'
```

Nano 异步：

```bash
curl -i -sS -X POST "$API_BASE/v1/images/generations" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Prefer: respond-async" \
  -H "Idempotency-Key: ${RUN_ID}-nano" \
  -d '{
    "model": "nano-banana-2",
    "prompt": "绿色叶子图标，白色背景",
    "size": "1K",
    "n": 1,
    "response_format": "url"
  }'
```

Qihang Seedream：

```bash
curl -i -sS -X POST "$API_BASE/v1/images/generations" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-qihang" \
  -d '{
    "model": "seedream-5-qihang",
    "prompt": "极简风格的未来城市海报",
    "size": "2K",
    "n": 1,
    "response_format": "url"
  }'
```

HTTP `200` 时核对 `data[].url`。HTTP `202` 时保存 `Location` 或响应中的 `task_xxx`：

```bash
curl -sS "$API_BASE/v1/images/tasks/<task_id>" \
  -H "Authorization: Bearer $API_KEY"
```

通过标准：

- 三个客户模型分别命中正确渠道和上游模型；
- HTTP 200 和 202 均按预期处理；
- 已选中持久化媒体任务 route 后，在上游 POST 前已经建立 `prepared` attempt，预扣与
  `sending` 原子提交；
- 异步任务进入 `completed`，结果位于 `result.data[].url`；
- 异步 Task 使用同一幂等 Key 重放时不重复创建或扣费；
- 同步 HTTP 200 不提供结果回放；原响应丢失后同键重放返回
  `409 idempotency_result_unavailable`，且不再次调用上游；
- 失败和超时只退款一次；
- 无效轮询响应进入 `reconciliation_required` 而不是立即退款；可信完成结果超过请求 `n`
  时进入内部 `PROVIDER_CONTRACT_FAILURE`，对外投影
  `failed/provider_contract_failure`，按零目标结算并记录 exposure；
- `PROVIDER_CONTRACT_FAILURE` 零目标资金成功后 billing 为 `settled`；注入资金写入失败时
  先为 `failed`，再由共享补偿扫描恢复为 `settled`，exposure 始终只有一条；
- 用量日志中的图片数量、尺寸、分组和最终费用正确。

## 7. 监控与对账

重点监控：

- HTTP 200 / 202 比例；
- `queued`、`in_progress`、`unknown`、`failed`、`completed` 数量与耗时；
- 轮询 429、查询错误和任务超时；
- `billing_state` 的 `pending`、`failed`、`debt`；
- 失败退款、超时退款、计费补偿和上游超发图片。
- `sending` 陈旧数、create unknown 数、hold 金额/年龄；unknown 不存在到期自动释放；
- `reconciliation_required` 数量/年龄、`provider_contract_failure` 与
  `upstream_outcome_unresolved`。

必须按客户模型、渠道和 converter 配置以下告警：

| 指标 | Warning | Paging / 自动动作 |
| --- | --- | --- |
| 单笔 exposure 金额 | 达到审批阈值 | 达到高风险阈值时暂停对应客户模型新流量 |
| 单位时间 exposure 金额/数量 | 超过正常基线 | 超过发布阈值时 paging |
| unknown 人工核实积压 | 连续窗口异常 | 通知技术人员核实 Provider 任务与账单 |
| 最老 `sending/unknown/reconciliation_required` 年龄 | 接近资金或任务 SLA | 达到 SLA 立即 paging |

阈值必须在渠道上线审批中填写，不能留空。新 converter 首期灰度时，任何
`provider_contract_failure` 或
`upstream_outcome_unresolved` 都立即 paging。

自动停用前不计算候选交集，也不寻找替代渠道。若异常渠道是某客户模型的唯一实现，立即停止该模型的
新流量；不得临时切换到不支持同一同步/异步、字段或计费合同的渠道。恢复必须人工完成 exposure 与
上游账单对账、根因修复、合同回归和内部灰度；指标回落本身不能自动重新启用。

必须人工对账：

| 情况 | 操作 |
| --- | --- |
| 上游可能已接受但本站未取得任务 ID | 不自动重提或退款；技术人员根据 request ID 核实。明确未创建后人工拒绝并释放，取得可信 task ID 后人工恢复成功事实 |
| 已取得上游任务 ID但本站 Task 写入失败 | 不重新 POST；查询上游终态并登记人工对账 |
| 本站退款后上游晚成功 | 核对退款、上游账单和结果，按运营政策处理差额 |
| usage 与真实账单不一致 | 关闭动态计费，回退固定价并保留脱敏证据 |

对账记录只保存本站 request ID、平台 task ID、脱敏上游请求/任务 ID、最终状态和资金处理结果。

## 8. 回滚

1. 从生产分组移除异常客户模型或渠道。
2. 保留 `UPDATE_TASK=true`，让在途任务继续查询和结算。
3. 保留共享补偿调度器对陈旧 sending 和 reconciliation 的扫描；unknown 不做自动退款或恢复。
4. 价格异常时回退最近一次已验收固定价。
5. 不删除 Task、attempt、幂等记录或消费日志。
6. 完成在途任务、exposure 与上游账单对账后再恢复。
