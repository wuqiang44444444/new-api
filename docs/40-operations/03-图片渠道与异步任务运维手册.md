# 03 图片渠道与异步 Provider 运维手册

> 本手册描述当前普通图片渠道。FunCloud 的 Provider 异步任务只在一次请求内由 adaptor 轮询，Moxing
> 使用一次同步 POST；两者都继续返回原生图片响应，
> 不创建平台图片 Task，也不提供 `/v1/images/tasks/:task_id`。代码已存在不等于生产已上线；上线前
> 仍需完成真实 Provider、价格、超时和退款灰度验收。

## 1. 创建统一图片中转渠道

管理端只选择「图片中转」（`ChannelType=62`），然后显式选择一个上游协议。每条渠道只能使用一个协议；
需要同时使用 FunCloud 和 Moxing 时创建两条渠道，不能在同一条渠道中混放 Provider 模型。

### 1.1 FunCloud

选择 `funcloud_aigc_v2`：

```text
Base URL: https://mm-internal-cn.leonecloud.com
API Key:  <FunCloud API key>
Models:   nano-banana-2-lite,nano-banana-2,seedream-5.0-lite,seedream-5.0-pro
```

### 1.2 Moxing

选择 `moxing_images_v1`：

```text
Base URL: https://www.moxing.pro
API Key:  <Moxing API key>
Models:   seedream-5-moxing,seedream-5-pro-moxing
ModelMapping:
  seedream-5-moxing     -> doubao-seedream-5-0-260128
  seedream-5-pro-moxing -> doubao-seedream-5-0-pro-260628
Test model: seedream-5-moxing
```

两种协议都允许管理员使用客户自定义模型名，并通过 `model_mapping` 精确映射到所选协议登记的 Provider
模型。协议选择、Models、ModelMapping 和价格是彼此独立的管理员配置；代码不生成、补齐或改写 mapping。
客户模型直接使用 Provider 模型名时可省略对应映射。body pass-through 必须关闭，Param Override、
Advanced Custom route 和模型抓取均不得配置。

Moxing Lite/Pro 代码合同都固定为 `2K`、`n=1`、URL 响应；客户固定价可分别配置为
`0.035 USD/次` 和 `0.09 USD/次`，但这些价格不代表供应商成本已经验真。渠道在真实 Provider 与账单验收
前保持手工禁用；参考图、组图、联网搜索、stream、任意尺寸以及 Pro `1K` 保持未发布。

## 2. 部署闸门

1. `RELAY_TIMEOUT` 必须为有限正数；建议按真实 P99 加安全余量配置。`0` 表示无整体应用层上限，
   不得用于上线该渠道。
2. 分别完成 FunCloud/Moxing 价目、失败扣费/退款、余额不足和输入图收费规则的书面核实；一个 Provider
   的证据不能替代另一个。
3. 当前仅灰度固定规格文生图；Moxing Lite/Pro 都只有 `2K` 单图。参考图、高规格、高质量、Pro `1K`
   和组图在计费规则核实并实现预扣前不得开放。
4. 两种协议都关闭透传请求体且 Param Override 为空；Header Override 首次上线保持为空；Base URL 使用
   所选协议的站点根地址。
5. 观测请求耗时、`RELAY_TIMEOUT` 命中率、HTTP 400/429/502/504、Provider code 及退款成功率。

### 2.1 从独立 Moxing 类型升级

该升级不能与仍会读写旧类型 63 的版本滚动混跑：

1. 备份主数据库，并在相同数据库引擎的生产等价副本上完成一次演练；
2. 摘除流量并停止全部旧版本实例，确认没有旧管理端或自动任务继续写 Channel；
3. 先启动一个新版本 master，由其完成 `migration.image_relay_protocol_v1`；迁移遇到非法 settings、
   Param Override 或冲突协议时会整体回滚，必须先修正对应渠道再重试；
4. 确认 marker 为 `done`、旧类型 63 计数为零，并抽查旧 62/63 渠道的协议、Base URL、Models、mapping、
   Key、分组、价格和 Ability；settings 中与协议无关的扩展字段必须仍然存在；
5. master 启动检查通过后再启动其它新版本节点。每个节点都会只读验证迁移结果，验证失败的节点不得接流量；
6. 全部新节点健康后恢复业务流量。不得通过恢复类型 63 alias、运行时 fallback 或手工跳过 marker 解除阻塞。

## 3. 北向请求合同

```http
POST /v1/images/generations
Authorization: Bearer <customer-key>
Content-Type: application/json
```

允许的通用字段为 `model`、`prompt`、`n=1`、`size`、`quality`、`response_format=url`、
`output_format` 和 `extra_fields`。当前 `nano-banana-2` 只允许 1K，`seedream-5.0-lite`
只允许 2K/basic，`seedream-5.0-pro` 只允许 1K/basic；`extra_fields.reference_images`
明确返回 `400`。`callbackUrl`、Base64、`stream` 和其它未知字段也必须返回 `400`。

渠道 adaptor 会校验模型专属 prompt 长度、固定规格和宽高比。参考图能力未发布，不进行远程探测或
额外下载；待 input-image 计费核实后再单独实现。

Moxing 只接受 `model`、`prompt`、省略或为 `1` 的 `n`、省略或为 `2K` 的 `size`，以及省略或为
`url` 的 `response_format`。其它图片字段、显式提交的 `stream`（包括 `false`）和未知字段均应在发送前
返回 `400`；管理端渠道测试必须使用图片生成 endpoint，并根据精确 Provider 映射生成 `2K` 请求。

## 4. 等待、超时与重试

- 创建成功后 adaptor 立即查询一次；Provider 仍为 `processing/queued` 时，前 30 秒每 3 秒、之后
  每 5 秒查询一次。
- 总等待受 `RELAY_TIMEOUT` 和本次请求 context 共同限制；命中任一边界返回 HTTP `504`。
- 超时、取消、非法响应、空结果或多结果均沿用普通同步图片失败/退款语义。
- 不自动重发、跨渠道重试或把 Provider task ID 暴露给客户。调用方如需重试，应由业务自行决定，
  并承担可能的重复生成风险。
- Moxing 只发送一次同步 POST；网络错误、超时、Provider 4xx/5xx、非法响应和结果合同错误均不得自动
  重发或换到 FunCloud。`504` 不能证明 Provider 未受理或未计费。

## 5. 故障处置

| 现象 | 处置 |
| --- | --- |
| 大量 `504` | 核对 `RELAY_TIMEOUT`、Provider P99 和网络代理；必要时先停用渠道 |
| `10002` | 修正客户模型参数或请求字段，不能通过 Header/Param Override 绕过校验 |
| `10005/40001/90003` | 核对 API Key、FunCloud 余额和 Provider 状态；不切换其它渠道掩盖故障 |
| 成功响应非单 URL | 立即停用受影响模型并保留脱敏错误日志，等待协议核实 |
| 退款失败 | 按现有同步计费补偿流程处理；该渠道没有图片 Task 对账入口 |
| Moxing 返回 `429` | 保持禁止重试，核对供应商限流与流量分组；不得临时打开 fallback |
| Moxing 鉴权/余额错误 | 核对 KEY 和供应商余额；客户只接收脱敏 `502`，日志不得记录原始响应或 KEY |

真实 Provider 验收至少分别覆盖：FunCloud 四模型和 Moxing Lite/Pro 固定规格文生图、错误码、超时/取消、
单 URL 响应、预扣/结算/失败退款、供应商账单以及有限 `RELAY_TIMEOUT`。Moxing 还需确认同步超时或
客户端取消后是否已受理并计费；完成前保持禁用。
