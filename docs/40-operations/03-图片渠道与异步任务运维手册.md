# 03 图片渠道与异步任务运维手册

## 1. 当前公开 SKU

| 公开模型 | 上游模型 | 上游路径 | Converter |
| --- | --- | --- | --- |
| `seedream-5-moxing` | `seedream-5-0-260128` | `/v1/images/generations` | `media_task_image_blocking` |
| `nano-banana-2` | `gemini-3.1-flash-image-preview-usage` | `/v1/media/generations` | `media_task_image_blocking` |
| `seedream-5-qihang` | `seedream-5` | `/v1/images/generations` | `none` |

客户端统一使用：

```text
POST /v1/images/generations
GET  /v1/images/tasks/:task_id
```

价格、渠道 `Models`、路由 `models` 和模型映射必须使用同一个公开模型名。

## 2. Moxing 图片渠道

新建独立 `Advanced Custom` 渠道：

```text
Base URL: https://www.moxing.pro
API Key:  <Moxing Key>
Models:   seedream-5-moxing,nano-banana-2
```

选择模板“TokenSave / Moxing Images”，确认配置为：

```json
{
  "advanced_routes": [
    {
      "incoming_path": "/v1/images/generations",
      "upstream_path": "/v1/images/generations",
      "converter": "media_task_image_blocking",
      "models": ["seedream-5-moxing"],
      "auth": {
        "type": "header",
        "name": "Authorization",
        "value": "Bearer {api_key}"
      }
    },
    {
      "incoming_path": "/v1/images/generations",
      "upstream_path": "/v1/media/generations",
      "converter": "media_task_image_blocking",
      "models": ["nano-banana-2"],
      "auth": {
        "type": "header",
        "name": "Authorization",
        "value": "Bearer {api_key}"
      }
    }
  ]
}
```

模型映射：

```json
{
  "seedream-5-moxing": "seedream-5-0-260128",
  "nano-banana-2": "gemini-3.1-flash-image-preview-usage"
}
```

## 3. Qihang 图片渠道

Qihang 图片使用独立 `Advanced Custom` 渠道，不修改承载聊天模型的既有渠道：

```text
Models: seedream-5-qihang
```

```json
{
  "advanced_routes": [
    {
      "incoming_path": "/v1/images/generations",
      "upstream_path": "/v1/images/generations",
      "converter": "none",
      "models": ["seedream-5-qihang"],
      "auth": {
        "type": "header",
        "name": "Authorization",
        "value": "Bearer {api_key}"
      }
    }
  ]
}
```

模型映射：

```json
{
  "seedream-5-qihang": "seedream-5"
}
```

TokenSave 如需上线，必须先建立独立公开 SKU，完成真实生成、异步任务和账单验收；不要直接复用 Moxing 的公开 SKU。

## 4. 渠道开关

所有图片专用渠道确认：

- 请求体透传：关闭；
- 跳过异步轮询延迟：生产关闭；
- Header Override：不用于本路由鉴权；
- 参数覆盖：首次上线保持为空；
- Base URL：只填站点根地址，不以 `/` 结尾；
- 路由只加入上游已开通的模型。

后台任务：

```text
UPDATE_TASK=true
TASK_TIMEOUT_MINUTES=1440
```

`TASK_TIMEOUT_MINUTES` 至少大于上游任务 P99/SLA 加安全余量。

## 5. 计费门禁

1. 在“模型定价”按公开 SKU 配置审批后的固定 `ModelPrice`。
2. 每个尺寸分别核对上游成本和本站售价。
3. `nano-banana-2` 的 1K、2K、4K 未全部完成价格覆盖前，只开放已验收尺寸和测试分组。
4. 只有真实 usage 与上游账单一致、且已配置可信预扣 Token 上界时，才允许改为动态表达式。
5. usage 异常时立即回退固定价。

## 6. 上线测试

```bash
export API_BASE="https://<本站域名>"
export API_KEY="sk-<测试令牌>"
export RUN_ID="image-<唯一编号>"
```

Moxing Seedream：

```bash
curl -i -sS -X POST "$API_BASE/v1/images/generations" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-seedream" \
  -d '{
    "model": "seedream-5-moxing",
    "prompt": "白色桌面上的蓝色陶瓷杯，产品摄影",
    "size": "2K",
    "n": 1,
    "response_format": "url"
  }'
```

Nano 异步：

```bash
curl -i -sS -X POST "$API_BASE/v1/images/generations" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Prefer: respond-async" \
  -H "Idempotency-Key: ${RUN_ID}-nano" \
  -d '{
    "model": "nano-banana-2",
    "prompt": "绿色叶子图标，白色背景",
    "size": "1K",
    "n": 1,
    "response_format": "url"
  }'
```

Qihang Seedream：

```bash
curl -i -sS -X POST "$API_BASE/v1/images/generations" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${RUN_ID}-qihang" \
  -d '{
    "model": "seedream-5-qihang",
    "prompt": "极简风格的未来城市海报",
    "size": "2K",
    "n": 1,
    "response_format": "url"
  }'
```

HTTP `200` 时核对 `data[].url`。HTTP `202` 时保存 `Location` 或响应中的 `task_xxx`：

```bash
curl -sS "$API_BASE/v1/images/tasks/<task_id>" \
  -H "Authorization: Bearer $API_KEY"
```

通过标准：

- 三个公开 SKU 分别命中正确渠道和上游模型；
- HTTP 200 和 202 均按预期处理；
- 异步任务进入 `completed`，结果位于 `result.data[].url`；
- 异步 Task 使用同一幂等 Key 重放时不重复创建或扣费；
- 同步 HTTP 200 不提供结果回放，成功后不要再次提交；
- 失败和超时只退款一次；
- 用量日志中的图片数量、尺寸、分组和最终费用正确。

## 7. 监控与对账

重点监控：

- HTTP 200 / 202 比例；
- `queued`、`in_progress`、`unknown`、`failed`、`completed` 数量与耗时；
- 轮询 429、查询错误和任务超时；
- `billing_state` 的 `pending`、`failed`、`debt`；
- 失败退款、超时退款、计费补偿和上游超发图片。

必须人工对账：

| 情况 | 操作 |
| --- | --- |
| 上游可能已接受但本站未取得任务 ID | 不自动重提；复用原幂等 Key，查请求日志和上游请求 ID |
| 已取得上游任务 ID但本站 Task 写入失败 | 不重新 POST；查询上游终态并登记人工对账 |
| 本站退款后上游晚成功 | 核对退款、上游账单和结果，按运营政策处理差额 |
| usage 与真实账单不一致 | 关闭动态计费，回退固定价并保留脱敏证据 |

对账记录只保存本站 request ID、平台 task ID、脱敏上游请求/任务 ID、最终状态和资金处理结果。

## 8. 回滚

1. 从生产分组移除异常公开 SKU 或渠道。
2. 保留 `UPDATE_TASK=true`，让在途任务继续查询和结算。
3. 价格异常时回退最近一次已验收固定价。
4. 不删除 Task、幂等记录或消费日志。
5. 完成在途任务与上游账单对账后再恢复。
