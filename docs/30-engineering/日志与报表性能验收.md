# 日志与报表性能验收

## 适用范围与前置条件

适用于控制台使用日志读取、日账单和日用量后台生成、客户账单明细导出。用隔离数据副本准备可追溯的来源行数、
资金总额与已发布旧代际。固定构建版本、数据库参数、数据分布、缓存预热、连接池和负载曲线。
保留单钱包和多钱包负载，先确认对照组没有排队饱和，再测量突增和回落。使用执行真实授权、结算和入库的路径。

## 验收步骤

1. **使用日志**。从浏览器网络和数据库观测核对最近一小时、历史窄窗、跨日、稀疏条件和深页。
   覆盖 0、20、21 条、同秒多条和同 Request ID 多事件。首页和顺序翻页应无精确计数，
   跳页和末页应与显式计数一致。未点击范围统计时统计请求数应为零。同筛选的并行统计数应为零。
   对照个人、管理员的隔离与授权，验证筛选变化、超时保留列表、主动重试和新旧制品混跑。
2. **日报**。在相同快照上交替运行停用后台的基线和启用后台的候选，窗口等长且多轮换序。
   使用开放日期、已结束日期、带旧代际的大日期、历史冻结证据和跨日退款。覆盖候选构建、抢占、恢复、
   最终核验与指针切换。任一来源越界或覆盖下降时，核对旧版本与待办的保护条件。
3. **导出**。用相同版本、日期及筛选生成分片。覆盖多百万行、稀疏查找、空范围和部分日期未发布。
   在读取、上传和续跑边界注入压力或执行租约失效，核对已提交分片及进度。按冻结来源身份逐行核对请求、
   入账时间、事件类型和金额。另验扣款、退款、净额、分片字节校验及实际对象存储下载。
4. **归因与放行**。同窗对齐 API、钱包结算和日志提交的吞吐、失败率与 P95/P99，记录连接等待、数据库
   等待事件、WAL 和临时文件增量。后台另记有效扫描与写入量、发布时间和积压。使用实际执行计划核对
   过滤行数和堆访问，累计统计先计算同一观测窗的增量。候选仍无进展的窗口仅用于说明已观测到的前台表现。
   前台保护、后台进度和账务正确性分别验收。阈值取自目标业务基线，发布操作见
   [计费与分组运维手册](../40-operations/01-计费与分组运维手册.md#日报数据库预算与灰度)。

## 回归命令

在仓库根目录验证分页、日汇总覆盖、后台准入、导出接管及告警邮件的领取顺序。

```bash
go test ./controller ./model ./service -run 'Test(UsageLog|LogDeferredPagination|DeferredUsageLog|DailyReport|SharedReportSlot|StatementDetails|ChannelAlertMail)'
```

在 `web/` 验证范围统计请求触发与重试。

```bash
bun run test src/features/usage-logs/components/__tests__/range-statistics.test.tsx
```

故障复现需关联请求 ID、实例和时间窗。共用一台宿主的多个网关进程应在日志中能够独立识别。
跨数据库按部署所用引擎分别核对执行计划和语义，隔离回归结果与目标环境发布证据分别记录。
