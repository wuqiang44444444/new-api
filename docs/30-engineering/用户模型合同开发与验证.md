# 用户模型合同开发与验证

## 1. 最小接线约束

合同主体必须放在独立 `customer_contract` 文件。NEWAPI 原生热路径只允许鉴权上下文字段、分发前守卫、
模型/价格接口早返回、舍入前合同乘数和异步快照接线。`contract_mode=false` 必须直接保留原生分支。

新增计费路径需要同时验证预扣、终态、退款/补偿和 quota saturation 审计。固定价音频/Realtime 必须把
`ModelPrice` 传入统一 quota 计算；异步首次终态和补偿必须使用同一已规范化 `ActualTokens`。

## 2. 数据库和字符串语义

折扣只用八位定点整数持久化。模型授权使用精确字符串；同一合同拒绝仅大小写不同的重复模型，避免依赖
MySQL 默认不区分大小写排序规则。所有事务、迁移和查询必须同时支持 SQLite、MySQL 5.7.8+ 与
PostgreSQL 9.6+。

完整替换事务使用 `lockForUpdate` 锁用户行。渠道/Ability 可用性批量校验应在用户行锁外完成；请求时仍
必须重新按当前渠道状态失败关闭。

## 3. 必测回归

- 原生异步非表达式终态保留当前 `GroupRatio` 和 `GroupGroupRatio[group][group]` 行为。
- 合同 Task 使用冻结模型倍率、组倍率和合同折扣；改价不影响运行中 Task。
- 特定 Channel、普通分发、Seedance 和已解析异步模型都执行合同白名单与 Token 模型限制交集。
- 可用模型查询排除停用 Channel，并按大小写精确匹配。
- `expected_version` 冲突、缓存版本不一致和数据库失败均失败关闭。
- 固定价、token、tiered、图片、音频、Realtime、异步、工具附加费覆盖公式回归。
