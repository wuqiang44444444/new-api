# 用户模型合同开发与验证

## 1. 接线约束

合同主体放在 `customer_contract_*` 文件，原生入口保留状态解析、候选读取、发送前校验/计费和投影
窄接线。唯一范围政策是 `EffectiveContractRules`，唯一优先级/权重算法仍是原生选择器。
无合同和停用合同的请求不得进入合同候选分支。具体接线面见[专题架构](../20-architecture/账单计费-用户模型合同定价架构.md)。

## 2. 数据与资金

同模型同渠道唯一、同模型同折扣、大小写精确、八位定点、版本乐观锁和事务审计保持不变。
本次无需新表/迁移；已有索引迁移须继续兼容 SQLite、MySQL、PostgreSQL。数据库读取失败不可伪装
成组合无效或原生模式。已接受来源失效只影响履约，不阻止编辑和停用。

计费必须完整追踪预估、补充预扣、结算与退款；同请求折扣和基础计价事实保持冻结，组相关字段按
真实选中组合刷新。不同资金策略的实际预扣和估算目标不得混淆。durable attempt、异步图片和 Batch
的原子 hold 不得再叠加请求级预扣。unknown 禁止自动换渠/退款；历史任务不按当前合同重新授权计价。

## 3. 必测边界

- Default 用户及 default/已失效组选路 Key 可用合同内部有效组，不要求用户可用组包含合同组；
  Key 模型排除、合同组倍率缺失、渠道失效或范围外来源仍须失败关闭。
- 缓存开/关均使用完整候选和原生优先级/权重；2+1 跨组分布与对应完整原生候选抽样一致。
- 范围外 pin/亲和、Playground 覆盖、后解析模型和重试不得越界；跨组重试开关按首次实际组约束。
- 未列模型/失效组合失败，停用/解绑恢复原生；读取、归属、版本、折扣和缓存围栏异常失败关闭。
- 同步与 Task 固定价/token/表达式使用真实组；涨价补差、降价终态退差、免费转付费、付费转免费、
  信任、钱包欠费、订阅和 Key 额度失败覆盖资金不变量。工具费用保留原边界。
- 新 remix 使用当前合同与锁定渠道；历史任务/文件查询、下载、取消不依赖现存选路组或合同，
  但仍拒绝跨用户/应用访问；Realtime、模型发现和素材操作不得误入历史例外。
- 只改合同 Key 名称时，失效组、超出现行数量限制的既有 Auto 顺序及重试设置保持不变；修改路由仍校验。
- Gemini thinking 通配模型限制下，合同发现、报价和执行授权保持一致。
- Seedance/Batch 无 Ability 也能按自身资格服务。
- 模型发现/详情、普通/Batch 报价与执行范围一致；合同明细保留失效条款，不公开内部身份。

建议按改动边界执行：

```bash
go test ./model ./middleware ./controller ./service ./relay ./relay/helper
go build ./...
cd web && bun run typecheck && bun run test && bun run i18n:sync
task docs:check
task ai:check
```

服务端数据库测试只允许专用空库，分别配置 `TEST_CUSTOMER_CONTRACT_MYSQL_DSN` 与
`TEST_CUSTOMER_CONTRACT_POSTGRES_DSN`；未配置为跳过。变更 relaykit 时另行独立构建。
公开 API 文档变更执行 `cd web && bun run docs:validate`。

## 4. 升级与发布核对

升级前只读盘点启用合同规则、绑定 Key、失效渠道/组、原生 Key 组配置、未列模型的既有流量、跨组价格
及重试开关。不得自动修改权限、绑定或重试开关。内部合同组无需向普通 Key 开放；禁止为合同履约批量扩大用户的原生组权限。
停用后的 Key 原生组也须确认可用；回滚旧代码恢复纯折扣语义，不能宣称仍有合同范围保护。

避免新旧实例同时处理同一批合同请求。按实际日志/账单核对渠道、组、折扣、预扣和结算；真实 Provider、
账单、外部数据库及灰度结果分别记录，不由本地测试推断上线成功。历史图片折扣为 1 的核查独立处理，
本功能不授权历史重算或退款。
