# 用户模型合同开发与验证

## 1. 最小接线约束

合同主体必须放在独立 `customer_contract` 文件。NEWAPI 原生热路径只允许鉴权上下文字段、分发前折扣
解析守卫、价格接口早返回投影、舍入前合同乘数和异步快照接线。合同只提供折扣：原生热路径不得因合同
设置组、pin 渠道、过滤候选或改变重试；Key 未绑定或绑定停用合同时必须直接保留原生分支。

新增计费路径需要同时验证预扣、终态、退款/补偿和 quota saturation 审计。固定价音频/Realtime 必须把
`ModelPrice` 传入统一 quota 计算；异步首次终态和补偿必须使用同一已规范化 `ActualTokens`。

## 2. 数据库和字符串语义

折扣只用八位定点整数持久化。折扣匹配使用精确公开模型字符串；同一合同拒绝仅大小写不同的重复模型
名，避免依赖 MySQL 默认不区分大小写排序规则。规则唯一键为 `contract_id + public_model + channel_id`，
历史 `contract_id + public_model` 唯一索引由 `migrateCustomerContractEntityRuleIndex` 显式删除。
同一合同同一公开模型的所有规则折扣必须一致；所有事务、迁移和查询必须同时支持 SQLite、
MySQL 5.7.8+ 与 PostgreSQL 9.6+。

完整替换事务使用 `lockForUpdate` 锁合同行。渠道引用校验只针对新增或变更的来源三元组；存量来源渠道
后续不可用或原组被删除不得取消折扣，也不得阻止修改折扣、停用或重新启用合同。

## 3. 必测回归

- 原生异步非表达式终态保留当前 `GroupRatio` 和 `GroupGroupRatio[group][group]` 行为。
- 合同 Task 使用冻结合同折扣与实际执行事实；改价、换绑和合同修改不影响运行中 Task。
- 绑定合同不改变原生分发结果、优先级、权重、重试与 Token 模型限制；未列出模型回退原生价格；
  Seedance、普通分发和任务后解析路径都只冻结折扣事实。
- 可用模型查询排除停用 Channel，并按大小写精确匹配。
- `expected_version` 冲突、缓存版本不一致和数据库失败均失败关闭。
- 固定价、token、tiered、图片、音频、Realtime、异步、工具附加费覆盖公式回归。

新增验证要求：

- 对比合同绑定前后原生渠道优先级胜出结果，分别覆盖内存缓存开与关；不能仅断言命中任一候选。
- 同一合同保存普通与 Batch 同名同折扣来源，分别核对基础价格；Batch 定价接口同时验证会话和 Key。
- 合同查询的业务失败信封不能显示成无合同；编辑未绑定 Key 不自动改绑；客户明细由后端去重。
- 数据库升级演练先构造旧唯一索引并写入单渠道规则，再执行迁移与 AutoMigrate 两次，校验旧行不变、
  同模型不同渠道可插入、同模型同渠道仍拒绝。服务端测试只允许专用空库；分别配置
  `TEST_CUSTOMER_CONTRACT_MYSQL_DSN`、`TEST_CUSTOMER_CONTRACT_POSTGRES_DSN`，未配置时为跳过。
- 升级核对存量 Key 原组、模型限制和指定渠道 pin；原生 pin 分支的限制检查语义保持原样，
  不再叠加此前合同门的模型检查，需针对存量配置记录实际影响。

## 4. 管理员总览入口

管理员合同总览使用独立的 `GET /api/customer-contracts` 路由，仅允许管理员访问，支持 `keyword`、
`status`、分页和汇总字段。它只检索已建立的客户合同，不创建第二套合同事实；详情、编辑、选项和审计
继续复用 `/api/user/:id/contract*` 接口。新增或修改该入口时，必须同时验证未授权拒绝、状态筛选、
分页稳定性和与用户侧边栏读写结果一致。

建议签入前执行：

```bash
go test ./model ./middleware ./controller ./service ./relay/helper
go vet ./...
go build ./...
cd web && bun run typecheck && bun run test && bun run i18n:sync
task docs:check
task ai:check
```

真实 Provider、真实账单、最低数据库版本和灰度验收仍由发布流程完成，不得由单元测试结论替代。
