# 本地搭建

## 前置条件

根模块使用 Go 1.26。安装 Bun、Docker Compose、`lsof` 和 `curl`。
使用开发库前确认端口与数据卷归属。

## 开发启动

开发 PostgreSQL 由本仓库的 `docker-compose.dev.yml` 启动，Compose 项目名为 `yuan-gateway`。
数据库名为 `yuan_gateway_dev`，宿主机地址为 `127.0.0.1:54330`，数据卷为 `yuan-gateway_dev_pg_data`。
首次搭建时，在仓库根目录的 `.env` 中设置 `YUAN_DEV_POSTGRES_PASSWORD`。密码可用 `openssl rand -hex 24` 生成，
使用已有数据卷时须沿用初始化该卷的密码。

```dotenv
YUAN_DEV_POSTGRES_PASSWORD=<生成的十六进制密码>
```

从仓库根目录启动数据库和本地服务：

```bash
./start.sh
```

脚本启动或复用 `yuan-gateway` 项目中的 `postgres` 服务，等待容器健康，再用该容器的本机映射端口和密码
生成本次后端进程的 `SQL_DSN`。数据库未就绪或无法取得连接配置时，脚本会在停止旧服务前退出。
默认后端端口 3501、前端端口 3500，`BACKEND_PORT`、`FRONTEND_PORT` 可覆盖；
`STARTUP_TIMEOUT` 默认为 300 秒。前后端端口必须是 1—65535 的整数，且与 PostgreSQL 发布端口互不相同；
超时必须为 1—2147483647 的整数秒，避免超长输入导致计时算术溢出。
脚本先完成全部参数校验；配置不合法时直接退出，不停止正在运行的进程。

有效配置下，脚本停止两个配置端口上的原监听进程：先 TERM，最多等 5 秒，仍占用则 KILL，
释放成功后重启服务。运行前应确认配置端口就是本次要重启的服务端口。
前端依赖不存在时安装锁定依赖，缺少开发嵌入入口时创建占位入口；后端 `/api/status` 明确成功后
才启动前端，前端就绪后持续监控。每次启动会打印独立的 `logs/start-<后端端口>.<随机后缀>/` 目录，
`backend.log` 和 `frontend.log` 都写入该目录，终端也从这里读取日志。
启动失败、任一服务运行退出、SIGINT 或 SIGTERM 均清理本次启动的进程组与子进程。

前端仅监听本机回环地址，默认访问 `http://localhost:3500`。需要验证 HTTPS 时，将证书和私钥分别保存为
`web/.tls.local/localhost.pem` 和 `web/.tls.local/localhost-key.pem`，使用
`LOCAL_DEV_HTTPS=1 bash start.sh` 启动。用 `https://localhost:3500` 访问时，证书须覆盖
`localhost` 并受浏览器信任。保留证书文件也可以按默认方式启动 HTTP。

## 隔离验证

`python3 scripts/test_start_script.py -v` 使用临时目录、随机端口和一次性测试服务，覆盖 Compose 数据库选择、
停止占用者后重启、错误配置保留旧进程、健康检查失败、编译失败、孤儿子进程清理、运行退出和信号后再次启动。
不需要启动真实项目或更改实际服务端口。语法检查使用 `bash -n start.sh`。

其他环境与生产配置应按[命令清单](命令清单.md)及运维目录执行；此脚本不承担密钥迁移和生产部署。
