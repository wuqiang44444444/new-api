# 本地搭建

## 前置条件

根模块使用 Go 1.26。安装 Bun、Docker Compose、`lsof` 和 `curl`。
使用开发库前确认端口与数据卷归属。

## 开发启动

开发 PostgreSQL 由本仓库的 `docker-compose.dev.yml` 启动，Compose 项目名为 `yuan-gateway`。
数据库名为 `yuan_gateway_dev`，宿主机地址为 `127.0.0.1:54330`，数据卷为 `yuan-gateway_dev_pg_data`。
首次搭建时，在仓库根目录的 `.env` 中设置以下两项。密码可用 `openssl rand -hex 24` 生成，
使用已有数据卷时须沿用初始化该卷的密码。

```dotenv
YUAN_DEV_POSTGRES_PASSWORD=<生成的十六进制密码>
SQL_DSN=postgresql://yuan_gateway:${YUAN_DEV_POSTGRES_PASSWORD}@127.0.0.1:54330/yuan_gateway_dev?sslmode=disable&application_name=yuan-gateway-dev
```

从仓库根目录启动数据库和本地服务：

```bash
docker compose -p yuan-gateway -f docker-compose.dev.yml up -d --wait postgres
bash start.sh
```

环境中的 `SQL_DSN` 优先于 `.env`。
缺少连接配置或 URL 不是 `postgres://` 或 `postgresql://` 格式时，脚本会在停止旧服务前退出。
默认后端端口 3501、前端端口 3500，`BACKEND_PORT`、`FRONTEND_PORT` 可覆盖；
`STARTUP_TIMEOUT` 默认为 300 秒。端口必须是 1—65535 的整数、两端口不能相同；
超时必须为 1—2147483647 的整数秒，避免超长输入导致计时算术溢出。
脚本先完成全部参数校验；配置不合法时直接退出，不停止正在运行的进程。

有效配置下，脚本停止两个配置端口上的原监听进程：先 TERM，最多等 5 秒，仍占用则 KILL，
释放成功后重启服务。运行前应确认配置端口就是本次要重启的服务端口。
前端依赖不存在时安装锁定依赖，缺少开发嵌入入口时创建占位入口；后端 `/api/status` 明确成功后
才启动前端，前端 HTTP 就绪后持续监控。日志分别写入 `logs/backend.log` 和 `logs/frontend.log`。
启动失败、任一服务运行退出、SIGINT 或 SIGTERM 均清理本次启动的进程组与子进程。

## 隔离验证

`python3 scripts/test_start_script.py -v` 使用临时目录、随机端口和一次性测试服务，覆盖停止占用者后重启、
错误配置不停止旧进程、健康检查失败、编译失败、孤儿子进程清理、运行退出和信号后再次启动。
不需要启动真实项目或更改实际服务端口。语法检查使用 `bash -n start.sh`。

其他环境与生产配置应按[命令清单](命令清单.md)及运维目录执行；此脚本不承担密钥迁移和生产部署。
