# 素材库对接指南

## 1. 边界

平台是官方或第三方素材库的中转代理，不保存媒体二进制，也不自建真人认证表单。客户只接触
`ast_*`、`astgrp_*` 和 `asset://ast_*`，不接触 Provider 资源 ID、账号、Region、Project 或凭据。

资源按 `user_id + app_id` 隔离；当前 Token ID 作为 `app_id`。素材创建时冻结客户模型、Seedance
Channel、素材协议和凭据身份，不跨模型、渠道、账号或区域复用。

## 2. 接口

```text
POST   /v1/asset-groups
GET    /v1/asset-groups
GET    /v1/asset-groups/{group_id}
DELETE /v1/asset-groups/{group_id}

POST   /v1/assets
GET    /v1/assets
GET    /v1/assets/{asset_id}
PATCH  /v1/assets/{asset_id}
DELETE /v1/assets/{asset_id}
```

所有接口使用平台 Bearer Token。创建请求不支持 `Idempotency-Key`；每次 POST 都表示一次新建操作，
客户端超时后不得自动重发。

## 3. 创建普通素材组

```json
{
  "name": "产品素材",
  "description": "广告片素材",
  "group_kind": "general",
  "model": "seedance-global"
}
```

平台根据 `model` 找到唯一启用的 Seedance Channel，再由代码化 `asset_upstream_protocol` 调用固定上游。
响应 ID 为 `astgrp_*`，状态只有 `processing`、`ready`、`failed` 或 `deleted`。

## 4. 真人素材组

创建时使用 `group_kind=real_person`：

```json
{
  "name": "演员认证",
  "group_kind": "real_person",
  "model": "seedance-global",
  "redirect_url": "https://client.example.com/verified"
}
```

平台返回上游 `verification_url`；用户直接在官方或第三方页面完成认证。平台不接收人脸、证件、活体或
授权表单。`GET /v1/asset-groups/{group_id}` 会向固定上游刷新状态。认证尚未产生 Provider Group ID 时，
删除只删除平台记录，不表示取消了上游认证会话。

## 5. 创建素材

源只接受有足够有效期的公网 HTTPS URL：

```json
{
  "name": "产品正面图",
  "asset_kind": "general",
  "media_type": "image",
  "model": "seedance-global",
  "asset_group_id": "astgrp_example",
  "source": {
    "type": "url",
    "url": "https://cdn.example.com/product.png?signature=...",
    "expires_at": 1786300000
  }
}
```

源 URL 只存在于当前请求内存，不写入数据库。真人素材必须是图片、必须指定同模型且已 `ready` 的
真人素材组。普通素材若指定素材组，组类型也必须与素材类型一致。

取得可信 Provider Asset ID 后平台返回 `ast_*`。未取得可信 ID 时请求失败、不创建本地资源，并记录
脱敏技术日志；系统不建立 `create_unknown`、自动重试或核查队列。

## 6. 在视频中引用

ModelArk V3 请求使用：

```json
{"type":"image_url","image_url":{"url":"asset://ast_example"}}
```

Resolver 校验 `user_id + app_id`、`ready` 状态、客户模型、Channel、协议和凭据身份，然后改写为固定
Provider 引用。HTTP/HTTPS URL 与 Data URL 可直接作为请求媒体，但不会自动获得素材身份或迁移语义。

## 7. 查询和删除

- 单资源 GET 刷新固定 Provider 状态；列表以主数据库为准，不逐项访问 Provider。
- 删除只调用创建时的固定 Channel 和 adapter，不重新选渠。
- Provider 未明确确认删除时返回失败并保留本地状态；不自动重试、不切换渠道、不建设核查机制。
- 渠道存在活动素材时不得原地更换凭据、协议、Region 或 Project；应新建渠道。

## 8. 上游扩展

管理员只选择代码中已登记的 `asset_upstream_protocol`，不配置 JSON 映射。第三方中转通常只配置
Base URL 和平台 Key；官方直连所需字段由对应 adapter 定义。新上游完全兼容已有协议时可直接配置，
不兼容时由技术人员新增代码 adapter。
