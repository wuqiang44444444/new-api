# 素材库对接指南

## 1. 目的与适用范围

本文描述当前 new-api 已实现的平台素材库和真人授权北向合同，供客户端、SDK 和业务系统接入。

素材库属于平台控制面，只提供一套供应商中立的 API、平台资源 ID、状态、错误和生命周期合同。客户端不接触南向 profile、渠道 ID、上游账号、真实素材 ID、素材组 ID、Action/Version、签名算法或 Provider 凭据。

本文不描述视频创建、查询和下载合同。Seedance、Kling、即梦的视频调用方式见[视频模型 API 用户调用指南](视频模型API用户调用指南.md)；素材通过该视频模型官方合同规定的媒体字段，以 `asset://ast_...` 形式引用。

平台当前只接受由客户托管的公网 HTTPS 源 URL，不提供素材文件上传、base64 上传、素材内容下载或临时上传桥接，也不会保存或托管素材二进制。

## 2. 通用约定

### 2.1 地址、认证与资源隔离

```text
Base URL: https://api.example.com
Authorization: Bearer <platform-api-key>
```

除真人本人打开的同意和认证页面外，本文接口均使用平台 Bearer Token。

资源归属绑定平台用户，而不是可轮换的 Token 字符串。同一用户的不同 Token 可以访问该用户资源；跨用户访问按资源不存在处理。

### 2.2 内容类型

请求体使用 JSON：

```http
Content-Type: application/json
```

素材创建不接受 `multipart/form-data`，也不提供素材二进制响应。

### 2.3 ID、时间与敏感信息

| 资源 | 对外格式 |
| --- | --- |
| 素材 | `ast_...` |
| 素材绑定 | `ab_...` |
| 真人授权 | `rpa_...` |
| 时间 | Unix 秒 |

客户端只保存平台 ID。普通用户响应不会包含源 URL、上游素材 ID、渠道 ID、Provider profile、凭据指纹或密钥。

### 2.4 幂等

以下创建接口支持 `Idempotency-Key`：

- `POST /v1/assets`
- `POST /v1/assets/{asset_id}/migrations`

规则：

- 同 Key、同请求：返回原素材，不重复调用上游；
- 同 Key、不同请求：返回 `409 idempotency_conflict`；
- 创建幂等记录有效期为 24 小时；
- 网络超时或结果不确定时复用原 Key，不要换 Key 重建。

幂等 Key 最长 191 个字符。Key 只用于一次业务操作；创建新素材或发起新迁移时使用新 Key，重试原操作时复用原 Key。

## 3. 接口总览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/v1/assets` | 从公网 HTTPS URL 创建素材 |
| `GET` | `/v1/assets` | 查询素材列表 |
| `GET` | `/v1/assets/{asset_id}` | 查询素材 |
| `PATCH` | `/v1/assets/{asset_id}` | 修改名称 |
| `DELETE` | `/v1/assets/{asset_id}` | 删除素材 |
| `GET` | `/v1/assets/{asset_id}/bindings` | 查询素材绑定 |
| `POST` | `/v1/assets/{asset_id}/migrations` | 用新 URL 创建迁移后的新素材 |
| `POST` | `/v1/real-person-authorizations` | 创建真人授权 |
| `GET` | `/v1/real-person-authorizations/{id}` | 查询并刷新授权 |
| `POST` | `/v1/real-person-authorizations/{id}/retry` | 重试认证 |
| `POST` | `/v1/real-person-authorizations/{id}/revoke` | 撤回授权 |

平台不提供 `complete`、后绑定、素材内容下载或供应商原生素材入口。

## 4. 创建素材

### 4.1 创建普通素材

```bash
curl -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $REQUEST_ID" \
  -d '{
    "name": "reference-image",
    "asset_kind": "general",
    "media_type": "image",
    "model": "seedance-model",
    "source": {
      "type": "url",
      "url": "https://cdn.example.com/signed/reference.png?signature=...",
      "expires_at": 1784785200
    }
  }'
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 1～64 字符 |
| `asset_kind` | 是 | `general` 或 `real_person` |
| `media_type` | 是 | `image`、`video` 或 `audio` |
| `model` | 二选一 | 绑定视频模型 |
| `target` | 二选一 | 规范值为 `management_library`，不参与视频路由 |
| `authorization_id` | 真人素材必填 | 当前用户的有效授权 |
| `source.type` | 是 | 固定为 `url` |
| `source.url` | 是 | Provider 可访问的公网 HTTPS URL |
| `source.expires_at` | 否 | URL 到期 Unix 秒；临时 URL 应提供 |

`model` 与 `target` 必须且只能提供一个。历史输入值 `joycreator_library` 在兼容期会归一化为 `management_library`，新响应和新客户端不得再使用供应商名称。真人素材只能是图片、必须绑定 `model`，并与授权共享用户、模型和 Provider 账号。

普通素材使用 `asset_kind=general`。绑定 `model` 的素材可用于该公开视频模型；`target=management_library` 的素材只进入平台管理素材域，不参与视频路由。

成功返回 HTTP `202`：

```json
{
  "asset": {
    "id": "ast_xxx",
    "name": "reference-image",
    "asset_kind": "general",
    "media_type": "image",
    "model": "seedance-model",
    "status": "processing",
    "created_at": 1784781600,
    "updated_at": 1784781600
  }
}
```

保存 `asset.id`，后续查询、迁移、删除和视频引用均使用该平台 ID。创建响应不会回显源 URL。

### 4.2 素材状态

```text
creating / processing -> ready
creating              -> create_unknown / failed
ready                  -> deleting -> deleted / deletion_failed
```

只有 `ready` 素材可用于新视频。

| 状态 | 客户端动作 |
| --- | --- |
| `creating` / `processing` | 继续查询，建议间隔 5～10 秒 |
| `ready` | 可以查询绑定或用于新视频 |
| `create_unknown` | 保留原 Key 和素材 ID，等待平台对账，不要盲目重建 |
| `failed` | 读取 `error_code`，修正输入或上游配置后使用新 Key 创建 |
| `deleting` | 等待上游清理；该素材已禁止新引用 |
| `deleted` / `deletion_failed` | 不再用于新视频；后者联系运维处理上游残留 |

## 5. URL 安全合同

素材 URL 必须使用 HTTPS、公网地址、无 userinfo、无 fragment、无非 443 端口，并满足渠道配置的最小剩余 TTL。平台拒绝 loopback、私网、link-local、云元数据地址和非 URL 来源。

平台只做控制面校验，不主动 GET/HEAD 源 URL，也不替代 Provider 的 SSRF 防护。创建素材不会使平台保存或托管素材二进制。

如果 `source.expires_at` 非零，平台会在创建前检查剩余有效期。返回 `asset_url_ttl_insufficient` 时，根据 `details.required_min_ttl_seconds` 重新签发更长有效期的单对象 URL。

临时 URL 应至少覆盖 Provider 最晚首次抓取、可能的重复抓取、队列延迟和时钟偏差。客户必须在 Provider 完成抓取前保留源对象及访问权限。

## 6. 查询、改名和删除

### 6.1 列表与详情

```text
GET    /v1/assets?page=1&page_size=20
GET    /v1/assets/{asset_id}
GET    /v1/assets/{asset_id}/bindings
```

列表的 `page_size` 最大为 100，支持以下过滤参数：

- `status`
- `asset_kind`
- `media_type`
- `name`

列表响应：

```json
{
  "data": [
    {
      "id": "ast_xxx",
      "name": "reference-image",
      "asset_kind": "general",
      "media_type": "image",
      "model": "seedance-model",
      "status": "ready",
      "created_at": 1784781600,
      "updated_at": 1784781660
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 20
}
```

绑定列表只返回平台绑定 ID、目标、模型和状态，不返回渠道、Provider profile、上游素材 ID 或凭据。

### 6.2 修改名称

```http
PATCH /v1/assets/{asset_id}
Content-Type: application/json

{"name":"new-name"}
```

名称必须为 1～64 个字符。平台更新名称后返回素材对象；需要同步上游的操作可在后台继续执行。

### 6.3 删除

```http
DELETE /v1/assets/{asset_id}
```

删除成功返回 `204`。本地事务提交后立即禁止新引用，上游清理可异步完成；平台不会删除客户自己的源对象。

## 7. 迁移素材

渠道账号、Project、Region、公开模型或管理目标需要变化时，必须用新的源 URL 创建迁移后的新素材，不能原地修改 binding：

```bash
curl -sS -X POST "$API_BASE/v1/assets/$ASSET_ID/migrations" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $REQUEST_ID" \
  -d '{
    "name": "reference-image-migrated",
    "model": "seedance-model-v2",
    "migration_reason": "move to the new public model SKU",
    "source": {
      "type": "url",
      "url": "https://cdn.example.com/signed/reference-v2.png?signature=...",
      "expires_at": 1784788800
    }
  }'
```

只有 `ready` 素材可以迁移。`migration_reason` 必填，长度为 1～300 个字符且必须位于单行；`migration_batch_id` 可选。`model` 与 `target` 仍必须且只能提供一个。

成功返回 HTTP `202` 和新的 `ast_...`，响应通过 `supersedes_asset_id` 指向旧素材。真人素材迁移必须提供新的或再次确认有效的 `authorization_id`。

## 8. 在视频请求中引用素材

ModelArk v3 使用：

```json
{
  "content": [{
    "type": "image_url",
    "role": "reference_image",
    "image_url": {"url": "asset://ast_xxx"}
  }]
}
```

Kling 图生视频使用：

```json
{
  "model_name": "kling-model",
  "prompt": "让画面产生自然运动",
  "image": "asset://ast_xxx"
}
```

即梦使用：

```json
{
  "req_key": "jimeng-model",
  "prompt": "让画面产生自然运动",
  "image_urls": ["asset://ast_xxx"]
}
```

客户端必须把 `asset://` 放在对应视频厂商官方合同规定的媒体字段中，不能使用 `metadata`、`extra` 或 Provider 私有透传字段。

平台在渠道分配前校验：

- 素材属于当前用户；
- 素材状态为 `ready`；
- 真人授权仍为 `authorized`；
- 素材绑定的公开模型与视频请求一致；
- 多素材请求存在共同可用渠道；
- 渠道账号和凭据指纹与素材创建时一致。

校验通过后，平台在每次南向尝试前把 `asset://ast_...` 改写为该渠道账号下冻结的上游引用。客户端不会看到上游引用。任一校验失败时，请求在预扣和上游调用前失败。

## 9. 真人素材授权

### 9.1 创建授权

```bash
curl -sS -X POST "$API_BASE/v1/real-person-authorizations" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "seedance-model",
    "locale": "zh-CN"
  }'
```

成功返回 HTTP `201`：

```json
{
  "id": "rpa_xxx",
  "status": "awaiting_consent",
  "consent_url": "https://api.example.com/consent/real-person/...",
  "expires_at": 1784785200,
  "created_at": 1784781600,
  "updated_at": 1784781600
}
```

响应中的 `consent_url` 必须交给照片本人打开。客户端或运维人员不得代替本人提交同意。

### 9.2 查询、重试与撤回

```http
GET /v1/real-person-authorizations/{authorization_id}
```

查询会刷新 Provider 认证结果。只有 `authorized` 可创建真人素材。状态包括：

```text
awaiting_consent
consent_rejected
awaiting_verification
verifying
authorized
failed
expired
revoked
deleting
deleted
```

认证失败或过期且状态允许重试时：

```http
POST /v1/real-person-authorizations/{authorization_id}/retry
```

成功响应中的 `verification_url` 必须继续交给本人完成认证。

撤回授权：

```http
POST /v1/real-person-authorizations/{authorization_id}/revoke
```

撤回事务完成后，相关真人素材立即不能用于新任务，上游清理可在后台继续。

### 9.3 创建真人素材

授权进入 `authorized` 后，使用同一模型创建图片素材：

```bash
curl -sS -X POST "$API_BASE/v1/assets" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $REQUEST_ID" \
  -d '{
    "name": "authorized-person-reference",
    "asset_kind": "real_person",
    "media_type": "image",
    "model": "seedance-model",
    "authorization_id": "rpa_xxx",
    "source": {
      "type": "url",
      "url": "https://cdn.example.com/signed/person.png?signature=...",
      "expires_at": 1784788800
    }
  }'
```

真人素材只能是图片，且授权、素材和视频请求必须属于同一用户、公开模型和 Provider 账号。

## 10. 错误与客户端动作

| HTTP | 典型错误 | 客户端动作 |
| --- | --- | --- |
| `400` | `invalid_request`、`unsafe_asset_url` | 修正请求，不自动重试 |
| `400` | `asset_url_ttl_insufficient` | 重新签发满足 `required_min_ttl_seconds` 的 URL |
| `401` | 平台鉴权失败 | 检查平台 Token |
| `403` | `real_person_consent_required`、`real_person_verification_rejected` | 完成或重新发起本人授权，不得绕过 |
| `404` | `asset_not_found`、`authorization_not_found` | 停止操作并核对用户和平台 ID |
| `409` | `idempotency_conflict` | 原 Key 已用于不同请求；核对调用方重试逻辑 |
| `409` | `asset_binding_required`、`asset_credential_changed` | 核对模型、素材状态、渠道账号或执行迁移 |
| `409` | `asset_limit_reached` | 删除无用素材，等待清理完成后重试 |
| `422` | `unsupported_asset_binding_target`、`unsupported_asset_type` | 使用已发布的平台目标和素材类型 |
| `502` | `asset_upstream_error` | 上游拒绝创建；修正配置后使用新 Key 创建 |
| `503` | `asset_upstream_unavailable` | 保留原 Key，稍后重试或联系运维 |

错误响应使用平台素材错误外壳：

```json
{
  "error": {
    "message": "asset request is invalid",
    "type": "asset_error",
    "code": "invalid_request",
    "request_id": "req_xxx"
  }
}
```

不要记录完整签名 URL、Token、`consent_url`、`verification_url` 或临时凭证。排障时使用平台素材 ID、真人授权 ID、错误码和 `request_id`。

## 11. 对接检查表

- [ ] 只通过 `/v1/assets` 使用平台素材合同，不调用供应商素材路径。
- [ ] 新业务操作使用新 `Idempotency-Key`，原操作重试复用原 Key。
- [ ] 只持久化 `ast_...`、`ab_...` 和 `rpa_...` 平台 ID。
- [ ] 使用 Provider 可访问且 TTL 充足的公网 HTTPS 单对象 URL。
- [ ] 等素材进入 `ready` 后再创建视频。
- [ ] 在视频厂商官方媒体字段中使用 `asset://ast_...`。
- [ ] 真人素材只在本人授权为 `authorized` 后创建。
- [ ] 把 `create_unknown` 当作结果未知，不要换 Key 盲目重建。
- [ ] 不记录完整签名 URL、Token、同意 URL、认证 URL 或临时凭证。
