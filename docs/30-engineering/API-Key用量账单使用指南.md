# API Key 用量账单使用指南

## 1. 适用范围

本文面向查看自身 API 调用用量和已结算费用的用户。账单按周期、API Key 和模型汇总：

- 输入、输出和总 Token；
- 调用次数；
- 平均 RPM、TPM 和响应耗时；
- 流式请求比例；
- 消费、退款和最终净费用；
- 当前余额和累计消费。

这是用量与费用结算记录，不是税务发票或完整账务流水。

## 2. 打开账单

登录控制台后进入：

```text
/billing
```

默认展示本周数据。可切换本周、上周、近 7 天、近 30 天或最长 31 天的自定义周期。

页面支持按 API Key 和模型筛选，并可在以下视图间切换：

- API Key × 模型明细；
- 按模型汇总；
- 按 API Key汇总。

如果侧栏没有“账单”，检查管理员和个人侧栏模块是否启用了 `billing`。

## 3. 指标口径

| 指标 | 含义 |
| --- | --- |
| 请求数 | 逻辑模型调用次数，不重复计算异步任务结算调整 |
| 输入/输出 Token | 周期内消费和退款结算日志记录的 Token |
| 总 Token | 输入 Token + 输出 Token |
| 消费额度 | 周期内消费日志 quota 合计 |
| 退款额度 | 周期内退款日志 quota 合计 |
| 最终费用 | `max(消费额度 - 退款额度, 0)` |
| 平均 RPM/TPM | 按整个查询周期计算 |
| 平均耗时 | 消费日志的秒级 `use_time` 平均值 |
| 流式比例 | 流式逻辑调用数 / 请求数 |

历史费用直接读取请求当时已经结算的日志，不使用当前模型价格重新计算。

消费和退款按各自日志发生时间归属周期。跨周期退款不会改写原消费周期，因此两个周期之间不一定能按单个请求直接勾稽。

## 4. 查看调用明细

账单行的“查看调用明细”会跳转到：

```text
/usage-logs/common
```

并携带当前周期、API Key名称、模型和消费/退款日志类型。单次用量日志可查看：

- 请求与上游请求 ID；
- 计费来源；
- 模型和分组倍率；
- 动态计费表达式与命中档位；
- 缓存、音频、图片和搜索等附加费用；
- 异步任务结算或退款。

账单页只负责聚合，不复制单次费用解释器。

已删除且历史名称为空的 API Key可能无法按名称精确下钻，但仍保留账单中的 Key ID、模型和周期汇总。

## 5. 导出

账单支持导出当前可见聚合行的 CSV。导出继承页面当前周期、API Key、模型和视图筛选。

CSV 不包含 API Key密钥值、prompt、请求体、 Provider 凭证、渠道或管理员私有信息。下载后的文件可能包含业务用量和费用信息，应按内部数据规范保存和共享。

## 6. 直接调用接口

前端使用：

```http
GET /api/billing/self
```

该接口使用控制台 `UserAuth()` 的 Bearer 凭据（登录访问令牌或个人访问令牌），不是模型 Relay API Key。

查询参数：

| 参数 | 必填 | 说明 |
| --- | ---: | --- |
| `start_timestamp` | 是 | Unix 秒 |
| `end_timestamp` | 是 | Unix 秒；跨度不超过 31 天 |
| `token_id` | 否 | 大于 0 的 API Key ID |
| `model_name` | 否 | 模型名，最长 255 字符 |

示例：

```bash
curl -sS \
  'https://api.example.com/api/billing/self?start_timestamp=1785168000&end_timestamp=1785254399' \
  -H 'Authorization: Bearer <dashboard-access-token>'
```

服务端只读取当前登录用户 ID，不接受任意 `user_id`。响应顶层包含：

```text
period
funds
summary
items
generated_at
data_source=settlement_logs
```

## 7. 数据边界

以下情况会影响账单完整性：

- 消费日志被关闭；
- 历史日志已按保留策略清理；
- 异步任务尚未结算；
- 退款发生在另一个查询周期；
- 历史日志没有记录更高精度耗时或完整 Token。

账单不展示任意历史时点的期初/期末余额、本周期充值与用量的逐笔勾稽、跨期冲销凭证、税务发票或 Provider 成本账单。

如需核对差异，记录账单周期、API Key ID、模型、平台请求 ID和相关任务 ID，再从用量日志和管理员审计继续追踪。
