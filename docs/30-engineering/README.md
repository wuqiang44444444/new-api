# 30-engineering — 工程指南

## 目标

让开发者和 AI 能够使用可复现的命令搭建环境、验证改动，并按照项目约束实现、接入和维护代码。

## 放什么

- 本地搭建、构建、测试、格式化和文档校验命令；
- 编码规范、AI 编码指南和上游代码同步流程；
- 面向开发者的 API 调用、Provider 接入与回归规约；
- 可长期复用的工程实践和故障定位入口。

## 不放什么

- 产品行为和验收口径，放入 `10-product/`；
- 当前架构事实和架构决策，放入 `20-architecture/`；
- 生产配置、发布、监控和处置，放入 `40-operations/`；
- 路线图和阶段计划，放入 `50-planning/`；
- 临时问题分析、实施和验证记录，放入 `80-dev/`。

## 命名格式

- 使用稳定的中文工程主题，不加日期前缀，例如 `命令清单.md`、`上游代码合并指南.md`；
- API 和 Provider 文档名称必须包含实际能力或供应商范围，避免使用泛化的“开发文档”；
- 框架要求固定名称的工具文件、脚本和配置保持原名，不为统一中文而改名。

## 内容格式

- 指南按适用范围、前置条件、执行步骤、验证命令和常见问题组织；
- 命令必须注明执行目录，区分根模块、`web/` 与 `relaykit/`；
- API 调用指南以当前 Router、DTO 和可观察响应为准，代码路径仅作为补充证据；
- 回归规约写输入、预期输出和必须保护的不变量，不记录一次性测试流水。

## 编写要求

- 只记录当前可执行的命令和长期工程规则，失效命令必须及时更新；
- 新增或修改原生代码时遵守最小入侵、跨数据库兼容、计费安全和 `relaykit` 独立构建约束；
- 示例不得包含真实密钥、完整签名 URL、生产配置或原始 Provider 私有数据；
- 不把单元测试通过写成真实 Provider、真实账单或生产灰度验证完成。
