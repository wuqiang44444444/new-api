# 术语表

## Link 合同

`Link 合同` 是由项目负责人明确决定新增、通过本地代码变更实现并在代码中显式注册的扩展合同。它只作为这些明确代码扩展的端到端产品合同，不是 NEWAPI 全部路由的总分类，也不通过 Ability、候选渠道、模型发现或运行时探测推断。已由 NEWAPI 原生支持的渠道或模型必须继续使用原生合同，不得建立 Link 合同。

一个能力是否属于 Link 合同，只看它是否存在获批的代码扩展、唯一合同 ID/版本和显式注册项。配置一个 Channel、模型名、Ability、映射或价格不会自动产生 Link 合同。经明确代码扩展和注册的 Moxing Seedance 合同是 Link 合同的典型示例。

```text
Link 合同
├─ 客户 API 合同
├─ SKU 能力合同
├─ 任务与计费合同
├─ Link 资源合同
└─ 渠道适配协议
```

同一 Link 公开 SKU 只能对应一份 Link 合同。Provider、反代或中转渠道变化不得改变客户调用方式和可观察语义；该约束不得外溢到 NEWAPI 原生 relay 候选渠道。

同一公开 SKU 可以由多个能力等价的 Link Provider 实现服务。实现以不可变的
`link_implementation_id + link_implementation_version` 代码注册，渠道显式绑定精确版本；实现
身份用于候选过滤、binding、任务快照、exposure 和审计，不进入公开 capability hash。

## 渠道适配协议

`渠道适配协议` 是 Link 合同中的实现子概念，定义平台连接某类 Provider、反代或中转渠道所需的地址、鉴权、真实模型 ID、请求转换、响应归一化、查询方式和上游资源标识。

渠道适配协议只证明“如何调用该渠道”，不定义客户能力。只有完整实现目标 Link 合同的渠道，才能成为对应 SKU 的候选。

`profile` 是渠道适配协议的形状标识，不是 Provider 身份。相同 profile 的不同 Provider 仍需各自的
Link 实现注册；只配置 profile、模型名、Ability 或前端模板不会产生实现身份。

## Link 资源

`Link 资源` 是 Link 合同中可治理、可授权、可路由的平台素材身份。当前使用 `ast_*` 与 `asset://ast_*` 表示，可解析为 Provider 托管绑定或受保护源 URL。

`Link` 作为本地扩展设计分类时使用“Link 合同”；指代具体素材时使用“Link 资源”，避免只写“Link”造成歧义。

## 方向性表述

`客户端` 和 `Provider` 只用于描述数据流向，不是两套合同：

```text
客户端
  -> Link 合同
  -> 类型化校验、SKU 能力、路由、任务、计费与资源治理
  -> 渠道适配协议
  -> Provider
```

对 Link 扩展的新文档，不再使用历史方向性合同术语作为正式分类；统一使用“Link 合同”和“渠道适配协议”。NEWAPI 原生功能仍沿用其原有概念和实现，不因本术语表被重分类。

## 兼容字段

以下名称是已持久化的代码、数据库或任务快照字段，当前为避免迁移风险而保留，不再作为文档概念名：

| 兼容名称 | 文档语义 |
| --- | --- |
| `northbound_contract_id` | Link 合同 ID |
| `northbound_contract_version` | Link 合同版本 |
| `southbound_adapter_version` | 渠道适配协议版本 |
| `video_upstream_profile` | 视频渠道适配协议 profile |
| `asset_upstream_profile` | 素材渠道适配协议 profile |

如需修改这些字段，必须作为独立数据迁移和公共 API 兼容项目评估，不在文档术语统一中顺带改名。
