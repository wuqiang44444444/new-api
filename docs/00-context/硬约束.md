# 硬约束

以下规则适用于所有产品、代码、数据、文档和发布变更。详细机制以链接的专题架构和工程规范为准。

## 1. 项目与技术

- 不得删除、替换或弱化 new-api、QuantumNous 相关身份、署名、授权和元数据。
- 后端使用 Go 1.22+、Gin、GORM v2；前端位于 `web/`，使用 React 19、TypeScript、Rsbuild、Base UI、Tailwind CSS 和 Bun。
- 数据库逻辑必须同时兼容 SQLite、MySQL >= 5.7.8 和 PostgreSQL >= 9.6。
- `relaykit/` 必须保持独立构建，不得依赖根模块。

## 2. 原生能力与 Link 边界

- NEWAPI 原生 Router、DTO、Relay、Provider adapter、模型发现和计费语义以上游代码为权威。
- Link 类型化入口只承载本地明确支持的扩展合同；不得包装、复制或收紧 NEWAPI 原生入口。
- Seedance 身份由 `ChannelTypeSeedanceLink` 和代码注册的上游协议明确表达。模型兼容性由技术人员线下
  审核后交付管理员配置，不在运行时根据名称、价格或请求字段推断。
- 已有原生能力不得再建立平行 Link Router、DTO、任务体系、模型别名或计费账本。
- 不得为了识别或拒绝 Link 模型而修改 NEWAPI 原生入口；Link 隔离只发生在自身的类型化 Router、
  ChannelType、协议 adapter 和校验中。
- 原生与 Link 可以复用鉴权、渠道、Task、计费、资源和日志底座，但不得互相推断、包装或兼容降级。
- Link 南向 `Channel.base_url` 继承 NEWAPI 的绝对 HTTP(S) 地址语义；Provider 官网面向直连客户的
  HTTPS 要求、示例地址或安全建议不能据此收紧网关中转语义，也不能成为 Channel 或协议资格。只有
  协议本身依赖 HTTP 无法表达的传输能力，并有代码与测试证明时，才允许在精确
  adapter 边界显式拒绝 HTTP；客户可控 URL、Link 资源和内容回源仍分别遵守各自的安全约束。

## 3. Link 渠道与履约

- 客户模型、Channel、Provider 模型和代码协议是独立身份；`model_mapping` 只负责客户模型到 Provider
  模型的转换。
- Link 不建立 publication、Link SKU、逐模型 capability、不可变 implementation、execution binding、
  内容 hash 等价证明、Link Access Plan 或候选交集。
- Seedance 客户模型必须由管理员明确配置到 `ChannelTypeSeedanceLink`。同一个已启用客户模型只能
  对应一个 Seedance Channel；只在创建、保存已启用配置、编辑已启用配置和重新启用时校验。
- Seedance 运行时不使用 Priority、Weight、Affinity、随机分发、失败重选、跨渠道重试或 fallback。
- 南向差异只能由代码注册的 `video_upstream_protocol` / `asset_upstream_protocol` adapter 表达；
  管理员不得编写协议 JSON、字段映射或状态脚本。
- 客户端不得透传合同外 Provider 私有参数；不支持字段必须明确拒绝或保持未发布，不得静默删除、钳制、降级或改义。

## 4. 异步执行与计费

- 适用的异步 Provider POST 必须先建立 durable create attempt；资金 hold、必要额度 reservation 与 `sending` 必须原子提交后才允许发送。
- 没有可信 Provider task ID 时不得创建伪 Task；Task 创建、hold 转移和 attempt 完成必须原子提交。
- 创建结果 unknown 时不得自动重发、换渠道或退款；单次轮询响应不可采信时不得直接判业务失败。
- Task 必须按创建时冻结的客户模型、Channel、Provider 模型、代码协议/adapter 版本、连接、素材和计费
  事实完成生命周期。
- 预扣、结算、差额、退款和补偿必须幂等；所有客户可控乘数必须先校验上界。
- quota 转换必须使用统一 checked 饱和函数；不得因溢出、NaN 或非法输入产生负费用。
- 客户退款与 Provider exposure 必须分账；未知 Provider 金额保持未知，不得用客户 quota 冒充供应商成本。

## 5. Link 素材与真人认证代理

- 素材控制面是调用方自管的无状态单资源代理。所有创建、查询、更新和删除必须携带客户模型名，由
  客户模型选择唯一 Seedance Channel 和代码 adapter；平台不持久化 Asset/AssetGroup，不提供素材或
  素材组列表、迁移、物化、source fallback 或跨 Provider fallback。
- 创建和查询可以返回 Provider opaque 素材/组 ID 以及 `asset://<opaque-id>`。公开响应不得返回
  Provider、ChannelID、上游原始模型名、账号、Region/Project 或凭据；source URL 只允许出现在创建
  请求和当次 Provider 调用中，不得持久化、记录或返回。
- 客户模型允许使用部署方自定义名称，并通过 `model_mapping` 精确映射到代码协议登记的上游模型。
  素材能力不得从名称推断；公开元数据以匿名 `reuse_scope` 表示复用域，只有两个非空值完全相同时才可
  尝试跨模型复用，实际存在性、权限和兼容性仍由 Provider 最终裁决。
- ModelArk V3 中的 `asset://<opaque-id>` 不触发本地素材查询或可用性校验。平台不验证所有权、应用、
  ready 状态、创建模型、Channel 或 Provider 作用域；当前客户模型对应的 Provider 判断存在性、权限、
  兼容性与审核结果。错误 ID 只发送到当前 Provider，失败不得切换模型、Channel 或 Provider。
- 该合同按“一个中转站用户是一个受信应用、应用自行隔离最终用户素材”成立，不提供共享 Provider 账号
  下应用间的技术强隔离。需要强隔离时必须使用独立 Provider 账号/Project 或另行决策所有权层。
- 真人认证仍是上游素材组流程。平台直接返回上游会话 ID、认证链接和完成后的组 ID，并按调用方明确
  提供的单个会话 ID 查询；不自建人脸/活体表单、法律授权域、reservation 或撤回状态机。
- 素材操作不建立 `create_unknown`、`delete_unknown`、自动重试、孤儿扫描或管理员核查系统；未取得
  可信 Provider ID 或删除结果不明确时返回失败并写脱敏技术日志。

## 6. 安全与数据

- 不得提交或输出密钥、Token、Cookie、支付凭据、生产配置、完整签名 URL、Task 私有数据或原始 Provider 响应。
- 平台持久化的客户资源必须按 `user_id + app_id` 隔离；第 5 节无状态素材代理不持久化资源映射，按其明确接受的调用方自管边界执行。素材组真人认证不建立独立最终用户身份域。
- Redis、进程缓存和前端状态可重建，不得成为合同、Task、资金、资源或授权的唯一事实源。
- Go 业务 JSON 编解码必须使用 `common/json.go`；Provider 请求 DTO 的可选标量必须使用指针与 `omitempty`，保留显式零值。
- 涉及表达式计费前必须阅读 `pkg/billingexpr/expr.md`；涉及数据库锁必须使用项目统一跨数据库封装。

## 7. NEWAPI 原生代码最小入侵

- 本地扩展优先不修改 NEWAPI 原生文件；能够通过 Link 专属 Router、middleware、service、adapter、注册表或新增文件完成时，禁止侵入原生实现。
- 确需接入原生热路径时，只允许保留单行调用或极窄分支；类型、常量、校验、转换、状态和测试等主体逻辑必须隔离到新增文件。
- 允许新增文件内存在少量清晰、局部的重复，以换取更小的原生文件改动；不得为抽象复用而扩大原生修改面。
- 禁止借本地功能修改原生文件的命名、目录、结构、格式或无关逻辑；只有无法安全实现或无法满足既有接口时才可扩大改动，并必须记录原因。
- 每次修改原生文件都必须能够说明必要性、最小接线点和未来接取上游时的冲突影响；无法说明时不得修改。
- 旧 Link 合同中已无用途的 publication、SKU、capability、implementation、execution binding、Access
  Plan、素材 binding、独立真人授权及其路由、字段和 UI 必须直接删除；不得增加兼容层、deprecated
  alias、双读双写、历史 decoder、空壳接口或回退分支。

## 8. 变更与文档

- 接取上游代码必须遵循[上游代码合并指南](../30-engineering/上游代码合并指南.md)，并验证数据库迁移与本地保留白名单。
- 架构事实写入 20，产品行为写入 10，工程步骤写入 30，运维流程写入 40，临时实施记录写入 50/80。
- `docs/99-archive/` 只增不改：只允许把已完成事实收敛、补齐历史 frontmatter、通过校验且目标不存在的
  新归档文件移动进去；文件进入后不得修改、覆盖、删除、重命名或格式化。勘误和新事实只能写入
  `docs/00-context/`—`docs/90-ui-ux/`。
- 开发过程中，未经用户针对当前任务主动、明确授权，不得在 `docs/60-marketing/` 或 `docs/70-research/` 下创建、修改、删除、移动、重命名、格式化或自动同步文档；一般文档维护请求不构成授权，只读检查不受影响。
- ADR 编号创建后永不重排或复用；被取代的 ADR 保留原编号并填写 `status: superseded`、`superseded-by`。
- 未完成真实 Provider、账单、外部数据库和灰度验证的能力，不得写成生产已发布。
