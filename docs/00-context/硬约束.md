# 硬约束

## Technology
- 后端使用 Go 1.22+、Gin、GORM v2。
- 前端实现位于 `web/`，使用 React 19、TypeScript、Rsbuild、Base UI、Tailwind CSS。
- 数据库代码必须同时兼容 SQLite、MySQL >= 5.7.8、PostgreSQL >= 9.6。
- 前端包管理和脚本优先使用 Bun。

## Security
- 绝不提交密钥、Token、Cookie、真实支付凭据或生产环境配置。
- 认证、计费、额度、限流、审计相关改动必须保留可验证的行为边界。
- 受保护的项目名称、组织/作者身份、授权、署名和元数据不得删除、替换或弱化。

## Architecture
- 代码按 Router -> Controller -> Service -> Model 的分层边界推进。
- Provider relay 请求 DTO 的可选标量字段必须使用指针类型并配合 `omitempty`，保留显式零值。
- Go 业务代码的 JSON marshal/unmarshal 必须使用 `common/json.go` 中的封装。
- 涉及表达式计费前必须先读 `pkg/billingexpr/expr.md`。

## 北向合同与南向适配

- 图片产品默认且受保障的产品合同是统一 NEWAPI 图片接口。客户端应优先使用统一的路径、字段语义、鉴权、错误信封和任务查询方式；供应商路径、字段、鉴权、同步/异步信封及任务查询差异全部在南向适配。
- 供应商原生协议是按渠道开放的可选附加能力，不属于统一图片产品的兼容承诺。只有上游真实支持、NEWAPI 已有对应转发能力并完成该渠道验证时才能开放；上游不支持或尚未适配时可以不开放，网关不得为了表面兼容而模拟一套供应商原生协议。
- 统一图片接口与供应商原生接口必须作为两个明确合同治理。统一接口可跨兼容渠道适配和切换；原生接口按其官方路径、请求及响应工作，不承诺通过替换 `model` 跨供应商迁移，也不能反向改变统一图片接口语义。
- 客户端可见的路径、字段、类型、枚举、默认值、错误和响应必须来自可追溯的标准合同。合同来源按“NEWAPI 当前稳定北向合同 -> 模型厂商官方 API”确定，并记录文档链接、版本或验证日期；第三方聚合商、反代或渠道私有字段只能作为南向事实，不能直接升级为北向公共合同。
- 北向不得要求客户端根据供应商切换字段。供应商的路径、字段名、鉴权、同步/异步信封和任务查询差异必须由渠道配置、模型映射、参数覆盖或独立 converter 在南向消化。
- 公开模型名标识一个稳定、可计费、可验证的北向合同 SKU，而不只是基础模型家族。同一公开模型名只能进入北向请求、响应、错误、生命周期和计费语义等价的渠道。
- 同一基础模型在不同南向渠道的接口或已发布能力无法证明等价时，必须拆分公开模型名并分别绑定渠道、路由、模型映射、ability 和价格；不得让同一公开模型随机进入不兼容渠道，也不得依赖失败重试掩盖合同差异。
- 因南向差异拆出的同基础模型 SKU，仍必须使用同一 NEWAPI 图片接口族、相同语义字段、统一错误信封和统一任务查询方式；不得把“拆模型名”变成供应商私有接入协议。模型支持的字段集合、枚举、数量上限、输入载体及同步/异步能力可以不同，但必须按公开 SKU 明确声明和校验，不能静默降级。
- 拆分模型名不能成为暴露供应商私有请求结构的理由。不同公开 SKU 仍使用同一套已选定的北向标准字段，由各自南向适配器完成转换。供应商真实模型 ID 只存在于渠道配置、执行快照和审计信息中。
- 同一产品面发布的图片模型统一使用 `/v1/images/generations`、`model`、`prompt`、`image`、`size`、`n`、`response_format` 和 `stream` 等已选定北向字段。即使 Nano 等不同模型的南向字段或路径不同，也必须在适配器内转换，不能要求客户端改用供应商字段或供应商路径。
- 北向合法字段不得被静默删除或改义。暂未适配的标准字段必须明确返回 400/能力不支持，或在能力表中保持未发布；兼容旧私有字段只能作为有期限的迁移别名，不得继续写入新文档或新客户端示例。

### 视频与素材库 API 对接要求

- 当前公开视频模型范围仅包括 Seedance、Kling 和即梦：Seedance 使用其 ModelArk 官方合同，Kling 和即梦分别使用各自官网合同。OpenAI 视频模型已经下架，不得重新接入、出现在模型发现或参与新任务创建、计费和渠道分发；现有 `openai_videos` 类型及相关代码只可用于存量任务兼容读取，并应在存量退出后移除公开路由。
- 视频生成属于模型数据面。每个公开视频模型或 SKU 的北向路径、请求字段、字段类型、枚举、默认值、校验、流式事件、响应、错误、异步任务状态、查询、取消、删除和内容下载语义，必须以该模型厂商可追溯的官方 API 合同为准；不同模型可以使用各自不同的官方协议，不得为了表面统一而强制伪装成另一厂商协议或平台自定义协议。
- 同一公开视频模型或 SKU 无论实际进入官方直连、第三方反代还是第三方中转渠道，北向合同都必须保持完全一致。上游地址、鉴权、真实模型 ID、字段名、请求结构、同步或异步信封、任务 ID、状态枚举、查询路径和结果结构等差异，必须全部由南向 profile、渠道配置和独立 converter 消化，客户端不得根据所选渠道改变调用方式。
- 同一公开视频模型只能绑定已证明能够完整实现其北向官方合同的渠道。南向渠道缺少已发布能力时，应从该模型能力和选渠集合中移除；确需拆分公开 SKU 时，除 `model` 值和已明确声明的能力范围外，不得改变该模型所属官方协议。不得先随机选中不兼容渠道，再依赖重试、字段删除或内部错误掩盖合同差异。
- 视频北向不得开放 `metadata`、`extra`、任意参数透传等供应商私有逃生口。官方合同中的合法字段必须在北向完成校验并在南向完整适配；不能适配时必须返回该北向合同对应的明确 4xx/能力不支持错误，或保持该能力未发布，禁止静默忽略、删除、钳制或改义。
- 素材库属于平台控制面，不按视频模型厂商拆分多套北向 CRUD。平台必须提供一套稳定、统一、供应商中立的素材库 API、资源 ID、状态、错误和生命周期合同；客户只使用平台素材 ID 与 `asset://` 引用，不接触南向 profile、渠道 ID、上游账号、真实素材或素材组 ID、Provider 路径、Action/Version、签名算法或凭据。
- 素材库的创建、查询、更新、删除、迁移、真人授权、幂等、用户隔离和生命周期由平台统一合同治理。Ark Assets、Relay Assets、BytePlus Action、JoyCreator 或未来 Provider 的路径、字段、鉴权、素材组、认证和状态差异只存在于南向适配器；不得把 `ark_assets`、`official_action_assets`、`joycreator_assets`、`joycreator_library` 等供应商或实现名称升级为新的北向公共字段、枚举或资源类型。历史兼容值只能作为有期限的迁移别名。
- 视频请求引用平台素材时，仍使用该视频模型官方合同规定的图片、视频或音频字段，只允许在字段值中提交平台 `asset://` 引用。网关必须在选渠前完成素材所有权、状态、授权、模型、渠道账号和多素材交集校验，并在每次南向尝试前将平台引用改写为所选渠道账号下的上游引用；该过程不得改变视频北向字段和响应合同。

## 最小入侵

- “最小入侵”是本仓库本地开发的最高优先级代码组织约束，优先目标是减少未来接取上游代码时的冲突、合并成本与错误风险。
- 新增类型、常量、辅助逻辑、适配器及可独立放置的测试等，原则上放入额外的单独文件；不得为追求抽象复用而扩写、重排或重构现有上游文件。
- 现有热路径只保留单行调用或极窄分支。无法完全隔离时，必须将绝大部分新增逻辑放入新文件，并把现有文件改动限制在完成接线所必需的最小范围。
- 允许新增文件中存在少量、清晰且局部的重复；不得仅为消除重复而扩大现有文件的修改范围。
- 禁止随功能改动进行无关的重命名、移动、格式化、抽象提取或顺手重构。只有在无法安全实现、无法满足既有接口或无法通过必要验证时，才可扩大现有文件改动，并必须明确记录原因。

## 上游代码同步

- 任何从最上游仓库、上游主分支或上游发布版本接取代码的任务，都必须遵循 `docs/30-engineering/上游代码合并指南.md`。
- 除明确批准的首页、首页专属交互、纯视觉样式、主题、品牌资源及不改变业务语义的部署配置外，所有业务逻辑和运行逻辑必须完整以上游为准。上游修改过的业务文件必须按文件整体直接覆盖本地版本，并同步上游的新增、删除、重命名与目录调整；禁止挑选代码块、手工拼接或暗中保留本地旧实现。
- “首页、样式等”中的“等”不是开放式例外。每次同步必须先列出本地保留白名单；未列入白名单的文件一律按上游完整覆盖。新增例外必须获得明确批准并写入合并记录。
- 本地业务诉求与上游冲突时，先完整采用上游实现；本地诉求必须独立评估并优先提交上游，不得在同步过程中形成隐性本地分叉。
- 每次上游同步都必须检查数据库 Model、迁移、索引、约束、默认值、数据回填和数据语义是否需要更新，并验证 SQLite、MySQL >= 5.7.8、PostgreSQL >= 9.6 的匹配与兼容性。数据库结论未明确、迁移未验证或业务文件仍与上游存在未批准差异时，不得宣布合并完成或进入发布。
