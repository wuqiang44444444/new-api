# 需求清单

## 1. 产品目标

new-api 必须以稳定客户合同聚合多家 AI Provider，并统一治理身份、路由、额度、计费、异步任务、
Link 资源、日志和公开文档。Provider 或渠道变化不得静默改变客户已经使用的
接口、模型语义和历史任务。

## 2. 身份与访问

- 客户使用 API Key 调用当前用户、应用和分组获准的模型与资源；
- 越权与不存在使用一致对外语义，不能泄露其他用户的模型、任务、素材或账单；
- 管理员能够配置渠道、客户模型、分组、价格、优先级和权重，客户不感知 Provider 凭据与内部实现；
- 普通响应、日志、指标、CSV 和公开文档不得暴露密钥、完整签名 URL、上游 ID 或执行快照。

## 3. 模型与合同

### 3.1 NEWAPI 原生能力

- 原生 Chat、Responses、Images、OpenAI Videos 等沿用上游已有客户协议、Relay、模型发现和计费；
- 本地 Link 代码不得包装、复制、收紧或为原生入口增加 Link SKU 识别和兼容推断。

### 3.2 Link 扩展

- Link 只承载项目新增的客户入口和代码 adapter，不建立第二套 publication、SKU 或 implementation 身份；
- 技术人员线下确认上游兼容性，管理员只配置客户模型、Channel、`model_mapping` 和已登记协议；
- `ChannelTypeSeedanceLink` 只销售 Seedance 模型，一个已启用客户模型只允许对应一个该类型 Channel；
- Seedance 不使用 Priority、Weight、Affinity、随机分发、失败重选或 fallback；
- 不兼容已有协议时由技术人员新增代码 adapter，不让管理员编写 JSON 转换或状态机。

## 4. 图片、视频与异步任务

- 图片使用已发布的统一图片合同；同步和异步 Provider 不能形成两套客户 API；
- NEWAPI 原生 OpenAI Videos 与 ModelArk、Kling、即梦等 Link 视频合同分别遵守自己的路径、字段、
  状态和错误信封；
- 客户可控数量、时长、Token 和其它计费乘数在进入额度计算前必须有明确上界；
- 适用的异步 Provider POST 在发送前必须建立 durable attempt、资金 hold 和发送许可；
- 取得可信 Provider task ID 后才创建 Task，并冻结客户模型、Channel、协议、连接、素材和计费事实；
- 创建结果不可确定时不得自动重发、换渠道或退款；单次轮询响应不可采信时不得直接判业务失败；
- Task 终态、资金状态和 Provider 风险可以独立补偿，但不能重复扣费、退款或覆盖已确认事实。

## 5. Link 素材与真人素材组

- `/v1/assets` 和 `/v1/asset-groups` 只提供带客户 `model` 的单资源增删改查，不提供列表；
- 创建和查询直接返回 Provider opaque 素材/组 ID，可返回 `asset://<opaque-id>`；调用方保存
  `model + id + reference`，平台不建立本地 Asset/AssetGroup 映射；
- 平台不保存媒体二进制或 source URL，不建立 binding、resolver、迁移、自动物化、跨 Provider 探测、
  fallback、自动重试或孤儿修复；
- ModelArk V3 的 `asset://<opaque-id>` 只做基本格式校验并交给当前模型选定的 adapter；平台不校验素材
  所有权、应用、状态、客户模型、Channel、账号或 Region/Project，最终由 Provider 判断；
- 错误 Provider ID 只发送给所选 Provider，失败返回脱敏错误；不支持的模型或操作明确返回
  `unsupported_asset_operation`；
- 真人认证由上游页面完成，平台只代理会话创建和单项状态查询，不保存人脸、证件或授权表单。

## 6. 计费、账单与风险

- 预扣、结算、差额、退款和补偿必须幂等，不得因溢出或非法输入产生负费用；
- Link 复用 NEWAPI quota 和消费日志，不建立平行客户账本；
- 客户退款与 Provider 潜在成本分账，exposure 使用独立、幂等、可审计事实；
- Provider 金额未知时保持未知，不能用客户 quota 冒充供应商货币成本；
- 自助账单按周期、API Key 和客户模型聚合已结算日志，不按当前价格重算历史；
- 可选 breakdown 只解释基础账单，数据缺失必须明确显示不可用，不能显示为零。

## 7. 公开 API 文档

- 公开范围由 operationId 白名单明确批准，不能从路径、DTO 或内部文档自动推导；
- OpenAPI 定义机器合同，Manifest 定义导航和文件映射，Markdown 提供人类可读说明；
- 内部 `docs/`、后台 API、Provider 私有字段和真实凭据不得进入公开产物；
- 文档内容、搜索索引和最终静态文件必须在 Web 构建期校验，并与应用一起发布；
- 未验证或未发布能力不得通过文档提前形成客户承诺。

## 8. 非功能要求

- 数据库路径同时兼容 SQLite、MySQL >= 5.7.8 和 PostgreSQL >= 9.6；
- Redis 和进程缓存可重建，不能成为合同、Task、资金、资源或授权的唯一事实源；
- 客户合同与关键资金、安全边界由确定性测试保护，生产能力还需真实 Provider、账单和灰度验收；
- 客户合同管理员可以从独立总览按客户、公开模型和合同状态检索已建立合同；该入口与用户侧边栏复用同一合同事实和写入语义；
- 新增能力遵循最小入侵，保持 `relaykit/` 独立构建能力，并避免形成无依据兼容分支；
- 架构事实、产品行为、工程步骤、运维流程和临时实施记录必须写入各自文档目录。

## 9. 非目标与验收入口

- 平台不是对象存储、内容审核机构、会计总账或税务发票系统；
- 不用 Provider 模型或当前候选反向创建客户合同；
- 不为未发布旧实现保留 alias、双读、fallback 或第二套任务系统；
- 产品级条件见[验收标准](../10-product/验收标准.md)，生产执行见
  [全渠道上线验收手册](../40-operations/05-全渠道上线验收手册.md)，未完成门禁见
  [路线图](../50-planning/路线图.md)。
