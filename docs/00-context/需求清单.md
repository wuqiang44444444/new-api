# 需求清单

## 1. 产品目标

new-api 对外提供统一的 AI API 网关，将多个 Provider 的文本、图片、视频和素材能力收敛为稳定的客户合同，并统一治理用户、API Key、分组、选渠道、限流、计费、异步任务和审计。

## 2. 核心功能需求

### 2.1 身份、路由与渠道

- 用户通过 API Key 调用已授权模型；所有数据访问必须限定到当前用户和应用作用域。
- 管理员通过 Channel、Ability、分组、优先级、权重和模型映射管理 Provider；客户不感知 Provider 凭据和内部实现身份。
- 公开 SKU 的能力、字段、错误和价格不得随候选渠道改变；候选实现必须通过合同与能力等价校验。

### 2.2 媒体合同

- 图片默认使用统一 `POST /v1/images/generations` 合同，同步与异步 Provider 都投影为同一产品语义。
- rc23 原生 OpenAI Videos/`sora-*` 使用上游 `/v1/videos` 及其 Remix、查询和内容合同；本地 Link
  代码不得包装、复制或收紧该入口。Seedance、Kling、即梦等显式 Link SKU 只使用各自类型化
  官方合同、注册和候选实现，不要求原生入口识别或拒绝 Link SKU。
- 异步创建必须先建立 durable attempt 和资金门闩；请求已发送但上游结果不可确定时，不得自动换渠道、重发或退款。
- Task 在创建时冻结客户合同、公开/上游模型、渠道连接、实现版本、素材解析与计费事实；轮询与结算不跟随后续配置编辑。

### 2.3 虚拟素材与真人授权

- 客户通过 `/v1/assets` 创建平台逻辑素材，业务请求仅使用 `asset://ast_*`；Provider 素材 ID、凭据、路径和签名 URL 不进入客户合同。
- 一个 Asset 可由加密的短期 `AssetSource` 或一个及以上上游 binding 解析；binding 优先，选渠道和每次发送前都重新校验所有权、状态、实现版本、凭据作用域与 TTL。
- 平台不下载或托管客户媒体字节；请求级 URL/Data URL 不自动进入 Asset 生命周期。
- 真人素材另外要求应用接受生效规则、稳定匿名最终用户作用域、Provider 技术验证和可索引授权 reservation。撤回后立即阻止新任务和平台内容回源，但不声称可收回平台外副本。

### 2.4 计费与账单

- 预扣、结算、差额和退款必须幂等；任何用户可控乘数在进入额度计算前必须有上界，额度转换统一饱和且可审计，不得产生负费用。
- 用量账单按“周期 × API Key × 模型”聚合已结算日志，历史费用不用当前价格重算。
- 基础账单是费用和 Token 权威来源；缓存、长短 Context、动态计费和数据质量 breakdown 只用于解释，历史元数据缺失时不猜测。

## 3. 非功能与约束性需求

- 数据库必须同时支持 SQLite、MySQL >= 5.7.8 和 PostgreSQL >= 9.6；补偿扫描使用普通可索引列，不依赖方言专有 JSON 查询。
- 客户可见合同、幂等、计费、授权与安全边界必须由确定性回归和真实 Provider 黑盒验收共同保护。
- 凭据、上游资源 ID、签名/源 URL、完整 Provider 错误和真实身份信息不得进入普通响应、日志、指标或可分享证据。
- 实施遵循最小入侵：新能力优先放入独立文件，现有热路径只保留必要接线，禁止借功能变更做无关重构。

## 4. 非目标

- 账单不是税务发票、复式记账、任意历史余额快照或 Provider 成本账单。
- 素材库不是对象存储、不识别“同一媒体”、不用裸上游 ID 建立跨 Provider 身份。
- Link profile 只描述适配形状，不代替代码所有、不可变的实现 ID/version。
- 不为了“兼容”保留未发布的旧 FunCloud H5/raw upload/multipart 或第二套异步任务状态机。
