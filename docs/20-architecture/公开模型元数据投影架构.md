# 公开模型元数据投影架构

## 1. 范围与边界

本文定义模型目录中 `api` 公开元数据的统一投影规则：调用方只从后端投影获得每个客户模型的
API 合同（创建入口、操作矩阵、逐字段参数和素材能力），不从模型名、价格、端点枚举或前端启发式
推断能力。投影是只读目录事实，不构成运行时路由、capability 注册表或第二套模型状态。

投影覆盖三类模型，公开形状统一为 `dto.PublicModelAPI`（`relaykit/dto/public_model_api.go`）：

| 模型族 | 公开合同 | 投影构造 |
| --- | --- | --- |
| Seedance 客户模型 | `api.video`（北向 `modelark_v3`）+ `api.assets` | `model/channel_seedance_public_catalog.go` |
| 图片中转与原生图片模型 | `api.image`（北向 `/v1/images/generations`） | `model/public_image_model_api.go` + `pkg/publicmodel/image.go` |
| gemini_image 族（Gemini/Vertex imagine 模型） | `api.image`（生成 + 编辑 `edit_image` 操作、异步查询） | `model/public_image_model_api.go` + `pkg/publicmodel/image_gemini.go` |
| 原生 Sora 视频 | `api.video`（北向 `openai_videos`，`/v1/videos`） | `model/public_image_model_api.go` + `pkg/publicmodel/video.go` |

Seedance 目录的模型选择、`reuse_scope` 与素材矩阵细节由
[Seedance 专用渠道与 Link 架构](Seedance专用渠道与Link架构.md)、
[公开模型调用与素材能力元数据设计](Seedance模型接入设计/公开模型调用与素材能力元数据设计.md) 和
[Seedance 模型素材库支持矩阵](Seedance模型素材库支持矩阵.md) 负责；图片模型逐字段合同由
[图片服务与异步 Provider 适配架构](图片服务与异步Provider适配架构.md) §5.1 负责。本文只描述
跨模型族共享的投影机制，不复制上述专题内容。

## 2. 投影入口

同一份合同由以下入口复用，不建立逐入口的独立构造：

| 入口 | 覆盖 | 说明 |
| --- | --- | --- |
| `GET /v1/models` | Seedance + 媒体模型 | 媒体合同经 `GetPublicMediaModelAPIs` 合并进列表项 |
| `GET /v1/models/{model}` | Seedance + 媒体模型 | 先做 Token 白名单、分组可见性与计费可见性校验 |
| `GET /api/pricing` | Seedance + 媒体模型 | Seedance 目录整目录挂载；媒体合同按全分组一致规则发布 |
| `GET /api/v3/contents/generations/models` | 仅 Seedance | 只筛出 Seedance 条目，复用同一目录 |

## 3. 两套确定性投影机制

### 3.1 Seedance 专用目录

Seedance Channel 不进入原生 Ability，目录直接遍历 Channel 的全部客户模型：每个客户模型按
`video_upstream_protocol + model_mapping` 解析的精确 Provider 模型生成参数合同。客户模型没有
已登记的公开参数合同时目录构建失败（fail closed），不以空合同或通用合同代替。`reuse_scope`
在进入模型循环前按 Channel 批量加载，不逐模型查询。

### 3.2 原生媒体模型的一致性规则

图片中转、原生图片和 Sora 视频模型走原生 Ability。`GetPublicMediaModelAPIs`
（`model/public_image_model_api.go`）按运行时真实可选渠道决定合同：

1. 按调用方分组顺序取第一个有可用渠道的分组；
2. 取该分组内最高 Priority 的全部已启用渠道（运行时可按 Weight 选中的同级候选）；
3. 每个候选按其类型构造合同：`ChannelTypeAsyncImage` 走协议 + 最终 Provider 模型的 profile，
   `ChannelTypeGemini`/`ChannelTypeVertexAi` 按管理员映射后落在 imagine 登记表的 Provider 模型
   发布 gemini_image 合同，`ChannelTypeSora` 用原生视频合同，原生图片生成模型按模型族识别；
4. 统一图片族和视频候选合同须完全一致；原生图片候选的基础生成合同须一致，编辑、异步与对应
   操作只发布所有候选共有且一致的部分。任一候选缺少已登记 profile、基础合同冲突或严格合同
   不一致时不发布，并记录系统日志，不用 Weight、Channel ID 或模型名猜测单一合同。

普通 `/api/pricing` 没有单一调用方分组上下文，汇集各可见分组的最高 Priority 候选，再按上述
一致性规则发布；原生图片仅保留一致的基础合同与共有操作。候选缺失或基础合同不一致属于
“不发布”，不是错误响应。合同定价投影使用下节的授权规则。

### 3.3 合同授权投影

启用合同绑定的 Key 先以有效合同来源与 Token 模型限制过滤模型，复用 `GetContractModelMetadata`
生成目录与价格元数据；Batch 来源不进入普通模型目录。媒体候选只保留已授权的 Channel + Group，
然后跨授权分组比较最高 Priority，再执行既有合同一致性规则。它不是普通 Key 的“首个分组”规则。
会话价格只有显式选择且归属校验通过的合同才使用该投影，不隐式选择默认合同。

合同范围外的详情查询返回 `404 model_not_found`；合同目录加载失败返回 `500` 的
`success=false` / `message`，鉴权阶段合同读取失败为 `503`。失败不得降级为原生目录或空列表。

## 4. 公开合同形状

- `parameters` 是逐字段的客户安全白名单：字段名、类型、必填性、固定值、默认值、枚举、上下限和
  数量限制；嵌套字段使用点路径（如 `extra_fields.aspect_ratio`）。未出现在列表中的字段即该
  客户模型不支持，调用方不得按其它模型、渠道或 Provider 经验补发。
- `enum` 表示穷举允许值；`suggested_values` 仅为非穷举推荐值，不参与拒绝请求，也不能被客户端
  当作所有支持值。没有 `enum` 不表示任意值均已验证。两者必须忠实区分供应商文档的限制与建议。
- Seedance 的模型参数来自已激活插件声明；`omitOutputFormat` 可排除通用 ModelArk 参数集中的
  输出格式字段，避免通用扩展参数反向覆盖逐模型的明确不支持事实。声明和请求校验同步变更。
- 已登记 Gemini/Vertex 图片与图片中转投影发布 `api.image.async`（Prefer、respond-async、
  查询路径、stream_priority=false）和 `query_image`；OpenAI/Azure 原生图片沿用同一公开形状。
  这是已有执行器的能力声明，不是存储健康或受理成功保证；异步结果默认 URL，显式 Base64 在
  创建时冻结。
- `api.image.edit` 使用与创建相同的 DTO，投影 JSON 编辑输入：`image` 为字符串，
  `images` 为数组（`item_type=string`，1—14 项）；`required_one_of` 表示列出的字段必须且只能
  提供一个。multipart 输入详见图片编辑文档，不能把数组数量约束发布为 integer。
  `stream` 固定为 false；尺寸不以不完整枚举代替运行时支持范围。
- 北向协议名（`modelark_v3`、`openai_videos`）是公开客户合同的一部分；南向
  `video_upstream_protocol` / `image_upstream_protocol` 枚举、Provider 模型、Channel 身份、
  账号、Region/Project、凭据和私有路径不进入投影。
- 原生媒体模型只按可由代码稳定识别的模型族返回精确字段（DALL·E 2、DALL·E 3、GPT Image、
  sora-2/sora-2-pro）；无法识别到稳定模型族的名称只返回网关稳定公共字段，不推测 Provider
  私有枚举。
- 前端与文档只能消费该投影：当前模型广场已按 `api.assets.reuse_scope` 聚合匿名素材共享组短标签
  （scope 哈希的可变长度前缀，当前可见集合内碰撞时延长，不用列表序号）；API 示例与参数表消费
  `api.video` / `api.image` 参数投影仍在待办中，期间不得用模型名正则或模拟数据代替。

## 5. 架构不变量

1. 投影是只读目录事实，不能获得 `/v1/video/generations` 或任何履约资格，也不建立第二套
   capability、路由或模型注册表。
2. 客户模型合同只能来自代码登记的协议 spec 与 Provider profile；客户模型名、价格、端点枚举和
   模型名正则不得作为能力推断来源。
3. 投影不泄露南向协议枚举、Provider 模型、Channel、账号、凭据或上游私有路径。
4. 同一模型的列表、详情和价格目录合同必须一致；原生媒体模型按运行时可选渠道的一致性规则发布，
   无法确定唯一合同时不发布。
5. 客户模型没有已登记公开合同时 fail closed，不生成通用或空壳合同，也不用模拟数据填充。

## 6. 图片编辑参数投影

`api.image.edit.content_type` 与 `parameters` 描述推荐编码，不是全部可用传输格式的清单。
原生已登记 GPT Image（包括 2、2.5 及明确登记快照）以 JSON 对象数组投影；DALL-E 2 仍为 multipart。
DALL-E 3 及未登记编辑合同的未知原生模型不发布编辑操作，不以“非 DALL-E 3”推断编辑能力。
这只影响公开说明，不修改运行时资格或原生校验。

- 原生 GPT Image 的 `images.item_type=object`，`images[].image_url` / `images[].file_id` 表示元素子字段；
  参数级 `required_one_of` 约束每个对象的互选属性。可选 `mask` 同样描述引用对象。
- 统一图片适配保留 `images.item_type=string`、单图 `image` 与编辑级 `required_one_of`；
  不将其 14 张预算或输入字段限制套入原生合同。标准图片 `response_format` 的显式返回格式由网关适配；原生 GPT Image 默认仍为 Base64。
- 原生生成与编辑按已映射模型的精确文档配置投影，公开 `model` 始终替换为客户别名；
  2.5 的质量档位、prompt 上限和输出数量不落入未知模型的通用参数分支。
- 同一模型多个可选渠道合同时仍通过现有一致性规则合并；不同编辑合同不得任选一个发布。

## Gemini 图片尺寸约束

Gemini/Vertex 图片模型的 `api.image.creation.parameters` 与 `api.image.edit.parameters` 中，
`size` 通过可选 `size_constraints` 发布 `format=WxH`、`min_dimension`、`max_dimension` 和
`aspect_ratios`。两个维度都须为范围内正整数，比例精确匹配，不按最近比例或推荐值推断。
`auto` 由 `default_value` 表达，省略或 auto 不发送 Google imageConfig。

投影只使用管理员映射后的 Provider 模型选择 `pkg/geminiimage` 的共享尺寸规则，不公开该身份。
Lite 以 `enum=["auto","1024x1024"]` 发布已支持范围，省略 `size_constraints`；不再把网关长边阈值当成原生 1K 定义。
其他 Gemini 模型保留现有上限 4096；未使用此规则的参数省略新字段。
Vertex Lite 编辑的 `image` / `images` 额外发布 `max_decoded_bytes=7000000`，代表每张内联图片
解码后的预算，不代表 URL 字符长度；运行时和投影共用模型与渠道规则。
`enum` 是完整允许集合，`suggested_values` 只是推荐项，均不得替代尺寸约束校验。
