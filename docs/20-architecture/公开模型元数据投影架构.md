# 公开模型元数据投影架构

## 1. 范围与边界

本文定义模型目录中 `api` 公开元数据的统一投影规则：调用方只从后端投影获得每个客户模型的
API 合同（创建入口、操作矩阵、逐字段参数和素材能力），不从模型名、价格、端点枚举或前端启发式
推断能力。投影是只读目录事实，不构成运行时路由、capability 注册表或第二套模型状态。

投影覆盖三类模型，公开形状统一为 `dto.PublicModelAPI`（`relaykit/dto/public_model_api.go`）：

| 模型族 | 公开合同 | 投影构造 |
| --- | --- | --- |
| Seedance 客户模型 | `api.video`（北向 `modelark_v3`）+ `api.assets` | `model/channel_seedance_public_catalog.go` |
| 图片中转与原生图片模型 | `api.image`（北向 `/v1/images/generations`） | `model/public_image_model_api.go` + `pkg/publicmodel/image.go` |
| 原生 Sora 视频 | `api.video`（北向 `openai_videos`，`/v1/videos`） | `model/public_image_model_api.go` + `pkg/publicmodel/video.go` |

Seedance 目录的模型选择、`reuse_scope` 与素材矩阵细节由
[Seedance 专用渠道与 Link 架构](Seedance专用渠道与Link架构.md)、
[公开模型调用与素材能力元数据设计](Seedance模型接入设计/公开模型调用与素材能力元数据设计.md) 和
[Seedance 模型素材库支持矩阵](Seedance模型素材库支持矩阵.md) 负责；图片模型逐字段合同由
[图片服务与异步 Provider 适配架构](图片服务与异步Provider适配架构.md) §5.1 负责。本文只描述
跨模型族共享的投影机制，不复制上述专题内容。

## 2. 投影入口

同一份合同由以下入口复用，不建立逐入口的独立构造：

| 入口 | 覆盖 | 说明 |
| --- | --- | --- |
| `GET /v1/models` | Seedance + 媒体模型 | 媒体合同经 `GetPublicMediaModelAPIs` 合并进列表项 |
| `GET /v1/models/{model}` | Seedance + 媒体模型 | 先做 Token 白名单、分组可见性与计费可见性校验 |
| `GET /api/pricing` | Seedance + 媒体模型 | Seedance 目录整目录挂载；媒体合同按全分组一致规则发布 |
| `GET /api/v3/contents/generations/models` | 仅 Seedance | 只筛出 Seedance 条目，复用同一目录 |

## 3. 两套确定性投影机制

### 3.1 Seedance 专用目录

Seedance Channel 不进入原生 Ability，目录直接遍历 Channel 的全部客户模型：每个客户模型按
`video_upstream_protocol + model_mapping` 解析的精确 Provider 模型生成参数合同。客户模型没有
已登记的公开参数合同时目录构建失败（fail closed），不以空合同或通用合同代替。`reuse_scope`
在进入模型循环前按 Channel 批量加载，不逐模型查询。

### 3.2 原生媒体模型的一致性规则

图片中转、原生图片和 Sora 视频模型走原生 Ability。`GetPublicMediaModelAPIs`
（`model/public_image_model_api.go`）按运行时真实可选渠道决定合同：

1. 按调用方分组顺序取第一个有可用渠道的分组；
2. 取该分组内最高 Priority 的全部已启用渠道（运行时可按 Weight 选中的同级候选）；
3. 每个候选按其类型构造合同：`ChannelTypeAsyncImage` 走协议 + 最终 Provider 模型的 profile，
   `ChannelTypeSora` 用原生视频合同，原生图片生成模型按模型族识别；
4. 所有候选合同完全一致时才发布；任一候选缺少已登记 profile 或合同不一致时不发布，并记录
   系统日志，不用 Weight、Channel ID 或模型名猜测单一合同。

`/api/pricing` 没有单一调用方分组上下文，只有该模型在各可见分组的最高 Priority 候选合同全部
一致时才发布。候选缺失或不一致都属于“不发布”，不是错误响应。

## 4. 公开合同形状

- `parameters` 是逐字段的客户安全白名单：字段名、类型、必填性、固定值、默认值、枚举、上下限和
  数量限制；嵌套字段使用点路径（如 `extra_fields.aspect_ratio`）。未出现在列表中的字段即该
  客户模型不支持，调用方不得按其它模型、渠道或 Provider 经验补发。
- 北向协议名（`modelark_v3`、`openai_videos`）是公开客户合同的一部分；南向
  `video_upstream_protocol` / `image_upstream_protocol` 枚举、Provider 模型、Channel 身份、
  账号、Region/Project、凭据和私有路径不进入投影。
- 原生媒体模型只按可由代码稳定识别的模型族返回精确字段（DALL·E 2、DALL·E 3、GPT Image、
  sora-2/sora-2-pro）；无法识别到稳定模型族的名称只返回网关稳定公共字段，不推测 Provider
  私有枚举。
- 前端与文档只能消费该投影：当前模型广场已按 `api.assets.reuse_scope` 聚合匿名素材共享组短标签
  （scope 哈希的可变长度前缀，当前可见集合内碰撞时延长，不用列表序号）；API 示例与参数表消费
  `api.video` / `api.image` 参数投影仍在待办中，期间不得用模型名正则或模拟数据代替。

## 5. 架构不变量

1. 投影是只读目录事实，不能获得 `/v1/video/generations` 或任何履约资格，也不建立第二套
   capability、路由或模型注册表。
2. 客户模型合同只能来自代码登记的协议 spec 与 Provider profile；客户模型名、价格、端点枚举和
   模型名正则不得作为能力推断来源。
3. 投影不泄露南向协议枚举、Provider 模型、Channel、账号、凭据或上游私有路径。
4. 同一模型的列表、详情和价格目录合同必须一致；原生媒体模型按运行时可选渠道的一致性规则发布，
   无法确定唯一合同时不发布。
5. 客户模型没有已登记公开合同时 fail closed，不生成通用或空壳合同，也不用模拟数据填充。
