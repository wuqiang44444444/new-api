# 架构概览

new-api 是统一 AI API 网关。NEWAPI 原生能力沿用原生路由、relay、渠道分发和计费；需要本地代码扩展并显式注册的能力才进入 Link 合同。两类合同可以共享鉴权、Task、计费、素材和日志底座，但不能互相推断或降级。

## 1. 系统边界

```mermaid
flowchart LR
    Client[API 客户端 / Dashboard]

    subgraph Gateway[new-api]
        Entry[Router / Middleware]
        Controller[Controller]
        Service[Service]
        Relay[Relay / Provider Adapter]
        Model[Model]
        Worker[Task / Asset Worker]
        Web[React Web 与公开文档]
    end

    MainDB[(主数据库)]
    LogDB[(日志数据库)]
    Cache[(Redis / 进程缓存)]
    Provider[AI / 素材 Provider]

    Client --> Entry --> Controller
    Controller --> Service --> Model --> MainDB
    Controller --> Relay --> Provider
    Relay --> Model
    Worker --> Model
    Worker --> Provider
    Entry --> Cache
    Model --> LogDB
    Client --> Web
```

主分层为 `Router -> Controller -> Service -> Model`：

- `router/` 与 `middleware/` 定义路径、鉴权、合同选择和选渠前约束；
- `controller/` 负责 HTTP 解析、错误外壳和响应投影；
- `service/` 编排跨模型的业务状态、计费、补偿和 Provider 生命周期；
- `model/` 保存数据库事实并提供事务、行锁和 CAS；
- `relay/` 与 `relay/channel/` 位于 Provider 边界，负责协议转换和上游调用，不建立第二套产品状态；
- `web/` 是控制面与公开文档的展示层，不是协议、计费或任务状态的权威来源。

## 2. 运行平面

| 平面 | 入口与组件 | 权威事实 |
| --- | --- | --- |
| API 数据面 | relay Router、鉴权/限流/分发 middleware、Provider adapter | 请求上下文；异步成功后转入 Task |
| 控制面 | Dashboard API、`setting/`、用户/渠道/模型服务 | User、Token、Channel、Ability、价格与运行配置 |
| 异步任务面 | `TaskCreateAttempt`、`Task`、轮询与补偿调度 | 创建结果、冻结执行快照、业务终态与计费状态 |
| 素材控制面 | Asset API、binding/source Resolver、asset job、真人授权 | Asset 所有权、受保护源、上游 binding 与授权状态 |
| 计费与审计面 | Billing session、Task billing、`Log`、exposure | 预扣/结算/退款事实、消费日志与平台风险事实 |
| Web 与公开文档 | React Dashboard、`/docs`、构建期文档校验 | 只读展示；内容由受控 Markdown 与公开 operation 白名单生成 |

## 3. 两类协议边界

### NEWAPI 原生合同

原生 Chat、Responses、Images、OpenAI Videos 等继续使用上游已有 Router、DTO、Relay、adapter、
Ability、模型发现和计费语义。Link 隔离、素材治理和发送前创建尝试只接入显式 Link 路由与实现，
不得包装或复制原生路径，也不得为原生路径增加 Link SKU 识别、`client_protocol`、fallback 或历史
协议推断。

### Link 合同

Link 合同只由代码注册建立：

```text
客户 API 合同 + SKU 能力合同
  -> 类型化校验与规范化
  -> 显式 Link implementation 过滤
  -> Ability / 分组 / 优先级 / 权重分发
  -> 渠道适配协议
  -> Provider
```

`contract_id` 与 SKU capability 定义客户承诺；`link_implementation_id + version + content_hash` 标识实现；profile、converter、路径和模型映射只描述如何调用 Provider。配置、Ability 或模型名不能创建 Link 身份。

## 4. 核心控制流

### 同步请求

```text
鉴权与限流 -> DTO 校验 -> 选渠 -> 预扣 -> Provider 调用 -> 同步结算 -> Log
```

### 可能创建异步 Task 的请求

```text
合同与 SKU 校验
-> 选定渠道、单 Key 与实现版本
-> TaskCreateAttempt(prepared)
-> 预扣 + held + sending 原子提交
-> Provider POST
-> 可信 task ID：创建 Task + 转移 hold
-> 模糊结果：unknown 对账；到期释放并记录 exposure
```

视频合同和选中的持久化媒体图片 route 都执行该边界；普通同步图片、素材创建和真人认证使用各自的生命周期状态机。

### Task 轮询

```text
读取冻结快照 -> 调用原渠道/凭证/adapter -> 归一化状态
-> 活动态继续轮询
-> 响应不可采信进入 RECONCILIATION_REQUIRED
-> 可信终态 CAS 提交
-> 使用冻结计费目标结算、退款或补偿
```

## 5. 状态与数据所有权

| 事实 | 权威来源 | 设计约束 |
| --- | --- | --- |
| 用户、Token、额度 | 主数据库 | 资源查询绑定用户和应用作用域 |
| 新请求的路由配置 | Channel、Ability、settings | 编辑只影响之后创建的请求 |
| 发送前创建与资金持有 | `TaskCreateAttempt` | 先落库再发送；模糊结果不自动重发或退款 |
| 在途任务执行与计费 | `Task` 及私有快照 | 轮询不随渠道、Key、价格编辑漂移 |
| Link 资源身份 | `Asset` | `ast_*` 是逻辑身份，不代表平台保存媒体字节 |
| 素材执行路径 | `AssetSource`、`AssetBinding` | Resolver 选择受保护 URL 或匹配账号的上游引用 |
| 真人使用许可 | authorization 与 `TaskAssetAuthorization` | 发送前 reservation 与撤回在同一授权行上线性化 |
| 历史费用 | `Log` | 账单不按当前价格回算历史 |
| 平台潜在成本 | `ProviderCostExposure` | 与客户退款分账，幂等记录 |
| 热缓存和限流 | Redis / 进程内存 | 可重建，不能替代数据库业务事实 |

主数据库同时支持 SQLite、MySQL >= 5.7.8 和 PostgreSQL >= 9.6。共享查询优先使用 GORM；需要行锁时使用 `lockForUpdate(tx)`。Redis、ClickHouse 和外部 Provider 都不能成为核心业务正确性的唯一事实源。

## 6. 全局不变量

1. NEWAPI 原生合同优先；Link 合同不能复制、替换或收紧原生能力。
2. Link 身份来自显式代码注册，公开能力与 Provider 实现身份相互独立。
3. 同一 Link SKU 只路由到客户可观察语义等价的实现；候选耗尽时 fail closed。
4. 显式接入共享异步创建安全边界的 Link/持久化媒体上游 POST 必须先建立 durable attempt，资金
   hold 与 `sending` 原子提交；不能从路径名称把该约束扩张到 NEWAPI 原生协议。
5. Task 使用冻结的合同、能力、实现、连接、单 Key 和计费事实完成生命周期。
6. 业务终态、计费状态和 Provider 可观测性分开建模；一次不可采信响应不等于业务失败。
7. 计费乘数先校验，quota 换算使用统一 checked 饱和函数，资金变更幂等且可审计。
8. API Key、Provider 凭据、完整签名 URL、Task 私有数据和上游资源 ID 不进入普通用户响应或日志。
9. Asset 是逻辑身份；平台素材、请求级媒体和 Provider 上游资源是三种不同生命周期。
10. 所有持久化和补偿路径继续兼容三种数据库。
