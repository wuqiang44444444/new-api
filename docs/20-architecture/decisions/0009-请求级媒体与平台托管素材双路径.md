# ADR-0009: 请求级媒体与平台托管素材双路径

> 本决策已被 [ADR-0016](0016-Seedance专用渠道与确定性素材代理.md) 取代；当前事实见
> [Seedance 专用渠道与 Link 架构](../Seedance专用渠道与Link架构.md)。

## Context

本项目显式注册的 Link 视频合同允许客户端在类型化媒体字段中直接提交 HTTP/HTTPS URL 或
Data URL。平台同时提供 `/v1/assets`、`ast_xxx` 和 `asset://ast_xxx`，用于需要复用、迁移、授权、
撤回、渠道账号绑定和生命周期治理的平台托管素材。

此前硬约束把所有视频媒体统一表述为必须使用 `asset://`。这会把请求级媒体错误地纳入素材
控制面，也与已经发布的 ModelArk 公网 URL 用法不一致。另一方面，如果把直接 URL/Data URL
当成平台素材的替代入口，又会绕过所有权、真人授权和渠道绑定。

new-api 的产品定位是模型 API 中转与治理平台，不是媒体内容审核机构或对象存储服务。平台不
对请求级媒体执行人工审核、主动抓取或长期托管，但仍必须保护自身合同、租户、凭据、计费和
敏感信息边界。

## Decision

- 显式 Link 合同中的媒体字段支持两条输入路径：
  - **请求级媒体：** 当前公开 SKU/profile 明确支持的 HTTP/HTTPS URL 或 Data URL；
  - **平台托管素材：** 通过 `/v1/assets` 创建并以 `asset://ast_xxx` 引用的素材。
- 请求级媒体只在当前请求的内存或临时 `BodyStorage` 和正式 Provider 请求中存在。不得写入 Task、
  幂等 recovery snapshot、计费探针、普通日志、metrics 或 trace；请求结束后释放。
- 请求级媒体不创建 Asset、AssetBinding、所有权声明或授权记录，不承诺复用、迁移、撤回、
  删除上游对象或跨渠道可用。网关不主动下载媒体，也不把渠道 Key、Cookie 或平台认证信息
  附加到媒体地址。
- Link 合同层仍校验媒体字段、角色、scheme 和通用大小上限；SKU/profile 在预扣和上游调用前
  校验支持的媒体类型、数量、MIME、组合和值域。不支持时返回明确 4xx，不静默删除或改义。
- 平台不对请求级媒体执行人工内容审核。调用方负责确认其有权向模型服务提交媒体，Provider
  可以按自身合同继续执行格式、内容安全和合规判断。平台“不做内容审核”不改变鉴权、租户
  隔离、合同校验、凭据隔离、计费安全和日志脱敏责任。
- `asset://ast_xxx` 继续执行所有权、状态、授权、模型、账号指纹、多素材渠道交集和每次 Provider
  尝试前的引用改写。任何原始上游素材 ID 都不得直接作为客户端平台素材引用。
- 平台已经识别为真人，或业务明确要求平台同意、认证、撤回和审计能力的素材，必须先完成已
  发布的授权流程，再通过 `asset://ast_xxx` 绑定到兼容渠道账号。未开放真人能力的 SKU 或
  分组在选渠和上游调用前拒绝已标记的真人托管素材。
- 在没有内容分类或审核能力时，网关不能仅凭直接 URL/Data URL 判断其是否包含真人。因此，
  “真人不得走请求级媒体”对未分类直接媒体是调用方义务和受控业务政策，不是平台已经实现的
  自动识别保证。若未来要求技术强制，必须先增加可验证分类/审核，或禁止全部无法证明类型的
  请求级媒体。
- 同一请求是否允许混用请求级媒体和 `asset://ast_xxx` 由公开 SKU 能力显式声明。未声明时
  fail closed；第一阶段 ModelArk 视频 SKU 拒绝混用，避免渠道 binding 交集与直接媒体能力
  产生隐式路由语义。
- 真人授权撤回只对平台可控制的后续动作给出保证：发送前 `sending` 事务锁定授权并写
  attempt—任务—素材—授权 reservation，撤回事务锁定同一授权行。撤回先提交则不得发送，
  reservation 先提交则属于可索引在途任务；任务级视频/last-frame 内容端点每次回源前检查
  授权，撤回后 fail closed；撤回流程按该关系查找 attempt/Task，并在冻结能力支持时尝试取消。
  平台不得声称撤回能收回已经提交给 Provider 的媒体、保证取消成功或删除 Provider 已处理/
  缓存的数据。
- `asset_upstream_profile: none` 只表示渠道没有平台素材 binding 能力，不表示该渠道不能接受
  其视频 profile 已声明支持的请求级媒体。
- 本决策不改变 NEWAPI 原生视频、图片或音频 DTO 的媒体字段，也不授权为原生入口增加
  `asset://`、素材中间件、协议识别或兼容分支；原生能力以上游代码为准。

## Consequences

- 收益：客户端可以直接使用模型官方合同支持的普通图片和音频，不必为一次性媒体先创建平台
  Asset。
- 收益：平台素材和真人素材继续拥有明确的所有权、账号绑定、撤回和生命周期边界。
- 收益：渠道 profile 可以独立声明是否支持 URL、Data URL 或 `asset://`，不会把 Provider
  私有字段扩张到客户端。
- 代价：渠道能力判断必须区分请求级媒体和平台托管素材，不能仅用“请求是否含媒体”决定是否
  进入 AssetRouteConstraint。
- 代价：请求级媒体不能获得平台素材的可恢复性；URL 过期、Provider 无法拉取或格式不兼容时，
  任务可以按上游合同失败。
- 风险：直接媒体可能包含调用方无权提交的内容。平台通过合同条款、调用方责任声明、Provider
  安全判断和受控能力开放管理该风险，但不把网关包装为内容审核结论提供方。
- 风险：Data URL 会消耗网关请求解析内存和 CPU，HTTP URL 存在明文传输风险；必须使用单项
  和请求总体上限、解析预算和可观测性控制，生产优先 HTTPS。

## Alternatives Considered

- 所有媒体强制先创建 `asset://`：未采用。它增加一次性媒体的接入成本，与模型官方请求级
  URL/Data URL 合同和中转平台定位不一致。
- 所有媒体都直接透传 URL/Data URL：未采用。它无法提供平台素材所有权、渠道账号绑定、真人
  授权、撤回和复用能力。
- 自动把直接媒体隐式导入素材库：未采用。它会在客户端未知的情况下产生持久化资源和生命周期，
  并扩大平台的数据持有范围。
