# ADR-0007: 视频官方北向合同与共享任务底座

## Context

[ADR-0001](./0001-视频上游协议适配与任务执行快照.md) 已确定 DoubaoVideo 渠道使用显式南向 profile，并冻结在途任务的上游连接事实。但 `video_upstream_profile` 只描述 new-api 如何调用 DoubaoVideo 上游，不能同时承担客户端产品合同。

当前公开视频产品覆盖 Seedance、Kling 和即梦。三者的请求字段、路径、错误外壳、状态和生命周期不同；同一公开模型又可能通过官方渠道、反向代理或第三方中转执行。如果用南向 profile、渠道类型或统一宽松 DTO 决定北向行为，会让客户端合同随选渠结果变化，并允许未知字段经 `metadata` 或任意 map 绕过校验。

OpenAI 视频模型已经下架，但系统仍需只读存量任务。新合同必须复用现有 Task、渠道分配、素材约束、轮询、计费和审计主链路，不能为每种厂商协议建设第二套任务系统。

## Decision

- 视频北向按公开模型/SKU 绑定厂商官方合同，使用稳定 `contract_id`：
  - ModelArk v3：`modelark.contents.generations.v3`，版本 `2024-01-01`；
  - Kling v1：`kling.v1.videos`，版本 `v1`；
  - 即梦：`jimeng.cv.async.2022-08-31`，版本 `2022-08-31`。
- 每套北向合同拥有独立 Router、类型化 DTO、字段白名单、错误外壳和响应投影。未知字段直接拒绝，正式媒体字段不得通过 `metadata` 或任意 map 搬运。
- 北向转换层只把已验证请求转换为内部统一视频任务，并把原始类型化合同保存在请求上下文中；它不选择渠道，也不决定南向鉴权、路径或响应解析。
- 三套合同共享 `Task`、创建幂等、渠道分配、素材渠道交集、轮询、取消能力判断、计费和审计。Task 使用 `client_protocol` 隔离查询范围，并冻结北向合同 ID/版本和南向 adapter 版本。
- 查询、错误和生命周期响应始终按任务创建时的 `client_protocol`/`contract_id` 投影，不按当前命中的渠道或南向响应外壳投影。
- 南向协议继续由渠道 adapter 决定。DoubaoVideo 使用 ADR-0001 的 `official`、`third_party_reverse_proxy`、`third_party_relay`；Kling 和即梦使用各自渠道 adapter。北向 ModelArk 不限定南向必须为 `official`。
- `asset://ast_xxx` 在北向合同字段中完成所有权和渠道交集约束，并在每次南向尝试前改写为该账号下的上游引用；北向合同不直接接受上游素材 ID。
- OpenAI 视频创建和 Remix 不再提供；`/v1/videos` 只保留存量任务读取，历史 `/v1/video/generations/:task_id` 只作为迁移期兼容入口。

## Consequences

- 收益：同一公开 SKU 无论命中官方、反代还是中转渠道，客户端看到的合同保持一致。
- 收益：厂商 DTO、错误和生命周期相互隔离，同时共享已有异步任务与计费事实来源。
- 收益：任务快照能够解释创建时使用的北向合同和南向 adapter，渠道编辑不会改变在途任务语义。
- 代价：新增视频厂商合同必须同时实现创建、查询、错误和生命周期投影，不能只增加一个宽松转发入口。
- 代价：兼容入口退出前需要维护只读协议隔离和存量任务查询。
- 风险：若渠道被错误标记为支持某个公开 SKU，南向可能成功接受但无法保证北向等价；生产启用必须通过合同级灰度。
- 后续约束：北向合同和南向 profile 不得互相推断；任何不兼容的北向变化必须新增合同版本或 ADR。

## Alternatives Considered

- 用一套平台视频 DTO 覆盖所有厂商：未采用。它会丢失厂商字段、错误和生命周期语义，并迫使客户端依赖私有合同。
- 根据最终选中渠道决定北向响应：未采用。同一请求的客户端合同会随权重、故障切换或管理员配置变化。
- 为 Seedance、Kling、即梦分别建设 Task 表和 worker：未采用。状态、幂等、计费和补偿会形成多套事实来源。
- 继续提供 OpenAI 视频创建作为统一入口：未采用。相关模型已经下架，继续扩展会产生没有产品事实支持的兼容承诺。
