# ADR-0017: 调用方自管无状态素材代理

## Context

ADR-0016 建立了 Seedance 专用 Channel、确定性单渠道路由和平台 `Asset` / `AssetGroup` 映射。后者把
素材固定到创建时的客户模型、Channel、Provider 作用域和 `user_id + app_id`，并在视频发送前解析
`asset://ast_*`。实际业务中，中转站用户就是一个自行管理最终用户和素材的受信应用；多个客户模型
可以配置到同一 Provider 账号与 Project。平台固定 Channel 的检查会在上游收到请求前错误拒绝真实
可复用的素材。

产品已经接受共享上游账号下的应用自律，不要求“知道另一个应用的素材 ID 仍绝对不可使用”。中转站
仍须隐藏 Channel、Provider 配置和上游原始模型名，但没有必要拥有素材目录或替 Provider 判断素材
存在性、状态、账号权限和模型兼容性。

## Decision

- 本 ADR 取代 ADR-0016。ADR-0016 中 Seedance 专用 Channel、一个启用客户模型一个 Channel、ModelArk
  V3 北向、代码协议 adapter、无随机分发/重选/fallback、durable attempt、Task 和计费决定继续有效。
- 素材控制面改为调用方自管的无状态单资源代理。所有 CRUD 请求必须携带客户模型名，由该模型选择唯一
  Seedance Channel 和 `asset_upstream_protocol`；中转站不持久化客户 `Asset` / `AssetGroup`。该边界由
  [ADR-0018](0018-Channel默认素材组基础设施配置.md)细化：允许 Channel 保存一个内部默认 Provider group
  ID 作为基础设施配置，但不得据此恢复客户资源目录、所有权或状态事实。
- 只开放创建、单项查询、已验证的单项更新/删除；不注册素材列表和素材组列表接口。创建和查询返回上游
  opaque 资源 ID；素材可用时返回 `asset://<opaque-id>`。调用方保存 `model + id + reference`。
- 视频请求中的 `asset://<opaque-id>` 原样进入所选视频 adapter。中转站不查询素材，不验证所有权、
  ready 状态、创建模型、ChannelID、Provider 作用域或兼容性；当前 Provider 作最终裁决。
- 错误 ID 只发送到当前客户模型选定的 Provider。中转站不探测 ID 来源、不切换 Channel、不跨 Provider
  fallback，并统一脱敏错误。
- 公开响应和模型元数据不返回 Provider、ChannelID、`model_mapping`、Region/Project 或上游原始模型名。
  模型元数据逐操作说明实际支持、素材组要求、URL/大小限制、`requires_model=true` 和
  `management_mode=caller_managed_stateless`，并用匿名 `reuse_scope` 表示当前配置的素材复用域。
  scope 不暴露 Provider 身份，也不替代 Provider 对存在性、权限和兼容性的最终判断。未配置素材协议或 adapter 未实现的操作明确返回
  `unsupported_asset_operation`。
- 旧 `ast_*` / `astgrp_*` 运行时合同硬切换，不保留双读、别名或 resolver。升级不自动删除历史数据库
  表或数据；如需提取历史映射，由管理员在升级前离线处理。

## Consequences

收益是去除错误的 Channel/模型素材绑定，Volcengine 同账号/Project 下的多模型可以按上游真实能力自然
复用；第三方也只需 adapter 履约，不必适配平台资源模型。网关没有账号级素材目录，跨上游差异通过逐
操作元数据和脱敏错误显式表达。

代价是中转站不提供素材所有权强隔离、目录恢复或生成前可用性保证。共享 Provider 凭据时，已知其它
应用素材 ID 可能被上游接受；调用应用必须维护自己的最终用户权限和素材记录。需要技术强隔离时，必须
使用独立 Provider 账号/Project 或重新引入经过决策的所有权层，不能在本方案上增加隐式校验。

单项查询只是按已知 ID 调用上游，不构成所有权证明，查询成功也不保证随后生成成功。Provider 状态、
内容审核和模型限制始终以当次响应为准。

## Alternatives Considered

- 保留平台 `ast_*` 映射并删除 ChannelID 检查：仍保留两套素材身份和本地作用域推断，无法获得最大
  上游兼容性，也继续承担目录与迁移责任。
- 为多个 Channel 配置共享素材作用域：需要新增共享组、指纹或白名单配置，重复表达 Provider 已有的
  账号/Project 边界，配置漂移仍会造成本地误拒绝。
- 返回加密句柄或 `asset://<provider>/<id>`：增加状态和命名空间，而调用方已接受保存 opaque ID，且
  不需要知道 Provider。
- 生成前强制查询素材：增加延迟和调用量，查询与生成之间仍存在竞态，不能替代 Provider 最终裁决。
