# ADR-0020: 客户合同范围约束与原生分发协同

## Context

取代 [ADR-0019](0019-合同解耦为客户折扣层.md)。客户合同编辑器选择模型、组和渠道，业务要求这些
组合成为绑定 Key 的履约范围。纯折扣层允许请求进入范围外渠道，不能满足该目标。

旧决策担忧跨组语义不可比、另建分发器与资格漂移。本决策明确接受跨组首次竞争改变原生 auto 组顺序，
但不把价格用作优先级：按实际组合的原生组倍率成交，不承诺跨组同价；候选汇集后仍调用原生选择器，
不建立影子组、Ability、合同随机算法或独立账本。

## Decision

本决策适用于本地客户合同明确绑定的 NEWAPI 请求及已支持的类型化入口，不改变上游协议定义；
无合同或明确停用合同的 Key 保持原生行为。用户已授权按方案实施；accepted 不代表生产验收完成。

- 启用合同限定精确模型、组和渠道组合，同时提供同模型唯一折扣。作为原生业务之上的授权层，
  替代用户可用组及 Key 的 group/auto_groups 选路范围，不与其求交集；保留 Key 模型限制、
  入口资格、额度和安全约束。用户组仍可参与原生特殊倍率计算，但不得限制合同授权。
- 完整有效候选按现有渠道优先级及权重竞争，pin/亲和必须在范围内。禁止先按组抽样造成额外权重偏差。
- 跨组重试关闭时，后续限于首次实际选中组；开启时可在合同内跨组。原生重试次数及异步发送闸门保留。
- 未列模型、无有效组合、合同读取或一致性异常失败关闭。只有明确停用或解绑恢复 Key 原生范围与价格。
- 模型费用为原生费用小计 × 实际有效组倍率 × 合同折扣。发送前刷新组价，同一资金会话补足较高
  预估，终态结算差额；保留原生信任、钱包、订阅和 Key 额度策略及实际资金证据。
- Key 模型发现和报价反映有效范围；完整合同明细保留不可用条款并标注状态，不公开渠道身份。
- 旧任务继续冻结事实；新的 remix 必须在当前合同内使用锁定渠道，否则拒绝。类型化渠道按自身事实
  校验，不依赖通用 Ability，不因原生另有可用渠道而豁免合同。

## Consequences

合同选定的范围能够约束实际履约，原生优先级、权重和组倍率仍各司其职。代价是绑定合同的 Key
可能失去未列模型或合同组合失效时的调用资格；非 auto Key 原存储的跨组重试关闭状态不会自动打开。
停用/解绑可能恢复更宽的原生范围，界面须明确提示。升级前核对存量合同、Key、权限、渠道与价格差异，
避免新旧语义实例混用。旧代码回滚会恢复纯折扣语义，不默认视为范围安全的止血措施。

运行事实与最小接线见[合同定价架构](../账单计费-用户模型合同定价架构.md)；真实 Provider、真实账单、
外部数据库和生产灰度仍需单独验收。

## Alternatives Considered

- 继续纯折扣层：不能满足合同选择渠道即限定履约范围的业务要求。
- 合同固定渠道 pin：压制原生多渠道优先级和权重，不能表达本次确认的竞争机制。
- 按用户可用组或 Key 默认组求交集：会错误排除合同明确授权的内部组；Default 用户不应因
  内部组未向普通 Key 开放而无法履约，也不应为合同调用额外扩大用户的原生组权限。
- 按合同组顺序或最低倍率选路：引入未经要求的排序和价格择优政策。
- 单独复制随机选择器：形成两套优先级/权重语义，增加上游同步成本。
- 失效时回退原生：把履约失败误当成合同停用，重新造成越界。
