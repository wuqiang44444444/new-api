# ADR-0008: 共享异步任务计费状态机与原子补偿

## Context

本决策取代 [ADR-0002](./0002-异步任务表达式计费快照与补偿结算.md)。ADR-0002 最初只让 `tiered_expr` 视频任务进入持久化计费状态机；当前系统已经把该边界扩展到所有正式北向视频任务和持久化异步图片任务。普通按次任务也需要终态退款与幂等门闩，图片任务还需要按实际结果数或可信 usage 结算。

异步业务终态与资金写入不能组成跨 Provider 的单一事务。任务可能成功、失败、取消或过期，而钱包、订阅、Token、任务额度和日志尚未完成调整。系统必须在 SQLite、MySQL 和 PostgreSQL 上用同一状态模型恢复，并确保任何异常输入、算术饱和或重试都不会产生负费用或重复资金变更。

## Decision

- 所有正式北向视频任务和持久化异步图片任务使用 `Task.private_data.async_billing`。同步请求和未持久化的普通图片请求保持原同步计费链路。
- `tiered_expr` 任务冻结表达式、版本、哈希、分组倍率、预估 token、额度换算和白名单计费探针；普通按次任务通过冻结的 `BillingContext.PerCallBilling` 使用同一状态机，但不伪造表达式快照。
- 计费状态为 `pending`、`settled`、`failed`、`debt`，并投影到普通列 `billing_state`：
  - `pending`：已预扣，等待业务终态；
  - `settled`：目标额度已原子应用，重复执行为空操作；
  - `failed`：计算或持久化失败，允许有界重试；
  - `debt`：表达式实际目标超过冻结预扣上界，禁止自动突破上界。
- 只有 `SUCCESS`、`FAILURE`、`CANCELLED`、`EXPIRED` 可以进入补偿。`UNKNOWN` 仍是活动状态，不能因暂时无法识别上游状态而提前结算。
- 失败、取消和过期终态的目标额度为零。成功终态按冻结合同计算；图片固定价格按不超过请求 `n` 的实际去重结果数结算，表达式任务只使用经过验证的 usage。
- 在写入资金前持久化 `operation`、`target_quota`、`reason`、实际 token 和可选 `quota_clamp`，使进程退出后的重试使用同一个确定目标，而不是重新读取管理员当前价格。
- `ApplyTaskBillingTarget` 在单一数据库事务内锁定 Task；订阅记录使用行锁，用户钱包和 Token 使用带余额条件的原子更新。同时提交资金、Task quota、私有计费状态和 `billing_state`，任何已 `settled` 的重复调用都不再次调整资金。
- 所有额度换算使用统一的 checked 饱和函数。发生饱和时把标记写入任务计费快照、管理员日志和请求关联警告；不得使用裸整型转换产生负收费。
- `pending`、`failed`、`debt` 的终态任务进入带退避和次数上限的补偿扫描。`debt` 不自动补扣超过冻结上界的差额，达到上限后留给管理员审计处置。
- 计费探针只保存经过白名单构造的业务维度，不保存 Authorization、Cookie、完整请求头、原始图片或其他可重放秘密。

## Consequences

- 收益：视频、异步图片、按次和表达式任务共享一个可恢复计费事实来源。
- 收益：业务终态与资金操作可以独立重试，且管理员改价不会改变在途任务目标。
- 收益：取消、过期、超额、饱和和部分持久化失败都有显式、可审计的处理语义。
- 代价：普通按次异步任务也需要保存计费状态和冻结上下文，Task 私有数据更复杂。
- 代价：`debt` 和达到重试上限的任务需要管理员监控与处置。
- 风险：遗漏新的终态、资金来源或计费乘数会破坏原子性；新增异步产品必须覆盖完整链路测试。
- 后续约束：任何异步计费路径都必须追踪“输入上界 → 预扣 → 冻结快照 → 业务终态 → 原子目标额度 → 补偿和审计”。

## Alternatives Considered

- 仅对表达式任务持久化计费状态：未采用。普通视频和固定价格异步图片同样可能在终态退款或结算时进程退出。
- 每种异步产品建立独立计费状态机：未采用。钱包、订阅、Token 和补偿语义会重复并产生不一致。
- 终态时重新读取当前价格：未采用。任务执行期间改价会改变已经成立的计费合同。
- 实际目标超过预扣时直接补扣：未采用。它可能突破用户余额和管理员配置的安全上界。
- 只记录错误日志、不保存目标额度：未采用。补偿时无法证明重试使用的是同一资金目标。
