# ADR-0014: Link 资源源引用与双模式解析

## Context

本决策取代 [ADR-0004](./0004-中转型素材代理与上游绑定.md) 和 [ADR-0012](./0012-真人素材单图同步流式边界.md)。ADR-0004 把 `ast_*` 限定为创建时选定的单一上游素材 binding 的平台别名，不保存完整源 URL；ADR-0012 又为 FunCloud 增加了单图 multipart 同步流式例外。FunCloud 最新视频合同已改为直接消费 HTTPS 媒体 URL，旧二进制例外失去事实依据；同时，平台的业务目标是让 FunCloud、Moxing、官方等上游在同一 Link 资源合同下为客户提供一致的 `asset://ast_*` 体验。

客户希望只在创建 Link 资源时提交一次源 URL，以后只使用 `asset://ast_*`。但 `ast_*` 是平台逻辑引用，不是媒体字节容器。对提供托管素材生命周期的 Provider，源 URL 只用于建立 binding；对 FunCloud 这类只接受 URL 的 Provider，源 URL 是每次任务的实际数据路径。如果平台不托管媒体字节、Provider 也不创建上游素材，则临时签名 URL 过期后无法继续履行“长期可重复使用”承诺。

平台仍必须保持网关边界：不主动 GET/HEAD 客户 URL，不保存媒体二进制，不引入 multipart 转换桥、本地暂存或对象存储。完整源 URL 可能包含 OSS/CDN 签名和可重放凭据，必须作为敏感数据加密保存并严格限制使用边界。

## Decision

1. **Link 资源是平台逻辑身份。** `Asset` 保存 `ast_*`、所有权、App/最终用户作用域、类型和状态；它可关联一个不可变 `AssetSource` 和零到多个 `AssetBinding`。`model` / `target` 只是可选的首个 binding 预创建提示，不再定义 Asset 身份。
2. **客户创建后只使用 `asset://ast_*`。** 客户无需在后续视频请求中重复提交源 URL。但 `ready` 只表示当前至少存在一条可解析路径，不表示平台已永久托管媒体或承诺所有 Provider 永久可用。
3. **权威 Resolver 支持两种内部解析模式：**
   - `upstream_binding`：返回选中 channel/profile/凭据作用域下的 active 上游素材引用。binding 成功后，源 URL 对该 binding 只是初始建立输入；源过期不使已有 binding 自动失效。
   - `source_url`：在内存中短暂解密并返回 HTTPS 源 URL。该 URL 是 Provider 每次执行的实际依赖，其过期、撤销、对象删除或上游无法访问都可使当前任务不可用。
   [ADR-0005](./0005-官方-action-素材合同与-bearer-兼容边界.md) 定义的官方 Action 凭据和合同隔离继续作为 `upstream_binding` 模式的 Provider 专项约束，不因本决策被取代。
4. **解析优先级为 active binding，其次才是渠道明确支持的 `source_url`。** Provider converter 不查库、不解密、不自行决定授权。选渠和每次发送前必须使用同一套 Resolver 规则重新校验所有权、状态、真人授权、binding 凭据作用域、源过期时间和 Provider 最小抓取 TTL。
5. **`AssetSource` 是最小化的短期执行引用，不是 Asset 身份。** 它只保存 `asset_id`、带 Asset scope 的认证加密 URL 和客户声明的 `expires_at`；不设置公开 ID、URL HMAC、独立状态机、错误字段、密钥版本或后台清理任务。URL 字符串不能证明媒体相同，平台资源身份只由 `ast_*` 表达；创建幂等继续使用规范化完整请求的作用域 HMAC。明文不得进入 API 响应、Task/attempt 快照、普通日志、metrics 或 trace。
6. **`expires_at` 是可用性提示，不是 URL 类型识别机制。** 值大于 0 时，`source_url` 候选渠道只在其剩余时间覆盖 `AssetSourceMinTTLSeconds` 时可用；值为 0 表示客户未声明有效期，不解释为永久有效，平台按 best-effort 交给 Provider。平台不解析 OSS 签名参数，也不为未知有效期增加域名猜测或永久 URL 识别。明确不足或已过期时不再发送给 Provider。
7. **源过期不等于 Asset 必然失效。** 有 active binding 的渠道可继续使用；已声明过期的 `source_url` 渠道从候选集合移除。当所有 binding 和 source 路径均不可用时，Asset 才表现为当前不可解析。`ready` 是查询时点的资产级聚合状态，不保证任意 SKU 或渠道可用；具体请求以选渠和发送前校验为准。API 不建立独立 source 状态合同。
8. **不原地刷新或替换源 URL。** 客户为同一 OSS 对象取得新签名 URL 后，通过显式 migration 创建新 `ast_*`，保留 `supersedes_asset_id` 等谱系。本决策不引入 source refresh、原地内容替换或“相同对象”字节级证明。
9. **公开产品能力与内部解析能力分层。** `SupportsLinkAssets` 属于公开 `VideoSKUCapability`，参与客户合同等价 hash；`SupportsManagedAssets`、`AssetResolutionModes` 和 `AssetSourceMinTTLSeconds` 属于 channel/profile 内部实现声明，使用独立实现版本/快照，不参与公开 SKU 等价 hash。
10. **一次性 URL 仍使用请求级媒体路径。** 仅为当前视频任务服务的短时签名 URL 不应被包装为长期可复用 Link 资源。[ADR-0009](./0009-请求级媒体与平台托管素材双路径.md) 的双路径决策继续有效；同一请求是否允许 URL 和 Link 资源混用仍由公开 SKU 显式声明，未声明时 fail closed。
11. **FunCloud 只作为 URL-only 视频执行 Provider。** 它可在源 TTL 足够时通过 `source_url` 消费 `general` Link 资源，不创建 `AssetBinding`。旧 H5、`bytedToken`、multipart、material list、raw upload 和专用 attempt 链路全部退出目标架构。FunCloud `realPersonMode` 语义书面澄清前不注册公开 SKU、不发送 `true`，平台 `real_person` Link 不路由到 FunCloud。

## Consequences

- 收益：客户创建后统一使用 `asset://ast_*`，无需了解 FunCloud、Moxing 或官方的素材 ID 与生命周期协议。
- 收益：Link 资源不再固定为单一 Provider 别名，既可使用已托管 binding，也可在 URL-only Provider 上使用受保护源引用。
- 收益：平台仍不成为媒体二进制事实来源，不引入对象存储、下载型 SSRF、扫描、容量配额和文件 janitor。
- 代价：平台在源有效期内保存可重放的敏感 URL，必须使用现有持久密钥做带 Asset scope 的认证加密、严格日志脱敏，并在无法解密时关闭 `source_url` 路径；本决策不建设独立密钥注册表、密文迁移或 source 保留系统。
- 代价：`source_url` 的可用性取决于客户源站、签名 TTL、队列时间和 Provider 抓取能力；一部分失败会从 Asset 创建阶段延后到视频任务执行阶段。
- 代价：对 FunCloud 这类无 binding 的 Provider，客户虽然只提交 `asset://ast_*`，但可复用时间仍不超过源 URL 实际可用期；本决策不宣称“Asset 创建成功后源立即可丢弃”。
- 风险：平台不访问源 URL、不保存字节哈希，因此无法证明两个 URL 指向同一媒体、远程 URL 的内容从未替换，或客户声明的 `expires_at` 之前一定可访问；`expires_at=0` 的任务只能 best-effort 执行。
- 后续约束：公开 API 和文档必须区分“客户不需重传 URL”与“平台已永久物化媒体”；不得将前者误写为后者。
- 后续约束：引入原地 source refresh、稳定客户 ID 下的内容替换、平台二进制托管或自动 URL-to-multipart 都会改变当前身份、安全和数据边界，必须另行架构评审。

## Alternatives Considered

- **保留 ADR-0004 的单主 binding 模型**：安全和运行时边界更简单，但会将 `ast_*` 固定到创建时的模型、渠道和凭据，且 FunCloud 等 URL-only Provider 无法进入统一 Link 资源体验，未采用。
- **要求 Asset 创建成功即至少存在一个永久 binding**：可以让源 URL 在创建后退出数据路径，但会再次排除没有 managed-assets API 的 Provider，也无法履行统一 FunCloud 体验的业务目标，未采用。
- **平台对象存储作为唯一媒体事实来源**：可提供长期稳定 URL 和跨 Provider 恢复，但会使网关承担二进制存储、SSRF、扫描、容量、跨区和敏感数据生命周期，未采用。
- **保留 FunCloud URL-to-multipart/单图流式桥**：新 Provider 合同已直接接受 HTTPS URL，继续保留会扩大二进制处理、故障恢复和安全面，未采用。
- **允许原 `ast_*` 原地刷新签名 URL**：可保留客户 ID，但平台无法在不下载字节的前提下证明新旧 URL 对应同一媒体，并会引入与已排队/发送任务的版本竞态，未采用。
- **FunCloud 只支持请求级 URL，完全退出 Link 资源**：实现最简单，但同一客户素材无法使用统一 `asset://ast_*` 在兼容渠道间选路，与已确认的 Link 产品目标不符，未采用。
