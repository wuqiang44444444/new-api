# ADR-0002: 异步任务表达式计费快照与补偿结算

> 本决策已由 [ADR-0008](./0008-共享异步任务计费状态机与原子补偿.md) 取代。ADR-0008 将持久化计费状态机扩展到所有正式北向视频任务和异步图片 Task，并补齐取消、过期、固定价格、目标额度与饱和审计。

## Context

同步请求可以在单次调用内完成预扣和结算，异步视频任务则需要在创建后经过多次轮询才能得到终态和实际用量。任务执行期间，管理员可能修改模型表达式、分组倍率或预扣上界；如果终态重新读取当前配置，同一任务的预扣与结算会使用不同计费合同。

终态状态写入与资金调整也不能视为一个天然原子操作。进程退出、数据库错误或额度不足都可能使任务已经成功或失败，但钱包、令牌、订阅和任务计费状态尚未完成调整。补偿机制必须可重试、幂等、跨 SQLite/MySQL/PostgreSQL 工作，并且不得把非终态任务提前结算。

## Decision

- 只有启用 `tiered_expr` 的异步任务进入表达式计费状态机；普通异步任务继续使用既有按次/倍率计费与退款链路。
- 创建任务时，以客户端公开模型名读取管理员配置的表达式和任务预扣 token 上界。表达式是价格事实来源，不叠加 Provider 内置价格或隐式倍率。
- 预扣时在 `Task.private_data.async_billing` 冻结可复算的 `BillingSnapshot`，至少包含模型、表达式及哈希、表达式版本、分组倍率、预估 token、预估额度、命中档位和 quota 换算参数。
- 请求相关计费维度必须来自发送给上游的受类型约束 DTO。任务计费探针只持久化经过白名单构造的 `_task` body，不持久化 Authorization、Cookie 或任意请求头。
- 计费状态使用 `pending`、`settled`、`failed`、`debt`：
  - `pending` 表示已预扣、等待终态结算；
  - `settled` 表示资金目标已原子应用；
  - `failed` 表示可重试的计算或持久化失败；
  - `debt` 表示实际目标超过预扣上界或无法安全补扣，需要审计处理。
- 任务进入 `SUCCESS` 或 `FAILURE` 后才能执行结算或退款。补偿查询必须在数据库 WHERE 条件中同时限制任务终态和待处理计费状态，不能只依赖 Go 内存过滤或方法命名。
- 结算使用冻结表达式和冻结分组倍率，根据已验证的实际上游用量计算目标额度；上游未返回可信用量时不得伪造 usage。
- 资金调整、Task quota 和计费状态变更必须位于同一数据库事务，并使用 `lockForUpdate(tx)` 保护任务及相关资金记录。重复执行已经 `settled` 的任务必须成为无操作。
- 实际目标低于预扣时退还差额；失败终态目标为零；实际目标超过预扣上界时进入 `debt`，不得让用户、令牌或订阅额度变为负数。
- `billing_state` 作为 `private_data.async_billing.state` 的可索引投影，仅服务于跨数据库补偿扫描；完整计费事实仍保存在任务私有数据中。
- 失败记录采用有上限的重试与退避，并在管理员可见日志中保留任务、状态、原因和额度饱和标记；用户日志不得暴露表达式探针中的敏感信息。

## Consequences

- 收益：任务创建后的价格、倍率和表达式变更不会影响在途任务，预扣和终态结算可以确定性复算。
- 收益：资金调整与计费状态具有事务性和幂等性，终态后失败可以通过补偿扫描恢复，而不是依赖单次轮询进程存活。
- 收益：投影列避免跨数据库查询 JSON 字段，保持 SQLite、MySQL 和 PostgreSQL 一致实现。
- 代价：Task 私有数据和任务表增加计费状态，轮询、结算、退款和补偿之间形成显式状态机。
- 代价：模型必须配置任务预扣上界；过低会进入 debt，过高会增加任务执行期间的资金占用。
- 风险：错误的终态过滤会提前结算非终态任务；错误的 usage 语义会产生系统性错账。因此终态条件、无 usage、表达式失败、退款、debt 和重试上限都属于接受本 ADR 前的强制回归边界。
- 后续约束：任何新增异步计费路径都必须追踪“请求校验 → 预扣估算 → 快照 → 终态 → 原子资金调整 → 补偿与审计”的完整链路。

## Alternatives Considered

- 终态直接读取管理员当前价格重新计算：未采用。它会让运行中改价追溯性丢失，并使预扣与结算合同不一致。
- 只在轮询进程内完成结算，不保存独立计费状态：未采用。进程退出或资金写入失败后缺少确定性补偿入口。
- 把表达式和完整原始请求、请求头全部写入任务：未采用。它会扩大 Authorization、Cookie 和用户输入的持久化与泄露面。
- 对实际超额无条件补扣：未采用。它可能突破余额安全边界；上界估计失败必须进入可审计的 debt，而不是产生负余额。
- 使用数据库专用 JSON 查询定位待补偿任务：未采用。它会增加三种数据库的方言分支和迁移成本；采用可索引投影列更直接。
