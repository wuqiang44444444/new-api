# ADR-0023: 全站 API 密钥合同准入

## Context

ADR-0020 为绑定了启用合同的 API 密钥限定模型、分组和渠道。未绑定或合同停用后，密钥会恢复原生分组
模型和价格。部署需要能要求每把密钥先取得合同授权，避免解绑、停用或新建未绑定密钥使模型访问范围扩大。
用户确认在系统请求策略中提供开关，默认开启，适用于所有用户分组。

## Decision

- 开启时，API 密钥必须绑定启用的客户合同才能发现模型和发起新模型调用。禁止按用户分组、密钥指定组或
  `auto` 回退。关闭时只有未绑定或明确停用的合同密钥使用原生分组规则，启用合同继续决定调用范围和折扣。
- 准入覆盖原生代理和本地扩展的模型入口，沿用各自公开协议。模型发现与调用共用授权规则。已受理资源的
  查询、交付和取消沿用资源归属及冻结事实，新的派生操作重新授权。
- 在现有每把密钥的绑定和事务化请求策略之上实施。该决策修订
  [ADR-0020](0020-客户合同范围约束与原生分发协同.md) 的无条件原生分组回退条款，其合同范围、
  原生选渠协作及计费边界继续有效。

## Consequences

未保存该选项的部署按开启处理，未绑定的存量密钥随新版节点启用而失去模型访问。仍需要原生分组的部署
可以在接流量前持久化显式关闭值。合同启用、停用和解绑的影响应按实际策略解释。已有任务的结算与已冻结
授权不依赖当前开关。关于实际路径和灰度边界，见[用户模型合同定价架构](../账单计费-用户模型合同定价架构.md)。

## Alternatives Considered

- 默认关闭。可以减少旧部署升级影响，但新安装和未配置环境仍会直接授权分组模型，和确认的默认规则相冲突。
- 按用户组分别设置。会使全站授权取决于原生路由分组，增加管理和验证成本。
- 固定开启。会移除用户明确要求保留的原生分组使用方式。
