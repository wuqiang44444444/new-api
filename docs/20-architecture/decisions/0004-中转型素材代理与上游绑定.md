# ADR-0004: 中转型素材代理与上游绑定

## Context

本决策取代 [ADR-0003](./0003-统一素材库与托管真人授权.md)。new-api 是 AI API 中转网关，原决策却要求平台把客户 URL、base64 和直传文件统一固化到 Azure Blob，因而承担了长期二进制存储、下载型 SSRF 防护、扫描、容量配额和跨境敏感数据保存等超出网关定位的责任。

MOXING 现有素材协议均能以 Provider 可访问 URL 创建上游素材。平台仍需隐藏上游 ID、保证租户隔离、冻结素材所属渠道账号，并在视频请求中安全改写资源引用。

## Decision

- 素材只有 URL 中转模式：客户提供 Provider 可访问的公网 HTTPS URL，平台不对该 URL 执行 GET/HEAD，不保存二进制或完整 URL。
- 创建请求必须且只能指定 `model` 或管理 `target`。平台在首次创建时选定单 Key 渠道，并把唯一主 binding 固定到 Provider profile、channel 和凭据指纹。
- 平台仅持久化 `ast_xxx` 与上游 resource/reference、渠道账号和授权 scope/group 的控制面映射。`asset://ast_xxx` 只能在原 binding 账号和严格匹配的请求模型中使用。
- 所有 remote Provider profile 必须配置经合同验证的 `asset_min_url_ttl_seconds`。缺少抓取窗口或抓取端 SSRF 保护证据时 fail closed。
- `Idempotency-Key` 以 HMAC 摘要保留 24 小时。网络结果不确定时进入 `create_unknown`，同键重放不再次创建；无可靠对账能力时在有界期限后以 `asset_creation_outcome_unknown` 结束并记录孤儿风险。
- 原 Azure/managed 方案从未部署，因此不保留兼容模式、Blob SDK、扫描器、存储字段、上传/下载端点或 `ASSET_SOURCE_MODE`。未来若需要托管数据面，必须单独立项，不在本素材代理中预留失效实现。
- 真人授权、H5 session、scope/group、素材和视频路由必须固定到同一 Provider 账号。未获得书面合同、官方白名单或可验证协议时，对应 profile 保持关闭，不猜测官方 AK/SK 接口。

## Consequences

- 收益：平台不是客户素材二进制的事实来源，核心依赖中不包含 Azure Blob SDK、扫描器、下载导入或存储配额。
- 收益：仍保留稳定的平台 ID、租户隔离、渠道账号约束、状态归一化和可重试删除。
- 代价：remote 素材不能透明跨渠道迁移；上游资源丢失或凭据变更后，客户必须从自有源对象重新签发 URL 并创建新 `ast_xxx`。
- 代价：客户必须自备 OSS/S3/Blob/CDN，并承担源对象保留、签名和流量责任。
- 风险：网关侧 DNS 预检查不能替代 Provider 真实连接阶段对重定向、DNS rebinding 和元数据地址的防护。
- 后续约束：未确认抓取和删除合同的 Provider 不得进入 remote 路由集；改变不保存 URL/二进制边界必须再次架构评审。

## Alternatives Considered

- 继续以 Azure Blob 作为唯一事实来源或保留 managed 兼容层：未采用。该方案从未部署，没有存量数据需要兼容；保留无调用方的 SDK 和环境变量只会扩大依赖、配置和安全面。
- 临时上传桥接：未采用，因为依然需要平台接收、扫描、保存和清理二进制，与责任边界相冲突。
- 允许客户直接使用上游 `asset://asset-xxx`：未采用，因为平台无法验证归属或保证重试不跨账号。
- 同一 remote asset 挂多个 binding：第一版未采用，因为没有平台二进制副本时无法在签名 URL 失效后可靠重建。
