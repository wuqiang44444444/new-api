# ADR-0021: 视频创建占款 24 小时资金保障退款

## Context

ADR-0016 及当时 Seedance 架构要求 `unknown` 不自动退款、不设置自动释放期限，只有技术人员核实
Provider 明确未创建后才人工释放资金。线上运行显示该设计把"无法确认上游是否创建"与"客户资金必须
一直冻结"绑定：大量 unknown + held 记录既进不了自动退款路径，也缺乏持续有人处理的人工闭环，
客户余额被无限期占用。DNS 解析失败等确定未发送的错误还被误归为 unknown，进一步扩大占款规模
（见 docs/99-archive/2026/09/2026-09-22-视频创建未知结果长期占款问题分析与退款闭环方案.md）。

用户明确要求客户资金不得无限等待，并指定保障期限为 24 小时。

## Decision

1. 视频创建 attempt 在预扣成功时冻结 24 小时客户资金保障期限（`funds_deadline_at`，不复用 Task
   执行期限 `task_deadline_at`）。到期仍 held 且未完成 Task 原子转移的
   `sending/unknown/upstream_succeeded` 记录由系统自动释放客户预扣（保障退款）。
2. 资金结果与业务结论分开表达：保障退款只释放客户 hold 并写入 `release_reason`，不伪造 Provider
   拒绝、成功或失败；`unknown` 语义保持未知。潜在 Provider 成本记录 `ProviderCostExposure`，
   金额未知时保持未知，不得以客户 quota 冒充上游成本。
3. 释放事务原子提交资金回退、hold 状态、处置审计与 exposure；已软删除或硬删除的 Token 不阻断
   客户退款。业务方明确本站不支持订阅，本决策仅处理钱包并同步 Key 额度；不引入订阅周期、核销
   或权益补偿，异常非钱包来源保留可见且禁止转换为钱包信用。
4. 资金保障调度独立于 Provider 轮询开关与 `next_attempt_at` 技术调度，按固定周期扫描到期与退款
   失败记录；失败项推进下次执行时间并告警，不因尝试次数上限静默退出。到期后的创建恢复入口把
   未转移记录转入保障退款，不得补建收费 Task 绕开期限。
5. 继续禁止自动重发与换渠道；确定未发送的传输错误进入既有拒绝释放路径立即退款，不等期限；
   人工保障退款（可早于期限）复用同一资金入口。正式视频 Task 支持独立的售后退款指令，
   按当前净收费退回并免收未扣差额；原结算与 Provider 状态保留，退款后禁止自动补扣。

本决策部分取代 ADR-0016 中"unknown 不设置自动释放期限、不自动退款"的条款；ADR-0016 其余决策与
ADR-0017 继续有效。

## Consequences

- 每笔已预扣的视频钱包创建请求最终必有资金结果：正常转移结算，或按期限释放；不再出现无期限占款。
- 上游已执行但响应丢失的场景由平台承担潜在 Provider 成本并以 exposure 审计；响应大量丢失时用
  渠道监控与运营处置控制故障扩散，不转嫁给客户。
- 退款后收到的迟到成功结果仅用于核实与平台成本记录，不重新扣费、不恢复执行。
- 存量 held 记录按 `created_at + 24 小时` 回填期限并直接进入保障退款队列。

## Alternatives

- 维持人工核实后释放：被线上事实否定，缺少人工闭环时客户资金无限占用。
- 缩短到分钟级自动释放：上游创建延迟通常在秒级到分钟级，过短期限会把"上游成功、响应在途"误
  退款的比例放大，24 小时在客户体验与平台风险之间取得平衡。
- 按 Provider 查询能力自动补查后退款：多数无 Provider 查询通道，且不能替代客户资金的期限保障。
