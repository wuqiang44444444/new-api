# ADR-0007: 视频 Link 合同与共享任务底座

## Context

[ADR-0001](./0001-视频上游协议适配与任务执行快照.md) 已确定 DoubaoVideo 渠道使用显式渠道 profile，并冻结在途任务的上游连接事实。但 `video_upstream_profile` 只描述 new-api 如何调用 DoubaoVideo 上游，不能同时承担客户端产品合同。

当前公开视频产品覆盖 Seedance、Kling 和即梦。三者的请求字段、路径、错误外壳、状态和生命周期不同；同一公开模型又可能通过官方渠道、反向代理或第三方中转执行。如果用渠道 profile、渠道类型或统一宽松 DTO 决定客户端行为，会让客户 API 合同随选渠结果变化，并允许未知字段经 `metadata` 或任意 map 绕过校验。

OpenAI 视频模型已经下架，但系统仍需只读存量任务。新合同必须复用现有 Task、渠道分配、素材约束、轮询、计费和审计主链路，不能为每种厂商协议建设第二套任务系统。

## Decision

- 视频客户端按公开模型/SKU 绑定厂商官方合同，使用稳定 `contract_id`：
  - ModelArk v3：`modelark.contents.generations.v3`，版本 `2024-01-01`；
  - Kling v1：`kling.v1.videos`，版本 `v1`；
  - 即梦：`jimeng.cv.async.2022-08-31`，版本 `2022-08-31`。
- 每套 Link 合同拥有独立 Router、类型化 DTO、字段白名单、错误外壳和响应投影。未知字段直接拒绝，正式媒体字段不得通过 `metadata` 或任意 map 搬运。
- 每个公开 SKU 使用版本化能力声明冻结字段值域、规范化、媒体组合、查询、取消、删除和内容
  下载语义。该声明是 SKU 能力合同的唯一权威；渠道/profile 只能声明是否完整实现，不能反向改变公开
  SKU。具体等价规则遵循 [ADR-0010](./0010-视频公开SKU能力与候选渠道等价.md)。
- 客户端转换层只把已验证请求转换为内部统一视频任务，并把原始类型化合同保存在请求上下文中；它不选择渠道，也不决定 Provider 鉴权、路径或响应解析。
- 三套合同共享 `Task`、创建幂等、渠道分配、素材渠道交集、轮询、取消能力判断、计费和审计。Task 使用 `client_protocol` 隔离查询范围，并冻结 Link 合同 ID/版本和渠道适配协议版本。
- 查询、错误和生命周期响应始终按任务创建时的 `client_protocol`/`contract_id` 投影，不按当前命中的渠道或 Provider 响应外壳投影。
- Task 同时冻结创建时的 SKU 能力版本和生命周期能力。Ability 发布时拒绝能力不等价的候选
  绑定，运行时再次 fail closed；不得让同一 SKU 的 DELETE、内容下载或字段支持随随机渠道变化。
- 渠道适配协议继续由对应渠道 adapter 实现。DoubaoVideo 使用 ADR-0001 的 `official`、`third_party_reverse_proxy`、`third_party_relay`；Kling 和即梦使用各自渠道 adapter。客户端 ModelArk 不限定 Provider 必须为 `official`。
- 官方合同允许的请求级 URL/Data URL 与 `asset://ast_xxx` 是两条媒体路径；
  `asset://ast_xxx` 在 Link 合同字段中完成所有权和渠道交集约束，并在每次 Provider 尝试前改写为该
  账号下的上游引用；Link 合同不直接接受上游素材 ID。两条路径遵循
  [ADR-0009](./0009-请求级媒体与平台托管素材双路径.md)。
- OpenAI 视频创建和 Remix 不再提供；`/v1/videos` 只保留存量任务读取，历史 `/v1/video/generations/:task_id` 只作为迁移期兼容入口。

## Consequences

- 收益：同一公开 SKU 无论命中官方、反代还是中转渠道，客户端看到的合同保持一致。
- 收益：厂商 DTO、错误和生命周期相互隔离，同时共享已有异步任务与计费事实来源。
- 收益：任务快照能够解释创建时使用的 Link 合同和渠道适配协议，渠道编辑不会改变在途任务语义。
- 代价：新增视频厂商合同必须同时实现创建、查询、错误和生命周期投影，不能只增加一个宽松转发入口。
- 代价：兼容入口退出前需要维护只读协议隔离和存量任务查询。
- 风险：若渠道被错误标记为支持某个公开 SKU，Provider 可能成功接受但无法保证客户端等价；生产启用必须通过合同级灰度。
- 后续约束：Link 合同和渠道 profile 不得互相推断；任何不兼容的客户端变化必须新增合同/SKU
  能力版本或 ADR。

## Alternatives Considered

- 用一套平台视频 DTO 覆盖所有厂商：未采用。它会丢失厂商字段、错误和生命周期语义，并迫使客户端依赖私有合同。
- 根据最终选中渠道决定客户端响应：未采用。同一请求的客户 API 合同会随权重、故障切换或管理员配置变化。
- 为 Seedance、Kling、即梦分别建设 Task 表和 worker：未采用。状态、幂等、计费和补偿会形成多套事实来源。
- 继续提供 OpenAI 视频创建作为统一入口：未采用。相关模型已经下架，继续扩展会产生没有产品事实支持的兼容承诺。
