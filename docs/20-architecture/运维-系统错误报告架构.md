# 系统错误报告与资源告警架构

## 边界与权威

日报复用系统任务调度和既有错误事件。主库保存统计进度、冻结正文、逐地址投递状态及资源告警异常记录。
日窗口覆盖北京时间前一自然日，次日 06:00 为最早发送时间。错误详情仍由管理后台读取。模板、发信通道
与提交成功语义见[邮件投递架构](运维-用户生命周期邮件通知架构.md)。

## 日报生成与投递

1. 主节点通过现有 `error_report` 系统任务推进日窗口。首次配置运维收件人时从前一自然日开始。清空收件人或重启时保留游标。
   升级迁移移除旧日报开关、停止待投递的小时邮件并保留历史与日报游标。运行时只领取日报投递。
2. 每轮读取有限个已结束的五分钟切片，查询已记录错误总数、类型和受影响渠道。每批数据库读取限时，
   持久化游标和有上限的候选聚合结果。读取失败时保持当前进度。
3. 全部切片完成且到达次日 06:00 后，汇入当日失败运维任务及资源异常开启次数。只生成一份汇总正文，
   说明迟到记录和排行估计的边界。报告状态、冻结正文及逐地址投递行原子发布。
4. 投递采用租约和按地址轮转，发送前重新核对收件人。明确失败采用有界退避。提交结果不明或发送租约
   失效时保留 `submission_unknown` 待核对，后续日报可继续发送。提交成功写为 `transport_accepted`，
   历史 `smtp_accepted` 保持终态含义。通道受理表示已交付给发信服务，收件结果由收件箱验证。

## 网关资源告警

- 每个运行中的网关实例低频采样。Linux 容器按有效 cgroup 限额计算 CPU 和内存，硬盘检查本机数据目录
  与日志目录所在文件系统。同一卷去重。无有效读数时保持异常状态。
- 达到或超过阈值开启该节点、资源的一次异常，低于阈值才关闭。主库的唯一开放异常键抵御重复采样、
  重启和并发。开启异常时同事务保存冻结正文和逐地址待投递记录。有界队列满或进程重启后可从主库续跑。
  明确失败按收件人退避，已受理及结果不明的记录停止自动投递。升级前已开放的异常没有逐地址提交证据，
  恢复后再次越过阈值时按新逻辑记录。
- 资源告警、日报和上游余额提醒共用报告收件人。网关进程停顿或无法运行的探活不由此邮件链路承担。
  上游低余额提醒记录结果不明的时间，并按原有 24 小时提醒周期决定下一次发送时间。

实现见[日报处理器](../../service/daily_error_report.go)、[日窗口持久化](../../model/daily_error_report.go)
和[资源采样](../../service/resource_alert.go)。本地性能结果与真实通道验收分开记录，未完成的
Microsoft 365 收件验收见[路线图](../50-planning/路线图.md)第 39 项。

## 渠道不可用邮件告警

- 网关各节点从转发、现有巡检、素材操作及后台任务的南向结果采样。请求路径在进程内合并成功时间和有限失败
  样本。已接入共享 Redis 的部署每 5 秒写入有界批次，批次保留 5 分钟。观测包含渠道配置摘要、模型、操作和
  必要的节点或凭据槽位。任务使用冻结时取得的观测范围。没有该快照的存量任务保留原有日志与业务行为。
- 主节点从系统实例心跳获取在线成员，按成员读取 Redis 批次。未使用 Redis 时，每个节点以本机窗口判定，
  普通故障邮件标明观察节点。120 秒内同范围至少三次独立失败且无后续同范围成功时，确认持续失败。
  连接失败按观察节点归属。只读巡检、任务提交、任务查询和生成终态使用各自的操作范围。明确的凭据或配置
  证据可以直接确认。Redis 断连、丢批次、成员变化或实例重启时放弃尚未确认的跨节点窗口，从新批次重新累计。
- 告警随网关启动。配置运维收件人后，主库在事务内复核渠道配置并原子保存故障摘要和逐地址待投递记录。发送复用活动
  通道和运维收件人。后台按租约领取、重试明确失败并保留结果不明的记录。逐地址保存首次实际发起提交和
  通道受理的时间。已关闭、投递处理完成的记录保留 30 天。观测批次保留在 Redis 或本机内存。Root 可在
  系统诊断的 `channel_alerts` 字段查看观测丢弃、重新计数、故障确认及首次提交超时计数。

实现见[观测批次](../../service/channel_alert.go)、[跨节点判定](../../service/channel_alert_evaluate.go)、
[告警与投递记录](../../model/channel_alert.go)及[运维配置](../40-operations/环境配置.md#渠道不可用邮件告警)。

## 管理员错误详情的请求与响应

`error_events.detail.http_exchange` 保存错误事件的有界脱敏 JSON 快照，与普通文本日志和邮件正文隔离。
已鉴权 relay/asset 请求由现有 recorder 观察入口请求与网关返回；共用 HTTP 发送入口观察实际南向请求与
上游返回。渠道测试另在构建请求和 adapter 边界接线，包含自动测试与手工测试。只在产生既有错误事件时
持久化，不新增成功请求日志，不改变鉴权、请求、响应、重试、计费或任务状态。

- 每个正文最多观察 16 KiB，含两层 JSON 转义后的单段存储预算为 12 KiB，四段合计为 MySQL TEXT 留出元数据余量；超限、非 JSON、格式错误或读取失败均省略正文并记录原因，不保存未经脱敏的前缀。
- 凭据、源 URL、签名 URL、媒体二进制字段及已知私有数据字段不保存；自由文本复用技术诊断脱敏，最长
  512 字节，保留 JSON 结构、精确数值与显式零值。快照不是逐字节原文或重放材料。
- 管理员详情区分原始请求、上游请求、上游返回与网关返回。上游返回保留自身 HTTP 状态；后台测试无客户
  HTTP 状态时不显示为 HTTP 0。旧事件、未经过采集入口的路径和后台异步失败无相应正文时明确显示未记录，
  不从现行配置重建历史请求。
- 上游重试只保留最后一次被观察的请求与响应。响应仍由原 handler/adapter 读取，不预读、重放或改变原始字节。
- JSON 快照沿现有管理员错误查询权限展示；普通 WARN 行、系统错误邮件均不输出正文。不增加数据库列，
  复用已有 TEXT/ClickHouse String 详情字段。

变更性质：NEWAPI 原生 `controller/channel-test.go`、`relay/channel/api_request.go` 与 `service/error.go`
仅保留请求/响应观察的窄接线；采集、限长、脱敏和展示位于本地错误日志模块。未来同步上游只需核对这些
发送/读取边界的接线仍在，不改动 Provider 履约语义。
