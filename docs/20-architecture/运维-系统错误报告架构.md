# 系统错误报告架构

## 边界与权威

小时报告复用系统任务调度和既有 `error_events`、性能采样。报告不是错误事实源，不承诺未登记路径或
队列丢弃事件可见；性能采样不等同全站请求总量。调度窗口、冻结正文、逐地址投递状态以主数据库为权威。
SMTP 成功以 DATA 的 250 接受回复为准，后续 QUIT 失败或取消不能把已接受邮件改判失败。
服务器接受不能证明收件箱到达；接受后状态写回失败仍可能重复投递。
错误采集的 WARN 与数据库出口分别恢复自身 panic 并计数；WARN 返回错误或 panic 后仍尝试数据库
持久化。单队列及阻塞输出的既有资源边界不变，不承诺队列丢弃事件或进程崩溃后的恢复。

## 数据与控制流

1. 窗口按北京时间自然小时、左闭右开计算，启用时段和待处理进度保存在 schedule 行。
2. 错误源在日志库中通过一次有序 SQL 游标读取；ClickHouse 相同时间/请求 ID 的行全部保留，不做去重推断。
   渠道名称在源游标关闭后从主库分批取得，避免同库单连接时互相等待。
3. 事件先暂存到权限为 0600、打开后立即取消目录链接的临时文件，随后分批渲染。文件只用于当前生成，
   关闭或进程退出自动释放；重建未发布报告重新读取来源。已发布报告不重新读取来源或模板。
4. 汇总与完整明细按 HTML 字节预算拆卷，所有分卷总数确定后才包装最终主题和正文。
5. 发布锁定报告和调度记录，复核启用时段，逐卷读取临时文件；分卷、投递行和 ready 状态在同一事务提交。
   任何读取、计数、数据库或取消错误均不得发布部分内容。只有可恢复的 ready 报告才推进窗口。
6. 投递领取按持久游标在地址之间轮转；一个地址只领取最早未完成窗口的最早未完成分卷。
   某地址退避不阻止其他地址，同地址后卷等待前卷。发送发生在事务外，通过租约和退避恢复。

## 不变量与资源预算

- 不抽样、不截断、不因资源超限跳过窗口；失败记录保留，恢复后允许重建。
- 每批最多 200 条或约 1 MiB 源记录；单条序列化最多 8 MiB；摘要每维最多 10,000 个分组，
  文本键总预算 4 MiB；两类暂存文件合计最多 256 MiB；单窗口生成和发布最多 2 分钟。
  这些是工程预算，不能解释为任意部署吞吐保证。
- 每封 HTML 正文最多 48 KiB，超长安全详情按关联编号续段，拆分预算包含实际双语表头和包装开销。动态字段转义，历史任务失败详情继续使用
  公共错误投影；转义和限长不替代脱敏。邮件只覆盖已登记的安全事件字段。
- 新生成报告的固定主题、状态说明、统计标题、明细表头、数据范围、续段和补发标识使用中英双语；源事件值不翻译。双语文本在既有字节预算分卷前生成，不按收件人推断语言、不增加配置或重复投递。
- 已发布正文冻结；后续重试、渠道改名或模板变化不覆盖旧正文。没有新的独立投递队列或采集协议。

## 管理员错误详情的请求与响应

`error_events.detail.http_exchange` 保存错误事件的有界脱敏 JSON 快照，与普通文本日志和邮件正文隔离。
已鉴权 relay/asset 请求由现有 recorder 观察入口请求与网关返回；共用 HTTP 发送入口观察实际南向请求与
上游返回。渠道测试另在构建请求和 adapter 边界接线，包含自动测试与手工测试。只在产生既有错误事件时
持久化，不新增成功请求日志，不改变鉴权、请求、响应、重试、计费或任务状态。

- 每个正文最多观察 16 KiB，含两层 JSON 转义后的单段存储预算为 12 KiB，四段合计为 MySQL TEXT 留出元数据余量；超限、非 JSON、格式错误或读取失败均省略正文并记录原因，不保存未经脱敏的前缀。
- 凭据、源 URL、签名 URL、媒体二进制字段及已知私有数据字段不保存；自由文本复用技术诊断脱敏，最长
  512 字节，保留 JSON 结构、精确数值与显式零值。快照不是逐字节原文或重放材料。
- 管理员详情区分原始请求、上游请求、上游返回与网关返回。上游返回保留自身 HTTP 状态；后台测试无客户
  HTTP 状态时不显示为 HTTP 0。旧事件、未经过采集入口的路径和后台异步失败无相应正文时明确显示未记录，
  不从现行配置重建历史请求。
- 上游重试只保留最后一次被观察的请求与响应。响应仍由原 handler/adapter 读取，不预读、重放或改变原始字节。
- JSON 快照沿现有管理员错误查询权限展示；普通 WARN 行、系统错误邮件均不输出正文。不增加数据库列，
  复用已有 TEXT/ClickHouse String 详情字段。

变更性质：NEWAPI 原生 `controller/channel-test.go`、`relay/channel/api_request.go` 与 `service/error.go`
仅保留请求/响应观察的窄接线；采集、限长、脱敏和展示位于本地错误日志模块。未来同步上游只需核对这些
发送/读取边界的接线仍在，不改动 Provider 履约语义。
