# 系统错误报告与资源告警架构

## 边界与权威

日报复用系统任务调度和既有错误事件。主库保存统计进度、冻结正文、逐地址投递状态及资源告警异常记录。
日窗口覆盖北京时间前一自然日，次日 06:00 为最早发送时间。错误详情仍由管理后台读取。模板、发信通道
与提交成功语义见[邮件投递架构](运维-用户生命周期邮件通知架构.md)。

## 日报生成与投递

1. 主节点通过现有 `error_report` 系统任务推进日窗口。首次配置运维收件人时从前一自然日开始。清空收件人或重启时保留游标。
   升级迁移移除旧日报开关、停止待投递的小时邮件并保留历史与日报游标。运行时只领取日报投递。
2. 每轮限时读取有限个已结束的五分钟切片，按客户 API 5xx、429、其他 4xx、流式异常、取消或断开、
   流式软错误、异步任务失败、视频交付故障、渠道测试失败等分别统计。错误组以事件类型、渠道、模型、HTTP 状态和原因分组，
   持久化游标和有条数及字节上限的候选。高基数切片优先保留客户事件组，另行统计完整分类计数。
   邮件按字节预算裁剪候选卡片，保留分类计数。读取失败保留未读进度。
   已持久化为通过的渠道检查（例如 Azure Foundry Claude 的 `400 / 555420`）仍保留在管理端错误日志，
   日报的失败计数、分组和最近错误样本均排除这些记录。缺少检查结论的历史记录沿用原有统计规则。
   升级时对尚未发布且缺少分类的旧窗口重新统计，已冻结的邮件保持原样。
   业务拒绝按钱包、订阅及 API Key 额度分别计数。转发链路记录最终拒绝原因，已匹配的耗尽 API Key 可在认证拒绝处
   记录最小事件。账户去重和筛选链接仅覆盖生成时保留的日志。
3. 全部切片完成且到达次日 06:00 后，汇入失败运维任务、资源告警和窗口内已有的确认渠道异常。
   确认记录来自现有渠道告警，关闭及恢复按生成时的记录展示。邮件提供值班判断和有界分组，由站点公开地址
   生成带筛选的错误日志链接。管理员仍通过原有权限查看详细记录。报告说明迟到数据、候选裁剪和留存边界，
   仅从已记录事件判断排查方向，不据此推断失败率或全站可用性。正文、报告状态及逐地址投递行原子发布。
4. 投递采用租约和按地址轮转，发送前重新核对收件人。SMTP 在收件人或正文阶段明确返回 5xx，以及 Graph
   明确拒绝邮件请求时，将该封邮件标记为 `stopped / permanent_rejection`，同地址后续日报可继续投递。
   暂时失败和发件通道配置错误仍退避重试。提交结果不明或发送租约
   失效时保留 `submission_unknown` 待核对，后续日报可继续发送。提交成功写为 `transport_accepted`，
   历史 `smtp_accepted` 保持终态含义。通道受理表示已交付给发信服务，收件结果由收件箱验证。

错误事件清理在删除前持久化单调递增的清理截止时间。日报续跑时跳过受保留期影响且尚未聚合的时段，
在冻结摘要中保留覆盖缺口，已统计的数据继续计入。覆盖不完整时，错误量展示为未知或已记录下限，
仍展示可取得的异常与运维记录。延长或关闭清理不会抹掉已记录的清理边界。升级前已清理但未记录
截止时间的历史窗口，按当前保留期限保守标记。

## 客户钱包拒绝摘要

邮件开关默认关闭，收件人沿用报告名单。系统任务每分钟检查最近一个已结束的北京时间 10 分钟窗口，
窗口关闭后留一分钟给错误事件写入。只按已落库的 `wallet_quota_insufficient` 分类累计，
使用主库当天已纳入摘要的账户记录去重。冻结摘要、逐地址投递和账户纳入记录在同一事务写入。
迟到日志不会登记为已纳入，账户在后续窗口再次被拒时仍可进入摘要。账户记录按日滚动清理，保留今天和昨天。
短周期摘要不会补发停机错过的窗口。迟到或停机期间已落库的日志，仍可按次日错误日报的覆盖规则统计。
邮件显示最多十个受影响账户的显示名称、ID 及拒绝次数，并展示这些账户在当前窗口内最新五条钱包拒绝。
分析使用本封账户的完整计数，错误正文和上游响应仍由需登录的后台查询。

## 邮件错误样本

- 系统错误日报从报告的可读取日窗口取最新五条，保留全日汇总及重点错误组。关系库按时间和事件 ID
  倒序。ClickHouse 沿用时间和请求 ID 的排序，补充样本字段区分同一请求的多条记录。
  钱包摘要和用量日报在各自账户与时间范围中使用同一错误投影。个人用量日报以收件账户 ID 过滤。
- 邮件读取时间、账户、接口、模型、HTTP 状态、结构化原因和请求 ID 的白名单，不读取或展示请求响应正文。
  客户名称批量取主库显示名称或用户名，缺失可用事件中的用户名快照。外部输入在渲染时限长、去敏和转义。
  日志或名称读取失败不影响既有摘要的生成，邮件明确提示可用范围并保留已知标识。
- 渠道告警确认时从实际纳入判定的失败取最近五条。确认阶段只保存告警和已有观测。
  投递任务按观测请求和渠道限时补充名称与接口，查询失败时使用已保存观测。首封准备好的样本块供重试复用。
  邮件读取采用普通查询。迟到日志、缺失名称与样本和统计之间的轻微差异均可接受。旧事件沿用原有摘要。

## 网关资源告警

- 每个运行中的网关实例低频采样。Linux 容器按有效 cgroup 限额计算 CPU 和内存，硬盘检查本机数据目录
  与日志目录所在文件系统。同一卷去重。无有效读数时保持异常状态。
- 达到或超过阈值开启该节点、资源的一次异常，低于阈值才关闭。主库的唯一开放异常键抵御重复采样、
  重启和并发。开启异常时保存冻结正文和待准备标记，邮件任务独立添加逐地址投递。有界队列满或进程重启后可从主库续跑。
  明确失败按收件人退避，已受理及结果不明的记录停止自动投递。升级前已开放的异常没有逐地址提交证据，
  恢复后再次越过阈值时按新逻辑记录。
- 资源告警、日报和上游余额提醒共用报告收件人。网关进程停顿或无法运行的探活不由此邮件链路承担。
  上游低余额提醒记录结果不明的时间，并按原有 24 小时提醒周期决定下一次发送时间。
- 证据清理健康监控每 15 分钟检查。首次检测出异常时复用资源告警的逐地址持久投递，立即唤醒发送工作，
  并发与重启由主库的开放事件键去重。健康检查恢复才关闭事件。正文只含受控健康指标和排查入口。
- 渠道、资源和证据清理告警确认时保存待准备标记。独立邮件任务普通读取配置，配置读取失败时保留标记。
  待投递行与标记使用短事务和条件更新，收件人和偏好在提交前复核。事件已关闭也可完成这次准备。

实现见[日报处理器](../../service/daily_error_report.go)、[日窗口持久化](../../model/daily_error_report.go)
和[资源采样](../../service/resource_alert.go)。本地性能结果与真实通道验收分开记录，未完成的
Microsoft 365 收件验收见[路线图](../50-planning/路线图.md)第 39 项。

## 渠道不可用邮件告警

- 网关各节点从转发、现有巡检、素材操作及后台任务的南向结果采样。请求路径在进程内合并成功时间和有限失败
  样本。已接入共享 Redis 的部署每 5 秒写入有界批次，批次保留 5 分钟。观测包含渠道配置摘要、模型、操作和
  必要的节点或凭据槽位。任务使用冻结时取得的观测范围。没有该快照的存量任务保留原有日志与业务行为。
- 主节点从系统实例心跳获取在线成员，按成员读取 Redis 批次。未使用 Redis 时，每个节点以本机窗口判定，
  普通故障邮件标明观察节点。120 秒内同范围至少三次独立失败且无后续同范围成功时，确认持续失败。
  连接失败按观察节点归属。只读巡检、任务提交、任务查询和生成终态使用各自的操作范围。明确的凭据或配置
  证据可以直接确认。Redis 断连、丢批次、成员变化或实例重启时放弃尚未确认的跨节点窗口，从新批次重新累计。
- 上游 HTTP 402、明确的欠费或余额不足错误码，以及明确的上游欠费文案，首次观察即进入渠道告警。
  规则按上游响应判定，适用于不同渠道类型，包括普通转发、流式响应、任务提交和查询、素材与渠道探针。
  同一渠道配置与凭据槽位的未恢复欠费跨模型和操作去重。触发范围观察到更新的成功后可关闭，渠道配置变更
  或删除也会关闭。本站客户额度拒绝、普通权限错误和普通限流不进入此告警。告警只保存分类和脱敏范围，
  不保存上游响应正文。尚无明确错误信号的上游仍依赖既有渠道告警规则。
- 邮件附渠道 ID、确认时的渠道名称、计入判定的去重失败样本数和观测时间。最近的失败样本可附 HTTP
  状态、网关分类的错误原因及可用的网关请求 ID。管理员可打开邮件中的链接，按渠道、模型和告警时间查看
  留存的脱敏错误日志。上游响应正文和自由文本错误不进入告警；重试成功或未被日志采集的观测可能没有对应
  错误日志。历史事件缺少名称快照时，可显示明确标注的当前渠道名称。
- 告警随网关启动。主库普通读取渠道配置并保存故障摘要，开放键约束去重。邮件任务独立准备逐地址待投递记录。发送复用活动
  通道和运维收件人。后台按租约领取、重试明确失败并保留结果不明的记录。逐地址保存首次实际发起提交和
  通道受理的时间。已关闭、投递处理完成的记录保留 30 天。观测批次保留在 Redis 或本机内存。Root 可在
  系统诊断的 `channel_alerts` 字段查看观测丢弃、重新计数、故障确认及首次提交超时计数。

实现见[观测批次](../../service/channel_alert.go)、[跨节点判定](../../service/channel_alert_evaluate.go)、
[告警与投递记录](../../model/channel_alert.go)及[运维配置](../40-operations/环境配置.md#渠道不可用邮件告警)。

## 管理员错误详情的请求与响应

`error_events.detail.http_exchange` 保存错误事件的有界脱敏 JSON 快照，与普通文本日志和邮件正文隔离。
已鉴权 relay/asset 请求由现有 recorder 观察入口请求与网关返回；共用 HTTP 发送入口观察实际南向请求与
上游返回。渠道测试另在构建请求和 adapter 边界接线，包含自动测试与手工测试。只在产生既有错误事件时
持久化，不新增成功请求日志，不改变鉴权、请求、响应、重试、计费或任务状态。

- 每个正文最多观察 16 KiB，含两层 JSON 转义后的单段存储预算为 12 KiB，四段合计为 MySQL TEXT 留出元数据余量；超限、非 JSON、格式错误或读取失败均省略正文并记录原因，不保存未经脱敏的前缀。
- 凭据、源 URL、签名 URL、媒体二进制字段及已知私有数据字段不保存；自由文本复用技术诊断脱敏，最长
  512 字节，保留 JSON 结构、精确数值与显式零值。快照不是逐字节原文或重放材料。
- 管理员详情区分原始请求、上游请求、上游返回与网关返回。上游返回保留自身 HTTP 状态；后台测试无客户
  HTTP 状态时不显示为 HTTP 0。旧事件、未经过采集入口的路径和后台异步失败无相应正文时明确显示未记录，
  不从现行配置重建历史请求。
- 上游重试只保留最后一次被观察的请求与响应。响应仍由原 handler/adapter 读取，不预读、重放或改变原始字节。
- JSON 快照沿现有管理员错误查询权限展示；普通 WARN 行、系统错误邮件均不输出正文。不增加数据库列，
  复用已有 TEXT/ClickHouse String 详情字段。

变更性质：NEWAPI 原生 `controller/channel-test.go`、`relay/channel/api_request.go` 与 `service/error.go`
仅保留请求/响应观察的窄接线；采集、限长、脱敏和展示位于本地错误日志模块。未来同步上游只需核对这些
发送/读取边界的接线仍在，不改动 Provider 履约语义。
