# TokenSave 与墨行 Seedance 素材库对接设计

## 1. 范围

本文定义 TokenSave 海外与墨行国内三种第三方素材协议、无状态单资源代理和真人认证边界。视频合同见
[渠道对接设计](渠道对接设计.md)，共同素材合同见
[Seedance 官方素材库与素材引用设计](../../Seedance官方素材库与素材引用设计.md)。

三种素材协议是代码注册的 Provider 合同，不根据 Base URL、模型名或 ID 前缀自动识别；不兼容时开发
新 adapter，不建立运行时协议推断或 fallback。

## 2. 协议配对

| 素材协议 | 唯一视频协议 | 客户模型 |
| --- | --- | --- |
| `tokensave_assets_v1` | `tokensave_media_task_v1` | TokenSave 2.0 |
| `moxing_joycreator_assets_v1` | `moxing_media_task_v1` | 墨行国内 2.0 |
| `moxing_volc_assets_v1` | `moxing_modelark_media_v1` | 墨行 Fast、Mini、2.5 |

Channel 保存时执行精确配对。管理员可选 `none` 关闭素材 CRUD；系统不在三种协议之间自动切换、迁移或
降级。

## 3. 当前能力

| 能力 | TokenSave | 墨行 JoyCreator | 墨行火山 |
| --- | --- | --- | --- |
| general 图片/视频/音频 | 创建、查询、改名、删除 | 创建、查询、改名、删除 | 创建、查询、改名、删除 |
| general 素材组 | 不支持 | 创建、查询；删除未确认 | 创建、查询、删除 |
| 真人素材组 | 不支持 | 不支持 | 图片真人组与 Provider 验证会话 |
| 只读连通性 | `POST /assets/list` | 无已验证安全 probe | `POST /v1/volc/assets/list` |

平台只发布表中可由代码 adapter 履约的操作；未发布操作返回 `unsupported_asset_operation`。Provider
列表只可用于连通性或已知 ID 的单项实现，不形成客户素材目录。

## 4. opaque ID 与资源责任

所有创建和单项查询直接返回 Provider opaque 素材、素材组或验证会话 ID；ready 素材可返回
`asset://<opaque-id>`。调用方保存 `model + id + reference`。平台不持久化 Asset/AssetGroup，不建立
`user_id + app_id`、Channel、账号、Region/Project 或凭据指纹映射，也不返回 Provider、Channel 或
上游原始模型。

GET/DELETE 通过查询参数、POST/PATCH 通过请求体携带客户 `model`。平台按模型选择唯一 Channel 和精确
adapter，只调用该 Provider。另一个 Provider 的 ID 不会被本地识别或重新路由。

## 5. source URL 与媒体

创建素材只接受经统一安全校验且满足渠道最短 TTL 的远程 HTTPS URL。source URL 只存在于创建请求和
当次 Provider 调用，不写入 Task、日志或数据库。平台不保存媒体二进制，也不把请求级 URL/Data URL
自动物化为素材。

## 6. Provider 协议

TokenSave 使用 `/assets` 创建，`GET /assets/{id}` 查询，`POST /assets/{id}/update` 更新，
`POST /assets/{id}/delete` 删除。它不实现素材组或真人认证。

JoyCreator 使用 `/joycreator/openApi/v1/asset/*` 控制面。素材支持 general 图片、视频和音频；普通组
支持创建与查询。未确认的组删除保持不支持，不通过删除本地记录伪造成功。

墨行火山使用 `/v1/volc/assets/*` 且 `ProjectName=default`，支持 general 组和素材 CRUD，以及
`/visual-validate/sessions` / `/visual-validate/results/{session_id}` 真人验证流程。平台只返回 Provider
H5 链接和单项状态，不保存生物识别材料或建立法律授权域。

## 7. 视频引用

ModelArk V3 中的 `asset://<opaque-id>` 不进入素材控制面。平台只验证前缀后存在非空值，并交给当前
视频 adapter；adapter 不根据 ID 推断 Provider、所有权、状态或模型兼容性。Provider 最终决定是否
存在、是否可访问、是否 ready 以及是否支持当前媒体组合。

Provider 拒绝使用脱敏统一错误返回，不探测其它 Provider，不更换 Channel，不回退 source URL，也不
创建 binding、resolver、迁移或素材 unknown 状态。

## 8. 不变量

1. 三种素材协议只能与登记的视频协议精确配对。
2. 客户直接管理 opaque ID；平台不提供列表、`ast_*`、`pubref_*` 或本地素材映射。
3. 单资源操作必须携带客户模型并执行 Token 模型授权。
4. source URL 不持久化，平台不保存媒体二进制。
5. 视频素材可用性由当前 Provider 判断，失败不跨 Provider fallback。
6. 未确认操作明确不支持，不伪造成功或建立素材 unknown 状态机。
