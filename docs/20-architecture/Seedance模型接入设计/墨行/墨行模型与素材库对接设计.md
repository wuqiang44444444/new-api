# 墨行模型与素材库对接设计

## 1. 两条视频协议

| 线路 | 协议 | Provider 模型范围 | 公开状态 |
| --- | --- | --- | --- |
| TokenSave 海外 2.0 | `tokensave_media_task_v1` | `doubao-seedance-2-0-260128` | 可配置，待完整账单验收 |
| 墨行国内统一入口 | `moxing_modelark_media_v1` | `doubao-seedance-2-0-260128-0818`、`...fast...`、`...mini...`、`...2-5...` | 四个精确模型登记于 Seedance 插件的 `MOXING_MODEL_METADATA`；Fast 有实证；Mini 素材生成有单例实证，完整验收未通过；0818 的官方 `content` 与国内素材有文档依据，真实履约仍待验收 |

客户模型名、Channel、Provider 模型和协议分离；`model_mapping` 是唯一模型转换。一个 Channel 可以包含
多个管理员命名的客户模型，保存时逐项解析到所选协议登记的最终 Provider 模型；映射链、额外管理员条目
和客户名称不决定协议资格。四模型接受已发布的 ModelArk 标准字段，不因供应商参数表未列出
`seed`、`camera_fixed` 等字段就提前拒绝；合同外私有字段仍由北向边界拒绝。

已登记的 Provider 模型可直接通过 `model_mapping` 配置；未登记的新墨行 Provider ID 仍需先更新
唯一模型登记并验证默认值、预算和公开投影，不能仅凭协议名称相同绕过校验。0818 使用
`POST /v1/media/generations` 和 `GET /v1/media/tasks/{task_id}`，不新增 Ark 路由。

## 2. 视频参数合同

共同北向为 ModelArk V3 `content`，四模型按官方多模态形状发送，不做 `prompt/reference_*` 转换。
当前运行时与公开投影读取同一 Seedance 插件元数据；精确参数与来源见
[模型与素材能力元数据](墨行模型与素材能力元数据.md)。

- 0818 分辨率限定为 480p/720p/1080p/4k；2.5 限定为 480p/720p。
- Fast/Mini 的 480p/720p 只作为 `suggested_values` 发布，不从推荐值推导穷举白名单。
- 0818 上游明确不支持 `output_format`，Fast/Mini 页面没有该字段的支持证据；这三款不发布该参数，
  显式请求在 Provider POST 前失败。2.5 发布并原样发送 mp4/mov，不静默降级输出格式。
- 四模型本站缺省时长为 5 秒，未传 `duration` 与 `frames` 时 adapter 显式补 5；显式 -1 仍原样发送，
  仅按已有 15/30 秒上限预算。2.5 上游默认 -1 不覆盖本站已发布默认值；其它三页不足以证明自动时长。
- `frames` 沿用既有北向计费探针语义，只传 `frames` 时不补 `duration`。
- `generate_audio` 缺省 true，显式 false 保持不变；参考音频与输出音频开关相互独立。
  Fast/Mini 页面未明确默认值，不能根据示例 false 推导新的默认值。
- 2.5 本地校验图≤30、视频≤10、音频≤10、总数≤50。其首帧/首尾帧/延长场景仅支持 adaptive，
  首帧/首尾帧与多模态参考互斥，参考音视频各自总时长≤30 秒，视频编辑尚未开放。
  Provider 负责实际素材及任务意图判断；平台不按提示词推断编辑或延长，不新增场景路由。
- Fast/Mini 音频应搭配图片或视频。原有请求传输接受纯音频不等于供应商证明支持；真实效果仍待验收。

其它已发布 ModelArk 标准字段保持既有语义，合同外私有字段仍在北向拒绝。
本次参数来源不构成其它 Provider、原生视频入口或既有 Task 冻结合同的变更。

0818 来源页存在路径矛盾：说明段写 `/v1/ark/media/generations`，接口标签、示例与通用查询段仍写
`/v1/media/generations`、`/v1/media/tasks/{task_id}`。当前 adapter 保留既有 media 路径，不根据页面
冲突新增 fallback 或双发；真实路径兼容性仍需 Provider 验收。

## 3. 素材协议

| 代码协议 | 关键操作 | 平台边界 |
| --- | --- | --- |
| `tokensave_assets_v1` | `/v1/asset` 组创建/查询、素材创建/查询/更新/删除 | 创建素材必须使用组创建返回的资源 `id`；不再调用 `/assets` 默认组代理 |
| `moxing_volc_assets_v1` | 组创建/查询、素材 CRUD、真人认证会话/结果 | 创建素材组不传 `ProjectName`；创建素材必须携带 `GroupId`；其它已登记操作沿用各自 Provider 合同 |

墨行四模型统一配对 `moxing_volc_assets_v1`（或 `none`）；旧 JoyCreator 素材协议已随
`moxing_media_task_v1` 一并退出新建配置，不保留旧创建或素材兼容入口。旧视频协议标识仅用于
识别已创建任务的冻结查询及计费事实。

平台统一要求每次操作携带客户模型；不提供列表；Provider opaque ID 由调用方保存。普通素材组策略由
`GeneralAssetGroupPolicy` 统一发布为可选并支持 Channel 默认组回退。视频中的 `asset://<opaque-id>`
不查询本地、不验证所有权或模型，原样进入当前视频 adapter。source URL 不持久化，失败不跨协议
fallback。

TokenSave `/v1/asset` 的真实创建响应将 `id`、`groupId` 或 `assetId` 直接放在 `result` 下，详情响应则放在
`result.group` 或 `result.asset` 下。adapter 按操作支持这两种已验证形状，创建成功不得因套用详情响应
结构而误判为上游失败。

使用相同 Moxing ModelArk 视频协议、Volc 素材协议和连接配置的四个精确模型可以位于同一多模型
Channel。TokenSave 和 CMCC 即使当前只登记一个 Provider 模型，也不限制管理员只能
配置一个客户模型；每个 Channel Model 的最终映射目标仍必须属于对应协议登记表。

## 4. 异步与状态

创建只发送一次 Provider POST，TaskCreateAttempt、hold、sending 和可信 task ID 原子提交。查询无效、ID 不匹配或状态未知时只能标记不可采信，不得直接退款。Task 冻结协议、Provider 模型、连接和计费事实，后续配置变化不重新选渠。

已冻结 `moxing_media_task_v1` 的任务继续适用 Seedance 用量补采、按冻结表达式结算及资金写入保护，
缺失用量不能把预扣直接认作最终账单。此历史识别不赋予旧协议新建资格。
同一 Channel 原地改协议不触发自身模型唯一性冲突，但素材租户边界变化仍须明确确认；
JoyCreator 与国内素材库不能仅因视频路径相同就视为同一租户。

## 5. 代码事实

协议身份在 `relaykit/dto/upstream_protocol.go`；当前视频与素材转换、模型参数声明在
`plugins/seedance-link/plugin.js`，宿主通过冻结插件执行。公开视频参数由
`pkg/publicmodel/seedance_plugin.go` 投影。共同素材公开矩阵见上位文档。


## 6. Mini 真实验收边界

Mini 已有独立普通素材组创建、真实图片素材创建/查询、asset 引用视频生成、后台结算的完整单例实证。
4 秒、480p、1:1 请求输出约 4.096 秒、640×640，画面保留参考杯子；成功用量由
usage.completion_tokens 提供，客户账按冻结价格完成差额结算。generate_audio=false 仍产生
非静音 AAC 音轨，音频开关履约和供应商账单仍待验收；该单例不能视为生产发布。
详见[同图测试记录](../../../99-archive/2026/09/2026-09-07-FunCloud新版视频协议与统一素材库实施方案.md#14-moxing-与-funcloud-mini-同图实测及明确失败重试2026-09-07)。
