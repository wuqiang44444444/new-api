# TokenSave 与墨行全模型与计费设计

## 1. 商务结论

当前五个模型不是同一种计价方式：

- TokenSave 海外 Seedance 2.0：按输出秒数计费；
- 墨行国内 Seedance 2.0：按输出秒数计费；
- 墨行国内 Fast、Mini、2.5：按 completion tokens 计费。

这不是推测。两份价格原文和当前数据库价格设置一致：国内 2.0 是按秒，Fast、Mini、2.5 是按 Token。
如果商务合同后续把国内 2.0 改成 Token 计价，必须先取得新的价格依据，再同时更新研究文档和系统配置。

## 2. 模型与计价方式

| 线路 | 客户使用的模型名 | 计价单位 | 当前状态 |
| --- | --- | --- | --- |
| TokenSave 海外 2.0 | `doubao-seedance-2-0-260128-tokensave` | USD/输出秒 | 已配置价格，生产前仍需真实账单核对 |
| 墨行国内 2.0 | `doubao-seedance-2-0-260128-moxing` | USD/输出秒 | 已配置价格，生产前仍需真实账单核对 |
| 墨行国内 Fast | `doubao-seedance-2-0-fast-260128-moxing` | USD/百万 completion tokens | 真实视频与 Token 账单已核对，模型未发布 |
| 墨行国内 Mini | `doubao-seedance-2-0-mini-260615-moxing` | USD/百万 completion tokens | 价格已配置，模型未发布 |
| 墨行国内 2.5 | `doubao-seedance-2-5-260628-moxing` | USD/百万 completion tokens | 价格已配置，模型未发布 |

价格必须配置在上述带 `-tokensave` 或 `-moxing` 后缀的客户模型上，不能配置在去掉后缀的 Provider
模型上。

## 3. TokenSave 海外 2.0 价格

当前视频合同只开放文字和图片输入，因此系统价格只包含实际可用档位：

| 分辨率 | 生成方式 | 单价（USD/输出秒） |
| --- | --- | ---: |
| 480p | 文字、图片、参考图 | $0.0679 |
| 720p | 文字、参考图 | $0.1462 |
| 720p | 首帧、尾帧等图片控制 | $0.1461 |
| 1080p | 文字、图片、参考图 | $0.3647 |

海外价格原文还列出了视频输入价格，但当前 TokenSave adapter 会在提交前拒绝视频输入，所以这些价格
不能进入当前系统设置。

## 4. 墨行国内 2.0 价格

国内人民币价格按固定汇率 `1 USD = 6.82 CNY` 换算。当前模型合同只开放 480p 和 720p：

| 分辨率 | 输入方式 | 人民币/输出秒 | 美元/输出秒 |
| --- | --- | ---: | ---: |
| 480p | 无视频输入 | ¥0.462 | $0.067741935484 |
| 480p | 有视频输入 | ¥1.124 | $0.164809384164 |
| 720p | 无视频输入 | ¥0.994 | $0.145747800587 |
| 720p | 有视频输入 | ¥2.420 | $0.354838709677 |

价格原文中还有 1080p 报价，但当前墨行 2.0 渠道合同不接受 1080p，因此真实系统价格没有配置该档位。
只有图片或音频而没有视频时，按“无视频输入”价格计费。

## 5. 墨行 Fast、Mini、2.5 Token 价格

单位均为 `USD / 1M completion tokens`：

| 模型 | 文生/图生，无视频输入 | 视频生或含视频输入 |
| --- | ---: | ---: |
| Fast | $5.425219941349 | $3.225806451613 |
| Mini | $3.372434017595 | $2.052785923754 |
| 2.5 | $10.263929618768 | $6.158357771261 |

图片或音频输入不等同于视频输入。只有请求中实际包含视频时，才使用“含视频输入”价格。

## 6. 当前墨行视频参数合同

北向统一使用 ModelArk V3 typed request，允许表达 `seed` 和 `camera_fixed`；这只表示公共请求结构
能够承载字段，不表示每个 Provider 模型都支持。南向支持范围以当前墨行模型接口文档明确列出的参数为准，
文档未列出的字段视为不支持，不发送给 Provider 试探。

当前四个墨行模型的已核验结论如下：

| Provider 模型 | 视频协议 | `seed` | `camera_fixed` |
| --- | --- | --- | --- |
| `doubao-seedance-2-0-260128` | `moxing_media_task_v1` | 不支持 | 不支持 |
| `doubao-seedance-2-0-fast-260128` | `moxing_modelark_media_v1` | 不支持 | 不支持 |
| `doubao-seedance-2-0-mini-260615` | `moxing_modelark_media_v1` | 不支持 | 不支持 |
| `doubao-seedance-2-5-260628` | `moxing_modelark_media_v1` | 支持 | 不支持 |

合同处理规则：

- 客户未提供字段时保持缺失，不补 `0`、`false` 或 `null`；
- 客户显式提供不支持的字段时，即使值为 `seed=0` 或 `camera_fixed=false`，也必须在模型映射后的
  Provider 规格校验中返回 `400 invalid_video_parameter`；
- 不得静默删除客户显式参数后继续调用，否则客户会误认为参数已经生效；
- 校验必须发生在价格计算、资金 hold、`TaskCreateAttempt` 和 Provider POST 之前；
- 只按 `video_upstream_protocol + Provider 模型` 的当前确定组合判断，不根据客户模型后缀、Provider
  名称或 JSON 外形推断，也不为未来接口变化建立 capability、数据库配置或自动透传机制；
- 后续若墨行接口变化，由技术人员重新核验后再针对性修改当前合同。

本结论依据 `docs/70-research/墨行/国内/` 中的四份当前接口文档：`seedance 2.0.md`、`seedance 2.0 fast.md`、
`seedance 2.0 mini.md` 和 `seedance 2.5.md`。其中只有 Seedance 2.5 明确列出 `seed`；四份文档均未列出
`camera_fixed`。`watermark` 在四份文档中均有明确记录，不受本节限制。

## 7. 当前系统价格设置

数据库中的真实配置如下：

| 客户模型 | 价格模式 | 预扣 Token |
| --- | --- | ---: |
| `doubao-seedance-2-0-260128-tokensave` | 动态价格 | 1 |
| `doubao-seedance-2-0-260128-moxing` | 动态价格 | 1 |
| `doubao-seedance-2-0-fast-260128-moxing` | 动态价格 | 324,000 |
| `doubao-seedance-2-0-mini-260615-moxing` | 动态价格 | 324,000 |
| `doubao-seedance-2-5-260628-moxing` | 动态价格 | 648,000 |

这里的“动态价格”表示系统会按照请求内容选择上表中的正确档位：

- 两个 2.0 模型按分辨率、输入方式和输出秒数计算；预扣 Token 填 `1` 只是系统配置占位；
- Fast、Mini、2.5 按预估 completion tokens 预扣；
- 智能时长 `-1`：2.0、Fast、Mini 按最多 15 秒预估，2.5 按最多 30 秒预估；
- 生成明确失败时按异步任务退款规则处理；结果不明确时不自动退款，避免 Provider 已生成但平台重复赔付。

### 7.1 已取得的 Fast usage 证据

Fast 的一次真实成功终态查询已返回：

```json
{
  "usage": {
    "completion_tokens": 40594,
    "prompt_tokens": 0,
    "total_tokens": 40594
  }
}
```

墨行账单同时记录输出 `40,594 Tokens`、总计 `40,594 Tokens`，并按
`40,594 × ¥37/百万 Tokens = ¥1.501978` 扣费。查询响应、账单数量和官方单价三者一致，足以确认
Fast 的 `usage.completion_tokens` 是本次客户结算应采用的实际输出 Token。

该次历史任务按预估 `324,000 Tokens` 结算，不是因为 Provider 没有返回实际用量，而是当时共享墨行
响应归一器的调用方写死了 `IncludeVerifiedUsage=false`。该参数原本用于在第三方 `usage` 的类型、单位
和终态稳定性尚未取证时，阻止未经核验的数字直接改变客户资金；它是已删除的内部“结算信任门”，
不是 Provider 协议字段，也不是管理员配置。

删除前，这个布尔门没有实际价值：运行调用均传入 `false`，只有测试显式传入 `true`，它既隐藏了真实
用量观测，又把“是否解析响应”与“该模型按什么单位计费”混在一起。当前代码已直接删除
`IncludeVerifiedUsage` 参数，没有把它改成另一个 Provider、模型或管理员配置。墨行 adapter 始终归一
成功终态原始响应中的任何明确 `usage` 或 Token 相关用量字段；是否用于客户结算只由创建时冻结的计价
方式决定：

| 墨行模型 | 冻结计价方式 | 终态 Token usage 的处理 |
| --- | --- | --- |
| Seedance 2.0 | 输出秒 | 保存为 Provider 用量证据，不改变按秒结算 |
| Fast、Mini、2.5 | completion tokens | 使用实际 completion tokens 对预扣做幂等差额结算 |

Fast 的现有证据已经证明不能继续让 `IncludeVerifiedUsage=false` 控制用量采集。Mini、2.5 尚无真实
任务证据，不据此宣称两者已经完成生产验收；但两者合同本来就是按 Token 计价，成功终态原始响应只要
返回任何明确的 `usage` 或 Token 相关数值，就必须视为合法用量并纳入结算，不再额外等待配置开关或
账单页面人工确认。终态没有任何可形成数值的合法实际用量时，才保留对应模型的预扣估算。

### 7.2 返回形态与转换边界

墨行接口文档把 `usage` 标为 `string`，真实 Fast 返回则是对象，且文档成功响应示例完全省略 `usage`。
这是已经存在的返回描述差异。当前转换应同时接受结构化对象和“只包一层 JSON 对象”的字符串，并从
成功终态原始响应中采集任何明确的 `usage` 或 Token 相关数值；这不是按模型维护字段白名单，也不需要
额外的 verified 配置。进度、时长、金额以及无法转换成数值的普通文本不属于 Token 用量。

Fast 当前返回字段的结算优先级为 `completion_tokens` > `total_tokens - prompt_tokens` >
`total_tokens`；若出现其它明确输出 Token 字段，其优先级同样高于 total。多个字段不能累加；Fast
实例中三者满足 `0 + 40,594 = 40,594`。归一后的字段和来源进入私有计费证据，完整 Provider 响应、
Task 私有 ID 和媒体 URL 不进入客户响应或通用日志。

## 8. 商务使用原则

1. 对外报价使用客户模型名，不使用 Provider 模型名。
2. 不把国内 2.0 的按秒价格套到 Fast、Mini、2.5。
3. 不把 Fast、Mini、2.5 的 Token 价格套到国内 2.0。
4. 海外 TokenSave 和国内墨行分别定价，不能因为 Provider 模型名相同而共用价格。
5. 汇率或 Provider 报价调整只影响新任务，历史任务按创建时价格结算。
6. 代码中有模型和价格不等于已经生产发布；真实生成、素材和账单必须逐模型验收。
7. `IncludeVerifiedUsage` 不属于商务合同，也不应继续存在；墨行成功终态原始响应中的任何明确 usage
   或 Token 数值均形成合法用量，客户结算单位由创建时冻结的模型计价方式负责。
