# 移动云模型与素材库对接设计

## 1. 范围与状态

本文定义移动云 AICC-Doubao-Seedance 系列的目标接入合同。Standard 的设计边界已经确定；Fast、Mini
和 2.5 先作为客户模型候选。Standard 的目标租户 raw REST 已完成文本、分辨率和参考视频最小探测；
代码协议与管理字段已经实现；真实素材链路和 Provider 账单尚未验收，因此不得把本文件解释为已上线。

首版范围包括：

- 非加密 REST 视频创建、查询、列表、删除/取消和内容回源；
- AIGC 素材组与 Image/Video/Audio 素材单资源 CRUD；
- 真人人像 H5 认证会话、token 换素材组和 Image/Video/Audio 素材；
- 移动云实际 usage 驱动的异步结算与 Provider 成本记录。

首版代码可以一次登记四个客户模型名称，但只有取得移动云官方模型 ID、字段、规格、素材兼容性和
价格证据的模型才允许配置 `model_mapping`、客户价格并启用。当前公开证据只满足 Standard 的文档设计
前提，Fast/Mini 保持候选，2.5 仅在移动云确认存在时继续实现。

官方 SDK 加密调用不进入首版 `modelark_v3_cmcc`。如后续需要，必须新增独立、代码注册且完成安全审计
的 secure 协议，不得在同一协议中按运行时错误静默回退到明文。

## 2. 身份、协议与模型映射

| 概念 | 首版值 |
| --- | --- |
| 客户模型 | Standard、Fast、Mini 和条件候选 2.5，见下表 |
| ChannelType | `ChannelTypeSeedanceLink` |
| 北向视频合同 | ModelArk V3 |
| `video_upstream_protocol` | `modelark_v3_cmcc` |
| `asset_upstream_protocol` | `cmcc_aicc_assets_v2` |
| `model_mapping` | 只为已取得移动云证据的模型建立精确映射 |
| 视频 Gateway | Channel Base URL；首版已验证 `https://zhenze-huhehaote.cmecloud.cn` |
| 素材 Gateway | 代码固定 `https://ecloud.10086.cn/api/openapi-maas/exp/aicc/v2` |

| 客户模型 | 移动云 Provider 模型 | 设计状态 |
| --- | --- | --- |
| `seedance-2.0-cmcc` | `doubao-seedance-2.0` | Standard；代码已实现，等待生产素材与账单验收 |
| `seedance-2.0-fast-cmcc` | 待移动云官方确认 | 候选；不得借用火山 Fast ID 进行映射 |
| `seedance-2.0-mini-cmcc` | 待移动云官方确认 | 候选；不得借用火山 Mini ID 进行映射 |
| `seedance-2.5-cmcc` | 待移动云官方确认 | 条件候选；当前未发现移动云公开产品证据 |

客户模型、Channel、Provider 模型和协议保持四层分离。不得根据 `cmcc`、`doubao`、价格、域名或请求
内容推断线路。每个已启用客户模型只对应一个移动云 Seedance Channel，不参加 Priority、Weight、
Affinity、随机分发、失败重选、跨渠道重试或 fallback。

同一移动云租户确认支持多个模型时，应把这些客户模型和精确 mapping 配置在同一个 Channel，使视频
API Key、素材 AK/SK、固定素材 endpoint 和 `reuse_scope` 共同冻结；不能为了不同模型复制成多个相同
账号 Channel。当前只有 Standard Provider 模型获得证据并进入代码登记表；管理员可以在一个 Channel
配置多个客户模型名称并按 NEWAPI 原生映射语义最终解析到该已登记模型。候选 Fast、Mini、2.5 尚未取得
Provider mapping 时不得作为新的最终 Provider 模型加入登记表；客户名称不能使未登记 Provider 模型获得
协议资格。

## 3. 开通与凭据配置

### 3.1 服务开通

管理员配置渠道前，运维必须确认目标账号为移动云允许的非免费账号，订单与模型权益均显示开通成功，
并配置移动云 MaaS 公布的 Base URL。Base URL 是服务接入点，不是另一种登录或凭据；租户与模型权限
由 Bearer API Key 决定。开通是调用资格，不由 SDK 替代。首版地址只是已验证示例；Channel 继续遵守
Link 的绝对 HTTP(S) 网关语义，允许部署方使用合法中转地址及路径，不把 Provider 官网 HTTPS origin
收紧为协议资格。

### 3.2 两套凭据，同一租户

首版按已确认的业务前提配置：视频 API Key 与素材 AK/SK 完全属于同一个移动云租户，但两者仍是两套
独立鉴权材料。

| 用途 | 管理事实 | 使用方式 |
| --- | --- | --- |
| 视频 | Channel 单一 Key | `Authorization: Bearer`；随 Task/attempt 冻结 |
| 素材 | Channel 专用受保护 AK/SK | V2.0 Query 签名；仅在当次素材调用内使用 |

不增加 Region 或 ProjectName 管理字段。素材 AK/SK 不复用视频 Key 字段，不进入日志、公开元数据、
Task 公共响应或浏览器。保存/启用渠道时可校验两套凭据均已配置，但“同租户”最终仍以真实素材创建后
可被同渠道视频引用的验收为准。

## 4. 视频 adapter

### 4.1 创建转换

`modelark_v3_cmcc` 以 Channel Base URL 拼接 `/api/v3/contents/generations/tasks`，使用 Bearer API Key，
并把客户模型精确映射为已经由移动云确认的 Provider 模型。当前只有
`seedance-2.0-cmcc -> doubao-seedance-2.0` 可写入设计配置；Fast、Mini、2.5 不允许使用猜测 ID。

首版发布非加密 REST 文档或目标账号探测已经确认的字段。Standard 已确认 `content` 的 text、
`image_url/reference_image`、`video_url/reference_video`、`audio_url/reference_audio`，以及
`generate_audio`、`ratio`、`duration`、`watermark`；目标账号另行确认了
`resolution=480p/720p/1080p`，未传时 Provider 默认为 720p。移动云页面没有声明三类参考媒体的最大
数量，因此 adapter 不借用火山、BytePlus 或其它渠道的 `9/3/3` 上限；最终数量兼容性由移动云返回。
其余 SDK 字段必须返回明确的 `unsupported_video_parameter`，不能静默删除、钳制、改义或转为默认值。

平台北向缺省 duration 为 5 秒，校验和预扣使用同一值；可选字段未提供时保持不出现在南向 JSON，符合
ModelArk V3 的可选字段合同。当前目标租户样本都显式传了 5 秒，生产启用前仍须验证移动云对缺省字段
采用同样语义；不一致时不能在共享 BuildRequestBody 中静默补值。

请求中存在 video content 时，adapter 必须从结构化 content 得出“含视频输入”，不能信任客户自报
计价档，并固定发送 `Input-Has-Video: true`。该 Header 与 `video_url/reference_video` 已由目标 API Key
成功验证。冻结计费事实必须记录结构化判断；Header 被接受和 usage 计入输入视频不等于 ¥56/百万 Token
已实际落账，Provider 价档仍以账单核验。

### 4.2 Task 状态与实际用量

状态映射如下：

| 移动云状态 | 平台语义 |
| --- | --- |
| queued、running | 非终态，继续按冻结连接轮询 |
| succeeded | 成功终态；解析结果与 `usage` |
| failed、cancelled、expired | 明确终态；客户资金处理与 Provider 成本分别记账 |
| 未知状态、无效 JSON、ID 不匹配、成功缺少必要结果 | 本次观测不可采信，进入对账而不是判失败 |

成功终态优先归一 `usage.completion_tokens`，`total_tokens` 仅按共享异步用量规则作为补充证据。实际
用量、原始字段名和含视频计价档进入私有计费快照，不保存完整 Provider 响应或完整结果签名 URL。

目标租户实测表明 24fps 下 usage 符合
`floor((((input_seconds + output_seconds) × fps) + 1) × width × height / 1024)`：5 秒纯文本输出分别得到
480p 50638、720p 108900、1080p 245025 Token；5 秒参考视频输入加 5 秒 720p 输出得到 216900 Token。
预扣必须保守覆盖额外一个输出帧，终态结算不得用估算值覆盖真实 `completion_tokens`。

### 4.3 加密调用边界

`modelark_v3_cmcc` 不设置“是否加密”的管理员布尔值，也不调用移动云 SDK。官方加密 SDK 涉及安全信道
协商、请求/响应加解密和 RSA 视频解密密钥生命周期，属于另一套 transport 安全合同。未来若引入
`modelark_v3_cmcc_secure`，必须独立注册、独立验收、明确密钥托管与灾备，不允许 secure 失败后明文
重试。

## 5. 素材 adapter

### 5.1 为什么必须新建协议

`cmcc_aicc_assets_v2` 使用固定移动云 OpenAPI Gateway、V2.0 Query AK/SK 签名、REST 路径和移动云
响应信封。它没有火山/BytePlus Action、Region 或 ProjectName，因此不得复用
`volcengine_assets_action_v2024_01_01` 或 `byteplus_assets_action_v2024_01_01`。

adapter 只代理单资源操作：

- 素材组：创建 AIGC 组、查询；列表、更新和删除均不发布，平台也不主动删除；
- 素材：创建、查询、更新名称、删除；列表不发布；
- 真人：创建 H5 会话、按 `bytedToken` 取得 group ID；
- opaque ID 原样在 Provider 请求中使用，平台不建立 Asset/AssetGroup 数据库事实。

### 5.2 所有素材均要求素材组

移动云创建素材的 `groupId` 是必填项。首版对 general 与 real_person 的 Image/Video/Audio 都公开
`asset_group_requirement=required`：

- AIGC/虚拟素材由调用方先创建 `groupType=AIGC` 的组；
- 真人素材由调用方先完成 H5 认证并取得真人 group ID；
- 平台不创建默认组，不把素材组当项目名，不在缺少 group ID 时猜测或补值。

共享入口保留“真人素材必须带 group ID”的北向不变量；adapter 的 `Supports` 再决定 Provider 可接受的
媒体类型，`AssetGroupRequirementAdapter` 负责移动云 general 与 real_person 的逐媒体组要求。公开目录
只为 `cmcc_aicc_assets_v2` 增加真人 Video/Audio 投影，因此移动云能够支持全部六种组合，同时没有扩大
其它 Provider 的媒体能力。不得删除共享真人组校验，否则会与其它 Provider 的既有公开合同分叉。

### 5.3 真人 H5 流程

```text
受信调用方创建真人认证会话
  -> 平台签名调用 /real-person-auth/sessions
  -> 返回脱敏 H5 URL、bytedToken 和过期时间
  -> 用户在移动云 H5 完成认证
  -> 调用方携带 customer_model + bytedToken 查询结果
  -> 平台调用 /real-person-auth/asset-group/by-byted-token
  -> 返回 opaque group ID
  -> 调用方在该组创建 Image/Video/Audio 素材
```

移动云创建会话不接收 `redirect_url`。客户对移动云模型传入非空 `redirect_url` 时必须明确返回不支持，
不得静默丢弃。H5 登录、真人同意、驳回和撤回均由 Provider 页面处理；平台不建立真人授权状态机。

### 5.4 无状态引用与复用域

素材创建处于 PROCESSING 时可以只返回 opaque `id`；查询到 ACTIVE 后返回
`asset://<opaque-id>`。视频 adapter 原样接收该引用，不查询本地数据库，不验证所有权、READY 状态、
素材组或 Provider 作用域；最终兼容性由同一移动云租户判定。

移动云与其它素材协议统一使用 Channel identity 形成匿名 scope：

```text
asset_scope_ + hex(SHA-256("seedance_channel_asset_scope:v1" + "\n" + stable_channel_identity))
```

`stable_channel_identity` 具体定义为 Channel 专用的 `asset_scope_identity`：使用密码学安全随机源生成
至少 128 bit 的 opaque 值，在 Channel 首次保存/启用素材协议时生成一次。它作为按 Channel ID 关联的
独立受保护持久化事实保存，不写入 `Channel` 公共列、`OtherSettings`、管理请求/响应或素材凭据值。
管理员不能输入、查看或修改；普通配置编辑和 AK/SK 轮换必须保留该值，复制或新建 Channel 必须生成
新值，删除 Channel 时一并删除，删除后重建也不复用旧值。

公开 `reuse_scope` 不返回 `asset_scope_identity` 本身。该 identity 不是 Provider 凭据，不得使用可枚举
的 Channel ID、会随编辑漂移的配置哈希、Channel Key、API Key、AccessKey 或 SecretKey 代替。协议与
固定 endpoint 不进入公式；不同 Channel 依靠随机唯一 identity 隔离，不会因配置相同产生跨租户假阳性。

首版只允许同一 Channel 内的模型得到相同 scope；另建 Channel 即使人工确认仍属同一租户，也先得到
不同 scope，形成安全的假阴性。若移动云以后提供稳定 tenant ID，必须通过明确合同变更再扩大跨
Channel 复用。

source URL 只允许存在于创建请求和当次 Provider 调用，不能持久化、记录或返回。移动云查询响应中的
短期签名 URL 也必须在 adapter 投影时剥离，不进入北向响应、数据库或普通日志。

## 6. 最小入侵落地边界

移动云差异优先隔离在新增文件：视频模型合同与专用 Header 分别由
`relay/channel/task/seedance/provider_mapped_validation_cmcc.go`、
`relay/channel/task/seedance/request_headers_cmcc.go` 承担；素材签名与 REST 映射由
`relay/channel/task/seedance/assets/cmcc_aicc_v2.go` 承担；Channel 约束与匿名素材域身份分别由
`model/channel_seedance_cmcc.go`、`model/channel_asset_scope_identity.go` 承担。不得把这些 Provider
规则扩写进 NEWAPI 原生视频入口、通用分发池或另一套公共任务状态机。

现有文件只保留完成接线所必需的窄改动：协议枚举与 adapter 注册、Seedance 设置校验的一次调用、
CMCC Header helper 的一次调用、素材 adapter 构造分支，以及 stable identity 的迁移、创建与删除钩子。
其中独立 identity 行是所有素材协议统一的必要持久化事实：平台不能从配置或凭据可靠证明 Provider
tenant。随机稳定身份只用于匿名 scope，凭据轮换不改变它，Channel 删除时一并删除。

不复用火山/BytePlus 素材 adapter 的原因是移动云使用独立的 V2.0 Query AK/SK 签名；不新增移动云计费
状态机的原因是共享 durable attempt 与 tiered expression 已覆盖相同异步不变量。允许在移动云新增文件中
保留少量局部重复，以降低对共享上游文件的改动和未来同步冲突。

## 7. 耐久创建与结算

移动云视频 POST 在写出任何请求字节前必须建立 durable `TaskCreateAttempt`，资金 hold、必要额度与
`sending` 原子提交。状态、资金和异常语义直接复用
[异步任务与计费事实架构](../../账单计费-异步任务与计费事实架构.md)，本 Provider 文档不另建或复制
第二套函数级状态机。只发送一次：

```text
prepared -> held/sending -> Provider POST
  -> 可信 task ID：原子创建 Task、转移 hold、完成 attempt
  -> 明确拒绝：幂等释放 hold
  -> 结果不明：unknown，保留 hold，不重发、不换渠道、不退款
```

验收时按现有唯一实现核对：`service.PrepareTaskCreateAttempt` 建立 journal 与 hold，
`service.MarkTaskCreateAttemptUpstreamStarted` 标记已开始发送，明确拒绝走
`service.ReleaseRejectedTaskCreateAttempt`，不明结果走 `service.MarkTaskCreateAttemptOutcomeUnknown`；可信
task ID 先由 `model.RecordTaskCreateAttemptUpstreamSuccess` 记录，再由
`model.InsertTaskWithCreateAttempt` 原子创建 Task 并转移 hold。移动云 adapter 不复制这些函数或另建状态机。

Task 冻结客户模型、Provider 模型、`modelark_v3_cmcc` adapter 版本、Base URL、受保护视频凭据、素材
引用、含视频判断和计费表。查询、删除、内容回源与结算都使用冻结事实，不读取当前 Channel 重新选路。

素材 CRUD 与真人会话不建立视频级 `unknown` 状态机；未取得可信 ID 时向客户返回脱敏失败，可能形成的
Provider 孤儿资源由技术人员按受控记录排查。

## 8. 错误与安全边界

- 未开通/无模型权限、未验证规格与不支持字段分别返回可区分的脱敏错误，不伪装成功；
- 素材操作由代码注册表决定，不支持时返回 `422 unsupported_asset_operation`，不得改投其它 Provider；
- Provider opaque ID、任务私有 ID、AK/SK、API Key、完整签名 URL 和原始响应不得出现在公开元数据或日志；
- 客户退款与 Provider exposure 分账，移动云金额未知时保持未知，不以客户 quota 冒充供应商成本；
- 两套凭据虽然属于同租户，也不能相互替代或被客户端透传。

## 9. 上线闸门

1. 已完成代码注册 `modelark_v3_cmcc` 与 `cmcc_aicc_assets_v2`，且管理端只展示所需字段；
2. 目标非免费租户开通成功，视频与素材凭据经最小权限审查；
3. raw REST 已完成 text、480p/720p/1080p、`reference_video`、含视频 Header 和成功 usage 最小验收；
   image/audio、字段边界、失败状态、删除和结果生命周期继续逐项验收；
4. AIGC 与真人 Image/Video/Audio 的创建、查询、更新、删除和失败闭合通过；
5. 素材在同租户视频任务中真实可引用，跨租户 scope 不发生假阳性；
6. 每个启用模型的移动云官方 Token 单价、失败不收费口径和 Provider 账单完成对账；资源包只属于
   Provider 采购事实，不改变客户 Token 合同；
7. durable attempt、unknown、终态结算、退款和 quota 饱和审计测试通过。
8. Fast、Mini 和 2.5 分别取得移动云模型 ID、开通权限、REST 合同、素材复用和账单证据；缺一项的
   模型保持未映射、未定价、未启用，不能套用 Standard 或火山/BytePlus 合同。

本地直接建渠时，`cmcc_seedance_channel_credentials.sh` 只选择唯一的手动禁用 Channel，并同时核对
客户模型、精确 mapping 和两项 CMCC 协议；凭据无回显写入，权限为私有的数据库备份只进入已忽略的
`.local-tests/cmcc-backups/`。`go run ./cmd/verify-cmcc-seedance -channel-id <id>` 只执行视频任务列表与素材查询的只读
鉴权检查，输出不包含密钥、Task/素材 ID 或签名 URL。只读检查通过仍不自动启用渠道，必须继续满足上述
完整生产闸门。
