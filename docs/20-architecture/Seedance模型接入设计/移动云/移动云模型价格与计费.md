# 移动云模型价格与计费

## 1. 官方成本基准

移动云 AICC-Doubao-Seedance 2.0 公布的按量价格单位为人民币/百万 Token：

| 输出规格 | 含视频输入 | 不含视频输入 |
| --- | ---: | ---: |
| 480p/720p | ¥56 | ¥92 |
| 1080p | ¥62 | ¥102 |

资料来源：[AICC-Seedance2.0 资费及资源包使用规则](https://ecloud.10086.cn/op-help-center/doc/article/99164)，
于 2026-08-20 核对。四个档位是移动云 Provider 成本的首版基础，价格变更只影响新建 Task；历史 Task
继续使用创建时冻结的价格事实。

平台客户价格表达式统一使用 USD/百万 Token。移动云人民币成本按项目固定汇率
`1 USD = 6.82 RMB` 换算为 USD 成本基准：

| 输出规格 | 含视频输入 USD 成本基准 | 不含视频输入 USD 成本基准 |
| --- | ---: | ---: |
| 480p/720p | $8.211143695015 | $13.489736070381 |
| 1080p | $9.090909090909 | $14.956011730205 |

汇率只在生成客户 USD 单价/表达式时使用，不参与每次请求的运行时选择。Task 创建时冻结最终 USD 单价
和表达式；历史 Task 不因后续汇率政策或人民币 Provider 价格变化重新换算。

### 1.1 Fast、Mini 与 2.5 的价格状态

| 客户模型 | 移动云官方按量价 | 移动云资源包 | 客户计费状态 |
| --- | --- | --- | --- |
| `seedance-2.0-cmcc` | 已公布，见上表 | 已公布 | 已按 USD 成本预配置；生产账单验收前保持禁用 |
| `seedance-2.0-fast-cmcc` | 未发现 | 未发现 | `unpriced`，不得发布 |
| `seedance-2.0-mini-cmcc` | 未发现 | 未发现 | `unpriced`，不得发布 |
| `seedance-2.5-cmcc` | 未发现 | 未发现 | 条件候选，`unpriced`，不得发布 |

火山国内和 BytePlus 的 Fast、Mini、2.5 价格只能用于供应商比较，不能作为移动云成本。移动云未给出
价格时，不得用 Standard 单价、相邻型号单价、火山价或 BytePlus 换汇价兜底；客户模型必须保持未定价
和未启用。

“含视频输入”必须由结构化 content 是否包含 video 判断。图片或音频输入不能命中视频输入低价档，
客户 Header 或自定义参数也不能覆盖该判断。

## 2. Token 估算与实际结算

官方估算公式：

```text
estimated_tokens = (input_video_seconds + output_seconds) × output_width × output_height × fps / 1024
```

预扣使用有上界的输入时长、输出时长、分辨率和 fps 计算估算 Token；成功终态优先使用移动云返回的
`usage.completion_tokens` 结算。不能用裸 `int` 转换或无界乘法，所有 quota 换算必须使用项目统一的
checked 饱和转换并把异常写入管理员审计。

ModelArk V3 北向缺省 duration 为 5 秒，校验与预扣都使用该值；可选字段缺失时南向 JSON 仍保持缺失，
不在 adapter 内伪造客户输入。移动云目标租户尚未验收“不传 duration”的真实结果，因此该行为属于
生产启用闸门；未证明 Provider 同样采用 5 秒前不得启用渠道。

2026-08-20 目标 API Key 的四个成功样本显示，24fps 终态 usage 符合：

```text
observed_completion_tokens = floor(
  (((input_video_seconds + output_seconds) × fps) + 1) × output_width × output_height / 1024
)
```

额外 `+1` 为一个输出帧。该规律是当前 Provider 版本的实测预扣依据，不替代终态
`usage.completion_tokens`。预扣使用 checked 的向上保护值，不能按官方名义秒公式少扣一个帧。

按标准尺寸与 24 fps 推导的估算值如下，仅用于预扣说明，不取代 Provider 实际 usage：

| 规格 | 假定尺寸 | Token/计费秒 | 含视频输入成本/计费秒 | 不含视频输入成本/输出秒 |
| --- | ---: | ---: | ---: | ---: |
| 480p | 864×496 | 10,044 | ¥0.562464 | ¥0.924048 |
| 720p | 1280×720 | 21,600 | ¥1.209600 | ¥1.987200 |
| 1080p | 1920×1080 | 48,600 | ¥3.013200 | ¥4.957200 |

含视频输入档的“计费秒”是 `input_video_seconds + output_seconds`；不含视频输入时只有输出时长。尺寸、
fps 或 Provider 取整规则与上述假定不同会改变估值，真实结算仍以终态 `completion_tokens` 为准。

| 脱敏实测 | 实际 `completion_tokens` | 按公开价计算的名义 Provider 成本 |
| --- | ---: | ---: |
| 480p、5 秒、无视频输入 | 50638 | ¥4.658696 |
| 720p、5 秒、无视频输入 | 108900 | ¥10.018800 |
| 1080p、5 秒、无视频输入 | 245025 | ¥24.992550 |
| 720p、5 秒视频输入 + 5 秒输出 | 216900 | ¥12.146400 |

前三项按无视频输入价计算，第四项按含视频输入价计算。表中金额是公开单价乘实际 Token 的数学结果，
不是移动云账单回执；API 已证明 usage 计入视频输入，但实际价档仍须账单验证。

## 3. 客户价格设计

客户合同保持与移动云一致的 Token 计费单位，但结算币种统一为 USD。价格以按 `1 USD = 6.82 RMB`
换算后的移动云成本为基础，不复制 BytePlus、火山或第三方售价。Provider 成本与客户收费必须分账：

```text
provider_cost_rmb = actual_completion_tokens / 1,000,000 × frozen_cmcc_price_rmb
frozen_customer_unit_price_usd = frozen_cmcc_price_rmb / 6.82
customer_cost_usd = actual_completion_tokens / 1,000,000 × frozen_customer_unit_price_usd × frozen_group_ratio
customer_quota = customer_cost_usd × QuotaPerUnit
```

首版不增加商业加成，客户 USD 单价就是移动云人民币按量价除以固定汇率 6.82 的结果；不新增独立运行
时 margin 或动态汇率字段。Standard 四个移动云成本档直接写入既有客户价格表达式，并在 Task 创建时
冻结最终客户合同、组倍率和表达式；不能在终态按当前配置重算。

`QuotaPerUnit` 是项目既有的 USD 到内部 quota 换算因子，定义于
[common/constants.go](../../../../common/constants.go)，不是移动云 Channel 字段。表达式的 USD/百万
Token 单位与换算合同以 [billingexpr 设计](../../../../pkg/billingexpr/expr.md) 为准；最终整数转换必须使用
[统一 quota checked 转换](../../../../common/quota_math.go)，不得在 Provider adapter 内另建换算逻辑。

实现时用请求条件区分已验证的 `resolution=480p/720p/1080p` 与结构化含视频判断，但表达式本身仍是
唯一客户计费合同，不能同时保留另一套隐式倍率表。客户提供的 Header 或价格档参数没有选择低价档的
资格。

Standard 按移动云成本、不加商业加成时的 USD 表达式为：

```text
param("_task.has_video_input") == true
  ? (param("_task.resolution") == "1080p"
      ? tier("1080p_video", c * 9.090909090909)
      : tier("480p720p_video", c * 8.211143695015))
  : (param("_task.resolution") == "1080p"
      ? tier("1080p", c * 14.956011730205)
      : tier("480p720p", c * 13.489736070381))
```

`c` 是移动云终态 `completion_tokens`。首版异步预扣 Token 估算值配置为 `1,460,025`，覆盖单个
15 秒参考视频输入、15 秒输出、1080p、24fps 和额外一个输出帧的已验证取整规律；这只是预扣保护值，
不冒充 Provider 的内容数量上限，也不参与终态用量重算。若实际请求允许更多或更长输入、不同 fps 或
更高尺寸，必须先提高预扣估算并完成余额不足结算路径验收，再发布相应能力。

## 4. 预扣、终态与异常

| 阶段 | 计费处理 |
| --- | --- |
| 创建前 | 按请求上界估算，attempt hold 与 `sending` 原子提交 |
| 创建结果不明 | 保留 hold；不自动重发、换渠道或退款 |
| succeeded 且 usage 可信 | 按冻结价格和实际 `completion_tokens` 幂等结算差额 |
| succeeded 但无可计费用量 | 按[异步任务与计费事实架构](../../账单计费-异步任务与计费事实架构.md) §6.1 保留预扣估算，并进入用量证据审计 |
| failed/cancelled/expired | 按客户合同处理客户资金；Provider 成本另行记录和对账 |
| usage 非法、负数、溢出或前后不一致 | 不覆盖既有结算，进入合同异常与 quota 饱和审计 |

移动云资料称仅成功生成的视频收费，审核失败等不收费；上线前必须用目标租户账单验证。即使客户资金
释放，也不能据此推断 Provider 一定无成本。Provider 金额未知时保持未知，禁止用客户 quota 冒充人民
币成本。

## 5. 资源包处理

移动云提供多档预付 Token 资源包，但本平台客户合同始终按 Token 计费。资源包只影响 Provider 采购
与财务对账，不改变单个客户 Task 的冻结 usage 或客户单价事实：

- 首版客户定价以移动云公布的按量 Token 成本为基础；
- 不把资源包余额、折扣或抵扣顺序引入客户 Task 计费表达式；
- 资源包余额或延迟扣减不能作为 Task 成功、结算完成或 Provider 成本为零的证据；
- 后续若将资源包折扣纳入成本，只能作为独立的 Provider 采购/对账事实，不能回写历史客户账单。

## 6. 生产验收

至少以同一移动云租户完成以下账单样本：

1. 已取得 480p/720p/1080p 无视频输入和 720p 含视频输入的成功 usage 样本；上线前补齐其实际账单；
2. 补齐 480p/1080p 含视频输入的成功 usage 与实际账单；
3. 成功终态 `completion_tokens`、平台冻结档位和移动云账单金额一致；
4. failed、cancelled、expired、审核失败和创建结果不明的扣费事实；
5. 明文 REST 与未来加密 SDK 如同时存在，确认官方价格是否完全一致；
6. Fast、Mini、2.5 若由移动云上线，逐模型取得按量价、usage 与真实账单，不与
   Standard 共用未验证表达式。

任何一个价档未验证时，只能保持未发布，不能静默套用相邻分辨率或另一 Provider 价格。
