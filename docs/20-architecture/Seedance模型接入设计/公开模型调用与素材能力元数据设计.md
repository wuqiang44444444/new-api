# 公开模型调用与素材能力元数据设计

## 1. 目标与身份边界

下游只认识部署方定义的客户模型名。公开模型目录不得返回上游原始模型名、Provider 名称、Channel ID、
协议标识、账号、Region/Project、凭据或南向私有路径。

内部身份保持分离：

```text
客户模型 -> 唯一 Seedance Channel -> model_mapping -> 代码协议 adapter -> 上游模型
```

管理员可以把客户模型命名为任意业务名称；`model_mapping` 只在内部把该名称映射到代码协议已登记的
上游模型。运行时不得根据客户模型的名称、前缀或后缀推断路由、素材能力或素材作用域。

## 2. 公开模型元数据

`GET /v1/models`、`GET /v1/models/{customer_model}` 和
`GET /api/v3/contents/generations/models` 对每个 Seedance 客户模型返回同一份 `api`：

| 字段 | 含义 |
| --- | --- |
| `api.video.creation` | 创建任务的方法、路径、内容类型、必填字段和应填写的客户模型名 |
| `api.video.operations` | 视频创建、列表、查询、删除和内容下载入口 |
| `api.assets.supported` | 当前客户模型是否配置了已验证的素材协议 |
| `api.assets.operations` | 每个素材/素材组操作是否支持 |
| `api.assets.media` | 素材类型及其素材组要求 |
| `api.assets.creation` | 创建素材的 URL、MIME、大小、重定向和示例请求限制 |
| `api.assets.reuse_scope` | 匿名素材复用域；不支持素材时省略 |

`available` 表示当前 Key 能否调用，不能替代 `api.assets.supported`。模型被停用时仍保留元数据，便于
调用方区分“模型存在但不可调用”和“模型不存在”。

## 3. 素材支持判定

素材支持只由 Channel 上明确配置且有代码 adapter 的 `asset_upstream_protocol` 决定。模型名中的
`720p`、`1080p`、`4k` 或其它词不参与运行时判定。

当前已验证事实如下：

| 通用模型类别 | 素材元数据 | 依据 |
| --- | --- | --- |
| 固定分辨率系列（现有客户名通常含 `720p`、`1080p` 或 `4k`） | `supported=false` | 当前接入只发现视频创建、查询和计费合同，没有可验证的素材 CRUD/素材组接口；Channel 配置为 `none` |
| 配置已验证素材协议的 Standard/Fast/Mini/下一代系列 | `supported=true` | 由对应素材 adapter 逐操作发布 |
| 未配置素材协议的任意系列 | `supported=false` | 例如当前有一条下一代模型线路实测返回 `422 unsupported_asset_operation` |

因此，“固定分辨率系列不支持”是当前事实，但“其它名称一律支持”不是安全不变量。下游必须读取
`api.assets.supported` 和 `operations[].supported`，不得根据名称反推能力。

## 4. 素材互通

`reuse_scope` 是由当前素材协议、素材服务地址及已配置项目/区域形成的匿名稳定标识，不包含凭据值，
也不能反推出 Provider 或上游模型名。它遵循“共享上游账号、调用方自管素材”的已接受边界，不是账号
隔离证明；需要账号级强隔离时必须使用独立账号/Project，不能依赖 scope。

调用方按以下规则处理：

1. 两个模型都必须满足 `api.assets.supported=true`；
2. 两个非空 `reuse_scope` 必须完全相同，才表示平台已知它们落在同一素材复用域；
3. scope 不同或缺失时，不得跨模型发送素材 ID；
4. scope 相同只是选路提示，不是所有权或 ready 状态证明，实际查询与生成仍由上游最终裁决。

部署方可以让相同 `reuse_scope` 的客户模型使用同一业务后缀，让后缀便于人工识别；后缀只是命名约定，
不能替代 API 元数据。这样避免“同后缀但实际素材协议不同”造成错误互通。

## 5. 调用流程

客户端应先查询客户模型，再构造请求：

```text
GET /v1/models/{customer_model}
  -> 检查 available
  -> 按 api.video.creation 创建视频
  -> 需要素材时检查 api.assets.supported / operations / media / creation
  -> 跨模型复用前比较 reuse_scope
  -> 保存 customer_model + opaque asset id/reference
```

视频创建和素材操作都只携带客户模型名。素材响应只返回客户模型和 opaque ID/reference；中转站不提供
素材列表，不验证视频请求中素材的可用性，也不因失败切换模型、Channel 或上游。

## 6. 不变量

- 一个已启用客户模型只对应一个 Seedance Channel；
- 客户模型允许任意业务命名，但必须精确映射到代码协议已登记的上游模型；
- 公开元数据不返回 Provider 身份或上游原始模型名；
- 素材能力来自协议配置，不来自模型名；
- `reuse_scope` 来自实际素材域，不来自客户模型后缀；
- 不支持的素材操作返回 `422 unsupported_asset_operation`；上游失败不能改判为“不支持”。
