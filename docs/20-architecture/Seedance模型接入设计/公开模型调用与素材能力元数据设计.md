# 公开模型调用与素材能力元数据设计

本文定义 Seedance 公开模型目录中 `api` 元数据的跨 Provider 规则。它回答“调用方能看到什么、如何
判断能力和复用范围”，不维护某个 Provider 的逐模型能力表。

## 1. 权威分工

| 问题 | 权威来源 |
| --- | --- |
| 公开模型目录、`api.video` 与 `api.assets` 字段形状 | 代码中的 `SeedancePublicModel`、`PublicModelAPI`、`PublicAssetAPI` |
| 具体模型的素材操作、素材组要求和错误合同 | [Seedance模型素材库支持矩阵](../Seedance模型素材库支持矩阵.md) |
| 单个 Provider 的原始接口、对接设计、价格和元数据 | [Seedance模型接入设计索引](README.md) 下对应 Provider 的四份文档 |
| Task、创建尝试、计费和结算事实 | [账单计费-异步任务与计费事实架构](../账单计费-异步任务与计费事实架构.md) |

本文不描述 Provider 签名、Task 状态机、计费公式、迁移步骤或上线过程；这些内容只在上述专题中维护。

## 2. 身份与公开边界

下游只认识部署方定义的客户模型名。内部身份保持分离：

```text
客户模型 -> 唯一 Seedance Channel -> model_mapping -> 代码协议 adapter -> Provider 模型
```

管理员可以使用任意业务名称；`model_mapping` 只负责精确映射到代码协议登记的 Provider 模型。运行时
不得根据客户模型名称、前缀、后缀、价格或分辨率推断路由、素材能力或复用域。

公开响应不得返回 Provider 名称、上游模型名、Channel ID、账号、Region/Project、凭据、南向路径、
原始 Task ID、签名 URL、source URL、媒体二进制或原始 Provider 响应。

## 3. 公开元数据形状

以下入口为同一份客户模型目录投影：

- `GET /v1/models`
- `GET /v1/models/{customer_model}`
- `GET /api/v3/contents/generations/models`

每个 Seedance 客户模型包含 `api.video` 和 `api.assets`：

| 字段 | 公开语义 |
| --- | --- |
| `api.video.protocol` | 固定为 `modelark_v3`，表示北向视频合同 |
| `api.video.creation` | 创建方法、路径、内容类型、必填字段和客户模型名 |
| `api.video.operations` | 视频创建、列表、查询、删除和内容下载入口及逐操作支持状态 |
| `api.assets.supported` | 当前客户模型是否配置非空的已登记素材协议 |
| `api.assets.operations` | 素材/素材组各操作的支持状态；列表操作固定不提供 |
| `api.assets.media` | 可创建的素材类型及素材组要求 |
| `api.assets.creation` | URL 来源限制、大小/重定向限制和请求示例；不支持创建时省略 |
| `api.assets.management_mode` | 固定为 `caller_managed_stateless` |
| `api.assets.requires_model` | 固定为 `true`，每次素材操作都必须带客户模型 |
| `api.assets.reference_format` | 固定为 `asset://{opaque_upstream_asset_id}` |
| `api.assets.reuse_scope` | 非空时表示匿名素材复用域；无素材协议时省略 |

`available` 只表示当前 Key 是否可以调用，不能替代 `api.assets.supported`。模型停用时仍可返回元数据，
使调用方能区分“模型存在但不可调用”和“模型不存在”。

## 4. 素材能力与复用域

素材能力只由 Channel 上明确配置且由代码注册的 `asset_upstream_protocol` 决定。具体逐 Provider、逐
模型和逐操作结果以 [素材库支持矩阵](../Seedance模型素材库支持矩阵.md) 为准；本文不复制该矩阵。

`reuse_scope` 由 Channel 随机稳定 identity 和格式版本
`seedance_channel_asset_scope:v1` 单向生成，不包含凭据、Provider、协议、服务地址、Project 或 Region，
也不能反推出上游模型。同一 Channel 内模型使用相同 scope；不同 Channel 即使配置相同也使用不同 scope。
它是管理员声明且平台冻结的渠道租户边界，不是 Provider 真实租户、所有权、兼容性或 ready 状态证明。

调用方只有在以下条件同时满足时才可尝试跨模型复用：

1. 两个模型的 `api.assets.supported` 都为 `true`；
2. 两个 `reuse_scope` 均非空且完全相同。

scope 相同只是选路提示，最终兼容性由选定 Provider 判定。scope 不同或缺失时不得跨模型发送素材
引用。素材 ID 是 Provider 返回的不透明值，调用方应保存 `customer_model + id/reference`。

定价/模型列表只对本次可见且 `available=true` 的模型按 scope 聚合。界面短标签取 scope 哈希前缀并在
发生碰撞时增加长度，不使用列表序号；模型详情展示同组客户模型，不展示 Channel、Provider 或上游模型。

## 5. 调用方流程

```text
查询客户模型
  -> 检查 available
  -> 按 api.video.creation 创建视频
  -> 需要素材时读取 supported / operations / media / creation
  -> 跨模型复用前比较 reuse_scope
  -> 保存 customer_model 与 opaque asset id/reference
```

平台只按客户模型选择唯一 Seedance Channel。`/v1/assets` 与 `/v1/asset-groups` 是单资源、无状态代理，
不提供列表，不建立平台 Asset/AssetGroup 事实，不查询或验证视频请求中的素材引用，不因失败切换模型、
Channel 或 Provider。

## 6. 不变量与变更边界

- 一个已启用客户模型只对应一个 Seedance Channel；
- 能力来自代码协议注册和已验证 Provider 合同，不来自名称、价格或分辨率；
- 公开元数据不泄露 Provider 身份及上游私有信息；
- 不支持的操作返回 `422 unsupported_asset_operation`；明确的上游失败不得改判为“不支持”；
- 新增或变更 Provider 能力时，先更新对应 Provider 四文档和素材支持矩阵，再更新代码投影；
- 本文只在跨 Provider 公开合同发生变化时修改，不能重新引入逐 Provider capability 表。
