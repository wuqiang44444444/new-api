# 飞彩总体架构与履约设计

## 1. 主链

```text
独立 customer_model
  -> 唯一 Feicai ChannelTypeSeedanceLink
  -> model_mapping
  -> media_arrays_v2 或 media_arrays_v3
  -> 精确 Provider model
  -> 一次 Provider POST
```

飞彩每个独立产品模型使用自己的前端客户模型名。v2 带 `-feicai` 后缀的 Provider 模型与 v3 无后缀
模型使用不同 Channel/客户模型，不共享前端名称、Task、价格、size 证据或 Provider 成本事实。

## 2. 渠道配置

管理员配置：Base URL、Bearer Key、视频协议、`asset_upstream_protocol`、客户模型、`model_mapping`
和价格。Priority/Weight 对飞彩 Seedance 无效；失败后不换到飞彩其它模型、v2/v3 另一版本或其它
Provider。

完全兼容现有 media-arrays 协议的新模型可由技术人员确认后配置；字段或状态不同则新增代码 adapter。

## 3. 请求转换

adapter 负责：

- ModelArk text 按顺序合并为 `prompt`；
- 精确 Provider 模型写入 `model`；
- duration 显式整数发送；
- `(protocol, provider_model, resolution, ratio)` 查受验证 size 表；
- `reference_image`、`reference_audio`、`reference_video` 分别形成 `images[]`、`audios[]`、`videos[]`；
- 保留媒体顺序；
- 拒绝模型未验证的媒体角色、数量和字段。

size 表是 adapter 的代码协议事实，不是通用 capability/implementation 身份。某个模型没有精确 size
证据时技术人员不得通知管理员启用该组合；运行时未知组合明确拒绝，不从同分辨率其它模型推导。

## 4. 创建和 Task

发送前建立 durable attempt、客户资金 hold，并冻结客户模型、Channel、Provider 模型、协议、Key、
媒体和计费规格。每次创建只发送一次 Provider POST。

飞彩返回的可信 task ID 必须结构合法并与后续查询顶层 ID 一致。发送后断连、坏 JSON、未登记错误或
缺少可信 ID 进入视频 unknown，不重发或切换。

查询状态归一：`queued`/`processing`/`in_progress` 为运行中，`completed`/`success` 为成功，可信
失败为失败。未知状态、ID 不一致、成功无内容或结果冲突进入不可采信观测，不直接退款。

内容只通过平台代理，使用 Task 冻结 Key 和允许的 HTTPS origin；不把飞彩 video URL、Bearer、Provider
模型或 task ID 返回客户。

## 5. 素材

飞彩当前按第三方媒体数组消费请求级 URL。若没有独立素材库 CRUD 协议，Channel 配置
`asset_upstream_protocol=none`，平台 `asset://ast_*` 不可通过旧 source URL fallback 使用。

未来飞彩提供完整素材协议时，一个平台 Asset 必须一对一固定到该飞彩 Channel/账号/Provider Asset；
不建立多 Channel binding 或自动迁移。真人认证同样只通过 Provider AssetGroup 链接代理。

## 6. v2/v3 隔离

- v2 只发送带 `-feicai` 后缀的精确 Provider 模型；
- v3 只发送无后缀精确 Provider 模型；
- 两个版本分别维护 adapter、size、错误和账单证据；
- v2 成功不能使 v3 同名档位自动上线，反之亦然；
- 旧 v1 只在确认无在途 Task、资金和内容依赖后移除，不进入新请求。

## 7. 不变量

1. 每个飞彩客户模型只对应一个已启用 Channel。
2. v2/v3 使用不同客户模型名，不建立同名聚合。
3. 不使用 Priority/Weight/Affinity/fallback。
4. size 和媒体能力只依据精确 Provider 模型证据。
5. 视频创建只发送一次，unknown 不自动退款。
6. Task、内容和计费使用创建时冻结 Channel/协议/Key。
7. Provider 私有身份和完整 URL 不进入普通响应或日志。
