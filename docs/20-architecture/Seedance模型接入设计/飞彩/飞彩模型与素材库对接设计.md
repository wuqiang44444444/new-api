# 飞彩模型与素材库对接设计

## 1. 身份与边界

飞彩使用 `ChannelTypeSeedanceLink`、ModelArk V3 和代码协议 `feicai_videos_v1`。一个已启用客户模型只绑定一个飞彩 Channel，Provider 模型只由 `model_mapping` 精确得到；不得按名称、价格或 URL 推断。飞彩当前 `asset_upstream_protocol` 固定为 `none`，不建立飞彩素材 CRUD。

## 2. 北向到南向

| ModelArk V3 | 飞彩 `/v1/videos` | 规则 |
| --- | --- | --- |
| 客户模型 | `model` | 使用映射后的精确 Provider 模型 |
| `text` | `prompt` | 按顺序以换行合并非空文本 |
| `duration` | `duration` | 先过全局时长上界和逐模型范围 |
| `resolution` | 模型登记 | 固定为 720p/1080p/4K，不发送像素 `size` |
| `ratio` | `ratio` | 只发送精确登记的比例集合 |
| `image_url`/`audio_url`/`video_url` | `images[]`/`audios[]`/`videos[]` | 保留顺序；`asset://` 原样交给 Provider |

协议级上限为图片 9、音频 3、视频 3；图片支持 HTTP、HTTPS 和图片 Data URL，音频/视频只接受 HTTPS。非空 `asset://<opaque-id>` 不查询本地、不验证所有权或模型作用域，由飞彩最终判断。

## 3. 模型合同

代码登记十个模型：Mini、SD2、Fast、933/ VIP 的 720p、1080p、4K 档以及 Pro PI。SD2 只允许 `16:9`/`9:16` 且必须有 1–9 张图片；Pro PI 固定 15 秒并允许最多 3 个参考视频；其余模型允许 `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`。显式提供未支持字段必须在 Provider I/O 前返回 `invalid_video_parameter`。

## 4. 异步、内容和错误

创建沿用 `TaskCreateAttempt + hold + sending` 原子边界，只发送一次 Provider POST。无可信 task ID 时保持 `unknown`，不重发、不换渠道、不退款。查询结果只接受与冻结 task ID 一致的受支持状态和 HTTPS 结果；不可采信的单次响应不得直接判业务失败。

飞彩不提供已验证的素材组、真人认证或素材生命周期；URL 仅为本次请求媒体，不持久化 source URL，不建立 Asset/AssetGroup、resolver、列表索引或跨 Provider fallback。Provider 失败统一脱敏返回。

## 5. 配置与验收

Channel 必须保存 `video_upstream_protocol=feicai_videos_v1`、单一凭据、精确 `model_mapping`；管理端展示“飞彩视频 V1（不提供素材 CRUD）”。上线前按 Provider 模型分别验收请求字段、媒体、任务终态、结果回源、失败扣费和账单；代码实现不等于生产发布。

## 6. 代码事实

权威位置：`relaykit/dto/upstream_protocol.go`、`relay/channel/task/seedance/thirdparty/feicai/model_spec.go`、`create_request.go`、`response.go` 和 `model/channel_seedance_public_catalog.go`。共同异步与素材合同见上位架构文档。
