# 飞彩全模型与计费设计

## 1. 两个渠道与十个模型

下表是当前 Provider 模型能力和证据目录，不是 Link SKU。管理员用两个 Channel 分别承载 VIP 五模型和性价比五模型，
每一行仍使用独立客户模型和精确 `model_mapping`。表中的客户模型是当前配置快照，不是代码合同；管理员可以
改成任意名称，adapter 只能读取映射后的 Provider 模型做判断。
飞彩只维护这一组当前模型，不保留 v1/v2/v3 配置族或带 `-feicai` 后缀的旧 Provider 模型。

| 渠道 | 客户模型 | Provider 模型 | 固定分辨率 | duration | 图片 min–max | 音频 max | 视频 max | 计费模式 |
| --- | --- | --- | --- | --- | ---: | ---: | ---: | --- |
| VIP | `seedance-2.0-mini-720p` | `seedance-2.0-vip-720p-mini-azhw` | 720p | 4–15 | 0–9 | 3 | 0 | 按秒 |
| 性价比 | `seedance-2.0-sd2-720p` | `seedance2.0-sd2` | 720p | 11–15 | 1–9 | 0 | 0 | 按秒 |
| VIP | `seedance-2.0-fast-720p` | `seedance-2.0-vip-720p-fast-azhw` | 720p | 4–15 | 0–9 | 3 | 0 | 按秒 |
| 性价比 | `seedance-2.0-value-720p` | `seedance-2.0-933-720p-azhw` | 720p | 4–15 | 0–9 | 3 | 0 | 按秒 |
| VIP | `seedance-2.0-720p` | `seedance-2.0-vip-720p-azhw` | 720p | 4–15 | 0–9 | 3 | 0 | 按秒 |
| 性价比 | `seedance-2.0-value-1080p` | `seedance-2.0-933-1080p-azhw` | 1080p | 4–15 | 0–9 | 3 | 0 | 按秒 |
| VIP | `seedance-2.0-1080p` | `seedance-2.0-vip-1080p-azhw` | 1080p | 4–15 | 0–9 | 3 | 0 | 按秒 |
| 性价比 | `seedance-2.0-value-4k` | `seedance-2.0-933-4k-azhw` | 4K | 4–15 | 0–9 | 3 | 0 | 按秒 |
| VIP | `seedance-2.0-4k` | `seedance-2.0-vip-4k-azhw` | 4K | 4–15 | 0–9 | 3 | 0 | 按秒 |
| 性价比 | `seedance-2.0-pro-pi-720p` | `seedance-933-pro-pi` | 720p | 固定 15 | 0–9 | 3 | 3 | 按秒 |

全部模型要求显式 duration；没有精确默认值证据时不依赖 Provider 默认。SD2 要求至少一张图且禁止
音频/视频；Pro PI 才允许 `reference_video`，并且固定为 15 秒。十个模型全部按秒计价。

两个 Channel 分别固定单一 Base URL、凭据和运营作用域；它们不是十条逐模型渠道。一个 Channel 的
启用或停用会同时影响其五个客户模型。若需要逐模型灰度，必须先调整该 Channel 的模型清单，不能依赖
Ability、Priority、Weight 或 fallback。

## 2. 当前比例合同

模型名称中的 720p/1080p/4K 表达固定输出分辨率；SD2 和 Pro PI 使用精确登记表，不做模糊推断。
北向 `resolution` 必须与映射后的 Provider 模型固定档位一致。比例不再转换成像素 `size`，而是按精确
Provider 模型允许集合校验后直接发送飞彩比例字段。范围不读取或判断管理员定义的客户模型名称。

| Provider 模型范围 | 支持比例 |
| --- | --- |
| `seedance2.0-sd2` | `16:9`、`9:16` | Provider 明确范围 |
| 其余九个精确 Provider 模型 | `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` | Provider 资料；Mini 四个补充比例已取得真实创建 Task ID |

Mini 的 `21:9`、`4:3`、`1:1`、`3:4` 请求均已由飞彩创建接口接受。该证据只证明参数合同成立，不把
终态生成成功作为比例发布条件。同一个 Provider 模型的所有合法比例价格相同；ratio 只参与请求转换、
合法性校验和审计，不选择计费档位，也不改变客户价格或 Provider 每秒价。

## 3. 客户计费

每个客户模型使用自己审批的 NEWAPI 价格和表达式：

- 十个按秒模型：冻结 duration、固定分辨率、实际 ratio、输入类型和分组倍率；
- Pro PI 固定 15 秒，但表达式仍使用每秒单价乘以冻结 duration；
- Provider 预期成本和实际账单只供管理员对账，不覆盖客户结算；
- 预扣与终态使用同一冻结 probe；
- 所有乘数先校验上界，quota 使用 checked 饱和函数；
- 失败、退款和视频 unknown 按共享异步事实处理。

渠道 59 和 60 的十个客户模型统一使用火山国内对应模型“输入不含视频”的无折扣官方原价。
Mini 和 Fast 分别对应国内 Seedance 2.0 Mini 和 Fast，其余档位对应国内 Seedance 2.0；
表达式使用按 `1 USD = 6.82 RMB`换算后的 6 位小数 USD 单价乘以 `1,000,000`。
Pro PI 保持固定 15 秒并按秒计费。新飞彩表达式不读取 ratio、size 或比例倍率，不允许建立宽幅或其它比例倍率。
为保证管理员把现存表达式原子迁移到新形状前不发生预扣失败，billing probe 暂时继续提供恒为 `1` 的
`size_multiplier`；该字段不代表尺寸或比例能力，任何非 `1` 值均违反合同。
价格调整只影响之后创建的 Task，已创建 Task
继续使用冻结表达式。

飞彩 `/v1/tasks` 在目标生产 HTTPS Base URL 实测 404，不能作为任务级对账源。subscription/usage 只
能作为账户趋势，不能按相近时间或模型猜测单任务成本。历史账户 usage 增量与研究报价存在不一致，
因此生产价格必须单独审批。

## 4. 不变量

1. 十个 Provider 模型分别配置客户模型、价格和证据，不合并档位。
2. 只维护当前 Provider 模型和飞彩专用 `feicai_videos_v1` 协议，不恢复通用 URL 协议或飞彩版本族。
3. 固定分辨率不能在请求期切到另一价格档。
4. 未验证默认值、媒体或账单不由相邻模型推导；比例只使用精确 Provider 模型登记范围。
5. 客户账单读取冻结 NEWAPI 计费和结算日志，不按当前 Provider 报价回算。
6. 同一个 Provider 模型的所有合法比例同价，ratio 不得改变计费结果。
