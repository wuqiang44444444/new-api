# 飞彩全模型发布门禁与验证设计

## 1. 目的与目录边界

本文只定义飞彩单轨 v2 的发布状态、证据权威、逐模型门禁和不可绕过的不变量，不承载逐条测试步骤、
日期进展或生产操作记录。

- 确定性代码用例见[飞彩全模型回归规约](../../../30-engineering/飞彩Seedance全模型回归规约.md)；
- 真实 Provider 黑盒与停流操作见[飞彩全模型上线验收手册](../../../40-operations/06-飞彩Seedance全模型上线验收手册.md)；
- 当前研究证据仍由 `docs/70-research/飞彩/` 承载。

## 2. 发布状态模型

| 状态 | 必要事实 | 允许行为 |
| --- | --- | --- |
| 设计已接受 | 10 模型身份、差异、未决项和 v2 单轨决策完整 | 文档可作为目标，不配置生产 Ability |
| v1 可移除 | 所有环境无 v1 新流量、在途/资金/内容依赖 | 可以删除飞彩 v1 代码与配置，不代表 v2 可用 |
| v2 结构完整 | 10 capability、implementation、binding、adapter、size、billing 和 content hash 一致 | 禁用渠道可执行确定性验证 |
| 单模型证据闭合 | 该模型的 HTTPS、凭据、字段、size、媒体、Task、账单和内容黑盒通过 | 仅该模型可进入 publication 审批 |
| 分组发布 | 价格、exposure、回滚和分组验收通过 | 原子创建/核对 publication 与 Ability |
| 生产开放 | 指定分组的真实流量、账单与观测闭环 | 对批准范围开放，不横向授权其它模型 |

代码注册、Provider 证据、publication 和生产开放是不同状态。任何后置状态不能反向补足前置事实。

## 3. 单轨 v2 总门禁

### 3.1 v1 移除门禁

飞彩不建设 v1/v2 共存。删除 v1 前必须证明：

1. 所有飞彩 v1 Channel/Ability 已停流；
2. 没有 v1 非终态 Task 或未决 create attempt；
3. 没有 v1 hold、退款、结算或 exposure 待处理；
4. 没有仍需使用冻结 v1 Key/adapter 的内容访问；
5. AssetBinding、publication、缓存和运维配置不再引用 v1；
6. 回滚可以恢复完整旧版本和配置快照，而不是在 v2 代码中保留兼容分支。

任一环境不满足时，v2 部署失败关闭。

### 3.2 v2 结构门禁

- 唯一飞彩 implementation 为 `feicai.seedance-videos/v2`；
- media-arrays profile 只允许 `54:third_party_json_video_media_arrays:v2`；
- 10 个目标 SKU 均有唯一 capability version/hash；
- 10 个 Provider 模型均有唯一 execution binding；
- v2 implementation hash 覆盖全部 binding、素材、路径、adapter 和任务/计费合同；
- size 使用四元 registry，旧 `{resolution}:{ratio}` resolver 不再存在；
- SD2 图片最小数量和 Pro PI 视频角色/按次模式进入 capability hash；
- create、polling、reconcile、content 和 billing 只接受冻结 v2；
- v1 fixture、v1 terminal rejection 和 v1 adapter 分派全部移除。

## 4. 10 模型逐一证据门禁

每一行是独立发布单元；其它行的成功证据不可复用。

| # | Link SKU | 发布前必须闭合的模型专属证据 |
| ---: | --- | --- |
| 1 | `seedance-2.0-mini-720p` | 精确模型权限；4–15 秒及默认；准备发布的每个 size；图片/音频组合；按秒账单；排队时延 |
| 2 | `seedance-2.0-sd2-720p` | 11–15 秒；省略 duration 的真实行为；无图确定拒绝；1/9 张图；禁音频/视频；两画幅精确 size；按秒账单 |
| 3 | `seedance-2.0-fast-720p` | 精确模型权限；4–15 秒及默认；逐模型 size；图片/音频组合；按秒账单；“Fast”时延证据但不自动形成 SLA |
| 4 | `seedance-2.0-value-720p` | v2 正式凭据重新验证 16:9/9:16；4/15 秒；图片/音频；成功内容；按秒账单 |

Pro PI 未闭合按次与宽幅倍率前只允许倍率 1 的已验证 size。

## 5. Provider 合同总门禁

每个准备发布的模型至少取得：

1. 可验证证书的正式 HTTPS Base URL；
2. 目标 Key 对精确 Provider 模型有权限；
3. 创建、查询和内容下载全部使用 HTTPS；
4. 下载 Bearer 的作用域、有效期、同源和跳转规则；
5. 创建/查询顶层 `id` 与非权威 `task_id` 的稳定语义；
6. v2 下精确 terminal rejection 组合及“确定未创建”证据；
7. 逐模型 duration、默认、size、媒体数量/角色/格式/大小限制；
8. 排队、媒体抓取、重试和结果保留时间；
9. 失败扣费、取整、宽幅倍率和正式 Provider 账单口径；
10. `/v1/tasks` 的大写状态、唯一关联、分页、过滤与延迟；
11. billing 端点的鉴权、Key 隔离、币种和单位；
12. 内容 URL 的 HTTPS、同源、认证、Range 和过期行为。

`GET /v1/models` 还必须证明目标 Key 能看到精确 Provider 模型，但只作为发布预检，不能自动登记未知模型或改写 publication。

## 6. v2 确定拒绝门禁

当前 v1 的 `403 + feicai_account_required` 不继承到 v2。v1 分支随旧实现删除。v2 初始规则是：

```text
所有未登记的发送后 HTTP/解析异常 -> create outcome unknown
```

只有正式 v2 凭据和协议证据能证明某个 `HTTP status + error.code` 确定未创建时，才能登记该精确组合。
必须同时验证近似 status、近似 code、同 message 和无 code 均保持 unknown。

## 7. 状态与对账门禁

- 主轮询 `/v1/videos/{id}` 只接受小写 `queued/processing/completed/failed`；
- 对账 `/v1/tasks` 只接受大写 `QUEUED/IN_PROGRESS/SUCCESS/FAILURE`；
- 两套 parser 独立，未知值均进入 reconciliation required；
- 主轮询以顶层 `id` 为身份，对账必须证明任务列表 `task_id` 与冻结 id 的稳定唯一关系；
- 未证明唯一关联前，`/v1/tasks` 只能只读观察，不能自动恢复 create unknown；
- 任何对账推进使用 CAS，重复执行不重复建 Task、结算、退款或写 exposure。

## 8. 计费与内容门禁

- 九个按秒 SKU 和一个按次 SKU 使用不同 billing mode；
- converter 与 billing probe 使用同一 size/billing class 证据；
- 预扣和终态使用同一冻结 probe；
- duration、媒体数量、size multiplier 在 quota 计算前有上界；
- quota 转换使用 checked helper，saturation 进入管理员审计；
- Provider task quota、subscription、usage 与客户 quota 分离；
- 成功内容只经平台代理，使用冻结 v2 Key 和同源 HTTPS，拒绝重定向；
- Key、Provider 模型、任务 ID、完整 URL 和账单私有字段不进入普通响应与日志。

## 9. 发布不变量

1. 飞彩只有单轨 v2；v1 删除条件不满足时停止发布，不增加兼容分支。
2. 10 个模型分别取证、分别批准、分别发布，证据不横向外推。
3. 研究报价、示例 size 和模型列表不能替代正式合同与生产黑盒。
4. 任一未决合同字段保持未发布，不用默认值或 fallback 掩盖。
5. 未登记 size、媒体角色、billing mode 或确定拒绝均 fail closed。
6. 代码注册、Provider 验证、publication 和生产开放是四个不同阶段。
7. 发布门禁不触碰 NEWAPI 原生 OpenAI Videos 实现。
