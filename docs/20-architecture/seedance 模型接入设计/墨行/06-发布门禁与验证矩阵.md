# 墨行 Seedance 发布门禁与验证矩阵

## 1. 发布阶段

| 阶段 | 必要事实 | 允许状态 |
| --- | --- | --- |
| 设计 | 当前 V2、历史 Ark、素材证据缺口和账单边界已分离 | 文档 accepted，不表示 Ability 可用 |
| capability | 当前模型字段、值域、默认、媒体和生命周期有证据 | SKU 可解析，仍不表示生产可用 |
| implementation | 精确版本、binding、profile、路径、素材和 adapter/hash 完整 | 禁用渠道可做结构校验 |
| publication | HTTPS、单 Key、价格、exposure、素材作用域和实现覆盖通过 | 启用时原子 publication + Ability |
| 生产开放 | 成功、失败、unknown、内容、素材、usage 和账单黑盒通过 | 仅指定分组可用 |

## 2. 当前门禁状态

结构性阻断项已关闭，但真实 Provider 证据未闭合，因此墨行 Seedance 仍不应视为生产就绪：

| 项目 | 当前事实 | 状态/发布要求 |
| --- | --- | --- |
| V2 与 Ark 等价性 | Ark v1 仅保留 deprecated 历史解析，不进入当前候选 | 已关闭；不得重新作为等价候选 |
| 分辨率 | oversea 只登记 480p/720p；doubao 登记 480p/720p/1080p | 已关闭；4K 均不发布 |
| last frame | 当前 lifecycle 不声明返回尾帧 | 已关闭 |
| prompt/default | 初版强制文本、时长、分辨率和比例显式 | 已关闭；`duration=-1` 按 15 秒预扣 |
| 真人素材 | v2 implementation 只登记 `general` | 已关闭 |
| Ark 素材/H5 | 原配套参考文档已改为 doubao V2 模型页，不再提供 Ark 素材或认证合同 | 阻断任何新 Ark binding；重新接入必须重新取证 |
| 结果/usage | `doubao-seedance-2-0-260128` 的 480p、1080p 精确文生样本为对象 result、无 usage，MP4/Range 可用；另有请求快照不完整的 720p 成功产物；两个 v2 relay 均不把未验 usage 投影为 token | 该 SKU 文生结果已部分闭合；素材、720p 精确请求、本站高分辨率 E2E、账单与 oversea 仍阻断 |
| Provider 对账 | `seedance-2-0-oversea` 有账户接口资料；`doubao-seedance-2-0-260128` 只有模型页与终态 | 阻断；分别验证请求 ID、账号归属、最终一致性和失败扣费 |
| oversea 部署数据 | 本地渠道 49 为 v2、Channel/Ability 禁用、无 publication；www 与裸域名认证预检均返回 401 | 阻断；更换有效 Moxing 模型 Key 后实测 |
| doubao 部署数据 | 本地渠道 50 已升级 v2，保留 publication，Channel/Ability 禁用；4 秒 480p 本站 E2E 成功，4 秒 1080p 直连成功 | 保持禁用；补齐素材、720p 请求溯源、高分辨率本站 E2E、智能时长与 Provider 账单后再恢复 |

## 3. 确定性回归矩阵

### 3.1 注册与发布

- 精确 `moxing.seedance-media-task@v2` 或 `tokensave.seedance-media-task@v2`、channel type、profile、
  create/query path、adapter、`relay_assets` 和单 Key 校验；
- 两个客户模型经 `model_mapping` 分别唯一得到自己的 Provider 模型；
- execution binding 唯一解析同一 Link SKU，缺失、重复或歧义均失败；
- 同范围普通候选冲突、publication 创建/核对/显式改绑和零候选保持 publication；
- Ark、JoyCreator 和另一个当前 SKU 的 implementation 均不能加入本 SKU 候选；TokenSave v1 与
  Moxing Ark v1 只能解析冻结历史事实，不能再选作新任务；
- implementation/capability hash 改变时旧 Task 不由新版本轮询。

### 3.2 请求

| 用例 | 期望 |
| --- | --- |
| 文本 + 4/15/-1 秒 | 通过并产生精确 V2 字段；`-1` 保留发送，billing probe 固定按 15 秒预扣 |
| 3、0、16 秒或非整数 | 预扣前 4xx |
| 480p/720p | 两个 SKU 都通过 |
| 1080p | 仅 doubao 通过；oversea 预扣前拒绝 |
| 4K/未知分辨率 | 两个 SKU 都预扣前拒绝 |
| 七种已登记比例 | 逐值映射到 `aspect_ratio` |
| 无文本 | 初版拒绝 |
| 单首帧、首尾帧、1/9 张参考图 | 分别转换为 `single_image/none`、`multi_image/end_frame`、`multi_image/reference` |
| 10 张图、多个首帧/尾帧、首尾帧与参考图混用 | 拒绝 |
| 音频或视频输入 | 初版拒绝 |
| `generate_audio=false` | 上游仍收到显式 false |
| `watermark`、Provider 私有字段、metadata/extra 旁路 | 未发布前拒绝 |
| 直接媒体与 `asset://ast_*` 混用 | 拒绝 |

### 3.3 Task 与错误

- 创建 task ID 正常、缺失、空白、过长和控制字符；
- 发送前拒绝、发送后断连、超时、无效 JSON 和非可信非 2xx；
- `queued/running/succeeded/failed`、未知状态和任务 ID 不匹配；
- 成功结果缺失、URL 非 HTTPS、userinfo、SSRF、重定向和过期；
- unknown hold、人工恢复/拒绝、到期释放和 exposure 全部幂等；
- 轮询合同违例可在后续合法响应恢复，不被提前退款。

### 3.4 素材

- `/assets` 创建、Pending/Processing/Active/Failed、更新和删除；
- `upstream_id` 优先、缺失时 uuid fallback，以及客户永不看到两者；
- 所有者、App、publication、implementation、channel、凭据指纹和 profile 围栏；
- Key/Base URL 轮换后旧 binding 失败关闭；
- general 图片可用，real_person、音频/视频素材对当前 SKU 拒绝；
- Ark binding、JoyCreator ID 和当前 relay binding 不互换；缺少完整冻结事实时 Ark binding 失败关闭；
- 多素材共同候选和发送前二次校验。

### 3.5 计费与对账

- 预扣上界存在、越界、余额不足和 quota saturation；
- 模型时长只接受 `4..15/-1`，`-1` 按 15 秒预扣，且不能用全局 3600 秒上限替代模型校验；
- 两个 v2 SKU 对缺失/字符串/对象/负数/超大 usage 均不参与结算；
- oversea 按 token 上界表达式、doubao 按秒表达式分别命中正确档位，不能共享价格；
- 成功结算、失败退款、unknown 保留、到期释放与 exposure；
- 捕获 `X-Oneapi-Request-Id`，不误用客户端 request ID；
- Provider 对账 pending/success/failed/404/401/403 与退避；
- 模型 Key 不能调用账户接口，集成 Token 不能发往模型接口；
- `charged_quota/charged_yuan` 不覆盖 NEWAPI 客户 Log；
- 同一 request ID 重复对账幂等，敏感 Token 和响应 body 不落库。

## 4. 真实 Provider 验收

对 Moxing 的 `www.moxing.pro` 与 `tokensave.pro` 两条线路使用各自目标模型 Key 和隔离测试账号完成；
`seedance-2-0-oversea` 账户对账另使用独立集成 Token，
`doubao-seedance-2-0-260128` 不得复用：

1. 模型权限、证书、创建与查询路径；
2. 文生、首帧、首尾帧、参考图和所有边界时长/比例/分辨率；
3. 显式 `generate_audio=false/true`，以及 watermark 是否准备发布；
4. 创建和每次轮询的完整脱敏响应 schema、请求 ID 和状态延迟；
5. 成功结果 URL、下载鉴权、Range、有效期、同源和跳转；
6. `/assets` 归属、状态、引用、Key 轮换、删除和多素材；
7. 余额不足、限流、无权限、非法字段和 Provider 失败；
8. 终态 usage 与 `/usage-records` 的 token、金额、状态和时间一致性；
9. 失败是否扣费、重复请求是否重复扣费、create unknown 是否可唯一关联；
10. 客户消费日志、退款、Provider 对账和 exposure 的分账结果。

截至 2026-08-05，`doubao-seedance-2-0-260128` 的 4 秒 480p 文生完成创建、52 次轮询、成功终态、
MP4 下载和 Range 验证；请求捕获到 Provider request ID，但文档不保存其值。输出像素为 864×496，
不能据此把 `480p` 解释为固定像素。追加脱敏产物证明 4 秒 1080p、16:9 直连在 89 次轮询后成功，
输出 1920×1080；标为 720p 的产物也成功输出 1280×720，但缺少请求字段快照，不能进入精确合同。
`seedance-2-0-oversea` 认证预检仍为 401；doubao 的素材场景、高分辨率本站 E2E、`duration=-1`、
音频开关和 Provider 实际账单仍未闭合。

## 5. 发布不变量

1. 任一当前 V2 模型通过不代表另一个当前模型、历史 Ark 模型或 Ark 素材/H5 合同通过。
2. 官方营销描述、价格表和示例不能代替字段与账单黑盒。
3. 任一未决默认值、结果、usage 或素材作用域保持未发布。
4. 代码注册、渠道启用、publication 和生产开放是四个不同阶段。
5. 发布门禁不触碰 NEWAPI 原生 OpenAI Videos 路径与语义。
