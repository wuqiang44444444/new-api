# 墨行上线证据与验证矩阵

## 1. 责任边界

系统不建立 publication/capability/implementation 自动门禁。技术人员在线下确认协议、字段、Task、
素材、计费和账单证据，再通知管理员启用对应的独立客户模型和 Channel。

保存/启用时系统只校验 Seedance 客户模型不与其他已启用 Seedance Channel 重名，以及必要 Channel
字段完整。真实兼容性和上线批准不由运行时推断。

## 2. 当前结论

| 线路 | 当前证据 | 结论 |
| --- | --- | --- |
| oversea | www 与裸域名认证预检均 401 | 更换有效 Key 并完成付费黑盒前禁用 |
| doubao | 480p 本站 E2E、1080p 直连成功；无 usage；素材/账单未闭合 | 保持禁用，补齐缺口 |
| 历史 Ark | 素材/H5 证据已失效 | 不新建 Channel 或 Asset |

## 3. 技术人员验收

- 独立客户模型、Channel、Key、Base URL、模型映射和价格；
- duration `4..15/-1`、允许分辨率/比例、文本与图片组合；
- `generate_audio` 显式 false/true 和未开放字段拒绝；
- 一次 Provider POST、正常 task ID、断连/超时/坏 JSON 的 unknown；
- 查询状态、任务 ID 一致性、成功内容、HTTPS、Range 和 URL 生命周期；
- 客户预扣/结算/退款、Provider 成本证据和 exposure 分账；
- 若开放素材：一对一 Asset/AssetGroup、账号作用域、Key 轮换、删除和视频引用；
- SQLite、MySQL、PostgreSQL 的 attempt、Task、计费和素材事实。

## 4. 上线不变量

1. 任一线路通过不代表另一线路或历史 Ark 通过。
2. 营销描述、价格表和示例不能替代真实字段与账单黑盒。
3. 启用前由技术人员明确给出管理员配置，不建立自动认证系统。
4. 两条线路不共用客户模型，也不使用 Priority/Weight/fallback。
5. 代码存在不等于生产开放。
