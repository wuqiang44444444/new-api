# 音视频请求证据架构

## 边界与目标

媒体请求证据为客服与运维提供"客户请求、履约选择、南向发送、上游响应、轮询观察、
结果交付"的事实记录。证据只描述发生过的事实，不是任务状态、资金或重放许可的第二事实源；
不得为补日志自动重发、换渠、退款或改写任务结果。

当前处理原则是：有界捕获的正文直接保存，目录查询只读定位信息，选中单条内容后才读取对象；
正文 JSON 的解析与美化由查看者主动触发。这里的“直接保存”仍包含元数据序列化、加密和持久化，
不代表没有数据库、内存复制或文件 I/O 成本，也不代表全部采集路径都已异步化。

## 职责与事实源

| 职责 | 权威实现 | 边界 |
| --- | --- | --- |
| 媒体范围、实际交换观察与任务去重 | [通用观察器](../../service/api_request_evidence.go)、[Task 会话](../../service/task_request_evidence_capture.go) | 只观察已接入的实际 I/O，不改变路由或 Provider 语义 |
| 任务查询归属 | [媒体查询关联](../../service/media_evidence_queries.go) | 按鉴权用户/应用关联已有媒体任务，不因批量查询开启新保留窗口 |
| 正文对象封装与保存 | [原始对象保存](../../service/task_request_evidence_raw.go) | `persistRawEvidenceEvent` 是正文保存入口；无正文事件只写最小事件行 |
| 加密、不可覆盖发布与读取 | [对象存储](../../service/task_request_evidence_store.go) | 对象位于独立私有命名空间，不复用正式结果或恢复输入 |
| 索引、事件与清理围栏 | [证据模型](../../model/task_request_evidence.go)、[对象发布守卫](../../model/task_request_evidence_cleanup.go) | 主库保存关联与期限；原文及敏感元数据只在加密对象内 |
| 目录、单条内容和下载 | [查询 Controller](../../controller/task_request_evidence_query.go)、[读取服务](../../service/task_request_evidence_helpers.go) | 目录不触发正文读取；单条查看与下载分别发起审计 |
| 展示与主动格式化 | [原文弹窗](../../web/src/features/usage-logs/components/evidence-original-dialog.tsx) | 默认显示 raw；JSON 美化仅改变展示，不回写对象 |

## 数据与控制流

- 主库索引：`task_request_evidences`（请求、用户/应用、Task/attempt 关联、协议事实、保留期、
  正文过期标记）+ `task_request_evidence_events`（内容名称、交换序号、对象定位、HTTP 元数据）+
  `task_request_evidence_access_logs`（查看/下载审计）。
- 私有对象：正文（北向/南向/上游响应）进入独立命名空间的加密对象存储（一期本地 AES-256-GCM
  目录实现，接口为 `TaskRequestEvidenceObjectStore`）。加密密钥显式配置优先，未配置时从
  CRYPTO_SECRET/SESSION_SECRET 派生（派生密钥随宿主密钥轮换失效，读取得到明确解密失败）。
  已捕获凭据、签名 URL 与素材源 URL 可随原文进入受保护对象，不进入事件行或普通日志。
- 采集点（全部为窄调用）：
  - ModelArk 转换前、`executeTaskSubmissionWith`（其他任务类）与 `AudioHelper`（音频类）建立证据会话，
    有界保存北向原文；采集、索引和存储故障均只停止对应观察，不拒绝业务。
  - `doRequest` 发送前接入南向正文观察器并独立核对 durable sending 许可；正文随实际读取有界捕获，
    请求体关闭时尽力保存。上游响应在协议解析前边读取边捕获，关闭时保存已有字节。
  - Seedance HTTP 返回边界在归一化前捕获原始轮询；其他 adapter 在 `task_polling` 正文读取点追加证据。
  - Task 会话在外层响应呈现结束记录客户 JSON/文本响应；其它内容类型只写交付事件。
    通用内容代理同样不留存媒体交付正文；传输层的实际写出统计不等于新事件维护正文长度。
  - 动态插件内层 Gin 复用外层观察器，由已鉴权的内层上下文完成任务去重及查询绑定；
    外层跳过已完成记录，不生成应用事实缺失的副本。
  - 范围外内容代理继续记录状态与实际写出字节；Link 托管结果入口返回 302，网关不再传输视频
    正文，其响应写出不代表客户已经从 OSS 下载。OSS 实际下载字节属于对象存储侧事实。

## 保存与读取的处理边界

| 阶段 | 当前处理 | 正文 JSON 解析 |
| --- | --- | --- |
| 采集 | 随实际读取或写出有界复制字节；Task 北向从已有正文缓存读取 | 通用捕获不解析、不改写正文 |
| 保存 | 建立最小事件行，序列化交换元数据，拼接正文，加密并写入不可覆盖对象 | 不解析正文；元数据使用 `common.Marshal` |
| 目录查询 | 查询索引和事件，返回名称、序号及 HTTP 定位信息 | 不读对象、不解密、不生成预览 |
| 单条查看 | 解密选中对象，拆分并解析对象元数据；正文按 UTF-8 文本或 Base64 返回 | 服务端不解析正文 JSON |
| JSON 美化 | 查看者点击 `Format JSON` 后在浏览器解析并缩进显示 | 仅此展示操作解析正文；失败继续显示 raw |
| 下载 | 解密并返回完整已存对象，包括 v2 标记和元数据 | 不拆分对象，不解析正文 JSON |

任务归属是明确的采集期解析例外：MJ 创建从已捕获客户响应中解析 `result`，MJ POST 查询与
Suno POST 批量查询从已捕获请求中解析 `ids`。这些解析用于关联证据索引，不参与通用正文保存、
脱敏或预览；不能把当前实现概括成“整个证据系统只在读取时解析 JSON”。业务处理器自身的请求
校验、Provider 协议解析也仍由各自链路负责。

保存调用仍可能等待数据库、加密和文件写入。文件 worker 最多八个，槽位等待和写入等待共用
配置超时；超时不强制取消底层文件系统操作，晚到对象仍须经过清理围栏。此边界说明已移除
通用保存路径的正文解析和预览计算，不能代替真实流量下的吞吐、延迟或磁盘容量验收。

## 原始对象与保存不变量

- 创建响应的上游请求追踪 ID 由 HTTP 响应边界统一提取与校验，Task 和证据索引复用同一结果。
  索引反映当前请求最后一次响应；后续响应未提供可用 ID 时清空前次值，不把旧尝试的 ID 冒充最终响应。
  平台请求 ID、Provider 任务 ID、创建请求追踪 ID 分别保留其身份，不互相填充，也不把创建追踪 ID
  标为失败轮询的追踪 ID。错误日志中的“查看任务”按公开 Task ID 定位既有任务页面，Provider 任务 ID
  继续仅在任务详情的 Root 视图显示。
- 对象键使用数据库事件 ID；先建立最小事件行，再写不可覆盖对象。新事件不写 phase、complete、
  redacted、字节统计、正文摘要或 detail。历史列仅支持期限内的既有对象读取，不继续旧写入。
- 新对象格式为 `new-api/evidence-v2` 标记行、单行元数据 JSON、其余原始正文字节。头、查询参数、
  读取错误仅在加密对象内；正文不做 JSON/SSE/multipart 解析、正则扫描、URL 替换或重新编码。
- 历史对象按既有负载读取，不重写、不补造已脱敏内容；既有事件携带正文摘要时在读取侧校验。
  单条查看优先拆分 v2 元数据；无法拆分时保留原负载，历史事件 Detail 仅在读取时尽力解析。
- 捕获上限只限制留存字节；超限、中断和格式错误均可保留已有前缀，不为每条内容判断完整性。
  证据不是业务输入校验器。独立 HTTP 错误诊断快照继续使用既有脱敏规则，不复制原始证据。
- 正文保存入口为 `persistRawEvidenceEvent`，通用观察器、Task 会话、轮询和图片观察器共用它。
  证据故障不改变业务响应、发送次数、Task 或资金。发送许可无法核实时仍按既有 unknown 语义阻止发送。

### 视频创建响应的最终写出边界

`TaskCreateResponseContract` 在内部响应缓冲器之外接入
[交付观察器](../../service/task_create_evidence_delivery.go)。内部 Relay 写入缓冲器，外层呈现器
完成公开成功／错误响应投影后，只有实际写给下游 writer 的字节进入 `client_delivery`。

该呈现器接管交付采集时，Task 会话只建立索引与北向原文，不再叠加内部交付 writer；内层结束调用
不提前保存正文。呈现器完成最终写出后才释放交付采集所有权，复用既有保存入口生成一条交付事件。
业务的 `server_written`／`write_failed` 观察先于可选证据落盘，不等待证据数据库或文件 I/O。
未经过该呈现器的普通媒体入口继续由原有 Task writer 结束采集；通用观察器不另存相同交付正文。

成功响应、合同错误重投影和未重投影错误均按实际写出内容留存。断连或短写只保存下游 writer
接受的前缀，错误放入私有加密元数据；采集上限只限制保留字节，不限制业务响应。证据开关或存储
故障不改变公开响应、业务状态、发送次数和资金观察；正文不增加 JSON 解析、格式化或脱敏步骤。
这里记录的是服务端写出观察，仍不能证明客户端完整收到或读取正文。

历史已保存的内部响应对象不覆盖、不修写，也不根据内部字段重建最终北向正文。HTTP 错误诊断
快照的延迟处理保持独立；不能为修复证据而重新发送生成请求。

## 配置与采集开关

- `TASK_REQUEST_EVIDENCE_ENABLED` 默认 `false`：只有显式 `true` 开启；未配置或其它值都不采集，
  单独提供加密密钥不产生采集资格。显式开启后仅采集已登记图片、音频、视频及素材操作；
  早期方案的 `TASK_REQUEST_EVIDENCE_TYPES` 已移除，不提供 `all` 别名或并行模式。
- `TASK_REQUEST_EVIDENCE_RETENTION_DAYS` 只允许整数 1～7，默认 `7`；不再支持 `0` 永久保留或
  超过七天。非法配置在加载期明确报错；配置或存储装配故障不改变业务受理、发送和资金结果。
- 存储读取、删除与过期清理和采集开关解耦：关闭采集只停止新增正文，历史读取、七天回收与
  Root 手动清理继续；存储装配不创建目录，无历史对象时清理不产生对象目录。

## 清理申请与观察窗口

- Root 手动清理入口 `POST /api/system-task/evidence-cleanup`（JSON `target_timestamp`）：
  截止时间必须为有效正整数且不晚于当前时间，等于截止点的记录保留；操作者取自已鉴权身份。
  已有清理任务运行时返回明确忙碌及当前任务信息，不修改正在运行的范围。
- 手动提前清理依赖索引上的持久清理申请标记（`cleanup_requested_at`）：申请落库后读取与追加
  立即关闭。手动受理将 SystemTask 与当前 `created_at < target_timestamp` 范围的申请标记在同一
  事务提交，忙碌或事务失败不改变范围。取消、重启及扫描前失败后，自动任务仍可按已接受标记重试。
  对象全部删除成功且空目录回收成功后才写“正文已过期”完成事实；失败重试保持已接受范围，
  不会被七天筛选漏掉。这只是证据清理状态，不是任务或资金状态机。

## 故障与业务隔离

- 正常到期、已接受手动清理或索引已删除表示观察窗口结束。数据库、加密和存储故障也只影响
  对应证据，不拒绝或重试业务，不触发退款；存储继续使用现有并发槽位与有界等待。
- durable attempt 的 sending/held 发送资格独立于证据会话、索引或存储是否存在。恢复已接管、unknown
  或资格查询失败时保持禁止发送与禁止基于过期本地状态退款的原有边界。
- 无 attempt 的音频路径（TTS/转写/翻译）按平台请求 ID 建立证据，不创建伪视频 Task。
- 崩溃窗口语义不变：hold/sending 后、发送前崩溃仍按 unknown 保守处理；不凭证据缺失退款或重发。

## 按需读取与访问审计

- 权限：Admin/Root 查看内容目录，并显式选择 `/events/:event_id/content` 读取单条正文与元数据，
  或 `/events/:event_id/object` 下载完整已存对象。普通用户无权访问；整个路由组禁止缓存。
- 详情只返回内容名称、序号、HTTP 状态、方法、净化目标、类型和时间，不读取对象或返回自动预览。
  事件 ID 即可定位新对象，不用 object_key 非空判断正文是否存在。缺失、到期、解密及读取故障在
  选中读取时分别返回。正文 UTF-8 文本原样返回，二进制以 Base64 交付展示层；解析失败不妨碍下载。
- 目录、原文查看、下载分别发起 `view/directory`、`view/original`、`download/original` 审计；
  审计沿用尽力写入，失败输出净化系统错误，不改变交付，也不宣称审计一定落库。
- 任务日志和带平台请求 ID 的消费日志详情按需加载证据；错误日志只要具备关联 ID 即可展开查询，
  不按事件类型猜测是否采集，有 HTTP 快照也可查询。任务失败优先仅按任务 ID 查询，无任务 ID 时
  按请求 ID；普通请求错误按请求 ID。无记录、过期与读取失败分别展示；统一说明捕获可能不完整，
  不恢复历史缺失正文。
  无快照任务失败事件不展示空 HTTP 正文区块。错误码与失败原因独立展示，不向错误事件复制正文。
- 证据索引计数或列表查询失败返回失败响应，不包装为成功空列表；页面显示加载失败并支持重试。
  “查看任务”的显式零起始时间保持为零，不触发默认当天范围，历史任务与跨日任务仍按 Task ID 查询。
- 原文弹窗共用于错误、任务和使用日志；任务两个快捷入口先按内容名称列出位置，再选择单条读取。
  默认显示 raw，可主动格式化合法 JSON 或预览受支持的位图；原文作为数据展示，不执行 HTML、SVG
  或脚本，不自动访问正文内的远程 URL。格式化不修改对象，数字精度以 raw 为准。
  关闭、切换记录、角色或登录身份时取消查询并清除原文缓存，不将原文保存到浏览器持久化存储。

## 保留期与清理一致性

所有格式的已捕获字节原样保存；结构化正文无法解析或被截断不改变其读取与下载资格。
存量任务首次轮询或结果交付时可按可信创建时间补建索引；复用同一保留期限计算规则并写入到期时间，
不因首次观察较晚而延长窗口。

- 正文和事件明细按 `TASK_REQUEST_EVIDENCE_RETENTION_DAYS`（1～7，默认 7）回收；索引最多
  保留七天，访问审计按访问时间独立保留七天；证据清理/监控两类系统任务历史保留三十天，
  活动任务及各类型最新调度行不删。其他 SystemTask、正式产物、输入、Task 与资金事实独立。
- 有效正文期限取“索引创建时间 + 当前配置天数”与原有非零更早期限中的较早值；历史零期限
  同样有上限，恰好到期不算超期。后台依据可信 `Task.CreatedAt` 建立固定窗口，复用同一索引。
  已关闭索引拒绝新增事件与正文；索引删除后过期 Task 也不得重新按当前时间建证据。
  缺少可靠创建时间时跳过取证并输出净化诊断，不从可由轮询改写的 SubmitTime 推断新期限。
- 原生 MJ 的 SubmitTime 会被通知改写，TokenId 属于计费退款事实。其证据窗口仅由新创建请求
  的开始时间及已鉴权用户/应用建立；单项和批量查询复用既有索引，不用这两个原生字段补建。
  已关闭、超期、删除或历史缺少创建锚点时停止取证，保留原生查询与交付行为。
- 事件预留在主库短事务中锁定索引并检查存在、关闭与期限；最终对象发布使用同一索引锁。
  SQLite 取得写锁，MySQL/PostgreSQL 使用 `lockForUpdate`。加密、暂存和文件 fsync 在事务外。
  无正文的传输和交付事件也走守卫；新对象不回写完成状态，不复活已删除事件。
- `task_request_evidence_retention` 每小时运行，无关闭开关。先持久申请关闭读写，事件按主键
  分页定位对象；文件全部回收且目录安全处理后标记 BodyExpired，再短事务分批删除明细。
  数据库扫描包含 BodyExpired 行，崩溃和部分删除后可继续。索引到七天且无事件后物理删除；
  手动提前清理或缩短正文期限时保留最小关闭索引至七天，不建立永久墓碑。
- 历史已完成正文行和孤儿事件同样先确认对象删除，再删除定位记录。缺失对象幂等且单独计数，
  已关闭命名空间中的无事件匹配正文和暂存也回收。无索引的纯文件孤儿按文件修改时间
  执行当前期限或 Root 显式截止；不跟随目录符号链接，不递归删除根目录，不在应用内自动 VACUUM。

## 错误归属与公开响应

`TaskRequestEvidenceError` 仅承载 durable sending 资格无法核实的拒绝，保留既有
`send_unverifiable` 和 unknown/资金处理语义。证据存储、采集上限或内容格式不再生成客户拒绝。
客户请求校验、正式结果存储、恢复输入与账务仍由各自业务链路负责。普通诊断经
`SanitizeTaskDiagnostic` 净化，不输出原始正文或对象元数据。

## 覆盖边界（媒体操作）

方法与已登记业务路径表达前台媒体操作；后台依据冻结 Task 协议、执行来源和媒体类型判定，
不猜模型名、价格或空模型字段。纳入图片生成/编辑、音频 speech/transcriptions/translations、
视频、MJ、Kling、Jimeng、音乐生成与媒体素材。通用任务查询仅在已鉴权 Task 为媒体时采集。
普通聊天、Responses、Gemini 通用多模态、Embedding、Rerank、Batch/通用文件、模型列表以及
纯歌词排除；素材 source URL 只可随原文进入受保护证据，不进入普通业务字段或日志。成功、失败与本地拒绝均保留实际信息。
管理、登录、静态、健康及证据查询/维护不产生业务证据。已接入交换以实际 I/O 为准，不宣称
任意 WebSocket 全量帧归档。

MJ 精确匹配已登记业务操作和可选 mode 前缀，管理列表与未知操作排除。Suno 大小写等价的
纯歌词操作及对应任务查询排除。通用任务提交 `/v1/tasks/:key` 只作为候选：依据准备阶段
已固定的插件图片/视频协议或明确 MUSIC 操作建立会话；文本插件不产生持久证据。索引冻结
通用创建的媒体资格，后台使用已有索引与 Task 时间，不查当前插件注册表重新解释旧任务。

通用观察器与任务证据按实际交换声明阶段归属：北向及客户交付由有效任务索引持有；任务南向正文
观察器只声明第一个 HTTP 交换，重定向继续独立观察；任务响应包装器只接管其实际
响应对象。未被接管的 HTTP、握手、Realtime 帧继续追加到同一索引。会话初始化失败仍记录实际客户
拒绝响应；不以“会话存在”丢弃所有观察结果，也不新建重复索引。

## 覆盖矩阵与验证边界

| 路径／协议 | 已接入的观察点 | 有界或尚未接入的部分 |
| --- | --- | --- |
| 图片、音频、视频专用 HTTP | 客户请求/交付、绑定上下文的南向请求/响应，成功与拒绝均观察 | 只记录实际接收且容量内的内容；未绑定上下文的独立客户端交换不伪造 |
| SSE | 实际转发片段、捕获错误与 HTTP 状态 | 不把 SSE 业务失败反推为 HTTP 错误 |
| 视频与 HTTP 音频任务 | 北向、履约、南向、响应、既有轮询与交付 | 超期/提前申请后不续期、不追加正文；媒体内容代理只写交付事件，不留存视频正文 |
| Realtime 音频 WebSocket | 已接入的握手与客户端帧观察；显式调用观察器的南向帧 | 不保证任意 WebSocket 帧的全量归档；限额及 EOF 边界照常生效 |
| 讯飞 WebSocket | 握手、已显式接入的发送/响应帧、客户交付 | 仅实际取得的消息，无法取得的帧不补造 |
| Volcengine 独立 TTS WebSocket | 握手与客户交付 | 独立二进制帧未逐帧接入，不宣称完整帧归档 |
| MJ、Kling、Jimeng 等业务 HTTP 入口 | 北向与交付；已绑定观察载体的上游交换 | MJ 自建后台 context 等未绑定交换仍是南向覆盖缺口 |
| 后台媒体 Task | `BeginBackgroundRequestEvidence` 及已接入的实际交换；固定期限复用索引 | 后台执行记录不补造此前客户上传正文；不把必要输入对象作为证据副本删除 |
| 通用媒体任务提交 | 已固定插件声明媒体协议后记录创建与拒绝，复用已有会话和去重 | 不按模型名推断；无已冻结媒体依据的历史通用任务不补建 |
| MJ 单项与批量查询 | 按鉴权用户/应用复用创建证据索引 | 无创建锚点、已关闭或过期不重建；未鉴权公共图片交付不补建证据 |
| Link 素材 | 业务交换观察，原文进入私有加密证据 | source URL 不进入普通业务字段和日志；不建立额外素材索引 |
| 管理、登录、静态、健康、证据查询与清理接口 | 排除正文采集 | 不为自身查询、维护操作再创建业务正文 |

这些是当前代码接线事实，不代表真实 Provider 的生产验收。普通协议回归、真实任务接管/未接管交换、
本地拒绝和阶段去重各自验证；未接入路径仍明确列为缺口，不以媒体开关声称所有帧已保存。

## 清理可观察性

Root 日志维护页面使用既有日期与确认组件，并通过当前任务和历史结果恢复进度/结果；完成或失败后
可继续查看删除、缺失、失败、未归属文件、对象移除字节及删除事件/索引/审计/历史行数。系统任务历史提供同一结果的详情入口。

事件、索引、孤儿事件、访问审计和证据任务历史按删除批次持久化实际累计进度；数据库阶段
运行中即可读取计数。进度更新校验既有任务租约，失去租约后停止执行，不写他人的终态。

`task_request_evidence_monitor` 每十五分钟独立检查主库清理事实，避免清理任务自身卡住时失去观察。
结果包含最近成功时间、最多两次连续失败、正文与数据库待清理数量/最旧创建时间、所在文件系统可用字节与 inode。
连续两次失败、两小时无成功、相关积压、磁盘使用达到既有阈值、inode 使用达到 95% 时发出净化
后端告警，并在 Root 页面及历史中展示类别。平台不支持 inode 统计时保持未知，不报告虚假的零余量。
告警仅包含类别与统计，不输出正文、存储路径、凭据或 Provider 原始响应。

## 变更性质与上游同步边界

证据属于本地观察能力，采集、存储、查询和清理主体位于独立 evidence 文件中。NEWAPI 原生
请求、发送、轮询和响应边界只接入观察调用或包装器；业务校验、路由、Provider 转换、任务和计费
继续由原链路负责。未来接取上游时应核对这些实际 I/O 接线及上下文传播，避免重复包装、漏采或
把取证成功作为发送前提。durable attempt 发送许可是独立业务守卫，不随取证开关或存储状态取消。
