# 业务请求证据架构

## 边界与不变量

显式开启后，证据覆盖已登记业务 API 的实际输入输出，包括聊天、Responses、Gemini、Embedding、
Rerank、模型列表、歌词、Batch 控制交换以及图片、音频、视频、素材。管理、登录、静态、健康、
证据自身接口与基础设施文件搬运排除。范围由方法、业务路径和外层协议元数据确定，不从模型名推断。已登记插件入口由内层
Gin 引擎的实际路由匹配与 relay 标签确定资格，不维护 Provider 前缀副本；未匹配的插件路径不采集。
权威规则见[硬约束第六节](../00-context/硬约束.md)。

证据只描述实际发生的 I/O，不是 Task、资金、发送许可或请求重放的事实源。取证故障只损失证据，
不改变业务响应、Provider 调用次数、重试、Task、结算或退款。durable sending 许可仍独立校验。
不为补证据提前读、重复读、拒绝后补读输入，或在业务停止后继续消费上游。证据是非核心、尽力
保存的数据，允许正常停机、重启和故障时损失未封存内容；进程退出不增加证据专用等待、封存或补记。

## 唯一保存路径与职责

```text
业务实际 Read/Write 或已有 WebSocket 消息
  → 方法/路径/外层类型确定正文资格
  → 有界字节块非阻塞交接
  → 独立窗口索引与事件预留
  → 私有流式认证加密暂存
  → 清理围栏内不可覆盖发布
```

| 职责 | 权威实现 | 边界 |
| --- | --- | --- |
| 范围与文件排除 | [范围](../../service/media_evidence_scope.go)、[观察器](../../service/api_request_evidence.go) | 不解释正文；上传请求与普通响应独立判断 |
| 固定资源与顺序写入 | [捕获](../../service/image_error_evidence.go)、[worker](../../service/request_evidence_runtime.go) | 非阻塞交接，资源不足停止该对象，不接续后缀 |
| 流式加密与发布 | [存储](../../service/task_request_evidence_stream_store.go) | 暂存始终加密，事件位置不可覆盖 |
| Task 事实与发送许可 | [会话](../../service/task_request_evidence_capture.go)、[发送守卫](../../service/task_request_evidence_attempt.go) | 会话附加已有事实，不重读 BodyStorage |
| 已知批量任务关联 | [关联表](../../model/task_request_evidence_links.go)、[轮询](../../service/api_request_evidence_polling.go) | 一次物理交换只保存一次，可信 Task 列表建立最小关联 |
| 保留与清理 | [生命周期](../../model/task_request_evidence_lifecycle.go)、[清理](../../controller/system_task_evidence_cleanup.go) | 锁定窗口后删对象、事件、索引与关联，不触碰业务数据 |
| 磁盘高水位 | [监测](../../service/request_evidence_disk.go) | 每五秒采样所在文件系统，超过 90% 暂停写入并申请一天规则清理 |
| 授权读取 | [读取](../../service/task_request_evidence_stream_read.go)、[Controller](../../controller/task_request_evidence_query.go) | 目录不读对象，查看有界，下载顺序解密 |

Task 会话、图片查询、媒体交付和插件内层 engine 复用同一载体，不维护第二套正文缓存。
通用任务查询与制品列表在授权取得 Task 后附加真实 TaskID；图片查询不叠加 writer，媒体下载不再
计数或另建证据窗口。正文资格在原始路径仍可用时冻结；文件交付不因返回 JSON/文本类型而进入采集。最终创建响应在
`TaskCreateResponseContract` 内部缓冲器之外观察，保存公开投影实际写出的字节，不另存内部响应。
短写仅捕获 writer 接受的前缀；写失败的完整接受情况仍不能证明客户端实际收到内容。业务交付状态
独立于可选证据；事件预留可异步发生，交付对象在实际写出和观察结束后封存。

同步图片处理器将刚读完的上游正文原样交给客户端 writer，且 writer 无错误接受全部字节时，
`upstream_response` 保存正文，`client_delivery` 保存自己的加密元数据和同一证据窗口内的上游事件引用。
此判断使用转发代码已知的字节来源和实际写入结果。格式转换、短写、写入失败或上游正文跨窗口时，
各阶段沿用独立采集。上游对象成功发布后才发布交付引用。共享后的后续写入单独记录。

## 零正文解析与文件边界

证据采集与保存不解析 JSON、SSE、multipart、JSONL，不格式化、扫描、转码、压缩、解压或计算正文去重摘要。
格式错误、重复字段、空白和大普通正文按实际字节保存，不设置正文长度截断阈值。业务校验、Provider
协议解析及计费所需的解析仍由原链路负责。保存所需的小型元数据编码与认证加密属于必要封装。

- multipart、明确文件上传（包括文件接口与 MJ 上传）、媒体类型、octet-stream、JSONL/NDJSON、PDF、
  attachment 和文件内容下载方向在第一次复制前旁路，只留最小事件。上传的普通 JSON 响应仍保存。
- Batch 输入/结果、私有 OSS、受保护 URL 回源和恢复输入读取不因继承 context 自动采集。业务文件
  仍按独立的业务存储合同处理，本证据清理不删除它们。
- 图片/视频 URL 随所在原始 JSON 保存，不解析提取、不解引用下载媒体；媒体回源及对象存储搬运
  明确旁路取证。已有视频托管交付的业务对象与证据存储独立。
- 普通 JSON 中可能嵌入 Base64/Data URL；不扫描或解码，也不按大小猜测文件，因此这些字节仍随
  普通 JSON 保存。“排除文件”只指采集前可从操作或外层类型明确判定的文件传输。
- SSE 保留实际字节；已接入的 OpenAI Realtime、Responses WebSocket 和讯飞消息按消息边界、类型和
  方向保存文本，二进制消息只留元数据，不增加 `data:` 包装。每连接、每方向复用一个记录，按十五秒
  片段或连接结束封存，复用现有 worker 的一秒 tick；实际可见时间受调度和盘写影响。不是任意
  WebSocket wire 帧归档。讯飞请求只编码一次，保留原 WriteJSON 的末尾换行并复用实际发送字节
  留证；读取侧使用实际消息类型，不按 Provider 通常返回文本的假设改变二进制旁路规则。
- MJ/Suno 不再解析证据正文中的 result/ids 建关联；没有业务现成 Task 列表的调用按平台 RequestID
  查询，不猜任务归属。单 Task 使用已有 TaskID，批量轮询仅用调用方传入的可信列表。

## 有界内存与故障退让

四个固定 worker 按块调度，同对象绑定同一 worker 保序；不让空闲长连接独占 worker。64 KiB 块的
全局预算为 1024 块（64 MiB），活动记录与流式对象分别最多 512，单对象外层头最多复制 64 KiB，
序列化存储元数据小于 128 KiB。SIO 内部缓冲、元数据和网络层自身内存不包含在 64 MiB 块预算中。
读取最多八个并发，查看只取前 64 KiB；内存不随新对象整份正文长度增长。

WebSocket 同一方向的相邻片段在异步交接期间共享一个对象预算；有序 worker 先封存已处理完的
前段，再打开后段，避免切段瞬间重复申请预算导致正常容量缺证据。队列正文仍受全局块预算约束。
无正文 HTTP 握手立即释放请求记录；上游握手前更新一次身份，后续不逐消息读取 Gin 身份。

队列、块或对象预算不足、磁盘压力、数据库和存储故障时，停止该对象观察并回收资源，不等待盘写，
不重新分配无限队列、不逐块打印错误。客户交付首次申请失败后保持已放弃状态，后续 Write 不重新
申请、不保存响应后缀；头仅在取得记录预算后复制，文件事件不复制原始头或查询串。加密失败的暂存尽力删除，异常残留由原有清理回收。聚合
accepted/written/failed/dropped 和活动资源由健康信息报告。身份在第一次正文读取时观察，最终事实在请求结束回填；不对每个 Read/Write 重复读取 Gin 身份键。
正常容量保存完整实际消费/写出字节，
故障下不承诺绝不缺证据。异步写入改变等待位置，不消除加密、落盘和扩大采集范围的总 CPU 成本。

## 加密格式与历史读取

主库保存 `task_request_evidences`、`task_request_evidence_events`、访问审计和 `evidence_task_links`。
TaskID 查询分别通过直接关联和批量关联的 TaskID 索引生成候选 ID，UNION 去重后统一过滤、计数与
分页，避免每条窗口执行相关子查询；关联表索引仍由 GORM 迁移，支持数据库表名前缀。
原始头、RawQuery、错误和正文只在独立私有命名空间中加密保存；目录中的 Target 去掉查询串和用户
信息。平台 ID、Provider Task ID 与创建追踪 ID 不混用；最终响应没有可信追踪 ID 时清空前次值。

新密文标记为 `NEVSIO3\n`，使用固定 `github.com/minio/sio v0.5.1` DARE v2 流式 AEAD，验证块序号、
认证与最终包边界；每个不可变对象路径通过 HMAC-SHA256 从稳定主密钥派生独立密钥，防止跨事件
替换。nonce 随机性、包序号和结束认证由 SIO 实现。解密负载仍为 `new-api/evidence-v2` 标记行、
单行元数据 JSON 和原始字节。元数据只解释存储封装，不解释业务正文。

同步图片交付引用使用独立认证的对象标记、同窗口源事件 ID 和该次交付的元数据封装。读取时在同一窗口
打开源正文，并将交付元数据与正文拼成原有查看和下载格式。源对象缺失时返回正文不可用。清理按整个
窗口回收两个事件和文件。旧版本读取器无法打开新引用对象。

对象先在事件命名空间中加密暂存，结束后完成认证、文件 fsync，并在主库窗口锁守卫下通过硬链接
不可覆盖发布，再同步目录。中断暂存不可由事件下载接口读取。数据库和文件系统不是同一事务，
崩溃可能留下缺失位置或孤儿暂存；按清理队列恢复，不据此重放业务。历史 AES-GCM 对象只读，不
重写、不双写；历史带摘要事件继续在读取侧核验。旧 AES-GCM 必须整份认证：读取前检查密文上限为
32 MiB + 128 KiB（含封装余量），使用一个独立非阻塞槽位并原地解密，直到关闭 reader 才释放；
超限或忙时返回 `storage_unavailable`，不改写对象，不进行迁移。预览统一经过八个共享读取槽位，
只保留前 64 KiB；旧摘要通过顺序扫描剩余字节核验，不再为预览复制整份明文。新 SIO 对象不受旧格式
大小上限约束，仍流式下载大正文。

## 独立窗口与两天清理

每次前台请求或后台执行周期建立独立窗口；长连接每小时封存并滚动，空闲已有片段也由 worker tick
封存。窗口期限按自身开始时间起算，正常默认两天，可配置 1～2 天；历史更早非零期限仍优先。
旧 Task 第五十小时的新轮询仍可形成新窗口，清理旧窗口不延长旧证据，也不关闭未来新交换。

事件预留与最终对象发布共用主库窗口锁。MySQL/PostgreSQL 使用 `lockForUpdate`，SQLite 使用写锁。
清理申请一旦提交，窗口立即禁止授权读取、新事件预留与最终发布。暂存创建后、写入前再读一次
窗口，已经关闭或删除则立即中止并尽力移除空目录；不增加逐块/逐消息查库或额外事务。已有暂存
可能继续接受已观察字节直到片段结束，但不能通过最终发布守卫；清理删除后打开的句柄可能延迟
空间释放，受既有分段与磁盘压力退让约束。文件全部删除后标记完成，分批删除事件、索引
及关联。关闭索引没有固定七天墓碑；没有事件的已关闭窗口也进入恢复队列。访问审计从访问起保留
七天，证据清理/监控任务历史三十天，活动与各类型最新调度行保留。

每小时自动清理与 Root 手动任务继续复用现有 SystemTask。手动 cutoff 固定持久化，严格删除开始时间
早于 cutoff 的窗口，等于 cutoff 保留。取消或重启不会撤销已提交的关闭申请；失败保留定位并重试。
无索引文件孤儿按修改时间及相同期限清理，不跟随符号链接，不删除业务对象，不自动 VACUUM。
根目录与单窗口文件使用 256 项批次迭代，不将全部文件名载入内存；每批目录 ID 一次查库排除仍存活
窗口，不逐目录查库。进度按批持久化；全量遍历总工作仍随文件数增长，不在业务请求线程执行。

磁盘采样独立于采集开关和可选性能监控。首次观察使用率大于 90% 时立即暂停新记录及在途证据写入，
申请 `trigger=disk_pressure`、固定 `now−86400` cutoff 的同类型清理任务并唤醒 runner；高位时最多
每分钟申请一次，与已有清理互斥。已有手动任务不改范围，完成后下一次采样再申请。低于或等于
90% 恢复未来采集，关闭或中止的对象不恢复。五秒为采样周期，实际清理完成时间还受调度、主节点、
磁盘和存量影响；一天内数据不因压力被提前删除。

WebSocket 每方向的十五秒片段只建立一个事件和加密对象，片段仍执行事件预留、清理围栏内发布与
文件/目录同步。正文按消息流式追加，不积攒十五秒消息数组；内存沿用现有块和对象预算，不增加连接
worker、逐消息数据库行或持久消息索引。正常 HTTP 保持既有保存粒度。

WS 片段元数据 `body_format=websocket-segment-v1`；正文是重复的固定 32 字节大端消息头与负载：

| 字节偏移 | 字段 |
| --- | --- |
| 0—3 | 有符号 int32 消息类型 |
| 4—7 | uint32 错误元数据长度 |
| 8—15 | uint64 Unix 毫秒时间 |
| 16—23 | uint64 原始消息字节数 |
| 24—31 | uint64 已保存正文字节数，二进制消息为零 |
| 32 起 | 错误 UTF-8 字节，再接未经改写的正文，随后是下一条消息头 |

消息头、错误与正文在同一记录锁内追加，封存不能切在一条消息中间；资源不足时废弃整个未发布
片段，不发布断裂边界、不接续后缀。单条普通大消息不按长度截断，可能延后该段封存。二进制消息
只保存类型、时间、原始大小等元数据。读取时按长度拆分，换行、重复 JSON、空消息和非法 JSON
均不会改变边界；仅为展示返回片段内字节 offset，不建立持久消息索引。

每个方向记录持续占用现有活动记录预算，空闲封存后释放对象与块；全局 512 记录/对象上限仍可能
限制并发长连接；双向代理通常有四个采集方向，不能把 512 当作可完整采集的连接数。
需按生产消息率核对容量与 dropped/failed，不能只看正文目录字节数。正常停机、重启或崩溃均可能
损失未封存片段；HTTP Shutdown 不等待已劫持的 WebSocket，接受此边界，不另建停止观察、
强制封存或恢复流程。十五秒封存会影响可读等待及损失窗口，暂停/存储故障仍只停止取证。分段降低固定成本，不保证整站 CPU 必然下降。

高水位不能保证整机永不满盘：其它业务仍可写入，一天内存量也可能很大。生产开启前必须配置证据
专用卷或文件系统配额，验证配额耗尽时业务库/日志/正式文件仍可写，详见[运维手册](../40-operations/11-音视频证据运维手册.md)。

## 普通错误日志边界

全局 `clienterrlog.Recorder` 只记录结构化错误事实，不安装 HTTP 正文观察器，不重复复制、解析或
脱敏业务正文。上游真实 HTTP 状态码单独放在现有 requestReport 的轻量元数据字段中，沿原 transport
回调赋值、在每次原生重试开始清零；错误分类不依赖正文采集器，也不继承前次响应。使用日志 `other` 和错误日志 `detail` 继续按原合同序列化、读取解析；请求证据按
RequestID/TaskID 关联，证据关闭或到期后不回退到普通日志保存原文。管理端渠道测试、连接探测的
显式脱敏快照入口独立保留，历史脱敏快照继续可读，不扩展原文例外。

OpenAI Realtime 每消息的输入/输出 Token 运行诊断使用已有 Debug 日志，仅在调试开启时格式化和
写出；错误、完成时用量汇总、数据库消费记录及四方向证据仍走原路径。

## 按需查看与授权

仅 Admin/Root 可显式读取单条或下载，普通用户无权访问；整个接口组禁止缓存。目录、查看、下载
分别发起访问审计，审计失败只输出净化诊断，不宣称必然落库。列表查询故障返回失败，不伪装为空。

raw 查看最多前 64 KiB，并返回 `display_limited`；完整下载按 64 KiB 缓冲顺序解密，不加载整个新
对象。认证错误可能在流中后段出现，连接失败代表下载未完整，不能当作正常完整文件。页面不提供
位图预览，不执行 HTML/SVG、不自动访问正文链接；关闭/身份变化取消并清除原文和格式化缓存。
Admin/Root 在单条查看中显式请求 `format=json` 时才格式化，目录和默认原文读取不执行正文解析。
使用 `common.IndentJson` 保留字段顺序、重复键、大整数及数字词法，不重新构建 JSON 对象或回写。
格式化前计算保守展开上界，所有可见消息共用 64 KiB 格式化输出预算；截断、非 JSON、非文本或
展开过大时保持原文。WS 只对预览中完整的文本消息格式化，整个片段仍可完整流式下载。
支持文件流 API 的浏览器直接流式保存；其它浏览器保留显式 Blob 下载，浏览器内存仍可能随文件
增长，服务端保持流式。该兼容限制须在部署验收中核对，不宣称所有浏览器下载均有界。

## 验证边界

本地确定性测试覆盖实际四方向、大于 32 MiB 原文与有限查看、文件旁路、加密损坏/跨对象替换、
最终客户投影、sending 资格、窗口清理竞争、批量关联、权限、磁盘阈值与资源退让。本地隔离 MySQL 5.7.44/PostgreSQL 9.6.24 的迁移、窗口锁、关联查询与清理合同也已验证。真实 Provider、
生产数据库、多节点共享卷、配额耗尽及真实生产流量的 CPU/内存对照仍需部署验收；不能用
代码存在、单机测试或前端构建通过代替生产可用结论。
