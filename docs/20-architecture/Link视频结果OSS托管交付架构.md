# Link 视频结果 OSS 托管交付架构

## 1. 范围

本文描述本地 Link 视频结果的本站私有 OSS 托管与预签名交付：Seedance 的 Synlink、FunCloud、
墨行（Moxing）、Vidu、官方及其他已登记 `video_upstream_protocol` 线路，以及 MiniMax 标准
视频扩展（`ChannelTypeMiniMaxLink`）。同一交付规则覆盖范围内全部 Provider 线路，不按客户
模型后缀选择方式。成功主视频与实际提供的尾帧采用相同托管规则。

范围外线路（ModelArk V3 北向下挂的原生 Gemini、VertexAI、OpenAI/Sora 等）继续沿用冻结
连接回源交付，不建立托管事实，不受本文约束。素材控制面、参考音频暂存、请求证据、
`funcloud_material_hosted` 托管素材各自遵守既有合同。

## 2. 数据与控制流

```text
上游生成成功事实耐久提交（轮询 CAS 赢家）
    ↓
task_video_result_objects 登记 pending 行（主视频必有；上游响应携带尾帧时独立登记）
    ↓
system task worker（DB lease + 行级领取租约）按冻结协议与连接读取完整结果文件
    ↓
有界流式/分片上传本站私有 OSS（单对象键：videos/tasks/{task_id}/{part}）
    ↓
CAS 提交 ready 对象登记事实（存储实例、桶、对象位置、MIME、大小）
    ↓
授权查询按对象事实签发固定 86400 秒预签名 GET URL
    ↓
客户直连 OSS 下载；网关不再传输结果字节
```

- 成功状态提交后重新读取耐久 Task 再登记；全部部件事务提交，已有部件通过唯一键保留原事实。
- 转存在可信生成完成后及时执行，不等第一次客户端下载；需要附加 Provider 凭据的线路由
  代码 adapter 逻辑在后台履约，客户看到的来源与下载方式不受南向差异影响。
- 上游生成状态与资金事实保持既有语义：转存准备中或失败不能覆盖已确认生成成功，不重复
  扣费，不因转存失败自动退款。
- 对象位置由平台生成（任务 ID + 部件），不从上游文件名或模型后缀推导；主视频与尾帧各有
  独立对象登记。登记保存对象引用，不保存本站完整预签名 URL。

## 3. 唯一持久事实与恢复

- `task_video_result_objects`（本地扩展表，主数据库）按 `user_id + app_id` 隔离记录任务归属、
  结果部件、状态（`pending / transferring / ready / unavailable`）、存储实例/桶、对象位置、
  MIME、大小、累计尝试、退避时间与脱敏失败描述。它是交付的唯一事实源；不冒用 `ImageTask`
  登记，不建立第二套 Provider 结果事实（上游结果 URL 仍只保存在 Task.PrivateData.ResultURL）。
- 领取是行级 CAS UPDATE（状态 + 租约过期 + 退避时间三条件），多节点并发领取每行只被一个
  worker 取得；租约过期后可被重新领取，崩溃与多节点重启按持久事实恢复。
- 对象键确定且成功上传幂等覆盖：上传成功但数据库提交失败时，重试复写同一对象键后重新提交
  登记，不产生新对象身份；部分上传（未完成分片）不成为可交付对象。
- 重试只针对同一任务、同一结果的读取或上传，指数退避、累计领取次数有上限；用尽后如实标记
  `unavailable`。不重发生成 POST、不换 Provider、模型或渠道。
- 上游结果读取失败分类：404/403/410、data: 编码、代理回环、超出大小上限、冻结快照缺失、
  冻结 adapter 版本失效等按交付不可用处理；5xx、网络与存储故障按可重试处理。
- 存储不可用（未配置或读写失败）时不下发上游直链，不回退旧字节代理；行退避重试或明确交付
  不可用。签名前必须校验登记存储位置与当前配置完全一致，不一致失败关闭。
- 登记缺口补扫：按成功完成时间的最近 24 小时窗口，补齐范围内任务缺失的主视频或实际尾帧；
  即使没有可领取对象行，缺口也会启用后台调度。已完整登记的任务不产生新工作，存量缺少任一
  部件的任务也可恢复；窗口外任务不自动迁移，其范围由部署方上线前盘点决定。

## 4. 固定 24 小时预签名合同

- 范围内全部结果下载采用私有 OSS 预签名 GET URL，签发时固定 86400 秒，从每次签发时刻起算；
  与任务创建、生成完成或首次查询时间无关。每个结果文件独立签名。
- `content.video_url` 返回主视频预签名地址；实际存在尾帧时 `content.last_frame_url` 返回尾帧
  预签名地址。API 单查、列表与控制台制品使用同一对象登记与签名规则。
- 内容入口的 HEAD 请求使用 HEAD 签名；ModelArk 的下载字段始终签 GET。
- 客户访问签名 URL 不附加平台 API Key 或 Provider Key；实际 MIME、Range/206、HEAD、浏览器
  播放与 CORS 由真实对象存储验收。签名凭据有效期与对象保留策略必须覆盖签发后的完整 24 小时。
- 到期后在对象仍存在且调用方仍获授权时重新查询即续签新的 24 小时 URL；不重新生成视频、
  不再次复制对象、不读取上游。
- 本合同是「禁止完整签名 URL 进入公共响应」的已登记例外：仅限托管范围内的结果交付地址。
  上游凭据与私有结果链接不进入普通日志；请求证据的原文例外与授权边界以[硬约束](../00-context/硬约束.md)第 6 节为准。

## 5. 公共交付状态合同

成功范围内任务在 ModelArk 投影与内容入口上按唯一公共合同表达交付进度，生成成功状态
（`succeeded`）不变：

| `content.delivery_status` | 含义 | `video_url` / `last_frame_url` | 内容入口行为 |
| --- | --- | --- | --- |
| `ready` | 主视频已托管 | 主视频预签名地址；末帧独立就绪时返回其地址 | 就绪部件 302 重定向签名地址 |
| `preparing` | 已登记待转存/转存中 | 省略 | `409 video_delivery_preparing` |
| `unavailable` | 上游失效或转存不可用 | 省略 | `410 video_delivery_unavailable` |

- `content.delivery_status` 描述主视频的公共交付状态，`ready` 不保证末帧已经就绪。
  `last_frame_url` 缺失不能单独证明 Provider 未提供末帧；`?part=last_frame` 按该部件的持久事实
  返回 302、409 或 410，确无末帧事实时返回 `404 content_not_found`。ready 对象签名失败时内容
  入口返回 `503 video_delivery_unavailable`；任务投影在主视频签名失败时表达 `preparing` 并省略 URL。

- 范围内任务无登记行时：补扫窗口内的成功任务表达 `preparing`（将被领取）；窗口外存量任务
  如实表达 `unavailable`，缺少完成时间也不承诺可自动恢复，不把未托管历史写成已托管。
  已存在待转存行继续按持久重试事实执行；实际存在但缺少登记的尾帧在补扫窗口内返回准备中，
  窗口外返回不可用，不能误报为 Provider 未提供尾帧。
- 外用户、外 app、已删除任务和错误部件不得获得签名；主视频签名不授权尾帧或其它对象。
- 范围外线路继续返回本站内容代理路径，保持既有鉴权、过期与回源语义；本合同不新增平行的
  上游直链字段或临时代理交付开关。

## 6. 边界与不变量

- 转存 worker 是范围内结果读取的唯一实现：保留冻结协议/连接/凭据语义、SSRF 防护与带凭据时
  的重定向禁止；供应商地址与凭据不进入客户 URL、响应或普通日志。
- Synlink 尾帧使用冻结接口与凭据，其它已提供尾帧的线路读取耐久响应中的尾帧地址，不附加 Provider 凭据。
- 上游文件读取只接受完整 HTTP 200；S3 multipart 在初始化阶段设置对象 MIME，完成阶段必须
  取得合法成功 XML 和非空 ETag。响应正文关闭后才取消请求 context，空或畸形完成证据不发布 ready。
- 上传有大小上限与有界缓冲（S3 分片、Azure UploadStream），不保存完整视频正文到 Task、
  数据库、日志或缓存；不在请求时临时探测或静默迁移存量任务。
- 内容入口（`/v1/videos/{task_id}/content` 与任务制品接口）对范围内任务仅重定向或返回交付
  状态；不回退旧字节代理，不双读旧合同。
- 未完成真实 Provider、真实对象存储、浏览器播放、外部数据库与生产灰度验收前，本能力不得
  写成生产已发布。


## 7. 变更性质与上游同步

Task 结果登记、存储上传、恢复和授权交付均位于 Link 独立文件。原生轮询仅保留成功 CAS 后的
登记调用，迁移与启动注入继续采用既有最小接线；不修改原生 Provider 请求、生成状态或计费语义。
未来接取上游时，轮询接线须保持在成功事实耐久提交之后，其余主体文件独立保留。
