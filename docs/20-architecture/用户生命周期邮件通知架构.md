# 用户生命周期邮件通知架构

> 本专题描述账户创建、密码修改、API Key 创建三类事件邮件的当前实现事实。代码与管理开关已完成；
> 真实 SMTP 投递与灰度验收仍未完成，见 [路线图](../50-planning/路线图.md#用户生命周期邮件生产验收)。
> 本文件只描述代码已存在的事实，不声称生产已发布。产品行为、触发场景与验收口径见
> [用户生命周期邮件通知产品设计](../10-product/用户生命周期邮件通知产品设计.md)。

## 范围与边界

- 覆盖三类用户生命周期事件的事务性邮件：账户创建、密码修改、API Key（Token）创建。
- 复用既有的 SMTP 收发（`common.SendEmail`）与多通道分发（`service.NotifyUser`）；本专题只新增
  per-event 开关、触发封装和 i18n 内容，不新建邮件通道、事件总线或 observer。
- 不负责账户余额低提醒（已有 `service.checkAndSendQuotaNotify`），不做退订、邮箱验证与法律分类。

## 职责与事实源

| 组件 | 文件 | 职责 |
| --- | --- | --- |
| 开关配置 | `setting/operation_setting/notification_setting.go` | 三个 per-event bool 开关，默认全关；经 `config.GlobalConfig.Register("notification_setting", ...)`（Pattern b）自动接入 GET/PUT `/api/option`，无 schema 迁移 |
| 触发封装 | `service/user_lifecycle_notify.go` | 三个导出函数，开关门控 + 异步发送 + 双语渲染 + 统一走 `NotifyUser` |
| NotifyType | `relaykit/dto/notify.go` | `NotifyTypeAccountCreated` / `NotifyTypePasswordChanged` / `NotifyTypeTokenCreated` |
| i18n 内容 | `i18n/locales/{en,zh-CN,zh-TW}.yaml` | `notify.account_created.*` / `password_changed.*` / `token_created.*` 标题与正文 |
| 接线点 | `controller/user.go`、`controller/token.go` | 5 处单行调用 |
| 管理开关 UI | `web/src/features/system-settings/` | 三个开关塞进 Operations → Monitoring & Alerts |

## 控制流

事件发生 → controller 提交事务后内联调用 `service.NotifyXxx(userId)` → 函数读取对应开关，关闭则
立即 `return` → `gopool.Go` 异步执行 → 解析用户与语言（`model.GetUserById` + `User.GetSetting().Language`）
→ `i18n.Translate` 渲染双语标题/正文 → `service.NotifyUser(userId, email, setting, dto.NewNotify(...))`
完成地址解析、`NotificationEmail` 覆盖、每用户渠道选择和限频。

关键约束：

- 触发点在 **controller 提交事务之后**，不放 model 层，避免 `model → service` 循环依赖。
- **异步 fire-and-forget**：发送失败只记 `common.SysError` 日志，不重试、不阻断主请求。
- **默认全部关闭**，管理员按事件逐个开启。

## 接线点

| 事件 | 文件 / 函数 | 调用 |
| --- | --- | --- |
| 账户创建（注册） | `controller/user.go` `Register` | `service.NotifyAccountCreated(insertedUser.Id)` |
| 账户创建（管理员建号） | `controller/user.go` `CreateUser` | `service.NotifyAccountCreated(cleanUser.Id)` |
| 密码修改（自助） | `controller/user.go` `UpdateSelf` 密码分支 | `service.NotifyPasswordChanged(cleanUser.Id)` |
| 密码修改（管理员改） | `controller/user.go` `UpdateUser` 密码分支 | `service.NotifyPasswordChanged(updatedUser.Id)` |
| API Key 创建 | `controller/token.go` `AddToken` | `service.NotifyTokenCreated(c.GetInt("id"))` |

注册时 `GenerateDefaultToken` 自动建 Token 的路径**不**触发密钥通知，避免注册即发两封；密钥通知
仅在用户显式 `AddToken` 时发。忘记密码重置路径不接线（重置链接本身已发邮箱）。普通资料更新不
进入密码修改分支，因此不触发密码通知。

## 邮箱必填边界

- `Register`：`user.Email == ""` 直接拒绝（`i18n.MsgUserEmailEmpty`）；注册表单邮箱字段始终渲染
  且必填，邮箱验证码字段仍按 `emailVerificationRequired` 条件渲染。
- `CreateUser`：初始必填判断含 `user.Email == ""`，并通过 `cleanUser.Email = user.Email` 确保入库。
- OAuth/微信注册不强制邮箱；Provider 未返回邮箱时欢迎信静默跳过。
- 不做邮箱验证，不加 `email_verified` 列。
- 存量无邮箱用户目前在个人设置页**没有**前端提示，见 [路线图](../50-planning/路线图.md#用户生命周期邮件生产验收)。

## 管理开关（前端）

Operations → Monitoring & Alerts 新增三个开关（`web/src/features/system-settings/`）：

- `types.ts` 声明 `notification_setting.send_email_on_account_created` /
  `send_email_on_password_changed` / `send_email_on_token_created` 三个 boolean option key。
- `integrations/monitoring-settings-section.tsx` 新增 zod 字段与三个开关项，复用既有逐字段 diff +
  `updateOption.mutateAsync` 保存循环，不新建 settings tab。
- 管理员建号抽屉 `features/users/components/users-mutate-drawer.tsx` 新增邮箱输入与必填校验。

## 约束与取舍

- **最小入侵**：新逻辑全部在新文件（`notification_setting.go`、`user_lifecycle_notify.go`、i18n
  key/常量）；现有 controller 文件只保留单行接线和极窄校验，便于未来接取上游 NEWAPI 代码时低冲突合并。
- **无 schema 迁移**：开关经 `options` key-value 表持久化，天然兼容 SQLite/MySQL/PostgreSQL。
- **限频取舍**：`NotifyUser` 的每用户每小时限频可能压掉连续密码修改邮件；当前接受该行为，未来如需
  绝对保证可让该事件绕过 `NotifyUser` 直发 `common.SendEmail`（与现有重置密码邮件一致）。
- **邮箱不可信**：本期只发往注册或管理员填写的邮箱，不做送达校验。
- **未完成**：真实 SMTP 投递、灰度验收、OAuth/微信与存量无邮箱用户边界验证、存量无邮箱用户前端
  提示见 [路线图](../50-planning/路线图.md#用户生命周期邮件生产验收)。
