# 邮件投递与用户生命周期通知架构

此文描述当前代码的邮件通道和账户流程。产品验收口径见
[邮件与运维通知产品设计](../10-product/用户生命周期邮件通知产品设计.md)。本地收件与三库迁移已验收；
Microsoft 365 Graph 真实邮箱收件验收未完成，见[路线图](../50-planning/路线图.md)第 39 项。

## 配置与投递

- [邮件设置](../../model/mail_settings.go)把活动协议、发件邮箱和该协议所需字段保存在主库的一条选项记录。
  保存时在事务内取得旧配置。身份与服务器相同且凭据字段留空时才保留原凭据。通用选项接口隐藏秘密字段，
  写入走专用 Root 路由。升级时可从原 SMTP 选项取得有效配置，保存新配置后由新配置决定协议。
- [统一发信入口](../../common/mail_transport.go)取得发信并发槽后，从主库读取一次活动配置。各节点的新提交
  以主库为准，正在提交的请求继续使用当次快照。SMTP 以 DATA 接受回复为提交成功，Graph 以 HTTP 202 为
  提交成功。可能已经提交但没有可信回复时记录结果不明。运维可在设置页提交测试信，实际到达由收件箱核对。
- Graph 使用应用身份和 Microsoft 公有云固定端点，按配置邮箱的用户主体名或对象 ID 提交。
  客户端凭据及访问令牌不会返回浏览器。租户管理员负责在 Exchange Online 将发信授权限定到专用邮箱。
- [邮件类型目录及偏好](../../model/mail_preferences.go)由专用 Root 路由读取及更新。主库保存每类开关和变更时间，
  升级时导入欢迎信、API Key 创建通知、个人日报和财务收件名单的生效值。历史生命周期开关对其他通知渠道的
  生效值随迁移保留。类型开关仅控制邮件。
- 排队按邮件类型普通读取主库偏好，邮件路径不对业务数据加显式锁。关闭时更新偏好并停止待发与等待重试的投递；已领取的工作在
  [发送前](../../service/mail_policy.go)与 SMTP/Graph 正式提交边界复核偏好。重新开启不恢复已经停止的邮件，
  从下一个符合时间条件的窗口发送日报；仍开放且从未排队的渠道、资源或证据清理异常可触发一次。
  保留已提交或结果不明的记录。验证码、找回链接和手动测试走各自入口。
- 用户通知复用既有的个人通知方式、地址优先级与限频。欢迎信与显式创建 API Key 通知各有开关，默认关闭。
  账户安全变更和换绑凭证按各自入口选择账户邮箱。密码修改的独立生命周期开关已退役，用户自助改密仍由
  账户安全事件发通知。

## 账户创建与找回

- 管理员建号入口规范化邮箱，在保存前要求非空和合法格式，沿用既有账户邮箱唯一性规则。
- 找回请求返回统一的受理结果。后台通过账户邮箱定位唯一有效用户，对同一账户限制发码频率。
- [密码重置](../../model/password_reset.go)复用持久化认证流程。主库保存凭证摘要、用户、邮箱、账户认证
  版本和有效期。一次性链接在 URL 片段携带凭证，有效期 15 分钟。多节点使用同一认证密钥时可跨节点完成。
- 重置页面和接口均要求两次新密码一致。确认消费凭证、更新密码和提升认证版本在同一事务提交，旧会话
  由认证版本和既有会话撤销路径处理。邮箱更换、账户停用或密码已变更时，旧链接无法重置账户。

## 资源与模板

- 普通事件通知由有界工作队列处理。队列满与投递失败记录脱敏结果，业务事务与邮件分开完成。
  找回链接、邮箱绑定验证码与手动测试保留独立的操作结果和有限等待。
- 账户验证码和找回邮件可在共享发信槽位满载时有限等待。邮箱验证在槽位等待超时时返回可重试的
  服务暂不可用响应。找回任务仅在等待槽位超时时重试一次，明确未获通道受理的凭证释放账户限频。
  提交结果不明时保留原凭证。
- 钱包和订阅结算只在达到提醒条件时提交邮件工作。钱包邮件工作在独立有界队列内读取当时有效的个人设置，
  低余额或已确认的钱包拒绝复用主库告警记录和逐地址投递。持续低余额按账户去重，
  观察到恢复后关闭该异常，待投递的低余额邮件也会在发送前重查当前余额与阈值。
  钱包拒绝邮件描述已发生的拒绝，独立于发信时的余额。余额仍高于提醒阈值的拒绝按账户及自然日去重。
  拒绝提示还复核前 24 小时的个人钱包提醒。准备阶段满载会计数并跳过，已入库的邮件按投递规则重试。
  订阅和个人其他通知渠道沿用各自的投递行为。
- 标题和正文由随版本维护的简体中文与英文模板生成。运维公共邮件使用双语正文，用户通知使用既有语言选择。账户邮件、手动测试和告警共用 HTML 外层版式。凭据、完整重置链接、验证码和原始 Provider 响应不进入投递诊断。
- 新增业务逻辑位于独立文件。原生路由只补管理员入口，账户控制器保留必要的建号校验和既有通知接线。
  后续上游同步重点核对路由授权、密码重置入口及邮箱校验。

## 邮件明细与排查入口

- 资源与证据告警展示使告警成立的读数或清理事实，视频资金通知展示该次检查的占款和退款结果。
  渠道巡检完成通知展示本次统计和最近失败记录。管理入口仍执行当前权限。
- 账户安全邮件带通知时间与安全入口，欢迎、API Key 创建和钱包提醒链接到对应操作。
  验证码和找回邮件继续使用当次安全凭证、有效期和已有用途边界。

## 管理员钱包通知

- 管理员改额与补单在资金事务提交前后余额及业务流水。邮件任务只读已提交且满足通知条件的新流水，独立准备回执和高风险提醒。
  名称不可用时使用账户 ID。邮件配置、排队或发信失败仅影响通知，不影响余额、订单状态或业务流水。
  每种通知按流水号去重。邮件处理记录单独保存，历史流水不补发。补单订单重复完成和原值覆盖不产生新流水或邮件。
- 用户回执使用账户邮箱，展示受影响账户名称和 ID。财务日报附前一自然日最近五笔人工操作。发送前重新核对地址。财务收件人及高风险阈值见[运维配置](../40-operations/环境配置.md#钱包财务邮件)。
  系统任务每天从主库流水汇总昨日的操作笔数及额度增减，按北京时间日期去重。摘要生成依赖次日调度，跨日停机期间的摘要不自动补发。
