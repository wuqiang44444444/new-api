# 邮件投递与用户生命周期通知架构

此文描述当前代码的邮件通道和账户流程。产品验收口径见
[邮件与运维通知产品设计](../10-product/用户生命周期邮件通知产品设计.md)。本地收件与三库迁移已验收；
Microsoft 365 Graph 真实邮箱收件验收未完成，见[路线图](../50-planning/路线图.md)第 39 项。

## 配置与投递

- [邮件设置](../../model/mail_settings.go)把活动协议、发件邮箱和该协议所需字段保存在主库的一条选项记录。
  保存时在事务内取得旧配置。身份与服务器相同且凭据字段留空时才保留原凭据。通用选项接口隐藏秘密字段，
  写入走专用 Root 路由。升级时可从原 SMTP 选项取得有效配置，保存新配置后由新配置决定协议。
- [统一发信入口](../../common/mail_transport.go)取得发信并发槽后，从主库读取一次活动配置。各节点的新提交
  以主库为准，正在提交的请求继续使用当次快照。SMTP 以 DATA 接受回复为提交成功，Graph 以 HTTP 202 为
  提交成功。可能已经提交但没有可信回复时记录结果不明。运维可在设置页提交测试信，实际到达由收件箱核对。
- Graph 使用应用身份和 Microsoft 公有云固定端点，按配置邮箱的用户主体名或对象 ID 提交。
  客户端凭据及访问令牌不会返回浏览器。租户管理员负责在 Exchange Online 将发信授权限定到专用邮箱。
- 用户通知复用既有的个人通知方式、地址优先级与限频。欢迎信与显式创建 API Key 通知各有开关，默认关闭。
  账户安全变更和换绑凭证按各自入口选择账户邮箱。密码修改的独立生命周期开关已退役，用户自助改密仍由
  账户安全事件发通知。

## 账户创建与找回

- 管理员建号入口规范化邮箱，在保存前要求非空和合法格式，沿用既有账户邮箱唯一性规则。
- 找回请求返回统一的受理结果。后台通过账户邮箱定位唯一有效用户，对同一账户限制发码频率。
- [密码重置](../../model/password_reset.go)复用持久化认证流程。主库保存凭证摘要、用户、邮箱、账户认证
  版本和有效期。一次性链接在 URL 片段携带凭证，有效期 15 分钟。多节点使用同一认证密钥时可跨节点完成。
- 重置页面和接口均要求两次新密码一致。确认消费凭证、更新密码和提升认证版本在同一事务提交，旧会话
  由认证版本和既有会话撤销路径处理。邮箱更换、账户停用或密码已变更时，旧链接无法重置账户。

## 资源与模板

- 普通事件通知由有界工作队列处理。队列满与投递失败记录脱敏结果，业务事务与邮件分开完成。
  找回链接、邮箱绑定验证码与手动测试保留独立的操作结果和有限等待。
- 账户验证码和找回邮件可在共享发信槽位满载时有限等待。邮箱验证在槽位等待超时时返回可重试的
  服务暂不可用响应。找回任务仅在等待槽位超时时重试一次，明确未获通道受理的凭证释放账户限频。
  提交结果不明时保留原凭证。
- 钱包和订阅结算只在达到提醒条件时提交邮件工作。额度邮件使用单独的有界队列，模板渲染、通知限频和
  网络提交在后台执行。队列满时合并记录跳过数量。个人通知的其他渠道沿用各自的投递行为。
- 标题和正文由随版本维护的简体中文与英文模板生成。运维公共邮件使用双语正文，用户生命周期通知使用
  既有语言选择。凭据、完整重置链接、验证码和原始 Provider 响应不进入投递诊断。
- 新增业务逻辑位于独立文件。原生路由只补管理员入口，账户控制器保留必要的建号校验和既有通知接线。
  后续上游同步重点核对路由授权、密码重置入口及邮箱校验。
