# 渠道亲和架构

本文描述渠道亲和缓存的当前边界：既有的显式会话规则亲和，以及按 API Key 的默认渠道亲和。
两者共用选渠底座和缓存机制，但键空间、优先级和写入条件相互独立。

## 范围与状态

- 显式会话规则亲和是既有已发布行为：管理员按规则把匹配的请求绑定到渠道。
- 默认 API Key 亲和已实现（`service/default_channel_affinity*.go`）并通过本地三库、竞态、
  Redis 故障注入与多实例回退演练回归，**生产未发布**：开发环境对照验证了预热后串行的缓存与
  输入费用收益，但冷启动并发无可归因收益且首 token P95 上升，延迟验收未通过。发布门槛见
  [路线图](../50-planning/路线图.md)第 39 项。

## 职责与事实源

亲和缓存是尽力使用的选渠提示，不是路由合同，也不改变任何请求的可用性语义：

- 权限、模型、协议、分组、客户合同、优先级与权重过滤仍是选渠的权威；
  客户合同路由由[合同定价架构](账单计费-用户模型合同定价架构.md)定义。
- 亲和写入或读取失败不改变已完成请求的结果；无可用绑定或缓存异常时按普通选渠继续。
- 不因亲和新增客户端字段、管理开关或数据库迁移。

## 优先级

同一请求依次应用：显式固定渠道 → 既有会话规则 → 默认 API Key 亲和。

已匹配会话规则的请求（含规则模式 `off`、规则缓存未命中和读取异常）完全沿用该规则的既有
处理，跳过默认绑定的读取和写入；满足原规则写入条件时仍按原规则建立会话绑定。

## 默认 API Key 亲和

### 触发范围

按方法与精确路径识别三个入口：`POST /v1/chat/completions`、`POST /v1/responses`、
`POST /v1/messages`。请求须走原生分发、输入自包含且未匹配任何会话规则。引用上游状态
（`previous_response_id`、`conversation`、上游文件、向量库、工具容器）的请求，转入专用
插件或任务履约的请求，WebSocket、媒体与异步入口均不进入。Responses 中按 `call_id` 在
同一请求内配对的函数调用与文本结果可以进入。只有已缓存在内存且不超过 1 MiB 的 JSON
正文参与判定；更大正文、磁盘正文与无法判定的输入沿用原路由。

### 绑定键与选渠整合

绑定键由鉴权后的 API Key 内部 ID、客户请求模型、协议入口和有效路由范围组成；
普通分组、Auto 的有序可用范围和客户合同按现有范围事实区分。同一账号的不同 Key 各自
建立绑定，缺少有效 Key ID 时走普通选渠。键不含原始 Token、请求正文或状态引用。

命中绑定只在本次首次尝试会使用的**有效优先级层**内作为偏好择优：Auto 先确定首个有候选
的分组，合同先汇集授权候选；数据库与内存两条候选路径都接收该偏好。未命中或被停用、
移出范围的绑定按现有权重正常选渠；重试继续遵守现有可重试条件、次数和分组规则。

### 写入语义

- 只有实际成功且取得可信终态的请求可建立或刷新绑定。流式请求须有协议终态：Responses
  HTTP SSE 使用现有 `completed` 终态，仅 EOF 不写；Chat Completions 请求多个流式结果时
  须确认全部结果结束（渠道覆盖 `n` 的双向语义已回归）。
- 只更新同一首选范围及优先级层内实际成功的渠道；跨层或跨 Auto 分组的重试成功不覆盖仍有效
  的首选绑定。全局「切换成功后更新会话绑定」关闭时，换渠成功保留旧绑定，无旧绑定时此次不建。
- 首次并发不等待绑定写入；后完成的同范围、同层有效成功请求可覆盖先写入的绑定。

### 缓存与容量

- 默认绑定使用独立命名空间 `new-api:default_channel_affinity:v1`，与显式规则的本地 LRU
  隔离；本地每进程最多 10,000 条，条目有效期缺省一小时。绑定键从账号切换到 Key 后，旧
  账号键留待过期或全量清理。
- Redis 读写各限时 10 毫秒，建立 TLS 连接也受本次操作期限约束；读取超时或失败立即走普通
  选渠且当次不写绑定。后台「清空全部渠道亲和性缓存」同时覆盖显式规则与默认两个命名空间，
  按规则清理的范围不变。管理统计以 `default_user_entries` 单独披露默认键规模。
- 共享 Redis 实例的键前缀不提供实例内配额；部署须按活跃 Key、模型、范围和 TTL 评估新增
  键量与淘汰策略。

## 约束与取舍

- 渠道 ID 稳定不等于上游缓存域稳定：渠道内多 Key 轮换、第三方网关二次分发、输入前缀变化
  和缓存过期都会产生未命中；亲和收益只对本平台直接管理的渠道落点可下结论。
- 亲和与上游提示词缓存是两层机制：Anthropic 缓存域依平台而异且需要稳定前缀；OpenAI
  Responses 的 WebSocket 连接内状态断线后消失，同渠道重连无法恢复。
- 首次并发按现有权重分散，允许绑定建立前落点多渠道；冷启动并发阶段不承诺亲和收益。
- 首期不做动态调度、不新增健康状态；单一大流量 Key 绑定后的负载集中依赖现有重试与
  全局关闭能力兜底。
