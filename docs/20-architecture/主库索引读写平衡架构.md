# 主库索引读写平衡架构

## 范围与边界

本文描述主数据库高写入表（`logs`、`tasks`、`error_events`、`casbin_rule`）的物理索引治理：
当前索引集合、迁移行为与部署约束。物理索引只影响执行计划和写入维护成本，不改变租户隔离、
权限唯一约束、排序分页、历史计费事实、任务状态推进和事务语义；不以提高慢查询阈值或省略
业务写入掩盖问题。

不承担：账单对账投影逻辑（见[客户与上游对账架构](账单计费-客户与上游对账架构.md)）、
error_events 事件模型与查询边界（见[运维-API错误日志架构](运维-API错误日志架构.md)）、
Task create attempts 的既有索引集合（不在治理范围）、ClickHouse 专属迁移（保持原分支，不执行
下述索引迁移）。

## 当前索引事实

- 退款取证与原生 Task ID 查询共用非唯一联合索引 `idx_tasks_task_user_app(task_id, user_id, app_id)`，
  替换原 `task_id` 单列索引：同一索引服务不带身份的历史查找、用户内查找和每批最多 200 个任务 ID
  的带身份退款取证，Task 总索引数保持不变。早期曾按附加式设计新增
  `idx_tasks_user_app_task(user_id, app_id, task_id)`，因纯写场景约一成开销被替换方案取代；
  已部署该索引的实例由迁移创建新索引后自动退役，不保留双份。
- 日志时间排序索引 `idx_created_at_id` 的目标列序为 `(created_at, id)`；历史实例上曾出现与声明
  相反的 `(id, created_at)` 实际结构，使时间排序回退临时排序。索引名不是迁移完成的证据，
  以实际列序为准。
- 已退役的冗余普通索引：`idx_logs_user_id`（由 `(user_id, id)` 前缀覆盖）、`idx_logs_model_name`
  （由 `(model_name, username)` 前缀覆盖）、`idx_error_events_created_at`（由
  `(created_at, id)` 覆盖）、`idx_casbin_rule` 普通索引（与七列唯一索引同列，唯一索引保留）。
  两个账单日志联合索引和任务用量轮询索引保留。
- Task/attempt 状态、资金与恢复调度索引不因当前取值集中而删除；Task 全字段更新保留既有业务
  含义，不为降低索引维护成本省略字段。

## 职责与事实源

- `model/read_write_index_migration.go`：索引退役的统一入口 `retireRedundantIndex`，只处理明确
  列出的索引对，从不发现或删除任意前缀索引；日志排序修复、Casbin 普通索引退役在本文件。
- `model/billing_statement_task_index.go`：Task 联合索引的元数据描述与创建，创建后退役原单列
  索引与早期附加式索引；描述类型不进入 AutoMigrate，不改 Task 字段、默认值或唯一约束。
- 接线：本地账单迁移入口创建 Task 联合索引并调用日志索引迁移；`model/error_event.go` 迁移中
  退役 error_events 冗余索引；`model/main.go` 在 AutoMigrate 之后调用 Casbin 索引迁移。
  原生 `model/log.go`、`model/task.go` 仅移除已退役索引的声明标签（否则 AutoMigrate 每次启动
  重建再删除）。

## 迁移行为与安全边界

- 删除前置校验：原索引必须是普通完整索引（非唯一、无条件/表达式/前缀/降序、预期列序），
  替代索引已存在且列序、唯一性符合预期；否则返回迁移错误拒绝删除，不损坏自定义约束。
- 方言适配：索引元数据分别适配 SQLite（pragma）、MySQL 5.7 与 PostgreSQL 9.6（信息目录）；
  PostgreSQL 按 `indkey` 顺序读取列，不使用 GORM `GetIndexes` 未保证顺序的结果作删除依据。
  不支持的方言返回错误，不静默跳过。
- 中断可恢复：日志排序修复经"建临时索引 `idx_logs_sort_repair` → 删除错序旧索引 → 按目标列序
  重建 → 退役临时索引"过渡，任意中断后按实际结构继续，不持久化迁移状态、不修改业务行；
  MySQL DDL 隐式提交不影响恢复设计。DDL 故障注入验证：替代索引创建失败时原始记录不变、
  临时索引仍可用、下次迁移可恢复。
- 迁移已存在且结构正确时跳过；失败沿启动错误路径返回。不在请求期执行 DDL、不隐藏错误、
  不为通过检查放宽校验。

## 部署与验收边界

- 不重启在用服务、不直接对业务库执行 DDL；部署后由主节点启动迁移完成。首次建索引须备份并
  安排受控升级窗口，避免多节点并发迁移，预留临时索引空间；索引 DDL 可能等待锁或阻塞写入，
  与迁移完成后的稳态写入成本分开评估。
- 上线后核对实际索引结构与执行计划，观察写入尾延迟、连接池等待和账单读取。本地基准只衡量
  数据库/GORM 层，不构成生产 SLA；未复现的历史慢查询在定位前不得宣称已消除，也不得以增大
  阈值隐藏。
- 本地三库（SQLite、MySQL 5.7.44、PostgreSQL 9.6）回归不替代最低支持版本（MySQL 5.7.8）与
  生产峰值验收。生产验收门槛与跟进入口见
  [80 目录未完成事项汇总](../50-planning/2026-09-19-80目录未完成事项汇总.md)。
