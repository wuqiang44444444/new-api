# 用户模型合同定价架构

## 1. 边界与事实源

用户模型合同是按 `User ID` 生效的增强授权与客户定价层。它只表达：

```text
精确公开模型 + 唯一渠道组 + 八位定点合同折扣
```

主数据库中的 `users.contract_mode`、`users.contract_version`、`customer_model_contracts` 和
`customer_contract_audits` 是合同事实源。Redis、进程缓存、鉴权缓存和前端状态均可重建。

`contract_mode=false` 必须字面量早返回 NEWAPI 原生路径，不查询合同规则、不改变原生组和计费；
`contract_mode=true` 必须取得与鉴权版本一致的不可变合同快照，否则在预扣和 Provider 调用前失败关闭。

合同不替代 NEWAPI 原生模型、Group、Ability、Channel、分发或计费语义，而是在明确的本地接线点收窄授权、
锁定渠道组并对模型费用小计应用客户折扣。

## 2. 身份、匹配与路由

合同匹配使用客户端请求中的精确公开模型名（`OriginModelName`）：

1. Token 鉴权取得合同模式与版本；
2. 合同快照按 `user_id + version` 读取；
3. 精确模型白名单与 Token 模型限制取交集；
4. 命中规则后把 `UsingGroup` 固定为合同 `route_group`；
5. 组内继续使用 NEWAPI 原生选渠，Seedance 继续使用唯一专用 Channel 的确定性路由。

合同不能通过 Token 固定组、AutoGroups、Playground、Affinity、指定 Channel 或跨组重试扩大权限。组内
Priority、Weight、随机选择和原生重试语义仅在合同组内有效；合同组不可用时失败关闭，不跨组 fallback。

Seedance 合同仍遵守 `ChannelTypeSeedanceLink` 的一模型一 Channel 约束，不把合同组变成第二个 Link 候选池，
也不把 Seedance 写入 NEWAPI Ability 或通用分发缓存。

## 3. 持久化与事务

### 3.1 数据结构

| 事实 | 结构 | 不变量 |
| --- | --- | --- |
| 用户模式 | `users.contract_mode`、`contract_version` | 存量用户初始化为原生；版本单调递增 |
| 模型合同规则 | `customer_model_contracts` | `UNIQUE(user_id, public_model)`；`ratio_units` 为 `1..100000000` |
| 管理审计 | `customer_contract_audits` | 只追加；before/after 使用 `common.Marshal` 保存脱敏快照 |

应用层使用大小写精确匹配。写入时拒绝同一用户仅大小写不同的模型名，避免 MySQL 默认不区分大小写的索引行为
与 SQLite/PostgreSQL 分裂。规则不保存“当前不可用”状态；可用性由当前 Channel/模型事实派生。

### 3.2 完整替换事务

管理写接口提交 `expected_version`、目标模式、完整规则集和必填原因。服务端在一个事务中：

1. 先在用户行锁外校验启用规则的当前可履约性；
2. 使用 `lockForUpdate(tx)` 锁定用户并比较版本；
3. 增加现有 `auth_version` 失败关闭围栏；
4. 替换规则、写入模式与新版本；
5. 写入脱敏审计；
6. 提交后刷新鉴权缓存。

任一步失败都不留下部分规则。停用只关闭模式并保留规则；删除最后规则不会自动回到原生模式，而是形成零模型
权限状态；重新启用必须重新校验全部规则。

## 4. 缓存与失败关闭

合同读取只有三态：

```text
native                 明确 contract_mode=false
contract(snapshot)     模式开启且版本一致
error                  数据库、缓存、版本或快照异常
```

只有 `native` 可以进入原生路径。缓存 miss 可回源主数据库；主库失败、快照损坏、版本不一致、比例非法、规则
重复或目标模型当前不可履约时均返回错误，不回退到原生权限、旧合同或倍率 `1`。提交后的 pending fence 先于
缓存刷新生效，避免陈旧 KEY 继续授权。

## 5. 模型发现、价格与异步事实

合同模式的 `/v1/models`、模型详情、控制台模型选择器和 `/api/pricing` 只投影精确合同规则、当前可用性和
合同折后价格；读取失败返回失败，不显示原生列表或原生价格。普通用户不看到渠道组、Channel、Provider、
上游模型或特殊组倍率。管理员选项接口可以看到内部渠道组，但只服务低频配置面。

同步请求在模型费用小计和完整原生组倍率完成后乘合同折扣；工具费、违规费、充值折扣和 Provider 成本不参与。
折扣使用 `ContractBillingFact` 的八位定点事实，最终 quota 仍走统一 checked 饱和函数。

异步 attempt/Task 在发送前或创建时冻结：客户模型、合同版本、公开模型、绑定组、合同折扣、原生组倍率、
表达式/价格版本、资金来源和协议快照。终态只补齐可信实际用量；合同变化、原生价格变化和规则删除不影响
已创建任务。没有合同事实的原生/历史 Task 继续使用原有语义，不由当前用户合同反向推断。

## 6. 管理员合同总览

`GET /api/customer-contracts` 是只读聚合投影，不是第二套合同资源。`contract_version > 0` 且用户未删除时才
进入总览，状态由当前模式和规则数派生：

| 条件 | 状态 |
| --- | --- |
| `contract_mode=true` 且规则数 > 0 | `active` |
| `contract_mode=true` 且规则数 = 0 | `zero_access` |
| `contract_mode=false` 且版本 > 0 | `inactive` |

接口服务端分页，支持 User ID/用户名/显示名/公开模型关键词和状态筛选；摘要统计不受当前筛选影响。规则数、
当前版本审计和不可履约规则数通过聚合与当前页批量计算，禁止前端逐用户调用详情接口拼装。响应不返回渠道组、
凭据、Provider 或上游模型。合同写入仍只有 `PUT /api/user/:id/contract`，列表页只复用既有
`UserContractDrawer`。

## 7. 变更性质：NEWAPI 原生窄接线与本地优化

| 接线面 | 性质 | 必要性与边界 |
| --- | --- | --- |
| `middleware/auth.go`、`model/user_auth_cache.go` | NEWAPI 原生鉴权缓存的必要字段接线 | 传递模式/版本并复用现有 auth fence；不在鉴权层查询合同规则 |
| `middleware/distributor.go` | NEWAPI 原生分发前的必要窄守卫 | 只调用新增合同服务并锁定合同组；不复制分发实现 |
| `controller/model.go`、`controller/pricing.go` | NEWAPI 原生投影入口的早返回优化 | 合同用户返回专用投影；原生用户保持原路径 |
| `relay/helper`、Task 计费接线 | NEWAPI 原生计费/异步热路径的最小乘数与快照接线 | 只对存在 `ContractBillingFact` 的请求生效，原生 nil fact 原样返回 |
| `model/customer_contract*.go`、`service/customer_contract*.go`、`types/customer_contract.go` | 本地新增权威实现 | 承载规则、事务、缓存、审计、计费事实，不扩写原生文件 |
| `model/controller/router/customer_contract_admin_*` | 本地新增只读总览 | 只读聚合，不新增写接口、状态源或计费分支 |
| `web/src/features/customer-contracts/` | 本地新增管理界面 | 复用既有合同抽屉和写接口，不复制编辑逻辑 |

上述原生文件改动仅为接线或早返回；业务判断、数据模型、验证和测试均隔离在新增文件，以降低未来接取上游时的
冲突面。

## 8. 架构不变量

1. 未启用合同的请求不读取合同规则，也不改变 NEWAPI 原生模型发现、路由和计费。
2. 合同只授权精确公开模型，并固定一个具体渠道组；不使用通配、候选交集或请求时模型名推断。
3. 合同读取、缓存、版本和可用性异常均失败关闭，不回退到原生或旧快照。
4. 合同折扣只作用于模型费用小计，工具费、违规费、充值折扣和 Provider 成本保持独立。
5. 异步任务按创建时冻结合同与原生计费事实完成生命周期，历史任务不重定价。
6. 管理员总览是只读投影，合同写入只有一个权威接口。
7. 主数据库是合同、审计、Task、资金和日志事实源；缓存与前端状态可重建。
