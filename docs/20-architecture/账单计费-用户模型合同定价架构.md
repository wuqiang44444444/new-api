# 用户模型合同定价架构

长期取舍见 [ADR-0020](decisions/0020-客户合同范围约束与原生分发协同.md)。本文件描述本地代码边界，
不代表真实 Provider、外部数据库升级或生产灰度已经验收。2026-09-19 完成本地真实文本调用验收
（范围约束、越界拒绝、停用回退原生路由、折扣结算与错误双写，见
[用户模型合同定价](../10-product/用户模型合同定价.md)）；供应商账单核对与生产灰度仍未验收。

## 1. 边界与事实源

客户合同按 API Key 绑定，限定精确公开模型、路由组和渠道组合，并提供同模型唯一折扣。用户可持有
多份合同，一个 Key 至多绑定一份。合同是原生业务逻辑之上的授权与折扣层；生效时由合同定义调用
范围，原生层负责在该范围内履约和计费。合同不定义优先级、权重或第二套资金账本。

主数据库 `customer_contracts`、`customer_contract_entity_rules`、`customer_contract_entity_audits`
和 `tokens.contract_id` 是唯一事实源。旧用户级合同列不参与运行时；缓存和前端投影可重建。
规则唯一键仍为 `contract_id + public_model + channel_id`，使同模型的选中渠道对应唯一合同组。
折扣使用 `1..100000000` 的八位定点整数；同模型各规则必须完全一致，拒绝模型名仅大小写不同。

## 2. 请求状态、权限与范围

| 状态 | 行为 |
| --- | --- |
| Key 未绑定或绑定合同明确停用 | 使用 Key 原生组、auto 顺序、权限与价格，无合同折扣 |
| 启用合同列出精确模型且存在有效组合 | 按合同范围选路并冻结折扣 |
| 未列模型、Key 模型限制排除、所有组合失效 | 拒绝，不恢复原生候选 |
| 绑定缺失、归属/版本异常、读取或折扣一致性异常 | 失败关闭 |

身份校验先于合同读取。无合同或合同明确停用时，用户分组通过 `GetUserUsableGroups` 决定可用
路由组；Key 指定组必须在该范围内，未指定时使用用户组，auto 按原生可用组及 Key 配置选路。

启用合同是模型、路由组、渠道组合与折扣的授权来源，替代用户可用组及 Key 的 `group/auto_groups`
选路范围；不得再与这些范围求交集，也不得通过给用户开放内部组来补偿合同授权。用户保持 Default
仍可使用合同明确指定的内部路由组。合同不修改用户或 Key 保存的组配置，停用/解绑后恢复原生行为。
用户/Key 启停、有效期、IP、模型限制、额度和限流继续生效；绑定归属必须校验。
编辑已有合同 Key 的名称、额度或绑定时，不自动替换其已保存的组，也不裁剪原有 Auto 顺序；
未改变的原生路由配置可以保留，显式修改的路由配置仍经过原生校验。

请求状态与合同定义按请求冻结。重试不重新读取绑定、启停或折扣；当前渠道和组资格仍须满足。
缓存按合同 ID 组织，以用户 `auth_version` 围栏失效；合同提交递增版本并发布鉴权缓存。

## 3. 原生候选与选择

`EffectiveContractRules` 共享运行时和投影的组倍率存在性及渠道/模型资格校验，不接收用户组作为
授权条件。合同内组必须实际存在、配置倍率且渠道能够在该组提供模型；这属于履约资格而非用户组权限。
普通渠道使用原生 Ability 事实，类型化渠道使用自身 Channel 组与模型事实。读取故障不能伪装为空。
资格来源按最多 200 条规则分批读取，每批最多查询一次 Channel 和一次 Ability，查询参数及 OR 条件有界；
类型化渠道按 Channel 中的精确组和模型成员判断。管理保存、管理投影和运行时共享来源判定，
投影任一批读取失败均整体报错，不发布部分可用性，也不修改调用方已有的合同快照。
来源判定同时产生受控失效类别。管理员合同和模板响应通过 `unavailable_reason` 投影同一类别；
共享模型快照保持不序列化诊断字段，客户投影不含原因、渠道或分组身份。前端不自行重判来源政策。

合同 service 汇集完整允许组合，原生模型层只扩展候选读取：内存路径汇集合同各组的精确模型候选，
数据库路径读取相同组/渠道组合。之后沿用原生优先级层级、权重和平滑算法，不每组先抽一个渠道。
两条原生路径已有的权重细节保持各自原样。合同不向通用池写入影子分组或 Ability。

原生 pin 和首次亲和只在有效范围内使用。Playground 的组选择不能替代合同范围。
选中渠道后写入其唯一合同组，再由原生 `HandleGroupRatio` 解析普通/特殊组倍率。
用户所属组仅继续参与已有的用户组专属倍率计算，不得因此否决合同组合；不能把合同组选路改为
Default 来规避权限提示，因为这会改变实际组价。
首次选择可跨合同组；`CrossGroupRetry=false` 时后续限定首次实际选中组，true 时可在合同内跨组。
原生重试次数、错误可重试性、pin、已发送 attempt 和 unknown 闸门继续有效。

Seedance、素材代理和 Azure Batch 保持各自确定性入口与协议资格；Seedance 不使用权重/亲和/失败换渠。
类型化渠道不因缺少 Ability 而误拒绝，但合同渠道失效时也不使用范围外的替代渠道。

## 4. 计费与任务生命周期

```text
客户模型费用 = 原生模型费用小计 × 实际执行组的有效原生倍率 × 合同模型折扣
```

合同折扣只作用于模型费用；工具费、违规费、充值和 Provider 成本沿用既有边界。
`ContractBillingFact` 只冻结用户、合同身份/名称/版本、精确模型与折扣；组和渠道从真实选中结果冻结。
同模型换渠道不重选或重复叠乘折扣。

普通同步重试使用已解析的模型基础价格刷新组相关预估；表达式使用原有冻结表达式与请求条件。
Task 重试保留第一次估算的价格/表达式事实及业务乘数，仅刷新选中组。较高预估在同一个
`BillingSession` 补充预扣，较低预估不提前释放，终态按实际金额结算。免费转付费建立会话，
付费转免费保留既有会话。预估值不冒充实际 hold；信任旁路、钱包欠费、订阅和 Key 策略仍由原生
资金会话决定。资金错误阻止下一次外发。quota 使用统一严格/checked 转换，不能溢出为负消费。

durable attempt、异步图片受理和 Batch 继续各自事务持有资金，不叠加请求级预扣。已发送/unknown
不得自动重发、换渠道或退款。已有 Task 的查询、恢复、交付、结算不重套当前合同；创建时冻结事实继续有效。
已发布的历史任务/文件读取、交付和取消入口不检查当前用户/Key 的选路组，也不读取当前合同；
身份、Key 启停/有效期/IP 等检查及资源所属用户/应用校验继续生效。该例外按具体资源入口识别，
不能把所有 GET/DELETE 都视为历史访问；模型发现、素材代理和 Realtime 仍走当前授权。
新的 remix/continuation 和 Midjourney 派生调用在原生归属和原渠道锁定之后校验当前合同；范围外拒绝，不切换渠道。
范围内使用本次合同组、当前折扣与新计费事实；只继承原生要求的时长等业务参数。

## 5. 发现、报价与客户明细

绑定启用合同的 Key 模型列表/详情从合同有效范围取得，保留原生价格配置和 Key 模型限制；能包含
Key 默认组以外的有效合同模型。未列或不可用模型不通告调用资格，读取失败明确报错。
合同模型限制统一使用 `ContractTokenModelAllowed`；模型列表不在合同投影后执行不同口径的重复过滤。
发现响应内复用一次有效规则读取；元数据按去重渠道分批读取，报价折扣索引每次投影只构建一次。
全站目录和未显式选择合同的会话保持原生投影；会话选择合同须校验归属，停用合同不冒充生效报价。

`/api/pricing` 按普通/Batch 执行模式校验实际合同来源，再叠加一次折扣。每个模型的 `enable_groups`
和有效 `group_ratio` 只含合法合同组合。基础价格、普通/Batch 候选和响应组信息从合同有效来源
投影，不得先经过用户可用组或 Key 保存组过滤；原生 auto 组不参与合同报价。不同组倍率按现有公开组维度展示，不承诺最低价必然成交。
不返回内部渠道 ID、Provider 或上游模型身份。

Key 合同明细按模型去重，保留全部约定折扣；`availability` 标明 `available / unavailable / disabled`，
不返回 `group_denied` 或管理端 `group_allowed`；内部组未向普通 Key 开放不构成合同不可用。Key 编辑界面同时提示自身模型限制，不在前端复制服务端通配符匹配算法。
加载失败与无绑定/停用分开处理。管理员保留完整来源明细，可见渠道可用性与当前价格预览。

## 6. 写入、审计和管理

创建与完整替换仍只有合同实体写接口。`expected_version`、`lockForUpdate`、八位折扣校验、版本递增、
规则替换和审计在同一事务完成；提交后发布缓存。历史已接受的来源失效不阻止修改、停用或重新启用，
但运行时会排除这些来源；“可保存”不等于“可履约”。停用保留绑定、规则与审计，没有硬删除。

管理员总览和用户摘要只是只读投影，启用状态不保证所有组合可用。规则数按渠道规则计，模型数单独去重。
旧用户级合同迁移不在运行时双读；新请求以迁移后的实体和绑定为准。
本次范围政策无需新增数据表或索引迁移；原同模型多渠道唯一索引迁移保留三库兼容和幂等性。

## 7. 最小接线与上游同步

| 原生接线面 | 必要性及冲突边界 |
| --- | --- |
| `middleware/auth.go` | 身份通过后区分历史资源访问与新调用，决定是否沿用 Key 保存组选路检查 |
| `middleware/distributor.go` | 启用合同进入专属候选编排；无合同分支保持原样 |
| `service/channel_select.go` | 重试入口进入同一合同范围政策 |
| `model/channel_cache.go`、`model/ability.go` | 只替换候选读取，不复制或改写优先级/权重算法 |
| `dto/channel_constraints.go`、`model/channel_constraint.go` | 新增允许组合过滤，pin 和候选读取共享范围 |
| `model/public_image_model_api.go` | 只读元数据增加合同来源过滤；复用既有协议描述及优先级投影 |
| `relay/mjproxy_handler.go` | 新派生操作在晚绑定原渠道后、计费与外发前校验合同范围 |
| `controller/token.go` | 编辑合同 Key 时保留未改变的原生 Auto 配置，仅增加一处保存接线 |
| `controller/model.go` | 发现/详情采用合同有效范围；无合同保留原生投影 |
| `controller/relay.go`、`relay/relay_task.go` | 原渠道解析后校验范围、发送前组价/资金接线 |

主体均在独立 `customer_contract_*` 文件；合同 CRUD、价格覆盖、Seedance、素材和 Batch 在现有
本地扩展文件接入。未来接取上游时只复核这些调用点及原生选择/资金接口，不做无关重构。
验证入口与上线限制见[开发与验证指南](../30-engineering/用户模型合同开发与验证.md)。
