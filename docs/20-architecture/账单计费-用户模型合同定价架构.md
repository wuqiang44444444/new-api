# 用户模型合同定价架构

## 1. 边界与事实源

客户合同是按合同实体生效的增强授权与客户定价层。一个用户可持有**多份合同**，每份合同表达：

```text
精确公开模型 + 具体渠道（Channel ID） + 唯一路由组 + 八位定点合同折扣
```

主数据库中的 `customer_contracts`（合同实体）、`customer_contract_entity_rules`（合同规则）、
`customer_contract_entity_audits`（审计）和 `tokens.contract_id`（Key 绑定引用）是合同事实源。
`users.contract_mode`/`contract_version` 是存量迁移前的历史列，仅作迁移数据源与历史保留，
不再参与请求时授权。Redis、进程缓存、鉴权缓存和前端状态均可重建。

授权以 **Key 绑定**为范围：`tokens.contract_id = 0` 的 Key 完整走原生路径，不读取任何合同表；
绑定了启用合同的 Key 走合同授权路径；绑定的合同已停用时该 Key 恢复原生逻辑（绑定关系与原组
设置保留）。合同读取失败或绑定数据异常失败关闭，绝不回退原生。

合同不替代 NEWAPI 原生模型、Group、Ability、Channel、分发或计费语义，而是在明确的本地接线点
收窄授权、固定具体渠道并对模型费用小计应用客户折扣。

## 2. 身份、匹配与路由

合同匹配使用客户端请求中的精确公开模型名（`OriginModelName`）：

1. Token 鉴权取得 `tokens.contract_id` 与用户 `auth_version`；
2. 合同快照按 `contract_id` 读取，缓存以 `auth_version` 作 fence；
3. 精确模型白名单与 Token 模型限制取交集；
4. 命中规则后把 `UsingGroup` 固定为合同 `route_group`，并以 `ChannelPin`
   （`PinSourceContract`，`PinRetrySingleAttempt`）把执行渠道固定为规则的 `channel_id`；
5. 不做组内原生随机选渠；原生分发通过 `channelSatisfiesCustomerContract` 验证组、模型、具体渠道和
   启用状态。Seedance 在专属入口检查最终 pin 与合同渠道一致，再由带渠道 ID 的
   `GetEnabledSeedanceChannel` 查询执行同样约束，不增加二次查库；不满足即失败关闭。

合同不能通过 Token 固定组、AutoGroups、Playground、Affinity、指定 Channel 或跨组重试扩大权限。
Seedance 渠道可作为合同规则的绑定渠道，但其一模型一 Channel 约束不变；Azure Batch 渠道同样可
以被合同规则绑定，但规则无法由 Batch 渠道履约时在预扣前明确拒绝，不回退普通池。

## 3. 持久化与事务

### 3.1 数据结构

| 事实 | 结构 | 不变量 |
| --- | --- | --- |
| 合同实体 | `customer_contracts` | 归属一个 `user_id`；`enabled`、单调 `version`、客户可读名称 |
| 合同规则 | `customer_contract_entity_rules` | `UNIQUE(contract_id, public_model)`；`ratio_units` 为 `1..100000000`；必须绑定具体 `channel_id` + `route_group` |
| Key 绑定 | `tokens.contract_id` | 可空（0 = 未绑定）；只能绑定当前用户自己的合同 |
| 审计 | `customer_contract_entity_audits` | 只追加；before/after 使用 `common.Marshal` 保存脱敏快照；`operation` 含 create/update/enable/disable/migrate |

同一用户可持有多份合同，同一模型可出现在不同合同中并绑定不同渠道与折扣；同一份合同内客户模型
唯一（大小写精确，写入拒绝仅大小写不同的重复）。规则不保存“当前不可用”状态；可用性由当前
Channel/模型事实派生。

### 3.2 完整替换事务

合同写入只有 `PUT /api/contract/:contract_id` 一个权威接口（创建走
`POST /api/user/:id/contract`）。提交 `expected_version`、名称、启停、完整规则集和必填原因。
服务端在一个事务中：

1. 保存前校验每条规则的渠道资格：渠道启用、路由组一致、能服务该模型（普通渠道查 Ability，
   Seedance 查专用渠道清单）；
2. `lockForUpdate` 锁定合同行并比较版本；
3. 增加现有 `auth_version` 失败关闭围栏（失效所有绑定 Key 的合同缓存）；
4. 替换规则、写入新版本；
5. 写入脱敏审计；
6. 提交后刷新鉴权缓存并失效本进程合同缓存。

任一步失败都不留下部分规则。停用只关闭 `enabled` 并保留规则；绑定该合同的 Key 自动恢复原生
逻辑；重新启用必须重新校验全部规则。首期不提供硬删除。

## 4. 缓存与失败关闭

合同读取只有三态：

```text
native                 Key 未绑定，或绑定的合同已停用
contract(snapshot)     绑定的合同启用且 auth_version 与缓存一致
error                  数据库、缓存、版本或快照异常
```

只有 `native` 可以进入原生路径。缓存 miss 回源主数据库；主库失败、快照损坏、版本不一致、
比例非法、规则重复或目标模型当前不可履约时均返回错误，不回退到原生权限、旧合同或倍率 `1`。
合同缓存按 `contract_id` 组织，以用户 `auth_version` 为 fence：每次合同写入都递增该版本，
因此任何进程中的陈旧条目都不能通过缓存复用。

## 5. 模型发现、价格与异步事实

Token 鉴权的 `/v1/models`、模型详情与 `/api/pricing` 只投影调用 Key 所绑定合同的精确规则、
当前可用性和合同折后价格；读取失败返回失败，不显示原生列表或原生价格。会话控制台
（DashboardListModels、自服务合同页）按用户分别展示其全部合同。普通用户不看到渠道、路由组、
Provider、上游模型或特殊组倍率；管理员合同抽屉为低频配置面，可以使用内部渠道标识。

同步请求在模型费用小计和完整原生组倍率完成后乘合同折扣；工具费、违规费、充值折扣和 Provider
成本不参与。折扣使用 `ContractBillingFact` 的八位定点事实（含 `contract_id` 与 `channel_id`），
最终 quota 仍走统一 checked 饱和函数。

异步 attempt/Task 在发送前或创建时冻结：客户模型、合同 ID、合同版本、公开模型、绑定组、具体
渠道、合同折扣、原生组倍率、表达式/价格版本、资金来源和协议快照。终态只补齐可信实际用量；合同
变化、原生价格变化、规则删除或 Key 换绑不影响已创建任务。没有合同事实的原生/历史 Task 继续使用
原有语义，不由当前合同反向推断。

## 6. 管理员合同总览

`GET /api/customer-contracts` 是只读聚合投影，以合同实体为行：用户、合同名、状态
（active / zero_access / inactive）、版本、规则数、不可用规则数、绑定 Key 数与最近审计操作人。
接口服务端分页，支持 User ID/用户名/显示名/合同名/公开模型关键词与状态筛选；摘要统计不受当前
筛选影响。删除用户的合同不出现在总览。响应不返回凭据、Provider 或上游模型身份。

存量迁移（旧用户级规则 → 合同实体 + Key 绑定）由 `GET /api/customer-contracts/migration/preview`
与 `POST /api/customer-contracts/migration` 支撑：预览列出每条旧规则的渠道候选，唯一候选自动
映射，零或多候选必须管理员显式指定；迁移把用户全部存量 Key 绑定到迁移合同，保留启停状态与折扣
精度，不改写 Key 原组，且每用户至多执行一次（幂等）。迁移前必须完成数据库备份与离线预检；
应用运行时不读取旧用户级规则（无双读路径），旧规则行仅作为历史与迁移数据源保留。

## 7. 变更性质：NEWAPI 原生窄接线与本地优化

| 接线面 | 性质 | 必要性与边界 |
| --- | --- | --- |
| `middleware/auth.go` | 原生鉴权的必要字段接线 | 写入 `ContextKeyTokenContractId`（来自 Token 列）；不在鉴权层查询合同规则 |
| `middleware/distributor.go`、`middleware/customer_contract.go` | 原生分发前的必要窄守卫 | 解析合同事实、固定组并以 `ChannelPin` 固定渠道；不复制分发实现 |
| `dto/channel_constraints.go` | 新增 `PinSourceContract` 常量 | 合同渠道钉住的可观测来源标识 |
| `controller/model.go`、`controller/pricing.go` | 原生投影入口的早返回优化 | 有绑定合同的 Key 返回专用投影；未绑定 Key 保持原路径 |
| `relay/helper`、Task 计费接线 | 原生计费/异步热路径的最小乘数与快照接线 | 只对存在 `ContractBillingFact` 的请求生效，原生 nil fact 原样返回 |
| `model/customer_contract*.go`、`service/customer_contract*.go`、`types/customer_contract.go` | 本地新增权威实现 | 承载合同实体、规则、事务、缓存、审计、迁移、计费事实，不扩写原生文件 |
| `web/src/features/customer-contracts/`、`web/src/features/users/`、`web/src/features/keys/` | 本地管理界面与 Key 绑定选择 | 合同实体 CRUD、迁移入口、Key 合同选择、价格详情复用 |

上述原生文件改动仅为接线或早返回；业务判断、数据模型、验证和测试均隔离在新增文件，以降低未来
接取上游时的冲突面。

## 8. 架构不变量

1. Key 未绑定或绑定合同停用时，不读取合同规则，也不改变 NEWAPI 原生模型发现、路由和计费。
2. 合同只授权精确公开模型，并固定一个具体渠道与一个路由组；不使用通配、候选交集或请求时模型名
   推断。
3. 合同读取、缓存、版本和可用性异常均失败关闭，不回退到原生或旧快照；绑定数据异常不是“未绑定”。
4. 合同折扣只作用于模型费用小计，工具费、违规费、充值折扣和 Provider 成本保持独立。
5. 异步任务按创建时冻结合同与原生计费事实完成生命周期，历史任务不重定价；Key 换绑不影响在途
   任务。
6. 管理员总览与迁移预览是只读投影；合同写入只有实体替换一个权威接口；迁移每用户至多一次且多
   候选渠道必须显式决策。
7. 主数据库是合同、审计、Task、资金和日志事实源；缓存与前端状态可重建。
