# 用户模型合同定价架构

本边界的长期取舍见 [ADR-0019](decisions/0019-合同解耦为客户折扣层.md)。

## 1. 边界与事实源

客户合同是按合同实体生效的**客户折扣层**。合同只提供折扣，不影响模型权限、分组、渠道选择、优先级、
权重、重试和任何既有分发逻辑。一个用户可持有**多份合同**，每份合同表达：

```text
精确公开模型（可对应多个渠道来源）+ 唯一合同折扣
```

主数据库中的 `customer_contracts`（合同实体）、`customer_contract_entity_rules`（合同规则）、
`customer_contract_entity_audits`（审计）和 `tokens.contract_id`（Key 绑定引用）是合同事实源。
`users.contract_mode`/`contract_version` 是存量迁移前的历史列，仅作迁移数据源与历史保留，
不参与请求时授权。Redis、进程缓存、鉴权缓存和前端状态均可重建。

授权以 **Key 绑定**为范围：`tokens.contract_id = 0` 的 Key 不读取任何合同表；绑定了启用合同的 Key
在请求时按精确公开模型解析折扣；绑定的合同已停用时该 Key 只是不再获得折扣（绑定关系保留）。
合同读取失败或绑定数据异常失败关闭，绝不静默按原价处理。

合同不收窄也不扩大 NEWAPI 原生模型、Group、Ability、Channel、分发或计费语义：同一请求即使选中了
合同管理明细中不存在的渠道，仍然获得该公开模型的合同折扣。

## 2. 身份、匹配与执行边界

合同折扣按客户端请求中的精确公开模型名（`OriginModelName`）解析：

1. Token 鉴权取得 `tokens.contract_id` 与用户 `auth_version`；
2. 合同快照按 `contract_id` 读取，缓存以 `auth_version` 作 fence；
3. 启用合同包含该模型时冻结 `ContractBillingFact`（用户、合同 ID、合同版本、公开模型、定点折扣）；
4. 合同不设置或覆盖 `UsingGroup`、`TokenGroup`、AutoGroups、跨组重试，不添加渠道 pin，不筛选
   候选渠道，不参与 Affinity 或指定渠道仲裁；
5. 渠道选择、入口验证、Token 模型限制、用户组权限全部沿用原生路径；绑定合同不豁免任何原生校验。

三种解析结果必须区分：

| 状态 | 结果 |
| --- | --- |
| 启用合同列出该模型 | 折扣事实（同模型多条渠道规则必须给出同一折扣） |
| 启用合同未列出该模型 | nil 事实，原生计价，不拒绝请求 |
| 读取、归属、版本或折扣一致性异常 | 计费前失败关闭，不按原价、旧折扣或倍率 1 处理 |

计费顺序保持：

```text
客户模型费用 = 原生模型费用小计 × 实际有效原生组倍率 × 合同模型折扣
```

实际有效组倍率来自既有分组规则（含特殊组倍率）与真实执行上下文，不来自合同明细的 `route_group`。
合同明细中的 `channel_id`、`route_group` 只是管理配置来源，不参与运行时折扣匹配，也不得覆盖实际
执行渠道或组。折扣只在请求受理时冻结一次，原生重试换渠道时不重新读取、不重复叠乘。

合同规则可以绑定 Seedance、Azure Batch 类型化渠道，也可以绑定普通渠道；这只说明折扣的配置来源，
不改变各入口的资格、选渠与计价方式。同一模型的普通与类型化渠道规则在折扣相同时可以共存。
Seedance 保留一个已启用客户模型只对应一个 Seedance Channel 的约束。

## 3. 持久化与事务

### 3.1 数据结构

| 事实 | 结构 | 不变量 |
| --- | --- | --- |
| 合同实体 | `customer_contracts` | 归属一个 `user_id`；`enabled`、单调 `version`、客户可读名称 |
| 合同规则 | `customer_contract_entity_rules` | `UNIQUE(contract_id, public_model, channel_id)`；`ratio_units` 为 `1..100000000`；同一合同同一公开模型的所有规则折扣一致；模型名大小写精确，拒绝仅大小写不同的重复 |
| Key 绑定 | `tokens.contract_id` | 可空（0 = 未绑定）；只能绑定当前用户自己的合同 |
| 审计 | `customer_contract_entity_audits` | 只追加；before/after 使用 `common.Marshal` 保存脱敏快照；`operation` 含 create/update/enable/disable/migrate |

同一公开模型在一个合同内可绑定多个渠道来源，前提是所有规则折扣相同；同模型同渠道重复（即使
`route_group` 不同）被拒绝。折扣相等按八位定点 `ratio_units` 判断，不比较输入文本或浮点近似值。

### 3.2 完整替换事务

合同写入只有 `PUT /api/contract/:contract_id` 一个权威接口（创建走
`POST /api/user/:id/contract`）。提交 `expected_version`、名称、启停、完整规则集和必填原因。
服务端在一个事务中：

1. 规范化并校验完整规则集：模型名、路由组、折扣范围、同模型折扣一致、同模型同渠道不重复；
2. `lockForUpdate` 锁定合同行并比较版本；
3. 只对**新增或变更的来源**（`(public_model, channel_id, route_group)` 三元组未存储）校验渠道引用
   合法性及当前组倍率存在性；已被接受的来源后续不可用或原组被删除时，不自动取消折扣，也不阻止保存其他折扣或重新启用合同，
   即“所有明细渠道当前可履约”不是合同生效条件；
4. 递增现有 `auth_version` 失败关闭围栏（失效所有绑定 Key 的合同缓存）；
5. 替换规则、写入新版本；
6. 写入脱敏审计；
7. 提交后刷新鉴权缓存并失效本进程合同缓存。

任一步失败都不留下部分规则。停用只关闭 `enabled` 并保留规则；绑定该合同的 Key 只是失去折扣，
模型权限与路由本就由原生机制决定。首期不提供硬删除。

### 3.3 索引迁移

历史唯一索引 `idx_cc_entity_rule_contract_model`（`contract_id, public_model`）由
`migrateCustomerContractEntityRuleIndex` 在 AutoMigrate 之前显式删除（SQLite、MySQL、PostgreSQL
同构，幂等，无标记行），随后 AutoMigrate 创建
`idx_cc_entity_rule_contract_model_channel`（`contract_id, public_model, channel_id`）。既有单渠道
规则数据无需改写，在新唯一索引下保持有效。

## 4. 缓存与失败关闭

合同读取只有三态：

```text
native                 Key 未绑定，或绑定的合同已停用（或启用合同未列出该模型）
contract(snapshot)     绑定的合同启用且 auth_version 与缓存一致
error                  数据库、缓存、版本或快照异常
```

缓存 miss 回源主数据库；主库失败、快照损坏、版本不一致、比例非法或同模型折扣不一致均返回错误，
不回退到原生价格、旧合同或倍率 `1`。合同缓存按 `contract_id` 组织，以用户 `auth_version` 为 fence：
每次合同写入都递增该版本，因此任何进程中的陈旧条目都不能通过缓存复用。

## 5. 模型发现、价格与异步事实

`/v1/models`、模型详情、控制台模型选择器保持原生权限与入口可用性投影；合同不收窄也不扩大模型
清单。API 密钥处的合同折扣明细按公开模型去重，仅展示“模型 + 合同折扣”，不展示渠道名称、渠道 ID、
路由组、Provider 或上游模型；模型当前不可用不抹去其已约定折扣。未绑定、已停用、加载失败三种状态
明确区分，不虚构生效折扣。

`/api/pricing` 对绑定启用合同且读取成功的调用方返回**原生价格投影 + 折扣覆盖**：可访问模型、执行
模式与组倍率先按原生语义展示，已约定模型附加 `contract_discount` 及按组的有效倍率覆盖（原生组倍率
× 合同折扣）；未约定模型保持原生价格。投影不暴露内部渠道身份。
显式 `execution_mode=batch` 先读取独立 Batch 模型与表达式，再应用合同折扣，不能取同名同步价格。
会话显式选择停用合同返回失败，绑定停用合同的 Key 沿用原生价格。管理员来源预览依据渠道类型区分
普通与 Batch 基础价，组倍率仍来自管理明细上下文，不等同于实际请求成交价。
客户明细去重只在后端完成；HTTP 200 的 `success:false` 同样是读取失败，前端不将其显示为无合同或停用。


同步请求在模型费用小计和完整原生组倍率完成后乘合同折扣；工具费、违规费、充值折扣和 Provider
成本不参与。折扣使用 `ContractBillingFact` 的八位定点事实（含 `contract_id` 与 `contract_version`，
不含渠道与组），最终 quota 仍走统一 checked 饱和函数。日志只记录 `contract_version` 与
`contract_discount`。

异步 attempt/Task 在发送前或创建时冻结：客户模型、合同 ID、合同版本、公开模型、合同折扣与实际执行
的组、渠道、原生组倍率、表达式/价格版本、资金来源和协议快照。合同事实只负责折扣；实际执行字段从
真实执行上下文取得，不从合同管理明细复制。终态只补齐可信实际用量；合同变化、规则删除或 Key 换绑
不影响已创建任务。没有合同事实的原生/历史 Task 继续使用原有语义；旧冻结记录中的渠道和组是历史
事实，不反向参与新请求分发。

## 6. 管理员合同总览

用户列表与搜索仅按 `customer_contracts` 聚合只读 `contract_summary`（`total`、`enabled`），
不把合同规则数解释为整个账号的模型权限。摘要不参与授权或持久化；其实现位于
`model/customer_contract_user_summary.go`，原生用户列表只保留摘要接线。

`GET /api/customer-contracts` 是只读聚合投影，以合同实体为行：用户、合同名、状态（`active` /
`inactive`）、版本、规则数（渠道规则数量）、不可用规则数、绑定 Key 数与最近审计操作人。“规则数”
按渠道规则计；“模型数”如需展示必须单独按公开模型去重，不与规则数混用。启用合同即为 `active`，
规则数不再构成“零模型权限”状态（该状态已随折扣层语义删除）。接口服务端分页，支持 User ID/用户名/
显示名/合同名/公开模型关键词与状态筛选；摘要统计不受当前筛选影响。删除用户的合同不出现在总览。
响应不返回凭据、Provider 或上游模型身份。来源渠道失效仅为管理信息，不解释为 Key 零调用权限。

存量迁移（旧用户级规则 → 合同实体 + Key 绑定）由 `GET /api/customer-contracts/migration/preview`
与 `POST /api/customer-contracts/migration` 支撑：迁移只生成折扣明细与 Key 绑定，不产生运行时渠道
授权；其余幂等与决策约束不变。应用运行时不读取旧用户级规则（无双读路径）。

## 7. 变更性质：NEWAPI 原生窄接线与本地实现

| 接线面 | 性质 | 必要性与边界 |
| --- | --- | --- |
| `middleware/auth.go` | 原生鉴权的必要字段接线 | 写入 `ContextKeyTokenContractId`（来自 Token 列）；合同不再豁免原生 Token 分组校验 |
| `middleware/distributor.go` | 原生分发前的最小折扣解析接线 | 解析合同折扣事实并失败关闭；不固定组、不 pin 渠道、不过滤候选 |
| `relay/helper`、Task/Batch 计费接线 | 原生计费/异步热路径的最小乘数接线 | 只对存在 `ContractBillingFact` 的请求生效，原生 nil fact 原样返回 |
| `controller/pricing.go` | 原生价格入口的早返回投影 | 绑定合同返回原生投影 + 折扣覆盖；未绑定 Key 保持原路径 |
| `dto/channel_constraints.go` | 无合同 pin 标识 | 合同 pin 来源与秩已删除，无兼容别名 |
| `model/customer_contract*.go`、`service/customer_contract*.go`、`types/customer_contract.go` | 本地新增权威实现 | 承载合同实体、规则、事务、缓存、审计、迁移、折扣事实与投影，不扩写原生文件 |
| `web/src/features/customer-contracts/`、`web/src/features/users/`、`web/src/features/keys/` | 本地管理界面与 Key 绑定选择 | 合同实体 CRUD、迁移入口、Key 合同选择与折扣明细展示 |

## 8. 架构不变量

1. 合同只提供折扣：不改变 NEWAPI 原生模型发现、权限、分组、选渠、优先级、权重、Affinity、重试，
   不写入 pin、组覆盖或候选过滤；绑定合同前后相同请求的原生选渠结果一致。
2. 合同折扣按精确公开模型解析；同模型多条渠道规则必须同折扣；未列出模型回退原生价格而非拒绝。
3. 合同读取、缓存、版本和折扣一致性异常均失败关闭，不回退到原生价格或旧快照；绑定数据异常不是
   “未绑定”。
4. 合同折扣只作用于模型费用小计；实际有效组倍率来自真实执行上下文，不来自合同明细。
5. 异步任务按创建时冻结的合同折扣与实际执行事实完成生命周期，历史任务不重定价；Key 换绑不影响
   在途任务，旧冻结记录不重解释为新请求的路由限制。
6. 管理员总览与迁移预览是只读投影；合同写入只有实体替换一个权威接口；渠道引用校验只针对新增或
   变更来源，存量来源不可用不阻止保存或重新启用。
7. 主数据库是合同、审计、Task、资金和日志事实源；缓存与前端状态可重建。
