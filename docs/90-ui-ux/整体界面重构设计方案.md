# TokenAI 整体界面重构设计方案

本文定义公开站、客户控制台和管理后台的界面设计目标。首轮用模型广场、我的用量、视频 Playground 和渠道管理四个页面验证导航、数据视图、异步任务和复杂表单。四张图为桌面浅色概念稿，使用示例数据和临时品牌图形。页面与功能的当前状态见[页面清单](页面清单.md)。

## 1. 信息架构

| 界面 | 一级入口建议 | 用户要完成的事 |
| --- | --- | --- |
| 公开站 | 首页、模型广场、API 文档、登录或控制台 | 了解服务，确认模型能力与价格，找到接入示例 |
| 客户控制台 | 概览、API Key、体验与任务、素材、我的用量、我的账单、账户 | 完成首次调用，跟踪任务与结果，按 Key 核对消耗 |
| 管理后台 | 渠道与模型、客户与合同、用量与对账、日志与审计、系统设置 | 验证渠道配置，处理异常，核对费用与权限 |

- 首页延续蓝色商务风格，首屏突出快速接入，根据会话状态提供获取 Key 或进入控制台的主操作。公开文档沿用[文档中心交互规范](API文档中心交互规范.md)的导航、搜索和响应式结构。
- 实现时从现有站点品牌配置读取 Logo 和名称，沿用现有署名与授权展示。
- 客户与管理界面复用同一控制台布局，授权用户可从导航进入对应区域。管理员进入个人用量和账单时，数据范围仍是本人。
- 一级分组表达用户任务，子页面保留可直达入口。支持 URL 筛选的页面在返回和刷新时恢复筛选，切换筛选后从首页开始分页。菜单隐藏和直达访问均遵守现有站点设置、模块开关和角色权限。

## 2. 视觉与组件

| 项目 | 设计规则 |
| --- | --- |
| 颜色 | 沿用[首页样式示例](首页样式设计示例.md#61-颜色)的业务蓝 `#0B6BEA`、画布 `#F8FAFC`、白色面板、墨蓝文字 `#0F2744`、弱边框 `#DDE5EF`。浅色主题的辅助正文采用 `#56677D`，以便覆盖浅色画布及次级底色。主题仍通过语义 CSS 变量表达。 |
| 排版 | 使用现有字体与中英文回退栈。控制台页面标题建议 `28/36`，章节标题 `16/24`，正文 `14/22`，次要信息 `12/18`。等宽用于代码和 ID，表格金额与数值右对齐并使用等宽数字。 |
| 间距 | 以 `4px` 为基础，控制台主内容桌面内边距 `24–32px`、窄屏 `16px`。公开站留出更多浏览空间，管理端列表行高建议 `44px` 起。 |
| 层级 | 主操作使用实心蓝，次操作用描边或文字。用标题、对齐与分隔线组织信息。状态显示文字，并按语义配色或配图标。复杂表单分组，可滚动内容与保存区分开。 |
| 组件 | 沿用 [shadcn/ui Base Nova 配置](../../web/components.json)及[项目 UI 组件](../../web/src/components/ui/)。导航使用 `Sidebar`、`Breadcrumb`，页内切换使用 `Tabs`，筛选使用 `Combobox`、`Select`，数据表复用现有 `Table`、分页和 TanStack Table 组合，编辑使用 `Sheet`、`Field`，确认使用 `AlertDialog`，状态使用 `Badge`、`Alert`、`Empty`、`Skeleton`。 |

桌面端常驻可折叠侧栏，窄屏由菜单打开。筛选工具栏可换行，长表格保留列标题、单位和关键字段，可在容器内横向滚动。桌面编辑抽屉使用独立滚动区，窄屏占满宽度。键盘可遍历全部主要操作，关闭弹层时恢复触发点焦点，校验失败将焦点移到首个错误字段。正文字色与底色对比度至少 `4.5:1`。深色主题沿用同一套状态语义，交付时单独检查图表、焦点和状态文字。用户可见文案维护简体中文与英文。

## 3. 首轮四个页面

### 模型广场

![模型广场设计稿](assets/ui-redesign/model-catalog.png)

- 页面按「标题 → 模态切换 → 搜索与排序 → 模型结果」组织。默认全模态，提供文本、图片、视频、音频切换，细项筛选以公开模型元数据为准。保留列表与紧凑表格切换，窄屏把细项收进筛选面板。
- 主列表包含客户模型名、简述、公开能力和价格单位。详情页提供字段说明、代码示例及相应的体验入口。可见价格按其公开口径展示，专属合同价格沿用 API Key 合同视图。
- 搜索无结果时可清除条件。站点状态待确认、模块停用和需要登录时分别沿用现有[模型广场可见性规则](页面清单.md#模型广场)。客户侧展示客户模型与公开能力，模型筛选和详情使用同一数据口径。

### 我的用量

![我的用量设计稿](assets/ui-redesign/customer-usage.png)

- 页面顶部使用日、周、月切换、期间选择和 API Key 筛选。页头注明北京时间、快照时间与数据发布状态。摘要先呈现净费用、调用数与失败数、总 Token，随后按各自计量单位列出非 Token 用量。
- 月视图先看趋势与逐日数据，再按调用数、总 Token 或净费用检查模型排行。选择日期或模型时，在支持下钻的入口携带周期、Key、模型及报表版本。我的账单沿用独立月账期，明确区分用量归属日与费用入账日。
- 空结果、已发布零用量、未发布、部分数据和未记录分别展示。当日阶段性数据标注估算。导出提交与当前筛选和报表版本一致，并可从已有导出记录查看进度和取回文件。口径与权限见[使用日志与报表产品设计](../10-product/使用日志与报表产品设计.md)。

### 视频 Playground

![视频 Playground 设计稿](assets/ui-redesign/video-playground.png)

- 桌面左侧为客户模型、提示词、参考素材和参数，右侧为结果与任务反馈。窄屏按输入、提交、结果顺序排列。表单取已发布的 ModelArk V3 字段与公开能力数据，提交前校验合法输入。
- 平台托管素材通过授权素材选择器引用，已有上游素材使用显式引用输入。两类入口各自遵循实际素材合同。API 示例使用同一北向请求语义，示例密钥和域名使用占位符。
- 提交期间防止重复提交。收到可信任务标识后展示任务记录，进度使用已返回的状态。结果待核实时保留已知信息并提供状态说明，避免把观测错误改写为业务失败。视频成功但制品暂不可取时，分别说明执行状态和交付状态。预览和下载使用现有授权入口。
- 交互与[视频和素材产品设计](../10-product/Seedance视频与素材产品设计.md)、[ModelArk V3 北向合同](../20-architecture/Seedance专用渠道与Link架构.md#6-modelark-v3-北向合同)对齐。Playground 画面代表设计目标，验证范围按对应模型与制品能力确定。

### 渠道管理与编辑抽屉

![渠道管理与编辑抽屉设计稿](assets/ui-redesign/channel-management.png)

- 列表提供名称搜索、类型与状态筛选，优先显示渠道名称、接入方式、启停、模型摘要和最近检查。行级菜单提供已授权的编辑与操作。打开右侧抽屉后保留列表的筛选、分页和滚动位置。
- 抽屉按基本信息、连接与凭据、模型映射、进阶设置排布。渠道类型决定可见字段和操作。Seedance 编辑场景展示客户模型到上游模型的映射及已注册协议，说明该客户模型使用唯一启用渠道。普通渠道沿用其已有配置能力。
- 已保存凭据显示设置状态，字段异常与保存错误就地呈现。保存失败保留草稿。素材租户替换在原抽屉显示字段差异并沿用既有确认。可用的探针展示实际检查结果，无对应能力时标为不支持。高级区的默认素材组操作仅在满足现有条件时出现。详见[渠道交互模式](交互模式.md#代码协议字段)。

## 4. 推广顺序与验收

1. 用四张首轮画面确认视觉令牌、公开导航、控制台侧栏、筛选表格与详情抽屉。延伸至首页、文档、登录和常见错误页面时复用这些规则。
2. 顺着客户路径完善「发现模型 → 创建 API Key → 查看示例 → 运行视频并查看结果 → 查看用量与账单」，涵盖账号、余额、任务和素材相关入口。
3. 顺着管理员路径完善「筛选渠道 → 编辑并保存 → 核对运行日志 → 查看对账」，覆盖客户与合同、定价、审计和系统设置。

| 验收项 | 可观察结果 |
| --- | --- |
| 响应式 | 1440px、1024px、390px 三类视口可完成首轮主要任务，窄屏筛选、表格、抽屉和固定操作区不互相遮挡。 |
| 权限与合同 | 匿名用户、普通客户和管理员分别验证导航与直达访问。客户视图和导出使用公开客户字段，任务按原有授权和状态规则展示。 |
| 操作恢复 | 刷新能恢复已支持的筛选，返回恢复列表上下文，失败保留可继续编辑的内容。暗色与中英文视图保持焦点和标签可读。 |
| 异常状态 | 覆盖加载、空数据、部分数据、未发布、错误、无权限、结果待核实和结果不可用。金额、单位和状态与相应的后端事实一致。 |

## 5. 参考案例

- 公开接入与模型查找参考 [Vercel AI Gateway](https://vercel.com/ai-gateway) 和 [OpenRouter Models](https://openrouter.ai/models) 的入口与筛选组织。
- 用量与账单参考 [OpenRouter Activity](https://openrouter.ai/blog/announcements/activity-dashboard/) 的图表下钻和 [Stripe 对账报表](https://docs.stripe.com/reports/balance) 的汇总、明细与导出路径。
- 视频体验参考 [fal 视频模型页](https://fal.ai/models/fal-ai/veo3.1/image-to-video) 的输入、结果与 API 入口。后台参考 [Portkey 日志](https://portkey.ai/docs/product/observability/logs) 和 [LiteLLM 管理界面](https://docs.litellm.ai/docs/proxy/ui) 的列表排障与配置入口。
