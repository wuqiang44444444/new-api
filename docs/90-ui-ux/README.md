# 90-ui-ux — 页面与交互

## 目标

让产品、设计和开发人员能够基于同一套页面结构、交互状态和可访问性约定实现管理端与用户端体验。

## 放什么

- 信息架构、页面与屏幕清单；
- 表单、列表、任务、素材、账单和管理配置的交互模式；
- 加载、空、成功、失败、无权限和不可用状态；
- 组件、响应式布局、键盘操作和可访问性约定。

## 关键文档

- [页面清单](页面清单.md)
- [交互模式](交互模式.md)
- [API 文档中心交互规范](API文档中心交互规范.md)
- [用户模型合同管理界面](用户模型合同管理界面.md)

## 不放什么

- 产品角色、业务流程和可观察验收，放入 `10-product/`；
- 后端架构、协议和数据模型，放入 `20-architecture/`；
- 前端工程命令和编码规则，放入 `30-engineering/`；
- 对外营销文案，放入 `60-marketing/`；
- 临时页面分析和验证截图，放入 `80-dev/`。

## 命名格式

- 使用稳定的中文页面或交互主题，不加日期前缀，例如 `页面清单.md`、`交互模式.md`；
- 文件名应准确说明页面范围或交互对象，避免“UI 设计”“新版页面”等泛化名称；
- 同一交互模式只由一份当前事实文档详细解释，其它页面通过链接引用。

## 内容格式

- 页面清单按用户角色、入口、核心任务、主要状态和权限组织；
- 交互规范按触发、界面反馈、成功、失败、禁用和恢复路径组织；
- 表单必须说明字段含义、默认值、保存/启用校验、错误提示和是否对普通管理员可见；
- 图示和截图只用于补充当前行为，正文必须能够独立说明交互合同。

## 编写要求

- 使用普通用户或管理员能理解的文案，不向界面泄露内部协议、Provider 账号或实现细节；
- 覆盖加载、空数据、部分失败、无权限、超时和移动端等必要状态；
- 所有用户可见文案必须接入项目 i18n，交互必须支持键盘操作和清晰焦点；
- 未实现或未验证的页面不得写成当前可用；实现过程和一次性设计讨论放入 `80-dev/`。
