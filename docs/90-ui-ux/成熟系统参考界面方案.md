# TokenAI 成熟系统参考界面方案

十个方案各选一个代表性界面，覆盖开发者首次接入、模型比较、视频生产、费用核对和管理员排障。设计沿用项目的 shadcn/ui + Base UI，按任务调整导航、首屏优先信息和页面密度。图片展示桌面场景，采用示例数据。角色权限、业务字段与异常状态继承[整体界面重构设计方案](整体界面重构设计方案.md)及对应业务文档。

## 1. 接入首页

![接入首页](assets/ui-redesign/benchmark-home.png)

Vercel AI Gateway 的首屏同时提供获取 Key、阅读文档和接入代码。TokenAI 可用左右布局把「获取 API Key」和可复制的最小调用放在同一屏，再用少量入口通往模型广场和完整文档。适合从访问首页直接开始接入。 [Vercel AI Gateway 首页](https://vercel.com/ai-gateway)

## 2. 模型对比

![模型对比](assets/ui-redesign/benchmark-catalog.png)

OpenRouter 提供模态筛选、价格视图和比较入口，Hugging Face 按任务组织模型发现。TokenAI 可把模型广场的比较视图按同一模态排列为并列规格列，固定展示客户模型名、价格单位、公开输入能力和文档入口。按秒、按次等价格分开标注，避免跨单位误读。 [OpenRouter 模型广场](https://openrouter.ai/models) · [Hugging Face 模型目录](https://huggingface.co/models)

## 3. API 文档工作台

![API 文档工作台](assets/ui-redesign/benchmark-docs.png)

Stripe API Reference 把方法、参数、请求和响应组织在同一操作页。TokenAI 可为 API 参考页加宽代码区，保留左侧文档导航，并把正文、请求例和返回例按正在阅读的操作对齐。图中使用已发布的 ModelArk V3 视频创建入口，创建成功仅返回任务 ID。正式示例从文档构建产物读取。 [Stripe API Reference](https://docs.stripe.com/api/payment_intents/create) · [本站 API 文档中心交互规范](API文档中心交互规范.md)

## 4. 视频生成工作台

![视频生成工作台](assets/ui-redesign/benchmark-video.png)

fal 把模型文档与 Playground 相邻组织，并分出输入和结果。TokenAI 可让预览占据主要空间，右侧固定模型、提示词和素材输入，下方显示已受理任务的状态与交付结果。适合高频调整参数和检查成片。 [fal 视频 Playground](https://fal.ai/models/fal-ai/veo3.1/image-to-video)

## 5. 任务与交付

![任务与交付](assets/ui-redesign/benchmark-tasks.png)

GitHub Actions 从运行记录进入单次执行，再关联步骤与制品。TokenAI 可让用户从最近任务进入一个独立详情页，分开显示执行状态和结果可用性，并在有授权制品时提供下载。时间信息仅展示已有记录，待核实的结果沿用真实状态。 [GitHub Actions 运行日志](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-workflow-run-logs) · [运行制品](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)

## 6. 托管素材库

![托管素材库](assets/ui-redesign/benchmark-assets.png)

Cloudinary Media Library 用缩略图、搜索与类型筛选帮助定位媒体。TokenAI 可按图片、视频、音频浏览账号托管素材，选择后展示授权预览与可用引用。列表仅覆盖本站已有托管资源，调用方自管的上游素材继续按单资源引用处理。 [Cloudinary Media Asset Search](https://cloudinary.com/documentation/dam_media_asset_search) · [本站素材边界](../00-context/硬约束.md#5-link-素材与真人认证代理)

## 7. 用量分析

![用量分析](assets/ui-redesign/benchmark-usage.png)

OpenRouter Activity 可以从图表下钻到筛选后的日志，Grafana 的链接可携带时间范围和当前变量。TokenAI 可让日期和 API Key 筛选统一作用于视图，从日期或模型进入已有明细时携带授权范围和报表版本。设计重点是解释「哪一天、哪个模型」，同时显示数据发布时间及阶段性状态。 [OpenRouter Activity 官方截图](https://openrouter.ai/blog/announcements/activity-dashboard/) · [Grafana Dashboard Links](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/manage-dashboard-links/)

## 8. 月度账单

![月度账单](assets/ui-redesign/benchmark-billing.png)

Stripe 的余额报表按期间组织净额、分类交易和逐笔导出。TokenAI 可先给出账单范围、已入账扣款、退款与净费用，再展示可展开的入账明细。保留 Key、客户模型、计量单位和版本，以便用户核对单笔费用。 [Stripe Balance Summary Report](https://docs.stripe.com/reports/balance) · [本站账单与用量产品设计](../10-product/使用日志与报表产品设计.md)

## 9. 请求日志排障

![请求日志排障](assets/ui-redesign/benchmark-logs.png)

Portkey 支持从请求列表打开侧栏详情，并提供单条日志链接。TokenAI 可保留筛选和滚动位置，用详情侧栏突出请求 ID、可见状态、计费解释和脱敏错误。需单条授权读取的请求证据继续走既有审计入口。 [Portkey Logs 官方截图](https://portkey.ai/docs/product/observability/logs) · [本站安全与数据规则](../00-context/硬约束.md#6-安全与数据)

## 10. 渠道配置

![渠道配置](assets/ui-redesign/benchmark-channels.png)

LiteLLM Admin UI 将模型和上游凭据放在管理界面，Kong Manager 按网关对象承载配置。TokenAI 可把渠道列表和实体配置工作区连起来，以页内章节组织基本信息、协议、模型映射和检查。保留保存草稿与操作上下文，Seedance 的配置和启停沿用当前约束。 [LiteLLM Admin UI](https://docs.litellm.ai/docs/proxy/configuration/ui) · [Kong Manager](https://developer.konghq.com/gateway/kong-manager/) · [本站渠道交互模式](交互模式.md)

## 如何比较

| 想改善的体验 | 建议先对照的界面 | 要验证的任务 |
| --- | --- | --- |
| 开发者自助接入 | 接入首页、模型对比、API 文档工作台 | 找到合适模型，从示例完成首次调用 |
| 视频生产 | 视频生成工作台、任务与交付、托管素材库 | 选择素材，生成视频，回到已完成任务取回结果 |
| 费用与运维 | 用量分析、月度账单、请求日志排障、渠道配置 | 从趋势定位明细，同一筛选下核对费用或检查渠道 |

外部参考采用可访问的公开产品页和官方文档。需要登录的管理页面以官方说明或截图为依据。十张图为视觉设计稿，金额、状态、日期、模型和媒体内容均为示例。

整体界面可以从一个完整路径起步。开发者路径统一顶栏、模型规格行和代码示例，视频路径统一素材选择器、预览区域和交付状态，运维路径统一筛选栏、可排序表格和详情面板。品牌名与标识读取站点现有配置，业务状态和角色权限使用同一套组件语义。
