# TokenAI 整体界面重构备选方案

三套方案延续[整体界面重构设计方案](整体界面重构设计方案.md)的商务蓝与 shadcn/ui + Base UI。对照图使用同一个「我的用量」场景、同一份虚构月度数据和桌面视口，便于比较导航位置、首屏优先信息和下钻方式。品牌标志以实际站点配置为准。

## 概览优先

![概览优先的我的用量设计稿](assets/ui-redesign/usage-overview.png)

全站使用顶栏承载少量一级入口，二级入口放在页内标签。用量首页先给净费用、调用数、失败数和计量摘要，主区左侧展开趋势，右侧直接显示模型费用排行。选择模型后在对应入口查看详情。窄屏先呈现摘要和趋势，再显示排行，一级导航收起为菜单。

适合以快速接入和自助查询为主的客户路径。后台功能增长时，需要把同一工作区的二级入口收在该区域内，避免顶栏拥挤。

## 明细优先

![明细优先的我的用量设计稿](assets/ui-redesign/usage-table.png)

采用深海军蓝侧栏，主页面使用浅色背景。紧凑的筛选工具栏和可排序的模型表占据首屏，净费用和调用情况用短摘要呈现。选中模型时，右侧详情保留当前周期、Key 和客户模型上下文。窄屏优先显示模型、调用和费用，较宽的列在表格容器内滚动，详情可全屏打开。

适合反复筛选、比对、排障的场景。需要给首次使用者保留醒目的摘要和清晰的筛选说明。

## 趋势下钻

![趋势下钻的我的用量设计稿](assets/ui-redesign/usage-drilldown.png)

使用紧凑浅色侧栏，主区以带日期选择的月趋势为视觉中心。选中一个日期后，右侧展示当日摘要与进入明细的操作，下方月度排行保持自己的期间标签。日期选择同时提供键盘可达的列表入口。窄屏把当日详情放到图表后、排行前。

适合需要从费用波动追踪到具体日期、模型或调用的用户。只有图表、日详情和下钻链接都能使用一致的报表范围与版本时，才开放完整联动。

## 推广到首轮页面

| 页面 | 概览优先 | 明细优先 | 趋势下钻 |
| --- | --- | --- | --- |
| 模型广场 | 模态标签和搜索居前，模型列表突出能力与计价单位 | 同屏显示筛选与可排序比较表，优先支持逐列比较 | 选择模型时保留列表上下文，在详情区查看调用示例和价格 |
| 我的用量 | 净费用摘要、趋势与费用排行同屏 | 先看可筛选的模型表，再打开当前模型详情 | 点选日期，核对当日摘要后进入明细 |
| 视频 Playground | 输入与预览并排，主操作集中在生成和查看结果 | 把参数、任务记录和当前状态放在同一个紧凑工作区 | 执行状态与交付状态在结果区并列，任务详情保留当前输入上下文 |
| 渠道管理 | 工作区按渠道状态组织入口，列表保留常用筛选和编辑抽屉 | 渠道列表先展示接入方式、状态、模型与检查结果，行操作随列表可达 | 先从渠道或检查结果打开详情，再进入当前渠道编辑抽屉 |

若优先改善客户上手体验，概览优先适合作为公开站和客户控制台的起点。管理员的渠道、审计和对账页面更适合采用明细优先的表格密度。趋势下钻可集中用在用量和日志之间，减少全站依赖复杂联动的页面数量。

三套方案的任务状态、账单口径、权限和响应式验收均引用[整体方案](整体界面重构设计方案.md#4-推广顺序与验收)。设计图用于比较桌面信息结构，移动端、深色主题和交互状态按正文设计规则评审。
