# TokenAI 首页样式设计示例

## 1. 文档目标

本文档定义 TokenAI 默认首页的一套样式设计示例，作为后续视觉稿、交互原型与 `web/src/features/home/` 实现的讨论基线。

设计参考来自用户提供的 Google AI Studio Playground 截图，只提取其“低干扰工作台、大量留白、弱容器、中心任务、底部操作坞”的视觉语法，不复制 Google 的品牌、导航、产品结构或组件细节。

## 2. 设计范围

### 包含

- 公开首页的桌面端、平板端与移动端视觉规则。
- 首屏、价值入口、快速接入、工具配置、企业能力与页尾的信息层级。
- 颜色、字体、留白、容器、控件、代码块、状态与响应式规则。
- 首页必需的复制、切换、验证反馈与无障碍约束。

### 不包含

- 登录后管理后台的全局改版。
- 模型列表、价格页、密钥管理、用量日志等独立页面的详细交互。
- 固定模型数量、固定模型清单、不可验证的 SLA 数字或绝对化市场表述。
- 项目简报中的对外文案定稿；本文档只定义其在页面中的层级和呈现方式。

## 3. 风格定义

### 3.1 风格名称

**Blue Workspace Minimal（蓝色极简工作台）**

### 3.2 核心气质

- **商务可信：** 使用深海军蓝文字、高明度中性底色与单一业务蓝强调色。
- **现代克制：** 依靠留白、对齐、排版与弱分割建立层次，不依赖大面积渐变、重阴影或装饰动画。
- **工具感而非广告感：** 让首页像可立即开始工作的产品界面，而不是堆叠功能口号的营销长页。
- **低认知负担：** 首屏只呈现一个主任务、一个主操作和必要的支撑信息。

### 3.3 明确禁止

- 不使用紫色、洋红、粉色或蓝紫渐变作为品牌主色。
- 不使用赛博朋克、霓虹光、玻璃拟态、AI 大脑、机器人或装饰性 3D 物体。
- 不默认使用“卡片墙”；优先使用开放画布、分隔线、行和轻量分组。
- 不在卡片中再嵌套多层卡片，不为每一个功能都设置彩色图标。
- 不直接照搬参考截图的侧边栏、文案、图标、组件排列或交互。

## 4. 首页任务与信息层级

首页应帮助用户在一次连续阅读中完成以下理解：

1. TokenAI 同时提供专业模型 Token 服务与企业级 AI 网关。
2. 用户可通过一个统一 API 连接平台当前开放的主流文本、图像、音频与视频模型。
3. 快速开始只需注册或登录、创建 API Key、复制对应协议的 Base URL、选择可用模型并发起最小请求。
4. 企业价值来自多渠道调度、失败重试、权限与额度、透明计费和调用可观测。
5. 配置成功后，用户可在用量日志中验证模型、Token 用量与计费记录。

首页的主转化动作为 **“立即开始”**，企业用户的次要转化动作为 **“企业咨询”**。“查看文档”作为文字链接，不与主操作抢占视觉权重。

## 5. 页面结构示例

### 5.1 桌面端整体框架

- 参考画布：`1440px` 宽。
- 顶部导航：高 `56px`，白色半透明底，使用 `1px` 底部分隔线，滚动后保持吸顶。
- 公共首页不使用参考图中的应用级左侧边栏；其窄导航感通过顶部导航的紧凑尺寸、弱强调和清晰分组表达。
- 主内容画布：最大宽度 `1200px`，居中，左右安全边距为 `24px`。
- 首屏内容顶部留白 `112–144px`，内容带宽度控制在 `720–880px`，形成参考图中“宽画布上的中心任务”。
- 主要段落间距为 `96–128px`，不使用频繁的大面积背景色切换分割页面。

### 5.2 顶部导航

**左侧**

- TokenAI 品牌标识与站点名称。
- 导航：模型服务、价格、开发文档、企业方案。

**右侧**

- 语言切换、主题切换、登录。
- 小型主按钮“开始使用”。

导航文字默认使用中性深色，仅 hover、focus 与当前项进入业务蓝状态。导航不使用彩色徽章、渐变按钮或额外的装饰光效。

### 5.3 首屏：中心开始区

**标签**

`TokenAI · 模型 Token 服务与企业级 AI 网关`

使用 `14px` 中等字重的业务蓝文字，不加胶囊背景。

**主标题**

` 稳定接入主流 AI 模型，为企业应用而生。`

- 桌面端 `48px / 56px`，字重 `600`，最多两行。
- 整句使用深海军蓝，不对局部文字使用渐变。

**说明文案**

使用项目简报的首页推荐文案，桌面端宽度不超过 `680px`，字号 `16px`，行高 `28px`。

**行动区**

- 主按钮：立即开始。
- 次按钮：企业咨询。
- 文字链接：查看文档。

按钮统一使用项目营销页 `xl` 尺寸档，不单独写死高度。按钮组与说明文案间距 `28px`。

### 5.4 首屏底部：快速接入操作坞

将参考截图的底部 Prompt 输入框转译为 TokenAI 的“快速接入操作坞”，而不保留聊天输入含义。

**默认内容**

- 左侧标题：“从一个 API 开始”。
- 中部步骤：注册或登录 → 创建 API Key → 复制 Base URL → 发起最小请求。
- 右侧主操作：“创建 API Key”；未登录用户跳转注册或登录。

**展开状态**

用户选择“开始接入”后，操作坞在当前文档流中展开，不强制打开模态框：

1. 选择“OpenAI 兼容”或“Anthropic 兼容”。
2. 显示由当前部署配置生成的 Base URL。
3. 显示 `sk-your-key` 占位符和 `<available-model-id>` 占位符。
4. 提供“复制完整配置”和“查看可用模型”操作。

操作坞使用单层白色容器、`1px` 边框和 `--radius` 圆角，最大宽度 `880px`。它是首页唯一可使用轻量阴影的非浮层容器，阴影只用于表达其“可操作入口”属性。

### 5.5 价值入口：弱卡片网格

首屏下方使用 `2 × 2` 弱卡片网格，对应 TokenAI 的四类客户结果：

1. 统一多模型接入。
2. 可靠性路由与失败重试。
3. 成本、额度与用量治理。
4. 安全、日志与调用可观测。

卡片高度保持一致，仅包含一个线性图标、标题和最多两行说明。默认使用透明背景和弱边框；hover 时只将背景提升为浅蓝色，不位移、不缩放、不增加重阴影。

### 5.6 工具配置模块

模块标题为 **“一个 API，连接主流 AI 模型”**，使用三个场景标签页：

- 代码编辑器。
- 命令行工具。
- 前端应用。

每次只展示一个工具的完整配置。其他已验证工具使用轻量行列表切换，不在同一屏堆叠多个代码卡片。

完整配置区必须包含：

1. 配置位置。
2. 必填字段。
3. 启动或保存方式。
4. 验证方法。
5. 查看完整文档。
6. 配置失败排查。

代码区可使用深海军蓝背景，但不使用高饱和彩虹语法高亮。所有 Base URL、API Key 占位符和完整配置均必须提供复制操作。

### 5.7 企业能力与收尾

使用开放式左右分栏，而非新增一组功能卡片：

- 左侧：“让 AI 应用从测试走向持续运营”标题与企业服务说明。
- 右侧：多渠道调度、失败重试、权限与额度、透明计费和调用日志的分隔行列表。
- 操作：“企业咨询”主按钮与“了解网关部署”文字链接。

页尾仅保留产品、开发文档、企业服务、法律信息和必需品牌信息，避免使用高度复杂的多列导航。

## 6. 视觉令牌示例

### 6.1 颜色

| 语义 | 参考值 | 用途 |
| --- | --- | --- |
| `background` | `#F8FAFC` | 页面主画布 |
| `surface` | `#FFFFFF` | 操作坞、展开配置和必要容器 |
| `surface-subtle` | `#F1F5F9` | hover、次级分组、代码区外围 |
| `foreground` | `#0F2744` | 标题与主文本 |
| `muted-foreground` | `#66758A` | 辅助说明 |
| `primary` | `#0B6BEA` | 主操作、选中、焦点和关键链接 |
| `primary-hover` | `#095BC8` | 主操作 hover |
| `primary-subtle` | `#E8F2FF` | 选中行与轻量信息底色 |
| `border` | `#DDE5EF` | 分隔线和弱边界 |
| `code-background` | `#0B1F36` | 代码区 |
| `success` | `#16834A` | 验证成功、健康状态 |
| `warning` | `#A95C00` | 配置提醒 |
| `destructive` | `#B42318` | 错误与失败状态 |

上表是视觉目标，实现时应映射到项目现有语义 CSS 变量，不在业务组件中到处硬编码色值。营销首页可使用受控的装饰色，但不改变“单蓝色品牌轨”。

### 6.2 排版

- 字体：使用项目现有 `--font-sans` 及其 CJK 回退栈，不为首页额外引入新字体。
- 主标题：桌面端 `48/56`，平板端 `40/48`，移动端 `32/40`，字重 `600`。
- 区块标题：桌面端 `32/40`，移动端 `26/34`，字重 `600`。
- 卡片或工具标题：`16/24`，字重 `600`。
- 正文：`16/28`；辅助文字：`14/22`；标签与辅助操作：`12/18`。
- 代码、Base URL、API Key 占位符与模型 ID 使用现有等宽字体轨。

### 6.3 间距与容器

- 基础间距单位：`4px`。
- 页面主间距：`8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128px`。
- 单层容器内边距：桌面端 `24px`，移动端 `16px`。
- 统一圆角：使用现有 `--radius`；同类容器不混用多种大圆角。
- 容器边界：默认使用边框；只有操作坞、菜单、弹层等需表达层级的区域可使用轻量阴影。

## 7. 核心组件样式

### 按钮

- 主按钮：纯业务蓝背景、白色文字，不使用渐变。
- 次按钮：白色或透明背景、弱边框、深色文字。
- 文字按钮：业务蓝文字，hover 时使用浅蓝底色。
- 焦点状态：使用可见的业务蓝 focus ring，不仅靠颜色深浅变化。

### 标签页与切换

- 标签页容器优先使用无底色文本导航和底部选中线。
- 当切换的是协议或关键配置时，可使用单层浅蓝选中底色和边框。
- 所有切换必须有文本标签，不只用图标或颜色表达状态。

### 复制控件

- 图标按钮必须提供 `aria-label`。
- 复制成功后，图标短暂切换为成功状态，并显示“已复制”文本反馈。
- 反馈不只依赖颜色，不在复制后弹出阻断式对话框。

### 代码块

- 桌面端可使用深色代码区，移动端允许横向滚动。
- 复制按钮保持在可见的右上角，不随代码内容横向滚动移出视口。
- 不在代码示例中写死部署域名、真实密钥或未验证模型名。

## 8. 交互与状态

### 登录状态

- 未登录：主操作为“立即开始”，快速接入操作坞引导登录或注册。
- 已登录：主操作为“进入控制台”，操作坞可直接跳转创建 API Key。

### 协议切换

- 切换到 Anthropic 兼容工具时，显示 `<TokenAI_ANTHROPIC_BASE_URL>`，默认不追加 `/v1`。
- 切换到 OpenAI 兼容工具时，显示 `<TokenAI_OPENAI_BASE_URL>/v1`。
- 协议、Base URL、模型 ID 与代码示例必须同步更新。

### 验证状态

- 等待：显示骨架或 spinner，不使用循环跳动的彩色效果。
- 成功：显示“请求成功”、模型 ID、Token 用量与“在用量日志中查看”链接。
- 失败：需覆盖 Base URL 路径错误、API Key 无效、模型不存在、额度不足、请求被限流和旧环境变量未更新等场景。
- 失败提示与错误原因同屏显示，并提供“配置失败排查”入口。

### 动效

- 颜色与透明度过渡不超过 `150ms`。
- 展开、收起可使用短时长的高度与透明度过渡。
- 不使用大面积 stagger、平移入场、缩放入场或模糊入场。
- 必须支持 `prefers-reduced-motion`，该模式下取消非必需动效。

## 9. 响应式规则

### 桌面端（`>= 1024px`）

- 保留居中主任务、完整导航与快速接入操作坞。
- 价值入口使用两列，工具配置使用左侧工具列表与右侧详情。

### 平板端（`640–1023px`）

- 导航只保留品牌、必需入口与菜单触发器。
- 首屏内容宽度不超过 `720px`，操作坞与工具配置改为单列。

### 移动端（`< 640px`）

- 页面左右安全边距 `16px`，首屏顶部留白降为 `64–80px`。
- 主、次操作优先纵向排列，主按钮满宽。
- 快速接入操作坞不固定在视口底部，作为正常文档流内容展示，避免遮挡内容或软键盘。
- 场景标签页允许横向滚动，复制按钮保持可见。
- 代码块可横向滚动，不截断 URL、环境变量名或模型 ID。
- 指针目标不小于 `24 × 24px`，主要操作优先使用营销页 `xl` 按钮档。

## 10. 无障碍与内容约束

- 语义结构使用 `header` / `nav` / `main` / `section` / `footer`。
- 所有主要文本与背景对比度满足 WCAG AA；不使用低对比度浅灰展示必需信息。
- 键盘用户可依次访问导航、主操作、协议切换、配置复制和验证入口。
- 装饰性图标标记 `aria-hidden="true"`，图标按钮提供可理解的 `aria-label`。
- 用户可见文案实现时必须接入 i18n，不在组件中直接硬编码单一语言。
- 页面只显示 `sk-your-key` 占位符，不渲染、缓存或写入真实密钥。
- 模型数量、模型名称、可用协议和 Base URL 来自当前平台配置，不写死到产品文案或静态数据中。

## 12. 实现前检查清单

- [ ] 确认本轮实现范围只包含公开首页。
- [ ] 使用项目现有 PublicLayout、设计系统适配层和语义令牌。
- [ ] 用户可见文案全部接入 i18n，并补齐全部支持语言。
- [ ] Base URL、协议、模型 ID 和可用工具从当前平台配置获取。
- [ ] 不显示真实 API Key，示例只使用 `sk-your-key`。
- [ ] 复制、协议切换、工具切换、验证成功和常见失败均有明确反馈。
- [ ] 移动端代码块可横向滚动，复制按钮保持可见。
- [ ] 模型数量、名称与支持协议没有被写死。
- [ ] 主要交互支持键盘操作，文本对比度满足 WCAG AA。
- [ ] 首屏不使用紫色、重渐变、玻璃拟态或功能卡片墙。
- [ ] 不删除、替换或弱化受保护项目信息、授权、署名与元数据。
