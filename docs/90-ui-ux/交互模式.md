# 交互模式

## 派生字段

由代码注册事实决定的字段使用只读投影，不让用户自由拼装。投影必须由单一函数全量计算；输入变化、
方案切换或解析失败时同时更新或清空所有受管字段，不能保留上一方案的路径、profile 或 route。

## 敏感变更确认

普通表单保存不得隐式执行合同变更。需要修改稳定 publication 时使用独立确认对话框，固定展示对象、
当前值、目标值和版本，要求填写原因，并只向具备敏感写权限的管理员开放。

## 并发与错误反馈

- 参数或目标 SKU 无效：指出需修正的字段，不建议重试；
- publication 不存在：刷新当前对象并重新检查发布流程；
- 版本或并发冲突：关闭盲目重试，刷新最新版本后重新确认影响；
- 暂不可履约：保留已发布身份，明确它与“模型不存在”不同。

## 模型命名最小关注面

管理员在渠道配置中只操作客户模型名（`channels.models`）和真实模型名（`model_mapping` 最终目标）。Link SKU
是内部合同身份，不作为常规配置项展示，不要求管理员填写或理解 SKU 字符串；模型映射沿用 NEWAPI 原生方向，
无 mapping 时使用身份翻译，不自动生成自映射。完整身份分离与默认投影来源见
[Link 服务合同概念与协作关系 §3.6](../20-architecture/Link服务合同概念与协作关系.md)。

## 默认模型投影

新建且 `models` 与 `model_mapping` 均为空的 Link 视频渠道表单，在选择 Link 接入方案后可由系统把真实模型
候选填入 `Models` 编辑器，作为可编辑默认值。候选只来自当前 implementation create execution bindings 的
`provider_model`，不取自 SKU、`plan_name`、展示名或模型相似度。已有 `models` 或 `model_mapping` 时不改写；
切换或清除方案不自动创建、改写或删除 `model_mapping`。填充只是未保存的编辑辅助，不触发保存、Ability 发布
或 publication 创建。

## 信息分层可见性

| 角色 | 默认展示 | 默认不展示 |
| --- | --- | --- |
| 客户 | 客户模型名、请求与结果 | 真实模型、SKU、implementation、Provider 路径 |
| 渠道管理员 | 客户模型名、真实模型名、mapping、可操作的兼容性错误 | SKU 字符串、content hash、完整 binding 键、内部快照 |
| 审计/高级诊断 | publication、SKU、implementation/version/hash、binding、冻结快照 | 客户不应看到的凭据或原始 Provider 响应 |

不展示不等于不记录或不校验：内部合同事实必须完整、可追溯、可复检，但只在对当前角色任务有实际作用时展示。
