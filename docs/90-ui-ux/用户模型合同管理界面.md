# 用户模型合同管理界面

## 1. 客户合同总览

管理员侧边栏在“用户”后显示“客户合同”，进入 `/admin/customer-contracts`。页面标题为“客户模型合同”，
普通用户不可见且无权访问。

页面顶部显示全部合同、生效合同和已停用三项角色范围内的全局摘要；下方支持按 User ID、
用户名、显示名、公开模型和合同状态进行服务端检索与分页。列表展示客户、合同状态、规则数（渠道规则
数量）、不可履约规则数、版本、最近修改时间和管理员。启用合同即为“生效”，不再存在“零模型权限”状态；
来源渠道失效会使该组合不可履约，所有组合失效时绑定 Key 的模型调用被拒绝。行操作“管理模型合同”打开与用户列表相同的合同侧边栏。

总览按合同实体列示未删除用户的合同，不把旧用户级字段或未创建合同的用户伪装成合同。页面不提供批量启停、批量折扣
或内联规则编辑，所有写入继续通过单用户合同编辑器完成。移动端使用共享列表卡片布局。

## 2. 用户列表

用户名旁按当前合同实体显示摘要，不读取旧 `users.contract_mode` / `contract_version` 来判断合同状态：

| 状态 | 文案与语义 |
| --- | --- |
| 无合同 | 暂无合同；仅有历史用户级合同字段不计为当前合同 |
| 已有合同 | 显示合同总数与已启用数；全部停用时使用中性色 |
| 摘要缺失 | 合同摘要暂不可用，不解释为零权限或原生模式 |

列表与搜索接口通过只读 `contract_summary` 返回 `total` 与 `enabled`，不改写历史迁移字段。
权限以 API Key 绑定的合同为范围；用户可同时持有多份合同及未绑定的 Key，因此用户列表不显示账号级
“无模型权限”。具体规则、可履约状态与绑定 Key 在合同管理中查看。

行操作菜单提供“管理模型合同”，不把合同字段混入通用用户资料抽屉。

## 3. 合同侧边栏

侧边栏使用宽桌面布局和小屏近全宽布局。头部显示用户名、User ID、模式、规则数和版本；主体包含“合同
配置”和分页“审计历史”两个页签；底部固定取消、启停和保存操作。

配置顺序固定为：

```text
渠道组 -> 多选当前可履约模型 -> 批量折扣 -> 逐规则调整 -> 价格预览 -> 变更原因 -> 保存
```

折扣接受小数、百分比和中文折扣写法，在输入结束后归一为最多八位的小数显示。同一公开模型可以继续
添加其他渠道来源；相同模型与渠道的重复、同模型折扣冲突和仅大小写不同的模型名会被明确拒绝，
同模型折扣调整必须在一次完整替换中覆盖该模型的所有规则。新添加但尚未保存的规则也必须立即显示当前
价格；tiered 模型显示“阶梯价格 × 折扣”。

## 4. 风险与恢复

- 特殊原生组倍率显示叠加提示。
- 启用合同没有规则时明确提示无法提交模型请求；渠道失效与无组访问权限分别标注。
- 停用合同和丢弃未保存更改都需要确认；停用提示 Key 将恢复自身分组路由与计价，可能使用范围外渠道。
- 版本冲突不允许盲目重试；界面加载服务端最新版本并提示重新确认。
- 系统设置修改组倍率时，若影响生效合同，保存前显示合同数、规则数和渠道组。

## 5. 普通用户只读区域

API Key 处展示所绑定合同的折扣明细：按公开模型去重后的“模型 + 合同折扣”两列；同模型多渠道只显示
一行。未绑定合同时明确显示未绑定；合同已停用时提示恢复 Key 自身分组逻辑；读取失败显示明确失败状态，不虚构
生效折扣。完整合同条款标注渠道/组权限不可用，Key 编辑界面另外提示自身模型限制；发现与报价只显示
有效范围。明细不展示渠道组、Channel、
Provider、上游模型、合同审计或内部错误原因。新建 API Key 且用户全部合同中恰有一份已启用合同时，
表单自动选中该合同并显示其折扣明细；用户手动取消绑定或其他选择不会被数据刷新覆盖。
