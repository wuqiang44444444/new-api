# API 文档中心交互规范

本文定义 `/docs` 的信息架构、页面状态、导航、搜索、代码示例和无障碍交互。公开合同、构建与安全
边界见[公开 API 文档交付架构](../20-architecture/公开API文档交付架构.md)，内容维护规则见
[公开 API 文档维护指南](../30-engineering/公开API文档维护指南.md)。

## 1. 信息架构

文档中心按用户完成调用任务的顺序组织，而不是按后端目录或 Provider 分类：

```text
概述
开始使用
  ├─ 快速开始
  ├─ 鉴权
  └─ Base URL
核心概念
  ├─ 模型
  ├─ 错误
  ├─ 限流
  ├─ 计费
  └─ 异步任务与幂等
API Reference
  ├─ 文本
  ├─ 图片
  ├─ 视频
  └─ Link 资源
指南
  └─ 排障与工具接入
```

导航结构和页面顺序由 Manifest 决定。未通过公开白名单的接口不显示占位页面，也不使用“即将支持”
代替真实合同。

## 2. 页面布局

桌面端使用三栏结构：

```text
顶部文档导航
  -> 左侧全站目录
  -> 中间正文
  -> 右侧本页目录
```

- 顶部区域提供品牌返回、文档首页、主题和全站搜索入口；
- 左侧目录展示当前 locale 的 Manifest 分组与页面；
- 正文保持适合长文阅读的宽度，代码块允许横向滚动；
- 右侧目录只展示当前页 `h2`、`h3`，随滚动高亮；
- 上一页/下一页按 Manifest 顺序生成，不从文件系统推断。

移动端隐藏固定侧栏，通过独立按钮打开全站目录和本页目录；抽屉关闭后焦点返回触发按钮。

## 3. 路由与导航行为

- `/docs` 进入概述页；
- `/docs/{slug}` 只接受 Manifest 登记的规范 slug；
- 未找到 slug 显示文档专用 404，不静默回退到首页正文；
- 内部链接使用客户端路由，保留浏览器前进/后退语义；
- 页面切换后聚焦正文 H1；
- 合法 `#heading` 在正文加载后滚动并更新焦点；
- 外部 HTTP(S) 链接新窗口打开并使用 `noopener noreferrer`；
- 非规范大小写、非法转义或危险 scheme 不猜测跳转目标。

站点 `docs_link` 的交互规则统一为：

```text
空值                     -> 内部 /docs
合法 http:// 或 https:// -> 外部文档
单个 / 开头              -> 内部路由
其他值                   -> 安全回退 /docs
```

首页、顶部导航和文档页复用同一解析结果，不能出现不同入口跳向不同文档源。

## 4. 搜索

搜索覆盖：

- 页面标题；
- description；
- keywords；
- `h2`、`h3` heading。

浏览器首次打开搜索时按需加载当前 locale 的构建期索引，不抓取全部 Markdown，也不把内部 `docs/`
加入搜索。结果按稳定相关性和 Manifest 顺序展示，至少包含页面标题、匹配 heading 和所属分组。

交互要求：

- 打开搜索后焦点进入输入框；
- 上下方向键移动结果，Enter 打开，Escape 关闭；
- 无结果、索引加载失败和网络失败分别展示明确状态；
- 索引失败不阻止左侧目录和直接路由访问；
- 移动端搜索占据可用视口，但不能困住键盘焦点。

## 5. 正文与代码示例

- 页面只允许一个 H1；
- `h2`、`h3` 生成稳定、唯一且可复制的锚点；
- 表格在窄屏横向滚动，不能挤压为不可读布局；
- 提示块通过受控样式表达信息、警告和危险，不依赖颜色作为唯一信号；
- 代码块显示语言、复制按钮和复制结果反馈；
- 高亮失败时降级为转义后的纯文本，不能丢失代码内容；
- 动态 Base URL 和占位符以文本呈现，不读取真实用户凭据；
- 请求、响应和错误示例应能独立理解，不要求读者掌握内部渠道或 Task 私有结构。

复制成功通过可见文本和 `aria-live` 提示，反馈不抢夺焦点。复制按钮具有包含代码块上下文的可访问名称。

## 6. 页面状态

| 状态 | 页面行为 |
| --- | --- |
| Manifest 加载中 | 显示稳定骨架，保留页面主结构 |
| Manifest 加载失败 | 显示文档不可用、重试和返回站点入口 |
| slug 不存在 | 显示文档 404 和返回文档首页 |
| Markdown 加载中 | 保留导航，正文显示加载状态 |
| Markdown 缺失/解析失败 | 不渲染半成品，显示受控错误与重试 |
| `/api/status` 失败 | 使用当前 origin 和安全占位符，不阻塞正文 |
| 搜索索引失败 | 保留目录导航，禁用搜索并解释原因 |
| 代码高亮失败 | 降级纯文本代码块 |

普通用户错误不能显示绝对文件路径、堆栈、原始 Markdown、内部配置或网络响应原文。

## 7. 响应式与无障碍

- 所有导航、搜索、目录、复制和抽屉功能可仅用键盘完成；
- 使用语义化 `nav`、`main`、heading 和 landmark；
- 当前页面、当前 heading 和展开状态通过 `aria-current`、`aria-expanded` 等表达；
- 抽屉打开时焦点受控，关闭后恢复；
- 页面切换和加载错误通过适度的 live region 通知；
- 焦点样式在浅色和深色主题下都清晰可见；
- 颜色对比满足当前项目无障碍基线；
- 尊重 `prefers-reduced-motion`，滚动和抽屉动画不成为完成任务的前提；
- 触控目标具有足够尺寸和间距，代码复制按钮在窄屏仍可达。

## 8. 国际化

文档框架文案使用现有 `react-i18next`，包括搜索、复制、分页、目录、加载、错误和 404。正文按
`docs-content/{locale}` 独立维护，不将整篇 Markdown 放入 i18n JSON。

同一主题在各语言中保持相同 page ID 和逻辑 slug。当前 UI locale 不存在或单页缺失时回退
Manifest 的 `defaultLocale`，并向用户明确当前为回退语言。

## 9. 交互不变量

1. 导航、搜索和分页都使用同一份 Manifest 顺序和页面身份。
2. 路由不能按用户输入直接拼接 Markdown 文件路径。
3. 页面切换、抽屉和搜索必须有完整键盘与焦点语义。
4. 加载失败只影响对应能力，不能泄露内部信息或渲染半成品。
5. 复制、动态变量和代码高亮不能读取或注入真实 API Key。
6. 移动端提供与桌面端等价的信息访问能力。
7. 正文语言与框架语言分离，回退状态对用户可见。

## 10. 验收视口与场景

发布前至少覆盖：

- 桌面宽屏、普通笔记本、平板和窄屏手机；
- 浅色、深色和系统主题；
- 纯键盘打开目录、搜索、跳转、复制和返回；
- 长标题、长代码、宽表格、无本页目录页面；
- Manifest、Markdown、状态接口和搜索索引分别失败；
- 深层链接刷新、带 heading 链接、浏览器前进后退；
- locale 缺失与单页回退。
